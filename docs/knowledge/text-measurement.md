# C ロケールで日本語テキストを扱うときの注意事項

シェルコマンドで日本語テキストを数える・切る・探すときの落とし穴。どれも、コマンドが文字ではなくバイトを単位にして動き、エラーを出さずに誤った結果を返す。

## 作業環境のロケール

このリポジトリの作業環境は C ロケール（`LC_ALL` / `LANG` が空で、`locale` は `POSIX` を返し、`locale charmap` は `ANSI_X3.4-1968` を返す）である。UTF-8 のロケールも入っており、`locale -a` は `C`・`C.utf8`・`POSIX` を返す。コマンドの前に `LC_ALL=C.UTF-8` を付けると、そのコマンドだけ UTF-8 で動く（`LC_ALL=C.UTF-8 locale charmap` は `UTF-8` を返す）。

UTF-8 の日本語は1文字3バイトなので、C ロケールのコマンドは日本語の1文字を3つの別々の文字として扱う。

## 数える: awk / wc

`awk` や `wc` で日本語テキストの文字数を測ると、バイト長が返る。

```sh
# 誤り: どれもバイト長を返す
echo "いらっしゃる" | awk '{ print length($0) }'  # → 18 (6文字×3バイト)
echo -n "いらっしゃる" | wc -c                    # → 18 (バイト数)
echo -n "いらっしゃる" | wc -m                    # → 18 (C ロケールでは wc -m もバイト長)
```

`LC_ALL=C.UTF-8` を付けると `wc -m` は 6 を返す。`awk` の実体は mawk で、`LC_ALL=C.UTF-8` を付けても `length()` はバイト長（18）を返す。

UI の実装（JavaScript/TypeScript）が参照するのは **`String.length`**（UTF-16 コードユニット数）。日本語は基本多言語面（BMP）内のため、`String.length` = 文字数と一致する（サロゲートペア外）。文字数の計測（特に UI の表示幅・折り返し見積もり）は `node -e` または `npx tsx` で `String.length` を使う。

```sh
node -e "console.log('いらっしゃる'.length)"    # → 6
npx tsx -e "console.log('いらっしゃる'.length)" # → 6
```

根拠: 実測（cycle-216・cycle-316）。cycle-216 で keigo-reference の尊敬語の最長値を awk `length()` で測ると「81」になったが、これはバイト長で、`String.length` では「27」（`いらっしゃる・おいでになる・お見えになる・お越しになる`）だった（81 バイト ÷ 3 = 27 文字）。cycle-316 にこの節の各コマンドを現在の作業環境で実行し、記載どおりの値を確かめた。

## 切る: cut -c / head -c

`cut -c` と `head -c`（`--bytes`）はバイト単位で切る。日本語の行は字の途中で切れ、長い行を先頭だけ出して読んだつもりでも、思ったより短い範囲しか読めていない。

```sh
echo -n "あいう。" | cut -c1-4   # → 「あ」と壊れた字（4バイト = 1文字と1バイト）
echo -n "あいう。" | head -c 4   # → 同じ
echo -n "あいう。" | head -c 6   # → あい（6バイト = 2文字）
```

この環境の GNU coreutils 9.4 では、`cut -c` は `-b` の別名で、`LC_ALL=C.UTF-8` を付けてもバイトで切る（`cut -c1-4` の結果は同じ）。GNU coreutils 9.11（2026年4月20日）からは `cut` がマルチバイトの入力を扱い、`-c` が `-b` の別名でなくなった（[coreutils-9.11 の告知](https://lists.gnu.org/archive/html/info-gnu/2026-04/msg00006.html)、2026-10-05 に確かめた）ので、環境の版が上がると UTF-8 のロケールでの `cut -c` の結果が変わる。版は `cut --version` で確かめる。`head -c` は版によらずバイトで数える。

文字の数で切るなら `node -e "console.log('あいう。'.slice(0, 2))"`（→ あい）か `LC_ALL=C.UTF-8 grep -o '^.\{0,2\}'`（→ あい）を使う。長い行を全文読むときは、切らずにファイルへ書き出して、そのファイルを読む。

根拠: 実測（cycle-318、GNU coreutils 9.4）。上の各コマンドを実行し、`od -An -tx1` で `cut -c1-4` の出力が `LC_ALL=C.UTF-8` の有無によらず `e3 81 82 e3` であることを確かめた。

## 探す: grep の1文字の単位

C ロケールの `grep` では、1文字を単位にする書き方がすべて1バイトに掛かる。角括弧（`[^。]`・`[あ]`）は「その字を作る3バイトのどれか」という集合になり、`.` と `.\{n\}` は1バイトに一致し、日本語の字の後ろの `*`・`\+` はその字の最後の1バイトにだけ掛かる。結果は、一致するはずの行が一致しない（偽の「無い」）か、一致しないはずの行が一致する（偽の「有る」）か、一致の範囲が短くなるかで、エラーは出ない。

```sh
# 偽の「無い」: 一致する行があるのに 0 を返し、終了の値は 1
echo "あいう。" | grep -c "あ[^。]*。"     # → 0
echo "あいう。" | grep -c "あ.う"          # → 0（. は1バイト）
echo "あ"       | grep -c "^.$"            # → 0
echo "あいう"   | grep -c "^.\{3\}$"       # → 0

# 偽の「有る」: 一致しないはずの行に一致し、終了の値は 0
echo "い"       | grep -c "[あ]"           # → 1（「い」と「あ」は先頭のバイトが同じ）
echo "あ"       | grep -c "^...$"          # → 1（「あ」は3バイト）

# 一致の範囲が短い: \+ と * が「い」の最後の1バイトにだけ掛かる
echo "あいいう" | grep -o "あい\+"         # → あい（UTF-8 なら あいい）
echo "あいいう" | grep -o "あい*"          # → あい

# LC_ALL=C.UTF-8 を付けると文字を単位にする
echo "あいう。" | LC_ALL=C.UTF-8 grep -c "あ[^。]*。"   # → 1
echo "あいう。" | LC_ALL=C.UTF-8 grep -c "あ.う"        # → 1
echo "あ"       | LC_ALL=C.UTF-8 grep -c "^.$"          # → 1
echo "い"       | LC_ALL=C.UTF-8 grep -c "[あ]"         # → 0
echo "あいいう" | LC_ALL=C.UTF-8 grep -o "あい\+"       # → あいい
```

`[^。]` が「い」に一致しないのは、「い」（E3 81 84）と「。」（E3 80 82）が先頭のバイト E3 を共有するためで、`[^、]`（E3 80 81）でも同じことが起きる。ひらがな・カタカナ・和文の記号は先頭のバイトがどれも E3 なので、この取りこぼしは珍しくない。

C ロケールのままでも正しく一致するのは、固定の文字列（`grep -F "あいう"`）と、日本語の字の並びをそのまま書き、`.*` でつなぐか `^`・`$` で行の端に寄せるだけの型（`grep -o "あ.*。"` → あいう。、`grep -c "いう。$"` → 1）である。それ以外の型で探すときと、「この字・この言い回しはどこにも無い」を確かめるときは、`LC_ALL=C.UTF-8` を付ける。偽の「無い」はそのまま不在の主張になる。

Claude Code の Grep の道具（ripgrep）は、ロケールによらず UTF-8 の文字を単位に一致を取るので、この落とし穴に当たらない。C ロケールのままで `rg -c "あ[^。]*。"` は 1、`rg -c "あ.う"` は 1、`rg -o "あい+"` は「あいい」を返し、Grep の道具でファイルを `あ[^。]*。` で探すと「あいう。」の行に一致した。

根拠: 実測（cycle-318、GNU grep 3.11・ripgrep 14.1.0）。角括弧に日本語を入れた `grep` が一致する行を見落としたことから、上の各コマンドを実行し、記載どおりの出力と終了の値を確かめた。バイトの値は `printf %s "あい。、" | od -An -tx1`（→ `e3 81 82 e3 81 84 e3 80 82 e3 80 81`）で確かめた。
