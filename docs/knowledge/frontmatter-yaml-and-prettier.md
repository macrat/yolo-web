# frontmatter の YAML と Prettier の整形

記事の frontmatter は「YAML として書かれ、Prettier に整形され、`js-yaml` に読まれる」という3者の合意の上に立っている。
その合意が思い込みと違っていた点を実測で記録する（測定日 2026-09-14 / `js-yaml` 4.3.1 / Prettier 3.9.5 / `printWidth: 80`）。

## `js-yaml` がタイムスタンプとして読む書き方は一様でない

「引用符を落とすと `Date` になる」は成り立たない。`k: <値>` を `yaml.load` に掛けた実測結果は次のとおり。

| 書き方（引用符なし）        | 読まれる型 |
| --------------------------- | ---------- |
| `2026-07-16`                | `Date`     |
| `2026-07-16 12:00:00`       | `Date`     |
| `2026-07-16T12:00:00`       | `Date`     |
| `2026-07-16T12:00:00Z`      | `Date`     |
| `2026-07-16T12:00:00+09:00` | `Date`     |
| `2026-07-16T12:00:00+09`    | `Date`     |
| `2026-07-16T12:00:00+0900`  | `string`   |
| `2026-7-16`                 | `string`   |
| `20260716`                  | `number`   |

**コロンの無いオフセット `+0900` は、引用符が無くても文字列のまま読まれる。**
そのため「引用符を外せば型が変わる」という前提で回帰テストを書くと、`+0900` 形の値では
**引用符を外しても検査が落ちない**（型は期待どおりの文字列のまま）。型の検査だけでは引用符の欠落を捕まえられず、
「書かれている文字列とパース結果を突き合わせる」検査が別に要る。

日付を4桁-2桁-2桁で揃えているかどうかでも結果が変わる（`2026-7-16` は文字列）。
値の見た目が似ていても型が揃う保証は無いので、**日付は必ず引用符で囲む**。

## Prettier は markdown の frontmatter を YAML として整形する

Prettier の[公式オプション一覧](https://prettier.io/docs/options)に markdown frontmatter の整形についての規定は無い。
**未文書の挙動**なので、次の観測に設計を依存させない（依存させた結果が下の「壊れていると整形しない」である）。

- **flow 配列（`key: [...]`）は行が 80 桁を超えると折り返す。** ASCII だけの行で閾値を挟んで実測すると、
  80 桁は1行のまま、81 桁から折り返しが起きる。折り返された形は `key:` だけの行＋字下げされた `[` 以下になる。
- **ブロック配列（`key:` ＋ `  - "値"`）は折り返さない。** 20 要素でも各要素が1行のまま保たれる。
  flow 配列で書く限り、値が増えれば必ずいつか折り返される。ブロック配列で書けばその条件が発生しない。
- **引用符の種類は正規化される。** `'値'` は `"値"` になり、値が `"` を含むときだけ `'値'` が選ばれる
  （`"has \"quote\""` → `'has "quote"'`）。したがって引用符の**種類**を検査に固定してはいけない。
  一方、**引用符の無い値に引用符が足されることはない**。整形は引用符の有無を直してくれない。
- **frontmatter が YAML として壊れていると、Prettier は frontmatter を整形せず `--check` も通す。**
  壊れている間は手で直した書き方がそのまま残り、**壊れ方が解消された瞬間に整形が走る**。
  「今は整形されていないから安全」は、YAML として壊れていることの裏返しでしかない。

markdown 本文中のコードブロックも言語ごとに整形される（`yaml` / `typescript` / `json` で実測）。
記事で整形前後を対比したいときの回避策は `docs/blog-writing.md` にある。

## `.gitignore` された場所で Prettier を試すと、何も起きずに成功する

Prettier 3 の既定の `--ignore-path` は `.gitignore` を含む。このリポジトリの `.gitignore` は `tmp/*` を
無視しているため、`./tmp/` 配下のファイルに `prettier --write` を掛けても**何も実行されない**。

```
$ printf -- '---\ntitle:    "x"\n---\n' > tmp/a.md
$ npx prettier --write tmp/a.md   # 出力なし
$ echo $?
0
$ cat tmp/a.md                    # 整形されていない
---
title:    "x"
---
```

`--write` は対象ファイル名すら出さず、`--check` は無条件に `All matched files use Prettier code style!` を返す。
**整形の挙動を実験で確かめるとき、`./tmp/` は使えない。** ここで測ると「走らなかった」を
「変化しなかった」と読み違える。リポジトリ外の作業ディレクトリを使うか、`--ignore-path /dev/null` を渡すこと。
設定は `--config <リポジトリの .prettierrc>` で明示的に渡す。
