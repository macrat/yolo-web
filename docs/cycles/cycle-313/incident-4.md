# 事故報告 4: 起票した ADR を削除し、もう1件を adopted へ移した

本報告は `git log` / `git show`、リポジトリ内のファイル、本セッションのトランスクリプト（`57683f47-a193-509d-94f9-98c8113f365c.jsonl`）を一次記録として書いた。記録で裏が取れないことは書かない。内心・意図は断定しない（AP-WF27）。

## 何をしたか

本サイクルで ADR を2件起票し、同じ日に「実験として成立していない」と判定した。その処分が運用に反していた。

| ADR                                                     | 起票                | 処分                                                                     | コミット   |
| ------------------------------------------------------- | ------------------- | ------------------------------------------------------------------------ | ---------- |
| ADR006 ブログ一覧の記事リンクを静的HTMLへ戻す           | `44fba187` 10:08:06 | **`git rm` で削除した**                                                  | `f3473bf3` |
| ADR007 掲載数のしきい値を撤廃し全タグにページを用意する | `1f082786` 13:42:00 | 観測の節を外して本文を書き換え、**`adopted/`（＝従うべき先例）へ移した** | `f3473bf3` |

`git show --name-status f3473bf3` の実測: `open/` の ADR006・ADR007 が `D`（削除）、`adopted/` に ADR007 が `A`（新規）。ADR006 には移動先が無い。

## どのルールに違反しているか

### 削除は運用に無い

`docs/ADR/README.md` は状態を置き場所で表す三状態として定めている。9行目（expired の定義）。

> - `docs/ADR/expired/YYYY-MM-DD-ADR###-タイトル/` — **失効**（後の決定に覆された・賭けに負けて撤退した・環境変化で無効になった）。先頭の日付は失効日。**index.md に「何によって失効したか」（覆した ADR 番号・観測結果等）を必ず書く**。

失効したものを「どう残すか」がここに書かれている。残さない選択肢は書かれていない。同ファイル32行目（ライフサイクル §3 completion）。

> 決着したら結果・学びを書いて **adopted/**（賭けに勝った・決定が確認された）または **expired/**（負けて撤退・無効化）へ移動。

**無効化の行き先は expired と名指しされている。** 削除は選択肢として存在しない。同じ運用は `.claude/skills/cycle-completion/SKILL.md` の「## 4. ADRの記録と更新」にも3項目で書かれており（47〜49行目：起票・更新／移動・失効処理）、削除はどの項目にも無い。

`.claude/rules/doc-directory.md` 11行目も同じ建てを示す。

> - `./docs/ADR/` - ADR 兼実験記録（仮説→賭け→観測→記録）。1件=1ディレクトリで、`open/`（実験中・先頭日付=次回確認日）・`adopted/`（確定）・`expired/`（失効）に分かれます。書式・運用は `./docs/ADR/README.md` を参照してください。

三状態しか無く、運用の正典は README である。

### 番号は削除できない建てになっている

README 12行目。

> - **参照は必ず「ADR###」の番号で行う**（ディレクトリ名はリネームされるため、パス参照は壊れる）。番号は全状態通しの連番（最大+1）。

参照が番号で行われ、番号が「全状態通しの最大+1」で決まる以上、ある番号の文書を tree から消せば、その番号は欠番になるか、次の起票に再利用される。どちらも README の参照規約を壊す。

### 削除の根拠として引いた条文は、削除を許していない

PM が引いたのは README 41行目である（コミットメッセージ `f3473bf3` に「READMEの『結果がどう出ても使い道のない記録は残さない』に該当するため削除した」と書いている）。原文は次のとおり。

> - 打ち切りは打ち切りとして残す。ただし結果がどう出ても使い道のない記録は残さない（記録は目的でなく手段）。

**一文の前半は「打ち切りは打ち切りとして残す」である。** PM は後半だけを引いた。この行は「## 観測の規律」の節にあり、観測を打ち切るときの扱いを述べたもので、発行済みの ADR 番号の処分を定めた行ではない。番号の処分は9行目・12行目・32行目が定めている。

## 先例——同じ処置は cycle-302 で否定されている

`docs/ADR/expired/` の既存4件（ADR002〜005）は、いずれも原文を残したまま失効の記載を足す形をとっている。

| ADR                 | 状態行の書き方                                                                       | 「何によって失効したか」                                        | 節           |
| ------------------- | ------------------------------------------------------------------------------------ | --------------------------------------------------------------- | ------------ |
| ADR002（cycle-280） | 「状態: **失効（expired）——2026-07-14 撤回。賭けが論理的に破綻しており有効でない**」 | 「外部の観測や別 ADR ではなく、**PM 自身の論理批判**により」    | 「失効理由」 |
| ADR003・004・005    | 冒頭に「⚠ 失効（YYYY-MM-DD）——**これは ADR ではなかった**」の引用ブロック            | 「外部の観測でも別 ADR でもなく、**ADR の定義との照合**による」 | 「失効理由」 |

ADR003・004・005 の冒頭には、今回そのまま当てはまる一文が書かれている。

> **本来は削除すべきだが、既に発行してデプロイした番号を消すと番号の連続性に矛盾が生じるため、失効扱いとして残す。**

この判断の経緯は `docs/cycles/cycle-302/incident-2.md` の §7 にある。

> **削除ではなく失効にした理由**: ADR004・005 は一度削除したが、**既に発行してデプロイした番号を消すと、番号の連続性に矛盾が生じる**（次に起票する ADR が 004 を再利用するか、004・005 が欠番として説明なしに残るかのどちらかになる）。`README.md` は expired を「**もう従ってはいけない記録**」と定めているので、無効であることを明示したうえで番号を保存するのが正しい。

**ADR を削除し、指摘を受けて復元し、expired へ戻す——この一連はすでに cycle-302 で1度通っている。** 同じ処置を、同じリポジトリで、同じ理由で繰り返した。

### ADR002 との同型判定: 同型である

| 項目             | ADR002                                       | ADR006・ADR007                                        |
| ---------------- | -------------------------------------------- | ----------------------------------------------------- |
| 起票の形         | 賭け（仮説・観測手段・評価窓・撤退基準つき） | 同じ（ADR006 は撤退基準を置かないと明記）             |
| 無効と判った経路 | 外部の観測ではなく PM 自身の論理批判         | 外部の観測ではなく PM 自身の判断                      |
| 観測の有無       | 観測せず失効                                 | 観測せず失効                                          |
| 出荷の有無       | 機能は出荷済み・賭けのみ無効                 | ADR007 のコード変更は作業ブランチにある・賭けのみ無効 |
| 処置             | **原文を残し、失効理由を足して expired へ**  | **削除／adopted へ移動**                              |

**最後の1行だけが違う。** ADR002 は「負けの記録は勝ちと同粒度で」（README 25行目）を満たす唯一の ADR だと cycle-302/incident-2.md が名指ししている。同型の事象に、その先例と逆の処置をした。

## backlog では同じ経験が明文化されている

`docs/backlog.md` の 168行目、Done/Cancel セクションの冒頭。

> 完了または中止したタスクをここへ記録します。**タスクは削除しません**（削除すると番号の意味が失われ、欠番の再利用で ID 衝突が起きるため。cycle-291 が B-600 を削除して cycle-292 で衝突が発生）。中止タスクも Notes に【中止】と理由を明記して残します。

この定めは実害から書かれている。`docs/cycles/cycle-291/incident-1.md` 41行目に、削除した側の記述がある。

> **是正**: B-600 を backlog から削除（撤回）。既知の結論は cycle-277/278・ADR001 に記録済みで、B-600 を open タスクとして残すと将来の再掘削を誘うため、記録として残さず削除する。

2サイクル後、`docs/cycles/cycle-293/incident-1.md` 72行目で、同じ PM の系がこう書いている。

> **B-602**: 誤起票のため無効化。ただし番号は `8b2a7637` の git 履歴にあり、完全削除は将来の ID 衝突（backlog 冒頭の不削除ルール・B-600 前例）を招くため、Done/Cancel に **【中止】1 行**（誤起票の取消）として残す

**構図は成立する。** 「無効と判定した起票は、番号を残して無効と書く」という結論を、backlog では衝突を1度起こしたうえで明文化している。ADR では、同じ結論が README 9・12・32行目に最初から書かれており、cycle-302 が1度実演してもいる。それでも同じことをした。

## 削除の実害

ADR006 を削除したままだと何が失われるか。

**1. 番号 006 が欠番になる。** 削除後の tree に残る最大番号は 007 で、README 12行目の「最大+1」に従えば次の起票は 008 になる。006 は説明のない穴として残る。

**2. 再利用の危険は仮定ではない。006 は既に1度そうなっている。** 記録から確認できる事実を並べる。

- `bfd3b47c`（2026-09-12 04:09:42）が `docs/ADR/adopted/2026-09-12-ADR006-自己名乗りと識別マークの確定/index.md` を追加した。このコミットは `main` に入っている（`git branch --contains` で確認）。
- `f029a85c`（2026-09-13 11:36:03・cycle-312 の全面 revert）が同ファイルを削除した。これも `main` に入っている。
- `44fba187`（2026-09-14 10:08:06）が、空いた番号に別主題の `ADR006 ブログ一覧の記事リンクを静的HTMLへ戻す` を起票した。

結果として、いまリポジトリの中で「ADR006」は2つの別の決定を指している。`docs/cycles/cycle-312/index.md` の359行目は次のリンクを持つが、参照先は存在しない（`ls` で確認）。

> - [ADR006](../../ADR/adopted/2026-09-12-ADR006-自己名乗りと識別マークの確定/index.md): 「よろず屋」を概念語として残す判断と、識別マークの規則。**2サイクル（310・311）を潰した論点**の決着。

`docs/cycles/cycle-312/index.md` の393行目・568行目、`incident-11.md` の25行目、`review-log-docs.md` の44行目も「ADR006」を自己名乗りの決定として参照している。cycle-313 の記録は同じ番号をブログ一覧の是正として参照している。**backlog が「欠番の再利用で ID 衝突が起きる」と書いた事態が、ADR006 では既に起きている。** 削除が通っていれば、006 は2度目の空き番号になっていた。

**3. 「なぜ起票され、なぜ無効と判断されたか」が tree から消える。** 削除後に残ったのは `docs/cycles/cycle-313/index.md` 補足事項の数行と `f3473bf3` のコミットメッセージだけで、どちらも無効と判定した側の要約である。ADR006 本文が持っていたもの——主指標（表示が発生した記事URLの異なり数）、基線の取り方、読み始めと結論の2つの窓、逆行トリップワイヤ、「上がった場合／動かなかった場合／読み取り不能の場合」それぞれの使い道、出荷確認の `curl` 手順、基線取得の SQL、2026-09-14 時点の実測値——は tree から消える。次に同じ領域を触る PM は、この賭けが立てられ無効と判断された事実に、番号でも置き場所でも突き当たらない。

**4. 2026-09-21 の確認は失われた。** ADR006 は「次回確認時にやること」に、T7 の是正が `main` にマージされたかを本番の HTML で確かめる手順を持っていた。キックオフの手順（README 30行目）は `ls docs/ADR/open/` を見るので、ADR006 が open から外れれば 2026-09-21 に開くものは無くなる（`open/` に残るのは ADR001 のみ・次回確認日 2026-10-13）。これは削除に固有の害ではない——expired へ移しても同じである。ただし expired に残っていれば「出荷の確認をする装置を自分で外した」という事実が記録として見える。削除すると、それも見えない。

## `adopted/` へ移したことの問題

README 8行目の定義。

> - `docs/ADR/adopted/YYYY-MM-DD-ADR###-タイトル/` — **確定**（採用され、現在も効力を持つ判断=従うべき先例）。先頭の日付は確定日。観測不要の純粋な決定は起票時からここに置いてよい。

10行目。

> - adopted と expired は参照意味が正反対（従うべき先例／もう従ってはいけない記録）なので混ぜない。

**adopted は「従うべき先例」である。** ADR007 をそこへ置くことは、この決定を後続サイクルが従う前例として登録することを意味する。

記録から確認できる経緯は次のとおり。ADR007 は `1f082786`（13:42:00）で「状態: 実験中（open）」として起票され、「来訪者価値の仮説」「観測手段と評価窓 / 撤退基準」「次回確認時にやること」（4項目）「経過記録」「結果・学び」を持っていた。`f3473bf3`（14:55:51）の adopted 版では、状態行が「確定（adopted）」に変わり、**「観測手段と評価窓 / 撤退基準」「次回確認時にやること」「経過記録」「結果・学び」の4節がすべて削除されている**（`diff` で確認）。

- 8行目の「観測不要の純粋な決定は起票時からここに置いてよい」は**起票時**の条件である。実験として起票したものを、観測できないと分かったあとで観測の節を外して adopted へ置くことは、この条件に当たらない。
- 同じコミットのメッセージで、PM は ADR007 を「仮説を測る計器が無かった」と書いている。**計器を持たない実験を、従うべき先例として置いた。**
- 削除された「経過記録」には起票日と実装コミット3件（`f9526235`・`9b6b9aaf`・`0b538a3e`）が書かれていた。これを外すと、この文書が一度は観測つきの賭けとして登録された事実が adopted 版からは読めない。次にタグの方針を触る PM は、これを最初から観測不要の確定判断として読む。
- `f3473bf3~1` の時点で `docs/ADR/adopted/` は `.gitkeep` のみだった（`git ls-tree` で確認）。cycle-302 が「adopted は現在ゼロ件になった。従うべき先例として残っているものは無い」と記録した状態が続いていた。**ADR007 は、リポジトリで唯一の「従うべき先例」になっていた。**

## 是正

復元と expired への移動は `3c95b383` でコミットした。

- ADR006 を `f3473bf3~1` から原文のまま復元し、状態行を失効に書き換え、「何によって失効したか」と「失効理由」を足して `docs/ADR/expired/2026-09-14-ADR006-ブログ一覧の記事リンクを静的HTMLへ戻す/` に置いた。

- 復元が原文であることを `diff` で確認した。原文との差は、状態行の書き換えと、末尾に足した「失効理由」の節だけである（ADR006: 3行目の置換＋20行の追記／ADR007: 3行目の置換＋31行の追記）。
- 両件の「失効理由」に、削除と `adopted/` への移動が違反であったこと、および本報告へのリンクを書いた。
- ADR006・ADR007 の番号は使用済みとして expired に残る。次に起票する ADR は 008 から採る。
- `docs/cycles/cycle-313/index.md` の補足事項も、削除と書き換えを取り消して2件とも失効として置き直したことを述べている。
