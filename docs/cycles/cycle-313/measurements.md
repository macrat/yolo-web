## 6. 回帰テストが何を捕まえるか

`src/blog/__tests__/blog-frontmatter-validation.test.ts` を記事の作業用コピー（`./tmp/`）に向けて、
1記事だけを壊した状態で走らせた。本物の記事は壊していない。

| 壊し方                                              | 落ちた検査                                     |
| --------------------------------------------------- | ---------------------------------------------- |
| `tags` の値を次の行へ折り返す（今回の欠陥そのもの） | 検査1（書かれ方の一致）・検査2（宙に浮いた行） |
| キーを持たない配列ブロックを混ぜる（今回の残骸）    | 検査1・検査2・検査3（型）                      |
| `published_at`（`+09:00` 形）の引用符を外す         | 検査1・検査3                                   |
| `category` の引用符を外す                           | 検査1                                          |

`published_at` を `+0900` 形で引用符なしにした場合は**検査3が落ちない**（`js-yaml` が文字列のまま読むため）。
検査1だけが捕まえる。現行87記事は `+0900` が35件・`+09:00` が52件なので、
「引用符を落とせば必ず `Date` になる」という前提でテストを書くと35件分が素通りする。
