## 3. いつから届いていなかったか

**測り方**——(1) `git log --follow --name-status fe94f907 -- <path>` で各記事の全リビジョンと、
そのリビジョン時点でのパスを取り出す。`--follow` を付けないと `src/content/blog/` から
`src/blog/content/` へ移る前の履歴が丸ごと欠ける。(2) 各リビジョンの本文を `git show <commit>:<path>` で
取り出し、`fe94f907` 時点の `parseYamlBlock` / `parseYamlScalar` を逐語で移植したスクリプトに掛ける。

## 4. 値の側を直したら2時間27分38秒で戻った

この欠陥は2026年3月に一度診断され、**値の側を書き戻すことで「直され」ている。**
`24bcb80c`（2026-03-27 10:56:46）のコミットメッセージにこうある。

> 指摘1【致命的】: 7記事でtags複数行フロー配列がYAMLパーサーで未対応のためタグが空になっていた問題を修正。複数行フロー配列（`tags:\n  [...]`）をインライン配列形式に変換

§3 と同じ判定条件で、その前後の3リビジョンについて当時の全52記事を走査した。

| 時刻（JST）         | コミット                                        | `tags` が読めない記事 |
| ------------------- | ----------------------------------------------- | --------------------- |
| 2026-03-27 10:41:45 | `24bcb80c~1`                                    | 7                     |
| 2026-03-27 10:56:46 | `24bcb80c` 折り返しをインライン配列へ書き戻す   | 2                     |
| 2026-03-27 13:24:24 | `0630a8a8` cycle-122 カテゴリ再編・シリーズ解体 | 6                     |

書き戻しで5記事が読めるようになり、**2時間27分38秒後、そのうち4記事が元へ戻った。**
`0630a8a8` はカテゴリ名とシリーズを付け替えるコミットで、**52記事の frontmatter を書き換え、記事本文は1文字も触っていない**
（52件すべてについて `---` の後ろを前後で突き合わせ、差分0）。戻した力は Prettier である。

戻り方は手元で完全に再現する。

- 残骸ブロックが `series: "ai-agent-ops"` のような**引用符付きスカラーの直後**にある間、その frontmatter は
  YAML として壊れている（`js-yaml`: `bad indentation of a mapping entry`）。
  **Prettier はこの状態のファイルを整形せず、`--check` も通す。** だから 10:56 に書き戻したインライン配列はそのまま残った。
- `0630a8a8` は同じ記事に `series_order: 5`（平文スカラー）を足した。**残骸が継続行として吸収され、
  frontmatter は YAML として通るようになる。** こうなると Prettier は frontmatter を整形し、
  80桁を超える `tags` の flow 配列を折り返す。折り返された形は、旧パーサが読めない形そのものである。
- この2つの入力に `npx prettier --config .prettierrc --write` を掛けると、前者は無変更、
  後者は `0630a8a8` の実物と**差分1行**になる（残骸ブロックの字下げが4桁から2桁へ変わるところまで一致し、
  唯一違うのは同コミットが意図的に行った `category: "ai-ops"` → `"ai-workflow"` の改名）。

**測る場所に注意が要る。** `.gitignore` は `tmp/*` を無視しており、**Prettier 3 の既定の `--ignore-path` は `.gitignore` を含む**。
そのため `./tmp/` 配下のファイルに `prettier --write` を掛けても**何も実行されず、しかも exit 0 を返す**。
`--check` は無条件に `All matched files use Prettier code style!` と言う。
ここで測ると「走らなかった」を「変化しなかった」と読み違える。**この再現は無視されない場所で行うこと。**

**値を直しても、フォーマッタが次に走ったときに戻る。** 本サイクルが値ではなくパーサの側を直した根拠がここにある。

## 5. `tags` が効いている面

`src/` から `tags` を参照する箇所を機械的に拾い、**props で受け渡す面と同名別物を人手で仕分けた**うえで、
記事の `tags` に行き着くものだけを残した。`src/app/page.tsx` や辞典・遊びの一覧が持つ `tags` は
値札（`Nefuda`）用の別物で、記事の `tags` とは無関係である。

消費箇所は**関数名・定数名で示す**。行番号は前後の編集のたびにずれ、指した先がいつのまにか別の行になる。

| 面                                    | 消費箇所                                                                 |
| ------------------------------------- | ------------------------------------------------------------------------ |
| 記事ページのタグ表示                  | `src/app/blog/[slug]/page.tsx` の `BlogPostPage`（`TagList` へ渡す）     |
| 一覧カードのタグ表示                  | `src/blog/_components/BlogList.tsx` の `BlogList`（`TagList` へ渡す）    |
| タグ一覧ページへの掲載                | `getPostsByTag`（`src/blog/_lib/blog.ts`）                               |
| タグページの生成可否                  | `getAllTags`（同）                                                       |
| `sitemap.xml` のタグURL               | `src/app/sitemap.ts` の `indexableTags`（`MIN_POSTS_FOR_TAG_INDEX = 5`） |
| 関連記事のスコア＝共有タグ数          | `getRelatedPosts` の `sharedTagCount`（`src/blog/_lib/blog.ts`）         |
| 一覧の「人気タグ」算出                | `src/blog/_components/BlogListPanel.tsx` の `tagCounts` / `popularTags`  |
| ブログ内キーワード検索の対象文字列    | `filterPostsByKeyword`（`src/blog/_components/searchFilter.ts`）         |
| RSS / Atom フィードの `category`      | `buildFeed`（`src/lib/feed.ts`）                                         |
| 記事ページの `<meta name="keywords">` | `generateBlogPostMetadata`（`src/lib/seo.ts`）                           |

タグページが生成されるのは掲載3本以上のタグだけで（`MIN_POSTS_FOR_TAG_PAGE = 3`）、
**それに満たないタグは `TagList` が `filter` で落とし、記事ページにも一覧カードにも DOM として出ない**（§14・[B-726](../../backlog.md)）。
そのため**タグを失った記事は、その記事が面から抜けるだけでは済まない**——同じタグを持つ記事が他に無ければ、
タグそのものがサイトから消え、タグページも人気タグもフィードの `<category>` も一緒に失われる。
10の面は互いに独立ではない。

フィードの `<category>` は最新20件が対象で、公開86本のコーパスでは **65 → 70** に増える（本番の `https://yolos.net/feed` は65件・`curl` で実測）。

## 12. JS 無しで機能しないコントロールの扱い

> **この節が扱った「一覧の検索欄」は撤回した（[incident-10.md](./incident-10.md)）。**
> 静的HTMLに検索欄が出るのは T7 の産物だったので、戻した現在は出ない。
> テーマトグルとハンバーガーの実測はそのまま有効である。

サイト内に3通りが同居している。本番の静的HTML（`curl`）と実装の双方で確認した。

| コントロール         | 静的HTMLでの状態                                                 | 見え方                                            |
| -------------------- | ---------------------------------------------------------------- | ------------------------------------------------- |
| テーマトグル         | `disabled` ＋ `aria-hidden="true"` ＋ `tabIndex={-1}` の空ボタン | 箱（52×28px）は残るが中身が空                     |
| ヘッダのハンバーガー | `disabled` も `aria-hidden` も `tabindex` も付かない             | 見た目も Tab 順も生きたまま、押しても何も起きない |
| 一覧の検索欄         | `readOnly` のみ                                                  | 有効時と完全に同一                                |

倣うべき先が無いので、一覧の検索欄（T8b）はこの面自身の条件で決めた。満たすべき条件は3つ——
入力が黙って捨てられる状態を無くす、レイアウトシフトを新たに作らない、支援技術での読み上げが意味の通るものになる。

**`aria-hidden` で消す（あるいは要素ごと出さない）解は採れない。** 検索欄は一覧の中にあり、
消すと入力欄の 44px と前後の gap だけ記事リストが上へ寄って、ハイドレーションで元へ戻る。
来訪者の目の前で一覧が跳ねることになる。テーマトグルが箱を空にできるのは、それがヘッダの中で、
下に何も押し出していないからである。

採った解は `disabled` である。`Input` の `:disabled` は `background` / `color` / `cursor: not-allowed` だけを変え、
箱の寸法に効く宣言を持たない。3つの条件を同時に満たすのはこの形だけだった。
ただし `:disabled` の塗り `--paper-2` と地 `--paper` のコントラスト比は
**ライトで 1.06:1・ダークで 1.08:1**（`globals.css` のトークン値から WCAG の式で算出）で、
塗りの違いだけでは「いま使えない」ことが伝わらない。
そのため、JavaScript が動かない環境でだけ現れる一文を入力欄の直下に置いている。

ハンバーガーは B-695、`readOnly` の見分けがつかない件は B-694 として起票した。

## 15. 記事タイトルの分割不能な連続

6巡目のレビューが「`useSearchParams` はサイトで唯一の13文字以上のラテン語トークン」として、
記事2のタイトルが 360px で横スクロールを生むと指摘した。**この理由づけは誤りである。**
全89記事のタイトルを数えると、14文字以上のトークンは4本ある。

| トークン              | 長さ | 記事                                                     |
| --------------------- | ---- | -------------------------------------------------------- |
| `global-not-found.js` | 19   | Next.js複数root layoutで not-found.tsx が効かない        |
| `Worker.terminate`    | 16   | 50字で215秒フリーズした正規表現を、Worker.terminate()で… |
| `useSearchParams`     | 15   | useSearchParams の Suspense で記事一覧が静的HTMLから…    |
| `mermaid.render`      | 14   | Mermaid ganttチャートのコロンの罠と…                     |

ただし、折り返しどころ（ハイフン・ピリオド）を除いた**連続する英数字だけ**で数え直すと順位が変わる。

| 連続              | 長さ |
| ----------------- | ---- |
| `useSearchParams` | 15   |
| `emulateMedia`    | 12   |
| `frontmatter`     | 11   |
| `JavaScript`      | 10   |

`global-not-found.js` はハイフンとピリオドで4つに割れるため、最長の連続は `found` の5文字にとどまる。
**折れる場所を持たない連続としては `useSearchParams` が site 最長で、2位に3文字の差がある。**
つまり指摘の結論（この記事が最初にこの幅を超える）は成り立つが、
「唯一の長いトークン」という理由づけでは成り立たない。トークンの長さではなく、
トークンの中に折れる場所があるかどうかが効いている。

このサイトは API 名を題に採るため、`generateStaticParams`（20）・`IntersectionObserver`（20）・
`dangerouslySetInnerHTML`（24）のように、折れる場所を持たない、より長い連続は今後も現れる。
タイトルを言い換えて避けるのは1本ぶんの手当てにしかならない。

測定コマンド:

```sh
grep -h "^title:" src/blog/content/*.md | sed 's/^title: *//' | tr -d '"' |
  python3 -c "
import sys,re
rows=[(len(m),m,t) for t in (l.rstrip() for l in sys.stdin)
      for m in [max(re.findall(r'[A-Za-z0-9]+',t) or [''],key=len)]]
rows.sort(reverse=True)
print(*rows[:8],sep='\n')"
```

## 16. タグの分布

サイクル終了時点の、1タグあたりの掲載記事数。タグは37種、母数は全87記事（下書き1本を含む）である。
**このうちページを持つのは掲載3本以上の29種で、残る8種にはページが無い**（`MIN_POSTS_FOR_TAG_PAGE = 3`・§14）。

| タグ           | 記事数 | 全体に占める割合 |
| -------------- | ------ | ---------------- |
| Web開発        | 36     | 41.4%            |
| 設計パターン   | 30     | 34.5%            |
| 失敗と学び     | 30     | 34.5%            |
| AIエージェント | 20     | 23.0%            |
| ワークフロー   | 17     | 19.5%            |
| Next.js        | 17     | 19.5%            |
| SEO            | 15     | 17.2%            |
| UI改善         | 15     | 17.2%            |

掲載1本のタグは5件、2本のタグは3件で、この8件はページを持たず記事ページにも DOM として出ない
（[§14](#14-タグページを持たないタグが読者から隠れていた)・[B-726](../../backlog.md)）。
**両端が離れている。** 最も広い `Web開発` は押しても4割強しか絞れず、
最も狭い8件はそもそも押せる形で読者の前に出ていない。

広い側がカテゴリ軸の言い換えになっていないかも確かめた。`Web開発`（36本）と
カテゴリ `dev-notes`（35本）の重なりは22本で、`Web開発` だけが14本・`dev-notes` だけが13本ある。
**2つの軸は同じ切り方をしていない**ので、広さは軸の重複ではなくタグ自身の粒度に由来する。

この分布は [B-710](../../backlog.md)（掲載の少ないタグページに横へ広がる道が無い）と
[B-711](../../backlog.md)（押せるタグと押せない値札が見分けられない）が先送りしている
「タグページに何を出すか」の判断の入力になる。本サイクルでは判断しない——
GA を参照できないため、どちらの端が実際に読者を困らせているかを測れない（[index.md](./index.md) 補足事項）。
