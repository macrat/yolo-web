## A. 来訪者価値の観点

### [Blocker] A-1: 「このサイクルが完遂したとき来訪者に何が起きるか」が計画のどこにも書かれていない

`docs/cycles/cycle-314/index.md` の完了条件（L42–46）は4件すべてが**文書の内部状態**である。

1. 後貼り・⚠注記・例外・過去 cycle 参照が無い
2. ブランドイメージが site-concept.md に統合されている
3. DESIGN.md の各規定がコンセプトから導かれている
4. `brand-image.md` が恒久文書として存在しない

L72–75 で `src/` は触らないと明示しているため、**来訪者に届くものはゼロ件**である。にもかかわらず、計画本文には「来訪者」という語が、T8 の「全レビューに来訪者価値の観点を渡す」（L33）と、B-685 の説明の中にしか現れない。**この計画が来訪者にとってどういう意味を持つのかを述べた文が一つも無い。**

cycle-311 のキャリーオーバー §5 は「渡すべき問い: **この言葉は来た人にどう見えるか／一言になっているか／そもそも変える必要があったか**」と書いている。T8 はそれをレビュアーに渡すと言うが、**計画自身がその問いに答えていない状態でレビュアーに丸投げしている。** AP-WF02 が cycle-311 に対して「10回のレビューすべてで来訪者価値の観点を渡さなかった」と記録した失敗は、観点をレビュアーに渡すかどうかの問題ではなく、**決定者が来訪者を見ていたかどうか**の問題である。

**要求**: 計画に「本サイクルが来訪者に直接届けるものはゼロである」と明記したうえで、(a) B-651 完了によって解ける具体的な来訪者価値のブロック（B-652 / B-573 / B-663 / B-644 等）を名指しし、(b) **次サイクルで何を来訪者に届けるか**を書くこと。4サイクル連続ゼロという事実は constitution Goal に対する重大な逸脱であり、「P0 だから」だけでは弁明にならない。

### [Blocker] A-2: 選択の論拠が来訪者価値ではなく「作業の心理的性質」になっている（AP-P07 / AP-P25 / AP-P09）

L79–85 の逐語:

> B-685 は機械的で安全な作業、B-651 は言い切りを要求される判断である。
> ここで B-685 を選ぶことは、サイクル選択のレベルで同じ逃避を繰り返すことになる。

**この論法は来訪者を一度も参照していない。** 基準にしているのは「どちらが自分にとって安全か」であり、「どちらが来訪者により高い価値を届けるか」ではない。AP-P25 が要求する「分析を始める前に constitution Goal との整合を最初に問う」を通っていない。

PM の自己点検「この論法自体が正当化として都合よく作られていないか」への回答は **「作られている」** である。理由は、**この論法は符号を反転させても同じ強度で成立する**からである。

- 本計画の版: 「B-685＝機械的で安全 / B-651＝批判されうる判断 → だから B-651」
- 反転版: 「B-651＝`src/` を触らない文書仕事で、失敗しても来訪者は何も失わない＝安全 / B-685＝本番に出て来訪者の目に触れ、壊せば即座に批判される＝危険 → だから B-685」

**反転版のほうが、直近3サイクルの事実（cycle-311・312 は文書のみで `src/` 一文字も変えず、313 は出したものを全撤回）に整合する。** 同じ論法から逆の結論が同じ強度で出る以上、これは優先順位の根拠として機能していない。優先順位は来訪者価値と依存関係で決めるべきで、作業の難度・心理的安全性で決めてはならない。

**要求**: B-651 を先にやる判断自体は**依存関係（B-652・B-573・B-663・B-644 が B-651 完了を着手条件にしている）を根拠にすれば擁護できる。** 論拠をそこへ差し替えること。「逃避の再演になるから」という心理的論拠は削除すること。

### [Major] A-3: 放置する側（B-685）の実害を来訪者価値で評価していない。実害は本番で生きていることを独立に確認した

本レビューで production を直接確認した。

```
$ curl -sS "https://yolos.net/blog/html-tags-cheatsheet" | grep -o 'blog/tag[^"<]*' | sort -u
blog/tag/SEO
blog/tag/Web開発
blog/tag/早見表

$ curl -sS "https://yolos.net/blog/memo-system-rise-and-fall" | grep -o 'blog/tag[^"<]*'
（0件）
```

`src/blog/content/2026-03-16-memo-system-rise-and-fall.md` は frontmatter に5つのタグを宣言しているが、**本番の記事ページにタグ欄が1件も出ていない。** 原因も特定した——prettier が長いインライン配列を

```
tags:
  [
    "AIエージェント",
    ...
  ]
```

の形へ整形するため、`src/lib/markdown.ts` の `parseYamlBlock()` が `value === ""` の後に `/^\s+-\s+(.*)/` のブロック配列しか探さず、`[` 始まりの折り返しを拾えずに `null` を返す。

**これは「40件のリンクが出ない」だけの話ではない。** 当該8記事はタグページの母集団からも落ちるため、来訪者の回遊経路と内部リンクが同時に失われている。しかも原因が prettier の整形である以上、**新しい記事でも再発し続ける。**

計画はこの欠陥を「事実として記録しておく」（L123）と書くだけで、**放置した場合に来訪者が何を失うのかを一行も評価していない。** AP-P27（実害を放置して別作業に着手）に該当する。

**要求**: 見送るなら、見送りの代価を来訪者の言葉で書くこと。そのうえで、`docs/backlog.md` の B-685 を P2 以上へ引き上げ、**次サイクルの着手を計画に明記すること**（現状 P2 で Target Cycle は `-`。3サイクル連続で先送りされている）。
