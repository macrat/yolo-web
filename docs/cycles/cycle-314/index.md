# サイクル-314

**このサイトには、いま信じてよい規範が無い。**

`docs/site-concept.md` と `DESIGN.md` は、どちらも冒頭にこう掲げている——
「⚠️ この文書は信用してはならない（サイクル310で破壊）」。
前者はコンテンツの判断基準、後者は「フロントエンドを作る・レビューするときの唯一の視覚規範」である。
その両方が、自分で自分を無効と宣言したまま置かれている。

結果がどうなったかは、直近3サイクルが示している。**cycle-311 と cycle-312 はどちらもこの B-651 に
着手して成果ゼロで倒れ**（合わせて約76時間・$1,393.69＋約¥89,000）、cycle-313 は別の作業を選んで全撤回された。
判断の拠り所が無いので、**cycle-312 は17件を「規範が決まるまで違反か判定できない」として中止し、
cycle-313 はさらに42件を「B-651 による作り直しで無効」として中止した**（実測・両者は別の集合）。

**本サイクルは B-651（P0）を実施する。** 両文書を、最初からそう書かれていたかのように読める
単一の状態へ作り直す。

### 完了条件（何が届けば達成か）

cycle-312 が定義した8件を引き継ぎ、9件目を足す。**すべて第三者がコマンドで検証できる形にする。**

1. 両文書の冒頭から「この文書は信用してはならない」警告が消えており、**消せる実体がある**（無効・裏取り不能な記述が本文に残っていない）。
2. 両文書に、⚠注記・改訂履歴・過去 cycle への参照・後貼りの例外／特例・経緯の痕跡が **1件も無い**。
   **走査語集合をここで確定する**——`⚠`／`改訂履歴`／`cycle-[0-9]+`／`B-[0-9]+`／`旧称`／`立証済`／`是正済`／`撤回`／`当時`／`docs/cycles/`／`例外の例外`。
   `grep -nE` の出力が空であることを示す。語の網に掛からない型（後付けの強調・弁明）は条件3の対照表で拾う。
3. 両文書の**内部の自己矛盾とツギハギが解消**している——**T2 の処遇対照表 全45件**（site-concept 9行＋DESIGN 36行）について、
   それぞれ「削除／書き換え／保持（理由）」のいずれかが記録されている。
4. **裏取り不能な主張が残っていない**（オーナー帰属・出典不明の数値・実装と食い違う記述）。
   **ここでいう「実装と食い違う」の定義**: 規範が実装の**事実**と矛盾すること（実在しない値を書く・実装が提供しない機能を前提にした規定）。
   **規範が実装に先行している状態は違反ではない**——それを違反と読むと「実装を正として規範を書き換える」ことになり、cycle-312 の失敗の型に戻る。
5. `reference-map.md` 3-A のファイル群が新文書と整合している（**ファイル数は T6 で実測して確定する**。11 は cycle-311 の未検証の数）。
6. `DESIGN.md` の **§1〜§11 の節番号と主題が保存**されており、コード側の §参照（実測1,265箇所・`src/` 261ファイル）が壊れていない。
7. `docs/site-concept.md` が「**来訪者にどう感じてほしいか**」を持っている。
8. `DESIGN.md` の**全規則**が次の3カテゴリのいずれかに分類され、**分類なしが0件**である。
   1. **`docs/site-concept.md` から導出**できる
   2. **外部の一次資料に接地**している（WCAG・iOS の16px・oklch のブラウザ対応・AdSense の要件など、コンセプトからは導けないが外部が決めている規則）
   3. **削除**する
      **「導出元を作るために上流へ加筆した規則」は全件を別表にし、T4 のレビューで個別に問う**——ここが
      「下流を正として上流を書く」への抜け道になるため。
9. **`git diff --stat 967d684 HEAD -- src/` が空である**（射程の境界を宣言でなく機械で担保する）。

**条件6と条件8の両立について。** 2巡目のレビューが「86件の導出元なし規則は、削除すれば条件6違反・上流へ加筆すれば
cycle-312 の失敗の型・放置すれば条件8違反の三すくみ」と指摘した。**これは計画の欠陥だった。**
カテゴリ2（外部一次資料への接地）を認めることで解く——§9（AdSense）・§10（WCAG・iOS 16px）・§2（oklch 対応）は
そもそもコンセプトから導けない種類の規則であり、それを「導出元なし」と数えていたことが三すくみの正体である。
**節番号と主題は保存したまま、各規則に3カテゴリのいずれかを与えることは両立する。**

**なお「118規則単位」は使わない。** cycle-312 の導出検証は**198行版**の `DESIGN.md` に対するもので

### 最小着地セット——「終わらなかったので cycle-315 も B-651」を構造的に禁じる

cycle-311 は10巡、cycle-312 は19巡のレビューを回して何も着地させなかった。
**「まだ欠陥が出ているか」だけを継続条件にすると、無制限に続く。** そこで着地の単位を先に決める。

- **必ず着地させる**: `docs/site-concept.md` **全体**（ツギハギは冒頭に局在しており、上流なのでここが決まらないと下流が決まらない）。
- **§単位で着地させる**: `DESIGN.md` は §ごとにレビューを受け、**通過した § から確定**する。
- **着地しなかった § は、B-651 に戻さず別番号で起票して carryover する。**
  B-651 を丸ごと次サイクルへ送ることはしない——それが3サイクル続いた形である。
- **T4（site-concept.md）がレビューを通過するまで `DESIGN.md` を一文字も編集しない**（関門）。

### 作業内容

**何を信じ、何を疑うか。**

- **地（信じてよい）**: `docs/constitution.md` ／ サイト名 yolos.net の由来＝「YOLO×よろず」の二重の意味 ／ 生の観測データ ／ 外部の一次資料。
- **容疑者（結論の根拠に引かない）**: 現行 `site-concept.md`・`DESIGN.md` の記述、cycle-310 の結論、**現行の実デザイン**。
  とりわけ最後の一つは cycle-312 が倒れた場所である——規範への22件の変更のうち10件が実装の側から導かれていた。
  **実装を正として規範を書き換えない**（`cycle-226.md:209`・86サイクル前から書かれている）。

**進め方の規律。**

- **停止規則**: cycle-311 §7 は「継続可否は巡回数ではなく**まだ欠陥が出ているか**で決める」と申し送った。
  **これだけでは上限が無く、cycle-311（10巡）・cycle-312（19巡）と同じ終わり方になる。** そこで2つを併用する。
  - **質の条件**（cycle-311 の申し送り）: 欠陥が出ているあいだは続ける。Minor と Question だけになったら通過とする。
  - **量の条件**（本サイクルで追加）: 同一対象のレビューが**5巡**を超えたら、そこで**着地の単位を切り下げる**——
    対象を分割して通過した部分を確定し、残りを別番号で起票する。**巡回を続けることでは解決しない。**
- **改稿したら、差分だけでなく前版と現版を並べて確認する**（cycle-311 §7）。指摘箇所を直すたびに書き換えた箇所へ同型が生まれる現象が3版連続した。
- **「すべて」「全件」と書く前に、走査した対象の数を数える**（AP-WF09）。
- **判断から作業へ逃げない。** T4 は ADR006 を読んで追認か反駁かを決めるだけである。**候補の再探索はしない**——同じ半日の判断を3度目に実行することが、まさに逃避にあたる。

**射程の境界。** 触るのは `docs/` と `.claude/` の規範文書だけで、**`src/` は触らない**（完了条件9）。
実装側の是正は B-652・B-573・B-663 等が担う。ただし **T6 で §1〜§11 の節番号と主題を変えれば、
その瞬間にコード側の約1,132箇所の §参照が嘘になり、本サイクルでは直せない。**
規範を整えるためにソースコードへツギハギを1,132箇所作ることになるので、**節構成は保存する**（完了条件6）。

### 検討した他の選択肢と判断理由

**候補は B-685 との1対1ではない。** Queued には来訪者に届く未着手項目が複数あるので、来訪者価値の軸で並べて比較した。

| **B-651**（採用）                                   | 直接はゼロ                             | 大     | ——                                                  |
| B-685 タグ40件が届いていない                        | 8記事がタグ面と回遊に復帰              | 小     | 無関係（ブロックされていない）                      |
| B-573 UI/UX の全面展開（81ページ）                  | 全ページで操作性と読みやすさが揃う     | 特大   | **DESIGN.md を全ページへ焼き付ける**ので B-651 の後 |

**B-632・B-641・B-644 を単独で先にやると、値と組みを `DESIGN.md` から決められない**——その `DESIGN.md` が
「信用してはならない」と自ら掲げているからである。実装側で決めれば、それは cycle-312 が倒れた
「実装を正として規範を書き換える」の入口になる。**B-685 だけが規範と無関係に単独で直せる。**

**それでも B-651 を選ぶ。** 理由は、上の6件のうち5件が `DESIGN.md` の確定を待っており、
**B-651 を通さないかぎり、来訪者に届く作業のほとんどが着手できないか、着手すれば規範を壊すかのどちらかになる**ためである。

- **B-685（8記事のタグ40件が読者に届いていない）を先にやる**: 採らない。**根拠は依存関係である**——
  上表の4件（P1 は B-652 の1件のみ）が B-651 の完了を着手条件にしており、B-685 は何もブロックしていない。
  ただし**見送りの代価は来訪者が払う**: 当該8記事はタグページの母集団から落ちるため、
  タグ欄のリンクだけでなく**回遊経路と内部リンクが同時に失われている**。原因が prettier の整形である以上、
  **新しい記事でも再発し続ける**。本番で生きていることはレビューが `curl` で独立確認した
  （`/blog/memo-system-rise-and-fall` のタグリンク **0本**・frontmatter は5タグ宣言）。
  **次サイクル（315）で着手する**と本計画に明記し、backlog の Target Cycle にも書く。
- **B-651 と B-685 を同時にやる**: 採らない。2件は互いに無関係で、キックオフ手順は「密接に関係していて2つ以上同時にやる必要がある場合に限る」と定めている。
- **T4 で「よろず屋」の候補比較をやり直す**: 採らない。**cycle-312 が実行済みである**——
  ADR006 が候補4案（よろず屋／道具箱／実験室／比喩なし）を「来訪者にとっての分かりやすさと魅力だけ」で比較して
  「よろず屋」据え置きを決定し、レビューも「決定そのものの向きは支持できる」と判定している。
  **失効理由は決定の当否ではなく、決定を載せていた成果物が cycle-312 の全取り消しで消えたこと**と ADR 自身が明記しており、
  **内容は一度も反駁されていない**。3度目の再探索は「判断から作業への逃避」そのものになる。
  T4 は追認か反駁かの判断に絞り、覆すなら根拠は**来訪者の側からの新しい事実**に限る（ADR006 自身の定め）。
- **`npm ci` の失敗（cycle-313 未決事項#2）を直す**: 採らない。**リポジトリの欠陥ではなかった。**
  失敗するのは本実行環境の npm 10.9.7 だけで、CI の Node 24（npm 11）では成功している。
  ローカルでも `npx npm@11.19.1 ci` は通り、`package-lock.json` に変更は要らない。B-736 に起票した。
- **cycle-311 の `concept-decision.md`（第8版）を土台にする**: 採らない。10回のレビューを一度も通過していない。
- **cycle-310 の `brand-image.md` を削除する**: 採らない。完了条件が言う「存在しない」は**恒久文書を作らない**という意味で、
