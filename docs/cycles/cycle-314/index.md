# サイクル-314

**このサイトには、いま信じてよい規範が無い。**

`docs/site-concept.md` と `DESIGN.md` は、どちらも冒頭にこう掲げている——
「⚠️ この文書は信用してはならない（サイクル310で破壊）」。
前者はコンテンツの判断基準、後者は「フロントエンドを作る・レビューするときの唯一の視覚規範」である。
その両方が、自分で自分を無効と宣言したまま置かれている。

結果がどうなったかは、直近3サイクルが示している。cycle-311 は B-651 に着手して成果ゼロで失敗し、
cycle-312 も cycle-313 も来訪者に何も届けられずに終わった。判断の拠り所が無いので、
どの面をどう直すべきかが決まらず、42件の起票が「規範が決まらないと違反か判定できない」として中止された。

**本サイクルは B-651（P0）を実施する。** 両文書を、最初からそう書かれていたかのように読める
単一の状態へ作り直す。

## 作業計画

### 目的

`docs/site-concept.md` と `DESIGN.md` を、**コンセプト → デザインシステム**の導出で整合した
**単一 coherent 状態**にする。完了条件は B-651 の定義どおり:

1. 両文書に、後貼り・⚠注記・例外・特例・過去 cycle への参照・経緯・試行錯誤の跡が**一つも無い**（最初からそう書かれていたかのように読める）。
2. コンセプト＝**ブランドイメージ**（来訪者に持ってほしい印象）が `site-concept.md` の中に**一つの記述として**統合されている（別文書にしない）。
3. `DESIGN.md` の各規定が、コンセプトから**飛躍なく導かれている**。
4. 恒久文書としての `brand-image.md` が存在しない。

### 作業内容

**何を信じ、何を疑うか。**

- **地（信じてよい）**: `docs/constitution.md` ／ サイト名 yolos.net の由来＝「YOLO×よろず」の二重の意味 ／ 生の観測データ ／ 外部の一次資料。
- **容疑者（結論の根拠に引かない）**: 現行 `site-concept.md`・`DESIGN.md` の記述、cycle-310 の結論、現行の実デザイン。これらは本サイクルが正す対象であって、正しさの根拠ではない。過去サイクルの導出は、**その根拠まで遡って再確認できたものだけ**を採る。

**変える範囲は、思っているよりずっと狭い。** 現行の一言は「AIが営む」「やってみる」「よろず屋」の3要素、
来訪者への一言は「読むサイトではなく、やってみるサイト」（cycle-278）。cycle-310 が壊したのは
**周辺の注記と店メタファーの末端**であって、この一言そのものではない。棚卸しが特定したツギハギは
`site-concept.md` で9行、`DESIGN.md` 側の汚染は4箇所に局在する。
**「決め直す」を「白紙から作り直す」と読まない。**

**判断から作業へ逃げない。** T4 は候補を並べて選ぶだけで半日で終わる。cycle-311 はこれを一度もやらず、
代わりに測定値の精度と長文の整合性を10回のレビューで追いかけて失敗した。
候補を並べて選ぶのは批判されうる判断で、測定と検算は安全な作業である。安全なほうへ流れた瞬間に
cycle-311 が再演される。

**コンセプトは決めるものであって、GA4 から導くものではない。** 実測は「誰が来ているか」の接地には
使えるが、「どうありたいか」の答えにはならない。

**コンセプト文書の形**は、一言で言い切る → その一言を支え実現可能にする解釈が続く、というもの。
在庫目録にしない（「◯◯と△△の集まりである」は何があるかの説明であって、どうありたいかではない）。
コンテンツ数・PV・デバイス比は書かない。

**射程の境界。** 本サイクルが触るのは `docs/` と `.claude/` の規範文書だけで、**`src/` は触らない。**
実装側が新しい規範と食い違う場合の是正は B-652（favicon/OGP 等）・B-573（全面展開）・B-663 等が担い、
いずれも B-651 の完了が着手条件である。**ここで実装に手を出すと、規範が固まる前に末端を変えることになり、
cycle-310 の失敗の型（末端を先に変え、後から上流を作って正当化する）を再演する。**

### 検討した他の選択肢と判断理由

- **B-685（frontmatter をサイトのパーサが読めず12記事でタグ／ツールリンクが落ちている）を選ぶ**: 採らない。
  実測で欠陥が**生きている**ことは確認した（下記「計画にあたって参考にした情報」）。しかし cycle-313 は
  まさにこれを P0 より先に選んで失敗し、自らの結論として「**P0 を差し置いて別の作業を選んだことが誤り**」
  と記録している（cycle-313/incident-21.md §7）。さらに cycle-311 は失敗の根を「**単純な判断を避けて
  複雑な作業へ逃げたこと**」と診断した。B-685 は機械的で安全な作業、B-651 は言い切りを要求される判断である。
  ここで B-685 を選ぶことは、サイクル選択のレベルで同じ逃避を繰り返すことになる。
  **B-685 は Queued へ戻し、次サイクル以降の候補として残す。**
- **B-651 と B-685 を同時にやる**: 採らない。2件は互いに無関係で、キックオフ手順は「密接に関係していて
  2つ以上同時にやる必要がある場合に限る」と定めている。範囲を広げることは cycle-313 の失敗の型そのものである。
- **`npm ci` の失敗（cycle-313 未決事項#2）を本サイクルで直す**: 採らない。**リポジトリの欠陥ではなかった。**
  実測の結果、失敗するのは本実行環境の npm 10.9.7（Node 22.22.2）だけで、CI の Node 24（npm 11）では
  成功している（run 1093・現 HEAD `22e820e` で conclusion: success）。ローカルでも `npx npm@11.19.1 ci` は
  成功し、`package-lock.json` に変更は要らない。原因は `vite-tsconfig-paths` に入れ子の `tsconfck` が持つ
  optional peer `typescript: "^5.0.0"` の扱いが npm のメジャー版で異なることで、**出荷にも CI にも影響しない。**
  本サイクルは `npx npm@11.19.1` で依存を導入して作業する。ローカル環境限定の不便として B-736 に起票する。
- **cycle-311 の `concept-decision.md`（第8版）を土台にする**: 採らない。10回のレビューを一度も通過していない。
  参照するなら「何がどう却下されたか」の記録としてのみ扱う。
- **cycle-310 の `brand-image.md` を削除する**: 採らない。完了条件4が言う「存在しないこと」は、
  **恒久文書としてのブランドイメージ別文書を作らない**という意味である（一つの決定は一つの権威ある場所に）。
  `docs/cycles/cycle-310/` 内のそれは失敗の記録であり、消すことは経緯の隠蔽にあたる。恒久文書側（`docs/` 直下）には作らない。

### 計画にあたって参考にした情報

**外部仕様の一次資料確認（本計画が依拠する唯一の外部仕様）**

- WCAG 2.2 SC 1.4.11 Non-text Contrast（https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html ・2026-09-15 確認）:
  要求は「隣接色に対して **3:1 以上**」。ただし**理解に必要でないグラフィック（純粋な装飾・区切り線）は対象外**で、
  「すべてのグラフィックが周囲とコントラストする必要はなく、利用者がそれが伝えている内容を理解するために
  必要なものだけである」と明記されている。
  → **T3 の判定はここで決まる。** `--rule` が単なる装飾の区切りなら 1.52:1 でも違反ではない。
  しかし `DESIGN.md` は同トークンを「**構造の主役**」と呼んでおり、構造の理解を罫に依存させているなら
  「理解に必要」となって 3:1 が掛かり、現状値は不足する。**文書の位置づけか、値か、どちらかが誤っている。**
