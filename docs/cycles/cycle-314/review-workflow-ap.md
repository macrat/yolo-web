### C2. アンチパターン集に、本サイクルの発生記録が1件も無い（CLAUDE.md「Check anti-patterns on failure」違反）

番号追記の前に、各型について「本サイクルのどの記述・どの操作が該当するか」を1行で特定すること
（特定せずに番号だけ足すのは AP-WF09 そのものになる）。

- `incident-2.md` §2(d): 「**それでも開いたのは、そこに「もう決まっている」と書いてあったからである。**」

constitution の Goal）が併記されていないため、次のPMには「Owner が言ったからやる」構図に読める。

### m2. `incident-2.md` の節番号が 3 → 5 → 4 の順に並んでいる

`## 3. 何が壊れたか` → `## 5. アンチパターン集の点検` → `## 4. 次のわたしへ` の順で並ぶ。

### m3. キャリーオーバー #3 の根拠が、文字どおりには不正確

再利用を禁じる項目は存在しない」と書けば同じ結論が壊れずに残る。

### m4. B-740 は着手条件付きなのに Queued（すぐに着手できる）にある

### m7. T3 の禁止が、外部規範まで封じたように読める
