## 5. 判定

### C. 引き継ぎは機能するか

**部分的にしか機能しない。**

**機能している部分**（これらは価値が高い。是正で壊さないこと）:

- Owner の指示の逐語提示と「やること」5項目。何をすべきかは一意に読める。
- 「やってはいけないこと」表の左右対照。**本サイクルが実際に何をしたか**が並記されているので、抽象的な訓戒になっていない。
- `DESIGN.md` の逆算禁止と WCAG の切り分け（L59-64）。m7 の是正が効いており、アクセシビリティ要件ごと落とす危険は消えた。
- 「ただし2択に狭めないこと」（L76-78）。**次のPMの選択肢を先に畳まない**という姿勢が明文化された。M5 の是正は成功している。

**誤らせる危険が残っている部分**:

1. **B-685 が見えない**（M-1）。「次のPMへ」だけを読むと、来訪者に届いていない欠陥の存在を知らないまま `site-concept.md` に向かう。
2. **「それだけを読む」「リポジトリを探索する＝禁止」が、義務づけられた実体確認まで止めうる**（M-5）。
   本サイクル自身が、その義務を怠った結果として C-1・M-4 を生んでいる。
3. **backlog の件数が信用できない**（C-1）。正本が「5件」と断言する一方で7件ある状態は、
   次のPMに「消すべきか残すべきか」の余計な判断を強いる。
4. **`t2a-site-concept.md` が無印**（C-3）。`site-concept.md` を扱う次のPMが、同名の表を検索で引き当てる可能性が高い。

### D. 失敗クローズとして閉じてよいか

**閉じてはならない。** 残っている理由は次の4点である（いずれも Critical / Major）。

1. **正本が事実に反する数を断言している**（C-1）。完了チェックリストの `[x]` が偽であることは AP-WF23 が
   「完了状態の捏造」と定義する状態であり、**失敗サイクルの記録としてすら正確でない**。
2. **本サイクルが踏んだ型のうち AP-WF27 が記録から漏れ、`---` 行の破損を引き継いだ**（C-2）。
   C2 の目的（次のサイクルから型が見えるようにする）が、M1 が指摘した当の型について達成されていない。
3. **「次のPMへ」に B-685 が無い**（M-1）。1巡目 M4 の是正指示に対する不適合であり、
   来訪者に届いていない欠陥が担当者不在のまま次サイクルへ渡る。
4. **無効の警告が2ファイルに無く、M8 の処遇が空白**（C-3・M-3）。
   incident-1 が中心の事故と認定した構造が、縮小した形で残っている。

いずれも `docs/` 内の記述の修正で閉じられる範囲であり、`src/`・成果物の作り直しは不要である。
**14件を是正したうえで、`cycle-completion` の手順を最初からやり直すこと。**
そのとき `completed_at` を取り直し（m-4）、`git diff 22e820e HEAD -- docs/backlog.md` を**書く直前に実行**して数を確定すること（C-1）。
