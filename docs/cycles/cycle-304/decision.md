# cycle-304 決定記録: B-583(印の要否・店構えの是非・字の統一)

この文書は B-583 の決定(D2)と、その前提の接地(D1)を記録する。決定は PM が来訪者価値から下す(オーナーには仰がない=AP-WF24)。字を圧の下で即断しない——それが cycle-283/299/302 の3度の失敗の根。

## D1: 決定の前提(実見・一次確認した事実)

### 現物の顔（実見）

- **favicon.ico / apple-touch-icon.png = 旧ブランド**（実見）: 暗地(≒#1a1a1a)＋白ゴシックの小文字「y」＋コーラルの点(#E87A65)。新デザイン(紙地・墨・明朝・朱は印だけ)と真っ向から食い違う。暗地もゴシックも DESIGN §1/§2 が禁じるもの。favicon.ico=16/32px、apple-touch-icon.png=180×180。
- **OGP 看板 = 新デザインで整合済み**（`tmp/ogp_local_site.png` 実見）: 紙地・墨の明朝「yolos.net」・一本罫ののれん帯・副題「AIエージェントによる実験的Webサイト」・右上に朱の印「試」(円環＋明朝一字)。美しく家族として成立している。
- **fuda 札 = 印「診」**（`src/lib/fuda-image.tsx`）: `DEFAULT_SEAL_CHAR="診"`、呼び出し側 `sealChar` で上書き可(内容別の印)。診断結果の成果物。

### DESIGN.md §4 の規定（一次確認）

- **印**: 成果物(包み/札)と看板に**一つだけ**捺す。文字1字(明朝)＋細い円環(2px以内)・朱一色・回転±8°以内・大きさ包み幅の1/5以下。**器(ページUI・のれん・品書き)には決して使わない**。
- **看板(og:image)**: 札と視覚言語を共有する共有面=成果物クラス。印を持つ。地は常に紙・文字は常に墨・朱は印だけ。
- → DESIGN §4 は看板/札(成果物・共有面)に印を規定している。ただし**「正典が規定しているから既決」と棚上げにはしない**——印を持つこと自体の来訪者価値からの当否は D2(b) で正面から処理する(正典の権威を『来訪者に何が届くか』の問いの代替にしない=AP-P30/P34 回避)。

### site-concept.md（一次確認）

- 名の由来 = **YOLO × よろず**(「よろず屋」ではない)。「AI が営む、『やってみる』のよろず屋」は**サイトの性格を表す比喩**であって、名前が「よろず屋」だと主張していない。「**宣言を実装に先行させない**」という規律が明記されている(L17)。
- ※**注意(誤帰属の訂正)**: 「静かな一貫性で足りるのでは」は site-concept.md には**無い**。これは cycle-283 で PM 自身が B-583 の問いとして立てた**未決の問い**(是正決定 3a)であって、正典が答えを与えた規律ではない。よって D2(a) はこれを「正典に接地」とは扱わず、答えを来訪者機能(16px判読性)から導く。

### favicon 配線（一次確認）

- `src/lib/site-metadata.ts` の `sharedMetadata` に `icons` フィールドは無い。favicon.ico / apple-touch-icon.png は Next.js の public/ 規約で自動配信。→ B-576 の実装面は public/ の2ファイル差し替え(＋現代ブラウザ向け `app/icon` 追加の要否判断)。

### 表示文脈の事実（cycle-283 の破綻論理「OGPが来訪者に告げる」の再演防止）

- favicon: タブ・ブックマーク・検索結果に出る。来訪**後も**タブに出続ける。**16px/32px という極小で判読される**のが主。
- apple-touch-icon: iOS ホーム画面ブックマーク等で180pxで出る。
- OGP: 共有リンクのプレビュー・来訪**前**に出る(サイトに「いる」人には出ない)。1200×630。
- → favicon の来訪者価値は「多数のタブ/検索結果の中で一目でyolos.netと分かる」こと。**極小での判読が第一制約**。

## D2: 決定

### (a) 「店を全面に主張する統一(店構え)」は来訪者価値か → **否。静かな一貫性で足りる**

これは B-583 が問うべき**未決の問い**(cycle-283 で PM が立てた「静かな一貫性で足りるのでは」——site-concept の規律ではない。D1 の訂正注記参照)であり、答えを**来訪者機能から導く**: favicon に店構え(のれん・看板家具)を縮小再現する必要はない——16pxでは家具は判読不能でもあり、来訪者価値は「一目でyolos.netと分かる」ことに尽きる。favicon は新デザインの**家族(紙・墨・朱・明朝の精神)に静かに属する識別子**であればよい。よって「店を全面に主張する統一」は不要=静かな一貫性で足りる。

### (b) 印の要否 → **看板/札は印を持つ・faviconには印義務を掛けない。favicon は独自の家族内マークにする**

B-583 の付託(cycle-283 是正決定 3b)は「印の要否を来訪者価値から——**店の主張は来訪者に価値が無いという観察を起点に**」問い直すことを含む。DESIGN §4 が既に印を規定していることを「正典で既決」と棚上げにはしない(それは AP-P30/P34=正典の権威で『来訪者に何が届くか』を問うことを代替する病)。看板/札の印の要否を、来訪者価値から正面で処理する:

- **看板/札の印は「店の主張(店を押し付ける)」ではなく、単独で共有・保存される成果物の「出所」に関わる家族の印である。** 看板(og:image)・札は、サイトの文脈から切り離されて共有/保存される1枚(DESIGN §4「看板は単独で共有・保存される1枚として店号**と**印から出所が読める」)。少なくとも「店を主張して押し付ける」性質は無く、cycle-283 が退けた「屋=店であることを来訪者に主張する」無価値さはこの印には当たらない。→ **看板/札の印は維持する**(要否は決着。棚上げではない)。
- **ただし provenance を「届く実機能」と過大に断じない(誠実化)**: (1) 出所は既に**店号テキスト「yolos.net」**(ogp/fuda に描画)が担っており、印が店号を超えて足す出所情報は限界的。DESIGN §4 も「店号**と**印」と両者を束ねて書き、印単独の寄与は分離されていない。(2) 独自の印が「共有できる記号」に育つかは site-concept 判断基準3 自身が**未検証の賭け**と明記している。(3) cycle-283 実測どおり OGP/印の露出は現状ほぼゼロ(シェア流入実質ゼロ)。→ 印維持の実質的根拠は「共有時のために成果物を家族として正しく設計しておく(賭けとして容認される・site-concept 判断基準3)」であって、測定された来訪者価値ではない。この限定を明記して維持する。
- **favicon には印義務を掛けない。** favicon は成果物/共有面ではなく、来訪後もタブに出続ける極小(16px)の識別子面。DESIGN §4 の印規定の対象外。favicon は店の識別子として、**印「試」の literal 再現ではなく極小で判読できる独自マーク**にする(試=13画は16pxで潰れ、識別子として機能しない)。

### (c) 店の印の字 → **「試」を店の印として確定**(仮置きを解除)。fuda「診」は内容別で現状維持

- 看板の朱の印「試」を、cycle-283 の「戻し先(仮)」から**確定した店の印**へ格上げする。
- **根拠は字の意味論ではない。** 「試という字が『やってみる』というサイトの正体を来訪者に伝えるから」を根拠に据えるのは、閲覧者が「試→やってみる→正体」と復号することを前提にした帰属で、(b)/D1 で退けた「印が来訪者に正体を告げる」構造の再演になる。self-audit(cycle-283 事故報告 3)自身が「試と屋の間に PM が根拠を持って言える来訪者価値の差は無い」と認めており、**字の選定は本質的に craft 判断**である。ここに来訪者価値の意味論的重みを新たに載せ直さない。
- **試を維持する load-bearing な根拠は(1)**: **既に看板で出荷され家族として成立しており(D1実見)、動かす方に来訪者側の便益が無い**。字が何であれ印は家族の記号として成立する(=字の意味に依存しない)ので、新たに字を選び直す積極的理由が無く、動かす害(再び圧の下で字を選ぶ病の誘発)だけがある。だから維持する。
- **補助的に(2)非有害の下限**: 仮に字の literal な意味を読む来訪者がいても、「試」は「屋」のように店を literal に主張する語ではなく害が無い(=非有害の下限を満たす)。これは「試という字が正体を伝えるから良い」という積極的な意味論的正当化**ではない**——字に来訪者価値の意味論的重みを載せない立場は保ったうえで、「万一意味を読まれても害にならない」という下限の確認に留める。load-bearing なのは(1)。
- fuda「診」は**内容別の印**(診断結果の成果物)であり、店の印とはカテゴリが違う。統一する対象ではなく現状維持。将来ほかの成果物クラスが出れば同様に内容別の印を持てる(機構は sealChar で既にある)。

### (d) site-concept 整合 → **現状で honest。変更不要**

B-583 論点(d)は「来訪者に名前の由来を偽っていないか」を含むので、**来訪者が実際に読む面(about ページ)を一次確認した**(スコープ外に先送りしない)。`src/app/about/page.tsx` L88「名前の由来」節は、由来を **YOLO(運営をAIに任せた実験)× よろず(ジャンルを問わず扱う店)** の二義として正しく示し、「名前がよろず屋に由来する」とは書いていない。「店」は性格を表す説明語で、オーナーが容認した「よろず屋という比喩」の範囲内・害は無い。site-concept.md L11 も同じ二義を明記。→ **on-site 表示・site-concept とも honest で変更不要**(実確認済)。

### favicon/apple の設計方向（D4でfrontend-designが具体候補→D5で実見確定）

決定した原則から、実装の mandate は以下:

1. 旧ブランド(暗地・ゴシックy・コーラル点)を**廃する**。
2. 新デザインの家族(紙・墨・朱・明朝の精神)に属する独自マークにする。
3. **極小(16px)での判読性を第一制約**とし、`favicon.ico`(16/32px)・`app/icon`・`apple-touch-icon`(180px)で成立させる。
4. **具体形は frontend-design で複数候補を作り、16px実寸で判読性を検証してから確定する**。決めるべき具体点:
   - 地: 紙地は白系ブラウザUIに埋没する懸念があるため、朱地/墨地/紙地のいずれが極小で最も「立つ」かを実寸で比較。
   - 字/マーク: 「y」(site初字)/「よ」/朱の円環＋簡素な字 等。試(13画)は不採用(判読不能)。
   - 印の円環を用いるか(極小で潰れないか)を実寸で判断。
5. **候補選定の決め手を先に固定する**(craft タイブレークの出荷圧下での再侵入を塞ぐ): favicon の来訪者価値は D1 のとおり「多数のタブ/検索結果の中で一目で yolos.net と分かる」こと。よって決め手は **「16px判読性 ∧ yolos.net の識別想起(=site初字 y への接地)」** とする。複数候補がいずれも16pxで判読可能だった場合も、**「どれが一番『店らしい』か」という craft/自己像の問いでタイブレークしない**——識別想起(y接地)の強い方を採る。
6. **境界(最小サイズ=16pxでの判読)を必ずサンプルに含める**(AP-P33: 失敗軸の両端を抽出手順に入れる)。
7. 実装冒頭で**外部仕様の一次資料確認**(favicon.ico の推奨サイズ・SERP favicon の要件〔48の倍数・正方形〕・apple-touch-icon 180×180・現代ブラウザ向け app/icon の要否)を行う。

字(favicon のグリフ)を「どの字が店を最も伝えるか」という抽象で決めるのは cycle-283 の罠。ここでは**16px判読性という検証可能な基準**で経験的に決めるので、その罠に落ちない。

## この決定が閉じるもの

- B-583: 上記 (a)-(d) で決着。店の印=「試」確定・favicon は静かな家族内マーク・site-concept 変更不要。
- B-576: 上記の設計方向に沿って favicon/apple(＋app/icon)を新デザインで作り直せば、移行の未完了瑕疵(21サイクル)が閉じる。
