# 回答フェーズの可視性 実測ログ（cycle-301 A1・2026-07-30）

対象: 本番 `https://yolos.net/play/character-personality` の回答フェーズ（playing フェーズ）。

**なぜ再実測したか**: cycle-300 は同じ計測を一度 `375×812`（端末画面高）で行い「全選択肢が第一ビューに収まる」と結論し、後から `375×635` で測り直して撤回している（cycle-300/observation §7）。前サイクルの数値を土台にすると同じ誤りを継承しうるため、cycle-301 では**独立に取り直した**。

## 方法

- Playwright MCP。`browser_resize` で viewport を設定 → 本番を開く → GA 送出を無効化 → 「はじめる」→ 各設問で `browser_evaluate` により `getBoundingClientRect()` を数値取得。
- 可視性の判定基準: 要素の `bottom <= innerHeight` なら完全可視、`top < innerHeight < bottom` なら途中で切れる、`top >= innerHeight` なら完全に fold 下。
- `375×635` は「端末画面高 812 からブラウザ UI を差し引いた保守的な実可視高」の想定値。`375×550` は小型端末の Safari 相当。

### 本番 GA4 への注入（正直に記録する）

- 手段: `window.gtag = () => {}` と `window.dataLayer.push = () => 0` へ差し替え。
- **注入されたもの: `page_view` 1件**。ページ読込と同時に gtag.js が初期 `page_view` を送出するため、ページ内 JS 実行（evaluate）でしか介入できない今回の手段では抑止できなかった。
- それ以降の操作（はじめる・全10回の選択肢クリック・375×550 へのリサイズ）では `google-analytics.com/collect` へのリクエストは**新たに発生していない**（`browser_network_requests` で全操作の前後を照合）。
- `375×550` の計測はページ再読込を避け、既存セッションを `browser_resize` するだけで取得した（再読込による `page_view` 追加送出を防ぐため）。

→ **cycle-300 の 375×635 の報告は再現した**（導入ブロック高さのみ 176→175.5px の僅差）。

## 結果3: 設問より上を占める要素のうち、回答中に機能を持たないもの

| 要素                                        | rect                    | 実テキスト                                                                                                                                                                                                                                              | 回答中の機能                                     |
| ------------------------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| パンくず `nav[aria-label="パンくずリスト"]` | top=73, height=21       | 「ホーム / 遊ぶ / あなたに似たキャラ診断」                                                                                                                                                                                                              | **なし**（ナビゲーションリンクのみ）             |
| h1                                          | top=110, height=24.6    | 「あなたに似たキャラ診断」                                                                                                                                                                                                                              | **なし**（静的なタイトル表示）                   |
| 説明文                                      | top=138.6, height=146.9 | 「12個の日常シチュエーションに答えて、あなたの性格に最もよく似たキャラクターを判定します。『締切3分前に5手先を読む炎の策士』や『夢の中で3本の論文を書き終えた学術夢想家』など、24タイプのキャラクターから1つが決まります。友達との相性診断もできます!」 | **なし**（診断開始前の紹介文）                   |
| 進捗表示                                    | top=310.4, height=6     | `11/12` ＋ `role="progressbar"`                                                                                                                                                                                                                         | **あり**（現在位置を示す。退かせる対象ではない） |

上3要素の合計占有高（内部余白を含む）: `bottom(285.5) − top(73)` = **212.5px**。

**実装の意図との食い違い**: `QuizPlayPageLayout.tsx:115` のコメントは「コンパクトな h1 + 短説明（**ファーストビューを占有しない**）」と書いている。しかし 375px 幅では `.shortDescription`（`font-size: 0.9rem`・`line-height: 1.7`）が4行に折り返して 146.9px になり、意図と実体が食い違っている。CSS には幅に応じた出し分けがない（`.header` は `display:flex; flex-direction:column; gap:0.25rem` のみ）。
