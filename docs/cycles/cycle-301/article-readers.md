## 誰が読みに来るか

**主読者: React でフォームやウィザードを書いていて、二重送信ガードを「入れたつもり」でいる開発者。**

検索で来るとしたら「react 二重送信 防止」「二重クリック 防止 useRef」あたり。この語で検索する人は、すでに `if (submitting) return` か `useRef` のロックを書き終えていて、テストも緑になっている。つまり「解き方を知りたい」のではなく「これで足りているのかを確かめたい」状態にある。だから記事の冒頭は解説ではなく、その人が立っている場所（送信ボタンにガードを置いた、テストが緑になった）の描写から入れた。

この読者にとっての持ち帰りは3つ。ガードのフラグが立たない分岐がありうること、マウント単位の ref は別タスクの2打目に原理的に届かないこと、jsdom は「発見」はできないが「回帰」は守れること。3つとも自分のコードベースで今日確かめられる形にした。

**副読者: 当サイトの診断で遊んだことがある人。**

この記事は「あなたが受けた結果は1件足りない回答から出ていたかもしれない」を含む。技術記事として書きつつ、この人が読み落とさない位置に「修正は出荷済み」と「受け直せば正しく数えられる」を置く必要がある（憲法 Rule 2 と Rule 3 の両方が要求する）。実害を述べた §1 の末尾に置いた。
