## Blocker

### BL-1. 中身の色に前景を選ぶ手続き（§2 L78）が、実在の色で成立しない

§2 L78:

> 色の上に文字や線を置くときは、**その色の輝度から前景（`--paper` か `--ink`）を選び、文字は 4.5:1、線と枠は 3:1 を満たす**。

**この手続きは、`--paper` と `--ink` の2択である限り、中間輝度の色に対して 4.5:1 を返せない。** 実計算:

| テーマ | 前景2択で到達できる最大比の最小値 | 4.5:1 に届かない中身色の輝度帯 |
| ------ | --------------------------------- | ------------------------------ |
| light  | **4.372**                         | Y = 0.1767〜0.1902             |
| dark   | **4.152**                         | Y = 0.1639〜0.2012             |

（light は `--paper` Y=0.9703 / `--ink` Y=0.003375、dark は `--paper` Y=0.005832 / `--ink` Y=0.912673 で、2つの比が交差する点が最小値になる。）

**この帯は机上の話ではない。** このサイトが実際に扱う伝統色で検算した:

| 色   | hex       | Y      | light paper/ink | dark paper/ink                  |
| ---- | --------- | ------ | --------------- | ------------------------------- |
| 灰色 | `#7B7B7B` | 0.1981 | 4.11 / 4.65 ✓   | **4.44 / 3.88 — 両方 4.5 未満** |
| 鈍色 | `#727171` | 0.1658 | 4.73 / 4.04 ✓   | **3.87 / 4.46 — 両方 4.5 未満** |
| 素鼠 | `#7C7C80` | 0.2026 | 4.04 / 4.73 ✓   | 4.52 / 3.81（辛うじて）         |

ダークテーマで **灰色・鈍色の見本に色名を載せると、どちらの前景を選んでも §14 L263（文字 4.5:1 以上）に落ちる。**
§2 L76 が「**色の範囲を制限しない**」と明記している以上、この帯を避ける逃げ道は文書に無い。手続き自体が、自分の品質バーを満たせない場合を持っている。

（`線と枠` の 3:1 は最小値 4.15 なので常に満たせる。落ちるのは文字の 4.5:1 だけである。）
**解は文書が決めること**だが、成立する形は「色の上に文字を置かない（見本の外に置く）」「見本に `--rule-w` の枠を回して文字は枠外」「前景の2択に無彩の第3値を足す」のいずれかになる。現状は、**実装者が伝統色の一覧を作った時点で必ず詰まる。**

### BL-2. §5「格子」の規定が、3箇所で自分および他節と矛盾している——1巡目 BL-3 と同じ型の再発

**(a) 「それ以外に主罫を引かない」が、§6・§8・§12 に破られている。**

§5 L121:

> **主罫が入る場所は決まっている**——上端の下・下端の上・節と節のあいだ・結果の区画の四辺・一覧の外枠。**それ以外に主罫を引かない。**

§5 L113 の太さトークン表も、`--rule-w` の使う場所を同じ5箇所に限っている。ところが `--rule-w` の主罫は、この5箇所の外に4種類ある。

| 場所                     | 出典                                               |
| ------------------------ | -------------------------------------------------- |
| 主操作・副操作のボタン枠 | §6 L145・L146「`--rule-w` の罫」                   |
| hover のオフセット罫     | §6 L147「罫の外側に 3px のオフセット罫が増える」   |
| 現在地の左端の縦罫       | §6 L148「左端に `--rule-w` の縦罫」                |
| フォーカスの外側リング   | §6 L151「外側 3px `--ink`」                        |
| 広告区画の罫             | §12 L235「`--paper-2` の区画 ＋ 罫」（太さ未指定） |

**「それ以外に引かない」という禁止の形で書かれているため、読み替えの余地が無い。** 実装者は §5 と §6 のどちらかを無視するしかない。

**(b) 「横罫は内容の幅で切らない」が、同じ節の次の行と衝突している。**

§5 L120:

> **横罫は画面の左端から右端まで届かせる。** 内容の幅で切らない。これが格子を成立させる。

L121 が主罫の場所に挙げる「**結果の区画の四辺**」「**一覧の外枠**」は、定義上、内容の幅で閉じた箱である。その上辺と下辺は横罫であり、必ず内容の幅で切れる。
**隣り合う2行が、同じ罫について反対のことを言っている。** しかも L120 は「これが格子を成立させる」と、担い手1の成立根拠をこの一文に置いている。

**(c) 「縦の基準線は全ページで同じ位置」が、同じ節の骨格表と衝突している。**

§5 L122:

> **縦の基準線は全ページで同じ位置**。内容の左端を `--gutter`（狭い画面 16px・広い画面では中央寄せした枠の左端）に揃える。

§5 L135:

> 読む面は `--measure` に絞る。操作面は `--max-width: 960px` まで。

`--measure` = 640px、`--max-width` = 960px。**1440px の画面では、読む面の左端は x=400、操作面の左端は x=240 で、160px ずれる。** 「全ページで同じ位置」は成立しない。
`--gutter` の広い画面での値が「中央寄せした枠の左端」という相対指定なのに、その枠が2種類あるため、**トークンの値が定まらない。**

1巡目 BL-3 の講評は「**部分修正が新しい矛盾を生んだ**」だった。**色の置き場所（BL-3 の当のもの）は今回きれいに解けている**（(C) 参照）。**同じ型が、今度は §5 の格子に移って再発している。**

### BL-3. 「二重の罫／リング」が3つの意味を持ち、§6 が自分で課した規則に違反している

§6 L140 は節の冒頭で規則を宣言している。

> **役割ごとに別の記号を割り当てる。** 一つの記号が二つの意味を持たないこと。

同じ文書に、外側に線が1本増える記号が3つある。

| 記号                                                   | 意味             | 出典    |
| ------------------------------------------------------ | ---------------- | ------- |
| 罫の外側に 3px のオフセット罫（二重罫）                | hover / active   | §6 L147 |
| **二重リング**（内側 2px `--paper`・外側 3px `--ink`） | フォーカス       | §6 L151 |
| **罫を二重にする**                                     | 入力エラーの位置 | §8 L197 |

**帰結1——hover とフォーカスが同じ見え方になりうる。** 二重リングは `--paper` 地の面では内側の 2px が地に溶けるので、利用者に見えるのは「3px の隙間 ＋ 3px の `--ink` の線」である。hover の二重罫も「オフセット ＋ 3px の罫」で、**オフセットの量が文書のどこにも書かれていない。** 3px にすれば完全に同じ絵になる。キーボード利用者は、フォーカスがどこにあるかをポインタの通過跡と区別できない。

**帰結2——入力エラーが hover と同じ記号になる。** §8 L197 は「**色で示さない**」と決めた代わりに二重罫を割り当てたが、その二重罫は §6 が hover に割り当て済みである。エラーのある入力欄にカーソルを乗せると、エラーの記号と hover の記号が重なって、どちらでもなくなる。

**この3つは §6 L140 が禁じた「一つの記号が二つの意味を持つ」の実例である。** 規則を掲げた節が、その節と隣の節で規則を破っている。

### BL-4. §1 の自己点検が、構造上けっして失敗しない——条件1を担保する仕組みが文書に無い

§1 L41:

> **上端と下端の共通部分を除いて**、各画面に担い手1〜3 のうち**2つ以上**が現れること。

1巡目の指摘（BL-5 末尾）を受けて「上端と下端を除く」が足されたが、**点検はまだ失敗できない。**

- **担い手2（巨大な明朝の見出し）は、§4 L101 が全ページに義務づけている。** 「各面の主見出しの下限は——画面幅 320px で 32px・1024px 以上で 47px」。主見出しは上端ではなく本文にあるので、除外に当たらない。**主見出しの無い面を作ることは §4 が許していない。**
- **担い手3（操作を色で示さない）は、§13-2 が全ページに義務づけている。** これは不作為で満たされる性質なので、**違反しない限り必ず「現れて」いる。**

したがって、操作が1つでもある面は担い手2と3で自動的に2つに達する。**「現れないなら、その画面は yolos.net に見えていない」という判定は、定義上一度も発火しない。**

**条件1（デザインだけで yolos.net だと分かる）を検査する仕組みは、この文書にこの1つしかない。** それが空回りしている以上、**条件1は文書の中で担保されていない。**
点検が働く形にするには、担い手1に固有の観測可能な事実（例: 上端・下端を除いて全幅の主罫が1本以上あること、縦罫が基準線に立っていること）を条件に据えるか、担い手2に既定を超える閾値（例: 主見出しが画面幅の何割を占めるか）を置く必要がある。**「2つ以上」という数え方のままでは、何を足しても数は勝手に埋まる。**

### MJ-1. 担い手1の「格子」に、縦の規定が1件も無い——宣言だけで実体がない（(D) の名指し1）

§1 L29 は担い手1を「**端まで届く太い罫の格子**」と呼び、§5 の題も「**構造——罫の格子**」である。
**§5 が定める罫は、すべて横罫である。** L120（横罫は全幅）・L121（主罫の場所5つ＝すべて横方向の区切りか箱の輪郭）・L114（細罫＝行の区切り・表の内部）。

**縦罫の規定はゼロである。** L122 の「縦の基準線」は**揃える位置**であって、線を引く規定ではない。列の分割数も、どの列に線が立つかも書かれていない。
この文書に完全に従って作れる画面は、**全幅の横帯が積み重なった縦一列の面**である。それは「格子」ではなく「罫線で区切った段組み無しのページ」で、editorial 系のテンプレートに広く存在する顔である。

**「格子」という語が、規定の実体より強い。** どちらかを直す必要がある——縦罫の規定（何列に割るか・どこに立てるか・`--rule-w` と `--rule-w-hair` のどちらか）を書くか、担い手1の名を実体（「端まで届く太い横罫」）に合わせるか。
`design-center-options.md` の案F が中心に据えたのは「格子」のほうなので、**落とすなら選定の根拠が1つ減ることになる。**

### MJ-2. 担い手2の書体が決まっていない。3候補は個性の強さが大きく違う（(D) の名指し2）

§3 L85:

> 源ノ明朝（Source Han Serif）／Noto Serif JP／しっぽり明朝から実装時に1つ選ぶ

1巡目から候補の列挙まで戻ったが、**決まっていない。** L3 は「**値はここが出どころで、コードのトークンはここから生成する**」と宣言しているので、決まっていない値がここにあること自体が宣言と食い違う（MN-7 も同じ形）。

**それ以上に、この3つは「どれでもよい」関係にない。**

- 源ノ明朝と Noto Serif JP は**同一の書体**（Adobe と Google の別名）である。候補として2つ数えているが、選択肢は実質2つしかない。
- Noto Serif JP は、Google Fonts で日本語明朝として最も広く使われている書体である。**これを選ぶと、担い手2は「よそでも見る顔」になる。** §1 L30 が担い手2に与えた理由は「**既定 sans では作れない顔。書体そのものが器の個性を担う**」だが、その理由は「既定 sans と違う」までしか保証しておらず、**「他の明朝サイトと違う」は保証していない。**
- しっぽり明朝は字面が明らかに異なる。**選択の結果として、個性の強さが大きく変わる。**

**担い手2が条件1を担うなら、どれを選ぶかは実装時の裁量ではなく、この文書の決定事項である。** 本文・UI がシステムゴシックである以上、画面の文字の大半は既定の顔で出る。**個性は見出しの書体1つに集中している。** その1つが未定なのは、担い手2の実体が無いということである。

### MJ-3. 数字用の第3書体が、§3・§13 と正面から衝突する（1巡目 MN-7 が未解消・悪化）

§3 L87:

> | 数字 | **tabular 数字を持つ書体1つ**。数字と単位記号だけをサブセット |

同じ §3 の L93:

> 本文にモノスペースを使わない。**見出しの一部だけ書体を切り替えない。**

§13-9（L252）:

**§8 L204 は「数字は tabular で桁を揃え、大きく」と定めている。** 結果の数字は見出し級の大きさで出る。そこに数字専用書体を当てれば、**見出しの中で数字だけが別書体になる**——L93 と §13-9 が名指しで禁じた状態そのものである。本文中の数字も同じで、ベースラインと線の太さが明朝／ゴシックと合わない。

### MJ-4. §7 の色見本に枠が無く、§10 の色見本には枠がある——淡い中身色が消える

§7 L168:

> **主題が色である項目に限り**、行の先頭に 8px の色の見本を置く。

§10 L224:

> 主題が色である面だけ、**罫で囲んだ**色の見本を1つ置いてよい。

**同じものに、片方は枠を付け、片方は付けない。** どちらが正しいかを実装者は決められない。

**実害は §7 側にある。** 中身の色は §2 L76 で範囲を制限されていないので、`#FFFDF6`（白練）や `#F8F4E6`（象牙色）のような淡色が来る。**枠の無い 8px の見本は `--paper`（`#fcfcfc`）の上で消える。**
これは 1.4.11 Non-text Contrast の対象である。色見本は「主題が色である項目」の識別に必要な図形で、隣接色に対して 3:1 が要る。§2 L78 の「線と枠は 3:1」は**見本の上に線を置く場合**の規定であって、**見本と地の境界**には手当てが無い。

あわせて、**8px の見本が担い手4（§1 L35「無彩の器の上で、中身の色だけが立つ」）の主たる出番である**ことも記しておく。一覧で色が現れる面積は 8×8px の点1つで、「並んだときに見えるのは中身の色だけになる」という絵にはならない。**担い手4は §1 が書いている強さを持っていない。**

### MJ-5. `--paper-2` の用途が §2 と §5 で割れ、参照先の節番号が間違っている（1巡目 MN-2 も未解消）

§2 L51 の用途欄:

### MJ-6. WCAG 2.2 AA のうち 2.5.7 Dragging Movements が無い（(E)）

§7 L175 は「**並び順を変えられること**」を求めている。並べ替えの一般的な実装はドラッグである。ゲームやツールの面（このサイトの中心的な作りもの）でも、スライダー・並べ替え・盤面の操作はドラッグになりやすい。

**WCAG 2.2 の 2.5.7 Dragging Movements は AA で、ドラッグを伴う操作には単一ポインタの代替（タップ・ボタン）が必須である。**（W3C WCAG 2.2、レベル AA。）
§14 の品質バーには 2.5.8（44px）・2.4.11（隠れない）が入ったが、**2.5.7 だけが抜けている。** 1巡目で 2.2 の新設項目を洗った際の取りこぼしである。

なお 1.4.13 Content on Hover or Focus は、この文書が hover で追加内容を出す部品を1つも定義していない（§7 L183 の6部品にも無い）ため、実害のある穴とは見ていない。

### MJ-7. 四角ひとつで単一選択と複数選択の両方を表すことになる（(E)）

§6 L149:

> | 選択済み／未選択 | 先頭の四角を**塗る／空のまま**にする。反転で示さない |

§13-6（L249）は「`0px` 以外の角丸。ピル形状」を理由の如何を問わず禁止している。**丸を作れないので、ラジオボタンも四角になる。**

- 利用者は形で選択の性質を読む——**丸は「1つだけ選べる」、四角は「いくつでも選べる」。** これは OS・ブラウザ・アプリを横断して安定した慣習で、支援技術ではなく**視覚から**得ている情報である。
- 両方を四角にすると、**選択肢の集合を見ただけでは単一選択か複数選択かが分からない。** 1つ選んで他が消えるまで分からない。
- **§6 L140 の「一つの記号が二つの意味を持たないこと」に、この行自身が反している。**

§13-6 を曲げずに解くなら、単一選択には別の記号（塗りつぶした四角の中の細い横棒、四角の中の四角、選択肢群の左に立てる縦罫など）を割り当てて、この表に書く必要がある。**現状は、色を使わないと決めた代償を、形の区別でも払っている。**

### MJ-8. §5「すべての寸法は 8px の倍数」が、§4・§6 の数値とほぼ全面的に食い違う

§5 L123:

> **すべての寸法は 8px の倍数**（4px は微調整のみ）: 8 / 16 / 24 / 32 / 48 / 64 / 96。

「すべての寸法」に当たるもので 8 の倍数でない値: **17px**（本文 L98）、**14px**（補助情報の下限 L99・§13-15）、**33 / 47 / 65px**（見出しスケール L100）、**44px**（タップ標的 L155・L264）、**3px / 1px / 2px**（罫とリング L113-114・L151）。
8 の倍数なのは `--measure` 640px と `--max-width` 960px だけである。

**規定と実際の値が逆転している。** 意図は「余白と間隔は 8px の倍数」であろうが、書かれているのは「すべての寸法」で、しかも §13-7 が「**一律のパディング**」を禁じているため、実装者は「8の倍数に揃えよ」と「一律にするな」を同時に読むことになる。
**この節が担い手1の規定を担っているので、曖昧なまま残すと格子の目が実装ごとにずれる。**

## Minor

- **MN-1. 訪問済みリンクの状態が §6 の表に無い。** §6 は「押せる／押せない／現在地／選択済み／無効／フォーカス」を網羅したが、**既訪問／未訪問が無い。** 既定のブラウザは `:visited` を色で示すが、この文書は色を封じているので、**何もしなければ区別が消える。** §7 が「項目は増え続ける」「走査の速さは設計で作るもの」と書いた面でこそ効く区別なので、示す／示さないの決めが要る。

- **MN-2. 本文中のリンクの hover / active が未定義。** §6 L147 の hover は「**罫の外側に** 3px のオフセット罫が増える」で、罫を持つ部品を前提にしている。**罫を持たないのは本文中のリンク（下線のみ・L144）で、最も数が多い操作である。** 下線が太るのか、何も起きないのかが決まらない。

- **MN-3. 主操作の「＋ `--rule-w` の罫」が、どちらの色でも見えない。** §6 L145 は「反転（`--ink` 地に `--paper` 文字）＋ `--rule-w` の罫」。罫を `--ink` にすれば地と同化し、`--paper` にすれば紙地と同化する。**この罫が何のためにあるのかを文書から読めない**（色の指定も無い）。

- **MN-4. §13 の担保手段が、16項目中7項目で決まっていない**（1巡目 MN-5 が未解消・項目が増えて広がった）。L242 が機械検査に回すのは「フォント名・彩度・`box-shadow`・`border-radius`・見出し内の絵文字」、レビューに回すのは「定型構成・イラスト質感・モーションの意図」。**割り当てが無いのは 3（色を装飾）・4（グラデーション）・7（一律のパディング／中間の罫の太さ）・13（出し惜しみ・煽り）・14（他人の行動の煽り）・15（14px 未満）・16（無限スクロール）。** 15 と 16 と 4 は機械検査できる。8 も「見出し**内**の絵文字」しか回していないので、ナビとボタンが漏れている。

- **MN-5. `--measure: 40rem` がルート 16px を前提にしているが、その前提が書かれていない。** 本文が 17px なので、`html { font-size: 17px }` と実装すると `40rem = 680px = 40字` になり、L98 の「全角37字以内」が崩れる。`em` で書くか、ルートを動かさない旨を明記すれば決着する。

- **MN-7. 未決定が3箇所、規範の中に残っている**（1巡目 MN-9 が未解消）。§3 L85「実装時に1つ選ぶ」、§3 L94「実機で確かめて確定する」、§4 L104「実機で確認して書体を確定する」。L3 の「**値はここが出どころ**」と噛み合わない。決まっていないものは cycle ドキュメントに置く。

- **MN-8. 明朝サブセットの 300KB 上限と、字種が増え続ける前提が衝突する。** §3 L90-91 は「かな＋常用漢字＋約物＋その面で使う表外漢字」「**足りない字が出る面では、その字を含めてサブセットを作り直す**」、L92 は「合計 300KB（WOFF2）を上限」。**面が増えるほど表外漢字は単調に増えるが、上限は固定である。** いつか必ず当たる。加えて「作り直す」が**1本のファイルを作り直す**のか**面ごとにファイルを分ける**のかが読めない（前者なら全面の再配信、後者なら面ごとに別ファイルでキャッシュが効かない）。日本語明朝の WOFF2 はおおむね 1字 100〜140B なので、常用漢字 2,136 ＋ かな ＋ 約物だけで 250〜320KB になり、**上限に最初から余裕が無い。**

- **MN-9. §10 に AI 運営の告知の扱いが無い**（1巡目 MN-8 が未解消）。共有画像はサイトの外へ単体で出ていく成果物で、下端（§9 L216・§5 L136）の告知が付かない。constitution rule 3 に関わるので、**載せる／載せないのどちらかを文書が決める必要がある**（§10 L224 が「図像・イラスト・記号を足さない」と書いているため、判断を要する）。あわせて `theme-color` とアプリアイコン（Android は角丸でマスクする）の扱いも無い。

- **MN-10. §13-8 の「多用」が、§13 前文の「理由の如何を問わず禁止」と同居できない**（1巡目 MN-6 が未解消）。「all-caps の英字ラベルの**多用**」だけが程度で判定する項目である。

- **MN-11. §6 L151 の「§6 末尾を参照」は、同じ節の中を指す自己参照である。** 表のすぐ下の箇条書きを指しているので情報はゼロで、**注記を後から足した痕跡だけが残っている**（CLAUDE.md「ツギハギ禁止」——「retrofitted annotations を残さない」）。
