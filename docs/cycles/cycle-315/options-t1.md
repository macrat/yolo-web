# T1: `docs/site-concept.md` の「コンセプト／非コンセプト」の線引き——5案

Owner の指示は「サイトコンセプト**以外**の内容を削ぎ落とす」である。
**何が「以外」なのかは自明ではない。** 解釈によって残るものが大きく変わるので、線引きの案を並べて選ぶ。

## 判断基準——何をもって良い線引きとするか

この文書は来訪者が読むものではない。だから「来訪者に何が起きるか」は一段の間接を経る。

1. **次にこの文書を引く者が、迷わず1つの答えに到達できるか。** いま到達できないせいで、画面の欠陥20件以上が「規範が決まるまで違反か判定できない」として止まっている（`docs/backlog.md` Done/Cancel）。止まっているのは文書整備ではなく画面の修理である。
2. **`DESIGN.md` の導出元として機能するか。** Owner は「作ったサイトコンセプトから自然に導出できる形の」デザインシステムを求めている。導出元になれない線引きは、次の工程で行き詰まる。
3. **削ぎ落とした先が存在するか。** 落とすと決めたものに行き先が無いなら、それは削ぎ落としではなく破棄である。

## 案1: 「判断基準の文書」として定義する（現行の自己申告を採る）

現行 L5 が自ら「コンテンツについて追加/削除/どう作るかに迷ったとき、判断基準として参照する」と名乗っている。これをそのまま文書の定義とする。

- **残す**: 正体／ゴール／中心原則と弁別子／判断基準1・2・3／ガード／禁じるもの
- **落とす**: 自己否定バナー・使い方の但し書き・改訂履歴・L9 全体・検証状態のメタ・トリップワイヤ・「文書の地位と検証」節

**この案を採ると何が起きるか。** 文書は短くなり、引くべき規則だけが並ぶ。
一方で「この文書は仮説を含む」という情報が消える。**中心原則の「体験型が耐性を持つ」は現時点で仮説であり、確認済みの事実ではない。**
それを仮説と知らずに引いた者は、検証せずに岩盤として扱う——`docs/anti-patterns/planning.md` の AP-P34 が名指しで警告している型そのものである。
トリップワイヤ（どうなったら再検証するか）も失われるため、仮説が外れても誰も気づけない。

**捨てる。** 仮説を仮説と示す機能は、判断基準そのものと同じくらい規範的である。

## 案2: 「正体 → 導出」の2層として定義する

第1層にサイトの正体を置き、第2層にそこから導かれる規則だけを置く。**正体から導出できない規則は、この文書に属さない**とする。

- **残す**: 正体／正体から導ける規則
- **落とす**: 案1の落とすもの + 正体から導けない規則

**この案を採ると何が起きるか。** 構造が「正体 → 導出」になり、`DESIGN.md` も同じ構造で導ける（判断基準2を満たす）。Owner の言い方とも揃う。

**しかし現行の判断基準の多くは、正体からではなく外部環境の観測から来ている。**
「参照型は訪問を失う」はゼロクリック環境の観測であり、「AI が営むよろず屋」という正体からは1ミリも導けない。
「scaled content abuse に当たる」は Google のスパムポリシーであって正体とは無関係である。
この線引きを厳密に適用すると、**判断基準の実質がごっそり外に出る**。出した先が無い。

**捨てる。** ただし**「正体 → 導出」という構造の考え方は採る**（案5 へ引き継ぐ）。

---

## 案3: 「このサイトが何であるか」だけに絞る（最小案）

文字どおりに読む。コンセプト＝サイトの正体であり、それ以外（判断基準・ガード・禁止事項）は運用規約として別文書へ移す。

- **残す**: 正体・ゴール・中心原則と弁別子（現行 L11〜L37 相当）
- **落とす**: 判断基準1・2・3／ガード／禁じるもの／文書の地位 → 別文書へ

**この案を採ると何が起きるか。** 最も短く、最も読みやすく、最も矛盾が起きにくい。

**しかし Owner は「site-concept.md という単一のファイル」と言っている。** 分割は指示と食い違う。
さらに `.claude/rules/doc-directory.md` は「新しいドキュメントを作るときは既存と重複していないか確認せよ」と言う。
判断基準を移す先の新文書は、site-concept.md と不可分の内容を持つため、**2文書が互いを参照し合う状態＝いま解こうとしている問題の再生産**になる。

**捨てる。**

---

## 案4: 「規則」と「規則の来歴」で切る

線引きを一本にする——**これは規則か、それとも規則がどう生まれたかの話か。** 後者だけを落とす。

- **残す**: 現行の全節（正体・ゴール・原則・基準1-3・ガード・禁じるもの・地位と検証）
- **落とす**: 自己否定バナー／改訂履歴／L9 の 3・8／後付けの強調（L19 末尾）／裏取り不能な帰属（L57「オーナーは積極的な実験を奨励する」）／過去の失敗との対比（L57 末尾・L76）／検証状態の重複（L36 と L93）

**この案を採ると何が起きるか。** 削ぎ落としが明確な操作になり、判定に迷いが出ない。
`CLAUDE.md` のツギハギ禁止（「History, rationale, and trial-and-error belong in the cycle document, never in the file itself」）と完全に一致する。行き先の問題も起きない（来歴はサイクル文書に既にある）。

**弱いのは、順序を問わないこと。** 落とすものを落とすだけでは、残った規則がどこから来たのかは見えないままになる。
`DESIGN.md` を導出するとき、「どの規則から何を導くか」が読み取れない。判断基準2 を満たさない。

**単独では採らない。骨格として採る。**

---

## 案5: 来歴を落とし、残りを「正体 → 導出」の順に組み直す（案4 の線引き × 案2 の構造）

- **落とす**: 案4 が落とすものすべて（線引きは「規則か、規則の来歴か」の一本）
- **残す**: 案4 が残すものすべて
- **組み直す**: 残った規則を、**それが何から来ているのかが節の構造で分かる順**に並べる。来源は3種類しかない——(a) サイトの正体から導いたもの、(b) 外部環境の観測から来たもの、(c) 外部が決めている要件（constitution・法令・検索エンジンのポリシー・WCAG）。

**この案を採ると何が起きるか。**

- 判断基準1（迷わず1つの答えに到達できる）: 規則を引くとき、それが**疑ってよいもの（観測由来＝更新されうる）か、動かせないもの（外部要件）か**が構造で分かる。いまは全部が同じ平面に並んでいて区別がつかない。
- 判断基準2（`DESIGN.md` の導出元になる）: (a) の規則からデザインを導き、(c) は外部要件としてそのまま引く、という手順が明示できる。**Owner の「自然に導出できる形」はこれで満たせる。**
- 判断基準3（落とした先がある）: 落とすのは来歴だけで、行き先はサイクル文書である。

**この案の代価。** 節の順序が現行から変わるため、既存の「site-concept §◯」という参照が切れる可能性がある。
ただし `docs/` 内の参照は節番号ではなく文書名で引いているものが大半であり、切れた参照は T8 で洗い出して起票する。

**弱点を1つ認めておく。** (a)(b)(c) の分類自体が判断を含む。「体験型が耐性を持つ」は (a) なのか (b) なのか——正体から導いた願望なのか、観測から来た推定なのか。
**これは弱点であると同時に、この案の効き目でもある。** いま同じ平面に並んでいるせいでこの問いが立たない。分類を強いれば、立つ。

---

## 選定——案5

**案5 を採る。** 案4 の線引き（規則か来歴か）を骨格に、案2 の構造（正体 → 導出）で組み直す。

**理由。** 判断基準2 が決め手である。本サイクルは `site-concept.md` を直して終わりではなく、**そこから `DESIGN.md` を導出する**ところまでが Owner の指示である。
案1・案3・案4 はいずれも「site-concept.md を読みやすくする」ことはできるが、**次の工程に何も渡さない**。
案5 だけが、「この規則は正体から来ている／これは外部が決めている」という形で次の工程に渡す材料を作る。

**案2 を単独で採らない理由をもう一度。** 「正体から導けないものは属さない」を厳密に適用すると判断基準が空洞になる。
案5 は同じ構造を使いながら、**導けないものを追い出すのではなく、導けないものとして明示して残す**。ここが違う。

**選ばなかった案から拾うもの。** 案1 が警告した「仮説を仮説と示す機能」は、案5 の (a)(b)(c) 分類がより強い形で担う——
分類そのものが「これは観測由来だから更新されうる」と告げるからである。トリップワイヤは残す。
