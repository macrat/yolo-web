## Blocker

### BL-1. `--rule-hair` が、同じ文書の中で別々の2つのものとして定義されている

§2（L49）——**色**トークンとして。

> | `--rule-hair` | `oklch(0.80 0 0)` | `oklch(0.38 0 0)` | 細罫（行の区切り・表の内部） |

§5（L88）——**太さ**トークンとして。

> **罫の太さは2段階**: `--rule-bold: 3px`（面の外枠・主な区切り・上端と下端）と `--rule-hair: 1px`（行の区切り・表の内部）。

**同名のカスタムプロパティに、色と長さの2つの値が定義されている。** 用途の説明文（「行の区切り・表の内部」）まで逐語で一致しているので、書き分けの意図ではなく衝突である。
L3 は「**値はここが出どころで、コードのトークンはここから生成する**」と宣言している。この宣言のとおりに生成すると、どちらか一方が上書きされて消える。実装者はどちらを採るかを文書から決められない。

### BL-2. `--rule-hair` の色が、§13 が自分で定めた 3:1 を満たさない（light 1.82 / dark 1.96）

§13（L196）:

> **コントラスト**: 本文と文字は 4.5:1 以上。**罫・UI 部品**・フォーカスリングは 3:1 以上。**トークンを変えたら再計測する。**

§2 の値で実計算した結果:

| 組み合わせ                                  | sRGB                  | 相対輝度 Y      | コントラスト比 | 3:1 |
| ------------------------------------------- | --------------------- | --------------- | -------------- | --- |
| light `--rule-hair` 0.80 / `--paper` 0.99   | `#bebebe` / `#fcfcfc` | 0.5120 / 0.9703 | **1.82:1**     | ✗   |
| light `--rule-hair` 0.80 / `--paper-2` 0.95 | `#bebebe` / `#eeeeee` | 0.5120 / 0.8574 | **1.61:1**     | ✗   |
| dark `--rule-hair` 0.38 / `--paper` 0.15    | `#424242` / `#0b0b0b` | 0.0549 / 0.0034 | **1.96:1**     | ✗   |
| dark `--rule-hair` 0.38 / `--paper-2` 0.21  | `#424242` / `#181818` | 0.0549 / 0.0093 | **1.77:1**     | ✗   |

（参考・満たしている値: `--ink`/`--paper` = 19.12:1、`--ink-2`/`--paper` = light 7.55:1 / dark 8.53:1、`--ink-2`/`--paper-2` = light 6.71:1 / dark 7.68:1。**落ちているのは細罫だけである。**）

**これは「装飾の罫だから免除される」で逃げられない。** §5（L92）は「**面は罫で作る。** 背景色で区切らない」と定め、§7（L127・L130）は一覧を「細罫で区切る」「**行全体がクリック標的**」と定めている。
つまり細罫は、**押せる部品の境界を示す唯一の視覚情報**である。WCAG 2.2 の 1.4.11 Non-text Contrast（AA）が求める 3:1 の対象そのもので、かつ §13 が自分の言葉で 3:1 を課している対象でもある。

3:1 に届かせるための実計算値: **light は `--rule-hair` ≤ `oklch(0.662 0 0)`（`#939393`）、dark は ≥ `oklch(0.479 0 0)`（`#5d5d5d`）。**
なお `--paper-2` の上にも細罫が乗る（§11 の広告区画・§2 のコード面）ので、上限／下限は `--paper-2` 側で決める必要がある。

### BL-3. 中身の色の置き場所が、§2・§8 と §7 で正面から食い違う

§2（L59）は、色を漏らしてはならない場所として**一覧を名指ししている。**

> 使ってよい場所は、**罫で囲まれた中身の区画の内側だけ**（§8）。器（上端・**一覧**・ボタン・罫）には漏らさない。

§8（L146）も排他で書いている。

> 結果・生成物は、**3px の罫で囲んだ区画**に置く。**中身の色が入るのはここだけ。**

§7（L131）が、その一覧に色を置く。

> **主題が色である面に限り**、行の左端に 8px の色帯を置いてよい。器は無彩のまま、中身の色だけが行に差す。

さらに §12-2（L180）は「**器にアクセント色を置くこと**」を「理由の如何を問わず禁止」に挙げている。一覧は §2 が器だと定義した当のものである。

**これは `design-audit.md` D-2 と完全に同じ型である。**

> **持たないと書いた同じ段落が、持つ場合を定義している。**

書き直しの理由の中心が②（文書内の矛盾）だったのに、**同じ型が新しい文書に再生産されている。** しかも「器は無彩のまま、中身の色だけが行に差す」という一文は、`design-audit.md` D-3 が指摘した自己弁明（「その規定と看板の識別マークは矛盾しない」）と同じ働きをしている——**規定が割れているので、割れていないと文書が自分で言い足している。**

一覧行の色帯は案K1 の弱点を塞ぐ手段として `design-center-options.md` が選んだものなので、**捨てるのではなく、§2 の「器」の定義を「行の色帯を含む」形に書き直して一箇所に決着させること。**

### BL-4. フォーカスリングが、反転した面と色の面の上で消える

§6（L116）:

> | フォーカス | **3px の `--ink` アウトライン ＋ 2px のオフセット**。両テーマで見える |

**「両テーマ」はライトとダークのことしか見ていない。** この文書が作る画面には、テーマとは別に**地が `--ink` になる面**と**地が中身の色になる面**がある。

1. **反転した行・面の内側。** §6（L115）は「現在地・選択状態＝**反転**」、§7（L130）は「行内に副リンクを持つ場合は、副リンクを独立に押せるようにする」。**選択状態の行（地＝`--ink`）の中の副リンクにフォーカスすると、`--ink` のリングが `--ink` の地に載る。コントラスト比 1.00:1。完全に不可視である。** 2px のオフセットも同じ反転面の内側なので効かない。
2. **`--ink` 地のボタンが `--ink` の面に隣接する場合**（上端のナビが反転した現在地を持ち、その隣に反転した主操作が並ぶ等）。オフセットの 2px が何色になるかは親が決めるため、文書からは保証できない。
3. **§8 の結果区画。** §2（L60）は「**色の範囲を制限しない**」と定めている。暗い中身の色が区画を占めたとき、その上の操作部品の `--ink` リングは沈む。§2（L61）は**文字**については「輝度から前景（`--paper` か `--ink`）を選び、4.5:1 を満たす」と手続きを書いているのに、**フォーカスリングには同じ手続きが無い。**

WCAG 2.2 の 2.4.7 Focus Visible（AA）と 1.4.11（フォーカス表示 3:1）に落ちる。
**リングの色を `--ink` に固定したまま「両テーマで見える」と宣言している点が、この文書で唯一「宣言だけ」で済ませている安全性の規定である。**
（実装可能な解のひとつは二重リング——内側 `--paper` ＋ 外側 `--ink`（または逆順）の 2 本で、どちらの地の上でも片方が必ず立つ。Chrome の既定 `:focus-visible` と GOV.UK が採る型。文書はリングの色を地から選ぶ手続きを書くか、二重リングを規定するかのどちらかを決める必要がある。）

### BL-5. 個性の担い手1と2が、規定になっていない——「格子」の規定がゼロ、明朝の実体が無い

**これが条件1（デザインだけで yolos.net だと分かる）に対する最大の穴である。**

**担い手1「太い黒罫の格子」（L25）。** §5 が定めているのは、太さ2段階（L88）・主罫は画面端まで（L89）・角丸0（L90）・影なし（L91）・面は罫で作る（L92）。
**「格子」を作る規定が1件も無い。** 縦の罫の規定が無く、罫を置く位置・間隔・モジュール（何分割か、どの列に罫が立つか）の規定も無い。
この文書に完全に従って、**上端の下に主罫1本・下端の上に主罫1本だけを引いた画面**を作れる。それは編集系のサイトにいくらでもある顔で、「それだけで見分けがつく」（L25）は成立しない。
`design-center-options.md` の案F は「太い黒罫（3px）の**格子**。罫は画面端まで届く」を見た目の中心に据えた。**`DESIGN.md` は「画面端まで届く」だけを受け継ぎ、「格子」を落としている。**

**担い手2「巨大な明朝の見出し」（L26・L81）。** 拘束力のある数値は1つしかない。

> **見出しは大きく取る。** 各面の主見出しは、狭い画面（375px）でも `32px` を下回らない。**これが個性の担い手2である。**

- **広い画面での下限が無い。** デスクトップで主見出しを 24px にしても、この文書には違反しない。**個性の担い手が、最も面積のある画面で規定されていない。**
- **32px は「巨大」ではない。** 一般的なサイトのモバイル h1 は 28〜32px の帯にある。下限が業界の中央値と同じなら、その規定は個性を作らない。
- **書体名が無い。** §3（L68）は「**明朝の Web フォント1書体**（ウェイト1本）」としか書いていない。L3 は「値はここが出どころ」と宣言しているのに、**個性の担い手2の実体——どの明朝か——が文書に無い。** 書体が決まらなければ、担い手2は実装できない。旧版は候補（源ノ明朝／しっぽり明朝系）まで書いていたので、**これは書き直しで後退した箇所である。**

**L34 の自己点検が、点検として働かない。**

> **どの画面からも、1〜3 のうち最低2つが見えること。** 見えないなら、その画面は yolos.net に見えていない。

§5 の骨格（L101・L103）が、上端に主罫と明朝のサイト名を、下端に主罫を**全ページ必須で**置いている。つまり担い手1と2は**どのページでも自動的に「見えて」いる。** この点検は構造上けっして失敗しない。**失敗しえない検査は検査ではなく、宣言である。**

**§1 の4担い手のうち、実際に具体の規定として書かれているのは3（反転・§6）だけ**である。1は不在、2は下限1つ、4は「主題が色である面」（一覧・ブログ・多くのツールでは発生しない）に限られる。
**条件1は、この文書のままでは満たせない。**

### BL-6. 反転が4つの意味を同時に担い、状態が判別できない

§6 の表（L111-117）が反転に割り当てている意味:

| 行               | 反転の意味           |
| ---------------- | -------------------- |
| 主操作（ボタン） | 押せる               |
| 現在地・選択状態 | いま居る／選んである |
| hover / active   | 指が乗っている       |

そして「hover / active: **反転する、または反転を解く**」（L114）。

**帰結1——主操作の hover が、副操作の静止形と同じ見た目になる。**
主操作＝`--ink` 地 ＋ 3px 罫（L112）。その hover で「反転を解く」と、`--paper` 地 ＋ 3px 罫。これは副操作の定義（L113「罫だけ（3px）・地は `--paper`」）と**同一である。** 隣り合った主操作と副操作にカーソルを置くと、2つのボタンの重みが入れ替わって見える。

**帰結2——押せるものと、押しても何も起きないものが同じ記号を持つ。**
上端のナビの現在地は反転（L101・L115）。同じ画面の主操作も反転（L112）。**「反転＝押せる」と「反転＝いま居るので押す意味がない」が同居する。**
L121 は「**押せるものと押せないものを、形で区別する。**」と課しているが、§6 の表は**その形の区別を提供していない。** 規定が、同じ節の中で自分が課した条件を満たしていない。

**帰結3——未選択の状態に記号が無い。**
選択状態＝反転。未選択＝（規定なし＝地のまま）。選択肢が2つ以上並ぶ UI（絞り込み・タブ・チェックボックス・ラジオ）では、**未選択の選択肢が「ただの文字」になり、選択肢の集合であることが見えない。**
§7（L136）は部品を「行・罫・見出し・本文・入力・結果」の6つに限っているが、**チェックボックス・ラジオ・トグル・セレクトはこの6つのどれにも当たらない。** 「入力」が全部を兼ねる読みだとしても、その見え方の規定はゼロである。

**帰結4——無効状態の反転が未定義。**
L117「無効状態: 罫を**破線**にし、理由を文字で添える」。**無効になった主操作（反転済み）は、反転のまま破線なのか、反転を解いて破線なのかが決まらない。** 後者なら副操作の hover と衝突する。

**条件2（誰もが使える）は、色覚に依存しないことだけでは達成されない。** 記号が1対1で意味に対応していなければ、誰も状態を読めない。現状の §6 は**1つの記号（反転）に4つの意味を載せている。**

### MJ-2. 「タップ標的 44px 以上」が、本文中のリンクでは満たせない——文書のまま実装できない

§6（L119）・§13（L197）はいずれも無条件で書いている。

> - **タップ標的は 44px 以上。** 反転する面は必ずこれを満たす。

§4（L78）の本文は `17px` / 行間 `1.85` なので、**行ボックスの高さは 17 × 1.85 = 31.45px。** §6（L111）が定める「本文中のリンク」の標的は、この 31.45px を超えられない。文中のリンクを 44px にすれば行が分断される。
**文書に完全に従うことが不可能である。** WCAG 2.5.8 はインライン（テキストの流れの中）のリンクを明示的に例外にしているので、**例外を書けば解ける。** 現状は書かれていないため、実装者は「規定に違反する」か「本文の行間を壊す」かの二択になる。

### MJ-3. 個性の担い手2を担う明朝 Web フォントに、実装上の穴が3つある

1. **§13（L200）がリフローの対象から見出しを外している。**

   > Web フォントの読み込みで**本文と結果**がリフローしない（`font-display: swap` ＋ フォールバックのサイズ調整）。

   `font-display: swap` は、フォールバック（システムゴシック）で一度描いてから明朝に差し替える。**差し替わるのは見出しである。** つまり **個性の担い手2が、最も大きな面積で、最も目立つ形で差し替わる（CLS と FOUT の主因）ことを、品質バーが明示的に免除している。** §1 が「巨大な明朝は器の個性を担う」と書いたことと噛み合っていない。

2. **サブセットの範囲が、このサイトの中身と合っていない。** §3（L68）は「かな＋**常用漢字**＋約物」。常用漢字は 2,136 字で、**表外漢字を含む見出しは明朝で出ない**（フォールバックのゴシックに落ちるか、混植になる）。このサイトには伝統色辞典のようなコンテンツがあり（`design-audit.md` D-6 が言及）、「縹色」「鴇色」「橡色」の類は表外漢字である。**見出しの一字だけがゴシックになる画面**は、§12-8（L186）が禁じている「**見出し1語だけの書体切替**」がそのまま起きた状態である。文書はこの場合の扱いを決めていない。

3. **重量の規定が無い。** かな＋常用漢字＋約物のサブセットは 2,300 字規模で、日本語明朝の WOFF2 では数百 KB〜1MB 台になる。§13 にパフォーマンスの下限（転送量・LCP・CLS のいずれか）が無いため、**「巨大な明朝」と「狭い回線でも読める」のどちらを優先するかが決まらない。**

### MJ-4. ダークの値が、自分で書いた「純黒・純白は使わない」を実質的に満たしていない

§2（L53）:

> **ダークは反転ではなく、別に定義した値を使う。純黒・純白は使わない（`0.15`/`0.99`）。**

実測値: `oklch(0.15 0 0)` = `#0b0b0b`、`oklch(0.99 0 0)` = `#fcfcfc`。**コントラスト比 19.12:1**（純黒／純白は 21:1）。
**視覚的には純黒・純白と区別がつかず、回避しようとしたもの（ハレーション）を回避できていない。** 乱視のある利用者に白文字が滲んで見える現象は、暗い地と明るい文字の輝度差で起きるもので、19.12:1 は 21:1 とほぼ同じ条件である。実務のガイドは地を `#121212`（= `oklch(0.18 0 0)`）程度までしか落とさないことを勧めている。**`#0b0b0b` はその推奨より暗い。**

（参考: `--ink` を `oklch(0.92 0 0)`、`--paper` を `oklch(0.19 0 0)` にすると 14.57:1 で、AA の 4.5:1 に十分な余裕を残したままハレーションを抑えられる。数値の選定は実装側の判断だが、**「純黒・純白は使わない」という規定が実効を持つ値にする必要がある。**）

**なお、同じ L53 の前半「ダークは反転ではなく」は、同じ表と矛盾している**（Minor MN-1）。

### MJ-5. 一覧が増え続ける前提に対する規定が無い——constitution rule 4 と site-concept の中心に当たる

§7（L127-132）が定めているのは、1行1項目・細罫・品名／ひとこと／種別・行全体が標的・煽り禁止。**それだけである。**

- **並び順の規定が無い。** 新着順か、種別順か、手で並べるのか。
- **絞り込み・検索・分類の規定が無い。**
- **件数の規定が無い。** 1ページに何行まで載るか、ページ送りをするか、無限スクロールにするか。

`site-concept.md` は「**たくさん作って、たくさん試します**」を骨格の1つに据え、「試す数が増えるほど、当たりに出会う回数が増える」と書いている。**項目は増え続ける前提である。**
constitution rule 4 は「**well organized for easy to explore**」を課している。

`design-center-options.md` が案K1 を選んだ根拠は「**1画面に入る項目数と走査の速さ**」だった。**その根拠は、項目が1画面に収まる間しか成立しない。** 100行・200行になったとき、案K1 の強みは無条件には残らない。
これは `docs/anti-patterns/planning.md` AP-P03（今ある状態を所与にして、今後の展開を見据えない）に当たる。

**同じ欠落が回遊にもある。** §5 の骨格は上端・本文・下端だけで、**面から面への導線（関連・パンくず・前後）の規定が1件も無い。** 一覧を経由しない移動手段が文書に存在しない（WCAG 2.4.5 Multiple Ways も AA）。

### MJ-6. favicon・OGP・共有画像——「デザインだけで分かる」面が規定から丸ごと抜けている

**条件1を最も素朴に試される面は、ブラウザのタブ・検索結果・SNS のカードである。** そこには太い罫も巨大な明朝も入らない（16〜48px には入らない）。
新しい `DESIGN.md` には、**favicon・アプリアイコン・`theme-color`・OGP 画像に関する規定が1件も無い。**

さらに、§12（L177-192）の禁止は書かれた時点でこれらの面にも及ぶ:

- §12-5「`0px` 以外の角丸」——角丸のアイコン形は禁止側に入る。
- §12-2「器にアクセント色を置くこと」——単色のアイコンが作れるのかどうか、文書からは判定できない。

**旧版はここを（朱のタイル＋明朝の y として）規定していた。** 書き直しで規定だけが消え、禁止だけが残った。**「識別マークを持たない」と決めたのなら、そう書かれていなければならない。書かれていないので、実装者は禁止リストに当たらない形を自分で発明することになる。**

§8（L150）の共有画像も同じ穴を持つ。

> 共有用の画像を作る場合、**画像単体で、何の結果かとサイト名が読めること**。サイト名は明朝で置く。図像や記号を足さない。

規定があるのは結果の共有画像だけで、**ブログ・一覧・トップの OGP には規定が無い。**

### MJ-7. 旧版にあったアクセシビリティ規定が1件、受け皿なく落ちている

旧 `DESIGN.md` L72:

> 行内に副リンク（タグ等）を持つ場合も、視覚単位全体を主リンクの標的にしつつ副リンクを独立に押せるようにする。**スクリーンリーダーに読ませるのは主リンク名のみに保つ**（視覚単位全体を1本の `<a>` で包むとアクセシブル名が行内容の連結になり冗長——許容はするが主リンク名のみが望ましい）。

新 §7（L130）は**前半（標的）だけを引き継ぎ、後半（アクセシブル名）を落としている。**

> **行全体がクリック標的。** 品名の文字幅だけを標的にしない。行内に副リンクを持つ場合は、副リンクを独立に押せるようにする。

これは §7 の一覧——**このサイトのすべての探索が通る面**——の読み上げ品質を決める規定である。落とすと、リンクの読み上げ名が「品名＋ひとこと＋種別」の連結になる（WCAG 2.4.4 Link Purpose に効く）。
`design-audit.md` 冒頭の表には載っていないが、**出所は同じ constitution rule 4 で、入力は変わっていない。**

## Minor

- **MN-1. §2（L53）「ダークは反転ではなく、別に定義した値を使う」が、同じ表と食い違う。** 表の `--paper` は light `0.99` / dark `0.15`、`--ink` は light `0.15` / dark `0.99`。**この2つは完全な反転である。** 反転でないのは `--paper-2`・`--ink-2`・`--rule-hair` の3つだけ。「反転ではない」と言い切る書き方が、地と文字という最も目立つ2トークンで成立していない。

- **MN-2. `--paper-2` が、唯一許された背景による区切りなのに見えない。** light `0.95`/`0.99` = **1.12:1**、dark `0.21`/`0.15` = **1.11:1**。§5（L92）は「面は罫で作る。背景色で区切らない（**例外は広告区画の `--paper-2` のみ**）」と、この1件のために例外を作っている。**例外として認めた当の区別が、事実上見えない値である。**（§11 が罫とラベルを併用するので WCAG 違反ではないが、`--paper-2` というトークンを置く意味が無くなっている。）

- **MN-3. §4（L81）の `32px` が、同じ節のスケールに存在しない。** L80 のスケールは「17 / 24 / 33 / 47 / 65px」。32 はどの段でもない。実装者は 33 に丸めるのか、32 を新設するのかを決められない。担い手2の唯一の拘束値なので、段の名前（例: 第3段 `33px`）で書くべきである。

- **MN-4. §5（L101）「背景色と影を付けない」と、同じ行の「現在地は反転」が語として衝突する。** 反転とは地に `--ink` を敷くことなので、読み手は「上端に背景色を付けてよいのか」を一度考えることになる。「上端の帯そのものに地色を敷かない」の意味であれば、そう書く。

- **MN-5. §12 前文（L177）の機械検査リストに、§12-14（`14px` 未満の文字）が入っていない。** 列挙は「フォント名・彩度・`box-shadow`・`border-radius`・見出し内の絵文字」。文字サイズは機械検査できるのに、機械検査側にもスクリーンショット側（「定型構成・イラスト質感・モーションの意図」）にも属していない。**14 項目の禁止のうち1項目だけ、担保の手段が決まっていない。**

- **MN-6. §12-7（L185）に程度語が入っている。** 「all-caps の英字ラベルの**多用**」。§12 の前文は「**理由の如何を問わず禁止**」と宣言しているので、程度で判定する項目は同居できない。何件から多用かを書くか、この項目を §4 の組版側へ移す。

- **MN-7. §3（L70）の「数字用の書体をもう1つ」が、§12-8 の理由と衝突する。** §12-8（L186）は「見出し1語だけの書体切替」を禁じる。理由は混植の不整合である。**同じ不整合は、本文の中で数字だけが別書体になったときにも起きる**（ベースラインと線の太さが合わない）。`font-variant-numeric: tabular-nums` で足りるかを確かめずに3書体目を規定に入れているので、根拠が弱い。

- **MN-8. §8（L150）の共有画像に、AI 運営の告知が無い。** constitution rule 3 は「the website is run by AI as an experiment and that its content may be broken or incorrect」の告知を求めている。§9（L160）と §5（L103）は下端に置くと定めた。**共有画像はサイトの外へ単体で出ていく成果物で、そこには告知が付かない。** 画像に載せるか、載せないと決めるかのどちらかを文書が決めるべきである（§8 は「図像や記号を足さない」と書いているので、判断が必要になる）。

- **MN-9. 未決定が3箇所、規範の中に残っている。** §3（L74）「実機で確かめて確定する」、§4（L83）「実機で確認して書体を確定する」、§3（L68）の書体名の不在。L3 の「**値はここが出どころ**」という宣言と噛み合わない。`design-audit.md` D-7/D-8 が指摘した「規範に属さないものが規範文書の中にある」の裏返しの形で、**決まっていないものが規範文書の中にある。** 未決定は cycle ドキュメントに置き、`DESIGN.md` には決まった値だけを載せる。
