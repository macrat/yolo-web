# 決定（作り直し）: site-concept.md をコンセプト本体だけに絞る

Owner の指摘2件（[incident-3.md](./incident-3.md)）を受けて、[decision-2.md](./decision-2.md) の判断を撤回し、立て直す。

## 撤回する判断

| decision-2 で決めたこと            | なぜ撤回するか                                                                                                                                                                         |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **「文書を分割しない」**           | 「サイトコンセプト以外を削ぎ落とす」の射程を取り違えていた。落とすべきは来歴だけでなく、**運用規則・判断基準・デザインへの制約のすべて**だった                                         |
| 「ターゲットの不在には理由がある」 | **理由になっていなかった。** 廃止されたのは蓋然性のないピンポイントなペルソナ設定であって、コンセプトが定めるターゲットではない。しかも根拠に引いた `rebuild-plan.md` は失効文書だった |

## 決定

### 1. `docs/site-concept.md` に残すもの——コンセプト本体だけ

**コンセプトの定義（調査で確認した一次資料）に従う。**

- Kotler & Keller: アイデアを**消費者の言葉で**具体化したもの
- JMR生活総合研究所: **①誰に ②何を ③どのように**を**ひとことで**言い表したもの
- デジタル大辞泉: 全体につらぬかれた、**骨格となる発想や観点**

**残す4つ。**

| #   | 何を書くか                                     | 対応する項目   |
| --- | ---------------------------------------------- | -------------- |
| 1   | **このサイトは何か**（一文の定義・名前の由来） | 骨格となる発想 |
| 2   | **誰のために作るか**（ターゲット）             | ①誰に          |
| 3   | **来訪者は何を得るのか**（提供価値）           | ②何を          |
| 4   | **ゴール**（constitution の Goal）             | 運営側の目的   |

**「③どのように」は書かない。** JMR は構成要素に挙げているが、**それは商品コンセプトの話であり、いまのこの文書では「どのように」が 51% を占めて本体を埋めている。**
どのように作るかは、下の受け皿へ移す。

### 2. 削ぎ落とすもの——捨てずに移す

**Owner の指示は「削ぎ落とす」であって「捨てる」ではない。** 規則には資産としての価値がある（止まっていた17件の判定に使える）。**行き先を作って移す。**

| 削ぎ落とすもの                                        | 行き先                            | 理由                                                     |
| ----------------------------------------------------- | --------------------------------- | -------------------------------------------------------- |
| 何を作るか（弁別子・追加6条件・賭けの枠・作りの構造） | **新設 `docs/content-policy.md`** | コンテンツの取捨の判断基準。コンセプトではない           |
| 何をやめるか（撤退6条件）                             | 同上                              | 同上                                                     |
| どう作るか（8条件・来訪者に届く言葉）                 | 同上                              | 同上                                                     |
| 守るもの（constitution rule 1〜5 の接地）             | 同上                              | 規則をコンテンツへ適用する規定であってコンセプトではない |
| デザインへ渡すもの（制約4層）                         | **`DESIGN.md`**                   | 受け取る側が持つ。Garrett の5層では Surface 層の判断     |

**新設する文書は1つだけにする。** `docs/content-quality-requirements.md` は個々のコンテンツの品質要件（一行価値・FAQ・関連導線）で層が違い、受け皿にならない。

### 3. ターゲットをどう書くか

**Owner が廃止したのは「蓋然性のないピンポイントなペルソナ設定」である。** したがって次を守る。

- **架空の個人像を作らない**（年齢・職業・休日の過ごし方といった設定を置かない）。
- **根拠を持つ。** 本サイクルで実測したデータから書ける範囲に留める。
- **各コンテンツの制作判断に使う具体のターゲットは、ここでは決めない。** それは廃止された仕組みである。

**書ける根拠**（[facts-ga.md](./facts-ga.md) の実測）:

- 流入は検索が主で、指名検索はほぼ無い（保持全期間で26表示・2クリック）。
- ボット疑いを除いた PV は、**やってみる側 88.7%／読む側 8.4%**（直近28日）。
- ただし**やってみる側の実体はほぼ単一コンテンツ**（`/play/character-personality` 系が28日で 78.4%）。

**したがって「いま来ている人」と「これから来てほしい人」は分けて書く。** 前者は実測、後者はコンセプトからの導出である。

### 4. この作り直しで、これまでの7巡は無駄になるか

**ならない。** 規則群は捨てずに移すので、7巡かけて直した内容（事実の誤り・論理の穴・一次資料との食い違い）はそのまま生きる。
**変わるのは、どの文書に置くかである。**
