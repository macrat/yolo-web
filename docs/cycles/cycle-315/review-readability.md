## (A) ツギハギが残っていないか

#### A-1. 「担い手は3つ」と言った直後に4つ目が足されている（`DESIGN.md` 20・36-38・148行）

20行: 「**無彩のまま個性を出す担い手は3つ。**」

#### A-2. §1 の署名と §5 の格子が、ほぼ逐語で二度書かれている（30-34行 / 128-130行）

#### B-2. 「面」が4つの意味で使われ、どこにも定義がない（`DESIGN.md` 全編）

160行: 「**押せるものは、下線か反転を必ず持つ。押せないものは、どちらも持たない。** これが操作を色なしで示す土台である。」

#### B-9. 「1.4 倍」から列挙された値が再現できない（`DESIGN.md` 107行）

107行: 「スケールは本文から 1.4 倍（1.0625 / 1.5 / 2.06 / 2.94 / 4.06rem）」
1.0625 × 1.4ⁿ は 1.4875 / 2.0825 / 2.9155 / 4.0817 で、列挙値との比は 1.412 / 1.373 / 1.427 / 1.381 とばらつく（丸めの向きも桁数も揃っていない）。段を足す読者は、1.4 倍を計算するのか列を引き継ぐのかを決められない。

#### B-10. 略語がそのまま置かれている（`DESIGN.md` 266行）

266行: 「枠は最初から確保され、**CLS を出さない**。」
文書の中で唯一の略語で、展開も説明も無い。「読み込み中に枠がずれない」と書けば説明は要らない。

#### B-11. 「コード区画」がここにしかなく、何の書体で組むのかが無い（`DESIGN.md` 51行・99行）

51行は `--paper-2` の用途に「コード区画」を挙げるが、コードについての規定は他に一つも無い。99行「本文にモノスペースを使わない。」とどう両立するのか（コードは何で組むのか）が読み取れない。

#### B-12. 「すべての欧文」と指定された範囲が一致しない（`DESIGN.md` 86行）

86行: 「**IBM Plex Sans**（ウェイト400・600）。**見出しを含むすべての欧文**（`unicode-range: U+0000-007F`）」
`U+0000-007F` は ASCII だけなので、アクセント付きラテン文字も欧文の記号類も入らない。「すべての欧文」と範囲指定のどちらが規定なのかが決まらない。

#### B-13. 読み幅と操作幅で単位が違う理由が無い（`DESIGN.md` 132行）

132行: 「読む面（`--measure`）と操作面（`--max-width: 960px`）」
`--measure` は `40rem`（105行）なので既定サイズの変更に追従するが、`--max-width` は px なので追従しない。104行「**ルートの文字サイズを固定しない。** 来訪者がブラウザで既定を大きくしたら、本文もそれに従って大きくなる。」を読んだ後だと、操作面だけ追従しないのが意図なのか漏れなのか判断できない。

#### B-14. 一覧の行が持つ「種別」の値域が無い（`DESIGN.md` 191・203行）

191行「行は**品名・ひとこと・種別**を持つ。」／203行「**種別で絞り込める。**」
「種別」が何の分類なのか（形式なのか、話題なのか）が書かれていないため、絞り込みの UI を設計できない。「品名」「ひとこと」もこの文書だけの語で、初出時に説明が無い。

#### B-15. 状態変化にだけ時間の規定が無い（`DESIGN.md` 252行）

252行: 「**器の動きは3つだけ**——**結果の登場**（1回・250–400ms）、**操作フィードバック**（150ms 以下）、**状態変化**（開閉）。」
3つのうち2つには時間があり、3つ目には無い。任意なのか、書き漏れなのかが分からない。

#### B-16. `--paper` / `--ink` の別名が終盤で初出する（`DESIGN.md` 247行）

247行: 「**共有画像**: **紙地・墨**・全幅の主罫・見出し書体。」
「紙地」「墨」はここにしか出ない。トークン名で書けば読者は §2 に戻って確認できる。

#### B-17. 太字が多すぎて、規定と地の文の区別がつかない（両文書）

`DESIGN.md` 160-161行、`site-concept.md` 28-33行のように、段落のほぼ全文が太字になっている箇所が多数ある。**強調が常時なら強調ではない**ので、初読者は「必ず守る一行」を拾えず、全文を等速で読む負担を負う。`DESIGN.md` 112行が「**強調**: 太字は一段落に一箇所まで。」と定めている以上、この文書自身がその形を見せていないのは説得力も損なう。

#### B-18. 文書内で辿りにくい指示語（`site-concept.md` 20行、`DESIGN.md` 97行）

`site-concept.md` 20行: 「上のゴールを達成するための骨格である。**この3つを守ることが…**」——「この3つ」は引用の3段落を指すと推測できるが、直後の「一文ずつの意図」が8つの見出しに割っているため、3と8の関係が読み取れない。
`DESIGN.md` 97行: 「和文と欧文の分担（上）はこの対象ではない」——「（上）」が §3 の3行上の項目を指すのか表を指すのかが特定できない。

#### B-19. 「一文ずつの意図」の単位が文ではない（`site-concept.md` 24行）

24行の見出しは「## 一文ずつの意図」だが、14行の一文「AI が全自動で作り続けているから、面白いものがここにあります。」は43行と62行の2つの見出しに割られている。52行では文書自身が「**この句は**ターゲットを決める語ではない」と句と呼んでいる。見出しと中身が食い違う。

#### B-20. `site-concept.md` が何を作るサイトの話なのかを書いていない

「もの」「コンテンツ」（134行）とだけ書かれ、記事なのか道具なのか遊べるものなのかが最後まで示されない。唯一の手がかりは10行の否定例「記事を分割してページ数を稼ぐ」である。41行「定番のものを、より良く作り直そうとする。それは他所の土俵である」を実際の判断に使うには、何の定番の話かが要る。
