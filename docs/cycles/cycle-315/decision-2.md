# 調査を受けた判断——site-concept.md をどう直すか

Owner の指示で3点を調べた結果（[concept-gap.md](./concept-gap.md)）、成果物に3つのずれが見つかった。
**7巡のレビューはいずれもこれを捉えていない**——レビューは完了条件と指摘への対応を見るもので、「そもそもこれはコンセプトか」を問う枠が無かった。

| #   | ずれ                               | 実測                                                                                                                  |
| --- | ---------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 1   | **提供価値が書かれていない**       | 「入力すると結果が出る」はあるが、**誰のどんな課題が解けるのかが無い**。Kotler の言う consumer terms になっていない   |
| 2   | **Surface 層の判断が混じっている** | 「デザインへ渡すもの」1,561文字（20.6%・最大の節）が WCAG の等級を指定している。Garrett の5層ではこれは Surface 層    |
| 3   | **文書名と中身がずれている**       | 「サイトコンセプト」を名乗るが、「このサイトは何か」は 509文字（6.7%）。規則群が 51.0%、全体の約9割が正体ではなく規則 |

## 判断

### 1. 提供価値を足す——直す

**これは素の欠落である。** ターゲットの不在には理由があるが（cycle-278 のオーナー指示で仕組みごと廃止）、提供価値の不在には理由が見当たらない。

一般的な定義がそろって求めている——Kotler「消費者の言葉で表現されたもの」、JMR「メリットは何か」、Garrett「User Needs」、デジタル庁「利用ニーズの特定」、ISO 9241-210。

**足す内容は「来訪者は何を得るのか」である。** ただし**特定の誰かを想定しない**——ターゲット定義は廃止されているので、
「検索してここへ来た人が何を得るか」という形で書く。

### 2. Surface 層の判断を `DESIGN.md` へ移す——直す

**WCAG の等級をどこに置くかの判断**である。いまは `site-concept.md` が「等級 AA を下限とする」と決めている。

Garrett の5層では、これは Surface 層（スタイルガイド）の判断である。**`DESIGN.md` が持つべきものを、コンセプトが持っていた。**

**ただし全部を移さない。** 「外部の要件に従う」こと自体はコンセプトの側にあってよい——
「AI が作り、誤りうる」から「来訪者を選ばない」ことが導けるためである。**移すのは等級の指定（AA か AAA か）という具体の選択だけ**とする。

### 3. 文書を分割するか——**しない**

3つの道を検討した。

| 案                           | 内容                                                          | 判断                                                                                                |
| ---------------------------- | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| **分割する**                 | `site-concept.md` を正体だけにし、規則群を新しい文書へ移す    | **採らない**（下記）                                                                                |
| **文書名を変える**           | 「サイトコンセプト」→「サイトの判断基準」                     | **採らない**。Owner が `site-concept.md` を名指しで指定しており、名前を変えると指示との対応が切れる |
| **分割せず、性格を明示する** | 1文書のまま、「正体」と「そこから導く規則」の関係を構造で示す | **採る**                                                                                            |

**分割を採らない理由。** 分割すると、規則がコンセプトから導かれているかを確認しにくくなる。
本サイクルで判明した最大の問題は「**規則の多くが正体から導かれていない**」ことだった（自分で分類して (a) 正体由来7件・(b) 観測由来16件・(c) 外部要件9件と数えている）。
**離せば、その検証がさらに遠のく。** 近くに置いて、導出されていないものは「導出されていない」と明示するほうが、次に読む人が扱える。

**この文書は「判断基準として引くもの」として設計されている**（射程にそう書いた）。規則が多いことは、その設計の帰結であって、それ自体は誤りではない。
**誤りは、名前と中身のずれを明示していないことである。** 冒頭の射程でそれを述べる。

## この判断の限界

**「分割しない」は、一般的な定義（Garrett の層分離・Pichler のビジョンと戦略の分離）とは逆方向である。**
一般論に反する選択をしているので、その理由を上に書いた。**次のサイクルがこれを見直すときは、上の理由が今も成り立つかから確かめること。**
