## (2) 実行できない手順 — 6件

### 2-1 コントラスト「Chromium の canvas から実測して比を出す」

比を出すには2色の**組**を決める必要があるが、画素からどれを文字とし、どれをその背景とするかを決める方法が書かれていない。文字の縁はアンチエイリアスされるので、拾う画素で比が変わる。
さらに、`DESIGN.md` が比の要件を掛けている対象のうち、**既定の描画に出ない状態**——§6 の hover（細いボーダー）・フォーカス（二重リング。§6 は「内外のどちらかが 3:1 を満たす」と個別に規定）・訪問済み（`--ink-2`）・無効（破線・`--ink-2`）・§8 のエラーの太いボーダー——を、どう出現させて測るかが無い。テーマ（light/dark）のどちらで測るかも書かれていない。

### 2-2 色の直書きの `grep`

実際に走らせると `src/` で `oklch(` が51件、16進数が778件当たる。当たりには
`src/app/globals.css` の**トークン定義そのもの**（`--paper: oklch(0.975 0.006 90);`）と、コンテンツの色（`accentColor: "#16a34a"` 等）が含まれる。
手順は当たった件を合否に振り分ける基準を持たないので、grep の結果からは何も判定できない。（1-3 と同じ行）

### 2-3 タップターゲット「押せる要素の矩形を測る」

§6 が「ラベルを含む行全体」をタップターゲットと定めているラジオボタン・チェックボックスでは、押せる要素（20px の円／四角）の矩形を測っても 44px の判定にならない。本文中のインラインリンクも、測れば全件が不合格になる。測る対象を決める規則が無いため、この手順では §6 への適合を判定できない。（1-1 と同じ行）

### 2-4 文字サイズ 200%「ルートの `font-size` を2倍にして描画する」

手順は描画までで終わっていて、「内容が欠けない」をどう判定するかが無い。出力は画像なので、**機械で確かめる**の列にありながら、合否は人が見るまで出ない。

### 2-5 静止画4枚で判定できない項目が、目で確かめるに入っている

- 「一律の fade-in やスクロール連動の登場アニメが無いか」——動きは静止画に写らない。
- 「操作が色だけで示されていないか」のうち、§6 が状態へ割り当てた見え方（hover の細いボーダー・フォーカスの二重リング・訪問済みの `--ink-2`・無効の破線）は、読み込み後に1枚撮るだけでは画面に出ない。`take-screenshot` の `take.ts` は `setViewportSize` → 撮影で、hover もフォーカスも作らない。

### 2-6 Web フォント「読み込み前後でレイアウトの矩形を比べる」（minor）

`font-display: swap` では「読み込み前」は一過性の状態で、フォント要求を止めるなどの作り方が要る。その作り方が書かれていないため、比べる2つの状態のうち片方を取れない。
