# デザインモックによる検証

`DESIGN.md` のとおりに画面を組み、**実現できるか**と**魅力的か**を実物で確かめた。
モックは素の HTML と CSS だけで作った（画像なし・JavaScript なし）。3つの面を1枚に並べている——一覧・入力のある面・結果のある面。

## 実現できるか——できる

| 規定                      | 実測                                   |
| ------------------------- | -------------------------------------- |
| 本文 17px                 | 17px                                   |
| 読む幅 `--measure: 40rem` | 640px                                  |
| 主見出し 65px（広い画面） | 65px。しっぽり明朝が実際に当たっている |
| 角丸 0px                  | 0px 以外の要素 **0件**                 |
| 影を使わない              | `box-shadow` を持つ要素 **0件**        |
| タップ標的 44px           | 一覧の行 86px・ボタン 57px             |
| 320px で横スクロールなし  | 出ない                                 |

**特別な仕掛けを必要としなかった。** 罫・余白・書体・反転だけで組めている。

### この検証の1回目は、書体を確かめていなかった

**1回目の記録は「しっぽり明朝が実際に当たっている」と書いたが、誤りだった。**
根拠にしたのは `document.fonts.check()` が `true` を返したことだが、**この API は存在しない書体名でも `true` を返す。** 検証になっていない。

実際には Web フォントの要求が証明書の検証に失敗しており、**読み込まれた書体は0件**だった。
正しい確かめ方は、書体を変えて文字列の幅を測ることである——実測すると、明朝指定・`serif`・存在しない書体名の3つが**すべて同じ幅**（795.23px）だった。**画面に出ていたのは全部フォールバックのゴシックである。**

書体をローカルに置いて読み込ませ、撮り直した。読み込まれた書体は122件、明朝指定の幅は 780.00px でフォールバック（795.23px）と異なる。**このとき初めて、担い手2が画面に現れた。**

## 魅力的か——担い手が実際に効いている

- **巨大な明朝の見出し**が画面の顔になっている。既定 sans の画面とは一目で違う。**フォールバックのゴシックで見ていたときとは別物で、担い手2の効き方はここで初めて確かめられた。**
- **端まで届く罫と、内容を挟む縦罫**が、画面全体を一つの格子に見せている。
- **反転した主操作・破線の無効・円と四角の選択記号**が、色を一切使わずに操作を区別している。
- **無彩の器の上で、藍色の見本だけが色を持つ。** 器と中身が混ざらない。
- ダークでも同じ構造がそのまま成立する。

## 見て初めて分かった欠陥——`DESIGN.md` を5点直した

| #   | 何が起きたか                                                                                      | 直したこと                                                           |
| --- | ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 1   | 縦罫が `--max-width` より広い画面でしか出ず、**狭い画面で格子が横帯だけになった**                 | **幅を問わず縦罫を通す。** 狭い画面では画面の左右端に接する          |
| 2   | 節の余白を縦罫の外側に取っていたため、**節の境目で縦罫が切れた**                                  | 縦罫は上端から下端まで途切れさせない。**節の余白は縦罫の内側に取る** |
| 3   | 見出しを読む幅に閉じ込めたため、**65px の見出しが語の途中で折れた**（「見つからないも／のを、」） | **`--measure` は本文にかける。見出しはこの制約を受けない**           |
| 4   | 自動の折り返しに任せると、見出しが意味と無関係な位置で折れた                                      | **見出しは意味の切れ目で折る。** 実装で改行位置を決めてよい          |
| 5   | 一覧の種別ラベルが右端に居座り、**狭い画面で品名が「藍色（あいい／ろ）」と折れた**                | **狭い画面では種別を品名の下に落とす**                               |

**5件とも、文書を読んでいるだけでは見つからなかった。** 規定どうしは矛盾しておらず、**組んで初めて結果が見えるもの**だった。

## この検証で確かめていないこと

- **実機の表示**（Windows の游ゴシック・Android の書体解決）。モックはヘッドレス Chromium 1つで確認した。
- **明朝 Web フォントの転送量**。しっぽり明朝 500 の配信実体は122分割・合計約 3.7MB で、**サイト全体を賄う量ではない。** 面ごとに必要な字だけを配信する前提が要る。
- **フォーカスの見え方**。静止画では確かめられないため、実装時に操作して確認する。
