# T5: `DESIGN.md` をコンセプトから導出する骨格——4案

新 `docs/site-concept.md` が `DESIGN.md` に渡すのは**5つの制約**である。**どんな様式でそれを満たすかは `DESIGN.md` が選ぶ。**

| 正体のどこから      | 制約                                                       |
| ------------------- | ---------------------------------------------------------- |
| あらゆる題材を扱う  | 全体の作りは一貫していなければならない                     |
| その場でためせる    | 入力と結果が主役。それを載せる枠組みが目立ってはならない   |
| 結果を持ち帰れる    | 成果物は単体で（サイトの文脈なしで）成立しなければならない |
| AI が作り、誤りうる | 誤りを隠す装飾をしない。確からしさを演出で作らない         |
| 量より質（rule 4）  | 面の数を増やす方向の設計をしない                           |

## 先に確かめておくこと——制約だけでは様式は決まらない

**5つの制約を満たす様式は1つではない。** 少なくとも2つある。

- **紙と墨**（現行の様式）: 生成りの地・墨の字・朱一色のアクセント・罫で組む・明朝の見出し×ゴシックの本文。
- **無装飾のモダン**: 白地・黒字・サンセリフ・余白で組む・色はほぼ使わない。

**どちらも5つの制約を満たす。** 一貫していて、枠組みが目立たず、成果物を独立させられ、演出的な装飾を持たない。

**では何が分けるか。** 現行 `DESIGN.md` はここに観測を置いている——

> 差別化の最大の層は日本語の組版と文章の自然さ（調査: 信頼を壊す第1因子＝日本語の不自然さ 40.91%）
> 「明朝の見出し×ゴシックの本文」は日本の編集デザインの正統で、AI 量産サイト（全ページ同一の既定 sans）から最も遠い顔を作る

**つまり様式の選択は、制約からではなく観測から来ている。** 無装飾のモダンは AI 量産サイトの典型そのものであり、
**制約4（誤りを隠す装飾をしない）を満たしながら、同時に「AI が雑に作った」という見た目に接近してしまう。**

**この事実は、どの案を採るにせよ `DESIGN.md` に明示しなければならない。**
「様式は制約から導いた」と書けばそれは嘘になる。**制約が候補を絞り、観測が1つを選んだ**——その順序を書く。

## 判断基準

| #     | 基準                                                         | なぜ見るか                                                                                                                                                                                                                                   |
| ----- | ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## 案1: 制約から組み直し、様式は選び直したうえで据える（白紙起草）

`DESIGN.md` を白紙から書き起こす。構成は制約から立て、様式は「紙と墨」を**選び直したものとして**据える（現行の踏襲ではなく、判断としてやり直す）。

**構成の骨格:**

> 1. 何を決める文書か／様式をどう選んだか（制約が絞り、観測が選んだ順序を明示）
> 2. 外が決める下限（WCAG 2.2 から直接引く。コントラスト・文字サイズ・タップ標的）
> 3. 色
> 4. 文字と組版
> 5. 間隔と罫
> 6. 動き
> 7. 言葉
> 8. 成果物（持ち帰るもの・共有されるもの）
> 9. 広告との同居
> 10. やらないことの一覧（機械で検査できるもの／目で見て確かめるもの）
> 11. この文書の地位と、いつ見直すか

- **基準1**: 節が役割で分かれるため、止まっている17件の各項目がどの節の管轄かが決まる。**判定できるようになる。**
- **基準2**: **最も強い。** 各規則の冒頭で「どの制約から来たか／外が決めているか／観測から選んだか」を示せる。
- **基準3**: 現行の入れ子（§4 の識別マークの3層条件）を解体できる。
- **基準4**: **最も強い。** 来歴が構造的に入らない。
- **基準5**: **最も弱い。** 節番号が全部変わり、`src/` の §参照 1,245件がずれる。本サイクルでは直せない。

## 案2: 現行の11節を保ち、店語彙を置換して来歴を落とす（最小変更）

節番号と節の役割を保ったまま、(a) 店語彙を平明な語へ置換、(b) 来歴・実測データ・「正典」「本丸」を落とす、(c) §1 をコンセプトの制約から書き直す。

- **基準1**: 現行の規則がそのまま残るので、判定できる項目の数は変わらない。**いま判定できないものは判定できないまま。**
- **基準2**: **弱い。** 現行の規則は cycle-278 のコンセプト（よろず屋）から導かれており、**新コンセプトからの導出になっていない。** §1 だけ差し替えても、§2〜§10 の規則がそこから導かれている保証がない。
- **基準3**: §4 の肥大は構造の問題なので、語の置換では解けない。
- **基準4**: **弱い。** 「置換した跡」が構造に残る。節の並びが旧コンセプトの順序のまま。
- **基準5**: **最も強い。** §参照がずれない。

## 案3: 「外が決める下限」と「こちらが選んだもの」を構造的に分離する

文書を2部に分ける。**第1部＝動かせないもの**（WCAG 2.2・法令・プラットフォーム要件）、**第2部＝こちらが選んだもの**（様式・色・書体・間隔）。
第2部の各項目には、その選択がどの制約とどの観測から来たかを添える。

- **基準1**: 判定するとき「これは動かせない違反か、選択の不一致か」が即座に分かる。**止まっている17件のうち、外部要件に当たるもの（コントラスト・タップ標的・文字サイズ）が明確に切り分けられる。**
- **基準2**: **強い。** 導出できないものが第1部に隔離される。
- **基準3**: 強い。ただし**実装者は「色について知りたい」ときに2箇所を見る**ことになる（第1部のコントラスト要件と第2部の色の選択）。
- **基準4**: 強い。
- **基準5**: 案1 と同じく弱い。

## 案4: 5つの制約それぞれを節にする

制約1〜5 をそのまま5節にし、各節でその制約を満たす具体（色・字・罫・間隔）を書く。

- **基準1**: **弱い。** 「文字サイズが規範の下限を割っている」（B-676）を判定したいとき、どの制約の節を見ればよいか決まらない——文字サイズは制約1（一貫）にも制約2（枠組みが目立たない）にも関わる。
- **基準2**: **最も強く見えるが、見せかけである。** 制約と具体が1対1に対応しないため、**同じ具体が複数の節に現れるか、恣意的にどれかの節へ割り振られる。**
- **基準3**: **最も弱い。** 引く者は「色の規則はどこか」を探せない。
- **基準4**: 強い。
- **基準5**: 弱い。

**捨てる。** 導出の筋道を構造にすると読めなくなる。**導出は各規則に添える注記で示せば足りる**（案1・案3 がそうする）。

## 選定——案1 を骨格に、案3 の分離を節の中で行う

**案1（白紙起草）を採る。** ただし案3 の「外が決める下限とこちらが選んだものを分ける」は、**文書を2部に割るのではなく、各節の中で行う。**

**理由。**

**基準2 が決め手である。** 案2（最小変更）は節番号を守れるが、**§2〜§10 の規則が新コンセプトから導かれている保証がない。**
現行の規則は「よろず屋の店構え」から導かれたものであり、その前提を外した以上、**各規則を導出し直さなければ、旧コンセプトの遺産が新しい看板の下で生き続ける。**
これは cycle-310 が犯した誤り（実デザインを先に決めて後からコンセプトを書き換える）と、向きが逆なだけで同じ型である。

**案3 を2部構成にしない理由。** 実装者が「色について知りたい」と思ったときに2箇所を見るのは、基準3（迷わず1つの答えに到達）を損なう。
**同じことは各節の中でできる**——たとえば色の節に「AA 4.5:1 以上は WCAG 2.2 が決めている下限である／その下限を満たす中でどの色を選ぶかは、次の観測から決めた」と書けばよい。

**基準5（実装との距離）は、案1 の代価として引き受ける。**
`src/` の §参照 1,245件がずれるが、**本サイクルは `src/` を触らない**と決めており、この是正は B-672（ソースコードのコメントに経緯が残っている・着手条件「B-651 の後」）の射程である。
**ずれることを承知で節構成を変える。** 節番号を守るために旧コンセプトの構成を保つことは、**参照の維持のために規範の正しさを犠牲にすること**であり、`CLAUDE.md` の意思決定原則（実装コストを理由に劣る方を選ばない）に反する。

### 決定の内容

1. **`DESIGN.md` を白紙から書き起こす。** 現行は最後に「落ちている規則が無いか」の照合にのみ使う。
2. **様式は「紙と墨」を据える。ただし「制約から導いた」とは書かない**——制約が候補を絞り、観測（何が信頼を壊すか）が1つを選んだ、という順序で書く。
3. **各節の中で、「外が決める下限」と「こちらが選んだもの」を書き分ける。** 外部規範は **WCAG 2.2** として明示的に引く（現行は「WCAG」の文字列が0件で、等級名「AA」だけで引いている）。
4. **来歴を入れない。** 実測データ（コントラストの計測値・モバイル比の生データ）は、**規範としての値だけを残し、計測の経緯はサイクル文書に置く。**
5. **「正典」「本丸」を使わない。**
6. **節番号が変わることを受け入れる。** `src/` の §参照のずれは B-672 で扱う（本サイクルのキャリーオーバーに記録する）。
