# T5: `DESIGN.md` をコンセプトから導出する骨格——5案

> **⚠ この文書は、サイトコンセプトが確定する前に作られた。** 入力に置いた「`decision.md` §8 が渡す制約」は、
> **4巡目のレビュー中で未確定の `docs/site-concept.md` から取ったものである**（経緯は [incident-2.md](./incident-2.md)）。
> **コンセプトが確定したら、その時点の制約で全体を見直すこと。** 選定（案5）も、その見直しを経るまで決定ではない。

> **1巡目（4案）は REJECT された**（[review-t5.md](./review-t5.md)・Blocker 6 / Major 8）。
> 制約表の引用が自分の決定と食い違い、様式の決め手にした数字は**向きが逆**で、節の構成は現行の規則を受け止められなかった。ここで立て直す。

## 入力——`decision.md` §8 が渡すもの（逐語で引く）

1巡目はこれを引き写す際に「その場でためせる」を別物に書き換え、4項目を落としていた（レビュー B2）。**逐語で引く。**

**(1) 正体から導かれるもの**

| 正体のどこから      | 制約                                                                                           |
| ------------------- | ---------------------------------------------------------------------------------------------- |
| あらゆる題材を扱う  | 題材が変わっても作りが変わらないこと。来訪者が別のサイトに来たと感じる状態を作らない           |
| その場でためせる    | **入力と結果に最短で到達できること。待たせない・探させない・主操作を折り返しの下へ落とさない** |
| 結果を持ち帰れる    | 成果物が単体で成立すること。サイトの文脈なしで何の結果か読み取れる                             |
| AI が作り、誤りうる | 確からしさを演出で作らないこと。見た目の作り込みで信頼を調達しない                             |

**(2) constitution から直接来るもの**: rule 4 から「面の数を増やす方向の設計をしない・分類と回遊を設計する」、rule 2 から「煽らない・出し惜しみしない・偽の限定を作らない」。

**(3) 外部が決める下限**: WCAG 2.2。

**(4) 観測から来るもの**: モバイルを前提に組む。ただし面によって比率が大きく違うため単一デバイス想定は禁物。

## 外部の下限を正確に引き直す（T0 の確認結果）

1巡目は「44px・16px が外の下限」と書いたが、**どちらも誤りだった**（レビュー M6）。[index.md](./index.md) の T0 確認結果に照らして訂正する。

| 成功基準                     | 等級    | 要件                                                                                |
| ---------------------------- | ------- | ----------------------------------------------------------------------------------- |
| 1.4.3 Contrast (Minimum)     | **AA**  | 本文 **4.5:1** 以上／大きい文字（18pt または 14pt bold 以上）**3:1** 以上           |
| 1.4.11 Non-text Contrast     | **AA**  | UI 部品の識別に必要な視覚情報・内容理解に必要な図が、隣接色に対し **3:1** 以上      |
| 2.5.8 Target Size (Minimum)  | **AA**  | **24 × 24 CSS px** 以上（Spacing・Inline 等の5例外あり）                            |
| 2.5.5 Target Size (Enhanced) | **AAA** | 44 × 44 CSS px 以上                                                                 |
| 1.4.4 Resize Text            | **AA**  | 200% まで拡大してもコンテンツ・機能を失わない。**最小フォントサイズは定めていない** |

**したがって: 44px は外の下限ではなく、AAA を採るという選択である。16px の本文下限も外の要件ではない。**
どちらも「こちらが選んだもの」として書かなければならない。

## 様式の決め手についての訂正

1巡目は「制約が候補を絞り、**観測が1つを選んだ**」と書き、その観測に「日本語の不自然さが信頼を壊す第1因子 40.91%」を置いた。**これは使えない。**

- **向きが逆である。** この数字は「**視覚ではなく日本語**が信頼を壊す」ことを示す（2位のデザイン違和感は 14.77%）。
  **視覚様式の選択が二次的であることの根拠**であって、ある視覚様式を選ぶ根拠ではない。
- **単独の根拠にしないと既に決まっている。** `cycle-311/concept-decision.md` 実測7 が「母集団の拡張なので補助的な傍証として扱い、単独の根拠にしない」と決定している。
- もう一方の根拠（「日本の編集デザインの正統／AI 量産サイトから最も遠い顔」）は**研究文書に存在せず**、書き直し対象の `DESIGN.md` 自身の記述だった。

**結論: いま手元に、ある視覚様式を選ぶ根拠は無い。** この事実が、以下の案の分かれ目になる。

## 判断基準

1巡目は5基準のうち4つが文書と実装者の都合だった（レビュー M1）。立て直す。

| #     | 基準                                               | なぜ見るか                                                                                                                                     |
| ----- | -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **1** | **来訪者の画面の欠陥が、いくつ直せる状態になるか** | 止まっている17件のうち**来訪者の画面に現れるのは10件**。文書の目的はこれを動かすことである                                                     |
| **2** | **来訪者に届く体験の下限が上がるか**               | コントラスト・文字の大きさ・タップ標的・速さは、来訪者が直に受け取るものである                                                                 |
| **3** | **書いてあることが本当か**                         | 導出していないものを導出したと書かない。外の下限でないものを下限と書かない。**嘘を規範に焼き付けない**                                         |
| **4** | **引く者が迷わず1つの答えに到達できるか**          | 現行 §4 は識別マークの項が1段落で数千字あり、条件の入れ子が3層ある                                                                             |
| **5** | **既存の参照が指す先を保てるか**                   | `src/` の `DESIGN.md` 名指しコメント **169行/155ファイル**、裸の `§N` 参照 **681件**、および `.claude/skills/frontend-design/SKILL.md` の8箇所 |

## 案1: 制約から組み直し、様式も選び直して据える（白紙起草・様式あり）

構成を制約から立て、様式（紙と墨）を**選び直したものとして**据える。

- **基準1**: 節が役割で分かれ、17件の受け皿ができる（ただし後述の受け皿検証が要る）。
- **基準2**: 下限を書き直せる。
- **基準3**: **満たせない。** 様式を選ぶ根拠が手元に無い以上、「選び直した」と書けば嘘になる。
- **基準4**: 強い。
- **基準5**: 弱い。

**捨てる。** 基準3 で落ちる。**根拠の無い選択を「導出した」と書くことは、この文書が5サイクル繰り返してきた失敗そのものである。**

---

## 案2: 現行の11節を保ち、語彙を置換して来歴を落とす（最小変更）

- **基準1**: いま判定できないものは判定できないまま（受け皿が増えない）。
- **基準2**: 下限は現行のまま（44px を AA と誤記したままになる）。
- **基準3**: 現行の規則が新コンセプトから導かれている保証がない。
- **基準4**: §4 の肥大は構造の問題なので語の置換では解けない。
- **基準5**: **最も強い。**

**捨てる。** 基準1・2 で何も前に進まない。

---

## 案3: 様式を無装飾側へ振る

紙と墨を降ろし、白地・黒字・サンセリフ・余白で組む。

- **基準3**: **満たせない。** 無装飾を選ぶ根拠も手元に無い。しかも手元の調査はむしろ「シンプルで清潔感 13.47%・読みやすさ 13.13%」が信頼要因だと示しており、
  1巡目が書いた「無装飾＝AI 量産サイトの典型」には**出典が無い**（レビュー M8）。
- 他の基準は案1 と同等。

**捨てる。** 案1 と同じ理由で落ちる。**根拠が無いのは紙と墨だけではない。**

## 案4: 5つの制約それぞれを節にする

- **基準1**: 弱い。「文字サイズが下限を割っている」（B-676）を判定するとき、どの制約の節を見るか決まらない。
- **基準4**: **最も弱い。** 引く者は「色の規則はどこか」を探せない。

**捨てる。** 導出の筋道を構造にすると読めなくなる。導出は各規則に添える注記で示せば足りる。

## 案5: 様式を未決のまま、下限と制約を確定する

**様式を選ばない。** 代わりに次を確定する。

1. **外が決める下限**（WCAG 2.2 を正確に引く）
2. **コンセプトから導かれる制約**（decision.md §8 の4層）
3. **いま採っている様式の記述**——紙と墨を「**現在そうなっているもの**」として記述し、**それを選んだ根拠が手元に無いことを明記する**
4. **様式を見直す条件**——何が観測されたら選び直すか

**なぜこれで足りるのか。** 止まっている17件を1件ずつ当ててみると、**様式に依存するのは4件だけである。**

| 様式に依存しない（13件） | 内容                                                     |
| ------------------------ | -------------------------------------------------------- |
| B-654                    | 情報の境界に `--rule` を使っている（罫の用途の規定）     |
| B-656                    | 店語彙の内部識別子（語彙の規定）                         |
| B-660                    | 本文と見出しが値から外れている（**値の下限**の規定）     |
| B-667                    | 評価窓と読み返しの手順（プロセス）                       |
| B-668                    | 速度と代替テキストの下限が無い（**下限の追加**）         |
| B-669                    | 最小幅 375px と実測 360px の食い違い（**数値の確定**）   |
| B-671                    | 状態変化だけ時間の規定が無い（**数値の追加**）           |
| B-673                    | 疑問符・感嘆符の全角/半角の混在（組版の規則）            |
| B-676                    | 12px が下限を割っている（**下限の確定**）                |
| B-678                    | 絵文字にゲートが無い（禁止の追加）                       |
| B-679                    | 面を覆う幕がトークンを持たない（トークン化）             |
| B-681                    | 機械で判定できる項目に見張りが揃っているか（検査の整備） |
| B-670                    | 規範が自分に適用される射程（文書の規定）                 |

| 様式に依存する（4件） | なぜ                                                         |
| --------------------- | ------------------------------------------------------------ |
| B-659                 | 識別マークが罫を横断（識別マークを置くかどうかが様式の判断） |
| B-662                 | favicon が §4 と衝突（同上）                                 |
| B-677                 | 共有画像が濃紺の地を直書き（色の選択が様式の判断）           |
| B-682                 | 操作部品に信号色（同上）                                     |

- **基準1**: **13件が判定できるようになる。** 残る4件は様式が決まるまで待つ——**ただし「規範が無いから判定できない」ではなく「様式が未決だから待つ」と、理由が明確になる。**
- **基準2**: **最も強い。** 下限（コントラスト・文字の大きさ・タップ標的・速さ）を正確に確定することが、この案の中心である。
- **基準3**: **最も強い。** 根拠の無い選択を「導出した」と書かずに済む。**いま採っている様式は記述するが、正当化しない。**
- **基準4**: 強い。
- **基準5**: 案1 と同等に弱い（節構成が変わる）。

**代価**: 様式が未決のままなので、**新しく面を作るとき「どう見せるか」の判断は現行の実装に倣うことになる。**
これは現状追認であり、`decision.md` が避けようとしたことでもある。**ただし「未決である」と書いてあれば、次の PM は追認だと分かって扱える。** 黙って追認するのとは違う。

## 選定——案5

**採るのは案5 である。** 決め手は**基準3**——**書いてあることが本当か。**

案1・案3 はどちらも様式を確定するが、**そのどちらを選ぶ根拠も手元に無い。**
根拠が無いまま確定すれば、`DESIGN.md` に新しい嘘（「観測が様式を選んだ」）を焼き付けることになる。
**これは B-651 が5サイクル解けずにいる理由そのものである**——根拠の無い判断が「決定済み」の顔で積み重なり、次のサイクルがそれを岩盤として引用してきた。

**そして基準1 が示すとおり、様式を決めなくても13件が動く。** 本サイクルの目的（止まっている画面の修理を動かすこと）は、様式の確定を必要としない。

### 決定の内容

1. **`DESIGN.md` を書き直す。構成は次のとおり。**

   > 1. この文書が決めること／決めないこと（**様式が未決であることをここで明示する**）
   > 2. 外が決める下限（WCAG 2.2 を等級つきで正確に）
   > 3. コンセプトから導かれる制約
   > 4. 色
   > 5. 文字と組版
   > 6. 画面の骨格と部品の既定形（ヘッダ・一覧・クリック標的・本文幅と操作幅・角丸・間隔・罫）
   > 7. 動き
   > 8. 言葉
   > 9. 成果物（持ち帰るもの・共有されるもの）
   > 10. 広告との同居
   > 11. やらないこと（機械で検査できるもの／目で見て確かめるもの）
   > 12. いま採っている様式と、それを見直す条件
   > 13. この文書の地位

   **6 を独立させたのは、現行 §4 の大半（ヘッダ・一覧の既定形・クリック標的・読む幅／操作幅・角丸）が「間隔と罫」に収まらないためである**（レビュー B3）。
   cycle-313 が中止した4件（B-714/715/724/726——狭い画面での一覧・ページ送り・関連記事）も、この節が受け皿になる。

2. **節に番号を振らない。** 見出しの語で引く。
   1巡目は「節番号が変わる代価」を案1 の弱点として計上したが、**番号を捨てれば代価自体が消える**（レビュー B4——1巡目は偽の二者択一を立てていた）。
   **番号があると、ずれた参照が「もっともらしい別の節」を指したまま生き続ける。** 語で引けば、指す先が無くなったことが分かる。

3. **`.claude/skills/frontend-design/SKILL.md` を本サイクルで直す。** 同ファイルは `DESIGN.md` の §1〜§10 を8箇所で名指しし、
   「作業の型」第1項が節番号のルーティング表になっている。**`src/` でも `docs/` でもないので、本サイクルのスコープに入る**（レビュー B5——1巡目は代価として計上すらしていなかった）。
   これを直さないと、案2 を退けた理由（旧コンセプトの遺産が新しい看板の下で生き続ける）が別ファイルで起きる。

4. **禁止リストは、各項目の根拠を書き直す。** 現行11項目の根拠は「AI slop からの距離＝差別化」だが、**新コンセプトに「差別化」も「AI slop」も無い**（レビュー B6）。
   残す項目は「確からしさを演出で作らない」「煽らない」「待たせない」のいずれかに接地させ、**接地できない項目は落とすか、様式の項へ移す。**

5. **`src/` は触らない。** `§N` 参照 681件のずれは B-672 の射程である（本サイクルのキャリーオーバーに記録する）。
