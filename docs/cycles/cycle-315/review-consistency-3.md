### D-1. 「主リンク」「副リンク」「主リンク名」（L255）

- L254: `- **行は名前・ひとこと・種別を持つ。** ひとことは何ができるかを一文で言い、種別はそれが何の仲間かを一語で言う。`
- L255: `- **下線は名前に付く。** 押して反応するのは行全体で、行内の副リンクは独立に押せる。読み上げに渡る名前は主リンク名だけ。`

この3語は `DESIGN.md` のどこにも定義が無く、L255 の一文にしか現れない（`grep` 確認済み）。§7 が行について使う語は「名前・ひとこと・種別・行」だけなので、**「副リンク」が名前・ひとこと・種別のどれを指すのか、この文書だけでは決まらない。** また同じ一文の中で「名前」と「主リンク名」が併走するため、読み上げに渡す名前が行の名前と同じものなのか、別に用意する文字列なのかが読者に決められない。ここは実装が分岐する箇所である。

普通の日本語で言うと——主リンク = 行全体のリンク、副リンク = 行の中に置く別のリンク、主リンク名 = 行の名前。

**この3語は実装から入った語である。** `git log -S "副リンク" -- DESIGN.md` は `c969ab81`（cycle-281「移行UX回帰(カードのクリック領域劣化)をstretched-linkで是正」）を指し、当時の本文は「視覚単位全体を主リンクの標的にしつつ副リンクを独立に押せるようにする。スクリーンリーダーに読ませるのは主リンク名のみに保つ」だった。stretched-link とアクセシブル名という実装の語彙が、圧縮されたまま現行の文書に残っている（`docs/anti-patterns/planning.md` AP-P03 の「実装に固有の記述」）。

直し方: L255 を §7 自身の語だけで書く。例——「**下線は名前に付く。** 押して反応するのは行全体で、行の中に別のリンクを置くときは、それだけを独立に押せる。読み上げに渡る名前は、行の名前だけ。」
