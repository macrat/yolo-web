## (B) 今回の修正が生んだ新しい誤り

### Major

#### Major 1. 「面」の用例に1件だけ定義外が残り、同じものが4通りの名で呼ばれている（5・112・117・118・139行）

5行の定義「**「面」は、1つの URL で開く画面のことである。**」で、`面` の全27用例のうち26件は一貫した。**残る1件が 117行である。**

> 117行: 内容の左端は全ページで同じ位置。本文の幅（`--measure: 40rem`）と**面の幅**（`--max-width: 60rem`・既定で 960px）は同じ左端から始まり、右にだけ伸びる。

面は「1つの URL で開く画面」であり、111行によればその画面には**左端から右端まで伸びる全幅の横罫**がある。つまり面の幅は画面の幅であって 60rem ではない。ここで言っているのは面の幅ではなく、**内容を収める枠の幅**である。

さらに同じ枠が、近接した4行で4通りに呼ばれている。

| 行  | 呼び方       | 文                                                         |
| --- | ------------ | ---------------------------------------------------------- |
| 112 | 内容の枠     | 縦罫は…**内容の枠**の左右端を通り                          |
| 117 | 面の幅       | **面の幅**（`--max-width: 60rem`）                         |
| 118 | 外側の枠     | **外側の枠**を画面の中央に置き、内側の枠はその左端に揃える |
| 139 | （名前なし） | 一覧・入力・結果は `--max-width`                           |

2巡目 B-1 が指摘した「読む面／操作面」の改名で「読む面→本文の幅」は直ったが、「操作面→面の幅」は定義に反する側へ着地した。**枠に1つ名前を付け（例:「内容の枠」）、112・117・118・139 をその1語に統一する必要がある。**

#### Major 2. §6 の4分類に「現在地」が属さず、分類の宣言と表が正面から衝突する（146・158行）

146行の宣言は **「必ず」** で書かれている。

> **進む・実行するもの**（リンク・**ナビ**・一覧の行・ページ送り・主操作）は、**下線か反転を必ず持つ。**

158行の表は、そのナビの一項目について逆を言う。

> 現在地 | **下線を持たない。** 太字にし、他のナビ項目を `--ink-2` に下げる

現在地は「何も起こらないもの」なのか、それとも下線を持たないナビなのかが、どこにも書かれていない。**読者は「ナビ項目は必ず下線を持つ」と「現在地は下線を持たない」のどちらを採るかを決められない。** 現在地を押せるようにするのかどうかも決まらないので、実装は分かれる。

同じ穴が「無効」にもある。無効は 162行で **破線の枠**を持つが、146-149行の4つのどれでもない——進む・実行するものなら下線か反転が要り、何も起こらないものなら「どれも持たない」はずである。**4分類は「漏れなく重複なく」になっていない。**

#### Major 3. 132行の部品の列挙が閉じているのに、同じ文書が定義している4つが入っていない（132行）

> **面を組む部品は、見出し・本文・罫・一覧の行・入力・結果・操作の記号・帯である。**

「〜である」で閉じた定義だが、文書自身が別の場所で定義している次のものが入っていない。

| 欠けているもの   | どこで定義されているか                                                                  |
| ---------------- | --------------------------------------------------------------------------------------- |
| コード（の区画） | 46行（`--paper-2` の用途）・73行（等幅）・81行・115行（区画の対象）                     |
| 表               | 105行「`--rule-w-hair`…**表の内部**」                                                   |
| 図像             | 123行「図像が現れるのは、それが中身そのものであるときだけ——図解・地図・生成された画像」 |
| 色の見本         | 61行・105行・184行・236行                                                               |

2巡目 B-2 は「帯がこの列挙に無い」ことを指摘した。今回帯だけを足したため、**同じ欠落が4つ残った状態で列挙が閉じている。** 読者は「コードブロックは面に置けないのか」「表は罫の一種なのか」を決められない。とくにコードは、この巡で `--paper-2` の用途と区画の対象に新しく入った要素であり、**同じコミットの中で片方が追加され、もう片方が追加されていない。**

#### Major 4. エラーの「左端の太い棒」が、格子の縦罫と見分けられない（104・112・117・120・139・209行）

209行が新しく定めた記号はこうである。

> **入力欄の枠は `--rule-w-hair`。** エラーの欄は**左端に `--rule-w` の太い棒**を持ち、…

この棒が置かれる位置を、他の規定から追うとこうなる。

1. 139行: **入力は `--max-width`** の幅を持つ。
2. 117行: `--max-width` は内容の枠の幅である。
3. 112行: **縦罫は内容の枠の左右端を通り、上端から下端まで途切れない。**
4. 104行: 縦罫は格子の太い罫なので `--rule-w`（3px）。エラーの棒も `--rule-w`（3px）。

**つまり、エラーの棒は左の縦罫と同じ太さの垂直線が、同じ x に（あるいは 120行の「罫の内側に最低 16px の余白」を採るなら 16px 隣に）立つことになる。** どちらの読みでも、来訪者には「格子の縦罫が太くなった／二重になった」としか見えない。**色を使わずにエラーを示すという §8 の中核が、§5 の署名そのものに潰される。**

同時に、3つの規定が同時には成り立たない。

- 117行（`--max-width` = 縦罫が通る内容の枠の幅）
- 139行（入力は `--max-width` いっぱい）
- 120行（罫の内側に最低 16px の余白がある）

入力が枠いっぱいなら 16px の余白が無く、余白があるなら入力は `--max-width` ではない。**`--max-width` が縦罫の位置なのか、その内側の内容幅なのかが決まらない**（Major 1 と同じ根）。

なお、他の記号との衝突は無い——165行が「**閉じた** `--rule-w` の枠」と限っているので区画とは分かれ、下線は水平、反転は塗り、破線は実線と分かれる。**衝突しているのは縦罫だけである。**

#### Major 5. `--rule-2`（細罫）に使う場所が1つも無く、太さのトークンと色のトークンが結ばれていない（47・49・50・104・105行）

`--rule-2` の用途欄は「細罫」だが、**「細罫」という語は文書全体でこの1行にしか出ない。** どの罫が細罫なのかがどこにも書かれていないので、`--rule-2` は使い道の無いトークンとして残っている。

裏返しに、§5 の罫の表は太さ（`--rule-w` / `--rule-w-hair`）だけを決め、**色を一度も指定しない。** 結果、次が決まらない。

- 一覧の行の区切り・表の内部・入力欄の枠（すべて `--rule-w-hair`）の色は `--rule` か `--rule-2` か。
- 縦罫の色は。主罫は 138・140・235行でいずれも「全幅の横罫」を指しており、縦罫は主罫と呼ばれていない。

「細い罫＝`--rule-2`」と推測したくなるが、**61行が「色の見本は `--rule-w-hair` の `--ink` の枠を持つ」と明示的に `--ink` を当てているため、その推測は安全でない。** 2人の実装者は違う画面を作る。

`--ink` と `--rule` の用途欄がどちらも「主罫」である（47・49行）点も、同じ表の中の未整理である（Minor 17）。
