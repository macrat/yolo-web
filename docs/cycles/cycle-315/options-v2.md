# 2巡目: `docs/site-concept.md` をどう作り直すか

1巡目は「何を残すか」（[options-t1.md](./options-t1.md)）と「何を名乗るか」（[options-t2.md](./options-t2.md)）を別々に決め、どちらも REJECT された。
**分けたこと自体が誤りだった**——構造の根の中身は名乗りが決めるため、独立には決められない。
ここでは**文書全体を単位**として案を立てる。各案は「何を残すか」と「何を名乗るか」の両方を含む。

## 判断基準

1巡目の基準は3つとも「文書と後続工程の都合」で、**来訪者が一人も出てこなかった**（レビュー T1-B1）。立て直す。

| #     | 基準                                                                 | なぜこれを見るか                                                                                                                                                                                                                                                                                                                        |
| ----- | -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1** | **来訪者が「このサイトは何？」と思った瞬間に、何を受け取るか**       | この文書の自己定義は、トップ・`/about`・メタデータに流れて来訪者の目に触れる（現行 L21 が「実体が伴った時点で書き換える」と規定＝いずれ流れる）。**最優先。**                                                                                                                                                                           |
| **2** | **検索結果に並んだとき、他と見分けがついて、何が得られるか分かるか** | 検索が主な入口である。自己定義は `title`・`description`・OGP になる。来訪者が最初に見るのはページではなく検索結果の一行である。                                                                                                                                                                                                         |
| **3** | **この文書を引く者が、迷わず1つの答えに到達できるか**                | いま到達できないせいで35件が止まっており、うち**20件は来訪者の画面に現れる欠陥**である。止まっているのは文書整備ではなく画面の修理である。                                                                                                                                                                                              |
| **4** | **`DESIGN.md` を導出できるか**                                       | Owner は「作ったサイトコンセプトから自然に導出できる形の**デザインシステム**」を求めている。導出元になれないコンセプトでは次工程が成立しない。**ただしこれは Owner が「コンセプトをそういう形にせよ」と言ったのではない**——次工程を成立させるための、わたし自身の判断として置く（1巡目はこれを Owner の指示に帰属させた。誤読だった）。 |
| **5** | **ツギハギ禁止を満たすか**                                           | `CLAUDE.md` は「最初から正しく書かれたかのように読め、追加や変更の痕跡が一切残らない単一の状態」を求めている。**どこを直したか分かる文書は、それ自体が違反である。**                                                                                                                                                                    |

### 1巡目の基準から外したもの

| 外したもの                                                   | 理由                                                                                                                                                                                                                                      |
| ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 「削ぎ落とした先が存在するか」                               | ツギハギ禁止が求めているのは **strip out** であって、行き先の確保ではない。この基準は実質的に**保存バイアス**として働き、最も削ぎ落とす案を不当に不利にしていた（レビュー T1-M8）。                                                       |
| 「Owner の『自然に導出できる形』はこれで満たせる」という論拠 | **Owner 逐語で「自然に導出できる形の」が係るのはデザインシステムであって、コンセプトではない。** 実在する発言を本来かかっていない対象に付け替えていた（レビュー T1-B2・AP-P34）。基準4 自体は残すが、帰属を外して自分の判断として立てる。 |

### 検討したが基準に入れなかったもの

- **既存コピーとの連続性**（いま出ている文言からの飛び幅）。これは基準ではなく**決定に付随する実装タイミングの問題**として扱う。現行 L21「サイト上の自己表示の書き換えは、実体が伴った時点で行う／宣言を実装に先行させない」がその規則であり、採る案に関わらず適用される。
- **記憶に残るか（個性）**。基準2 に畳んだ——「他と見分けがつくか」は検索結果という具体の場面で問える。抽象的な「個性」のままでは、どの案も自分に有利に読める。

### 由来を訂正して読み直すと見えること

現行 L15 はこう書く。

> サイト名がそのまま正体を表す——**YOLO**（運営を AI に丸投げした実験サイト）×**よろず**（あらゆるコンテンツを扱う）のダブルミーニング。

一次資料の由来を当てはめると「**YOLO（人生一度きり）× よろず（万事・あらゆるもの）**」になる。**このとき「サイト名がそのまま正体を表す」という主張が崩れる。**

- **よろず**＝サイトが扱う**範囲**（あらゆるもの）。これはサイトの属性である。
- **YOLO**＝**姿勢**（一度きりだから、やってみる）。これはサイトの属性ではなく、**来訪者にも運営にも向く態度**である。

**2語は別の種類のものを指している。** 現行はこれを「ダブルミーニング」として同格に扱い、
そのために **YOLO の側を「運営を AI に丸投げした実験サイト」と読み替えて、両方をサイトの属性に揃えた。**
**その読み替えが、食い違いの発生源である。**

正しい由来から素直に読むと、2語は次のように噛み合う。

> **あらゆるものを（よろず）、一度きりの人生なんだから、やってみる（YOLO）。**

**ここで注目すべきは、「やってみる」が由来そのものから出てくることである。** 「運営の実験」からではない。
そして `cycle-309/grounding.md` §4 は、来訪者主語の「やってみる」を明示的に許している。**一次資料どうしが一貫する。**

**1巡目の決定（「屋（店）」を落とす）は、誤った由来を根拠にしていた。** 正しい由来に照らしても「よろず」はあるが「屋」は無いため、
**結論は変わらない見込みだが、根拠は差し替えが要る。** 案の比較でこれを扱う。

## 案（5案）

**軸を1本にしないために、次の5案を立てる。** 1巡目は「店語彙をどれだけ残すか」の1軸上に6案を並べただけで、
見かけの数の下で実質2択を再演していた（レビュー T2-B2）。今回は**文書の作り方そのものが違う案**を並べる。

各案について、**冒頭「このサイトは何か」の実物**を書く。ここが最も差の出る部分であり、要点の列挙では比較できないためである。

### 案A: 白紙起草——constitution と由来だけから書き起こす

現行文書を**入力にしない**。constitution（Goal と rule 1〜5）と、一次資料で裏付けの取れた由来だけを材料に書き起こし、
現行文書は最後に「落ちている論点が無いか」の照合にだけ使う。

**冒頭の実物:**

> ## このサイトは何か
>
> **yolos.net は、あらゆる題材で「その場でためせるもの」を作って置く場所である。**
>
> 名前がそのまま構えを表している。**よろず**は万事・あらゆるもの。**YOLO** は You Only Live Once——一度きりなんだから、やってみよう。
> 扱う範囲を狭めず、来訪者がその場で手を動かして何かを持ち帰れるものを作る。
>
> 来訪者に「ここは何ができるの？」と聞かれたときの答え: **「入力すると、あなた用の結果が出ます。診断・計算・変換・印刷物・あそび。」**
>
> 作っているのは AI である。人が書いたように見せかけない。内容が誤っていることがあり、それを隠さない。

- **基準1（何を受け取るか）**: 「入力すると、あなた用の結果が出ます」——**受け取るものを直接言っている。**
- **基準2（検索結果での見分け）**: 「あらゆる題材で、その場でためせるもの」は範囲を伝えるが、**他のツール寄せ集めサイトとの差は弱い。**
- **基準3（迷わず引けるか）**: 現行の堆積を引き継がないので、最も曖昧さが少ない。
- **基準4（`DESIGN.md` の導出）**: 導出元が「あらゆる題材」「その場でためせる」「AI が作る・誤りうる」の3つ。**細い。** 色や字の具体は出ない。
- **基準5（ツギハギ禁止）**: **最も強く満たす。** 定義上、痕跡が残らない。
- **代価**: 現行が持っていた観測由来の規則（参照型の敗北・評価窓・撤退基準）を拾い直す必要がある。照合で拾えるが、拾い漏らせば規範に穴が開く。

### 案B: 現行の像を保ち、可視面での店語彙を機械的に禁じる

「よろず屋」の像を**内部の設計語彙として保つ**。そのうえで、**来訪者に届く面（可視テキスト・`aria-label`・メタデータ・URL）での店語彙の使用を、機械的に検査できる規則として禁じる**。
現行 L9 の「自明に伝わると仮定しない」という弱い注意を、**検査可能な禁止**へ格上げする。

**冒頭の実物:**

> ## このサイトは何か
>
> **yolos.net は「AI が営む、『やってみる』のよろず屋」である。**
>
> 名前の由来は **YOLO**（You Only Live Once＝一度きり）と**よろず**（万事・あらゆるもの）。
> 「よろず屋」は、この由来からわたしたちが立てた**設計のための像**であって、名前の由来そのものではない。
>
> 来訪者に「ここは何ができるの？」と聞かれたときの答え: **「入力すると、あなた用の結果が出ます。診断・計算・変換・印刷物・あそび。」**
>
> **来訪者に届く面で、店の語（店・屋・のれん・品書き・棚・値札・包み・札・看板・印）を使わない。**
> 可視テキスト・`aria-label`・`alt`・メタデータ・URL のいずれにも出さない。像は内部にとどめる。

- **基準1**: 来訪者が受け取るものは案A と同じ（同じ一言を使える）。
- **基準2**: 案A と同じ。
- **基準3**: 「内部の像」と「来訪者に届く言葉」の二層を読み手が常に意識する必要があり、**引くたびに判定が要る。**
- **基準4**: **最も強い。** 「よろず屋」の像がそのまま `DESIGN.md` の導出元になる（現行 `DESIGN.md` は §1 と §11 のみが真に依存しており、他はラベル置換で主張が残るため、像を保てば組み直しの量が最小になる）。
- **基準5**: 現行の構造を保つため、**痕跡が残る。**
- **代価**: 検証できない像が規範に残り続ける。「よろず屋」が来訪者価値に資するという立証は、**内部語彙である限り永久に行えない。**

### 案C: 像を別の像へ置き換える

「よろず屋（店）」を降ろし、**別の像**を据える。候補は現行 `DESIGN.md` §2 が既に使っている「**紙と墨**」——
和紙に墨と朱で刷ったものの手ざわり。店ではなく、**作られたものの質**を指す像である。

**冒頭の実物:**

> ## このサイトは何か
>
> **yolos.net は、あらゆる題材で「その場でためせるもの」を作って置く場所である。**
>
> 名前の由来は **YOLO**（You Only Live Once＝一度きり）と**よろず**（万事・あらゆるもの）。
>
> 作るものの手ざわりは、**紙と墨**である。白い紙に黒い字、要るところにだけ朱。
> 罫で区切り、余白で息をつかせる。飾りを足すのではなく、組みを丁寧にする。
>
> 来訪者に「ここは何ができるの？」と聞かれたときの答え: **「入力すると、あなた用の結果が出ます。診断・計算・変換・印刷物・あそび。」**

- **基準1**: 案A と同じ。
- **基準2**: **「紙と墨」は検索結果には出ない**（見た目の話なので）。基準2 への寄与は案A と同じ。
- **基準3**: 像が「作られたものの質」に限定されるため、**コンテンツの取捨（何を作るか）には使えない。** そこは別の規則が要る。
- **基準4**: **強い。** `DESIGN.md` の §2（色）・§3（書体）・§4（罫とレイアウト）が像から直接導ける。§1 も書き換えられる。
- **基準5**: 像を入れ替えるので、現行の店語彙は全部落ちる。**痕跡は残りにくい。**
- **代価**: 「紙と墨」は**見た目の像**であって、**サイトが何をする場所かを言わない。** 正体の説明を別に立てる必要がある（上の実物ではその分だけ冒頭が長い）。

**冒頭の実物:**

> ## このサイトは何か
>
> **yolos.net は「AI が営むよろず屋」である。**
>
> 名前の由来は **YOLO**（You Only Live Once）と**よろず**（万事・あらゆるもの）。扱う範囲を狭めない。

- **基準3**: 来源が構造で分かるので、**どの規則が疑ってよいかは読める。**

## 実測が案の評価を動かした——「内部語彙」は既に来訪者に届いている

[facts-src.md](./facts-src.md) の実測で、**案B（内部の像を保ち、可視面での店語彙を禁じる）の前提が崩れた。**

**現状が既に案B の形になっている。** そして、その二層構造は境界で漏れている。

| 届き方                    | 実測                                                                                                                 | 誰に届くか               |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------ |
| 可視テキスト（サイト UI） | **6件 / 3ファイル**（「AIが営む、よろず屋です。」「結果は札にして持ち帰れます。」など）                              | 全員                     |
| **スクリーンリーダー**    | **コード上11箇所 / 8ファイル・描画される文言17種**（`aria-label="〜の品書き"` が10箇所・16種、`aria-label="印 診"`） | **SR 利用者だけ**        |
| メタデータ                | **4件 / 3ファイル**（トップと `/about` の description・OGP に「よろず屋」、`og:image:alt="診断結果の札"`）           | 検索結果・SNS 共有で全員 |
| URL パス                  | **2件**（`/play/…/fuda-image`・`/blog/character-quiz-result-as-fuda`）                                               | 全員                     |

**決定的なのは `/dictionary` で観測された状態である。**

> 可視テキストの店語彙は**ゼロ**。`aria-label="辞典の品書き"` のみ。アクセシビリティツリーは `list "辞典の品書き"` と読む。
> **視覚的な来訪者は「品書き」に一度も出会わず、スクリーンリーダー利用者だけが聞く。**

トップも同型である——**同じ区画を、可視では「診断・占い・あそび」、読み上げでは「品書き」と別の語で呼んでいる。**

### ここから分かること

**1. 「可視／不可視」で線を引いたことが誤りだった。** スクリーンリーダーに読まれる文字列は「不可視」だが、**来訪者に届いている。**
線は「目に見えるか」ではなく「**来訪者に届くか**」で引かなければならない。現行 L9 の「来訪者可視の顔・コピーは平明な言葉で組み」という書き方が、その誤りを固定している。

**2. 二層構造は、境界で必ず漏れる。** 実測された漏れは3種類——`aria-label`（17種）・メタデータ（4件）・URL（2件）。
可視テキストだけを平明にしても、**SR 利用者には符牒が届き続ける。** これは案B が抱える構造的な欠陥であり、規則の書き方を厳しくしても境界は残る。

**3. 説明の非対称。** 「よろず屋」の意味を説明している面は `/about` **1面だけ**で、しかも説明されるのは「**よろず**」のみ——「**屋**」は説明されない。
「札」に至っては画面上に説明がなく、**隣の見本画像との対応を来訪者が推測するしかない**（見本画像の中に「札」の字は出ない）。

### 案の評価の更新

| 案           | 更新                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **案B**      | **不利になった。** 「内部の像を保ち可視面で禁じる」は**現状そのもの**であり、その現状が SR 利用者に符牒17種を届けている。案B を採ることは、この漏れを規則として追認することになる。境界の定義を「来訪者に届く面すべて」に広げれば漏れは塞げるが、**そのとき像は本当に内部だけに閉じ、来訪者価値からの立証が永久に不可能になる**（現行 L9 自身が「keep/remove とも来訪者価値からの立証を要する」と課している条件を、構造的に満たせなくなる） |
| **案A・案C** | **有利になった。** 像を降ろせば境界の漏れ自体が消える。塞ぐべき境界が無くなる                                                                                                                                                                                                                                                                                                                                                               |
| **案D**      | 変わらず一次資料に反する                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **案E**      | 変わらず——現行構造を保つため、この漏れも保たれる                                                                                                                                                                                                                                                                                                                                                                                            |

**なお、本サイクルは `src/` を触らない。** 実測された漏れの是正は B-649（SR 可視の店語彙ラベルの平明化）と B-652 の射程である。
本サイクルがやるのは、**規範をどちらに決めるか**であって、実装の是正ではない。

## 選定

**採るのは案A（白紙起草）である。そのうえで、案A の弱点を「像ではなく制約を渡す」という形で解く。**

### なぜ案A か

| 基準                                                 | 判定                                                                                                                                                                                                                                                                                                         |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **1 来訪者が何を受け取るか**                         | **案A が最も直接に渡す。** 「入力すると、あなた用の結果が出ます」。対して「よろず屋」は、**意味を説明している面が `/about` 1面だけ**で、しかも説明されるのは「よろず」のみ——「屋」は説明されない。「札」に至っては画面上に説明がなく、隣の見本画像との対応を推測させている（[facts-src.md](./facts-src.md)） |
| **2 検索結果で見分けがつき、何が得られるか分かるか** | **ブランドクエリが全期間ゼロ**である以上、現行の名乗りはこの基準で0点である。**変更のコストも同時にゼロになる。** 案A の「その場でためせるもの」は範囲と利得を伝える                                                                                                                                         |
| **3 迷わず引けるか**                                 | **案A が最強。** 現行の堆積（cycle-278〜310）を引き継がない                                                                                                                                                                                                                                                  |
| **4 `DESIGN.md` を導出できるか**                     | **案A の唯一の弱点。** 導出元が細い。→ **下記で解く**                                                                                                                                                                                                                                                        |
| **5 ツギハギ禁止**                                   | **案A が最強。** 定義上、痕跡が残らない。Owner の動詞「削ぎ落とす」を最もよく満たす                                                                                                                                                                                                                          |

### 案B・案E を捨てる理由（実測に基づく）

**案B の「内部の像を保ち、可視面で禁じる」は現状そのものであり、その現状が漏れている。**
`aria-label` 17種・メタデータ4件・URL 2件が来訪者に届いており、とりわけ `/dictionary` では**スクリーンリーダー利用者だけが「品書き」を聞く**。
境界の定義を「来訪者に届く面すべて」へ広げれば漏れは塞げるが、**そのとき像は完全に内部へ閉じ、現行 L9 自身が課す「来訪者価値からの立証」が構造的に不可能になる。**
案E も現行構造を保つため、同じ漏れを保つ。

### 案C から採るもの・採らないもの

**「紙と墨」の像は `DESIGN.md` 側に置く。`site-concept.md` には置かない。**

案C を評価するうちに、**像には2種類あることが分かった。**

- **正体の像**（「よろず屋」）は、**来訪者に伝わらなければ機能しない。** 伝わっていないことは実測で確定した（ブランドクエリ0・説明は1面のみ）。
- **様式の像**（「紙と墨」）は、**来訪者に伝わる必要がない。** 来訪者が「これは紙と墨の様式だ」と認識する必要はなく、落ち着いて読めればよい。

**この区別が、案B を捨てて案C の一部を採る根拠である。** 検証できない像を規範に置くなという原理は、**伝達を要求する像にだけ適用される。**

### 案A の弱点の解き方——像ではなく制約を渡す

`site-concept.md` が `DESIGN.md` に渡すのは**像ではなく制約**である。正体から次が導ける。

| 正体から            | `DESIGN.md` への制約                                                                 |
| ------------------- | ------------------------------------------------------------------------------------ |
| あらゆる題材を扱う  | **器は一貫していなければならない**（題材ごとに見た目を変えると一軒分の統一が崩れる） |
| その場でためせる    | **入力と結果が主役。器は目立ってはならない**                                         |
| 結果を持ち帰れる    | **成果物は単体で（サイトの文脈なしで）成立しなければならない**                       |
| AI が作り、誤りうる | **誤りを隠す装飾をしない。検証できる形で作る**                                       |
| 量より質（rule 4）  | **面の数を増やす方向の設計をしない**                                                 |

**`DESIGN.md` の仕事は、この制約を満たす様式を選ぶことである。** 「紙と墨」はその選択肢のひとつであって、コンセプトから必然的に出るものではない。
**これが Owner の言う「作ったサイトコンセプトから自然に導出できる形のデザインシステム」の形である**——コンセプトが制約を渡し、デザインシステムがその制約を満たす様式を選ぶ。

### 決定の内容

1. **`docs/site-concept.md` を白紙から書き起こす。** 現行文書は最後に「落ちている論点が無いか」の照合にだけ使う。
2. **サイト名の由来を一次資料どおりに書く**——**YOLO（You Only Live Once）× よろず（万事・あらゆるもの）**。「運営を AI に丸投げした実験サイト」という語釈は**誤りとして落とす**。「不変の事実」という格付けも落とす（裏付ける一次資料が無い）。
3. **店の像（よろず屋・のれん・品書き・棚・値札・包み・札・看板・印）を、正体の像として据えない。** 内部語彙としても置かない。
   （**この後半は [decision.md](./decision.md) §4 で改めた**——内部は規則の対象外とし、新しく増やさないことだけを求める。）
4. **「やってみる」は残す。** 主語は来訪者。由来（一度きりだから、やってみる）から直接出るものであり、`cycle-309/grounding.md` §4 が明示的に許しており、**実際の PV 比（やってみる側 88.7%。Singapore 由来のボット疑いを除いた値）とも一致する。**
5. **来訪者への一言は、受け取れるものの記述にする。** 名乗りの文にしない。
6. **AI 運営の開示は、名乗りと混ぜず独立して置く**（constitution rule 3）。**3要素を欠かさない**——AI が運営していること・実験であること・内容が誤りうること。現行サイト（`src/app/page.tsx:200`）は3要素を満たしているので、**そこから後退させない。**
7. **`DESIGN.md` へは像ではなく制約を渡す**（上表）。様式の選択は `DESIGN.md` の仕事とする。
