## Blocker

### B1. 決定4 の開示例文が constitution rule 3 の要求を満たしていない（過少）

**何が問題か。** rule 3 は「the website is run by AI **as an experiment** and that its content may be broken or incorrect」の3要素を来訪者に告げよと求めている。
決定4 が参照する案F の例文は「**このサイトは AI が作っています。内容が誤っていることがあります。**」（L123）で、

- 「実験である」——**欠落**
- 「AI が**運営**している」——「AI が作っています」は制作物の帰属であって運営主体の開示ではない。**要素がずれている**
- 「内容が誤りうる」——充足

**なぜ問題か。** 現行サイトはこの3要素を満たしている（`src/app/page.tsx:200`「運営しているのは人ではなくAIです。実験なので、内容に誤りがあるかもしれません。」、`DESIGN.md` §6 L94 の定型文も「AI が運営する実験サイト」）。
この決定を T3・T6 にそのまま渡すと、**憲法要求の開示が現状より弱くなる**。しかも本決定は「開示を独立させることで開示が薄まらない」ことを利点として掲げている（L127）ので、利点の主張と例文が逆を向いている。
さらに、L9(3)（「実験…を identity の売り込みにしない」）と rule 3（「実験であることを告げよ」）は衝突して見えるため、書き分けを明示しないと後続サイクルが「実験と書くと L9 違反」と誤読して開示を削る経路ができる。

**どう直すか。** 決定4 に「開示は rule 3 の3要素（**AI が運営している／実験である／内容が誤りうる**）をすべて含む」と明記し、例文を3要素を満たすものに差し替える。あわせて「**実験であることは開示する義務がある。売り込みに使わないのは価値の主張としてであって、事実の開示を削ることではない**」を1文で書く。

### B2. 6案が1軸に収束しており、現実に最有力な選択肢——「像を置き換える／像は内部に保ち、可視面で機械的に遮断する」——が欠落している

**何が問題か。** 6案は実質「店語彙をどれだけ残すか」という1軸（全部残す＝A/C → 可視だけ落とす＝B/E → 全部落とす＝D/F）の上に並んでいる。
PM 自身が L140 で「B・E・F の『来訪者には平明な言葉で』は全部正しい。争点はそこではなく、**内部でどう呼ぶか**である」と書いている。つまり**可視面の側は、どの案もそれを支持しているという理由で、検討されないまま決着している**。3案が同じ前提を共有していることは、その前提の検証ではない。

欠けている選択肢は具体的に2つある。

1. **内部の組織化の像は保ち、来訪者可視面での signifier 使用を機械的に禁じる案**（＝決定5 を強い規則に格上げし、案D の内部撤去を採らない）。これは (i)(ii) を案F と同じだけ満たし、かつ `DESIGN.md` の骨格と T5 の導出可能性を温存する。**6案のどれにも無い。**
2. **像を「店」から別の像へ置き換える案**（例: `DESIGN.md` §2 が既に使っている「紙と墨」＝帳面の像。店に依存せず、器の一貫性を語る力を持つ）。案D は像を外すだけで代わりを立てない。PM 自身が L96 で「『場所』は『店』より弱い像である。器の一貫性を語る比喩としては『店』のほうが強い」と**弱点を認めたまま決定している**。

加えて、矛盾の2語を keep/drop で組めば 2×2 の4通りがあるが、「**よろず屋を残し、やってみるを落とす**」セルが1案も無い。L9 の許可構造（やってみる＝禁止／よろず屋＝条件付きで可）に**最も忠実な選択肢**がこれであり、Owner の言う「片方に揃える」の最有力候補のひとつである。

**なぜ問題か。** サイクル-314 の申し送り「**2択に狭めないこと**」は、案の**数**ではなく**軸の数**への警告である。6案という見かけの幅の下で、実際には1軸になっている。結果、最も破壊的な選択肢（内部からも像を撤去）が、より穏当で同じ効用を持つ選択肢と**一度も比較されないまま**採用されている。これは 314 が記録した「レビューは枠の中の誤りは見つけるが枠そのものの誤りは見つけない」の再演の条件そのものである。

**どう直すか。** 上記2案を文章として書き起こし、(i)(ii) に加えて B-M5 で述べる基準で再評価する。再評価の結果が同じ D+F になるなら、それは正当な決定になる。

### B3. 「内部でも店の比喩を使わない」の根拠が、自分の決定に適用されていない

**何が問題か。** 案B・案E を捨てた唯一の理由は「**来訪者に出ない語は来訪者価値で検証できない。検証できない比喩を規範文書に置けば、それは仮説のまま岩盤になる**」（L142-144）である。
ところが決定1 は、内部の自己定義として「**AI が作った、あらゆる『やってみる』を置く場所**」を置く。これも来訪者に出ない語であり、同じ理由で検証不能である。
原理を一貫適用すれば**あらゆる自己定義が禁じられ、site-concept.md は成立しない**。したがってこの原理は強すぎ、案B・案E の棄却理由として機能していない。棄却理由が崩れれば、D を選んだ論理も崩れる。

**なぜ問題か（来訪者への帰結）。** 「内部でも使わない」は、来訪者価値の増分が**構造的にゼロ**である——内部語彙は定義上来訪者に届かない（`docs/cycles/cycle-309/grounding.md` §1 が「コードコメント・コンポーネント名 Shinagaki/Tsutsumi/Nefuda/In は来訪者不可視＝射程外」と明示して線を引いている）。
一方、代価は実測で大きい。実装側に `Shinagaki`・`Nefuda`・`Tsutsumi`・`In`・`ShareButtons`（札）・`Header`（のれん）等が店語彙で命名され、JSDoc が `DESIGN.md §4「品書き」` のように節を名指しで参照している。本サイクルは `src/` を触らない（完了条件7）ので、**新 `DESIGN.md` が確定した瞬間から、規範と実装が別語彙で並走する状態が B-652（Deferred）まで確定する**。これはリポジトリ規模のツギハギであり、CLAUDE.md が最上位で禁じている状態である。

「未検証の内部語彙が可視面へ滲み出た」という PM の因果（L144）は事実として正しい（OGP ののれん帯・朱印、`品書き` の aria-label）。しかしその**正しい対処は決定5（可視面での signifier 禁止）であって、内部の像の撤去ではない**。B2 の欠落案1 がまさにこれを担う。

**どう直すか。** 原理を「**検証不能な比喩に、規範としての導出力を持たせない**」へ書き直す（内部語彙の存在自体を禁じない）。そのうえで内部の像の keep / replace / drop は、来訪者価値ではなく「**T5 で `DESIGN.md` を導出できるか**」という本来の軸で判定する。決定を維持する場合は、src/ の語彙移行を誰がいつやるかを決定の一部として書く（B2・Q2 参照）。

## Major

### M1. 「L9 は主語を取り違えて禁止の網をかけた」は一次資料と食い違う

一次資料は `docs/cycles/cycle-309/grounding.md` §0.1-4 にある（L9 が自ら名指ししているファイル）。逐語:

> **「試作サイトである／いろいろ試している」ことに来訪者が価値を見出す前提は禁**（constitution 違反）。試しているのは PM（運営）であって来訪者ではない——これは PM 都合の押し付け。**Rule3 の AI 明示は「正直の開示」であって価値の売り込みではない**。「実験/やってみる」を identity の売りにしない（**来訪者の価値は、その場で得られる具体的な結果・成果物・体験そのもの**）。

これは主語の取り違えではなく、**主語を明示的に論じたうえでの意図的な禁止**である。かつ末尾の括弧は案F の主張（利得で答える）とほぼ同じことを既に述べている。
PM の結論（来訪者主語の「やってみる」は残しうる）自体はこの一次資料と両立するが、**理由付けが「過去の書き手の誤り」の断定**になっている点が問題である（AP-WF27: 検証不能な過去の内心・意図の断定）。
さらに手続きとして、site-concept L3 は L9 を「**無効**」と宣言している。無効宣言された記述を根拠に読解を組み立てるなら、一次資料に当たるのが唯一の筋であり、それは grep 1回で届く場所にあった。

**どう直すか。** grounding.md §0/§0.1 を一次資料として引き、「取り違え」ではなく「**この禁止の射程を来訪者主語に限定するほうが来訪者価値に適う**」という現在形の論として立て直す。

### M2. L9(3) の引用が、自説に不利な箇所で切り詰められている

原文（逐語確認）:

> (3) **「実験/試作/やってみる」を identity の売り込みにしない**（試しているのは運営であって来訪者ではない**・Rule3 の AI 明示は正直の開示に留める**）。

options-t2 L7 は「（試しているのは運営であって来訪者ではない）」で括弧を閉じ、後半を落としている。省略記号も無い。
落とした節は (a) 決定4 の直接の根拠であり、(b) L9(3) が rule 3 との関係まで含んだ一塊であること＝「主語の取り違え」説に不利な証拠である。**切り落とした箇所が、ちょうど自説を弱める箇所**である点で、単なる省略として扱えない。逐語で引き直すこと。

### M5. 判断基準 (i)(ii) が狭く、勝つ案があらかじめ決まる形になっている

落ちている軸が最低4つある。

1. **検索面での効き。** 自己定義は title / description / og:image に流れる（`/about` の description は現に「yolos.netは『AIが営むよろず屋』です。…」）。site-concept 全体が検索を主戦場に据えているのに、SERP の瞬間を「伝わるか」だけで評価し、クエリ適合・CTR・ブランド想起を一度も問うていない。
2. **記憶・識別（個性）。** 「個性を失う」は案F の「失うもの」に**結果としてだけ**現れ、基準に無い。基準に無い価値は比較で**値付けされない**ので、必ず (i)(ii) 最大の案が勝つ。これは基準設計による結論の先取りである。
3. **既存の来訪者・既存コピーとの連続性。** トップと `/about` は現に「AIが営む、よろず屋です」と名乗っている。site-concept L21 は「サイト上の自己表示の書き換えは、**実体が伴った時点で行う**」と定めており、決定はこの規則との関係を述べていない。
4. **T5 で `DESIGN.md` を導出できるか。** T1 は同じ問いを判断基準2 に据え、それを**決め手**にして案5 を選んでいる（options-t1 L125-127）。T2 で同じ軸が消えているのは一貫性を欠く。案D の「懸念: 『場所』は『店』より弱い像」（L96）はまさにこの軸の問題で、**未解決のまま決定に至っている**。

### M6. 来訪者価値からの立証が、来訪者の実データを一度も見ずに行われている

grounding.md §0.1-2 が求めるのは「論理的立証」なので、データ不在が即失格ではない。しかし:

- CLAUDE.md は「**Always check Google Analytics data before making any decisions that may impact user experience or traffic**」と定める。本決定はトップ・`/about`・meta description の文言に波及する。
- site-concept L71 は「**品質と面白さの審判は、来訪者の行動データのみ**。自分やレビュアーの『面白い』を判定に使わない」と定める。(i)(ii) はいずれも PM の内省である。
- 見に行けるデータは実在する: Search Console のブランドクエリ（"yolos"/"よろず"）、`/about` の流入と滞在、トップの離脱。

決定的なのは**非対称**である。PM は「検証できないものを規範に置くな」を案B/E の棄却理由に使いながら、自案の「平明な利得の記述のほうが役に立つ」という命題を**同じく未検証のまま規範化**している。
最低限、見られるデータを見ること。見ないと決めるなら、決定に「**これは賭けである**」と明記し、判定の窓と撤退条件（site-concept L57 の実験枠の形式／ADR）を付けること。

## Minor

- **m1. 「捨てる」ラベルが結果と一致しない。** 決定2 は案A の内容そのもの（禁止を「実験/試作」に限定し「やってみる」を外す）であり、決定5 は案C の論点を明示的に採用している。6案中4案の要素が最終決定に入っているのに、A と C には「**捨てる**」と書かれている。レビュー依頼の問い「最初から決まっていた結論を後から案の形に整えただけではないか」に対して、この不一致が疑いを生む主因である。「単独では採らないが、この部分は採る」と書き分けること。
- **m2. 「よろず屋＝日常語」は言い過ぎ。** 辞書語である点は正しい（コトバンク／Weblio）。ただし「万屋は現代ではあまり一般会話では使われない傾向にある」とされ（Wikipedia「よろずや」／Oggi）、現代語感では「なんでも屋（器用貧乏）」の含意も伴う。結論（(i) は伝わる）は変わらないが、「辞書語」と「日常語」を同義に使っている箇所（L31・L76）は直す。
- **m3. 決定1 の自己定義案が、自分で診断した主語の混線を再生産しかねない。** 「**AI が作った**、あらゆる『**やってみる**』を置く場所」は、運営主語と来訪者主語を一文に同居させている。T3 で主語が一意に読める文にすること。
- **m4. 矛盾の棚卸しが2語・2箇所にとどまり、L19 が欠落している。** L19 の「よろず屋の**店主**が AI であることは、このサイトの注意書きではなく**個性である**」は、(a)「店主」が L9 の signifier リストの直系であり、(b)「注意書きではなく個性」は L9(3) の「rule3 の明示は正直の開示に留める」に真正面から反する。T1 が別の観点（後付けの強調）で落としているが、**T2 の矛盾の一覧としては欠落**。矛盾は3箇所である。
