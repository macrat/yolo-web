# `DESIGN.md` の射程——デザイン定義に何を残し、何を落としたか

`site-concept.md` からコンセプト以外を削ぎ落としたのと同じ考え方を `DESIGN.md` にも当てた。

## 判断の線

**`DESIGN.md` は、このサイトの視覚が何であるかの定義である。**

| 残すもの                                 | 落とすもの                                     |
| ---------------------------------------- | ---------------------------------------------- |
| 何がどう見えるか（値・形・記号・組み方） | それをどう確かめるか（検査の手順・担保の手段） |
| このデザインが満たす下限                 | どう実装するか（技術の指定・作業のやり方）     |
| デザインの一部としての文章の質           | この文書自体の運用（改訂の規則）               |

**「〜しない」は定義の一部である。** 影を持たない・図像を持たない・角丸を持たない——これらはデザインが何であるかを決めている。
**「〜を検査する」「〜のときは書き直す」は手順である。** 定義から出てくる作業であって、定義ではない。

## 落としたもの

| 落としたもの                                                      | 本来の置き場所                                   |
| ----------------------------------------------------------------- | ------------------------------------------------ |
| 条件1を検査する2段の手順（機械で確かめる4項目＋文言を消した実見） | 作る・レビューするときの手順                     |
| 禁止リスト20項目の表と、各項の担保手段（機械／実見）              | 中身は各節の定義に畳んだ。手段は手順             |
| 「トークン値を変えたら比の表を計算し直す」                        | 手順                                             |
| 「サブセットを作り直す」「上限を超えたら字種の使い方を見直す」    | 手順                                             |
| 「実機で確かめて確定する」（游ゴシック・Android の書体解決）      | 手順                                             |
| `font-display: swap`・`size-adjust` 等の指定方法                  | 実装の技術。定義側は「リフローしない」だけを持つ |
| 「足した部品は必ずこの文書に書く」                                | 手順                                             |
| 手で入れた改行を幅に応じて無効化する方法                          | 実装の技術                                       |
| §15 改訂の規則（改訂の正当な理由・実装と食い違ったときの扱い）    | この文書の運用                                   |

| 数値の由来（なぜ 960px か・なぜ 1024px で切るか） | サイクルドキュメント。定義は値を持ち、由来は持たない |

**禁止リストは、定義に畳んで消えたのではなく、形を変えて残っている。**
「影を持たない」「図像を持たない」「無限スクロールを持たない」「他人の行動を根拠にした煽りを持たない」——**それぞれが属する節の中に、デザインが何であるかの言明として置いた。**

## 数値の由来をどこに書くか

レビューで「960px・1024px・720px・20px・8px・44px・2px・3px に根拠が無い」という指摘が3巡にわたって出た。
一度は `DESIGN.md` に根拠を書いたが、書いた根拠（「その大きさの主見出しが2行に収まる下限」）は読者に確かめる手段が無く、確かめられない根拠は無いより悪かった。

**決めたこと。定義は値だけを持ち、由来は持たない。** 由来は検討した巡のサイクルドキュメントに残す。
`site-concept.md` が「何を目指すか」だけを持ち、そこへ至った検討を持たないのと同じ扱いである。

## 未了
