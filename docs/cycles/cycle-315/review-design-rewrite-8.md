## Major-3: 見出しの段下げが、階層を反転させる。320px・文字 200% では主見出しが節の見出しより小さくなる

結果、**主見出し（34px）< 節の見出し（47.68px）** になる。§3 は「見出しにウェイトの差を使わない。**階層は大きさと罫が作る**」と定めているので、大きさが逆転した時点で階層の担い手は罫だけになる。§1 の担い手2「巨大なアンティーク体の見出し」も、面の題においては消える。

**PM が7巡目 Major-1 の提案（見出しも結果の段まで下げる）を退けた理由は「担い手2 が消えるから」だった。** 今回入れた L106 は、その退けた変更を語の長さを引き金にして自動で起こす。**同じ帰結を、制御できない条件で招いている。**

直し方は「揃って下がる」を貫くこと——一語が収まらないときは、その面の見出しの段をまとめて1段下げる（§4 の表と同じ操作にする）。そうすれば階層は保たれ、L98 と矛盾しない。

## Major-4: §4 が見出しに課す `palt` は、§3 が指定する3書体のどれにも存在しない

L96:「**見出し**: 行間 `1.25` 以下・`palt`。」

実測（Google Fonts の実体）。

| 書体          | GSUB の feature                                  | GPOS の feature             | `palt` |
| ------------- | ------------------------------------------------ | --------------------------- | ------ |
| Zen Antique   | `ccmp` `frac` `vert` `vrt2`                      | `kern` `mark` `mkmk`        | 無し   |
| BIZ UDPGothic | `ccmp` `dnom` `frac` `liga` `numr` `vert` `vrt2` | **GPOS テーブル自体が無い** | 無し   |
| IBM Plex Sans | `ccmp` `dnom` `frac` `liga` `locl` `numr`        | `kern` `mark`               | 無し   |

さらに Zen Antique の `kern` が覆う 88 + 225 グリフに**仮名は1字も含まれない**（代替の詰めも効かない）。したがって `palt` の指定は**常に空振りし、見出しの和文は全角ベタで組まれる。**

これは単独の誤りにとどまらない。**Major-3 の頻度を決めているのがこの1行である。** 仮に BIZ UDPGothic 相当のプロポーショナル字幅（仮名 0.89〜0.92em）が効けば「シミュレーション」は 2.08rem で 235.0px となり、既定ルートでは段が下がらない（実際は 266.24px で下がる）。**段下げが起きるかどうかの境界が、存在しない機能の有無で決まっている。**

`palt` を書くなら対応する書体を選ぶか、`palt` を落として全角ベタを前提に段と組み幅を決めるか、どちらかに寄せる必要がある。どちらを採るかで §4 の段の表と Major-3 の直し方が変わるので、先に決める必要がある。

## Major-5: 「操作部を開閉のつまみに畳む」が、同じ節の「既定の並び順が来訪者に見えている」を破る。7巡目 Major-3 の穴が2行下へ移っている

§7 の「増え続けることへの備え」は、次を並べて要求している。

- L262「種別で絞り込める。**現在の絞り込みと該当件数が常に見えている。**」
- L263「**既定の並び順**が来訪者に見えていて、変えられる。」
- L265「一覧の1行目が面の上端から1画面の中に入らない幅では、**操作部を §6 の開閉のつまみに畳む。つまみのラベルが、現在の絞り込みと該当件数を言う。**」
- L266「**全体の件数**が見えている。」

つまみのラベルが引き継ぐと書かれているのは L262 の2つだけである。**L263 の並び順は畳んだ先に隠れ、「見えていて」が偽になる。** (A)-4 の実数のとおり、320px では操作部が約 634px なので**携帯では常に畳まれる**——つまり L263 は、携帯の来訪者に対して常に成立しない。

L266 の「全体の件数」がどちらに属するかは、**「操作部」の範囲が定義されていないため決まらない。** 「操作部」は L265 に1回だけ現れる語で、文書のどこにも定義が無い（DESIGN.md で定義を持たない実質語はこれだけである）。件数の表示が操作部に含まれるなら L266 も偽になり、含まれないなら一覧の上に件数だけが残る——**どちらに読んでも文書は同じ姿を指さない。**

来訪者の側から見れば、並び順が見えないことは「いま何順で並んでいるのか」が分からないまま一覧を走査することを意味する。§7 が L263 をわざわざ立てた理由がそこにあるので、畳む先でも見えている必要がある（つまみのラベルに並び順を含める、または並び順だけ畳まない）。

## Major-6: 畳む閾値が「幅」で書かれているのに、条件は高さと中身の量で決まる。同じ幅でも面ごとに形が変わり、§13「位置の一定」を破る

L265 は「一覧の1行目が面の上端から**1画面**の中に入らない**幅**では」と書く。左辺は幅、右辺は高さである。発火するかどうかは次の3つで動く。

1. **画面の高さ**（320×568 と 320×740 で答えが違う）。
2. **種別の数**（(A)-4 の 634px のうち 308px が種別7個ぶん。種別が3個なら 458px で、機種によっては畳まれない）。
3. 主見出しが Major-3 で何段に落ちたか。

§7 自身が「項目は増え続ける」と書いているので、2 は**時間とともに変わる**。同じ面が、中身が増えた日を境に畳まれる側へ移る。さらに、種別の多い一覧と少ない一覧が同時に存在すれば、**同じ幅で一方は畳まれ、他方は畳まれない。**

これは §13 の「**位置の一定**——同じ働きの部品は、どの面でも同じ位置・同じ形にある」に反する。来訪者は、面を移るたびに絞り込みが畳まれているか開いているかを確かめ直すことになる。

閾値は幅の値で書き切る（§4 の段・§5 の余白・§7 の種別が使っている `45rem` に揃える、または別の値を決める）ほうが、文書のほかの閾値の精度とも揃う。

## Major-7: §9 の3分割が、来訪者が読む文章の大半を「自然な日本語」の外に出した。§9 冒頭の理由づけが、その文章に届かなくなっている

今回 §9 は3つに割れた。

- L305「**器の文章**は、文体の作法に従う。」＋ 自然な日本語 / 具体
- L310「**来訪者への約束**は、器の文章にも中身の文章にもかかる。」＋ 出し惜しみしない / AI 運営の告知
- L315「**中身が題材として選んだ文体は、中身が決める。**」

7巡目 Major-4（器の文体が作れる中身を狭める）は確かに解けている。しかし前文 L6 は「**「中身」は…結果・生成物・本文・主題そのものである**」と定めている。**本文＝記事の文章は中身である。** つまり L305 の作法は、来訪者が読む文章の大半（結果の文章・生成物・記事本文）に**掛からない。**

そのうえ §9 の冒頭 L303 は「文章はこのデザインの一部である。**信頼を最初に壊すのは、見た目ではなく不自然な日本語だからである。**」と**無条件に**述べている。**理由は全文章について語り、規定は器だけを縛る。** 節の中で前提と結論がずれている。

さらに L315 の存在が読みを割る。作法がもともと器にしか掛からないなら、「題材として選んだ文体は中身が決める」という免除は要らない。**免除が書かれていること自体が、既定では中身にも掛かることを含意する。** L305 と L315 は両立しない読みを同時に許している。

直し方は、7巡目が提案した切り方の1段手前に戻すこと——**文体の作法は器にも中身にも掛かり、中身が題材として文体そのものを見せるときだけ中身が決める**、と書けば、L303 の理由づけ・L315 の免除・7巡目 Major-4 の懸念（翻訳調を芸にする生成物が作れない）の3つが同時に立つ。いまの形は、Major-4 を避けるために品質の下限ごと外している。

## 判定

**改善指示。Blocker 0件・Major 7件・Minor 9件。**

7巡目の Major 6件・Minor 10件は、指摘した箇所ではすべて閉じている。幾何は8巡連続で全マス一致し、色のコントラストも初めて実測して全組み合わせが下限を満たした。内側の余白 8px は狙いどおり効いており、320px で中身に渡る幅は 212px → 244px（画面の 66.3% → 76.25%）に増えた。**この2つは今回の成果である。**
