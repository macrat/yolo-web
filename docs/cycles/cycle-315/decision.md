# 決定: `docs/site-concept.md` をどう作り直すか

案出しの経過は [options-t1.md](./options-t1.md)（1巡目・線引き5案）・[options-t2.md](./options-t2.md)（1巡目・矛盾解消6案）・
[options-v2.md](./options-v2.md)（2巡目・統合5案）に残る。**3巡とも REJECT を受けた。** ここに決定をまとめる。

## 3巡のレビューで潰された論拠

**採らなかった論拠を先に挙げる。** これらは誤りだったので、決定の根拠にしない。

| 使わない論拠                               | なぜ誤りか                                                                                                                                                                              |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 「内部の像を保つ案は、現状そのものである」 | **誤り。** 現行 L9 は可視テキストのみを射程とする弱い注意であり、案B は**届く面すべて**の機械検査できる禁止である。射程も強度も別物だった（レビュー v2-B1）                             |
| 「二層構造は境界で必ず漏れる」             | **誤り。** 漏れは全件 grep で列挙できている（可視6件・SR 17種・メタ4件・URL 2件）。**列挙できるものは検査できる。** 「必ず漏れる」は実測と矛盾する                                      |
| 「検証できない像を規範に置くな」           | **循環。** その要求は現行 L9 が課したものであり、**L9 ごと捨てる案がその要求を対抗案にだけ適用する**のは不公平だった（レビュー v2-B1）                                                  |

| 「L9 は出典の許可条項を落として転記した」  | **事実に反する。** L9 が出典として挙げるのは `grounding.md` §0/§0.1 であって §4 ではない。**落としたのではなく、そもそも引いていない。** また過去の書き手を断じていた（レビュー v2-M2） |

## 像についての区別——成り立つが、適用を誤っていた

2巡目は「**像には2種類ある**」という区別を立てた。**この区別自体は成り立つ**（レビューも反例なしと確認した）。

- **正体の像**（「よろず屋」＝このサイトが何であるか）
- **様式の像**（「紙と墨」＝作るものの見た目）

**しかし適用が逆だった。** 2巡目は「様式の像は伝わる必要がないから内部に置いてよい／正体の像は伝わらないと機能しないから降ろす」とした。
ところが `DESIGN.md` の「のれん・品書き・棚・値札」は**様式の像**である。**自分の原理に従えば、これらは内部に置いてよいことになる**——2巡目の決定（内部語彙としても置かない）は、自分の原理と矛盾していた（レビュー v2-M12）。

**正しい形はこうである。**

> **像の種類は、それを内部に置いてよいかを決めない。決めるのは「来訪者に届くか」だけである。**
> 届く経路があるものは、種類を問わず伝達が要求される。届かないものは、種類を問わず要求されない。

実測が示したのは「様式の像が漏れていた」ことであって、「様式の像は置けない」ことではなかった。

## 決定の決め手——像が判断に効いているか

**来訪者への効果では、案A（像を降ろす）と案B（像を内部に保ち、届く面で禁じる）に差がつかない。**
どちらを採っても、来訪者に届く面から店語彙は消える。基準1（来訪者が何を受け取るか）では決まらない。

**差がつくのは、像が判断に効いているかである。** `site-concept.md` の役割は「何を追加すべきか・どう作るべきか」に迷ったときの判断基準である。そこで問う。

| 問い                         | 「よろず屋」の像は答えを出すか                                                                      |
| ---------------------------- | --------------------------------------------------------------------------------------------------- |
| このコンテンツを追加すべきか | **出さない。** 「あらゆるものを扱う」は**よろず**から出る。**屋（店）**は何も足していない           |
| このコンテンツをやめるべきか | **出さない**                                                                                        |
| どう作るべきか               | **出さない**                                                                                        |
| 見た目をどう組むか           | ラベルの呼び名を提供する（のれん＝ヘッダ、品書き＝一覧）。**ただしこれは `DESIGN.md` の管轄である** |

**`DESIGN.md` での効き方も、実測では「呼び名」に留まる**——[facts-design.md](./facts-design.md) は §2〜§7 を「**語彙のみ**」と判定した。
店語彙を別の語に置き換えれば、主張はそのまま残る。真に依存しているのは §1（設計思想）と §11（検証項目）の2節だけである。

**判断に効かない像を、規範の中心に置く理由が無い。** これが決め手である。
「検証できないから」ではない（それは循環だった）。「**何も決めていないから**」である。

## 決定

### 1. 線引き——何を残し、何を落とすか

**落とすのは「規則の来歴」だけとする。** 判定は一本の問いで行う——**これは規則か、規則がどう生まれたかの話か。**

| 落とすもの                     | 現行の該当箇所                                              |
| ------------------------------ | ----------------------------------------------------------- |
| 自己否定バナー                 | L3                                                          |
| 文書の使い方の但し書き         | L5                                                          |
| 改訂履歴                       | L7                                                          |
| 過去サイクルの経緯を述べた注記 | L9 のうち文書の地位・cycle-309/310 の経緯                   |
| 後付けの強調                   | L19「注意書きではなく個性である」                           |
| 検証状態の重複記述             | L36（L93 と重複）                                           |
| 裏取りできない他者の権威ラベル | L57「オーナーは積極的な実験を奨励する」                     |
| 過去の失敗との対比（弁解）     | L57 末尾「過去の失敗とは異なる」・L76「（失敗済みの方向）」 |
| 一次資料で確認できない主張     | L83「明示はむしろ保護的に働く（一次資料確認済み）」         |
| 権威づけの語                   | L17「自己紹介の正典」                                       |

**残すのは規則である**——正体／ゴール／中心原則と弁別子／追加の条件／賭けの枠／撤退の条件／作り方／守るもの／禁じるもの／文書の地位と再検証の引き金。
**`t3-derivation-map.md` の (a)(b)(c) 分類は採らない**（分類に収まらない規則が9件あるとレビューが指摘し、その指摘が正しかった）。
同文書は**現行規則の棚卸しとしてのみ有効**であり、その旨を同文書の冒頭に明記する。

### 2. サイト名の由来——一次資料どおりに書く

**YOLO（You Only Live Once）× よろず（万事・あらゆるもの）。**
「YOLO ＝ 運営を AI に丸投げした実験サイト」という語釈は、オーナーの指示メモと食い違うため**誤りとして落とす**。
「不変の事実」という格付けも落とす（それを与えた一次資料が存在しない）。

### 3. 店の像——正体の像としては据えない

**「よろず屋」を `site-concept.md` の自己定義に置かない。** 理由は上記のとおり、**判断に効いていないから**である。

**「屋（店）」を落とし、「よろず」は残す。** 由来の一次資料で裏付けが取れるのは「よろず」の側であり、扱う範囲を狭めないという規則もそこから出る。

### 4. 来訪者に届く面での店語彙——機械検査できる禁止として書く

**これは案B から取り込む。** 像を降ろしても、実装には店語彙が残っている（[facts-src.md](./facts-src.md) の実測）。規範として明示的に禁じる。

**「来訪者に届く面」を列挙で定義する**——可視テキスト／`aria-label`・`alt`・`title`・視覚的に隠したテキスト／メタデータ（`title`・`description`・OGP・構造化データ）／URL のパス。
**「目に見えるか」で線を引かない。** スクリーンリーダーに読まれる文字列は目に見えないが、来訪者に届いている。

**内部（コンポーネント名・変数名・コメント）は、この禁止の対象外とする。** ただし新しく内部の店語彙を増やさない。
既存の是正は B-672（ソースコードのコメントに経緯が残っている）と B-649（SR 可視の店語彙ラベル）の射程であり、**本サイクルは `src/` を触らない。**

### 5. 「やってみる」——残す。主語は来訪者

由来（一度きりだから、やってみる）から直接出る。`grounding.md` §4 が来訪者主語の用法を「使ってよい」と判定している。
実際の PV 比（やってみる側 88.7%・28日）とも一致する。
**運営の営み（実験・試作）を来訪者への売りにしない**という禁止は残す——これは `grounding.md` §0.1(4) が主語を明示して論じた規則である。

### 6. 来訪者への一言——受け取れるものの記述にする

名乗りの文にしない。

**ブランドクエリがゼロであることは、「名乗りを変える代価が無い」ことの根拠にはするが、「現行の名乗りが検索面で0点だ」という主張の根拠にはしない。**
基準が働くのは非ブランドクエリの検索結果（28日で表示 66,094・CTR 3.2%）であり、指名検索の件数はそこを測っていない（レビュー v2-M3）。

### 7. AI 運営の開示——名乗りと分け、3要素を欠かさない

**AI が運営していること・これが実験であること・内容が誤りうること。** 現行サイト（`src/app/page.tsx:200`）はこの3要素を満たしているので、**そこから後退させない。**
維持する理由は constitution rule 3 であって、検索評価上の利得ではない。**利得を理由に据えると、利得が消えたときに rule 3 を捨てる論理になる。**

### 8. `DESIGN.md` へ渡すもの——像ではなく制約

**渡すものを3つの層に分けて書く。** 2巡目は5つを一枚の表に並べたが、そのうち1件は正体由来ではなく、1件は理由が落とすはずの店語彙に依拠していた（レビュー v2-M7/M8・concept-MJ3）。

**(1) 正体から導かれるもの**

| 正体のどこから      | 制約                                                                                            |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| あらゆる題材を扱う  | **題材が変わっても作りが変わらないこと。** 来訪者が別のサイトに来たと感じる状態を作らない       |
| その場でためせる    | **入力と結果に最短で到達できること。** 待たせない・探させない・主操作を折り返しの下へ落とさない |
| 結果を持ち帰れる    | **成果物が単体で成立すること。** サイトの文脈なしで何の結果か読み取れる                         |
| AI が作り、誤りうる | **確からしさを演出で作らないこと。** 見た目の作り込みで信頼を調達しない                         |

**(2) constitution から直接来るもの**（正体からは導けない）

| 出どころ                       | 制約                                                   |
| ------------------------------ | ------------------------------------------------------ |
| rule 4（量より質・探しやすく） | 面の数を増やす方向の設計をしない。分類と回遊を設計する |
| rule 2（害を与えない）         | 煽らない・出し惜しみしない・偽の限定を作らない         |

**(3) 外部が決める下限**（こちらでは動かせない）

**WCAG 2.2** のコントラスト比・文字サイズの拡大耐性・タップ標的の大きさ。**外部が決めるのは下限であって、選択ではない。**

**(4) 観測から来るもの**（正体からも constitution からも導けない）

**モバイルを前提に組む。** 診断面は 74.5% がモバイルで、しかもセッション最多面である（`DESIGN.md` §10 の実測）。
**ただし全面では非多数派**であり、単一デバイス想定は禁物である。**この制約は観測由来なので、観測が変われば変わる。**

**様式（紙と墨を据えるかどうか）は、ここでは決めない。** それは T5 で案を並べて決める（レビュー v2-B5——2巡目は T5 の判断を案ゼロで先取りしていた）。

**採るのは案A である。** 決め手は**基準4**——像が判断に効いていない。

像を保っても `cycle-NNN` 参照の除去（B-672 の本体）は必要であり、**遅かれ早かれ同じ範囲に手が入る。**
