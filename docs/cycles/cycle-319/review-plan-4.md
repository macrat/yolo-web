## 指摘

### 1. T5a-5 が残す段階を見る `useEffect` を、T5a-6 が外すことがどこにも書かれていない。残ると結果への着地の選び方が上書きされ、jsdom の試験では見つからない（中）

第3回の指摘1 の直しで、T5a-5 は「結果への送りとフォーカス（いまの `QuizContainer.tsx` の段階を見る `useEffect`）を今の形のまま残す」と書いた。これ自体は正しい分け方だが、T5a-6 の項はその受け取りを書いていない。T5a-6 の項が読ませる節は「4-5・4-6・4-8・4-9」で、送りとフォーカスの持ち主と時（1つの `useLayoutEffect` で、送りを先に、フォーカスをあとに）を決める 4-7 が入っていない（4-7 は T5a-5 の項にだけある）。7章の T5a-6 の行に「どの送りも 4-7 の `useLayoutEffect` の中で」とはあるが、T5a-5 が明示して残したものを外せとは書いていない。

T5a-6 の builder が結果の着地を `useLayoutEffect` に足し、77〜83行の `useEffect` を残すと、塗ったあとに `box.scrollIntoView({ block: "start" })` が走って、4-9 の着地の選び方（2打目が押せるものに落ちない送り）で選んだ位置をボックスの上端に戻す。PV の8割を占めるスマートフォンの来訪者が最後の答えを二度押ししたとき、守りが効かない形になる。しかも T5a-6 の完了の条件の試験（「結果の着地の量で送りの関数が呼ばれ、フォーカスが結果のボックスにある」）は、古い `useEffect` が残っていても両方とも通る（送りの関数は呼ばれ、フォーカスも同じボックスに置かれる）。見つかるのは T5a-7 の毎フレームの記録と着地の記録で、T5a-6 に戻ることになる。第2回・第3回の直しで受け持ちを分けたことで生じた受け渡しの隙間である（AP-WF41）。

直し方の案: T5a-6 の項の節の並びに 4-7 を足し（「4-5〜4-9」）、完了の条件に「T5a-5 が残した段階を見る `useEffect` の送りとフォーカスを外し、結果の送り・着地とフォーカスを 4-7 の `useLayoutEffect` に移す（`QuizContainer.tsx` に `scrollIntoView` と、段階を見て送りやフォーカスをする `useEffect` が残らないことを読んで確かめる）」を足す。
