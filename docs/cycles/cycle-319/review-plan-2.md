## 指摘

### 1. やり直しのあとの送りとフォーカスの受け持ちが、7章と食い違い、送りの試験が誰にも無い（中）

t5a-design.md 4-7 の「試験」は「やり直したあと（同じ状態の値）には**送りとフォーカス**が起きること」を求める。計画は次のように分けた。

- T5a-5: 「やり直したあとにフォーカスが移る」を受け持つ。
- T5a-6: 「マウントのときに呼ばれない」「結果への切り替わりのあと結果の着地の量で呼ばれ、フォーカスが結果のボックスにある」を受け持つ。

食い違いが2つある。

1. **やり直しの送りの試験が、どちらの完了の条件にも無い。** T5a-6 の列挙に「やり直したあと送りの関数が呼ばれる」が無い。切り替わりの番号（マウントとやり直しを見分ける作り）が働いたことを送りの側で確かめる唯一の試験が落ちる。
2. **やり直しのフォーカスを T5a-5 に置いたことが、7章と、結果の扱いと合わない。** やり直したあとのフォーカスの行き先は 4-8 の「はじめる」で、7章は T5a-6 の中身に「結果と『もう一度挑戦する』の着地とフォーカス」と書く。計画は、結果のボックスへのフォーカスは T5a-6 に置き、「はじめる」へのフォーカスは T5a-5 に置いており、同じ種類の2つを別々に分けている。T5a-5 の builder は、7章では T5a-6 のものである「はじめる」へのフォーカスを先に組むことになり、T5a-6 の builder は自分の中身と書かれたものがすでに入っている形で始まる（第1回の指摘4と同じ型の読み違いの元）。

直し方の案（7章の文に合う形）: 「結果と開始の画面への切り替わり（最後の答え・最後の『次へ』・『もう一度挑戦する』）は、送りもフォーカスも T5a-6」という1つの決まりで分ける。T5a-5 の完了の条件から「やり直したあとにフォーカスが移る」を外し、T5a-6 の完了の条件に「やり直したあと（同じ状態の値）に送りの関数が呼ばれ、フォーカスが『はじめる』にある」を足す。T5a-5 はマウントのとき `body` のまま・150ms のあと次の問の見出し（と 4-3 の試験3の押した行）を受け持つ。逆に、T5a-5 にフォーカスをすべて持たせる決まりを採るなら、結果のボックスへのフォーカスも T5a-5 に移し、7章の T5a-6 の行との違いとその理由を計画に書く。どちらでも、やり直しの送りの試験は T5a-6 に要る。

### 3. `Button` を使うページの洗い出しが、`Button` を中に持つ部品を通る分を落としうる（軽い）

完了の条件は「`src/` で部品の名前を `grep` して洗い出す」と書く。`from "@/components/Button"` を直に読み込むのは試験を除いて32ファイル（道具16・ゲーム・診断の部品・storybook など）だが、そのうち `ShareButtons`・`CopyButton`・`ListStatus` は部品で、`ShareButtons` はブログ・辞典の詳細（`DictionaryDetailLayout`）・ユーモア辞典・道具のページの枠（`ToolPageLayout`）・ゲームの枠・診断の結果のページに、`CopyButton` は `DataTable` と道具十数本に、`ListStatus` は `BrowsableList` と辞典の目次に入る。直の読み込みだけを洗うと、ブログや辞典の詳細のような数の多いページが比べから抜ける。`ShareButtons` を通じてほぼすべての種類のページが入るので、cycle-316 の T5-28 が全 616 ページを比べた形（review-t5-28.md 115行）に近い量になる。

直し方の案: 「直に読み込むファイルに加えて、`Button` を中に持つ部品（`ShareButtons`・`CopyButton`・`ListStatus` と、それを使う `DataTable`・`BrowsableList` など）を読み込みの連なりでたどり、それらを使うページもすべて含める」と書く。

### 4. preventScroll の参考の文が、結論に要る2つ目の一次資料と、確かめ方の地位を書いていない（軽い）

参考の情報の最後の箇条は `element.cc` だけを挙げ、「Android だけの分かれは無い」から「この設計は Chrome for Android でも送られない」と結ぶ。Android で `preventScroll` が無視される道（文字盤が出たときの送り）は `element.cc` でなく `third_party/blink/renderer/core/frame/web_frame_widget_impl.cc` の `ScrollFocusedEditableElementIntoView` にあり、そこが編集できない要素で戻ることが、結論のもう半分の根拠である（第1回の記録が確かめた）。また、結論はソースの読みによるもので、実機では確かめていない。もう1点、「MDN `HTMLElement.focus()` は Baseline Widely available」は `focus()` の方法についての印で、`preventScroll` の引数についての印ではない（MDN の頁の Baseline の欄は方法に付く）。続く文で引数の互換性を書いているので誤りではないが、並べ方から引数も広く使えると読める。

直し方の案: 箇条に `web_frame_widget_impl.cc` の `ScrollFocusedEditableElementIntoView` が `preventScroll` と編集できない要素で戻ることを足し、結びに「ソースの読みによる。実機では確かめていない」を添える。Baseline の文は「`focus()` の方法は Baseline Widely available。引数の互換性は次のとおり」のように、何に付く印かを書く。

### 5. B-624 の題が今の欠陥と合わず、Notes が「次へ」をいつも画面の外と読ませる（軽い）

題「知識クイズで回答するとフォーカスがbodyに落ちる」は、t5a-design.md 1-2 のとおり T2 のあとは当たらない（いまはフォーカスは「次へ」へ移る）。Notes は「いまは答えると画面外の『次へ』へ送らずにフォーカスが移り」と書くが、1-2 は「『次へ』が画面の下にあればフォーカスが見えない」と条件付きで書く。

直し方の案: 題を、たとえば「知識クイズで回答したあとのフォーカスが見えず、読み上げが正誤と解説を飛ばす」にする。Notes は「いまは答えると『次へ』へ送らずにフォーカスが移るので、『次へ』が画面の下にあると見えず、SRは正誤と解説を飛ばす(t5a-design.md 1-2)」とする。
