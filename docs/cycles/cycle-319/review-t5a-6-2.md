- **offsetParent が押せる範囲と一致するか**: 実ブラウザで、問の画面・知識クイズの答えたあと・結果の画面の `data-hit-area="after"` の要素すべて（character-personality と traditional-color の 375×550、kotowaza-level の 375×550 と 1280×800。計 114 個）について、`offsetParent` と、その矩形の四隅と縁の中ほど（1px 内側）と、左右の 1px 外の点の `elementFromPoint` を見た。`offsetParent` は、問の選択肢の `button` では `li.choice`、`ItemList` の `a` では `li.row` で、ほかの祖先に当たったものは0。矩形の内側の 9 点はすべて要素に当たり、外の点が要素に当たったものは0。押せる範囲は `offsetParent` の矩形に合う。
- **避けすぎにならないか**: 違いは選択肢の行の下の罫線 1px だけで、そこは `li` に当たり押せない（`::after` の `inset: 0` は余白の箱まで）。行の矩形はこの 1px を含むので、1px だけ多めに避ける。避ける送りの有り無しを変えうるのは点が罫線の 1px に掛かる送りだけで、害は無い。いまの組みで `offsetParent` が行より外の祖先（ページの箱や `body`）になるものは無い。両部品とも `::after` を持つ要素の親か親の親が `position: relative` の行で、あいだに `transform` などの包む箱を作るものも無い。`globals.css` の規則は「`::after` の位置と大きさは部品が決める」と書くので、将来、行でない箱に `::after` を広げる部品が `data-hit-area="after"` を使えば、この数え方は合わなくなる。そのときは `pressableRectOf` の説明（「位置を決めた祖先（一覧と問の選択肢の行）」）と部品の両方を見直すことになるが、いま直すことは無い。
