## 指摘

### 1.（重）問の見出しが字の箱の張り出しを失い、字が並びの左端から 8px 右へずれている

`QuestionCard.module.css` の `.questionText` が `margin: 0 0 var(--space-16)` の一括指定を持つ。同じ詳細度の `globals.css` の `[data-text-box="inline"]` の `margin-inline-start: calc(-1 * var(--text-box-pad))` を、後から読まれるモジュールの規則が 0 で打ち消している。

実測（本番ビルド、375×550 と 320×550、character-personality・kanji-level で同じ値）:

| 要素                                | 左端                                                 |
| ----------------------------------- | ---------------------------------------------------- |
| h1 の字・選択肢の一覧の罫線（`ul`） | 27                                                   |
| 問の見出しの箱（`h2`）              | 27（張り出していない。`margin-left` の計算値は 0px） |
| 問の見出しの字                      | 35（h1 と進み具合の「1 / 12」より 8px 右）           |

- DESIGN.md §5「縁が見えないもの（…）は最初の字か形を揃え」「押せないがフォーカスを受けるもののうち…問が替わったあとの問の見出し…は字の箱を持つ」と、t5a-design.md 4-4（「見出しは字の箱を持ち、左へ 8 張り出して…字の幅はコンテンツ幅 − 8」）から外れる。
- 来訪者には、h1・帯の数・見出しの左端がそろわず、見出しだけが字下げされたように見える（quiz-after の像のどれにも出ている。例: `personality_q1_375x550_light.png` で見出しの字が x≈36、帯の「1 / 12」が x≈27。builder の報告はこれに触れていない）。
- 字の幅も設計の 258（320 の画面）でなく 250 になり、見出しが1行増えうる。B-614 の「入る」の測り（T5a-7 の条件1）の前提が崩れる。
- フォーカスのリングも、並んだコントロールのリングと同じ位置（DESIGN.md §5 の「リングが、並んだコントロールのリングと同じ位置に出る」）に出ない。
- jsdom の試験は `data-text-box="inline"` が付いていることだけを見るので、この崩れを見分けない（docs/anti-patterns/implementation.md **AP-I07**: レイアウトに依る不具合は jsdom の単体試験で見つからない。撮った像に出ていたのに報告で拾っていない点は **AP-I01**）。

直し方の案: `.questionText` の余白を上下だけの指定（`margin-block: 0 var(--space-16)`）にし、左右は `data-text-box` に任せる（`ListStatus` の `.text` が `margin-block: 0` にしているのと同じ形）。直したあと、本番ビルドで 375・320 の既定と 200% について、見出しの字の左端が h1 の字の左端と等しく、見出しの箱の左端がそれより 8px 左にあることを測って記録し、quiz-after の像（押した形・知識クイズの答えたあと）を撮り直して前の像と見比べる。

## PM が挙げた3点の確かめ

1. **区切らずに渡した面の字の折れ（「描／く」・行頭の「」」）**: T5a-5 では直さず、T5a-4 と T5a-7 の条件8 への申し送りで足りると判断する。
   - 原因は `PhrasedText` の `word-break: keep-all` と `overflow-wrap: anywhere` である。区切りが1つ（文の全体）なので、句読点のほかに折り所が無く、行に収まらない塊を `anywhere` が禁則を見ずに折る。押す前の `Button` と押したあとの字はどちらも `[choice.text]` を受けるので、押しても折れは変わらない（実測で、押す前と押したあとの箱の位置と高さが等しかった）。
   - T5a-4 で解けるかを、`splitIntoPhrases` に character-personality Q1 の問と4つの選択肢を通して確かめた。行頭の「」」の行は `["「昨日やり","残した","ことは","なかったか」","を思い返し、",…]` になり、閉じ括弧は前の文節の終わりに付く。「描く」の行は `[…,"中で","思い描く"]` になり、1字の行にならない。ほかの3つも最長の文節は「試したくなる」「アラームなしで」程度で、行の幅に収まる。行に収まらない文節があれば `anywhere` の折れは残るので、T5a-7 の条件8 の「語の中の折れが 0・1行に収まらない文節の中の折れは位置と数を記録」で拾う。
   - 申し送りに書くこと: T5a-5 の時点の画面は面の字を区切らないので、行頭の閉じ括弧と1字の行が出る。T5a-4 は区切りを渡したあと、375・320 の既定と 200% で、これらが消えたことを撮って確かめる。
   - 出荷は design-rollout の最後の1回なので、この途中の形は来訪者に届かない。
2. **`.questionText` から `font-family` が外れたこと**: 問題は無い。`globals.css` の `h1, …, h6` の規則が `font-family: var(--font-heading)` を持つ。本番ビルドでの h2 の計算値は `plexSans, "IBM Plex Sans Fallback", "Zen Antique", …` で、見出しの書体のままである（字の大きさは設計どおり `--text-heading-sub` の 17px、行間は 21.25px）。
3. **storybook と qr-code の差を「撮影のゆらぎ」とした判断**: 記録で裏付けられる。
   - 同じサーバーを2回撮った比べ（`cross/before-vs-before`・`cross/after-vs-after`）で、storybook の 200% の像はどちらも、ページの下端の近く（y≈101347〜102616。ページの高さは約 102616px）に同じ規模の差を持つ。既定の s6・s8 の 96×12px の差（368 画素）も、同じ座標で前どうし・後どうしに出ている。
   - qr-code の w320 s4 の 368 画素も、前どうしの比べに同じ形で出ている。w1280 の s5 が後に無いのは、最初の撮りの前だけが `Button` を5つ数えたためで、撮り直し（`recheck-*.log`）では前も後も4つで、撮り直しの前後の比べ（`recheck-diff`）で qr-code は全部同じだった。
   - 撮り直しの前後の比べで残った storybook の 200% の s3・s5・s6 の差は、後どうしの比べにも同じ所（s3・s5 は y≈1017 から、s6 は y≈11939 から）に出ている。
