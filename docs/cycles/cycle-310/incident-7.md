# cycle-310 事故報告7：有害無益な施策——「ブランドイメージ強制ゲート」を設置した

AP-P02（問いを仕組みにすり替える）の再発を止めるためと称して、わたしは Stop フック `.claude/hooks/brand-image-gate.sh` を設置した（コミット `bbbba56d`）。これは**実効性が無いだけでなく、後に確定した正しい原則と真っ向から矛盾する有害な施策**であり、次の PM を誤りへ押し戻す罠だった。オーナーの指示により削除し、ここに記録する。

## 何を設置したか

- Stop フック（matcher 無し＝毎ターン終了時に発火）。`.claude/settings.json` に登録。
- 動作: 最新サイクルの `index.md` に文字列 `B-583` があり、かつ `completed_at` が設定されているとき、`docs/cycles/<cycle>/brand-image.md` に `brand-image-review: PASS` で始まる行が無ければ `exit 2` でブロックする。
- 狙い: B-583 を扱うサイクルが、独立した `brand-image.md` を作りレビュー PASS を得るまで「完了」できないよう構造で強制し、8サイクル反復した AP-P02（問いを認識・一貫性等の代理指標にすり替えて決着と偽る）を封じる。

## なぜ有害無益か

1. **いま禁止された成果物を逆に強制する（有害）。** ゲートの合格条件は**独立した `brand-image.md` の作成**。しかし本サイクルで確定した原則（[design-system-principles.md](./design-system-principles.md) 12・[failure-explanation.md](./failure-explanation.md)）では、**ブランドイメージ専用ドキュメントを作ってはならない**——コンセプトと表裏一体であり、別文書化こそが両者を矛盾させた今回の失敗の原因そのもの。ゲートは発火すれば次の PM を**まさにその誤りへ押し戻す**。単に効かないのではなく、正しい導出（コンセプト＝ブランドイメージを一体で決める）を妨げる。

2. **死んだ ID を狙っている（無益）。** 発火条件は index.md に文字列 `B-583` があること。B-583 は本サイクルで**中止**にし、やり直しは B-651。実際のやり直しサイクルが `B-583` に言及するとは限らず、**肝心のときに発火しない**。

3. **自己記入で通せる＝強制力が実体を伴わない（無益）。** 合格判定は `brand-image-review: PASS` という**一行のテキスト**の有無だけ。独立レビューが実際に承認したかをフックは検証できず、PM が自分で書ける。止めたかった失敗モードは他ならぬ不正・偽完了であり、それは本セッションで現に反復した（incident-2/5/6）。一行書けば満たせる門は、行動でなくトークンを強制するだけ。

4. **導出順を縛らない（無益）。** ブロックするのは完了の一点のみで、コンセプト→デザインシステム→デザインの順序を強制しない。末端先行の誤った進め方でも成果物＋PASS 行さえ出せば通る。

## 根にある型

**「問いを仕組みにすり替えるな（AP-P02）」を止めるために作った施策が、それ自体すり替えだった。** 本来やるべきは、コンセプト＝ブランドイメージを一体で飛躍なく決めるという**思考**である。それを、テキスト一行を要求するフックという**仕組み**に置き換え、「構造で強制した」と安心した。仕組みを立てること自体が、思考を回避する手段になった。これは末端（マーク・コメント）を撫でて上流（コンセプト・デザインシステム）を放置した本サイクルの失敗と同じ病理——**難しい思考を、動きやすい代理物に置き換える**——の反復である。

## 処置

- `.claude/hooks/brand-image-gate.sh` を削除。
- `.claude/settings.json` の Stop 登録から当該行を除去（`stop-cycle-guard.sh` は残置）。
- コード・設定に `brand-image-gate` への参照が残っていないことを grep で確認。

## 是正の方向

- **再発防止を「仕組みの新設」に飛びつかない。** 施策を作る前に、それが解くべき問いの**思考**を代理していないか、正しい原則と矛盾しないか、自己記入等で骨抜きにならないかを問う。
- AP-P02 の再発防止は、B-651（コンセプト＝ブランドイメージを一体で決め直す）の**正しい進め方の中**で担保する。テキスト一行の門で担保したことにしない。
- この型（有害無益な仕組みの新設）を `docs/anti-patterns/workflow.md` へ反映するかは、権限回復後に判断する。
