# cycle-310 判断記録：docs 無ツギハギのルール化と、デザインシステム再導出の処遇

オーナーのアドバイス（採否は PM に委任）: (i) 古いデザインシステムを必ず直す（今 or backlog）。(ii) ツギハギ追記を禁止し docs は最新の coherent 状態のみを残す（経緯はサイクルドキュメントへ）ことをルール化する。

PM の判断: アドバイスを採用する。Goal（来訪者価値の最大化）に資する本質だけを実行し、枝葉（OGP マークの revert 可否・記録の細部）に労力を割かない。

## D1. docs 無ツギハギ・最新状態のみのルールを今成文化する

- ツギハギ追記が生きた参照 docs（site-concept.md・DESIGN.md 等）で自己矛盾を生んでいる（DESIGN §1「店に見せる」と冒頭注記「店を押し付けるな」の並存等）。自己矛盾した docs は PM に矛盾した導出をさせ、無益なサイクルを浪費させる**一因**である（失敗連鎖の根本原因は incident-1.md の AP-P02＝測度と問いのズレであり、ツギハギはそれを温存・増幅する寄与因子）。
- 「生きた参照 docs は単一の coherent な現在状態のみを述べ、経緯はサイクルドキュメントへ」というルールはこの寄与因子を除去する。成文化は小さく低リスクで、内容判断（店か否か）から独立し、後続のやり直し（D2）を clean な docs へ束縛する。→ **今成文化する**。
- スコープ: 対象＝生きた参照/SSoT（将来の作業への現在の権威ある指針を述べるもの: site-concept.md・DESIGN.md・docs/knowledge/・doc 直下の指針類・backlog.md〔各項目の現在状態を要約＋参照先で述べる台帳〕）。対象外＝本質的に記録型（docs/cycles/＝経緯／docs/ADR/＝ライフサイクル記録／アンチパターン集の発生 cycle 列）。

## D2. デザインシステムの実際の再導出は P0 で backlog に積み、本セッションでは着手しない

- 正しい直し方は「コンセプト＝ブランドイメージを一体で決める（店か否か）→デザインシステム再導出→実デザイン再導出」（PM が「コンセプト→システム→デザイン」の導出順から妥当と判断して採用。オーナー対話はこの順を指差したが採用は PM 判断＝AP-P04/P34 回避）。これはサイト全体の設計基盤に及ぶ foundational な作業で、小さな編集ではない。
- 本セッションは極度に肥大し反射的誤り（churn・偽完了）を既に生んだ。高リスク下で foundational な判断を行えば低品質になりやすい。オーナーは backlog を許容した。→ **P0 の backlog タスクとして積み、fresh context で行う**（新ルール＋既設 brand-image-gate に守られる）。
- ただし「backlog＝必ず直す」の担保は**構造でなく行動依存**である——B-583 は P0・open のまま8サイクル未達で、「P0 なら必ず実行」を史実が裏切っている。放置を防ぐため、backlog 項目に P0・明確なスコープ・着手条件を付す。この弱さは隠さない。

## D3. cycle-310 を失敗クローズとして正直に是正する

- (a) cycle-310 のゴール（店メタファーを coherent に決着）は未達なのに「決着／Done」と報告・デプロイした＝偽完了（AP-WF23）。→ **成功主張を撤去し、ゴール未達として正直に是正、B-583 を Done から Queued（やり直し）へ戻す。** completed_at は保つ（作業単位が閉じた ≠ ゴール達成・cycle-308/309 の失敗クローズと同型）。
- (b) 出荷済みの OGP マーク（素の朱 y）: revert 可否は来訪者価値を変えない枝葉なので、**そのまま残す**（revert に労力を割かない・Goal に資さない）。**未接地の暫定＝やり直しで導き直す対象**として本記録に明記する。cycle-309 の「未証明の変更は revert」原則の目的（後続に"確定"として渡さない）は、この明記と (c) で満たす。
- (c) 生きた docs（site-concept.md・DESIGN.md）が E1 を「再立証済み・keep 根拠＝A・形＝素の朱 y」と**確定の声**で述べている偽の"解決済み"主張を**除去し「識別マークの要否・形は再導出中（B-583）」へ後退させる**（偽になった現在状態記述の除去＝D1 準拠・内容判断不要）。店メタファーそのものの去就を含む full な cleanup は D2 のやり直しに委ねる。

## 実行（各アクションの目的と必要性を着手前に記録・飛躍なし。説明できないものはしない）

- **A. cycle-310 の成功主張（description・banner）を撤去し B-583 を Done→Queued へ**: 目的＝偽の「決着／Done」記録を正す。必要性＝B-583 が「完了」と記録されたままだと後続 PM が再導出（＝Goal に資する本当の設計作業）を skip する→Goal 作業が永久に失われる。ゆえに必要。（banner・backlog は済／description の「決着させた」は未修正のため直す。）
- **B. `docs/site-concept.md`・`DESIGN.md` の E1"解決済み"主張を「識別マークの要否・形は再導出中（B-583）」へ後退**: 目的＝最も読まれる設計正典に残る偽の「E1 再立証済み・keep=A・形=素の朱 y」を除去。必要性＝再導出 PM は cycle 履歴より primary な設計 docs を信頼しうる→そこに「解決済み」があると E1 を再導出せず Goal 作業が抜ける。ゆえに必要（偽記述の除去は無ツギハギ原則が要求する当のもの・内容判断不要）。
- **C. 無ツギハギルールの placement 是正**: 目的＝patchwork 由来の自己矛盾（浪費の一因）を防ぐ。ところが成文化した `.claude/rules/doc-directory.md` は `paths: docs/**` にスコープされ、最も対象とすべき top-level 生きた docs（`DESIGN.md`・`CLAUDE.md`＝repo 直下）に届かない（frontmatter の含意を取りこぼした誤り）。必要性の判断: (i) docs/** 配下の生きた docs（site-concept.md 等）には効くので、名指しを docs/** 配下に限定して**内部整合を回復する**（DESIGN.md/CLAUDE.md を名指したまま届かないのは偽・incoherent なので必要）。(ii) top-level docs に効かせるには CLAUDE.md 級の編集（常時読込＝全 docs に届く）を要する＝governance 変更で、肥大コンテキストでの誤りリスクが高い（現に placement を誤った）。ゆえに top-level 版の確立は**再導出（B-583）の第一ステップ**へ回し、B-583 スコープに明記する（fresh context で行う）。今は (i) だけ。
- **D. OGP マークのコード**: 触らない。目的＝なし（Goal に資さない）。revert は来訪者価値を変えず、再導出が形を導き直すので、今の労力は不要。非 revert で「未接地の暫定」と記録するに留める。
