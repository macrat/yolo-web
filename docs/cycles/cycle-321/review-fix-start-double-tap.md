## コードで確かめたこと

- 時刻は `performance.now()`（単調）。テストでは vitest の偽の時計が `performance.now` も進めることを、500 ミリ秒の前後で結果が分かれるテストが通ることで確かめた。
- `pressPointRef` は window の捕捉の段階の click で、React の click の処理より先に入る。`handleStart` と `handleAnswer` が読む時点で、いまの押しの点になっている。キーボードの click（detail が 0）では null で、そのとき時刻を覚えず、答えも受け付ける（§5 の軸2・軸3 どおり）。
- 時刻は「はじめる」のたびに上書きし、500 ミリ秒を過ぎれば何も止めないので、解除のもれは無い。やり直しのあとの開始でも上書きされる。戻る・読み込み直しでは部品が作り直され、null から始まる。
- `isWithinStartPressGuard` は依存の無い `useCallback` で、window の受け手を付け直す原因にならない。
- 押した瞬間の既定の動きを止めるのは、500 ミリ秒の中で、1問目の選択肢の `ul` の中に落ちた mousedown だけである。タッチの送りは touch のイベントで起き、互換の mousedown はタップのあとに来るので、送りは止まらない。マウスで止まるのは、その 500 ミリ秒の中に選択肢の上で始めたフォーカスの移りと字の引き選びだけで、害は無い。
- 送りの側で「はじめる」のあとに1問目の選択肢を避けるのを外した（`exclude: stage`）。問の区画の外の押せるもの（よくある質問の開閉など）は引き続き避ける。`revealLanding` の `avoidNext` は知識クイズの「次へ」で使われ続けていて、使われなくなったコードは残っていない。
- `npx vitest run src/play/quiz/_components/__tests__/`: 28 ファイル・325 件が通った。
- DESIGN.md §8 の2つの項は実装と合っている。コード（QuizContainer.tsx）のコメントに経緯の言葉（直した・以前は）は無い。

## 直すもの（来訪者の損ではないが、後の作業を誤らせる）

### 1. `docs/knowledge/input-events-and-guards.md` の冒頭の段落が、自分と食い違っている

同じ段落の中で、「指やマウスで押した『はじめる』から 500ms のあいだ、1問目の選択肢への指やマウスの押しを受け付けない」と足した一方で、段落の終わりに「**時間ガードと `pointer-events` の窓は使っておらず**、二重発火の扱いは B-620 で判断する」が残っている。いまは時間ガードを1つ使っている。後の担当が「診断・クイズには時間ガードが無い」と読んで判断を誤る（B-620 を扱うときなど）。段落の終わりを、いまの作りに合うように書き直すこと（たとえば、時間ガードはこの1つだけで、2問目からの切り替わりと `pointer-events` の窓は使っていない、など）。足した文が段落の途中に差し込まれた形になっているので、段落ぜんたいを通して読める順に組み直すこと（CLAUDE.md の No patchwork）。

### 2. テストに、何も確かめていない書き足しが残っている（No patchwork）

- `QuizContainer.reveal.test.tsx` の「診断の答えのあとは、点の真下に次の問の選択肢が来ても送らない」と「知識クイズで答えたあと、基準の送りで点の真下に『次へ』が来るときは…」の2つは、「はじめる」をキーボード（`detail: 0`）で押しているので、受け付けないあいだは始まらない。足した `await advance(START_PRESS_GUARD_MS)` は何もしていない。読む人は「キーボードで始めても待たないと押せない」と読み違える。消すこと。
- `QuizContainer.secondPress.test.tsx` の `renderAndStart` は「はじめる」を `HTMLElement.click()` で押している。jsdom の `click()` は detail を渡さない（0）ので、キーボードの押しとして扱われ、受け付けないあいだは始まらない。足した `performance.now` の差し替え・`now += START_PRESS_GUARD_MS`・関数の説明「1問目の選択肢が指やマウスの押しを受け付ける時刻まで進める」は、どれも働いていない。消すこと（担当の報告の「1問目を指やマウスで押すテストなので、時刻を 500 ミリ秒進めてから押す形にした」も、理由が違う）。

### 3. 「2問目からは、切り替わりの直後の指やマウスの押しも答えになる」のテストが、名前のことを確かめていない

`QuizContainer.answer.test.tsx` のこのテストは、500 ミリ秒進めてから1問目に答え、さらに 150 ミリ秒進めてから2問目を押す。2問目を押すのは「はじめる」から 650 ミリ秒後で、受け付けないあいだはもう終わっている。`handleAnswer` の `currentIndex === 0` の条件を消しても、このテストは通る。DESIGN.md §8 の「2問目からは…どの押しもすぐに受け付ける」を守るテストになるよう、受け付けないあいだの中で2問目を押す形にすること（たとえば、指で「はじめる」を押し、1問目をキーボードで答え、500 ミリ秒の中で2問目を指で押して、答えになることを確かめる）。
