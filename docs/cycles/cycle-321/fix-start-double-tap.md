# 「はじめる」の速い二度押しの直し

確かめた日: 2026-11-11。測った版は、ポート 3104 のビルド（コミット e3472ea に、この直しを重ねたもの）である。

## 結論

- **「はじめる」を指やマウスで押してから 500 ミリ秒のあいだ、1問目の選択肢が指やマウスの押しを受け付けないようにした。** 「はじめる」のあとに1問目のまとまりを見せる送りは残している。
- 同じスクリプト・同じ 98 組で測り直し、**「はじめる」の組（92 組）で、直した版に害（読んでいない問に答えが入る）は1つも無かった。** 標準の文字サイズでも文字サイズ 200% でも、新しい版だけ害（D）は 38 → 0、どちらも害（C）は 24 → 0。
- 「次へ」（最後の問）の組は、直した版では前と同じく 36 回とも何も起きなかった。
- ふつうの使い方は変わらない。「はじめる」の 600・700・800 ミリ秒あとに1問目の選択肢を1度押すと、36 回とも答えが入った。1問目で選択肢が4つとも画面に入ることも、直す前と同じだった（375×550・320×550 の 15 本とも）。

## 直した中身

- `src/play/quiz/_components/QuizContainer.tsx`
  - 定数 `START_PRESS_GUARD_MS = 500` を置いた。二度押しの2打目が届く間隔より長く、1問目を読んで答えるまでの時間より短い長さである。
  - 「はじめる」を指やマウスで押した時刻を `performance.now()`（端末の時計を変えても動かない時刻）で覚える。1問目の選択肢への指やマウスの押しが、その時刻から 500 ミリ秒より前なら、何もせずに捨てる（答えを記録しない・選んだ形に見せない・画面を送らない）。500 ミリ秒を過ぎた押しは、すぐに受け付ける。
  - 掛かるのは「はじめる」から出た1問目だけである。2問目からの押し、知識クイズの「次へ」、「もう一度挑戦する」には掛からない。「もう一度挑戦する」のあとに開始の画面で「はじめる」を押し直したときは、また掛かる。
  - キーボードの押しには掛けない。「はじめる」をキーボードで押したとき（click の detail が 0）は時刻を覚えず、そのあとの押しはどれもすぐに受け付ける。答えのほうをキーボードで押したときも、すぐに受け付ける。キーボードの押しには、同じ点に落ちる2打目が無いからである（`docs/knowledge/input-events-and-guards.md` §5 の考え方に合わせた）。
  - 受け付けないあいだに選択肢へ落ちた押しでは、ブラウザがフォーカスを問の見出しから選択肢のボタンへ移す動きも止める（押した瞬間の既定の動きを止める）。選択肢の見た目は変えず、遅らせて出すこともしない。
  - 「はじめる」のあとの送りで、1問目の選択肢をよける働きを外した。2打目は受け付けないあいだが止めるので、要らなくなったためである。知識クイズの「次へ」のあとに次の問の選択肢をよける働きと、ほかの押せるもの（リンクなど）をよける働きは、そのまま残している。`src/lib/reveal.ts` は変えていない。
- テスト（`src/play/quiz/_components/__tests__/`）
  - `QuizContainer.answer.test.tsx` に足した: 500 ミリ秒より前の押しは答えにならず、選んだ形もフォーカスも変わらない／500 ミリ秒を過ぎた押しは答えになる／捨てたあとに押し直すと答えになる／受け付けないあいだは押した瞬間の既定の動きを止め、過ぎたら止めない／キーボードの押しはすぐ答えになる／キーボードで「はじめる」を押したあとは指やマウスの押しもすぐ答えになる／2問目からは、500 ミリ秒より前の押しも答えになる（指で「はじめる」→ キーボードで1問目に答える → 150 ミリ秒後に指で2問目を押す。実装の「1問目だけ」の条件を外すと落ちることを確かめた）／「もう一度挑戦する」のあとに始め直した1問目でも掛かる。
  - `QuizContainer.reveal.test.tsx`: 「はじめる」の点の真下の選択肢をよけて送るテストを、よけない（送らない）ことを確かめるテストに替えた。
- `DESIGN.md` §8: 送りをずらす項で、次の問の選択肢をよけるのは知識クイズの「次へ」のあとだけと書き、「はじめる」のあとの1問目の選択肢は送りではよけないと書いた。その次に「『はじめる』を押してから 500ms のあいだ、1問目の選択肢は、指やマウスの押しを受け付けない」の項を置いた。
- `docs/knowledge/input-events-and-guards.md`: 冒頭の、診断・クイズのいまの作りを書いた段落に、この受け付けないあいだを足した。

## 採らなかった案: 「はじめる」のあとに画面を送らない

はじめに、計画どおり「はじめる」のあとに画面を送らない（本番と同じふるまいにする）直しを試した。同じ 98 組で測ると、新しい版だけ害（D）は 38 → 40 に増え、標準の文字サイズの 375×550 では 10 → 16 組に増えた（A 22 → 19、B 14 → 1、C 24 → 38）。`/play/character-personality` の 375×550 も D のままだった。

理由は、送らなくても「はじめる」の真下に1問目の最初の選択肢が組まれるからである。新しい版では、開始の画面（事実の行 → 一文 →「はじめる」）と1問目（進み具合の帯 → 見出し → 選択肢）が同じ高さから積まれ、見出しが2行のとき、最初の選択肢の上端が「はじめる」の中心の約 3px 上に来る（character-personality は点 (70, 350) に対して選択肢の上端 346.6）。見出しが1行なら約 24px 上、見出しが3行のときだけ点が見出しに来る。本番と同じ版は、同じ診断で点が見出しの下端の数 px 上にあるだけだった。

送らないと、1問目で選択肢が4つとも見える診断は、375×550 で 15 本から 6 本に、320×550 で 15 本から 3 本に減り、本番と同じ版より見えなくなる診断もあった（375×550 の traditional-color と yoji-personality、320×550 の7本）。この案の変更はすべて元に戻した。

## 確かめられなかったこと

- **実機では確かめていない。** ぜんぶヘッドレスの Chromium のタッチのエミュレーションである。指の押しが click の detail を 1 以上で届けること、押した瞬間の既定の動きを止めるとフォーカスが移らないことが、iOS の Safari と Android の Chrome の実機でも同じかは見ていない。detail が 0 で届く端末があれば、その押しはキーボードの押しとして扱われ、受け付けないあいだが掛からない。
- 読み上げ（VoiceOver・TalkBack）のダブルタップで押したときに、受け付けないあいだが掛かるかどうかは確かめていない。掛かった場合でも、500 ミリ秒を過ぎて押し直せば答えになる。
- 500 ミリ秒より遅い2打目（たとえば 600 ミリ秒）は答えになる。測った間隔は 90ms と 300ms のねらいだけである。
- 「はじめる」のボタンの中心だけを押した。
- 画面は 375×550 と 1280×800（見え方は 320×550 も）だけで、ダークの配色と、動きを減らす設定では試していない。
- 1問目の見え方の「直す前」に使ったポート 3101 のビルドが、いまの作業ブランチと同じコミットかは確かめていない。
