## 結論

- 選択肢の文を、サーバーで文節に分けてから渡し、文節の切れ目でだけ折るようにした。
- `/play/character-personality` の全 12 問・48 個の選択肢で、「行頭に閉じ括弧・句読点が来る」「1字だけの行」は、375×550 でも 320×550 でも 0 個になった（本番は 2 個と 4 個、直す前は 6 個と 12 個）。
- 頼まれた案（選択肢の字だけブラウザの既定の折り方に戻し、`word-break: auto-phrase` を重ねる）は採らなかった。`auto-phrase` が効かないブラウザ（Safari と Firefox）に当たる状態で測ると、375 幅で 4 個・320 幅で 5 個になり、本番（2 個・4 個）を上回って、目標の線を満たさないからである。
- 押す前と押したあとで、折れる位置は変わらない。1280×800 の表示は直す前と同じである。

## 原因

見立ては正しかった。直す前の画面で、選択肢の字に当たっている指定を読むと `word-break: keep-all`・`overflow-wrap: anywhere`・`line-break: strict` だった。`QuestionCard` が選択肢の文の全体を1つの区切りとして `Button` と `PhrasedText` に渡していたので、文の中に折り所が1つも無く、ブラウザが折れるのは句読点と閉じ括弧の後ろだけだった。句読点までのひと続きが1行に入らないと、入りきらなくなった所でそのまま折れ、「、」だけの行や、行頭の「」」、1字だけの行ができていた。

`<html lang="ja">` であることは、ソース（`src/app/layout.tsx`）と、開いた画面の両方で確かめた。

## 採った案と、採らなかった案

### 採った案: サーバーで文節に分けて渡す

- どのブラウザでも同じ所で折れる。来訪者の多いスマートフォン（iPhone の Safari を含む）でも、文節の切れ目で折れる。
- このサイトの見出し・ボタンの名前・表のセルと同じ仕組みで、新しい折り方の決まりを足さない。
- 文節は短い（`/play/character-personality` でいちばん長い文節は「シミュレーションする」の 10 字。320 幅の1行は全角 13 字）ので、文節が1行に入らずに中で折れることが無い。
- クライアントに送るデータは、選択肢の文節の並びのぶんだけ増える（いちばん多い診断で 80 個）。文節に分ける辞書はサーバーだけにあり、ブラウザには送らない。

### 採らなかった案: 選択肢の字だけ `word-break: normal` に戻し、`auto-phrase` を重ねる

- `auto-phrase` の対応状況（MDN の対応表の元データ `browser-compat-data` の `css.properties.word-break.auto-phrase`）: Chrome 119 以降（Edge・Android の Chrome も同じ）。Firefox は未対応。Safari は試験版（Technology Preview）だけで、ふつうの Safari では効かない。Chrome でも、言語が日本語か韓国語の文にだけ効く。
- `auto-phrase` が効く場合（Chromium で実測）は 375 幅・320 幅とも 0 個で、線を満たす。
- 効かない場合（`word-break: normal`・`line-break: strict`・`overflow-wrap: anywhere` を選択肢の字に当てて実測）は、375 幅で 4 個・320 幅で 5 個で、本番の 2 個・4 個を上回る。本番より字が大きく（17px と 16px）、1行に入る字が少ない（375 幅で 17 字と 19 字）ので、同じ既定の折り方でも、最後の1字がこぼれる選択肢が本番より増える。
- 両方で線を満たすことが採る条件だったので、採らなかった。

- **1問の選択肢が1画面に入る**: 375×550・320×550 とも、12 問すべてで 4 つの選択肢の行が画面の中にあった（いちばん下の行の下端は 541px）。行数の合計は直す前より減った。
- **横スクロール**: どの問にも無い。コンソールのエラーも無い。
- **1280×800**: `/play/character-personality` の 48 個の選択肢はすべて1行で、選択肢ごとの行の高さと行数は直す前の版と同じだった。画面も撮って見た。
- **ほかの 14 本**: 375×550 と 320×550 で全問・全選択肢を測り、どれも当たるものは 0 個、4 つの選択肢が画面に入り、横スクロールは無かった。診断 10 本は、押す前後の折れ方も同じだった。

## 残った件

- `/play/character-personality` に、残った件は無い（375 幅・320 幅とも 0 個）。
- ほかの 14 本にも、375 幅・320 幅で当たる選択肢は無かった。
- 文節の分け方は辞書（BudouX）に任せているので、語の中に切れ目が入ることがある。見つけたのは「一度｜立ち｜止まって」の1つで、「立ち / 止まって」で折れうるが、375 幅・320 幅の実測ではそこで折れなかった。
- 問の見出し（h2）は触っていない。375 幅・320 幅の 12 問で、見出しに当たるものは無かった（前の調べも 0 個）。ただし見出しは `auto-phrase` に任せていて、Safari と Firefox では既定の折り方になる。そちらでの見出しの折れ方は測っていない。

## 確かめられなかったこと

- **iPhone の Safari（実機）と Firefox では確かめていない。** この環境のブラウザは Chromium だけである。直したあとの折り方は、どのブラウザも対応している指定（`word-break: keep-all` と `<wbr>`）だけで決まり、`auto-phrase` に頼らないので、同じ所で折れるはずだが、実機での確かめではない。
- **書体が実機と違う。** この環境には実機の和文の書体が無く、選択肢の字は環境の書体で描かれた。全角の字の幅はどの書体でも1字分なので、折れる位置はおおむね同じになるはずだが、半角の数字や英字を含む行は1字ずれることがありうる。
- 採らなかった案の数は、案をコードに入れてビルドしたものではなく、開いた画面の選択肢の字に指定を当てて測ったものである。
- 文字を大きくした設定（200%）、横向き、ダークでは測っていない。
- 確かめに使ったビルドは、この直しだけを入れたものである。同じ時に別の担当が直していたファイル（一覧のページなど）は入っていない。
