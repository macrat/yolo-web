## 指摘

### 1. 選択肢の下線で「答えになった」を確かめる行が、答えていなくても通る（偽のテスト）

選択肢のボタンは、押す前から `buttonUnderlineClassName` を持つ（同ファイル冒頭の「押した行の字だけが押す前と同じ下線を持ち」）。そのため `expect(faceOf(x)).toHaveClass(buttonUnderlineClassName)` は、答えが記録されなくても真になる。上の表のとおり、次の2件は名前のふるまいを壊しても落ちない。

- 「キーボードの押しは、500ms より前でも答えになる」（キーボードの答えも捨てる実装で通る）
- 「キーボードで「はじめる」を押したあとは、500ms より前の指やマウスの押しも答えになる」（キーボードで始めても掛ける実装で通る）

同じ行は「500ms を過ぎた…すぐ答えになる」「2問目からは…」「もう一度挑戦する…」の中にもあり、そこではほかの行（問の番号・答えの並び）が実際に確かめているが、下線の行そのものは何も確かめていない。「答えになった」は、字の箱が `SPAN` になったこと・ほかの行がボタンでなくなったこと（`queryByRole("button", { name: /^選択1/ })` が null）・`ANSWER_SHOWN_MS` のあとに問の番号が進むこと・結果の答えの並び、のどれかで確かめる。下線は「押す前と同じ下線を持つ」を確かめるときだけ、SPAN であることと組にして使う。

### 2. 500ms という長さを、どのテストも固定していない。「2問目から」のテストの前提もそれに寄りかかっている

テストは長さを `START_PRESS_GUARD_MS` から読むだけなので、定数を 300 や 100 に変えても全件通る。テストの名前は「500ms」と言い、DESIGN.md §8 と知見の文書は 500ms を「二度押しの2打目が届く間隔より長く、1問目を読んで答えるまでの時間より短い」値として決めている。値を変えれば DESIGN と食い違うのに、テストが気付かない。

さらに「2問目からは、500ms より前の指やマウスの押しも答えになる」は、「「はじめる」から 150ms で、1問目なら押しを受け付けないあいだにいる」（`ANSWER_SHOWN_MS` < `START_PRESS_GUARD_MS`）を前提にしている。定数が 150 以下になると、このテストは1問目だけに掛ける条件を確かめなくなる（長さ 100 と `currentIndex === 0` の除去を組み合わせても全件通った）。長さを `expect(START_PRESS_GUARD_MS).toBe(500)` で固定するか、境目のテストを 499 / 500 の数で書く。あわせて「2問目から」のテストの中で、押した時点がまだ受け付けないあいだにいること（`ANSWER_SHOWN_MS < START_PRESS_GUARD_MS`）を明示して確かめる。

### 3. 「選んだ形もフォーカスも変わらない」のフォーカスの行は、何も確かめていない

「500ms より前の指やマウスの押しは答えにならず、選んだ形もフォーカスも変わらない」は `fireEvent.click` だけを送る。実ブラウザでフォーカスを選択肢へ移すのは mousedown の既定の動きで、jsdom の click はフォーカスを動かさないので、`expect(document.activeElement).toBe(heading)` はどんな実装でも真になる（`preventDefault` を外しても、このテストは落ちない）。フォーカスを守っているのは次の「既定の動き（フォーカスの移り）を止め…」のテストである。名前から「フォーカスも」を外してフォーカスの行を消すか、そのテストで mousedown も送り、その戻り値（既定の動きを止めたか）を確かめる形にする。

### 4. 既定の動きを止めるのを「選択肢へ落ちた押し」に限る条件を、どのテストも確かめていない

`stopUnwantedPressDefaults` の `choicesRef.current?.contains(event.target)` を外して、受け付けないあいだのページ中の mousedown をすべて止めても全件通る。知見の文書（「選択肢へ落ちた押しがフォーカスを移す動きも止める」）と DESIGN の範囲を守るため、受け付けないあいだに選択肢の外（例: 問の見出し）へ落ちた mousedown は止めないことを、指やマウスで始めたあとのテストで確かめる（secondPress の「問の見出しの字の上で始めたダブルクリックは、語を選べる」はキーボード扱いの `.click()` で始めるので、受け付けないあいだに入っておらず、これを確かめていない）。
