## 作業計画

### 目的

本番のサイトは、刷新が止まっているあいだ古いデザインのままで、来訪者は更新の止まったサイトを見続けている。作り直した画面（読みやすい組版・ブラウザの文字サイズの設定が効くこと・フォーカス時に拡大しない入力欄・狭い画面で4択が見える診断の回答画面など）は、作業ブランチの中にあるだけで誰にも届いていない。このサイクルは、それを来訪者に届ける。

`docs/site-concept.md` の来訪者への約束は「面白いものがここにあります」と渡すものを決め、面白いかを来訪者の行動で確かめると定める。行動で確かめるには、まず本番に出ていなければならない。出荷は、ADR009 の観測（出荷の直前28日を基線にする）が始まる条件でもある。

**達成の条件**: 新しいデザインが本番（yolos.net）で配信され、本番で表示と主な操作と計測が確かめられていること。出荷の前の確かめは、「来訪者が、いまの本番より悪い画面を受け取らない」ことだけを線にする。

### 作業内容

タスクの中身と線は [cycle-320/rollout-plan.md](../cycle-320/rollout-plan.md) にあり、ここには進め方だけを書く。

- **順序**: T1 を最初に行う（ビルドが通らなければ、ほかの確かめができない）。T2a〜T2e と T3 は互いに独立なので、1タスクを1つのサブエージェントに頼む。同じファイルを直すことになったタスクは、並べずに順に行う。T4 は T1〜T3 の直しが出そろってから行う。
- **比べる相手**: T2a・T2b・T2c・T2d は、本番（https://yolos.net 。2026-11-11 にこの環境から 200 で届くことを確かめた）と、作業ブランチを `npm run build` して `npm run start` で起こしたものを比べる。T3 だけは、同じ機械で測るために origin/main もこの環境でビルドする。
- **直す範囲**: 確かめで見つけたもののうち、直すのは「本番より悪い」「表示が壊れている」「主な操作ができない」「記事の説明が画面と食い違う」ものだけである。本番にもある不具合と、新しいデザインの細かい規則が当たっていないだけの所は、backlog に書いて直さない。刷新が意図して変えたもの（解き終えた画面の保存と共有のボタンの位置など。ADR009 が見張る）は戻さない。
- **レビュー**: 確かめのタスクは、結果の一覧と撮った画面を reviewer に通す。直しを伴ったタスクは、その差分も通す。指摘への対応のなかで、来訪者が受け取るものを変えない修正だけが3回続いたら、そこで止めて次へ進む（cycle-kickoff の手順8）。
- **出荷**: このセッションの作業ブランチは `ccr-a14a408a-0hld66`（開始時点で `design-rollout` と同じコミット a8070aa。origin/main は取り込み済み）で、ほかのブランチへの push は許されていない。出荷は main への push なので、T1〜T4 を終えたら、結果を添えてオーナーに確かめ、許可を得てから行う。Instant Rollback で戻れるのは、Hobby プランではすぐ前の本番のデプロイだけなので（下の参考の情報）、本番で確かめ終えるまで main にほかの push をしない。戻したあとは、Vercel が本番ドメインの自動の割り当てを止めるので、直したものを出すときは promote が要る。
- **記録**: 確かめの結果は `docs/cycles/cycle-321/` に、タスクごとの別ファイルで置き、ここには結果の1行とリンクだけを残す。撮った画面は `./tmp/` に置く。

### 検討した他の選択肢と判断理由

- **確かめを省いてすぐに出荷する**: 最も早い。けれど 1,892 ファイルが変わっていて、閲覧の約8割を占める診断のプレイ面が本番より悪くなっていれば、出荷がそのまま来訪者の害になる。Hobby プランでは戻れる先がすぐ前のデプロイだけなので、出してから直すやり方は戻す道を狭くする。採らない。
- **cycle-316 の計画の残り（T5・T5a・T6〜T12）を終えてから出荷する**: cycle-316〜320 がこれを試み、出荷に必須でない作業に日数を使って何も届けなかった（cycle-320 の incident-2.md）。残りは、古いトークンの定義が残っているので表示を壊さず、出荷のあとに続けられる。採らない。
- **選んだ案（本番より悪くないことだけを確かめて出荷する）**: 確かめの線を「本番との比較」に置くので、作業の終わりがはっきりし、来訪者にとっての害だけを拾える。cycle-320 でレビューを4回通した rollout-plan.md を、そのまま使う。
- **T2 を1つのタスクにまとめる**: 頼む文は短くなるが、1人が診断の通しの比較・二度押し・全テンプレート・sitemap・記事の直しを抱えると、文脈が溢れて途中で止まり、レビューも1回で全体を見られない。5つに分ける（CLAUDE.md の「Keep task smaller」）。
