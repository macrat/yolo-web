# レビュー: DESIGN.md の線の太さの決まりと、語を選ぶゲームの盤のリングの例外

判定: **要修正**

対象: `DESIGN.md` §5「線」の冒頭と表（133〜138 行）、§5 の「語を選ぶゲームの盤」の決まり（204 行）、§6 の状態の表の「フォーカス」の行（273 行）、§6 の二重リングの項（301 行）。突き合わせた実装は `src/play/games/nakamawake/_components/WordGrid.module.css`・`WordGrid.tsx`・`GameContainer.module.css`・`SolvedGroups.module.css`、`src/app/globals.css` の `:focus-visible`・部品のリング・`[data-thick-frame]`。

## 確かめたこと（問題なし）

### 1. 例外を書いた4か所どうし

- §5 冒頭「例外は1つだけで、語を選ぶゲームの盤の、左右の内側の余白が 4px のマスに出るフォーカスの外リングを 2px」、表「フォーカスの外リング（上の例外のマスを除く）」、§5 の盤の決まり「リングの外の輪だけは、太い線より細い 2px（上の『線』の例外）」、§6 の表「左右の内側の余白が 4px のマスだけは、内が 1px、外が 2px」、§6 の二重リングの項「2px の輪は…ただ1つの例外で、ほかのリングには使わない」。どこから読んでも、例外の中身（どのマス・どの線・何 px）と範囲（そのマスの外の輪だけ）は同じ所に行き着く。寸法を持つのは §6 の二重リングの項だけで、ほかはそこを指している。
- 内の `--paper` の 1px と、hover の 1px の線は細い線の太さで、例外は 2px の輪だけ、という整理も食い違わない。
- 文書の全体を「太さ・リング・輪・hover・縁の内側・2px・1px」で grep した。§2 の色の表（内リング・外リング）、§5 の「縁の内側 8px」（201 行。204 行がこのマスは従わないと明記）、§10 の画像の線（§5 の2種類を2倍で引く）、§12 のコントラストとフォーカス、どれも例外と食い違わない。

### 2. 実装との寸法

`.wordButton` の式（`--cell-ring-w = min(3px, 余白 − 2px)`、`--cell-ring-gap = min(3px, 余白 − 輪 − 1px)`、`outline-offset = −(枠 + 地 + 輪)`、塗り `inset (地 + 輪)`、hover `inset 地 の --paper` と `inset (地 + 1px) の --rule-2`）を、マスの縁（枠の外側）から測って解いた。

| 余白 | 枠   | 地（挟む `--paper`） | 輪          | 輪と字のあいだ | hover の線  |
| ---- | ---- | -------------------- | ----------- | -------------- | ----------- |
| 8px  | 0〜3 | 3〜6（3px）          | 6〜9（3px） | 9〜11（2px）   | 6〜7（1px） |
| 4px  | 0〜3 | 3〜4（1px）          | 4〜6（2px） | 6〜7（1px）    | 4〜5（1px） |

8px のマスは `globals.css` の `[data-thick-frame]`（offset −9px・塗り 9px・hover は 3px の `--paper` の内に 1px）と同じ値になる。§5 の「マスの幅いっぱいに入る行だけが縁の内側 4px に届く」、§6 の「輪と字のあいだに 1px 以上」「中身は輪の内側に 2px 以上」と合う。

どの組みで 4px になるか: `.frame` が `45rem` 未満で `--word-stacked-pad` を 4px にし、`--cell-pad` がそれを取るのは四角を語の上に置く組み（2列で上・4列で上）だけ。1列・2列で左・広い4列（左）は 8px。`GameContainer.module.css` の `--board-gap` も `45rem` で 4px／8px が切り替わり、`SolvedGroups` も同じ間隔を使う。§5 の「`45rem` 未満の画面で、マスどうしの間隔と、印を語の上に置くマスの左右の内側の余白を 4px」「印を語の左に置くマスの左右の余白は 8px」と合う。

### 3. 決まりとしての読まれ方

- 中間の太さを持ち込む余地: §5 冒頭の「ほかの線とリングには、あいだの太さを使わない」と、§6 の「ほかのリングには使わない」の2か所で閉じている。範囲は「左右の内側の余白が 4px のマス」と寸法で決まっていて、「狭いマス」のような広げられる言い方になっていない。
- 3px に戻す余地: §5 冒頭と §6 の両方が「4px の中に太い線の太さの輪を置くと字に重なる」という理由を持ち、戻すと何が壊れるかが読める。

### 4. 経緯の言い回し

「直した」「以前は」の類は無く、どの文もいまの決まりとして書かれている。§5 冒頭の理由（見渡せることを優先して1か所にだけ例外を置く）も、いまの判断の理由として読める。

## 指摘

### 指摘1（要修正）: 語のマスの hover の線の決まりが §6 の hover の項になく、その下敷きになる「太い枠のコントロールの hover の線は、枠の内側に太い線の太さの `--paper` を挟む」がどこにも書かれていない

- §6 の二重リングの項（301 行）の終わりに「このマスでは、hover のボーダーも枠の内側に 1px の `--paper` を挟んで出る」とある。「も」が前提にしているのは、太い枠のコントロール一般の hover の線が枠から離して出ること（`globals.css` の `[data-thick-frame]` の `--hover-line`、3px の `--paper` の内に 1px の線。8px のマスもこの値）だが、これは `DESIGN.md` のどこにも無い。hover の決まりを持つ §6 の 303 行は、一覧の行・反転した地・色見本の3つの場合しか書いていない。
- そのため、§6 の hover の項だけを読んで次の太い枠のコントロールを作る人は、細い線を太い枠に接して引きうる。接した 1px は 3px の枠と一続きになり、4px の太い線に見える。これは今回の §5 が閉じようとした「あいだの太さ」が、hover の側から入り込む形である（見てほしい点の3）。また、語のマスの hover の 1px の地は、書かれていない一般の決まりからの例外として、リングの項の中にだけ置かれている。hover の決まりを探す人はリングの項を読まないので見つけにくく、リングの項の流れの中では、hover の1文が後から挟んだように浮いている（見てほしい点の4）。
- 直し方の案: 303 行の hover の項に、色見本・反転の地と並べて「太い枠が縁として見えるもの（ゲームの盤のマスなど）は、枠と一続きにならないよう、枠の内側に太い線の太さの `--paper` を挟んでボーダーを引く。左右の内側の余白が 4px の語のマス（§5）だけは、挟む `--paper` を 1px にする。ボーダーはどちらも細い線」の中身を書き、301 行の hover の1文はそちらへ移す。§5 の 204 行の「フォーカスのリングと hover のボーダーは、この 4px の中に、字に触れない位置で出す」は、そのままで両方の項を指せる。

### 指摘2（要修正・小）: 「印」が何かが `DESIGN.md` に無く、例外の範囲を決める「印を語の上に置くマス」が文書だけでは特定しにくい

- 204 行は例外の範囲を「印を語の上に置くマス」で決めているが、語のマスが 20px の四角（§6 のチェックボックスと同じ形）を持つことは `DESIGN.md` のどこにも書かれていない。文書の中で「印」はほかに §8（415 行）の「ゲームの盤の判定の印（1字の印）」として出てくるので、別の盤の印と読み違えうる。
- 四角を語の上に置くか左に置くかの決め方（マスの1行に4字が入るか、幅にゆとりがあるか）も文書には無く、`WordGrid.module.css` のコメントにだけある。例外の範囲そのものは「左右の内側の余白が 4px のマス」で一意に決まるので、来訪者の画面をすぐ悪くするものではないが、次にこの盤を組み直す人が「どのマスが例外か」を文書から辿れない。
- 直し方の案: 204 行で「印」を、選んだかを示す 20px の四角（§6 のチェックボックスと同じ形）と一度言い、四角を語の上に置くのは、語の左に置くとマスの1行に4字が入らない組みであることを1文で添える。
