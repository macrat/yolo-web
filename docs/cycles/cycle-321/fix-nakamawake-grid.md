# ナカマワケの盤をスマートフォンの1つの画面に収める直し

## 結論

375×667・360×640・390×844 のどれでも、言葉のマスが4列×4行に並び、盤の最初のマスの上端から「チェック」の下端までが画面の高さに収まるようになった。今日の問題で 433px（直す前は 747px）。50 問すべてを通しても、いちばん長い日で 608px。320×568 は2列のままだが、今日の問題で 531px（直す前は 747px）に縮み、50 問のうち 48 問で収まる。1280×800 は、直す前と1画素も変わらない。

## 採った案と採らなかった案

**採った案: 狭い画面でも4列×4行にする（依頼の案 a）。入らない幅では2列のまま四角を左に置く（案 b）。**

- 直す前は、4列にすると 375px 幅でマスの1行に 3.7 字しか入らなかった（コンテンツの幅 321px から、間隔 24px・枠 24px・余白 64px を引いて4で割ると 52px。字は 14px）。間隔と余白を 4px にすると、375px 幅で 63px（4.5 字）、360px 幅で 59.5px（4.25 字）になり、これまでの決まり「4字と、字の幅の揺れの分 0.2 字が入る」を満たす。
- 4列×4行は、16 の言葉がいちばん小さくまとまる（今日の問題で盤の高さ 282px）。本番と同じ並びなので、いま遊んでいる人にも変わらない。
- 上下の余白と、四角と語のあいだは 8px のままにした。詰める必要があるのは横だけで、縦はマスを押しやすい高さ（68px）のままにできる。
- 320px 幅は、4px に詰めても4列の1行に 3.5 字しか入らないので、2列にする。このとき四角を語の左に置き、マスを 44px にする。

**採らなかった案**

- **2列のまま四角を左に置く形を、すべてのスマートフォンで使う（案 b だけ）**: 試作して測った。360×640 で、片仮名の長い語の日 585px、ことわざの日 624px と画面には収まるが、4列（486px・608px）より 100px ほど高く、16 語が縦に8行並ぶので、行と列で見比べにくい。7字までの語が1行で読める良さはあるが、見渡しやすさを優先した。
- **「チェック」を画面の下端に貼り付ける（案 c）**: 16 の言葉を見渡せないことが残るので採らなかった。4列にすれば貼り付けなくても収まる。
- **マスの枠を隣どうしで共有して、余白は 8px のままにする**: 375px 幅では4字が入るが、360px 幅では 4.05 字で決まりを満たさない。広い画面と盤の見た目が別になることもあり、採らなかった。
- **字を小さくする**: 本番の字は 13.6px、作り直した版は 14px。本番より小さくしない、という線を守るため採らなかった。
- **操作の並び順を変えて「チェック」を盤のすぐ下に置く**: 52px 縮むが、広い画面の見え方が変わり、4つ選んだときに押せない理由の文が消えてほかのボタンが動く。目標の3つの画面は並び順を変えなくても収まるので、手を入れなかった。

## 長い語の日での確かめ

日付を切り替える手段がコードに無いので、確かめのためだけに取り出した先で、ページに日付を渡せるようにして見た（リポジトリには入れていない）。50 問すべてを、4つの画面の大きさで開いて測った。

| ------- | --- | -------------------------------------------------------- | ---------------- | --------------------------------------- | ------------------------ |
| 375×667 | 4   | 433／433／608                                            | 0                | 0                                       | 0                        |
| 360×640 | 4   | 433／433／608                                            | 0                | 0                                       | 0                        |
| 390×844 | 4   | 433／433／608                                            | 0                | 0                                       | 0                        |
| 320×568 | 2   | 531／531／657                                            | 2                | 0                                       | 0                        |

長い語の多い日の例（375×667 と 360×640。直す前 → 直したあと）:

- ことわざの日（「犬も歩けば棒に当たる」「風が吹けば桶屋が儲かる」など。16 語のうち 14 語が5字以上）: 800px → 608px。語は「犬も／歩けば／棒に／当たる」「風が／吹けば／桶屋が／儲かる」「雨降って／地固まる」と、句の切れ目でだけ折れる。
- 片仮名の長い語の日（「ガソリンスタンド」「シャープペンシル」など）: 747px → 486px。「ガソリン／スタンド」「シャープ／ペンシル」「サラリー／マン」「ランド／セル」「コンペ／イトウ」「ウイン／ドウ」と折れ、1字だけの行は無い。
- 擬音語の日（4字の片仮名の語が 16 語）: 747px → 451px。4字の語はすべて1行。折れたのは「ビュー／ビュー」だけ。
- 四字熟語の日: 747px → 451px。四字熟語はすべて1行。「白黒つける」は「白黒つ／ける」と折れる。

撮った画面を目で見て、4列のマスの中の語が読めること、4字の語が枠に触れないこと、詰まりすぎて見えないことを確かめた。

**通して遊ぶ確かめ**

- 4組当てる回: 今日の問題を 375×667（ライト）と 320×568（ダーク）で、ことわざの日を 360×640（ダーク）で通した。当てるたびに、当てた組が盤の上に 4px の間隔で並び、残りの語は4列のまま 12・8・4 語と減る。横へのはみ出しは無い。4組目を当てると結果が出て、成績と共有の区画が出る。
- 4回外す回: 今日の問題を 1280×800（ダーク）で、片仮名の長い語の日を 320×568（ライト）で通した。外すたびに「あと3回間違えると終わり」「はずれです」と出て、4回目で結果（「4回間違えて終了」と当てられなかった組）が出る。
- どの回でも、端末に保存された記録（当てた組・ミスの数・勝ち負け、遊んだ回数・勝った回数・続けて勝った日数・ミスの数の分布）は、これまでと同じ形で入っていた。JavaScript のエラーは 0。
- 4つ目の語を選ぶと、これまでどおり「チェック」が画面に入るよう送られる（どの回でも、4つ選んだあと「チェック」は画面の中にあった）。

**文字サイズ 200%**（ブラウザの既定の字を 32px にした）: 50 問すべてで、字の欠け・横へのはみ出し・1字だけの行は 0。375×667・360×640・390×844 は2列で四角は語の上（直す前と同じ並び）、320×568 は1列で四角は語の左（直す前は語の上。マスが 85px から 57px に低くなった）、1280×800 は4列。200% では盤は1つの画面に収まらない（今日の問題で 993〜1329px）。

**機械の検査**: リポジトリ直下で、型の検査・lint・書式の検査を通し、`npx vitest run src/play/games` は 47 ファイル・500 件すべて通った。

## 残ったことと確かめられなかったこと

- **320×568 で収まらない日が残る。** 50 問のうち2問（片仮名の長い語の日 583px、ことわざの日 657〜670px。画面は 568px）。1年の出題の予定では、合わせて 15 日。理由は、320px 幅では4列のマスの1行に 3.5 字しか入らず2列になること、2列のマスの1行に入るのが 5.8 字で、6字以上の語が2行になること。その日も、4つ目の語を選ぶと「チェック」が画面に入るよう送られる。
- **360×640 のことわざの日は、組を当てたあと、盤の頭から「チェック」の下端までが 622〜642px になる状態がある**（当てた組の箱が、元の語の行より少し高いため）。画面は 640px で、いちばん悪い状態で 2px 超える。年に7日の問題で、4つ選べば「チェック」は同じ行に上がって 507〜556px に収まる。
- **5字の語は、4列のマスで2行になる**（「白黒つ／ける」「チュー／リップ」など。全 800 語のうち5字以上は 65 語）。本番は枠が細いので5字が1行に入っていた。太い枠のまま4列にする限り避けられない。
- **`DESIGN.md` に、8px の倍数の決まりの例外を1つ足した。** サイト全体の決まりへの追加なので、レビューで是非を見てほしい。
- **キーボードで語のマスにフォーカスを置いたときのリング**は、枠の外側から 6〜9px の所に出る。4列のマスで4字の語が幅いっぱいに入ると（360px 幅）、字の端がリングの内側の縁から 0.25px の所まで寄る。タッチの端末ではリングは出ないので、画面での確かめはしていない（計算だけ）。
- **確かめたのは Chromium だけ。** Safari と Firefox の実機では見ていない。使っている仕組み（幅を測る入れ物ごとの切り替え）は、直す前から同じものを使っている。
- 390×844 の「見える高さ 660px」は、依頼の前提をそのまま使った。実機のブラウザの帯の出入りでは測っていない。
- 確かめに使った、直した版のサーバーは 3107 番で動かしたままにしてある（今日の問題だけを出す、リポジトリと同じ中身のビルド）。
