# ナカマワケの盤をスマートフォンの1つの画面に収める直し

## 結論

375×667・360×640・390×844 のどれでも、言葉のマスが4列×4行に並び、盤の最初のマスの上端から「チェック」の下端までが画面の高さに収まるようになった。今日の問題で 433px（直す前は 747px）。50 問すべてを通しても、いちばん長い日で 608px。320×568 は2列のままだが、今日の問題で 531px（直す前は 747px）に縮み、50 問のうち 48 問で収まる。1280×800 は、直す前と1画素も変わらない。

## 採った案と採らなかった案

**採った案: 狭い画面でも4列×4行にする（依頼の案 a）。入らない幅では2列のまま四角を左に置く（案 b）。**

- 直す前は、4列にすると 375px 幅でマスの1行に 3.7 字しか入らなかった（コンテンツの幅 321px から、間隔 24px・枠 24px・余白 64px を引いて4で割ると 52px。字は 14px）。間隔と余白を 4px にすると、375px 幅で 63px（4.5 字）、360px 幅で 59.5px（4.25 字）になり、これまでの決まり「4字と、字の幅の揺れの分 0.2 字が入る」を満たす。
- 4列×4行は、16 の言葉がいちばん小さくまとまる（今日の問題で盤の高さ 282px）。本番と同じ並びなので、いま遊んでいる人にも変わらない。
- 上下の余白と、四角と語のあいだは 8px のままにした。詰める必要があるのは横だけで、縦はマスを押しやすい高さ（68px）のままにできる。
- 320px 幅は、4px に詰めても4列の1行に 3.5 字しか入らないので、2列にする。このとき四角を語の左に置き、マスを 44px にする。

**採らなかった案**

- **2列のまま四角を左に置く形を、すべてのスマートフォンで使う（案 b だけ）**: 試作して測った。360×640 で、片仮名の長い語の日 585px、ことわざの日 624px と画面には収まるが、4列（486px・608px）より 100px ほど高く、16 語が縦に8行並ぶので、行と列で見比べにくい。7字までの語が1行で読める良さはあるが、見渡しやすさを優先した。
- **「チェック」を画面の下端に貼り付ける（案 c）**: 16 の言葉を見渡せないことが残るので採らなかった。4列にすれば貼り付けなくても収まる。
- **マスの枠を隣どうしで共有して、余白は 8px のままにする**: 375px 幅では4字が入るが、360px 幅では 4.05 字で決まりを満たさない。広い画面と盤の見た目が別になることもあり、採らなかった。
- **字を小さくする**: 本番の字は 13.6px、作り直した版は 14px。本番より小さくしない、という線を守るため採らなかった。
- **操作の並び順を変えて「チェック」を盤のすぐ下に置く**: 52px 縮むが、広い画面の見え方が変わり、4つ選んだときに押せない理由の文が消えてほかのボタンが動く。目標の3つの画面は並び順を変えなくても収まるので、手を入れなかった。

## レビューを受けた直し: フォーカスのリングと hover の線が字に触れないようにする

### 何が起きていたか

左右の余白を 4px にしたマス（四角を語の上に置くマス）では、字が枠の外側から 7px の所まで来る。太い枠のマスのリングは枠の外側から 6〜9px の所に出るので、幅いっぱいに入った語の字に 1〜1.6px 重なっていた。はじめの直しでは、タッチの端末ではリングが出ないことを理由に、画面で確かめていなかった。幅の狭い画面でキーボードを使う場面（画面を 200〜300% に拡大した PC、キーボードを付けたタブレット）を見落としていた。

### 直した中身

- `src/play/games/nakamawake/_components/WordGrid.module.css`: 語のマスのリングと hover の線の太さと位置を、マスの左右の余白から決めるようにした。リングの太さは「余白の中で、両側に 1px の地を残せる太さ。3px まで」、枠とリングのあいだの地は「字の側に 1px の地を残せる幅。3px まで」。余白 8px のマスでは、これまでと同じ 3px の地・3px のリング・2px の地になり、余白 4px のマスでは 1px の地・2px のリング・1px の地になる。hover の線も、枠とのあいだに同じ幅の地を挟む（余白 4px のマスで、枠の外側から 4〜5px）。
- `DESIGN.md` §5: 語を選ぶゲームの盤の決まりに、このマスが「中身は縁の内側 8px から始まる」に従わないこと、語は中央に置いて幅いっぱいの行だけが 4px に届くこと、リングと hover のボーダーをその 4px の中に字に触れないよう出すこと（§6）を書いた。
- `DESIGN.md` §6 の二重リングの項: 太い線と重なるマスでは、挟む地も外の輪も太い線の太さで、中身は輪の内側に 2px 以上の地を残して始まること、左右の余白が 4px のマスだけは地を 1px・輪を 2px にして輪と字のあいだに 1px 以上の地を残すこと、その理由、hover のボーダーも同じ 1px の地を挟むことを書いた。

`globals.css` と、ほかの `[data-thick-frame]` の部品には手を入れていない。

### 採った案と採らなかった案

- **採った案: 余白 4px のマスだけ、リングを 2px にして枠に寄せ、枠とのあいだの地を 1px にする。** 枠・地・輪・地・字、という二重リングの並びを保ったまま、4px の中に収まる。リングと地の対比は 19:1 ほど（`--ink` と `--paper`）で、`DESIGN.md` §12 の「線とコントロールは 3:1 以上」を満たす。WCAG 2.2 の 2.4.13（フォーカスの見え方。AAA）が求める面積には届かない。2.4.13 は、部品の外周の 2px の帯の面積以上を求めていて、縁から内側に離して出す 2px の輪はそれより小さい（375px 幅のマス 77×68 で、外周の帯 564px² に対して輪は 500px²。360px 幅のマス 74×68 で 552px² に対して 488px²）。このサイトが約束しているのは §12 の「フォーカスが必ず見え、隠れない」と上の対比で、2.4.13 は約束していない。等倍の画面（360px・412px 幅）でも、1px の地が潰れず、リングが枠とも字とも別の線として見分けられることを、レビューで撮った画面で確かめている。ほかの所の 3px のリングより控えめに見えることは受け入れる。
- **線の太さの決まりに例外を置く、という PM の判断**: `DESIGN.md` §5 は「サイトに引く線は2種類だけ（3px と 1px）で、あいだの太さを持たない」と決めていて、2px のリングはこれに反する。PM は 2px のリングを採ると判断した。理由は、スマートフォンで 16 の言葉を4列で見渡せるようにするにはマスの左右の余白を 4px にする必要があり、その 4px の中に、字に触れないリングを 3px では出せないこと。見渡せることを優先し、線の太さの決まりに、この1か所の例外を置く。`DESIGN.md` は、§5 の「線」の冒頭と表、§5 の語を選ぶ盤の決まり、§6 の状態の表の「フォーカス」の行、§6 の二重リングの項の4か所が、同じ例外を言うように書いた（寸法は §6 の二重リングの項だけが持つ）。hover の線は、余白 4px のマスでも太さは 1px のままで、枠に寄せて出すだけなので、線の太さの例外にはあたらない。
- **リングを枠の外側に出す**: 字からは離れるが、マスどうしの間隔が 4px しかなく、2px のリングの両側に 1px ずつしか残らない。隣のマスの枠と一続きの太い帯に見え、どのマスにフォーカスがあるかが分かりにくい。リングは範囲の内側に出す、という §6 の決まりからも外れる。
- **地を挟まず、リングを枠に付ける**: 枠が太って見えるだけになり、「線に重ねると外の輪が線に溶ける」（§6）と同じことが起きる。
- **余白を 5px 以上に戻す**: 360px 幅で4列のマスの1行に4字が入らなくなり、盤が1画面に収まらなくなる。
