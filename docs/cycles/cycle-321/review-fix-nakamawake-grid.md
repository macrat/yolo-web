# レビュー: ナカマワケの盤をスマートフォンの1つの画面に収める直し（コミット 8231b9b）

## 判定

**要修正（改善指示）**。直さないと来訪者が損をするものが1つある（フォーカスのリングが語の字に重なる）。それ以外の見るべき点は、来訪者にとって本番より悪くなっておらず、狙い（16 の言葉と「チェック」を1つの画面で見渡す）は果たしている。

## 直さないと来訪者が損をするもの

### 1. キーボードでフォーカスを置いたとき、二重リングが語の字に重なる

四角を語の上に置くマス（`45rem` 未満の画面で、4列のとき。2列で四角が上のときも同じ）の左右の余白を 4px にしたため、字が枠の外側から 7px（枠 3px + 余白 4px）の所まで来る。太い枠のマスの二重リングは、枠の外側から 6〜9px の所に出る（`globals.css` の `[data-thick-frame]`: `outline-offset: -9px`、太さ 3px）。字がマスの幅いっぱいに入る語では、リングが字の左右の端を横切る。

- 実測（語のマスの縁から、字の箱の端までのいちばん小さい距離）: 360px 幅で4字の語 8.09px、412px 幅で5字の語（「ランドセル」が1行に入る）7.42px、文字サイズ 200% の 375px 幅で 7.61px。リングの内側の縁は 9px なので、どれもリングが字の箱に 1〜1.6px 食い込む。
- 撮った画面: 412px 幅で「ランドセル」の「ラ」と「ル」の端をリングが切り、360px 幅（ライト・ダーク）で「一石二鳥」の「一」と「鳥」がリングに接して溶けて見える。直す前の版（3106）は余白 8px で、同じ語でもリングと字のあいだが空いていた。直す前より悪くなった。
- 来訪者に届く場面: 幅が 358〜541px の画面でキーボードを使うとき。ブラウザを 200〜300% に拡大した PC（1280px の画面を 250% にすると 512px）、タブレットの分割表示、外付けキーボードのタブレットがこれに当たる。拡大して使う人とキーボードで使う人は重なりやすい。担当の報告は「タッチの端末ではリングは出ないので、計算だけ」としていたが、タッチでない狭い画面はある。
- 決まりとの関係: DESIGN.md §6 は、リングが範囲の内側に密着し、太い線の内側に `--paper` を挟んで出ると決め、スライダーの節で「フォーカスのリングが数字に触れない」ことを理由に間隔を取っている。今回 §5 に足した 4px の決まりは、このリングの置き方と両立しない（9px のリングの内側に字を置く余地が無い）のに、そのことに触れていない。§5 の「縁に地や線が見えるもの……中身は縁の内側 8px から始まる」とも食い違ったままである。

直し方は担当に任せるが、少なくとも次を満たすこと。

- 4px の余白のマスで、リングと hover の線が字に触れない（4字の語が幅いっぱいに入る 358px 幅、5字の語が1行に入る幅、200% で四角が上の2列の幅で、Tab で撮って確かめる）。
- リングの置き方を変えるなら、DESIGN.md の §5 の決まりと §6 のリングの節を、どのマスでどこに出すかまで食い違いなく書き直す。§5 の「中身は縁の内側 8px」との関係も1か所で読めるようにする。
- 例: 語を選ぶ盤の狭い組みでだけ、リングを枠に `--paper` を挟まずに置く・リングを細くする、など。どれも §6 の決まりを変えることになるので、その是非も含めて判断し、記録に残す。

### 読みやすさ・押しやすさ

- マスは狭い画面で幅 73〜87px・高さ 68px、間隔 4px。字は 14px（本番 13.6px）。WCAG 2.2 の押す的の大きさ（24px）を大きく超え、隣のマスとの取り違えは起こりにくい。4px の間隔は、太い枠が並ぶので詰まって見えるが、枠どうしは離れて見え、どのマスの語かを取り違えない（ライト・ダークで撮って見た）。
- 字の欠け・横へのはみ出し: 字を差し替えた3組 × 5つの画面 × 文字サイズ 100%・200% で 0。1字だけの行は、ことわざの句を私が「井の中の／蛙」と切った1件だけで、これは試しの入力によるもの（本物の句の分け方では起きない）。
- 選んだ語は、四角の内側の 8px の塗りで分かる。この見せ方は直す前から同じで、このコミットは変えていない。
- タップしたあとに残る hover の線（枠の内側 6〜7px）は、字の箱から 0.4px 以上離れ、字の下に描かれるので字を隠さない。

### 通して遊ぶ

- 4組当てる回: 375×667 ライト、360×640 ダーク、320×568 ダーク。当てるたびに組の箱（高さ 79px）が盤の上に 4px の間隔で並び、残りは4列（320 は2列）のまま 12・8・4 語と減る。横へのはみ出し 0、JavaScript のエラー 0。終わると結果（「4組すべて正解」「ミス0回」と成績）にフォーカスが移る。端末の記録は勝ち・ミス0で入る。
- 4回外す回: 375×667 ダーク、320×568 ライト、1280×800 ライト。外すたびに「あと3回間違えると終わり」「はずれです」と出て、4回目で結果（「4回間違えて終了」と当てられなかった組）が出る。

### 列の数を決める式と実測

各コンテナの幅を字の大きさで割った値と、実際のマスの中で字が使える幅は一致した。358px 幅で4列のコンテナ 16.857em ÷ 4 = 4.214em、実測 4.214em。360px で 17em ÷ 4 = 4.25em、実測 4.25em。2列で四角を左に置くコンテナは、356px で 14.143em ÷ 2 = 7.071em、実測 7.071em。320px で 5.786em、実測 5.786em。格子の幅は、どの幅でも元の幅（266〜640px）に戻っている。

### 担当が「残ること」として挙げた点

どれも、直さないと来訪者が損をするとは言えない。

- 320×568 で収まらない日が残る: 直す前は毎日収まらなかった（747px）。いまは年 15 日で、その日も4つ目を選べば「チェック」が画面に入るよう送られる。本番より悪いが、320px 幅で4列にすると1行に 3.5 字しか入らず、4字の語が「ジュー／ス」と折れる。2列で四角を左に置く組みのほうが読める。
- 360×640 のことわざの日に 2px 超える: 4つ選べば「チェック」が上がって収まる。2px の超過で来訪者が困ることは無い。
- 5字の語が4列のマスで2行になる: 「チュー／リップ」「白黒つ／ける」と折れ、どれも読める。1字だけの行は無い。

### サイト全体の決まりに例外を足すことの是非

足すほうが来訪者のためになる、と判断する。狭い画面で 8px の間隔と余白のまま4字を4列に入れる道は無い（360px 幅のコンテンツ幅 306px から、間隔 24px・枠 24px・余白 64px を引くと1マス 48.5px で 3.5 字）。枠を細くしても（1px にして 3.75 字）、余白だけ 4px にしても（4.04 字）足りず、字を小さくするのは本番より読みにくくなる。例外は語を選ぶ盤の、`45rem` 未満の画面に限っていて、理由も決まりの中に書かれている。ただし上の指摘1のとおり、この例外はリングの置き方と「中身は縁の内側 8px」の決まりとの関係を書いていないので、そこは直す。
