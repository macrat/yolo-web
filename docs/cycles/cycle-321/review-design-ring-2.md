## 指摘

### 指摘1（要修正）: 204 行の幅の境目の px が誤っていて、357px と 541px の画面がどの組みにも属さない

- 文書: 「画面の幅が 356px までは2列で四角は語の左、358px から 540px までは4列で四角は語の上、542px からは4列で四角は語の左」。
- 実際: 格子の幅 W は画面の幅 − 54px（§5 のコンテナ: 32px と、`45rem` 未満の 22px）。4列で上になるのは W − 68 ≥ 16.8 × 14 = 235.2px、つまり画面 ≥ 357.2px。4列で左は W − 68 ≥ 30 × 14 = 420px、つまり画面 ≥ 542px。本番で測ると、**357px は2列（左）、541px は4列（上）** で、どちらも文書の範囲から抜けている（測った値: 356/357px → 2列・`row`、358px → 4列・`column`、540/541px → 4列・`column`、542px → 4列・`row`）。正しくは「357px までは…、358px から 541px までは…、542px からは…」。
- 偶数の幅だけを測って書いたような抜けで、境目を確かめようとして文書を信じた人が、357px・541px の扱いを誤るか、実装の誤りと取り違える。
- あわせて、この px は決まりではなく、§5 のコンテナの値（54px）・`--text-small`・`45rem` から導かれる値である。§5 にはコンテナの表のように「既定のルート（16px）での値」を px で示す前例があるので書くこと自体はよいが、(1) 上の値に直す、(2) 「文字の大きさが既定のとき」に加えて、コンテナの寸法から導いた目安であること（画面の幅でなく格子の幅で言えば 303.2px・488px）を読めるようにする、のどちらかで、固定の決まりとして読ませない形にしてほしい。スクロールバーが幅を取る画面では、同じ「画面の幅」でも境目がずれる点も、格子の幅で言えば生じない。

### 指摘2（要修正・小）: 205 行の「リングの外の輪だけは、太い線より細い 2px で引く」が、§6 の「内が 1px」「挟む `--paper` を 1px」と食い違って読める

- 205 行は「外の輪**だけ**は太い線より細い」と言うが、同じマスでは挟む `--paper` も 1px、輪の内側の地も 1px で、どちらも太い線より細い。§6 の表（274 行）は「内が 1px、外が 2px」、302 行は「挟む `--paper` を 1px」と書いている。205 行だけを読むと、挟む `--paper` は 3px のまま（つまり 4px の余白に 3 + 2 は入らない）と読める。
- 意図は「あいだの太さ（2px）を使うのは外の輪だけ」で、§5 冒頭の「例外は…外リングを 2px で引く」と同じことのはずである。205 行を「リングは、外の輪を 2px、挟む `--paper` と輪の内側の地を 1px にする（2px の輪が上の『線』のただ1つの例外。寸法は §6 の二重リングの項）」のように、「だけ」が何についての「だけ」かが分かる形にする。寸法を §6 が持つと言いながら 205 行にも 2px を書いているので、数を残すなら §6 と同じ組（1px と 2px）で書く。

### 指摘3（要修正・小）: 204 行の理由「4字の片仮名の語は、1行に入らないと1字だけの行でしか折れない」が誤り

- `line-break: strict` で行頭に置けないのは長音符と小書きの仮名で、それを含まない4字の片仮名は 2字 + 2字で折れる（本番の盤の「タンヤオ」は「タン／ヤオ」、ほかに「カボチャ」→「カボ／チャ」、「パソコン」→「パソ／コン」）。1字の行でしか折れないのは「ジュース」（「ジュー／ス」）のように長音符や小書きの仮名を含む語である。CSS のコメントはこの条件付きで正しく書いているが、文書は一般化している。
- 理由が誤っていると、次に列の数を見直す人が「2字ずつに折れる語なら3字幅でもよい」「片仮名でない語は別」などの判断を誤った前提で始める。「長音符や小書きの仮名を含む4字の語は、1行に入らないと『ジュー／ス』のように1字の行でしか折れない」など、正しい範囲で書く。
