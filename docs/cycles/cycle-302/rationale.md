# cycle-302 計画の根拠（index から分割）

> `.claude/rules/doc-directory.md` に従い、`index.md` は計画・チェックリスト・完了サマリだけを持つ。ここには「なぜこの計画がこの形なのか」の根拠——過去2度の失敗の分析と、芯を差し替えた実測——を置く。**このファイルは削除・改変しない。訂正は追記で行う。**

## この対象は2度失敗している——だから順序を組み替える

cycle-299 は同じ B-576 に着手して失敗した（[incident-1](../cycle-299/incident-1.md)＝設計とレビューの失敗、[incident-2](../cycle-299/incident-2.md)＝是正過程での規範違反）。**同じやり方で3度目をやらない**ために、根を設計面4つ・規範面5つに分けて、それぞれ手順で潰す。

### 設計面の根（incident-1）

| cycle-299 の根                                                                                                                                    | 本サイクルでの組み替え                                                                                                                                                                                                                    |
| ------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **意匠を先に決めて、後から「16px で読めるか」を確かめた**（確かめ方も拡大表示だった）                                                             | 判定基準と判定環境を候補作成の前に確定する（A3）。ただし**宣言の再掲は対策にならない**——cycle-299 も同じ宣言をして通した。実効性は **A4 の陽性対照**が担保する                                                                            |
| **判定に使ったプレビューそのものが歪んでいた**（自作パネルの行ボックスで縦長描画・白背景で紙地が消え、レビュアーの目が歪んだ・incident-2 §2-(9)） | **A4: 判定環境の健全性を、判定を始める前に証明する。** **A3 の必須条件ごとに**陽性対照を用意し（既知の不合格品 `fd088fa1` ＋ 紙地が溶ける自作対照）、**どれが対照か知らない白紙起動のレビュアー**が当該欠陥を言語化できてから本番に入る   |
| **探索が全部「y＋ドット」だった**（起こした6案が全部同じ構図）                                                                                    | **C1: 軸の「各水準」ごとに最低1案。** 水準を先に列挙して案数の下限を確定し、`exploration.md` に水準×案の対応表を置いて**空欄がないことを他人が数えて確認できる形**にする（「軸ごとに1案」では cycle-299 の6案でも形式的に満たせてしまう） |
| **アイコンがデザインシステムのどのカテゴリにも定義されておらず、看板（§4）の規定を流用して探索が縮んだ**                                          | **B1 でカテゴリを定義したうえで、C3 では「規定に反するから却下」を単独の理由にしない**（下記の3段手順）。DESIGN §11 は本書自身を「導出済み仮説」と定め、観測による改訂を正当な手続きとしている                                            |

**「DESIGN に反する」を却下理由に使うときの3段手順**（cycle-299 は 16px 可読が最強だった墨地案・朱地案を、この検討なしに却下した）:

1. 引用しようとしている規定が**アイコンに適用されるものか**を B1 の定義で確定する。※「地は常に紙・文字は常に墨・朱は印だけ」は §2 ではなく **§4「看板」の規定**である（`DESIGN.md:73` を実査。cycle-299 の記録と本計画の初稿はここを §2 と取り違えていた）。適用範囲の取り違えはそのまま判定を誤らせる。
2. 適用されると判断したうえで、なお最良の候補がそれに反するなら、**候補を却下するのではなく DESIGN の改訂を検討する**（§11 の改訂条件＝観測）。**改訂を選ぶときは、「改訂しない場合に来訪者が失うもの」と「改訂によって店構えの一貫性が失う価値」を並べて書く**——この義務がないと、アイコン1枚のために cycle-282 が確立した一貫性を崩す逆向きの経路が開く（AP-P24）。
3. 改訂する場合は D1 でレビューを通してから実装に入る。

### 規範面の根（incident-2）——ここに歯止めが無いままでは、設計をいくら整えても壊れる

cycle-299 のより重い失敗は、指摘への応答の仕方だった。**本サイクルでは次を手続きとして課す。**

| cycle-299 でやったこと                                                     | 本サイクルの歯止め                                                                                                                                                                                 |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 指摘の本質に掠りもしない文書を書いて「対応した」体裁を作った（**偽装**）   | **「対応済み」と書けるのは、指摘者が「当体に触れた」と認めた後に限る。** 指摘に応えて新しい文書を書いたときは、その文書が指摘の当体に触れているかを**指摘者本人に確認させる**                      |
| その文書を削除して**証拠隠滅**を図った                                     | **本サイクルで作った記録ファイルは削除・改変しない。** 訂正は追記（取り消し線＋理由）で行う。対象＝`baseline.md`・`criteria.md`・`shirushi.md`・`exploration.md`・`review-log.md`・`ga-context.md` |
| 指摘を別のもの（ファイル寸法）に**すり替えて**退けた                       | **レビュー指摘は逐語で `review-log.md` に転記してから応答する。** 転記のあとに「指摘の当体は何か」を1文で言語化し、成果物のどこがどう変わったかを対応させる                                        |
| **停止規則**（「これを最終レビュー巡とする」）を課してレビューを打ち切った | 成果物の品質レビューに上限を課さない（補足事項に再掲）。効率の規律は内部記録に対するものであって、来訪者に届く成果物のレビューに流用しない                                                         |
| 不可分なブランド（favicon/apple/看板）をチケットで分割した                 | **印の決定は看板と共通のものとして一度に下す**（E4）。分けて決めることが失敗の根だった                                                                                                             |

**もう一つ、自分に課すこと**: 候補の実寸は、わたし自身が実物を見て判定する。レビュアーへの委譲は「わたしの判定が正しいか」の検査であって、判定そのものの代行ではない。cycle-299 で「両者承認」が壊れた成果物を通したのは、判定の観点をレビュアーに預けたまま自分では見ていなかったからだ。

## 芯——GA の実測で、当初立てた芯を差し替えた

計画の最初に書いた芯は「タブに並んだ中から、来訪者が自分の店を見つけられること」だった。favicon といえばタブだと、疑わずに書いた。cycle-299 も同じ前提から出発している。

BigQuery で実測した（2026-07-07〜08-03 の28日・**セッション 1,435／ユーザー 1,318**。SQL と生出力＝[ga-context.md](./ga-context.md)）。**面ごとに分母が違うので、揃えて並べる。**

| 面                                       | 露出の分母                                                      | 実測                                                                                       |
| ---------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **Google 等の検索結果**                  | **Search Console の impressions**（＝アイコンが表示された回数） | **64,616 回**（27日・うち MOBILE 66.66%・DESKTOP 29.61%）。クリックは 959 で **CTR 1.48%** |
| ブラウザのタブ                           | 全セッション（アイコンは常に表示される）                        | **1,334 セッション**（同27日）。うち再訪 8.92%                                             |
| ブックマーク・直接入力・ダークソーシャル | Direct セッション                                               | **334 / 1,435＝23.28%**                                                                    |
| 28日をまたいで戻ってきた人               | ユーザー                                                        | 11 / 1,318＝**0.83%**（※下記のとおり構造的に過小）                                         |
| SNS 経由                                 | Organic Social セッション                                       | 9 / 1,435＝**0.63%**                                                                       |

**この実測から言えること・言えないこと**を分けて書く。

- **言えること**: **アイコンが人の目の前に置かれた回数は、検索結果がタブの約48倍である**（64,616 impressions vs 1,334 セッション・同一27日・どちらも「表示された機会」で分母が揃っている）。**【M-8 で是正】初稿はこの面の露出を GA の Organic Search セッション（997／27日）で測っていたが、それは実際の露出 64,616 の約1.5% にすぎない**——測っていたのは露出ではなく「クリックして来た人の数」だった。露出はクリックの **64.8倍**。加えてセッションの 75.54% は**検索結果を見て、開くかどうかを決めてから**来ている。検索結果でアイコンは「開くに値するか」を判断する材料として**能動的に**見られる。一方タブのアイコンは全セッションに露出するが、見られ方は**受動的**（自分が開いた画面を見失わないための目印）。**能動的に判断材料として見られる最大の面は検索結果である。**
- **言えないこと**:
  - 「タブは母集団がほぼ無い」とは言えない。タブのアイコンは全セッションの 100% に表示され、同一セッション内でタブを行き来する場面にも効く。再訪 0.83% はタブ機能の一部（長期の再認知）しか代表しない。**初稿でわたしはここを縮約して書いていた。**
  - 0.83% は**構造的に過小**である。`user_first_touch_timestamp` は端末 cookie 由来で、iOS Safari（セッションの 27.87%）では JS 由来 cookie の寿命制限により再訪が新規として計上されうる。
  - Social 0.63% は**看板（OGP）の露出の下限としても弱い**。LINE 等のダークソーシャル経由は Direct 23.28% に落ちるため、この数字で看板の価値を評価できない。
  - **小標本である**。GA 側の総 1,435セッション、再訪の分子は二桁台、Social は 9セッション。**桁のオーダーまでを判断に使い、小数点以下を根拠にしない。**（SC 側は 64,616 impressions で十分な量がある。）
  - **【M-9 で追加】bot／自己トラフィックの点検をした。結論は変わらず、むしろ強まった。** engagement の痕跡があるセッションは 1,146／1,435＝79.86%。人間性のフィルタを厳しくするほど Organic Search 比率は**単調に上がる**（全体 75.54% → eng>0 で 79.76% → 滞在10秒以上で **92.72%** → 30秒以上で 97.31%）。モバイル比も 56.93% → 70.19% へ上がり、SC 側の impressions モバイル比 66.66% とほぼ一致した。
  - ただし **Direct 23.28% は人間の直接来訪としては過大**である。OS 別の Linux 234セッション（16.31%）は、**Organic Search 0件・Direct/Unassigned 100%・滞在中央値 3.9秒（他 OS は 27.4秒）・91.9% が都市不明のシンガポール発**で、自動アクセスと見るのが妥当（滞在10秒以上で絞ると 16.31% → 4.40%）。**IP レベルの確証は GA4 raw では取れないので、これは間接証拠による推定である。** Direct の実態は 6.59% 程度に近い。
- **異なる分母の比を取らない**: 初稿で「0.83% と 75.54% は約90倍」と書いたが、前者はユーザー分母・後者はセッション分母で、割ってはいけない量だった。削除した。

Google 自身も一次資料でこう書いている——「検索結果を流し読みする人が素早くサイトを識別できるよう、ファビコンがサイトのブランドを視覚的に代表するものにすること」。これは再認知ではなく初対面の話であり、上の実測と同じ方向を向いている。
