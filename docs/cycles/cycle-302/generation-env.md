>
> **なぜ要るか**: 判定側（A4）だけ校正して生成側が無校正では、**道具の不在が設計判断を歪める**。cycle-299 の A2 は「環境に potrace/opentype 等が無くベクター化できない」という道具の都合を、SVG を作らない設計判断の後押しに使った（incident-1 §3-A が「工数・制約を口実に品質を妥協した」と記録している）。**探索の水準が道具の都合で消えることを防ぐ**ために、C1 の前に「各水準を実際に1枚出せる」ことを実証する。

## 2. 軸1の各水準を、実際に1枚ずつ出せるか

**4水準すべて生成できた**（48×48・紙地 `#f8f7f2`・墨 `#201e1a`・朱 `#af3622`）。

| 水準                      | 生成 | 48px 等倍での見え                                                       |
| ------------------------- | ---- | ----------------------------------------------------------------------- |
| **(a) 欧字の頭文字 y**    | 可   | **「V」に見えた**（下記 §3）                                            |
| **(b) 印＝円環＋漢字1字** | 可   | 朱の円環＋「試」。48px で明快に読める                                   |
| **(c) かな1字**           | 可   | 「や」。48px で読める                                                   |
| **(d) 文字によらない形**  | 可   | 罫2本＋朱の一本線（のれん由来）。ImageMagick のプリミティブのみで描ける |

**→ 道具の不在を理由に水準を落とす必要はない。** C1 は4水準すべてを起こす（index の C1 は「水準を減らせるのは A5 で物理的に生成不能と実証した場合に限る」と定めており、**その条件は満たされなかった**）。

## 3. 重要な発見: 「y が v に見える」は**2通りの独立した機序**で起きる

(a) の初回生成は、48px でも **「V」に見えた**。しかし原因は cycle-299 のものとは違う。

| 機序                     | 内容                                                                        | 出所                                   |
| ------------------------ | --------------------------------------------------------------------------- | -------------------------------------- |
| **① 細さで消える**       | 16px で明朝のヘアラインが 1px 前後に落ち、払い（descender）が最も薄く消える | cycle-299 incident-1 §2                |
| **② 天地の配置で切れる** | ディセンダを持つ y をキャンバス中央に置くと、**払いが下端で切り落とされる** | **本サイクル A5 で実測（2026-08-04）** |

**②は 48px でも起きる**——つまりサイズを上げても解決しない。**y という字形は、この用途で二重に脆い。**

これは C1/C3 の判定に直接効く: **(a) を採る場合、「細さ」と「天地の余白」の両方を craft として詰め切る必要がある**。cycle-299 は①だけを見て②を見ていなかった（第1回・第2回とも「下重心の是正」として位置を動かしてはいるが、**払いが切れているかを 48px で確かめた記録がない**）。

## 4. 決めたこと

- **生成器はフォントを実行時に取得する**（`ogp-image.tsx` が既に Google Fonts から取得しているのと同じ経路）。**`tmp/` のフォントに依存しない**——`tmp/` は非追跡で消えるため、依存すると再現性が失われる。7.5MB のフォントをリポジトリに置くことはしない（`git` 履歴の肥大は B-588 として既に問題になっている）。
- **B-611（生成器の色定数が `utsuwaHex.ts` から乖離してもテストが沈黙する）を、生成器を作り直す本サイクルで解消する。** cycle-299 は「`.mjs` ＋ node 直実行を維持する受容トレードオフ」として残したが、**生成器をゼロから作るいまなら `tsx` で `.ts` にして `utsuwaHex.ts` を直接 import でき、乖離ガードそのものが不要になる**（`tsx` は既に devDependency で `generate:release-id` が使っている）。前提が変わったので判断をやり直す。
- **生成物の健全性チェックを生成器に組み込む**（ゲート G-a のレビュアーが、意図的な欠陥対照を「レンダリング失敗の疑い」と指摘したことへの対応）。最低限、**暗部画素が存在するか・想定の色数があるか**を出力時に検査し、通らないものは候補として提示しない。
