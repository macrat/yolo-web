## 1. 判定環境

### 1-1. 画像の作り方（拡大しない）

- 判定画像は **16×16 および 48×48 の等倍ラスタそのもの**を、**判定用の地の色**に合成したものとする。**アップサンプル（拡大）を一切しない。**
- **自作パネルに文字・枠・ラベルを足さない。** cycle-299 で判定を壊したのは、自作プレビューパネルの行ボックスによる縦長描画と、白背景で紙地が消えたことだった（cycle-299 incident-2 §2-(9)）。要素を地の上に並べるだけに留めれば、この2つは構造的に起きない。
- **なぜ「実タブストリップのキャプチャ」にしないか**: Playwright はページ内容しか撮影できず、ブラウザのクロムを撮れない。物理的に取得不能である（→ [baseline.md](./baseline.md) A4-0）。手段を差し替えたが、核（拡大しない）は保っている。
- 拡大画像を**合否の根拠に使わない**。ファイルの同定など判定以外の目的で拡大する場合は、その旨を記録に明記する。

### 1-2. 判定用の地（4種すべてで見る）

検索結果の地の色は観測できなかったため（→ [baseline.md](./baseline.md) A1 続き）、**地を選ばないことを要求する**。

| 記号 | 地             | hex       | 由来                              |
| ---- | -------------- | --------- | --------------------------------- |
| G1   | ライトのタブ地 | `#DEE1E6` | Chrome ライトのタブストリップ相当 |

### 1-3. 判定者と一致の運用

- 判定者は **PM ＋ 白紙起動の視覚レビュアーの2名以上**。
- **言語化が一致しない場合は不合格として扱う**（cycle-299 は「両者承認」で壊れた成果物を通した）。

## 2. 第一基準（アイコンに帰属し、他人が再現できる形）

他サイトのアイコンが並ぶ中に等倍で置いたとき、次の3つをすべて満たすこと。

- **(i) 地に溶けず、面として存在が残る。**
- **(ii) 何の図像かを判定者が言語化でき、複数の判定者の言語化が一致する。**
- **(iii) 隣接するアイコンと弁別できる。**

> **これは「開いてみようと思えるか」ではない。** 検索結果の行はタイトル・URL・スニペットが支配的で、アイコンの寄与を分離できないし、自サイトを熟知した判定者が「初対面」を演じることもできない。動機（芯）と合否基準は分ける。

## 4. 陽性対照——判定環境が壊れていないことの校正

**なぜ必要か**: 「実寸で判定する」という宣言は cycle-299 もしていて、それでも壊れた成果物が通った。**宣言ではなく、環境が既知の不合格品を落とせることを先に示す。**

**なぜ1件では足りないか**: 対照1件が校正するのは1つの不合格モードだけで、残りの必須条件は**無校正の計器**で判定することになる。

### 4-1. 対照の一覧

| 対照 | 内容                                                       | 出所                                                                            | 校正する必須条件 | 状態     |
| ---- | ---------------------------------------------------------- | ------------------------------------------------------------------------------- | ---------------- | -------- |
| ①    | 紙地＋明朝 600 の極細 y ＋朱ドット（16px で「v」に潰れる） | `git show fd088fa1:public/favicon.ico`（cycle-299 第1回の出荷版・取得確認済み） | **N1**           | 取得済み |
| ②    | 紙地ベタ＋極細墨図（明るい地で本体を失う）                 | **自作**（cycle-299 第2回の 900y 版は `public/` に未コミットで取得不能）        | **N4・N6**       | 未作成   |

> **自作してよい理由**: §1-1 が禁じているのは判定用の**自作プレビューパネル**（cycle-299 で判定を歪めた当のもの）であって、**対照アーティファクトの自作ではない**。対照は「落ちるべきものが落ちるか」を測る道具であり、意図的に欠陥を持たせて作る。

### 4-3. 実施手順と合格の定義

1. 対照①〜④を候補群に**無記名で混ぜる**。
2. **どれが対照か知らない白紙起動の視覚レビュアー**にまず通す。**PM は正解を知っているので、PM 自身に対しては対照が機能しない**（「落とせた」と書けてしまう＝cycle-299 の完了チェック偽装と同じ入口）。
3. **合格の定義**: レビュアーが**当該欠陥を言語化できたこと**（第一基準(ii) と同じ形式）。例——①「y と読めない／v に見える」、②「地に溶けて点しか残らない」、③「端が切れて何か分からない」、④「地に沈んで見えない」。
4. 対照ごとの言語化を**このファイルに追記**する。落とせなかった対照があれば、**その必須条件は判定不能**として扱い、候補の合否に使わない（黙って使わない）。

## 5. 記録の形式（C2・F1）

候補ごとに次を `exploration.md` に記録する。**「見た」の自己申告で終わらせない。**

- 使った**基準の版**

- **言語化した内容**（判定者ごと）
- 各必須条件 N1〜N10 の**合否**
