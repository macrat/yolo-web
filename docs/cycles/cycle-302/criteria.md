## 1. 判定環境

### 1-1. 画像の作り方（拡大しない）

- 判定画像は **16×16 および 48×48 の等倍ラスタそのもの**を、**判定用の地の色**に合成したものとする。**アップサンプル（拡大）を一切しない。**
- **自作パネルに文字・枠・ラベルを足さない。** cycle-299 で判定を壊したのは、自作プレビューパネルの行ボックスによる縦長描画と、白背景で紙地が消えたことだった（cycle-299 incident-2 §2-(9)）。要素を地の上に並べるだけに留めれば、この2つは構造的に起きない。
- **なぜ「実タブストリップのキャプチャ」にしないか**: Playwright はページ内容しか撮影できず、ブラウザのクロムを撮れない。物理的に取得不能である（→ [baseline.md](./baseline.md) A4-0）。手段を差し替えたが、核（拡大しない）は保っている。
- **【追記・M-5】「16px」は device px を指す。** 主たる面と定めた検索結果は**モバイルが 56.93%**（GA 実測）で、その多くは DPR 2〜3 の端末である。つまり SERP のアイコンは「16 CSS px の枠に 32〜48 device px の情報量」で描かれる一方、デスクトップのタブは DPR 1 で**真に 16 device px** である。**要求される craft が別物**なので混ぜない。判定画像は **device px を 1:1 で持つ**。C2/F1 の判定記録には **CSS px と DPR を分けて書く**。
- 拡大画像を**合否の根拠に使わない**。ファイルの同定など判定以外の目的で拡大する場合は、その旨を記録に明記する。

### 1-2. 判定用の地（4種すべてで見る）

検索結果の地の色は観測できなかったため（→ [baseline.md](./baseline.md) A1 続き）、**地を選ばないことを要求する**。

### 1-3. 判定者と一致の運用

- 判定者は **PM ＋ 白紙起動の視覚レビュアーの2名以上**。
- **言語化が一致しない場合は不合格として扱う**（cycle-299 は「両者承認」で壊れた成果物を通した）。

## 2. 第一基準（アイコンに帰属し、他人が再現できる形）

他サイトのアイコンが並ぶ中に等倍で置いたとき、次の3つをすべて満たすこと。

- **(i) 地に溶けず、面として存在が残る。**
- **(ii) 何の図像かを判定者が言語化でき、複数の判定者の言語化が一致する。**
- **(iii) 隣接するアイコンと弁別できる。**

> **これは「開いてみようと思えるか」ではない。** 検索結果の行はタイトル・URL・スニペットが支配的で、アイコンの寄与を分離できないし、自サイトを熟知した判定者が「初対面」を演じることもできない。動機（芯）と合否基準は分ける。

1. 対照①〜④を候補群に**無記名で混ぜる**。

4. 対照ごとの言語化を**このファイルに追記**する。落とせなかった対照があれば、**その必須条件は判定不能**として扱い、候補の合否に使わない（黙って使わない）。

## 【基準 v1 の改訂・2026-08-04】ゲート G-a のレビュアー指摘により **N2 を分割し 32px を追加する**

§「版と凍結」の変更手続きに従い、変更前後の全文・理由・合否反転の有無を記す。

- **変更前**: `N2 | **48px** で図像として読める`
- **変更後**: `N2a | **32px** で図像として読める` ／ `N2b | **48px** で図像として読める`
- **理由**: ゲート G-a のレビュアーの指摘——「**Retina/HiDPI ディスプレイの Chrome・Safari はタブに 32px のアセットを選ぶ。今どきのノートPCの大半が HiDPI なので、32px は実際には最も多く見られるサイズである**」。16px と 48px の中間であり、**現行 favicon が実際に持っている2層のうちの片方**（16/32）でもある。落としていたのは誤りだった。
- **合否を反転させるか**: **させうる。** レビュアーは「item-c / item-e の合否がここで変わる可能性が高い」と述べている（16px で落ちたものが 32px では通りうる）。**つまりこの追加は基準を緩める方向に働きうる**ので、**N1（16px）は据え置き**とし、32px の追加は「16px で落ちたものを救う」ためには使わない——N1・N2a・N2b は**すべて満たすべき条件**である。

### 同じ指摘で受けた、ゲート設計の残りの穴（次の実施までに直す）

1. **隣接比較の材料がない。** 第一基準(iii)「隣接するアイコンと弁別できる」を検証する画像を用意していなかった。**他サイトの favicon を混ぜた実タブ列相当の並び**を作る。レビュアーは「item-c と item-e はどちらもクリーム地に細い y で、実際に並べたら区別できない可能性が高い」と指摘した。
2. **円マスクの検証が 16px にしかない。** 48px 側にもマスク版を置く。
3. **変数が交絡している。** 字形・地色・アクセント色が同時に動いているため「どれが良いか」は分かっても「なぜ良いか」が切り分けられない。**C1 の候補は1軸ずつ整理して提示する。**
4. **item-b（対照④）が「レンダリング失敗の疑い」と受け取られた。** これは**意図的な欠陥品なので想定どおり**だが、本番の候補提示時に同じ疑いが出ないよう、**生成物の健全性チェック（最低限「暗部画素が存在するか」）を A5 の生成環境確認に組み込む**。

## 【基準 v2 への改訂・2026-08-05】判定の一次根拠を「LLM が見た印象」から外す

4巡目レビューの Blocker-1 による。§「版と凍結」の変更手続きに従い、変更前後・理由・合否反転の有無を記す。

### なぜ変えるか——同じ対照が、提示の仕方で読めたり読めなかったりする

`fd088fa1`（cycle-299 が出荷した壊れた favicon）を等倍で見せたときの結果:

| 観測者                          | 提示の仕方                                          | 結果                                   |
| ------------------------------- | --------------------------------------------------- | -------------------------------------- |
| 3巡目レビュアー                 | 16×16 を単体／タブストリップ状の地に合成            | **「y ＋赤い点」と読めた**＝落とせない |
| ゲート G-a のレビュアー（白紙） | 4地色×2サイズ×円マスク有無を1枚に並べ、他候補と比較 | **「字が読めない」と落とせた**         |
| 4巡目レビュアー                 | 16×16 を単体／1280×300 の実面相当に合成             | **「y·」と読めた**＝落とせない         |

**2/3 の独立した観測者が落とせなかった。** ゲート G-a を「通過」と記録したのは、**3件中1件の結果を採ったことになる**。これは校正として弱い。

さらに根本的に——**「LLM が等倍のラスタを見て読めるか」は、人間の 16px 可読性の代理に原理的にならない**。人間の可読は画素の物理サイズと視距離という光学的限界で決まるが、LLM は画素配列をそのまま読む。**代理になっていない計器で合否を出していた**（AP-P02＝測度と問いのずれ）。

### 変更内容

- **変更前**: 必須条件 N1〜N8 の合否は、判定者が等倍の画像を見て言語化した結果で決める。
- **変更後**: **一次根拠を機械計測と人間の ground truth アンカーに置き、判定者の言語化は必要条件（それだけでは合格にできない）に降格する。**

#### (a) 機械計測を一次判定に据える（判定者に依存しない・再現可能）

16px ラスタ上で `identify` / `convert` により測る:

1. **図の最小ストローク幅（実効 px）** — 細さで消える欠陥（cycle-299 の①）を捕まえる
2. **図と各地 G1〜G4 の実効コントラスト比** — 地に溶ける欠陥（cycle-299 の②・N4/N6/N7）を捕まえる
3. **連結成分の最小径** — 潰れ・分断を捕まえる
4. **内接円の外にある図の画素比率** — 円マスクでの欠損（N3）を捕まえる

#### (b) 人間の ground truth をアンカーにする

本プロジェクトで**唯一の人間側の観測**は、`fd088fa1` について記録された「**y の下半分が切れて v に見える／細すぎる／ドットが中黒に見える**」（cycle-299 incident-1 §2・Owner の観測を PM が現物で再現確認したもの）である。

**装置の合格条件を「`fd088fa1` を機械計測で確実に落とすこと」に固定する。** 落とせないしきい値は採用しない。これは主観に依存しないので、他人が再現できる。

#### (c) 情報損失を先に適用してから見てよい

「拡大禁止」の目的は**情報の水増しを防ぐこと**である。したがって、16px ラスタに**人間の視角限界に相当する劣化（ダウンサンプル＋ぼかし）を先に確定**させれば、**その後の拡大は無害**になる。劣化量は (b) のアンカー（`fd088fa1` が「v に見える」こと）で較正する。

### 合否を反転させるか

**させる。** 判定者が「読める」と言った候補でも、機械計測でしきい値を割れば**不合格**になる。これは基準を**厳しくする**方向である。逆に、判定者が「読めない」と言っても機械計測が通る場合は——**不合格のまま**扱う（N1〜N8 は判定者の言語化を必要条件として残すため）。

### 【B-3】陰性対照は既に使っていた——記録を正す

§4-1 の表は陽性対照①〜④しか挙げていなかったが、**ゲート G-a の実施では陰性対照2件を混ぜていた**（`item-a`＝現行 favicon、`item-d`＝墨地＋太い紙色の図）。レビュアーは**2件とも「使える」と判定し、欠陥ありとは言わなかった**。

- **合格条件に明記する**: 「陽性対照を落とす」だけでなく「**陰性対照を欠陥ありと言わない**」ことを G-a の条件に含める（感度だけでなく特異度も較正する）。これが無いと、**何を見せてもだめだと言う装置**が全対照を通過して合格になり、次段で全候補を不合格にして「意匠が悪い」という結論に化ける。
- §4-1 の表に陰性対照2件を追記する（この追記をもって記録を正とする）。

### 【M-14】対照は「遠い端」しか持っていない——限界として明記する

対照②は 1px ストローク、④は明度差ほぼゼロ、③は四隅のみで、**いずれも極端な不合格品**である。これらを落とせても、**判定の分かれ目にある候補**を落とせる保証はない。AP-P33 が要求する「失敗軸の**両端**」のうち、遠い端しか置いていない。

**したがって「N1〜N8 の8件中6件（→G-a 実施後は5件）を校正した」という記述は、感度の下限を示したにすぎない。境界性能は未校正である。** この限界を判定の前提として扱う。

### 【M-4】N1（16px 可読）と N3（円マスク耐性）は 16px で正面から衝突する

`baseline.md` は「正方形表示では余白が増えるだけで損をしない」と書いたが、**16×16 で内接円の外を使わないということは、実効の図領域が約 11×11 に落ちる**ということで、**16px 可読を直接削る**。しかも円マスクの実在は未確認（Google 公式に記載なし）。**守る対象があるか不明な制約で、実在が確定している要件を損なう**構造になっていた。

**判断**: **N3 は 32px 以上の層にのみ課す。16px 層には課さない。** 理由——(i) 16px 可読は実在が確定した要件で、円マスクは未確認、(ii) 検索結果のアイコンは高 DPR 側（32px 以上のアセットが選ばれる面）で表示される公算が大きく、円マスクが効くとすればそちら、(iii) 16px は DPR 1 のタブが主で、そこに円マスクの報告はない。**この判断は合否を反転させうる**（16px で内接円の外を使う候補が救われる）ため、変更手続きに従ってここに記録する。

## 【計器の実装・2026-08-05】`scripts/icon-metrics.ts`

基準 v2 が「一次判定に据える」と定めた機械計測を実装し、**リポジトリにコミットして恒久化した**（それまで計器は git 管理外にあり、判定の再現性が担保されていなかった）。

### 測る量

| 量                         | 何を捕まえるか                                                                                       | 対応する必須条件 |
| -------------------------- | ---------------------------------------------------------------------------------------------------- | ---------------- |
| ストローク充実度           | 細さで消える（1px 幅の線は 0 に近づく）                                                              | N1               |
| 最大連結成分               | 図の潰れ・分断                                                                                       | N1               |
| 内接円の外の図の割合       | 円マスクでの欠損                                                                                     | N3               |
| 地ごとの**最大連結可視塊** | 地に溶けるか。**画素数だけでは足りない**——同じ画素数でも、まとまっていれば読め、散っていれば読めない | N4〜N7・N11      |

**片方だけを見て決めていない。** 落とすべきものの最悪（16）と通すべきものの最悪（26）の間である。

### 装置としての限界（正直に書く）

- **対照は「遠い端」しか持っていない**（1px ストローク・明度差ほぼゼロ・四隅のみ）。**判定の分かれ目にある候補を落とせる保証はない。** 感度の下限を示したにすぎず、境界性能は未校正である（4巡目 M-14）。
- **機械計測は「読める」を保証しない。** 測っているのは「消えていないこと」であって「何と読めるか」ではない。N1 の「図像として読める」の後半（何と読めるか）は、依然として人間の観測が要る領域に残っている。
