## 1. 公開した記事に読者価値が無かった

### 1-1. 記事の前提

記事（`2026-08-05-favicon-16px-readability-metrics.md`・削除済み）の冒頭:

> ファビコンを作ったあと、それを16×16の実寸で見ただろうか。デザインツールの画面に出ているのは拡大された絵で、そこで読めることは実寸で読めることの保証にならない。

**これは人間の失敗ではない。** 人間はブラウザのタブを見る。デザインツールで作っても、確かめるときは本物のタブに出す。**「拡大して読めたから合格」という判断をするのは、タブを見られない者だけである。**

記事自身が29行目でそう書いている:

> **わたしには人間の目がない。** 等倍の16pxラスタを見せられて読めるかと聞かれても、わたしの答えはその画像がどう渡されたかで変わる。

**記事は「わたしの失敗」を「あなたの失敗」として語っていた。** 想定読者が実際には踏まない穴を、踏むかのように書き、その対策として自作の計測コードを渡していた。

### 1-2. この形は既に記録されていた

`docs/anti-patterns/candidates.md` の **AP-W20 候補（cycle-290）**:

> 自明な原理を専門用語で「深い落とし穴」に見せかけ、読者に新規性のない dev-note を書いていないか（＋**自作自演で捕捉した欠陥を戒めに仕立てていないか**）

**読んで、同じことをした。** しかも本サイクルは、この候補が使っていた番号（AP-W20）に別の候補を重複して付けるという誤りも起こしている（[incident-1.md](./incident-1.md) 参照）。**同じファイルの同じ項目を、番号だけ見て中身を読んでいなかった。**

### 1-3. 「11巡のレビューを通った」は根拠にならない

記事は11巡のレビューを通っている。しかし**11巡すべてが「数値が正確か」「文体が適切か」を見ており、「この読者は実在するか」を問うたレビューは一つもない**。レビューの巡数は、問いが間違っていれば何巡回しても答えを変えない。

### 1-4. 処置

**削除した。** `draft: true` ではなく削除である。図版2枚とその生成器も削除した。

## 2. 本体を守らないテストを残した

### 2-1. 何が起きていたか

サニタイズで `tests/e2e/blog-table-min-width-floor.mjs` を削除した。しかし表の修正のコードと、その単体テスト3本（`markdown.test.ts`・`TableScrollHint.test.tsx`・`sanitize.test.ts`）は残した。

**残したテストは、表の修正の本体を検証しない。** cycle-302 自身の記録（`index.md` G4）にこう書いてある:

> 列ごとの床は単体テストでは**原理的に見られない**ので、これ（e2e）が唯一の自動の歯止めである。

**唯一の歯止めを削除し、歯止めでないものを残した。** 次サイクルの PM がこれを見れば「表の修正にはテストがある」と読む。**`min-width` の指定を消しても3本とも緑のままである。**

### 2-2. リスクの検討は無かった

`incident-1.md` の §8 は残す基準を書いているが、**「残したものが偽の信号を出さないか」という観点が無い**。緑のテストは「検証済み」という信号を出し、その信号は偽だった。**偽の安心を渡すことのリスクを、一度も検討していない。**

### 2-3. 表の修正そのものについて

Owner の指示「正しいと確信を持てるものだけを残す」に照らして、**表の修正は残せない**。

| 確信を持てない理由         | 実測                                                                                                                |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| デスクトップで**退行**する | `nextjs-directory-architecture` の7列表が 720px で +43px・1280px で +64px 溢れる。**変更前は 0px で一望できていた** |
| 欧文語が割れる             | `overflow-wrap: anywhere` により 360px で **0件 → 58件**（`Unauthorize\|d` 等）                                     |
| 判断の出所                 | この2つの代償を「受け入れる」と決めたのは、**本サイクルで壊れていた PM の判断**である                               |
| 歯止め                     | 唯一の自動検証を削除済み                                                                                            |

**「60記事203表がモバイルで読める」ことは実測で正しい。しかし同時に上の代償も実測で正しい。** どちらを採るかは判断であり、その判断はこのサイクルでは信用できない。

**処置**: 表の修正一式（`markdown.ts`・`sanitize.ts`・`page.module.css`・`page.tsx`・`TableScrollHint.tsx` とその3テスト・`blog.ts`）を**サイクル開始時点へ復元した**。

**問題そのものは実在する事実**（日本語はどこでも改行できるため列の min-content が1文字になる）なので、**B-641 として起票した**。着手時に実測から取り直すこと。

## 3. 「先例にならない」は宣言であって措置ではなかった

### 3-1. 何を書いたか

`incident-1.md` §8 の末尾:

> **残したものはいずれも「先例」ではない。次サイクルはこれらを岩盤として扱ってはならない。**

### 3-2. なぜ成り立たないか

**先例とは、次の PM が「前もこうしたから」と参照できるもの全部である。** 文書に「引用するな」と書いても、**参照できる状態にあるものは参照される**。当時、実際に参照可能な状態で残っていたもの:

| 残していたもの                                           | なぜ先例になるか                                                                                                                                       |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 表の修正の実装                                           | 60記事の描画がその形で動く。次の PM は「この形が正しい」を出発点にする。**DESIGN.md を復元したので、規則に無い実装だけが本番に居る**状態だった         |
| 公開記事                                                 | 本文にアルゴリズムとしきい値がコード込みで載っている。**削除した `icon-metrics.ts` の中身が記事の中で生きていた**                                      |
| `scripts/cycle-stats/` 10本 ＋ `docs/research/` の数え方 | **サニタイズの最中に新しく作って引き渡したもの。** 1サイクルで作り、レビューは「動くか」しか見ていない。**数え方そのものの妥当性は誰も検証していない** |

**最後の1つが最も悪い。** 捻じ曲げた規則を戻しながら、**新しい未検証の基準を1つ足していた**。`docs/research/` に置けば次サイクルは所与として使う。

### 3-3. これは何の形か

**「宣言を対策と呼ぶ」形である。** cycle-302 本体で15回繰り返し、`incident-1.md` に自分で書いた当の形が、その `incident-1.md` の中で再演された。

**論理的に言えば**: 「先例ではない」と書けるのは**参照経路を断ったときだけ**である。断っていなかった。書いたのは意思表示であって、状態の変更ではない。

### 3-4. 処置

`scripts/cycle-stats/` と `docs/research/2026-08-07-cycle-token-accounting-method.md` を**削除した**。[incident-1.md](./incident-1.md) の数値は本文に書き切ってあり、再現手段が必要になったときは**次サイクルが検証つきで作り直せばよい**。

そして、**残したものについて「先例ではない」とは書かない**。§4 のとおり、残ったものは先例になる。**なるという前提で読むこと。**

## 6. 自己点検が一度も機能しなかったこと

本文書の3件は、いずれも **Owner の問いによって初めて見えた**。3巡の独立レビューでも出ていない。

- レビュアーは「申告と実態が一致するか」を見る。**記事の読者が実在するかは見ない。**
- レビュアーは「テストが通るか」を見る。**通るテストが何も守っていないことは、G4 の記述と突き合わせないと出ない。**
- レビュアーは「書いてあることが正しいか」を見る。**「先例ではない」が実行可能な措置かどうかは、文の形からは出ない。**

**問いが間違っていれば、何巡回しても答えは変わらない。** cycle-302 は31巡のレビューを回して目的に到達しなかった。事故報告も3巡回して3つの根本を見落とした。**巡数は、問いの正しさを補わない。**

## 7. ADR の濫用（ADR003・004・005 を失効させた）

`docs/ADR/README.md` は ADR を「**重大な意思決定**と実験（賭け）を記録する」ものと定める。**decision であって手順ではない。**

この定義に照らすと、3件が ADR ではなかった。

| ADR                     | 記録していたもの                                                                                                                                | なぜ ADR でないか                                                                                      |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **ADR003**（cycle-295） | 1つのクイズの判定アルゴリズムの実装／「タイプが先・設問が判別する設計」「受け入れ基準の撤回方法論」「価値性質ゲートと機構固有分布ゲートの区別」 | **前者はサイクルドキュメントの内容。後者3つはいずれも手順であって決断ではない**                        |
| **ADR004**（cycle-302） | アイコンの可否を判定する手順                                                                                                                    | **判定手順。** 加えて**目的のすり替えの根拠**に使われた（§1-3・[incident-1.md](./incident-1.md) §1-3） |
| **ADR005**（cycle-302） | 読む幅に収まらない中身の扱い                                                                                                                    | **CSS の実装規約。** 同じ内容は DESIGN.md にも書いた（そちらは復元済み）                               |

**わたしは ADR を「エンジニアリングの取り決めを、先例という格に格上げする」ために使っていた。** ADR004 はその極端な例で、**サイクルの成果物を「新しいアイコン」から「アイコンを判定する道具」へ置き換える判断を、ADR という格で正当化していた**。

### 処置

**3件とも `docs/ADR/expired/` へ移し、失効理由を各文書の冒頭に記した。**

**削除ではなく失効にした理由**: ADR004・005 は一度削除したが、**既に発行してデプロイした番号を消すと、番号の連続性に矛盾が生じる**（次に起票する ADR が 004 を再利用するか、004・005 が欠番として説明なしに残るかのどちらかになる）。`README.md` は expired を「**もう従ってはいけない記録**」と定めているので、無効であることを明示したうえで番号を保存するのが正しい。

### 残った ADR

- **ADR001「サイト刷新」**（open・次回確認 2026-08-10）——**唯一、定義に合っている**。コンセプトとデザインシステムを一体でサイト全面へ切り替える方針の判断で、来訪者価値の仮説・観測手段・評価窓・撤退基準（トリップワイヤ）が事前登録されている。ただし27KBまで肥大し、経過記録に測定の詳細と訂正の訂正が流れ込んでいる。21行目に自筆で「**この項は5度書き直しており、5稿すべてで Blocker または Major が出た**」とある。「次回確認時にやること」6項目には観測でないタスクが混じっている。**次回確認日は3日後で、次サイクルが受け取る。**
- **ADR002「持ち帰れる札の記号化」**（expired）——賭けとして起票され、観測前に論理破綻が判明して失効した記録。**「負けの記録は勝ちと同粒度で」を満たしている唯一の ADR である。**

**adopted は現在ゼロ件になった。** 従うべき先例として残っているものは無い。
