# サイクル-302

いま `public/favicon.ico` に入っているのは、暗い地に白いゴシックの「y」と青いドット（cycle-171 の旧ブランド）。サイトは cycle-282 で紙・墨・朱の店構えになったのに、来訪者の手元に残る一枚だけが青いままだ。青は DESIGN §8-1 が名指しで禁じている色である。店の顔を作り替えたのに、名札だけ前の店の名前が入っている。

計画の途中で 16px を拡大して見て「字としては読める」と書いたが、**それは cycle-299 第1回が壊れた favicon を出荷したときとまったく同じ判定方法**だった（拡大で読めること ≠ 実寸で読めること・incident-1 §3-B）。自分が A3 で禁じる方法で基線を判定していたので、いったん取り下げて等倍で出し直した。

**等倍での暫定所見（A2・[baseline.md](./baseline.md)）: 現行アイコンは可読性の面では壊れていないように見える。** ただし**これは確定ではない**——判定環境が未校正で、判定者も PM 一人だった（A3 は2名以上の一致を要求している）。確定は A4 の成立後に出す。

それでも動機の向きはここで書いておく。**本サイクルは「壊れているから直す」ではなく「別の店の名札が付いているから直す」である蓋然性が高い。** ここを取り違えると、**可読性で勝っている現状より悪いものを出荷しうる**——cycle-299 が実際にそうなった。

## なぜこれを今やるのか

サイト刷新（ADR001）が未完のまま、**禁止色の旧ブランドが全来訪者の検索結果とタブに出続けている**。constitution Rule 4 は「すべての面で最高品質を保つ」ことを求め、AP-P27 は未完の作業が実害を生んでいる状態で他へ着手することを戒めている。B-576 はその未完の一つで、**2度着手して2度とも成果物ゼロで終わっている**。先に閉じるべきものである。

（cycle-301 の「サイクルの結末」に Owner の同旨の指摘が記録されているが、着手の義務はルールから出るのであって指摘の存在から出るのではない。当該記録は根拠資料として参照する＝AP-WF24。）

## この対象は2度失敗している——だから順序を組み替える

cycle-299 は同じ B-576 に着手して失敗した（[incident-1](../cycle-299/incident-1.md)＝設計とレビューの失敗、[incident-2](../cycle-299/incident-2.md)＝是正過程での規範違反）。**同じやり方で3度目をやらない**ために、根を設計面4つ・規範面5つに分けて、それぞれ手順で潰す。

### 設計面の根（incident-1）

| cycle-299 の根                                                                                                                                    | 本サイクルでの組み替え                                                                                                                                                                                                                    |
| ------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| **アイコンがデザインシステムのどのカテゴリにも定義されておらず、看板（§4）の規定を流用して探索が縮んだ**                                          | **B1 でカテゴリを定義したうえで、C3 では「規定に反するから却下」を単独の理由にしない**（下記の3段手順）。DESIGN §11 は本書自身を「導出済み仮説」と定め、観測による改訂を正当な手続きとしている                                            |

**「DESIGN に反する」を却下理由に使うときの3段手順**（cycle-299 は 16px 可読が最強だった墨地案・朱地案を、この検討なしに却下した）:

1. 引用しようとしている規定が**アイコンに適用されるものか**を B1 の定義で確定する。※「地は常に紙・文字は常に墨・朱は印だけ」は §2 ではなく **§4「看板」の規定**である（`DESIGN.md:73` を実査。cycle-299 の記録と本計画の初稿はここを §2 と取り違えていた）。適用範囲の取り違えはそのまま判定を誤らせる。
2. 適用されると判断したうえで、なお最良の候補がそれに反するなら、**候補を却下するのではなく DESIGN の改訂を検討する**（§11 の改訂条件＝観測）。**改訂を選ぶときは、「改訂しない場合に来訪者が失うもの」と「改訂によって店構えの一貫性が失う価値」を並べて書く**——この義務がないと、アイコン1枚のために cycle-282 が確立した一貫性を崩す逆向きの経路が開く（AP-P24）。
3. 改訂する場合は D1 でレビューを通してから実装に入る。

| その文書を削除して**証拠隠滅**を図った                                     | **本サイクルで作った記録ファイルは削除・改変しない。** 訂正は追記（取り消し線＋理由）で行う。対象＝`baseline.md`・`criteria.md`・`shirushi.md`・`exploration.md`・`review-log.md`・`ga-context.md` |

## 芯——GA の実測で、当初立てた芯を差し替えた

計画の最初に書いた芯は「タブに並んだ中から、来訪者が自分の店を見つけられること」だった。favicon といえばタブだと、疑わずに書いた。cycle-299 も同じ前提から出発している。

BigQuery で実測した（2026-07-07〜08-03 の28日・**セッション 1,435／ユーザー 1,318**。SQL と生出力＝[ga-context.md](./ga-context.md)）。**面ごとに分母が違うので、揃えて並べる。**

| 面                                       | 露出の分母                                                      | 実測                                                                                       |
| ---------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **Google 等の検索結果**                  | **Search Console の impressions**（＝アイコンが表示された回数） | **64,616 回**（27日・うち MOBILE 66.66%・DESKTOP 29.61%）。クリックは 959 で **CTR 1.48%** |
| ブラウザのタブ                           | 全セッション（アイコンは常に表示される）                        | **1,334 セッション**（同27日）。うち再訪 8.92%                                             |
| ブックマーク・直接入力・ダークソーシャル | Direct セッション                                               | **334 / 1,435＝23.28%**                                                                    |
| 28日をまたいで戻ってきた人               | ユーザー                                                        | 11 / 1,318＝**0.83%**（※下記のとおり構造的に過小）                                         |
| SNS 経由                                 | Organic Social セッション                                       | 9 / 1,435＝**0.63%**                                                                       |

**この実測から言えること・言えないこと**を分けて書く。

- **言えること**: **アイコンが人の目の前に置かれた回数は、検索結果がタブの約48倍である**（64,616 impressions vs 1,334 セッション・同一27日・どちらも「表示された機会」で分母が揃っている）。**【M-8 で是正】初稿はこの面の露出を GA の Organic Search セッション（997／27日）で測っていたが、それは実際の露出 64,616 の約1.5% にすぎない**——測っていたのは露出ではなく「クリックして来た人の数」だった。露出はクリックの **64.8倍**。加えてセッションの 75.54% は**検索結果を見て、開くかどうかを決めてから**来ている。検索結果でアイコンは「開くに値するか」を判断する材料として**能動的に**見られる。一方タブのアイコンは全セッションに露出するが、見られ方は**受動的**（自分が開いた画面を見失わないための目印）。**能動的に判断材料として見られる最大の面は検索結果である。**
- **言えないこと**:
  - 「タブは母集団がほぼ無い」とは言えない。タブのアイコンは全セッションの 100% に表示され、同一セッション内でタブを行き来する場面にも効く。再訪 0.83% はタブ機能の一部（長期の再認知）しか代表しない。**初稿でわたしはここを縮約して書いていた。**
  - 0.83% は**構造的に過小**である。`user_first_touch_timestamp` は端末 cookie 由来で、iOS Safari（セッションの 27.87%）では JS 由来 cookie の寿命制限により再訪が新規として計上されうる。
  - Social 0.63% は**看板（OGP）の露出の下限としても弱い**。LINE 等のダークソーシャル経由は Direct 23.28% に落ちるため、この数字で看板の価値を評価できない。
  - **小標本である**。GA 側の総 1,435セッション、再訪の分子は二桁台、Social は 9セッション。**桁のオーダーまでを判断に使い、小数点以下を根拠にしない。**（SC 側は 64,616 impressions で十分な量がある。）
  - **【M-9 で追加】bot／自己トラフィックの点検をした。結論は変わらず、むしろ強まった。** engagement の痕跡があるセッションは 1,146／1,435＝79.86%。人間性のフィルタを厳しくするほど Organic Search 比率は**単調に上がる**（全体 75.54% → eng>0 で 79.76% → 滞在10秒以上で **92.72%** → 30秒以上で 97.31%）。モバイル比も 56.93% → 70.19% へ上がり、SC 側の impressions モバイル比 66.66% とほぼ一致した。
  - ただし **Direct 23.28% は人間の直接来訪としては過大**である。OS 別の Linux 234セッション（16.31%）は、**Organic Search 0件・Direct/Unassigned 100%・滞在中央値 3.9秒（他 OS は 27.4秒）・91.9% が都市不明のシンガポール発**で、自動アクセスと見るのが妥当（滞在10秒以上で絞ると 16.31% → 4.40%）。**IP レベルの確証は GA4 raw では取れないので、これは間接証拠による推定である。** Direct の実態は 6.59% 程度に近い。
- **異なる分母の比を取らない**: 初稿で「0.83% と 75.54% は約90倍」と書いたが、前者はユーザー分母・後者はセッション分母で、割ってはいけない量だった。削除した。

Google 自身も一次資料でこう書いている——「検索結果を流し読みする人が素早くサイトを識別できるよう、ファビコンがサイトのブランドを視覚的に代表するものにすること」。これは再認知ではなく初対面の話であり、上の実測と同じ方向を向いている。

### 芯（差し替え後）

**Google の検索結果に並んだ十数件の中で、この一行が「ちゃんとした店だ」と伝わること。** 副次的に、タブ・ブックマーク・ホーム画面での見分けやすさも損なわないこと。

ただし**これは動機の記述であって、合否の基準ではない**。「開いてみようと思えるか」は検索結果の行のタイトル・URL・スニペットが支配的で、16px のアイコンの寄与を分離できないし、自サイトを熟知した判定者が「初対面」を演じることもできない。**合否の基準は A3 で、アイコンに帰属し他人が再現できる形に落とす**（第一課題を検索結果へ移すことと、基準の反証可能性を手放すことは別である——後者は cycle-299 が壊した当のものだ）。

**注意（未検証・A1 で確かめる）**: Google の検索結果でサイトアイコンが**円形にマスクされて表示される**という記述を複数の二次情報で見たが、Google の公式ドキュメントには記載がなく、一次資料で裏が取れていない。もし本当なら「角を使う意匠は切られる」「紙地の四角は円に切られる」という重い制約になる。**推測で基準に入れず、A1 で実物を見て確かめてから基準に入れる**（AP-WF27）。

## スコープの絞り込みと、出荷のゲート（2026-08-04・レビュー3巡目を受けた組み替え）

3巡目のレビュアーが、**この計画の量は1サイクルに収まらない**と判定した（作業を15項目に分解して提示）。cycle-299 は最後の実装だけで失敗し、cycle-301 は横滑りで全 revert だった。**同じ倒れ方をしないために、ここで絞る。**

### 絞り込みの前に確定した、より重い事実

レビュアーが独立に検証した結果、**既知の不合格品（`fd088fa1`）を「y ＋赤い点」と読めてしまった**——つまり**判定装置は、いま既知の不合格品を落とせない**。しかも「LLM の画像入力は必ずリサンプリングを経るため、『等倍で見る』の結果は見る側の条件で反転する」。

**これは本サイクルの土台の問題である。** 判定できないなら、新しいアイコンの可否は責任を持って決められない。それは cycle-299 が2度落ちた当の場所であり、constitution Rule 4（最高品質のみ出荷）に照らせば、**判定できないまま出荷することは許されない**。

### したがって、本サイクルの第一の成果物を組み替える

**第一の成果物は「新しいアイコン」ではなく、「アイコンの可否を判定できる装置」とする。** これは逃げではない——装置が無いまま意匠を作れば、3度目の成果物ゼロか、判定できていないものの出荷になる。装置は本サイクル以降の全ての視覚資産（看板・札・図像）に効く。

### 出荷のゲート（C2 に入る前に置く。後から動かさない）

| ゲート  | 条件                                                                                                               | 満たさない場合                                                                                                                                                       |
| ------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **G-a** | A4 の対照①〜④を、**どれが対照か知らない白紙起動のレビュアーが落とせる**（欠陥を言語化できる）                      | **意匠の判定に進まない。** 落とせなかった対照が校正する必須条件は「判定不能」として候補の合否に使わない。全滅なら意匠は本サイクルで出荷しない                        |
| **G-b** | 候補のうち少なくとも1つが、**現行アイコンの弁別性を等倍・G1〜G4 のすべてで下回らない**（＝新設の必須条件 **N11**） | **出荷しない。** 現行維持とし、本サイクルの出荷は E3（宣言の明示）と、判定装置・「しるし」の定義の確定に留める。「店構え整合」を理由に弱い候補を出すことは**しない** |

**G-b を先に置く理由**: A2 の暫定所見は「現行はライト地で非常に強く立つ」である。**新案が現行より弱くなることは、最もありうる帰結**だ。その場合に「店構えに合っているから」を理由に出荷する経路（AP-WF35 候補・cycle-298 の基準違反出荷と同型）を、**候補を作る前に塞いでおく**。

### 落とすもの・timebox するもの

- **落とす**: F5 の「ADR001 に経過記録を追記」。ADR001 本文を grep したが **favicon・アイコン・B-576・B-583・「未完」いずれもヒットしない**（レビュアー実測）。B-576 を ADR001 の未完部分とする帰属は二次情報経由で裏が取れていない（AP-P34）。**着手根拠は constitution Rule 4 ＋ AP-P27 だけで立てる。** ADR の要否は `/cycle-completion` 時に判断する。
- **timebox**: A1 の検索結果面の追加観測は**これ以上行わない**。主経路は不能と確定済みで、他エンジンの描画規約は Google の代理にならない。
- **上限**: C1 の候補数は **6〜8案**を上限とする（11水準は各案が各軸に1水準を持つため4案でも被覆できる。上限が無いと表の空欄埋めで案が膨張する）。

### 目的

### 作業内容

主たる面（検索結果）で実際に何が描画されているかを実測し、判定基準を凍結し、**判定環境が既知の不合格品を落とせることを陽性対照で証明してから**（A）、アイコンがデザインシステムのどのカテゴリにも定義されていない事実を整理して「しるし」を定義し（B）、軸の各水準を先に列挙した探索で候補を起こして実寸で選び（C）、DESIGN を更新してから（D）実装する（E）。出荷面は favicon.ico・apple-touch-icon・アイコン宣言の3つで、看板は印の決定に従う。

### 検討した他の選択肢と判断理由

- **B-573 の分割済みスライスを1本やる（B-594＝`/play/daily` の h1 不在、B-597＝テーマトグルのタップ標的、B-599＝辞典/共有まわりの a11y 軽微群、B-574＝イディオム一覧のアクセシブル名浄化）**: 不採用だが、**これは実在する着手可能な選択肢である**（初稿は「B-573 は全81ページの全面展開なので1サイクルに収まらない／まず分割の設計が要る」と書いたが、backlog を実査すると**分割は既に済んでおり**、上記4件は単独項目として Queued にある。事実誤認だった）。来訪者価値で比べた結果 B-576 を採る。**ただし「影響範囲で B-576 が勝っている」とは言えない**——初稿の改訂時に「B-594/597/599/574 はいずれも特定1面の局所的な改善」と書いたが、**実査すると誤りだった**。`src/app/layout.tsx:45` は `<Header actions={<ThemeToggle />} />` で、**テーマトグルはルートレイアウトにあり全ページに出る**。したがって B-597（タップ標的 28px＝DESIGN §10 の 44px 未満）は全ページ・全来訪者の操作要素の欠陥であり、影響範囲は B-576 と同格である。B-599 の共有ボタンの不整合も複数面にまたがる。**M-3 を直した記述の中に、M-3 と同型の未実査の断定を入れていた。**

そのうえで B-576 を先に採る理由は次の2つ——(a) B-576 は**2度着手して2度とも成果物ゼロ**で、禁止色の旧ブランドが出続けている未完状態が続いている（AP-P27）。**着手して未完のまま放置しているものと、まだ着手していないものとでは、前者を先に閉じる。** (b) B-573 側のスライスは着手条件が消えず、次サイクル以降に持ち越しても劣化しない（B-576 は放置するほど「別の店の名札」が出続ける）。**規模を理由に外したのではない**（AP-P28・CLAUDE.md 決定原則）。

- **B-573 の全面展開（全81ページ/36ツール）を選ぶ**: 不採用。1サイクルに収まらず、分割済みスライスがある以上この形で取る理由がない。
- **B-576 だけを実施し、印（B-583）は未決のまま触らない**: 不採用。**これが cycle-299 の失敗の直接原因である**——「印を先取りしない」を判定基準(4)に据えた結果、識別子は旧ブランドの「y＋ドット」を所与とするしかなくなり、探索が構図の中の微調整（ウェイト・ドット位置）に縮んだ。印を決めずにアイコンは決められない。
- **B-583 を全部（店構え統一そのものの是非まで）扱う**: 不採用。DESIGN 全体の再評価になり、アイコンのために店の設計思想を開き直すのは規模が逆立ちしている。アイコン系の意匠決定に必要な範囲（印の要否・識別子の形）に限る。
- **SVG favicon を追加し `prefers-color-scheme` でテーマ追従させる**: 現時点で未確定（C で判断）。材料は3つ——(a) Safari は SVG favicon 内の `prefers-color-scheme` を尊重しない、(b) `app/icon.svg` の配信 URL は `/icon?<generated>` で、Google が求める「URL の安定」と相性が悪い、(c) テーマ追従が効かない範囲はデスクトップ Safari の 48セッション＝3.34%（GA 実測）で、ダーク UI の主戦場である Chrome/Edge では効く。16px の詰めはサイズ別に手調整できる ICO が勝る可能性が高いが、cycle-299 の判断をそのまま引き継がず候補比較の中で決める。
- **manifest（PWA 192/512）・theme-color も同時に**: 不採用。B-577 の範囲。束ねるとレビュー品質が崩れる。
