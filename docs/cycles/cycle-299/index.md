# サイクル-299

玄関でも辞典でもツールでもなく、**来訪者が最初に目にして最後まで残る一枚**——ブラウザのタブ、ブックマーク、iOS ホーム画面に出るアイコンを、今の店構えに合わせる。

## 背景と芯

サイトは cycle-282 で「店構え(看板・札)」の視覚言語に刷新された——**紙地(`#f8f7f2`)・墨(`#201e1a`)・明朝(Noto Serif JP)・朱の印(`#af3622`)**。OGP も 410 ページも和色辞典も、この言語で揃っている。

ところが `public/favicon.ico` と `public/apple-touch-icon.png` の2枚だけは **cycle-171(最終更新)の旧ブランドのまま**残っている——**暗地ベタ塗り＋白ゴシックの「y」＋青ドット(`#2563eb`)**。これは cycle-282 が「§8 違反として廃止した」と明言した旧版の視覚言語そのもの(`src/lib/ogp-image.tsx:7-8`「旧版〔全面ベタ塗り＋絵文字＋ゴシック太字・青#2563eb〕を廃し」)。

この2枚は来訪者にとって最も露出の大きい面の一つだ。タブに常駐し、ブックマークやホーム画面に追加すれば手元に残る。SNS でリンクを開いた人のタブにも出る。**店の顔を新しくしたのに、名札だけ古いまま**の状態が続いている。cycle-282 はこれを認識しながら「16-32px の可読性は別種の図像 craft で、55面 OGP 展開に押し込むと拙速化=Rule4 違反」として専用タスク(B-576)へ分離した。その専用タスクが本サイクルである。

芯は「タブ・ブックマーク・ホーム画面という**手元に残る面**で、来訪者が今の店構えと同じ店だと分かるアイコンを、豆粒サイズでも読める品質で届ける」こと。

## 判定基準(着手前に確定・結果を見て緩めない=AP-P02回避)

新アイコンが満たすべき条件。**現物(実ブラウザのタブ・実寸プレビュー)で確認して合否を出す**。緑にするために基準を後から緩めない。

- **(1) 現店構えの言語である**: 地は紙(明色)・図像は墨/朱。**旧版の暗地ベタ・ゴシック・青(`#2563eb`)を一掃する**。並べて OGP/札/サイト本体と「別の店に見えない」こと。
- **(2) 16px で読める**: ブラウザタブ実寸(16px 相当)で、何の図像か潰れずに判別できる。favicon.ico(32×32)・SVG・apple-touch(180×180)の各実寸で確認。**小サイズ可読が本タスクの核心**(cycle-282 が分離した理由)。
- **(3) apple-touch-icon の規約を満たす**: **透過なし**(iOS は透過を黒く合成する)・角丸マスクを見越した安全余白(約 10%)。地は紙ベタなので透過問題は自然に回避できる。
- **(4) B-583 を先取りしない**: 印(店の主張)を出すか・どの字かは B-583 で未決(`ogp-image.tsx:33-39`)。**アイコンは未決の「印/店の主張」に依存させず、既に確定している識別子=ワードマーク(店号 `yolos.net`・その頭文字)に拠る**。旧アイコンも「y＋ドット」でワードマークに拠っていた。字を圧の下で新造しない(cycle-283 の印字すげ替え事故の轍)。
- **(5) 非退行**: `npm run lint && npm run format:check && npm run test && npm run build` 全緑。旧アイコンへの参照(あれば)を確実に新へ差し替え、`public/` の旧2枚と `app/` の新規経路が二重配信・競合しないこと(Next.js のアイコン規約=下記一次資料で確認済)。ダーク環境でのタブ表示も確認。

**先頭方向(design 段階の出発点・確定ではない)**: 旧アイコンの概念「y＋ドット」を保ちつつ、実行だけを店構えへ——**紙地に墨の「y」＋朱のドット**。ブランドの連続性(頭文字＋ドット)を保ったまま、暗地→紙・ゴシック→店の書体・青→朱に正す。印(試)は使わない=(4)。ただし letterform の最終形(明朝の y は小サイズで潰れうる)は design 段階で探索し、reviewer と実寸で検証する。

## 作業計画

### 目的

cycle-171 の旧ブランド(暗地ベタ+白ゴシック「y」+青ドット)のまま残る `favicon.ico`/`apple-touch-icon.png` を、cycle-282 で確立した店構えの視覚言語(紙地・墨・明朝・朱)へ作り直す。タブ・ブックマーク・ホーム画面という手元に残る面で、来訪者が今の店と同じだと分かるアイコンを、16-32px でも読める品質で届ける。

### 作業内容

判定基準(1)〜(5)を着手前に固定。design 段階で先頭方向(紙地/墨の y/朱ドット)を出発点に letterform と生成方式を決め、build 段階で favicon・apple-touch を作成、実ブラウザ・実寸・ライト/ダークで検証し reviewer のレビューを通す。図像は確定済みの識別子(ワードマーク)に拠り、未決の印(B-583)を先取りしない。スコープは favicon + apple-touch-icon の2面に限る。

### 検討した他の選択肢と判断理由

- **本サイクルで B-603(24タイプ一覧の再判定)を選ぶ**: 不採用。前サイクル 298 はこの領域で3層の失敗(測定面の誤り・基準の後退・レビュー省略)を出したばかり。B-603 は「主たる面で判定基準を立て直す」腰を据えた独立サイクルに値し、失敗直後に急いで戻ると同じ轍を踏むリスクが高い。まず来訪者価値が明確で小さく完結する B-576 で手続きを正しく回して立て直す(逃げでなく、今そこにある普遍的な破れを直す判断)。
- **manifest(PWA 192/512)や theme-color も同時に**: 不採用。それは B-577 の範囲。束ねるとサイクルが肥大化しレビュー品質を崩す。本サイクルは favicon + apple-touch の2面に限定。
- **Satori(ImageResponse)一択で全アイコン生成**: 現時点で未確定(A2 で判断)。favicon.ico は Next.js 規約上コード生成できず静的必須(一次資料確認済)。また 16-32px の明朝グリフは Satori だと潰れうるため、手描き SVG の方が可読の craft で勝る可能性がある。生成方式は可読品質で選ぶ。
- **旧「y＋ドット」の構図ごと捨てて新図像を作る**: 現時点で不採用寄り(design で再検討可)。ワードマークは確定済みの識別子でブランドの連続性を保てる。構図を全面刷新すると B-583(印/店の主張の未決)に踏み込みやすい。
