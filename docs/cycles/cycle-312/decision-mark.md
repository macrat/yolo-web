# 決定: 識別マークの規定を立て直す

`DESIGN.md` §4 の識別マーク規定は cycle-310 由来として無効と宣言されている。一方で実装は出荷済みで動いている。[実態の調査](./facts-identification-mark.md)で、**規定18項目のうち13項目は実装と一致していた**——規定そのものが作り話だったのではない。壊れているのは、規定の内部矛盾・扱っていない面・弁解の後貼りである。

## 何が壊れているか（調査で確定した6件）

| #   | 内容                                                                                                                                       |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | **共通仕様「朱一色」と個別仕様「favicon＝朱＋紙色の白抜き」が文書内で矛盾**している                                                        |
| 2   | **apple-touch-icon が文書に一切無い**。実装は出荷されている（180px・朱の全面・白抜き y）                                                   |
| 3   | §4「角丸は 0px 基調・例外は値札と入力欄の2つだけ」に、**favicon の角丸（rx 17.6）が入っていない**                                          |
| 4   | 看板規定「店号と識別マークから出所が読める」に対し、**札経由の看板（診断結果・伝統色辞典）は y を持たない**                                |
| 5   | **画面上の印が扁平に潰れている**。実測 63.5×13.2px（本来は正方形）で、円環は直径13px・字は8.8pxとなり判読できない。本番にも配信されている  |
| 6   | 「旧称」「なお」「当面」「別サイクルで扱う」「**その規定と看板の識別マークは矛盾しない**」——**矛盾を弁解する注記そのものがツギハギの証拠** |

加えて、cycle-310 のコミット `3dd4a30d` で **cycle-306 の「決定1・決定4」への引用が削除されていた**（「cycle-306 で形を確定した（…決定1・決定4）」→「（…）」）。決定4 は「favicon と OGP は同一の塗り標章」だったが、それを破棄する旨の記述は現行 §4 に無い。**矛盾を解消せずに、矛盾していた相手への参照だけを消していた。**

## 決定

### 1. マークは残す。仕事は「出所を伝えること」

**根拠は来訪者の側にある。** 共有カードも、保存された結果画像も、ブラウザのタブも、**サイトの文脈から切り離されて単独で流通する**。そこに出所の手がかりが無ければ、見た人は「これはどこのものか」「もう一度どうやって行くのか」が分からない。マークはその問いに答えるために在る。

これは「反復露出でブランドを刷り込む」といった仕組みではない。**見た人が来た道を辿れるようにする実務**である。だから、出所が他の手段で十分に伝わっている面では、マークは要らない。

### 2. 出所を伝えるのは、まず店号である

調査で分かったこと——**札の画像はすでに左上に "yolos.net" を刷っている**。だから診断結果の札に y が無いことは欠陥ではない。出所は店号が伝えており、右上の位置には中身を表す一字（診・色）が据わっている。

したがって規定をこう改める。

- **単独で流通する面（看板・札）には、店号を必ず刷る。** 出所を伝えるのはこれである。
- **右上に据える印は一つだけ。** サイト全体を指す面なら頭字 **y**、特定の中身を持つ札ならその**中身を表す一字**。
- 現行の「店号と識別マークから出所が読める」は、**識別マークを必須と読ませる点が誤り**だった。店号が必須で、印は面に応じて選ぶ。

### 3. 色は朱と紙色の2色

「朱一色」を撤回する。**朱だけで描くと 16px の favicon では字が消える**——実際、favicon は朱を地にして紙色で字を白抜きしている。矛盾していたのは実装ではなく規定の書き方である。

**使う色は朱と紙色だけ**と書けば、4つの形すべてが1つの規則に収まり、例外を彫る必要がなくなる。

### 4. 規定する面を、字と容器の2軸で決める

現行は favicon と OGP の2面しか定義していない。実装は4つあり、しかも**「札＝看板」（診断結果・伝統色エントリの共有画像）がどちらにも収まらない**——1200×630 の大きい共有面でありながら、印は素の y ではなく「円環＋中身の一字」である。面を size で並べる表では、この面が必ず落ちる。

だから**2つの軸に分けて決める**。

- **据える字は、その面が何を指すかで選ぶ。** サイト全体を指す面なら頭字 y、特定の中身を持つ面ならその中身を表す一字。
- **容器を付けるかは、字が地に埋もれるかで決まる。** 漢字一字は紙の上では本文に見えてしまうので細い円環で囲む。極小では素の字がつぶれて消えるので塗りで囲む。明朝の y は大きい面ではそれだけで印として立つため、容器を持たせない。

| 面                             | 据える字       | 容器                                                   |
| ------------------------------ | -------------- | ------------------------------------------------------ |
| 看板（サイト全体を指す共有面） | 頭字 y         | なし（素の朱）                                         |
| 札（特定の中身を持つ共有面）   | 中身を表す一字 | 細い円環                                               |
| 画面上の成果物                 | 中身を表す一字 | 細い円環                                               |
| favicon（16–48px）             | 頭字 y         | 朱の塗りの角丸正方形・字は紙色で白抜き                 |
| apple-touch-icon（180px）      | 頭字 y         | 朱を全面に敷く・字は紙色で白抜き（角丸は OS が付ける） |

**この2軸なら、出荷している5つの面がすべて1つの規則から導ける。** 面を列挙するだけの表は、新しい面が増えるたびに落ちる。

### 5. 正方形で描き、読める大きさで出す

現行の規定は**大きさの上限（包み幅の 1/5 以下）しか定めていない**。下限も縦横比も無い。その結果、画面上の印は 63.5×13.2px に潰れ、直径13pxの円環に8.8pxの字が入った状態で出荷されている——誰にも読めない。

- **縦横比は 1:1。** 幅だけを指定して高さを成り行きに任せない。
- **据える位置は右上、一つだけ。** 品名・本文・罫の可読性を損なう重なりを作らない——重ねてよいのは成果物の記号面だけである。
- **字が読めない大きさでは出さない。** 読めないなら、その面には印を置かない。

この2行があれば、いま起きている潰れは規定違反として検出できる。**上限だけを書いて下限を書かなかったことが、この欠陥を10ヶ月見逃させた。**

### 6. 角丸の規則は UI 要素に掛かる

§4 の「角丸 0px 基調・例外は2つ」は**ページの UI 要素についての規則**である。識別マークの形は本節が定めるので、favicon の角丸はこの規則の例外ではなく、そもそも管轄が違う。現行は管轄を書いていないため矛盾に見えていた。**管轄を書けば例外は要らない。**
