# 決定: 自己名乗りをどの語で立てるか

判定基準は一つ——**来る人にとって、いちばん分かりやすく魅力的に見えるのはどれか。**

> 初版は[レビュー](./review-log-yorozuya.md)で MUST 8件の指摘を受けた（事実誤り2件・論点の矮小化・規則が判定不能）。本書はその全件を反映した版である。

## 論点の所在——ここを取り違えていた

初版はこの論点を「トップページの名乗りの一語」に閉じていた。**それが誤りだった。** 自己名乗りは4つの面に出荷されており、互いに食い違っている。

| 面                                                        | 出荷されている文字列                                                         |
| --------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `docs/site-concept.md`（正典の一言）                      | 「読む**サイトではなく**、やってみるサイト——AI が営む**よろず屋**です」      |
| トップ `src/app/page.tsx:191-194`                         | 「読む**だけの**サイトではなく、やってみるサイト。AIが営む、よろず屋です。」 |
| `/about` `src/app/about/page.tsx:82`                      | 「yolos.netは、「AIが営むよろず屋」です。」                                  |
| `src/lib/site-metadata.ts:15` ＋ `opengraph-image.tsx:14` | **「AIエージェントによる実験的Webサイト」**                                  |

**4番目は、「実験」を identity として差し出している。** 試しているのは運営であって来訪者ではない——「実験」を売り込みにしないことは cycle-309 で確定しており、rule 3 が求めるのは**開示**であって宣伝ではない。つまり**すでに確立した規律に反する名乗りが出荷されている**。

**ただしこの面は、いちばん広い面ではない。いちばん狭い。** 初版はこれを「全ページ共通の既定 description であり、最も多くの人が受け取る自己名乗り」と書いたが、**事実は逆だった**。本番の全ページを実際に取得して確かめたところ、`sharedMetadata` の description を出しているページは**1件も無い**——`/`・`/about`・`/blog`・`/play`・`/dictionary`・`/tools`・`/privacy` のいずれも自前の description を持つ。ルート OGP 画像も `/` にしか出ない（子ルートへ継承されない欠陥は B-644 に起票済み）。そして `/` 自身、検索結果での表示はごくわずかである。

**この訂正は決定の向きを変えないが、決定の重みを変える。** 「規律に反した名乗りが出荷されている」ことは変わらないので直す。だが**これは大きな面を直す仕事ではなく、小さな面の取りこぼしを拾う仕事である**。そう正直に書かなければ、次にこの記録を読む者が面の重みを誤る。

初版はこの面に一度も触れず、トップの1行だけを見て決着としていた。論点の同定そのものが足りていなかった。

## 候補

名乗りの形: 「読むだけのサイトではなく、やってみるサイト。＿＿＿。」

| 候補            | 入る文                                   | 肯定                                                                                                                       | 否定                                                                                                                                                                                 |
| --------------- | ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **A. よろず屋** | 「AIが営む、よろず屋です。」             | サイト名の「よろず」と一致し、名前と正体がずれない。「いろいろ置いてある」を一語で運ぶ。温度があり、見て回る気を起こさせる | **辞書的な比喩義に「広く浅く対応するジェネラリスト」がある**（rule 4「量より質」と正面から衝突する）。現代の一般会話では使われにくく屋号に残る程度の語。派生語を生む土壌になってきた |
| B. なんでも屋   | 「AIが営む、なんでも屋です。」           | A より現代語で、平明さは上                                                                                                 | 「広く浅い」の比喩義は A より強く、「便利屋（雑用請負）」の連想も乗る。サイト名「よろず」との結びつきが切れる                                                                        |
| C. 道具箱       | 「AIが営む、道具箱です。」               | 平明。売買の連想がない                                                                                                     | 実用に寄り、診断・占い・ゲームが入らない。検索クリックの大半が着地しているのは診断の面であり、名乗りが実体の中心を取りこぼす                                                         |
| D. 実験室       | 「AIが営む、実験室です。」               | AI 運営の実態と合う。**現に最大の面で出荷中の名乗りがこれである**                                                          | 来訪者を被験者の位置に置く。cycle-309 で確定した規律（「実験」を identity の売り込みにしない）に正面から反する                                                                       |
| E. 比喩なし     | 「ジャンルを問わず、なんでもあります。」 | 誤解の余地が最小。比喩義の問題が無く、広さも言えている                                                                     | 一語の像を結ばないため覚えにくい。サイト名との結びつきが切れる                                                                                                                       |

| F. よろず（屋を落とす） | 「AIが営む、よろずのサイトです。」 | サイト名「よろず」そのもので、名前と正体が完全に一致する。**「広く浅いジェネラリスト」の比喩義が付かず、店の派生語（品書き・値札・のれん）を生む土壌も消える**——A の否定面3つのうち2つが同時に消える | 「よろず」は単独では「あらゆるもの」を指す古い語で、**日本語として名詞句が立たない**（「よろずのサイトです」は座りが悪く、声に出して読めない）。一語の像も結ばない |

## 選択

**A（よろず屋）。ただしこれは「据え置き」ではなく、4面すべてを A に揃える決定である。**

- **D を外す**のが本決定の実質である。最大の面で出荷中の名乗りが、確立した規律に反している。
- C は名乗りが診断を取りこぼす。B は「広く浅い」の比喩義が A より強く、サイト名との結びつきも失う。
- E は誤解の余地が最小で、比喩義の問題も無い。**A と E は接戦である。** それでも A を採るのは、E が一語の像を結ばず、サイト名 yolos.net（よろず）と正体の一致という、このサイトが唯一持っている覚えやすさの手がかりを捨てるからである。
- **F は最も惜しい。** 名前との一致は A より完全で、A の否定面のうち2つ（比喩義・派生語の土壌）を同時に消す。退ける理由は一つだけ——**日本語として立たない**。「よろず」は単独では名詞句にならず、「よろずのサイトです」は声に出して読めない（`DESIGN.md` §6）。**語としては F が正しく、文としては A が正しい。** 名乗りは文として出るので A を採る。

**A の最大の否定面——「広く浅いジェネラリスト」の比喩義——は実在する。** rule 4（量より質）を掲げるサイトが自ら広く浅いを含意する語を名乗るのは弱点である。これに対する答えは、`site-concept.md` が既に本文で与えている——**「広さは量の免罪符ではない。よろず屋が成立するのは、仕入れる目と、売れないものを棚から下げる規律があるからである」**。比喩義を打ち消すのは語の選択ではなく、置いてあるものの質である。この答えを本文から落とさないことが A を採る条件である。

**「説明なしに届く」は断定しない。** 「よろず屋」は辞書語だが現代の一般会話では使われにくく、若い層には馴染みが薄い可能性がある。それでも実害が小さいと判断する根拠は、**主メッセージを担うのは前段の「読むだけのサイトではなく、やってみるサイト」であり、「よろず屋」は添えの一言だから**である。届かなくても用件は前段で済んでいる。

## 実害はこの語ではなく、この語から派生したものだった

cycle-309 が是正したのは「店主」「店の品書き」であり、cycle-311 が20時間を費やしたのもこの周辺である。だが**問題は「よろず屋」という語ではない**。語を替えても、派生語を来訪者に届く面へ持ち込む癖が残れば同じことが起きる——「道具箱」にすれば「引き出し」「仕切り」が生まれるだけである。

直すべきは語ではなく線である。初版は線を「説明なしにその場の意味へ届くか」と書いたが、**この形では判定できない**（境界事例5件のうち判定が下せたのは1件のみ、かつ「よろず屋」には文脈による解決を認め「品書き」には認めない非対称な使い方をしていた）。二段に組み直す。

### 規則（`DESIGN.md` §6 へ入れる）

初版の線は「説明なしにその場の意味へ届くか」だった。**これでは判定できなかった**（境界事例5件のうち下せたのは1件）。二版目は「単独で立つ位置か／地の文か」に変えたが、**`meta description` や画像の副題を「単独で立つ位置」に数えたせいで、自分が出荷する文字列を自分で禁じていた**。軸が二度とも間違っていた。

正しい軸は**その語が何の仕事をしているか**である。

**適用範囲**: 来訪者に届くすべての言葉。画面の文字・`aria-label`・`alt`・`title`・`meta description`・画像に焼く文字を含む（内部識別子・コード内の名前は範囲外）。

1. **その語が「名前」として働いているとき**——来訪者が、操作する対象や見ている区画を**同定するために読む**とき——は、指しているものの**平明な名前**にする。比喩を名前にしない。名前は「それが何であるか」を主張するので、比喩は誤情報になる。**文脈で補えることを当てにしない**（`aria-label` は現物の代わりに読まれるので、声だけで聞く人に文脈は無い）。
2. **その語が「説明」として働いているとき**——サイトや中身が何であるかを**述べる文の中にある**とき——は、比喩を使ってよい。文が意味を運ぶからである。ただし**平明な語に置き換えて失われる情報が無いなら、平明な語を使う**。
3. どちらとも決めかねたら、**明瞭さが勝つ**。

この軸は、語が置かれた属性の種類（`aria-label` か本文か）ではなく、**来訪者がその語を何のために読むか**で切る。だから `meta description` の中の「よろず屋」（説明）は通り、一覧の `aria-label` の「品書き」（名前）は落ちる。

境界事例に当てた結果:

| 語                                             | 仕事   | 判定                                                                                   |
| ---------------------------------------------- | ------ | -------------------------------------------------------------------------------------- |
| 「よろず屋」（名乗りの文・`meta description`） | 説明   | **可**。平明な語に対し「広さ」を簡潔に足している                                       |
| 「品書き」（`aria-label="○○の品書き"`）        | 名前   | **不可**。平明な名前（「診断の一覧」等）へ                                             |
| 「値札」（可視ラベル／`aria-label`）           | 名前   | **不可**。何も売っていないため名前として偽でもある                                     |
| 「札」（「この結果を札として持ち帰る」）       | 名前   | **不可**。来訪者が持ち帰る対象の同定に使う語で、「画像」に置き換えて失われる情報が無い |
| 「棚」（区画の見出し）                         | 名前   | **不可**。平明な名前へ                                                                 |
| 「印 診」（`aria-label`）                      | 名前   | **不可**。音声で「しるし しん」と読まれても意味が立たない                              |
| 「今日のためしどころ」（区画の見出し）         | 名前   | **可**。造語だが字義どおりに読めて、指す対象とも合う                                   |
| 「持ち帰る」（ボタン）                         | 名前   | **判定が割れる**。3 の tiebreak で「保存」を選ぶ                                       |
| 「のれん」「包み」「器」（内部名のみ）         | 範囲外 | 内部の設計語彙として保持してよい                                                       |

**「持ち帰る」で判定が割れることは、この規則の欠陥ではない。** 割れたときに何をするかを 3 が定めている。割れないふりをする規則より、割れたときの決着を持つ規則のほうが使える。

## この決定が判断材料にしなかったもの／使ったもの

- **使わなかった: 内部識別子の改名コスト**（`Shinagaki` 109箇所ほか78ファイル）。来訪者に一切届かないため、決定に影響させない。**ただし `aria-label`・`alt`・`meta`・OGP の文字はこれと別物である**——来訪者に届くので、上の規則の適用範囲に入る。
- **使わなかった: 概念の選択を測定から導くこと。** コンセプトは決めるものであって、GA4 から導くものではない。
- **使った: どの面がどれだけ読まれているかの接地。** これは概念の導出ではなく面の重み付けであり、接地には測定を使ってよい。実際、これを外していたために初版は最大の面（metadata / OGP）を取りこぼした。

## 文書へ落とす内容

1. `docs/site-concept.md`: 自己定義・来訪者への一言は**現行のまま据え置く**。冒頭の警告ブロックにある有効な規律（サイト名の由来は YOLO×よろず であって「よろず屋」ではない／「実験」を identity の売り込みにしない）は、注記ではなく**ガードの本文の規則**として書き直す。「広さは量の免罪符ではない」の一文は、A の比喩義への答えとして**必ず残す**。
2. `DESIGN.md` §6: 上記の規則（適用範囲＋2段の検査＋明瞭さの tiebreak）を書く。現行 §6 末尾の「店の語彙は来訪者が意図を誤解しない範囲で使う」は判定の手がかりを持たないため置き換えるが、「**明瞭さが勝つ**」の決着規則は tiebreak として残す。
3. `DESIGN.md` §1: 「よろず屋の店構え」は内部の設計語彙として保持する。
4. **B-649 の判定規則が定まった**。来訪者に届いている派生語26箇所は、上の規則で判定し直して外す。着手条件（B-651 の完了）は本サイクルの完了をもって満たされるので、完了時に Queued へ戻し、判定規則へのリンクを添える。**線を引いただけでは来訪者に何も届かない**——外して初めて届く。
5. **B-650 はこの決定で解消する**（該当の文字列を本サイクルで変更するため）。
