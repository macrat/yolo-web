## 指摘

### 指摘1（軽）: t5a-measure.md 0章の「この max(dx, dy)」が、`l` と `n` の2つの隔たりを1つの文で混ぜている

0章の「記録」の項は、`l`（着地の範囲の中で、点から組を最も離せたときの max(dx, dy)）を書いた直後に、「条件7 の「避けられたのに落ちた件」の判断は、2打目の `click` の落ちた先と、**この** max(dx, dy) を Android の半辺（10px と 16px）と突き合わせて、数え直す」と続ける。続く文は「数え直すのは、道具では寄らなかったが max(dx, dy) が 16px より小さい件」と書く。

文の組みからは「この」は `l` を指して読める。ところが plan-t5a7.md 3 が数え直しに使うのは、点から最も近い押せるものまでの隔たり（`n`、report.mjs の `mayFall16`）である。`l` が答えるのは別の問い（範囲の中に、16px 離せる送りがあったか。避けられたかどうか）になる。どちらも条件7 の判断に要る値だが、一つの文に重ねると、次のサイクルの測りの担当が `l` を 16px と比べて「寄りうる件」を数える読み違いの道が残る。この文は前回の直しで書き換えた所の続きで、直しの範囲が文の前半に及んでいない（AP-WF41 の小さな形）。

直す向き: 文を2つに分ける。(a) 避けられたかは、`l` を Android の半辺（10px と 16px）と比べて決める。(b) 寄りうる件の数え直しは、`n` の max(dx, dy) で、道具では寄らなかったが 16px より小さい件を数える。この直しは、carryover.md が道具を直したあとに書き直すものに挙げる「0章の数え直しの文」と同じ所なので、書き直す一覧はそのままでよい。
