## 指摘

### 指摘1（重大）: 2a の理由の文が事実と違い、来訪者にいちばん重い件が 2a の外にあることが書かれていない

2a は「character-personality の 375×550 で起き、来訪者の答えを変える件である」と書くが、試しの走りの記録では、character-personality の 375×550 は 16/45 に入っていない。この回は範囲の中に両方の組を外す送りが無く（clearOfBoth 0）、2打目は選択肢に真上から落ちた。16/45 に入る character-personality は 1280×800 の回である。PV の 85.8% が character-personality、82.3% がスマートフォンであることを急ぐ理由にしている文で、その組の件を取り違えている（AP-P16。数の出どころを確かめずに書いた文）。

あわせて、試しの走りでは「はじめる」の 375×550 の4本と 200% の12本が、2a の直しでは消えない「避けられない件」として出ている。2a は「全体の測りのあとに直すと変更後の版を2度測ることになるので先に直す」を理由にするが、同じ理由はこの件にもっと強く当たる。この件は 5 で 8章の4つ（見せる範囲を広げる・組みを直す・第2の組を外す・受け入れる）から選ぶことになり、着地の関数か開始の画面の組みを変えれば、T5a-8 で「はじめる」（組みを変えれば「もう一度挑戦する」も）を測り直すことになる。「直した版を1度だけ全体で測る」は、2a だけでは達しない。

直し方: 2a の理由の文を記録のとおりに直す（375×550 の6本と 1280×800 の10本。character-personality は 1280×800）。そのうえで、試しの走りで見えた「はじめる」の避けられない件（375×550 の4本・200% の12本。cycle-319 の4本と同じかも書く）を、2a に入れて先に決めるか、5 まで待つかを PM が決め、待つなら、T5a-8 の測り直しが「はじめる」に掛かる見込みが大きいことと、それでも待つ理由（ほかの操作の件とそろえて決めたい、など）を書く（AP-P02。自分の段取りの理由を弱める材料を書く）。

### 指摘2（重大）: 直す形が、着地の関数の2つの枝のどちらをどう変えるかを決めておらず、完了の条件が満たせない

「範囲の中の送りのうち、max(dx, dy) が 16px 以上になるものを選ぶ。そうした送りが範囲に無いときの順は、設計 4-9 の手順5 のとおり」は、次を決めていない。

1. **基準が送らないときの枝**: 4-9 はここで「点からの距離は見ない」と決め、その理由（来訪者が動かないまとまりを見ているので、ずらせばそれだけで余計な動きになる。§11）を書いている。2a はこの枝でも距離を見ることになるが、(a) 送るかどうかの引き金を「s0 で真下に来る」のままにするのか、「s0 で 16px より近くに来る」に広げるのか、(b) 16px 以上の送りのうち、どれを選ぶのか（s0 に最も近いもの、と読めるが書いていない）が無い。(a) を「真下」のままにすれば、s0 で選択肢から 1〜15px の所に点が残る回は送らず、タッチの調整で寄る件が残る。広げれば、送らない回が送る回に変わり、1つの操作に応える動きが増える（§11）。どちらを選ぶかは設計の判断で、その比べを PM がここで書く必要がある（builder に任せる形では、4-9 の「分ける理由」の段落をどう書き直すかが決まらない）。
2. **基準が送るときの枝**: いまの順（d1≠0・d2≠0・d1 が大きい・d2 が大きい・s0 に近い）では、d1 を 100 に保つことが d2 を大きくすることより先に立ち、375×550 の5本が選択肢から 12px 前後に留まった。16px の線を、1・2 の「0 でない」を「16px 以上」に替える形で入れるのか、別の段として入れるのかで、選ぶ送りが変わる。距離も、いまは直線の距離（`Math.hypot`）で、3 の「タッチの調整の距離」は max(dx, dy) で決まると書く。d1・d2 の大きさの比べを max(dx, dy) に替えるのかも決める。
3. **16px 以上の送りが範囲に無いとき**: 「手順5 のとおり」は、いまの縁ぎりぎりの選び方に戻ることになる。試しの走りの yoji-level の 375×550 は farBoth が 10 で、この形では 0.0px の所に着いたままになる。16px に届かないときは、届く中で max(dx, dy) が最も大きい送りを選ぶ、のように、縁から離せるだけ離す順にしないと、来訪者の側の害（大きい触れ方で寄る）は残る。
4. **完了の条件**: 「16/45 の件が 0 になり、どの回も max(dx, dy) が 16px 以上」は、yoji-level の 375×550（farBoth 10）と、範囲に外す送りが無い16回（clearOfBoth 0）で満たせない。条件を「範囲の中に 16px 以上離せる送りがある回では、どれも 16px 以上。無い回は、範囲の中で最も離せる隔たりに着く」のように、関数の決めたことと照らして書く。また、走らせる範囲を「375×550 と 1280×800、全15本」とすると 30 回で、16/45 と比べられない。200% を含む 45 回にする。

あわせて、2a の判断に 16px の出どころの限りを書く。16 は Android の面の半辺の上限（knowledge の実測とソース）で、iOS の Safari の調整は `input-events-and-guards.md` のとおりこのコンテナでは測れない。iOS の閲覧の割合が分からないまま 16 で足りると読ませないよう、iOS の件は 5 の判断と T9 の見張りに渡すと書く。

### 指摘5（重大）: 基準の版の回ごとの記録を `tmp/` に置くと、日をまたぐ測りが続けられない

3 の「日をまたぐ記録と版」は、`tmp/` がセッションを越えて残らないので、担当が終わるたびと日の終わりに PM が `measure/` をコミットし、続きは記録のある走査を飛ばして測る、と定める。基準の版の測りは見積もりで壁時計 621 分（10-2）で、担当1人 4時間の物差しで3人以上、日をまたぐ見込みがある。回ごとの記録を `tmp/` に置けば、セッションが切れたときに基準の版の測った分が消え、続きから測れず、測り直しになる。集計の表を t5a-measure.md に写すのは測り終えてからなので、途中の分は守られない。

もう1つは、計画が道具と記録を残すとした理由との食い違いである。`measure/README.md` は「この道具と記録は … t5a-measure.md の条件7・D5 の表 … に書く数の出どころで、その数をセッションを越えて確かめ直すためのサイクルの記録」と書く。基準の版の表（条件7 の比べ・D5 の B-620 の材料。D5 は「両方の版を測る」で、基準の版の数も B-620 へ渡る）は、この形では出どころが残らず、あとから確かめ直せない。「判断（5）は押しごとに読まない」は押しごとの記録を置かない理由にはなるが、要約まで置かない理由にはならない。

直し方: 指摘4 の比べで基準の版の要約を置ける形を探す。置けないと決めるなら、(i) 日をまたぐ間の基準の版の記録の守り方（測り終えて表に写すまでは途中の記録もコミットし、表に写したあとで外す、など。外すときの履歴の大きさも書く）、(ii) README の「確かめ直す」の文を、基準の版の数は確かめ直せないと読める形に書き直すこと（ツギハギにせず、初めからそう書いた形で）、(iii) 確かめ直せないことが後のサイクルの判断（B-620・T5a の完了のレビュー）に害を出さない理由、を書く。
