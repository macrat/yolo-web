## 指摘（どれも来訪者に届く設計の決めごとで、改善指示の理由になる）

### 1. 1打目の点からの距離で絞る形を退けた理由が事実に反し、退けた形のほうが来訪者に良い見込みが高い

決定は「1打目の点から 100px（`DOUBLE_TAP_SLOP`）の中だけを受けない形」を、「Chromium のタッチの調整は点から離れた押せるものへ寄せる（knowledge §8）ので、距離で絞ると寄せた先を守れない」として退けている。knowledge §8 によれば、寄せる範囲は触れた面の半辺（CSS px で 10〜16px）までで、それより離れた押せるものへは寄せない。t5a-measure.md 10-1 でも、2打目の `click` の座標は寄せたあとの点で、1打目の点 (52, 763) に対して (52, 772) と 9px しか離れていない。100px の中で比べれば、寄せた2打目はどれも中に入る。マウスのダブルクリックは OS が数える矩形が数 px なので、なおさら中に入る。

したがって、距離で絞っても二度押しの2打目は1つも漏れず、窓の中に遠くを意図して押した1打（ヘッダ、別の選択肢、結果の画面の下のほうのリンクなど）は捨てずに済む。決定が「受ける害」として受け入れた害を、守りを弱めずに減らせる形である。cycle-301 の「領域を絞った窓」（knowledge §4）は押せるものの置き場で絞ったために、1打目の座標に来た窓の外のものが無防備になった失敗で、2打目の落ちる点そのもので絞るこの形とは型が違う。

次を直すこと。

- 距離で絞る形を採るか、採らないなら事実に支えられた理由を書く（例: iOS の Safari の二度押しの距離が公開されていないことをどう扱うか）。
- 採るなら、比べる座標を決める（画面の座標 `clientX`・`clientY` で比べる。着地の送りのあとも指の位置は画面の上で同じなので、ページの座標では比べない）。比べるのは2打目の `mousedown`・`click` の座標と1打目の `click` の座標であることを書き、試験と測り（D5 の2打目をずらす走査を窓の中で走らせて、100px の中で受けないこと・外で受けること）に入れる。

### 2. 理由の中の「はじめる」の事実が landing-options.md と食い違う

- 「閲覧の 85.8% を占める character-personality の 375×550 は、ボタンのどこを押しても直る形が無い（4-1）」は、4-1 が「はじめる」を上げる B′ だけの表で、landing-options.md 3 には「直るのは、B（この本だけなら +62px、全部の本なら +86px）と A″ の組か、C（帯を外して基準より +207px）」とある。直る形はあり、害（開始の画面に 86px の空き・320×550 で「はじめる」が最初の画面から外れる・C では帯が隠れる）があるので採らない、が事実である。
- 「下げる B は 320×550 で「はじめる」を最初の画面から出し、来訪者が始められなくなる」は言い過ぎで、landing-options.md 2-2 は4本で「はじめる」の上端が 543 になり「最初の画面からほぼ外れる」（t5a-design.md の「はじめるを狭い画面でも最初の画面に入れる」に反する）と書く。来訪者は送れば始められる。
- 結果の画面の B（知識クイズの結果のボックスの下を 105px 下げる。landing-options.md 2-2・2-5）を採らない理由が書かれていない。窓のあとの押しを合否に入れない（決めたこと 3）なら要らない、というのが理由なら、そう書く。

理由の結論（送りと組みでは 200% を含めて 0 にならないので時間の守りが要る）は変わらないが、決定の文は設計の文と knowledge に写されるので、事実のとおりに直すこと。

### 3. 診断の答え→次の問の2打目が読んでいない問に答えを入れる件が、残ることとして書かれておらず、掛けない理由が掛ける理由と食い違う

診断では、答えてから 150ms で次の問が出る（`ANSWER_SHOWN_MS`）。150ms より後に届く二度押しの2打目（Android の二度押しの上限 300ms の大半、道具の 300ms の回）は、次の問の選択肢に落ちて答えを入れる。t5a-design.md 4-9 は、この件を B-620 の類として条件7・D5 で数を記録すると決めており、決定の「空振りでないことの対」も「診断の答え→次の問を 150ms の間隔で押すと、2打目が次の問の答えを入れること」を合格にしている。閲覧の 85.8% を占める character-personality は診断で、この件は来訪者がいちばん多く通る所に残る。

ところが決定は、この件を残るものとして書いていない。「この決定で、来訪者の二度押しの2打目が読んでいない問に答えを入れる件が無くなるか」に対する答えは「3つの切り替わりでは無くなるが、診断の答え→次の問では残る」で、決定にそれが無いと、設計の文と knowledge に「二度押しは守った」と写される。

また、掛ける理由として「掛ける3つの切り替わりは、どれも新しく出たものを読んでからでないと意図して押せない所である」と書くが、診断の次の問も新しく出た問で、読んでからでないと意図して押せない点は同じである。掛けない理由として残るのは、cycle-301 の害（速く答える人の答えを捨てた）と、それが診断の次の問でどれだけ起きるかの見込みである。次を書くこと。

- 診断の答え→次の問で、150ms より後の2打目が次の問に答えを入れる件が残ること、その扱い（B-620 の材料として条件7・D5 で間隔ごとに数える。4-9 のとおり）。
- 掛けない理由を、3つと何が違うのかで書き直す（読む前の押しかどうかでは違わない）。
- この切り替わりに限って害の小さい形が無いかを比べる。例: 指摘1 の距離で絞った短い窓、または `detail >= 2`（連続の押しとブラウザが数えたもの）で、1打目が答えを入れた連続の2打目だけを受けない形（いまの `guardSecondPress` が `mousedown` で見ている判定と同じ）。4-9 の L2 の退けた理由（タッチの 500ms の2打目が `detail` 1、iOS 未確かめ）は「全部は塞げない」で、「塞げる分を塞ぐと害が出る」ではない。採らないなら、来訪者の側の理由を書く。

### 4. 「もう一度挑戦する」→開始の画面の扱いが書かれていない

決定の「掛ける」にも「掛けない」にも、「もう一度挑戦する」→開始の画面が無い。この切り替わりも押した点の下が入れ替わり（t5a-design.md 4-9）、cycle-301 で2打目が「X でシェア」・関連のリンク・FAQ に落ちた所である（knowledge §4）。t5a-design.md 4-9 は2打目が「はじめる」を押すのを来訪者のしようとしたことのとおりとして避けず、landing-options.md 4-2 では着地で「はじめる」のほかの押せるものから 56px 以上離れる。掛けないのが正しい見込みは高いが、決定がそれを決めていないと、実装と測りでどちらにも取られる。掛けないことと理由（2打目が「はじめる」を押すのは意図のとおりで、窓を掛けるとそれを捨てる・着地が第1の組から離す）を書き、2打目が「はじめる」を押して1問目に移ったときは、その押しが窓を開く（`detail >= 1` の click が「はじめる」を切り替えた）ことも書くこと。

### 5. 測りの合否で、決め直さなかった所の線と、走らせる範囲が定まっていない

- 条件7 の合否のうち、守りを掛けない切り替わりの線（診断の答え→次の問の間隔ごとの数の記録、知識クイズの答え→答えたあとの「次へ」を含む第1の組 0、「もう一度挑戦する」のあとの第1の組 0（「はじめる」を除く））が、そのまま残るのかが書かれていない。「直すもの」で条件7 を書き直すときに落ちないよう、残ることを書く。
- 窓の中の回の範囲: 「3つの切り替わりを、タッチとマウスで 0・90・150・300・500ms」の画面と本と問（知識クイズの「次へ」は9問すべてか、条件7 の「全問を最初の行と最後の行で解き切る」走査の中で押すのか。いまの条件7 は「次へ」を 90・300ms でしか押さない）を書く。
- D5 を 900ms で走らせるのは、守りを掛けた3つだけか、診断の答え→次の問の D5（いまは 90・300ms で、窓が無いので2打目の位置と次の問に落ちる数を見る走査）も 900ms にするのかが読み分けられない。後者は 90・300ms のままでないと B-620 の材料が取れない。
- 指摘1 で距離で絞るなら、窓の中の D5 の走査（ずれた2打目を受けないこと）を合否に入れる。

### 6. 数えるイベントの決めごとが、実装と T10 の線引きに渡せる程度に定まっていない

「窓の中で受けなかった click を、切り替わりの種類ごとに GA のイベントで数える（受けなかった数と、そのあと 3 秒以内に同じものが押されたか）」は、次が決まっていないので実装できず、T10 が線を引く数にもならない。

- 「同じもの」が何か（選択肢の id、リンクの `href`、同じ DOM の要素、同じ点の近く）。結果の画面のリンクと共有のボタンでの扱い。
- 3 秒の起点（受けなかった押しの時刻か、窓の終わりか）と、時刻の取り方（`event.timeStamp`）。
- 偶然の一致をどう分けるか。二度押しを正しく受けなかったあと、来訪者が1問目を読んで、たまたま同じ選択肢を選ぶことがある（2打目の点は1問目のどこかの選択肢の上にあることが多い）。害（押したのに効かなかったので押し直した）と見分けるには、たとえば押し直しまでの時間の分布を送るか、受けた押しのうち同じ選択肢が選ばれた割合を比べの基準に取るかを決める。
- 1つの窓で複数受けなかったとき（マウスの3連打など）に何回送るか、イベントの名前と引数。

### 7. 読み上げの起動が `detail === 0` で届くことは推論で、決定はそれを事実として書いている

knowledge §3 は、TalkBack・VoiceOver の起動が `element.click()` と同じ合成 click として届くことを「推論にとどまる」と書いている。決定は「キーボードと読み上げの起動（`detail === 0`）で切り替えたときは開かない」と事実として書く。推論が外れて読み上げの起動が `detail >= 1` で届くと、読み上げで「はじめる」を起動したあと 700ms のあいだの次の起動が捨てられる。読み上げの来訪者は見出しから選択肢へ身ぶりで移るので、700ms に収まる見込みは小さく、倒れる向きは「摩擦が残る」側だが、それを推論として書き、(iii)（t5a-design.md 8章）のどれで扱うか（見張るか、見張らずに受け入れるか）を書くこと。

### 8. 窓の境目にかかる押しと、受けなかった押しの見え方が決まっていない

- 押し下げが窓の中で、離しが窓の外の押し（マウスで 650ms に押し下げて 720ms に離すなど）では、`mousedown` は止まり（フォーカスが移らない）、`click` は通って答えが入る。click を自分の時刻で決めるのか、対の `mousedown`（か `pointerdown`）の時刻で決めるのかを書く。対の押し下げで決めれば、1つの押しが半分だけ止まる形にならない。
- 受けなかった押しでも、押し下げで hover・active の線（DESIGN.md §6「押せる範囲の内側に細いボーダーが現れる」）は出る見込みが高い。決定は「見た目は何も変えない」と書くが、来訪者から見ると「押した形が一瞬出たのに何も起きない」になる。出ることを確かめ、受け入れるか止めるかを書く（受け入れるなら、意図した押しの来訪者が押し直しに気づく手がかりになる、などの理由で）。

### 9. 直す文の一覧に `docs/backlog.md` の B-620 が無い

B-620 の行は「T5a-7の二度打ちの測りとB-613の出荷を材料に判断」「cycle-301の修正は600msの無言棄却等で正味マイナスでrevert」と書き、時間の窓を入れない前提で判断を先に送っている。この決定は、その前提を3つの切り替わりで覆し、B-620 の一部（「はじめる」・知識クイズの「次へ」・結果への切り替わりの2打目）を決める。残るのは指摘3 の診断の答え→次の問の件である。B-620 の行を、決めた所と残る所に合わせて直すことを「直すもの」に入れること。

## 確かめた事実

- Android の `ViewConfiguration` の `DOUBLE_TAP_TIMEOUT` 300ms・`DOUBLE_TAP_SLOP` 100、Windows のダブルクリックの既定 500ms は、決定の引用のとおり。
- 寄せる範囲が面の半辺（10〜16px）までであることは knowledge §8、2打目の `click` の座標が寄せたあとの点で1打目から 9px のずれだったことは t5a-measure.md 10-1 にある（指摘1 の根拠）。
- landing-options.md 3 の「character-personality の 375×550」の項と 2-2 の 320×550 の「ほぼ外れる」は指摘2 の根拠。
- t5a-design.md 4-9 の「診断の答えのあとは、次の問の選択肢を避けない」の項の最後と 6章 条件7 の合否は、診断の答え→次の問の2打目が次の問に落ちる件を B-620 の材料として数えると決めている（指摘3 の根拠）。
- `QuizContainer.tsx` の切り替わりの `useLayoutEffect` は「もう一度挑戦する」のあとの「はじめる」を避けない（`exclude: start`）。決定の3つの切り替わりにも掛けない一覧にも、この切り替わりは無い（指摘4 の根拠）。
- `docs/backlog.md` の B-620 の行は、時間の窓を入れない前提のままである（指摘9 の根拠）。
