## 指摘にしないが書いておくこと

- `pointerup` も `pointercancel` も届かないまま残った押しは、`hasStoppedWaiting` が離しの時刻を見るので、並びから外れない。後の押しの `click` を結んだ時に、その前の押しとして外れるまで残る。Chromium のマウスは番号がいつも 1 なので、残った押しが守りの中で受けない押しになっていると、次のマウスの `click` が番号でそれに結ばれて止まる。ただ、ブラウザは押しを `pointerup` か `pointercancel`（引いて送り・押したものの引き寄せの始まり）で必ず閉じる。クイズの面でこれが起きる操作は見つからなかった。起きる操作が見つかったら、同じ型と番号の押し下げが次に届いた時に、前の押しを外す形を考えるとよい。
- 番号で結べる `click` に同じ番号の押しが並びに2つあるときは、いちばん古い押しに結ぶ（決めごとのとおり）。点で選ぶ経路と違い、受ける押しを先に選ばない。そうなるのはペンだけで、Chromium の hover を持つペンは `click` を受けない押しが次の押し下げで外れ、hover を持たないペンは押しが `click` か `pointercancel` で閉じるので、残った押しと並ぶ組は Chromium では起きない。iPad のペンの `click` の型と番号は確かめられていない（knowledge §9）ので、確かめられたら見直すとよい。
- 前回までの変異 12（`click` の番号を `pointerType` を見ずに使う）を試験で捕まえられないことは、前回と同じである。
- 前回までの「`chooseTouchClearLanding` の `isClear(0) ? 0 : nearestClear` は `nearestClear` と同じ値」は、範囲に 0 が入るときだけ正しい。送れる範囲の上端が負（切り替わりでページが縮んだとき）だと 0 は範囲の外になり、この形は `chooseLanding` の基準が送らない枝（`isUnder(…, 0)` を範囲を見ずに見る）と同じ扱いになる。決めごとの「送らない枝は基準で両方の組から 16 以上なら送らない」のとおりで、直すものではない。
