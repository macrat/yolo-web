## 指摘

### 指摘1（中）: タッチの調整について、判断の段で要る記録が足りず、実際の端末との関係も書かれていない

Chromium のタッチの調整は、触れた面の大きさを、どの環境でも 20〜32 dip の幅に収めてから近くの押せるものを探す（`third_party/blink/renderer/core/page/touch_adjustment.cc` の `kMinAdjustmentSizeDip(20)`・`kMaxAdjustmentSizeDip(32)`。「Unified Touch adjustment」の Intent to Ship は6つの Blink の環境すべてで有効と書く）。道具は CDP の `touchPoints` に大きさを渡さない（既定は 1）ので、いちばん小さい 20 dip（点から約 10px）で調整される。レビューで同じ点を大きさを変えて押すと、1280×800 の kanji-level と impossible-advice では、`radiusX/Y` が 1・5・10 で 6px、16・24 で 9px 寄った（word-sense-personality は着地が 0 のままで、どの大きさでも字に落ちた）。実際の Android の Chrome は指の面の大きさを渡すので、上限の 32 dip（点から約 16px）までの所に選択肢があれば寄りうる。iOS の Safari は WebKit の別の調整を持つが、このコンテナでは測れない（推論）。

このため、試しの走りの 16/45 は、端末で起きることの下限に近い近似である。いまの着地の関数は送るときに「真下から外れる、基準にいちばん近い送り」を選ぶので、点が選択肢の縁から 1px の所に来ることが多く、調整の届く距離の中に選択肢が残る。判断の段（plan-t5a7.md 5）では、この件を条件7 の「避けられたのに落ちた件」に数えるか、着地の関数の直し（避けるものから距離を取る）で扱うかを決めることになる。ところが、いまの記録からはそれを決められない。

- 押しごとの記録に、選んだ着地での、点から最も近い第1の組と次の問の選択肢までの距離が無い（`summarizeLanding` は矩形の数 `nFirst`・`nNext` しか残さず、矩形そのものも残さない）。そのため「範囲の中に、選択肢から 10px・16px 離せる送りがあったか」を後から数え直せない。
- t5a-measure.md 0章の「落ちた座標」は「送った点と `click` の座標の両方を見る」とだけ書き、数え方を決めていない。

直し方の例: (a) `summarizeLanding` で、選んだ着地での `distanceToNearest` に当たる2つの距離と、範囲の中に第1の組と選択肢のどちらからも 10px と 16px 以上離せる送りがあったかの真偽を記録する。(b) 0章に、Chromium の調整の幅（20〜32 dip。道具の押しはいちばん小さい幅で調整される）、端末ではそれより遠くまで寄りうること、iOS は測れないこと、を書き、判断の段がこの件をどう数えるかを書く場所（plan-t5a7.md 5）を名指す。(c) 触れた面の大きさを渡す回（例: `radiusX/Y` 16）を条件7 の一部として足すかどうかを、PM が plan-t5a7.md 3 で決める材料として 10章に書く。device-triage.md D5 の (ii) は「指のずれ」の近似で、ずれた点もこの調整を受けるので、D5 の数は「ずれ＋いちばん小さい幅の調整」の値になる。このことも 0章か 10章に書いてほしい。

### 指摘2（中）: 条件7 の「語の選択の測り」の対（見出しの字の上のダブルクリックで語が選ばれること）を測る操作が無い

t5a-design.md 6章 条件7 は、語の選択の測りの対として「問の見出しの字の上で1打目から始めたダブルクリックでは語が選ばれることを確かめる（守りが字を選べなくしていないこと）」を求める。`measure.mjs` の操作は `start`・`answers`・`last`・`retry` の4つで、この対を測る操作が無く、README と t5a-measure.md 10章にも、この対の扱いと見積もりが無い。道具に操作を足すか、別の道具で測ると決めてその置き場を書く。

### 指摘3（中）: 指紋やブラウザが合わないときに、plan-t5a7.md 3 の手順どおりに続けられない

`ensureVersionLine` は、木・Node・npm・ブラウザ・道具の blob・チャンクの一覧のどれかが合わないと止まり、続ける道が無い。plan-t5a7.md 3 は「木が合いチャンクが違えば…違うチャンクが診断のページのコードを含まなければ続け、含めばそのチャンクが掛かる操作を測り直す」と定めるが、道具ではそれができない（同じ `.jsonl` に版の行が1つしか無く、別の版の行を持つファイルに分けて続ける形も決まっていない）。また、ブラウザの版と道具の blob が違ったときの扱いは plan-t5a7.md 3 にも README にも無い。このコンテナのブラウザは cycle-316 から cycle-320 のあいだに 1194 から 1243 に替わっており、数日に分けて測るあいだに替わることは十分ありうる。

直し方の例: 続きを別のファイル（新しい版の行を持つ）に書く形と、ファイルをまたいで回の記録を突き合わせる形を決め、README に書く。ブラウザと道具の blob が違ったときにどの範囲を測り直すかは、PM が plan-t5a7.md 3 に書く（担当には書けないので、PM への申し送りとして報告に入れる）。`compare` は、記録の `.jsonl` の版の行を直に読めるようにする（いまは手で版の行を別のファイルに書き出す必要があり、README にもその手順が無い）。

### 指摘4（中）: 誤りで終わった回が、印だけ付いて「測り終えた」扱いになる

誤り（`error`）の回は、間隔を越えた回と同じ3度の上限を数え、4度目も誤りなら `final: true`・`exhausted: ["error"]` の行になって、続きを測るときに飛ばされる。押しの記録の無い回が、測り終えた回として静かに残る。plan-t5a7.md 3 は、画面・入力・間隔・刻みを変えず、粗くしないと定めており、抜けた回は数の欠けになる。誤りは間隔を越えた回とは性質が違う（道具か環境の不具合）ので、上限を別にして `final` にしないか、少なくとも誤りで終わった回の数を走らせ終えたときに出し、README に「誤りで終わった回は測り直す」と書く。

### 指摘5（中）: 3 の記録の上限に合わせて記録を絞る形が道具に無い

10-2 の見積もりでは、押しごとの記録のまま置くと版ごとに 22〜30MB、絞っても 7〜8MB で、plan-t5a7.md 3 の1ファイル 1MB・合計 3MB を大きく超える。3 の決まりでは、そのときは「走査ごとの要約だけを置き、押しごとの記録は置かない」ことになりうる。いまの道具は、全部の欄を1つの `--out` に書く形しか持たず、絞った欄だけを書く形、要約を書く形、1MB を超えないよう分ける形のどれも無い。README は「走査ごとの記録（`.jsonl`）を置く」と書く。

PM が 3 で形を決めたあと、道具はその形を書けるように直す必要があり、直すと道具の blob が変わる。測りを始める前に直すことになるので、3 の決定と道具の直しを同じ流れで行い、直した道具をレビューに通す段取りを PM が組む（要約だけを置くなら、生の記録をどこに置き、`measure/` の要約がそこからどう作られたかを確かめ直せるようにするかも、README の「ここに置く理由」の文と合わせて決める）。

### 指摘6（低）: `last` の回で、着いた結果が答えの組の結果かを確かめていない

extra を持つ3本は、答えの組で決めた結果に着くことで「全結果」を測るが、記録の `resultId` は組の側の id を写すだけで、ページで実際に着いた結果を読んでいない。途中の1度ずつの押しが別の行に落ちれば（タッチの調整を含む）、別の結果に着いたまま、組の結果を測ったことになる。結果の名前の字（または結果のページの道）を記録し、組の結果と合うかを確かめる。

### 指摘7（低）: 着地の関数の形が見つからなくても、変更後の版で何も言わずに進む

`LANDING_PATTERN` がチャンクに見つからないと止め所が置かれず、`landings` が空のまま記録が続く。最小化の出力が変われば（T5a-8 の測り直しの版など）、着地の記録だけが黙って欠ける。止め所を置けたかを版の行か回の行に残し、着地の関数を持つはずの版で置けなければ止まるようにする。

### 指摘8（低）: 走査の中のマウスの押しで `detail` が 2 でないものに印が無い

`needsResend` は `answers` の操作では何も返さないので、走査の中のマウスの押しで2打目の `mousedown` の `detail` が 2 でないものには、語の選択の数から外す印が付かない（`md2` は残るので後から外せる）。plan-t5a7.md 4 は越えた押しに印を付けると定めるので、`detail` にも同じ形の印を付けるか、README の記録の形に「語の選択の数は `md2` が 2 の押しだけで数える」と書く。
