## 指摘

### 1. 基準の版で測るものの列挙から 5-2（答え・「次へ」）が落ちている（中）

作業内容 3 の「基準の版で測るもの」は「合わない操作と、5-1・5-4 に無い操作（5-3 の最後の問と D5 の走査）だけを基準の版で測る」と書く。5-2 の答え・「次へ」の走査も 5-1・5-4 に無い操作だが、括弧の列挙に入っていない。括弧を列挙として読む担当と PM は、基準の版の 5-2 の 720走査を測らずに分け方の表を作りうる。t5a-measure.md 5-2 は「比べる先は、T5a-7 が基準の版で、この節の全ての走査…を測り直した値にする」と定め、B-620 の材料（次の問に答えが入った割合の基準の版と変更後の版の比べ）と B-623 の変更前の値はこの走査から出る。落とせば、このサイクルの比べの柱の1つが欠ける。

改稿で入った欠け（AP-WF41）である。括弧を「5-2 の答え・「次へ」、5-3 の最後の問、D5 の走査」にする。あわせて、作業内容 4 の条件7 の箇条の「6章の…すべてを測る」に「基準の版は 3 で決めた範囲」を添え、3 と 4 が食い違って読めないようにする。

### 2. 「収まらないとき」の (a) が自分と食い違い、来訪者の重みを本ごとに見ず、(b) は件の出た画面を送る（中）

使われる見込みが大きい道なので（「確かめたこと」の算術）、中身を見た。

- **食い違い**: (a) は「cycle-319 で件が出た操作（「はじめる」・「もう一度挑戦する」）は設計の密度のまま測り」と書いたすぐあとに「ほかの画面と入力の「もう一度挑戦する」の掃きの刻みを…48px に粗くする」と書く。「もう一度挑戦する」を密度のまま残すのか粗くするのか、残すなら 375×550 のタッチだけか全画面かが読めない。
- **(b) が送るのは件の出た画面**: cycle-319 のキャリーオーバーの「もう一度挑戦する」の件は、kanji-level を 375×550 と 1280×800 で押したもので、1280×800 では `scrollY` 236 でパンくずと h1 が画面の外に出た。(b) はその 1280×800 を次のサイクルへ送る。送れば、そこで外れが出たときに直しと測り直しが2回に分かれ、計画が「cycle-319 で分かっている件だけを先に測る」案を退けた理由（直しが2回になる）に当たる。送るなら、件の出た kanji-level の 1280×800 は残す、などの手当てが要る。
- **重みを本ごとに見ていない**: 計画の目的の段落は、プレイ面の閲覧の 85.8% が character-personality だと書く。画面の重み（82.3% がスマートフォン）は (a) に入っているが、本の重みが入っていない。どの画面でも character-personality（と件の出た本）は 24px のまま残し、ほかの本から粗くする道のほうが、同じ時間で来訪者の多くが通る所の密度を保てる（AP-P33: 母集団の不均質を見ずに一律の規則を掛けない）。
- **48px の根拠**: 押せるものの高さは 44px から（`Button` の最小の高さ）で、刻みを 48px にすると、高さ 44〜47 の `summary` やボタンを1点も踏まずに通り過ぎうる。24px はどの押せるものも少なくとも1点で踏む刻みとして読める。24時間の線も出どころが書かれていない（AP-P01）。48px にするなら、踏み落としが起きうることを書いて受け入れるか、ずらした2列（24px ずらしの奇数番だけ）のような踏み落とさない間引きを選ぶ。24時間は、このサイクルに測りを何人分まで置けるか（担当1人4時間 × 6人）から来ると1文で書く。
- **それでも超えるとき**: (b) のあとにも超えるときの道が無い。PM がその場で決めるなら、そう書く（例: 分け方を見直して作業内容 3 のレビューに戻す）。

### 3. 5-1・5-4 の値と「合う」の物差しが無く、基準の版を替えたときの扱いが書かれていない（中）

作業内容 3 は、新しい道具で基準の版を数本走らせて 5-1・5-4 と「合えば」その値を使うとする。何をもって合うとするかが無い。5-1 は本ごとの落ちた先の区分（選択肢か字か）で比べられるが、5-4 は t5a-measure.md 自身が「点ごとの一致 216/252。結果が回ごとに違いページの長さが変わるための差」と書くとおり、走らせるたびに結果とページの長さが変わり、点ごとには合わない。物差しが無いと、担当か PM がその場で線を引き、最も重い項目（基準の版の「もう一度挑戦する」）を測り直すかがそこで決まる。

「合う」を、5-1 は本・画面ごとの落ちた先の区分が同じ、5-4 は同じ結果に固定した回（`Math.random` を固定するなど）で点ごとに同じ、または画面ごとの第1の組の割合の差が何ポイント以内、のように決めて書く。

あわせて、作業内容 2 の 0章の確かめで基準の版を直前の版に替えたときは、5-1・5-4 は古い基準の版の値で使えず、基準の版の条件7 をすべて測ることになる。前回の指摘2 が求めたこの1文がまだ無い。見積もりの合計も大きく変わるので、作業内容 3 の「基準の版で測るもの」に書く。

### 4. T5a-8 の測り直しが1人の担当で、作業内容 3 の分け方が掛からない（中）

作業内容 6 の測り直しは「新しい測りの担当が…測る」と1人で書き、範囲は 5 で決めた範囲（全本・全画面）とする。`reveal.ts` の着地の関数を変える直しなら、範囲はその関数を呼ぶ操作のすべてで、変更後の版の条件7・D5 のほぼ全体（見積もりでは十数時間）になる。作業内容 3 は担当1人を4時間・表1つと決めたが、T5a-8 の測り直しにはその物差しが掛からず、cycle-316 の T5a-2 の打ち切り（担当の負荷）と同じ形がここで起きうる。測り直しも作業内容 3 の物差しで担当を分け、範囲と分け方を 5 の判断のレビューで見る、と書く。作業内容 3 の「収まらないとき」の (a)(b) で粗くした刻みを測り直しでも使うかも書く。

### 5. index.md が 40,000 バイトの上限に近く、作業内容 3 の表と申し送りを書く場所が無い（中）

index.md はいま 37,219 バイトである。作業内容 3 は分け方の表を「ここに書いて」とし、作業内容 7 は申し送りに10の項目を書く。どちらを足しても 40,000（`.claude/rules/doc-directory.md`。後続のサイクルが Read 1回で全文を読むための線）を超える見込みが大きく、50,000 を超えるとコミットの前の検査で止まる。作業内容 3 の表と見積もり、作業内容 5 の件ごとの判断の要約などは同じディレクトリの別のファイル（例: `measure-plan.md`）に書いて index.md には1行の要約とリンクを残す、と計画に書く。レビュー結果の段落も回を重ねるごとに伸びているので、経過は review-plan-*.md に任せて短くできる。

### 6. 「切れる見出し」の数え方が、h1 が丸ごと画面の上に外れた件と、2行目より下が切られた件を拾わない（中）

作業内容 4 は「`h1` か問の見出し（`h2`）の1行目の行の箱を画面の上端が横切っている」ものを数える。cycle-319 のキャリーオーバーの件のうち、kanji-level の 1280×800 の「もう一度挑戦する」（`scrollY` 236。パンくずと h1 が画面の外）は、h1 が丸ごと上に外れており、この数え方では 0 になる。4-8・4-9 の「もう一度挑戦する」のあとは「ページの頭から見せる」ことを守る形で、来訪者には、何のページか分からないまま開始の画面の途中を見る、切れるより重い件である。また、2行の h1 の1行目が丸ごと上に外れて2行目を上端が横切る件も、1行目を見るだけでは拾えない。

「見出しのどれかの行を上端が横切る」件と、「開始の画面で h1 が丸ごと画面の上にある」件を分けて数える、と書く。作業内容 5 の判断（第2の組を外す・行の切れ目にそろえる・そのまま）もこの2つを材料にする。

### 7. T5a-7a-1 が組むものが作業内容 3 に散っている（軽）

途中から再開できる道具と、`.jsonl` が `format:check` に掛からないことの確かめは、作業内容 3 に「T5a-7a-1 が組む」「T5a-7a-1 が確かめる」と書かれ、T5a-7a-1 の箇条（作業内容 2）に無い。担当は作業内容 2 を自分の仕事として読むので、落としうる。記録を `.jsonl` で書くこと（作業内容 3 の決定）も、道具を組む作業内容 2 の時点で要る。作業内容 2 の箇条に移すか、作業内容 2 から 3 を名指す。

### 8. 間隔の境の決まりの掛かる範囲と、送り直しの上限が無い（軽）

作業内容 4 の「間隔」の箇条は 90ms と 300ms だけを書く。「はじめる」と最後の答え・最後の「次へ」の 0・150・500ms（150ms は見せる間の境そのもの）をどう扱うか、基準の版（見せる間を持たない）にも同じ送り直しを掛けるか（掛けないと版の比べで間隔の束がそろわない）が無い。負荷が高いときに送り直しが続く回の上限（例: 3回で止めて記録する）も無い。

### 9. 設計の文を直す builder のポート（軽）

作業内容 6 の設計の文を直す builder（文書だけを書く）にポート 3102 を渡すが、サーバーを起こす仕事が無い。害は無いが、担当がサーバーを起こすべきかで迷いうる。要らないなら外す。
