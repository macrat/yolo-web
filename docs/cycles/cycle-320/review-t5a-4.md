## 依頼の4点

### 1. `PhrasedText` の書き換え

描く DOM は同じと確かめた。builder の基準の版のビルド（担当の木の `tmp/cycle-320/t5a4/base/`。`src/` は 46114389 と同じことを確かめた）と変更後のビルドで、前もって描かれた HTML の全 3,378 ページ（トップ・`/blog` と記事 121・辞典 3,130・道具 36・結果のページ 72 などを含む）を比べた。`<script>`・`<link>`・チャンクの名前・CSS モジュールの名前の揺れを外すと、違いは属性の並び（`class` が `id` などの後ろへ移る）だけで、属性を並べ替えて比べると 3,378 ページすべてが一致した。診断のページは要求ごとに描くので比べの外だが、撮り比べと試験が見ている。

設計の外のファイルを変えたことは妥当と判断する。4-10 は「見出しを `PhrasedText`（`as="h2"`）で組む」と決め、4-7 はその見出しにフォーカスを移す（`headingRef`）ので、`PhrasedText` が ref を受けることは設計がすでに要っていたことで、7章の触るファイルの表がそれを書き落としていた。React 19 では ref は props として渡り、変えたのは型（`ComponentPropsWithRef`）と、型の和を通すための `createElement` だけで、DOM と見え方は変わらない。設計の表から外れたことは、PM がこのサイクルの記録に書く（指摘5）。

### 2. 「今日／一日を」の折れ

直すべきと判断する。しかも、同じ根から出る語の中の折れがほかに2つあり、こちらは DESIGN.md §4 にはっきり外れる（指摘1）。

- 「今日一日を」は1つの文節である（「今日一日をね」とは言えても「今日ね、一日をね」とは言わない）。§4 の「見出しは文節で折る。文節が1行に収まらないときだけ、その文節の中で折る」に照らすと、375 の既定で収まる文節の中で折れている。前の版は「、」の後ろで折れていて、この変更で悪くなった。375×550 は来訪者の多くが使う画面で、character-personality の Q1 は解く人がみな見る。
- BudouX は「今日|一日を」と分け、`Intl.Segmenter` も「今日|一日」と2語に分けるので、`splitIntoPhrases` の語の中の境目を外す処理（`isInsideWord`）は外さない。条件8 の数え方（スキルの「見出しとコントロールの名前の折り方を測る」）も、`<wbr>` の所の折れを「折り所での折れ」と数えるので、T5a-7 の測りではこの折れは見つからない。

直す形は、`DEFAULT_READING_HEADING_PHRASES` の先例（文ごとに区切りを書いて引く表）は合わないと判断する。あの表はコードに書いた決まった文の区切りを書き手が持つもので、スキルは「データから来る文（…診断の選択肢…）は `splitIntoPhrases` が分ける」と決めている。文ごとの表を作れば、決まりの外の例外になり、同じ語がほかの見出しに出れば同じ折れがまた出る（AP-I02）。合うのは、`splitIntoPhrases` が語を決めるのに使う語の辞書を補う形で、指摘1の推奨に書く。

## 指摘

### 指摘1（重大）: 区切りが語と文節の中に折り所を置き、測りでも見つからない

上の 2 の表の3つ（「今日／一日を」「超／能力」「基本省／エネ」）は、どれも 1行に収まる文節や語の中で折れ、§4 と、スキルの「どの折り所も語の中には置かない」から外れる。「超／能力」と「基本省／エネ」は語そのものを割り、「基本省」は別の語に読める。根は2つある。

- **「基本省|エネ」は `splitIntoPhrases` の誤り。** BudouX は「基本省エネだけど、」を1つの文節にしている。最初の文節に字の種類が変わる所の折り所を足す `splitFirstPhraseAtWords` が、片仮名に移る所で分けている。`Intl.Segmenter` は「基本|省エネ」と分けていて、`refineAtWords` なら語の中として外す位置だが、`splitFirstPhraseAtWords` は語の中かを見ない。785 本のうち、語の辞書の語の中に区切りが落ちるのはこの1つだった。決まりを変えずに直せる。
- **「1つだけ超|能力が」と「今日|一日を」は BudouX の境目で、`Intl.Segmenter` も割る語（複合の語）。** いまの作りでは語の中だと分からない。

この区切りで T5a-4 を取り込めば、T5a-7a の条件7・D5 の測りは、この折れのままの選択肢の行の高さで測ることになる。あとで折れを直せば行の数が変わり、着地の位置が動いて測り直しが要る。T5a-7 の条件8 の数え方も、上のとおりこの折れを見つけられない。そこで、T5a-7a-1 が変更後の版を決める前に直す。

推奨する形:

1. `splitFirstPhraseAtWords` が足す折り所から、`isInsideWord` で語の中に落ちる位置を外す（決まりは変わらない）。
2. `Intl.Segmenter` が割る複合の語を1つの語として扱う「語の辞書の補い」を `src/lib/word-starts.ts` か `phrase-breaks.ts` に持ち、`isInsideWord` と `wordStartsOf`（測りが使う語の頭）の両方がそれを使う。欧文の組版で、分綴の辞書が誤る語を例外の表で補うのと同じ考え方で、文ごとではなく語ごとに持つので、同じ語がサイトのどこに出ても同じに組める。入れる語は、上の5つ（超能力・今日一日・省エネ・自分自身。四字熟語は語として入れる）を起点に、全15本の約50か所を人が読んで決める。
3. 2 は §4 の「語の切れ目は、語の辞書（`Intl.Segmenter`）が分ける語の境目で決める」とスキルの区切りの項の文を変えるので、cycle-320 の作業内容 6 と同じく、builder が設計の文（DESIGN.md §4・スキル・t5a-design.md 4-10 と条件8 の語の頭の言い方）を先に直してレビューに通し、そのあとコードを直す。
4. `phrase-breaks.ts` はサイトの全体の見出しを組むので、直したあとに前もって描かれた全ページの HTML を前と後で比べ、変わった見出しをすべて挙げて、それぞれ語を割らなくなったことを確かめる（属性の並びと揺れる名前を外して比べる道具は、このレビューで作った手順と同じでよい）。

### 指摘2（軽）: 全角の空白で始まる文節

全角の空白（U+3000）で始まる区切りが 17 本にある（「すごく嬉しいことがあった！　最初のリアクションは？」が「あった！」「　最初の」と分かれる、など）。Chromium は行末の全角の空白をぶら下げて空白の後ろで折るので、測った画面で行頭に空白は出なかった。ただ、`<wbr>` は空白の前にあり、そこで折る組み方では行頭に全角1字の空きが出る。空白を前の文節の終わりに付ければ、どのエンジンでもこの空きは出ない。指摘1 の `phrase-breaks.ts` の直しと一緒に、全角の空白を前の文節に付けるようにする（§4 の「空白の前後で折れても読める」とも合う）。

### 指摘3（軽）: CSS の説明の「（§12）」が何の §12 か読み違える

`src/app/play/[slug]/page.module.css` の説明は「（Pointer Events 3 §8.2）」の直後に「指でつまむ拡大は残る（§12）」と書く。前の文の出典に続くので、Pointer Events の §12 に読める。指すのは DESIGN.md §12 なので「（DESIGN.md §12）」と書く。

### 指摘4（軽・PM）: 条件8 の測りに、`<wbr>` の所の折れを読む手順を足す

指摘1 の直しのあとも、`Intl.Segmenter` と補いの辞書に無い複合の語は同じ形で割れうる。スキルの数え方は `<wbr>` の所の折れをすべて「折り所での折れ」とするので、T5a-7 の条件8 では、漢字・片仮名どうしが接する `<wbr>` で実際に折れた所を挙げて人が読み、語や文節を割っていないかを見る項を足す。
