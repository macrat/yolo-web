## 指摘

### 1. 「削らないもの」が、基準の版で既に件が出た画面（B-623 の `summary`、375×800 で離れる件）を含まず、B-623 を閉じる作業と食い違いうる（中）

plan-t5a7.md 3 の「このサイクルに収まらないとき」は、削らないものを「375×550 のタッチ、character-personality、cycle-319 で件が出た操作と画面」とし、「次のサイクルへ送るのは、件が出ていない画面と入力だけ」とする。ところが、来訪者に重い件のうち次の2つは、cycle-319 ではなく t5a-measure.md 5章（基準の版）で出たもので、この物差しでは送ってよいものとして読める。

- **B-623**（知識クイズの「次へ」の2打目が FAQ の `summary` を叩く）: 5-2 で 320×550 が 176/216、375×800 が 208/216、375×550 の 200% が 142/216、375×550 のマウスも同じ表に入る。どれも「375×550 のタッチ」でも character-personality でもないので、知識クイズの答え・「次へ」の 320×550 や 375×800 を送れる。送れば、index.md の「実施する作業」の「B-623 を Done に移す（条件7 と D5 の走査のどちらでも…0 と確かめたあと）」がこのサイクルで閉じられず、計画の中で食い違う。device-triage.md D9 は B-623 を条件7 と D5 の走査で閉じると決めている。
- **375×800 の最後の「次へ」**: 5-3 で kanji-level・kotowaza-level・yoji-level の2打目がどの間隔でもリンクに落ちてページを離れた（32/150。T5-5b からの件）。離れるのは 5-2 が「来訪者にいちばん重い結果」と書く害で、375×800 は削らないものに入っていない。

どちらも「件が出ていない画面」の「件」を、どの測りで出た件と読むかで扱いが分かれる。担当（PM）がその場で読み方を決めることになり、迷う。直し方の例: 削らないものに「t5a-measure.md 5章（基準の版）で第1の組に落ちた件か離れた件が出た操作と画面（5-2 の知識クイズの「次へ」の各画面、5-3 の 375×800 など）」を足すか、少なくとも「B-623 の操作（知識クイズの「次へ」）は全画面を残す」と書く。送るものの側でも「件」が cycle-319 と t5a-measure.md 5章の両方を指すと書く。

### 2. 「このサイクルで走らせられる量」に物差しが無い（軽）

24時間を外したことで、削る道に入るかどうかの線が「このサイクルで走らせられる量」だけになった。刻みと画面の数には「出どころを書く」とあるが、この量には無い。作業内容 3 の決定で、その量（例: 何人の担当 × 4時間で、なぜその人数か）と出どころも書く、と1文足すと、3 のレビューが同じ物差しで見られる。

### 3. 基準の版の「もう一度挑戦する」をどの方法で測るかが書かれていない（軽）

plan-t5a7.md 3 は「条件7 と D5 の操作のすべてを、基準の版でも新しい道具で測る」とする。t5a-measure.md 5-4 は、押したあとに送らない基準の版では、各位置の `elementFromPoint` の走査が間隔ごとの二度押しの代わりになる（その版でだけ成り立つ）と書き、t5a-design.md 6章 条件7 は各位置で 90・300ms の実際の二度押しと定める。どちらで測るかで、条件7 でいちばん重い操作の基準の版の押しの数が約4倍違い、見積もりと分け方が変わる。また、理由の文の「5-1・5-4 の値は回ごとに結果が変わる走査」は、5-1 には当たらない（基準の版は送らず、5-1 の2打目はどの間隔でも同じ所に落ちた）。測り直す理由は「新しい道具と同じ手順・同じ記録の欄でそろえるため（5-1 は 200% のマウスを測り残し、5-2・5-3 は測り直しを定める）」のほうが合う。方法を T5a-7a-1 の見積もりで両方出させて 3 で決める形でもよいので、どちらかを書く。

### 4. T5a-8 の測り直しで、3 で決めた刻みと範囲を使うこと、並行させないことが書かれていない（軽）

plan-t5a7.md 6 の測り直しは「3 の物差しで担当を分け」とするが、3 で刻みを粗くしたり画面を送ったりしたとき、測り直しも同じ刻み・範囲で測ることが書かれていない（違えば、変更後の版の値と点ごとに比べられず、合否の「変更後の版の測りに無かった外れ」が決められない）。また、index.md の「T5a-7a は…並行させない」は T5a-8 の測り直しの担当に掛かるかが読めない（同じ t5a-measure.md・`measure/` に書き、ポート 3112 を使う）。「3 で決めた刻みと範囲のまま」「担当は並行させない」と書く。

### 5. index.md の移したあとの残り（軽）

- 46行目の「2〜7 の細目は plan-t5a7.md にある。」が、T5a-4 の完了の条件の最後の箇条（全試験…取り込む）の続きの段落として字下げされており、T5a-4 の条件の一部に読める。作業内容の冒頭の段落か、2 の前の独立した行に置く。
- 「実施する作業」の「測りの分け方と記録の上限を決める」が「この文書の作業内容に書いて」のままで、plan-t5a7.md 3 の「この節に書いてから」と食い違う。

### 6. 送り直しの上限と、語の選択の `detail` の送り直しの関係（軽）

plan-t5a7.md 4 の「間隔」は、境を越えた回の送り直しを3度までとする。t5a-design.md 6章 条件7 の語の選択の測りは、2打目の `detail` が 2 でない回を「数えずに送り直す」と定め、上限を持たない。同じ回が両方の理由で送り直しになるとき、3度の上限がどちらに掛かるか（`detail` の送り直しにも掛けるか）を書くと、担当が迷わない。
