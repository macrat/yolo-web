## 指摘

### 指摘1（中）: `accept` の行が、測る回の残るファイルに入らないまま新しいチャンクの回が足される

`checkFingerprint` は、`fingerprint.jsonl` の最後の行とチャンクが合えば `accepted: null` を返す（measure.mjs 307 行）。`--accept-chunks` で受け入れた呼び出しのあとは、最後の行が受け入れた指紋なので、次の呼び出しからは `accepted` がずっと null になる。`accept` の行は、受け入れた呼び出しの中で回を測り始めたファイルにしか書かれない。受け入れた呼び出しが、測る回の残っているファイルにたどり着く前に終われば（`--limit`、道具の停止、セッションの切れ、絞り込みの違い）、そのファイルには、あとの呼び出しで、新しいチャンクで測った回が `accept` の行なしで足される。頭の行の `chunksDigest` は古いチャンクのまま残る。

after の版をポート 3148 で起こし（`/proc/<PID>/cwd` が `tmp/measure-builds/after` を指すことを確かめ、終えたあとにグループのプロセスが 0 でポートが空いたことも確かめた）、`tmp/cycle-320/review13/hole/` で次のとおり確かめた。

1. `start` を 2本 × タッチ × 90ms で、375×550 と 1280×800 にそれぞれ `--limit 1` で1回ずつ測る（どちらのファイルも書きかけ）。
2. `fingerprint.jsonl` のチャンクの大きさを1つ書き換える。
3. 2つの画面を並べて `--accept-chunks "review: hole test" --limit 1` で測ると、375×550 に `accept` の行と1回が足される。
4. 同じコマンドをもう一度走らせると（`--limit` 無し）、1280×800 に animal-personality の回が足されたが、`accept` の行は無かった。

README の「確かめ直す」と plan-t5a7.md 3 の「`accept` の行も、測る回の残っているファイルにだけ、そこで測り始めるときに足す」は、この道筋では成り立たない。これは今回の書き直しの前（ファイルを開くときに書いていた形）からある穴だが、今回の変更の目的（続きの測りの道筋）の中にある。書きかけのファイルが2つ以上になるのは、誤りで残った回（`unresolved`）が複数のファイルにまたがったときや、絞り込みを替えて測ったときで、測りの途中で起きうる。害は、版をまたいだ回が記録の上で見分けられないことで、PM が「違うチャンクが掛かる操作を測り直す」と決める材料が欠ける。

あわせて、plan-t5a7.md 3 の「同じファイルの版が重なるのは、次の2つの道筋だけである」は、`--accept-chunks` のたびに `fingerprint.jsonl`（`.jsonl` なので履歴の数えに入る。1行約 5KB）の新しい版ができる道筋を数えていない。測り終えた組しかない置き場で受け入れても、この行は足される。大きさは小さいが、「だけ」と言い切る数え上げとしては欠けている（AP-WF09）。

直す向き: ファイルで回を測り始めるときに、そのファイルがいま持っているチャンク（頭の行の `chunksDigest`、`accept` の行があれば最後の `accept` の `chunksDigest`）と、いま続けている版の `digest` を比べる。違えば、`fingerprint.jsonl` の、その digest を持つ行の `decision` と `at` を使って `accept` の行を書く。こうすると、どの呼び出しで受け入れたかによらず、`accept` の行が要るファイルにだけ入る。plan-t5a7.md 3 の「2つの道筋だけ」には、`fingerprint.jsonl` の版が受け入れのたびに重なることを足す。道具を変えたら、上の手順（2つのファイルが書きかけのまま受け入れ、途中で止めて続ける）で確かめ、10-2 に書く。
