# T5a-7 の二度押しの測りの道具と記録

[t5a-design.md](../../cycle-316/t5a-design.md) 6章 条件7 と [cycle-318/device-triage.md](../../cycle-318/device-triage.md) D5 の二度押しの測りの道具と、その記録（`.jsonl`）を置く。手順の文は [t5a-measure.md](../../cycle-316/t5a-measure.md) 0章・5章にあり、合否は [decision-landing.md](../decision-landing.md) の「測りの合否（条件7・D5）」、着地の直しの害の確かめの突き合わせ方と害の線は [plan-t5a7.md](../plan-t5a7.md) 2b にある。道具はその文に沿って組んだ。

**状態**: この道具は、決め直した着地の作りに合わせる要件（[carryover.md](../carryover.md) の「測りの道具」の (1)(2)、decision-landing.md の「直すもの」の「測りの道具」と「測りの合否」）を持つ。測りに使うのは、道具のレビューを通した blob である。

## ここに置く理由

この道具と記録は、cycle-320 と次のサイクルの文書（t5a-measure.md の条件7・D5 の表、外れた件の判断、T5a-8 の測り直し）に書く数の出どころで、その数をセッションを越えて確かめ直すためのサイクルの記録である。主の木の `tmp/` はセッションを越えて残らず、別のブランチへの push はこのサイクルの作業ブランチの決まりに当たるので、`docs/cycles/cycle-320/measure/` にコミットする（[index.md](../index.md) の「検討した他の選択肢と判断理由」）。`.claude/rules/doc-directory.md` の「`docs/cycles/` にはサイクルドキュメント以外は保存しない」は、サイクルに属さないもの（計画書・調べものの結果・一般の文書）を置かせないための決まりと読む。ここの道具と記録はサイクルの外では使わないので、サイクルの記録の一部である。

- 道具は ESM の `.mjs` で、`npm run lint` と `npm run format:check` の対象になり、どちらも通す。
- 記録は `.jsonl` にする。Prettier は `.jsonl` の書式を知らず（`prettier --file-info` の `inferredParser` が `null`）、`prettier --check .` はディレクトリを広げるときに飛ばすので、道具が書いたままの1行1回の形が保てる。`.json` は対象になるので、記録には使わない（1行1回の形を持たない比べの出力だけを `.json` にし、コミットの前に `npm run format` で整える。下の上限の箇条）。
- 記録は、すべての回を回ごとの要約で置き、押しごとの記録は、変更後の版の判断（plan-t5a7.md 5）に要る回と、どちらの版でも誤りで終わった回だけを置く。判断が押しごとに読むのは変更後の版の件だけで、基準の版の数は比べるためのもの（要約から出す）なので、道具は着地の関数を持たない版（頭の行の `landing` が false）では、誤りで終わった回と、どの版でも PM が確かめる押し（下の「押しごとの記録」の `first-blocked`・`mismatch`）のほかの押しを置かない。誤りで終わった回の押しは、誤りの原因を確かめるために置く（続きの測りで測り終えた回を飛ばすかは、要約の行だけで決める）。ファイルは版（置き場）と操作と画面で分ける。置き方は plan-t5a7.md 3 の「記録の形と上限」のとおりである。
  - 木に残すのは、変更後の版と T5a-8 の版の置き場（要約と押しごとの記録）で、どの組と画面も、いま数に使う1つの置き場のファイルだけを残す。新しい置き場で組と画面を測り終えたら、同じ名の古い置き場のファイル（`<組>-<画面>.jsonl` と `<組>-<画面>.presses.jsonl`）を木から消す（履歴には残る）。記録のファイルが無くなった置き場は、`fingerprint.jsonl` も消す。版の指紋がファイルの置き場ごとにそろうよう、新しい置き場の記録を古い置き場に写さない。新しい置き場は次の2つで、どちらも名の末尾に回の番号を足す。
    - ブラウザの版か道具の blob が替わって組を測り直すとき（下の「確かめ直す」）: 同じ版の新しい置き場（`after` なら `after-2`、その次は `after-3`）に組のすべての画面を測り直し、測り終えたら古い置き場のその組のファイルを消す。
    - T5a-8 の測り直し: 1回目は T5a-8 の版の置き場 `t5a8` に測り、測り終えたら、測り直した組と画面の変更後の版の置き場（`after` か `after-2` など）のファイルを消す。外れが残って直しを重ねた2回目からは、版のコミットが替わって木のハッシュが違い、道具は `t5a8` では止まるので、回ごとに新しい置き場（`t5a8-2`、その次は `t5a8-3`）に測り、測り終えたら、測り直した組と画面の前の回までのファイル（`t5a8` と変更後の版の置き場のもの）を消す。
  - 基準の版の置き場（`base`）は、測りが日をまたいでも続きから測れるよう、測っているあいだはここにコミットして push する。続きから測る道筋は要約の数える行で回を飛ばすので、押しごとの記録が無くても変わらない。測り終えたら、`report.mjs` の集計を t5a-measure.md に表として写してから、置き場を木から消す（履歴には残る）。
  - 上限は1ファイル 1MB、サイクルを閉じるときの木で合計 4MB、木から消した記録を含めて履歴に入る量の合計 15MB で、後のサイクルがリポジトリを取り直す重さを抑えるための予算である（決め方は plan-t5a7.md 3）。上の変更後の版と基準の版の箇条のとおり、古い置き場のファイルと基準の版の置き場を木から消すので、木に残るのは変更後の版の1回分で、4MB に収まる。消した記録は履歴の 15MB に入る。履歴に入る量は、ここの `.jsonl`（測りの記録）のうちコミットしたことのあるすべての blob（同じファイルの版ごとに1つ）の生のバイト数の合計で数える。「着地の直しの害の確かめ」の比べの出力（`compare.mjs` の出力。[carryover.md](../carryover.md)）は `.json` で置き、この数えにも上限にも入れない。比べの出力にも1ファイル 1MB の線を掛け、越えるときは操作ごとのファイルに分けて書く（下の「比べる」）。数えるコマンドと見積もりの内訳は plan-t5a7.md 3 にある。道具は 1MB を越えたファイルを終わりに知らせる。上限を越える見込みになったときは PM に報告して形を決め直す。
- 要約の行と押しごとの記録は、道具が測りながら書いたままのもので、ほかの所の生の記録から作ったものではない。数え上げ（t5a-measure.md の表の数）は `report.mjs` がここの要約から出すので、同じ数をいつでも出し直せる。
- 像と生のログは置かない。試しの走りの記録と、害の確かめの回ごとの記録は、ここに置かず、担当の木で走らせても主の木の `tmp/cycle-320/<走りの名>/` に絶対のパスで書く（`--out-dir /home/user/yolo-web/tmp/cycle-320/<走りの名>/<版>`。担当の木の `tmp/` は、取り込んで木を消すと一緒に消えるため。plan-t5a7.md 2b の「記録の置き場」）。

- ファイルを重ねる版は `--overlay <コミット>:<パス>` を足す（例: `--commit fff3d31f --overlay da102212:src/play/quiz/data/character-personality.ts`）。1つのビルドは2〜5分で、`.next` が約 1.3GB になる。
- 書き出す場所は、担当の木で動かしても主の木の根（`git rev-parse --path-format=absolute --git-common-dir` の親）の `tmp/measure-builds/<名>` である。担当の木の `tmp/` は木を消すと一緒に消え、続きの測りとレビューが同じ版を読めなくなるからである（`.claude/rules/worktrees.md` の 4）。その場所がもうあれば止まる。作り直すときは `--replace` を足す（その場所と別の索引を消してから書き出す）。
- `node_modules` は主の木のものをハードリンクで写すので、版のコミットの `package-lock.json` の blob が主の木の `package-lock.json` と違えば止まる（2db1c7d9・5ea1ab89・dac2972e はどれも `248519ea`）。
- 履歴が浅いクローン（`git rev-parse --is-shallow-repository` が `true`）では、先に `git fetch --unshallow origin main design-rollout` で履歴を深くする。

### 指紋

`tmp/measure-builds/<名>/fingerprint.json` に、もとのコミットと重ねたファイル、ソースの木のハッシュ、`package-lock.json` の blob（`lock`）、Node と npm の版、書き出した場所（`buildPath`）、`.next/static/chunks` のファイルの名前と大きさの一覧と、その SHA-256 の頭 16 字（`chunksDigest`）を書く。`measure.mjs` は、測り始めるときに、この指紋を記録の置き場の `fingerprint.jsonl` の1行目に写す。

| 名      | 木のハッシュ                               | lock       | Node     | npm    | チャンク | chunksDigest       |
| ------- | ------------------------------------------ | ---------- | -------- | ------ | -------- | ------------------ |
| `base`  | `367f5d377ed8c3ae15775ecbcbe6447343daf87a` | `248519ea` | v22.23.4 | 10.9.9 | 170      | `f49483997b5d6a98` |
| `after` | `b5c1609f5badff26930b25183b9f17bc3038cf4f` | `248519ea` | v22.23.4 | 10.9.9 | 175      | `b3ba654d9d06799e` |
| `t5a4`  | `1d5cfedfcd6379aad3205266e39b49a08d8646ec` | `248519ea` | v22.23.4 | 10.9.9 | 175      | `2486b270c604480d` |

- **書き出す場所は名で決める**: 書き出した版は主の木の下にあるので、Next.js は主の木の根の `package-lock.json` を見てそこを Turbopack の根にし（ビルドの記録の「We detected multiple lockfiles」）、チャンクには根からの道（`/ROOT/tmp/measure-builds/<名>/node_modules/…`）が入る。道が違えば、同じコミットでもチャンクの名前（中身のハッシュ）がすべて変わる（`tmp/` の別々の2つの場所で HEAD 5ea1ab89 をビルドすると、175 のチャンクの名前がすべて違った）。同じ場所に書き出し直してビルドすると、チャンクの名前と大きさは一致した（5ea1ab89 の 175 と 2db1c7d9 の 170 を `--replace` で作り直しても、すべて一致した）。上の表は、どの版も主の木の `tmp/measure-builds/<名>` に作った値である。そこで `version.mjs` は書き出す場所を、どの木で動かしても主の木の `tmp/measure-builds/<名>` に決め、指紋は木のハッシュ・`package-lock.json`・Node と npm の版・場所・チャンクの一覧で組む。
- **GA の release の字**: ビルドの前の `generate:release-id` は、環境の `VERCEL_GIT_COMMIT_SHA` が無ければ `git rev-parse HEAD` を読む。書き出した版は主の木の下にあるので、そのままでは主の木の HEAD を拾い、主の木が進むとチャンクの中身が変わる。`version.mjs` は、もとのコミットとその日付を `VERCEL_GIT_COMMIT_SHA`・`VERCEL_GIT_COMMIT_DATE` で渡す。
- **見出しの Web フォント**: `next/font/google` の Zen Antique はビルドのときに取りに行く。取ったファイルが変われば CSS とメディアのチャンクが変わり、指紋の比べで分かる。

### 確かめ直す

続きを測る前に版を作り直し（`--replace`）、`node docs/cycles/cycle-320/measure/version.mjs compare docs/cycles/cycle-320/measure/<名>/fingerprint.jsonl tmp/measure-builds/<名>/fingerprint.json` で比べる（`.jsonl` は最後の行、つまりいま続けている版を読む）。`measure.mjs` も測り始めるときに同じ比べをし、次のように動く（plan-t5a7.md 3 の「日をまたぐ記録と版」）。

| 違うもの                  | 道具                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | 扱い                                                                                                                                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 木のハッシュ              | 止まる                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | 作り直しの誤りなので、記録したコミットから作り直す                                                                                                                                         |
| `package-lock.json`       | 止まる                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | 依存が違うので、記録の依存で作り直す                                                                                                                                                       |
| Node・npm                 | 止まる                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | 記録の版で作り直して比べ直す                                                                                                                                                               |
| チャンクだけ              | 止まって、違うチャンクの名を出す。PM が「続ける」と決めたときだけ、`--accept-chunks "<決定>"` を渡して続ける。道具は新しい指紋を決定とともに `fingerprint.jsonl` に足す。どのファイルも、回を測り始めるときに、そのファイルのチャンク（頭の行か最後の `accept` の行の `chunksDigest`）をいまの版のチャンクと比べ、違えば `fingerprint.jsonl` の決定から `accept` の行を足してから測る（どの呼び出しで受け入れたかによらない。決定の記録でいまのチャンクまでたどれなければ止まる。測り終えたファイルは書き換えない） | PM に報告する。PM は、違うチャンクが診断のページのコードを含むかで、続けるか、そのチャンクが掛かる操作を測り直すかを決める                                                                 |
| ブラウザの版・道具の blob | 同じ組（操作。D5 は `<操作>-d5`）のファイルのどれかと違えば止まる                                                                                                                                                                                                                                                                                                                                                                                                                                                   | その操作と版の組を、新しい置き場（`after-2` など）で1つのブラウザの版と1つの道具の blob ですべて測り直し、測り終えたら古い置き場の組のファイルを木から消す（上の「ここに置く理由」の箇条） |

ブラウザの版は版ごとではなく組ごとにそろえるので、組が違えばブラウザの版が違ってもよい。測っている途中で道具を書き換えない（道具の blob は `measure.mjs`・`version.mjs`・`knowledge.mjs`・`records.mjs` の4つで、どれかが替われば、その時までに測った組は続けられない。`report.mjs` と `compare.mjs` は記録を読むだけなので blob に入れない）。

## サーバー

基準の版はポート 3111、変更後の版はポート 3112 で、版のディレクトリから `next start` を起こす。着地の直しの害の確かめでは、`t5a4` をポート 3111、`after` をポート 3112 で起こす（[carryover.md](../carryover.md) の「着地の直しの害の確かめ」）。ほかの作業者のプロセスを巻き込まないよう、自分のグループだけを止める形で起こし、止める（`docs/knowledge/playwright-mcp.md` の「バックグラウンドのプロセスを起こして止める」）。

```sh
# 起こす（ログに Ready が出るまで、上限を決めて待つ）
DIR=/home/user/yolo-web/tmp/<自分の作業の名前>/server-after; mkdir -p "$DIR"
cd /home/user/yolo-web/tmp/measure-builds/after && PORT=3112 setsid bash -c 'echo $$ > "$0/server.pgid"; exec npx next start' "$DIR" > "$DIR/server.log" 2>&1 < /dev/null &
# 止めて、グループのプロセスが 0 でポートが空いたことを確かめる
kill -- -"$(cat "$DIR/server.pgid")"
ps -eo pgid= | awk -v g="$(cat "$DIR/server.pgid")" '$1 == g' | wc -l
lsof -nP -iTCP:3112 -sTCP:LISTEN
```

## 測る

```sh
node docs/cycles/cycle-320/measure/measure.mjs --base http://localhost:3112 --version /home/user/yolo-web/tmp/measure-builds/after \
  --op <操作> --out-dir docs/cycles/cycle-320/measure/after --landing on [--d5] [絞り込み]
```

## 働いたかと落ちた先

守り（`src/play/quiz/pressGuard.ts`）は `window` の捕捉の段階で、受けない押しの `mousedown` と `click` を止める。道具の受け手はページのどのスクリプトより前に同じ段階に置くので守りより先に走り、守りが止めた click も記録する。そのため、道具が記録した click は2打目が働いた証拠にならない。道具は次のように決める（decision-landing.md の「測りの道具」と t5a-measure.md 0章の「落ちた先」）。

- **働いたか**は押しのあとの状態で決める。道具は押しの前と記録の時点に、段階・帯の番号・答えの有無・URL・開いている `details`・フォーカスの置き場と、フォーカスがいちばん新しい `pointerdown` の的の押せるものにあるかを読み（`__yolosState`）、開いたタブ（`context.route` で取る最初の遷移）とダウンロードの始まり（`page` の `download`）を押しごとに数える。2打目は、記録の時点の状態を「1打目だけが働いたときの画面」と比べる（「はじめる」なら1問目で答えが無い、診断の答えと知識クイズの「次へ」なら次の問で答えが無い、知識クイズの答えなら同じ問で答えがある、最後の答えか最後の「次へ」なら結果、「もう一度挑戦する」なら開始の画面）。1打目が働いたかは、押しのあいだのどれかの時点（切り替わりのあとのフレームの段階・帯の番号・答えの有無、2打目の `pointerdown` と `click` の時、記録の時点）に1打目の働きが一度でも出たかで決める（2打目が結果の画面の「もう一度挑戦する」やリンクで画面を離れても、1打目の働きはその前のフレームに出る）。一度も出なかった（1打目が守りに止められた）回は、押しの前の画面と比べる。働いたことは字で残す（`s` 画面が違う、`u` URL が変わった、`t` 新しいタブが開いた、`w` ダウンロードが始まった、`o` `details` の開閉が変わった、`f` 押した要素にフォーカスが移った。その押しの種類の置き場へのフォーカスは `f` に数えない）。字が空なら働かなかった。
- **どこに落ちたか**は2打目の `pointerdown` の捕捉の段階の記録（的の要素・押せるものの上か・帯の番号・段階）で決める。Chromium はタッチの調整を `pointerdown` の前に掛けるので（knowledge §8）、`pointerdown` の的は寄せたあとの点のものになる。ただし、押し下げが切り替わりの前で `click` が切り替わったあとの画面に届いた2打目（`q` の `shown` が 0 で `clickShown` が 1。タッチの `click` の的は離した時の組みで決まるので、速い二度押しと、見せる間に触れて切り替わったあとに離す押しで起きる）は、押し方によらず `click` の的で決める。押し下げも `click` も切り替わる前の画面のものだった押しは、守りが無くても働かないので、落ちた先を持たない。この決め方は `records.mjs` の `landedOf` にあり、`measure.mjs`（押しごとの記録の理由・空振りでないことの対を送るか・5-2 の確かめ）、`report.mjs` の束と合否の行、`compare.mjs` の線が同じものを使う。要約の `s`・`c`・`n` の落ちた先の欄と押しごとの記録の `grp` は2打目の `pointerdown` の的の記録で、落ちた先は `q` の押しから `landedOf` で読む。
- **的の突き合わせ**: `click` の的とタッチの回の `touchstart` の的も押しごとに残し、守りを掛けない回（守りを持たない版のすべての押しと、守りを持つ版の知識クイズの答え・「もう一度挑戦する」・語の選択の対）で3つが合うかを突き合わせる（`q` の `targetMismatch`。`report.mjs` の `target-mismatch`。合わなければ PM に報告する）。突き合わせるのは、`pointerdown` の時と `click` の時で画面（段階・帯の番号・答えの有無）が同じ押しだけで、あいだに画面が替わった押し（`q` の `clickMoved`）は的が違って当たり前なので、別に数える（`target-mismatch` の `moved`）。
- **試した回**: 2打目の落ちた先（上の `landedOf`）が、切り替わったあとの画面の押せるもの（`reveal.ts` の集め方で `closest` した押せるもの）だった回。
- **時刻**: 1打目と2打目の `pointerdown` の `event.timeStamp` の差（`downGap`）と、1打目の離し（`pointerup`、無ければ `touchend`）から2打目の `pointerdown` までの差（`releaseGap`）を押しごとに残す。
- **空振りでないことの対**: 窓の守りを掛けた切り替わりの条件7 の回（`same`・`aim`。D5 を除く）で、離れていなければ、1打目を送ってから 900ms のあとに1回押し、その押しが働いたかを同じ判定で読む（`q` の `pair`）。試した回は、その回の2打目と同じ点を押す（`same`）。狙った2打目で 80px の中に的が無く2打目を送らなかった回（守る的が無い組の押し。decision-landing.md の「空振りでないことの対」）は、900ms のあとの組みで、1打目の点から直線の距離がいちばん近い押せるもの（画面の中の部分）の、押せる範囲の画面の中の部分の中心を押す（`nearest`。画面に押せるものが無ければ押さず、押せるものの上でない対として残す）。
- **2打目で離れたか**（t5a-measure.md 0章）: 記録の時点の道が2打目の `pointerdown` の時点の道と違えば、その道へ移った。2打目の `pointerdown` の時に結果の画面が出ていて、記録の時点に開始の画面なら、「もう一度挑戦する」が働いた。走査は空振りでないことの対の押しで離れたときもそこで終える（要約の `vq`）。

## 記録の形

置き場 `<名>/` の中に、次のファイルを置く。組は操作の名（D5 は `<操作>-d5`）、画面は `375x550`（200% は `375x550-200`）。

- `fingerprint.jsonl`: 1行目が測り始めた版の指紋（`fingerprint.json` と同じ形に、写した時刻 `at`）。2行目からは、チャンクだけが違って PM が続けると決めたときの版の指紋で、決定（`decision`）と、それまでの `chunksDigest`（`previous`）を持つ。
- `<組>-<画面>.jsonl`: 1行目は頭の行（`"type": "head"`。操作・D5 か・木のハッシュ・`chunksDigest`・ブラウザの版・道具の blob（`measure`・`version`・`knowledge`・`records`）・着地の止め所を置いたか `landing`・着地の関数の形 `shape`（`hit`・`row`。下の「着地の関数の記録の取り方」）・版が二度押しの守りを持つか `guard`・乱数の種の字 `seed`（`--seed` を渡したときだけ））。チャンクを受け入れたあとに初めて回を足すところには、`fingerprint.jsonl` の決定を写した `"type": "accept"` の行（`chunksDigest`・`decision`・`at`）が入る。ほかの行は回の要約で、1つの回の測りごと（送り直しと誤りを含む）に1行。
- `<組>-<画面>.presses.jsonl`: 押しごとの記録。変更後の版の判断に要る押しと、どちらの版でも誤りで終わった回の押しと、PM が確かめる押しだけ（下の「押しごとの記録」の `why`）。

### 回の要約

どの操作にも共通する欄:

- `k`: 回の名（本・入力・間隔・ずれ・行か高さか結果か `keyboard` の切り替わり・2打目の押し方。操作と画面はファイルの名にある）。`a` はその回の何度目の測りか、`f: 1` はその回の数える行。`r` は送り直した理由か、上限まで越えたまま数えた理由（`crossed`・`detail`・`result`・`check`・`error`）。`e` は誤りの字、`ms` は1回の壁時計の時間、`p` はこの回の押しごとの記録の数、`v` は2打目で離れたときの離れ方（`link:<道>` か `retry`。上の「2打目で離れたか」）。
- `q`: 押しごとの短い記録（下の「押しの短い記録 q」）。1度の押しで終わる操作は1つ、走査は押しの数だけ持つ。

1度の押しで終わる操作（`start`・`last`・`retry`・`select`）の欄:

- `g`: 1打目と2打目の押し下げの実際の間隔（タッチは `touchstart`、マウスは `mousedown`）。送り直しの「150ms の側を越えた」はこの間隔で決める。
- `s`: 2打目の `pointerdown` の的の組。`link`・`summary`・`button`・`pressable` が第1の組、`next` は次の問（1打目の問より後の問。「はじめる」と「もう一度挑戦する」のあとは1問目）の選択肢、`choice` は同じ問の選択肢、`start` は「はじめる」、`text` は押せない字、`none` は要素の無い所。`null` は2打目の `pointerdown` が無かった回。押し下げの的の記録なので、押し下げが切り替わりの前で `click` が切り替わったあとの画面に届いた回では落ちた先と違う（落ちた先は `q` から `landedOf` で読む。上の「働いたかと落ちた先」）。
- `d`・`w`（マウス）: 2打目の `mousedown` の `detail` と、記録の時点の選択の字（頭の 12 字）。語の選択の数は `d` が 2 の回だけで数える。
- `n`（タッチ）: 2打目の `pointerdown` を受けた時の組みでの、1打目の点から最も近い押せるものの押せる範囲までの横と縦の隔たり。`[第1の組, 問の選択肢, 「はじめる」]` の順で、それぞれ `[dx, dy, "<組>:<名前の頭の 10 字>"]` か `null`（その組の押せるものが無い）。「はじめる」は画面にあるときだけ。`n2`（D5 と狙った2打目）は、2打目の点からの同じ隔たり。2打目がページを移ったあとに来て点を持たない回は `null`。読み方は t5a-measure.md 0章の「タッチの調整」。
  - **取る時**: Chromium は受け手のあるページで、2打目の `pointerdown` を出す前の組みで点を寄せる（`docs/knowledge/input-events-and-guards.md` §8 の「寄せと落ち先が決まる時と、隔たりを取る時」）。道具は `window` の捕捉の段階の `pointerdown` の受け手を、ブラウザの文脈の初期化スクリプトでページの読み込みの前に置き、寄せたすぐあと、ページの受け手が組みを変える前の組みで取る。
  - **押せるもの**: 着地の関数と同じ集め方（`a[href]`・`button`・`summary`・入力・`label`・`[role="button"]`・`[role="link"]`）で、Chromium のタッチの調整の候補より狭い。Chromium は、マウスでフォーカスできる要素（問の見出し `h2[tabindex="-1"]`・結果のボックス `section[tabindex="-1"]`）や `:hover`・`:active` で見た目が変わる要素にも寄せうる。それらが記録の押せるものより点に近い回では、Chromium の寄せる先は記録の「最も近い押せるもの」と違いうる（そこへ寄っても答えは入らない）。
  - **押せる範囲**: `data-hit-area="after"` の要素（問の選択肢など）は `::after` で押せる範囲を位置を決めた祖先（行の `li`）に広げているので、祖先の内側の箱（`getBoundingClientRect()` から `getComputedStyle` の `border-*-width` を引いた padding box）で取る。行の下の罫線 1px は押せない。ほかの要素は要素の箱で取る。
  - 最も近いものは `max(dx, dy)` で決める。
- `l`（着地の関数を持つ版）: 2打目が受けた画面（2打目の押し下げの時点までの最後の着地。2打目より前に画面が替わっていなければ、2打目のあとの最初の着地）の着地の関数の記録で、`[範囲の中に点の真下から第1の組を外す送りがあったか, 両方の組を外す送りがあったか, 範囲の中で点から第1の組を最も離せたときの max(dx, dy), 両方の組の近いほうを最も離せたときの max(dx, dy)]`（隔たりは 100 で頭打ち）。避けるものの矩形は `n` と同じ押せる範囲で数える（下の「着地の関数の記録の取り方」）。基準の版は着地の関数を持たないので、`l` を持たない。
  - 範囲の中で押せるものを離せたかは、最も離せたときの値（3つ目・4つ目。16px 以上で離せた）で読む。真下を外す送りがあったか（1つ目・2つ目）は、点を行の罫線の上に置くだけの送りも含むので、離せたかの読みには使わない。`report.mjs` はこの4つの値を数えず、件ごとに読む記録である（B-620 の材料の数え方は t5a-measure.md 0章の「B-620 の材料と写す数」）。
  - 隔たりは、着地の関数が受けた1打目の点から数える。D5 の回では、ずらした2打目の点が避けられたかを表さない。
- `hu`（着地の関数を持つ版）: 着地の記録で、`data-hit-area="after"` の祖先の箱のうち関数の矩形と一致せず、押せる範囲に置き換えられなかった数。`l` を持つ行は 0 でも持つ。下の「着地の関数の記録の取り方」。
- `cut`: 着地のあとの最初のフレームのどれか（2打目が働いて切り替えた画面のフレームを含む）で、`h1`・問の見出し・結果の名前のどれかの行の箱を画面の上端が横切った。`lo`: 結果への切り替わり（`rv` の切り替わり）で、結果の名前の下端が画面の下端から 8px 上より下にあった。`ins`: extra の差し込みが画面の中に入った。`h1a`: 「もう一度挑戦する」のあとに開始の画面の `h1` が丸ごと画面の上端より上にあった。`at: 0`: 「もう一度挑戦する」の中心が決めた高さに着かなかった。
- `rv`（結果に切り替わった回。`last`）: 結果への切り替わりの着地のあとの最初のフレームの `[結果のボックスの上端, 結果の名前の下端]`（画面の上端からの px。t5a-design.md 6章 条件7 の「結果の名前が見えること」）。`re`（着地の関数を持つ版）: 結果への切り替わりの着地の記録（そのフレームの1つ前のフレーム、無ければ押しの頭より後で、そのフレームより前の最後の着地）で、ページが送れる範囲で打ち切った範囲が空でなければ 0。空だった（着地の関数が基準の送り s0 にした）回は、打ち切る前の範囲（見せる範囲の高さから決まる）を関数と同じ `ceil`・`floor` で丸めて整数の送りが無ければ 1（範囲が 1px より狭く整数の送りを含まない回も入る）、打ち切る前は整数の送りがあり、ページの送れる範囲で打ち切って無くなったなら 2。押しごとの記録の `land` の2・3つ目（打ち切る前の範囲）は四捨五入した値なので、端の回（例: 10.3〜10.7 は `[10, 11]` に見えるが 1）の見分けには使えない。前の画面の着地を結果の着地と取り違えないよう、1つ前のフレームより前の着地は見ない。そうした着地の記録が無ければ `re` を持たない（基準の版は着地の関数を持たないので、どの回も持たない）。
- `res`（`last` の答えの組の回）: 着いた結果の名前の字から決めた結果の id（決められなければ `?`）。`bs`（`last`）: 最後の押しの前の1度ずつの押しのうち、来訪者の送りを挟んだ押しの順の番号と送りの量。

`keyboard` の欄:

- `kb`（入力 `keyboard`）: `[切り替わったか（1・0）, Tab で移った先の要素（タグ:字の頭の 10 字）, Enter が働いたことの字]`。字は上の「働いたかと落ちた先」と同じで、フォーカスの移りは数えない（Tab で移しているため）。空なら働かなかった。
- `kb`（入力 `touch`・`mouse`）: `[切り替わったか, 押した的（組:名前の頭の 10 字）, 働いたことの字, 切り替える前の押しの pointerdown からの差（ms）, 押しの pointerdown の的が押せるものの上か, 切り替える前の押しの点からの直線の距離]`。切り替える前の押しは、切り替える押しの矩形のすぐ外（12px 上・下・左・右のうち押せるものの上でない最初の点）に1度送るポインタの押しで、Enter で切り替えて 150ms のあとに、その点から矩形までの直線の距離が 80px 以下の新しい画面の押せるもののうちいちばん近いもの（狙った2打目と同じ選び方）を1度押す。キーボードで切り替えたあとは窓を開かないのが決めなので、この押しは働くのが合格（窓が誤って開けば、点の 100px の中の押しが止められる）。的が無ければ的と字は null で、最後の欄はいちばん近い押せるものまでの距離。字はフォーカスの移りも数える（ポインタで押した要素へのフォーカス）。

走査（`answers`）の欄:

- `np`: 押しの数。`c`: 2打目の `pointerdown` の的の組ごとの押しの数（組の名は上の `s` と同じ。落ちた先は `q` から `landedOf` で読む）。`cm`: 実際の間隔が 150ms の側を越えた押しの、同じ数（`c` に入れない。90・300ms の間隔ごとの比べから外し、確かめと落ち先には残す。plan-t5a7.md 4 の「間隔」）。`x`: 越えた押しの数。`dm`: マウスの2打目の `detail` が送った `clickCount` でない押しの数。`w`: 語が選ばれた押しの数（`detail` が 2 の押しだけ）。`cut`: 切れた見出しのあった押しの数。
- `n`（タッチ）: 1打目の点（D5 は2打目の点も）から最も近い第1の組か問の選択肢の `max(dx, dy)` が 0 より大きく 20 以下の押しの、`[押しの番号, 帯の番号, 2打目の pointerdown の的の組, 1打目の点からの隔たり, 2打目の点からの隔たり, 着地の記録, 押しの種類, 押せる範囲に置き換えられなかった祖先の箱の数, そのうちの問の選択肢の行の数]`。的の組は上の `s` と同じ字（落ちた先は `q` の同じ番号の押しから `landedOf` で読む）、隔たりは上の `n`・`n2` と同じ形（ずれの無い回は2打目の点からの隔たりが `null`）、着地の記録は上の `l` と同じ形（基準の版は `null`）、押しの種類は押しごとの記録の `kind`（`answer`・`next`）、最後の2つは押しごとの記録の `land` の最後の2つと同じ数（基準の版は `null`）。0 の押しは点の真下に押せるものがあり、`c` に入る。どの押しの送りの量と着地のあとの離れも `q` にある。
- `ck`: 5-2 の確かめ `[1打目で答えた問の数, X, S, 空振りでないことの対の押しで答えた問の数, 和が問の数に等しければ 1]`。どれも押し下げの記録と押しのあとの状態で数え、click の記録では数えない（t5a-measure.md 5-2 の「数える条件」）。1打目は、押し下げが押せる選択肢に落ち、押しのあとの状態でその問に答えがあるもの。X・S は、2打目の押し下げの帯の番号が1打目の問より後の問で、押せる選択肢に落ち、押しのあとの状態でその問に答えがあるもの（最後の問なら S）。押し下げが切り替わりの前で click が切り替わったあとの画面に届いた2打目（hold・hold-aim・hold-out など）は、働けば離した時の組みの問に答えるので、click の的の組と帯の番号で数える（`landedOf` と同じ決め方）。
- `vp`（2打目で離れた走査）: 離れさせた押しの `[帯の番号, 押しの種類]`（t5a-measure.md 5-2 の「離れた所」）。種類は `answer`・`next` で、結果に切り替えた押し（最後の答え。知識クイズは最後の「次へ」）は `last-answer`・`last-next`。移った先は共通の欄の `v`、空振りでないことの対の押しで離れたときは `vq: 1`。
- `rv`・`re`・`lo`: 走査が結果に切り替わった押し（最後の答えか、2打目が最後の問に答えた S の押し。知識クイズは最後の「次へ」）の、上と同じ値と印。S の切り替わりは2打目の答えを見せる 150ms のあとに来るので、道具はその切り替わりのあとの最初のフレームまで待ってから記録を閉じる（上の「押しの空け方」）。

`report.mjs` は、結果の名前の見え方（t5a-design.md 6章 条件7）を束（画面）ごとの `resultView` に分けて出す。`expected`・`missing` は、結果に切り替わるはずの回（`last` のどの回と、2打目で離れなかった走査と、結果に切り替えた押しの2打目で離れた走査。離れた押しは `vp` で分かる）の数と、そのうち `rv` の無い回の数で、`missing` は 0 のはずである。`runs`・`boxTop`・`nameBottom` は、`rv` のある回の数と、結果のボックスの上端と結果の名前の下端の `[最小, 中央, 最大]`（画面の上端からの px）。`spanRecorded` は、そのうち `re` のある回（結果への着地の範囲が分かった回）の数で、`spanMissing` は、着地の関数を持つ版（頭の行の `landing` が true）の束で `rv` があって `re` の無い回（結果への着地の記録が取れなかった回）の数である。`re` の無い回は、範囲が空で s0 にした回でも `emptyRuns` にも `clampEmptyRuns` にも出ずに消えるので、`spanMissing` は 0 のはずで、0 でなければ PM に報告する（着地の関数を持たない版の束では出さない）。`spanEmpty`・`emptyRuns` は、打ち切る前の範囲が高さで空で s0 にした回（`re` が 1。t5a-design.md 4-9 が受け入れた回）の数と、その回ごとの `[回の名, ボックスの上端, 名前の下端]`（条件7 の「その旨と値」）。`clampEmptyRuns` は、ページの送れる範囲で打ち切って空になり s0 にした回（`re` が 2）ごとの同じ値で、4-9 は範囲が空になるのを高さで空のときだけとしているので、設計の前提が崩れた回として判断（plan-t5a7.md 5）に渡す。`lowInSpan` は、`lo` のある回のうち 4-9 が受け入れた回でない回（`re` が 1 でない回。2 の回を含む）の数で、範囲が空でない回の名前は着地の関数が見せる範囲の中に置くので、変更後の版では欠けか道具の誤りとして判断に渡す（基準の版は `re` を持たないので、`lo` のある回がすべて入る）。`flags.nameLow` は、1度の押しで終わる操作の回と走査の、範囲が空だった回を含む `lo` の数である。

### 押しの短い記録 q

`q` の1つは押し1つの配列で、欄の並びは `records.mjs` の `Q_COLUMNS` である（`readPress` で欄の名で読める）。どの版でも同じ数え方で取る。

- `i`: 走査の中の押しの番号。`kind`: 押しの種類（`start`・`answer`（診断の最後でない答え）・`last-answer`・`knowledge-answer`・`next`（知識クイズの最後でない「次へ」）・`last-next`・`retry`・`heading`（語の選択の対））。`band`: 1打目を押した時の帯の番号。
- `downGap`・`releaseGap`: 上の「時刻」。`detail`・`clickDetail`: 2打目の `mousedown` と `click` の `detail`（タッチも記録する）。
- `group`・`pressable`・`shown`: 2打目の `pointerdown` の的の組（要約の `s` と同じ字）と、押せるものの上か、切り替わったあとの画面が出ていたか（切り替わらない押し（語の選択の対）は `null`。知識クイズの答えは、同じ問に答えがある画面を切り替わったあととする）。
- `clickShown`・`clickMoved`: 2打目の `click` の時に切り替わったあとの画面が出ていたかと、`pointerdown` と `click` のあいだに画面（段階・帯の番号・答えの有無）が替わったか（`click` が無ければ `null`）。`shown` が 0 で `clickShown` が 1 の押しは、落ちた先を `click` の的で決める（上の「働いたかと落ちた先」）。
- `firstTook`: 1打目の働きが、押しのあいだのどれかの時点の状態に一度でも出たか（0 なら道具の1打目が守りに止められた。上の「働いたかと落ちた先」）。`worked`: 2打目が働いたことの字（空なら働かなかった。状態が読めなければ `null`）。`focusOff`: 記録の時点のフォーカスが切り替わりの置き場（問の見出しか結果のボックス。t5a-design.md 4-7）に無いか（窓の守りの押しだけ）。
- `downDistance`: 1打目と2打目の `pointerdown` の直線の距離（守りと同じ画面の座標）。
- `sent`: 送りの量（選んだ着地と基準の送り s0 の差。carryover.md の「測りの道具」の (1)）。`landing`: 2打目が受けた画面の着地の `[s0, 打ち切った範囲の上, 下, 選んだ着地, 着地に使った点の x, y]`（範囲の上が下より大きければ空。点が無ければ x・y は `null`）。どちらも着地の関数の記録から取り、着地の関数を持たない版は `null`。
- `reaches`: 着地のあとの組み（切り替わったあとの画面の最初のフレーム）での、1打目の点から `[第1の組, 問の選択肢]` までの max(dx, dy)（100 で頭打ち。組が無ければ 100）。どの入力でも取る。押せる範囲は上の `n` と同じ箱。
- `aim`: 狙った2打目（`aim`・`hold-aim`。`hold-aim` は下見で選んだもの）の `[的（組:名前の頭の 10 字。無ければ null）, 1打目の点からいちばん近い押せるものまでの直線の距離]`。`hold-out` の押しでは、下見で選んだ `[的, 1打目の点から選んだ点までの距離]` で、120px 以上離れた押せるものが無かった押しは `[null, 画面の中の押せるものの点のうちいちばん遠いものまでの距離]`（押せるものが画面に無ければ 0）、下見が本番と合わなかった押しは `[null, null]`（どちらも2打目を送らない）。`pair`: 空振りでないことの対の押しの `[1打目からの差, 押せるものの上か, 組, 働いたことの字, 点の選び方（same か nearest）]`（押さなかった `nearest` の対は `[null, 0, null, null, "nearest"]`）。
- `click`: 2打目の `click` の `[組, 帯の番号, 段階, 的が押せるものの上か]`（離した時の組みでの落ちた先）。`targetMismatch`: `pointerdown` と `click` の時の画面が同じ押しで、2打目の `pointerdown`・`click`（タッチは `touchstart` も）の的が合わない（画面が替わった押しと `click` の無い押しは `null`）。
- `selected`: 記録の時点に語が選ばれていたか（マウスだけ）。`marks`: 読む所の印の字（`c` は `cut`、`l` は `lo`、`i` は `ins`、`h` は `h1a`、`a` は `at: 0`）。2打目が働いて切り替えた画面の印は入れず、`follow` に持つ。`point`: 1打目を送った点。`previous`: 1打目の、直前の切り替わりの起点（直前の二度押しの記録で画面を切り替えた押し。2打目が働いたなら2打目、そうでなければ1打目）からの `[時刻の差, 起点の点からの直線の距離, 直前の離しからの差, 1打目の mousedown の detail, 起点の押しの種類]`（道具の1打目が守りに止められた押しを、決めどおりか害かに分ける材料。前の二度押しが無ければ `null`）。2打目の起点からの時間・隔たり・`detail` は `downGap`・`releaseGap`・`downDistance`・`detail` にある。
- `mode`: この押しの2打目の押し方（`same`・`aim`・`hold`・`hold-aim`・`hold-out`・`d1`・`read`）。ふつうは回の名の最後の欄と同じで、知識クイズの走査の答えは、回の押し方によらず `same`。`report.mjs` と `compare.mjs` は押しをこれで分ける。
- `nearest`: 2打目の `pointerdown` の時の組みで、1打目の点から画面の中の押せるもの（押せる範囲の画面の中の部分）までのいちばん近い直線の距離（どの入力でも。押せるものが画面に無ければ `null`）。`shown` が 1 の押しでは、切り替わったあとの画面に守る的（80px 以下の押せるもの）があるかの証しになる（下の「合否の行」の `noTarget`）。
- `follow`: 2打目が働いて画面を切り替えた押し（X・S の次の問か結果、結果の画面の「もう一度挑戦する」からの開始の画面、「はじめる」のあとの2問目など。1打目だけの画面のフレームのあとで、同じ道のまま段階か帯の番号が替わったフレームから）の、その切り替わりの `[行き先（question・result・intro）, 送り, 着地, 着地のあとの隔たり, 印]`。送りと着地は `sent`・`landing` と同じ形（着地は切り替わりのフレームの1つ前のフレームより後の最後の着地の記録）で、隔たりは切り替わりの着地のあとの最初のフレームでの、2打目の点（この着地は2打目の click の点から決まる）から `[第1の組, 問の選択肢]` までの max(dx, dy)（100 で頭打ち）、印は `c`・`l`。無ければ `null`。

### 押しごとの記録

1行が1つの押しで、`k`・`a` で回の要約と結び、`why` に置いた理由を持つ: `first`（2打目が第1の組）・`next`（次の問の選択肢。答えの2打目が次の問の選択肢に落ちた押しは、条件7 が数だけを求めるので置かず、要約の `c` と `q` に数える）・`selection`（語が選ばれた。`select` では `no-selection`、語が選ばれなかった）・`name-low`（結果の名前の下端が見せる範囲の外）・`insert`（extra の差し込みが画面の中）・`error`（誤りで終わった回の押し。押しの前に誤った回は `i: null` と `error` だけ）。ここまでは着地の関数を持つ版だけで置く。次の理由は、守りを持つ版で合否の行のどれかで外れた押しで置く: `guard-miss`（窓の守りか連続の押しの守りの「受けない」で働いた2打目）・`accept-miss`（タッチの受ける側で答えを入れなかった2打目）・`hold-miss`（hold の2打目が働いた）・`pair-miss`（空振りでないことの対の押しが働かなかった）。次の理由は、どの版でも置く: `first-blocked`（道具の1打目が守りに止められた）・`mismatch`（守りを掛けない押しで、`pointerdown` と `click` の時の画面が同じなのに、`pointerdown`・`click`・`touchstart` の的が合わない）。`first`・`next`・`guard-miss`・`hold-miss` の落ちた先は `landedOf` で決める。

- `i`: 走査の中の押しの番号。`kind`: 1度の押しで終わる操作では `start`・`last-answer`・`last-next`・`retry`・`heading`。走査（`answers`）では、答えを入れる押しが `answer`（診断の最後の答えと知識クイズの答えを含む）、知識クイズの「次へ」が `next`（最後の「次へ」を含む）で、最後の押しか知識クイズの答えかの別は `q` の `kind`（`last-answer`・`knowledge-answer`・`last-next`）にある。`band`: 押した時の帯の番号（開始と結果の画面では `null`）。`pt`: 押した点。`sc`: 押す前の来訪者の送り。`gap`: 実際の間隔。`x`: 実際の間隔が 150ms の側を越えた。`dm`: マウスの2打目の `detail` が送った `clickCount` でない。
- `c1`・`c2`: 1つ目と2つ目の `click` の `[組, 名前の頭の 16 字（リンクは道）, x, y, 帯の番号]`。`c2` は末尾に、`click` の時点の `scrollY` を持つ。組は `link`・`summary`・`button`・`pressable`（第1の組）、`choice`（問の選択肢）、`start`（「はじめる」）、`text`（押せない字）、`none`。`nc`: `click` の数が 2 でないときの数。`md2`: 2打目の `mousedown` の `detail`。`grp`: 要約の `s` と同じ、2打目の `pointerdown` の的の組。`sel`: 記録の時点の選択の字。`pop`: 開いたタブの行き先。
- `d1`・`d2`: 1打目と2打目の `pointerdown` の `[組, 名前の頭の 16 字（リンクは道）, x, y, 帯の番号, 段階]`。`d2` は末尾に、押せるものの上か（1・0）を持つ。`st`: 押しの前と記録の時点の状態の `[段階, 帯の番号, 答えの有無, URL, 開いている details の番号, フォーカスの置き場, 押した要素にフォーカスがあるか]`。`q`: 要約の `q` と同じ形の、この押しの短い記録。
- `land`（着地の関数を持つ版だけ）: 着地の関数を呼ぶたびの `[基準の送り s0, 見せる範囲の上, 下, ページが送れる範囲で打ち切った範囲の上, 下, 基準の送りで点の真下に来る組（first・next・null）, clearOfFirst, clearOfBoth, farFirst, farBoth, 選んだ着地, 押せる範囲に置き換えられなかった祖先の箱の数, そのうちの問の選択肢の行の数]`。clearOf・far は要約の `l` と、置き換えられなかった数は要約の `hu` と同じで、選んだ着地は着地のあとの最初のフレームの `scrollY` と、関数を呼んだときの `scrollY` の差。2打目が働いて切り替えた画面の着地は入れず、`q` の `follow` に持つ。`li`: 要約の `l` に写した呼び出しの番号。
- `fr`: この押しのあいだ（2打目が働いて切り替えた画面を含む）に画面が替わるたびの、着地のあとの最初のフレーム（`requestAnimationFrame`）の `[段階|帯の番号|答えの有無|「次へ」の有無, scrollY, h1, 問の見出し, 結果の名前, 結果のボックスの上端, 「はじめる」の上端と下端]`。h1・見出し・名前は `[行の箱の上端, 下端, 行の数, 画面の上端が横切った行（無ければ 0）]` か、無ければ 0。
- `near`・`near2`: 要約の `n`・`n2` と同じ（「はじめる」を含めた3つ。2打目の `pointerdown` の時に取る）。`cut`・`lo`・`h1a`・`ins`・`at`: 要約と同じ印。

### 着地の関数の記録の取り方

本番のコードに測りの口を足さずに、版の `reveal.ts` の着地の関数の引数を、CDP の Debugger の条件付きの止め所で取る。着地の関数には2つの形があり、道具は版のソース（`src/lib/reveal.ts`）で見分ける（頭の行の `shape`）。

- `hit`（`export function chooseTouchClearLanding` がある版。着地の作りを決め直した版）: 入り口の `chooseTouchClearLanding` は、避けるものを行の矩形（罫線を含む `avoidFirst`・`avoidNext`）と罫線を除いた押せる範囲の矩形（`avoidFirstHitAreas`・`avoidNextHitAreas`）の両方で受け、16px 以上離せないときは中で `chooseLanding` を呼ぶ。止め所は入り口だけに置き、1回の着地に1つの記録にする。
- `row`（`export function chooseLanding` だけがある版。5ea1ab89）: `chooseLanding` が、避けるものを行の矩形だけで受ける。

最小化したチャンクでは、どちらも `revealLanding` の中の関数になり、引数の名前も変わるので、`measure.mjs` はチャンクを読み込むたびに、形の字（`hit` は `function(<名>){let{plan:…,point:…,avoidFirstHitAreas:`、`row` は `function(<名>){let{plan:…,point:…,avoidFirst:`。`measure.mjs` の `LANDING_SHAPES`）を探し、その本体の頭に、引数を JSON にして `console.debug` に書き `false` を返す条件の止め所を置く（止まらない）。基準の版のチャンクにはどちらの形も無いので止め所は置かれないが、比べをそろえるため、Debugger はどの版でも有効にする。範囲の中に点の真下を外す送りがあったか（`clearOfFirst`・`clearOfBoth`）と、最も離せたときの隔たり（`farFirst`・`farBoth`）は、引数の矩形と範囲から、関数と同じ1px 刻みで道具が数える。

2つの版で同じ数え方にするため、道具はどちらの形でも行の矩形（`avoidFirst`・`avoidNext`）を読み、要約の `n` と同じ押せる範囲に直して数える。止め所の条件で、そのときの組みの `data-hit-area="after"` の祖先ごとの `[要素の箱, 押せる範囲, 問の選択肢の行か]` もページから読み（`measure.mjs` の `__yolosHitAreas`）、引数の矩形のうち要素の箱と一致するものを押せる範囲に置き換えてから数える。関数の見方（`row` の形は罫線を押せるものに含める）では真下から外せない送りでも、点が行の罫線の上に来る送りは、道具では真下から外す送りに数える。そうした回の最も離せた隔たりは 1px より小さく、避けられた件（16px 以上）には入らない。

置き換えが外れると、罫線 1px を押せる範囲に含めた値に黙って戻るので、道具は、祖先の箱のうち関数の矩形のどれとも一致しなかった数と、そのうちの問の選択肢の行の数を、着地の記録ごとに残す（押しごとの記録の `land` の最後の2つ、走査の要約の `n` の押しの最後の2つ、1度の押しで終わる操作の要約の `hu`）。`report.mjs` は、置き換えが外れた箱の数を `hitUnmatched` に押しの種類ごとに足す。走査は押しごとの記録に置いた押しと、そこに無い `n` の押しから、1度の押しで終わる操作は `hu` から数える。種類は押しごとの記録（`n` の押しは `n` の記録）の `kind` で、答えは診断の答え（`diagnosis-answer`。走査の診断の最後の答えも入る）と知識クイズの答え（`knowledge-answer`）に分け、走査の最後の「次へ」は `next` に入る。1度の押しで終わる操作は操作から決める（`start`・`last-answer`・`last-next`・`retry`・`heading`）。知識クイズの本は `knowledge.mjs` の組で、`measure.mjs` と同じ組で分ける。診断の答えのあとの呼び出しは問のまとまりを関数が避けないもの（`exclude`）に渡し、その問の選択肢の行は一致しないのが正しいので、`diagnosis-answer` は一致しなかった箱のうち問の選択肢の行でないもの（一致しなかった数から、一致しなかった問の行の数を引いた数）を外れに数え、ほかの種類は一致しなかった数をそのまま外れに数える。どちらも負にならず、どの種類も 0 になるはずで、0 でない種類があれば、関数の矩形の取り方が変わったので、PM に報告して道具を直す。要る数（一致しなかった数と、`diagnosis-answer` ではそれに加えて一致しなかった問の行の数）を持たない着地の記録は `hitUnmatched` に入れず、`hitUnrecorded` に数える。1度の押しで終わる操作の `l` があって `hu` の無い行、走査の `n` の押しで押しの種類と2つの数の無いもの、押しごとの記録の `land` で一致しなかった数（12番目）の無いもの、`diagnosis-answer` の `land` で一致しなかった問の行の数（13番目）の無いものがこれにあたる。ほかの種類の `land` は、12番目があれば、13番目が無くても `hitUnmatched` に入る。

着地の記録が黙って欠けないよう、道具は版の着地の関数の形を版のソースから見分け、測り始める前に `--landing` の期待と比べる。見分けが外れると（着地の作りを決め直して関数の名前や置き場が変わったときなど）、変更後の版が基準の版と見なされ、着地の記録・`re`・押しごとの記録が誤りにならずにすべて欠けるので、食い違えば止まる。持つ版では、測り始める前にビルドのチャンクにその形があることを確かめ、毎回ページを開いたあとに止め所を置けたことを確かめる。どれかが欠ければ止まる（関数の名前や置き場、最小化の出力が変わったときは、`LANDING_SHAPES` と見分けを直して道具をレビューに通す）。

## 集計する

```sh
node docs/cycles/cycle-320/measure/report.mjs docs/cycles/cycle-320/measure/after
```

1行に1つの束（ファイル・入力・間隔・ずれ・2打目の押し方）を JSON で出し（数えるのは数える行。欄の意味は `report.mjs` の頭の注）、そのあとに条件7・D5 の合否の行を1行に1つ出す。

- **押し方**: 束の `mode` は回の名の最後の欄（`same`・`aim`・`hold`・`hold-aim`・`hold-out`・`d1`・`read`）である。条件7 の表に写す落ちた先の数は `same` の束から読み、狙った2打目と、守りを試すために置いた押し（`hold` など）と、診断のマウスの `d1` と、害の確かめの組（`read`・`hold-out`）の数は、その押し方の束に出る。
- **落ちた先**: 束の落ちた先（`groups`・`marked`・`material`・`fellFar10`）は、どれも `q` の押しから `landedOf` で決める（上の「働いたかと落ちた先」）。`groups` には、要約の `s` の組のほかに、押し下げも `click` も切り替わる前の画面のものだった押し（`before`）と、2打目の押し下げが無い押し（`noDown`。狙った2打目で的が無く送らなかった押しを含む）が入る。走査の `marked` は `q` の `downGap` で 150ms の側を越えた押しを見分け、その数が要約の `x` と違う行を `markedDiffers` に数える（0 のはずで、0 でなければ PM に報告する）。`fellFar10` は、タッチの同じ点の押しで2打目が寄せで落ち、その組まで 10px 以上だった押しの数で、道具の押しの面は半辺 10px なので 0 のはずで、0 でなければ PM に報告する。
- **B-620 の材料**（`material`）: 診断の答え→次の問の2打目のうち、連続と数えられない押し（タッチは1打目の離しからの差 `releaseGap` が 300ms 以上で、守りの `TOUCH_CONSECUTIVE_MS` と同じ。マウスは2打目の `detail` が 1）で、次の問の選択肢に落ちた押しの数 `cases`、そのうち次の問に答えを入れた数 `answered`、その押しのある回の名 `runs` を束ごとに出す。守りはこの押しを連続の押しと数えずに受けるので、守りで塞げない二度押しの2打目が次の問に落ちた件である（t5a-design.md 4-9 の「守りのあとの押し」）。数えるのは二度押しの2打目として送る押し方（`same`・`d1`）だけで、守りの受ける側を試すために道具が組んだ押し（`read`・`hold-out`）は入らない。窓の守りの3つの切り替わりの空振りでないことの対の押し（`q` の `pair`。1打目から 900ms のあとに2打目と同じ点などを押す）も入らない。t5a-design.md 8章の5 は3つの切り替わりの窓のあとの数を D5 の 900ms の回から写すと決めており（下の合否の行の `d5-after`）、対は2打目が働かなかった回（送らなかった回を含む）にだけ送るので、その回の数は来訪者の頻度を表さないからである。条件7 の束では、タッチの同じ点の 300・500ms の束（離しから 300ms 以上になった押し）と、マウスの `d1` の束に出る。マウスの同じ点の束は2打目を `detail` 2 で送るので、`detail` が 2 にならなかった押し（要約の `dm`）のほかは出ない。どの束のどの欄を t5a-measure.md に写すかは、t5a-measure.md 0章の「B-620 の材料と写す数」の一覧にある。

### 合否の行

合否の行は、置き場のすべての数える行の `q` から数える（decision-landing.md の「測りの合否（条件7・D5）」）。どの行も `verdict`（行の名）・`transition`（切り替わり）・`input` を持ち、その行の組の押しの数 `seen`・試した回 `tried`・外れた回 `failed` とその一覧 `fails`（`[ファイル, 回の名, 押しの番号, 働いたことの字, …]`、50 件まで）・試さなかった回 `untried`・境目の回 `border`・下限 `lowerOk`（試した回が切り替わりごと・入力ごとに1回以上。タッチの連続の押しの守りは診断12本のそれぞれに1回以上で、届かない本は `missingSlugs`。`d5-inner` は 80px のずれの試した回が1回以上）・合格 `pass`（外れ 0 で、下限を満たすか `status` が `no-target`）・行の様子 `status` を出す。出すと決めた行（decision-landing.md の行 × 守りを掛けた切り替わり × 入力。D5 と hold はタッチだけで、hold は診断の答えと診断の最後の答え→結果だけ。`report.mjs` の `EXPECTED_ROWS`）は、押しが1つも来なくても出し、`status` で、組を走らせなかった行（`not-run`）と、2打目を受けないことを確かめる行で下限に数える試した回が無く、行の組がどれも守る的が無い組だった行（`no-target`）と、ほかの下限に数える試した回が無かった行（`no-qualifying`）と、下限に数える試した回のある行（`tried`）を分ける。下限に数える試した回は、`d5-inner` では 80px のずれの試した回で、ほかの行では試した回のすべてである。`no-qualifying` の行は合格としないので、PM に報告する。どの行も、試した回と落ちた先は「働いたかと落ちた先」の `landedOf` で決める。状態が読めなかった押し（`q` の `worked` が null）は、働いたかが分からないので、どの行にも数えず `worked-unread` の行に出す。

守る的が無い組の扱い（decision-landing.md の「下限」）は、2打目を受けないことを確かめる行（`window`・`consecutive-mouse`・`touch-block`・`d5-inner`・`hold`・`keyboard-pointer`。`report.mjs` の `TARGET_ROWS`）だけに当てる。この行は、行に来た押しの組の数 `pairs` と、そのうち守る的が無い組の一覧 `noTarget`（`[組, 1打目の点からいちばん近い押せるものまでの直線の距離]`）を出す（組の決め方と証しの集め方は `targets.mjs` にある）。2打目を受けることを確かめる行（`pair`・`d5-outer`・`touch-accept`）は、80px の中に押せるものが無くても 120px の所にはありうるので、この扱いを当てず、組も出さない。試した回が無ければ `no-qualifying` になる。組は、操作（D5 も同じ操作）・画面・本・入力・回の名の5つ目の欄（行か結果か切り替わりの名）・切り替わり（`answer`・`start`・`next`・`result`）・帯の番号を `|` でつないだ字で、`keyboard-pointer` は `keyboard|画面|本|入力|切り替わり`。同じ組は、間隔・ずれ・押し方によらず切り替わったあとの画面（1打目の点から決まる着地）が同じなので、守る的があるかの証しは、置き場のどの押しのものも組ごとに合わせる。証しは、`aim`・`hold-aim` の押しでは的を選んだか（`q` の `aim`）、ほかの押しでは、2打目の `pointerdown` が切り替わったあとの画面に来た押し（`shown` が 1）の `nearest` が 80px 以下か、`keyboard-pointer` では要約の `kb` の的があるか（無ければ最後の欄の距離）である。1つでも的のある証しがあれば的のある組、的の無い証しだけがあれば守る的が無い組で、証しの無い組はどちらでもない。

## 比べる（着地の直しの害の確かめ）

```sh
R=/home/user/yolo-web/tmp/cycle-320/<走りの名>
node docs/cycles/cycle-320/measure/compare.mjs $R/t5a4 $R/after \
  --before-repeat $R/t5a4-2 --after-repeat $R/after-2 \
  --out docs/cycles/cycle-320/measure/compare-<名>.json
```

2つの版（plan-t5a7.md 2b。`t5a4` と `after`）を同じ道具・同じ組・同じ `--seed` で測った置き場を読み、同じ名のファイル（組と画面）の数える行を回の名 `k` で、押しを帯の番号・押しの種類（`q` の `kind`）と、その組の中の何番目かで突き合わせる。直した版では守りが2打目を止めて押しの並びが変わるので、押しの番号では突き合わせない。2打目が働いて画面を切り替えた押し（`q` の `follow`）は、もとの押しをほかの押しと同じくどの線・帯・揺れの見分けにも入れたうえで、その切り替わりを、押しの id に行き先を足した id と、種類 `<押しの種類>><行き先>`（`answer>question`・`answer>result` など）の別の押し（切り替わりの写し。もとの押しも `follow` の欄を持つので、写しは `synthetic` の印で見分ける）として突き合わせ、着地の線（2・3・4・8）と分布に入れる（両方の版で切り替わりのあとの画面なので、2・4 の `shown` の別は持たない）。写しは、もとの押しが道具の1打目が止められた押し（下の `firstBlocked`）でも、着地の線に入れる（plan-t5a7.md 2b の線5。着地の線が見るのは A″ のふるまいで守りの帯と関わらず、件が増える向きなので害を隠さない）。境目の帯の押しは、その押し自身も写しも着地の線に入れる（下の `border`）。押し方は押しごとの `q` の `mode` で読む。`--before-repeat`・`--after-repeat` には、同じ版を同じ種でもう1度走らせた置き場を渡す（揺れる押しを見分けるため。省けば見分けない）。`.json` は Prettier の対象なので、コミットの前に `npm run format` で整える。

出力は1つの JSON で、`--out` を省けば標準出力に書く。`--out` に書いて 1MB を越えるときは、2つの版の置き場にあった操作（`start`・`answers`・`last`・`retry`・`select`・`keyboard` と D5 の各操作）ごとに `<出力の名>-<操作>.json` へ分けて書く（carryover.md の「着地の直しの害の確かめ」）。操作ごとのファイルは、その操作のファイルの件の一覧（下の `unmatched` から `outsideSpanSame` までの一覧と `reachMissingPresses` と `lines`）と分布と `operation` を持ち、件の無い操作も書く。`--out` のファイルには、版と種と、操作によらない `guardChecked`・`emptySpanSame`・`reachMissing` と、操作ごとのファイルの名 `parts`（`{操作: ファイルの名}`）を書く。分けても 1MB を越えるファイルがあれば知らせるので、PM に戻して置き方を決め直す。

- `seed`: 2つの版の頭の行の種の字と、同じか（`same`。どちらかに無ければ false で、選択肢の並びがそろっていないので比べを読まない）。
- `distributions`: 操作（`<組>/<押しの種類>`）ごとの、前と後の送りの量（`sent`）と、着地のあとの第1の組・第2の組までの max(dx, dy)（`reachFirst`・`reachNext`。1度の押しで終わる操作のタッチの回は要約の `n`、ほかは `q` の `reaches`。2打目の `pointerdown` が切り替わりのあとに来た押しだけ）の分布 `{count, nonzero, quantiles: [最小, 10%, 中央, 90%, 最大]}`。組になった押しだけで数える。
- `unmatched`: どちらかの版にしか無いファイル・回・押し（`side` が `before` か `after`）で、前の版が要る線（1・2・4・7）を読めなかったもの。直した版だけで決まる線（3・5・8）には、直した版にしか無い押しも入る（件に `unmatched: true`）。直した版にしか無い押しのうち、切り替わりの写しの件は場所だけを持ち、写しでない押しの件は、落ちた先 `group`（`landedOf` の組）・働いたことの字 `worked`・外れた回か `out`（線1 と同じ外れで、足した組の押しは外れにしない）を持つ。直した版にしか無い押しのうち、境目の帯の押しと道具の1打目が止められた押しは `unmatched` に入れず、`border`・`firstBlocked` の件に `unmatched: true` を付けて出す（前の版にしか無い押しはどれも `unmatched` に入れ、道具の1打目が止められた押しなら `firstBlocked` にも `unmatched: true` を付けて出す）。件ごとに PM が見る。
- `unmatchedOut`: `unmatched` のうち `out` が真の件（直した版にしか無い外れた回）。前の版が無いので線1 に入らないため、別の一覧に出す。件には、線1 と同じく時間で揺れる押しの2回の結果 `timingUnstable` を添える。件ごとに PM が見る。
- `unstable`: 同じ版を同じ種で2回走らせて、送り（`sent` と、`q` の `landing` の `[s0, 範囲の上, 下, 選んだ着地]`）が違った押しと、どちらかの回にしか無い押し（`missing` が、無かった回の `second` か `first`）。`side` と2回の値を出す。2・4・8 の比べから外すのは、両方の回にあって送りが違った押し（`missing` の無い件）の1回目の押しだけである（plan-t5a7.md 2b の「突き合わせ方」と「境目の帯」）。2回目に無い押し（`missing` が `second`）は、着地が揺れた証しではない（タッチの 300ms 前後の答えなどで、2打目が次の問に答えるかが回で分かれ、そこから先の走査の道がずれただけ）ので線に残し、着地の線（2・3・4・8）の件に、2回目に無かった版の一覧 `repeatMissing`（`["before"]`・`["after"]`・両方）を添える。2回目にしか無い押しは、1回目の置き場の比べに入っていない。
- `timingUnstable`: 同じ版を同じ種で2回走らせて、落ちた先（`landedOf` の組）か働いたこと（`q` の `worked`）が変わった押し（時間で揺れる押し。間隔の揺れで、見せる 150ms の内か外か・1打目の互換の事象より先か後かが替わる押し）。`side` と2回の `[組, 働いたことの字]` を出す。どの線からも外さず、線1 の件がどちらかの版の時間で揺れる押しなら、件の `timingUnstable` に版ごとの2回の結果を添える（揺れで外すと、直した版で新しく出た外れを隠しうるため。PM が件ごとに見る）。
- **境目の帯**（plan-t5a7.md 2b）: 帯は押しの単位で当て、`records.mjs` の `guardBand` で、守りを掛けた切り替わりのあとの押しを、守りが受けないと決めた押し（`block`）・受けると決めた押し（`accept`）・帯の押し（`border`）に分ける。窓の守りは `detail` によらず、起点からの差が 650ms 未満かつ起点の点から 84px 以下なら `block`、750ms 以上か 116px 以上なら `accept`。連続の押しの守りは、タッチは直前の離しからの差が 280ms 未満かつ起点から 650ms 未満かつ 84px 以下なら `block`、離しから 320ms 以上か起点から 750ms 以上か 116px 以上なら `accept`、マウスは `detail` 2 以上かつ 650ms 未満かつ 100px 以下なら `block`、`detail` 1 か 750ms 以上か 100px を越えるなら `accept`。そのあいだが `border`（84px と 116px は、境目の 100px からタッチの調整が寄せる最大の 16px を引いた値と足した値。マウスは調整で寄らないので 100px で分ける）。`read`・`hold-out` は `accept`、`hold`・`hold-aim` は `block` とする。
- `firstBlocked`: 道具の1打目が守りに止められた押し（`q` の `firstTook` が 0）。`q` の `previous` を `guardBand` で分け、`block` なら決めどおり（`byDesign`）、`border` なら帯、`accept` か守りの無い起点なら直した版の押しを `lines.guardStopped` にも入れる。どれもほかの線の比べから外す。片方の版にしか無い押しの件は `unmatched: true` を持つ。この押しが切り替えた画面の写しは線に入れる。
- `border`: 帯の押し。前と後の帯 `guard`（`[前の版, 直した版]` の `block`・`accept`・`border`。前の版に組の押しが無ければ前は `null`）・`downGap`・`releaseGap`・`downDistance` と働いたかを出す。帯の押しを外すのは、守りの判定で決まる線（1・5・7）だけである。2つの版を比べる線 1・7 は、どちらかの版で帯なら外し、直した版だけで決まる線 5 は、直した版の押しが帯のときだけ外す（前の版だけが帯で直した版が `accept` の押しは、線5 に入る）。着地の線（2・3・4・8）には、帯の押しも、その押しが切り替えた画面の写しも、ほかの押しと同じく入れる（plan-t5a7.md 2b の「境目の帯」。押しの着地は1打目が起こすもので、2打目が帯に入るかと関わらない）。空振りでないことの対の押しは、自分の1打目からの差で読むので、2打目が帯でも線5 に入る。直した版にしか無い押しの件は `unmatched: true` を持つ。
- `landingPointDiffers`: 2つの版で着地に使った click が違う押し（5ea1ab89 はいちばん新しい click から、直した版は画面を切り替えた click から点を取る）。走査では前の着地の違いで押す点そのものが版ごとに違うので、点どうしでなく、着地に使った点（`q` の `landing` の点）のその版の1打目の点（`q` の `point`）からのずれ（`offsets`。点が無ければ `none`）で比べる。2打目が切り替えた画面は、どちらの版もその切り替わりを起こした2打目の click から点を取るので、点そのもの（`points`）で比べる。2・4 の比べから外す。
- `reachMissing`・`reachMissingPresses`: 線2 で読む押し（2打目の `pointerdown` が両方の版で切り替わりのあとに来た押しと、2打目が切り替えた画面。切り替わらない語の選択の対は入れない）のうち、着地のあとの隔たりがどちらかの版に無かった押しの数と、その件（どの版に無かったかの `sides`）。隔たりの無い押しは、2打目が、1打目の着地のあとの最初のフレームより先に画面を替えた押し（来訪者が1打目だけの画面を見なかった押し）で、線2 と `reachFirst`・`reachNext` の分布と、線4 の `still`・`far`・`farEdge` を読めないので、黙って抜けないようここに数える。別の理由の欠けが混ざっていないかを件で見るため、0 でなければ PM が件を見る。`--out` を操作ごとに分けたときも、数は `--out` のファイルに書く。
- `outsideSpanSame`・`emptySpanSame`: 線3 に数えない押し。直した版で範囲の外に着いたが、前の版でも同じ押しで範囲の外の同じ着地だった押しの一覧（A″ と関わりなく、基準の送りのまま範囲の外に着く作り。「外れた件の判断」の材料）と、前の版でも範囲が空だった押しの数。
- `guardChecked`: 害の線 5 の試した押しの数。`<組>|<切り替わり>|<入力>` ごとに、その組を走らせた押しの数 `covered`・試した押し `tried`・試さなかった押し `untried`・止められた押し `stopped` と、下限 `lowerOk`（試した押しが1回以上。本や画面ごとではない）と、様子 `status`（組を走らせなかった `not-run`、試した押しの無かった `no-qualifying`、`tried`）。どの組も守りが受けるべき押しなので、守る的が無い組の扱い（decision-landing.md の「下限」）は当てず（plan-t5a7.md 2b の 5）、`no-qualifying` の組は合格とせず PM に報告する。出すと決めた組（窓の守りの 750ms 以上は3つの切り替わり × タッチ・マウス、116px 以上は3つの切り替わり × タッチ、連続の押しの守りのタッチとマウス、`read` のタッチとマウス、`shown` の診断の答えと結果 × タッチ。`compare.mjs` の `EXPECTED_SETS`）は、押しが来なくても出す。組は、窓の守りの 750ms 以上（`window-late`。空振りでないことの対の押し（守る的が無い狙った2打目の `nearest` の対を含む）と D5 の 900ms）と 116px 以上（`window-far`。D5 の 120px のずれ）、連続の押しの守りのタッチ（`touch-consecutive`）とマウス（`mouse-consecutive`）、読んでから答える押し（`read`）、見せる間に押し下げる受ける側（`shown`。`hold-out`）。切り替わりは `start`・`next`・`result`・`answer`。試した押しは、2打目の落ちた先（`landedOf`。押し下げが切り替わりの前で click が切り替わったあとの画面に届いた押しは、`shown` の組に限らず click の的）が、窓の守りと最後の答えの `shown` では切り替わったあとの画面の押せるもの（対の押しは押せるものの上で1打目から 750ms 以上）、連続の押しの守りと `read` と診断の答えの `shown` では次の問の選択肢だった押しである（働いたかはどの組も押しのあとの状態で決める）。`lines.newOut` は、この足した組の押し（`read`・`hold-out`・D5 の 116px 以上のずれ）を数えない。
