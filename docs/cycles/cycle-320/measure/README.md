# T5a-7 の二度押しの測りの道具と記録

[t5a-design.md](../../cycle-316/t5a-design.md) 6章 条件7 と [cycle-318/device-triage.md](../../cycle-318/device-triage.md) D5 の二度押しの測りの道具と、その記録（`.jsonl`）を置く。手順の文は [t5a-measure.md](../../cycle-316/t5a-measure.md) 0章・5章にあり、道具はその文に沿って組んだ。

**状態**: この道具は、決め直した着地の作りに合わせる要件（[carryover.md](../carryover.md) の「測りの道具」）をまだ持たない。それを足してレビューを通すまで、条件7・D5 の測りに使わない。

## ここに置く理由

この道具と記録は、cycle-320 と次のサイクルの文書（t5a-measure.md の条件7・D5 の表、外れた件の判断、T5a-8 の測り直し）に書く数の出どころで、その数をセッションを越えて確かめ直すためのサイクルの記録である。主の木の `tmp/` はセッションを越えて残らず、別のブランチへの push はこのサイクルの作業ブランチの決まりに当たるので、`docs/cycles/cycle-320/measure/` にコミットする（[index.md](../index.md) の「検討した他の選択肢と判断理由」）。`.claude/rules/doc-directory.md` の「`docs/cycles/` にはサイクルドキュメント以外は保存しない」は、サイクルに属さないもの（計画書・調べものの結果・一般の文書）を置かせないための決まりと読む。ここの道具と記録はサイクルの外では使わないので、サイクルの記録の一部である。

- 道具は ESM の `.mjs` で、`npm run lint` と `npm run format:check` の対象になり、どちらも通す。
- 記録は `.jsonl` にする。Prettier は `.jsonl` の書式を知らず（`prettier --file-info` の `inferredParser` が `null`）、`prettier --check .` はディレクトリを広げるときに飛ばすので、道具が書いたままの1行1回の形が保てる。`.json` は対象になるので、記録には使わない（1行1回の形を持たない比べの出力だけを `.json` にし、コミットの前に `npm run format` で整える。下の上限の箇条）。
- 記録は、すべての回を回ごとの要約で置き、押しごとの記録は、変更後の版の判断（[plan-t5a7.md](../plan-t5a7.md) 5）に要る回と、どちらの版でも誤りで終わった回だけを置く。判断が押しごとに読むのは変更後の版の件だけで、基準の版の数は比べるためのもの（要約から出す）なので、道具は着地の関数を持たない版（頭の行の `landing` が false）では、誤りで終わった回のほかの押しを置かない。誤りで終わった回の押しは、誤りの原因を確かめるために置く（続きの測りで測り終えた回を飛ばすかは、要約の行だけで決める）。ファイルは版（置き場）と操作と画面で分ける。置き方は plan-t5a7.md 3 の「記録の形と上限」のとおりである。
  - 木に残すのは、変更後の版の置き場（要約と押しごとの記録）である。T5a-8 の測り直しは、T5a-8 の版の置き場 `t5a8` に測り、測り終えたら、測り直した組と画面と同じ名の `after` のファイル（`<組>-<画面>.jsonl` と `<組>-<画面>.presses.jsonl`）を木から消す（履歴には残る）。版の指紋がファイルの置き場ごとにそろうよう、`t5a8` の記録を `after` に写さない。
  - 基準の版の置き場（`base`）は、測りが日をまたいでも続きから測れるよう、測っているあいだはここにコミットして push する。続きから測る道筋は要約の数える行で回を飛ばすので、押しごとの記録が無くても変わらない。測り終えたら、`report.mjs` の集計を t5a-measure.md に表として写してから、置き場を木から消す（履歴には残る）。
  - 上限は1ファイル 1MB、サイクルを閉じるときの木で合計 4MB、木から消した記録を含めて履歴に入る量の合計 15MB で、後のサイクルがリポジトリを取り直す重さを抑えるための予算である（決め方は plan-t5a7.md 3）。履歴に入る量は、ここの `.jsonl`（測りの記録）のうちコミットしたことのあるすべての blob（同じファイルの版ごとに1つ）の生のバイト数の合計で数える。「着地の直しの害の確かめ」の比べの出力（[carryover.md](../carryover.md)）は `.json` で置き、この数えにも上限にも入れない。数えるコマンドと見積もりの内訳は plan-t5a7.md 3 にある。道具は 1MB を越えたファイルを終わりに知らせる。上限を越える見込みになったときは PM に報告して形を決め直す。
- 要約の行と押しごとの記録は、道具が測りながら書いたままのもので、ほかの所の生の記録から作ったものではない。数え上げ（t5a-measure.md の表の数）は `report.mjs` がここの要約から出すので、同じ数をいつでも出し直せる。
- 像と生のログは置かない。試しの走りの記録は `tmp/` に置き、ここには置かない。

| 名      | もとのコミット                             | 中身                                                                                                                                                                                                                             |
| ------- | ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `after` | `5ea1ab898337274d7b799f7ba696a47f858cff2b` | 変更後の版。T5a-4 までを取り込んだコミット（plan-t5a7.md 3 の「版を作るコミットは固定する」）                                                                                                                                    |

```sh
node docs/cycles/cycle-320/measure/version.mjs build --label base --commit 2db1c7d9b5ac358c76e11ea3176f9bb94ddbdcbe
node docs/cycles/cycle-320/measure/version.mjs build --label after --commit 5ea1ab898337274d7b799f7ba696a47f858cff2b
```

- ファイルを重ねる版は `--overlay <コミット>:<パス>` を足す（例: `--commit fff3d31f --overlay da102212:src/play/quiz/data/character-personality.ts`）。1つのビルドは2〜3分で、`.next` が約 1.3GB になる。
- 書き出す場所（`tmp/measure-builds/<名>`）がもうあれば止まる。作り直すときは `--replace` を足す（その場所と別の索引を消してから書き出す）。
- `node_modules` はリポジトリのものをハードリンクで写すので、版のコミットの `package-lock.json` の blob がリポジトリの `package-lock.json` と違えば止まる（2db1c7d9 と 5ea1ab89 はどちらも `248519ea`）。
- 履歴が浅いクローン（`git rev-parse --is-shallow-repository` が `true`）では、先に `git fetch --unshallow origin main design-rollout` で履歴を深くする。

### 指紋

`tmp/measure-builds/<名>/fingerprint.json` に、もとのコミットと重ねたファイル、ソースの木のハッシュ、`package-lock.json` の blob（`lock`）、Node と npm の版、書き出した場所（`buildPath`）、`.next/static/chunks` のファイルの名前と大きさの一覧と、その SHA-256 の頭 16 字（`chunksDigest`）を書く。`measure.mjs` は、測り始めるときに、この指紋を記録の置き場の `fingerprint.jsonl` の1行目に写す。

| 名      | 木のハッシュ                               | lock       | Node     | npm    | チャンク | chunksDigest       |
| ------- | ------------------------------------------ | ---------- | -------- | ------ | -------- | ------------------ |
| `base`  | `367f5d377ed8c3ae15775ecbcbe6447343daf87a` | `248519ea` | v22.23.4 | 10.9.9 | 170      | `f49483997b5d6a98` |
| `after` | `1d5cfedfcd6379aad3205266e39b49a08d8646ec` | `248519ea` | v22.23.4 | 10.9.9 | 175      | `e9bd6b59a47b9e84` |

- **書き出す場所は名で決める**: 書き出した版はリポジトリの下にあるので、Next.js はリポジトリの根の `package-lock.json` を見てそこを Turbopack の根にし（ビルドの記録の「We detected multiple lockfiles」）、チャンクには根からの道（`/ROOT/tmp/measure-builds/<名>/node_modules/…`）が入る。道が違えば、同じコミットでもチャンクの名前（中身のハッシュ）がすべて変わる（`tmp/` の別々の2つの場所で HEAD 5ea1ab89 をビルドすると、175 のチャンクの名前がすべて違った）。同じ場所に書き出し直してビルドすると、チャンクの名前と大きさは一致した（5ea1ab89 の 175 と 2db1c7d9 の 170 を `--replace` で作り直しても、すべて一致した）。そこで `version.mjs` は書き出す場所を `tmp/measure-builds/<名>` に決め、指紋は木のハッシュ・`package-lock.json`・Node と npm の版・場所・チャンクの一覧で組む。
- **GA の release の字**: ビルドの前の `generate:release-id` は、環境の `VERCEL_GIT_COMMIT_SHA` が無ければ `git rev-parse HEAD` を読む。書き出した版は主の木の下にあるので、そのままでは主の木の HEAD を拾い、主の木が進むとチャンクの中身が変わる。`version.mjs` は、もとのコミットとその日付を `VERCEL_GIT_COMMIT_SHA`・`VERCEL_GIT_COMMIT_DATE` で渡す。
- **見出しの Web フォント**: `next/font/google` の Zen Antique はビルドのときに取りに行く。取ったファイルが変われば CSS とメディアのチャンクが変わり、指紋の比べで分かる。

### 確かめ直す

続きを測る前に版を作り直し（`--replace`）、`node docs/cycles/cycle-320/measure/version.mjs compare docs/cycles/cycle-320/measure/<名>/fingerprint.jsonl tmp/measure-builds/<名>/fingerprint.json` で比べる（`.jsonl` は最後の行、つまりいま続けている版を読む）。`measure.mjs` も測り始めるときに同じ比べをし、次のように動く（plan-t5a7.md 3 の「日をまたぐ記録と版」）。

| 違うもの                  | 道具                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | 扱い                                                                                                                             |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 木のハッシュ              | 止まる                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | 作り直しの誤りなので、記録したコミットから作り直す                                                                               |
| `package-lock.json`       | 止まる                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | 依存が違うので、記録の依存で作り直す                                                                                             |
| Node・npm                 | 止まる                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | 記録の版で作り直して比べ直す                                                                                                     |
| チャンクだけ              | 止まって、違うチャンクの名を出す。PM が「続ける」と決めたときだけ、`--accept-chunks "<決定>"` を渡して続ける。道具は新しい指紋を決定とともに `fingerprint.jsonl` に足す。どのファイルも、回を測り始めるときに、そのファイルのチャンク（頭の行か最後の `accept` の行の `chunksDigest`）をいまの版のチャンクと比べ、違えば `fingerprint.jsonl` の決定から `accept` の行を足してから測る（どの呼び出しで受け入れたかによらない。決定の記録でいまのチャンクまでたどれなければ止まる。測り終えたファイルは書き換えない） | PM に報告する。PM は、違うチャンクが診断のページのコードを含むかで、続けるか、そのチャンクが掛かる操作を測り直すかを決める       |
| ブラウザの版・道具の blob | 同じ組（操作。D5 は `<操作>-d5`）のファイルのどれかと違えば止まる                                                                                                                                                                                                                                                                                                                                                                                                                                                   | その操作と版の組を、新しい置き場で1つのブラウザの版と1つの道具の blob ですべて測り直す（古い置き場の組のファイルは数に使わない） |

ブラウザの版は版ごとではなく組ごとにそろえるので、組が違えばブラウザの版が違ってもよい。測っている途中で道具を書き換えない（道具の blob は `measure.mjs`・`version.mjs`・`knowledge.mjs` の3つで、どれかが替われば、その時までに測った組は続けられない）。

## サーバー

基準の版はポート 3111、変更後の版はポート 3112 で、版のディレクトリから `next start` を起こす。ほかの作業者のプロセスを巻き込まないよう、自分のグループだけを止める形で起こし、止める（`docs/knowledge/playwright-mcp.md` の「バックグラウンドのプロセスを起こして止める」）。

```sh
# 起こす（ログに Ready が出るまで、上限を決めて待つ）
DIR="$PWD/tmp/<自分の作業の名前>/server-after"; mkdir -p "$DIR"
cd tmp/measure-builds/after && PORT=3112 setsid bash -c 'echo $$ > "$0/server.pgid"; exec npx next start' "$DIR" > "$DIR/server.log" 2>&1 < /dev/null &
# 止めて、グループのプロセスが 0 でポートが空いたことを確かめる
kill -- -"$(cat "$DIR/server.pgid")"
ps -eo pgid= | awk -v g="$(cat "$DIR/server.pgid")" '$1 == g' | wc -l
lsof -nP -iTCP:3112 -sTCP:LISTEN
```

## 測る

```sh
node docs/cycles/cycle-320/measure/measure.mjs --base http://localhost:3112 --version tmp/measure-builds/after \
  --op <操作> --out-dir docs/cycles/cycle-320/measure/after --landing on [絞り込み]
node docs/cycles/cycle-320/measure/report.mjs docs/cycles/cycle-320/measure/after
```

基準の版は `--base http://localhost:3111 --version tmp/measure-builds/base --out-dir docs/cycles/cycle-320/measure/base --landing off` で測る。`--landing` は、版が着地の関数を持つかの期待（変更後の版と T5a-8 の版は `on`、基準の版は `off`）で、道具が版のソースから見分けた値と違えば、測り始める前に、何も書かずに止まる（終わりの値 3。下の「着地の関数の記録の取り方」）。

| 操作      | 1回                                                                                                      | 省いたときの範囲（条件7）                                                                             |
| --------- | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `start`   | 開始の画面で「はじめる」を二度押しする                                                                   | 15本 × 0・90・150・300・500ms × 6画面 × タッチ・マウス                                                |
| `answers` | 「はじめる」を `element.click()` で押し、全問を最初の行か最後の行で二度押しして解き切る（5-2 の走査）    | 15本 × 最初の行・最後の行 × 90・300ms × 6画面 × タッチ・マウス                                        |
| `last`    | 最後の問まで1度ずつ押して進め、最後の答え（知識クイズは最後の「次へ」）を二度押しする（5-3）             | 15本（`--answers` を渡せば extra を持つ3本は全結果）× 0・90・150・300・500ms × 6画面 × タッチ・マウス |
| `retry`   | 結果まで解き、「もう一度挑戦する」の中心を画面の上から決めた高さに送って二度押しする                     | 15本 × 画面の上端 24px から下端 −24px までの 24px 刻み × 90・300ms × 6画面 × タッチ・マウス           |
| `select`  | 「はじめる」を `element.click()` で押し、1問目の見出しの最初の字の上でダブルクリックする（語の選択の対） | 15本 × 90・300ms × 6画面 × マウス                                                                     |

- 6画面は 375×550・320×550・1280×800・375×800・740×360・375×550 の 200%（`--viewports` では `375x550@200`）。
- D5 は `--offsets 0:-20,0:-10,0:10,0:20,-10:0,10:0` を渡す。ずれを渡すと、省いたときの画面は 375×550・320×550、入力はタッチ、間隔は 90・300ms になり、組の名は `<操作>-d5` になる。`retry` と `select` は D5 に入らない。
- extra を持つ3本の答えの組は `npx tsx docs/cycles/cycle-320/measure/answers.mjs tmp/measure-builds/after character-fortune science-thinking japanese-culture > tmp/<自分の作業の名前>/answers.jsonl` で作り、`last` に `--answers` で渡す（2つの版で問と配点は同じ。`git diff 2db1c7d9 5ea1ab89 -- src/play/quiz/data src/play/quiz/scoring.ts` が空）。
- 1回を測り終えるたびに、押しごとの記録（あれば）と要約の行を足す。数える行（`f`）のある回は飛ばすので、止まったら同じコマンドで続きから測れる。書いている途中で止まって最後の行が欠けたときは、道具が次に開くときにその行を切り落とし、要約の行の無い回の押しごとの記録も除いてから、その回を測り直す。
- **送り直し**: 1度の押しで終わる操作（`start`・`last`・`retry`）は、実際の間隔が 150ms の側を越えた回（90ms の指定で 150ms 以上、300ms の指定で 150ms 未満）、マウスの2打目の `mousedown` の `detail` が 2 でない回、答えの組で回って組と違う結果に着いた回を、新しい文脈で送り直す。`select` は `detail` だけで送り直す。走査（`answers`）は、5-2 の確かめが合わない走査を1度だけやり直す。送り直しは最初の回のほかに3度までで、3度とも越えた回は理由を `r` に持ったまま数える。
- **誤りで終わった回**: 1つの回が誤り（道具か環境の不具合）で終われば、続けてもう1度だけ測り、2度とも誤りなら数えないまま次の回へ進む。誤りの行は送り直しの数に入れない。終わりに、誤りで終わったまま残った回を出して、終わりの値を 1 にする。同じコマンドをもう一度走らせれば、その回だけを測り直す。コミットしたファイルの新しい版を作らないよう、担当はコミットの前にそうする（plan-t5a7.md 3 の「日をまたぐ記録と版」）。着地の止め所が置けない、版や指紋が合わないなど、測りを続けられない誤りでは、すぐに止まる（終わりの値 3）。

## 記録の形

置き場 `<名>/` の中に、次のファイルを置く。組は操作の名（D5 は `<操作>-d5`）、画面は `375x550`（200% は `375x550-200`）。

- `fingerprint.jsonl`: 1行目が測り始めた版の指紋（`fingerprint.json` と同じ形に、写した時刻 `at`）。2行目からは、チャンクだけが違って PM が続けると決めたときの版の指紋で、決定（`decision`）と、それまでの `chunksDigest`（`previous`）を持つ。
- `<組>-<画面>.jsonl`: 1行目は頭の行（`"type": "head"`。操作・D5 か・木のハッシュ・`chunksDigest`・ブラウザの版・道具の blob（`measure`・`version`・`knowledge`）・着地の止め所を置いたか `landing`）。チャンクを受け入れたあとに初めて回を足すところには、`fingerprint.jsonl` の決定を写した `"type": "accept"` の行（`chunksDigest`・`decision`・`at`）が入る。ほかの行は回の要約で、1つの回の測りごと（送り直しと誤りを含む）に1行。
- `<組>-<画面>.presses.jsonl`: 押しごとの記録。変更後の版の判断に要る押しと、どちらの版でも誤りで終わった回の押しだけ（基準の版の置き場では、誤りで終わった回が無ければこのファイルはできない）。

### 回の要約

どの操作にも共通する欄:

- `k`: 回の名（本・入力・間隔・ずれ・行か高さか結果。操作と画面はファイルの名にある）。`a` はその回の何度目の測りか、`f: 1` はその回の数える行。`r` は送り直した理由か、上限まで越えたまま数えた理由（`crossed`・`detail`・`result`・`check`・`error`）。`e` は誤りの字、`ms` は1回の壁時計の時間、`p` はこの回の押しごとの記録の数、`v` は2打目で離れたときの離れ方（`link:<道>` か `retry`）。

1度の押しで終わる操作（`start`・`last`・`retry`・`select`）の欄:

- `g`: 1打目と2打目の押し下げの実際の間隔（タッチは `touchstart`、マウスは `mousedown`）。
- `s`: 2打目の `click` の落ちた先の組。`link`・`summary`・`button`・`pressable` が第1の組、`next` は次の問（1打目の問より後の問。「はじめる」と「もう一度挑戦する」のあとは1問目）の選択肢、`choice` は同じ問の選択肢、`start` は「はじめる」、`text` は押せない字、`none` は要素の無い所。`null` は2打目の `click` が無かった回。
- `d`・`w`（マウス）: 2打目の `mousedown` の `detail` と、記録の時点の選択の字（頭の 12 字）。語の選択の数は `d` が 2 の回だけで数える。
- `n`（タッチ）: 2打目の `pointerdown` を受けた時の組みでの、1打目の点から最も近い押せるものの押せる範囲までの横と縦の隔たり。`[第1の組, 問の選択肢, 「はじめる」]` の順で、それぞれ `[dx, dy, "<組>:<名前の頭の 10 字>"]` か `null`（その組の押せるものが無い）。「はじめる」は画面にあるときだけ。`n2`（D5）は、2打目の点からの同じ隔たり。2打目がページを移ったあとに来て点を持たない回は `null`。読み方は t5a-measure.md 0章の「タッチの調整」。
  - **取る時**: Chromium は受け手のあるページで、2打目の `pointerdown` を出す前の組みで点を寄せる（`docs/knowledge/input-events-and-guards.md` §8 の「寄せと落ち先が決まる時と、隔たりを取る時」）。道具は `window` の捕捉の段階の `pointerdown` の受け手を、ブラウザの文脈の初期化スクリプトでページの読み込みの前に置き、寄せたすぐあと、ページの受け手が組みを変える前の組みで取る。
  - **押せるもの**: 着地の関数と同じ集め方（`a[href]`・`button`・`summary`・入力・`label`・`[role="button"]`・`[role="link"]`）で、Chromium のタッチの調整の候補より狭い。Chromium は、マウスでフォーカスできる要素（問の見出し `h2[tabindex="-1"]`・結果のボックス `section[tabindex="-1"]`）や `:hover`・`:active` で見た目が変わる要素にも寄せうる。それらが記録の押せるものより点に近い回では、Chromium の寄せる先は記録の「最も近い押せるもの」と違いうる（そこへ寄っても答えは入らない）。
  - **押せる範囲**: `data-hit-area="after"` の要素（問の選択肢など）は `::after` で押せる範囲を位置を決めた祖先（行の `li`）に広げているので、祖先の内側の箱（`getBoundingClientRect()` から `getComputedStyle` の `border-*-width` を引いた padding box）で取る。行の下の罫線 1px は押せない。ほかの要素は要素の箱で取る。
  - 最も近いものは `max(dx, dy)` で決める。
- `l`（変更後の版）: 2打目が受けた画面（2打目の押し下げの時点までの最後の着地。2打目より前に画面が替わっていなければ、2打目のあとの最初の着地）の着地の関数の記録で、`[範囲の中に点の真下から第1の組を外す送りがあったか, 両方の組を外す送りがあったか, 範囲の中で点から第1の組を最も離せたときの max(dx, dy), 両方の組の近いほうを最も離せたときの max(dx, dy)]`（隔たりは 100 で頭打ち）。避けるものの矩形は `n` と同じ押せる範囲で数える（下の「着地の関数の記録の取り方」）。基準の版は着地の関数を持たないので、`l` を持たない。
  - 「避けられた」かは、最も離せたときの値（3つ目・4つ目）で決める（plan-t5a7.md 3。16px 以上で避けられた件）。真下を外す送りがあったか（1つ目・2つ目）は、点を行の罫線の上に置くだけの送りも含むので、避けられたかの判断には使わない。`report.mjs` もこの2つを数えない。
  - 隔たりは、着地の関数が受けた1打目の点から数える。D5 の回では、ずらした2打目の点が避けられたかを表さない。
- `hu`（変更後の版）: 着地の記録で、`data-hit-area="after"` の祖先の箱のうち関数の矩形と一致せず、押せる範囲に置き換えられなかった数。`l` を持つ行は 0 でも持つ。下の「着地の関数の記録の取り方」。
- `cut`: 着地のあとの最初のフレームのどれかで、`h1`・問の見出し・結果の名前のどれかの行の箱を画面の上端が横切った。`lo`: 結果の名前の下端が画面の下端から 8px 上より下にあった。`ins`: extra の差し込みが画面の中に入った。`h1a`: 「もう一度挑戦する」のあとに開始の画面の `h1` が丸ごと画面の上端より上にあった。`at: 0`: 「もう一度挑戦する」の中心が決めた高さに着かなかった。
- `rv`（結果に切り替わった回。`last`）: 結果への切り替わりの着地のあとの最初のフレームの `[結果のボックスの上端, 結果の名前の下端]`（画面の上端からの px。t5a-design.md 6章 条件7 の「結果の名前が見えること」）。`re`（変更後の版）: 結果への切り替わりの着地の記録（そのフレームの1つ前のフレーム、無ければ押しの頭より後で、そのフレームより前の最後の着地）で、ページが送れる範囲で打ち切った範囲が空だった（着地の関数が基準の送り s0 にした）なら 1、空でなければ 0。前の画面の着地を結果の着地と取り違えないよう、1つ前のフレームより前の着地は見ない。そうした着地の記録が無ければ `re` を持たない（基準の版は着地の関数を持たないので、どの回も持たない）。
- `res`（`last` の答えの組の回）: 着いた結果の名前の字から決めた結果の id（決められなければ `?`）。`bs`（`last`）: 最後の押しの前の1度ずつの押しのうち、来訪者の送りを挟んだ押しの順の番号と送りの量。

走査（`answers`）の欄:

- `np`: 押しの数。`c`: 2打目の落ちた先の組ごとの押しの数（組の名は上の `s` と同じ）。`cm`: 実際の間隔が 150ms の側を越えた押しの、同じ数（`c` に入れない。90・300ms の間隔ごとの比べから外し、確かめと落ち先には残す。plan-t5a7.md 4 の「間隔」）。`x`: 越えた押しの数。`dm`: マウスの2打目の `detail` が 2 でない押しの数。`w`: 語が選ばれた押しの数（`detail` が 2 の押しだけ）。`cut`: 切れた見出しのあった押しの数。
- `n`（タッチ）: 1打目の点（D5 は2打目の点も）から最も近い第1の組か問の選択肢の `max(dx, dy)` が 0 より大きく 20 以下の押しの、`[押しの番号, 帯の番号, 2打目の落ちた先の組, 1打目の点からの隔たり, 2打目の点からの隔たり, 着地の記録, 押しの種類, 押せる範囲に置き換えられなかった祖先の箱の数, そのうちの問の選択肢の行の数]`。落ちた先の組は上の `s` と同じ字、隔たりは上の `n`・`n2` と同じ形（ずれの無い回は2打目の点からの隔たりが `null`）、着地の記録は上の `l` と同じ形（基準の版は `null`）、押しの種類は押しごとの記録の `kind`（`answer`・`next`）、最後の2つは押しごとの記録の `land` の最後の2つと同じ数（基準の版は `null`）。0 の押しは点の真下に押せるものがあり、`c` に入る。
- `ck`: 5-2 の確かめ `[1打目で答えた問の数, X, S, 和が問の数に等しければ 1]`。
- `rv`・`re`・`lo`: 走査が結果に切り替わった押し（最後の答え。知識クイズは最後の「次へ」）の、上と同じ値と印。

`report.mjs` は、結果の名前の見え方（t5a-design.md 6章 条件7）を束（画面）ごとの `resultView` に分けて出す。`expected`・`missing` は、結果に切り替わるはずの回（`last` のどの回と、2打目で離れなかった走査）の数と、そのうち `rv` の無い回の数で、`missing` は 0 のはずである。`spanEmpty`・`emptyRuns` は、範囲が空で s0 にした回（`re` が 1。t5a-design.md 4-9 が受け入れた回）の数と、その回ごとの `[回の名, ボックスの上端, 名前の下端]`（条件7 の「その旨と値」）。`lowInSpan` は、`lo` のある回のうち範囲が空ではなかった回の数で、範囲が空でない回の名前は着地の関数が見せる範囲の中に置くので、変更後の版では欠けか道具の誤りとして判断（plan-t5a7.md 5）に渡す（基準の版は `re` を持たないので、`lo` のある回がすべて入る）。`flags.nameLow` は、1度の押しで終わる操作の回と走査の、範囲が空だった回を含む `lo` の数である。

### 押しごとの記録

1行が1つの押しで、`k`・`a` で回の要約と結び、`why` に置いた理由を持つ: `first`（2打目が第1の組）・`next`（次の問の選択肢。答えの2打目が次の問の選択肢に落ちた押しは、条件7 が数だけを求めるので置かず、要約の `c` に数える）・`selection`（語が選ばれた。`select` では `no-selection`、語が選ばれなかった）・`name-low`（結果の名前の下端が見せる範囲の外）・`insert`（extra の差し込みが画面の中）・`error`（誤りで終わった回の押し。押しの前に誤った回は `i: null` と `error` だけ）。

- `i`: 走査の中の押しの番号。`kind`: `start`・`answer`・`next`・`last-answer`・`last-next`・`retry`・`heading`。`band`: 押した時の帯の番号（開始と結果の画面では `null`）。`pt`: 押した点。`sc`: 押す前の来訪者の送り。`gap`: 実際の間隔。`x`: 実際の間隔が 150ms の側を越えた。`dm`: マウスの2打目の `detail` が 2 でない。
- `c1`・`c2`: 1つ目と2つ目の `click` の `[組, 名前の頭の 16 字（リンクは道）, x, y, 帯の番号]`。`c2` は末尾に、`click` の時点の `scrollY` を持つ。組は `link`・`summary`・`button`・`pressable`（第1の組）、`choice`（問の選択肢）、`start`（「はじめる」）、`text`（押せない字）、`none`。`nc`: `click` の数が 2 でないときの数。`md2`: 2打目の `mousedown` の `detail`。`grp`: 要約の `s` と同じ組。`sel`: 記録の時点の選択の字。`pop`: 開いたタブの行き先。
- `land`（変更後の版だけ）: 着地の関数を呼ぶたびの `[基準の送り s0, 見せる範囲の上, 下, ページが送れる範囲で打ち切った範囲の上, 下, 基準の送りで点の真下に来る組（first・next・null）, clearOfFirst, clearOfBoth, farFirst, farBoth, 選んだ着地, 押せる範囲に置き換えられなかった祖先の箱の数, そのうちの問の選択肢の行の数]`。clearOf・far は要約の `l` と、置き換えられなかった数は要約の `hu` と同じで、選んだ着地は着地のあとの最初のフレームの `scrollY` と、関数を呼んだときの `scrollY` の差。`li`: 要約の `l` に写した呼び出しの番号。
- `fr`: この押しのあいだに画面が替わるたびの、着地のあとの最初のフレーム（`requestAnimationFrame`）の `[段階|帯の番号|答えの有無|「次へ」の有無, scrollY, h1, 問の見出し, 結果の名前, 結果のボックスの上端, 「はじめる」の上端と下端]`。h1・見出し・名前は `[行の箱の上端, 下端, 行の数, 画面の上端が横切った行（無ければ 0）]` か、無ければ 0。
- `near`・`near2`: 要約の `n`・`n2` と同じ（「はじめる」を含めた3つ。2打目の `pointerdown` の時に取る）。`cut`・`lo`・`h1a`・`ins`・`at`: 要約と同じ印。

### 着地の関数の記録の取り方

本番のコードに測りの口を足さずに、変更後の版の `reveal.ts` の着地の関数（`chooseLanding`）の引数を、CDP の Debugger の条件付きの止め所で取る。最小化したチャンクでは、この関数は `revealLanding` の中の関数になり、引数の名前も変わるので、`measure.mjs` はチャンクを読み込むたびに `function(<名>){let{plan:…,point:…,avoidFirst:` の形を探し、その本体の頭に、引数を JSON にして `console.debug` に書き `false` を返す条件の止め所を置く（止まらない）。基準の版のチャンクにはこの形が無いので止め所は置かれないが、比べをそろえるため、Debugger はどちらの版でも有効にする。範囲の中に点の真下を外す送りがあったか（`clearOfFirst`・`clearOfBoth`）と、最も離せたときの隔たり（`farFirst`・`farBoth`）は、引数の矩形と範囲から、関数と同じ1px 刻みで道具が数える。

関数は `data-hit-area="after"` の要素を、位置を決めた祖先の要素の箱（罫線を含む）で渡す。道具は要約の `n` と同じ押せる範囲で数えるため、止め所の条件で、そのときの組みの `data-hit-area="after"` の祖先ごとの `[要素の箱, 押せる範囲, 問の選択肢の行か]` もページから読み（`measure.mjs` の `__yolosHitAreas`）、引数の矩形のうち要素の箱と一致するものを押せる範囲に置き換えてから数える。関数の見方（罫線を押せるものに含める）では真下から外せない送りでも、点が行の罫線の上に来る送りは、道具では真下から外す送りに数える。そうした回の最も離せた隔たりは 1px より小さく、避けられた件（16px 以上）には入らない。

置き換えが外れると、罫線 1px を押せる範囲に含めた値に黙って戻るので、道具は、祖先の箱のうち関数の矩形のどれとも一致しなかった数と、そのうちの問の選択肢の行の数を、着地の記録ごとに残す（押しごとの記録の `land` の最後の2つ、走査の要約の `n` の押しの最後の2つ、1度の押しで終わる操作の要約の `hu`）。`report.mjs` は、置き換えが外れた箱の数を `hitUnmatched` に押しの種類ごとに足す。走査は押しごとの記録に置いた押しと、そこに無い `n` の押しから、1度の押しで終わる操作は `hu` から数えるので、`avoidable` と `at16` に入る押しはどれも数に入る。種類は押しごとの記録（`n` の押しは `n` の記録）の `kind` で、答えは診断の答え（`diagnosis-answer`）と知識クイズの答え（`knowledge-answer`）に分け、1度の押しで終わる操作は操作から決める（`start`・`last-answer`・`last-next`・`retry`・`heading`）。知識クイズの本は `knowledge.mjs` の組で、`measure.mjs` と同じ組で分ける。診断の答えのあとの呼び出しは問のまとまりを関数が避けないもの（`exclude`）に渡し、その問の選択肢の行は一致しないのが正しいので、`diagnosis-answer` は一致しなかった箱のうち問の選択肢の行でないもの（一致しなかった数から、一致しなかった問の行の数を引いた数）を外れに数え、ほかの種類は一致しなかった数をそのまま外れに数える。どちらも負にならず、どの種類も 0 になるはずで、0 でない種類があれば、関数の矩形の取り方が変わったので、PM に報告して道具を直す。要る数（一致しなかった数と、`diagnosis-answer` ではそれに加えて一致しなかった問の行の数）を持たない着地の記録は `hitUnmatched` に入れず、`hitUnrecorded` に数える。1度の押しで終わる操作の `l` があって `hu` の無い行、走査の `n` の押しで押しの種類と2つの数の無いもの、押しごとの記録の `land` で一致しなかった数（12番目）の無いもの、`diagnosis-answer` の `land` で一致しなかった問の行の数（13番目）の無いものがこれにあたる。ほかの種類の `land` は、12番目があれば、13番目が無くても `hitUnmatched` に入る。

着地の記録が黙って欠けないよう、道具は版が着地の関数を持つかを版のソース（`src/lib/reveal.ts` に `export function chooseLanding` があるか）から見分け、測り始める前に `--landing` の期待と比べる。見分けが外れると（着地の作りを決め直して関数の名前や置き場が変わったときなど）、変更後の版が基準の版と見なされ、着地の記録・`re`・押しごとの記録が誤りにならずにすべて欠けるので、食い違えば止まる。持つ版では、測り始める前にビルドのチャンクにこの形があることを確かめ、毎回ページを開いたあとに止め所を置けたことを確かめる。どれかが欠ければ止まる（関数の名前や置き場、最小化の出力が変わったときは、見分けと形を直して道具をレビューに通す）。
