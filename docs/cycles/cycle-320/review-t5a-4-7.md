## 指摘

### 指摘1（中）: 4-10 の表の science-thinking の行で、セルの中の「|」が表の区切りになり、行が壊れている

`docs/cycles/cycle-316/t5a-design.md` の表の行（444行目）に足した「どの名も「〜型|思考者」と、補いの語の終わりで分かれる」の「|」が、エスケープされずに列の区切りとして読まれている。3列の表のこの行が4つのセルになり、整形（prettier）がそれを列として揃えたため、

```
…解き終えた画面の結果の見出し。どの名も「〜型               | 思考者」と、補いの語の終わりで分かれる（…）。「ダ・ヴィンチ型」は…手書きの並びの確かめを同じ語で行う |
```

と「〜型」の後ろに空白の詰め物が入った。GFM では列の数より多いセルは捨てられるので、表として描くと3列目は「…どの名も「〜型」で切れ、「思考者」と、…」から行の終わりまで（「ダ・ヴィンチ型」の中点の折り所と「キュリー型」の説明を含む）が消える。表の全行の3列目の幅も、この詰め物に合わせて書き換わっている。

直し方: セルの中の「|」を `\|` と書く（同じ表の外の項や、前回までのレビューの記録の表と同じ書き方）か、DESIGN.md と同じく「／」で書き、整形をかけ直して表の幅が戻ることを確かめる。

### 指摘2（軽）: スキルの「辞書の補い」の項の「ブラウザが字の所で割ることがない」が言い過ぎ

「語の中の境目を外した長い文節（「ダーウィン型思考者」）も、こうして語と語のあいだで折れ、ブラウザが字の所で割ることがない」とあるが、補いの語そのものが1行に入らない幅では、ブラウザはその語の中で割る。担当の木の `tmp/t5a4-2/h1-before.txt` でも、320px・既定の文字サイズで「アインシュタイ／ン型思考者」と割れており、(a) のあとも「アインシュタイン型」（9字）が入らない幅では同じに割れる（スキルの5の「語が1行に入らないときは、ブラウザがその語の中で折る」のとおり）。「語が1行に収まる幅では、字の所で割らない」のように、5の文と合わせる。

### 指摘3（軽）: 名前（数を添えたもの）の語の切れ目にも効くのかが、文から一つに読めない

(a) はスキルの5（広い文節を分ける語の頭）の決まりとして書かれているが、名前に括弧で数を添えたもの（`splitNameAtWords`）も、同じ語の頭（`wordStartsOf`）と同じ順位（`wordBreakRank`）で分けている。builder が順位の決め方を直すと名前にも効き、5の中だけで直すと名前には効かない。DESIGN.md §4 の名前の決まり（名前の中の語の切れ目で折る）から見れば、補いの語の終わりは名前でも語の切れ目なので、名前にも効かせるのが筋である。今のサイトの名前には当たる所が無い（上の洗い出し）ので来訪者に届く差は今は無いが、builder が迷わないように、スキルの5の新しい文か「辞書の補い」の項に「名前の語の切れ目でも同じ」と添える。
