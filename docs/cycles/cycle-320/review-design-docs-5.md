### 指摘1: T6-6 の完了の条件が、結果への切り替わりの合否を「働いたかの判定」より狭く書いている

場所: carryover-tasks.md の T6 の行の T6-6 の文と、それを引いた t5a-design.md 8章の1。

> 結果への切り替わりの窓の守りの回で2打目が答え・ページの移動・開閉のどれも起こさないこと

- 決定は、窓の守りの回の合否を「働かなかったこと（働いたかの判定）」にそろえた。この判定は7つの事象を見る。答えが入る・URL が変わる・新しいタブが開く・ダウンロードが始まる・`details` の開閉が変わる・段階が変わる・押した要素にフォーカスが移る、である。「画像を保存」「友達に診断を送る」のように答えも URL も変えないボタンは、ダウンロードかフォーカスの移りで読む、とも決めている。
- T6-6 の文は、そのうち3つ（答え・ページの移動・開閉）しか挙げていない。同じ文の前半の「同じ手順と合否でやり直し」とも食い違う。
- T6-6 は、解き終えた画面に保存と共有のボタンを置いたあとに、この測りをやり直すタスクである。狭い3つでは、新しく置くボタンに2打目が落ちてダウンロードや共有が始まっても、フォーカスが移っても、外れに数えない。来訪者の側では、結果を読む前の2打目で画像の保存や共有の画面が勝手に始まる型を、測りが見逃すことになる。
- 6章 条件7 の D9 の行の「答え・移動・開閉」は、B-623（FAQ の `summary` が開く件）に絞った合否なので、この指摘には当たらない。

直し方: T6-6 の文を「結果への切り替わりの窓の守りの回で2打目が働かなかったこと（t5a-design.md 6章 条件7 の『働いたかの判定』。試した回と下限も同じ箇条のとおり）」のように書き直し、t5a-design.md 8章の1の引用も同じ文にする。

## PM が直して閉じるもの（言い回し・置き場所・記録）

- 「下限」の括弧「（タッチの連続の押しの守りは、離しからの測った間隔が 280ms 未満の試した回で数える）」は、受ける側（320〜700ms の帯）にも掛かるように読める。受ける側に掛けると、下限は満たせない。決定・6章 条件7・t5a-measure.md 0章の3か所とも、plan-t5a7.md 3 と同じく「タッチの連続の押しの守りの受けない側は」と書けば、1つの読み方に決まる。受ける側の帯は受ける側の箇条が決めているので、決めごとは変わらない。
- plan-t5a7.md 3 の「記録の形と上限」の要約では、連続の押しの守りの回を「本ごと・入力ごと・間隔ごとに」数える。この「間隔」が指定の間隔とも読める。下限と合否の帯は、マウスでは測った差、タッチでは離しからの測った間隔で決まる。その数を要約から読むことは、同じ箇条の終わりの「下限を要約で読むため」と、4 の「間隔」の「離しからの実際の間隔で回を分ける」で決まっている。窓の守りの回と同じく「4 の『間隔』の測った帯ごとに」と書けば、言い方がそろう。

## 改善指示の理由にしないもの（記録だけ）

- タッチの受ける側（離しから 320〜700ms）の試した回は、起点の `pointerdown` からの差が 700ms 以上になれば、窓だけを掛ける誤った作りでも受ける。そのため、その回はその作りを見分けない。ただ、道具の押しは押している時間が短いので、500ms の回の起点からの差はふつう 700ms を大きく下回る。正しい作りがこの回で外れることも無い。測りの担当が、起点からの差を押しごとの記録から見て、見分けられない回ばかりなら PM に報告すれば足りる。
