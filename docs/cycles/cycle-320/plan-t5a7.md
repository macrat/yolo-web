## 3. 測りの分け方と記録の上限を決める

PM が T5a-7a-1 の見積もりから決め、この節に書いてから reviewer に通し、承認を受けてから担当を起こす。

- **分け方の物差し**: 担当1人の範囲は、見積もりで壁時計4時間以内（背景で走らせるコマンド1回は最長2時間なので2回まで）、担当が t5a-measure.md に書く表は1つの操作と1つの版に限る。分ける線と、担当ごとの範囲・見積もりの時間を表にする。T5a-8 の測り直しにも同じ物差しを掛ける。
- **このサイクルに収まらないとき**: PM はこの節の決定に、このサイクルで走らせられる量（壁時計の時間）とその出どころ（担当を並べられる数と、サイクルに残る日数）を書く。見積もりの合計がそれを超えるなら、PM は見積もりを見て、削る形を次の物差しで決める。数（刻み・画面）は見積もりと押せるものの大きさから出し、出どころを書く。
  - 削らないもの: 375×550 のタッチ（閲覧の 82.3% がスマートフォン）、character-personality（閲覧の 85.8%）、件が既に出た操作と画面（cycle-319 のキャリーオーバーの件: 「はじめる」の 375×550、「もう一度挑戦する」の kanji-level の 375×550 と 1280×800。t5a-measure.md 5章の基準の版の件: 5-2 の知識クイズの「次へ」の2打目が `summary` に落ちる件のある画面、5-3 の 375×800 の最後の「次へ」の2打目がリンクに落ちる件）。B-623 を閉じる知識クイズの「次へ」は、条件7 と D5 の全画面を削らない。
  - 掃きの刻みは、押せるもので最も低いものの高さ（いまの最小は 44px）より粗くしない。
  - 次のサイクルへ送るのは、件が出ていない画面と入力だけにする。送れば直しが2回に分かれうることを、送るものごとに書く。
  - どれも設計の条件7 の文を変えるので、t5a-design.md 6章 条件7 の文の直し方とともにこのレビューに通し、送ったものを申し送りに書く。
- **記録の形と上限**: 記録は `.jsonl` で、1ファイル 1MB 以下（いま git が追う最大のファイルが約 1.1MB）、T5a-8 の測り直しの記録を含めて合計 3MB 以下（いまの `.git` は約 57MB で、その 5% ほど）にする。押しの数と1回の大きさから合計を出し、収まらないときは、押しごとの記録を合否に要る欄（落ちた先・`detail`・間隔・着地の記録）だけに絞る。それでも収まらないときは、走査ごとの要約（間隔・操作・画面ごとの数）だけを置き、押しごとの記録は置かないと決めて、その旨を `measure/README.md` と t5a-measure.md に書く。
