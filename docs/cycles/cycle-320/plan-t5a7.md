## 3. 測りの分け方と記録の上限を決める

PM が T5a-7a-1 の見積もりから決め、この節に書いてから reviewer に通し、承認を受けてから担当を起こす。

- **基準の版で測るもの**: 条件7 と D5 の操作のすべてを、基準の版でも新しい道具で、変更後の版と同じ手順（設計の各位置・各間隔での実際の二度押し）で測る。「もう一度挑戦する」も、5-4 の `elementFromPoint` の走査でなく、実際の二度押しで測る。t5a-measure.md 5-2 は比べる先を基準の版で測り直した値と定めており、5-4 は回ごとに結果が変わる走査（216/252 のように回で揺れる）で、新しい道具の値と点ごとに合わせられない。5-1 は回で揺れないが、手順の違う古い道具の値なので、同じ道具の値で比べる。5-1〜5-4 の値は参考として並べる。
- **分け方の物差し**: 担当1人の範囲は、見積もりで壁時計4時間以内（背景で走らせるコマンド1回は最長2時間なので2回まで）、担当が t5a-measure.md に書く表は1つの操作と1つの版に限る。分ける線と、担当ごとの範囲・見積もりの時間を表にする。T5a-8 の測り直しにも同じ物差しを掛ける。
- **量が大きいとき**: 条件7・D5 は、設計の画面・入力・間隔・刻みのまま、どれも次のサイクルへ送らず、粗くもしない。t5a-measure.md 5章の基準の版では、「はじめる」（5-1）は6画面すべてで2打目が1問目の選択肢に落ち、知識クイズの「次へ」（5-2）は 1280×800 のほかの画面で `summary` に落ち、最後の答えと最後の「次へ」（5-3）は表のある画面のうち 1280×800 のほかの画面で、「もう一度挑戦する」（5-4）はどの画面でも、第1の組に落ちる回や点があった。送れば件の出た操作と画面の直しが2回に分かれ、刻みを粗くすれば、変更後の版では着地の関数が点ごとに送りを選ぶので、押せるものの高さより狭い帯の件を見落としうる。PM はこの節の決定に、直列で回せる壁時計の時間（測りの担当は並行させないので1人ずつ）と合計の見積もりを書き、合計が1日で回せる量を超えるときは、続きから測れる道具で数日に分けて測り切る日割りを書く。日割りに上の線（日数）を置き、測っているうちにそれを超える見込みになったら、画面・入力・間隔・刻みを変えない手順の見直し案（道具の待ち時間の詰め方など）とともにこの節に戻し、レビューを受ける。
- **日をまたぐ記録と版**: 主の木の `tmp/` はセッションを越えて残らないので、次のようにする。T5a-8 の測り直しにも同じ手順を掛ける。
  - 担当が終わるたびと、日の終わりに、PM が `measure/` と t5a-measure.md をコミットして `design-rollout` に push する（PM が作業ブランチを途中で push することは `.claude/rules/delegation.md` の決まりの内）。
  - 版を作るコミットは固定する。変更後の版は T5a-7a-1 が記録したコミット、T5a-8 の測り直しは PM が取り込んだコミットで、どの担当もその時の HEAD からは作らない。
  - 走査の記録には、測ったビルドのもとのコミット（基準の版は fff3d31f と da102212。T5a-7a-1 の「T5a-7 の前の確かめ」で基準をその直前の版に変えたときは、その版のコミットと、重ねたファイルがあればそのコミットとパス）と、そのビルドの指紋を残す。指紋は、もとのソースの木のハッシュ（`git rev-parse <コミット>^{tree}`。ファイルを重ねた版は、`tmp/` の下に置いた別の索引（`GIT_INDEX_FILE`）にもとのコミットを読み込み、重ねるファイルを足してから `git write-tree` で出した値で、主の木の索引は触らない）、ビルドに使った Node と npm の版、`.next/static/chunks` のファイルの名前と大きさの一覧（名前は中身のハッシュで決まる）である。チャンクの一覧の扱いは、T5a-7a-1 の「指紋の確かめ」の結果に従う。
  - 続きを測るときは、`git rev-parse --is-shallow-repository` が true なら `git fetch --unshallow origin main design-rollout` で履歴を深くしてから、記録したコミットから版を作り直す。作り直した版の指紋を記録の指紋と比べ、合えば続ける。走査の落ち先は選択肢と結果が回ごとに変わるので（t5a-measure.md 0章）、版の確かめには使わない。指紋が合わないときは PM に報告し、PM は次を見て、その版で測り直す範囲を決める。木のハッシュが合わなければ、作り直しの誤りなので作り直す。木が合いチャンクが違えば、まず Node と npm の版が記録と合うかを見て、違えば記録の版で作り直して比べ直す。それでも違えば、違うチャンクが、測る操作の面（診断のページ）のコードを含むかを見て、含まなければ続け、含めばそのチャンクが掛かる操作を測り直す。
  - ブラウザの版が記録と違うときは、その操作と版の組を1つのブラウザの版ですべて測り直し、版を混ぜない（2打目の落ち先とタッチの調整はブラウザの実装による）。道具を直して blob が変わったときは、古い blob で測った記録を、その操作と版の組の分だけ測り直す。チャンクだけが違い、PM が上の物差しで「続ける」と決めたときは、道具はその決定を引数で受けて続け、決定を記録に残す。
- **記録の形と上限**: 記録は `.jsonl` で、1ファイル 1MB 以下（いま git が追う最大のファイルが約 1.1MB）、T5a-8 の測り直しの記録を含めて合計 3MB 以下（いまの `.git` は約 57MB で、その 5% ほど）にする。T5a-7a-1 の見積もりでは、押しごとの記録は合否に要る欄に絞っても1つの版で 7〜8MB になり、収まらない。そこで次の2つに分ける。
  - すべての回を、走査ごとの要約（操作・画面・入力・間隔ごとの回の数と、落ちた先の種類ごとの数、送り直した数・印を付けた押しの数）で置く。
  - 押しごとの記録（落ちた先・`detail`・座標・間隔・着地の記録・下のタッチの距離）は、判断（5）に要る回だけを置く。2打目が第1の組に落ちた回、次の問の選択肢に落ちた回、語の選択が空でない回、結果の名前の下端が見せる範囲の外にあった回、extra の差し込みが画面の中に入った回、誤りで終わった回である。
  - ファイルは操作と版と画面で分ける。それでも上限を超えるときは、PM に報告して形を決め直す。この形は `measure/README.md` と t5a-measure.md に書く。
- **タッチの調整の距離**: Chromium はタッチの点を、触れた面の大きさ（20〜32 dip に収める）の届く範囲の近くの押せるものに寄せる。道具の押しは面の大きさを渡さないが、このコンテナのブラウザは Blink に渡す前に tap の面を一辺 25 dip の正方形に広げるので、試しの走りの数は半辺 12.5px の面での調整にあたる。Android の端末の面は一辺 20〜32 dip で、半辺 10〜16px の所まで寄る（T5a-7a-1 のレビュー第1回、knowledge のレビュー第2回の実測とソース）。面の大きさを変えた回は足さない。足すと測りの量が倍になるのに、次の記録で同じ判断ができるからである。代わりに、タッチの回ではどれも、着地のあとの1打目の点から、最も近い押せるもの（第1の組と次の問の選択肢）の矩形までの横の隔たり dx と縦の隔たり dy を記録する。触れた面は点を中心にした正方形で、要素の矩形がそれと交われば寄るので、届くかどうかは max(dx, dy) が正方形の半辺（10〜16px）より小さいかで決まり、直線の距離では決まらない（knowledge のレビュー第1回）。「最も近い」も max(dx, dy) で決める。判断（5）は、max(dx, dy) と調整の届く半辺を突き合わせて、両向きに数え直す。道具では寄らなかったが max(dx, dy) が 16px より小さい件は、Android の大きい触れ方で寄りうる件として数える。道具では寄ったが max(dx, dy) が 10px 以上の件は、Android の小さい触れ方では寄らないことがある件として数える。閲覧の 82.3% がスマートフォンなので、来訪者の側に立ち、「避けられたのに落ちた件」の合否は max(dx, dy) が 16px より小さい件を落ちうる件として判定する。

- **間隔**: どの版・どの間隔でも、1打目と2打目の実際の間隔を記録する。90ms は「見せる 150ms の内」を、300ms は「外」を試す値なので、実際の間隔が 150ms の側を越えた回（90ms の指定で 150ms 以上、300ms の指定で 150ms 未満）は数えずに送り直す。0・150・500ms は境を試す値ではないので送り直さず、実際の間隔を記録する。送り直しの単位は操作の性質で分ける。1回の押しで終わる操作（「はじめる」・最後の答えと最後の「次へ」・「もう一度挑戦する」）は、新しい文脈でその操作を送り直す。送り直す前に捨てた回も、落ち先と実際の間隔を記録し、その2打目が第1の組に落ちたものは、間隔によらず件として 5 の判断に渡す。全問を解き切る走査の中の押し（診断の答え・知識クイズの答えと「次へ」）は、その押しだけを送り直せないので、越えた押しに印を付け、走査は続ける。印の付いた押しを外すのは、90ms・300ms の間隔ごとの数（見せる 150ms の内と外の比べ）からだけである。t5a-measure.md 5-2 の確かめ（1打目＋X＋S＝問の数）と、落ち先の記録には残し、その2打目が第1の組に落ちたものは、間隔によらず件として 5 の判断に渡す。送り直しは1つの回につき3度までとし、3度とも越えた回は越えた印を付けて数え、送り直した数・印を付けて外した押しの数・越えた回の数を記録する。T5a-7a-1 の見積もりには、試しの走りで出た送り直しの割合を含める。語の選択の測り（6章 条件7。2打目の `mousedown` の `detail` が 2 でない回を送り直す）にも同じ3度の上限を掛け、3度とも 2 にならなかった回は印を付けて語の選択の数から外し、その数を記録する。

## 5. 外れた件の判断

PM が、変更後の版の条件7・D5 で外れた件を件ごとに決め、選んだ理由と件を t5a-measure.md に書き、reviewer に通す。基準の版の数は比べるためのもので、判断の対象にしない。

- **条件7 の合否と D5 を満たさない件**（第1の組に落ちた件が 0・避けられたのに落ちた件が 0）: t5a-design.md 8章の4つ（見せる範囲を広げる・組みを直す・第2の組を外す・件を受け入れる）から選ぶ。「件を受け入れる」を選んだ件は、8章のとおり (i)〜(iii) のどれで扱うかを決め、その振り分けもこのレビューに通す。
- **合否のほかの外れ**: 語の選択が空でない回（4-9 の守りの欠け）・結果の名前の下端が画面の下端から 8px 上より下にある回（4-9 の見せる範囲の条件の欠け）・extra の差し込みが画面の中に入る回（1-4・4-9）。どれも設計が守ると決めているものなので、直すか、設計の決まりを変えるかを件ごとに決める。
- **切れた見出し・外れた見出し**（合否の外）: 「第2の組を外す」か「着地を行の切れ目にそろえる」か、そのままにするかを決める。
- 選ぶときは、閲覧の重み（character-personality・375 の画面）と、直すことで1つの操作に応える動きが増えないか（§11）を比べる。
- **測り直しの範囲**: 直す件ごとに、T5a-8 の測り直しの範囲もここで決めて書く。着地の関数を変える直しは、その関数を呼ぶ操作のすべて。「組みを直す」直しは、変えた要素が、どの操作の2打目の落ち先か、どの操作の着地の計算に入るか（避ける押せるもの・見せる範囲の要素）でたどった操作のすべて（例: 開始の画面を変えれば「はじめる」と「もう一度挑戦する」の両方）。範囲はこのレビューで見てもらう。
