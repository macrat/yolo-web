## 2b. 着地の直しの害の確かめ

担当・版とポート・比べる欄・記録の置き場・レビューの時は、[carryover.md](./carryover.md) の「着地の直しの害の確かめ」の項にある。直す前の版は 5ea1ab89（ポート 3111）、直した版（2a）はポート 3112 で、直した版は着地の A″ と、穴を直した二度押しの守りの両方を持つ。比べの記録のレビューでは、下の線で判定する。

- **記録の置き場**: 害の確かめと試しの走りの回ごとの記録は、担当が担当の木で走らせても、主の木の `tmp/cycle-320/<走りの名>/` に絶対のパスで書く（担当の木の `tmp/` は、取り込んで木を消すと一緒に消えるため）。レビューは、その記録が残っているうちに同じセッションで行う。
- **突き合わせ方**: 2つの版の押しは、回の名（`k`）・帯の番号・押しの種類（答え・「次へ」・はじめる・もう一度・結果の画面の押し・足した組の押し（900ms のあとの押し・1 秒以上あとの押し・見せる間に押し下げて切り替わりのあとに離す押し））で突き合わせる。直した版では守りが2打目を止めるので、同じ走査でも押しの並びが前の版と変わり、押しの番号では突き合わせない。片方の版にしか無い帯の押しは別に数え、件ごとに PM が見る（直した版だけで決まる線 3・5・6・8 には、直した版にしか無い押しも入れる）。診断の選択肢の並びは問ごとに混ぜられる（`QuestionCard`）ので、2つの版の走りは、ページの乱数を同じ種で固定して同じ並びで走らせる（固定は道具がページに入れ、本番のコードには足さない）。それでも同じ版の中で着地が揺れる押し（同じ版を同じ種で2回走らせて送りが違う押し）は、2・4・8 の比べから外して数を記録する。同じ版を同じ種で2回走らせて、落ちた先か働いたかが変わる押し（間隔の揺れで、見せる 150ms の内か外か・1打目の互換の事象より先か後かが替わる押し）は、時間で揺れる押しとして別の一覧に出す。線1 の件が前の版の時間で揺れる押しなら、件から外さず、その一覧の印を添えて PM が件ごとに見る（揺れで外すと、直した版で新しく出た外れを隠しうるため）。道具の1打目（走査の次の問の1打目など）が守りに止められた押しは、下の「境目の帯」で決めどおりか害かを分け、どちらも数えたうえでどの線の比べからも外す（止められた押しは画面を切り替えず、着地を持たない）。
- **境目の帯**: 帯は押しの単位で当て、帯に入った押しは、守りの判定で決まる線（1・5・7）の件に数えず、間隔・隔たり・結果を記録する（同じ走査のほかの押しは線に入れる）。着地の線（2・3・4・8）は、帯に入った押しとその押しが切り替えた画面の写しも入れる（着地は1打目が起こすもので、2打目が帯に入るかと関わらないため）。2つの版を比べる線（1・2・4・7）は、どちらかの版で帯に入った押しを帯として扱い、直した版だけで決まる線（3・5・8）は、直した版の押しが帯に入ったかで決める。同じ版の2回目の走りに同じ押しが無いことは、着地が揺れた証しではないので、それだけで線から外さない（外すのは、両方の回に押しがあって送りが違う押しだけで、2回目に無い押しは印を添えて線に残す）。時間は、窓の守りでは直前のポインタの切り替わりの起点の `pointerdown` から、連続の押しの守りのタッチでは直前の押しの離しから、押しの `pointerdown` までの測った差で取る。隔たりは、起点の点から押しの `pointerdown` の点までの直線の距離で取る。守りに止められた押しは、窓の守りで起点から 650ms 未満かつ 84px 以下、タッチの連続の押しで直前の離しから 280ms 未満かつ起点から 650ms 未満かつ 84px 以下、マウスの連続の押しで `detail` 2 以上かつ起点から 650ms 未満かつ 100px 以下なら決めどおり、窓の守りで 750ms 以上か 116px 以上、タッチの連続の押しで直前の離しから 320ms 以上か起点から 750ms 以上か 116px 以上、マウスの連続の押しで `detail` 1 か 750ms 以上か 100px を越えるなら 5 の害で、そのあいだは帯に入る（84px と 116px は、境目の 100px から、タッチの調整が点を寄せる最大の 16px を引いた値と足した値。マウスは調整で寄らないので、100px で分ける）。

  7. **語の選択が前と変わった回**: 前の版で語が選ばれた語の選択の対（`select`）で、直した版で語が選ばれなかった回と、`select` でない操作の押しで、前の版で語が選ばれなかったのに直した版で語が選ばれた回（入れ替わった先の字に黒い地の選択が残る）。
  8. **読む所の印が新しく出た回**: 着地のあとの最初のフレームの印（`measure/README.md` の要約の印。`cut`: `h1`・問の見出し・結果の名前のどれかの行を画面の上端が横切った、`lo`: 結果の名前の下端が画面の下端から 8px 上より下にあった、`ins`: extra の差し込みが画面の中に入った、`h1a`: 「もう一度挑戦する」のあとに開始の画面の `h1` が丸ごと上に出た、`at: 0`: 「もう一度挑戦する」の中心が決めた高さに着かなかった）のうち、前の版で出なかったのに直した版で出た回。A″ は見せる範囲の中で着地を動かし、範囲の中でも見出しは切れうるので、3 とは別に見る。

## 3. 測りの分け方と記録の上限を決める

PM が見積もりから決め、この節に書いてから reviewer に通し、承認を受けてから担当を起こす。見積もりは、直した道具で直した版（2a）を走らせた「着地の直しの害の確かめ」の走り（carryover.md）から出し直す。下に引く T5a-7a-1 の見積もり（t5a-measure.md 10章）は、直す前の道具と 5ea1ab89 の値である。

- **基準の版で測るもの**: 条件7 と D5 の操作のすべてを、基準の版でも新しい道具で、変更後の版と同じ手順（設計の各位置・各間隔での実際の二度押し）で測る。「もう一度挑戦する」も、5-4 の `elementFromPoint` の走査でなく、実際の二度押しで測る。t5a-measure.md 5-2 は比べる先を基準の版で測り直した値と定めており、5-4 は回ごとに結果が変わる走査（216/252 のように回で揺れる）で、新しい道具の値と点ごとに合わせられない。5-1 は回で揺れないが、手順の違う古い道具の値なので、同じ道具の値で比べる。5-1〜5-4 の値は参考として並べる。
- **分け方の物差し**: 担当1人の範囲は、見積もりで壁時計4時間以内（背景で走らせるコマンド1回は最長2時間なので2回まで）、担当が t5a-measure.md に書く表は1つの操作と1つの版に限る。担当の範囲を組むときは、担当の境を記録のファイルの境（操作と版と画面）に置き、1つのファイルを2人の担当に割り振らない（履歴に同じファイルの版を重ねないため。下の「記録の形と上限」）。組んだ範囲の途中で担当が止まったときの続きは、下の「日をまたぐ記録と版」のとおりで、そのときだけ書きかけの1つのファイルが2人にまたがる。分ける線と、担当ごとの範囲・見積もりの時間を表にする。T5a-8 の測り直しにも同じ物差しを掛ける。
- **量が大きいとき**: 条件7・D5 は、設計の画面・入力・間隔・刻みのまま、どれも次のサイクルへ送らず、粗くもしない。t5a-measure.md 5章の基準の版では、「はじめる」（5-1）は6画面すべてで2打目が1問目の選択肢に落ち、知識クイズの「次へ」（5-2）は 1280×800 のほかの画面で `summary` に落ち、最後の答えと最後の「次へ」（5-3）は表のある画面のうち 1280×800 のほかの画面で、「もう一度挑戦する」（5-4）はどの画面でも、第1の組に落ちる回や点があった。送れば件の出た操作と画面の直しが2回に分かれ、刻みを粗くすれば、変更後の版では着地の関数が点ごとに送りを選ぶので、押せるものの高さより狭い帯の件を見落としうる。PM はこの節の決定に、直列で回せる壁時計の時間（測りの担当は並行させないので1人ずつ）と合計の見積もりを書き、合計が1日で回せる量を超えるときは、続きから測れる道具で数日に分けて測り切る日割りを書く。日割りに上の線（日数）を置き、測っているうちにそれを超える見込みになったら、画面・入力・間隔・刻みを変えない手順の見直し案（道具の待ち時間の詰め方など）とともにこの節に戻し、レビューを受ける。
- **日をまたぐ記録と版**: 主の木の `tmp/` はセッションを越えて残らないので、次のようにする。T5a-8 の測り直しにも同じ手順を掛ける。
  - 担当が終わるたびに、PM が `measure/` と t5a-measure.md をコミットして `design-rollout` に push する（PM が作業ブランチを途中で push することは `.claude/rules/delegation.md` の決まりの内）。担当の範囲は1日の内に終わるよう組み、日の終わりを担当の終わりに置く。担当が途中で止まったとき（道具が止まった、セッションが切れそうなど）は、止まった所までをコミットして push し、次の担当が同じコマンドで続きから測る（書きかけのファイルが新しい版として履歴に重なる。下の「記録の形と上限」）。誤りで終わったまま残った回（道具が終わりに出す一覧）は、担当がコミットの前に同じコマンドで続きを測り切り、2度目も誤りで残った回だけを、その一覧とともに PM に報告する。
  - 版を作るコミットは固定する。変更後の版は着地の作りを直して `design-rollout` に取り込んだコミット（PM が記録する）、T5a-8 の測り直しは PM が取り込んだコミットで、どの担当もその時の HEAD からは作らない。
  - 走査の記録には、測ったビルドのもとのコミット（基準の版は 2db1c7d9 で、重ねるファイルは無い。t5a-measure.md 0章）と、そのビルドの指紋を残す。指紋は、もとのソースの木のハッシュ（`git rev-parse <コミット>^{tree}`。ファイルを重ねた版は、`tmp/` の下に置いた別の索引（`GIT_INDEX_FILE`）にもとのコミットを読み込み、重ねるファイルを足してから `git write-tree` で出した値で、主の木の索引は触らない）、ビルドに使った Node と npm の版、`.next/static/chunks` のファイルの名前と大きさの一覧（名前は中身のハッシュで決まる）である。チャンクの一覧の扱いは、T5a-7a-1 の「指紋の確かめ」の結果に従う。
  - 続きを測るときは、`git rev-parse --is-shallow-repository` が true なら `git fetch --unshallow origin main design-rollout` で履歴を深くしてから、記録したコミットから版を作り直す。作り直した版の指紋を記録の指紋と比べ、合えば続ける。走査の落ち先は選択肢と結果が回ごとに変わるので（t5a-measure.md 0章）、版の確かめには使わない。指紋が合わないときは PM に報告し、PM は次を見て、その版で測り直す範囲を決める。木のハッシュが合わなければ、作り直しの誤りなので作り直す。木が合いチャンクが違えば、まず Node と npm の版が記録と合うかを見て、違えば記録の版で作り直して比べ直す。それでも違えば、違うチャンクが、測る操作の面（診断のページ）のコードを含むかを見て、含まなければ続け、含めばそのチャンクが掛かる操作を測り直す。
  - ブラウザの版が記録と違うときは、その操作と版の組を1つのブラウザの版ですべて測り直し、版を混ぜない（2打目の落ち先とタッチの調整はブラウザの実装による）。道具を直して blob が変わったときは、古い blob で測った記録を、その操作と版の組の分だけ測り直す。チャンクだけが違い、PM が上の物差しで「続ける」と決めたときは、道具はその決定を引数で受けて続け、決定を記録に残す。
- **記録の形と上限**: 上限は、セッションごとにリポジトリを取り直す後のサイクルの取り込みの重さを抑えるための予算である。記録は `.jsonl` で、1ファイル 1MB 以下（いま git が追う最大のファイルが約 1.1MB）、サイクルを閉じるときの木で T5a-8 の測り直しの記録を含めて合計 4MB 以下、木から消した記録を含めて履歴に入る量の合計 15MB 以下にする。深い履歴の `.git` の pack は約 350MB（`git count-objects -vH` の `size-pack`）で、木の 4MB はその約 1%、履歴の 15MB は約 4% にあたる。履歴に入る量は、`measure/` の下の `.jsonl`（測りの記録。「着地の直しの害の確かめ」の比べの出力は `.json` で置き、数えない。carryover.md）のうちコミットしたことのあるすべての blob（同じファイルの版ごとに1つ）の生のバイト数の合計で数える。git の pack は blob を圧縮し、伸びたファイルの版どうしを差分で持つので、生のバイト数は pack の増え方の上の線になる。浅い履歴では境より前のコミットが `git log` に出ず、木から消した記録が数えに入らないまま少なく出るので、PM はコミットのたびに、`git rev-parse --is-shallow-repository` が true なら `git fetch --unshallow origin main design-rollout` で履歴を深くしてから、`git log --format= --raw --no-abbrev -- 'docs/cycles/cycle-320/measure/*.jsonl' | awk '{print $4}' | grep -v '^0*$' | sort -u | git cat-file --batch-check='%(objectsize)' | awk '{s+=$1} END {print s+0}'` で数える。T5a-7a-1 の見積もりでは、押しごとの記録は合否に要る欄に絞っても1つの版で 7〜8MB になり、収まらない。そこで次のように分ける。
  - すべての回を、走査ごとの要約（操作・画面・入力・間隔ごとの回の数と、落ちた先の種類ごとの数、送り直した数・印を付けた押しの数）で置く。窓の守りの回（同じ点の2打目と狙った2打目）、D5 の窓の中の 80px 以下と 120px のずれの回、空振りでないことの対は、守りを掛けた切り替わりごと・入力（タッチ・マウス）ごと・組（本・画面）ごとに、試した回（t5a-design.md 6章 条件7 の「試した回」）と試さなかった回の数を、4 の「間隔」の測った差の帯ごとに要約に数える。診断の答え→次の問の連続の押しの守りの回（マウスと、タッチの受けない側・受ける側）は、本ごと・入力ごと・4 の「間隔」の測った帯ごとに、2打目の `pointerdown` の的が次の問の選択肢の上にあった回（試した回）と、そうでなかった回の数を要約に数える。狙った2打目の的（80px の中の押せるもの）が無かった組は、その回の数と、1打目の点からいちばん近い押せるものまでの直線の距離を要約に残す。どれも、t5a-design.md 6章 条件7 の「下限」（どの合否の行でも、切り替わりごと・入力ごとに、試した回が合わせて1回以上。窓の守りとマウスの連続の押しの守りの「受けない」の行は測った差が 650ms 未満の試した回で、タッチの連続の押しの守りの受けない側は離しから 280ms 未満の試した回で数え、タッチの連続の押しの守りは受けない側も受ける側も診断12本のそれぞれに1回以上）を要約で読むためである。
  - 押しごとの記録（落ちた先・`detail`・座標・間隔・着地の記録・下のタッチの距離）は、変更後の版の、判断（5）に要る回だけを置く。2打目が第1の組に落ちた回、次の問の選択肢に落ちた回（診断の答えのあとに次の問の選択肢に落ちた押しは、条件7 が数だけを求めるので要約に数えて置かない。そのうち合否で読む件、つまりマウスの `mousedown` の `detail >= 2` が答えを入れた回と、タッチの受けない側と受ける側（t5a-design.md 6章 条件7 の連続の押しの守りの回の「タッチ（受けない側）」「タッチ（受ける側）」）で外れた回は置く）、語の選択が空でない回、結果の名前の下端が見せる範囲の外にあった回、extra の差し込みが画面の中に入った回、空振りでないことの対で外れた回である。狙った2打目の回の押しには、選んだ的の要素と、的の矩形の中で1打目の点にいちばん近い点として押した点、2打目の `pointerdown` の的が押せるものの上にあったかを持たせる。空振りでないことの対で外れた回の押しは、その回の2打目と同じ点として押した点を持つ（t5a-measure.md 0章の「狙った2打目」と「落ちた先」）。判断が押しごとに読むのは変更後の版の件だけで、基準の版の値は比べるための数（要約）だけを使うので、基準の版（着地の関数を持たない版）ではこれらを置かない。誤りで終わった回の押しは、誤りの原因の確かめに要るので、どちらの版でも置く（続きの測りで測り終えた回を飛ばすかは、要約の行だけで決める）。
  - ファイルは操作と版と画面で分ける。この形は `measure/README.md` と t5a-measure.md に書く。
  - 木に残すのは、変更後の版（2a の直しを取り込んだ版）の要約と押しごとの記録である。見積もりは、要約が約 2.67MB、押しごとの記録が約 0.6MB で、合わせて約 3.3MB になり、4MB に収まる（下の「変更後の版の記録」）。組と画面を新しい置き場で測り直したときは、測り終えたら同じ名の古い置き場のファイルを木から消し（履歴には残る）、新しい置き場の記録を古い置き場に写さない（版の指紋を置き場ごとにそろえるため）。新しい置き場は、ブラウザの版か道具の blob が替わって組のすべての画面を測り直すときの同じ版の置き場（`after-2`・`after-3`）と、T5a-8 の測り直しの置き場で、T5a-8 は1回目を `t5a8` に、直しを重ねた2回目からを回ごとに `t5a8-2`・`t5a8-3` に測る（版のコミットが替わって木のハッシュが違い、道具は前の回の置き場では止まる）。T5a-8 の各回は、測り直した組と画面の、変更後の版と前の回までの置き場のファイルを消す。記録のファイルが無くなった置き場は `fingerprint.jsonl` も消す。どの組と画面も木に残すのは数に使う1つの置き場のファイルだけなので、木の合計は変更後の版の1回分に収まり、消した記録は下の履歴の見積もりに入る（README の「ここに置く理由」の箇条）。基準の版は、測りが日をまたぐので、測っているあいだは続きから測れるよう要約（と誤りで終わった回の押し）を `measure/` にコミットして push し、測り終えたら `report.mjs` の集計を t5a-measure.md に表として写してから、置き場を木から消す。続きから測る道筋は、要約の数える行で測り終えた回を飛ばすので、押しごとの記録が無くても変わらない（t5a-measure.md 10-2 の「直した道具での記録の大きさ」）。
  - 履歴に入る量の見積もりは、下の3つで約 9.5MB になり、残る約 5.5MB を起きるまで大きさの決まらない分に充てて、15MB に収まる。どの版も、T5a-7a-1 の見積もり（t5a-measure.md 10-2）の操作ごとの要約の大きさに、いまの道具で走らせ直した1行の大きさの比を掛けて足す。

    - 測りの途中のコミットで同じファイルの版が重なるのは、次の3つの道筋だけである。道具は画面ごとに1つずつファイルを書き終え（回の並びのいちばん外側が画面）、担当の範囲はファイルの境で組み、コミットは担当の終わりにするので（上の「分け方の物差し」と「日をまたぐ記録と版」）、コミットに入る画面のファイルはふつう書き終えたものだけである。道具は、測る回の残っていないファイルを書き換えない（チャンクを受け入れたことの `accept` の行も、受け入れたあとに初めて回を足すファイルにだけ、そこで測り始めるときに `fingerprint.jsonl` の決定から足す。README の「確かめ直す」）。下の1つ目と2つ目の道筋で重なるのは1つの画面のファイルの新しい版で、いまの道具の1行の大きさで、いちばん大きい「もう一度挑戦する」の 1280×800・375×800 の要約が1つ約 0.37MB（15本 × 32 の高さ × 2間隔 × 2入力の 1,920 行 × 約 194B）、上限は1ファイル 1MB である。
      - 担当が途中で止まってコミットしたとき: 書きかけの画面のファイル（要約と押しごとの記録）の版が、次の担当が続きを測ってコミットしたときに重なる。
      - 誤りで終わったまま残った回（`unresolved`）を、コミットのあとに続きで測り直すとき: その回のある画面のファイルの新しい版が重なる。担当はコミットの前に同じコマンドで続きを測り切り（上の「日をまたぐ記録と版」）、2度目も誤りで残った回だけがこの道筋に入る。
      - PM がチャンクの違いを受け入れて続けるとき: 置き場の `fingerprint.jsonl` に指紋の行（約 5KB）が足され、受け入れのたびに、それまでの行を含むファイルの新しい版が重なる（測り終えた組しかない置き場で受け入れても足される）。受け入れが n 度なら、重なる量は約 5KB ×（2＋3＋…＋(n＋1)）である。
    - 残る約 5.5MB を、基準の版の誤りで終わった回の押しの記録、上の3つの重なり、ブラウザの版か道具の blob が替わって組を新しい置き場（`after-2` など）で測り直す分、T5a-8 の測り直しの2回目からの分（`t5a8-2` など。6 の「外れが残ったら、5 の判断に戻って」）に充てる。この2つは、上の箇条のとおり置き換えた古い記録を木から消すので、木の合計は変更後の版の1回分のままで、置き換えた古い記録の分が履歴にだけ足される。誤りで終わった回の押しの記録は、押しの前に誤った回が1行 約 140B、押しのあとに誤った回がその回の押しの数 × 380〜840B（10-2。答えの走査の1回で最大 約 17KB）である。試しの走り（負荷 1.2〜10.6）では誤りが 0 だったが、負荷が高い時は増えうる。変更後の版の誤りの押しは、その版の木の 4MB に入る。どれも起きるまで大きさが決まらないので、PM はコミットのたびに上のコマンドで合計を数え、次にコミットする記録の見積もりを足して 15MB を超える見込みになれば、その記録をコミットする前に形を決め直す（次の箇条）。
  - この見積もりは、着地の作りを直した版の走りで見積もり直すときに出し直す。木の 4MB か履歴の 15MB を超える見込みになったときは、PM に報告して形を決め直す。
- **タッチの調整の距離**: Chromium はタッチの点を、点を中心にした触れた面と交わる押せるものへ寄せ、面の横と縦はそれぞれ 20〜32 dip に収める。診断のページは受け手のあるページで（`docs/knowledge/input-events-and-guards.md` §8）、面は横 2×radiusX・縦 2×radiusY の矩形で、道具の押し（面の大きさを渡さない）は半辺 10px、Android の端末は半辺 10〜16px にあたる（`docs/knowledge/input-events-and-guards.md`、T5a-7a-1 のレビュー第1回・第2回、knowledge のレビューの実測とソース）。要素の矩形が面と交われば寄るので、届くかどうかは、点から押せる範囲（選択肢は `::after` で広げた箱）までの横の隔たり dx と縦の隔たり dy がそれぞれ半辺より小さいかで決まり、直線の距離では決まらない。面の大きさを変えた回は足さない。足すと測りの量が倍になるのに、次の記録で同じ判断ができるからである。代わりに、タッチの回ではどれも、2打目が触れる時点で、1打目の点から最も近い押せるもの（第1の組と次の問の選択肢）までの dx と dy を記録し、「最も近い」は max(dx, dy) で決める。道具の押しは Android のいちばん小さい面と同じ幅なので、判断（5）が数え直すのは、道具では寄らなかったが max(dx, dy) が 16px より小さい件（Android の大きい触れ方で寄りうる件）である。閲覧の 82.3% がスマートフォンなので、来訪者の側に立ち、守りのあとの押し（窓のあとの押しと、連続と数えられない押し。t5a-design.md 4-9）の記録は、max(dx, dy) が 16px より小さい件を落ちうる件として数える。条件7 は、この件を合否に入れず、件の数と隔たりを B-620 の材料として記録する（t5a-design.md 6章 条件7 の D5 の窓のあと）。守りを掛けない切り替わり（知識クイズの答え→答えたあと・「もう一度挑戦する」→開始の画面）の合否の「第1の組に落ちた件 0」は、2打目が実際に落ちた件で数え、道具では寄らなかったが max(dx, dy) が 16px より小さい件は、合否に入れずに件の数と隔たりを別に記録する（t5a-design.md 6章 条件7 の「守りを掛けない切り替わり」）。落ちうる件ごとに、範囲の中に、1打目の点から押せるもの（第1の組と次の問の選択肢）までの max(dx, dy) が 16px 以上になる送りがあったか（着地の記録の最も離せたときの値が 16px 以上か）も残す。16px は Android の面の半辺の上限で、どの触れ方でも寄せられない隔たりだからである。点の真下を外すだけの送り（罫線の上に点を置くなど、16px に届かないもの）は、離せた送りに数えない。

## 5. 外れた件の判断

PM が、変更後の版の条件7・D5 で外れた件を件ごとに決め、選んだ理由と件を t5a-measure.md に書き、reviewer に通す。基準の版の数は比べるためのもので、判断の対象にしない。

- **条件7 の合否と D5 を満たさない件**（t5a-design.md 6章 条件7 の合否の、窓の守りの回・連続の押しの守りの回・D5 の窓の中のずれ・空振りでないことの対・守りを掛けない切り替わりのどれかで外れた件。守りのあとの押しの記録は合否に入れないので、ここに入らない）: t5a-design.md 8章の4つ（見せる範囲を広げる・組みを直す・第2の組を外す・件を受け入れる）から選ぶ。「件を受け入れる」を選んだ件は、8章のとおり (i)〜(iii) のどれで扱うかを決め、その振り分けもこのレビューに通す。
- **合否のほかの外れ**: 語の選択が空でない回（4-9 の守りの欠け）・結果の名前の下端が画面の下端から 8px 上より下にある回（4-9 の見せる範囲の条件の欠け）・extra の差し込みが画面の中に入る回（1-4・4-9）。どれも設計が守ると決めているものなので、直すか、設計の決まりを変えるかを件ごとに決める。
- **切れた見出し・外れた見出し**（合否の外）: 「第2の組を外す」か「着地を行の切れ目にそろえる」か、そのままにするかを決める。
- 選ぶときは、閲覧の重み（character-personality・375 の画面）と、直すことで1つの操作に応える動きが増えないか（§11）を比べる。
