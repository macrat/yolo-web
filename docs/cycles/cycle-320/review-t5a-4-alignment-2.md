## 指摘

### 1. `CopyButton` の7つのページを、測れないとして外しているが、ふつうの入力で測れる（中）

記録は color-converter・hash-generator・json-formatter を「その字を入れたあとも出なかった」、csv-converter・number-base-converter・sql-formatter・yaml-formatter を「押せないままだった」として外す。入れた字が1つ（「テスト abc 123」）で、どれもその道具が受け付ける入力ではないためである。道具ごとの入力（`select a, b from t where c = 1`、`a: 1` の YAML、`a,b\n1,2`、`255`、`{"a":1}`、`abc` と「生成」、`#ff0000`）を入れると、7つのどれでも押せる `CopyButton` が出る（あわせて 18 個。number-base-converter と hash-generator は4つずつ、color-converter は3つ）。

この外しは来訪者に関わる。T5a-4 は押したあとの面を1つの文節（「コピー済み」「コピー失敗」）にしたので、見えない箱が決める升の最小の幅が「コピー」から「コピー済み」に広がる（`CopyButton.module.css` の注釈のとおり）。升が最小の幅に詰まるのは、ラベル・値・ボタンを1行に並べる狭い行で、number-base-converter・hash-generator・color-converter の結果の行はまさにその形である。外した7つが、升の幅の変化で行が動きうる面の中心にあたる。

参考に、7つのページの 18 個を、320×550・375×550・1280×800・320×550 200%・375×550 200% で、前と後の両方で押す前と押したあとに測った（升の左端・幅・高さ、ボタンの箱の左端と幅、升を置いた行の子の左端・幅・高さ）。前と後で値はすべて一致した。結論は変わらない見込みだが、記録の根拠として、これらのページを測って加え、「測らなかったページ」の理由を事実に合わせて書き直す。

あわせて次も直す。

- `/tools/image-base64` も `CopyButton` を描く（画像を読み込んだあと）が、記録の測ったページにも測らなかったページにも出てこない。測るか、外す理由を書く。
- 押したあとの面は「コピー済み」だけを測っていて、「コピー失敗」を測っていない。クリップボードの権限を与えない文脈などで出して測るか、「コピー済み」と字数・字の種類が同じで升の幅を決めないことなど、測らなくてよい理由を書く。
- 画面に 320×550 の 200% が無い。升が最小の幅に詰まりやすいのはいちばん狭い 200% で、index.md 作業内容 1 と t5a-4-changes.md も「375・320 の既定と 200%」で見ている。少なくとも `CopyButton` のページは 320×550 200% も測る（クイズのページも、測らないなら理由を書く）。

「開始・答えたあと・解き終えた画面と下の区画」の表の最後の行は、関連・おすすめのパネルの一覧の行の「行の題・説明・件数の字」を 46 / 206 と書く。1280×800 では、種別・補助情報（`p.meta`。「診断 全8問」「運勢 毎日更新」「クイズ 全10問」「あなたのタイプ」「全10問」など）は行の右にあり、字の x は 961.39〜1037.59 である（担当の `out/after.json` にもその値があり、前も同じ）。DESIGN.md §7 は `45rem` 未満の画面でだけ種別と補助情報を名前の下に落とすので、広い画面で右にあるのは形のとおりで、揃いの外れではない。表の値を画面ごとに正しく書き分け（狭い画面は 46、1280×800 は題・説明が 206 で種別・補助情報は右）、「§5 の揃い」の節にも、左端の線に並べないもの（§7 の広い画面の種別・補助情報、横に接して並ぶ2つ目からのコントロール・パンくずの項目）を何と判断して外したかを書く。いまの「外れた面は前も後も0」は、何を測って何を対象から外したのかが読めない。

### 3. 「T5a-4 が変えた面」の範囲の決め方が書かれていない（小）

記録の冒頭は、T5a-4 が変えた面を `.quizPage` の箱の中・パンくず・`CopyButton` の押したあとの面とする。t5a-4-changes.md のとおり、T5a-4 はほかに 298 の前もって描くページ（記事・四字熟語・道具の h1 とよくある質問、`/about`・`/privacy` の h2）と science-thinking の結果のページの h1 の `<wbr>` の位置も変えている。これらを測らなくてよいのは、HTML の違いが `<wbr>` の位置だけで、CSS も変わっていない（`src` の CSS の差分は `page.module.css` の `:root:has(.quizPage)` と `CopyButton.module.css` の注釈だけ）ので、行の左端も最初の字の x も動きえないからである。この理由と根拠（t5a-4-changes.md の 1 と 3）を1〜2文で書き、範囲を読み手が確かめられるようにする。

同じく、クイズのページは全15本（`/play/[slug]` と `/play/music-personality`）が `QuizPlayPageLayout` を使うが、測ったのは2本である。`.quizPage` は見え方を持たない箱で、変わったのは `QuizContainer` と下の区画の祖先が1段増えたことだけなので、その2本で祖先と各区画の x が変わらなければ、ほかの本の結果の画面の中身も動かない、という理由を書く（2本で足りる理由が書かれていないと、診断ごとに違う結果の画面を測り漏らしたように読める）。
