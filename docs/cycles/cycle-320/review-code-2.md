## 指摘

### 指摘1（来訪者に届くもの・小さい）: 見せる間に押し下げて止めた押しは、押し直しの元にならず、`quiz_press_guarded_retry` が送られない

`noteStopped` は、押し直しの元にする押せるものを、止めた押しの `pointerdown` の的（`stopped.target`）から `closestPressable` で取る。見せる間に押し下げた押しの `pointerdown` の的は、答えた問の行の字（`QuestionCard` の答えたあとの `span`。押せるものの中に無い）なので `null` になり、押し直しを待たない。その押しの `mousedown` と `click` が実際に落ちて止められたのは、新しい画面の次の問の選択肢か結果の画面のリンクである。来訪者から見て「押したのに何も起きなかった」ものはそちらで、それを3秒以内に押し直しても数えられない。

- 前回のレビューの見立てでは、診断の答え→次の問で守りが止める押しのうち、いちばん多い型がこの押しである。`answer` と、診断の `result` の `quiz_press_guarded_retry` は、止めた数（`quiz_press_guarded` はこの押しも数える）に対して、この型の押し直しを系統だって落とす。T10 は `transition` ごとの押し直しの経過 ms の分布で守りの害を読み、戻すかの線を引くので、測る面が来訪者の通る面を写さない（AP-WF33）。
- 決定の「受けなかった押しの的から `closest` した押せるもの。押せるものの上でなかった押しは元に入れない」は、押し下げのあとに画面が入れ替わる押しを決める前の文で、どちらの的かを決めていない。来訪者の押し直しに合うのは、止めた事象（`mousedown` か `click`）の的である。守りが開いたあとに押し下げた押しは、押し下げと止めた事象の的がふつう同じなので、そこでのふるまいは変わらない。

**直し方の向き**: `noteStopped` に止めた事象の的を渡し、押し直しの元はそこから `closestPressable` で取る（`mousedown` と `click` の両方を止めたときは、あとの `click` の的で上書きしてよい）。押し直しの経過 ms は、決定のとおり押し下げの時刻から数えたままにする。試験を1つ足す（見せる間に答えた行で押し下げ、次の問の選択肢で離して止められたタッチの押しのあと、3秒以内に同じ選択肢を押して受けると、`transition: "answer"` の `quiz_press_guarded_retry` が1回送られる）。決定と t5a-design.md 4-9 の「数える」の「受けなかった押しの的」を「止めた `mousedown` か `click` の的」と明確にする（文の明確化だけで、決めごとは変わらない）。

### 指摘2（来訪者に届くもの（試験）・小さい）: 「引いて送りになった押しは数えない」の試験が、主でない押しとして捨てられ、何も試していない

`QuizContainer.pressGuard.test.tsx` の「押し下げのあと引いて送りになった押し（mousedown も click も来ない）は数えない」は、`pointerdown` を `isPrimary` を書かずに作る。`PointerEventInit` の `isPrimary` の既定は偽で、jsdom もそのとおりに作るので、今回足した `if (!event.isPrimary || event.button !== 0) return;` でこの押しは覚えられない。試験は、守りが押しを受けないと決めた押しが `pointercancel` で終わったとき数えないことを確かめず、押し下げの時に数える誤りがあっても通る。来訪者の指の送りの `pointerdown` は主の押し（`isPrimary` が真）である。ブラウザの値で組む、という試験の書き出しの約束にも外れる。

**直し方**: その試験の `pointerdown` と `pointercancel` を、ほかの試験と同じ `pointerOf({ pointerType: "touch" })`（`pointerId: 1`・`isPrimary: true`）で作る。あわせて、そのあとの窓の中の押しが止まって `quiz_press_guarded` が1回だけ送られること（送らなかったのは止めなかったからで、守りが外れたからではないこと）を確かめると、試験が仕様を確かめる形になる。
