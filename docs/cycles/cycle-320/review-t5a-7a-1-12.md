## 指摘

### 指摘1（中）: 「同じファイルの版は重ならない」が、道具が書き終えたファイルに行を足す道筋を落としている

plan-t5a7.md 3（53 行）は「重なるのは、担当が途中で止まってコミットした所だけ」とし、残る 1.1MB の充て先もそれに合わせている。ところが道具には、書き終えてコミットしたファイルの新しい版を作る道筋がほかに2つある。

- **チャンクを受け入れて続けるとき**: `main` は回ごとに `filesOf(run.viewport)` を `entry.final` の確かめより前に呼び（measure.mjs 1972・1979 行）、`openViewportFiles` は `accepted` があればそのファイルの最後の行が `accept` でない限り `accept` の行を足す（342〜349 行）。`--accept-chunks` で続けたコマンドが開く画面のファイルは、測り終えたものにも1行が足され、ファイル全体が新しい blob として履歴に入る。基準の版の「もう一度挑戦する」は1つの組で約 1.7MB あり、1度の受け入れで残りの 1.1MB を越えうる。
- **誤りで終わったまま残った回（`unresolved`）を、コミットのあとに続きで測り直すとき**: そのファイルの新しい版がまるごと入る。

直す向き: 道具を、測る回の残っていないファイルを開かない（または `accept` の行を足さない）形に直すか、plan-t5a7.md 3 の重なりの箇条と 1.1MB の充て先に2つを書き、見積もりの大きさ（組の要約の大きさ）を添える。担当が誤りの回を残したら、コミットの前に同じコマンドで続きを測り切ることも決めておくとよい。

### 指摘2（中）: 変更後の版の記録の見積もりが、基準の版と違う出し方で、いまの道具の1行の伸びを入れていない

plan-t5a7.md 3 は、基準の版の要約には、いまの道具で走らせ直した1行の比を掛けたが、変更後の版（51 行）には 10-2 の値（直す前の道具 `63750786`）に `rv`・`re` の 0.08MB を足しただけで「約 3.0MB」としている。10-2 自身が「上の表の値はそのままでは使えない」と書く値である。手元の走らせ直しでは、変更後の版の1行は 10-2 の1行より大きい。

- 「はじめる」タッチ 375×550: 211.1B（after-10）。10-2 の 145KB ÷ 900 ≒ 161B（入力と画面の平均）。基準の版のタッチの比 163/138 ≒ 1.18 より大きく、`n` の着地の記録と `hu` の分である。
- 答えの走査: 129.7B（after-10、3本）。10-2 の 80KB ÷ 720 ≒ 111B で 1.17。
- 最後の答え: 175.7B（375×550）・201.4B（200%）。10-2 の 169B で 1.04・1.19。

重みの大きい「もう一度挑戦する」（1,582KB）は、いまの道具では走らせ直していない。同じ出し方で足すと、変更後の版の要約は 2.5MB を越え、押しごとの記録 0.5MB と合わせて木の 3MB を越える見込みが高い。また同じ節の 48 行は「要約が約 2.4MB、押しごとの記録が約 0.5MB で、3MB に収まる」と言い切っていて、51 行の「約 3.0MB で木の線とほぼ同じ」と食い違う。

見積もりの出し直しを「着地を直した版の走り」に送ること自体はよいが、後の PM がこの節を読んで「木の 3MB にはおおむね収まる」と受け取ると、形の決め直しの要否の判断を誤る。直す向き: 変更後の版も、確かめた操作の比（上の値）と確かめていない操作（「もう一度挑戦する」・D5・語の選択の対）を書いて同じ出し方で足し、3MB を越える見込みならそう書く。48 行の言い切りは、51 行の見積もりに合わせる。

### 指摘3（軽）: 「1つのファイルを2人の担当に分けない」と「次の担当が同じコマンドで続きから測る」が字の上で食い違う

plan-t5a7.md 3 の「分け方の物差し」（36 行）は「1つのファイルを2人の担当に分けない」と言い切り、「日をまたぐ記録と版」（39 行）は担当が途中で止まったら「次の担当が同じコマンドで続きから測る」とする。後者は1つのファイルが2人に分かれる場合である。53 行がこの重なりを扱っているので中身は通るが、36 行は「担当の範囲を組むときは」と、組むときの決まりであることを書くとよい。

### 指摘4（軽）: 押しごとの記録を置くかが、版のソースの字から推した `landing` だけで決まる

`keepReasons` は `options.landing` が false なら何も置かない（1351〜1353 行）。`landing` は `src/lib/reveal.ts` に `export function chooseLanding` があるかで決まるので、着地の作りの決め直しで関数の名前や置き場が変われば、変更後の版が基準の版と見なされ、着地の記録・`re`・押しごとの記録が誤りにならずにすべて欠ける（頭の行の `landing` が false になるだけ）。carryover.md は新しい作りに合わせて道具を直すことと、両方の版で着地の記録が欠けないことの確かめを完了の条件に置いているので、すぐの害は無い。直す向き: README の「測る」か plan-t5a7.md 4 に、変更後の版と T5a-8 の版では頭の行の `landing` が true であることを測り始めに確かめる、と書く（道具が版の名から期待を受けて食い違えば止める形でもよい）。

### 指摘5（軽）: `re` が拾う着地を、結果のフレームの直前の画面のあとに限っていない

`before` は「結果のフレームより前の、その押しの最後の着地」である。5ea1ab89 では結果の段階で必ず `revealLanding` が呼ばれるので正しい着地を指すが、決め直した作りで結果の着地が呼ばれない枝（箱が無いときの `return` など）が出ると、同じ押しの前の画面の着地（知識クイズの答えの押しで2打目が「次へ」に落ちた回の、答えたあとの着地など）を結果の着地として数える。直す向き: 結果のフレームの1つ前のフレーム（無ければ押しの頭）より後の着地だけを候補にし、無ければ `re` を書かない。
