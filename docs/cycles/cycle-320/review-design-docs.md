### 指摘1: A″ の「16 以上の送りが無い回」の送り方が、決定とも、測った A″ とも、文書の中の説明とも合っていない

場所: t5a-design.md 4-9 手順5 の3つ目の枝（「範囲の中に、d1・d2 がどちらも 16 以上になる送りが無いとき」）、同じ文書の5章の §8 の文と `DESIGN.md` §8、スキルの送りの項。

- 決定 2 は「範囲の中に 16 以上の送りが無い回は、**いまの関数の送りのまま**にする」と書く。A″ を測った道具（`tmp/landing-options/page-init2.js` の `chooseA3`）もそこで `chooseCurrent` を呼び、いまの `reveal.ts` の `chooseLanding` と同じく、隔たりを**直線の距離（`Math.hypot`）**で測って `[d1 > 0, d2 > 0, d1, d2]` の順で選ぶ。landing-options.md 2-1 の「ほかの操作への害 0」はこの形で測った値である。
- t5a-design.md の手順5 は、冒頭で d1・d2 をどこでも max(dx, dy) で測ると決め、3つ目の枝で送る枝の順の1・2 を「0 でない」に替えるだけにしている。3・4（d1 が大きい・d2 が大きい）も max(dx, dy) で比べることになり、「いまの関数の送り」とも、測った A″ とも違う送りを選びうる。害を測っていない形を、決定の名で作ることになる。
- そのうえ、同じ枝の終わりの「点を 16 以上離せない回に、わずかな隔たりを空けるために大きく送ることはしない」と、`DESIGN.md` §8 の「わずかな隔たりのために大きく送らない」、スキルの「点の真下から外すことだけを見る」は、送る枝には当てはまらない。送る枝の順の3・4 は、隔たりが 0.1px 増えるだけでも基準から遠い送りを選ぶ（いまの関数も同じ）。builder は、順のとおりに組むか、説明の文のとおりに組むかを文書からは決められない。

直し方: PM が、3つ目の枝の隔たりを (a) 決定と測った値のとおり直線の距離で測るのか（いまの関数をそのまま呼ぶ）、(b) max(dx, dy) で測るのか（そのときは害を測っていないことを明記し、「着地の直しの害の確かめ」で確かめる）を決め、decision-landing.md の決定 2 に書く。そのうえで、t5a-design.md 4-9 手順5・5章、`DESIGN.md` §8、スキルの説明の文を、選んだ順が実際にすること（送らない枝は真下を外すだけ、送る枝は真下を外したうえで遠ざける）と合うように書き直す。決定の「いまの関数の送りのまま」の文面からは (a) が素直な読みである。

### 指摘2: D5 の走査の間隔・操作・ずれが、plan-t5a7.md 4 と t5a-design.md 6章で食い違い、新しいずれの向きも決まっていない

- plan-t5a7.md 4 の「D5」は「device-triage.md D5 の『行き先』の画面・ずれ・操作と間隔」で両方の版を測るとする。device-triage.md D5 の行き先は、どの操作も 90・300ms、ずれは (0, ±10)・(0, ±20)・(±10, 0)、入力はタッチだけ、合否は「どのずれでも第1の組 0」である。

- 80px・120px のずれは「直線の距離」とだけあり、向き（(0, ±80)・(±80, 0) か、斜めか、いくつの向きか）が決まっていない。担当ごとに選べば、版のあいだ・担当のあいだで数がそろわない。
- 6章の D5 の箇条は、知識クイズの答え→答えたあと（守りを掛けない操作で、device-triage.md D5 の操作に入っている）を挙げておらず、この操作を D5 で何 ms で走らせ、何を合否にするかが文書から読めない。入力（タッチだけか）も6章には書かれていない。

直し方: plan-t5a7.md 4 の D5 の箇条を、画面と入力は device-triage.md D5 から、操作ごとの間隔・ずれ・合否は t5a-design.md 6章 条件7 の D5 の箇条から取る形に書き直す。6章の D5 の箇条に、80px・120px のずれの向きと、知識クイズの答え→答えたあとの間隔と合否（device-triage.md のとおり 90・300ms で第1の組 0 を合否にするか、など）と、入力を書く。
