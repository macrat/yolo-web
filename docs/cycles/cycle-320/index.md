## 作業計画

### 目的

診断を解く人が、狭い画面で速く2度押しても、画面が拡大されず、読んでいない問に答えが勝手に入らず、FAQ のような押した覚えの無いものが開かず、選択肢の字を語の途中で折られずに読めること（B-614・B-623）。`docs/site-concept.md` の来訪者への約束は「面白いものがここにあります」と渡すものを決め、面白いかどうかを来訪者の行動で確かめると定める。診断の面白さは解き終えて結果を読むところで起きる。読んでいない問に答えが入れば、結果はその人の答えでなくなり、渡すはずの面白さそのものが崩れる。

診断のプレイ面の閲覧の 82.3% がスマートフォンで、85.8% が character-personality である（GA。下の参考の情報）。cycle-319 の走査では、375×550 で「はじめる」を速く2度押すと、character-personality を含む4本で2打目が1問目の選択肢に落ちて答えを入れた。来訪者の多くが使う画面と診断で起きる件なので、数を取り、件ごとに決めて直す（計画ではこのサイクルで行うとしたが、範囲の決め直しで次のサイクルへ送った。作業内容 2）。あわせて、いま 375・320 の画面では選択肢の文全体が1つの文節として組まれ、1字だけの行（「描／く」）や行頭の閉じ括弧が出る（cycle-319 のキャリーオーバー）。区切りを渡してそれを消し、根の `touch-action` で2度押しの拡大を止める（T5a-4）。

### 検討した他の選択肢と判断理由

- **T5a-4 と T5a-7 のすべてをこのサイクルで行う**: T5a-7 は、6章の14の条件と device-triage.md の6項目の測りに、全15本・6画面・5つの間隔の二度打ちの走査と、外れた件ごとの PM の判断と直しと、knowledge の書き直しと、T5a の完了のレビューが重なる。測りの道具は消えていて組み直しから始まり、二度打ちの走査の文（t5a-measure.md 5-2）はどの版でも走らせていない。cycle-318 は土台だけでレビューが30回を超え、cycle-319 も2タスクで20回を超えた。1サイクルに詰めると途中で止まる危険が大きい（split-plan.md 7「各サイクルのキックオフで、その回に収まるかを改めて見積もり、収まらなければさらに分ける」）。
- **二度打ちの前で切る（条件1〜6・8〜12 を先に測り、二度打ちを次へ送る）**: 条件7 の結果で、PM は 8章の「見せる範囲を広げる・組みを直す（開始の画面の「はじめる」の位置など）・第2の組を外す」を選ぶ見込みが大きい（cycle-319 のキャリーオーバーの「はじめる」の4本に character-personality が入る）。直せば、先に測った条件1（入る）・5（フォーカス）・6（「もう一度挑戦する」）・D1〜D4 の値が直す前の版の値になり、測り直しが要る。採らない。
- **cycle-319 で分かっている件（「はじめる」の4本・着地のずれ）だけを先に測る**: 先に直せる件は出るが、ほかの操作（診断の答え・知識クイズの「次へ」・結果への切り替わり・「もう一度挑戦する」の掃き）で避けられない件が出たときに、直しが2回に分かれ、測り直しも2回になる。条件7・D5 の全体を一度に測り、件をそろえて決めるほうが、直しと測り直しが1回で済む。採らない。
- **選んだ案（二度打ちを先に測り、直してから残りを測る）**: 来訪者の結果を変えてしまう件を先に片づけ、残りの測りを直しのあとの版で1度だけ行う。T5a は split-plan.md 7 の見込み（1〜2サイクル）を超えて4つ目・5つ目のサイクルに入り、表の3行目より後は順にずれる。出荷は1回なので、分けても来訪者に届く時は変わらない。
- **測りを1人の担当にまとめる、または計画の段で分け方を決め切る**: cycle-316 の T5a-2 は、同じ規模の測りを担当の負荷で打ち切った。担当の文脈が溢れて途中で止まる危険と、レビューが1回で全体を見られない害がある。一方、押しの数と時間は道具を組んで走らせるまで分からず（条件7 は1つの版で数万回の押しになる見込み）、計画の段で線を引けば根拠の無い線になる。T5a-7a-1 に見積もりを出させ、PM がそれを見て分け方と記録の上限を決める段を置く（CLAUDE.md の「Keep task smaller」）。
- **測りの道具と記録を `cycle-316-records` のような別のブランチに残す**: cycle-316 の先例はあるが、このサイクルの作業ブランチは `design-rollout` だけで、別のブランチへの push はその決まりに当たる。主の木の `tmp/` はセッションを越えて残らない。そこで道具と記録を `docs/cycles/cycle-320/measure/` にコミットする。`.claude/rules/doc-directory.md` は `docs/cycles/` に「サイクルドキュメント以外は保存しない」と定める。この決まりは、サイクルに属さないもの（計画書・調べものの結果・一般の文書）を `docs/cycles/` に置かせないためのものと読む。この道具と記録は、このサイクルと次のサイクルの文書に書く数の出どころで、その数を確かめ直すためにだけあり、サイクルの外では使わないので、PM はサイクルの記録の一部と判断する。`docs/cycles/` の中で `.md` でないファイルはこれが最初になるので、この理由を `measure/README.md` に書き、大きさは 3 で木と履歴の上限を決めて、セッションごとにリポジトリを取り直す後のサイクルの取り込みを重くしないようにする。
- **B-790・B-792（hook）をこのサイクルに入れる**: どちらも統合のブランチの上で扱う項目で、AP-WF29・シェルでの書き込みの再発を止めるが、T5a と密接ではなく、サイクルの作業を最小限にする決まりに従って入れない。このサイクルは手で守る。
