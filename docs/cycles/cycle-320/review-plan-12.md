## 指摘

### 1. T5a-4 の早い起こしを「補足事項」に置き、手順の外れとして書いていない（軽）

CLAUDE.md の「Review always」は、計画のレビューの指摘に応えてから次の段へ進むと定める。計画が要修正のまま実装の担当を起こしたのは、理由が妥当でもこの決まりの外である。いまの書き方は「理由があったので起こした」という通常の判断として読め、後のサイクルが「指摘が細目だけなら承認を待たずに起こしてよい」という先例に読みうる。次の2つを直す。

- この1行を「手順を外れたこと」に移し、どの決まりを外れたか（計画の承認の前に実装の担当を起こした）と、外れても T5a-4 に害が無いと判断した理由（いまの文）を書く。
- 「第3回より後の指摘が無く」は、第6回に T5a-4 の条件の塊に掛かる字下げの指摘があったので、「第3回より後に中身の指摘が無く」とする。あわせて、計画の承認を受けたときに、`git diff 46114389 <承認の HEAD> -- docs/cycles/cycle-320/index.md` で作業内容 1 が変わっていないことを PM が確かめてから T5a-4 を取り込む、と1句足す（変わっていれば担当に差を渡す）。

### 2. 指紋に Node の版を常に入れておらず、チャンクが違ったときに先に環境をそろえる手が無い（軽）

指紋の確かめは同じセッションの中で2度ビルドして比べるので、セッションを越えて変わりうるもの（Node の版。リポジトリでは固定されておらず、手元は v22、CI は 24）は試されない。同じセッションでそろえば、指紋は木のハッシュとチャンクの一覧のままで Node の版は記録されず、後の日に Node が変わってチャンクが違ったとき、PM は原因を記録から確かめられない。また、3 の物差しは「違うチャンクが診断のページのコードを含めば、その操作を測り直す」で、Node の差ならほぼすべてのチャンクが違い得るので、挙動の変わらない道具の差のために測り直しが膨らみうる。

直し方の例: 指紋に、確かめの結果によらず Node と npm の版（`node --version`・`npm --version`）を常に入れる。3 の「木が合いチャンクが違う」ときは、先に記録した Node の版で作り直してそろうかを見て、それでも違うときに今の物差し（診断のページのコードを含むか）を掛ける。

### 3. 0章で基準の版を変えたときの、基準の版のコミットと木のハッシュの出し方が無い（軽）

plan-t5a7.md 2 の「T5a-7 の前の確かめ」は、差が診断のページに掛かるときは「その直前の版を基準にし」と書く。3 の指紋の項は基準の版を fff3d31f と da102212 の重ねに決め打ちしており、基準を変えたときにどのコミットを記録し、木のハッシュをどう出すか（重ねが要るか、`<コミット>^{tree}` でよいか）が書かれていない。「0章で基準を変えたときは、その版のもとのコミットと、その版の作り方に合わせた木のハッシュを記録する」と1句足す。

### 4. チェックリストの T5a-8 の行が、設計の文の直しを常にあるものと読める（軽）

「判断で直すと決めた件を、設計の文と同じ中身の文書を直しに合わせてから builder が直し」は、作業内容 6 と plan-t5a7.md 6 の「直しが設計の決まりを変えるとき」の条件を落としており、どの直しでも文書を先に直すと読める。また、文書を直す人が書かれていない（plan-t5a7.md 6 では builder）。「判断で直すと決めた件を（設計の決まりを変えるときは設計の文を先に直して取り込んでから）builder が直し、…」のように条件を戻す。
