## 指摘

どれも軽で、PM が直してよい。

### 指摘1（軽）: 診断の答えの走査では `hitUnmatched` が毎回 0 でなく、知識クイズの答えの外れを埋もれさせる

README は「答えの走査では 0 にならないことがある」と書くが、実際は診断の答えのあとの呼び出しはいつも `exclude: stage` で、その問の行の数だけ必ず数が立つ。束の和しか出さないので、同じ束の知識クイズの答え・「次へ」で置き換えが外れても見分けられない。README の文を「診断の答えの走査ではいつも 0 でない（問の行の数）。知識クイズの答え・「次へ」では 0 になる」と書き分けるか、report.mjs で押しの `kind` か本で分けて出す。次のサイクルで着地の作りを変えると `exclude` の使い方も変わりうるので、要件を足すときに一緒に決めてもよい。

### 指摘2（軽）: 10-1 の「`n` は同じ」は、隔たりは同じだが要素の名は回ごとに違う

10-1 の「375×550 の 15 回は … 落ちた先・`n`・`farBoth` は … 同じ」は、`after` と `after-3` を突き合わせると、`n` の選択肢の名が 12 本で違う（選択肢の並びが回ごとに変わるため）。dx・dy と落ちた先の組は同じだった。「`n` の隔たり」と書く。

### 指摘3（軽）: 10-2 の「直した道具（blob `ff009a37`）は … 次の2点で違い」に `hu` が入っていない

`ff009a37` は `land` に1つ数を足し、要約に `hu`（0 のときは出さない）を足した。大きさへの効きは小さいが、「2点」と書くと形の違いがそれだけと読める。3点目として書くか、2点が `0c9b7969` からの違いだと書く。

### 指摘4（軽。PM へ）: plan-t5a7.md 3 の「記録するもの」と t5a-measure.md 0章の「着地の関数の記録」が、判断に使わない値だけを挙げている

plan-t5a7.md 3 の「記録するもの」は、「避けられたのに落ちた件」を決めるのに要る記録として「その範囲の中に点の真下を外す送りがあったか」を挙げ、最も離せた隔たりを挙げていない。同じ節の PM の決定では、避けられたかは最も離せた隔たりで決め、真下を外す送りは数えない。t5a-measure.md 0章の「着地の関数の記録」の箇条も「真下を外す送りがあったかは … 数える」だけを書く（隔たりは 0章の「記録」の箇条にある）。どちらも、判断に使う「最も離せたときの max(dx, dy)」に書き換える。
