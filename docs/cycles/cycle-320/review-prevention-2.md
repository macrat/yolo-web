## 指摘

### 1. 内部の文書と道具 / 決めごとが変わる: 3回の決まりの対象が空で、(c) を果たしていない

kickoff の「レビューの指摘の扱い」は、数える対象を「PM が直して閉じる指摘への直しだけ」が続いた回としている。ところが `reviewer.md` では、PM が直して閉じる指摘しか無いレビューの結論は「承認」で、もう一度のレビューは受けない。そのため、その対象の次の回は来ない。改善指示の回は決めごとやふるまいを変える直しを含むので、数え直しになる。どちらにしても数は1より大きくならず、決まりは字のうえでしか働かない。

一方、止まらずに残っている巡りがある。内部の文書と道具への「決めごとやふるまいが変わる」指摘は、直してもう一度レビューを受ける（`reviewer.md`、`cycle-completion` 手順5の2つ目の項）。その回数に上限が無い。incident の巡りのうち、道具 20回・knowledge 10回・アンチパターン集の更新 8回・計画 13回には、この種類の指摘が含まれていた（例: review-knowledge-8 の B20「道具の直しの項に無い」、review-anti-patterns-7 の指摘1）。言い回しだけの指摘は、新しい分け方で1回で閉じる。決めごとの指摘は閉じない。reviewer が迷う指摘を「決めごとが変わる」と書けば、巡りはいつまでも続く。Owner の (c) は「サイトの価値に寄与しない修正だけが3回以上続いたら手を止めて次に進む」である。スキル・規則・アンチパターン集の本文・knowledge の決めごとの直しは、来訪者に届くものを変えない。これも「サイトの価値に寄与しない修正」に入るが、いまの決まりでは数えない。

直す向き:

- 数える回を「その回の直しが、来訪者に届くものも、来訪者に届く作業が作るもの・判定するもの（計画や設計の出荷する中身、測りの結果や合否の線）も変えない回」と定める。ほかの言い方でもよいが、PM が直して閉じる指摘に限らず、決めごとやふるまいが変わる内部の直しも数えに入れる。測りの道具や計画の、来訪者に届く結果を左右する直しは数えないので、AP-WF39 の「来訪者に届く成果物の品質レビューを巡の数で止めない」とは食い違わない。
- 3回で止めたときに残った指摘の行き先を書く（例: `docs/backlog.md` に積んで、その対象は承認を待たずに次へ進む）。そのうえで、止めた対象は「載った項目を終えた」と数えてよいことを、kickoff 手順7・8、`cycle-completion` 手順1・5、テンプレートの「指摘が残っていない」の行と、末尾の「『次回対応』などの例外は一切認めません」にそろえる。いまの行のままだと、決まりを広げたとたんに完了の判定とぶつかり、PM は巡りを続けるか、チェックを偽るかを選ぶことになる（前回の指摘2で書いた二択と同じ）。
- AP-WF39 の括弧の「効率の規律」の並びに、この決まりを足すか、決まりの側から AP-WF39 を指す。来訪者に届くものには当てないことを、両方から読めるようにする。

### 2. サイクルの記録（PM が直して閉じる）: cycle-320 の description と冒頭の段落が、進行中に戻した状態と食い違う

`index.md` の frontmatter の description は「着地の作りの欠けを次のサイクルへ渡す」のままである。本文の1段落目も「T5a-8 を次のサイクルへ送った」「このサイクルで行ったのは…申し送りである」のままで、2段落目の「進行中に戻し、T5a-8 までをこのサイクルで行う」と食い違う。完了時のチェックリストの「description がこのサイクルの内容を正確に反映している」に当たる所なので、完了の処理の前に直しておく。
