## 指摘

1. **`hitUnmatched` が符号つきの差を足すので、外れが打ち消し合って 0 に見え、「0 の種類は出さない」とも合わない**（report.mjs 241〜244行）。`off = count - rows` は負にもなりうる（問の行が関数の矩形と一致した、つまり `exclude` が効かなかったとき）。押しをまたいで `+1` と `-1` を足すと 0 になり、種類の鍵は 0 のまま出る。合成の記録で、押しごとの記録の診断の答え `[…,5,4]`（差 +1）と `n` の診断の答え `[…,3,4]`（差 −1）を置くと、`"diagnosis-answer":0` が出た。README と注釈の「どの種類も差は 0 になるはずで、0 でない種類があれば PM に報告」という使い方では、外れがあったのに報告の印が立たない。差の絶対値を足すか、正と負を分けて出すか、下の指摘2の形で差が負にならない数にするかを担当が決め、注釈と README に合わせる（`off` が 0 の押しで鍵を作らないことも含めて）。
2. **`rows` の説明がコードと違う**。measure.mjs の `rows = hit.filter(([, , row]) => row).length` は、一致したかによらない、ページの問の選択肢の行のすべての数である。ところが measure.mjs の `summarizeLanding` の注釈、report.mjs の注釈（280行「rows はそのうちの問の選択肢の行の数」）、README の `land` の欄と「着地の関数の記録の取り方」の段、t5a-measure.md 0章の「着地の関数の記録」と 10-2 の箇条は、どれも「一致しなかった数と、**そのうちの**問の選択肢の行の数」と書く。after-5 の押しごとの記録の `land` の1つ目の呼び出しは `[…,0,4]`（一致しなかった 0、行 4）で、「そのうち」なら起こりえない値であり、記録を読む人が道具の誤りと取り違える。直し方は2つあり、担当が決める。(a) 文書を「問の選択肢の行の数（一致したかによらない）」に直す。(b) 道具を文書のとおり「一致しなかった行の数」に直し、診断の答えの差を「一致しなかった、行でない箱の数」にする。(b) なら差は負にならず指摘1も解ける。置き換えの外れが合否の材料に効くのは避けるものに渡る箱（行でない箱）だけなので、(b) のほうが目的の「押せる範囲への置き換えの外れを数える」にまっすぐ合う。ただし (b) は blob が替わるので、t5a-measure.md 10章の blob と大きさの値を走らせ直して直す。
3. **report.mjs の `hitUnrecorded` の注釈の括弧書きが、記録の事実と合わない**（43〜44行「そうした形の記録の置き場（頭の行の tool が knowledge の blob を持たない道具で測ったもの）では 0 にならない」）。(i) after-4 と review-t5a7a17-run は knowledge の blob を持つ道具（measure.mjs `329cecce`、53f52874）で測ったが、`hu` を 0 のとき書かないので、after-4 の start は `hitUnrecorded` 15 になる。blob で見分ける書き方はこの置き場を外す。(ii) 古い道具の置き場でも着地の記録が要約と押しごとの記録に無ければ 0 になる（after の answers-375x550 は blob `0c9b7969` で 0）。括弧書きは消すか、「`hu` を 0 でも書く道具（measure.mjs `6b50be64` から）より前の道具で測った置き場では、着地の記録のある分だけ数が立つ」のような、記録の形による書き方にする。
