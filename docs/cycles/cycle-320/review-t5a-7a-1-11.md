## 指摘

### 指摘1（中）: 履歴に入る量を数えるコマンドは、浅い履歴では黙って少なく出る

plan-t5a7.md 3 は、PM がコミットのたびに `git log --format= --raw --no-abbrev -- 'docs/cycles/cycle-320/measure/*.jsonl' | …` で合計を数え、10MB を超える見込みならコミットの前に形を決め直すと書く。この数えが 10MB の線を守る唯一の手立てである。

ところが同じ節の「日をまたぐ記録と版」が書くとおり、セッションのリポジトリは浅い（`git rev-parse --is-shallow-repository` が true）ことがある。浅い履歴では、境より前のコミットは `git log` に出ず、境のコミットは、その時の木にあるファイルだけを足したものとして出る。測り終えて木から消した基準の版の要約（2.9MB 以下）や、T5a-8 で置き換えた前の記録は数えに入らない。plan-t5a7.md 3 が履歴を深くするのは「続きを測るとき」だけで、T5a-8 の測り直しを新しいセッションで `t5a8` に測り始めるときなどは当たらない。数えが少なく出ても誤りにならず、線を越えたことに気づけない。

直す向き: コマンドの前に「`git rev-parse --is-shallow-repository` が true なら `git fetch --unshallow origin main design-rollout` で深くしてから」を足す（README 16 行の「数えるコマンドは plan-t5a7.md 3 にある」はそのままでよい）。

### 指摘2（軽）: 誤りで終わった回の押しの記録の大きさと、置く理由の文が事実と違う

plan-t5a7.md 3 の内訳は「誤りで終わった回の押しの記録は1行 約 140B で … 0.1MB を超えない」と書き、t5a-measure.md 10-2 の「履歴に入る量」の行も「誤りで終わった回の押し 0.1MB 以下」とする。

- 140B は、押しの前に誤った回の `i: null` の行（base-8 の1行）の大きさである。押しのあとに誤った回は、`records` のすべての押しを `compactPress` の形で置く（1999〜2010 行）。押し1つは 380〜840B（10-2）で、答えの走査では1回で数 KB になる。0.1MB は、そういう回が十数回で越える。
- 「試しの走りでは誤りが 0 だった」は 10-1 の負荷 1.2〜10.6 の時の値で、10-1 自身が「負荷の高い時の送り直しの割合はこの値より大きくなりうる」と書く。
- 同じ箇条の「誤りで終わった回の押しは、続きの測りと原因の確かめに要るので、どちらの版でも置く」の「続きの測り」は、道具の動きと違う。続きの測りが見るのは要約の行（`f` の有無と `r` の `error`）だけで、押しごとの記録は読まない（363〜374 行。上の走らせ直しでも、押しごとの記録の無い置き場で続きが測れた）。

直す向き: 大きさは「押しの前に誤った回は1行 約 140B、押しのあとに誤った回はその回の押しの数 × 380〜840B」と書き、0.1MB の線をその形で置き直すか、残りの 1MB に入れる。置く理由は「原因の確かめに要るので」だけにする。

### 指摘3（軽）: 「1割を足した上の線」の根拠が、確かめた範囲より広く言っている

plan-t5a7.md 3 は、基準の版の要約 2.9MB を「いまの道具で1行あたり増えた欄の分（基準の版の走らせ直しで、答えの走査の1走査あたり約 6%）を見込んで1割を足した上の線」とする。

- 6% は答えの走査2本（kotowaza-level・character-personality。15本の平均でない）の 184B と表の 174B の比である。
- 同じ走らせ直しの「はじめる」は 163.4B で、表の 124KB ÷ 900 ≒ 138B より 18% 大きい（表はマウスの回を含む平均なので、入力の混ざりの差かもしれないが、文はこの比べに触れない）。t5a-measure.md 10-2 の「上の表の1行（「もう一度挑戦する」198B、答えの走査 174B）とほぼ同じ」も「はじめる」を並べない。
- 基準の版の要約で2番目に大きい「最後の答え・「次へ」」（355KB）は走らせ直していない。

操作の重みで足すと 2.9MB の内に収まりそうだが、文が言う「上の線」は確かめた値から出ていない。直す向き: 確かめた3つの操作の比（はじめる +18%、もう一度挑戦する −2%、答え +6%）と、確かめていない操作を書き、重みで足した値で上の線を言うか、「着地を直した版の走りで出し直すまでの仮の値」と書く。

### 指摘4（軽）: 「着地の直しの害の確かめ」の比べの出力が、数えのコマンドに入るかが決まっていない

carryover.md 7 行は、比べの出力を「記録の上限（木の合計 3MB と履歴の合計 10MB）の外のファイルとして `measure/` にコミット」するとする。plan-t5a7.md 3 と README 16 行の物差しは「`measure/` の下の `.jsonl` のうちコミットしたことのあるすべての blob」で、比べの出力が `.jsonl` なら数えに入り、carryover.md と食い違う。直す向き: 比べの出力の置き場か拡張子を決めてコマンドから外すか、carryover.md を「数えに入る」と書き直す。

### 指摘5（軽）: plan-t5a7.md 4 の「基準の版では … 結果の名前の位置を記録する」が、変えたあとの道具の記録と合わない

plan-t5a7.md 4（62 行）は、基準の版で「落ちた先・`detail`・間隔・語の選択・結果の名前の位置を記録する」と書く。変えたあとの道具は、基準の版でそれらを要約の数と印（1度の押しの操作は `s`・`g`・`d`・`w`、走査は `c`・`cm`・`x`・`dm`・`w`、結果の名前は下端が外れたかの `lo` だけ）でしか残さない。前は、名前の下端が外れた回には押しごとの記録の `fr` に位置の値が残っていたが、それも無くなった。判断はこれを読まないので害は無いが、4 を読む次の測りの担当は、基準の版でも位置の値を取ると受け取る。直す向き: 4 の基準の版の文を「要約の数と印で記録する（結果の名前は外れたかだけ）」の形にそろえる。
