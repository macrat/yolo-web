## 指摘

### 1. 「前と後の違い」の結論が、クイズのページで比べていない幅まで一致したと書いている（小）

「前と後の違い」は「違ったのは、行数（と、それによる縦の位置）と、上の 1280×800 のよくある質問の3つの 0.02px 以下の幅だけ」と書く。けれども、クイズのページの比べ（担当の `compare.mjs`）が比べるのは `tag`・`text`・`box`・`char`・`bl`・`bt`・`bb` だけで、記録の要素にも幅は無い。測ると、1280×800 の character-personality Q1 の選択肢のボタンの幅は前と後で違った（545.2 → 545.28、499.83 → 499.86、547.09 → 547.14、543.5 → 543.55。答えたあとの字の箱も同じ）。「0.02px 以下」も超えている。左端の x には関わらないが、この記録はチェックの根拠で、結論の文が測った事実を超えている。

直し方: クイズのページでも幅を比べて違いを載せるか、結論の幅の文を「`<wbr>` が変わったページ・色の辞典・`CopyButton` で比べた幅」に限り、クイズのページは幅を比べていないと書く。

### 2. 「測る範囲」が、共有の画像の変化を挙げていない（小）

「測る範囲」は「T5a-4 が来訪者に見える形を変えた所は次の4つである」とする。けれども [t5a-4-changes.md](./t5a-4-changes.md) の 4. のとおり、`/tools/unix-timestamp` の共有の画像の名前の行が「UNIXタイム / スタンプ変換」から「UNIXタイムスタンプ / 変換」に変わった。これも来訪者に見える形の変化で、4つにも「測らない」にも入っていないので、範囲が差分と事実どおりかを読み手が確かめられない。

確かめると、`share-image.tsx` は中身の列を `left: frame.CONTENT_LEFT` に絶対の位置で置き、どの行もそこから組む。前と後の画像（`.next/server/app/tools/unix-timestamp/opengraph-image.body`）で画素の左端を測ると、名前の1行目は前も後も x=110、2行目は 112 → 106 で、これは行頭の字が「ス」から「変」に替わった字形の差である。サイト名・ほかの行の左端（103・104・105）は同じだった。

直し方: 共有の画像を範囲に入れて値を載せるか、「測らない」に、行の左端を CONTENT_LEFT に固定して組むので左端が動かないこと（行頭の字が替わったぶんの字形の差だけ）を書く。

### 3. 記事のページの 1280×800 の 171.5 が、DESIGN.md §5 の 179 と違う理由が書かれていない（軽）

`<wbr>` が変わったページの表は、`/blog/tools-expansion-10-to-30` の 1280×800 の値を 171.5・263.94・272.44 と載せる。§5 の表のコンテンツ幅の左端は 179 で、読み手には 7.5px ずれているように読める。これは目次を持つ記事のページの `scrollbar-gutter: stable` でスクロールバーの分だけ `main` が左に寄るためで（cycle-316 の review-t5-15-10.md・review-t5-15-11.md）、T5a-4 とも外れとも関係が無い。記録はこのページの §5 を判断しないとしているが、値を載せる以上、1行で理由を添える。
