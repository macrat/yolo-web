## 指摘

### 1. 内部の文書と道具 / ふるまいが変わる: 3回目のレビューの指摘を直すのか、直さずに積むのかが定まっていない

kickoff の「レビューの指摘の扱い」は「1回は、レビュー1回とそれへの直し」と定める。そのうえで「3回目の回のあとにまだ指摘が残っていたら、残った指摘を backlog に積み」と書く。字のとおりに読むと、3回目のレビューの指摘を直した（3回目の回を終えた）あとに「まだ残っている」指摘を積むことになる。しかし、直したあとに指摘が残っているかは、4回目のレビューをしないと分からない。そのため、PM は次の2つのどちらにも読める。

- (i) 3回目の指摘を直し、レビューを受けずに次へ進む。決めごとやふるまいを変える直しが、レビューを通らずに入る。
- (ii) 3回目の指摘は直さずに backlog に積む。AP-WF01（「止めて残った指摘を backlog に積むまで、直すたびにレビューを受けたか」）と CLAUDE.md（"the remaining findings go to `docs/backlog.md`"）はこちらに読める。

(i) で読むと、AP-WF01 の「直すたびにレビュー」と食い違う。また、スキル・規則の文が、レビューを受けないまま変わる。新しい食い違いを入れても、捕まえる所が無い。今回の依頼文の「このあと指摘が残っても PM は backlog に積んで次へ進む」も、どちらとも読める。

直す向き: kickoff の文で、3回目のレビューで出た指摘は直さずに `docs/backlog.md` に積むと言い切る。Owner の「3回以上続いたら手を止める」とも合う。直すのが手早い言い回し・記録の指摘を PM が直して閉じるのは、これまでどおりでよい。数え方の「1回は、レビュー1回とそれへの直し」も、これに合う形にそろえる（例: 「3回目のレビューのあとは直さない」）。

## 確かめて、問題なしとしたこと

- (a): `reviewer.md` の目的の文は「内部の文書を完全無欠にすることではない」と言い切る。そのうえで、見逃さずに指摘する範囲を、来訪者に届くものと内部の決めごとやふるまいに置いている。言い回し・記録の指摘を承認の条件にしないことも書かれている。completion 手順5の点検は「プロダクトの問題を見つける」ことを目的とし、記録の網羅の照合を頼まないと定めている。incident の 90 回の巡りの型（記録の言い回し、置き場所、発生の並びの照合）は、どれも1回で閉じる。
- (b): 守る範囲は「一度でも載った項目すべて」で、外す・送る・置き換える・狭めるの4つが、kickoff 手順7・completion 手順1・AP-WF23・テンプレートで同じ言い方になっている。手順1のコマンドは、トップの階層の消えた行（`-- [`）を拾う。cycle-320 にあてると、実際に指摘2を捕まえた。決まりは働く。欠けが項目を妨げるときは、欠けを直す仕事を足して進む。止められるのは Owner の入力が要るときだけである。incident の「範囲の決め直し」の道は閉じている。`stop-cycle-guard.sh` の案内（「すべてのタスクが完了しているなら」「Ownerの入力なしに進められない正当な理由がある場合に限り」）とも食い違わない。途中で害が分かった項目を外す道が無いことも考えた。しかし、それを開けると incident と同じ抜け道になる。条件つきの項目の書き方（「直す件が無ければ閉じる」）で正当な場合は扱える。だから、いまの厳しさでよい。
- (c): 決まりは「サイクルの進め方のスキル」（kickoff の、サイクル全体に効く節）にあり、completion・CLAUDE.md・`reviewer.md` から指されている。数える回が内部の決めごとの直しにも広がり、前回の指摘1は解けた。対象ごとに数えるので、対象を分けても回数は増えるだけで、早く止める方へは動かない。

- 決まりどうしの食い違い: テンプレートの「例外は一切認めません」と backlog に積んだ指摘の関係は、最後の文で解けている。Review always の "address the feedback before proceeding" も、CLAUDE.md の同じ項の中で3回の決まりを指して解けている。AP-WF38 の「すべて対応する」は、PM が直して閉じる扱いと食い違わない。古い言い方の grep で残っていたのは、`block-review-reuse.sh`（SendMessage の流用を止めるもの）と candidates.md の AP-WF20 候補で、新しい決まりとは関わらない。completion 手順2・3の「最初からやりなおして」は、記事とデプロイの手順のもので、点検の巡りとは別である。
