# cycle-320 着地の作りの決め直し

試しの走り（t5a-measure.md 10-1）で見つかった3つの型（「はじめる」の2打目が1問目の選択肢に寄る (1)・真上から落ちる (2)、知識クイズの最後の「次へ」の2打目が結果の画面のリンクに寄せられる (3)）を、どう直すかの決定。材料は [landing-options.md](./landing-options.md)、レビューは [review-decision-landing.md](./review-decision-landing.md)・[-2](./review-decision-landing-2.md)。

## 決めたこと

### 1. 二度押しの2打目を受けない守り

切り替わりごとの守りは次の表のとおり。

| 切り替わり                                            | 守り                                                                                                                                                                     |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 「はじめる」→1問目                                    | 窓の守り                                                                                                                                                                 |
| 知識クイズの「次へ」→次の問                           | 窓の守り                                                                                                                                                                 |
| 最後の答え（診断）・最後の「次へ」（知識クイズ）→結果 | 窓の守り。起点は答えた押し（診断は答えてから 150ms の `ANSWER_SHOWN_MS` のタイマーで切り替わるが、起点は押しの時刻）                                                     |
| 診断の答え→次の問                                     | 連続の押しの守り                                                                                                                                                         |
| 知識クイズの答え→答えたあと                           | 掛けない。画面は切り替わらず、押した点は押した行（押せない字）の上に残る（t5a-design.md 4-6）                                                                            |
| 「もう一度挑戦する」→開始の画面                       | 掛けない。2打目が「はじめる」を押すのは、もう一度解くという来訪者のしようとしたことのとおりで（4-9）、着地はほかの押せるものから 56px 以上離す（landing-options.md 4-2） |

- **窓の守り**: 起点の押しがポインタの click（`detail >= 1`）のときだけ開く。窓は、起点の click の `event.timeStamp` から 700ms 未満で、起点の click の画面の座標（`clientX`・`clientY`）から max(dx, dy) が 100px 以内の、ポインタの押し。キーボードの起動（`detail === 0`）で切り替えたときは開かず、`detail === 0` の click は窓の中でも通す。「もう一度挑戦する」のあとの2打目が「はじめる」を押して1問目に移ったときは、その押しが起点になり窓が開く。
- **連続の押しの守り**: 答えを入れた click に続く、ブラウザが連続の押しと数えた click（`detail >= 2`）で、答えを入れた click の画面の座標から max(dx, dy) が 100px 以内のものを受けない。時間はブラウザの数え方に任せる。
- **押しの単位**: 守るかどうかは、押し下げ（`pointerdown`）の `event.timeStamp`・座標・`detail` で決め、その押しの `mousedown` と `click` の両方に同じ判定を掛ける（押し下げが窓の中で離しが窓の外でも、1つの押しとして受けない）。
- **止め方**: `window` の捕捉の段階で、受けない押しの `mousedown` は `preventDefault`（フォーカスが押したものへ移らず、4-7 で置いたフォーカスと語の選択を保つ）、`click` は `preventDefault` と `stopPropagation`（React の `onClick`・素の `a[href]` の移動・`summary` の開閉・Next の `Link` の移動を止める）。形も動きも足さない。押し下げで出る hover と active の線は止めない（下の「受ける害」）。
- **数える**: 受けなかった押しを GA のイベント `quiz_press_guarded`（引数: `transition` は `start`・`next`・`result`・`answer` のどれか、`content_id` は本）で、1つの守りにつき最初の1回だけ送る。受けなかった押しの押し下げの `event.timeStamp` から 3 秒以内に、同じ要素（受けなかった押しの的になった要素と同じ DOM の要素）をポインタで押して受けたときは、`quiz_press_guarded_retry`（同じ引数と、受けなかった押しからの経過 ms）を1回送る。偶然の一致（二度押しを正しく受けなかったあと、読んで同じ選択肢を選ぶ人）とは、このイベントだけでは見分けない。T10 が、選択肢の数から出る偶然の割合（4択なら 25%）を基準に置き、それを越える割合と経過 ms の分布で線を引く。

### 2. 着地の選び方に余白を足す（A″）

着地の選び方（t5a-design.md 4-9）を landing-options.md 2-1 の A″ にする。送る枝の順の「0 でない」を「16 以上」に替え、送らない枝は基準で両方の組から 16 以上なら送らない。範囲の中に 16 以上の送りが無い回は、いまの関数の送りのままにする。

### 3. 守りのあとの押し

窓のあと（700ms 以上）の押しと、診断の答えのあとの連続と数えられない押しは、来訪者が新しい画面を見たあとの別の押しとして受ける。その押しが選択肢やリンクに落ちる件は、条件7・D5 の合否に入れず、件の数と隔たりを記録して B-620 の材料にする。

## 理由

- **送りと組みでは、害なく 0 にならない**: landing-options.md の実測では、着地に余白を取る形（A・A′・A″）と「はじめる」を上げる形（B′）では、character-personality の 375×550 を含めて直らない件が残る。直るのは、「はじめる」を下げる B（この本だけなら +62px、全部の本なら +86px）と A″ の組か、見せる範囲を広げる C（+207px）である。B は開始の画面に 86px の空きを足し、320×550 の4本で「はじめる」を最初の画面からほぼ外す（t5a-design.md の「はじめるを狭い画面でも最初の画面に入れる」に反する）。C は帯を画面から外す。200% は、どの形でも「はじめる」の 12 回と知識クイズの「次へ」の 16 回が残る（landing-options.md 3）。
- **窓の中の、1打目の近くの押しは、二度押しの2打目と見てよい**: その押しは、新しく出た問か結果を読む前の、前の押しの近くへの押しである。700ms は、Android の二度押しの間隔の上限 300ms（`android.view.ViewConfiguration` の `DOUBLE_TAP_TIMEOUT`）、道具の2打目（293〜306ms）、Windows のダブルクリックの既定の 500ms を覆い、条件7 の間隔（0・90・150・300・500ms）を境目から 200ms 離す。
- **1打目の点からの距離で絞る**: 100px は Android が二度押しとみなす距離（`DOUBLE_TAP_SLOP`）である。タッチの調整が寄せるのは触れた面の半辺（10〜16px）までで（knowledge §8）、試しの走りでも2打目の click は1打目から 9px のずれだった（t5a-measure.md 10-1）。寄せた2打目はどれも 100px の中に入るので、守りは弱まらない。窓の中でも 100px の外（ヘッダ・別の選択肢・結果の画面の下のリンクなど）を意図して押した1打は受ける。cycle-301 の「領域を絞った窓」（knowledge §4）は押せるものの置き場で絞ったために1打目の座標に来た窓の外のものが無防備になった型で、2打目の落ちる点そのもので絞るこの形とは違う。座標は画面の座標で比べる。着地の送りのあとも、指の位置は画面の上で同じだからである。
- **診断の答え→次の問に窓を掛けない理由と、連続の押しの守りを掛ける理由**: 診断の次の問も、新しく出た問を読む前に意図して押すことはない点で、3つの切り替わりと同じである。違うのは、来訪者が通る回数と、速く答える人の押しの間隔である。1回解くあいだに 10 回前後通り、cycle-301 は、ここに 600ms 未満を捨てる窓を掛けて、速く答える人の答えを日常的に捨てた（cycle-316/options.md「B-620 を含めない理由」）。窓の長さで絞ると、その害の型にまた近づく。そこで、ブラウザが同じ連続の押しと数えたもの（`detail >= 2`。ブラウザは同じ所への短い間隔の押しだけを連続と数える）だけを受けない。読んでから答える押しは連続と数えられないので捨てない。4-9 が L2（`detail >= 2`）を退けた理由は、Chromium のタッチの 500ms 前後の2打目が `detail` 1 で届くことと iOS の Safari の数え方を確かめられないことで、「全部は塞げない」であり「塞げる分を塞ぐと害が出る」ではない。塞げる分を塞ぐ。塞げない分（連続と数えられない2打目）は残り、B-620 の材料として条件7・D5 で間隔ごとに数える。
- **キーボードを開かず通す**: cycle-301 は、キーボードで答えたあとの指の押しと、キーボードだけの速い答えを窓で捨てた（knowledge §5 の軸2・軸3）。二度押しはポインタだけで起きる。読み上げの起動が `detail === 0` の合成 click として届くことは推論である（knowledge §3）。外れて `detail >= 1` で届くと、読み上げで「はじめる」を起動したあとの 700ms・100px の中の次の起動を受けない。読み上げの来訪者は見出しを聞いてから身ぶりで選択肢へ移るので、700ms に収まる見込みは小さく、倒れる向きは押し直し1回である。見張らずに受け入れる（t5a-design.md 8章の (iii)）。
- **受ける害**: 窓の中で 100px の中を意図して押したとき（もう一度解く来訪者が1問目の位置を覚えていて素早く押すなど）、その押しは何も起こさない。押し下げの hover と active の線は出るので、来訪者には「押した形が一瞬出て何も起きない」に見え、押し直す手がかりになる。害は押し直し1回で、答えも計測も壊れない。この害を受け入れ、`quiz_press_guarded_retry` で見張る。見張る数と戻す判断をする線は、T10 が ADR009 に書く（t5a-design.md 8章の (iii)）。
- **見た目を変えない**: 押せない形（無効）を見せる形（landing-options.md の D）は、DESIGN.md §6（無効は来訪者が揃えられる条件を待つ形）と §11（UI の動きは3つに限り、次の操作を待たせない）と食い違う。この決定は形も動きも足さない。
- **A″ を採る**: A″ は、ほかの操作の送りを測った範囲で1回も変えず（landing-options.md 2-1）、守りのあとの押しで、選択肢から 1〜14px に着いていた「はじめる」の 42 件を 16px 以上に離す。来訪者の側の害が見つからず、守りのあとの押しの寄りを減らす。
- **結果の画面の組みを直す B を採らない**: 知識クイズの結果のボックスの下を 105px 下げる形（landing-options.md 2-2）は、型 (3) の起きる高さを消すが、型 (3) は窓の守りが受け持つ。窓のあとの押しは合否に入れない（決めたこと 3）ので、組みを変えて結果の下の部品を下げる来訪者の側の得が無い。
- **守りのあとの押しを合否に入れない**: 窓のあとの押しと、連続と数えられない押しは、新しい画面が見えてからの押しで、その押しが選択肢に落ちるのは来訪者が見ている画面のその所を押したことである。t5a-design.md 8章の「件を受け入れる」を「答えを入れるものには選ばない」としたのは二度押しの2打目についての決まりで、この決定で、二度押しの2打目は守りが受け持つ。

## 覆す決めごと

- cycle-316/options.md「B-620 を含めない理由」の「時間の窓で回答を黙って捨てる仕組みは入れない」を、上の3つの切り替わりのポインタの押しに限って覆す。診断の答え→次の問には窓を入れず、連続の押しの守りだけを入れる。
- t5a-design.md 4-9 の表の L1（切り替わってから一定の時間、押しても捨てる）を「捨てる」とした判断を3つの切り替わりに限って、L2（click の `detail ≥ 2` を捨てる）を「捨てる」とした判断を診断の答え→次の問に限って覆す。
- t5a-design.md 8章の「件を受け入れる」の決まりの掛かる範囲を、二度押しの2打目に限る（上の理由）。

## 測りの合否（条件7・D5）

- **窓の守りの回**: 「はじめる」と結果への切り替わりは、条件7 の走査（全15本 × 6章の画面 × 最初の行と最後の行で解き切る）の中で、タッチとマウス（`clickCount: 2`）で 0・90・150・300・500ms の間隔で2打目を押す。知識クイズの「次へ」は、同じ走査で3本の9問すべてを同じ間隔で押す。2打目が、答え・ページの移動・開閉のどれも起こさず、フォーカスが 4-7 の置き場から動かないこと。外れた件が 0 で合格。
- **連続の押しの守りの回**: 診断の答え→次の問を、同じ走査で 0・90・150・300・500ms で押す。`detail >= 2` で届いた2打目が答えを入れないこと（外れた件 0 で合格）。`detail` 1 で届いた2打目が次の問に落ちた件は、間隔ごとに数を記録する（B-620 の材料。合否に入れない）。
- **D5 の2打目をずらす走査**: 守りを掛けた3つの切り替わりは、窓の中（300ms）と窓のあと（900ms）で走らせる。窓の中は、1打目から 100px の中のずれで受けないこと・外のずれで受けることを合否に入れる（外れた件 0）。窓のあとは、A″ の着地で選択肢・第1の組から 16px 未満に落ちた件の数と隔たりを記録する（合否に入れない）。診断の答え→次の問は、いまのとおり 90・300ms で走らせ、2打目の位置と次の問に落ちた数を記録する。
- **空振りでないことの対**: 同じ点を起点から 900ms のあとに押すと答えが入る・リンクが開く・ボタンが働くこと。キーボードで切り替えたあとの 150ms の Enter が働くこと。どれも 0 件の外れで合格。
- **守りを掛けない切り替わりの線**: 知識クイズの答え→答えたあとの第1の組（「次へ」を含む）0、「もう一度挑戦する」→開始の画面の第1の組（「はじめる」を除く）0 は、6章 条件7 のまま残す。

## 確かめること

- 着地の直しの害の確かめ（「実施する作業」）では、直す前と後の版で、診断の答え→次の問の読んでから答える押し（1秒以上の間隔）が前と同じに答えを入れること、守りを掛けた3つの切り替わりで窓のあとの押しが前と同じに働くこと、A″ がほかの操作の送りを変えないこと、受けなかった押しで hover と active の線が出ても形が残らないことを確かめる。
- iOS の Safari が二度押しの2打目を 700ms より後に届けるか、連続の押しを `detail` でどう数えるかは、このコンテナで確かめられない（t5a-design.md 8章の (iii)）。出荷のあと、上の数えるイベントで見張る。
