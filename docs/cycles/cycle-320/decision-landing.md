# cycle-320 着地の作りの決め直し

試しの走り（t5a-measure.md 10-1）で見つかった3つの型（「はじめる」の2打目が1問目の選択肢に寄る (1)・真上から落ちる (2)、知識クイズの最後の「次へ」の2打目が結果の画面のリンクに寄せられる (3)）を、どう直すかの決定。材料は [landing-options.md](./landing-options.md)、レビューは [review-decision-landing.md](./review-decision-landing.md)。

## 決めたこと

### 1. 二度押しの2打目を受けない守り

- **掛ける切り替わり**: 「はじめる」→1問目、知識クイズの「次へ」→次の問、最後の答え（診断）・最後の「次へ」（知識クイズ）→結果の3つ。診断の答え→次の問と、知識クイズの答え→答えたあとには掛けない。
- **窓を開く押し**: 切り替えた押しがポインタの click（`detail >= 1`）のときだけ開く。キーボードと読み上げの起動（`detail === 0`）で切り替えたときは開かない。診断の最後の答えは、答えてから 150ms（`ANSWER_SHOWN_MS`）のタイマーで結果へ切り替わるが、窓の起点は答えた押しの時刻にする。
- **窓**: 起点の click の `event.timeStamp` から 700ms 未満の `event.timeStamp` を持つ押し。時刻は入力が起きた時刻（`event.timeStamp`）で比べ、受け手が走った時刻では比べない。
- **受けない押し**: 窓の中に届いたポインタの押しすべて（ページのどこでも。新しく出たものかどうかで分けない）。`detail === 0` の click は窓の中でも通す。
- **止め方**: `window` の捕捉の段階で、窓の中のポインタの `mousedown` は `preventDefault`（フォーカスが押したものへ移らず、4-7 で置いたフォーカスと語の選択を保つ）、`click` は `preventDefault` と `stopPropagation`（React の `onClick`・素の `a[href]` の移動・`summary` の開閉・Next の `Link` の移動を止める）。見た目は何も変えない。
- **数える**: 窓の中で受けなかった click を、切り替わりの種類ごとに GA のイベントで数える（受けなかった数と、そのあと 3 秒以内に同じものが押されたか）。

### 2. 着地の選び方に余白を足す（A″）

着地の選び方（t5a-design.md 4-9）を landing-options.md 2-1 の A″ にする。送る枝の順の「0 でない」を「16 以上」に替え、送らない枝は基準で両方の組から 16 以上なら送らない。範囲の中に 16 以上の送りが無い回は、いまの関数の送りのままにする。

### 3. 窓のあとの押し

窓のあと（700ms 以上）の押しは、来訪者が新しい画面を見たあとの別の押しとして受ける。その押しが切り替わる前の点の近くの選択肢やリンクに落ちる件は、条件7・D5 の合否に入れず、件の数と隔たりを記録する。

## 理由

- **送りと組みでは 0 にならない**: landing-options.md の実測では、着地に余白を取る形（A・A′・A″）、「はじめる」を下げる・上げる形（B・B′）、見せる範囲を広げる形（C）を、どう組み合わせても全画面で 0 にならない。狭く短い画面（375×550・320×550・200%）では、問のまとまりが画面をほぼ埋め、1打目の点の下にどう送っても選択肢が来る。閲覧の 85.8% を占める character-personality の 375×550 は、ボタンのどこを押しても直る形が無い（4-1）。下げる B は 320×550 で「はじめる」を最初の画面から出し、来訪者が始められなくなる。
- **窓の中の押しは、二度押しの2打目と見てよい**: 窓の中の押しは、新しく出た問か結果を読む前の押しである。問の見出しと選択肢を読む前に答えを選ぶことも、結果を読む前にほかのものを押すことも、来訪者が意図してする見込みは小さい。700ms は、Android の二度押しの間隔の上限 300ms（`android.view.ViewConfiguration` の `DOUBLE_TAP_TIMEOUT`）、道具の2打目（293〜306ms）、Windows のダブルクリックの既定の 500ms を覆い、条件7 の間隔（0・90・150・300・500ms）を境目から 200ms 離す。
- **範囲をページ全体にする**: cycle-301 は、領域を絞った窓の外（「X でシェア」と FAQ の `summary`）に2打目が落ちた（input-events-and-guards.md §4）。窓の中にほかの所を意図して押す見込みも同じく小さいので、範囲を絞って得るものが無い。1打目の点から 100px（`DOUBLE_TAP_SLOP`）の中だけを受けない形も比べたが、Chromium のタッチの調整は点から離れた押せるものへ寄せる（knowledge §8）ので、距離で絞ると寄せた先を守れない。採らない。
- **キーボードと読み上げを開かず通す**: cycle-301 は、キーボードで答えたあとの指の押しと、キーボードだけの速い答えを窓で捨てた（knowledge §5 の軸2・軸3）。二度押しはポインタだけで起きる。
- **cycle-301 の失敗と違う所**: cycle-301 は、画面の切り替えから 600ms 未満の回答を、すべての問のあいだで捨てた（cycle-316/options.md「B-620 を含めない理由」）。診断の答え→次の問では、速く答える人が意図して押した答えが日常的に捨てられた。この決定は、その切り替わりに掛けない。掛ける3つの切り替わりは、どれも新しく出たものを読んでからでないと意図して押せない所である。
- **受ける害**: 窓の中の押しが意図したものだったとき（もう一度解く来訪者が1問目の位置を覚えていて素早く押すなど）、その押しは何も起こさず、それと分かる形も無い。害は押し直し1回で、答えも計測も壊れない。この害を受け入れる。数えるイベントで、受けなかった押しのあとに同じものがすぐ押された数を見張る。見張る数と戻す判断をする線は、T10 が ADR009 に書く（t5a-design.md 8章 (iii)）。
- **見た目を変えない**: 押せない形（無効）を見せる形（landing-options.md の D）は、DESIGN.md §6（無効は来訪者が揃えられる条件を待つ形）と §11（UI の動きは3つに限り、次の操作を待たせない）と食い違う。この決定は形も動きも足さない。
- **A″ を採る**: A″ は、ほかの操作の送りを測った範囲で1回も変えず（landing-options.md 2-1）、窓のあとの押しで、選択肢から 1〜14px に着いていた「はじめる」の 42 件を 16px 以上に離す。来訪者の側の害が見つからず、窓のあとの押しの寄りを減らす。
- **窓のあとの押しを合否に入れない**: 700ms 以上あとの押しは、二度押しの2打目ではなく、新しい画面が見えてからの押しである。その押しが選択肢に落ちるのは、来訪者が見ている画面のその所を押したことで、問の出し方の欠けではない。t5a-design.md 8章の「件を受け入れる」を「答えを入れるものには選ばない」としたのは、二度押しの2打目についての決まりで、この決定で窓の中の2打目は守りが受け持つ。窓のあとの件は、数と隔たりを記録して B-620 の材料にする。

## 覆す決めごと

- cycle-316/options.md「B-620 を含めない理由」の「時間の窓で回答を黙って捨てる仕組みは入れない」を、上の3つの切り替わりのポインタの押しに限って覆す。診断の答え→次の問と、キーボードと読み上げには、これまでどおり入れない。
- t5a-design.md 4-9 の表の L1（切り替わってから一定の時間、押しても捨てる）を「捨てる」とした判断を、上の範囲に限って覆す。L2（click の `detail ≥ 2`）は、Chromium のタッチの 500ms 前後の2打目が `detail` 1 で届き（6章 条件7）、iOS の Safari の数え方も確かめられないので採らない。
- t5a-design.md 8章の「件を受け入れる」の決まりの掛かる範囲を、窓の中の2打目に限る（上の理由）。

## 測りの合否（条件7・D5）

- **窓の中の回**: 3つの切り替わりを、タッチとマウス（`clickCount: 2`）で 0・90・150・300・500ms の間隔で押す。2打目の click が、答え・ページの移動・開閉のどれも起こさず、フォーカスが4-7 の置き場から動かないこと。外れた件が 0 で合格。
- **空振りでないことの対**: 同じ点を、起点から 900ms のあとに押すと答えが入る・リンクが開く・ボタンが働くこと（守りが窓のあとに解けること）。診断の答え→次の問を 150ms の間隔で押すと、2打目が次の問の答えを入れること（守りを掛けない所が変わらないこと）。キーボードで切り替えたあとの 150ms の Enter が働くこと。どれも 0 件の外れで合格。
- **窓のあとの回**: D5 の2打目をずらす走査は、窓のあと（900ms）の押しで行い、A″ の着地で選択肢・第1の組から 16px 未満に落ちた件の数と隔たりを記録する（合否に入れない）。

## 確かめること

- 着地の直しの害の確かめ（「実施する作業」）では、直す前と後の版で、診断の答え→次の問の速い押しが前と同じに答えを入れること、守りを掛けた3つの切り替わりで窓のあとの押しが前と同じに働くこと、A″ がほかの操作の送りを変えないことを確かめる。
- iOS の Safari が二度押しの2打目を 700ms より後に届けるかは、このコンテナで確かめられない（t5a-design.md 8章の (iii)）。出荷のあと、上の数えるイベントで見張る。
