# cycle-320 着地の作りの決め直し

試しの走り（t5a-measure.md 10-1）で見つかった3つの型（「はじめる」の2打目が1問目の選択肢に寄る (1)・真上から落ちる (2)、知識クイズの最後の「次へ」の2打目が結果の画面のリンクに寄せられる (3)）を、どう直すかの決定。材料は [landing-options.md](./landing-options.md)、レビューは [review-decision-landing.md](./review-decision-landing.md)〜[-7](./review-decision-landing-7.md)。

## 決めたこと

### 1. 二度押しの2打目を受けない守り

切り替わりごとの守りは次の表のとおり。

| 切り替わり                                            | 守り                                                                                                                                                                     |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 「はじめる」→1問目                                    | 窓の守り                                                                                                                                                                 |
| 知識クイズの「次へ」→次の問                           | 窓の守り                                                                                                                                                                 |
| 最後の答え（診断）・最後の「次へ」（知識クイズ）→結果 | 窓の守り。起点は答えた押し（診断は答えてから 150ms の `ANSWER_SHOWN_MS` のタイマーで切り替わるが、起点は押しの時刻）                                                     |
| 診断の答え→次の問                                     | 連続の押しの守り                                                                                                                                                         |
| 知識クイズの答え→答えたあと                           | 掛けない。画面は切り替わらず、押した点は押した行（押せない字）の上に残る（t5a-design.md 4-6）                                                                            |
| 「もう一度挑戦する」→開始の画面                       | 掛けない。2打目が「はじめる」を押すのは、もう一度解くという来訪者のしようとしたことのとおりで（4-9）、着地はほかの押せるものから 56px 以上離す（landing-options.md 4-2） |

- **起点**: 切り替えた押しがポインタの click（`detail >= 1`）だったときだけ、その押しを起点にする。起点の時刻と座標は、その click を出した押し（選び方は下の「押しの単位」）の `pointerdown` の `event.timeStamp` と画面の座標（`clientX`・`clientY`）で取る。キーボードの起動（`detail === 0`）で切り替えたときは起点を作らない。「もう一度挑戦する」のあとの2打目が「はじめる」を押して1問目に移ったときは、その押しが起点になる。
- **窓の守り**: 起点から、押し下げ（`pointerdown`）の `event.timeStamp` が 700ms 未満で、画面の座標が直線の距離で 100px 以下のポインタの押しを受けない。
- **連続の押しの守り**: 起点（答えを入れた押し）から、押し下げの `event.timeStamp` が 700ms 未満で、画面の座標が直線の距離で 100px 以下で、かつ連続の押しであるものを受けない。連続かどうかは、入力で数え方を分ける。タッチとペン（`pointerType` が `touch` か `pen`）は、守りが自分で数え、直前の押し（起点の押しか、受けなかった押しか、答えを見せる間に答えた問の押せない行の上で離した押し）の離し（`pointerup`）の `event.timeStamp` から次の押し下げまでが 300ms 未満（Android の `DOUBLE_TAP_TIMEOUT` と同じ物差し）なら連続とし、連続は押しごとに連鎖する（速い三度押しの3打目も、2打目の離しから数えて連続になる。マウスの `detail` が直前の押しから連鎖して増えるのと同じ）。受けない範囲は、連鎖しても起点から 700ms 未満・100px 以下のまま変えない。マウスは、ブラウザの数え方に任せ、その押しの `mousedown` の `detail >= 2` なら連続とする。
- **押しの単位**: 時刻と座標は押し下げ（`pointerdown`）から、マウスの連続の数は `mousedown` の `detail` から取る（`pointerdown` の `detail` はいつも 0 で、連続の数を持たない）。タッチとペンの連続は、上の `pointerup` と `pointerdown` の時刻で決める。押しの `mousedown` と `click`（互換のマウスの事象）は、ブラウザが押しの順に出すが、タッチでは離したあとにまとめて出すので、速い連打では2打目の `pointerdown` が、ときには2打目の `pointerup` まで、1打目の `mousedown` と `click` より先に届く（`docs/knowledge/input-events-and-guards.md` §9）。そこで押しを押し下げの順に並べて覚え、`mousedown` は `mousedown` をまだ受けていない押しに、`click` はまだ `click` を受けていない押しに、いちばん古いものから結ぶ（事象が届いた時に離し終えている押しのいちばん新しいものに結ぶと、2打目の離しまで先に届いた連打で、1打目の `click` を2打目に結ぶ）。`click` が押しと同じ `pointerType` でその押しの `pointerId` を持てば、その押しに結ぶ（Chromium の `click` の形。Chromium の番号は、マウスはいつも 1、ペンは初めて使った時に付いた番号を押しを分けても使い続け、タッチは押しごとに新しい番号になり、型をまたいで重ならない。同じ番号の押しが並びに2つあるのはペンだけで、そのときはいちばん古い押しに結ぶ）。WebKit は Safari 18.2 からタッチの `click` を `pointerType` が `"mouse"` の `PointerEvent` で出すことがあり（WebKit Bug 282988）、番号も押しと合うとは限らないので、番号は型の合うときだけ使う。ほかの互換の事象（番号を持たない `click`・型の合わない `click`・`mousedown`）は、事象の点から押し下げか離しの点までの縦と横の隔たりの大きいほう（`max(dx, dy)`）が 32px 以下の押しのうち、受ける押しのいちばん古いものに、受ける押しが無ければいちばん古いものに結ぶ。32px の中に押しが無ければ、すべての押しから同じく選ぶ。点で絞るのは、離しても互換の事象を出さない押し（2本の指で触れた押し・iOS の Safari の押せない字へのタップ）に、次の押しの事象を結ばないためである。同じ点に残ったその押しとは点でも見分けられないので、受ける押しを先に選び、迷ったら来訪者の押しを止めない側に倒す。受ける押しを先に選んでも、指の速い連打の結び方は変わらない。1打目の事象が届く時は守りがまだ開いておらずどの打も受ける押しで、守りの中の速い連打ではどの打も受けない押しなので、どちらでもいちばん古い押しに結ぶ。守りの起点にする押し（`click` を出した押し）は、結んだ押しと別に選ぶ。番号で結べた `click` では結んだ押しを、番号で結べない `click` では、`click` の点から 32px の中でいちばん新しく離した押しを起点にする。同じ点に残った互換の事象を出さない押しに結んだ `click` で、その押しを起点にすると、起点が来訪者の押しより前にずれて窓が早く閉じ、そのあとの二度押しの2打目を受けてしまうからである。いちばん新しく離した押しなら起点は前にずれず、2打目の離しまで先に届いた連打で起点が2打目になっても、窓は後ろへ延びる側にだけずれる。押し直しの経過の受けた側も、この押しの押し下げから数える。経過の止めた側の元（受けなかった押し）も、止めた事象（`mousedown` か `click`）を出した押しを、結んだ押しと別に選ぶ。番号で結べた `click` では結んだ押しを、番号で結べない事象では、事象の点から 32px の中の受けない押しのうち、`mousedown` ならいちばん新しく押し下げた押しを、`click` ならいちばん新しく離した押しを元にする。同じ点に互換の事象を出さない押しが残ると、画面を切り替えた押しは `click` を受けないまま並びに残って守りを開く時に受けない押しになり、そのあとの二度押しの2打目の事象は順でその押しに結ばれるので、結んだ押しを元にすると、経過が止めた押しより前から数えられて長いほうへずれるからである。守りを開く時、起点より前に押し下げた押しは範囲にも連続にも当てない（当てると、タッチとペンの連続の元が起点より前へ戻る）。ただ、並びに残っている起点とそれより前の押しは、切り替えた `click` を結んだ押しより後の、まだ `click` を受けていない押しで、互換の事象を出さないまま残った押しか、事象が遅れて届く連打の2打目からなので、受けない押しにする。並びに残すのは、押し下げているか、離して互換の事象を待つ押しだけである。`click` を受けた押しとそれより前の押し、`pointercancel` で引いて送りになった押しは外す。`click` を受けずに離した押しは、互換の事象の順で外し方を分ける。`mousedown` を離しより前に受けた押し（マウスと hover を持つペンの順）は、離しに続けて `click` まで出し終えるので、次の押し下げまでに `click` を受けていなければ（押し下げた的が離すまでに DOM から外れた押し）その押し下げで外す。残すと、同じ番号の次の押しの `click` がそれに結ばれる。離したあとに `mousedown` を出す押し（タッチと hover を持たないペン）は、速い二度押しの2打目の押し下げが1打目の `click` より先に届くので、次の押し下げでは外さず、離してから 1 秒たっても `click` を受けなければ（2本の指で触れた押しなど）外す。受けるかは押し下げの時刻と座標で決め、受けないと決めた押しは、その押しの `mousedown` と `click` の両方を受けない（押し下げが窓の中で離しが窓の外でも、1つの押しとして受けない）。守りが開く前に押し下げて、まだ `click` まで届いていない押しも同じ決まりで、守りが開いた時に決める。これに当たる押しは2つある。1つは「はじめる」と「次へ」の、1打目の `click` より先に押し下げた指の2打目である（守りは1打目の `click` の処理の中で開く）。もう1つは診断の答えと最後の答えの、答えを見せる 150ms のあいだに触れて切り替わったあとに離す指で、押し下げが切り替わりの前でも、`click` が新しい画面のもの（次の問の選択肢・結果の画面のリンク）に届く（タッチの落ちる要素は離した時の組みで決まる。knowledge §8）。タッチと hover を持たないペンは `mousedown` も新しい画面に届く。マウスと hover を持つペンは、`mousedown` が押し下げのすぐあとに見せる間の画面に届き、押し下げた的が切り替わりで DOM から外れるので、Chromium は `click` を出さない（knowledge §9。`click` を出すブラウザでも同じ決まりで止める）。マウスの連続は、見せる間に届いたその押しの `mousedown` の `detail` で決める。答えを見せる間に答えた問の押せない行の上で離した押しは、何も起こしていないので止めず、タッチとペンの連続の元にだけする。主のポインタでない押し（`isPrimary` が偽。2本目からの指）と主のボタンでない押し（`button !== 0`。右や中のボタン）は二度押しの2打目にならないので、受けない押しの判定にも押しの記録にも入れず、`quiz_press_guarded` にも数えない。対の `pointerdown` を持たない `click`（キーボードと読み上げの起動。`detail === 0`）は、窓の中でもそのまま通す。
- **止め方**: `window` の捕捉の段階で、受けない押しの `mousedown` は `preventDefault`（フォーカスが押したものへ移らず、4-7 で置いたフォーカスと語の選択を保つ）、`click` は `preventDefault` と `stopPropagation`（React の `onClick`・素の `a[href]` の移動・`summary` の開閉・Next の `Link` の移動を止める）。形も動きも足さない。押し下げで出る hover と active の線は止めない（下の「受ける害」）。
- **数える**: 受けなかった押しを GA のイベント `quiz_press_guarded`（引数: `transition` は `start`・`next`・`result`・`answer` のどれか、`content_id` は本）で、1つの守りにつき最初の1回だけ送る。送るのは、`mousedown` か `click` を実際に止めたときだけで、指で引いて送りになった押しは数えない。受けなかった押しの押し下げの `event.timeStamp` から 3 秒以内に、同じ押せるもの（止めた事象（`mousedown` か `click`）の的と受けた `click` の的から、`reveal.ts` の集め方で `closest` した押せるもの。押せるものの上でなかった押しは元に入れない）をポインタで押して受けたときは、`quiz_press_guarded_retry`（同じ引数と、受けなかった押しの押し下げから受けた押しの押し下げまでの経過 ms の `elapsed_ms`。どちらの押しも、上の「押しの単位」の、事象を出した押しの選び方で選ぶ）を1回送る。2つのイベントは出荷の日から数え始めるものとして T10 の基線の行に、見張りは T9 の行に載せる（D5 は (iii) で見張るものになる）。意図した押しを止めたときの押し直しは読む時間を要らずに早く来るので、T10 は、割合でなく経過 ms の分布（読んでから選んだ押しより早い山があるか）を主にして線を引く。

### 2. 着地の選び方に余白を足す（A″）

着地の選び方（t5a-design.md 4-9）を landing-options.md 2-1 の A″ にする。点から押せるものまでの隔たり d1・d2 は、max(dx, dy)（縦と横の隔たりの大きいほう）で測る。タッチの調整は縦と横のそれぞれで触れた面の半辺の中の押せるものへ寄せるので（knowledge §8）、直線の距離では、縦にも横にも 16px より近い斜めの点（dx = dy = 12 など）を 16 以上と数えて、寄る点を残す。landing-options.md の 16 も max(dx, dy) で測った値である。16 以上の送りがあるかの判定と、16 以上の送りの中での比べ（送る枝の順の 3・4 の「大きい」を含む）は、どれも max(dx, dy) で行う。範囲の中に 16 以上の送りが無い回は、いまの関数（`reveal.ts` の `chooseLanding`。行の矩形と直線の距離で比べる）を何も変えずにそのまま使う。16 以上の送りがある回は、送る枝の順の「0 でない」を「16 以上」に替え、送らない枝は基準で両方の組から 16 以上なら送らない。この回の矩形は、選択肢の行の罫線を除いた押せる範囲（`data-hit-area="after"` の箱）で取る。landing-options.md 2-1 で測った A″ はこの形である（`chooseA3`。16 以上の回は罫線の内側の矩形と max(dx, dy)、無い回は `chooseLanding` そのまま）。

### 3. 守りのあとの押し

窓のあと（700ms 以上・100px の外）の押しと、診断の答えのあとの連続と数えられない押しは受ける。その大半は来訪者が新しい画面を見たあとの別の押しだが、塞げない二度押しの2打目も入る（診断の答え→次の問の、連続と数えられない2打目。3つの切り替わりの 700ms 以上の2打目。ダブルクリックを遅くした人や手の遅い人の二度押しなど）。これらは条件7・D5 の合否に入れず、件の数と隔たりを記録して B-620 の材料にする。

## 理由

- **送りと組みでは、害なく 0 にならない**: landing-options.md の実測では、着地に余白を取る形（A・A′・A″）と「はじめる」を上げる形（B′）では、character-personality の 375×550 を含めて直らない件が残る。直るのは、「はじめる」を下げる B（この本だけなら +62px、全部の本なら +86px）と A″ の組か、見せる範囲を広げる C（+207px）である。B は開始の画面に 86px の空きを足し、320×550 の4本で「はじめる」を最初の画面からほぼ外す（t5a-design.md の「はじめるを狭い画面でも最初の画面に入れる」に反する）。C は帯を画面から外す。200% は、どの形でも「はじめる」の 12 回と知識クイズの「次へ」の 16 回が残る（landing-options.md 3）。
- **窓の中の、1打目の近くの押しは、二度押しの2打目と見てよい**: その押しは、新しく出た問か結果を読む前の、前の押しの近くへの押しである。700ms は、Android の二度押しの間隔の上限 300ms（`android.view.ViewConfiguration` の `DOUBLE_TAP_TIMEOUT`）、道具の2打目（293〜306ms）、Windows のダブルクリックの既定の 500ms を覆い、条件7 の間隔（0・90・150・300・500ms）を境目から 200ms 離す。`DOUBLE_TAP_TIMEOUT` は1打目の離しから2打目の押し下げまでで測り、窓は1打目の押し下げから数えるので、覆うのは1打目を押している時間が 400ms 未満のときである（ふつうの押しはそれより短い）。
- **1打目の点からの距離で絞る**: 100px は Android が二度押しとみなす直線の距離（`DOUBLE_TAP_SLOP`）で、同じく直線の距離で比べる。タッチの調整が寄せるのは触れた面の半辺（10〜16px）までで（knowledge §8）、試しの走りでも2打目の click は1打目から 9px のずれだった（t5a-measure.md 10-1）。寄せた2打目はどれも 100px の中に入るので、守りは弱まらない。窓の中でも 100px の外（ヘッダ・別の選択肢・結果の画面の下のリンクなど）を意図して押した1打は受ける。cycle-301 の「領域を絞った窓」（knowledge §4）は押せるものの置き場で絞ったために1打目の座標に来た窓の外のものが無防備になった型で、2打目の落ちる点そのもので絞るこの形とは違う。座標は画面の座標で比べる。着地の送りのあとも、指の位置は画面の上で同じだからである。
- **診断の答え→次の問に窓を掛けない理由と、連続の押しの守りを掛ける理由**: 診断の次の問も、新しく出た問を読む前に意図して押すことはない点で、3つの切り替わりと同じである。違うのは、来訪者が通る回数と、速く答える人の押しの間隔である。1回解くあいだに 10 回前後通り、cycle-301 は、ここに 600ms 未満を捨てる窓を掛けて、速く答える人の答えを日常的に捨てた（cycle-316/options.md「B-620 を含めない理由」）。窓の長さで絞ると、その害の型にまた近づく。そこで、連続の押しのうち、答えた押しから 700ms 未満・100px 以下のものだけを受けない。タッチの連続を守りが自分で数えるのは、iOS の Safari がタップの `detail` を数えず 1 のまま届けるとする資料があり（Leaflet の `DomEvent.DoubleTap.js`、Apple の開発者フォーラムの iOS 13 の報告。どれも古く、いまの版では確かめていない）、診断のプレイ面の閲覧の 58.9% が iOS（Android は 30.4%。cycle-318/device-triage.md）なので、`detail` に頼ると来訪者の約6割で働かない見込みが高いからである。iPad の Safari の Apple Pencil の押し（`pointerType` は `pen`）も同じタップの合成で click になるので、同じ見込みが当たる（推論）とみて、ペンもタッチと同じに数える。マウスを `detail` に任せるのは、マウスの連続の時間が来訪者が OS で選んだ設定に従い、それを守りが上書きしないためである。t5a-design.md 8章は、まず (i) の端末に頼らない作りで扱うと決めている。離しから押し下げまでの 300ms 未満は、捨てうる押しを、答えた押しの離しから 300ms 未満に押し下げた押し（見せる 150ms のあいだに触れて次の問が出てから離す押しと、次の問が出てから約 150ms のうちに押し下げた押し）と、そこから連鎖して、直前に受けなかった押しの離しから 300ms 未満の押しに絞る（どれも起点から 700ms 未満・100px 以下の中）。4-9 は L2（`detail >= 2` を捨てる）を「黙って捨てる点は同じ」と「iOS の Safari が2打目に 2 を付けるかも未確かめ」で退けた。1つ目への答え: 黙って捨てるのが害になるのは、来訪者が意図した押しを捨てるときである。連続と数える時間は来訪者の OS の設定で決まり（Windows は既定 500ms で 5000ms まで延ばせる。macOS もシステムの設定）、ダブルクリックを遅くした人がマウスを動かさずに同じ行の答えを続けて押すと、読んでからの答えも連続と数えられうる。次の問が出てから 550ms（700ms の上限から見せる 150ms を引いた長さ）のうちに読んで押す来訪者がいるかは、測っていない。窓はそういう押しを 700ms・100px の中ですべて捨てるが、連続の押しの守りは、そのうち OS が同じ連続と数えた押し（同じ点への、連続の時間の中の押し）だけを捨てるので、捨てうる押しが窓よりずっと狭い。残りの害は「受ける害」に書き、`quiz_press_guarded_retry` の `transition: answer` の経過 ms と B-613 で確かめる。なお、上で引いた cycle-301 の害（速く答える人の答えを日常的に捨てた）は、cycle-301 の記録ではコードから導いたもので実測は無く、別の所には 600ms 未満で答え続ける来訪者が 0 件だったとある（cycle-301/observation-impact.md・design.md）。どちらの前提でも、窓を掛けずに連続の押しに絞る判断は変わらない。2つ目への答え: タッチは守りが自分で数えるので、iOS の Safari の `detail` の数え方に頼らない。塞げない分（連続と数えられない2打目、700ms 以上の2打目）は残り、B-620 の材料として条件7・D5 で間隔ごとに数える。
- **キーボードを開かず通す**: cycle-301 は、キーボードで答えたあとの指の押しと、キーボードだけの速い答えを窓で捨てた（knowledge §5 の軸2・軸3）。二度押しはポインタだけで起きる。読み上げの起動が `detail === 0` の合成 click として届くことは推論である（knowledge §3）。外れて `detail >= 1` で届くと、読み上げで「はじめる」を起動したあとの 700ms・100px の中の次の起動を受けない。読み上げの来訪者は見出しを聞いてから身ぶりで選択肢へ移るので、700ms に収まる見込みは小さく、倒れる向きは押し直し1回である。見張らずに受け入れる（t5a-design.md 8章の (iii)）。
- **受ける害**: 窓の中で 100px の中を意図して押したとき（もう一度解く来訪者が1問目の位置を覚えていて素早く押すなど）、その押しは何も起こさない。押し下げの hover と active の線は出るので、来訪者には「押した形が一瞬出て何も起きない」に見え、押し直す手がかりになる。診断の答え→次の問の連続の押しの守りでも、ダブルクリックを遅くした人が 700ms 未満に同じ行を意図して押したときに同じことが起きる。害は押し直し1回で、答えも計測も壊れない。この害を受け入れ、`quiz_press_guarded_retry`（`transition` ごと。診断の答えは `answer`）で見張る。見張る数と戻す判断をする線は、T10 が ADR009 に書く（t5a-design.md 8章の (iii)）。
- **見た目を変えない**: 押せない形（無効）を見せる形（landing-options.md の D）は、DESIGN.md §6（無効は来訪者が揃えられる条件を待つ形）と §11（UI の動きは3つに限り、次の操作を待たせない）と食い違う。この決定は形も動きも足さない。
- **A″ を採る**: A″ は、ほかの操作の送りを測った範囲で1回も変えず（landing-options.md 2-1）、守りのあとの押しで、選択肢から 1〜14px に着いていた「はじめる」の 42 件を 16px 以上に離す。来訪者の側の害が見つからず、守りのあとの押しの寄りを減らす。
- **結果の画面の組みを直す B を採らない**: 知識クイズの結果のボックスの下を 105px 下げる形（landing-options.md 2-2）は、型 (3) の起きる高さを消す。窓の守りが 700ms 未満の2打目を受け持つので、B の得は、700ms 以上の2打目が結果の画面のリンクに寄せられてページを離れる件を減らすことに限られ、その件は少ない（遅い二度押しが、375×800 の画面の下の 27〜101px に1打目の点があるときだけ）。害は、知識クイズを解いたすべての来訪者の結果の画面で、共有・「もう一度挑戦する」・おすすめが 105px 下がり、そこまで送る量が増えることである。得が害より小さいので採らない。
- **守りのあとの押しを合否に入れない**: 窓のあとの押しと、連続と数えられない押しの大半は、新しい画面が見えてからの別の押しで、選択肢に落ちるのは来訪者が見ている画面のその所を押したことである。残る塞げない二度押しの2打目（決めたこと 3）は、送りと組みでは害なく 0 にできず（上の1つ目）、時間の上限を延ばすと読んでからの押しを捨てる。t5a-design.md 8章の「件を受け入れる」を「答えを入れるものには選ばない」としたのは二度押しの2打目についての決まりで、この決定で、守れる範囲の二度押しの2打目は守りが受け持つ。塞げない分は件の数を記録し、B-620 で判断する。

## 測りの合否（条件7・D5）

結果は、押しのあとの状態で数える（上の「測りの道具」）。

- **働いたかの判定**: 2打目（と対の押し）が働いたとするのは、次のどれかが起きたときである。答えが入る・URL が変わる・新しいタブが開く・ダウンロードが始まる・`details` の開閉が変わる・段階が変わる（開始の画面に戻るなど）・押した要素にフォーカスが移る。どれも起きなければ働かなかったとする（結果の画面の「画像を保存」「友達に診断を送る」のように、答えも URL も変えないボタンは、ダウンロードかフォーカスの移りで読む）。
- **試した回**: 試した回に数えるのは、2打目が切り替わったあとの画面（帯の番号・段階で読む）の押せるものに届いた回である。押し下げの時に切り替わったあとの画面が出ていた回は、2打目の `pointerdown` の的が押せるものの上にあった回とする。押し下げが切り替わりの前で、`click` が切り替わったあとの画面に届いた回（タッチの `click` の的は離した時の組みで決まるので、速い二度押しと、見せる間に触れて切り替わったあとに離す押しで起きる）は、押し方によらず、`click` の的が押せるものの上にあった回とし、落ちた先もその的で決める。押し下げも `click` も切り替わる前の画面のもの（古い「はじめる」や「次へ」）だった押しは、守りが無くても働かないので数えない。
- **間隔は測った差で数える**: 窓の守りとマウスの連続の押しの守りの合否は、1打目と2打目の `pointerdown` の `event.timeStamp` の測った差で回を分ける。650ms 未満の回を「受けない」の回にし、650〜750ms の回は境目として合否に入れず記録する。空振りでないことの対は、測った差が 750ms 以上の回だけを数える。
- **下限**: 下限は、どの合否の行でも、守りを掛けた切り替わりごと・入力（タッチ・マウス）ごとに、試した回が合わせて1回以上とする（組ごとではない）。窓の守りとマウスの連続の押しの守りの「受けない」の行は、測った差が 650ms 未満の試した回で数える（タッチの連続の押しの守りの受けない側は、離しからの測った間隔が 280ms 未満の試した回で数える）。窓の守りの回の狙った2打目で的（80px の中の押せるもの）が無かった組は、回の数と、1打目の点からいちばん近い押せるものまでの直線の距離を記録する。D5 の 80px・120px は、ずれた2打目の `pointerdown` の的が押せるものの上にあった回（試した回）で数える。タッチの連続の押しの守りは、受けない側も受ける側も、診断12本のそれぞれに1回以上とする。守る的が無い組（2打目を送る時の新しい画面で、1打目の点から直線の距離で 80px 以下に押せるものが1つも無い組。二度押しの2打目がどの押せるものにも届かず、来訪者の害が起きない）は、組の数と、1打目の点からいちばん近い押せるものまでの距離を記録し、その組だけでしか下限を満たせない行は、守る的が無いことを記録して下限に届かなくても合格を妨げない。見せる間に押し下げて切り替わりのあとに離す押し（hold）の行は、見せる間がある切り替わり（診断の答え→次の問と、診断の最後の答え→結果）だけで数える（「はじめる」と知識クイズの「次へ」は click の処理の中で切り替わるので、押し下げが切り替わりの前に来る押しは、1打目の互換の事象より先に2打目を押し下げる速い二度押しだけで、それは窓の守りの行の 0ms の同じ点の押しと単体の試験で受け持つ）。hold も、窓の守りの狙った2打目と同じく、新しい画面の 80px 以下の押せるものを的にして押す回を走らせる（同じ点の hold は、A″ が点を押せるものから離すので試した回にならないことが多いため）。どの行でも、守る的が無い組のほかで下限に届かなければ合格とせず、PM に報告する。PM は、測る組を足すかを決める。

- **窓の守りの回**: 「はじめる」と結果への切り替わりは、条件7 の走査（全15本 × 6章の画面 × 最初の行と最後の行で解き切る）の中で、タッチとマウス（`clickCount: 2`）で 0・90・150・300・500ms の間隔で2打目を押す。知識クイズの「次へ」は、同じ走査で3本の9問すべてを同じ間隔で押す。同じ点の2打目に加えて、狙った2打目を、新しい画面が出ている 150・300・500ms の間隔で押す。狙った2打目は、2打目を送る時の組みで、1打目の点から矩形までの直線の距離が 80px 以下の押せるもの（100px の境目から、タッチの調整で寄る 16px より離すため）のうちいちばん近いものを的にし、的の矩形の中で1打目の点にいちばん近い点（縁に当たるときは縁から 1px 内側）を押す。着地の A″ は点を押せるものから離すので、同じ点の2打目は押せるものの上に落ちず、守りを試さないことが多いからである。合否に数えるのは、2打目の `pointerdown` の的が押せるもの（`closest` した押せるもの）の上にあった回だけで、その回の2打目が働かなかったこと（上の「働いたかの判定」。フォーカスも 4-7 の置き場から動かない）。外れた件が 0 で合格。試した回の下限は上の「下限」のとおりで、試した回と試さなかった回の数を記録する。
- **連続の押しの守りの回**: 診断の答え→次の問を、同じ走査で 0・90・150・300・500ms で押す。タッチには、診断の答えの走査に 220ms の間隔を足す（離しからの間隔が、次の問が出る 150ms と合否の帯の 280ms の両方から離れている値）。
  - **マウス**: `mousedown` の `detail >= 2` で届いた2打目のうち、1打目からの測った差が 650ms 未満のもの（上の「間隔は測った差で数える」）で、2打目の `pointerdown` の的が次の問の選択肢の上にあった回（試した回）が働かなかったこと（上の「働いたかの判定」。外れた件 0 で合格）。試した回と試さなかった回の数を記録する。`detail` 1 で届いた2打目が次の問に落ちた件は、間隔ごとに数を記録する（B-620 の材料。合否に入れない）。0・90ms の2打目は、診断の 150ms の見せる間に答えた問の上に落ち、守りが無くても答えを入れないので、マウスで守りを試しているのは 300・500ms の回と、150ms のうち2打目の `pointerdown` の的が次の問の選択肢の上にあった回である。
  - **タッチ（受けない側）**: 離しからの測った間隔が 280ms 未満で、2打目の `pointerdown` の的が次の問の選択肢の上にあった回（試した回。上の「測りの道具」の押し下げの記録で読む）で、2打目が働かなかったこと（上の「働いたかの判定」。外れた件 0 で合格）。220ms の回が主にこれにあたる。下限は上の「下限」のとおり（診断12本のそれぞれに1回以上）。的が次の問の選択肢の上でなかった回（0・90ms と、150ms の一部、見出しの字や区画の空きに落ちた回）は、守りを試していない回として数を記録する。
  - **タッチ（受ける側）**: 離しからの測った間隔が 320ms 以上 700ms 未満（500ms の回）で、100px の中の2打目の `pointerdown` の的が次の問の選択肢の上にあった回（試した回）で、2打目が次の問に答えを入れること（外れた件 0 で合格。窓だけを掛ける誤った作りをここで見分ける）。下限は上の「下限」のとおり（診断12本のそれぞれに1回以上）。的が選択肢の上でなかった回は、試していない回として数を記録する。
  - **タッチの境目**: 離しからの測った間隔が 280〜320ms の回（300ms の回）は合否に入れず、間隔と結果を記録する。
- **D5 の2打目をずらす走査**: 守りを掛けた3つの切り替わりは、窓の中（300ms）と窓のあと（900ms）で走らせる。D5 の走査はタッチで行い、この節の決まりが plan-t5a7.md 4 の D5 の行と device-triage.md D5 に優先する。窓の中は、device-triage.md D5 のいまのずれ（(0, ±10)・(0, ±20)・(±10, 0)）に、境目から 16px 以上離した中のずれ（直線の距離 80px。(0, ±80)・(−80, 0)）と外のずれ（同 120px。(0, ±120)・(−120, 0)）を足し、80px 以下のずれで受けないこと・120px のずれで受けることを合否に入れる（80px 以下の行の下限は、基本のずれとは別に、80px のずれの試した回だけでも満たす。80px のずれは、境目から 16px 以上離した所で守りが受けないことを確かめるために足した押しなので）（外れた件 0。タッチの調整で点が最大 16px 寄るため、境目の 100px の近くは測らない）。窓のあと（900ms）は、device-triage.md D5 のいまのずれだけで走らせ、A″ の着地で選択肢・第1の組から 16px 未満に落ちた件の数と隔たりを記録する（合否に入れない）。診断の答え→次の問（連続の押しの守り）と知識クイズの答え→答えたあと（守りを掛けない）の D5 も、いまのずれだけで走らせる。診断の答え→次の問は、いまのとおり 90・300ms で走らせ、2打目の位置と次の問に落ちた数を記録する。守りを掛けない知識クイズの答え→答えたあとも、いまのとおり 90・300ms で走らせ、第1の組（「次へ」を含む）に落ちた件 0 を合否にする。
- **空振りでないことの対**: 窓の守りの回で試した回ごとに、その回の2打目と同じ点を、起点から 900ms のあとに1回押すと答えが入る・リンクが開く・ボタンが働くこと。対に数えるのは、900ms のあとの押しの `pointerdown` の的が押せるものの上にあった回だけで、無かった回の数を記録する。D5 の 80px 以下の「受けない」と 120px の「受ける」も、2打目の `pointerdown` の的が押せるものの上にあった回だけで数え、試さなかった回の数を記録する。D5 の 80px・120px と空振りでないことの対の試した回の下限は、上の「下限」のとおりである。キーボードで切り替えたあとの 150ms の Enter が働くことと、キーボードで切り替えたあとの 150ms に1打目の点（切り替える前にポインタで押していた点）の近くを押すポインタの押しが働くこと（キーボードで切り替えたあとは窓を開かないので、開いていれば外れ。試した回に数えるのは、切り替える前のポインタの押しから 650ms 未満で、`pointerdown` の的が押せるものの上にあった押しで、650ms は窓の守りの境目の帯の下の端である）。どれも 0 件の外れで合格。
- **D9（B-623）**: 知識クイズの「次へ」のあとの D9 の合否（2打目が答え・移動・開閉を起こした件 0）は、1打目の点から直線の距離で 100px 以下の2打目に限って数える。100px の外の2打目は守りが受ける正しい押しで、FAQ の `summary` などに落ちても外れではない。
- **守りを掛けない切り替わりの線**: 知識クイズの答え→答えたあとの第1の組（「次へ」を含む）0、「もう一度挑戦する」→開始の画面の第1の組（「はじめる」を除く）0 は、6章 条件7 のまま残す。

## 確かめること

- 着地の直しの害の確かめ（「実施する作業」）では、直す前と後の版で、診断の答え→次の問の読んでから答える押し（1秒以上の間隔）が前と同じに答えを入れること、守りを掛けた3つの切り替わりで窓のあとの押しが前と同じに働くこと、A″ がほかの操作の送りを変えないこと、受けなかった押しで hover と active の線が出ても形が残らないことを確かめる。
- iOS の Safari が二度押しの2打目を 700ms より後に届けるか、タッチの `pointerup` と `pointerdown` の時刻をどう付けるかは、このコンテナで確かめられない（t5a-design.md 8章の (iii)）。出荷のあと、`quiz_press_guarded` の率をブラウザ別に比べて守りが iOS でも働いているかを見る。すり抜けた2打目そのものは数えられないので、見張らずに受け入れる（「覆す決めごと」）。
