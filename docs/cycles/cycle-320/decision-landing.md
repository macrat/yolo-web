# cycle-320 着地の作りの決め直し

試しの走り（t5a-measure.md 10-1）で見つかった3つの型（「はじめる」の2打目が1問目の選択肢に寄る (1)・真上から落ちる (2)、知識クイズの最後の「次へ」の2打目が結果の画面のリンクに寄せられる (3)）を、どう直すかの決定。材料は [landing-options.md](./landing-options.md)。

## 決めたこと

**「はじめる」→1問目、知識クイズの「次へ」→次の問、最後の答え・最後の「次へ」→結果の3つの切り替わりのあと、新しく出た押せるもの（その問の選択肢・結果の画面のリンクとボタン）への押しを、切り替えた押しから 500ms のあいだ受けない。** 見た目は何も変えない。診断の答え→次の問と、知識クイズの答え→答えたあとには掛けない。着地の選び方（t5a-design.md 4-9）はいまのまま残す。

## 理由

- **送りと組みでは 0 にならない**: landing-options.md の実測では、着地に余白を取る形（A・A′・A″）、「はじめる」を下げる・上げる形（B・B′）、見せる範囲を広げる形（C）を、どう組み合わせても全画面で 0 にならない。狭く短い画面（375×550・320×550・200%）では、問のまとまりが画面をほぼ埋め、1打目の点の下にどう送っても選択肢が来る。閲覧の 85.8% を占める character-personality の 375×550 は、ボタンのどこを押しても直る形が無い（4-1）。下げる B は 320×550 で「はじめる」を最初の画面から出し、来訪者が始められなくなる。
- **窓の中の押しは、意図した押しでありえない**: 守る押しは、新しく出た問か結果への押しである。問の見出しと選択肢を読む前に答えを選ぶことも、結果を読む前にほかのページへ移ることも、来訪者が意図してすることではない。500ms は、二度押しの2打目（Android の二度押しの間隔の上限は 300ms。`android.view.ViewConfiguration` の `DOUBLE_TAP_TIMEOUT`。道具の2打目は 293〜306ms）を覆い、読んでから押すには足りない長さとして置く。
- **cycle-301 の失敗と違う所**: cycle-301 は、画面の切り替えから 600ms 未満の回答を、すべての問のあいだで捨てた（cycle-316/options.md「B-620 を含めない理由」）。診断の答え→次の問では、速く答える人が意図して押した答えが日常的に捨てられた。この決定は、その切り替わりに掛けない。掛ける3つの切り替わりは、どれも新しく出たものを読んでからでないと意図して押せない所である。再タップの動機（押しても手応えが無い）も作らない。捨てるのは、来訪者がまだ見ていないものへの押しだけだからである。
- **見た目を変えない**: 押せない形（無効）を見せる形（landing-options.md の D）は、DESIGN.md §6（無効は来訪者が揃えられる条件を待つ形）と §11（UI の動きは3つに限り、次の操作を待たせない）と食い違う。この決定は形も動きも足さない。
- **着地の選び方を残す**: 500ms のあとの押し（遅い二度押しや、送られた先での押し直し）では、いまの着地の選び方が押した点の真下を避ける。余白を足す A″ は「はじめる」の 42 件を直すが、守りがあれば窓の中の件は守りが受け持つので、着地の関数を書き換えて測り直す手間に見合わない。

## 覆す決めごと

- cycle-316/options.md「B-620 を含めない理由」の「時間の窓で回答を黙って捨てる仕組みは入れない」を、上の3つの切り替わりに限って覆す。診断の答え→次の問には、これまでどおり入れない。
- t5a-design.md 4-9 の表の L1（切り替わってから一定の時間、押しても捨てる）を「捨てる」とした判断を、上の範囲に限って覆す。L2（click の `detail ≥ 2`）は、iOS の Safari の数え方を確かめられないので採らない。

## 直すもの

- t5a-design.md 4-9（手当ての表と、守りの中身）と、それに合わせた 5章・6章 条件7 の合否の文、DESIGN.md・`frontend-design` スキル・`docs/knowledge/input-events-and-guards.md` の該当の文（plan-t5a7.md 6 の「設計の文を先に直す」の一覧）。
- コード: `QuizContainer` が、3つの切り替わりの押しの時刻を覚え、新しく出た押せるものへの 500ms 以内の click を止める。試験に、窓の中の押しが答えを入れないこと・窓のあとの押しが答えを入れること・診断の答え→次の問の速い押しが答えを入れることを入れる。
- 測りの道具: 条件7・D5 の合否を、守りの形で数える（窓の中の2打目が何も起こさないこと、窓のあとの押しの着地はいまの数え方）。

## 確かめること

- 着地の直しの害の確かめ（「実施する作業」）では、守りを入れる前と後の版で、診断の答え→次の問の速い押しが前と同じに答えを入れること、守りを掛ける3つの切り替わりで 500ms のあとの押しが前と同じに働くことを確かめる。
- iOS の Safari が二度押しの2打目を 500ms より後に届けるかは、このコンテナで確かめられない（t5a-design.md 8章の (iii)）。出荷のあと、問ごとの答えの計装（B-613）で1問目の答えの時間の分布を見張る。
