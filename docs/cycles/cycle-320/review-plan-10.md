## 指摘

### 1. 作り直した版の確かめ「前の日の同じ走査と落ち先が合う」は、同じ版でも合わない（中）

plan-t5a7.md 3 の「作り直した版で数本を走らせて、前の日の同じ走査と落ち先が合うことを確かめてから続ける」は、走査が回で揺れないことを前提にしている。ところが条件7 の走査はそうではない。

- t5a-measure.md 0章（14行）: 「条件6・7 と差し込み（7章）は固定しない（選択肢と結果は回ごとに変わる）」。`Math.random` を固定しないので、選択肢の並びと結果が回ごとに変わる。
- 5-4: 同じ版で実際に二度押しした 252回と走査の点ごとの一致は 216/252 で、その差は「結果が回ごとに違いページの長さが変わるため」と書かれている。5-3 も、最後の答えのあとの結果の画面の長さが回で変わる。
- 変更後の版は、着地の関数がその回のページの組みで送りを選ぶので、揺れはさらに広がりうる。

このため、同じコミットから正しく作り直した版でも「落ち先が合わない」ことが普通に起き、担当は日ごとに PM に報告することになる。そのとき PM が「測り直すか」を決める物差しが無く、全部を測り直す側に倒れれば日割りの上の線を押し上げ、測り直さない側に倒れれば版の取り違えを見逃す。担当に渡したときに迷わず進められない。

直し方の例: 確かめを、回で揺れないもので行う形に書き換える。たとえば (a) 版の同一性を機械的に比べる: T5a-7a-1 で版を作ったときに、ビルドの出力のうち中身から名前が決まるもの（`.next/static` の下のファイル名と大きさの一覧など。どれを使うかは道具の側で決めて `measure/README.md` に書く）を `measure/` に記録し、作り直した版で同じ一覧になることを確かめる。(b) 走らせて確かめるなら、`Math.random` を固定した走り（0章の並びの固定の形）に限り、「落ちた先の種類（第1の組・選択肢・字）が同じ」を合う物差しにする。どちらかを選んで、合わないときに PM が見るものを書く。

### 2. T5a-8 の担当の枝を `.claude/worktrees/` に残しても、セッションを越えては残らない（中）

「T5a-8 の担当の枝は、取り込むまで主の木の `.claude/worktrees/` に残す」は、日をまたいでも枝が残る前提で、続きの日に「担当の枝のコミット」から版を作り直す手順につながっている。しかし、`tmp/` がセッションを越えて残らないのと同じ理由で、主の木のローカルの枝と担当の木も残らない。

- index.md の補足事項: セッションの初めの主の木は浅いクローンで、`git fetch --unshallow` が要った。セッションごとに新しいクローンから始まる環境である。
- cycle-319/index.md のキャリーオーバー: 担当の木の `tmp/` は木とともに消え、主の木の `tmp/` とスクラッチパッドはセッションを越えて残らなかった。
- `.claude/rules/delegation.md`・`worktrees.md`: 担当の枝は origin に push しない。

したがって、T5a-8 の測り直しが日（セッション）をまたげば、担当の枝のコミット、つまり直したコードそのものが消え、記録したコミットから版を作り直せない。直しのやり直しと測り直しの全部が要り、来訪者に届く直しが遅れる。

直し方の例（どれかを選んで書く）: (a) T5a-8 のコードの直しは、測り直しの前に PM が `design-rollout` に取り込んで push し（`design-rollout` は B-754 の出荷まで main に入らない統合のブランチなので、来訪者には届かない）、測り直しはその取り込んだコミットで行う。外れが残れば 5 に戻り、次の直しを上に重ねる。(b) 取り込む前の枝を測る形を残すなら、T5a-8 の測り直しの1回分（担当の枝を作ってから測り終えるまで）を1セッションに収まる量に分け、収まらない見積もりなら (a) にする、と書く。

### 3. 途中の push の時が、plan-t5a7.md と index.md で違って読める（軽）

plan-t5a7.md 3 は「担当ごとの終わりと、日の終わりの早いほうで」と書き、index.md 作業内容 7 は「担当ごとの終わりと日の終わりに」と書く。「早いほう」は2つのうち片方でだけ push する読みになり、担当の終わりのあと同じ日に次の担当が測った分を、日の終わりに push しない読みが残る。「担当が終わるたびと、日の終わりに」のように、どちらが来ても push する形にそろえる。

### 4. 5-3 の「1280×800 のほかの画面」に、表に行の無い 375×550 の 200% が入る（軽）

t5a-measure.md 5-3 の表には 375×550 の 200% の行が無い（150回のうち12回で止まり、「表にこの画面の行は無い」）。「1280×800 のほかの画面で」と書くと、この画面でも第1の組に落ちた回があったと読める。「表のある画面のうち 1280×800 のほかで」のように限る。結びには影響しない。

### 5. 作り直しの手順に、深い履歴の取り直しが無い（軽）

続きの日に基準の版を fff3d31f と da102212 から作り直すには、それらのコミットが主の木に要る。index.md の補足事項のとおり、セッションの初めのクローンは浅く、`origin/main` との共通の祖先も持たなかった。plan-t5a7.md 3 の「記録したコミットから版を作り直し」の前に、「`git fetch --unshallow origin main design-rollout` をしてから」と1句足すと、担当が迷わない（plan-t5a7.md 2 の `cycle-316-records` の fetch は別の枝で、これを代わりにしない）。
