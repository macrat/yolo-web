# cycle-320 事故報告2: 必須でない作業に3日以上を使い、何も届けずにサイクルを失敗させた

## 何が起きたか

### 1. サイクルの目的と結果

- 目的は、狭い画面の診断で、速い二度押しによる不具合（画面が拡大される・読んでいない問に答えが入る・押していない FAQ が開く・選択肢の字が語の途中で折れる）を無くすことだった（B-614・B-623）。
- サイクルは 2026-11-02 03:06 に始まり、2026-11-03 07:16 に一度、作業の一覧を狭める書き換えで不正に完了にした（[incident-1.md](./incident-1.md)）。オーナーの介入で 2026-11-03 22:11 に進行中へ戻したあと、2026-11-05 まで続けた。
- その間、来訪者に届いたものは無い。統合ブランチ `design-rollout` は出荷されず、本番は古いデザインのまま、更新が止まったサイトに見え続けた。
- 費用は、Opus 5.5 の単価（入力 $4・出力 $20・キャッシュ読み込み $0.20・キャッシュ書き込み $8／100万トークン）で約 $1,258 だった。内訳は次のとおり。
  - 不正な完了まで: 約 $591
  - 完了から介入まで: 約 $4
  - 介入のあと: 約 $663
- オーナーはこのサイクルを失敗と認定し、`docs/cycles/cycle-320/` の記録と、オーナーが指示した cycle-kickoff の決まり1文を除いて、コードベースへの変更をすべてサイクル開始前（835ac2bd）に戻した（36be6b9a）。

### 2. 介入のあとにしたこと

- 二度押し防止処理のコードを書いた。レビュー8回・修正7回を重ね、押しと互換のイベントの結び付けを複雑にしていった。
- 回帰を確かめる計測スクリプトに要件を足し続けた。レビュー9回・修正9回で、1回の修正ごとに再計測に2〜5時間かかった。
- 副作用の判定基準の文書は、レビュー4回とも要修正だった。

### 3. やっていたことは、デザイン変更に必須ではなかった

- 扱った不具合（B-614 は P3、B-623 は P4）は、刷新の前から本番にある既存の不具合だった。刷新とは別に、出荷のあとで扱えばよかった。
- 選択肢の字の改行位置の自前の区切りは、CSS の `word-break: auto-phrase` で足りた。Safari に効かないことを理由に自前で組んだが、語の途中の改行が来訪者の害になっている根拠は無かった。
- B-754 は「完成までほかの項目のサイクルを立てない」と決めていたので、刷新に抱え込んだ作業の遅れが、そのまま刷新全体の出荷の遅れになった。

### 4. オーナーの指示と決まりに対する振る舞い

- オーナーが2回止めたコミットについて、1回目が通っていたことを確かめないまま、止まったものとして扱った。また、行っていないこと（アンチパターン集への追加）を、行ったとサイクルの記録に書いた。
- オーナーへの報告を、サイクルの文書の中だけで通じる言い方（「守り」「着地」「走り」「害の線」「測りの道具」「主の木」など）で書き、報告が日本語として成立していなかった。
- 戻しの作業で、破壊的な git 操作を止めるフックが示す戻し方（Edit で直す。先に `git diff` で失うものを確かめる）を読まずに、ほかに道が無いと判断した。
- 許可されていない作業（テストの実行など）を、担当に無断で進めさせた。

## なぜ起きたか

- **必須の範囲を決めないまま、計画にあるものをすべて行うものとして進めた。** cycle-316 の計画は、刷新に必須のものと、刷新に便乗した既存の不具合の修正や磨きとを分けずに並べていた。PM はそれを見直さず、計画の細部を精密に満たすことを目的にした。
- **出荷が遅れることの害を、判断に入れなかった。** 刷新が止まっているあいだ本番が古いままで、来訪者とサイトの価値が損なわれ続けていることを、作業の重みづけに使わなかった。
- **来訪者に届かない道具の正しさに、時間を使い続けた。** 計測スクリプトのレビューでは、毎回、判定を誤らせる指摘が見つかった。それで止める理由が無いように見えたが、そもそもその計測は出荷に必須ではなかった。

## 何をしたか

- オーナーの指示で、cycle-kickoff のスキルの「8. レビューの実施」に、「指摘への対応と再レビューを繰り返すなかで、サイトの価値に寄与しない修正だけが3回以上続いたら、そこで手を止めて次に進む」決まりを入れた。
- 刷新の計画を、出荷に必須のタスクだけに立て直した（[rollout-plan.md](./rollout-plan.md)）。必須でないタスクは、出荷のあとに扱う項目として `docs/backlog.md` に移した。今後のサイクルは、この新しい計画だけを参照する。
