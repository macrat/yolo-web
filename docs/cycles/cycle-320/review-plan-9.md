## 指摘

### 1. 数日に分けて測り切るのに、日をまたいで記録と版を残す手立てが無い（中）

道が「続きから測れる道具で数日に分けて測り切る」1つになり、日割りが計画の要になった。ところが、日やセッションをまたいだときに何が残るかが書かれていない。

- index.md 自身が「主の木の `tmp/` はセッションを越えて残らない」と書き、cycle-316 の測りの道具はそれで消えた（plan-t5a7.md 2 の組み直しはその後始末である）。基準の版と変更後の版のビルドは `tmp/` に置くので、日をまたげば消えうる。
- `measure/` の記録は主の木に書かれるが、コミットと push の時が書かれていない。index.md 作業内容 7 は「完了の処理で `design-rollout` に push する」としか書かず、途中で push しない読みになる。セッションが切れれば、未 push のコミットと未コミットの `.jsonl` ごと、何日分かの走査が消える。「続きから測れる形」は記録が残っていることが前提なので、これでは働かない。
- 続きを別の日に別のビルドで測るなら、そのビルドが前の日と同じ版か（同じコミットから作ったか）を確かめ、走査ごとの記録にどのビルドで測ったかを残さないと、点ごとの比べ（基準の版と変更後の版、変更後の版と T5a-8 の測り直し）の前提が崩れる。

PM が主の木の作業ブランチを途中で push することは `.claude/rules/delegation.md` の決まりの内なので、手立ては書ける。直し方の例: plan-t5a7.md 3 の日割りの項に、「担当ごとの終わり（少なくとも日の終わり）に、PM が `measure/` と t5a-measure.md をコミットして `design-rollout` に push する。日をまたいで続けるときは、`measure/README.md` の版の作り方で、記録した同じコミットから版を作り直し、走査ごとの記録にビルドのもとのコミットを残す」と書き、index.md 作業内容 7 の push の文を、途中の push を含む形に直す。T5a-8 の測り直しにも同じものを掛ける。

### 2. 1回で終わる操作の送り直しで捨てた回に、第1の組の落ち先があったときの扱いが残っている（軽）

前回の指摘2の後半（「1回で終わる操作の『数えずに送り直す』回も同じで、捨てた回に第1の組の落ち先があったときの扱いが無い」）への手当てが無い。今回の文の「その2打目が第1の組に落ちたものは、間隔によらず件として 5 の判断に渡す」の「その」は、走査の中で印を付けた押しを指す。「はじめる」・最後の答えと最後の「次へ」・「もう一度挑戦する」で、90ms の指定が 160ms になって捨てた回の2打目がリンクや `summary` に落ちていても、記録にも件にも残らない。150・300・500ms の回が近い時を覆うので見落としの見込みは小さいが、走査の中の押しと扱いがそろわず、担当が捨てた回の記録を消してよいかで迷う。直し方の例: 「送り直す前の回も、落ち先と実際の間隔を記録に残し、第1の組に落ちたものは件として 5 の判断に渡す」と1文足す。

### 3. 5-3 は 1280×800 で第1の組に落ちた回が 0 で、「どの画面でも」と合わない（軽）

plan-t5a7.md 3 の「最後の答えと最後の『次へ』（5-3）と『もう一度挑戦する』（5-4）はどの画面でも第1の組に落ちる回や点があった」のうち、5-3 の表は 1280×800 が 0/150 である（5-4 はどの画面にもある）。結びには影響しないが、5章の数を引く文なので、「5-3 は 1280×800 のほかの画面で」と限る。

### 4. 日割りの上限と、超えたときに計画へ戻す線が無い（軽）

「合計が1日で回せる量を超えるときは…日割りを書く」は下の線だけで、上の線が無い。5-4 の掃きは、基準の版でも実際の二度押しで測るので、15本 × 6画面で 2,115 の位置 × 2 間隔 × 入力 × 2 版の押しになり、どれも解き切ってから押すので、見積もりしだいで日数が大きくなりうる。3 の決定はレビューに通すので止まりはしないが、PM と reviewer が何を見て「このまま進める」と言えばよいかの物差しが無い。「日割りが N 日を超えるときは、測りの手順（解き切る道のりの短縮など、刻みと画面を変えないもの）を見直す案とともに計画に戻してレビューを受ける」のように、戻す線を1つ書いておくとよい。数 N は見積もりのあとで決めてかまわない。
