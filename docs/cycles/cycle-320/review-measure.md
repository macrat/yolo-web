## 指摘

### 指摘1（判定を変える・道具と要件の文）: 切り替わりの前に押し下げて、`click` が新しい画面に届いた2打目が、窓の守りの合否に入らない

after の `start` の `character-personality|touch|0|0:0||same` と `music-personality|touch|0|0:0||same` は、2打目の `pointerdown` が「はじめる」（段階 `intro`）に落ち、離した時の `click` が1問目の選択肢に届いて、1問目に答えが入った（`worked` が `s`、`click` が `["next", 1, "playing", 1]`）。守りを持つ版で、二度押しの2打目が読んでいない1問目に答えを入れている。ところが `report.mjs` の `window|start|touch` は `failed` 0・`pass` true で、この2回は `shown` が 0 なので試さなかった回に数えられる。押しごとの記録にも置かれない（`guardMisses` が `record.shown` を求め、`first`・`next` の理由も `pointerdown` の組で決めるので、`why` が付かない）。hold の行が拾うのは押し方が `hold` の回だけで、`same` の 0ms の同じ型は素通りする。

- 決めの「試した回」は「切り替わる前の画面の押せるもの（古い「はじめる」や「次へ」）への押しは、守りが無くても働かないので数えない」とするが、タッチではこの前提が成り立たない。タッチの `click` の的は離した時の組みで決まる（knowledge §8。decision-landing.md の「押しの単位」も同じことを書いている）ので、押し下げが古い「はじめる」の上でも、離しが切り替わりのあとなら新しい画面の押せるものが働く。「どこに落ちたかは2打目の `pointerdown` で決める」も、この型では落ちた先を取り違える。
- 同じ取り違えは、守りを掛けない切り替わりの行（`unguarded`。`pointerdown` の組で第1の組に落ちたかを決める）と、比べの線1（`isOut` が `pointerdown` の組で決める）にもある。今回の記録では、知識クイズの答えの 0ms の押しの `click` は押せない字に落ちていたので外れは出ていないが、`click` が「次へ」に届けば、どちらも見落とす。
- hold の行は、押し方が `hold` の押しを、押し下げが本当に切り替わりの前に来たかを見ずに数える。after の `start` の character-personality の hold は、2打目の `pointerdown` が切り替わりのあと（`shown` 1）に来ており、hold の型を試していないのに `tried` に入る。

**直し方の向き**: 2打目の `pointerdown` が切り替わりの前（`shown` 0）で、`click` が切り替わったあとの画面に届いた押しは、押し方によらず、`click` の的で試したかと落ちた先を決める（hold の数え方と同じ）。`window`・`unguarded`・`hold` の行、`guardMisses` の `guard-miss`、比べの `isOut` をそうそろえる。hold の行は、押し下げが切り替わりの前に来た押しと来なかった押しを分けて数え、前に来た押しが1回以上あることを下限にする。決めの「試した回」の文（「切り替わる前の画面の押せるものへの押しは、守りが無くても働かない」）と「どこに落ちたか」の文は、タッチで押し下げと離しのあいだに画面が替わる押しを含めて書き直す（planner）。

**直し方**: `d5-knowledge-answer` を、90・300ms の基本のずれ（`D5_BASIC`）の押しだけで数える。

### 指摘9（判定を変える・道具）: target-mismatch が、押し下げと `click` のあいだに画面が替わった押しを食い違いに数える

after の `target-mismatch` は知識クイズの答えの 19 件で、どれもタッチの 0ms（hold を含む）の押しだった。2打目の `pointerdown` が1打目の `click` より先に届いて答える前の選択肢に落ち、離した時の `click` が答えたあとの字（解説の字・パンくずの字など）に落ちている。t5a4 では、守りを掛けないのですべての押しが入り、答え 105・はじめる 11 などになった。どれも、押し下げと離しのあいだに画面が替わったので的が違うだけで、決めが確かめたい「同じ組みで `pointerdown`・`touchstart`・`click` の的が合うか」（`pointerdown` の的を落ちた先に使ってよいか）の食い違いではない。数が多いので、本当の食い違いがあっても埋もれる。

**直し方**: `pointerdown` の時と `click` の時の段階・帯の番号・答えの有無が同じ押しだけを突き合わせ、替わった押しは別に数える（指摘1 の「切り替わりの前に押し下げた押し」として扱う）。

### 指摘10（判定を変える・道具）: 見せる間の受ける側（hold-out）の結果への切り替わりで、2打目が押せるものに来ない

carryover.md の「着地の直しの害の確かめ」は、この組を「離す時の新しい画面で起点の点から 120px 離れた押せるものの上の2打目」とする。道具は点を縦に 120px ずらすだけで、新しい画面のその点に押せるものがあるかを見ない。今回の `last` の hold-out は4回とも離した時の `click` が押せない字に落ち、`shown|result|touch` の試した押しは 0 だった（診断の答え→次の問は、120px 下が次の問の選択肢になるので 44 押しを試せた）。全体の測りでも、結果の画面は答えの点の 120px 先に押せるものが来ない本が多い見込みで、下限に届かずに PM に戻る。

**直し方の向き**: 2打目の点を、新しい画面の組みから決める。たとえば同じ回の1打目だけの押しを先に一度送って結果の画面の押せるものの置き場を読み、起点から 116px 以上離れた押せるものの中の点を選んでから、本番の回でその点を押し下げる（並びの混ぜは指摘2 の種で固定する）。決めた点に押せるものが来なかった回は、試さなかった押しとして数を残す。

### 指摘11（判定を変える・要件の文）: キーボードの行が、キーボードの切り替えで窓が開く誤りを見分けられない

decision-landing.md の合否は「キーボードで切り替えたあとの 150ms の Enter が働くこと」で、道具はそれを測る。ただ、Enter の起動は `detail === 0` で、守りは窓が開いていても通すので、キーボードで切り替えたあとに窓が誤って開いても、この行は外れにならない。cycle-301 の害（キーボードで答えたあとの指の押しを窓が捨てた。knowledge §5 の軸2）を見分けるのは、キーボードで切り替えたあとのポインタの押しである。単体の試験（「キーボードで切り替えたあとは窓が開かないこと」）はあるが、本番のビルドでの確かめはこの行だけである。

**直し方の向き**: 合否の行に、キーボードで切り替えたあと 150ms のあとに、新しい画面の押せるもの（次の問の選択肢・結果の画面のボタン）をタッチとマウスで1度押すと働くことを足す（planner が decision-landing.md の合否を直し、道具がそれを測る）。

### 指摘12（軽い・数え方）: `consecutive-mouse` の `detail1Next` が、押し方 `d1` と `read` を間隔の欄で混ぜる

`detail1Next` は B-620 の材料（`detail` 1 で届いた2打目が次の問に落ちた件）だが、害の確かめの `d1`（`clickCount` 1 で送った2打目）と `read`（1,100ms のあとの読んでから答える押し）も同じ表に入る（今回の 1100 の欄の 22 件は `read`）。条件7 の本番の走りでは押し方を渡さないので数は変わらないが、害の確かめの置き場で集計すると読み違える。押し方の欄で分けるとよい。

### 指摘13（軽い・数え方）: `touch-block` が、`releaseGap` の無い押しを 280ms 未満に入れる

`gap < TOUCH_BLOCK_BELOW_MS` は `releaseGap` が null でも真になる。2打目が無い押しは `group` も無いので試さなかった回に入るだけで、合否は変わらないが、`untried` の数が膨らむ。null を先に除くとよい。

### 指摘14（軽い・書き違い。PM が直して閉じる）: README の指紋の表の `after` と `t5a4` の行が、主の木でその名で作った版の値でない

README は「道が違えば同じコミットでもチャンクの名前がすべて変わる」「記録を足す版は、いつも主の木で作る」とするが、`t5a4` の行の `chunksDigest`（`e9bd6b59a47b9e84`）は、主の木の `tmp/measure-builds/after`（5ea1ab89 を名 `after` で作った版）の値で、名 `t5a4` の道で作れば変わる。`after` の行の `54656a5c9a8869c0` も、主の木の `tmp/measure-builds/after` はまだ 5ea1ab89 なので、主の木の名 `after` の道で作った値ではない。表は測る時に主の木で作り直した値に書き直す。あわせて、版の表の `after`（76b81d2a）は、hold の穴（指摘の前の「担当の報告との突き合わせ」）を直してレビューを通したコミットに替わる。

### 指摘15（内部の決めごとが変わる・進め方）: 試しの走りの回ごとの記録が、担当の木の `tmp/` に置かれ、取り込みのときに木ごと消えた
