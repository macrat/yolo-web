# 着地の二度押しの案の比べ（cycle-320）

速い2度押しの2打目が、切り替わったあとの押せるものに落ちる件（t5a-measure.md 10-1 の型 (1)(2)(3)）を直す設計の材料。いまの版の実測と、案ごとの直せる件・残る件・足される動き・ほかの操作への害を並べる。決めるのは PM。

## 0. 出どころと測り方

- **版**: 枝 design-rollout の 080a1dc7。`.next` はこの HEAD で `npm run build` し直したもの（あった `.next` は `prerender-manifest.json` を欠いていた）。`next start -p 3121`。ブラウザは Playwright の Chromium 153.0.8010.12（headless）、タッチ（`hasTouch`・`touchscreen.tap`）。200% は measure.mjs と同じく、プロファイルの既定の文字サイズを 32px にした近似。
- **道具**: `tmp/landing-options/` の page-init.js（測りの関数）・run.cjs（走らせる）・report.cjs・robust.cjs（集計）。記録は同じ所の all2.jsonl（`tmp/` なのでコミットせず、残る保証は無い）。結果の画面の「起きる高さ」（1-3）と案 B の結果の側は、同じ道具に高さの走査を足した版で、知識クイズ3本だけを走らせ直した zone.jsonl・zone2.jsonl。
- **走らせた範囲**: 15本 × 5画面（375×550・320×550・375×800・1280×800・375×550 の 200%）× 押す行（どの問も最初の行・最後の行）＝150 走査、2,170 の切り替わり。選択肢の並びは `Math.random` を種 320 に固定してそろえた。知識クイズは答えのあと「次へ」を押し、結果のあと「もう一度挑戦する」を画面の高さの中ほどに置いて押した。押すものが画面の外にあるときは、下端が画面の下端から 8px 上に来るまで先に送った。
- **測るもの**: 切り替わりの 800ms あとの組みを、`scrollBy` の記録で切り替わる前の座標に戻し、着地の組（基準・範囲・送れる範囲）と押せるものの矩形を取り直した。reveal.ts の `chooseLanding` の写しで選び直した送りは、2,170 回すべてで実際の送りと一致した。隔たりは、`data-hit-area="after"` の選択肢を行の内側の箱（罫線を除く。input-events-and-guards.md §8）で取り、点から矩形までの max(dx, dy)（100 で頭打ち）で測った。**16 未満を「寄る」**、0 を「真上」とする。
- **点**: 1打目の `click` の座標（押したボタンの中心）。「ボタンのどこを押しても」の見方では、点を縦にボタンの半分（「はじめる」の高さ 44px なら ±21px）動かした全部で 16 以上かを見た（2-3）。
- **限り**: 答えの組は1つ（決まった種・最初か最後の行）で、型 (3) は最後の「次へ」の位置に左右される（1-3）。iOS の Safari の調整は測れない。Chromium の寄せる先の候補は、道具が集める押せるもの（reveal.ts の `PRESSABLE_SELECTOR`）より広い（§8）。

### 2-4. 案 D: 2打目を受けない状態を見せる

切り替わった直後の押せるもの（1問目の選択肢・結果の画面のリンクとボタン）を、押せないと分かる形で短く出し、終わったら押せる形にする。

- **長さ**: 10-1 の走りでは、道具の2打目の間隔は指定 300ms に対して実際 293〜306ms で、これを覆うだけでも 300ms を超える窓が要る。人の二度押しの間隔はこのコンテナで測れない。1回解くあいだに、「はじめる」1回・知識クイズの「次へ」9回・結果1回の切り替わりで出る。
- **直せる件**: 押せない形のあいだに落ちる2打目は、型 (1)(2)(3) と 200% を含めて全部（タッチの寄せが押せない形の要素を候補から外すか、近くの別の押せるものへ寄せるかは、このコンテナで測っていない）。
- **4-9 の退けた理由に照らして**: 4-9 の L1 は「一定の時間押しても捨てる」で、退けた理由は「押せる形のまま黙って捨てる」。D は窓の形は L1 と同じで、違うのは押せない形を見せることだけ。来訪者が窓の中で意図して押した1打は、見た目の形だけを知らせに捨てられる。
- **DESIGN.md との突き合わせ**: §6 は「無効」を「来訪者が揃えられる条件を待つ形」とし、「ページを読み込み終えるまで動かないだけのボタンは、無効の形で出さない」（破線の枠と理由の字が現れて消えると目がそこへ向く）と決めている。時間の待ちは来訪者が揃えられる条件ではない。§11 は UI の動きを3つ（結果の登場・150ms 以下の操作フィードバック・開閉）に限り、「いずれも、動きが終わるまで次の操作を待たせない長さ」とする。300ms 超の押せない形は、切り替わりのたびに形が変わる4つ目の変化で、次の操作を待たせる。場所だけ取って 300ms 後に選択肢を出す形にすると、問の部分がずれて現れる段階表示になる（§11 の「1つの操作に応える動きは1つだけ」）。

## 3. 型をすべて 0 にできる組み合わせ
