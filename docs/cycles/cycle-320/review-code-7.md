## 指摘

### 指摘1（来訪者に届くもの・小）: 番号で結べない `click` で、同じ点に残ったタップのあとに止めた押しの `elapsed_ms` が、止めた押しでなく前の押しから数えられる

`noteStopped` は、押し直しの経過の元（`pendingRetry.downTime`）を、止めた事象を `compatPairOf` で結んだ押しの押し下げから取る。番号で結べない `click`（番号を持たない形・WebKit の `"mouse"` の形）で、同じ点に互換の事象を出さないタップが残っていると、「はじめる」の `click` はそのタップに結ばれ、「はじめる」の押しは `click` を受けないまま並びに残る（守りを開く時に受けない押しになる）。すると、そのあとの窓の中の2打目の `mousedown` と `click` は、並びのいちばん古い受けない押し、つまり「はじめる」の押しに結ばれる。止めることはできているが、経過の元は2打目でなく「はじめる」の押しになる。

再現（`tmp/review320c7/mut/src/play/quiz/__probe__/probe7.test.ts`）: 押せない字へのタップ 100〜150 (100, 500)、「はじめる」1000〜1050、2打目 1250〜1300 (100, 520)、押し直し 2000。止めた2打目から 750 を期待したが、番号を持たない形と WebKit の形で `elapsed_ms` は 1000 になった（Chromium の形は 750）。ずれは「はじめる」から2打目までの長さで、守りの窓の中なので 700ms 未満になる。

来訪者への影響: 決めごと（decision-landing.md 1「数える」）は、経過を「受けなかった押しの押し下げ」から数えるとし、T10 は経過の分布に、読む時間を要らない早い山があるかで、守りが意図した押しを止めていないかを見る。このずれは経過を長いほうへ寄せるので、当たった回では早い山を隠す向きに働く。当たるのは iPhone の来訪者の、残ったタップのあとの二度押しで押し直した回だけで、件数はわずかと見込むが、iPhone の来訪者は多く、守りの害を見る物差しを誤らせる向きにずれる。担当はこの点を返しの中で残すとしたが、決めごとにも文書にも書かれておらず、コードのコメント（`noteStopped` の「経過は押し下げの時刻から数える」）とも合わない。

直し方の案: 止めた側の経過の元も、受けた側と同じ考えで、止めた事象を出した押しを選んで取る。たとえば、番号で結べた事象では結んだ押し、番号で結べない事象では、事象の点から 32px の中で、受けない押しのうちいちばん新しく押し下げた（`click` なら離した）押しにする。どの形にしても、上の再現を試験に入れ、番号で結べない2つの形で落ちて直したら通ることを確かめること。決めごとを変える形を選ぶなら、decision-landing.md 1「数える」、t5a-design.md 4-9 と 5章の写し、SKILL.md の「結び方」と、`noteStopped` のコメントを同じ中身に直すこと。直さずに残すと決めるなら、ずれの向きと大きさを decision-landing.md 1「数える」と T10 の読み方に書くこと（ただし来訪者に届くコードの数え方の誤りなので、直すほうを勧める）。
