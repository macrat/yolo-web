## 決めごとやふるまいが変わる指摘

### 指摘1: 「最後の答え→結果」の窓の守りの回の「本ごとに1回以上」が、診断12本ではつくりの上で満たせない見込みが高く、満たせないときの扱いも無い

場所: 6章 条件7 の「窓の守りの回」（「試した回は、守りを掛けた3つの切り替わりごとに、本ごとに1回以上要る。1本でも無ければ合格としない」）。decision-landing.md の「測りの合否」も同じ文。

- 狙った2打目は「1打目の点から矩形までの直線の距離が 80px 以下の押せるもの」を的にする。的が無い回は、狙った点を押せない。
- 同じ文書の 4-9 の「結果の範囲は、ボックスの上端の位置で決める」は、「診断12本は、どの画面でも上端 8px で押せるものから 100 以上離れ、ずれない」と書く（review-t5a-design-2.md の測り）。最後の答えの点から 100px の中に結果の画面の押せるものが無いなら、80px 以下の的も無い。着地も s0 から動かない。同じ点の2打目も押せるものの上に落ちない。そのため、診断12本の「最後の答え→結果」には、試した回が1回も出ない見込みが高い。
- そうなると、作りが正しくても条件7 は「合格としない」になる。外れた件の扱い（8章の4つの選び方・plan-t5a7.md 5）は、着地か組みを直す選び方である。試した回が足りないときには当たらない。そのため、測りの担当も PM も、次に何をするかを文書から決められない。
- 一方で、点から 100px の中に押せるものが無い画面は、二度押しの2打目がタッチの調整（最大 16px）を足しても押せるものに届かない。守りが受け持つ押しが、もともと無い画面である。その画面で試せないことは、守りの欠けではない。

直し方: 試した回の下限を、「80px の中に的があった組」で数える形に決め直す。たとえば、本ごとの下限は、その切り替わりのどこかの画面と行で80px の中に的があった本に限る。的が無かった本は、的が無かった回の数と、1打目の点からいちばん近い押せるものまでの直線の距離を記録する。守りの道筋そのものを試すため、下限は切り替わりごとに少なくとも1本ある、と決める。どの本にも的が無かった切り替わりがあれば、PM に報告すると書く。窓の守りの回、D5 の 80px と 120px、空振りでないことの対の下限も、同じ形で満たせないときの道を書く。

### 指摘2: 試した回が、切り替わる前の画面の押せるものへの押しで埋まりうる

場所: 6章 条件7 の「窓の守りの回」と「空振りでないことの対」の試した回の定義。t5a-measure.md 0章の「落ちた先」と「狙った2打目」も同じ。

- 試した回は「2打目の `pointerdown` の的が押せるものの上にあった回」とだけ決めてある。的がどちらの画面の押せるものか（切り替わったあとの画面のものか、1打目を押した画面のものか）は問わない。
- 0・90ms の同じ点の2打目は、1打目の click が切り替えを描く前に押し下げが届くことがある。そうなると、2打目の的は1打目の押せるもの（「はじめる」・「次へ」）そのものになる。タッチでは、1打目の離しから身ぶりの tap（click）が組まれる前に、道具の次の `touchStart` が届きうる。その押しは押せるものの上にあるので試した回に数えられる。そして守りが無くても、reducer が段階の外の更新を受け付けないので何も起こさない（4-3）。守りを試さずに合格の回になり、「本ごとに1回以上」をその回だけで満たしうる。
- 診断の最後の答え→結果の狙った2打目も同じである。150ms の回は、答えてから 150ms のタイマーで結果に切り替わる境目に当たる。「新しい画面が出ている 150・300・500ms」という前提がこの切り替わりでは成り立たず、的を、切り替わる前の答えた問の画面で選びうる。
- 測りの記録は、2打目の `pointerdown` の時の帯の番号を残すと決めている（0章の「落ちた先」）。これを使えば読み分けられるのに、試した回の決め方にそれが入っていない。

直し方: 試した回を「2打目の `pointerdown` の時に、切り替わったあとの画面（帯の番号・段階・結果のボックスで決める）が出ていて、的がその画面の押せるものの上にあった回」と決める。切り替わる前の画面に落ちた回は、試していない回として別に数える。狙った2打目は、的を選ぶ時に切り替わったあとの画面が出ていることを確かめてから押す。出ていなければ、試していない回にする。診断の最後の答え→結果の 150ms はこれに当たりうることを書く。空振りでないことの対も、900ms のあとの押しが同じ画面の上にあることで数える。

### 指摘3: 窓の守りと連続の押しの守りの合否が、指定の間隔で数えられ、実際の間隔が 700ms を越えた正しい受けを外れにする

場所: 6章 条件7 の「窓の守りの回」と「連続の押しの守りの回」のマウス、plan-t5a7.md 4 の「間隔」（「0・150・500ms は境を試す値ではないので送り直さず、実際の間隔を記録する」）。

- 守りは、起点の `pointerdown` から2打目の `pointerdown` までの `event.timeStamp` が 700ms 未満の押しだけを受けない。700ms 以上の押しを受けるのは、決定どおりの正しいふるまいである。
- 窓の守りの回の合否（「その回の2打目が、答え・ページの移動・開閉のどれも起こさず」）と、マウスの「`detail >= 2` で届いた 150・300・500ms の2打目が答えを入れないこと」は、指定の間隔で回を数える。実際の間隔で回を数える決まりが無い。
- t5a-measure.md 0章の「負荷」は、T5a-2 の測り（load average 26〜45）で実際の間隔が指定より長くなった回があったと書く。500ms の指定が 700ms を越えれば、守りは正しく受け、合否は外れと数える。その外れは 8章の着地と組みの選び方に回るが、どれも当たらない。
- タッチの連続の押しの守りだけは、離しからの測った間隔で受けない側・受ける側・境目に分けている。窓の守りとマウスには、それに当たる決まりが無い。

直し方: 窓の守りの回とマウスの連続の押しの守りの回は、1打目と2打目の `pointerdown` の `event.timeStamp` の差（守りと同じ物差し）で数える。たとえば 650ms 未満を合否に入れ、650〜750ms を境目として記録だけにし、750ms 以上は守りのあとの押しとして数える（帯の幅は、タッチの 280・320ms に合わせて決める）。狙った2打目と D5 の窓の中（300ms）も同じにする。空振りでないことの対の 900ms のあとの押しは、測った差が 700ms 以上であることを確かめて数える。plan-t5a7.md 4 の「間隔」の 500ms を送り直さない決まりと、この帯の分け方がぶつからないように書く。

### 指摘4: 「受ける」「ボタンが働く」を押しのあとの状態でどう決めるかが、結果の画面のボタンについて決まっていない

場所: 6章 条件7 の「空振りでないことの対」（「答えが入る・リンクが開く・ボタンが働く」）と D5 の 120px のずれの「受けること」、t5a-measure.md 0章の「落ちた先」（「2打目が効いたか（答え・ページの移動・開閉）は、押しのあとの状態（帯の番号・答えの数・URL・`details` の開閉・フォーカスの置き場）で決める」）。

- 結果の画面には、答え・URL・`details` のどれも変えないボタンがある。「画像を保存」（`FudaActions.tsx` の `handleSave`。ダウンロード）、「画像で共有」（`handleShare`）、「友達に診断を送る」（`InviteFriendButton.tsx`。共有か写し）である。狙った2打目は 80px の中のいちばん近い押せるものを的にするので、結果への切り替わりでは、これらが的になりうる。
- 守りが止めたかは、「フォーカスが 4-7 の置き場から動かない」で読める。しかし、対と 120px のずれで「働いた」と決める物差しは、0章の列挙（帯の番号・答えの数・URL・`details`・フォーカス）のどれをどう読むかが書かれていない。0章の「別のタブや共有の画面を開く押し」は開いたタブで効いたかを決めるが、ダウンロードと写しと `navigator.share` を持たない Chromium の分岐は挙げていない。担当によって「働いた」の判定が分かれ、空振りでないことの対が外れになるか、何も確かめないまま合格になる。

直し方: 「受けた」「働いた」の判定を1つの列に決めて、6章 条件7 と 0章に書く。たとえば次のどれかが起きたら受けたとする: 答えの数が増えた。URL が変わった。開いたタブの最初の遷移があった。ダウンロードが始まった。`details` の開閉が変わった。開始の画面に戻った。どれも起きないボタンには、押した要素へフォーカスが移ったこと（Chromium はポインタの押し下げでボタンとリンクにフォーカスを移す。守りはその `mousedown` を止める）を受けた印として使う。受けない側の「フォーカスが 4-7 の置き場から動かない」と同じ物差しにそろえる。

## PM が直して閉じるもの（言い回し・置き場所・記録）

- 6章 条件7 の「空振りでないことの対」と 0章の同じ文は、「窓の守りの回で試した回ごとに、狙った2打目と同じ点を…押す」とする。しかし、試した回には同じ点の2打目の回も入る。その回には狙った点が無い。「その回の2打目と同じ点」と言い直す。
- 狙った2打目の「的の矩形の中で1打目の点にいちばん近い点」は、的が点の上か左にあるとき、矩形の下か右の縁の上になる。Chromium のマウスの当たり判定は、矩形の右と下の縁を含まない。そのため、マウスの回は、的を外して試していない回になりやすい。指摘2 の直しで画面を確かめるときに、「縁から 1px 内側の点」などと点の取り方も1句で決めると、試した回の数が無駄に減らない。試していない回として数える決まりはあるので、合否は誤らない。
- 下限は入力を分けずに数える（切り替わりごと・本ごと）。窓の守りは入力によらず `pointerdown` で決めるので、決定の上ではそれで足りる。ただ、plan-t5a7.md 3 の要約の数え方を「切り替わりごと・本ごと・入力ごと」にすれば、片方の入力だけで試した組を後から見分けられる。これは道具の出力を変えるので、ここで閉じずに、指摘1 の直しで下限を決め直すときに一緒に決める。
