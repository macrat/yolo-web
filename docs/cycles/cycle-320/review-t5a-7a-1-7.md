## 指摘

1. **1度の押しで終わる操作の古い形の記録が、黙って「外れ 0・記録の欠け 0」になる**（report.mjs 290行）。`if (line.l) unmatched(null, line.hu ?? 0, null)` は、`l` を持つが `hu` を持たない行を 0 として数える。ところが `hu` は blob `ff009a37`（c9583d6e）で足されたもので、`l` を足した blob `0c9b7969`（47f619c8）の記録は `l` だけを持つ。実際に `tmp/cycle-320/t5a7a1-fix/after`（頭の行の `tool.measure` が `0c9b7969`）の start の3束は、置き換えの外れを1つも記録していないのに、`hitUnmatched` {}・`hitUnrecorded` 0 と出る。`hitUnrecorded` は「要る数を持たない記録の数」と注釈と README に書いてあり、走査の古い形はそのとおり数えるのに、1度の押しの古い形だけが「確かめて 0 だった」と同じ出力になる。この変更の目的の「古い形の記録の扱い」と、README の「`avoidable` と `at16` に入る押しはどれも数に入る」に当たらない。根は、measure.mjs が `hu` を 0 のとき出さない（`|| undefined`）ので、記録から「0」と「持たない」を分けられないこと。たとえば measure.mjs が `l` を持つ行には `hu` を 0 でも書き、report.mjs は `l` があって `hu` の無い行を `hitUnrecorded` に数える形にする（そのときは blob が替わるので、t5a-measure.md 10章の blob と大きさの値、README の `hu` の「0 なら無い」も合わせて直し、走らせ直す）か、頭の行の `tool` で見分けるか、担当が決めて README・注釈と合わせる。
2. **README の `hitUnrecorded` の書き方がコードと違う**（README 170行の最後の文）。「`land` が問の行の数を持たない形の置き場」の着地の記録を一律に `hitUnrecorded` に数えると読めるが、コードが問の行の数を要るのは `diagnosis-answer` だけで、ほかの種類の `land` は一致しなかった数だけで `hitUnmatched` に入る（合成の記録で確かめた）。report.mjs の注釈（「診断の答えでは問の行の数も」）と同じに直す。
3. **report.mjs の `hitUnrecorded` の注釈の文が切れている**（42〜43行）。「n の押しが7つ目からの欄を、押しごとの記録の land が問の行の数を持たない置き場（…）で 0 にならない。」は「欄を」を受ける動詞が無く、どの置き場で 0 にならないのかが読み取りにくい。「n の押しが7つ目からの欄を持たない置き場や、land が問の行の数を持たない置き場（…）では 0 にならない」のように直す。指摘1を直すなら、1度の押しの古い形もここに入る。
4. **t5a-measure.md 10-2 の「次の4点で違い」の箇条に、5つ目の箇条（375×550 の「はじめる」の 15 回の大きさ）が同じ深さで並ぶ**（435行）。違いの4点と、測った大きさの値が同じ並びに見え、「4点」と数が合わない。大きさの値は直前の箇条（434行）に入れるか、箇条の外の文にする。
