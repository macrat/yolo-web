## 決めごとやふるまいが変わる指摘

### 指摘1: タッチの連続の押しの守りの「受ける側」が、選択肢に落ちなかった回も外れに数え、正しい作りが落ちる

場所: 6章 条件7 の「連続の押しの守りの回」の「タッチ（受ける側）」（「離しからの測った間隔が 320ms 以上 700ms 未満（500ms の回）で、100px の中の2打目が次の問に答えを入れること（外れた件 0 で合格）」）。decision-landing.md の同じ箇条も同じ文。

- この箇条は、320〜700ms の帯の2打目がすべて答えを入れることを求める。2打目の `pointerdown` の的が次の問の選択肢の上にあったかを問わない。
- 同じ点の2打目は、いつも次の問の選択肢に落ちるわけではない。t5a-measure.md 5-2 の「参考の値」では、診断12本の最後の問でない問への1打目 3,096 回のうち、2打目が次の問の選択肢に落ちたのは 2,823 回だった。残りの約 9%（273 回）は選択肢に落ちていない。診断の選択肢はどの問も4つだが、見出しと選択肢の字の長さで行の位置と高さが問ごとに変わり、最初の行の点が次の問の見出しに、最後の行の点が区画の空きに来うる。
- 選択肢の上でない押しは、守りが正しく受けても答えを入れない。この箇条のままでは、そうした回が外れの件になる。作りが正しいのに条件7 は合格にならず、外れた件は 8章の4つの選び方（着地と組みの直し）に回るが、どれも当たらない。
- 「受けない側」も、試した回を「2打目の押し下げが次の問の上に落ちた回」と書き、選択肢の上かを決めていない。同じ合否の列の一般の「試した回」（的が押せるものの上）がここにも掛かるのかが読めない。次の問の見出しの字に落ちた回は、守りが無くても答えを入れない。そうした回が試した回に入ると、「診断12本のそれぞれに1回以上」の下限を、守りを試していない回で満たしうる。
- 「受ける側」には下限も無い。この箇条は窓だけを掛ける誤った作りを見分ける唯一の合否なのに、試した回が 0 でも合格になる。

直し方: タッチの「受けない側」と「受ける側」の回を、どちらも2打目の `pointerdown` の的が次の問の選択肢（`closest` した押せるもの）の上にあった回に限ると決める。選択肢の上でなかった回は、守りを試していない回として数だけを記録する。「受ける側」にも、「受けない側」と同じ下限（診断12本のそれぞれに1回以上、など）を置く。

### 指摘2: 下限の「的があった組から少なくとも1回」の単位と、満たせなかったときの扱いが決まっていない

場所: 6章 条件7 の「下限」、t5a-measure.md 0章の「下限」、decision-landing.md の「下限」。

- 「切り替わりごと・入力ごとに、狙った2打目の的があった組（本・画面）から少なくとも1回」は、2通りに読める。
  - (a) 切り替わり・入力ごとに、的のあった組のどれかから合わせて1回以上
  - (b) 的のあった組のそれぞれに1回以上
    plan-t5a7.md 3 の要約は組ごとに数えるので (b) とも読める。(a) と (b) では、合否で見る範囲が大きく違う。
- どちらで読んでも、満たせなかったときにどうするかが書かれていない。書いてあるのは「的のあった組が1つも無ければ PM に報告する」だけである。的のあった組はあるが、試した回が下限に届かないとき（狙った押しが切り替わる前の画面に落ちた、測った差が 650ms 以上になった、など）に、合格としないのか、PM に報告するのかが決まらない。前回まであった「1本でも無ければ合格としない」は、窓の守りの回から外れた。
- D5 の 80px・120px に「同じ下限」を掛けると、(b) では、正しい作りでも満たせない組が出る。D5 のずれは決まった向き（(0, ±80)・(−80, 0) と (0, ±120)・(−120, 0)）である。狙った2打目の的（80px の中のいちばん近い押せるもの）があった組でも、その向きのずれの先に押せるものがあるとは限らない。120px のずれは、そもそも 80px の中に的があるかと関わらない。
- 下限が数える回の帯も書かれていない。合否に入るのは測った差が 650ms 未満の回なので、下限も 650ms 未満の試した回で数えるべきである。いまの文では、境目や 750ms 以上の回で下限を満たしうる。plan-t5a7.md 3 は帯ごとに数えるとしているので、数は出る。決まりが無いのが欠けである。

直し方: 下限を (a) か (b) のどちらかに決め、650ms 未満の試した回で数えると書く。満たせなかったときの扱い（合格としない、または PM に報告する）を1つに決める。D5 は、ずれの先に押せるものがあった組から数える、など、D5 のずれの形で満たせる下限に決め直す。

## PM が直して閉じるもの（言い回し・置き場所・記録）

- 窓の守りの回の合否は「答え・ページの移動・開閉のどれも起こさず、フォーカスが 4-7 の置き場から動かないこと」と書く。新しく足した「働いたかの判定」（7つの事象）とは書き方が違う。守りが止めればフォーカスは動かず、止め損ねればフォーカスが移るので、どちらで読んでも合否は同じになる。D5 の 80px の「受けない」と合わせて、「働かなかったこと（上の『働いたかの判定』）」と言い直せば、1つの物差しにそろう。
- マウスの連続の押しの守りには、試した回（次の問の選択肢の上に落ちた回）の数を記録する決まりも下限も無い。CDP の `clickCount: 2` はいつも `detail` 2 を届けるので、300・500ms の回は毎問出る。そのため、合否が空振りになるおそれは小さい。指摘1 の直しでタッチの試した回を決めるときに、マウスも同じ言い方で「試した回の数を記録する」と1句添えれば足りる。
