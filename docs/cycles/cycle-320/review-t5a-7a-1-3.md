## 指摘

### 指摘1（中）: report.mjs の `avoidable`・`at16.clear` が 0章の判断の決まりと違う数え方で、罫線の上の送りを避けられた送りに数える

0章の「判断での使い方」は、「範囲の中に押せるものを避けられる送りがあったかは、`l` の最も離せたときの `max(dx, dy)` を Android の半辺（10px と 16px）と比べて決める」と書く。ところが report.mjs が出す数は次のとおりである。

- `avoidable` と `at16.clear` は `clearOfFirst`・`clearOfBoth`（点の真下から外す送りが1つでもあったか）で数える。真下から外れても、半辺 10px の面なら隔たりが 10px より小さい送りではまた寄る。0章の決まりとは違う数である。
- 10px と比べた数（`far` ≥ 10）は出していない。出しているのは `far16` だけである。

この違いは、副作用でもう表に出ている。375×550 の「はじめる」のタッチで report.mjs が出す `avoidable.next` は 10 で、そのうち4本（character-personality・word-sense-personality・character-fortune・music-personality）は `farBoth` が 0〜0.4px である。点を2つの行のあいだの罫線 1px の上に置く送りがあるだけで、道具の面でも Android のどの面でも、選択肢に寄るのは避けられない。`avoidable` か `at16.clear` を「避けられたのに落ちた件」の数として読むと、避けられない4本を避けられた件と取り違える。そうなると、次のサイクルの着地の作りの決め直しが「罫線の上に点を置けば避けられる」という誤った材料を受け取りかねない。10-1 は `at16` の値を並べるが、`avoidable` の値（10）とその読み方は書いていない。

直し方:

- report.mjs で、`avoidable` と `at16` の両方に、far が 10 以上の数と 16 以上の数を組ごとに出す（`far10`・`far16`）。0章の決まりと同じ物差しにする。
- `clearOf` で数える数は、残すなら「真下から外す送りがあった数（罫線の上の送りを含み、避けられたかの判断には使わない）」と注釈と README に書く。使わないなら外す。
- 10-1 の副作用の箇条に、report.mjs のどの数にこの4本が入り、どの数には入らないかを書く。

PM へ: plan-t5a7.md 3 は、「落ちうる件」（16px より近い件）は定めているが、「避けられた」をどの隔たりで決めるかは書いていない。0章は 10px と 16px の両方と比べると書く。16px より近い件を落ちうる件と数えるなら、筋が通るのは「16px 以上離せる送りがあった」を避けられたとする形である（`at16.far16`）。合否に使う数を plan-t5a7.md 3 か 5 に書いて、0章と report.mjs をそれに合わせる。

### 指摘2（低）: D5 の束では、`at16` が2打目の点からの隔たりと1打目の点からの着地の記録を組み合わせる

report.mjs は、ずれのある束で、落ちうる件の判定に `n2`（2打目の点からの隔たり）を使う。一方、組み合わせる `l` の `clear`・`far` は、着地の関数が受けた1打目の点から数えた値である。D5 の束の `at16.clear`・`far16` は、ずらした点が避けられたかを表さない。D5 の合否は第1の組に落ちた件が 0 か（device-triage.md の (ii)）なので、合否は誤らない。ただ、数を読み違えないように、report.mjs と README で D5 の束の `avoidable`・`at16` を出さないか、1打目の点からの値であることを書く。

### 指摘3（低）: 押せる範囲への置き換えが合わなかったとき、黙って要素の箱のまま数える

`summarizeLanding` の `pressable` は、`landing.hit` に同じ要素の箱が見つからなければ、関数の矩形（罫線を含む箱）のまま数え、跡を残さない。いまの版では組みが同じなので合うが、関数の側で矩形の取り方が変わる（決め直した着地の作りで変わりうる）と、指摘2（第2回）の 1px のずれが黙って戻る。README の「着地の記録が黙って欠けないよう…止まる」と同じ考えで、`data-hit-area="after"` の祖先の箱のうち、関数の矩形と一致しなかった数を着地の記録に持たせるか、`hit` があるのに一致が 0 なら止まるようにする。

### 指摘4（低）: README の `<名>/` の行が、T5a-8 の測り直しの置き場を別の置き場のように読める

「ここに置く理由」は「T5a-8 の測り直しの記録は、測り直した操作と画面の変更後の版の記録を置き換える」と書く（plan-t5a7.md 3 のとおり）。一方、ファイルの表の `<名>/` の行は「`after`、T5a-8 の測り直しの版。`base` は測っているあいだだけ」で、T5a-8 の版が別の名の置き場を持つように読める。置き換えるなら、`after` のどのファイルを、どの名で置き換えるかを1つの形で書く（同じ名のファイルに置き換えるのか、別の置き場で測ってから写すのか）。

### 指摘5（低）: 走り直しの記録のうち、変更後の版の答えの走査が 10章に出てこない

`tmp/cycle-320/t5a7a1-fix/after/` には、「はじめる」の3画面のほかに、答えの走査（375×550・タッチ・300ms と 90ms の各3本）と D5 の答えの走査（320×550・(0, −10)・90ms の2本）がある。10章は変更後の版について「はじめる」の 45 回しか書かない。この走りは、変更後の版で答えの2打目が次の問の選択肢に落ちた押しを押しごとの記録に置かないこと（300ms で `next` 13、押しごとの記録 0）を確かめる材料で、10-2 の「直した道具での記録の大きさ」の文の裏づけになる。何を走らせて何を確かめたかを1行で書く。
