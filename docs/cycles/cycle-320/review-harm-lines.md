# cycle-320 着地の直しの害の線のレビュー

対象: [plan-t5a7.md](./plan-t5a7.md) 2b の「害の線」1〜6（2160d6ff）。照らしたもの: [decision-landing.md](./decision-landing.md)（「確かめること」を含む）、[carryover.md](./carryover.md) の「着地の直しの害の確かめ」、[index.md](./index.md) の「実施する作業」の行、`git diff 5ea1ab89 758725fc -- src/lib/reveal.ts`、758725fc の `src/play/quiz/pressGuard.ts`、[landing-options.md](./landing-options.md) 2-1、[cycle-316/t5a-measure.md](../cycle-316/t5a-measure.md) 10-1、`measure/measure.mjs` と `measure/README.md`（いまの記録の欄）。

## 4 の主張をコードに照らした結果

`chooseTouchClearLanding` と `chooseLanding` を突き合わせると、次のことが言える。

- 範囲の中に、どちらの組からも 16px 以上離れる送りが無い回は、`chooseLanding(choice)` をそのまま呼ぶ。渡す矩形（`avoidFirst`・`avoidNext` は行の矩形）も、大きさの無いものを除く条件も前の版と同じなので、送りは変わらない。
- 基準が送らない回（`plan.base === 0`）では、基準の点で両方の組から 16 以上離れていれば、どちらの版も 0 を返す。送りが変わるのは、前の版の着地（0）で、どちらかの組までの max(dx, dy) が 16 未満の回だけである。前の版が真下を外す最も近い送りへ動いた回も、その着地が 16 以上なら、両方の版で同じ送りになる（16 以上の送りは真下を外しているので、前の版の最初の候補が A″ の最初の候補と同じになる）。
- 基準が送る回では、前の版の着地が両方の組から max(dx, dy) で 100 以上離れていれば、A″ もその送りを選ぶ。例外は、罫線 1px の差で行の矩形までの直線の距離が 99〜100 になる端の回だけである。
- よって「A″ が送りを変えるのは、離れが 16px 未満の回と、基準が送る回で 100px 未満の回だけ」は、1px の端を除いてコードどおりである。道具の `n` と `l` も罫線を除いた押せる範囲で数えるので、物差しはコードと合う。

ただし、この線の組み方には下の指摘1・2の欠けがある。

## 指摘（判定を変えるもの）

### 指摘1: 4 は「送らない枝で 16〜100px の回の送りが変わった」場合を害に数えず、決めの「ほかの操作の送りを変えない」より緩い

4 は 16 の条件と 100 の条件をまとめて「100px 未満でなかった回」だけを害に数える。上のとおり、基準が送らない回で送りが変わってよいのは 16 未満の回だけである。基準が送らない回で、前の版の着地が 16〜100px なのに送りが変わったら、決めにもコードにも合わない変わり（動かないまとまりを見ている来訪者の前で画面が動く、DESIGN.md §11 の害）である。それなのに、4 ではこの回が害に入らない。

また、decision-landing.md の「確かめること」は「A″ がほかの操作の送りを変えないこと」で、landing-options.md 2-1 の実測でも、A″ が「はじめる」のほかの操作（答え・「次へ」・最後の答えと「次へ」・「もう一度挑戦する」の 2,020 回）の送りを変えた回は 0 だった。4 は、ほかの操作でも 100px 未満の回の変わりを「決めどおり」として通す。決めの確かめより緩く、実測で 0 と見込んだ所に出た変わりを見逃す。

さらに、決めた所の中の変わりにも量の線が無い。carryover.md は線の例に「送りの量の増え方」を挙げ、landing-options.md 2-1 で A″ が直した回の送りの増えは +3〜+15px だった。基準が送る回で、A″ が max(dx, dy) の 100 を目指して範囲の奥まで送るようになっても、4 では害にならない。そうした回は、範囲の中なので 3 にも掛からない。

直し方:

- 4 を枝で分ける。基準が送らない回では、前の版の着地が両方の組から 16 以上なら、送りが変わったら害とする。基準が送る回では、100 未満でない回の変わりを害とする（いまの線）。`land` の1つ目（s0）で枝を分けられる。
- 「はじめる」のほかの操作で送りが変わった回は、隔たりによらず、件ごとに PM が見る線にする（決めの「確かめること」のとおり）。
- 決めた所の中の変わりも、送りの増えが landing-options.md の見込み（+15px）を越えた回を、件ごとに PM が見る線にする。

### 指摘2: 3 は、範囲が空で s0 にした回（4-9 が受け入れた回）を害に数えてしまう

`landingSpan` が空の回、つまり `span.min > span.max` の回は、どちらの関数も基準の `plan.base` を返す。これは前の版も同じで、t5a-design.md 4-9 が受け入れた回である（README の `re` が 1 か 2 の回。200% の「次へ」で範囲が1点の回もこの近くにある）。範囲が空なので、選んだ着地はいつも「範囲の外」になり、3 の書き方では直しと関わりなく害に数えられる。

直し方: 3 を「打ち切った範囲が空でない回で、選んだ着地がその外にある回」に絞る。空の回は、前の版でも空だったかを比べ、直した版で新しく空になった回だけを件として数える。道具の欄では、結果への切り替わりは `re` と `report.mjs` の `lowInSpan`・`clampEmptyRuns` が使える。ほかの切り替わりは、押しごとの記録の `land` の 4・5・11 番目（打ち切った範囲と選んだ着地）で読む。

### 指摘3: 5 の「1 秒以上」と「900ms のあと」は、守りが受けるはずの押しの大半を見ず、しかも試しの走りにその押しが無い

決め（decision-landing.md の決めたこと 1・3）では、守りが受けるのは次の押しである。

- 窓のあと（700ms 以上）の押し
- 窓の中でも、1打目の点から 100px の外の押し
- 診断の答えのあと、連続と数えられない押し（タッチは離しから 300ms 以上、マウスは `detail` 1）

5 は、そのうち「1 秒以上」と「900ms のあと」だけを見る。守りの作りの誤り（起点の取り違え、連鎖の数え違い、離しの時刻の取り違えなど）が出るのは、むしろ境目のすぐ外の押しである。来訪者の「押したい所が押せない」害のうち、速く答える人の答えが捨てられる型（cycle-301 の害で、決めが連続の押しに絞った理由そのもの）は、1 秒未満の連続でない押しで起きる。index.md の「実施する作業」の行も「診断の答え→次の問の速い押しが前と同じに答えを入れる」と書いており、5 の「1 秒以上」と食い違っている。

また、いまの試しの走り（t5a-measure.md 10-1 の表）には、診断の答えのあと 1 秒以上空けた押しも、3つの切り替わりの 900ms のあとの押しも無い。答えの走査は、2打目のあと、1打目から 450ms（`WAIT_FROM_FIRST_MS`）で次の問の1打目へ進み、`measure.mjs` には 900ms の押しが無い。決めの「空振りでないことの対」と D5 の 900ms は道具に足す要件で、試しの走りの組に入るとはどこにも書いていない。このままでは、5 は道具で取れない値に頼った、いつも 0 件の線になる。

直し方:

- 5 を、守りが受けると決めた押しの全部にする。つまり、直した版で、上の3つのどれかに当たる押し（試しの走りでは、タッチの診断の 300ms・500ms の2打目のうち離しから 300ms 以上のもの、走査の次の問の1打目、D5 の 120px のずれ、900ms の対など）が働かなかった回を害とする。
- 「1 秒以上」と「900ms」の押しを、試しの走りのどの組で出すか（足す走りか、道具に足す「空振りでないことの対」と D5 の 900ms を試しの走りに含めるか）を、carryover.md の「着地の直しの害の確かめ」か、道具の要件に書く。

### 指摘4: 走査の中の押しを何で突き合わせるかが無く、守りで道筋がずれた走査で 1・2・4 が誤って数えられる

直した版では、窓と連続の押しの守りが2打目を止める。そのため、同じ走査（同じ `k`）でも、前の版と押しの並びが変わる。前の版で2打目が次の問に答えを入れて1問飛んだ走査は、直した版では飛ばない。さらに、走査の次の問の1打目は、前の問の1打目から 450ms 余りで来る。知識クイズの「次へ」のあとは窓の 700ms・100px の中に入りうるので、道具の1打目そのものが守りに止められ、道具が黙って押し直すこともありうる（`measureAnswers` は、答えが入らなければもう一度押す）。押しの番号で並べると、別の問の押しどうしを比べ、無い「新しい外れ」を数えたり、出た外れを見逃したりする。

直し方:

- 走査の押しは、回の名（`k`）・帯の番号・押しの種類（答え・「次へ」）で突き合わせると線に書く。片方の版にしか無い帯の押しは、別に数えて件ごとに見る。
- 道具の1打目が守りに止められた回は、5 の害か決めどおりかを分けて数える。窓の中・100px の中なら決めどおり（「受ける害」）、そうでなければ 5 の害である。数えたうえで、比べの外に出す。

### 指摘5: 2 と 4 が読む「前の版の着地の max(dx, dy)」と「送りの量」は、いまの要約からは走査の押しで取れない

走査の要約の `n` は、タッチで、しかも 0 より大きく 20 以下の押ししか持たない。マウスの走査と、20 を越える押しは要約に残らない。そのため、4 の 100px の境目は走査の押しで読めず、2 も、前の版で 20 を越えていた押しの値が欠ける。送りの量（選んだ着地と s0 の差）は、いまは押しごとの記録の `land` にしかない。押しごとの記録は、判断に要る回と誤りの回にしか置かれない。carryover.md の道具の要件 (1) は「どの回の要約にも送りの量」で、走査の押しごとの送りの量と、100 まで取った隔たりを持つかが読めない。

直し方: 1〜4 がそれぞれどの欄で読むか（1度の押しで終わる操作は要約の `n`・`l`、走査は押しごとの記録の `near`・`land` など）を線に書く。走査の押しごとに、送りの量と、100 で頭打ちにした両方の組の max(dx, dy) が両方の版で取れることを、いま要件を足している担当の要件に入れる。2 の「着地の離れ」は、`n` が2打目の `pointerdown` の時の組みで測る値である。2打目が切り替わりより先に来る回（診断の 0・90ms など）では、着地の離れではない。そうした回を 2 から外すことも書く。

### 指摘6: 6 は、タッチの「残る hover」とマウスのカーソルの下の hover を、ふつうのふるまいなのに害に数える

回答の画面の hover の線は `@media (hover: hover)` で絞っていない（globals.css の §6 の部品の hover・active）。タッチの端末の Chrome と Safari は、触れた要素に `:hover` を付け、ほかを触るまで残す（下の出典）。そのため、守りが受けなかった押しでも、受けた押しでも、触れた所には hover の線が残る。マウスでは、カーソルが要素の上にある限り hover が出るのが正しいふるまいである。6 の「hover・active の形が残る回」は、このどちらも害に数えるので、いつも件が出るか、見る人ごとに判定が割れる。

決めの「形が残らないこと」で見たいのは、受けなかった押しが、受けた押しと違う形（押した行のリング、active の線、選んだ印など）を残し、答えが入ったように見えることだと読める。

直し方: 6 を次の形にする。

- 比べの元: 同じ版で、同じ要素を窓の外で押したとき（受けた押し）のうち、画面が替わらない押しの形。
- 見る時: 離してから一定の時（たとえば 300ms）のあと。
- 害とするもの: `:active` の線が残る回と、答えが入った・選んだと読める形（押した行のリングなど）が出る回。
- 害に数えないもの: タッチで hover の線だけが残る回（ふつうのタップと同じ）と、マウスでカーソルの下に hover が出る回。

また、撮るのを「タッチとマウスの「はじめる」の窓の中の押しを1回ずつ」に限ると、診断の連続の押しの守り（答えの行の上の押し）と結果への切り替わり（リンク・ボタンの上の押し）の形を見ない。守りの種類ごとに1回ずつ撮る。

### 指摘7: 語の選択の対（`select`）の変わりを見る線が無い

758725fc は「2打目で語を選ばない守り」を `pressGuard` の同じ受け手にまとめ、受けない押しの `mousedown` で `preventDefault` する。試しの走りの組には語の選択の対（30 回）があり、前の版では 60 回すべてで語が選ばれた（10-1）。来訪者が問の文や結果の字をダブルクリックで選べなくなるのは「読む所」の害だが、1〜6 のどれにも入らない。

直し方: 「前の版で語が選ばれた語の選択の対で、直した版で選ばれなかった回」を線に足す。
