## 指摘

### 1. 同じコミットを作り直したときにチャンクの一覧がそろうかを、どこでも確かめていない（中）

plan-t5a7.md 3 の指紋は、同じソースから作り直せば `.next/static/chunks` の名前と大きさが同じになる、という前提に立つ。この前提は確かめられていない。

- Next.js 16 の `next build` は Turbopack で、チャンクの名前は中身のハッシュで決まる。ただし同じ入力から同じ出力になることは、Next.js の側でも直しが続いている領域である（Turbopack の「Make tasks deterministic」[vercel/next.js#85524](https://github.com/vercel/next.js/pull/85524)、リポジトリに `test/production/deterministic-build` の試験がある）。書き出す場所（`tmp/` の下の道）・Node の版・環境の変数で出力が変わらないことは、このプロジェクトでは試していない（`docs/knowledge/nextjs.md` にも記述が無い）。
- そろわなかったとき、計画は「木が合うのに差があれば、ビルドの道具の差」とし、PM が「その版で測り直す範囲を決める」とだけ書く。何を見て範囲を決めるかの物差しが無い。作り直すたびに必ず差が出る性質だったなら、続きの日のたびにこの判断が要り、前回の指摘1と同じ形（全部を測り直せば日割りの上の線を押し上げ、測り直さなければ版の取り違えを見逃す）に戻る。

直し方の例: T5a-7a-1 の「手順の確かめ」に、同じコミットを `tmp/` の別の道に2度書き出してビルドし、チャンクの一覧が同じになるかを確かめる段を入れる。同じなら今の指紋のまま。違うなら、どのファイルが違い、何で揺れるかを調べ、揺れないもの（木のハッシュに `package-lock.json` から入れた依存の版と Node の版を足すなど）で指紋を組み直し、`measure/README.md` に書く。あわせて3に、「木が合いチャンクが違う」ときに PM が見るもの（違うチャンクが、測る操作の面のコードを含むか）を1行書く。

### 2. 基準の版の `git write-tree` は、主の木の索引を書き換える読みが残る（軽）

`git write-tree` は今の索引から木を作るので、「重ねたあとの `git write-tree` の値」を出すには、fff3d31f に da102212 の `character-personality.ts` を重ねた索引が要る。測りの担当は主の木で動くので、主の木の索引に `git read-tree` などで重ねれば、PM の作業の索引を壊す。「`tmp/` の下に置いた別の索引（`GIT_INDEX_FILE`）で重ねて `git write-tree` する」と道具の側の手順に書かせる1句を足す。

### 3. 変更後の版を作るコミットが、担当ごとに動く HEAD と読める（軽）

plan-t5a7.md 2 は変更後の版を「T5a-4 を取り込んだ HEAD」と書く。3 で PM が担当ごとに記録をコミットするので、`design-rollout` の HEAD は担当ごとに進む。後の担当がその時の HEAD から作ると、アプリのコードは同じでも木のハッシュが変わり、3 の物差しでは「作り直しの誤り」に見える。「変更後の版は T5a-7a-1 で記録したコミットで固定し、条件7・D5 の担当はみなそのコミットから作る」と書く（T5a-8 の測り直しも、取り込んだコミットで固定する）。

### 4. `--unshallow` は浅くない木では失敗する（軽）

`git fetch --unshallow` は履歴が既に深い木では「--unshallow on a complete repository does not make sense」で止まる。同じセッションで2度目の作り直しをするときなどに担当が迷う。「`git rev-parse --is-shallow-repository` が true のときに」と条件を付ける。

### 5. 「実施する作業」の T5a-8 の行が、新しい順と違って読める（軽）

index.md の「実施する作業」の T5a-8 は「…決めた範囲の測りをやり直して合否を満たし、レビューに通す」で、レビューが測りのあと1度だけと読める。作業内容 6 と plan-t5a7.md 6 では、コードのレビューを通して取り込んでから測り直し、測り直しの記録も担当ごとにレビューに通す。チェックリストの行を同じ順（直してレビューに通し取り込み、取り込んだコミットで測り直して合否を満たし、その記録をレビューに通す）に書き直す。
