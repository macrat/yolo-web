## 指摘

### 1. 塞げずに残す二度押しの2打目（答えを入れる・ページを離れる）を受け入れる決まりが、「覆す決めごと」に書かれておらず、8章の決まりと食い違う。見張りの書き方も見えるものを越えている（来訪者に届く設計の決めごと。改善指示の理由）

決めたこと 3 と理由の最後の項は、塞げない二度押しの2打目（診断の答え→次の問の連続と数えられない2打目、3つの切り替わりの 700ms 以上の2打目）を受け、合否に入れず、件の数を B-620 の材料にすると決めている。その中には、次の問に読まずに答えを入れるものと、結果の画面のリンクに寄せられてページを離れるもの（375×800 の知識クイズ。理由の「B を採らない」）が入る。

ところが t5a-design.md 8章の「件を受け入れる」は「ほかのページへ移るものと、答えを入れるものには選ばない」で、決定の「覆す決めごと」は、その掛かる範囲を「二度押しの2打目に限る」と書くだけである。残すと決めた件はどれも二度押しの2打目なので、この文のとおりに 8章を書き直すと、8章は残す件の受け入れを禁じたままになり、決めたこと 3 と食い違う（「限る」は、8章の選び方がもともと二度押しの2打目の件だけを扱うので、何も変えない）。設計の文の直しの担当がこの文から 8章を書くと、自分と矛盾する設計が残る。

あわせて、8章は受け入れた件ごとに (i)〜(iii) のどれで扱うかを決めることを求めているが、残す件の振り分けが無い。「確かめること」の「iOS の Safari が二度押しの2打目を 700ms より後に届けるか、連続の押しを `detail` でどう数えるかは…出荷のあと、上の数えるイベントで見張る」は、見えるものを越えている。`quiz_press_guarded` は止めた押しでしか送られないので、すり抜けた2打目（答えが入った件・ページを離れた件）は1件も数えられない。見えるのは、止めた押しの率をブラウザ別に比べて、iOS で守りが働いているらしいかどうかまでである。

次を決めること。

- 「覆す決めごと」に、塞げずに残す二度押しの2打目は、答えを入れるものとページを離れるものも、8章の4つの選び方に回さずに受け入れ、件の数と隔たりを記録して B-620 の材料にする、と書く（いまの「限る」の文と置き換える）。受け入れる理由（送りと組みでは害なく 0 にできず、時間の上限を延ばすと読んでからの押しを捨てる）は理由の最後の項にあるので、そこを指せば足りる。
- 残す件の (i)〜(iii) の振り分けを書く。すり抜けた2打目そのものは GA で見えないので「見張らずに受け入れた」とし、見えるもの（`quiz_press_guarded` の `transition` ごとの率のブラウザ別の比べで、iOS で守りが働いているかを見る。設問の飛びは B-613 に渡す。D5 の行と同じ）を分けて書く。

### 2. 直すものの一覧に、守りのもとで誤りになる測り方の文が3つ漏れている（測りの決めごとが変わる。改善指示の理由）

決定は、落ちた先と答え・移動・開閉を「捕捉の段階の `click` の記録でなく、押しのあとの結果で決める」とした（第3回の指摘3）。ところが、同じ測り方を決めている次の文が直すものに無い。

- t5a-design.md 6章 条件7 の「落ちた要素は、捕捉の段階の `click` の受け手で記録する（knowledge §3）」。直すものの「6章 条件7（合否の線…）」は合否の線だけを挙げている。
- `docs/knowledge/input-events-and-guards.md` §3 の小節「窓を『どこに』掛けるかは、2打目が落ちる先を測って決める」の「capture phase の click リスナで実測して初めて確定する」。守りが同じ `window` の捕捉の段階で click を止めるページでは、道具の受け手は止めた click も記録するので、この知見の文はそのままでは誤った測り方を教える。直すものは knowledge の冒頭と §5 だけを挙げている。
- plan-t5a7.md 5 の「t5a-measure.md 5-2 の確かめ（1打目＋X＋S＝問の数）」。5-2 は X・S を捕捉の段階の `click` の記録から数えると決めており（第3回の指摘3 の確かめた事実）、守りで止めた2打目が X か S に数えられると、この確かめが守りの効き目と無関係に崩れる。

この3つを直すものに足し、押しのあとの状態で数える決めごとに揃えること（知見は、守りのあるページでは捕捉の段階の click の記録が止めた click も含むことを、初めから書いたように書く）。

### 3. 連続の押しの守りが読んでからの答えを捨てないとする前提が、測っていないのに事実として書かれ、同じ項で引く cycle-301 の記録と張り合っている（設計の根拠の誤り。指摘1 と同じ直しで直す）

理由の「診断の答え→次の問に窓を掛けない理由と…」は、「次の問が出てから 550ms のうちに読んで押すことは無いとみて、その人の読んでからの答えは捨てない」と書く。同じ項は、窓を掛けない理由として「cycle-301 は、ここに 600ms 未満を捨てる窓を掛けて、速く答える人の答えを日常的に捨てた」を引いている。

- 550ms の前提は測っていない。cycle-301 の記録は、600ms の窓の害を「実コードから導出したもので…実測は記録に無い」とし（observation-impact.md）、別の所では BigQuery で「600ms 未満で答え続ける来訪者は 0 件」と書いている（design.md）。前提も、引く害も、どちらも確かめられていない（AP-P32: 仮説の地位を確かめずに根拠に使う）。
- 2つを並べると、「速く答える人は 600ms 未満で日常的に答える」と「550ms のうちに読んで押すことは無い」が同じ項にあり、読む人（T10・B-620 の判断）は害があるとみるのか無いとみるのかを決められない。決定の中身（`detail >= 2` と 700ms と 100px を重ねて、捨てうる押しを、OS の連続の時間の中で同じ点を押した押しに絞る）は、どちらの前提でも筋が通る。直すのは書き方である。

次のように書き直すこと。550ms のうちに読んで押す来訪者がいるかは測っていない。窓は、そういう押しを 700ms・100px の中ですべて捨てるが、連続の押しの守りは、そのうち OS が同じ連続と数えた（同じ点の、連続の時間の中の）押しだけを捨てるので、捨てうる押しが窓よりずっと狭い。その残りの害は「受ける害」に書いたとおりで、`quiz_press_guarded_retry` の `transition: answer` の経過 ms と B-613 で確かめる。cycle-301 の害は、窓を掛けない理由として、記録の地位（コードからの導出）とあわせて引く。

## PM が直して閉じるもの（言い回し。もう一度のレビューは要らない）

- 理由の「700ms は、Android の二度押しの間隔の上限 300ms…を覆い」: `DOUBLE_TAP_TIMEOUT` は1打目の離しから2打目の押し下げまでで測り、窓は1打目の押し下げから数えるので、覆うのは1打目の押している時間が 400ms 未満のときである。ふつうの押しはそれより短いので結論は変わらないが、物差しの違いを一言書く。
- 測りの合否の「連続の押しの守りの回」: 0・90ms の2打目は、診断の 150ms の見せる間で答えた問の上に落ち、守りが無くても答えを入れない。守りを試しているのは 150・300・500ms の回だと記録に書くよう、一言足す。

## 確かめた事実

- t5a-design.md 8章の「件を受け入れる」は「落ちる先がページを離れず、答えも変えないもの（開閉するもの）に限り…ほかのページへ移るものと、答えを入れるものには選ばない」で、受け入れた件ごとに (i)〜(iii) を決めると書いている。(iii) は「見張れないものは、見張らずに受け入れたと書く」（指摘1）。
- t5a-design.md 6章 条件7 に「落ちた要素は、捕捉の段階の `click` の受け手で記録する（knowledge §3）」、knowledge §3 の小節に「capture phase の click リスナで実測して初めて確定する」、plan-t5a7.md 5 に「t5a-measure.md 5-2 の確かめ（1打目＋X＋S＝問の数）」がある。`measure.mjs` は `touchstart`・`mousedown`・`click` の受け手を `addInitScript` で置き、2つ目の `click` を `second` にして落ちた先を決めている（指摘2）。
- cycle-301/observation-impact.md は 600ms の窓の害を「実コードから導出したもので、この間隔での掃引実測は記録に無い」とし、cycle-301/design.md は「600ms 未満で答え続ける来訪者は 0 件と判明」と書いている（指摘3）。
- 条件7 の「実際の間隔」は1打目と2打目の押し下げの差（タッチは `touchstart`、マウスは `mousedown`）で、`measure.mjs` も1打目からの時間で2打目を送る。
- `QuizContainer.tsx` は `ANSWER_SHOWN_MS = 150` のタイマーで診断の次の問へ移り、`window` に `touchmove` の passive の受け手を置いている。`reveal.ts` の `PRESSABLE_SELECTOR` は `a[href], button, summary, input, select, textarea, label, [role="button"], [role="link"]`。クイズの面の部品は押しを `onClick` で受け、`onPointerDown`・`onMouseDown` を持たない。
- 診断の character-personality は 12 問、知識クイズ3本は 10 問。
