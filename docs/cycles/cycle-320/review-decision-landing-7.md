## 指摘

### 1. タッチの受けない側の「2打目が次の問の上に落ちた回」は、押しのあとの状態では読めない（測りの道具の決めごと。改善指示の理由）

決定は、受けない側の合否を「離しからの測った間隔が 280ms 未満で、2打目が次の問の上に落ちた回（落ちた先は押しのあとの状態で読む）で、答えを入れないこと」とし、「測りの道具」でも「2打目の落ちた先と答え・移動・開閉は、…押しのあとの結果（帯の番号・答えの数・…）で決める」としている。

しかし、守りが2打目を止めた回の押しのあとの状態は、次の2つで同じになる。

- 2打目が、150ms の見せる間のうちに答えた問の上に落ちた回。答えた問はもう答えを受けず、そのあと次の問へ進む。押しのあとは「帯は n+1・答えの数は n」。
- 2打目が次の問の上に落ち、守りが止めた回。押しのあとは同じく「帯は n+1・答えの数は n」。

このため、決定の文どおりに作ると、220ms の回が「守りを試した回」か「試していない回」かを道具が決められない。全部を試した回と数えれば、外れの検出はできる（守りが働かなければ答えが入る）。しかし、次の問の上に1回も落ちていなくても合格になりうる。第6回の指摘1 が塞ごうとした「試さずに合格になる」形が、数え方の側から戻る。

押しのあとの状態で決めるべきなのは「2打目が効いたか（答え・移動・開閉・フォーカス）」で、「どこに落ちたか」ではない。落ちた先は、2打目の押し下げのときの記録で決められる。道具はいまも `window` の捕捉の段階の `touchstart`・`mousedown` の受け手で、そのときの要素と帯の番号を記録している（measure.mjs 509〜528 行）。この受け手は `addInitScript` で守りより先に置かれ、守りが止めても記録は残る。捕捉の段階の記録で誤るのは「止めた click も効いたように見える」ことであって、押し下げの時点で何の上にいたかではない。

次を決めること。

- 「測りの道具」の文を書き分ける。2打目が何の上に落ちたか（次の問か、答えた問か、ほかの組か）は、2打目の押し下げ（タッチは `touchstart`、マウスは `mousedown`）の捕捉の段階の記録の要素と帯の番号で決める。答え・移動・開閉・フォーカスは、押しのあとの状態で決める。「測りの合否」の受けない側の行の「落ちた先は押しのあとの状態で読む」もこれに合わせる。
- 「直すもの」の knowledge §3 の直しの文（「落ちた先は押しのあとの状態で決める」）も同じに書き分ける。この文のまま knowledge に入ると、後の測りが同じ混同をする。
- 受けない側の合否に、試した回の数の下限を入れる（例: 220ms の回のうち次の問の上に落ちた回が、本・画面ごとに1回以上あること。無ければ合格としない）。

### 2. タッチの連続を起点の離しだけから数えるので、速い連打の3打目が次の問に答えを入れる。マウスの数え方とも食い違う（来訪者に届く設計の決めごと。改善指示の理由）

決定は、タッチとペンの連続を「起点の押しの離し（`pointerup`）の `event.timeStamp` から次の押し下げまでが 300ms 未満」で数える。起点は答えを入れた押しだけである。マウスは `mousedown` の `detail >= 2` で数え、ブラウザの `detail` は直前の押しから連鎖して 3・4 と増えるので、700ms・100px の中の3打目以降も受けない。

タッチでは、たとえば離しから 150ms・300ms の間隔の三度押し（焦ったときの連打）で、次のようになる。

- 2打目（起点の離しから約 150ms）: 答えた問の上か、出たばかりの次の問の上に落ちる。後者なら守りが受けない。
- 3打目（起点の離しから約 300ms 以上、起点の押し下げから 700ms 未満、同じ点）: 起点の離しから 300ms 以上なので連続と数えられず、次の問に、読んでいない答えを入れる。

これは来訪者の約9割（iOS 58.9%・Android 30.4%）が使うタッチで起き、マウスでは同じ押し方が止まる。決めたこと 3 の「塞げない二度押しの2打目」の並びにも、3打目以降は入っていない。つまり、決めて受け入れた残りでも、測る残りでもない。

次のどちらかを決めること。

- （勧める）タッチとペンの連続を、直前の押し（受けなかった押しを含む）の離しから次の押し下げまでの 300ms 未満で連鎖して数える。受けないのは、これまでどおり起点の押し下げから 700ms 未満・100px 以下に限る。マウスの `detail` の連鎖と同じ形になり、捨てうる押しは 700ms・100px の中から広がらない。試験に、起点の離しから 300ms 以上だが直前の受けなかった押しの離しから 300ms 未満の3打目が答えを入れないことを足す。
- 起点からだけ数えるなら、3打目以降のすり抜けを決めたこと 3 の残りに書き、条件7 の記録で数える。

### 3. 走査でペンを押すかが決まっていない（測りの道具の決めごと。改善指示の理由）

「測りの合否」の診断の答えの行は「タッチとペン（受けない側）」「タッチとペン（受ける側）」「タッチとペンの境目」と書く。ところが走査の入力は「タッチとマウス」で、道具（measure.mjs `sendPress`）もタッチとマウスしか送らない。ペンを走査に足す（たとえば CDP の `Input.dispatchMouseEvent` の `pointerType: "pen"`）のか、ペンは単体試験で確かめて走査はタッチで代表させるのかが、測りの担当には決められない。どちらかを書くこと。後者なら、合否の行の見出しは「タッチ」にし、ペンは試験の行で受け持つと書く。
