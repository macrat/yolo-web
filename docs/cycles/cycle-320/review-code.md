## 指摘

### 指摘1（来訪者に届くもの・重い）: 見せる間に押し下げたタッチの2打目が、診断の次の問に答えを入れ、結果の画面のリンクを開く

`pressGuard.ts` は、押しを受けないかを `pointerdown` の時に、そのとき掛かっている守りで決める（`handlePointerDown`）。診断の答えのあとは、`QuizContainer` が答えたあとの画面で守りを外し（`guardAfter(null)`）、150ms の `ANSWER_SHOWN_MS` のタイマーで切り替わってから、`open` で守りを掛ける。そのため、**見せる間に押し下げた押しは、どれも受けない押しにならない**。

ふつうの指の二度押しでは、1打目を離してから 2打目を押し下げるまでがおよそ 100〜200ms で、指は 60〜100ms ほど触れている。1打目の `click` から 150ms で切り替わるので、2打目は見せる間に触れて、切り替わったあとに離す回が多い。タッチの落ちる先は離した時の組みで決まるので（knowledge §8）、その2打目の `mousedown`・`click` は次の問の選択肢か結果の画面のものに届き、守りはそれを止めない。

- 診断の答え→次の問: 2打目が、読んでいない次の問に答えを入れる。連続の押しの守りが受け持つはずの、いちばん多い型である。
- 診断の最後の答え→結果: 2打目が、結果の画面のリンク・共有のボタン・「もう一度挑戦する」を押す。型 (3) と同じく、来訪者をページの外へ連れていきうる。

決定の文は、この押しを受けない押しに入れている。連続の押しの守りは「起点（答えを入れた押し）から、押し下げの `event.timeStamp` が 700ms 未満で、100px 以下で、かつ連続の押し」を受けず、最後の答えの窓は「起点は答えた押し（…起点は押しの時刻）」である。どちらも、押し下げが切り替わりの前か後かで分けていない。見せる間の押しは、起点から 700ms 未満で、起点の離しから 300ms 未満で、条件に入る。いまの作りは、決定のこの部分を満たしていない。

「はじめる」と知識クイズの「次へ」は `click` の処理の中で切り替わり、次の押し下げより先に守りが掛かるので、この穴は無い。

**直し方の向き**: `open` のときに、まだ `click` まで届いていない押し（`press` が起点でなく `press.clicked` が偽）を、掛ける守りの条件で見直し、当たれば `blockedBy` に入れる。窓の守りなら `isWithinReach`、連続の押しの守りのタッチとペンなら、それに加えて起点の離しから 300ms 未満の押し下げ。マウスは、`mousedown` がすでに済んでいれば、その `detail` を押しに残しておいて 2 以上かで見る（Chromium では `click` が出ないので来訪者への害は無いが、同じ決まりで扱うほうが読みやすい）。こうすれば、その押しは「受けなかった押し」になり、builder の (a)（見せる間のタッチの押しを連鎖の元にする）は、決定の「直前の押し（起点の押しか、受けなかった押し）」の形にそのまま収まる。

**足す試験**: 指摘の再現と同じ組み立てで、(1) 見せる間にタッチで押し下げ、切り替わってから次の問の選択肢で離す押しが、答えを入れず、`mousedown` と `click` が止まること、(2) 最後の答えで同じ形にすると、結果の画面のリンクの `click` が止まること、(3) 見せる間に 100px の外で押し下げた押しは受けること。

### 指摘2（内部の道具のふるまい）: 条件7・D5 の測りは、この穴を見ない

条件7 の測りは、2打目の落ちた先を `pointerdown` の的で決め、「0・90ms と 150ms の一部は答えた問の上に落ちた回で、守りを試していない回」と数える。道具のタッチは触れと離しを続けて送るので、押し下げと離しのあいだに画面が入れ替わる回が起きない（knowledge §8 の「道具の押しは触れと離しを続けて送るので、2つの時はほぼ同じになる」）。指摘1 の穴は、道具の上では起きず、`pointerdown` の的の記録では「試していない回」に入る。測る面が来訪者の指の押しを写していない（AP-WF33）。

**直し方の向き**: 診断の答えと最後の答えのタッチの走査に、押し下げを見せる間に、離しを切り替わりのあとに置く押し（たとえば1打目の離しから 100ms で触れ、80〜120ms 触れたまま）を足す。その回は、落ちた先を `pointerdown` の的でなく、押しのあとの状態（答えの数・URL など）と `click` の的で読み、「働かなかったこと」を合否に入れる。決定と t5a-design.md 6章 条件7 の文（`pointerdown` の的で試した回を決める所）も、この回の扱いに合わせて planner が直す。knowledge §3 の「どこに落ちたかは `pointerdown` の記録で決める」も、押し下げと離しのあいだに入れ替わる回には当たらないことを書き足す（§8 の「落ちる要素は離した時の組みで決まる」と並べる）。

### 指摘3（来訪者に届くもの・小さい）: 主のボタンでない押しと、主でない指の押しも、守りに掛かり数えられる

`handlePointerDown` は、`event.button` と `event.isPrimary` を見ない。窓の中で 100px の中を右クリックすると、その押しは受けない押しになり、`mousedown` の `preventDefault` で `quiz_press_guarded` が送られる（メニューは出る）。中クリックでは自動の送りの始まりを止め、リンクの `auxclick`（新しいタブ）は止めない。2本目の指の `pointerdown` は `press` を上書きし、1本目の指の `mousedown`・`click` が2本目の押しと結ばれる。どれもまれだが、`quiz_press_guarded` の数（T10 の基線）に、二度押しでない押しが入る。主のボタンでない押し（`button !== 0`）と主でない押し（`isPrimary` が偽）は、受けない押しの判定と押しの記録から外す。試験を1つ足す（窓の中の右ボタンの押しで `quiz_press_guarded` が送られないこと）。

### 指摘4（来訪者に届くもの・小さい）: builder の (a) に試験が無い

見せる間のタッチの押しを連鎖の元にするふるまい（`open` の `chainPress`）を確かめる試験が無い。指摘1 の直しのあとの形で、「見せる間に押した2打目のあとの、2打目の離しから 300ms 未満の3打目（起点の離しからは 300ms 以上）が答えを入れないこと」を足す。いまの試験は、切り替わったあとの2打目からの連鎖だけを見ている。

## 見てほしいことへの答え

1. **来訪者への影響**: 読んでいない問への2打目は、切り替わったあとに押し下げた押しなら、窓の守りでも連続の押しの守りでも止まる。見せる間に押し下げたタッチの押しは止まらない（指摘1）。正当な押しは止めていない。`detail === 0` の click（キーボードと読み上げ）は守りの中でも通り、キーボードで切り替えたあとは守りが開かない。100px の外と 700ms 以上の押しは受ける。別の操作（指で引いた送り）は `preventDefault` されず、数えられない。守りが掛かっていない間、受け手は押しを覚えるだけで、`preventDefault` するのは前からある「2打目で語を選ばない」だけである。受け手は `QuizContainer` が外れると `attach` の返す関数で4つとも外れ、クイズのほかのページには残らない。クイズのページの中では、ヘッダ・フッタ・FAQ の `summary` も 100px・700ms の中なら止まる。これは決定のとおりである。
2. **着地（A″）**: 決定どおりである。`chooseTouchClearLanding` は、範囲の中に、罫線を除いた押せる範囲までの max(dx, dy) が先に避けるものと次に避けるもののどちらも 16 以上になる送りがあるかを `chooseLanding` と同じ範囲で調べ、無ければ `chooseLanding` を行の矩形でそのまま呼ぶ。ある回の、基準が送らない枝（基準で 16 以上なら送らず、そうでなければ基準にいちばん近い 16 以上の送り）と、送る枝（16 以上か・16 以上か・遠さ・遠さ・基準に近い）は、landing-options.md 2-1 で測った `chooseA3` と同じ結果になる（`chooseA` の基準が送らない枝の [min(d1,16), min(d2,16)] の比べは、16 以上の送りがある回では、基準にいちばん近い両方 16 以上の送りを選ぶ）。罫線の内側の矩形の取り方（`offsetParent` の矩形から `border-*-width` を引く）も道具と同じである。
3. **GA**: `quiz_press_guarded` は、`mousedown` か `click` を止めたときだけ、守りごとに1回（`Guard.reported`）送る。指で引いて送りになった押しは送らない。`quiz_press_guarded_retry` は、受けなかった押しの的を `closestPressable` した押せるものを元にし、押せるものの上でない押しは元にしない。受けた次のポインタの押しの押し下げが 3,000ms 以内で、`pointerdown` の的の `closest` が同じなら、`elapsed_ms`（丸めた ms）と一緒に1回送る。引数の名前と値は決定どおりである。数に二度押しでない押しが入りうること（指摘3）と、指摘1 の押しが数えられないこと（直せば数えられる）がある。
4. **試験**: 事象は、ブラウザの順（マウスは pointerdown → mousedown → pointerup → mouseup → click、タッチとペンは pointerdown → pointerup → mousedown → mouseup → click）と値（`pointerdown` の `detail` 0、マウスの連続の数は `mousedown`・`click` の `detail`、タッチは `detail` 1 のまま）で組まれている。境目（699・700ms、ちょうど 100px、離しから 299・300ms、3,000ms ちょうど）は、決定の「未満」「以下」「以内」を確かめていて、実装の写しではない。足りないのは、押し下げと離しのあいだに画面が入れ替わる回（指摘1）と、(a) の試験（指摘4）である。「フォーカスを動かさない」の確かめは、jsdom が `mousedown` でフォーカスを動かさないので空振りになるが、同じ試験で `mousedown` の `preventDefault` を確かめているので、指摘にしない。
5. **builder の判断**:
   - (a) 見せる間のタッチとペンの押しを連続の元にする: 来訪者にとって正しい。その押しは答えた問の上で何も起こさず、マウスなら同じ押しで `detail` が増えるので、タッチでも連鎖に数えるのが決定の「マウスの `detail` が直前の押しから連鎖して増えるのと同じ」に合う。ただし、その押し自身を受けない押しにしていないのが指摘1 で、直せば (a) は決定の「受けなかった押し」に収まる。
   - (b) 押し直しの元は最も新しく止めた押し、同じ押せるものかは `pointerdown` の的の `closest`、3,000ms ちょうどを含む: 正しい。押し直しは最後に何も起きなかった押しへの反応なので、最も新しく止めた押しから数えるのが、T10 が読む「早い山」に合う。「3 秒以内」に 3,000ms を含めるのは言葉のとおりである。
   - (c) 着地の点を「切り替えた click」にした: 正しい。前の作りでは、診断の見せる間の押しの `click` が点を上書きし、着地が答えた押しと違う点を避けえた。切り替えた click を `transitionAtClick` で選ぶ形では、キーボードで切り替えたときに、その前のポインタの点を誤って使うことも無い。
