## 指摘

### 1. `<wbr>` だけが変わったページを測らない理由が、事実として誤っている（中）

記録は「`<wbr>` が変えるのは行の折れる所だけで、どの行も同じ左端から始まるので、…箱の左端も最初の字の x も変わりえない」と書く。だが `<wbr>` は、折れる所と一緒に要素の最小の幅（min-content）も変える。表の自動の列の幅、flex の並びの各項目の幅、中身の幅に縮む箱は、この幅で決まる。そのため、隣や右の要素の箱と字の x は動きうる。記録自身も、`CopyButton` の節では「見えない箱の最小の幅を決める文節が替わった」と、この経路を扱って測っている。

変わったページのうち、この経路に当たりうるのは、`/blog/tools-expansion-10-to-30` の道具の一覧の表のセル（「バイト|数計算」→「バイト数計算」で、セルの最小の幅が広がる）である。h1・h2・よくある質問の `summary` は、どれもブロックの幅いっぱいで、当たらない。わたしが上のとおり前と後で測ると、その表と、ほかの3ページの x は一致した。来訪者に届く外れは無いと見られる。ただ、記録の理由は誤ったままで、チェックの根拠として読む人に誤りを渡す。

直し方: 理由を「`<wbr>` は折れる所と最小の幅を変える」と正しく書く。そのうえで、変わった所を、ブロックの幅いっぱいに組むもの（h1・h2・`summary` など。x が変わりえない）と、最小の幅が並びや表の幅を決めるもの（表のセル、`CopyButton` の見えない箱）に分ける。後者は前と後で測り、その値を記録に載せる（表のセルなら、320・375 の既定と 200% の、列ごとの箱と字の x）。

### 2. 道具のページの `CopyButton` を「§5 の揃いに外れなし」と判断した根拠が、DESIGN.md に基づいていない（中）

「§5 の揃い」の節は、道具の行の中の `CopyButton` を「線に並べないもの」とし、「置き方が DESIGN.md の別の決まりで決まる」と書く。そして節の終わりで「外れた面は、前も後も0」と結ぶ。だが道具のページは、まだ刷新の前の作りである（split-plan.md 7 の表の「7〜」の T5-18）。

- hash-generator の値の行（`HashGeneratorTile.module.css` の `.resultRow`）は、1px の枠と 12px（0.75rem）の内側の余白で組まれている。§5 の線の2種類（3px・1px の使い分け）とも、8px の倍数の余白とも合わない。左に寄せる `CopyButton` の 51 は、この余白から来る x である。
- 狭い画面で、値の下の左端にボタンを置く形（`--copy-button-align: start`）は、DESIGN.md §8 の「名前とボタンが1行に収まらないときは、ボタンを名前の次の行の右端に置き」と合わない。
- 右に寄せる形については、記録は DESIGN.md の決まりを1つも挙げていない（§6 の値を写すコピーのボタンの項と、§8 の結果のボックスの頭の行の項が当たる）。

T5a-4 が作ったものではなく、前と後で同じなので、T5a-4 の害ではない。だがこのまま「外れは0」と書くと、刷新の前の道具の作りが §5 と §8 に合うと記録が言うことになる。後に道具を刷新するときの読み手を誤らせる。

直し方: 道具のページについては、§5 の揃いを判断しないと書く。刷新の前の作りで、刷新は T5-18 で行うこと、そのため T5a-4 の根拠は前と後の一致であることも書く。そのうえで、「外れた面は0」を、判断した範囲（クイズのページと、刷新を済ませた色の辞典の表の行）に限る。判断する場合は、上の2点を、T5a-4 の前からある外れとして挙げる。

### 3. 前もって描くページで `CopyButton` を持つ 266 ページの内訳に、`/storybook` が抜けている（小）

### 4. 押したあとの数え方で、「幅いっぱい」のボタンがどちらに入るかが書かれていない（小）

表は寄せ方を「左・右・幅いっぱい」の3つに分ける。一方で、下の箇条書きは「左に寄せる 122 回では左端と字が、右に寄せる 288 回では右端が」と2つにしか分けない。business-email の「メール全文をコピー」（幅いっぱい）がどちらに入り、何が残ったか（左端・右端・字の両方）を書く。

### 5. 冒頭の「（§5）」が何の §5 かが分かりにくい（小）

「`frontend-design` スキルの「目で確かめる」の左端の揃いの項（§5）」と書くと、スキルの節の番号に読める。「DESIGN.md §5 の揃いを確かめる、`frontend-design` スキルの「目で確かめる」の左端の項」のように、§5 が DESIGN.md のものだと分かる形にする。
