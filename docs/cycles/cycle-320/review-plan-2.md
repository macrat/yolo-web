## 指摘

### 1. `measure/` に道具と記録を置く形が、lint・format と docs の決まりに当たることを計画が扱っていない（中）

- 元にする道具は CommonJS である（cycle-318 のキャリーオーバー「T5-6 の `lib.cjs` は `../node_modules/playwright` を…」、t5a-measure.md 0章「`scan.cjs` の `CSS`」）。そのまま `.cjs` で `docs/cycles/cycle-320/measure/` に置くと、上で確かめたとおり ESLint が設定の誤りで落ち、コミットの前の検査（`pre-commit-check.sh` の4）でも、push の前の `npm run lint` でも止まる。`.js` にして `require` を残しても誤りになる。`.ts` にすれば `npm run typecheck`（strict・`noImplicitAny`）に入る。
- 要約した JSON も `prettier --check .` の対象で、道具が書いたままの形では `format:check` で落ちうる。`npm run format` を掛けると配列が1要素1行に開き、押しごとの記録（条件7 だけで基準と変更後の2版で数千の走査、D5 でさらに 6ずれ × 2画面）は数 MB から数十 MB になりうる。`design-rollout` は最後に main へ入るので、その大きさが main の履歴に残る。
- `.claude/rules/doc-directory.md` は `docs/cycles/` に「サイクルドキュメント以外は保存しないでください」と書く。測りのスクリプトと JSON をサイクルの記録とみなすかは、計画の「検討した他の選択肢」で push の決まりだけを理由に選んでおり、この決まりとの関係を書いていない。

計画に、(a) 道具は ESM の `.mjs` で書き、`lint`・`format:check` を通すこと（必要なら `tests/e2e/*.mjs` の先例に倣う）を T5a-7a-1 の完了の条件に入れる、(b) 記録の形と大きさの上限（例: 押しごとの記録を必要な欄に絞る・1ファイルの上限）を決める、(c) doc-directory.md の決まりとの関係を PM が判断して書く（サイクルの記録とみなす理由、または決まりを直すか別の置き場にするか）。

### 2. T5a-8 の測り直しの範囲を「直した操作」で決めており、直したコードが掛かるほかの操作と面を落としうる（中）

T5a-8 は「直した件にかかわる条件7・D5 の回（直した操作の全本・全画面）」を測り直すとする。だが 8章の選択肢の多くは、1つの操作に閉じない所を変える。

- 見せる範囲や着地の選び方を変えると、`src/lib/reveal.ts` の `revealLanding` を通るすべての操作（「はじめる」・答え・「次へ」・最後の答え・「もう一度挑戦する」）の着地が変わりうる。`visibleRange()` を触れば nakamawake・kanji-kanaru のゲームの送りも変わる。
- 「組みを直す」は 8章が「ほかの面にも同じ部品があるなら、その面の測りもやり直す」と書いている。開始の画面の「はじめる」の位置を変えれば、「もう一度挑戦する」のあとの着地（開始の画面に戻る）も変わる。

測り直しの範囲を、直した差分が通るコードの道（どの関数・部品を変えたか）から決め、その道を通る操作・面をすべて入れる、と書く。範囲は判断のタスクで件ごとに決め、レビューに通す。

### 3. T5a-8 が設計の文と合わせる先が t5a-design.md だけで、出荷する文書と知見の文書を落としている（中）

見せる範囲・第1の組と第2の組・「はじめる」と「次へ」のあとに次の問の選択肢を避けること・開始の画面の見せる範囲は、t5a-design.md 4-5・4-9 だけでなく、`DESIGN.md` 424行（§8 の送りの段）と `.claude/skills/frontend-design/SKILL.md` 150行、`docs/knowledge/input-events-and-guards.md` の冒頭の段落にも同じ中身で書かれている。「見せる範囲を広げる」「第2の組を外す」を選べば、これらがコードと食い違う。CLAUDE.md のツギハギ禁止で、この3つは最初から正しく書かれた形に直す必要がある。

また、「組みを直す」（「はじめる」の位置・あき）は見た目を変えるので、T5a-8 の完了の条件に撮った像（`take-screenshot`、ライト・ダーク × モバイル・PC、前と後。AP-WF05）と、左端の揃いの測りを入れる。設計の文の直しを先にレビューに通すことは書かれているので、その対象に上の3つを足す。

### 4. cycle-319 のキャリーオーバーの「ずれた着地で切れる見出し」の決めどころが無い（中）

cycle-319 のキャリーオーバーは、「はじめる」と「もう一度挑戦する」のあと着地が 158〜236px ずれ、h1 やパンくずが画面の上で切れる件について、「T5a-7 は、ずれた件の数と量に加えて切れる見出しがあるかを記録し、PM が第2の組を外すか、着地を行の切れ目にそろえるかを決める材料にする」と書く。計画は T5a-7a-2 でこれを記録するが、判断のタスクは「条件7 の合否と D5 を満たさない件」だけを扱う。切れる見出しは合否の外（第1の組にも、避けられたのに落ちた件にも入らない）なので、このままでは誰も決めない。また「着地を行の切れ目にそろえる」は 8章の4つに無い手で、4-9 の手順5 を変える。
