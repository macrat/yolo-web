## 測定面の注意（着手前に固定・後から動かさない）

- **SC のバックフィル漂流**: 凍結基線ファイルの値（07-13 集計）と、今日同じ期間 06-15〜07-12 を再集計した値がずれる（例: dictionary 16,864→19,060 impr、play 4,634→5,059 impr、記名クエリ 222→250 clk）。原因は SC エクスポートの遅延バックフィル（凍結時に直近日が未成熟）。**方向読みは「今日同時取得の同成熟度 基線 vs 出荷後」で行う**。出荷後窓の直近日（07-25〜27）も同様に未成熟でやや過少の可能性がある点を割り引く。
- **トリップワイヤの発火基準は凍結値（222clk）を使う**（事前登録の基準は動かさない）。ただし本サイクルは+2週で**発火判定はしない**（発火判定は出荷+4週 ≒2026-08-10）。今回は軌跡確認のみ。
- **GA4 は漂流なし**: 再集計した基線が凍結値と完全一致（診断 84.0%=343→288・クイズ 86.4%=22→19）。測定面の妥当性が確認できた。
- **07-13 デプロイ境界の半日混入**: 刷新の本番反映（cycle-279 完了・main push）の起点は **2026-07-13 13:20:53**（commit `4fd0f5f5` のコミット時刻。実デプロイ完了はこれ以降で数分の幅がある）。ship 側窓は 07-13 全日を含むため、当日 00:00〜13:20 の約13.3時間は**旧デザインのトラフィックが ship 側に混入**する。これは ship 側完走率を基線側（高め）へ引くため、観測された低下は**真の低下をやや過小評価**している可能性がある（方向は覆さない・結論は+3ヶ月窓で保留）。cycle-298 の露出（約9時間30分）と同様、境界混入として明記する。

## 7. 実機点検（2026-07-30 実施・完走率低下の解釈を確定）

**なぜ+4週を待たず実施したか**: 「来訪者が結果に到達できていないかもしれない」という疑いを、実行3分の検査で12日先送りするのは constitution Goal（来訪者価値の最大化）と CLAUDE.md「Playwright で必ず確認する」に反する。レビュー指摘を受けてその場で実施した。

**方法**: 本番 `https://yolos.net/play/character-personality` を 375×812（モバイル実寸）で開き、12問すべてに回答して結果面まで通した。※**この点検自体が本番の GA4 にイベントを注入している**（07-30 分・`level_start`/`level_end` 各1件、`page_view` 1件＝開始率の分母とモバイル比率の PV/セッションにも入る）。+4週で 07-30 を含む窓を読む際はこの合成分を差し引いて解釈する（規模から結論には影響しない）。`gtag` 呼び出しを捕捉して `level_end` の発火を確認。

**結果——健全（「結果に到達できていない」仮説は棄却）**:

| 確認項目         | 結果                                                                                                |
| ---------------- | --------------------------------------------------------------------------------------------------- |
| 12問の進行       | 1/12→12/12 まで正常（全12問4択）                                                                    |
| 最終問後の結果面 | **描画された**（結果タイプ名が h2 で表示・シェア/もう一度挑戦も表示）                               |
| `level_end`      | **1回発火**（`content_id: quiz-character-personality`・`success: true`・`content_type: diagnosis`） |
| console error    | **0**（警告は Next.js の CSS preload 警告のみ＝無害）                                               |
| 入口の摩擦       | 設問見出しが viewport 内（y=349 / 812）・選択肢も折り返し内                                         |

**計器の意味の訂正（これが最も重要）**: `level_end` は **`setPhase("result")` と同 tick の回答ハンドラ内**で発火する（`src/play/quiz/_components/QuizContainer.tsx:105-106,118-119`）。**結果面の描画に依存しない**。したがって:

- **完走率（`level_end/level_start`）の実体は「最終問（12問目）まで回答した率」**であり、「結果を受け取れた率」ではない。低下が意味するのは**設問途中の離脱**である。
- §3-1 の仮説2に含めた「作り替えた結果面で `level_end` が取りこぼれる終了側の計装退行」は、**コード上ほぼ成立しない**（結果面描画は発火条件でない）。実機でも発火を確認したので、この筋は落とす。
- 以後この低下は「12問を最後まで答えきる人の割合が下がった＝設問途中の離脱が増えた」として扱う。残る問い＝**どの設問番号で落ちているか**（局在）と、それが母集団シフトか回答体験の摩擦か（帰属は同時期対照＝B-612）。
