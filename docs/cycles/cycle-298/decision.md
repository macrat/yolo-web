## 問1の判定: cycle-284 の「裏切り(バーナム種明かし)」は今も成立するか

**強い形では成立しない(cycle-284 の判定を再測で訂正)。**

- (条件A 即時露呈=バーナムの種明かし): **不成立**。一覧はタイトルのみで、その札は cycle-284 自身が line167 で「単体で貼れる強い資産」と認めた固有名。24の固有な札が並ぶことは「皆同じ褒め文」を露呈しない(褒め本文=バーナムは各結果ページに入らないと読めず、本文は cycle-296 で固有化済)。かつ一覧は肖像直後ではなくCTA2枚の後の末尾で、「自型の肖像の直後に他人が割り込む」構図でもない。
- (条件B 面積不均衡で肖像を押し下げ): **不成立**。一覧は末尾にあり、肖像(あるある・メッセージ)を下へ押し下げていない。肖像が先・一覧が後の順序。面積は約27〜31%と大きいが「押し下げ」はしていない。

→ 私が着手前に固定した基準(条件A・B の両方成立で「裏切りあり」)に照らすと、**cycle-284 の強い主張は成立しない**。裏切りを捏造して変更を正当化しない(基準を守る)。**cycle-284 の h=1653/37%/種明かし判定は stale・過大であったと訂正する。**

## だが再測が浮かせた別の所見(来訪者価値)

強いバーナム論とは別に、来訪者価値の観点で改善に値する所見がある。**ただし以下は実測された事実と、PM の質的判断を分けて書く**(判定レビュー Major-2 の是正=害を事実化しない):

- **PM の質的判断(未実測・断定しない)**: 私(PM)が現物を上からスクロールして受けた印象では、肖像を読み終えCTA2枚を過ぎた末尾で24型が等価に並ぶと、視界が「自分専用の結果」から「全24型の索引」へ切り替わり、自型が one-of-24 として**相対化されるように感じた**。これは A1 の主観的印象1件が根拠で、実測(post-R エンゲージ)は無い。撤回した種明かし論(中身の信憑性が死ぬ)とは別物だが「他型が並ぶと個人宛感が薄まる」という同じ直観の親戚である点は自覚する。事実として扱わず、賭けの一材料に留める。

判定の駆動源は cycle-284 の(訂正された)種明かし論ではなく、**constitution 決定原則(来訪者価値の最大化)**である。

## 問3(回遊実測)の含意 — 何を測れて何を測れないか(Major-1 の是正)

回遊(=`/result/*` への遷移)が測るのは**クリック(能動的な探索行動)**であって、**24の固有な札を眺める体験(ゼロタップのブラウズ・「こんな濃いキャラが24いる世界だ」という世界観の厚み・眺めての楽しさ)ではない**。回遊0が言えるのは「一覧は能動的にクリックされていない」までで、「一覧に読む価値が無い」ではない。index.md 20行が「露呈か、それとも探索の誘い(眺める楽しさ)か」を**未決の問い**として立てた通り、後者(受動的な眺めの価値)は本サイクルでは測れていない。よって:

- **確度が高い**: 能動的な探索導線としての実効価値はほぼゼロ(4ヶ月で別型回遊0)。→ 一覧を default から外しても**能動探索の喪失は実質ゼロ**。
- **未確定**: 受動的な眺めの楽しさ・世界観の厚み。これは畳み込みで default から隠れる(1タップの先に退く)ため、**この価値の分だけ畳み込みは費用を負う**。ただし畳み込みは全量を1タップ先に保持するため費用は上限付き。

→ よって以下の処遇判定は「実証で確定した最善」ではなく、**未確定の受動価値を織り込んだ、不確実性下の低リスクな賭け**として書く(判定レビュー Major-1・総評の是正)。

## 問2の判定: 処遇の選択 = **畳み込み(collapse)**(低リスクな賭け)

能動探索価値ほぼゼロ・受動の眺め価値は未確定、という前提で候補を比較(来訪者価値で・実装コストは理由にしない):

| **畳み込み(details 初期折畳)**          | 結果が肖像+CTAで締まり、能動探索ゼロの30%ブロックを default から外す。全24型+内部リンク24本は「他のキャラも見てみよう」1タップで全量保持(初期HTML由来でクロール可)。**費用=受動の眺めをゼロタップ→1タップへ後退させる(未確定価値)**。低リスク・容易に revert 可                 | **✓ 採用**  |
| 移設                                    | 既に末尾で移す先がない                                                                                                                                                                                                                                                          | ✗           |

| **可視のまま圧縮再設計(全24件・第6案)** | 全24件を可視のまま密度を上げ面積を縮小し肖像+CTAの後に短く置く。**ゼロタップの眺めを保持**する点で畳み込みに優る。一方(a)結果を依然「索引」で終わらせる・(b)相対化の懸念があるなら可視のまま残る・(c)密度再設計は枠崩れリスクを伴う別作業。眺め価値が高いと判れば最有力の対抗案 | △(有力対抗) |
| 一覧を近縁数件に絞る                    | 全探索を捨て関連度モデルを要する。畳み込み/第6案が全24保持で優る                                                                                                                                                                                                                | ✗           |

**採用=畳み込み(低リスクな賭け)。** 理由:

- 能動探索は4ヶ月で0=default から外す費用の確度が高い側はほぼゼロ。畳み込みが負う費用(受動の眺めの後退)は未確定だが、全量を1タップ先に保持するため上限付き。
- CTA2枚(相性/再診断)は既に一覧の前にあり、畳み込んでも行動の契機は肖像直後に保たれる。結果は「肖像→行動→(畳んだ)探索」で締まる。
- 撤去より扉を残す点で優り、第6案(可視圧縮)より低リスク・可逆(受動の眺め価値が高いと後で判れば `open` 既定化 or 第6案へ寄せるのが容易)。
- **これは確定ではなく賭け**。反証手段=将来の post-R エンゲージ計測で、畳み込み後に character-personality 結果面の下流エンゲージ(相性/再診断/滞在)が落ちていないかを見る。落ちていれば第6案へ寄せるか `open` 既定化で revert する(監視事項に記載)。

## SEO 一次資料確認(基準で約束した項目・Minor-1 の是正=一次資料へ)

UX 目的でアコーディオン/タブ/details に格納したコンテンツは、**モバイルファーストインデックスでフル加重でクロール・インデックスされる**(デスクトップ時代の「隠しコンテンツは減衰」から Google が方針変更)。要件は「モバイルの内容がデスクトップと同等であること」。一覧はSSRで初期HTMLにあり、モバイル/デスクトップ同一コンポーネントで内容同等のため、畳み込みで内部リンク24本のクロール価値は保たれる。

- **一次資料**: Google Search Central「Mobile-first Indexing Best Practices」(https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing)=アコーディオン/タブへの格納は UX 目的なら可・内容同等が要件。2026-07-25 確認。
- 補足(二次): Google の Gary Illyes 発言(隠しコンテンツにモバイルでフル加重)=seroundtable(https://www.seroundtable.com/google-content-hidden-mobile-24111.html)。
- 実装裏取り: 実装レビューが SSR HTML を curl し、`open` 属性なしの `<details>` 内に24本のユニーク内部リンクが存在することを確認済。

## 実装方針(C へ)

- 共有コンポーネント `CharacterPersonalityContent.tsx` の全タイプ一覧セクションを `<details>`(初期 closed)+`<summary>`「他のキャラも見てみよう」に変更。inline ResultCard(list 版・高トラフィック面=本体524PV)と standalone 結果ページ(grid 版)の両方に効く。
- 不変: typeId/title/color/icon/相性/判定/設問/配点/本文。変更はレイアウト/IA のみ。
- a11y: `<details>/<summary>` はネイティブでキーボード・SR 対応。見出しレベル(h2/h3)の扱い・aria-current ハイライトの保持を確認。展開時のスクロール保持。
- 検証(C2): inline ResultCard(高トラフィック面)を含め before/after を {幅360,1280}×{light,dark} で撮影。
- **heading-in-summary の SR 挙動(Minor-3 の是正)**: `<summary>` の content model は heading 1要素を許容する妥当な形。実装レビューが Chromium a11y ツリーで `heading [level=2]` がアウトラインに保持され消えていないこと、`aria-expanded` が null なのはネイティブ disclosure の正しい挙動(ブラウザが開閉状態を暗黙に AT へ伝える)であることを確認済。展開時に `aria-current="page"` のハイライトも保持。
