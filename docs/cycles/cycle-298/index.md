# サイクル-298

## 背景と芯

玄関 `/play/character-personality`(全PVの31%)は、判定(cycle-295/B-589)を結果先行に作り直し、本文(cycle-296/B-603 T2)を各型に固有化した。12問に答えた人は、正しい型と、その型にだけ言える言葉を受け取るようになった。

残るのが cycle-284 が確定した**欠陥4**——結果の直下に**他23タイプのタイトル一覧**(cycle-284 の DOM 実測で `h=1653`=結果領域の37%)が並ぶ件。cycle-284 の判定は「3つ読めばどれも『あなたは特別／欠点は実は強み』だと分かる＝**バーナム効果を自分で種明かしする**。一覧は37%を使ってこの結果が個人宛でないことを証明している」だった(cycle-284 line 155-157/224-226・T3=採用)。

ただし、この判定を**そのまま実装に移す前に問い直す必要がある**。種明かし論が立てられた時点から、前提が2点動いているからだ:

1. **一覧はタイトルのみを描画する**(`CharacterPersonalityContent.tsx:246-266`・註「各タイプの区別はタイトル文言で行う」)。褒め文(バーナム本文)は一覧に出ない。そして cycle-284 自身が line 167 で「**タイプ名は既に強い**。『締切3分前に5手先を読む炎の策士』は単体で貼れる質を持つ」と資産認定している。強く固有なタイトルが24並ぶことが「皆同じ褒め型」を露呈するのか、それとも「他にもこんな濃いキャラがいる」という**探索の誘い**として働くのかは、現物で確かめ直す価値がある。
2. **本文は cycle-296 で固有化済**。cycle-284 の種明かし論は本文がテンプレ(24/24 同一文型)だった時期の観察に接続していた。クリックして各型の本文へ入っても、今は固有の肖像が返る。

同時に、一覧は欠陥の面だけではない——**他タイプへの探索導線・内部リンク(回遊/SEO)・「友だちはどれ?」の相性入口**を担っている。単純撤去は来訪者価値を削る費用を伴う。

芯は「結果の直下に他23タイプの一覧を置くことが、今も来訪者を裏切っているか。裏切っているなら、探索の価値を保ちながら裏切りを止める最善の処遇は何か」を**現物と実測で問い直し、来訪者価値で判定する**こと。cycle-284 の T3 判定を岩盤化せず、動いた前提の上で再評価する。

- **cycle-284 の T3 判定(要処遇=種明かしを止める)をそのまま実装に移す**: 不採用。種明かし論の前提が2点動いている(一覧はタイトルのみ描画・cycle-284 自身がタイトルを強い資産と認定/本文は cycle-296 で固有化)。過去サイクルの判定でも根拠の前提が動いていれば「固定された事実」ではない(cycle-297 が外部仕様だけでなく内部前提でも学んだ轍)。結論を先に決めず現物で問い直す。
