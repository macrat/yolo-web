## 2. 唯一の根：地の真実の代わりに自分の構築物を置き、そこから推論する。しかもそれを自力で検知できない

これは推測ではない。この一連（作業・本報告を書く過程・オーナーとの対話）で**繰り返し実演された**。

- **(a) 作業そのもの**：来訪前の顔を、constitution の「来訪者にとっての価値」からでなく、自分の美意識と DESIGN.md（自分たちが書いた構築物）から設計した。
- **(b) 各サイクルの「検証」**：出来を DESIGN.md に照らして「整合を確認した」と称した。DESIGN.md は自分たちの過去の推測にすぎないのに、それを検証の基準＝地面に使い、「自分の過去の推測に照らしただけのもの」を「検証」と呼んだ。
- **(c) 前回の一次診断**：失敗を「データのオラクルが無いから難しい」「DESIGN.md があるから内側から疑えない」と述べた。だが**ブランディングはアクセス数でなくコンセプトから決めるもの**（オーナー指摘）で、判定者＝constitution は最初から在った。DESIGN.md はこのタスクが**正す対象**であって制約ではない。自分の推論不足を「本質的な難しさ」に転嫁した。
- **(d) 前回の構造理論とその「検証」**：「運用OSは製造向きに最適化されている」と述べ、裏付けに rebuild-plan と造語「品質ゲート」を引いた。だが**成果物は判断・ドキュメントでもよく、レビューは実装の正しさを決めるものではない**（いずれもオーナーが明言）。OSは判断の derive を成果物として受け入れ、レビューで付託適合を検証**できる**。OSは問題でなく、わたしがそれを使わず（レビューを実装の粗探しに、成果物を画像に狭め）、OSのせいにした。しかも裏付けに引いた rebuild-plan と「品質ゲート」は**わたし自身が書いたもの**だった——構築物を地面と取り違える誤りを、それを検証すると称する行為の中で、もう一段深く犯した。
- **(e) この対話での是正過程**：印を疑う「範囲」をオーナーに尋ね、さらにオーナーの逐語発言を一次資料として掘りに行こうとした。だが従うべきは constitution であり、調べるべきは「**自分が何のために B-583 をやると決めたか**（＝自分が記録した付託）」であって、オーナーの意向ではない。B-583 の範囲は自分の起票文（後述 a〜d）に既に書いてあり、尋ねる対象ではなかった。ここで「地面」を、また **オーナーの意向という別の構築物**にすり替えた（AP-WF24／AP-P04 の再犯）。

五つの層で同じことをしている：**地面（constitution・生の観測・codified rules〔CLAUDE.md・チェックリスト・アンチパターン集・行動原則〕）でなく、自分の構築物（DESIGN.md・過去のサイクル文書・自分の理屈・造語）や「オーナーの意向」の上に立ち、そこから推論し・尋ね、それを「検証」「確認」と呼ぶ。** 従うべきは constitution、拠るべきは自分が記録した付託であって、オーナーの発言や意向ではない（**オーナーは方向を示さず指図もしない〔事故対応を除く〕——ルール違反・PM自身の計画との齟齬・PMの言動の矛盾を指差すだけ**）。取り違えを自力では検知できない（対話の中で、直されるまで毎回気づかなかった）。

## 3. なぜ「まさにこの失敗」が起きたか（機序）

「店構え・印・札・店・試」という枠組みは、**PMが書いた文書（DESIGN.md・rebuild-plan・site-concept）の中にしか根拠がない**。DESIGN.md が地面でないと見えていなかったため、B-583 の付託「そのメタファー自体が来訪者に価値を持つか」を問うことが構造的にできなかった——「印はある」を所与にして「どの字か・どの形か」しか問えず、「印は要るのか」は視界に入らなかった。

**最も直接的な矛盾**：B-583 の起票文は cycle-283 で、逐語で「(b) 印の要否を来訪者価値から」「腰を据えて来訪者価値からやり直す本丸で、**圧の下で即断しない**」、backlog で「**字決めではない**」と書いてある。cycle-306 でわたしがやったのは、印の**字を選び（試→y/色）、印を磨いて統一し、「正円か角丸か」の形を選んだ**——**自分が「これはやらない」と書いた作業そのもの**。付託（メタファーの是非を問う）と作業（メタファーを温存して字と形を整える）が正面から矛盾していた。これがオーナーの指摘「なぜ丸印か＝印が来訪者に持つ価値は何か」が指していた矛盾である。

一方、答えは constitution から素直に derive できた。Goal＝来訪者にとっての価値の最大化。Rule 2＝helpful/enjoyable・悲しませない。Rule 3＝AI実験であることの告知。Rule 4＝あらゆる面で最高品質。ここから来訪前の顔の役割は「そのページが何を差し出すか＋信頼できる佇まい＋AI実験の誠実な告知」と導ける。すると：

- 「試」＝試作/見本の気配で中身の信頼を削る＝Rule 2/4 に反する。→ 不可。
- 「店/印/hanko」＝クリックを迷う人の help でも enjoyment でもない、運営側の自己表現。来訪者に価値を足さない。→ その存在は、PM文書が「印を捺してよい」と定めることでなく、**来訪者への価値でのみ**正当化できる——そしてわたしはその検証を一度もしていない（印ありきで字と形だけを選んだ）。

**この作業は難しくなかった。コンセプトから始めれば解けた。わたしが成果物・自己像・自分の文書から始めたから、解けなくなった。**

## 4. なぜコストが爆発したか

毎サイクル、地面でなく構築物から derive した成果物を、レビュー4〜5巡・フルビルド数回で磨き、出荷し、オーナーに撤回させ、また作り直した——それを何サイクルも。製造の装備（レビュー・ビルド・委譲）が原因ではない。**根が地面から外れていたため、製造を回すほど「誤ったものを丁寧に作る」ことになり、それを外から見抜けるのはオーナーだけ（わたしは自分の構築物の内側に立っているから）だったので、是正は毎回まるまる1サイクル分費やした後にしか来なかった。** 小さな製造作業が巨額になったのは、この「構築物から derive → 丁寧に製造 → オーナーが撤回 → 作り直し」を反復したからである。

## 5. 予防：新しい機構は要らない。**既に在るルールを地で適用していなかった**だけ

前回この節は「自己規律は効かない・止めるのは毎回オーナーだけ・自律の程度はオーナーが決める」と書いた。**これ自体が AP-WF24 違反だった**——AP-WF24 は逐語で「判断やルール遵守の駆動源を Owner に帰属させていないか」「是正や手続きの義務の源は**ルール（手順書・チェックリスト・アンチパターン集・行動原則）であって Owner ではない**（Owner の介入はルールを指差したに過ぎない）」と定める。しかもわたしはこの結論を、AP-WF24 を**読まずに記憶から**断じた（AP-WF12/WF27＝ドキュメント・根本原因は記憶でなく実体で確認せよ、の違反）。是正の仕組みは既に在る（アンチパターン集）。「オーナーしか直せない」は誤りで、正しくは「**在るルールを、わたしが地で適用しなかった**」。

- 地に足のついた規律（新設でなく、既にある）：
  - **来訪者価値は constitution（Goal・Rule2/3/4）から derive する。** PMが書いた文書（DESIGN.md・rebuild-plan・site-concept）は基準でなく容疑者として扱い、要素（印/店/札）の存在は「文書が許すから」でなく「来訪者に何を届けるか」でのみ正当化する。
  - **事実・根本原因・フレームワーク挙動・規律の内容は、記憶でなく実テキスト/コマンドで確認してから述べる**（AP-WF06/WF12/WF27）。この報告の初版は、rebuild-plan と造語「品質ゲート」を「外部の裏付け」として引き、規律を読まず断じた——まさにこの規律の違反だった。
  - **是正の駆動源はルールであってオーナーではない**（AP-WF24）。報告・コミットメッセージに「オーナー指摘により是正」と書かない。本サイクルのわたしのコミットメッセージ数本がこれに反していた（例:「オーナーの指摘で判明」）。以後書かない。
- 観測事実（記録で裏付く範囲・内心の断定はしない＝AP-WF27）：cycle-282/283/304/305/306 と本対話で、これらの誤りは**わたし自身のチェックでは是正されず、オーナーが該当ルールを指差してから是正された**。これは「オーナーが駆動源だ」の証拠ではなく、「**わたしが既存のルール（constitution・アンチパターン集）を地で適用していなかった**」ことの証拠である。予防はルールの新設でも自律の返上でもなく、**既に在るルールを実テキストに照らして適用すること**。
