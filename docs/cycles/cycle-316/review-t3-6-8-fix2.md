## 指摘

### Minor-1: §4 の新しい決まりが、名前が2語以上のときと、1語が幅に収まらないときの折り方を言わず、同じ節の「一覧は通常の禁則処理に従う」とも食い違う

**どこで何が起きているか**: DESIGN.md §4 の新しい項は、「名前の語と括弧の数をそれぞれ1つのまとまりにし、そのあいだでだけ折る。1行に収まらなければ、始め括弧の前で折る」と書き、例に「カテゴリから探す（10）」を挙げる。この文のとおりなら、名前が1行に収まらないときは「カテゴリから探す／（10）」と折れる。しかし実装は名前の中の語の切れ目でも折り、200% の 320・375px では「カテゴリから／探す（10）」になる。実装のほうが t3-design.md 2-9 と T3-8 の完了の条件（「そのあいだ（始め括弧の前）と名前の語の切れ目でだけ折る」）に合っていて、DESIGN.md の文だけが名前の語の切れ目を言っていない。

また、この項は1語が幅に収まらないときのことを言わない。語の中で折ってよいとするのはすぐ上の見出しの項（「一語がコンテンツ幅に収まらないときだけ、語中で折る」）だけで、しかもその項は「本文と一覧は通常の禁則処理に従う」と続く。§7 のとおり索引は一覧の形の1つなので、同じ §4 の中で「一覧は通常の禁則処理」と「索引の語は語と括弧のあいだでだけ折る」が並び、どちらが勝つかを文が言わない。`LinkIndex` と `IndexAccordion` のコメントは「1語が幅に収まらないときだけ、その語の中で折る」を §4 の決まりとして書いているが、§4 は索引の語についてそれを書いていない。SKILL.md の確かめる項（「語と括弧のあいだ（始め括弧の前）でだけ折れているか」）も同じ所が抜けている。

**来訪者にどう効くか**: いまの画面は正しく折れているので、来訪者にいま出ている害は無い。しかし次にこの決まりを読んで組む builder とレビューアは、「カテゴリから／探す（10）」を決まり違反と読むか、「オンラインツー／ル（12）」を決まり違反と読むかのどちらかに迷う。前回の「部／首（198）」も、DESIGN.md がどちらを先に守るかを書いていなかったことから起きた。書かれていない所を実装ごとに埋めると、同じ種類の語が一覧ごとに違う形で折れていく（§12 位置の一定）。

**直し方**: §4 の2つの項を、どれにも当てはまる1つの形に書き直す。例: 見出しの項の「本文と一覧は通常の禁則処理に従う」を「本文と、行の一覧の文は」のように範囲を言い直し、名前に数を添えた項に「名前の中では語の切れ目で折り、1語が幅に収まらないときだけその語の中で折る」を入れる。SKILL.md の確かめる項も同じ言い方にそろえる。コードのコメントは、書き直した §4 と同じ言い方にする。

### Minor-2: ブログのタグの「オンラインツール」「ワークフロー連載」が、語の切れ目で折れば収まるのに語の中で折れる

**どこで何が起きているか**: 200% の 320px で、ブログのアコーディオンのタグが「オンラインツー／ル（12）」「ワークフロー連／載（4）」と折れる。`LinkIndex` は索引の語を1語として扱い、幅に収まらなければ `overflow-wrap: anywhere` で字の境目のどこでも折るためである。

- 「オンライン」（170px）と「ツール（12）」（約 208px）、「ワークフロー」（204px）と「連載（4）」（約 155px）は、どれもリンクの字の幅 250px に収まる。語の切れ目で折れば、§4 の例外に当たらない。
- 「アクセシビリテ／ィ（4）」は、小書きの「ィ」が行頭に来る。和文の組版では行頭に置かない字で、`overflow-wrap: anywhere` が禁則を見ずに折るためである。「リファクタリン／グ（5）」とあわせ、この2語は1語が幅に収まらないので語の中で折ること自体は §4 の例外に当たる。

**来訪者にどう効くか**: 文字を大きくして狭い画面で読む来訪者が、タグの索引で「ツー」「ル」、「連」「載」を別々の字として読むことになり、§4 が「部／首」について書いた害（分かれた字が別々の語に読め、名前がすぐに伝わらない）がそのまま出る。「オンラインツール」は12記事、ワークフロー連載は連載を順に読みたい人の入口である。

**直し方**: ラベルの語の切れ目を各一覧の組み立てが渡すのと同じ形で、2語以上からなるタグ（オンラインツール・ワークフロー連載・AIエージェント・AIワークフローなど）の語の切れ目をブログの組み立てが持ち、`LinkIndex` が `<wbr>` にする。タグの一覧は `TAG_DESCRIPTIONS` として決まった集まりなので、切れ目を持たせる手間は小さい。1語が幅に収まらないときの折り方は、小書きの仮名を行頭に置かない形（`line-break` の指定や、`overflow-wrap: break-word` で足りるか）を実測して選ぶ。直したあと、200% の 320px でタグの29語の折れ方を測り直す。

### Minor-3: `/dictionary` の四字熟語辞典の行が、ページに無い「使い方」を言う

**どこで何が起きているか**: `/dictionary` の四字熟語辞典の行の説明は「よく使う四字熟語を、意味と使い方、カテゴリや難易度から探せます。」（a123792 で書かれ、このコミットでは変わっていない）。四字熟語のページにあるのは、読み・意味・カテゴリ・難易度・構成漢字・成立と出典・「AIが見た人間のひとコマ」で、使い方を説明する所は無い。名前の欄が探すのも「語・読み・意味・例文」で、「使い方」ではない。さらに seo.ts と seo.test.ts は、「実用の例文を期待して開いた人が、期待と違うと感じてすぐ離れないよう」に、実用の辞典を思わせる語を説明に入れないと決めている。「意味と使い方…から探せます」は文としても、何を何から探すのかが読み取りにくい。

このコミットは、同じページの導入の文と伝統色・ユーモア辞典の説明を「各辞典と一覧にあるもの」に合わせたが、同じ一覧の四字熟語の行を見直していない。

**来訪者にどう効くか**: 四字熟語の使い方（どんな場面でどう使うか）を知りたい来訪者が、行の説明を読んで四字熟語辞典を開き、使い方の説明を探して見つけられない。サイトが自分で避けると決めた「期待と違う」形が、辞典の入口に残る。

**直し方**: 四字熟語のページと一覧にあるものだけを言う文にする（例「四字熟語を、読みと意味で引き、カテゴリや難易度から探せます。」）。375×667 で最初の行が画面に入ることは変わらない見込みだが、測って確かめる。
