# cycle-316 の決定と申し送り: T6〜T12 への申し送り

T6〜T12 が受け持つことへの申し送りを、記録した順に並べる。索引は [decisions.md](./decisions.md)。

- T9 で、クリップボードの API に拒まれる端末の代わりの写し方（`src/lib/clipboard.ts`）が、iOS の Safari とアプリの中のブラウザで写せるかを実機で確かめる（結果の共有・道具・札・招待のコピー）。
- T6 で OGP の画像を組み直すときは、明朝の書体で「——」の2字のあいだに隙間が出て2本の短い線に見える（animal-personality・japanese-culture のタイトル。review-t4-4b.md の Minor-2）ことを直す。
- T9 で、札の画像の「画像を保存」が iOS の Safari で共有シートに進むか「ファイル」への保存に進むかを実機で確かめ、GA の数の読み方（`surface: fuda` の share）に反映する。
- T6-9 のレビューから T6-6 へ（review-t6-9-4.md）: `FudaActions` の保存と共有のボタンも、押すあいだだけ ref で守る形なので、人のダブルクリック（2打目が 100〜300ms 後）で2回保存され `save` が2回送られうる。T6-6 で札の保存を組み直すときに、`dblclick`・`clickCount: 3`・Enter の2打で測り、1回にする。
- T7 への申し送り（トップ）: h1 が上端のサイト名「yolos.net」を大きく繰り返している。目玉の「24タイプ」が1行に単独で置かれ、何の数か分かりにくい。
- T7 への申し送り（結果のページ）: japanese-culture の `?with=` のページでは「このタイプについて」の中身が相性だけになる。見出しの文言がその中身に合うかを T7 で見る。解き終えた画面でも、japanese-culture の `?ref=` の無いときは「このタイプについて」に招待だけが入る。traditional-color の朱色の結果のおすすめ「朱色の詳しい解説を見る」は、色の辞典に朱色の項目が無く（真朱・銀朱などはある）行き先が一覧 `/dictionary/colors` なので、文言が行き先と合わない。行き先に合う文言にする（置き場所は行き先で決まるので「次はこれを試してみよう」に出る）。
- review-t6-2-4.md が見つけた、負荷で落ちる yoji-kimeru の試験（ヒントの帯の高さの記録）は、試験が表示を待ってすぐ記録を読み、passive な effect の書き込みより先に読むことがあったのが原因。試験を記録そのものを待つ形にした（0cfb3a8a。review-flaky-yoji-1.md で承認）。コンポーネントは変えない。書き込みは描いた数ミリ秒後に必ず行われ、次に開いたときに読まれるだけだから。
- プレイ面の共有の画像（まだ古い `src/lib/ogp-image.tsx` で描く `src/app/play/[slug]/opengraph-image.tsx`）は、題を1つの字の並びとして渡すので「…科学者／型？」と字の所で折れる。新しい描き方（`share-image.tsx`）では「科学者型？」が1つの単位で、この折れは出ない（review-t6-2-3.md）。プレイ面を T6-3 で新しい描き方に移すと無くなる。
