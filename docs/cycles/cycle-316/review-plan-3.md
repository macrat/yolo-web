### major-1: B-620 を取り消した理由が事実と違い、前回の失敗を分析していない。完了の条件が同じ後退を許す（AP-P12・AP-P06・AP-WF12）

**どこ:**

- `options.md:105`: 「cycle-301 は同じ修正を実装して出荷したが、当初計画外の作業だったため src ごと取り消した」
- `backlog.md` の B-620（「当初計画外の作業だったため」）と B-614（「600ms無言棄却の唯一の緩和策」）
- `index.md:20`（T5a）と `index.md:113`（B-620 の完了の条件）

**なぜ問題か:**

- **取り消しの理由は「計画外」ではない。** `cycle-301/index.md:157-174` によれば、理由は「直したバグより増やしたバグのほうが多く、発生確率も実害も大きかった」ことで、来訪者にとって正味でマイナスだった。増えたのは次の2つである。
  - **600ms の無言棄却**: 画面が切り替わってから 600ms 未満の回答を、すべての設問のあいだで黙って捨てた。速く答える人には日常的に起きる。
  - **retry の2打目**: 2打目が X の投稿画面へ飛ぶようになった。
- しかも、出荷したコードは元の欠陥を塞ぎきれていなかった。
- **計画は、この修正を「同じ修正」としてやり直そうとしている。**
  - 完了の条件は「設問が飛ばず、回答が重複しない。次の設問の同じ位置の選択肢が意図せず押されない」だけである。
  - これは、600ms の無言棄却をもう一度入れても満たせる。
  - 後段の「同じ位置の選択肢」への対処は、cycle-301 自身が「正当な速い回答を妨げる副作用がある」と警告している（:109）。
- **B-614 の Notes は、存在しないコードを前提にしている。** 「600ms無言棄却」を緩和する、とあるが、その 600ms の仕組みは取り消し済みで、いまのコードには無い。
- review-response.md の 2巡目 major-1 の行は「指摘どおりだった」とだけある。2巡目のレビューが (c) で求めた「回帰の教訓」は反映されていない。

**どう直すか:**

- options の B-620 の行と backlog の B-620・B-614 の Notes を、cycle-301 の「サイクルの結末」の事実に合わせて書き直す。
- 「前回はなぜ正味でマイナスになったか」と「今回は何が違うか」を options に書く。たとえば、B-614 の即時の選択表示を先に入れて再タップの動機を消す。時間の窓で回答を黙って捨てない。
- index の B-620 の完了の条件に、次の2点を加える。
  - **正当な速い連続回答が黙って捨てられない**（受け付けないなら、そのことが見える）。
  - **結果画面の「もう一度」などの画面切替のあと、2打目が別の操作（シェアなど）に落ちない**。
- retry で画面外に取り残される件（cycle-301 で直して、取り消しで戻ったもの）を、含めるか外すか振り分ける。

### major-2: 表示の速さの合格の線では、完了を判定できない（AP-P01）

**どこ:** `index.md:91`

**なぜ問題か:**

- **実地の指標を実験室に当てている。** 2.5秒は、実地の計測で75パーセンタイルに掛ける基準である（facts-external §8 の引用そのもの）。これを Lighthouse の模擬スロットリングの3回中央値に掛けている。
- **変更前の値を測っていない。**
  - 現行の `/play/character-personality` などが、すでに実験室で 2.5秒を超えていれば、フォントと無関係に不合格になる。
  - その場合、T1 への差し戻しや、`DESIGN.md` §3 の見直しという誤った経路に入る。
  - facts にも、LCP の現在の値は無い。
- **許容の幅が0である。** 「出荷前より遅くならない」を5ページ × 3回中央値で判定すると、測定のゆらぎだけで、どれか1ページが「遅い」側に出る確率が高い。
- **測る時期が矛盾している。** 「出荷前と出荷後」を比べるとあるが、T9 は出荷前の確認である（options:64「出荷前の機械の検査と目視（T8・T9）」）。出荷後に測って不合格なら、遅いサイトをすでに届けたことになる。

**どう直すか:**

- T0 で、現行の値を同じ条件で測って facts に記録する。
- 比べる対象を「同じ環境（たとえばプレビューのデプロイ同士）での変更前のビルドと変更後のビルド」とし、出荷前に判定する。
- 合格の線を次の2つにする。
  - 変更前からの悪化が、事前に決めた幅（例: 10% または 200ms）以内であること。回数は5回中央値などに増やす。
  - 実験室の LCP が 2.5秒以下であること。変更前がすでに超えている面は、変更前を超えないことを線にする。
- 実地の 2.5秒（CrUX の75パーセンタイル）は、出荷後の観測として別に置く。
