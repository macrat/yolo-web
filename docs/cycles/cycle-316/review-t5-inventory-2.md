## Major

### Major-1. 「記事の外の表を §4『表のセルは文節で折る』に合わせる」の事実が、まだ無い（1巡目 Major-3 の1）

T5 の行と補足事項（T4-17 の行）は、keigo-reference・色の辞典・ContrarianFortuneContent・結果のボックスの表を §4 に合わせる作業を T5 に置き、測り方（t4-design.md 10章、`border-collapse` の罫線の半分を引く）まで決めている。棚卸しには `ContrarianFortuneContent` も「文節」「セル」の語も1度も出ない。

HEAD で記事の外に `table` を持つ TSX は9ファイル（`ColorDetail`・`ContrarianFortuneContent`・`AgeCalculatorTile`・`CharCountTile`・`KeigoReferenceTile` と、ゲーム4本の結果）。どの表のどのセルが、列に入る文節の中で折れているか（320・375px の既定と 200%）が分からないと、設計は「どの表を組み直すか」「直ったと言える条件」を決められない（AP-P01）。

**直し方**: 上の表を 10章の数え方で測り、表ごとの「列に入る文節の中の折れ」の数を書く。ゲームの結果の表を測らないなら理由を書く（6章の「1局を解き終えないと出ない」は、ゲームの結果を T5 の対象から外す理由にはならない。localStorage に解いた状態を置けば出せる）。決めることに、折れるセルをどう直すか（列の幅・言い回し・`<wbr>`）の問いが要るなら足す。

### Major-2. unix-timestamp: 200% で数字が桁の途中で折れる（§8 違反が残る）のに、「補足事項の現象は起きない」とだけ書いている

4-3 の unix-timestamp の行は、行の高さとボタンの位置が変わらないこと、375px の既定で値が1行に収まることを書き、「補足事項の『233px 下へずれる』『先のボタンが1行に戻る』は `c2d9fb8` では起きない」とまとめている。ずれが無いことは確かめられた。ところが、補足事項が同時に挙げた「数字を桁の途中で折るので §8 にも反する」は、200% ではいまも起きている。値の `code` を1字ずつ Range で行に分けると:

- 320px・200%: ミリ秒「17040672000／00」、ISO 8601「2024-01-／01T00:00:00／.000Z」
- 375px・200%: ISO 8601「2024-01-／01T00:00:00.00／0Z」
- 320px の既定でも UTC の行は2行（「…00:00:00／GMT」、行の高さ 116。ほかは 90）

`DESIGN.md` §8 は「数字を折るのは桁区切りの位置だけ」と定める。いまの書き方では、設計者が「unix-timestamp の表の組み直しは要らない」と読みうる。結果の値の並びの組み方（§8 の「値の並び」は §5 の表で組む）を 31本へ広げる 4-3 の作業の中で、長い値が 200% で桁の途中で折れるのは unix-timestamp に限らないはずである（number-base-converter・hash-generator・password-generator など、長い数字や記号の列を値に持つ道具）。

**直し方**: unix-timestamp の行に 200% の折れ方を足し、「ずれは起きない。桁の途中の折れは 200% で残る」と書き分ける。長い値を出す道具について、200% の 320・375px で値が桁や語の途中で折れるかを測り、数を書く。決めることに「§8 の『桁区切りの位置だけで折る』を、区切りを持たない長い値（タイムスタンプ・ハッシュ・パスワード）でどう満たすか（段を下げる・横に送る・区切りの位置を作る）」を足す。
