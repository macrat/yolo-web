## 指摘

### Major-1 文字サイズ 200% の 320・375px で、記事の題名がボックスとコンテナの罫線を越えてはみ出し、画面の外の字が読めない

- **どこで**: `/blog`・`/blog/page/2` の行の一覧。320px で3件、375px で1件。
  - 320px:「50字で215秒フリーズした正規表現を、Worker.terminate()で100msに収める」「Mermaid ganttチャートのコロンの罠とmermaid.render()…」「コンテンツ信頼レベルの導入: 全ページにverified/curated/generated…」
  - 375px:「コンテンツ信頼レベルの導入…」
  - 同じ記事を載せる分類とタグのページでも起きる。
- **何が起きるか**: ルートを 32px にした 320px で、「50字で…」の名前のリンクは右端が 334 に達する。行の右端は 282、画面は 320。
  - 題名の2行目「ーズした正規表現」と4行目「Worker.terminate(」は、行のボックスの太い枠とコンテナの右のボーダーを越える。そこから先は画面の端で切れる。
  - ページは横に伸びない（`scrollWidth` は 320）。そのため来訪者は横に送って読むこともできない。
- **来訪者への効き方**: 文字を大きくして読む弱視の来訪者が、スマホで記事を選ぶとき、題名の一部が読めない。はみ出した字が罫線の上に重なり、§1 の罫線の格子も崩れる。§12「文字サイズ 200% で内容が欠けない」に反する。
  - 1巡目のレビューは `document.documentElement.scrollWidth` だけを見ていたので、これを見落としていた。
- **原因**: `ItemList.module.css` の `.head` は `display: flex; flex-wrap: wrap` で、名前のリンクはその flex の項目になる。flex の項目の既定の `min-width: auto` は、最小の幅を最も長い折れない語（`Worker.terminate()`・`verified/curated/generated`）の幅にする。本文から継ぐ `overflow-wrap: break-word` はこの最小の幅を縮めないので、項目が行の幅を越える。
- **直し方**: 名前（と読み）の項目に `min-width: 0` を付けるか、`overflow-wrap: anywhere` にする。どちらでも、長い語が行の幅で折れる。
  - `ItemList` は T3-1 の共有の部品なので、ツール・遊び・辞典の一覧にも効く。
  - 直したあと、ブログの全記事の題名で、文字サイズ 200% の 320・375px で行の外へ出る字が無いことを機械で確かめる。今回の確かめ方は、各行の中の要素の右端を、行の右端と比べるもの。

### Minor-1 見出しを語の切れ目で折る手当てが Chromium でしか効かず、タグのページの見出しは 320px で語の途中で折れる

- **`/blog` の見出し**: 6c4e3d9 は、見出しの切れ目に `<wbr>` を入れた。`<wbr>` は折れる位置を足すだけで、ほかの位置で折れることは止めない。Chromium で「AI試行錯誤／ブログ」と折れるのは、`globals.css` の `word-break: auto-phrase` が「ブログ」の中で折ることを止めているからである。
  - `auto-phrase` は Chromium だけで効く。
  - Chromium で見出しに `word-break: normal` を当てると（Safari・Firefox と同じ条件）、320px で「AI試行錯誤ブロ／グ」に戻る。文字サイズ 200% の 768px でも同じになる。
  - 日本のスマホの来訪者の多くは iPhone で、iPhone のブラウザはどれも WebKit で組む。1巡目の Minor-4 は、来訪者の多くにとってはまだ直っていない。
- **タグのページの見出し**: 1語ずつの見出し（`blogListHeadingPhrases` が `/blog` のときだけ切れ目を持つ）は、320px で次のように折れる。
  - 「オンラインツー／ル」: 「オンライン」と「ツール」の切れ目があるので、§4 の「一語が収まらないとき」の例外に当たらない。
  - 「アクセシビリテ／ィ」「リファクタリン／グ」: 一語なので語の中で折ってよいが、小書きの「ィ」が行頭に来る。
  - 文字サイズ 200% の 320px の分類のページでは、「AIワー／クフロ／ー」と長音符が行頭に来る。
- **直し方**:
  - `/blog` の見出しは、`word-break: keep-all` にして `<wbr>` の位置でだけ折れるようにする。Chromium で当てて確かめると、320px で「AI試行錯誤／ブログ」になる。200% では、収まらない語だけが本文から継ぐ `overflow-wrap: break-word` で折れる（320px「AI試行／錯誤／ブログ」、375px「AI試行錯／誤ブログ」、768px「AI試行錯誤／ブログ」）。ページは横に伸びない。`keep-all` は Safari と Firefox も持つ。
  - タグと分類の名前は、次のどちらかにする。
    - 切れ目のデータ（「オンライン」「ツール」）を持たせて同じ形で組む。
    - 語の中で折れることを受け入れる判断を 3-1 に書き残す。
  - 行頭の小書きと長音符は、見出しに `line-break: strict` を当てれば避けられる。サイトの見出し全体に効くので、`DESIGN.md` §4 の禁則の書き方と合わせて PM が決める。

## PM の判断について

- **375×667 の条件を「最初の行の題名の1行目が画面に入る」にしたこと**: 妥当と考える。
  - 最初の画面で来訪者が知りたいのは「ここに記事が並んでいる」ことで、題名の1行目が見えればそれは伝わる。
  - 最初の行の高さは、そのときの最新記事の説明の長さで変わる（最長8行）。行の全体を条件にすると、記事を1本出すたびに合否が揺れる。
  - パンくずを足しても、見込みは 643 で、24px の余裕がある。ただし、この余裕は `/blog` の説明が 375px で3行に収まっていることに乗っている。説明を書き換えるときは測り直す必要がある。T3-10 の条件に測り直しが入っているので、それで足りる。
  - 分類とタグのページに同じ判断を広げるかは、Minor-2 で決めてほしい。
- **記事の一覧の見出しを、画面に見せず読み上げにだけ出したこと**: 妥当と考える。
  - 目で見る来訪者には、主見出しの直下に件数の行と一覧が続き、何の一覧かは主見出しで分かる。見える見出しを足すと、1280px で最初の行が画面の外へ出る。
  - 見出しで移る来訪者には、索引の「タグ」の節と一覧が分かれて聞こえる。この両方を満たす形として、見えない見出しは広く使われる手段である。
  - 見出しは件数の行と名前の欄の前にあるので、見出しで移った来訪者は件数から聞き始められる。
  - 閉じたアコーディオンの中の見出しは読み上げの木に出ないので、閉じているときの見出しは h1 と「記事の一覧」の2つだけになり、簡潔である。
