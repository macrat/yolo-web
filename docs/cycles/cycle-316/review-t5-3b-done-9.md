## 指摘

### 1. （小）「字の幅で大きさが決まる箱はその分だけ広がる」は、測ったことより強い

コードの説明（`hideJoiners` を使う受け手の説明の3段落目）と、`clipboard-and-copy.md` の 2 の3つ目の項は、「字の幅で大きさが決まる箱（inline-block など）はその分だけ広がる」と書く。これでは、縮めて組む箱がいつも 1/64px 広がると読める。

本番のビルドを Chromium の本体（`/opt/pw-browsers/chromium`、141.0.7390.37）で 1280×900 で開いた。語結合子を持つ要素の箱の幅を、写す前とコピーの出来事の中（受け手の後）で比べた。

- password-generator の「小文字 (a-z)」の `span`（flex の項目）: 89.813 → 89.828px。広がった。
- 同じページの「大文字 (A-Z)」の `span`（flex の項目。同じ組み方）: 92.938 → 92.938px。変わらない。
- `/dictionary/humor/wifi` の h1（親が flex の容器。幅 91.625px で、縮めて組まれている）: 91.625 → 91.625px。変わらない。

3つとも、字の x と幅は 0.0156px 動いた。しかし箱が広がったのは1つだけである。箱の幅は 1/64px の単位に丸められるので、字の動きが箱の幅の段を越えるかどうかは、字の並びによる。

また、知見の文書の根拠の段落は「箱の幅は、password-generator の「小文字 (a-z)」の span が…広がり、記事の h1 などブロックの箱は変わらなかった」と書く。これだと、変わらなかったのはブロックの箱だけだと読める。実際には、同じ組み方の「大文字 (A-Z)」の span も変わらなかった。

直すこと: 2か所を「広がることがある（1/64px まで）」と書く。根拠の段落に、同じ組み方の箱でも広がらないもの（「大文字 (A-Z)」の span）があったことを書き足す。そのとき、書き足した跡が残らないように書く。いま来訪者への害は無い。ただ、後の作業者は「いつも広がる」と読んで、測って確かめずに済ませるかもしれない。

### 2. （ごく小）`clipboard-and-copy.md` の 2 に、読み違えを招く語と、Chromium の外で成り立たない言い方がある

- **`MutationObserver` の項の「受け手の呼び出しが 2 回」**: この文書では、「受け手」は一貫してコピーの受け手（`WordJoinerCopyFilter`）を指す。例は「受け手を止めると」「受け手の後」である。この項で数えたのは `MutationObserver` のコールバックだが、読む人は、コピーの受け手が1回の写しで2回呼ばれると取る。「`MutationObserver` のコールバックの呼び出しが 2 回」と書く。値は下の測りのとおり正しい。
- **2 の冒頭の項の「`Selection.toString()` は `user-select` を見ない」**: これは Chromium の振る舞いである。WebKit は、bug 80159 を直した変更（[PR 7467](https://github.com/WebKit/WebKit/pull/7467)、257749@main）で、`DOMSelection::toString` も `user-select: none` の字を飛ばすようにした。文書は同じ 2 の中で Chromium の外を測っていないと断っているので、この句も「Chromium の `Selection.toString()` は」と、範囲を付けて書く。
