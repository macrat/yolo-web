## 指摘

### Minor-1: 横に送る表で行を開くと、開いた行の文が表の全幅に広がり、見える幅で切れる（§4・§5）

敬語の表を 320px の既定で開き（表は 520px で、枠の中で横に送る）、最初の行を開いた。開いた行のセルは表の全幅（`colSpan`）なので、段落の幅は 520px になる。枠の見える幅は 260px で、例文の「移動先を伝えるとき: 社長が東京に…」はどの行も右が切れる（`r2shots/keigo-detail-320` で見た）。読むには、1行ごとに右へ送ってから左へ戻ることになる。

- 開いた行の中身は、区切りの並びでない、読ませる文章である。横に送って読むのは、表の列（1つの値が縦に並ぶ）には合うが、段落には合わない。§4 が本文に求める、見える幅の中で折れる形にならない。
- いまの使う側では起きない。敬語早見表は、狭い画面では表を使わず（45rem 以上で表を出す）、1巡目の測りでは 1280px・200% でも送らない。ただ、部品は「開いた行の例文など」をどの表にも持たせる約束で（`DataTableRow` の `detail`）、表が送るかは画面の幅と字の大きさで決まる。使う側がそれを避ける手段を持たない。1巡目の Minor-4（開いた行に `keep-all` が掛かる）と同じ、部品の約束の穴である。

直し方（builder）: 開いた行の中身を、枠の見える幅に収める。たとえば、部品が中身を1つの箱で包み、その箱を `position: sticky; inset-inline-start: 0` にして、幅を枠の見える幅（組むときに枠に持たせる値か、コンテナの単位）に限る。表を横に送っても中身は左端に留まり、見える幅で折れる。送らない表では、いまの形と変わらないようにする。直したら、送る表（敬語の 320px・既定など）で行を開いて、段落の幅が枠の `clientWidth` 以下で、右が切れないことを撮って確かめる。送らない表（375px・1280px）で、開いた行が前と同じであることも確かめる。部品の試験に「送る表の開いた行は、枠の見える幅を超えない」を足す。

### 記録（指摘ではない）

- 幅0の枠（閉じた `details` の中など）は、枠の直後のスクリプトも水和も組まず、見えたときに ResizeObserver が組む。水和の前に来訪者が開くと、組む前の表が最長3秒隠れ、そのあと組まずに見える。いまの計画で、閉じた区画の中に `DataTable` を置く面は無いので記録にとどめる。置く面が出たら、その面のレビューで確かめる。
