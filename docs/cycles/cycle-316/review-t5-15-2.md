## 指摘事項

### 1. 一覧が中で送れる長さのとき、キーボードで項目を進むと、フォーカスした項目が見えなくなり、ページが数百 px 動く（重い）

`CollapsibleTOC.module.css` の `.toc, .toc * { scroll-margin-top: calc(var(--rule-w) + var(--box-padding) - var(--toc-height) - var(--space-16)); }` は、開いた一覧の中の項目にも掛かる。一覧は中で縦に送る箱なので、項目にフォーカスが移ると、一覧の箱とページの両方がこの負の余白で「見せる」位置を計算する。項目の高さ（44〜134px）より打ち消しの量（375 で約 80px）が大きいので、見せる範囲が項目の外（下）にずれ、次の2つが起きる。

| 画面・記事（留まったあと、y=4000 から開く）                   | Tab で最後の項目へ進んだとき       | そのあと Shift+Tab で上へ戻るとき                                                                                                                           |
| ------------------------------------------------------------- | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 375×667・character-counting-guide（21項目）                   | ページが 4000 → 4309（309px 下へ） | 一覧が送られず、フォーカスした項目が一覧の上端（66）より上へ出て見えない（17〜61 など）。最後の数項目でページが 4309 → 4001 へ戻る                          |
| 1280×800・同じ記事                                            | ページが 4000 → 4368（368px 下へ） | 同じ。「場面別ガイド: あなたのシーンに合った数え方」にフォーカスがあるのに一覧の外にあり、画面のどこにも見えない（`rv515b-shots/kb-hidden-1280.png`）       |
| 375×667 の 200%・javascript-date-pitfalls-and-fixes（11項目） | 動かない                           | 項目が一覧の上端に 19px 隠れ、次の項目でページが 297px 上へ戻り、読み始めの画面の位置では目次が上端から外れて一覧が再び画面の下へはみ出す（lt 381・lb 963） |

どの場合も、Escape や Tab で抜けて閉じたとき、ページは開く前の位置から 300〜370px ずれていて、来訪者は読んでいた所を失う。キーボードの来訪者には、見えない項目にフォーカスがある状態は目次が壊れているのと同じで、DESIGN.md §5 の「フォーカスのある要素は、留まった目次の下に隠れない」にも反する（WCAG 2.4.7 のフォーカスが見えることにも当たる）。一覧が送れない長さ（javascript-date-pitfalls-and-fixes の 375・1280 の既定、667×375）では起きないので、builder の測りはこの形を踏んでいなかった（AP-I07。前回の指摘1と同じく、送れる長さの一覧を撮っていない）。

原因の確かめ: 一覧の中の要素だけ `scroll-margin-top: 0` にすると、項目は必ず一覧の中に見えるようになる（ただしページが 8〜150px 動く）。さらに、目次が開いているあいだだけルートの `scroll-padding-top` と目次の中の `scroll-margin-top` を 0 にする（`html:has(.toc details[open])`・`.toc:has(details[open])` など）と、上の3つの場合と読み始めの画面の場合（計6通り）で、Tab で最後まで進み Shift+Tab で開閉の行まで戻るあいだ、どの項目も一覧の中に見え、ページは 0px 動いた。最後の項目の次の Tab で本文の最初のリンクへ出たときも、そのリンクは目次の下に隠れなかった（開いているあいだの余白の切り替えは、フォーカスが出たあと閉じるので影響しない）。どう直すかは builder が比べて選ぶ。

完了の条件（t5-design.md の T5-15 の行）に「2記事の 375px・1280px・375px の 200% で、留まる前後で開き、Tab で最後の項目まで進んで Shift+Tab で開閉の行まで戻るあいだ、フォーカスした項目が一覧の中に見え、ページの位置が変わらない（一覧が中で送れる長さの記事を含む）」を足す（PM）。

### 2. 知見のファイルの記述が実測と合わない（中）

`docs/knowledge/browser-layout-and-scrolling.md` について。

- 「上の式にすると、…中の項目を Tab で進むとき、…3つの大きさでページが動く量は 0px だった」は、指摘1のとおり一覧が中で送れる長さでは成り立たない。直したあとの対処と実測に書き直す。このままでは、次に sticky の要素を作る人が同じ式を写し、同じ不具合を持ち込む。
- 根拠の「Chromium 1194」は Playwright のブラウザのビルド番号で、Chromium の版ではない。`Chromium 141.0.7390.37（Playwright の chromium-1194）` のように書く。
- 見出しの「Chromium は…ページを上へ送る」は、ルートの `scroll-padding` の中にある要素へのフォーカスを見える所へ送るという、仕様（CSSOM View の scroll into view と CSS Scroll Snap の scroll-padding）どおりの動きに見える。ほかのエンジンでは測っていないので、Chromium に固有と読める書き方は避け、「Chromium で測った」ことが分かる書き方にする（推論の部分は推論と書く）。

### 3. `CollapsibleTOC.module.css` の打ち消しの説明（軽い。指摘1の直しに合わせる）

「打ち消す量は…（Chromium で測って決めた）」とあるが、この量は「目次の中の要素の上端（線と内側の余白の分だけボックスの上端から下）が、ルートの上の余白の下端に来る」という幾何から出るもので、測って合わせた値ではない。指摘1の直しでこの宣言を書き直すときに、なぜその量なのかを幾何で書き、測って決めたという書き方は外す（測ったことは知見のファイルとサイクルの記録に置く）。

## そのほか確かめたこと（問題なし）

- 完了の条件のうち、読み込みで開閉と h2 の y が変わらない・3000px 送ったあと目次が上端に見える・章へ移った見出しが目次の下に隠れない・Shift+Tab で本文へ戻るリング・667×375 で留まらない・表・パンくずと h1 の 16・計測・`check:phrased-names` は、前回の測りから該当のコードが変わっておらず、今回の開く処理と Escape はそれらに触れない（留まったあとに開くときは送らない、閉じる押し下げでは送らないことを試験と実測で確かめた）。
- 留まった目次の開閉の行へ Shift+Tab で戻ったとき・Tab で開閉の行へ進んだとき、ページは動かない（留まったあと）。読み始めの画面から Tab で開閉の行へ進むと、開閉の行は画面の中に入る。Enter で開くとマウスと同じに上端へ送られ、フォーカスは開閉の行に残る。
- Escape で開閉の行へ戻すとき `focus({ preventScroll: true })` で、ページは動かない（一覧が送れない長さのとき。送れる長さでは指摘1のずれが先に起きている）。
- DESIGN.md §5 の開閉の操作の列挙に「Escape を押す」が入り、JSDoc と一致する。開いたときに目次を上端へ送ることは、§5 の「開いた一覧は画面の高さの中で送れ」を満たす手段なので、DESIGN.md に書き足さなくてよい。
- 知見のファイルを docs/README.md の一覧に足さないのは、README の「一覧はここに書き写さない」の決まりどおり。
- ダークの目次・開いた一覧の地、`--text-small` への置き換え、ページのセクションの組み方は前回と同じで問題ない。
