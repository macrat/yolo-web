## 指摘事項

### 1. 最初の画面で目次を開くと、一覧の大半が画面の下にはみ出し、送っても見えない（重い）

目次が上端に留まる前の位置（記事を開いた最初の画面）で開くと、一覧は目次の下から `100dvh - --toc-height` の高さで出るので、画面の下の端を越える。一覧は中で縦に送れる箱なので、見えている帯の上でホイールやスワイプをすると、ページではなく一覧の中身だけが動き、画面の外にある箱の下半分は見えないまま残る。

| 画面・記事                | 開いた直後に一覧が見える高さ | 一覧の箱の下端（画面の高さ） | 一覧の上で 300px 送ったとき                   |
| ------------------------- | ---------------------------- | ---------------------------- | --------------------------------------------- |
| 375×667・counting-guide   | 58px（「はじめに」の1項目）  | 1210（667）                  | 一覧の中が 300 動き、ページは 0 のまま        |
| 375×667 の 200%・同じ記事 | 10px（何も読めない）         | 1239（667）                  | ページが送られる（一覧の上端が 657 にあった） |
| 1280×800・counting-guide  | 174px（4項目）               | 1344（800）                  | 一覧の中が 241 動き（端まで）、ページは 0     |
| 667×375（留めない画面）   | 画面の下の端まで数項目       | 画面の外                     | 同じ形                                        |

撮影: scratchpad の `rv515a-shots/top-open-375-16-chara.png`・`top-open-1280-16-chara.png`・`chara-667x375-16-open.png`。

8-b の E は「開くと中の一覧は画面の高さの中で送れ」と決めていて、この状態はそれに反する。来訪者が目次を最も開きやすいのは、読み始める前の最初の画面である。そこで押して1項目しか出ない（200% では何も出ないように見える）と、目次が助けにならないどころか、壊れて見える。1280 でも、一覧の最後の項目（「まとめ」など）は、一覧の中を送り切ったあとも画面の外にあり、ページを送って目次が上端に留まるまで押せない。builder の撮影は留まったあとの開いた形（`*-scrolled-open.png`）だけで、この形を撮っていなかった（AP-I01）。

直し方は builder が比べて選ぶ。たとえば (a) 開いたとき、目次が上端に留まっていなければ、目次のボックスが画面の上端に来るまでページを送る（留めない高さ 500px 未満の画面でも同じにすれば、一覧が画面の中に収まる）、(b) 一覧の高さを、目次の下端から画面の下端までの実際の高さにする（ただし 375 の最初の画面では 58px しか残らず、それだけでは足りない）。(a) なら送るのは来訪者が押した結果で、開閉の決まり（DESIGN.md §5）とも食い違わない。どれにしても、完了の条件に「留まる前の位置で開いた一覧の全体が画面の中にあり、最後の項目まで送って押せる」を足し、2記事の 375・1280・375 の 200%・667×375 で測って撮る。

### 2. 開いた一覧を Escape で閉じられない（軽い）

開いた一覧は本文の上に重なる表示なのに、Escape を押しても何も起きない（3つの大きさで確かめた）。キーボードの来訪者が一覧を閉じるには、Shift+Tab で開閉の行まで戻って Enter を押すか、項目をすべて Tab で抜ける必要がある。WAI-ARIA APG のナビゲーションの開閉の例（Disclosure Navigation Menu）も、開いているとき Escape で閉じて開閉のボタンへフォーカスを戻す。Escape で閉じて開閉の行（`summary`）にフォーカスを戻し、試験を足す。足すなら DESIGN.md §5 の開閉を変える操作の列挙にも入れる（PM）。

### 3. `CollapsibleTOC.tsx` の説明が DESIGN.md の新しい書き方と食い違い、自分の中でも食い違う（軽い）

JSDoc に「初めの状態はどの幅でも閉じていて、開閉は来訪者が押したときだけ変わる」とあり、同じ段落の後ろで「フォーカスが目次の外の要素へ移ったときも閉じ」と書いている。DESIGN.md §5 を 7a2defe8 で「来訪者の操作（開閉を押す・項目を選ぶ・フォーカスを目次の外へ移す）でだけ変わり、画面の幅や読み込みでは変わらない」に直したので、コメントも同じ言い方にそろえる。

### 4. t5-design.md の T5-15 の行に、T5-16 へ移した条件が残っている（軽い。PM）

7a2defe8 で T5-16 の行に「`##` の全幅の罫線が、留めた目次の左右を通って見える所を 375px と 1280px で撮る（T5-15 の完了の条件のうち、本文の罫線ができてから確かめるもの）」を足したが、T5-15 の行の完了の条件には「本文を送り、`##` の全幅の罫線が留めた目次の左右を通る所を 1280px と 375px で撮って見る」がそのまま残っている。T5-15 の完了を判断する人には、この条件が T5-15 で要るのか要らないのか読めない。T5-16 の行には、もともと「`##` の上の全幅の罫線が、留まった目次の下を通って画面の端まで届く（1280px・320px で撮る）」もあり、同じ確かめが2つ並ぶ。T5-15 の行から外し（移した先を書くならその一言だけにし）、T5-16 の行の2つを1つにまとめる。
