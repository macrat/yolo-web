## 指摘

### 1. 着地の選び方の比べる順が、「入っていれば送らない」と食い違う

4-9 の手順5 は、次の順で比べる。

1. d1 ≠ 0
2. d2 ≠ 0
3. **d1 が大きい（100 まで）**
4. **d2 が大きい（100 まで）**
5. s0 に近い

3・4 が 5 より先にある。そのため、基準の送りが「送らない」（s0 = いまの位置）のときも、押した点から 100 以内に押せるものがあれば、ページを送る。押した点の上には何も無くても送る。この結果、次の3か所と食い違う。

- 4-6「入っていれば送らない」。
- 4-9 の箇条「知識クイズの答えのあとは…答えたあとの形が画面に入っていれば送らないので、押した点は押した行（押せない字）の上に残る」。実際には、「次へ」が点から 100 以内にあれば送る。
- 5章 §8 の親の箇条「収まっていれば送らない」。D4 の箇条は「上の送りを基準にし…ずらす」と書くだけで、基準が「送らない」のときにも送ることを言っていない。

来訪者から見るとこうなる。知識クイズで答えた直後、答えたあとの形が画面に入っていても、指の下の押した行が数十 px 動くことがある。「次へ」のあとも、次の問の帯と見出しの位置が問ごとに変わりうる。4-9 は、診断でずらさない理由を「問ごとに選択肢の位置が動き…毎回探し直す」としている。同じ理由は「次へ」のあとにも当てはまる。一方で「次へ」のあとは「来訪者は動きとして受け取らない」とずらしている。この2つの説明が、互いに合っていない。

一方で、このレビューの測りでは、結果への切り替わりで距離を広げる手順に効き目があった。375×550 の知識クイズは、上端 8px のとき押せるものまで 13〜58 しかない。1280×800 の kotowaza は、上端 8px で「X でシェア」に落ちる。

次のどちらかに決め、4-6・4-9・5章 §8・6章 条件7 をそろえること。

- (a) 基準が「送らない」操作（知識クイズの答えたあとと「次へ」のあとで、まとまりが画面に入っているとき）では、手順5 の 1・2（押した点そのもの）だけでずらし、3・4（距離）は使わない。
- (b) 距離でもずらすなら、4-6 と §8 の「送らない」にその例外を書き、診断との違いを来訪者の側から説明する。

どちらの場合も、T5a-7 で、着地が s0 と違った回数と量を操作ごとに記録すること。

あわせて、測りで第1の組を避けられない件が出たとき（合否の 0 を満たさないとき）に誰が何を選ぶかを、8章に書くこと。今の文書は合否だけを書き、満たさなかったときの道を書いていない。

### 2. `DESIGN.md` に書く文が、既存の `DESIGN.md` と合わない所

- **(a) 「ボタンと同じ…行間 `1.4`」**: §6 に足す箇条は、面の字を「ボタンと同じ本文の大きさと行間 `1.4`」で組むとする。しかし、ボタンの行間 1.4 は `DESIGN.md` のどこにも無い。
  - §4 が決めている行間は、本文の 1.85 と見出しの 1.25 以下だけである。
  - 1.4 は `Button.module.css` の値でしかない。

  このまま書くと、選択肢だけが §4 に無い行間を持つ理由のない例外に見える。そうでなければ、`DESIGN.md` が決めていないボタンの行間を、選択肢の箇条が決めることになる。コントロールの面の字の行間を §4 の組版の1行として書き（理由とともに）、§6 の選択肢の箇条はそれを指す形にすること。

- **(b) §6 の表の「答えた選択肢」の行**: 「押したものは…「あなたの回答」と字で添える。知識クイズでは正誤も字で添える」は、字を2つ添えると読める。4-2 と §8 に足す箇条は、「1つの行には字を1つだけ」（「あなたの回答は正解」）と決めている。表の行を、「来訪者の回答であることを字で添える（知識クイズでは正誤と合わせた1つの文、§8）」のように、1つの字と読める形にすること。

  あわせて、診断の「あなたの回答」の大きさと色（補助情報の大きさ・`--ink`）も書くこと。今は §8 の知識クイズの箇条にしか無く、§7 の「来訪者の項目」（`--ink-2`）と取り違えうる。

- **(c) §5 ページの割り方の「太い線で囲んだもの（ボックスの太い枠・進み具合の帯）」**: 「ボックスの太い枠」は、太い線で囲まれたものではなく、その線である。「太い線で囲んだもの（ボックス・進み具合の帯）」とすること。

### 3. 問の見出しへのフォーカスが、診断にしか書かれていない

4-7 と §6 に足す箇条（「診断で次の問へ移ったら、フォーカスは問の見出しへ移る」）は、診断だけを書いている。フォーカスが問の見出しに移る場面は、ほかにもある。

- 知識クイズで「次へ」を押したあと
- 「はじめる」のあと

どちらもいまのコードではそうなっている。しかし設計にも `DESIGN.md` にも書かれておらず、6章 条件5 も診断の見出しだけを確かめる。知識クイズで「次へ」のあとフォーカスをどこに置くかは、B-624 の「フォーカスが見える場所に残る」の続きである。次の問が出たとき（「はじめる」・診断の答え・「次へ」のあと）はどれも問の見出しへ移すと書き、条件5 で知識クイズの「次へ」のあとも確かめること。

### 4. §5 の「押せないがフォーカスを受けるもの」の文

§6 の範囲の箇条は、押せないがフォーカスを受けるものを3つ挙げる。件数の行、問の見出し、押した行である。§5 の文は、件数の行と問の見出しの2つだけを挙げる。答えた行は縁が見えるので「縁が見えなければ」の条件に掛からず、文そのものは誤りではない。ただ、§5 だけを読むと、押せないがフォーカスを受けるものはこの2つに見える。§5 の文を「縁が見えないもの（件数の行・問の見出し）」と条件の側から挙げる形にし、§6 の列挙と対にすること。

### 5. `input-events-and-guards.md` の冒頭の文が、T5a のあとで事実と合わなくなる

5章は、§4 の「意図しないプレイ開始」の一文だけを書き直す。しかし、この文書の冒頭の段落は、T5a が入れるものと合わなくなる。冒頭の段落は次のように書いている。

- cycle-301 で試した修正（**状態更新の冪等化**・…・**retry 後の intro へのスクロールとフォーカス**）は、どれも現行のコードに無い。

- 現行のコードにあるのは、結果画面へ送ってフォーカスを移す処理だけである。

T5a は、冪等な reducer（4-3）、「もう一度挑戦する」のあとの送りとフォーカス（4-8）、着地の選び方（4-9）を入れる。書き換えないと、知識の文書がコードと食い違う（ツギハギ禁止）。T5a-1 か T5a-7 で冒頭の段落をいまのコードに合わせて書き直す文を、5章に足すこと。書き直す中身は3つある。何がどこにあるか（`quizProgress.ts`・`reveal.ts`）、B-620 に残るのは何か（150ms より後に次の問の選択肢に落ちる2打目）、着地の選び方で得た知見の置き場所。

### 6. B-620 への申し送りが、この文書の中にしか無い

### 7. 押し間違いを直す道を持たないことを、扱う範囲として書く

R2 では、見せている 150ms のあいだに押し直せない。問を戻る操作も無い。そのため、押し間違いに気づいた来訪者が答えを直すには、最後まで解いて「もう一度挑戦する」しかない。いまのコード（押すと即座に進む）でも同じなので、T5a が悪くするものではない。ただ、この設計は再入力の扱いを決める所である。4-12「このタスクで扱わないこと」に、「答えを選び直す手段（前の問へ戻る）は持たない」と理由を書くこと。理由は、PV の78%の面の流れを1問1タップに保つこと、などになる。要ると判断するなら backlog に起こすこと。
