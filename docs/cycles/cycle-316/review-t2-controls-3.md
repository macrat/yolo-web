## 指摘

### Major-1 一覧の行の区切りの罫線が、コンテンツ幅の外へ左右 8px ずつはみ出す

`[data-text-box="rows"]` は、一覧（`ul`）ごと `margin-inline: -8px` で左右に張り出し、各行の中で字を 8px 下げる。字の左端はそろった。しかし、行の区切り（`li` の下の細い罫線）と一覧の上の罫線は、いつも見えている線である。これらも一覧と一緒に、コンテンツ幅の外へ左右 8px ずつ出る。

- 道具のページの「関連ツール」「関連ブログ記事」では、区切りの罫線が、真上の見出しとセクションの罫線より左右に 8px 長い（`/tools/age-calculator` の 320px、`/tools/char-count` の 600px の dark、ほかの道具のページも同じ）。
- トップの 1280px では、一覧の罫線が上のヒーローのボックスより左右に 5〜8px はみ出す。

これは DESIGN.md の3か所と食い違う。

- §5「コンポーネントを置けるのはコンテンツ幅の中だけ。全幅の罫線はコンテンツ幅の外へ出る」。コンテンツ幅の外へ出てよいのは、全幅の罫線だけである。
- §5 の幅の表「一覧の行: コンテンツ幅いっぱい」。
- §7「行どうしはボックスのコンテンツ幅いっぱいの細い罫線で区切る」。

根は、§5 に足した規則が「一覧の行」を「字だけで見えるもの」に入れたことにある。一覧の行は区切りの罫線という、いつも見えている形を持つ。規則の冒頭の「左端に揃えるのは、見えている形の左端である」を当てれば、そろえるのは罫線の端になる。規則が自分の原則と食い違っている。そのうえで §6「一覧の行では左右に細いボーダーが現れて閉じ、上下は行の区切りがそのまま辺になる」を満たすには、hover の線と区切りの罫線が同じ幅でなければならない。どれを優先するかは、DESIGN.md で決めることである。

**直し方**: planner が DESIGN.md で、一覧の行を「見えている形を持つもの」として扱い直す。例えば次のようにする。

- 区切りの罫線と hover・リングの箱は、コンテンツ幅（ボックスの中ならボックスのコンテンツ幅）いっぱいにとどめる。
- 行の名前と説明の字は、箱の余白の分だけ内へ下げる。このずれは、罫線がそろっていることで一覧の形として読める。

§5 の規則・幅の表・§6・§7 が同じことを言うように書き直す。そのうえで builder が `rows` を直す。T3 の一覧の設計にも同じ規則が掛かる。

### Major-2 無効のボタンの破線の枠が、ほかの部品の左端より 8px 左へ出る。§5 の規則が自分の原則と食い違う

§5 の規則は、「線で囲んだもの（入力欄・色見本）は、その形の左端を揃える」と定める。一方で、プライマリでないボタンの「無効の枠」は字の側でそろえ、箱ごと 8px 左へ張り出すと定める。無効のプライマリでないボタンが見せているのは、太い破線で囲んだ形だけである（下線は消える）。規則の冒頭の原則「見えている形の左端」を当てると、そろえるのは破線の枠の左端になるはずである。

来訪者に見える結果は次のとおり。storybook の 375px では、無効のプライマリボタンの破線の枠と、無効のプライマリでないボタンの破線の枠が、縦に並んで 8px ずれる。どちらも §6 の「無効」で同じ見え方なので、ずれが揃え損ないに見える。入力欄の枠の左端とも 8px ずれる。前回の Major-2 の直し方で求めた「無効の破線の枠が、有効なときと同じ位置で、ほかの部品の左端と矛盾しない」は、満たされていない。

**直し方**: planner が、プライマリでないボタンの無効の見え方を §5 の原則と両立する形で決める。例えば次のようにする。

- 無効でも破線を箱の縁に出さない形にする（字の左端の位置は変えず、無効を別の形で示す）。
- または、プライマリでないボタンをどちらの状態でも枠の左端でそろえる。

どちらにするかと理由を、DESIGN.md（§5・§6）とサイクルの文書に書く。

### Minor-1 45rem 未満では、箱の縁がコンテナのボーダーに接し、リング・hover の線がボーダーと一体に見える

45rem 未満の `--box-padding` は 8px で、`--text-box-pad` と同じである。そのため、コンテンツ幅の左端にある字だけのコントロールは、箱の左の縁がコンテナの左のボーダーに接する。上端のサイト名・ナビ、下端のリンク、スキップのリンクがこれに当たる。

`/tools/age-calculator` の 320px の dark で「遊び」に Tab すると、リングの外の輪（3px）がコンテナのボーダー（3px）に接し、左側だけ 6px の1本の線に見える。二重リングは3辺だけに見え、コンテナの枠が太ったようにも見える。hover の細い線もボーダーに接する。§6 は、太い線で囲まれたものを線種・大きさ・位置で読み分けると定める。ボーダーと一体になると、その読み分けが崩れる。

320〜719px はモバイルの来訪者のほぼすべてが使う幅で、キーボードの利用者が最初に入る上端で起きる。

**直し方**: Major-1・2 で規則を決め直すときに、箱の縁とコンテナのボーダーのあいだに必ず間を残すか、狭い画面ではリングを別の形で出すかを決める。

### Minor-2 ボタンが字の途中で折れる。複数行のボタンの字が中央に寄る

`Button` から `white-space: nowrap` が外れた。代わりに、縮み方の決まりが入っていない。そのため、flex の行の中でボタンが字1文字の幅まで縮む。

- `/tools/business-email` の 320px では、プレビューの見出しの横の「コピー」が「コピ／ー」の2行に折れる。行には、見出しを縮める余地がある。
- `/tools/qr-code` の 320px の「PNG形式でダウンロード」は3行に折れ、最後の行が「ド」1字になる。`/tools/date-calculator` の「西暦→和暦 変換」も同じく折れる。これらは入れ子のボックスが狭いことが主な原因で、T5 で直す。
- `.button` の `text-align: center` が残っている。そのため、折れたときには、プライマリでないボタンの字も中央に寄る（§5「その中はすべて左端に揃える」）。

§5 は「コンテンツ幅に収まらない語は折り返す」と定めるが、収まる語を折ってよいとは言っていない。

**直し方**: ボタンが語の幅より縮まないようにする。例えば `flex-shrink: 0` と `max-width: 100%` を持たせ、コンテンツ幅に収まらないときだけ折り返す。字の揃えは左にする。

### Minor-3 ページ送りの「前へ」「次へ」の読み上げ名が、見える文言を含まない（WCAG 2.5.3）

見える文言は「‹ 前へ」「次へ ›」で、`aria-label` は「前のページ」「次のページ」である（`PaginationNav.tsx`）。音声で操作する来訪者が「前へ」と言っても押せない。前回の Minor-5 で共有のボタンは直ったが、同じ問題がページ送りに残っている。番号の「ページ3」は「3」を含むので問題ない。

**直し方**: 読み上げ名を見える文言で始める（例:「前へ（前のページ）」）。または `aria-label` を外して、見える文言をそのまま名前にする。

### Minor-4 本文の中のリンクで、hover の線が字に接して下線と重なり、リングが隣の字に掛かる

既定の hover（`:where(a[href]):hover` の内側の細い線）とフォーカスのリングは、本文の中のリンクにも掛かる。本文の中のリンクは字だけの箱を持たない。

- `/about` の 375px で「ブログ」に載せると、細い線が字に接して囲み、下の辺が下線のすぐ下に来て二重の下線に見える。
- Tab で入ると、外に出るリングが前の「、」と後ろの「に」に掛かる。§6「二重リングは、要素の外に余地があれば外、なければ内側に出る」とあるが、本文の中では外に余地が無い。

加えて、§5 の新しい規則は「字だけで見えるもの（リンク・…）」の hover・リングを「字の左右に 8px の余白を持つ箱」に出すと定める。本文の中のリンクはその箱を持たないので、規則と実装が合わない。

**直し方**: DESIGN.md の規則の「リンク」を、本文の外に置くリンクに限る（§6 のタップの標的と同じく、本文の中のリンクだけを別に書く）。そのうえで、本文の中のリンクの hover とリングの出し方を §6 に書き、隣の字に掛からない形にする。

### Minor-5 §5・§6 の書き方が、実装と細部で合わない

- §5 の規則は、箱が「コンテナの内側の余白に張り出す」と書く。実際には、ボックスの中のコントロール（`/tools/age-calculator` の「今日に設定」、共有のボタン）は、ボックスの内側の余白に張り出す。§5 のほかの行（「ボックスの中では、同じ割り当てがボックスのコンテンツ幅に対してかかる」）に合わせて、「コンテナかボックスの内側の余白」と書く。
- §6 は「二重リングは、要素の外に余地があれば外、なければ内側に出る」と書く。字だけで見えるものは、1280px のように外に余地があっても、箱の縁の内側に出る。§6 の箇条に、字だけで見えるものは箱の内側に出ることを書き、§5 の規則と同じことを言うようにする。

### Minor-6 index.md の補足事項と記録が、いまの状態と合わない

- 補足事項の「上端のナビは、45rem 未満で項目の間隔を 8px にし、…輪が隣の字やコンテナの左のボーダーに約 3px 重なる。…フォーカスのあいだだけの重なりを受け入れた。」は、T1 の組み方の説明である。いまは、上端のリンクも字だけの箱で組み、リングは箱の内側に出るので、隣の字には重ならない（コンテナのボーダーには接する。Minor-1）。いまの判断に書き直す。
- 「レビューの記録」の表に、T2 のレビュー（review-t2-inventory・review-t2-controls・-2・この回）の行が無い。

### Minor-7 スキップのリンクが現れたとき、上端のサイト名と最初のナビを隠し、残りの項目に接する

1280px の 404・410・道具のページで Tab を1回押すと、スキップのリンクが上端の左に重なる。サイト名・「遊び」・「ツール」が隠れ、リングの右の辺が「辞典」の字に接する。そのため「メインコンテンツへスキップ辞典　ブログ」と1つの並びのように読める。スキップのリンクを上に重ねる組み方は一般的だが、隠れる範囲と残りの項目との間を決めていない。

**直し方**: 上端の中で、スキップのリンクが上端の行全体を覆う形にする（地を上端の幅に広げる）。または上端の上に1行として出す。どちらでも、残りの項目と接しないようにする。

### Minor-8 共有のボタンの `setTimeout` が片付けられない（AP-I11）

`ShareButtons` の `handleCopy` は、`setTimeout(() => setCopied(false), 2000)` の ID を持たない。コピーの直後にページを離れると、外れた部品に `setState` が呼ばれる。続けて押したときには、先のタイマーが後の「コピーしました」を早く消す。この部品は今回 `Button` で組み直した範囲にある。

**直し方**: ID を `useRef` で持ち、押し直しと unmount のときに `clearTimeout` する。
