## 指摘

### Major-1: 率の分子の数え方がイベントの値で書かれておらず、いまの 45 には解き終えた画面の外の1件が入っている

T4-21 の完了の条件は「率の分子と分母の定義」を求めている。ADR は分子を「札の保存・札の共有・招待・文の共有」と言葉で書いただけで、どのイベントのどの値を数えるかを書いていない。ページの共有には数え方（`content_type`・`content_id`・`surface`）を書いたのに、率の側には無い。

これは言葉の問題にとどまらない。`surface="invite"` と `surface="text"` の `share` は、同じ `content_id="quiz-character-personality"` で**結果のページ**（`/play/character-personality/result/[resultId]`。`page.tsx:181` の `InviteFriendButton`、`ResultPageShell.tsx:123` の `ShareButtons`）からも送られる。実際、いまの 45 の中の招待 1 は `/play/character-personality/result/blazing-poet` から送られていて、解き終えた画面のものではない。分母の `level_end` は解き終えた画面でしか送られない。T4-5 が変えたのは解き終えた画面の並びなので、比べたいのは解き終えた画面の率のはずだ。出荷のあと、友だちの結果から来た来訪者が結果のページで招待や共有を押す数が増減すると、それが率に混ざり、T4-5 の損（保存のボタンが最初の画面から出た）の読みを誤らせる。

直し方: 分子を値で書く。例えば「`save`（`surface="fuda"`）と、`share` のうち `content_id="quiz-character-personality"` で `surface` が `fuda`・`invite`・`text` のもの。どれも `page_location` のパスが `/play/character-personality`（結果のページ `/result/…` を除く）」。そのうえで出荷の前の値を、その定義で数え直して書く（解き終えた画面に限ると 44 ÷ 1,181 = 3.7%、招待 0）。結果のページのものを入れると決めるなら、それを定義に書き、分母とずれることを書く。どちらにするかは PM が決めてよいが、いまの「言葉だけの定義で 45」は、次に読む PM が同じ数を再現できない。t4-design.md 2-2・T4-21 の行の数（45・3.8%）も同じ定義に合わせて直すこと。

### Major-2: 出荷の前の値の期間が、ADR 自身の基線の決め方（出荷の直前28日）とずれている

ADR の観測の最初の項目は「基線＝最初の出荷の直前28日」で、次回確認時にやることの2も「出荷の直前に」取ると書いている。書き足した値は 2026-08-29〜09-25 で、出荷（B-754）はまだ先である。出荷が10月に入れば、比べる2つの28日のあいだに数週間の空きができ、季節や検索の動きがその差に入る。

直し方: 次のどちらかを ADR に書く。(a) この値は仮の値で、T10 で Search Console の基線と同じ「出荷の直前28日」で取り直して置き換える（T10 の手順と index.md の T10 の行にも GA の率を足す）。(b) この期間をそのまま基線にすると決め、空きがあることと、その理由を書く。(a) のほうが、他の基線と同じ窓で読めるので来訪者の変化を読みやすい。

### Minor-1: この率を何のために見るのかが書かれていない

t4-design.md 2-2 では、この率は「T4-5 で保存のボタンを最初の画面から出した損」を見るために足したものである。ADR には値と比べ方だけがあり、来年この ADR を開く PM には、下がったときに何を疑えばよいか（T4-5 の並び）が分からない。1文で「T4-5 で結果の説明を先に置き、保存と共有のボタンが 375px の最初の画面から出たことの損を見る」と書く。

### Minor-2: 小さい n の読み方を、この2つの数に即して書く

ページの共有は 3回で、1回の違いで向きが変わる。率の分子も 45 程度である（AP-P26、ADR001 で `share` 2件が1件で反転しうると書いた実例）。親の項目に「小 n を常に疑う」とあるが、この2つの数にどこまで読みを許すかを書いていない。例えばページの共有は「0 になったかどうかだけを見る」、率は「方向だけを見る」と書く。

### Minor-3: 札の保存と札の共有の内訳が、T9 の結果で動きうる

index.md 263 行のとおり、iOS の Safari で「画像を保存」が共有シートへ進むなら、保存のつもりの操作が `share`（fuda）として数えられている可能性がある。分子の合計には影響しないが、ADR に内訳（34・9）を書いた以上、内訳の読み方は T9 の結果に従うことを1文添えるか、T9 のあとに経過記録へ書くことを次回確認時にやることに入れる。
