## 指摘

### Major-1 伝統色パレットで、見本を押しても色の名前とカラーコードが見える場所に出ない

- 起きていること（実測。3つ目の見本「似紫」を押したとき）: 見える変化は、押した見本の外の輪だけである。名前とカラーコードは、配色の結果の最初のカードにしか出ない。そのカードは 250 個の見本の格子と配色パターンの組の下にある。

  | 幅・文字サイズ | 押した見本の上端（ページの頭から） | 名前が出るカードの上端（ページの頭から） | 画面の高さ |
  | -------------- | ---------------------------------- | ---------------------------------------- | ---------- |
  | 1280px・既定   | 506                                | 1672                                     | 800        |
  | 375px・既定    | 476                                | 3745                                     | 667        |
  | 320px・既定    | 571                                | 4807                                     | 568        |
  | 375px・200%    | 1147                               | 20855                                    | 667        |

  吹き出しが無くなったので、見えている人が色の名前を知るには、押したあとに格子の下まで送るしかない。375px では約5画面、文字サイズ 200% では約30画面送る。押したあとにフォーカスもスクロールも動かない。

- 無彩色の見本を押すと、結果は無彩色の全件のカードになり、どれが押した色かの印が無い。名前は見えない読み上げの文にしか出ない。
- 文字サイズ 200% で格子が伸びるのは、列の幅の下限が `max(44px, 3rem)` だからである。見本は字を持たないので、字の大きさに合わせて大きくする理由が無い。375px・200% では2列（145px）になり、250個が 19,000px の格子になる。44px（px の値）だけを下限にすれば、200% でも 375px で5列のまま、§6 を満たす。
- 来訪者への影響: この道具の働きは「伝統色を選んで、その名前とコードと配色を得る」ことである。PC では、以前は吹き出しで名前が見えていたが、いまは押すたびに約 900px 下まで送って確かめ、また戻って次の色を押すことになる。スマホでは格子の下まで数画面ある。色を見比べながら名前を知りたい来訪者が、名前を知る前に離れやすい。§8「結果は、それを生んだ操作の直後に置く」にも合わない（見本を押す操作と、その結果の名前とコードのあいだに、残りの見本と配色パターンの組が挟まる）。
- 直し方: 押した色の名前とカラーコードが、押した場所から目を離さずに見える形にする。例:
  - 件数の行か格子の直前に「選んだ色」の行（色見本・名前・カラーコード）を置く、または格子を配色の結果より後ろに回して、色を選ぶ格子を畳める形にする、など。どの形も `DESIGN.md` に無い部品を足すなら先に書く。
  - 格子の列の下限を `44px` だけにする。
  - 無彩色の結果では、押した色のカードに「選んだ色」と字で添える。
  - 形は複数案を 375px と 1280px で撮り比べて決める。

### Minor-1 伝統色の見本の「選んだ」状態が `DESIGN.md` に無い形と、合わない役割で組まれている

- 選んだ見本は、外側に離した太い線の単色の輪で示している。§6 の「太い線で囲まれたもの」の読み分けの表にこの形は無く、表のとおりに読むと「どれでもない＝ボックス」になる。CSS のコメントは「（§6）」を根拠に挙げているが、§6 にこの規定は無い。
- 250 個の見本は1つだけを選ぶ組なのに、`button[aria-pressed]` で組んでいる。読み上げでは、どの見本も「切り替えボタン」と読まれ、1つを選ぶ組であることも、いくつ中の何番目かも伝わらない。
- 来訪者への影響: 見えている人には、輪がフォーカスや枠と読み違えられるおそれがある（キーボードで移ると、選んだ輪と二重リングの2つの太い枠が並ぶ）。読み上げの人には、選んだ色がどれかを探す手がかりが弱い。
- 直し方: 1つを選ぶ組として組む（`role="radiogroup"` と `role="radio"`／`aria-checked`、矢印キーで移る）かを決め、選んだ見本の見せ方を `DESIGN.md` §6 に書いてから実装する（SKILL.md「`DESIGN.md` に無いコンポーネントを足したくなったら、先に書く」）。Major-1 の直しと一緒に決めるとよい。

### Minor-2 伝統色の配色のカードで、1字の色名のリンクが 44px に届かない

- 「鉄」を選んだときのカードのリンク「鉄」は 30×44px（320・375・1280px、既定の文字サイズ）。`.paletteColorNameLink` は `min-height: 44px` だけを持ち、§5「字の箱が 44px に届かなければ、右へ広げる」の幅を持たない。1字の色名（鉄・藍・紅など）で起きる。
- 来訪者への影響: 狭い画面で色の辞典へ進むとき、指で押し損ねやすい。
- 直し方: `min-width: 44px` を持たせる（字の箱の規定どおり右へ広げる）。

### Minor-3 keigo の狭い画面の行で、敬語の形が表より小さい字で組まれている

- 狭い画面の行では、尊敬語・謙譲語・丁寧語の語（「いらっしゃる・おいでになる」）が `--text-small`（14px）で組まれている。同じ語は広い画面の表では本文の大きさ（17px）で、開いた行の例文（「社長が東京にいらっしゃる」）も本文の大きさである。そのため 375px で行を開くと、来訪者が引きに来た敬語の形が、その下の例文より小さく見える（撮影で確かめた）。
- 前回の Minor-4 で、yoji の意味を「説明は補助情報の大きさで組まない」として本文の大きさにしたのと、同じ判断が keigo の行に掛かっていない。ラベル（「尊敬語」）は補助情報の字でよいが、語は早見表の中身そのものである。
- 来訪者への影響: スマホで敬語を確かめに来た来訪者が、いちばん読みたい語を小さな字で読むことになる。
- 直し方: 語（`.mobileRowValue`）を本文の大きさにする。375×667 で最初の行の下端がいま 665 なので、上げると画面から出る。組み方（ラベルと語の並べ方、行の上下の余白、`表示する内容` の組の置き方）を合わせて見直し、375×667 で入ることを測る。入らないなら、どちらを採るかを PM が決めて index.md に書く。

### Minor-4 `ToolPageLayout` の CSS に、書き直した冒頭と食い違う古いコメントと値が残っている

- 冒頭のコメントを「トークンだけで組み」と書き直したが、同じファイルに `font-size: 1.5625rem; /* 25px（1.25 倍スケール帯） */`・`font-size: 1rem`・`line-height: 1.9`・`1.09375rem`・`@media (max-width: 768px)`（§5 の境は `45rem`）・`border-top: 1px solid var(--rule)`（§5 の細い線は `--rule-2`）が残り、冒頭の文と合わない。
- 「ゾーン1: 文脈確認」「SEO 用に保持しつつ視覚的にはコンパクトに」「ファーストビューを占有しないよう margin を絞る」「モバイル対応（375px 先行）」は、前の設計の言い方のままで、いまの `index.tsx` のコメント（「道具（タイル）を主役として…」）と用語がずれている。テストにも「N-2:」の番号が残る（`ToolPageLayout.test.tsx:233・235・253`）。
- 値の置き換え（h1 を §4 の段にするなど）は T5 の受け持ちだが、このコミットは同じファイルの冒頭と `.layout` だけを書き直しており、1つのファイルの中で新旧の言い方が混ざっている（CLAUDE.md「ツギハギ禁止」）。
- 直し方: 冒頭の文を事実に合わせる（値の置き換えを T5 に回すなら「トークンだけで組み」と書かない）。経緯の言い方（ゾーン・SEO 用に保持・375px 先行・N-2）を、いまの働きの記述に直す。

### Minor-5 3つの道具が、使わない `variant` の prop と型を持ち続けている

- `YojiSearchTile`・`KeigoReferenceTile`・`TraditionalColorPaletteTile` は `variant?: "full"` を受け取るが、どれも中で使わない。page.tsx は `variant="full"` を渡している。伝統色の型のコメントは「検索＋カテゴリ＋スウォッチグリッド＋ハーモニー＋色詳細カード＋コピー／このツールは参照・検索系のため full 1種のみ」と前の形の言い方のまま、keigo は「表示バリエーションの設定差。別実装ではない。」と、前回の Minor-6 で消した「将来の拡張に備えて」と同じ趣旨の型が残る。
- 来訪者への影響は無いが、読む人に「ほかの形がある」と思わせ、組み替えの妨げになる。
- 直し方: 3つの道具から `variant` の prop・型・コメントを消し、page.tsx の `variant="full"` も外す。伝統色のテスト名の「スウォッチ」も、コードの言い方（色見本）にそろえる。

### Minor-6 yoji の行のコメントが、広い画面の実際の組み方と合わない

- `YojiSearchTile.tsx` の説明と CSS のコメントは「閉じた行は四字熟語辞典の一覧の行（ItemList）と同じ値を同じ位置に見せる」と書く。実際は、広い画面の yoji の行は意味を1行目の読みの後ろに置き（`"name reading meaning meta"`）、`ItemList` は説明を2行目に置く。行の高さを1行に保つ判断は妥当だが、コメントがそれと逆のことを言っている。
- 直し方: 狭い画面は辞典の一覧と同じ並び、広い画面は行の高さを保つため意味を1行目に置く、と事実どおりに書く。
