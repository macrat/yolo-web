### 1-2. いまの組み方と、ずれの原因

`applyTableLayout` は各列のいちばん長い文節の幅（mins）を測り、`planColumns` で次の3つに分ける。

- 収まる: 幅を指定しない。表は `width: 100%` の自動の組みで、余りの幅はブラウザが列の中身の長さ（max-content）に応じて配る。
- 細くする: `table-layout: fixed` にし、全部の列に幅を指定する。
- 送る: 下限の幅のまま、枠の中で横に送る。

漢字カナールの2つの表は、どちらも「収まる」に当たる。

- 「読みと意味」は、値の列が長い（音読み・訓読み・意味・例を並べる）。そのため、余りのほとんどが値の列に行く。
- 「これまでの成績」は、値が「12日」のように短い。そのため、見出しの列が余りの半分ほどを取る。

こうして見出しの列の幅が表ごとに違ってくる。review-t5-20d.md の実測では 320 の既定で 66 と 131px、1280 の既定で 239 と 476px だった。見出しの列が中身と関係の無い幅になるのは、この2つの表に限らない。行の見出しを持つどの表でも、広い画面では見出しと値のあいだに空きが開く。

## 3. 採る案の中身

### 3-1. 行の見出しの列の幅（`src/lib/scroll-frame.ts`）

`applyTableLayout` に、行の見出しの列の扱いを足す。

- **行の見出しの列を持つ表**: `tbody` のいずれかの行の最初のセルが `th[scope="row"]` である表。記事の Markdown の表は当たらないので、組み方は変わらない。
- **収まる表（`planColumns` が送らず、どの列も細くしない）**: 次の手順で組む。
  1. 行の見出しの列の max-content の幅を測る。表の幅を `max-content` にして、最初の行の最初のセルの幅を取る。このとき開いた行（`[data-detail]` を持つ行）は隠して測る。表の幅いっぱいのセルの長い文が、列の max-content に混ざらないようにするためである。
  2. 測った幅を、最初の行の最初のセルの `style.width` にする。値は、左右の余白を除いた中身の幅である。
  3. 表は自動の組みのまま `width: 100%` に置く。ブラウザは、幅を指定した列より先に、指定の無い列（値の列）へ余りを配る。値の列がそれぞれの下限（いちばん長い文節の幅）に届かないときは、見出しの列がその分だけ細くなり、見出しを文節で折る。値の文節を割らないことが先になる（§4）。
- **細くする表と送る表**: いまのまま変えない。細くする表は全部の列に幅を指定しており、行の見出しの列も `planColumns` の幅になる。
- **コピーのボタンの列を持つ表**: 値のセルの最小の幅が「値＋あき＋ボタン」になるだけで、手順は同じである。ボタンを値の次の行に送る判断（`data-copy-below`）の前後も変えない。

実測（この planner。Chromium 1194。作業ツリーの外に置いた素の HTML の表で、書体は既定の sans-serif。サイトの書体ではないので、形の確かめに限る）:

- 自動の組みの表で、最初のセルに幅を指定した。すると余りの幅はすべて指定の無い列に行き、見出しの列は指定の幅のまま残った。884px で見出しの列が 73.8px、値の列が 810.3px になった。
- 値の列の下限が入らない幅（299px・字 32px）では、見出しの列が指定の 138px から 127.5px に細り、値の列は下限の 171.5px を保った。
- 列の見出しを持つ4列の表（irodori の形）では、問の列が 25px になり、残りの3列に余りが中身に応じて配られた。

### 3-2. 組（`DataTableGroup`）

`src/components/DataTable` に組の部品 `DataTableGroup` を置き、`index.tsx` から名前付きで書き出す。

- **DOM**: 部品は `<div data-table-group>` を描く。div には `display: contents` のクラスを付けて、親の flex や grid の並びとあき（漢字カナールの `.resultBody` の `gap`）に影を落とさない。組は入れ子にしない。
- **そろえる幅**: 組の中の表のうち、行の見出しの列を持ち、「収まる」に当たるものを、そろえる対象（そろえる表）とする。
  1. そろえる表をそれぞれ 3-1 で組み、実際に組まれた行の見出しの列の幅を読む。
  2. そのいちばん広い幅 G を、そろえる表の全部の見出しの列に指定する。
  3. 値の文節が入らない表では、3-1 のとおりブラウザがその表の見出しの列を細くする。
  4. 細くする表と送る表（自分の枠か結果のボックスの中で横に送る表）は、G を決めるのにも数えず、G も受けない。そうした表は自分の組みのままにする。送る表は太い線と内側の余白を持つ自分のボックスに入るので、字の左端がもともと罫線の分だけずれていて、そろえる意味が無い。
- **組むときの流れ**（どれも `createFrameLayout` の中に書き、文字列にしても動くように外の名前を使わない）:
  - `layoutGroup(group)` を足す。組の中の枠（`.table-phrased`）をすべて組み、そろえ、各枠に組んだ印（`data-layout-key`）を付ける。組には、組んだときの枠の数を覚えさせる。
  - `layoutTable(frame, contentChanged)` は、枠が `[data-table-group]` の中にあれば `layoutGroup` に任せる。組を組み直さずに済むのは、どの枠の印も今の幅・字の大きさ・Web フォントの状態と同じで、枠の数も同じで、中身が変わっていない（contentChanged でない）ときだけである。1つの枠の中身が変わったら、組の全部を組み直す。
- **サーバーで描いた組**:
  - `LAYOUT_PREVIOUS_TABLE` は、組の中の枠では何もしない。
  - `DataTableGroup` が div の前に `FRAME_LAYOUT_DEFINE` を置き、div の直後に `LAYOUT_PREVIOUS_GROUP` を置く。これは直前の組を `layoutGroup` で組む文で、失敗したら組の全部の枠に `data-layout-failed` を付けて見せ、失敗は投げる。
  - 組の枠は、組の最後の文が組むまで隠れたままになる（今の CSS の `data-layout-key` と3秒の決まりのまま）。先に届いた表を描いたあとで、あとの表に合わせて組み直して動かすことが無い。
- **ブラウザで描いた組**:
  - 各 `DataTable` の layout effect は、今のとおり `layoutTable` を呼ぶ。最初に動いた表の effect が組の全部を描く前に組み、あとの表の effect は印が同じなので飛ばす。
  - `DataTableGroup` にも依存を持たない layout effect を置き、`layoutTable` と同じ決まりで組を確かめる。組の中の表が増えたり減ったりしたとき（条件で描く表）も、描く前に組み直すためである。
  - 置かれた幅・字の大きさ・Web フォントの変化は、今の各表の ResizeObserver と `document.fonts.ready` がそのまま組の組み直しにつながる。

## 4. 完了の条件

### 4-1. 見込み（推論。合否に使わない）

漢字カナールで、そろえた幅 G（「最長連続」の太字4字＋余白）の横に「読みと意味」の値の列のいちばん長い文節が入るかを見積もった。

- 見積もりのしかた: 全2136字のデータ（`src/data/kanji-data.json`）の文節を、canvas の `measureText`（既定の sans-serif）で測った。表の幅は review-t5-20d.md の実測（320 で 244px、375 で 299px。200% でも同じ）を使った。
- 既定の文字サイズでは、どの幅でも 2136字の全部でそろう。
- 200% では、320 で 1917字、375 で 834字が、そろえると値の文節が入らない。これらの字では、3-1 のとおり「読みと意味」の見出しの列が細くなり、ずれは1字（32px）以内になる。
- 前の `ResultTable` は見出しの列を縮めなかった。そのため同じ字では、値の文節が割れるか、表が横に送られていた。

### 4-2. 条件

1. **漢字カナールの罫線**:
   - 測る組み合わせ: 320・375・1280 の3幅、既定と 200%（ブラウザの既定の文字サイズ 32px）の全部。
   - 使う値: review-t5-20d.md と同じ字と成績（3〜4桁）の組と、成績が2桁の組。
   - 合格: 「読みと意味」と「これまでの成績」の行の見出しのセルの右端の x の差が 0.5px 以内であること。
   - 例外: そろえると値の文節が入らない組（200% の狭い画面）と、成績の表が送られる組（320・200% の4桁）だけは例外とする。そのときは、差が見出しの字の大きさ1字以内で、値のセルに文節の中の折れが0であることを確かめる。
   - 全2136字を 320・375 の既定と 200% で組み、そろう字の数と例外の字の数を数えて報告する。既定では例外が0であること。
2. **行の見出しの列の幅**:
   - 対象: 1-3 の全面、3幅・2つの文字の大きさ。
   - 合格: 「収まる」表の行の見出しの列が、その列の max-content を超えないこと。組に入っていない表では、値の文節が入る限り max-content に等しいこと（差 0.5px 以内）。
3. **文節の中の折れ**: 棚卸し 10-9 の手順（t4-design.md 10章）で、1-3 の全面の表の「列に入る文節の中の折れ」が0であること。
4. **撮り比べ（AP-I14）**:
   - 撮る版: 前の版は HEAD に作業ツリーの T5-12・T5-20d を重ねたもの、後の版はそれに T5-8b を重ねたもの。
   - 撮る面: 1-3 の5面の全部（伝統色は、名前の長い色と短い色の2色以上。ゲームは遊び終えた画面）。
   - 撮る組み合わせ: 320・375・1280、既定と 200%。ライトは全部、ダークは各面1幅以上。
   - 表を持つブログ記事3本以上（例: 2026-02-14-character-counting-guide・2026-02-17-cron-parser-guide・2026-06-15-html-tags-cheatsheet）を 320 と 1280 で撮る。前と後で、表の画素が同じであること。

### 4-3. 試験

`scroll-frame.test.ts` と `DataTable.test.tsx` の作り物の組み（jsdom の `getBoundingClientRect` の決まり）に、max-content の幅（セルの文節の字数の和 × 10px）と、幅を指定した列の扱い（指定の幅を取り、指定の無い列が下限に届かなければその分だけ細る）を足す。そのうえで、次を確かめる。

- 行の見出しを持つ収まる表で、最初の行の最初のセルに、見出しの列の max-content（余白を除く）が指定されること。値の列には幅を指定しないこと。
- 行の見出しを持たない表（記事の表の形・列の見出しだけの表）には、どのセルにも幅を指定しないこと。
- 細くする表と送る表の組みが、今と変わらないこと（今の試験がそのまま通る）。
- max-content を測るあいだ開いた行が隠れていて、測ったあとに元へ戻ること。
- 組の2つの表の見出しの列に、同じ幅（広いほう）が指定されること。
- 送る表と細くする表が、組の幅を決めるのにも数えず、組の幅も受けないこと。
- 組の1つの枠に `layoutTable` を呼ぶと組の全部が組まれて印が付き、もう1度呼んでも組み直さないこと。中身を描き替えたと渡すと組の全部を組み直すこと。組の枠の数が変わると組み直すこと。
- `LAYOUT_PREVIOUS_TABLE` が組の中の枠を組まないこと。`LAYOUT_PREVIOUS_GROUP` が組の全部を組むこと。失敗したら組の全部の枠に `data-layout-failed` を付けて投げること。
- `DataTableGroup` を `renderToString` すると、定める文・組・組む文の順に並ぶこと。組の中の表が自分の組む文を置いても何もしないこと。水和で警告が出ないこと。
- 漢字カナールの `GameResult` の試験: 2つの表が同じ `[data-table-group]` の中にあること。

## 5. DESIGN.md と SKILL.md に書く文

AP-I08 のとおり、この設計のレビューで文を確かめてから実装する。書くのは T5-8b のコミットで、同じコミットにコードを入れる。

**DESIGN.md §5「コンポーネント」の表の項**: 「表の字の左端は本文の字の左端とそろう。」のあとに次を入れ、項全体が1つの文章として読めるようにつなぐ。

> **行の見出しの列は、見出しを1行に組める幅までしか取らず、表の残りの幅は値の列が取る。** 値はラベルのすぐ右から始まり、ラベルと値のあいだに、中身と関係の無い空きが開かない。値の列のいちばん長い文節が入らないときは、見出しの列が見出しを文節で折って幅を譲る。**1つのボックスや区画の中で縦に並べて続けて読ませる値の並びは、行の見出しの列を同じ幅にそろえ、縦の罫線を1本に通す。** 幅はそのうちいちばん広い見出しの列に合わせる。表を読み終えた目が次の表の値を探すとき、値の始まりが横に跳ばない。そろえると値の文節が入らない表だけは、文節を割らないことを先にして、その表の見出しの列が細くなる。横に送る表は自分のボックスに入るので、そろえる組に入らない。

**SKILL.md の「記事の外の表は `DataTable` で組み…」の項**: 列の幅の文のあとに次を入れる。

> 行の見出しの列の幅も同じ関数が決め、収まる表では見出しの列に max-content の幅を指定して、余りを値の列に渡す（§5）。1つのボックスや区画の中で縦に並べて続けて読ませる値の並びは `DataTableGroup` で囲む。組の最後で1度だけ組み、いちばん広い行の見出しの列に全部の表をそろえる。呼ぶ側では列の幅を指定しない。
