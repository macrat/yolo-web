## 指摘

### 1. 最初の描画の試験が、jsdom がすべてを 0 と測る偶然で図を描いている【builder・小】

`describe("RadarChart")` の「頂点に点を置かず、多角形1つと格子で描き、読み上げでは名前を1つ持つ図になる」は `stubMeasurement` を呼ばない。jsdom では図の幅・字の幅・行の高さ・字の大きさ（あき）がすべて 0 になり、大きさ 0 の字の箱は、半径 0 の多角形にも互いにも「重ならない」（比べが厳密な不等号のため）ので、幅 0 の図が組めてしまう。この試験はその偶然の上で `svg` を見つけている。

eac5fd89 で「組めなければ図を描かない」になってから、この前提は危うくなった。scratchpad の worktree で `layoutRadar` の頭に

```tsx
if (frame.width <= 0) return null;
```

を足す（幅 0 では描かないという、いまの約束どおりで来訪者に害の無い変更）と、この試験だけが落ち、ほかの7件は通る。直す人は「多角形1つと格子で描く」が壊れたと受け取るが、壊れたのは試験の前提の方である。逆に、この試験が見ている SVG は半径 0 のつぶれた図で、実際の画面の形を確かめてもいない。前回のレビューで `width < 120` の後退をこの試験が捕まえたと書いたのも、同じ偶然による。

- この試験も `stubMeasurement()` で測らせて描く（`describe("RadarChart を測り直す")` の中へ移すか、測りの手だてを両方の describe から使える所へ出す）。そうすれば図は 320px・14px の実際に近い測りで組まれ、試験の言う「描く」が本当の描画になる。確かめる中身（点が無い・多角形1つ・読み上げの名前・名前の字）は変えなくてよい。
