## 判断を頼まれた3つの点

どれも T5-9 で直すものではない。T5-9 の受け持ちは枠（パンくずと名乗りの一言・FAQ・共有・おすすめのセクション）で、3つとも Detail の中の CSS が原因である。ただし受け持ちの記録が足りないので、指摘2で記録を頼む。

1. **1280px で FAQ・共有・おすすめの見出し（46.72px）が h1（25px）より大きい**: h1 の 25px は `KanjiDetail.module.css`・`YojiDetail.module.css`・`ColorDetail.module.css` が書いている。FAQ とおすすめの見出しは HEAD の時点ですでに 46.72px で、T5-9 が足したのは同じ段の共有の見出しだけである。出荷はサイクルの終わりの1度だけ（index.md の description）なので、途中の状態は来訪者に出ない。T5-10・T5-11 は行に「h1 を §4」がある。**T5-12 の行には無い。**

3. **伝統色の 320px・200% の横のはみ出し**: はみ出すのは `.codeTable` の行と `CopyButton` で、HEAD のまま。T5-12 の完了の条件（「いまは toki でボタンが升より広く画面の外に出る」）がすでに受け持っている。ページの `scrollWidth` は 320 のまま（html の `overflow-x: clip`）で、ボタンが切られて見えない。

## `children: (head) => ReactNode` の API

受け入れてよい。

- 詳細のページの最初のセクションの頭にパンくずを置くには、枠が作る頭を、Detail が作る最初の `Section` の中に入れる必要がある。枠が最初の `Section` で包むと、Detail は1つのセクションしか返せず、T5-10〜T5-12 が同じ仲間の索引や関連を別のセクション（7-e）に分けるときに、`page.tsx` と枠を触ることになる（t5-design.md 10-1 は T5-10〜T5-12 が `page.tsx` を触らないとしている）。関数で頭を渡せば、Detail の中だけでセクションを分けられる。
- 同じ形は、プレイ面ですでに使っている。`QuizPlayPageLayout` は頭（パンくずと h1）を作って `QuizContainer` に `head` で渡し、`QuizContainer` がそれを最初のセクションに置く。辞典は枠が頭を作って Detail に渡すので、向きも名前（`head`）もそろっている。
- `page.tsx` は `{(head) => <KanjiDetail kanji={kanji} head={head} />}` の1行で、つぎはぎの痕は無い。枠のコメントは、いまの4つの部分を言う言葉で書かれ、HEAD にあった「店構え」「ToolLayout のパターンに準拠」「Server Component として実装」などの経緯の注記は消えている。`PlayRecommendBlock` のコメントも `Section` が罫線を持つ形に書き直されている。
- JSON-LD の出し分けを `(Array.isArray(jsonLd) ? jsonLd : [jsonLd]).map` の1つにまとめたのも良い。

ただし、この API には、テストで守られていない約束がある（指摘1）。

## anti-patterns/implementation.md の点検

- AP-I01（来訪者の目で見たか）: 5ページを4つの幅と2つのテーマで撮り、読める順・罫線・セクションの割り方を見た。中央寄せと h1 の段の逆転は、来訪者に見える問題として上に挙げ、受け持ちを指摘2で求めた。
- AP-I02（場当たりの回避）: 当たらない。頭の置き場所を、特定の辞典の分岐でなく、どの Detail にも同じ形で渡す API で解いている。`head` は必須の prop で、オプショナルにして逃げていない。
- AP-I03（Core Vitals・バンドル）: 当たらない。`ColorDetail` に渡すのはサーバーで描いた要素で、クライアントの JS にパンくずの部品は足されない。静的なデータの import も増えていない。
- AP-I04（指標を目的に配置）: 当たらない。共有の見出しは 7-e の決定（共有の区画に見出しを立てる）によるもので、共有の数を増やすための配置ではない。
- AP-I05（目的と無関係な中身）: 当たらない。新しく足した中身は共有の見出しだけで、ページの最後のほうにある。
- AP-I06（反対の極端）: 当たらない。
- AP-I07（jsdom で分からないもの）: 本番ビルドを Chromium で開いて、左端・見出しの大きさ・罫線・はみ出しを測った。
- AP-I08（DESIGN.md に無い見た目）: 当たらない。CSS の値は `--space-16`・`--space-8`・`--text-small`・`--measure`・`--ink-2` だけで、見出しの大きさは h2 の既定に任せている。
- AP-I09（コミットの順）: 移したファイル・消した `new/`・3つの `page.tsx`・Detail は、1つのコミットにしないと途中でビルドが壊れる。下の申し送りのとおり、1つのコミットにまとめること。
- AP-I10（keyframes）・AP-I11（タイマー）: 当たらない（アニメーションもタイマーも足していない）。
- AP-I13（撤去の網羅）: `_components/new` と「店構え」を `src`・`docs` で grep した。`src` の残りは、ブログ記事の本文（当時の記録）と、ほかの面のテストの describe の名（`middleware-gone-slugs.test.ts`・`ogp-image.test.tsx`。T5-9 の範囲の外）だけ。古い `.container`・`.shareSection`・`.related` のクラスは、どの CSS にも残っていない。
- AP-I14（共有の部品の変更）: T5-9 は共有の部品（`Section`・`FaqSection`・`ShareButtons`・`ItemList`）を変えていない。`DictionaryDetailLayout` と `PlayRecommendBlock` を使うのは3つの `page.tsx` だけで、3つとも測った。

workflow.md の点検: builder が Detail の3つに触ったのは PM が受け入れた範囲で、T5-10〜T5-12 の中身（h1・値の並び・索引）には手を出していない（AP-WF13）。報告の3つの論点は、どれも測り直して確かめた（AP-WF14）。
