## 指摘

### Major-1 補助情報の「{診断名}の結果」が、長い題名のままで不自然な日本語になる

`ResultCard` は補助情報に `quizTitle`（`meta.title`）をそのまま使っている。題名が問いかけや副題を持つ診断では、次のようになる。

- 伝統色診断: 「あなたを日本の伝統色に例えると?の結果」
- 理系思考タイプ診断: 「理系思考タイプ診断 — あなたはアインシュタイン型？チューリング型？の結果」（375px で2行）

§9 の「自然な日本語」に反し、来訪者が画面を撮って人に見せたときに最初に読まれる行が崩れている（補助情報を残す理由は、撮った画面で何の結果か分かるようにするため。設計 2-2 の置き換えの表）。結果のページでは、T4-7 のレビューを受けた PM の決定 (2) で「短い名前（`shortTitle`）があればそれを使う」ことになっている。同じ働きの行が、解き終えた画面と結果のページで違う文になるのは §12 の位置の一定にも合わない。

直し方: 解き終えた画面の補助情報も `shortTitle ?? title` で組む。短い名前を持たない診断で、題名がそのまま「〜の結果」につながらないものが残らないかを、15診断すべてで見て記録する。共有の文（`shareText` の「{診断名}の結果は…」）とハッシュタグも同じ題名から作っているので、そちらを変えるかどうかも決めて記録する（ハッシュタグの語を変えると、これまでの共有と数え方が変わる点に注意）。

### Major-2 「この結果を共有」の区画が、空の知らせの行で2つに割れて見える

`FudaActions` と `ShareButtons` が、それぞれ知らせの文の行（`role="status"`、1行の高さ）を空のままいつも取っている。375px の実測（guardian-charger）:

- 「画像を保存・画像を共有」の行の下端 831 → 空の知らせの行 839〜865 → 「X でシェア」の上端 873。2つのボタンの並びのあいだが 42px 空く。
- 「結果をコピー」の下端 969 → 空の知らせの行 977〜1002 → 次の区画 1026、その中の最初の要素 1058。区画の下にも約 90px の空きが出る。

撮った画面では、「画像を保存」の組と「X でシェア」の組が別々のものに見え、1280px では見出し・ボタン・大きな空き・ボタン・大きな空きと、区画が間延びする（`compare/*-1280-*.png`・このレビューで撮った 1280px の画面）。§8 は結果の共有と保存を「1か所」に置くとしており、見た目も1つの組であるべきである。知らせの行が2つあるので、読み上げの知らせの場所も2つに分かれている。

直し方の例: 区画の知らせの文を1か所（区画の末尾の1行）にまとめ、札の画像と文の共有のどちらの知らせもそこに出す。出たり消えたりでボタンが動かないことは保つ。`ShareButtons` は T4-4 の共有の部品なので、変えるならその部品を使うすべての面を変える前と後で撮り比べる（AP-I14）。

### Minor-1 読み（「しゅいろ」「しっぷうじんらい」）が、タイプ名より下の要素に近く見える

読みはボックスの本体（`.result`）の最初の段落なので、タイプ名とのあいだが頭の行の `margin-block-end` の 16px、読みと色見本・キャッチコピーのあいだも 16px で、同じ間隔になっている。読みはタイプ名の読み方なので、タイプ名に寄せて見せたい（index.md の補足は「見出しの下に」）。PM の決定で補助情報とタイプ名のあいだを 8px にするので、読みとタイプ名のあいだも同じ考えで詰め、読みの下は 16px のままにする形を、伝統色と言葉センスの 375px で撮って確かめる。

### Minor-2 キーボードで結果に着くと、ボックスのフォーカスのリングの上辺が画面の外に出る

最後の設問を Enter で答えると、ボックスが `:focus-visible` になり二重のリングが出るが、`scrollIntoView({ block: "start" })` でボックスの上端を画面の上端にぴたりと合わせるので、リングの上辺（ボックスの線の外）が画面の外に切れる（§12「フォーカスが必ず見え、隠れない」）。マウスや指で答えたときも、ボックスの太い線が画面の上端に貼り付いて見える。送り先に、リングの外端が入るだけの上の余白（`scroll-margin-top` など）を持たせる。ボックスの形とリングは T4-17 の builder が `ResultBox` を直している最中なので、どちらのファイルで持つかは PM が受け持ちを決める。

### Minor-3 `FudaActions` のコメントが、iOS の Safari について事実と違うことを書いている

コメントに「アンカーの download が使えない端末（iOS の Safari など）は navigator.share({files}) で保存へ進み」とあるが、iOS の Safari は 13 から `a[download]` を持つ（[Can I use: download attribute](https://caniuse.com/download)）。いまの iOS の Safari では `"download" in a` が真になり、共有シートではなくダウンロード（「ファイル」への保存）に進むはずである。このタスクで書き直したコメントなので、事実に合う文に直す。振る舞い（iPhone で「画像を保存」を押すと写真でなく「ファイル」に入ること、`trackSave` の `download` と `web_share_files` の数の読み方）は札を扱う T6 の受け持ちなので、PM が T6 か backlog に渡す（66% が WebKit の面のいちばん使われるボタンである）。

### Minor-4 見出しの区切りを作る処理が2か所にある

`QuizPlayPageLayout` と `src/app/storybook/page.tsx` が、同じ「`nameParts?.name ?? title` を `splitIntoPhrases` と `headingFontAttr` で見出しにする」処理を別々に持つ。storybook の見本は本物の画面と同じ組み方であることに意味があるので、どちらかを直したときに黙って食い違う。1つの関数（`readingHeadings.ts` の隣など）にまとめる。

### Minor-5 色見本にテストのためだけの属性がある

色見本の `data-swatch={resultColor}` は、単体テストが色見本を探すためだけのもので、来訪者の HTML に色の値を重ねて持たせている。テストは要素の `style` の背景色で確かめられる。外す。

- 条件 (1)〜(8) は「24タイプすべてで、375×667 のライトとダーク」と「1280×800 でも (2)〜(6)」だが、最後の測り（`solve-final3-*`）は 375 のダークと 1280 が3タイプずつである。直したあとの測りで、24タイプすべてを測る。
