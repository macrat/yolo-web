## 指摘

### Major-1: `globals.css` に旧トークンの別名を置いている（AP-P28）。別名をやめる作業の受け持ちも無い

`src/app/globals.css`:

```css
/* §2 に無い UI の色の名前。部品が参照しているあいだ、意味の近い §2 のトークンを指す。 */
--accent: var(--ink);
--accent-weak: var(--paper-2);
--rule-strong: var(--rule);
...
--radius: 0px;
--radius-sm: var(--radius);
```

- AP-P28 は「トークン互換レイヤー／色エイリアス」を名指しで禁じている。index.md の「作業中に守ること」にも「トークンの別名で旧値を新値に付け替えて済ませない（AP-P28）」とある。T1 はまさにこの別名を土台に入れた。参照は `src/` の `globals.css` 以外に、`var(--accent)` 385件、`var(--accent-weak)` 50件、`var(--rule-strong)` 53件、`var(--radius…)` 290件ある。
- 来訪者への害は、別名が「朱の見え方」を無彩の似た値へ黙って置き換えることで起きる。朱で示していたリンク・現在地（例: `CharacterPersonalityContent.module.css` の現在のタイプ）は、`--ink` の文字と見分けがつかなくなる。hover と選択の座布団（`--accent-weak`）は `--paper-2` になり、`--paper` との差はほとんど見えない。§6「明度の差だけで押せるかどうかを示さない」にも反する。
- index.md の T2 の行が着手の前に洗い出すのは「朱の色だけでリンクや操作を示していた箇所」だけである。`--accent-weak` の hover・選択の地、`--rule-strong` の枠の太さ（1px の `--ink` の線は §5 の2種類のどちらでもない）、`--radius` を消すことは、どのタスクの行にも無い。完了の条件の「トークンは DESIGN.md に名のあるものだけ」に T8 で初めて引っかかると、155ファイルを最後にまとめて直すことになる。
- コメントの「部品が参照しているあいだ」は、経過の状態を説明する注記で、ツギハギ禁止のルールに当たる。storybook も `--accent` を「リンク・主ボタン・現在地・記入印。--ink を指す」と、正規のトークンのように並べている。

**直し方**: index.md に、別名をやめる作業の受け持ちを書く。部品（`src/components` など）は T2、面は T4・T5 が持つ。完了の形は「`globals.css` から `--accent`・`--accent-weak`・`--rule-strong`・`--radius`・`--radius-sm` の定義が消え、参照が §6（下線・反転・形）と §5（線は2種類）で組み直されている」とする。あわせて T2 の着手前の洗い出しを、朱の色だけのリンク・操作に加えて、`--accent-weak` の地で示していた hover・選択・現在地まで広げる。`globals.css` のコメントは、経過の説明でなく、何を指すかだけにする。別名の定義を最後に消すタスクを1つに決め（T5 の終わりか T8）、そこで検査が別名の再流入を防ぐようにする。

### Major-2: §4 の見出しの折り方を `word-break: auto-phrase` だけに頼っていて、iOS の Safari では効かない。判断の記録も無い

`globals.css` の h1〜h6 は `word-break: auto-phrase` で文節の切れ目で折る。この値に対応しているのは Chromium 119 以降だけで、Safari と Firefox は対応していない（[Can I use: word-break: auto-phrase](https://caniuse.com/mdn-css_properties_word-break_auto-phrase)、[caniuse issue #6922](https://github.com/Fyrd/caniuse/issues/6922)）。対応していないブラウザでは通常の禁則処理になり、見出しが語の途中で折れる（例: 「あなたに似たキャラ診 / 断」）。

- `DESIGN.md` §4 は「見出しは意味の切れ目で折る。語の途中・括弧の前後で折らない」と定め、`frontend-design` スキルの「目で確かめる」にも入っている。どちらも見出しの書体で組む §1 の仕掛け2の見え方を左右する。
- PV の78% が集まる `/play/character-personality` は自然検索からの流入が93.2%で、モバイルの来訪者の中で iOS の Safari が占める割合は小さくないと見られる。検査を回すのは Linux の Chromium だけなので、この差は検査にも T9 の予定にも現れない（fonts-decision.md の「T9 で確かめること」にも無い）。
- 実装の方法（ビルドの時に BudouX などで文節の区切りに `<wbr>` を入れ、`word-break: keep-all` と `overflow-wrap: anywhere` で組む、など）も、「Chromium だけで満たし、ほかでは通常の禁則処理にとどめる」という判断も、cycle-316 のどの文書にも書かれていない。

**直し方**: §4 をどのブラウザで満たすかを決め、[index.md](./index.md) の補足事項か fonts-decision.md に理由を残す。ブラウザを問わず満たすなら、見出しの文字列から文節の区切りを作る仕組みを T1 で用意する（見出しを描く部品に共通の入口が要るので、T2〜T5 に回すなら index.md の該当の行に書く）。Chromium だけにするなら、`DESIGN.md` を変えるときの手順（[options.md](./options.md)）に沿って判断を示し、レビューを受ける。どちらにしても、iOS の Safari で主要な見出しの折れ方を確かめる項目を T9 に足す。

### Minor-2: `design-gate.test.ts` の冒頭のコメントが、いまのコードと `DESIGN.md` に合わない

- `global-not-found.js` を「テンプレート文字列に CSS/HTML を埋め込む面」「トークンを import できず hex を直書きする」としている。いまの `global-not-found.js` は `globals.css` を import し、`SiteFrame` の JSX を返すだけで、CSS も HTML も埋め込んでいない。`middleware.ts` も、トークンは oklch で持ち、hex は `utsuwaHex` から import している。

### Minor-3: 既定のフォーカスの輪が 2px の単色で、§5 の線の太さ（3px・1px）にも §6 の二重リングにも当たらない

### Minor-4: §4 の補助情報の下限（0.875rem）を下回る文字サイズの受け持ちが、はっきりしない

`src/` の CSS で、`font-size` が 0.875rem 未満の宣言は 188件（0.8rem 52・0.85rem 46・0.8125rem 45・0.75rem 33・0.7rem 11・0.65rem 1）あり、121ファイルにまたがる。ほかに `12px`・`14px` の固定値が6件ある（入力欄の分は B-663 として T2 にある）。§4 は T1 の範囲だが、個々の部品の値は T2〜T5 で直すことになる。いまは「ページ固有の CSS から DESIGN.md に無い値を消す」という一般的な書き方でしか受け持ちが無い。T8 の機械の検査に「`font-size` が `--text-small` を下回らない」を加え、T2〜T5 の各行が自分の範囲の分を直すと書く。

### Minor-5: 410 の見出しがアンティーク体にならない理由が、コードのコメントにしか無い

410 は Web フォントを読まないので、h1「このコンテンツは終了しました」が本文のゴシックで組まれ、§1 の仕掛け2（巨大なアンティーク体の見出し）が出ない。`middleware.ts` のコメントは「このページは Web フォントを読み込まない」と書くだけで、なぜ読まないかと、何を失うかは書かれていない。index.md の補足事項の 410 の項に、この判断を加える。

### Minor-6: 高さの `100vh` と、`utsuwaHex` の名前の食い違い

- `body { min-height: 100vh; }`（410 も同じ）。モバイルのブラウザでは `100vh` がアドレスバーを畳んだときの高さなので、中身が短いページ（404・410）でも、アドレスバーの分だけ下端が画面の外に出て縦に送れるようになる。`100svh` を使えば、下端が最初の画面に収まる。
- `src/lib/utsuwaHex.ts` の `RULE` は `--rule-2`（細い線）、`RULE_STRONG` は `--rule`（太い線）、`ACCENT` は `--ink` を指している。CSS のトークンと名前が食い違っていて、OGP や札の画像を組み直す T6 が取り違えやすい。T6 の行に「CSS のトークンと同じ名前にそろえる」と書くか、T1 で名前を直す。
