## 指摘事項

### 1. 開いた一覧を送り切ったあとも送り続けると、一覧の下でページが見えないまま送られ、閉じると読んでいた所を失う（中）

開いた一覧（`.list`）は `overflow-y: auto` の箱で、`overscroll-behavior` を持たない。一覧の端まで送ったあとのホイールや指の送りは、ページへ引き継がれる。一覧は目次の下から画面の下端までを覆うので、来訪者にはページが動いたことが見えない。

| 画面・記事（y=4000 で開き、一覧の上で 400px ずつホイールを8回） | 一覧の中                 | ページ                          |
| --------------------------------------------------------------- | ------------------------ | ------------------------------- |
| 375×667・character-counting-guide                               | 1回目で端（387）まで送る | 2回目から 400px ずつ、6800 まで |
| 1280×800・同じ記事                                              | 1回目で端（241）まで送る | 同じく 6800 まで                |

来訪者が一覧を見渡して、選ばずに閉じる（Escape・開閉の行を押す）と、開く前の位置から 2800px 先の、読んだことのない所にいる。一覧の最後の項目を探して送りすぎるのはよくある操作で、指の送りでも同じ引き継ぎが起きる。開くときに目次を上端へ送り、キーボードでもページを動かさないようにした今回の組み方の目的（読んでいた所を失わせない）が、ここで崩れる。

確かめ: 一覧に `overscroll-behavior: contain` を当てると、上の2通りでページは 4000 のまま動かなかった。一覧が中で送れない長さ（javascript-date-pitfalls-and-fixes の 1280）では、ホイールはこれまでどおりページを送り、目次の下に見えている本文が動くので、来訪者には見える。どう直すかは builder が比べて選ぶ。直したら、CSS のコメントに理由を書き、完了の条件の測り（留まる前と後、2記事、3つの大きさ）に「一覧の端を越えて送ってもページが動かない」を足して測る。

### 2. 関連記事のセクションの中に、もう1つの `<section>` ができる（軽い）

`page.tsx` は `<Section>` で `RelatedArticles` を包むが、`RelatedArticles` は自分で `<section>` を描く。描いた HTML は `<section class="section"><section><h2>関連記事</h2>…` の二重になり（4つの大きさで確かめた）、外の `<section>` は頭に見出しを持たない。`Section` の決まり（頭に見出しを1つ置く）と食い違い、ほかの3つのセクション（見出しを直下に持つ）と組み方がそろわない。空のときの扱いも、ページ（`relatedPosts.length > 0`）と部品（`posts.length === 0` で `null`）の2か所にある。`RelatedArticles` を使うのはこのページだけなので、どちらか一方がセクションを持つ形にそろえ、空の扱いも1か所にする。

### 3. `page.test.tsx` の「ページが自前の余白と右の列を持たないこと」が、外した組み方の名残を試している（軽い）

この試験は `page.module.css` に `padding: … var(--space-24)`・`grid-template-columns`・`position: sticky` が無いことを確かめる。「右の列」は DESIGN.md にもコードにも無い言葉で、前の組み方を知らない人には何を守る試験か読めない（ツギハギ禁止）。`padding` に `--space-24` を使うことを一律に禁じるのも、§5 の決まりから出るものではない。留めるのは目次（`CollapsibleTOC`）の役目で、ページの CSS に `sticky` が無いことは、何かの決まりを確かめていない。記事の組み方の決まり（コンテナのコンテンツ幅で組む）を確かめたいなら、今の組み方に向けた正の形で書くか、ほかの試験（セクションの並び）で足りるなら外す。
