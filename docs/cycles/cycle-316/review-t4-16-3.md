## 指摘

### Major-1 共有の Button の `overflow-wrap: anywhere` で、既定の文字サイズの 320・375px で、パスワード生成のコピーのボタンが「コピ／ー」と2行に折れる

`tmp/cycle-316/rv41603/_tools_password-generator-w375-f16-now.png`（変更後）と `-without.png`（`overflow-wrap: normal` を当てたもの）。パスワードを生成したあと来訪者がまず押す「コピー」が、375px・16px（来訪者のいちばん多い幅の1つで、既定の文字サイズ）で「コピ」と「ー」の2行になる。行頭に長音符が来て、§4 の禁則にも反し、ボタンの高さも 44px から 63.6px に伸びる。320px・16px でも同じ。変更前は1行だった。

原因は `anywhere` の働きにある。`anywhere` は、字の所の折り所を min-content の大きさの計算に入れる（MDN。`break-word` は入れない）。ボタンの min-content が1字の幅になるので、ボタンを包む要素が縮める並びの中にあると（パスワード生成では `.copyButtonWrap` が `resultDisplay` の flex の子で、縮められる）、包む要素がボタンの字の幅より狭く縮み、ボタンの字が文節の中で折れる。ボタン自身の `flex-shrink: 0` は、包む要素には効かない。builder の報告の「既定の文字サイズで Button を使うほかのページの見え方は変わらない」は4ページを比べたもので、これを拾えていなかった。

168ページを測って変わったもの（どれも開いたときの状態）:

| ページ                      | 幅・文字サイズ  | 変更後                           | `overflow-wrap: normal` のとき |
| --------------------------- | --------------- | -------------------------------- | ------------------------------ |
| `/tools/password-generator` | 320・375 × 16px | 「コピー」2行（コピ／ー）        | 1行                            |
| `/tools/password-generator` | 320 × 32px      | 「パスワード生成」2行、枠の中    | 1行で枠の外へ出る              |
| `/dictionary/colors/toki`   | 320・375 × 32px | 「コピー」3行（1字ずつ）、枠の中 | 1行で表と枠の外へ出る          |
| `/tools/qr-code`            | 375 × 32px      | 3行、字はボタンの中              | 2行で字がボタンの外へ出る      |
| `/tools/business-email`     | 320 × 32px      | 3行、字はボタンの中              | 2行で字がボタンの外へ出る      |
| `/dictionary/humor/morning` | 320 × 32px      | 2行、字はボタンの中              | 1行で字がボタンの外へ出る      |

200% の行は、変更前は字か箱が枠の外へ出ていたのが枠の中に収まったので、良くなっている（§4 は 200% で文節の中の折れを受け入れる）。問題は 16px の2行だけだが、これは来訪者のほとんどが見る大きさである。

なお、`overflow-wrap: break-word` に替えるだけでは直らないことも確かめた。`break-word` にすると unix-timestamp の 320・375px・200% の「コピーしました」の字がボタンの外へ出る（ボタンの中の字の塊の min-content が文節の幅のままで、縮まないため）。

直し方は builder が決める（例: 包む要素の側を縮めないようにする、ボタンの字の塊にだけ文節の中の折れを許し、ボタンの min-content には効かせない組み方にする、など）。直したら、**Button を使う全ページについて、16px では変更前と見え方が1つも変わらず、32px では字も箱も枠の外へ出ないこと**を、320・375 × 16px・32px で測る。開いたときの状態だけでなく、押したあとに出るボタン（結果のコピー・「コピーしました」・共有の区画など）も測る。上の168ページの測り方（同じページで `overflow-wrap` を当て替えて比べる）は `tmp/cycle-316/rv41603/sweep.mjs` にある。

### Minor-2 報告の「別のコピーを押すと下のボタンが詰まる」は、T4-16 の直しを止める理由ではない。ただ、同じ結果の表には、既定の文字サイズでもっと大きく跳ぶ、この変更の前からある問題があり、T5 に確実に渡す

判断: 200% の 320・375px で、先に押したボタンが1行に戻って下の行が1行ぶん（約 48px）上へ詰まるのは、押した来訪者が「コピーしました」を読もうとしたボタンが動くので、良くはない。ただ、これは「コピー」と「コピーしました」の字の量の違いから来る揺れで、2巡目で決めたとおり、サイトのすべてのコピーのボタンに関わる共有の部品の課題である（道具の中の1つのボタンだけで押さえない）。変更前は同じ場面で「コピーしました」が枠の外へ出ていたので、枠に収まるいまの方が来訪者にとって良い。T4-16 の直しとしては受け入れる。

一方、測ってみると、同じ結果の表は**既定の文字サイズの 375px** でもっと大きく動く（`tmp/cycle-316/rv41603/table-w375-f16-base.png`・`table-w375-f16-local.png`）。「ローカル時刻」のコピーを押すと、ボタンが「コピーしました」に広がった分だけ値の欄が縮み、`word-break: break-all` の値が「20／2／4/／0／1/…」と2字ずつに折れて、行が 68px から 301px に伸び、下の行がまとめて 233px 下がる。次に「UTC」を押すと、ローカル時刻の行が戻って UTC の行が伸び、押したボタンの位置も動く。値の数字が桁の途中で折れるのは §8 にも反する。この動きは `overflow-wrap: normal` を当てても同じで、この変更の前からあり、T4-16 の受け持ち（止める・動かすのボタン）の外である。builder の報告は 200% のことしか言っておらず、この動きを拾えていなかった。

unix-timestamp の結果の表は、t4-design.md の9章のとおり T5 が結果の形（§8。コピーのボタンを結果の頭の行に置く）で組み直す。PM は、T5 の unix-timestamp の組み直しのタスクに「375px・16px でコピーを押すと値が2字ずつに折れて表が 233px 跳ぶ」「値が桁の途中で折れる（§8）」の2つを、この測り方（`tmp/cycle-316/rv41603/table2.mjs`）と一緒に書き込み、組み直しの合格の条件に「どの幅・文字サイズでもコピーを押して表の行の高さと押したボタンの位置が変わらない」を入れる。T4-16 の builder はここを直さない。
