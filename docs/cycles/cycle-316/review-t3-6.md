## 指摘

### Minor-1: 3b6111a 単体ではビルドが通らない。ツールの種別の値を替えたとき、`seo.test.ts` の古い値を拾い損ねた

3b6111a で `npm run build` すると、型の検査で止まる（`Failed to type check`、EXIT 1）。T3-6 に由来するのは `src/lib/__tests__/seo.test.ts` の10件で、ツールの見本のデータが `category: "developer"` のまま、新しい `ToolCategory`（`text`・`number`・`data`・`image`・`color`）に合わない。

```
src/lib/__tests__/seo.test.ts(1180,7): error TS2322: Type '"developer"' is not assignable to type '"number" | "data" | "text" | "image" | "color"'.
```

いまの HEAD（a123792）では、T3-8 のコミットが同じ行を `"data"` に直していて、ビルドは通る。来訪者に出る害はもう無い。それでも、T3-6 の builder が型の検査を通さずにコミットしたこと、種別の値を替えたあとに古い値を網羅して探さなかったこと（`docs/anti-patterns/implementation.md` AP-I13）は残る。このままだと、コミットを1つずつ辿って不具合の入った場所を探すときに、3b6111a で止まる。なお 3b6111a には、381d2d9 のデータの形の変更に追いついていない `BlogListView.tsx`・`kanji-list.ts` の型の誤りもあり、これは T3-6 の範囲の外である（並行作業の重なり。index.md の補足事項にある件）。

直し方: コードの直しは要らない（HEAD で直っている）。この件をサイクルの記録に残し、直しの作業では `npm run typecheck` を通してからコミットする。

### Minor-2: /play の説明が、種別の語と違う「占い」を使い、今日のユーモア運勢に当てはまらない「どれも答えたら」と言う

`/play` の見出しの下の文は「占い・診断・クイズ・パズル。どれも答えたらすぐ結果が見られます。」（`src/play/play-list.ts` の `PLAY_LIST_INTRO`）。

- すぐ下の種別の組と各行の種別は「運勢・診断・クイズ・パズル」で、説明だけが「占い」と言う。4つを並べて種別を紹介している文なので、来訪者は組の中に「占い」を探し、「運勢」と同じものかを読み替えることになる。設計の3-2は「種別の語は、サイトの中で1組にします」と決めている。
- 今日のユーモア運勢（`/play/daily`、種別順で先頭の行）は、何も答えずに開くだけで今日の運勢が出る。「どれも答えたら」は、この1件に当てはまらない。§9「具体。何が出てくるかを言う」の信頼に関わる。

直し方: 種別の語をそのまま使い、全件に当てはまる言い方にする。例「運勢・診断・クイズ・パズル。登録なしで、その場で結果まで見られます。」。375×667 で説明が2行のまま、最初の行の全体が画面に入ること（いまの余りは 5px）を測って確かめる。

### Minor-3: /tools の「入力は送信しません。」は、どこへ送らないのかが無く、読み違えうる

「登録不要。入力は送信しません。」の「送信しません」には行き先が無い。前の説明が言っていた「外部に送信されません」の「外部に」が落ち、「入力しても送信ボタンは無い」とも読める。ツールの一覧でこの文が伝えたいのは、入力した文章や画像がサイトの外へ出ないという安心で、それは行き先があって初めて伝わる。

直し方: 行き先を足す。例「登録不要。入力は外部に送りません。」（17字）。375px のコンテンツ幅（322px）には1行で収まる見込みなので、375×667 で1行に収まり、最初の行の全体が画面に入ることを測って確かめる。

### Minor-4: `TOOL_LIST_INTRO` のコメントが、320px で最初の行が最初の画面に入ると読める

`src/tools/_lib/tool-list.ts` のコメントは「320px でも1行に収め、最初の行を最初の画面に入れる」。320px で説明が1行に収まるのは正しいが、320×667 では最初の行の下端が 706 で、画面（667）に入らない（上端のナビが2行に折れるため）。最初の画面に入るのは、完了の条件の 375×667 と 1280×800 である。コメントがコードの効き目を実際より大きく言っていると、次に説明を直す人が 320px の確かめを省く。

直し方: コメントを事実に合わせる（例「375px の幅で1行に収め、375×667 と 1280×800 で最初の行を最初の画面に入れる」）。Minor-3 で文を替えるなら、そのとき測った幅で書く。

### Minor-5: `/tools/page/[page]`・`/play/page/[page]` の SEO のテストが、いまは何も確かめずに通る

`src/app/__tests__/seo-coverage.test.ts` に足した2つのテストは、`toolListPageParams().length === 0` なら `return` する。ツールは36本・遊びは20本で1ページなので、どちらも何も確かめずに「通った」と出る。このサイクルは 7bad847 で、同じ形の中身の無いテスト（いま無い連載で組まれたテスト）を中身のある検査に直したばかりである。51本目で2ページ目ができたとき、題の「（2ページ目）」や canonical が壊れていても、それまで誰も気づけない。

直し方: 2ページ目があるかに頼らず確かめる。`toolListMetadata(2)`・`playListMetadata(2)` は純粋な関数なので、直に呼んで `assertSeoMetadata` に掛ければ、いまのデータでも「（2ページ目）」の題と `/tools/page/2` の canonical を確かめられる。

### Minor-6: 遊びの行で、名前と種別が食い違うものがあり、種別で絞ると名前で探した人の予想と外れる

各行に種別が出るようになり、次の食い違いが1行の中で並んで見える。

- 「漢字力診断」「四字熟語力診断」「ことわざ力診断」の種別は「クイズ」。「診断」で絞ると、名前に「診断」を持つこの3本が出ない。
- 「逆張り運勢診断」の種別は「診断」。「運勢」で絞ると今日のユーモア運勢の1件だけになり、この1本は出ない。

種別の語（`resolveDisplayCategory`）は T3-2b のおすすめの一覧とも共有していて、名前か種別のどちらを直すかは中身の判断になる。T3-6 の実装の誤りではない。

直し方: T3-6 のコードは直さなくてよい。名前を種別に合わせる（例「漢字力クイズ」）か、種別の割り当てを見直すかを PM が決め、バックログに積む。題を替えると検索の流入に効くので、GA と Search Console で3本の流入を確かめてから決める。
