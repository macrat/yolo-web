## 指摘

### 1. [Major] タイプ名の折れ方は Chromium だけのもので、来訪者の3分の2が見る折れ方ではない。2-2 の「折り方の指定が無く」も誤り

2-2 のタイプ名の行は「折り方の指定が無く、語の途中で折れる（2-5）」と書く。しかし解き終えた画面のタイプ名は `Tsutsumi` が `h2` で出すので、`globals.css:235-245` の `h1〜h6 { word-break: auto-phrase; }` が掛かる（実測の計算値も `auto-phrase`）。結果のページのタイプ名は `p` なので `normal` になる。`globals.css:233-234` のコメントのとおり、`auto-phrase` は Chromium でしか効かない。caniuse では Safari（iOS を含む）と Firefox は対応していない（Safari は Technology Preview だけ）。

GA では、直近28日の character-personality の `level_end` 1,181 のうち、iOS のモバイル 693（Safari 577・Chrome 59・アプリ内 Safari 57）、iOS のタブレット 34、Mac の Safari 49 で、計 **約776回（66%）が WebKit** で描かれている。iOS では Chrome も WebKit で描く。2-5 の表と「語の途中で折れるもの 375px で9タイプ」「高さの分布 454px 2・497px 9・540px 7・584px 6」「保存が最初の画面に入るのは11タイプ」は、Chromium で `auto-phrase` が効いたときの値である。いちばん多い来訪者（iPhone の Safari）が見る折れ方とは違う。

Chromium で `word-break: normal` にして同じ23タイプ（guardian-charger を除く）を測ると、折れ方は次のように変わる。WebKit の実物ではないので近似である。

- 375 で、23タイプのほぼすべてが語の途中で折れる（`auto-phrase` では9タイプ）。例「叫んで3／秒後に空を見上／げる」「10／年経っていた博／士」「安全確認を17回／やってから実験／を始める慎重博／士」。数字と助数詞も割れる（「3／秒」「10／年」「7／本」）。
- 包みの高さは 454px 5・497px 16・540px 2 になる（guardian-charger を除く23タイプ）。「保存」が最初の画面に入るタイプは、23のうち21になる（`auto-phrase` では24のうち11）。

直すこと。

- 2-2 のタイプ名の行を「解き終えた画面は h2 なので `globals.css` の `word-break: auto-phrase`（Chromium だけ）、結果のページは `p` で `normal`」と直す。
- 2-5 の折れ方の表と高さの分布・「保存」の数に、Chromium の `auto-phrase` の値であることを書く。WebKit で測れない環境なら、`normal` での近似の値を並べ、「近似」と書く。どちらが何割の来訪者に当たるかは、上の GA の数を9章に足して示す。
- 11-1 の1に論点を足す。§4「見出しは意味の切れ目で折る。語の途中で折らない」を WebKit でも守る手段（`auto-phrase` に頼らない折り所の指定。たとえばデータ側で折り所を持つ、`<wbr>`、語の単位の `inline-block`）を決めること。これは解き終えた画面に限らず、サイトのすべての見出しに関わる。T4 で決めるか、T1 の土台に戻すかも論点になる。
