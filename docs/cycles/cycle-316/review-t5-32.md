## 指摘

1. **SKILL.md 52行目と playwright-mcp.md 68行目が、同じ条件を2度書いている（builder）。** 「字が2字以上の要素で」と書いた時点で、全体が1字の要素は外れている。そのあとの「要素の字の全体が1字のもの（伝統色の「藍」の見出し）は…数えない」は同じことの言い直しで、1つの事例のために足した例外の書き方になっている（CLAUDE.md のツギハギ禁止。確かめ1・4）。定義の条件だけを残し、次の形にすること。理由は §4 が持つので、手順の側には要らない。「字が2字以上」は「字」が重なって読みにくいので、「字が2つ以上」にする。
   - SKILL.md: 「1字だけの行（字が2つ以上の要素で、字が1つだけの行。その字がどの文節の字かは問わない）」
   - playwright-mcp.md: 「1字だけの行は、字が2つ以上の要素で、行に分けたあとの字の数（コードポイントの数）が1の行である。区切りの関数が…（以下は今のまま）」
2. **DESIGN.md 111行目が、規則のあとに例外の文を足す形になっている（builder）。** 最後の「見出しの全体が1字のとき（伝統色の「藍」）は、切り離される語が無いので、その1行は1字だけの行に当たらない。」は、先に規則を言い切ってから特定の場合を外す書き方で、始めから正しく書いた文には見えない（確かめ1）。語の意味そのものを規則の中で決め、例外の文を消すこと。例えば太字の中を「見出しに1字だけの行（2字以上の見出しで、字が1つだけの行）・禁則の破れ（…）…を作らない」とし、理由の文は今の「1字だけの行はその字を前の語から切り離して読ませ、…」のままにする。こうすれば、全体が1字の見出しが当たらない理由も、同じ理由の文から読み取れる。

## 段に上げるコマンド（T5-32 の hunk だけ）

`-U0` の hunk を、元の行の番号（`@@` の2つ目の欄）で1つだけ選んで段に上げる。一時の索引（`GIT_INDEX_FILE` に `.git/index` の写し）で走らせ、段に上がるのが上の3つの hunk だけで、残りの5つ（`DESIGN.md` 109、`SKILL.md` 46・129・141、`playwright-mcp.md` 71）が作業ツリーに残ることを確かめた。指摘を直しても1行の置き換えのままなら、hunk の頭は `-111`・`-52`・`-68` のまま使える（行の数が変われば `-111,2` のようになるので、そのときは `git diff -U0` で頭を見て合わせる）。

```bash
cd /home/user/yolo-web
pick() { git diff -U0 -- "$1" | awk -v h="$2" '/^diff --git/||/^index /||/^--- /||/^\+\+\+ /{print;next} /^@@ /{keep=($2==h)} keep'; }
pick DESIGN.md -111 | git apply --cached --unidiff-zero -
pick .claude/skills/frontend-design/SKILL.md -52 | git apply --cached --unidiff-zero -
pick docs/knowledge/playwright-mcp.md -68 | git apply --cached --unidiff-zero -
git diff --cached -U0   # 3つの hunk だけであることを確かめる
```
