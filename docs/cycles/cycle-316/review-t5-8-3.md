## 指摘

### Minor-1: 開いた行のセルに、同じものを指す印が2つある（ツギハギ）

`index.tsx` の開いた行のセルは、`className={styles.detail}` と `data-detail=""` の2つを持つ。

- CSS は `.table .detail`（折り方）をクラスで選ぶ。
- `.detailContent` の直しと `scroll-frame.ts` は `[data-detail]` を使う。

この部品のほかの印（`data-narrowed`・`data-copy-below`・`data-in-box`）は、CSS もスクリプトも属性の1つで選んでいる。開いた行だけが、クラスと属性の2つを持つ。

- 読む人は、2つの印が別のものを指すのかを確かめることになる。
- 2つの印がそろっていることを誰も確かめていない。片方だけを外すと、折り方か見える幅の一方だけが効かなくなる。
- 属性は、スクリプトの文字列からは CSS Modules のクラス名が見えないため要る。クラスは、属性を足す前の形の名残である。

直し方（builder）: 開いた行のセルの印を `data-detail` の1つにし、CSS の `.table .detail` を `.table [data-detail]` にして `styles.detail` を外す。1巡目の試験（開いた行の折り方）と、今回の試験が通ることを確かめる。

### Minor-2: 開いた行をすべて閉じても、見える幅の値が枠に残る

`layoutTable` は、開いた行があるときだけ `--frame-visible-width` を付け、無いときに外さない。320px の表3で確かめた。

| 状態                      | 枠の `--frame-visible-width` |
| ------------------------- | ---------------------------- |
| 初め（開いた行無し）      | 無し                         |
| 1行目を開く               | 244px                        |
| 閉じる                    | 244px（残る）                |
| 閉じたまま 375px に広げる | 244px（古い幅のまま残る）    |
| 375px で開き直す          | 321px                        |

- 開き直すと中身が変わったとして組み直すので、古い値が開いた行に使われることは無い。来訪者に見える崩れは無い。
- ただ、枠が持つ状態が、関数のコメント（「開いた行を持つ表には、見える幅を枠の --frame-visible-width に持たせる」）と、試験の名（「開いた行を持たない表には、見える幅を持たせない」）の約束と食い違う。試験は、一度も開いていない表しか確かめていない。
- 古い値が残ることに頼らない形にしておかないと、あとで開いた行の組み方を変えたときに、古い幅が使われる穴になる。

直し方（builder）: 開いた行が無ければ `removeProperty("--frame-visible-width")` で外す。部品の試験に、開いてから閉じた表が見える幅を持たないことを足す。

### Minor-3: `DataTable` の部品のコメントの1行だけが、ほかの行より長い（ツギハギ）

`index.tsx` の部品のコメントの3段落目の141行目は、全角を2と数えて 145 桁ある。ほかの行は 107〜111 桁でそろっている。

> 組む。表が届き終えて組むまでは表を描かない。ブラウザで描く表は描く前に組む。そのあとは、置かれた幅・字の大きさ・Web フォントが変わったときと、

文を足したときに、段落を折り直さなかった跡である。prettier はコメントを折り直さないので、`prettier --check` では見つからない。

直し方（builder）: 3段落目（「組みは最初の描画の前に決める。」から「中身が変わったときに組み直す。」まで）を、ほかの段落と同じ幅で折り直す。
