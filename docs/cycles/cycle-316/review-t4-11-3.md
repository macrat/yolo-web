## 2. CLS と戻る位置（8回ずつ）

どの場面も、320・375・1280 × 既定・200% × 勝ち・負けの全部で、8回とも同じ値だった。

- 初めての来訪者: 0〜0.0001（0.0005 を超えるずれは無い）
- 判定を1秒遅らせたとき: 0
- 途中まで遊んだ回を開き直したとき: 0〜0.0001
- 解き終えた回を、同じ画面で開き直したとき: 0〜0.0001
- 共有の見出しまで送ってから読み込み直したとき: CLS 0。見出しは読み込み直す前も後も画面の上から 100px にあり、ずれは 0px
- 戻るで戻ったとき: CLS 0、ずれは 0px。ナビゲーションの種類は `back_forward` で、bfcache からの復元ではなく、読み込み直した状態で測れている

`level_end` は、その場で解き終えたときに1回だけ送られた。開き直したとき・読み込み直したとき・戻ったときは、どれも 0 回だった（96回とも）。

## Major

### Major-1. 判定を待つあいだに次の字を入れると、判定が返ったときにその字が消える

- **再現**: 推測の判定を3秒遅らせ、そのあいだに次の字（木）を入力した。判定が返ると、`GuessInput` が送った結果を受けて `setValue("")` を実行し、あとから入れた字も消える。送信のボタンは、判定が返るまで押せない。判定が返ったあとに押すと、空の入力を送ることになり、「漢字を1文字入力してください」と出る。自動で遊ばせた回では、この字は盤に入らなかった（証拠: 375-0-lose の盤は 山・川・火・水・金）。
- **来訪者に起きること**: 回線の遅い来訪者ほど、判定を待つあいだに次の字を考えて打つ。IME で変換して確定した字が、黙って消える。入力欄は、文字盤を閉じさせないよう、送っているあいだも無効にしない作りになっている。それなのに、打った字を捨てるのは、その作りと食い違う。
- **直すこと**: 欄を空にするのは、送ったその場（字を判定待ちの行に移すとき）にする。または、送ったときの値のままのときだけ空にする。判定に失敗したとき（`unavailable`）に字を戻すかどうかも、あわせて決める。テストを足す。

## Minor

### Minor-1. 2つの表の値の始まりがそろわず、コメントとも食い違う（m2 の残り）

`th { width: 4em }` が、表の自動の組みで下限としてしか効いていない。そのため、答えの表と成績の表で、見出しの列の幅が違う。375px・1280px の既定では 68px と 77px、320px・200% では 111px と 146px になる（R-375-0-win-light.png で、値の縦の線が 9px ずれて見える）。`ResultTable.tsx` と CSS のコメントは「値の始まりがそろう」と書いているが、事実と合わない。2つの表で列の幅を本当にそろえる（`table-layout: fixed` と、padding を含めた幅にするなど）。そして、4つの幅で実測する。
