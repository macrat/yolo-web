既定の字で落ちる仕組みも確かめた。図に `ResizeObserver` を付けて記録すると、Playwright の `fullPage: true` の撮影のあいだに、図の幅 0・ビューポート 1×1 の通知が1回来る（`[0, 1, 1]`）。直す前はここで字を置けず、字の位置0個の組みを使って落ちる。builder の根本原因 (1)（どの半径でも置けないとき、長さ0の `labels` を返す）が、既定の字での報告と、大きい字の狭い画面の両方を説明する。(2)（別の axes で測った値で組む）は、いまの呼び出し元（`ScienceThinkingResultExtra` は `useMemo` で軸を作り、数は5か0で0なら図を出さない）では起きないが、3→5 と変わると同じ所で落ちるので、部品として閉じておくのは正しい。`current.axes === axes` の比べ方は、同じ中身の新しい配列を受けても、最初の描画だけ図を出さず `useLayoutEffect` の中で測り直すので、描画の前に図が戻り、ちらつかない。

ほかに落ちる道: 幅 0（字の箱も 0）、`ResizeObserver` の無い環境、軸 0 本（`placeLabels` が空の配列を返し、`Math.min(-radius)` のまま組める）を読んだが、どれも落ちない。落ちたあとの状態を持ち越す所も無い。

### 図を描かないことは「壊れた図を黙って描く」ことになっていないか

なっていない。組めないときは SVG を出さず、`role="img"` の図そのものが無くなるので、読み上げにも中身の無い図は残らない。測りの字は `aria-hidden` のまま。画像 `sec-after-f48-w320.png` のとおり、見出し「あなたの思考プロフィール」のすぐ下にスコアの帯が5本、軸の名前と「22%」の形の値で並び、帯は見出しで名前が付いている。レーダーの形の読み取りは失うが、値はすべて帯にあり、300% の字の 320px で図を諦める PM の判断は妥当（WCAG 1.4.10 も2次元の配置が要る図を例外にしている）。`sec-after-f16-w375.png`・`sec-after-f32-w320.png` で、既定と 200% の図が前と同じ形で出ることも見た。

### ツギハギ

足したコメント（`layoutWithLines`・`layoutRadar`・部品の説明の「図の幅が軸の名前を置くのに足りなければ図を描かない。同じ値はスコアの帯が字で言っている」・`Measured`）は、いまの動きをそのまま言っていて、経緯の書き込みは無い。`sameFrame` から null の扱いが消えたのも、状態の形に合わせた書き直しになっている。

## 指摘

### 1. index.md の記録が、落ちる条件を「画面の大きさが変わると」と書いている【PM・小】

index.md の補足事項（302 行目）は「結果が出たあとに画面の大きさが変わる（端末を回す・窓を変える）と `RadarChart` が落ちて」としている。確かめた事実は違う。

- 落ちるのは、図の幅が補助の字の大きさのおよそ 6.9 倍より狭いとき。300% の字の 320px では、**大きさを変えなくても解き終えた瞬間に**落ちていた。既定の字では、実際の端末を回したり窓を変えたりしても落ちない（図の幅が 96px を切らない）。
- 既定の字での最初の報告は、Playwright の全ページ撮影がビューポートを一瞬 1×1 にする（図の幅 0）ことで起きていた。

このままだと、あとのサイクルで「回転で落ちる不具合があった」と読まれ、実際に結果を失っていた来訪者（大きい字の狭い画面）が記録から見えない。補足事項を、落ちていた条件・誰が失っていたか・既定の字の報告は撮影の道具による一時の幅 0 だったこと、に書き直す（サイクルの記録なので、書き直しの経緯を残してよい）。

### 2. 描き直しの試験の「描かない幅」の境目が、本当の境目と違う数で書かれている【builder・小】

`RadarChart を測り直す` の1つ目の試験は `if (width < 60) { svg が無い } else { 描く }` で期待を分けている。試験の測りの値（14px の字）で組めなくなる境目はおよそ 96px で、60 には意味が無い。いまの幅の列（266・0・400・40・320・0・266）には 60〜96 の値が無いので通っているが、読む人は境目が 60 だと受け取り、列に 80 を足すと誤った期待で落ちる。また、組める側の境目の近くを試していないので、「組めるのに描かない」向きの後退（たとえば null を返す条件を広げすぎる直し）は 266 まで気づけない。

- 期待をステップごとに書く形（`[[266, true], [0, false], [90, false], [100, true], …]` のように、描くかどうかを値で持つ）にし、境目の両側（90 と 100 のような）を入れる。`layoutRadar` の試験も、null の側（0・60・90）だけでなく、すぐ上の幅で組めることを1つ確かめる。
- `let figureWidth` に付いた説明「図の幅と、字1つあたりの幅（14px の字）。測りの字の幅は字数から出す。」は、変数でなく `stubMeasurement` の中身の説明になっている。説明を `stubMeasurement` に移す。
- 試しの `ResizeObserver` は `disconnect` しても `observers` から外さないので、effect が走り直すと古い `measure` も呼ばれる。いまの試験では結果に響かないが、`disconnect` で外すほうが本物に近い。
