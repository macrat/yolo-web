## 指摘

### 1. 添えた字は「名前の最後の行の右」には来ない。名前が2行以上なら、右に余りがあっても必ず下に落ちる

4-2 は「押した行には字を添える（名前の最後の行の右、入らなければ名前の下）」、「例外は1つで、名前の最後の行の右に添えた字が入らないときだけ、添えた字は名前の下の行に置かれ」と書き、5章 §6 の表の行も「添えた字が名前の最後の行の右に入らないときだけ、名前の下に置き」と書く。PM の決定もこの書き方を前提にしている。

ところが、この設計が決める組みでは、添えた字は名前の**箱**の右に並ぶ flex の要素である（`.choice` は `display: flex; flex-wrap: wrap`、4-4 の `column-gap: 8px`）。名前の箱は `max-width: 100%`・`flex-shrink: 0` を持つので、名前が2行以上に折れると箱の幅は行の中の幅いっぱいになり、添えた字は必ず次の flex の行（名前の下）に回る。最後の行がどれだけ短くても、右には来ない。

実測（上の組み。各問の最初の行と最後の行を押した 298 回）:

| 画面 | 添える字             | 名前の下に落ちた回 | そのうち名前が2行以上 | そのうち最後の行の右に字と 16px のあきが入る余りがあった回 | 右に入った回で、名前の字と添えた字の見えるあいだ（最小・中央・最大） |
| ---- | -------------------- | ------------------ | --------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------- |
| 320  | あなたの回答         | 206（69%）         | 166（2行以上の全部）  | 131                                                        | 19.5・101.1・152.1                                                   |
| 320  | あなたの回答は不正解 | 223（75%）         | 166                   | —                                                          | 17.0・45.8・96.8                                                     |
| 375  | あなたの回答         | 184（62%）         | 115（2行以上の全部）  | 101                                                        | 16.8・151.5・207.1                                                   |

- 2行以上の名前で、添えた字が右に入った回は 0 だった。落ちた回のうち 320 で 131 回は、最後の行の右に余りがあった。
- したがって、PM が受け入れた「例外」は、320 の診断ではいちばん多い形で、character-personality Q1 のように4つとも2〜3行の問では、どの行を押しても押した行が 26 伸び、その下の行が下がる。PM は「名前の最後の行に入らない、たまに起きる件」として受け入れたので、判断の前提が実際の組みと違う。§11「1つの操作に応える動きは1つだけ」から外れる回の多さを、設計が見積もっていない（AP-P02。例外が起きる頻度を、組みで確かめずに書いている）。
- `justify-content: space-between` が残るので、右に入った字は行の右端に寄り、名前の字との見えるあいだは 16px ではなく、上の表のとおり 17〜207px になる。4-4 の「名前の字と添えた字の見えるあいだを 16px（8 の倍数。§5）にする」は成り立たない。`column-gap` は最小のあきを決めるだけである。
- 知識クイズの答えたあとの形にも響く。1-3 と 4-6 の近似（review-t5a-design-1.md）は、いまの `.choiceText`（`flex-shrink` が既定の 1）で組んでいたので、名前が縮んで添えた字の横に並んでいた。この設計の組みでは、2行以上の名前の押した行と正解の行で、添えた字がそれぞれ下に落ち、答えたあとの形が最大で約 52 高くなる。4-6 の「最初の行から「次へ」の下端まで 378〜441 で、534 に入る」は、この分も、字の幅が狭くなる分（4-4 の「高さの算術」）も持たない。
- 別の組み方も1つ測った。添えた字を名前の `PhrasedText` の中の最後に、`<wbr>` のあとの `inline-block`（左の余白 16px）として置くと、320 では 149 問のうち 98 問で最後の行の右に入る（最初の行を押した回）。ただし落ちたときは名前の箱が1行伸び、名前が1行だった行では、箱の上下の中央に置かれていた字が 2.1px 上がり（149 問中 28 問）、落ちた字の頭が 16px 下がる。PM の決定（名前の位置は変えない）を満たさない。どちらの組みにも代償がある。

直すこと:

- 添えた字をどの要素のどこに置くかを 4-2・4-4 で決め、そのうえで、添えた字が名前の下に落ちる条件を、その組みで実際に起きるとおりに書く（いまの flex の並びのままなら「名前が1行で、名前の箱の右に入らないとき、または名前が2行以上のとき」）。5章 §6 の表の行と、`justify-content` をどうするか（行の右端に寄せるか、名前の後ろに 16px で置くか）もそろえる。
- 落ちる頻度（320・375 で押した回の何割か）を T5a-2 の近似で測る項目に入れ、4-6 の答えたあとの高さの見込みに、添えた字が落ちる分を入れる。
- 実際の頻度を添えて、PM に例外の受け入れを決め直させる（8章に、PM が選ぶ形で書く。上の2つの組みの代償と、全行に場所を取っておく案を並べる）。

### 2. 答えたあとの字の箱を掛ける要素が決まっておらず、`PhrasedText` の要素にじかに掛けると Firefox で字が列に割れる

4-4 は「答えたあとの字も `data-text-box="inline"` を持ち」、4-10 は「答えたあとの行の字（ボタンでない字）は `PhrasedText`（`as="span"`）で組む」、4-11 は「`.choiceText` を消し、`Button` と共有する箱の規則と `data-text-box="inline"` に替える」とする。箱（`display: inline-flex`）を `PhrasedText` の `span` にじかに掛けるのか、`Button` と同じく箱の要素の中に `PhrasedText` の `span` を入れるのかを書いていない。`PhrasedText` は `className` を受けるので、じかに掛けるのがいちばん自然な実装になる。

- `PhrasedText` の中は、文の字と `<wbr>` が交互に並ぶ。Firefox は flex の入れ物の子の `<wbr>` を flex の要素にする（[Bugzilla 1499348](https://bugzilla.mozilla.org/show_bug.cgi?id=1499348)。未解決。Chrome と Safari はしない）。じかに掛けると、Firefox では区切りのあいだの字がそれぞれ別の flex の要素になり、折り返さない1列の並び（`flex-wrap` は既定の `nowrap`）に縮んで並ぶ。
- Chromium で、`<wbr>` の代わりに flex の要素になる空の `span` を置いて確かめた（Firefox の扱いの再現）。「「もう少しだけ」と布団の中で、…思い描く」は、字が文節ごとの細い列に割れ、名前の字の位置も折り返しも `Button` と別物になった。`<wbr>` のまま（Chromium）では割れない。
- `Button` は `button`（箱）の中に `PhrasedText` の `span` を入れる形なので、`<wbr>` は flex の入れ物の子にならず、この件は起きない。同じ入れ子にすれば、Chromium の実測で位置も一致した（「確かめたこと」）。
- もう1つ、押す前（`button`）と押したあと（`span`）の字が同じ所に来ることは、Chromium でしか確かめていない。WebKit の `button` は中に名前の無い箱を1つ持って組む（`button` に固有の組み方）ので、`span` と同じになるかは別に確かめる必要がある。character-personality の結果に着いた回の 66% が WebKit である（1-1）。6章の測りはどれも Chromium で、8章の T9 に渡す項目にもこの比べが無い。

直すこと: 4-4 と 4-10 に、答えたあとの字は `Button` と同じ入れ子（箱の要素の中に `PhrasedText` の `span`）で組むと書く。8章の T9 に渡す項目と「PM が足す行」の3に、iOS の Safari の実機で、押す前と押したあとの名前の位置と折り返しが変わらないか（1行・2行以上・添えた字が落ちる行）を加える。

### 3. 見出しの字の幅を「W − 8」と書くが、見出しの W は行の中の幅ではない

4-4 の「高さの算術」は、直前の箇条で W を「行の中の幅」（320 で 250）と決めたうえで、「問の見出しの字の幅が 8px 狭い。…字の幅は W − 8 になる」と書く。見出しは選択肢の行の中に無く、左右の余白 16 を持たないので、見出しの字の幅はコンテンツ幅 266 から 8 を引いた 258 である（左へ 8 張り出し、左右に 8 ずつ余白。算術）。「8px 狭い」は正しいが、「W − 8」と読むと 242 になる。「コンテンツ幅 − 8（320 で 258）」と書く。

### 4. 添えた字の太さが決まっていない

いまの `.feedbackTag` は `font-weight: 700` を持つ。4-2 は添えた字を「§4 の補助情報の大きさで、`--ink`」とし、4-11 は「添える字を 4-2・4-4 の値にする」とするが、太さに触れないので、700 が残る。

- 6章 条件3 は「押した行が添えた字を持ち、太字でなく」と確かめさせる。添えた字が太字のままだと、この条件の読み方が割れる。
- 知識クイズでは、押した行と正解の行の2か所に太字が出る。`DESIGN.md` §4 は「太字は一段落に一箇所まで」とする。
- 太さは添えた字の幅を変え、名前の右に入るか落ちるか（指摘1）に掛かる。

直すこと: 4-2 と 4-11 で、添えた字の太さ（400 にするか、700 を残す理由）を決め、条件3 の「太字でなく」が名前のことだと分かる書き方にする。

### 5. `globals.css` の `data-text-box="inline"` の説明に、答えた選択肢の字が入らない

`globals.css` の `[data-text-box="inline"]` の規則の上の説明（409〜418行）は、`inline` を使うものを「縁が見えないもの（リンク・プライマリでないボタン・ページ送り・パンくず・ラジオボタンやチェックボックスの行・アコーディオン）」と並べる。T5a で、押せずフォーカスも受けない答えた選択肢の字がこの属性を持つようになり、5章が `DESIGN.md` §5 にもそのことを足すが、コードの説明は並びが古いまま残る。T5a-5 は `globals.css` を触るので、4-11 か T5a-5 の中身に、この説明の並びに答えた選択肢の字を加えることを書く。

### 6. 字の誤り

- 4-4 の「**余りは減りうり、**」は活用の誤り。「減りえ、」か「減ることがあり、」にする。
- 4-2 の「ボールドは字幅が広く」だけが「ボールド」で、文書のほかの所（4-2 の前の文・5章）は「太字」である。「太字は」にそろえる。
