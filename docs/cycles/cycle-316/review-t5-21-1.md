## 指摘

### 指摘1（planner → builder）: privacy の見出しの3段を、DESIGN.md に無い段で組んでいる。狭い画面で h2・h3・本文の区別が消える

privacy は h2（章9つ）の下に h3（「Google Analyticsによるアクセス情報」など5つ）を持つ3段の文書である。今回、h2 を §5 の「セクションの中の小見出し」（`--text-heading-sub`、上に細い線）にし、h3 をそのさらに下の `.minorHeading`（`--text-step-1`、`64rem` 以上で `--text-step-2`、線なし）にした。

1. **`.minorHeading` は DESIGN.md に無い段である**（AP-I08）。§4 の表のページの見出しは主見出し・セクションの見出し・セクションの中の小見出しの3段で、「1段下げて本文の大きさで止める」は §4 が Markdown のプレビューにだけ決めた組み方である。§5 は「セクションの中の小見出しは、上に細い罫線を引いて前の内容と分ける」と言い、線を持たない小見出しは「前に分ける内容を持たない」ときだけである。`.minorHeading` の「上に内容を持っても線を持たず」は、この規則の外の形をページの CSS で作っている。
2. **来訪者に見える損**: `45rem` 未満（320・375px）では `--text-heading-sub` も `--text-step-1` も 17px で、本文も 17px である（`results.json` の fontSize も h2・h3 とも 17px、200% では両方 34px）。
   - 「収集する情報」（h2）と「Google Analyticsによるアクセス情報」（h3）は、同じ大きさ・同じ書体で、違いは h2 の上の細い線だけ。
   - 「Google Analytics」「Google AdSense」（h3）は和文を含まないので、見出しの欧文の書体（IBM Plex Sans・400）で組まれ、本文とまったく同じ字に見える。375px の切り出しでは、見出しなのか1行の段落なのか見分けられない。
   - 前（HEAD）の 375px では h2 が 1.49rem（約 24px）で、章の頭が一目で分かった。今回それが本文と同じ大きさに下がり、9章ある規約文を狭い画面で拾い読みしにくくなった。
3. これは t5-design.md 8-a の「本文の見出しの段」の表で「`##` を小見出し、`###` をそれより下の段 — 捨てる。§4 の小見出しの段は `45rem` 未満で本文と同じ大きさで、その下の段が無い」とした形と同じである。9-b は about と privacy をまとめて「見出しの下線を小見出しの形に」としたが、privacy の h3 を見ていない。

**直し方**（9-b を planner が書き直し、builder が組む）: privacy の h2 の章を `Section` に分け、h2 をセクションの見出し（全幅の罫線と §4 の段。page の CSS で大きさを持たない）、h3 をセクションの中の小見出し（§5 どおり、前に内容を持つもの＝「Google AdSense」は上に細い線、章の見出しのすぐ下のものは線なし）にする。DESIGN.md に無い段が消え、狭い画面でも章の見出し（1.49rem）・小見出し（1.0625rem・線）・本文が見分けられる。1ページのなかの格子の形（§1）も、ほかの面（7-e の詳細のページ、8-a の記事）と同じ文法になる。最初のセクションには h1 と冒頭の2段落を置く（「はじめに」を、主見出しのすぐ下の線を持たない小見出しとして残すか、見出しを外すかは planner が決める）。

about は見出しが2段（h1 と h2 だけ）で、今回の「1つのセクション＋小見出し」は §4・§5 の中に収まっている。about はこのままでよい。ただし、privacy を上の形に変えるとき、about の h2 も同じ理由（狭い画面で章の見出しが 20px から 17px に下がる）でセクションにするほうが来訪者に良いかを、planner は 9-b の中で比べて書くこと（どちらに決めても、決めた理由を 9-b に残す）。

### 指摘2（builder）: privacy の本文の中のサイト内リンクが `<a>` のまま

`src/app/privacy/page.tsx` の「このサイトについて」（`/about`）は `<a href="/about">` で、about の「ブログ」「プライバシーポリシー」は `next/link` の `Link` である。`<a>` だとページ全体を読み直し、先読みも効かない。今回の変更で持ち込んだものではないが、同じ2つのページを組み直すタスクの中で、兄弟のページとそろえて `Link` にする。外へのリンク（Google・GitHub）は `<a>` のままでよい。

## とくに見てほしいと言われたこと: 200% の privacy の h1 の「ー」だけの行

320px・200%（ルート 32px、h1 66.56px、コンテンツ幅 266px）では1行に3字しか入らない（4字で 266.24px）。「プライバシー」（6字）も「ポリシー」（4字）も1行に収まらない文節なので、どの組み方でも文節の中で割れる。「ポリシ／ー」は、§4「文字を大きくしたとき（200%）は、1行に収まらない文節の中の折れから出た1字だけの行と禁則の破れを受け入れる」にそのまま当たる。

文節の区切りを変えて避ける道は無い。

- 「ポリ／シー」の区切りを並びに入れると、§4 の「折り所には優先の順が無く、文節が1行に収まる広い画面でも行の終わりに来れば使われるので、そこで折れても語が割れない所に限る」に反する。「ポリシー」は1語で、しかも「いちばん狭い画面の1行（全角6字ほど）より長い文節」でもないので、中に折り所を持たせる理由も無い。
- 「ー」が行頭に来るのは、PhrasedText の `overflow-wrap: anywhere` の非常の折りが `line-break: strict` の禁則を見ないためで、サイト全体の部品の仕組みである。§4 はこの場合の禁則の破れを受け入れると決めている。
- 見出しの文言を変えるのは、§4 では既定の文字サイズで避けられないときの手当てで、200% では求められていない。「プライバシーポリシー」は来訪者が探す決まった呼び名で、変えると損が大きい。

したがって、この折れは受け入れてよい。about の 320px・200% の h1 の「この／サイト／に／ついて」（「サイトに」が1行に入らず「に」だけの行ができる）も同じ理由で受け入れられる。builder の報告は「など」とまとめていたので、完了の記録にはこの2つを名指しで書くこと。375px・200% の「プライバ／シー／ポリシー」と、1280px・200% はどれも §4 の内にある。
