## 指摘

### Minor-1 `ContrarianFortuneContent` の冒頭のコメントに、出さない理由が残る

- 冒頭のコメントの「核心の一文（coreSentence）は、呼び出し側が置く説明と同じ「一般的な占いなら…ですが」の話を縮めた文で、説明のすぐ後に続けると同じことを2度言うので置かない」は、部品がいま何を並べるかではなく、並べないものとその判断の理由で、CLAUDE.md の「ツギハギ禁止」（理由や経緯はサイクルの文書に置く）に当たる。理由は index.md の補足にすでにある。T4-9 で `coreSentence` を消すと、無い値を指すコメントとして残る。この段は消し、コメントは並べるものの説明だけにする
- 同じく、テストの冒頭の「説明と重なる coreSentence を出さないこと」と `it("説明と同じことを言う coreSentence を出さないこと")` は、データに値が残るあいだは意味があるが、T4-9 で値を消すときに一緒に消すことを、T4-9 の作業に書き足しておく（index.md の補足の1行に足せば足りる）

### Minor-2 共有の文が短い名前を使うことを、テストが確かめていない

- `src/app/play/[slug]/result/[resultId]/__tests__/page.test.tsx` の「ページの題と共有の文」のテストの診断は、どれも `shortTitle` を持たないので、`shortTitle ?? title` を `title` に戻しても通る。`shortTitle` を持つ診断（前からある「あなたの言葉センス診断」の模型など）で、共有の文の診断名が短い名前になり、ハッシュタグは `title` のままであることを1件足す

### Minor-3 決まった文に `headingFontAttr` を通している

- `headingFontAttr` は「データから描く見出しの文字列」に使う関数で、`ReadingHeading` の `headingFont` の説明も「データから来る見出しは…渡す」と言う。character-fortune の `headingFontAttr(THIRD_PARTY_HEADING.join(""))` と、汎用のルートの `readingHeading` が既定の並びにも `headingFontAttr` を通す所は、コードに書いた決まった文なので、見出しの書体で組めることは書き手が知っており、いつも `{}` を返す。読む人が「この文は書体に無い字を含みうる」と読み違えるので、決まった文には渡さず、言い替えた文（データ）のときだけ渡す形にする
