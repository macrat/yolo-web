## 指摘

### Major-1: 描く時間のテストが、負荷の掛かった実行で落ちる

`share-image.test.tsx` 487行は、`beforeAll` で1枚ずつ描いた壁時計の時間（`performance.now()`）が1000ms 未満であることを確かめている。スクラッチで同じ入力を3回ずつ描いて、壁時計と CPU の時間（`process.cpuUsage`）を測った:

| 入力                   | 壁時計（1回目/2回目/3回目） | CPU（同じ）        |
| ---------------------- | --------------------------- | ------------------ |
| 69字のブログの題       | 872 / 276 / 129 ms          | 551 / 209 / 101 ms |
| 67字の SEO の題        | 93 / 75 / 154 ms            | 90 / 86 / 112 ms   |
| guardian-charger・35字 | 189 / 152 / 164 ms          | 87 / 52 / 50 ms    |
| とても長い語…          | 221 / 156 / 139 ms          | 145 / 108 / 105 ms |

落ちる訳は2つある。

1. **いちばん初めの入力が、和文の書体を初めて使う分の時間を背負っている。** 温めの `renderShareImage({ name: "yolos.net" })` は欧文（IBM Plex Sans）しか使わない。`INPUTS` の1つ目の `longestBlogTitle` が Zen Antique と BIZ UDPGothic を初めて通すので、同じ入力が2回目には3分の1以下になる。このテストは「1枚描く時間」ではなく「最初の1枚の温まりの時間」を測っている。t6-log.md の表の「896ms」も同じ温まりの数。
2. **壁時計は、ほかのテストのファイルが同じ CPU を使うだけ伸びる。** 1ファイルだけなら通り、20ファイル並べると 1778ms、PM の実行では 4.06s になった。CI の `npm test` は全部のファイルを並べて走らせる。

こういう時間の検査は、落ちたときに誰の変更のせいでもなく、デプロイを止め、やがて「また時間のテストか」と無視されるようになる。今のうちに、描き方が遅くなったときにだけ落ちる形にする。

直すこと（builder）:

- 温めの1枚を、4つの書体（IBM Plex Sans・Zen Antique・BIZ UDPGothic・BIZ UDGothic）と、補助情報・数字の結果・名前・読み・副題・色見本のどの段も通る中身にする。
- 描く時間は CPU の時間（`process.cpuUsage()` の差）で測り、同じ入力を数回描いたうちのいちばん短い値を使う（ほかのプロセスとの取り合いと GC の揺れを外すため）。上限の1秒は t6-design.md の完了の条件のままでよい（温まった後の CPU の時間はどれも 250ms 未満なので、描き方が数倍遅くなったときにだけ落ちる）。
- 直したあと、`npm test` を全部のファイルで2回走らせて、このテストが落ちないことを確かめる。
- t6-log.md の「描く時間」の列を、同じ測り方の数に取り替え、測り方（温めの後の CPU の時間の最小）を1行で書く。

### Minor-1: 1行に収まらない単位を字で割るとき、行の頭に「？」「、」「」」「ー」が来る

（PM から追加で頼まれた確かめ。）

`breakUnits` は、1行に収まらない単位を字の範囲のまとまりに、それでも収まらないまとまりを1字ずつ（`graphemes`）に分け、`fillLines` が前から詰める。1字ずつの所には禁則が無い。スクラッチで補助情報に `"カ".repeat(k) + 末尾 + "です"` を渡して組むと、k=58 と k=87 で、末尾の「？」「、」「」」「ー」のどれもが次の行の頭に来た（`["カカカ…","カカカ…","？です"]`）。

§4 は、見出しの行頭の禁則を厳しい側（`line-break: strict`）で組むとしている。ブラウザは文節の中を字で割るときも行頭の禁則を守るので、ここでは画像が画面より悪い。いまのブログの題では起きないが、T6-3 以降で道具の説明や補助情報の長い片仮名・欧文の語（「…!?」など）がこの道を通る。共有の描き方を作ったこのタスクで直す。

また、画像の側の禁則の字の定義が `phrase-breaks.ts` と2か所に分かれている。`share-image.tsx` の `CLOSING_BRACKET` は `phrase-breaks.ts` の同名の正規表現と同じ字の写しで、`NO_BREAK_BEFORE` は `phrase-breaks.ts` の `NO_LINE_START`＋`STARTS_WITH_DASH` の一部だけ（小書きの仮名・「：；」・「々」などが無い）。前回 `parenDepthAfter` を1か所にしたのと同じ理由で、1か所にする。

直すこと（builder）:

- `phrase-breaks.ts` から、行の頭に置かない字・行の終わりに置かない字・直後で折れる閉じ括弧の判定を出し、`share-image.tsx` はそれを使う（写しを消す）。空白の後ろで割らない判定（`NO_BREAK_BEFORE`）も、この判定とダッシュの判定で書く。
- 字で割るとき（`graphemes` にした所）、行の頭に置かない字は前の字に付け、行の終わりに置かない字は次の字に付けた塊にしてから詰める。
- テスト: 上の形の補助情報（字で割られる長さを、組みの幅から決めて作る）と、名前の字で割られる欧文の語の後ろの「!?」で、どの行も行の頭に置かない字で始まらず、行の終わりに置かない字で終わらないこと。
