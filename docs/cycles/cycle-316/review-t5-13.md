## builder が自分で決めたことの判断

1. **セクションの見出し「この言葉を評価」「この言葉を共有」「ほかの言葉を探す」**: どれも採れる。
   - 共有の見出しは、t5-design.md 7-e の「この漢字を共有（四字熟語・伝統色・ユーモアも同じ言い方）」に沿う。
   - 「言葉」は一覧の名乗り（「身近な言葉を、AIが…」）と同じ語で、来訪者が一覧で読んだ呼び方とそろう。
   - 「この言葉を評価」は、面「おもしろかった」の1つのボタンと合わせて、押すと何が起きるかが読める。
   - 「ほかの言葉を探す」は、リンク「ユーモア辞典の一覧へ」の行き先と食い違わない。
   - 200% では「この言葉を／評価」「この言葉を／共有」「ほかの／言葉を探す」と、どれも文節の切れ目で折れる。1字の行・禁則の破れ・はみ出しは無い。
   - 1つのセクションに1つのコントロールだけを置く形は、伝統色の「関連ツール」と同じで、§5 のページの割り方に沿う。
2. **読みの【】を外したこと**: 採れる。§4 のとおり、読みは見出しの外に出して補助情報として添える形になった。補助情報の大きさ 14px・`--ink-2` で h1 の 8px 下に置き、伝統色の読み（ローマ字）と同じ組みである。
3. **戻るリンクの矢印「←」を外したこと**: 採れる。どのページのリンクも矢印を持たず、操作は下線が示す（§1 の3）。読み上げで「左矢印」と言わせることも無くなった。
4. **blockquote を段落にしたこと**: 採れる。定義と用例は、どこかから引いた文でなく、この項目の本文である。§5 の引用（左の細い線で字下げ）にすると、引用でないものを引用と読ませる。前の「用例」の `--ink-2` の字も、§2 の「前に出ない文字」に当たらない中身に掛かっていたので、`--ink` に戻ったのは正しい。辞書の形（見出し語・読み・語釈が続けて並ぶ）として自然に読める。
5. **`EntryRatingButton` の `.wrapper` の上下の余白を外したこと**: 採れる。この部品を使うのはこのページだけである（`src` を grep して、テストのほかには `page.tsx` の1か所）。外したあとの間隔は、1280 では見出しの下 16px・セクションの下 48px、320 では見出しの下 16px・セクションの下 32px になり、ほかのセクションと同じ値である。外さなければ、ボタンの上に 24 + 16px、下に 32 + 48px があいていた。注記は、いまの置き方だけを書いている。

## 指摘

1. **パンくずの下に、辞典の名乗りの一言が無い。ほかの3つの辞典の詳細と形がそろわず、検索から項目に直に来た来訪者に、定義が冗談であることが伝わらない。**
   - 漢字・四字熟語・伝統色の詳細は、`DictionaryDetailLayout` がパンくずのすぐ下に名乗りの一言を置く（伝統色なら「日本の伝統色250色のカラーコードと色見本をすぐ確認できる」。補助情報の大きさ）。そのため、どの詳細でも h1 は 1280 で y=189 に立つ。ユーモア辞典の詳細だけがこれを持たず、h1 が y=147 に上がる。辞典から辞典へ移ると、同じ働きの頭が違う形になる（§12 位置の一定）。
   - 来訪者にとって大きいのは中身のほうである。一覧のページは「身近な言葉を、AIがまじめな顔で定義し直しました。本当の意味ではありません。」と名乗る（`HumorListView.tsx` 42行目）。ところが、来訪者の多くが着く詳細のページには、この一文が無い。「Wi-Fi」「パスワード」の定義を、まじめな語釈と受け取る来訪者がいうる（constitution の 2・3）。
   - 直し方: パンくずのすぐ下に、ほかの辞典の詳細と同じ組み（`DictionaryDetailLayout` の `.head` の `.valueProposition`。補助情報の大きさ・`--ink-2`・本文の幅・上下 16px）で一言を置く。文は一覧の名乗りと同じ出どころにし、一覧と詳細で食い違わないようにする（たとえば `humorDictMeta` に持たせ、`HumorListView` もそこから読む）。
   - 置いたあとは、320・375・1280 の既定と 200%、ライトとダークで、h1 の上端がほかの辞典の詳細とそろうことを撮って確かめる。テストに、一言がパンくずと h1 のあいだにあることを1本足す。
