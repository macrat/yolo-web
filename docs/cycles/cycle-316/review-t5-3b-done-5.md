## 指摘

### 1. （小）layout-shift と `scroll` が出るかは、Chromium の種類でなく、ページがマウスの入力を受けたかで決まる。見出しだけの選択でも出る

`docs/knowledge/clipboard-and-copy.md` の 2 は、「Playwright の headless shell では、ページ全体（Ctrl+A）を写すと……layout-shift の記録が 2 件出て……`scroll` の出来事が 2 回来る。Chromium の本体（`chromium`。新しい headless）では、どちらも出なかった」と書き、根拠に「見出しだけと段落までの選択で 0 件」「同じ `chromium-1194` の 1280px で見出しだけを写すと、layout-shift の記録は、字を 100ms 除いたままにする対照で 2 件出て、受け手では 20 回写しても 0 件だった」と書いている。

自分のビルドを `/opt/pw-browsers/chromium`（`chromium-1194`、Chrome 141.0.7390.37。`Browser.getVersion` で確かめた）と `chromium_headless_shell-1194` で開き、記事 `nextjs-global-not-found-for-multiple-root-layouts` で、写す前のマウスの入力の有無を分けて測ると、次のとおりだった（どれもコピーのたびに同じ値。3回ずつ）。

| 場面                                                         | 本体・マウスの入力なし | 本体・マウスの入力あり（ページを1度押す、または h1 を3度押して選ぶ） | headless shell（どちらでも） |
| ------------------------------------------------------------ | ---------------------- | -------------------------------------------------------------------- | ---------------------------- |
| 見出しだけ・1280px の上端                                    | 0 件                   | 2 件（0.118・0.104）                                                 | 2 件（0.118・0.104）         |
| 見出しだけ・375px の上端                                     | 0 件                   | 2 件（0.024・0.018）                                                 | 2 件（0.024・0.018）         |
| Ctrl+A・1280px の上端                                        | 0 件                   | 2 件（0.118・0.104）                                                 | 2 件（0.118・0.104）         |
| Ctrl+A・375px の上端                                         | 0 件                   | 2 件（0.024・0.018）                                                 | 2 件（0.024・0.018）         |
| Ctrl+A・1280px で 3000px 送った所の layout-shift と `scroll` | 0 件・0 回             | 2 件（0.044・0.044）・2 回（2918 → 3000）                            | 2 件・2 回（同じ値）         |

どれも `hadRecentInput: true` で、CLS には数えない。マウスの入力が無いときも、Ctrl+A の選択（11,980 字）とコピーの出来事（1 回）とクリップボード（11,971 字、語結合子 0）は同じで、違うのは記録が出るかだけだった。見出しだけを写す 20 回（本体・マウスの入力あり）では、受け手で 40 件（0.118・0.104 が 20 組）、100ms 除いたままにする対照で 2 件（同じ値）で、layout-shift の記録では受け手と対照を見分けられない。

来訪者は、字を選ぶときにマウスか指を使うので、本体でも「マウスの入力あり」の列になる。いまの文書を読んだ人は、来訪者の Chrome では layout-shift も `scroll` も出ず、見出しだけの選択なら一瞬の組みも外から見えないと受け取る。逆で、どちらの種類でも、見出しを含む選択を写すたびに記録が出る（第3回の「見出しだけは 0 件」も、第4回の「本体は 0 件」も、マウスの入力の無い測りと読める）。

描いた画面が変わらないことは、自分の測りでも成り立つ。本体・マウスの入力ありで CDP の screencast を取ると、コピーのあとの枠は、h1 を3度押して選んだときは 1280px・375px とも前の枠と画素が同じで、Ctrl+A は 1280px で同じ・375px で 1 画素（26, 26）だけ違い、1280px で 3000px 送った所の Ctrl+A も同じだった。受け手を止めると、コピーのあとに枠は出なかった。

直すこと:

- 2 の「除いたあいだの DOM は外から見える」の項を、「見出しを含む選択を写すたびに、layout-shift の記録が 2 件出て、送った所では `scroll` が 2 回来る（どちらの種類でも。本体では、ページがマウスの入力を受けていないと記録が出ないので、測るときはページを押してから選ぶ）」という形に直す。
- 2 の根拠の「見出しだけと段落までの選択で 0 件」「受け手では 20 回写しても 0 件」「`chromium-1194` では……layout-shift も `scroll` も 0 件」を、上の測り（review-t5-3b-done-5.md）に置き換える。「描く前に戻るので描かれない」の根拠は、layout-shift の記録でなく screencast の枠にする（対照は h1 の組みが変わった枠を出し、受け手は出さない）。
- 本体で layout-shift の記録がマウスの入力の後にだけ出ることは、この組み方に限らない測り方の落とし穴なので、`docs/knowledge/` の Playwright か測り方の文書（`playwright-mcp.md` か `research-and-verification-techniques.md`）にも1項として書く。第3回・第4回とこのレビューの食い違いは、測った条件を記録に残さなかったことから来ている。

### 2. （小）スキルの「見えない字は語結合子にする」の項が、`WORD_JOINER` を使うことを言っていない

第4回の指摘 3 で、置く所（`joinDashes`・`keepTogether`）と除く所（`WordJoinerCopyFilter`）は、どれも `@/lib/phrase-dashes` の `WORD_JOINER` を読むようになり、結び付きがコードから読めるようになった。ただ、次に見えない字を置く人が読む `frontend-design` スキルの項は「語結合子（U+2060）にする」とだけ言うので、`"\u2060"` をその場で書いても規則に合って読める。項に「`@/lib/phrase-dashes` の `WORD_JOINER` を使う」を足す（知見の文書の 1 の、受け手が除くのは U+2060 だけ、の文にも同じことを添えるとよい）。
