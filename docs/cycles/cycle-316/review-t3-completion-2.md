## 指摘

### Minor-1: 文字サイズ 200% の広い画面で、「次へ」とページ番号が、ページによって最大 51px 左右にずれる

- **どこで**: ページが9以上ある一覧（漢字辞典のトップ22ページ・学年7の12ページ・10ページを超える学年や画数）の、番号の並びを出す幅（38rem 以上。文字サイズ 200% では 1216px 以上）のページ送り。`src/components/Pagination/Pagination.module.css` の `.pageItem`。
- **何が起きるか**: `.pageItem` の最小の幅は 44px（px で固定）で、既定の文字サイズでは2桁の番号も 44px に収まる。文字サイズ 200% では、1桁の番号は 44px のままだが、2桁の番号は字が 32px になって 56.8px に広がる。7つの枠に並ぶ2桁の番号の数がページごとに変わるので、その後ろの番号と「次へ」が動く。1280px・200% で測ると、漢字辞典の「次へ」の箱の左端は 444（1〜8ページ）・457（9ページ）・470（10ページ）・482（11〜18ページ）・495（19〜22ページ）の5通り、学年7では 444（1〜8ページ）と 470（9〜12ページ）の2通りになる。四字熟語（8ページ）・ブログ・伝統色は1桁だけなので動かない。
- **来訪者にどう効くか**: 文字を大きくして使う人が「次へ」を続けて押すと、9ページ目で「次へ」の字の頭（465 前後）を押したあと、10ページ目では同じ所に最後のページの番号「22」の箱（412.8〜469.6）が来る。2打目で最後のページへ飛ぶ。前回の Minor-1 と同じ形の失敗が、文字を大きくする来訪者にだけ残っている。§12「位置の一定」と、`PaginationNav.tsx` のコメント（「前へ」・番号・「次へ」の位置をどのページでも同じにする）に、200% では届いていない。§12 は文字サイズ 200% を「拡大と上書き」の条件に挙げており、文字を大きくしている来訪者はまさにタップの位置の狂いに弱い。
- **直し方の方向**: 番号の箱の最小の幅を、その一覧の最も大きい番号（総ページ数）の桁の字の幅と字の箱の余白で決め、44px と大きいほうを取る（`ch` で持つか、狭い画面の「n / N」がすでに使っている、最も広い番号の幅で場所を取る組み方と同じ考え方）。「…」も同じ幅にする。直したら、1280px の 200% で漢字辞典の1〜22ページと学年7の1〜12ページの「次へ」の x が一覧ごとに1つになること、既定の文字サイズの値（「次へ」の箱 539.1）が変わらないか変わったなら記録を直すことを測り、t3-completion.md に書く。
