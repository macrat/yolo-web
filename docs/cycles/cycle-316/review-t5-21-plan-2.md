見出しの段の組み方（章ごとに `Section`、h2 をセクションの見出し、h3 を §5 の小見出し）は前回の指摘1の問い（DESIGN.md に無い段を作らず、狭い画面でも章・節・本文が見分けられること）にまっすぐ答えている。privacy の3案の比較、about の2案の利点と欠点、200% で受け入れる折れの名指しも十分で、builder が行と 9-b だけで組める。直してほしいのは、今回新しく決めた見出しの文言（指摘1）と、1か所の書き方のあいまいさ（指摘2）の2つだけ。どちらも小さく、計画の骨組みは変わらない。

## 良い所

- **§4・§5 に合っている。** h1・h2・h3 が §4 の3段にそのまま当たり、§4 に無い段が消える。`45rem` 未満でも章の見出し 23.84px・小見出し 17px（見出しの書体・行間 1.25・前に内容があれば細い線）・本文 17px が見分けられる。小見出しの線の有無（章の見出しのすぐ下の2つは線なし、前に内容を持つ3つは線あり）は §5「前に分ける内容を持たない小見出しは、線を持たない」どおりで、どの h3 がどちらかも名指ししてある。
- **§3 の読み方が正しい。** 欧文は見出しでも IBM Plex Sans（400）なので、和文を含まない「Google Analytics」「Google AdSense」は `45rem` 未満で本文と大きさも字も同じになる。前回のレビューで 375px の切り出しで見分けられなかった点を、書体の規則までさかのぼって説明しており、見出しに和文を含める理由として十分である。
- **「はじめに」を外す判断は妥当。** 主見出しのすぐ下で線を持たない小見出しが「はじめに」と言うだけで、中身は文書の頭書きである。about の冒頭の一言と同じ形になり、兄弟の文書の形がそろう。見出しの移動先を指すリンク（`/privacy#…`）もリポジトリに無い。
- **about も同じ形にする判断は、比較の書き方が良い。** 前回の依頼どおり、B の利点（ページが短い、1280px で短い章に大きな見出しが立たない）も書いたうえで、狭い画面で章の見出しが 20px から 17px に下がる損と、兄弟の文書の組み方の食い違いを比べている。
- **完了の条件が測れる。** `Section` の数・2つ目からの頭の要素・`getComputedStyle` の大きさ・`data-heading-font` の有無・線の数と色・`Link` の有無がどれも機械で数えられ、見た目で見るもの（375px の既定の切り出しで h3 と1行の段落を並べる、撮影の組み合わせ）も場所と幅が決まっている。200% の折れは、受け入れる2つを名指しし、ほかに出たら名指しで記録すると決めていて、前回の「など」でまとめる問題が起きない。
- **T7 との関係に問題は無い。** index.md の T7 は「来訪者が読む UI の文言」と名指しの項目を受け持つが、privacy の見出しは名指しの項目に無い。T5 が組み方の理由で文言を決める先例（url-encode の選択肢の名前を短くする、7章の表）もあり、§4 の規則（書体で見分けられない見出しを直す）から来る変更なので T5-21 の範囲でよい。about の文言は B-746（about の作り直し）に残すという棚卸しの線引きとも食い違わない（about の文言は変えていない）。
- **ツギハギは無い。** 9-b は「本文の列」「見出しの段」の2つの小見出しで分かれ、前の計画（1つのセクションに積み h2 を小見出しにする）の痕跡や「前回は」の類の書き方が残っていない。T5-21 の行も新しい形だけを言う。

## 指摘

### 指摘1（planner）: 新しい h3 の文言が、同じページのほかの h3 と2字しか違わず、AdSense の見出しは本文より強く言い切る

9-b は第三者サービスの章の h3 を「Google Analyticsによるアクセス解析」「Google AdSenseによる広告配信」に決めたが、言い換えの案が1つしかなく、次の2つを見ていない。

1. **「収集する情報」の章の h3「Google Analyticsによるアクセス情報」と、末尾の2字（情報／解析）しか違わない。** 9章の文書を拾い読みする来訪者（とくに「Google Analytics を止めるには」を探す人）は、見出しの頭の「Google Analyticsによるアクセス」で目を止めるので、2つの節を取り違えやすい。オプトアウトの案内があるのは第三者サービスの章のほうで、取り違えると目当ての段落に届かない。前の見出し（「Google Analytics」）は言い換えで和文を得たが、そのぶん隣の章の見出しに近づいた。
2. **AdSense の見出しが、本文と今のサイトより強く言い切る。** 本文は「第三者配信の広告サービス（Google AdSense）を利用することがあります」で、リポジトリには AdSense の広告のコード（`adsbygoogle`・`pagead2`・`ca-pub`）が無い（いまは配信していない）。「Google AdSenseによる広告配信」は、この節が話題として扱うことを言うつもりでも、広告が出ているかのように読める。プライバシーポリシーは来訪者が自分の情報がどう扱われるかを確かめる文書なので、見出しが本文より強く言わないほうがよい。

**直し方**（9-b に言い換えの比較を足す。AP-P17）: 次の条件で2〜3案を比べ、採った文言と理由を 9-b に書く。T5-21 の行と完了の条件の文言もそれに合わせる。

- 和文を含み、§3 の見出しの書体で本文と字の形が分かれる（いまの理由のまま）。
- 同じページのほかの見出し（とくに「Google Analyticsによるアクセス情報」）と、見出しの前のほうの字で見分けられる。
- 本文より強く言わない（AdSense は「利用することがある」）。

案の例（決めるのは planner）: サービスの名前を頭に置いて用途を和文で添える形（「Google Analytics（アクセス解析）」「Google AdSense（広告）」など。§4 の丸括弧の一続きの規則がかかるので、320px の既定で括弧の中が1行に収まることを確かめる）。あるいは「収集する情報」の側の h3 を、何を送るかを言う形に変えて2つを離す。どの案でも、見出しの折れ（既定で1字だけの行と禁則の破れが0）を完了の条件で測ることは変わらない。

### 指摘2（planner）: 「ページの CSS は見出しの大きさと線を持たない」が、h3 の細い線と読み合わない

9-b の A の組み方の2つ目の項目は「ページの CSS は見出しの大きさと線を持ちません」、T5-21 の行は「（大きさは globals.css の段のまま。ページの CSS は見出しの大きさと線を持たない）」と書く。ところが、すぐ次で h3 の上の細い線（`--rule-w-hair`・`--rule-2`）を求めており、globals.css にこの線の共通の規則は無いので、線を引くのはページの CSS である（結果のページ10本と同じ先例）。文字どおりに読む builder は「線を持たない」と「上に細い線」のどちらを守るかで迷う。完了の条件は「h2 は線を持たない」「ページの CSS に見出しの `font-size` が無い」と正しく書き分けているので、本文の2か所も同じ区別にそろえる（例: 「ページの CSS は見出しの大きさを持たず、h2 に線を引かない。線は h3 の上の細い線だけ」）。
