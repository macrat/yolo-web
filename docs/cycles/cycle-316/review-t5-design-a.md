## Major

### Major-1. 目次の列をやめる決定（8-a・8-b・8-c）が、目次で移る使い方を失い、それを避ける案を比べていない

- **事実**: いまの 1280px では、目次は本文の右の `position: sticky`（`top: 16px`）の列で、読み進めてもずっと画面にあります（測った2記事で 11項目・21項目。3000px 送っても上から 16）。D にすると、目次は記事の頭にしか無くなり、読み進めたあとで別の章へ移るには記事の頭まで戻ることになります。ブログの記事の来訪者の 89.1% は PC です。
- 設計は「D の損」に「本文を読み進めると目次は画面の上に残ります」と書いていますが、比べる表の「来訪者の側」の列には「PC で目次を見るには1回押す」とだけあり、読みながら章へ移れなくなる損が比べる材料に入っていません。
- 採る理由は「全ページで同じ罫線の格子と、ずれない最初の画面」ですが、ずれない最初の画面は C でも得られます（設計の表でも C は「どの幅でもずれない」）。C を捨てる理由は、罫線が列を貫くこと（見た目の規則）と HTML が2つになること（作り方の都合）です。つまり来訪者が失うもの（読みながら移れる目次）と引き換えにしているのは §1 の格子だけで、その重さを来訪者の側から比べていません。CLAUDE.md の「実装の量でなく来訪者の価値で選ぶ」と、AP-P17（案を並べる）・AP-P28（見た目の一律化のために中身を落とす）に当たります。
- **求めること**: 読みながら移れることを残す案を、少なくとも1つ表に足して比べてください（例: 閉じた目次を読み進めても画面の上に留める、`##` のセクションの頭から目次へ戻る道を置く、広い画面で罫線と両立する目次の置き方）。その案を捨てるなら、来訪者の側の理由を書いてください。目次がどれだけ使われているかを示すデータ（いまは目次のクリックのイベントが無い）が無いことも、判断の材料として書いてください。結論が D のままでも構いませんが、9章の §5 の文「本文の横に目次の列を置かない」は、この比べの結論が出てから書いてください。

### Major-2. 長い値の規則（10-d・10-e と 9章の §8・§4）に、成り立たない前提と範囲のあいまいさがある

1. **UNIX 時間の (3)「区切りを入れず、値に行の幅を渡す」**: 設計は「区切りの無い13桁は 200% の 320px でもボックスの幅に入る」とします。しかし入るのは、いまの `code` の 0.875em（28px）のときだけです。§8 の結果の値の最下段は本文の大きさで、34px にすると Plex Sans でも等幅でも 265px になり、ボックスのコンテンツ幅 244px に入りません。値の並び（表）の値の列はこれより狭くなります。そうなると、(3) と「数字を折るのは桁区切りの位置だけ」が同時には成り立たず、はみ出すか桁の途中で折れるかのどちらかになります（§12 の 200%）。値の大きさを決め、それでも入らないときの組み方を規則に書いてください。10-d の B を捨てる理由の「棚卸し 10-10 は本文の大きさで測った値」も、unix-timestamp については 28px で測った値なので、直してください。
2. **§8 の書き換えの「2進と16進は4桁ごと」**: この文だけを読むと、16進で書いたハッシュ値や色のコード（「#1a2b3c」）にも空きを挟むように読めます。10-e はハッシュ値を「符号にした文字列」としているので、§8 の文を「数（量）を2進・8進・16進で書いたもの」のように、範囲を言う形にしてください。
3. **§4 の日時の文字列**: 「符号にした文字列」の項の中に続けて書くと、日時が符号の一種に読めます（規則は逆で、折る所を限っています）。独立した項にしてください。あわせて、日付の塊（「2024-01-01T」）が1行に入らないときの扱いも書いてください。

### Major-3. 9章の `DESIGN.md` の文のうち、そのまま書くと食い違うもの

- **§4 のラベルの項**: 置く場所を「「表のセルは文節で折る。」の項の前」とし、名前に括弧で数を添えたラベルは「下の項に従う」と書いています。しかし「名前に括弧で数を添えたもの」の項はそれより上にあります。また、§4 の導入文「次の3つは…」の数が変わることに触れていません。ボタンの面の字（「パスワード生成」など）が「コントロールのラベル」に入るかどうかも書かれていません。
- **§5 の頭の位置**: 「その頭にパンくずを置く」と書いていますが、パンくずを持たないページ（トップ・404・410）があります。書いたとおりに読むと、それらのページは規則に反します。どのページにもかかる1つの規則になるよう書き直してください（例: 最初のセクションの頭の位置だけを言い、パンくずはそこに置かれるものの1つとして書く）。
- **§3 の大字の置き場所**: 「辞典の詳細では」と面を名指しした規則で、7-a が同じ扱いにするという伝統色の大きい色見本（§2）を含みません。また、書体の節に置き場所の規則が入ります。「項目の中身そのものを見せる大きな見本（字の形・色）」の置き場所として、1つの規則にまとめ、ふさわしい節（§5 のページの割り方）に置くことを検討してください。

## Minor

1. **404 の `robots`（0-8・1-a・T5-22 の完了の条件）**: 取り出した木に `not-found.tsx`（`metadata` に `robots: { index: false }`）を置いて建てると、6つの URL のどれでも `<meta name="robots" content="noindex"/>` が**2つ**出ました（Next が足すものと `metadata` のもの）。0-8 の「1つにする」と、T5-22 の完了の条件「`robots` の meta が1つ」は、このままでは満たせません。1つにできる書き方を確かめるか、条件を「`index` を含む `robots` が0」にしてください。寄せる判断そのもの（案 A）は正しく、題・Tab の順・h1 の左端 43 は設計のとおり再現しました。
2. **5-c の解き終えた画面の3番目のセクション**: 「「もう一度挑戦する」はその見出しの前、セクションの頭の一覧の上に置く」は、見出しの前なのか、見出しの下で一覧の上なのかが読み取れません。見出しの前に置くと、§5「セクションの頭には見出し書体の見出しが1つ立つ」に反します。位置を1つに決めて書いてください。
3. **5-a の開始の画面**: いまの開始の画面では「はじめる」の直後に関連の入口（「守護キャラ診断を受ける」「音楽性格診断を受ける」）があります。説明を「はじめる」のすぐ下に移すと、説明がこの入口と「はじめる」のあいだに入ります（試作で確認）。説明と入口の順を決めて書いてください。
4. **0-3・5-a の「測った7本」**: 0-3 の表は6本（×2幅）です。数を表に合わせてください。
5. **4-k と 8-a の理由の食い違い**: 4-k の「1段ずつ下げる」を狭い画面でたどると、`###` から下は小見出しの段より下（本文と同じ大きさ）になり、見出しの深さが見えなくなります。これは 8-a で B を捨てた理由と同じ損です。4-k の損として書いてください。
6. **7-a の「§2 の色見本の細い枠・角丸を外す」**: §2 は色見本を細い線で囲むとしていて、T5-12 も「`--rule-2` の細い線で囲む」としています。7-a の文は「§2 の細い枠を外す」と読めるので、「角丸と細い `--ink` の枠を外し、§2 の細い線で囲む」に直してください。
7. **5-c の D（すべてのタイプを畳む）を捨てる理由**: 「§7 は…結果の中の全件の一覧を畳まない」と書いていますが、§7 にその文はありません。来訪者の側の理由（24のタイプを眺めたい来訪者が1回押すことになる など）だけで書いてください。
8. **4-a の D**: 「頭はいまのまま」と書いていますが、数（844 / 662）は O1（h1 を §4 にしたとき）のものです。案の名前を数に合わせてください。
