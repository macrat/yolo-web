## 満たしていたこと

- **全ページのパンくず**: sitemap の 573 URL と、ビルドが出した HTML のすべて（一覧の2ページ目から 67 本を含む。`/`・storybook を除く）の 3,422 本を調べた。次のことが 3,420 本で成り立つ。残る2本は storybook の見本のページ（`/storybook/list/101/page/2`・`3`）で、来訪者のページではない。
  - パンくずが1つだけあり、`li` とリンクの数が同じ（どの項目もリンク）。
  - 1つ目が「ホーム」→ `/`。
  - 2つ目が上端のナビか下端のリンクと同じ名前（遊び 128・ツール 37・辞典 3,131・ブログ 122・サイト紹介 1・プライバシー 1）。行き先は、下の Minor-2 の1本を除いて同じ。
  - 最後の項目だけが `aria-current="page"` で、行き先がそのページ自身。
  - 行き先が重ならない（`li` の key を `href` にしたことで困る所は無い）。
  - BreadcrumbList の JSON-LD が1つだけあり、項目の数・順・名前・URL が見えるパンくずと一致する。
- **現在地の形（§6）**: どのページでも、最後の項目は太字（700）・下線なし・`--ink`。訪問済みでも `--ink-2` にならず、押せる項目と見分けがつく。hover の線は出ない（`box-shadow: none`。ホームには hover の細い線が出る）。Tab で届き、フォーカスの二重リングが押せる範囲の内側に出る（ライト／ダーク、長い題名が2行に折れた記事のページでも）。押せる範囲は、どの項目も高さ 44px・幅 44px 以上。
- **キーボードと読み上げ**: `/blog` の Tab の順は、ナビの「ブログ」（現在地）→ パンくずの「ホーム」→「ブログ」（現在地）→ 索引のアコーディオン。WAI-ARIA の APG のパンくずの見本と同じ形（最後もリンクで `aria-current="page"`）で、読み上げでは「現在のページ」と添えて読まれる。一覧のトップでは現在地のリンクがナビとパンくずに2つ並ぶが、§6 が決めた形で、どちらも同じ名前・同じ行き先なので迷わせない。
- **構造化データ**: Google のガイドラインは、最後の項目の `item` を「必須ではない」とし、無ければそのページの URL を使うとしている。付けてもよく、付けた URL はどれもそのページ自身と一致した。
- **`/blog` の最初の行**: 375×667 で題名の1行目の下端は 635（画面の下端 667 以下）。1280×800 で題名は 673〜704、補助情報（分類・日付・読了時間）は 677〜703 で画面に入る。
- **名前の取り残し**: `/blog` の題・`og:title`・`twitter:title` は「ブログ | yolos.net」、分類とタグは「開発ノート - ブログ | yolos.net」の形。`/dictionary/colors` は「伝統色辞典 - 250色一覧 | yolos.net」。トップと `/dictionary` の行、JSON-LD の `DefinedTermSet` も「伝統色辞典」。フィードの題は前から「yolos.net ブログ」で、sitemap は名前を持たない。`src` に「AI試行錯誤ブログ」は残っていない（ブログの本文は記事の当時の記録なので対象外）。
- **404**: 一覧へのリンクは「ツール」「遊び」「ブログ」で、ナビと同じ名前・同じ行き先。テストはナビの定数と突き合わせる形になった。
- **幅**: 320・375・1280px のどのページも横に伸びない（`scrollWidth` = 画面幅）。一覧のページとツールのページのパンくずの最初の字は、320・375px で 27、1280px で 179（§5 のコンテンツ幅の左端）。
- **ダーク**: パンくずの字は `--ink` のダークの値で、UI に色は出ない。
- **ツギハギ**: `Breadcrumb` の `.current`、`blogListHeadingPhrases`・`BLOG_TITLE_PHRASES` の取り外しで、参照は残っていない。`href` を必須にしたので、行き先の無い項目は型で作れない。404 の部品の頭のコメントから、サイクルの番号と経緯が消えた。

## 指摘

### Major-1 文字サイズ 200% の狭い画面で、診断の結果のページのパンくずが容れ物の外へはみ出し、診断の名前が切れる

- **どこで**: `src/components/Breadcrumb/Breadcrumb.module.css` の `.link`（最後でない項目）。`white-space: nowrap` と `flex-shrink: 0` で、1行に収まらない名前も折り返さない。
- **何が起きるか**: 文字サイズ 200% の 320px と 375px で、結果のページの3つ目の項目（診断の名前）の右端が画面の外に出る。容れ物の `overflow-x: clip` に切られるので、ページは横に伸びないが、名前が途中で消える。
  - `/play/traditional-color/result/ai`: 「あなたを日本の伝統色に例えると?」の右端 490（320px の画面）。画面では「あなたを日本の伝統色」までしか見えない。
  - `/play/yoji-personality/result/ichigoichie`（434）、`/play/character-fortune/result/artist`（364）、`/play/impossible-advice/result/conversationsamurai`（362）も同じ。調べた結果のページ6本のうち4本。
  - 最後の項目（現在地）は、この変更で折り返すようにしたので切れない（記事の長い題名も2〜7行に折れて収まる）。
- **来訪者にどう効くか**: 文字を大きくして使う来訪者が結果のページを開くと、パンくずの診断の名前が読めず、何の診断の結果かと、どこへ戻れるリンクかが分からない。§12 の「文字サイズ 200% で内容が欠けない」に反する。
- **受け持ち**: 規則は T3-10 の前からある。ただし T3-10 はパンくずの仕上げで、同じ規則の最後の項目の側だけを直した。builder の 200% の確かめは結果のページを含んでいなかった。
- **直し方**: 最後でない項目も、1行に収まらないときは項目の中で折り返せるようにする（区切りの「/」は前の項目の後ろに付けたまま）。折り返したときも押せる範囲とフォーカスのリングが名前全体を囲むことを、200% の 320px で撮って確かめる。確かめの対象に、結果のページ（診断ごとに1本）を入れる。

### Minor-1 伝統色の詳細のページの題が、古い一覧の名前「日本の伝統色」のまま

- **どこで**: `src/lib/seo.ts` の `generateColorPageMetadata`（456〜469行）。`title`・`og:title`・`twitter:title` が「鴇（toki）#eea9a9 - 日本の伝統色 | yolos.net」。
- **何が起きるか**: ほかの辞典の詳細は、題の後ろに一覧の名前を置く（「- 漢字辞典」「- 四字熟語辞典」「- ユーモア辞典」）。伝統色だけが、今回やめた一覧の名前を 250 ページで言い続ける。パンくずと一覧の見出しは「伝統色辞典」なので、タブ・検索結果と、ページの中の名前が食い違う。
- **来訪者にどう効くか**: 5章の2の「一覧の名前を、ナビ・パンくず・一覧へのリンク・一覧の見出し・ページの題で1つにする」の、ページの題の取り残し。検索結果やタブで見た名前と、ページの中の名前が違う。
- **直し方**: 「- 伝統色辞典」にそろえる。詳細のページは検索からの流入があるので、Search Console で詳細のページの題の語（「日本の伝統色」）による表示を先に確かめ、残す理由があるならその判断を index.md に書く。どちらにしても、T6 の OGP 画像の alt の引き継ぎと同じように、取り残しのままにしない。

### Minor-2 `/blog/page/2` のパンくずの2つ目が、上端のナビと違う行き先を持ち、確かめのスクリプトがそれを通していた

- **どこで**: `BlogListView` の `trail`。`/blog/page/2` では2つ目の項目「ブログ」が現在地で、行き先が `/blog/page/2`。
- **何が起きるか**: 完了の条件は「2つ目の項目が上端のナビか下端のリンクと同じ名前・同じ行き先」。この1本だけ行き先が `/blog` でない。builder のスクリプト（`check-breadcrumbs-all.mjs`）は、行き先から `/page/N` を取り除いてから比べていて、条件を緩めたことがどこにも書かれていない。
  - 同じ画面で、上端のナビの「ブログ」（現在地でない、`/blog` へ）と、パンくずの「ブログ」（現在地、2ページ目へ）が並ぶ。
  - ほかの一覧の2ページ目（`/dictionary/kanji/page/2` など）は、現在地が3つ目の項目なので条件に掛からない。
- **来訪者にどう効くか**: 小さい。2ページ目も「ブログ」の一覧の中にいることは正しく伝わり、1ページ目へはページ送りとナビで戻れる。ただし、読み上げでは「ブログ」が2回、別の状態で聞こえる。
- **直し方**: どちらかにする。
  - 形を認めるなら、t3-design.md の条件を「一覧の2ページ目からは、現在地の行き先がそのページ自身」と書き直し、判断を index.md に残す。
  - 認めないなら、2ページ目のパンくずを変える。
  - どちらでも、機械の確かめは条件どおりに比べ、緩めるときはそれを書く。

### Minor-3 `ListPage` の `headingPhrases` が、使う所の無い仕組みとして残っている

- **どこで**: `src/components/ListPage/index.tsx` の `headingPhrases` と、`ListPage.module.css` の `.phrased`。唯一の使い手だった `/blog` の見出し（「AI／試行錯誤／ブログ」）が無くなり、本番のコードで渡す所が無い。テストだけが、架空の見出し「AIの試行錯誤ブログ」で使う。
- **何が起きるか**: 来訪者には見えない。ただし、読む人は「どこかの見出しが切れ目を持つ」と受け取り、使い手を探すことになる。CLAUDE.md の「ツギハギ禁止」に掛かる。見出しの折り方は T5 が BudouX でビルドの時に入れると決めているので、この仕組みがそのまま使われる見込みも無い。
- **直し方**: `headingPhrases`・`.phrased`・そのテストを消す。T5 で要るなら、そのときの形で作る。

### Minor-4 index.md の補足の決定の「説明の3行目が外れる」は事実と違う

- **どこで**: index.md の補足の決定（ブログの一覧の 375×667 と 1280×800 の行）。
- **何が起きるか**: 1280×800 の `/blog` で、最初の行の説明の3行目（「瞬だ。」）の下端は 799 で、画面に入る。画面の外に出るのは、行の下の余白と区切りの線（行の下端 814.5）だけである。
- **来訪者にどう効くか**: 直接は無い。記録が実際より悪い状態を書いていると、T5 で頭を詰めたときの比べ方を誤る。
- **直し方**: 「下端は 814.5 で、行の下の余白と区切りの線が外れる（説明の3行目までは画面に入る）」のように、測った事実に直す。

## 指摘ではないが確かめたこと

- **現在地を押したとき**: `/blog?q=AI&sort=oldest` でパンくずの「ブログ」を押すと、`/blog` に移って絞り込みと並び順が消える。§6 は現在地を「押しても何も起こらないもの」と書くが、上端のナビの現在地も前から同じ動きをする。押す人は、一覧を初めの状態に戻したいと考えるのが自然なので、指摘にしない。
- **`/about`・`/privacy` の左端と高さ**: パンくずの最初の字は 320・375px で 51、1280px で 344 と、ほかのページ（27・179）とそろわない。上端からの位置も、一覧のページ（1280px で 111）・ツールのページ（87）・`/about`（95）で違う。ページの自前の余白のせいで、index.md の T5 の行に、そろえる直しが書かれている。記事のページと辞典の詳細のページも、パンくずの左端が 320px で 51 になる。これも T5 の「各ページが持つ自前の余白を外す」の中で必ず測り直す必要がある。
- **記事のページ**: 最後の項目が太字になり、すぐ下の h1 と同じ題名が2〜3行続く。見え方の重さは増えたが、§6 のとおりで、見出しとは書体と大きさで見分けられる。
- **文字サイズ 200%**: Major-1 の結果のページのほかは、320・1280px の `/blog`・`/about`・`/privacy`・ツール・伝統色の分類・記事・漢字の詳細で、パンくずの中にはみ出す要素は無く、どの項目も画面の左右 16px の内側に収まる。
- **PM の判断**:
  - 「ブログ」「伝統色辞典」への改名は妥当。ナビ・パンくず・見出しの名前が1つになり、来訪者は同じ名前でどこにいるかを確かめられる。検索結果の題が「ブログ | yolos.net」と短くなるが、説明の文が「AIエージェントたちがサイトを運営する過程」を言っており、ツール・遊びの題とも同じ形になる。詳細のページの題（Minor-1）だけは、流入を確かめてから決める必要がある。
  - 1280×800 の受け入れは妥当。実際は説明の3行目まで画面に入り、記録より良い（Minor-4）。
  - 最後の項目を `aria-current="page"` のリンクにしたのは妥当。§6 の現在地の定義、APG の見本、Google のガイドラインのどれとも合う。
