## 行き先で置き場所を決める規則について

**来訪者にとって自然か。** 自然だと判断する。

- 辞典の項目へのリンクは、「このタイプについて」の最後の小見出し（「この色からのひとこと」「座右の銘として」）の文のすぐ後ろに、段落と同じ 16px で続く。「一期一会——今この出会いを、全力で大切にしよう。」を読んだ直後に「四字熟語辞典で「一期一会」の詳しい解説を見る」が来るので、読み終えた語の続きを知りたい来訪者が、そのまま進める（375・1280・ダーク・320 の 200% で同じ）。
- Tab の順も読む順と同じで、共有のボタン → 辞典の項目へのリンク → 「もう一度挑戦する」→ 次の遊びの一覧、と進む。word-sense-personality と知識クイズでは、共有のボタン → 「もう一度挑戦する」→ おすすめのリンク → 次の遊び。
- 行き先で分けるのは、来訪者が押して着くページで決まるので正しい。朱色の結果のように文言が「朱色の詳しい解説を見る」でも、行き先が一覧なら「このタイプについて」に置くと、押した来訪者は朱色の解説でなく一覧に着いて期待を裏切られる。文言の側を行き先に合わせる（T7 への申し送り）のが正しい向きである。

**データを足したときに崩れないか。** 守りがある。

- `recommendationPlacement` は、いまの辞典の経路（`colors`・`yoji`・`kanji`・`humor` の項目、`page`・`category`・`grade`・`radical`・`stroke` の一覧）をすべて正しく分ける（`src/app/dictionary` の経路と突き合わせた）。
- 試験「おすすめのリンクを持つ診断・クイズの結果は、この分け方で次のように分かれる」は、全診断・全結果の分かれ方を丸ごと持つので、おすすめのリンクを足すか変えると必ず落ち、足した人が置き場所を目で確かめることになる。たとえば知識クイズの結果に辞典の項目へのリンク（`/dictionary/kanji/山` など）を足すと、知識クイズに「このタイプについて」がリンク1本だけで出るが、この試験が落ちるのでその時点で気づける。

## 指摘

### 1.（builder）追加の読みものを持つ診断の並びが、`ResultExtraLoader.tsx` の中に2つある

`hasResultExtra` が引く `RESULT_EXTRA_SLUGS`（3つの slug の Set）と、`ResultExtraLoader` の本体の `if (slug === …)` の並びが、同じ3つの診断を別々に持っている。4つ目の追加の読みものを足すとき、片方だけ足すと次のように崩れる。

- 本体の `if` だけに足すと、`QuizContainer` が `extra` を渡さないので、その読みものが解き終えた画面に出ない（試験でも気づけない）。
- Set だけに足すと、詳しい読みものを持たない診断では、見出し「このタイプについて」だけで中身の無いセクションが出る。

slug から部品を引く1つの表（`{ "character-fortune": CharacterFortuneResultExtra, … }`）にし、`hasResultExtra` はその表に slug があるか、本体はその表から引いた部品を描く、の形にすると、並びが1つになりどちらの崩れも起きない。`ResultExtraLoader.test.tsx` の「3つだけ」の試験はそのまま使える。

### 2.（PM）index.md「T5-5b の PM の判断」の、おすすめのリンクの分け方の言い方を実装に合わせる

index.md の「T5-5b の PM の判断」は「結果ごとのおすすめのリンク（`result.recommendation`）は、**中身で**置き場所を分ける」と書くが、実装（`recommendationPlacement.ts` の説明「分け方はリンクの行き先で決める」）と、同じ index.md の T7 への申し送り（「置き場所は行き先で決まるので」）は「行き先」で分けている。朱色の結果は、中身（文言が朱色の解説）で分ければ「このタイプについて」、行き先（一覧）で分ければ「次はこれを試してみよう」になり、2つの言い方で答えが変わる。T7 やあとのサイクルが読み違えないよう、「行き先で分ける（辞典の項目のページは「このタイプについて」、辞典の一覧・分類とほかの遊びは「次はこれを試してみよう」）。来訪者が押して着くページで決まるため」の言い方に揃えてください。
