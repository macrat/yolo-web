### major-1: B-620 を外す理由が事実と合わない。B-614 の振り分けも漏れている

**どこ:** `options.md:112`（「B-620 | 診断の二重発火。見た目の規定では解消しない」）、`options.md:63`、`index.md:114`

**なぜ問題か:**

- **cycle-301 は寄与要因として見た目を特定している。** 該当箇所は `cycle-301/index.md:108`。
  - personality では押しても見た目のフィードバックが無い（`getChoiceClassName` が knowledge 以外で素の class を返し、`disabled` も効かない）。
  - そのため来訪者が再タップする。
  - いまのコードでもそのまま残っている（`QuestionCard.tsx:55-70`、`answered` は knowledge のときしか立たない）。
- **B-614 の Notes は、見た目を必須の申し送りにしている。** 「`:active` を受理された選択の見た目へ」とあり、これは DESIGN.md §6 の選択状態・hover/active と §11 の操作フィードバックの仕事そのものである。
- **同じファイルを書き換える。** T2 と T5 は `QuestionCard.tsx`・`QuizContainer.tsx` を DESIGN どおりに書き直す。PM 自身の吸収基準（「同じファイルを書き換えるため、この作業の中で扱わないとツギハギが残る」）に照らせば、B-614 は含める側に当たる。B-620 も、少なくとも検討の対象になる。
- **来訪者の実害が最も大きい。** 回答1件が置き換わると、結果が変わる確率は 26.6%〜46.3% ある（cycle-301 の悉皆集計）。しかも PV の78%が集まる面である。
- **外すと修正はかえって遅れる。** A を選んだ以上、外せば B-620 はこの長いサイクルが終わった後になる。含めれば、同じ1度の出荷で届く。A の代償として B-620 を挙げながら、含めることを検討していない。

**どう直すか:**

- options の振り分けで、B-620 と B-614 を正しい事実に基づいて判断し直す。
- 選択肢は3つある。
  - (a) 含める。T2・T5 の QuestionCard の作業と直列に置き、単独でレビューを受ける。
  - (b) B-614 の見た目の申し送り（選択が受理されたことの即時表示）だけを含め、B-620 の進行ガードは外す。
  - (c) 外す。その場合は、cycle-301 で修正が回帰した教訓を踏まえた「大きな出荷に混ぜる危険」を理由として書く。
- いずれでも、書き直した QuestionCard の完了の条件に「personality 診断で、選んだ選択肢が即座に選択状態として見える」を入れる。
- B-613 は同じ `QuizContainer.tsx` に触る計装の作業なので、振り分けの表で扱いを1行書く（外すなら、刷新後のコードに突き合わせ直す旨を書く）。
