## 指摘

### Major-1: 空白で折れないので、画面の見出しと違う所で折れ、段も小さくなる

画面の見出し（`PhrasedText`、`word-break: keep-all`）は、`<wbr>` の文節の切れ目に加えて、文節の中の空白でも折る（ダッシュの前の空白だけは折れない空白にしている）。`src/lib/share-image.tsx` の `breakUnits`・`fillLines`・`everyPhraseFits` は、文節を丸ごと1つの単位にし、空白を折り所にしない。文節が1行に収まらないときも、字の範囲のまとまりと字で割り、空白では割らない。

配信したビルドの PNG で確かめた結果:

「Git」だけの行は、`splitIntoPhrases` が最初の文節に足す語の切れ目（「Git|コマンド」。画面ではその部分が1行に収まらないときの代わりにだけ使われる）が、空白で折れない画像では最初に使われるために出る。「Gitコマンド」という1つの語が割れ、カードを見た人は一目で題を読めない。69字と67字の題は、枠の縦に大きな空きを残したまま 48px（400px のカードで 16px）で組まれている。ブログは来訪の大半を占める面で、カードの名前が小さいのは来訪者に直に見える損である。DESIGN.md §10「どの字も §4 の見出しの折り方で折る」、スキルの「どの字も §4 の見出しの折り方で折れていること」に当たらない。

直すこと:

- 行に詰める単位を、画面の見出しが折れる所と同じにする。文節の切れ目に加えて、文節の中のふつうの空白（`PhrasedText` の `joinDashes` と同じく、ダッシュの前の空白とダッシュの字どうしのあいだは除く）の後ろを折り所にする。§4「閉じ括弧の直後は、文節の中でも折ってよい」も、画面（ブラウザが閉じ括弧の直後で折る）と同じにする。1行に収まらない単位だけを、いまの字の範囲のまとまり・字の順で割る。
- 段を選ぶ `everyPhraseFits` も、同じ単位で「どれも1行に収まるか」を測る（いまは空白を含む文節を丸ごと測っている）。
- テスト: 上の3つの題を試しの入力に足し、折れた所が画面の折り所（文節の切れ目・空白・閉じ括弧の直後）のどれかであること、「Git」のように語の切れ目だけで最初の行ができていないことを確かめる。名前のテスト「文節の切れ目でだけ折れる」の許す位置も、同じ折り所に合わせる。
- 直したあと、ブログの題の長いもの（上の3つと 63〜65字の2本）の PNG を並べて見て、段が上がったことを t6-log.md に記録する。

### Major-2: 代替テキストは案 c でなく案 b にする（来訪者にとって b がよい）

builder の見立て（Next 16.3 は Route Handler の `generateStaticParams` を最後の段にしか付けず、`generateImageMetadata` のルートでは親の `[slug]` が列挙されないので、案 a では画像をビルドで書き出せない）は、`node_modules/next/dist/build/segment-config/app/app-segments.js` の `collectAppRouteSegments` と `next-metadata-route-loader.js` で確かめて正しい。

一方、案 b は試されていない。最小の Next 16.3.0 のアプリ（このリポジトリの `node_modules`）で次を確かめた:

- `app/b/[slug]/opengraph-image/route.tsx`（規約のファイルでなく、フォルダ名 `opengraph-image` の Route Handler。`dynamic = "force-static"`・`generateStaticParams`・`GET` が `ImageResponse` を返す）と、ページの `generateMetadata` の `openGraph.images: [{ url, width, height, alt }]`・`twitter: { card: "summary_large_image" }`。
- ビルドが `.next/server/app/b/one/opengraph-image.body` を書き出す（ビルドの表で `● /b/one/opengraph-image`）。
- ページの HTML に、ページごとの `og:image:alt` と、Next が `openGraph` から補う `twitter:image`・`twitter:image:alt`（同じ URL と同じ文）が出る。
- `GET` の中で例外を投げると「Error occurred prerendering page "/b/one/opengraph-image"」でビルドが exit 1 で止まる。
- 画像の URL は `…/{slug}/opengraph-image` のままにできる（フォルダ名を別にしてもよい）。

つまり b は、a で得たかったもの（読み上げで聞く人に画像の名前が届く、DESIGN.md §10「代替テキストは、画像に書いてある字を、書いてある順に言う」）を、ビルドで書き出す PNG と書体の失敗でビルドが止まることを保ったまま出せる。来訪者が払うものは無い。c は §10 とスキルの「`og:image:alt` が画像に書いた字を言うこと」に反したまま残る（`shareImageAltByKind` は「ブログの記事の題と yolos.net を書いた画像」で、どの記事かを言わない）。b のコストは、各面のページの `generateMetadata` に画像を渡すことと、並行するタスクとの受け持ちの整理で、どちらも実装の手間である（CLAUDE.md の判断の原則により、劣る体験を選ぶ理由にならない）。

直すこと:

- planner が t6-design.md 3-2 の渡し方を b に改める。描き方のモジュールに、同じ `ShareImageContent` から `openGraph.images` の値（`url`・`width`・`height`・`alt = shareImageAlt(content)`）を作る関数を置き、画像のルートとページの `generateMetadata` が同じ中身を使う形にする（画像と代替テキストが食い違わない）。受け持ちの表で、各面のページの `generateMetadata`（`src/lib/seo.ts` の `generate*Metadata`・`src/play/seo.ts`・各 `page.tsx`）を触るタスクと T5 のタスクとの順を決める。1ページだけのルート（道具・privacy・トップ）を規約のファイルのままにするか b にそろえるかも、理由とともに決める。
- 決め方の比べに入れること: b では Next が規約のファイルの `og:image` に付ける `?{hash}`（`next-metadata-image-loader.js` で、`opengraph-image.tsx` の中身の hash。描いた PNG の hash ではない）が付かない。SNS から来る人は28日で3件（2-3）で、影響は小さいが、付けるかどうかを決めておく。
- builder がブログを b で組み直し、ビルドの HTML の `og:image:alt`・`twitter:image:alt` が記事ごとの画像の字であること、`.body` が86枚あること、書体の URL を壊すとビルドが止まることを確かめて t6-log.md に記録する。t6-log.md の「案 c にした」の段落は、b にした判断と確かめた事実に書き直す。

## 良かった所（直さなくてよい）

- 枠の寸法のモジュール（`share-image-frame.ts`）は何も import せず、クライアントから読める。描き方のモジュールは `server-only` で、ブログのページ（サーバー）からだけ使われている。
- 書体は4つとも取れなければ例外を投げ、取り直せるように Promise を捨てる。Google Fonts の CSS から TrueType の URL がちょうど1つ取れること、取れたファイルの頭が TrueType であることまで確かめている。builder の記録（書体の URL を壊すとビルドが exit 1）と、テストの2本（404・TrueType でない）がある。
- ブログの画像のルートは、無い記事で `notFound()` を返す（配信で 404 を確かめた）。題は記事の h1 と同じ `post.title`。
- JSON-LD の `image` は `shareImageUrl` から取られ、配信で 200・PNG・ビルドの `.body` とバイト単位で同じだった。`og:image`（`?295fbd91e57f2170` 付き）も同じ PNG を返す。ブログのディレクトリに `twitter-image.tsx` は無く、`twitter:card` は `summary_large_image` のまま。
- 枠・罫線・切り取り・彩度・はみ出し・空白・数字の結果の大きさ（1.40倍）・Plex の幅・「——」の線は、PNG の画素で確かめるテストがある。builder の 400px の並べ（`t62-montage-400.png`）で、名前・補助情報・サイト名が読める。
