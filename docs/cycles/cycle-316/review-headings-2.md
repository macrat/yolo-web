## 指摘

### Major-1: ダッシュが行の頭に来る折れが残り、「ダッシュだけの行」は前より増えた

前回の Major-1（Cron の早見表）は、`— ` が同じ文節の中にあるときだけ直った。次の3つの形が残っている。

1. **文節の境がダッシュの前の空白の所にあるとき。** BudouX は「自律運用する| -- サイクル…」のように、空白の前に境を置く。`NO_LINE_START` は次の文節の最初の字（空白）で調べるので、ダッシュの前の境を外さない。`PhrasedText` は空白を折れない空白にするが、その前の `<wbr>` で折れ、`&nbsp;--` が行頭に来て、後ろの空白でも折れる。
   - 320px 既定の記事の h1: `自律運用する ／-- ／サイクルドキ／…`（workflow-skill-based-autonomous-operation。前は `用する -- サイ／…` でダッシュだけの行は無かった）、`ライトだった ／-- ／emulateMedia`（playwright-dark-mode-screenshot-next-themes）。`splitIntoPhrases("AIエージェントを4つのスキルで自律運用する -- サイクル…")` は `…|自律運用する| -- サイクルドキュメントと|…` を返す。
   - 同じ形で行頭が `-- ` / `— ` になるもの（既定）: site-search-feature・nextjs-dynamic-and-dedicated-route-coexistence・adsense-content-quality-audit-methodology の h1、how-we-built-this-site・memo-system-rise-and-fall ほかの h2/h3。
2. **`--` は `NO_LINE_START` に入っていない。** SKILL.md は「ダッシュ（「—」「--」）は行の頭に置かない字とし」と書くが、コードの字の組は `—―─` だけで、`--` は `PhrasedText` の空白の置き換えでしか扱わない。`-` の後ろは Unicode の改行の規則で折れるので、`--` 自体も割れる。1280px 既定の `書いたのに効かない -／- CSS GridはDOM／…`（grid-column-and-dom-order。前の WebKit の近似では割れていなかった。折れない空白で「効かない --」が一続きになり、その中で折れた）。
3. **空白の無いダッシュ**（`ガイド──シェア`・`ホンドタヌキ——化かす`）は、`keep-all` でもブラウザがダッシュの前で折る（`—` は改行の規則の B2、`─` は AI）。320px 既定で `最適化ガイド／──／シェアボタン`（sns-optimization-guide。375px も同じ）、`ホンドタヌキ／——／化かすどころか`（結果の名前。前も同じ）。

直す向き: 文節の境を調べるとき、次の文節の頭の空白を飛ばしてダッシュ（`--` を含む）を見る。境はダッシュの後ろに移す。空白の無いダッシュを前の字に付けるか（語結合子 U+2060 など）は、写し・ページ内検索・読み上げの名前への影響を測ってから決める。付けないなら §4 に受け入れる形として書く。単体テストは、先頭の空白とダッシュの組（` --`・` —`）と `--` を入れた文で書く（いまのテストは `/^[—―─]/` しか見ないので、この形を捉えない）。DESIGN.md §4 にはダッシュの扱いが一語も無いので、§4 にも書く（Major-5 と一緒に）。

### Major-2: 片仮名の語どうしと、英字の語の頭に折り所が無く、既定で行頭の小書きの仮名・長音符と語の中の折れが出る

`wordBreakRank` は、字の種類が変わる所（`left !== right`）でしか語の頭を認めない。そのため、`Intl.Segmenter` が語の境とする片仮名の語どうしの所（`チャレンジ|ゲーム`・`オンライン|ツール`・`マルチ|エージェント`・`サイクル|ドキュメント`・`レビュー|ループ`・`シェア|ボタン`。node の ICU で確かめた）と、仮名から英字の語に移る所（`プログラマティック|SEO`）が折り所にならない。PM の決定（「漢字・片仮名の語の頭」）と DESIGN.md §4（「漢字か片仮名の語が始まる所」）の文は、片仮名の語どうしの境も語の頭として読める。コードのほうが狭い。

これが無いため、1行に入らない片仮名の続きをブラウザが字の所で割り、既定で次が出る。

- 320px: `マルチエージ／ェントで`（pm-premise-contamination-in-multi-agent-ai。Chromium の前の組み `AIマルチエー／ジェントで` より悪い）、`チャレンジゲ／ームと`（irodori-and-kanji-expansion）、`オンラインツ／ールを`（how-we-built-10-tools）、`サイクルドキ／ュメントと／レビュールー／プの設計`、`ステータスコ／ードの`（http-status-code-guide-for-rest-api。Chromium の前の組みより悪い）。
- 375px: `レジストリパター／ンの導入`（game-infrastructure-refactoring）。
- 1280px 既定: `プログラマティックS／EO戦略の実践`（tools-expansion-10-to-30）、`プログラマティックS／EOの実践`（japanese-traditional-colors-dictionary）。Chromium の前の組みは `プログラマティック／SEO…` で、1280px で Chromium より悪くなった3件のうち2件がこれ（下の問い2）。

直す向き: 片仮名の語どうしの境（前回の1巡目にあった「どちらも3字以上」の条件つき）と、英字の語の頭を、順位 0 の語の頭に入れる。`Intl.Segmenter` は片仮名の続きを誤って刻むことがある（`リ|ファクタ|リング`・`レジスト|リ|パターン`・`デザイン|トーク|ン`）ので、誤りの刻みを拾わない条件を決め、全面を測り直す。DESIGN.md §4 の文とコードの言い方をそろえる。

### Major-3: BudouX が語の中に置く境（「見た|目」「切り|替え」）をそのまま折り所にしている

`splitIntoPhrases` は BudouX の境をそのまま文節の境にする。BudouX は `見た|目が`・`切り|替えられる…` のように語の中に境を置くことがあり、この `<wbr>` は広い画面でも行の終わりに来れば使われる。`Intl.Segmenter` はどちらも1語（`見た目`・`切り替え`）とする。

- builder が「強制の折れのせいで悪くなった」とした choosing-html-tags-by-meaning（375px）は、強制の折れではない。`意味で／選ぶHTML — 見た／目が同じでも／…` の `見た／目` は `<wbr>`（BudouX の境）の所で折れている。規則に沿った折り所で避けられる（この境を外せばよい）。
- dark-mode-toggle（1280px）の `手動で切り／替えられるようにな／りました` も、`切り|替え` の `<wbr>` が語を割り、そのうえ残りの `替えられるようになりました`（13字）に折り所が無いので強制の折れが出ている。
- ほかに 320px の `サイト／内検索を`（site-search-feature。字の種類の変わり目の足し分）も、語（`サイト内`）を割る。

直す向き: BudouX の境のうち、漢字を含む `Intl.Segmenter` の1語の中に落ちるものを外す（文節の境を語の中に置かない）。§4 の「語の中で折れるのは、語が1行に入らないときだけ」を、BudouX の境にも当てる。

### Major-4: 既定の文字サイズで、1字だけの行と禁則の破れが0にならず、§4 はその残り方を書いていない

§4 は「既定の文字サイズでは、見出しに1字だけの行・禁則の破れ・丸括弧の一続きの中の折れを作らない。組み方で避けられないとき（1行に収まらない丸括弧の一続き・鉤括弧の文節）は、見出しのうち来訪者に渡していない文を直す」と言う。いまの記事の h1 は既定で次のとおりで、どれもこの規則の外にある。

| ----------------------- | ------------------------- | ------------------------ |
| 320px                   | 13 → 1 → 5                | 21 → 0 → 12              |
| 375px                   | 7 → 0 → 1                 | 17 → 2 → 6               |
| 1280px                  | 9 → 0 → 0                 | 19 → 0 → 0               |

（禁則の破れはダッシュを数えない。数えると増える。Major-1）

1件ずつ前と比べて既定で増えたもの（13件）と、依頼の3件の判定:

- **規則に沿った折り所で避けられるもの**: choosing-html-tags-by-meaning 375px（Major-3）、pm-premise 320px・irodori 320px・how-we-built-10-tools 320px・game-infrastructure 375px の一部・workflow-skill 320px（Major-2）。
- **いまの PM の規則のもとでは避けられないもの**: dark-mode-toggle 1280px の `な／りました`（`替えられるようになりました` に規則の折り所が無い。ただ、上の `切り|替え` は Major-3 で外せる）、design-token-migration 320px `教えてくれな／い`、removing-ai-slop 320px `していなかっ／た`、stop-piling-rules 320px `守らないなら／、ルールより`（行頭の読点）と 375px `渡してみてほし／い`、nextjs-hydration 320px `ハイドレーシ／ョン`、url-structure 320px `フレームワー／ク`、game-infrastructure 375px `リファクタリング／: 12`（行頭のコロン）。
  - このうち平仮名の続きの4件は、「て／で の後ろに続く補助の動詞（くれる・いる・みる・ほしい・おく）の頭」と「ように／なる」の境を語と語の切れ目として足せば、語を割らずに避けられる（`教えて|くれない`・`して|いなかった`・`みて|ほしい`・`ように|なりました`）。1巡目に問題になった `守ら|ないなら` のような語の中の所は含まない。Chromium の前の組みも `替えられるように／なりました`・`渡してみてほしい` と組んでいた。より良い規則の候補として、PM が採るかを決め、測って確かめる。

直す向き: PM が、(a) 既定で避けられない折れ（1行に入らない1語・丸括弧の一続き）を §4 のとおり見出しの文を直して無くすのか、(b) 受け入れる形として §4 に書き足すのかを決める。いまの §4 は「0 にする」と言いながら、上の残りをどちらにも入れておらず、規定と実物が食い違っている。どちらにしても、判定は種類ごとの数（1件ずつの増減）で出す。

### Major-5: Chromium の読み上げの名前に、`<wbr>` ごとに空白が入る

`ariaSnapshot` では見出しの名前は元の文のままだが、Chromium が支援技術に渡す名前（CDP の `Accessibility.getFullAXTree`）は `<wbr>` の所に空白を入れる。

- 最小の例: `<h1>意味で<wbr>選ぶ</h1>` の名前は `"意味で 選ぶ"`、`<h2>見た目<span>が</span>同じ</h2>` は `"見た目が同じ"`（Chromium 141）。
- 245ページ（375px）で、見出しの名前 2,636件のうち 853件が、94f531e と比べて空白だけ違った（例 `"Cron 式 早見表 — フィールド・ 特殊文字・ 実用パターン 一覧"`）。空白を除いて違ったのは、文を変えた 404 の1件だけ。
- 日本語の読み上げでは、文節ごとに短い間が入るか、点字の表示に空白が出る。読み違えにはならないが、依頼の「読み上げの名前が変わらない」は、Chromium の実際の名前では満たしていない。`docs/knowledge/playwright-mcp.md` の「`<wbr>` は名前に字を足さない」も、`ariaSnapshot` の結果で、Chromium の AX ツリーの名前とは違う。

直す向き: PM が、この違いを受け入れるか（受け入れるなら理由を §4 か t4-design.md に残す）、別の組み方を探すかを決める。どちらにしても、knowledge の測り方を「CDP の AX ツリーの名前も見る」に直し、T9 に iOS の VoiceOver での読み方を確かめる型として渡す。

### Minor-1: 200% の記事の h1 の1字だけの行は多いまま

320px・200% の記事の h1 の1字だけの行は、前 37 → 1巡目 143 → いま 137。1件ずつ見ると、ほぼすべてが1行に入らない文節の中の強制の折れから出たもので、§4 の受け入れの内にある。ただし、折れない空白で「早見表 —」が一続きになり、それが入らずに `—` だけの行ができたもの（html-tags-cheatsheet・markdown-cheatsheet・sql-cheatsheet・git-command-cheatsheet の h1、320px・375px）は、この変更で新しく出た形である（Major-1 を直すときに一緒に見る）。

### Minor-2: SKILL.md の手順 5 の「同じ順の中は」の「順」が何を指すかが読めない

いまの文は、分ける所を2つ（漢字か片仮名の語の頭と「〜する」の頭）に絞ったあと「同じ順の中は BudouX の境目の度合いの高い所を選ぶ」と続く。順位（語の頭を先に、「〜する」を後に）を書いた文が無いので、「同じ順」が宙に浮いている。コードの `wordBreakRank` の順位を文にする。

## 依頼の問いへの答え

1. **測り直し**: builder の数（1280px の記事の h1 の語の中 108 → 11、グループの合計で前より悪いものが無い）は正しい。ただし、種類ごとに1件ずつ見ると既定で13件が前より増え、ダッシュだけの行は 1 → 5 に増えた。3件の判定は Major-4 のとおりで、choosing-html-tags-by-meaning は強制の折れでなく避けられる。dark-mode-toggle は今の規則では避けられない部分があるが、`切り|替え` と「ように|なる」で避けられる。ai-agent-concept-rethink-3 は `<wbr>` の規則では避けられず、§4 は文を直すことを求めている。
2. **1280px・既定の記事の h1 と、94f531e の Chromium の `auto-phrase` の比べ**（86件）: 同じ 27、良い 13、悪い 3、種類の合計が同じで組みが違う 43。合計は、語の中 19 → 11、片仮名の語の中 13 → 6、禁則 3 → 0、1字だけの行 1 → 0、行の数 393 → 391。**たいていの読者にとって、前と同じか良い。** 悪い3件は `プログラマティックS／EO` の2件（Major-2）と dark-mode-toggle（Major-3・Major-4）で、どれも直す向きがある。375px では良い 24・悪い 1、320px では良い 37・悪い 3。
3. **読み上げと写し**: `ariaSnapshot` の名前は元の文と同じ。Chromium の AX ツリーの名前は `<wbr>` ごとに空白が入る（Major-5）。折れない空白（U+00A0）は、AX の名前にはそのまま入り、Chromium で見出しを写すとクリップボードには普通の空白（U+0020）で入る（`getSelection().toString()` では U+00A0）。写した文の検索や貼り付けで困ることは無く、**受け入れてよい。**
4. **DESIGN.md §4 の文とコード**: 「長い文節」の項は、ひとつのいまの形として読め、履歴の跡も無い。ただし、(1) 「漢字か片仮名の語が始まる所」はコード（字の種類が変わる所だけ）より広い（Major-2）、(2) 「語の中で折れるのは、語が1行に入らないときだけ」は、BudouX の境（Major-3）で守れていない、(3) ダッシュの扱いが §4 に無く、SKILL.md にだけある。その SKILL.md の「--」もコードと合わない（Major-1）、(4) 既定で0とする規定と、1行に入らない1語の強制の折れの関係が書かれていない（Major-4）。
5. **コードの質とテスト**: `wordBreakRank` と `splitWidePhraseAtWords` は短くなり、使われない値や履歴のコメントは残っていない。前回の Minor-1（`tableCell` の説明）と Minor-2（`boundaryScores` と `parse` の一致のテスト）は直っている。`phrase-breaks`・`PhrasedText`・`markdown` のテスト 108件はすべて通り、prettier も通る。足りないのは、ダッシュの前に空白がある文と `--` のテスト（Major-1）、片仮名の語どうしの境のテスト（Major-2）、BudouX の境が語の中に落ちる文のテスト（Major-3）。
