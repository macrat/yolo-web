## 指摘

### 1. §6 冒頭の1つ目の定義の線引き「実行のあいだも画面に残って次を待つもの」は、ゲームの「送信」を含む。上の注は `DESIGN.md` に入れるべきものではなく、線引きの言葉そのものを直す

5章が §6 冒頭の1つ目の定義に書き入れる文（445行）:

> 押したあと、実行のあいだも画面に残って次を待つもの（リンクなど）は、実行が終わるまで、押す前と同じ下線と hover の線を持ったままでいる（実行のさいちゅう）。

kanji-kanaru・yoji-kimeru の「送信」は、押したあと判定が返るまで画面に残り、次を待つ。この文の線引きに当てはまるので、`DESIGN.md` だけを読むと「送信」は押す前と同じ形（反転と hover の線）を持ったままでいなければならない。実際は §6 の無効の形（破線の枠・`--ink-2`・「送信中……」）になり、hover の線も `:disabled` で消える。同じ `DESIGN.md` の4つ目の定義のもとでは無効にも読めるので、1つのボタンが2つの種類に同時に当てはまり、形が食い違う。PM の決定（リンクと診断で押した選択肢に限り、ボタン全体の決まりにしない）が、文の言葉では表せていない。

443行の注（「実行のさいちゅうの形は、実行のあいだも面が画面に残るものに限って言う。押してから実行が終わるまで無効の形に替えるボタン——ゲームの『送信』——は別の状態で、この設計の範囲の外である」）について:

- **置き場**: 注は引用の外にあり、`DESIGN.md` には入らない。置き場は正しい。この注を `DESIGN.md` に移すのは誤りである。規範の文に「ただし〇〇は別」と足すのは、線引きが決まっていないことを例外で埋める形で、ツギハギにあたる。線引きは文の言葉だけで決まるべきである。
- **中身**: 注は食い違いを解いていない。「面が画面に残るもの」は「送信」にも当てはまる（面は画面に残り、字と形が替わるだけ）。注の基準でも「送信」は外れない。「別の状態」と言うが、`DESIGN.md` にそういう状態は無い。いまの `DESIGN.md` で「送信中……」は4つ目の定義の無効の形で、T4-12 もそう扱った。

直すこと:

- 445行の文を、当てはまるものが言葉だけで決まる形にする。PM の決定のとおりに限るなら、線引きの基準でなく当てはまるものを名指すのが確かである。たとえば「押したリンクと、答えると次の問へ進む選択肢は、次のページか次の問が出るまで、押す前の下線のままでいる（実行のさいちゅう）」。名指しにすれば「送信」はもともと当てはまらず、注も例外の文も要らない。
- 443行の注は、残すなら事実に合わせる。「ゲームの『送信』は、判定を待つあいだ4つ目の定義の無効の形になる（review-t4-12-3.md）。実行のさいちゅうは名指したものだけなので当てはまらない」。「別の状態」とは書かない。

### 2. `DESIGN.md` に入る2つの文の「hover の線を持ったまま」は、4-2 が受け入れたタッチのふるまいと食い違う

- 445行（§6 冒頭の1つ目の定義）: 「押す前と同じ下線と hover の線を持ったままでいる」
- 466行（§6 の箇条）: 「押したものは実行のさいちゅうとして下線と hover の線を持ったまま」

hover の線は、ポインタが上にあるあいだだけ出る応えで、押したものが持ち続ける印ではない。4-2（181行）は、タッチでは要素が `span` に替わると線が消えることを受け入れ、「押したものの印は下線で、それはタッチでも残る」と書いている。`DESIGN.md` の文は「持ったまま」なので、タッチで線が消える形はこの決まりに反すると読める。また文字どおりに実装すると、ポインタの位置によらず押した行に線を出し続ける形（`::after` にいつも `box-shadow` を掛ける）になりうる。第9回の実測のとおりの形（ポインタが上にあれば押す前と同じ線が出る）とは違う。本文の中のリンクの hover は下線が太くなる形で、「hover の線」の形でもない。

直すこと: 2つの文で、持ち続けるものを下線だけにする。hover は「押す前と同じに応える」と書き分ける。たとえば「押す前の下線のままでいる。hover にも押す前と同じに応える」。4-2 の「hover」の箇条の書き出し（「押す前と同じ hover の線も持ったままでいる」）も同じ言い方にそろえる。

### 3. 押した行の `span` の `data-hit-area="after"` と `::after` が、4-11 と T5a-5 の CSS の説明に運ばれていない

4-2（181行）と 4-4（253行）は、押した行の字の `span` にも `data-hit-area="after"` と `::after` を持たせるとする。一方、次の2か所はそれを持たない。

- 4-11（417行）: 「`.choiceButton` の面の指定は消し、押せる範囲を行へ広げる `::after` だけを残す」。いまの `QuestionCard.module.css` の `::after` の規則は `.choiceButton::after` にだけ掛かる。4-11 のとおりに片付けると、押した行の `span` は `::after` を持たず、hover の線が出ない（第9回の実測で「線が消える」の形）。
- 7章 T5a-5 の `globals.css` の説明（560行）: `data-hit-area` の規則の上の説明は「押せる範囲を ::after に広げた要素（一覧の行の名前）」と言い、hover の規則の上の説明は「押しても何も起きない現在地と無効には出さない」と言う。押せない `span` がこの属性を持ち hover の線を出すなら、2つの説明は書いてあることと合わなくなる。ツギハギ禁止のとおり、説明もいまの組み方を言う形に書き直す必要があるが、T5a-5 の説明には入っていない。第9回の指摘5 と同じ類の漏れである。

直すこと: 4-11 を「`::after` の規則を、選択肢のボタンと押した行の字の両方に掛かる形にして残す」にする。T5a-5 の `globals.css` の説明に「`data-hit-area` と hover の規則の上の説明に、実行のさいちゅうの選択肢の字（押せないが、押す前と同じ hover を出すもの）を入れる」を足す。

### 4. 4-2 が「iOS の Safari のふるまいは T9 の実機で見る」とした hover の確かめが、8章の T9 の一覧と「PM が足す行」の3に無い

4-2（181行）は、押した行の hover の線がタッチで消えることについて、iOS の Safari のふるまいを T9 の実機で見るとした。8章の「T9 に渡す」（591〜597行）と「PM が足す行」の3（613行）には、この確かめが無い。4-4 の WebKit の字の位置（592行）や VoiceOver（595・596行）は、4章で T9 に渡したものがどれも 8章に載っているので、これだけが抜けている。T9 の担当は index.md の行（PM が足す行の3）から作業を読むので、このままでは見られない。

直すこと: 8章の T9 の一覧と PM が足す行の3に、「診断で選択肢を tap したあと、押した行に hover の線が出るか消えるか（受け入れる形。見え方を記録する）」を足す。記録も要らないと判断するなら、4-2 の「T9 の実機で見る」を外す。
