## builder が報告した「375 で 0.0185 → 0.0527」の原因

builder の計測（2回目で勝った回を記録で入れ、結果の高さが無い状態で 375×667 で開く）を再現した。同じ組みで 375 で 0.0527、1280 で 0.0679。ずれるのはどれも「くわしい遊び方」から下（`DETAILS.howToPlayAccordion` 627→画面の外）で、結果の区画が 0 から結果の高さに伸びるときに押し下げられる。

原因は、Minor-2 の直しで、解き終えた回のヒントの帯が次のヒントの行の1行（22px）ぶん低くなったこと。盤が2行しかない回では「くわしい遊び方」が画面の下端の中にあり、前は下端から 18px ほどしか見えていなかったのが、1行上がって 40px 見えるようになった。ずれの大きさは同じでも、画面の中で動く面積が増えたので CLS が増えた。結果の区画を取っておけない（その画面で一度も描いていない）ことが元で、帯の直しそのものは正しい。

## Minor

### Minor-1: 別の画面で解いた回を初めて開くとき、1回目で勝った回は 1280 で 0.10 を超える

PM は「解き終えたのと別の画面の大きさで初めて開いたときに残るずれ（四字キメルで 0.02・0.06）」を受け入れた（t4-design.md）。しかし推測の数が少ない回では、その値を超える。

| 解いた回数（勝ち） | 320 既定 | 375 既定 | 1280 既定  |
| ------------------ | -------- | -------- | ---------- |
| 1回目              | 0.0322   | 0.0941   | **0.1042** |
| 2回目              | 0.0001   | 0.0527   | 0.0679     |
| 4回目              | 0.0001   | 0.0001   | 0.0209     |

（2回ずつ測り、2回とも同じ値。）1280 の1回目は Core Web Vitals の「良い」の線（0.1）を超える。盤が短いと、「くわしい遊び方」・難易度の選び・フッターまでが最初の画面に入り、結果が出るとそれがまとめて下へ飛ぶ。

起きるのは、窓の大きさや向き・字の大きさを変えて開き直したときと、この版の前に解いた回をこの版で初めて開いたときで、来訪者は多くない。PM が受け入れた値は実際より小さく見積もられていたので、次のどちらかを PM が決める。

- 受け入れる値を実測（最大 0.104）に改めて記録する。
- 直す: 覚えた高さが別の画面のものしか無いときも、その高さを近似として取っておく（結果が出たら外すので、合わなくても下に空きは残らない）、または結果の区画に最小の高さを取っておく。

### Minor-2: 1〜4回目で勝った瞬間、盤が1行ぶん上へ跳ねる

判定を待つあいだは、送った推測を1回と数えて帯に次のヒントの行（「5回目のあとに分類」）を出す。勝ちが返ると、その行が消えて帯が1行低くなり、盤が上へ動く。375×667 で判定を1秒遅らせて4回目で勝つと、盤の上端が画面の 255px から 229px へ 26px 動く（1280 では 41px。スクロールの変化を含む）。`layout-shift` には出ない（CLS 0）が、勝った行を見ている来訪者の目の前で盤が跳ねる。DESIGN.md §11 の「結果が出る推測では、結果の登場だけが動く」（コードの注釈にもある）に反する。

直し方の向き: 判定を待っている推測については次のヒントの行を足さない（判定が返ってから、遊び続ける回だけ次の行を出す）。または、判定を待つあいだは前の行の数のまま帯の高さを保つ。直したら、勝ち・負けの両方で、判定を遅らせたときの盤の位置を幅ごとに測る。

### Minor-3: サイト内の移動で描く経路と、ヒントの帯の高さの覚え方にテストが無い

前回、Major-1 を直したらテストを足すよう求めた。`GameContainer` の最初の `useState` の初期化で、サーバーで描いていないときに値を書く経路のテストが四字キメルに無い（`GameContainer.test.tsx` の差分は漢字カナールだけ）。帯の高さを覚える `useEffect`（読み込み中は覚えない・外された帯の高さ0を覚えない）のテストも無い。どちらも Major-1・Minor-1 の直しの芯で、後の変更で壊れても気づけない。

## コードについて

- 死んだコード: `saveTodayGame` は四字キメルから消えた（ナカマワケ・イロドリ・漢字カナールの同名の関数はそれぞれで使う）。`hintLineCount` の `finished` と `finishedValues` はどちらも使う。
- 履歴の注釈: 無い。「負けを記録した古い形の途中の回」は今も読む記録の形の説明である。
- 最初の `useState` の初期化で `<head>` に要素を足すのは、描画の中の副作用である。先に `releaseSavedLayout` を呼ぶので、StrictMode で2回動いても値は1つになる。描画の前に値を書くために必要で、意図は注釈で読めるので指摘にしない。
- `YojiKimeru.module.css` の `.hints` の注釈の2行目が、ほかの行より長い1行になっている（「…最後の行は動かない。取っておく高さは、前に…」）。組み直しの跡に見える。Minor-3 と一緒に行をそろえてほしい。
- `rememberedHeights` と結果の高さは、覚えるのが最後の画面の1つだけである。解き終えてから向きを変えたままページを離れると、元の向きでは次に開いたときに取っておけない（200% の 375 で帯の高さが 155px と取っておかれ、実際は 207px）。最初の画面では下にずれるだけで CLS は出ず、覚える画面は1つという決定の範囲の中なので、指摘にしない。

## 見た目（320・375・1280 × 既定・200% × ライト・ダーク × 勝ち・負け、24通り）

- ヒントの帯: 勝ちの前は「ヒント／読みの最初の字 し／4回目のあとに出典」、勝ったあとは「…／出典 中国古典由来」で、次のヒントの行は無い。負けは前もあとも4行（分類まで）で変わらない。ダークでも「次のヒント」の行は `--ink-2` で読める。
- 成績の表: 値は「1回」「100%」「0日」がどれも1行。名前は文節で折れる（320・200% で「いちばん／長く／続けて／正解した／日数」）。表のはみ出しとページの横送りはどれも無い。
- 待っている行: 送った字だけが盤に並び、ボタンは「送信中……」の無効の形（24通りとも）。
- 印: 盤の ◯・× と凡例の ◯・△・× は同じ書体と語で、ダークでも当たりのマスの地と外れの淡い印が見分けられる。

## アンチパターンのチェック（docs/anti-patterns/implementation.md）

- AP-I03（Core Vitals・バンドル）: 通る道はどれも 0.1 未満。別の画面で1回目に勝った回だけ 1280 で 0.104（Minor-1）。本体の前のスクリプトは関数1つで小さい。
- AP-I04（指標を目的にした配置）: 該当なし。`level_end` は解いたその場でだけ送る。
- AP-I05（目的を妨げる追加）: 該当なし。既定の字の大きさでは、どの幅でもヒント・盤・入力欄が最初の画面に入る。
