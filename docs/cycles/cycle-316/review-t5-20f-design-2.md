## 指摘

### 指摘1（planner・大）: 辞典の詳細のページの並びが 1-4 と違い、6-1・6-2 の規則が入れた日から事実と食い違う

1-4 は、辞典の詳細を「よくある質問 → 項目の共有 → 遊びのおすすめ」とし、そこから「よくある質問 → 勧める → 関連・おすすめの一覧 → 関連の記事の順がサイトの全体でそろっている」と結論している。しかし実際の並びは違う。`DictionaryDetailLayout` の JSDoc と t5-design.md 7-e の決定（B を採る）では、次の順である。

> 項目の本文 → 同じ仲間の索引 → 関連ゲーム（伝統色では関連ツール）→ よくある質問 → 共有 → 遊びのおすすめ

`KanjiDetail.tsx`・`YojiDetail.tsx` には「関連ゲーム」、`ColorDetail.tsx` には「関連ツール」があり、どれもよくある質問の前にある。

そのため、次の3つが起きる。

- **6-1 の §5 の文**（「中身のあとのセクションは、どのページでも、よくある質問 → 共有 → 関連・おすすめの一覧 → 関連の記事の順」）は、辞典の詳細の3種で入れた日から偽になる。
- **6-2 の §7 の規則**（「1つのページに置く選んだ一覧は、同じ項目を重ねて載せない」）に、漢字と四字熟語の詳細が入れた日から反する。作業ツリーの関数で確かめた。
  - 漢字の詳細は「関連ゲーム」が漢字カナールを指し、「遊びのおすすめ」（`getPlayRecommendationsForDictionary("kanji")`）も kanji-kanaru・yoji-kimeru を並べる。
  - 四字熟語の詳細は「関連ゲーム」が四字キメルを指し、「遊びのおすすめ」も yoji-kimeru・yoji-level を並べる。
  - 同じ遊びが1ページに2度出る。これは、この設計が直そうとしている重なりそのものである。
  - 6-4 の「あとに終わるタスクのコミットに入れる。先に入れると、まだ直していない面が文に反する」は、ゲームと診断・クイズの2つの面しか数えていない。
- **3-1 の §12 のページの間の列**で D を捨てた理由（「ほかの分類の一覧は、どのページでも勧めるのあと」）は、辞典の詳細では成り立っていない。E を採る結論が変わるとは限らない。辞典の詳細が同じ仲間の索引を本文のすぐあとに置くこと（§7 の索引の表「項目の本文のあと」）は、むしろ E の「同じ種類は中身のすぐあと」の先例になる。とはいえ、比べる事実を直してから選び直す必要がある。

直し方:

- 1-4 に辞典の詳細の実際の並びを書く。ほかに漏れている面が無いか、一覧・トップ・ブログの記事の前後の記事も含めて棚卸しする（AP-P14）。
- 3-1 の比べ直し。
- 6-1 の §5 の文を、辞典の詳細の「同じ仲間の索引」「関連ゲーム・関連ツール」も言い当てる形に書き直す。辞典の関連をよくある質問のあとへ動かすなら、それを決め、受け持ちのタスク（T5-10・T5-11・T5-12）へ渡す。
- 6-2 の規則を入れる前に、サイトのすべての面で選んだ一覧の重なりを数える。漢字と四字熟語の詳細の重なりを誰がいつ直すかを決め（辞典の詳細のファイルを受け持つ T5-10・T5-11 か、この設計のタスク）、6-4 の入れる時をその後にする。

### 指摘2（planner・大）: 診断・クイズの開始の画面で、「関連の入口」と新しい一覧が隣り合って同じ遊びを並べる

`QuizContainer` の開始の画面は、説明のすぐ下に「関連の入口」（`quiz.meta.relatedLinks`）のリンクを並べる。t5-design.md の T5-4 の「事実の行 → 一文 →『はじめる』→ 説明 → 関連の入口」である。設計はこれに一度も触れていない。E では、そのすぐ下（遊びのセクションのすぐあと）に「他のクイズ・診断も試してみよう」が来る。作業ツリーの登録で、「関連の入口」と、5-2 の新しい一覧か「他のジャンルも」とで重なる遊びを数えると、15本のうち12本で重なる（`tmp/rv-t520f-2/rl.ts`）。例は次のとおり。

- kotowaza-level: 入口が漢字力診断・四字熟語力診断。そのすぐ下の一覧が四字熟語力診断・漢字力診断で、2件とも同じ。
- impossible-advice・contrarian-fortune・animal-personality: 入口の2本がどちらも一覧の3件に入る。
- character-personality: 入口の1本目（character-fortune）が一覧の1件目。

来訪者から見ると、「はじめる」の下で同じ遊びの名前を2度読むことになる。いまは一覧がよくある質問と勧めるの下にあるので離れているが、E で隣り合う。

そのため、次の3つが事実と合わない。

- 5-3 の「どの状態でも重ならない」は、開始の画面で成り立たない。
- 3-1 の E を推す理由の2つ目（「一度だけ来た来訪者は、いまはよくある質問と勧めるの下まで送らないと次の遊びに出会わない」）は、診断・クイズでは事実と違う。開始の画面には、すでに説明のすぐ下に1〜3本の入口がある。E で得るものは、その分小さい。
- 6-3 の機械の検査は「選んだ一覧の行のリンクの `href`」を集める。「関連の入口」は行の一覧でなく、辞典の詳細の「関連ゲーム」「関連ツール」も1本のリンクなので、どちらも検査から漏れうる。規則が数えるものと検査が数えるものが一致しない。

解き終えた画面の結果ごとのおすすめのリンク（5-3 で規則の外とした）にも、同じ形の近さがある。kotowaza-level は5つの結果のすべてが、漢字力診断か四字熟語力診断を指す。E では、その1本のリンクのすぐ下に、同じ2本を並べる一覧が来る。5-3 の理由（結果に合わせた1文の中のリンクで、一覧の繰り返しとは読まれない）は成り立ちうる。ただし、同じ分類が2本しかない知識のクイズで、隣り合う2つが同じ行き先を言うことを、来訪者の目で比べてはいない。

直し方:

- 1-3 に「関連の入口」を書く。
- 開始の画面で入口と新しい一覧をどう分けるかを、3案程度で比べて決める。例は、入口を外して一覧に任せる、入口から一覧に並ぶ遊びを外す（辞典など遊びでない行き先だけを残す）、入口を残し一覧から除く、など。
- §7 の文と 6-3 の検査に、何を「選んだ一覧」と数えるかを書く（入口のリンクの並び、1本だけの関連のセクション、結果ごとのおすすめのリンク）。数え方と規則の言うことを一致させる。
- `relatedLinks` のデータ（`src/play/quiz/data`）を触るなら、同じファイルを触る T5-27 との順も 7-2 に書く。

### 指摘3（planner・中）: 診断・クイズを解き終えた来訪者から、ほかの分類の遊びが遠のく量を小さく書いている

3-1 の E の行と「失うもの」は、「ほかの分類の遊びへの道は、よくある質問と勧めるのぶん遠くなる」と書く。しかし診断・クイズの解き終えた画面では、E のあとの並びは次のとおりである。

> 次はこれを → 他のクイズ・診断も → **すべてのタイプ** → よくある質問 → 勧める → 他のジャンルも

いまの「次はこれを」にある他の分類の2件（今日の占いと知識のクイズなど）は、すべてのタイプの全件の一覧のぶんも遠くなる。15本のうち12本がすべてのタイプを持ち（6〜24行）、character-personality の24行は 375 で約 2,370px である（t5-design.md 5-c）。B の行はこの距離（「診断ではすべてのタイプの下も」）を書いているが、E の行は書いていない（AP-P02）。解き終えた閲覧でページの 90% まで送るのは 4.7% なので、この道はほとんどの来訪者から見えなくなる。

GA で見ると、失うものは小さくない。

- 解き終えて遊びへ移った 90人のうち、「次はこれを」と「他のジャンルも」の両方に並ぶ遊びへ移ったのは 24人（34 閲覧）で、約27%（算術）。そのうち 11 閲覧は今日の占いへ移っている。
- 並びを変えると、「他のクイズ・診断も」にだけ並ぶ遊びへ移った 19 閲覧のうち 8 閲覧の行き先が、ページのどの一覧からも消える。
- 逆に、どの一覧にも無かった遊びへの 12 閲覧が、新しい一覧に入る。

設計は、この出入りを書いていない。

3-1 の列の名前「解き終えた来訪者（常連）」も、診断・クイズには当たらない。解き終えた閲覧 3,429 は 3,156人で、ほとんどが一度だけの来訪者である。

E を捨てよという指摘ではない。同じ分類へ移る閲覧はほかの分類の約2倍あり、E は結果のすぐ下にそれを3件、説明付きで置く。比べる事実を正しくしたうえで、E を採るか、解き終えた画面でほかの分類の遊びへの道をどう残すかを決めること。例は、すべてのタイプとの順、今日の占いの扱いなどである。

直し方:

- 3-1 の E の行と「失うもの」を、すべてのタイプを含む距離と上の GA の数で書き直し、比べ直す。
- 8-2 の条件8で、「他のクイズ・診断も」の見出しに加え、「他のジャンルも」の見出しの上端までの距離も、前の版の「次はこれを」の一覧の上端までと並べて記録する。
- 9章のリリースのあとの見方に、ほかの分類への移り（とくに今日の占い）が壊れていないかを足す。

### 指摘4（planner・中）: T5a の測り直しの範囲が足りない

8-2 の条件4は、T5a の完了の条件のうち「入る」と「問のまとまりを見せる送り」だけを測り直す。E では、設問の区画（`.stage`）のすぐ下が、よくある質問の `summary` から、ほかの診断へ移るリンクの行の一覧に替わる。

T5a は二度打ちの2打目が区画の外（「FAQ・関連・フッタ」）に落ちないことを、`.stage` の最小の高さと着地の選び方（t5a-design.md 4-5・4-9）で守っている。その合否は、t5a-design.md 6章の条件7「2打目が第1の組（`a[href]`・`summary`・ボタン）に落ちた件が 0」である。落ちる先がリンクに替わると、2打目は解きかけの答えを捨ててほかのページへ移す。答えは端末に残らないので、`summary` を開くより来訪者の損が大きい。「もう一度挑戦する」のあと（条件6）も、開始の画面のすぐ下が一覧に替わる。

直し方:

- 8-2 の条件4の測り直しに、t5a-design.md 6章の条件6（「もう一度挑戦する」）と条件7（二度打ち。とくに `a[href]` に落ちた件が 0）を足す。
- 8-2 の条件1は Q2 の並びを書いているのに、測る状態が「Q1・Q3」になっている。Q2 を測る状態に入れる。
