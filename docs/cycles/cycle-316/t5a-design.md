### 1-3. T5-4 のあとの値と、550 の画面

index.md の T5-4 の値（画面の高さ 667、px。「はじめる」の下端と、進み具合の帯の上端から最後の選択肢まで＋8。375/320。**1問目だけ**）を、帯を上端から 8px に置いた 550 の画面に当てる。入る条件は「値 + 下の 8 ≦ 550」、つまり値が 542 以下であること。

## 4. 案1 の中身

### 4-1. 選択肢の種類（§6）

選択肢は、押すと回答が決まる**ボタン**（§6「そのページで何かが実行されるもの」）で、1行に1つずつ、一覧の行の罫線で区切って並べる。いまの組み方の種類は変えない。ラジオボタンにしない理由は2つある。

- ラジオボタンは、選ぶ操作と確かめの操作を分けないと組めない。
- 選んだだけで進める組み方は、矢印のキーで選ぶ所を動かしただけで答えが決まる。WCAG 3.2.2（入力で文脈を変えない）にも当たる。

`DESIGN.md` にこの決まりは無いので、5章の文を足す（T5a-1）。

### 4-2. 押した形と再入力

押すと、次のことが同時に起きる。

- その問のどの選択肢も、下線を外した字になる。押しても何も起こらないものの形（§6）で、ボタンでなくなる。
- 押した行は、名前を太字にし、行の右に「あなたの回答」と字で添える。§7 の「来訪者の項目」と同じく、太字だけでなく字で言う。
- **診断**: この形を 150ms（§11 の操作フィードバックの上限）見せてから、次の問（最後の問なら結果）へ移る。見せるのは止まった形で動きではないので、`prefers-reduced-motion` でも長さを変えない。
- **知識クイズ**: この形のまま、押した行の添えを「あなたの回答」「正解」か「あなたの回答」「不正解」にし、正解の行（押していなければ）に「正解」を添える。解説と「次へ」を出す。

再入力の扱いは次の3つを比べた。

| 扱い                                                                                | 判断                                                                                                                                                                          |
| ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1 見せているあいだは受け付け、押し直した選択肢に替える                             | 捨てる。人は 150ms で押し直せない（反応に 200ms 以上かかる）ので、選び直せる得は無い。二度打ちの2打目が指のずれで隣の行に落ちると、**来訪者の知らないうちに答えが隣に替わる** |
| **R2 見せているあいだは受け付けず、どの行も下線の無い字にして押せないことを見せる** | **採る。** 答えを黙って替えない。押せない形は §6 の語彙そのままで、知識クイズで答えたあとの形と同じになる                                                                     |
| R3 次の問が出てから一定の時間は押しても捨てる                                       | 捨てる。cycle-301 で正味マイナスだった形（押せる形のまま黙って捨てる）                                                                                                        |

同じ描画の中に2回の click が届いた場合（再描画の前）は、2回目を同じ問への回答として受けない。次の描画で押せない形が見える。これは時間の窓ではなく、1つの問に答えは1つという不変条件である。親の `handleAnswer` は、いまの `answers` を閉じ込めずに、前の状態から作る形にする。

最後の問でも、見せる 150ms のあとで結果へ移る。計測（`trackContentEnd`）もそのときに送る。

### 4-3. 選択肢が画面に入る組みと送り

**組み**（どれも §4・§5 に合わせる直しで、それが塊を短くもする）:

- 問の見出し（h2）は、§4 の「セクションの中の小見出し」の段（`--text-heading-sub`。`45rem` 未満で 1.0625rem）と見出しの行間（`--leading-heading`）にする。問は最初のセクションの中の見出しで、セクションの見出しではない。見出しの要素は h2 のまま（最初のセクションに h2 がほかに無いので、段を飛ばさない）。セクションの見出しの段（`45rem` 未満で 1.49rem）も比べたが、320px で1行 11字ほどになり、いまと同じ高さ（2〜3行×30）になるので採らない。
- 見出しの下の余白は 16px、選択肢の行の上下の余白は 8px にする（8 の倍数）。
- 選択肢の面はボタンの面と同じ本文の大きさ（1.0625rem）で、`Button` と同じ行間 1.4 にする。
- 帯の下の 24px は `ProgressBar` が持つ。irodori と共有で、T4-14 が 180 通りを確かめた部品なので変えない。
- 押す範囲は行全体のまま（44px 以上）。iOS の Safari が速い2度の押しを拡大に取らないよう、選択肢に `touch-action: manipulation` を掛ける（`Slider` と同じ）。

**算術の例**（320×550、character-personality Q1。問は30字、選択肢は各35〜37字）:

- いまは 547（T5-4 の 555 から上の 8 を除いたもの）。
- 問: 20px・1.6 の3行（96）→ 17px・1.25 の2〜3行（42.5〜63.8）。
- 余白: 20 → 16。
- 選択肢: 16px・1.6 の3行＋上下20（約 96.8×4）→ 17px・1.4 の3行＋上下16（約 87.4×4）で、約 37 減る。
- 合わせて **約 453〜474**、上下の 8 を足して **469〜490 ≦ 550**（余り 60〜80、選択肢の行 2〜3 本ぶん）。

文節で折るので行の終わりに空きが出て、行が増えうる。この算術は T5a-2 の全問の実測で置き換える。

**送り**（§8「操作のあと、次に見るものが画面に収まっていなければ送る」をそのまま当てる）:

- 「はじめる」を押したときと、次の問が出たときに、問のまとまり（帯の上端から最後の選択肢の下端まで）が画面に丸ごと入っているかを見る。入っていれば送らない。入っていなければ、帯が画面の上端から 8px に来る送りと、最後の選択肢の下端が画面の下端から 8px 上に来る送りの、少ないほうで送る（道具の結果の送り `revealResult` と同じ決め方）。
- 上端（サイト名とナビ）とパンくず・h1 は、送った来訪者には画面の上の外にある。上へ送れば見える。消してはいない。
- **測り方**: 上端を含めて測る。`scrollY = 0`（上端・パンくず・h1 が見えている状態）から「はじめる」を押し、送ったあとの画面で選択肢が入るかを見る。
- 200% では塊が画面より高い。帯を上端から 8px に置き、残りは来訪者が送る。「はじめる」は 200% ではどの診断でも最初の画面の外にある（T5-4）。

**問の区画を低くしない**:

- 1回解くあいだ、問の区画（`.stage`）の最小の高さを、それまでに出た区画のいちばん高いものに保つ。短い問に移っても、下のよくある質問が持ち上がらない。
- 前の問で押した指の下（とくに知識クイズで答えたあとの「次へ」の位置）に、解いている区画の外のもの（FAQ の問い）が来ない。**B-623 の直しになる**。
- 「はじめる」と「もう一度挑戦する」でやり直し、画面の幅か文字の大きさが変わったら、そのときの高さからやり直す。
- `min-height` なので中身は欠けない（§4「高さを固定した領域を持たない」に触れない）。

### 4-4. 知識クイズの答えたあと

- 解説は結果でなく、操作への応え（§8「推測への判定は操作への応えで、結果ではない」と同じ位置づけ）なので、ボックスに入れない。地（`--paper-2`）と角丸を外し、本文の大きさ・行間・`--ink` で、本文の幅（`--measure`）で組む。
- 答えたら、押した行と正解の行・解説・「次へ」を画面に入れる。
  - 「次へ」が画面に入っていれば送らない。
  - 入っていなければ、「次へ」の下端が画面の下端から 8px 上に来る送りと、押した行と正解の行のうち上のほうが画面の上端から 8px に来る送りの、少ないほうで送る。
  - 帯と問の見出しは画面の上に出てよい。index.md の条件は「正誤・解説・次へ」で、正誤は行の添えが言う。
- 推論（375×550、kotowaza Q1）: 行 4×45＋添えの折り返し＋間16＋解説4行（126）＋間16＋「次へ」44 ≒ 400〜430。上下の 8 を足して入る。320×550 は記録だけ（条件は 375×550）。
- 入らない問が出たら、帯と見出しを外に出しても入らない分は解説の文の長さにあたる。PM が、解説の文を短くするか（来訪者にまだ渡していない文言ではないので、T7 と相談）を決める。

### 4-5. 答えたあとのフォーカス（B-624）

| 置き場                                                                                                                                   | 判断                                                                                                                                                             |
| ---------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1 「次へ」（いま）                                                                                                                      | 捨てる。読み上げが正誤と解説を飛ばす。送らないので画面の外で隠れる                                                                                               |
| F2 解説と正誤の区画（`tabIndex=-1`）                                                                                                     | 捨てる。区画が大きく、リングが画面より大きくなりうる。押した所から目が離れる                                                                                     |
| **F3 押した行に残す**（行は押せない字になるので `tabIndex=-1` で受け、リングは行の字の箱に出す。§6「押せないがフォーカスを受けるもの」） | **採る。** B-624 の「見える場所に残る」そのまま。読み上げは行の名前と添え（「あなたの回答」「正解」）を読む。次の Tab で「次へ」に着き、解説は読み進めれば読める |

- 診断では、見せる 150ms のあいだ押した行にフォーカスを残し、次の問が出たら問の見出しへ移す（いまと同じ）。見出しへのフォーカスは、キーボードで操作していれば共通の二重リングで見せる（`outline: none` を外す）。リングは行の字の箱に出す（件数の行 `ListStatus` と同じ組み方）。
- 送りを先に、フォーカスをあとに（`preventScroll`）する。
- ポインタで押したときは `:focus-visible` にならないので、リングは出ない（ブラウザの決まりどおり）。

### 4-6. 「もう一度挑戦する」のあと

- 開始の画面をページの頭から見せる（`scrollY = 0`）。既定の文字の大きさでは、550 の画面で「はじめる」の下端は 533 まで（T5-4）なので入る。
- 入らないとき（200% など）は、「はじめる」の下端が画面の下端から 8px 上に来るまで送る。
- フォーカスは「はじめる」に移す（`preventScroll`）。
- 送りは即時（§11）。cycle-301 で、滑らかな送りの約 800ms が座標の不安定な窓になったため。
- 4-7 の着地の選び方をここにも当てる。

### 4-7. 画面が切り替わる操作の2打目

切り替わる操作は、「はじめる」（開始→問）、答え（問→問。知識クイズは「次へ」）、最後の答えか最後の「次へ」（問→結果）、「もう一度挑戦する」（結果→開始）の4つ。

| 手当て                                                        | 判断                                                                                             |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| D1 切り替わってから一定の時間、押しても捨てる                 | 捨てる。押せる形のまま黙って捨てる（cycle-301 の失敗）                                           |
| D2 click の `detail ≥ 2`（ブラウザが数える連続押し）を捨てる  | 捨てる。黙って捨てる点は同じ。iOS の Safari が2打目に 2 を付けるかも未確かめ                     |
| D3 何もしない                                                 | 捨てる。T5-5b の測りで、kanji-level の 375×800 の最後の「次へ」の2打目がおすすめのリンクに当たる |
| **D4 押した点に押せるものが来ない送りを選ぶ（着地の選び方）** | **採る**                                                                                         |

D4 は次のように決める。

- 切り替わったあとの送りを、上の決まりの送りにいちばん近い量のうち、押した点（1打目の click の座標）に次のものが来ない量から選ぶ。
  - 別のページへ移るもの（`a[href]`）
  - 開閉するもの（`summary`）
  - ボタン（共有・保存・「もう一度挑戦する」）
- 開始の画面の「はじめる」だけは避ける対象にしない。押した来訪者の意図（もう一度やる）に沿う。
- 送れる範囲は、見せるもの（結果のボックス、開始の画面の「はじめる」）が画面に入る範囲に限る。
- 押せるものの矩形は、指のずれとして上下左右に 8px 広げて見る。
- キーボードで押したとき（click の `detail === 0`）は点が無いので、決まりの送りのまま。
- 押した点は、`QuizContainer` が捕捉の段階の `click` の受け手で覚える。`ResultCard.tsx` の `onRetry` の形は変えない。

操作ごとの当て方:

- **「はじめる」・問→問**: 2打目は問の区画に落ちる。区画を低くしないので、区画の外に落ちない。次の問の選択肢に落ちるのは B-620 の類で、T9 で記録する。
- **問→結果**: 結果のボックスを上端から 8px に置くのを決まりの送りにする。いまは 0。`REVEAL_GAP` にそろえる。
- **結果→開始**: 4-6 の送りが決まりの送り。

選び方は描画から切り離した関数（`src/lib/reveal.ts`）にして、単体で試す。どの送りを選んでも押せるものが来ないときは、決まりの送りのまま（測りで0件であることを完了の条件にする）。

## 5. `DESIGN.md` に足す文

**§6 の種類・状態の表**（「来訪者の項目」の次の行）:

| **押した選択肢**——押すと回答が決まる選択肢のうち、押したもの | 太字。「あなたの回答」と字で添える。押したあとは同じ問のどの選択肢も押しても何も起こらないので、どれも下線を持たない |

**§6 の箇条**（「タップターゲットは 44px 以上」の前）:

- **問に答える選択肢は、押すと回答が決まるボタンを1行に1つずつ並べて組み、ラジオボタンにしない。** 診断は1つ押せば次の問へ進み、来訪者は問の数だけ押せば結果に着く。ラジオボタンで組むと、選んだあとに確かめのボタンをもう1つ押すことになる。選んだだけで進めると、矢印のキーで選ぶ所を動かしただけで答えが決まる。
- **選択肢を押すと、その問の選択肢はどれも下線を外し、押したものが押した選択肢の形になる。診断では、この形を操作フィードバックの長さ（§11）見せてから次の問へ移る。** 来訪者に、どれを押したかが見え、押し直す理由が残らない。見せているあいだに押しても何も起こらず、そのことは下線が無いことで見える。見せる長さは動きではないので、`prefers-reduced-motion` のときも変えない。知識クイズでは、この形のまま、押した行と正解の行に正誤を字で添え、解説と「次へ」を出す。
- **答えたあと、フォーカスは押した行に残す。** 行は押せないがフォーカスを受け、二重リングは行の字の箱に出る。次の Tab で「次へ」に着く。診断で次の問へ移ったら、フォーカスは問の見出しへ移る。

**§8「操作のあと…送る」の下の箇条**:

- **問に答える画面では、問のまとまり（進み具合の帯から最後の選択肢まで）を道具の結果と同じ送りで見せる。** 「はじめる」を押したときと次の問が出たときに、まとまりが画面に収まっていなければ、帯が画面の上端から 8px に来るまで送る。まとまりの下端が画面の下端から 8px 上に入る送りで足りるときは、そこで止める。
- **知識クイズで答えたあとは、押した行と正解の行・解説・「次へ」が画面に入るまで送る。** 「次へ」の下端が画面の下端から 8px 上に来るまで送り、押した行と正解の行の上のほうが画面の上端から 8px に来たら、そこで止める。
- **問の区画は、1回解くあいだ、それまでのいちばん高い区画より低くならない。** 短い問に移っても下のよくある質問などが持ち上がらず、前の問を押した指の下に、解いている区画の外のものが来ない。
- **「もう一度挑戦する」のあとは、開始の画面をページの頭から見せる。** 「はじめる」がそれで画面に入らなければ、「はじめる」の下端が画面の下端から 8px 上に来るまで送る。
- **画面が切り替わる操作（「はじめる」・答え・「次へ」・「もう一度挑戦する」）のあとの送りは、押した点に、別のページへ移るもの・開閉するもの・ボタンが来ない量のうち、上の送りにいちばん近いものを選ぶ。** 二度押した2打目が、来訪者の意図と違う所へ連れていかない。開始の画面の「はじめる」は、意図に沿うので避けない。

`frontend-design` スキルの「実装の技術」の「操作のあとの送り」の項に、問のまとまりの送り・着地の選び方も `src/lib/reveal.ts` の関数で組み、面ごとに書かないことを足す。
