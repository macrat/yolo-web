## 指摘

### Minor-1 既定の仕組みが、部品と文の中のリンクで逆に効いている

`globals.css` の既定は、次の2つである。

- hover: `:where(a[href], button, …):hover` が、字を囲む細い線を出す。これは部品向けの形である。
- フォーカス: `:focus-visible` が、リングを要素の**外**に 6px 出す。これは文の中のリンク向けの形である。

部品向けの形と文の中のリンク向けの形が、既定の中で混ざっている。そのため、どちらの側にも §6 と合わないものが出る。

- **文の中のリンク**の hover 線を外しているのは、ブログの `.prose a` だけである（ページの CSS で `--hover-line: none`）。ほかのページの文の中のリンクには、字に接する囲みが出る。例えば `/about` の「ブログ」では、囲みの下の辺が下線のすぐ下に来て、二重の下線に見える。これは §6「文の中のリンクは、下線が太い線と同じ太さになる」と合わない。前回の Minor-4 と同じ見え方が、ブログの外に残っている。
- **プライマリボタン**のリングは、要素の外に 6px 出る（`outline-offset: 3px`、外向きの `box-shadow` 3px）。これは §6「二重リングは、押せる範囲の内側に密着して出る。押せる範囲の外に出ない」と合わない。

いまは、字や縁で見える部品のすべてが `data-text-box` か `data-hit-area` を持つ。既定を逆にすれば、1か所の直しで両方が正しくなる。

- 既定: `a[href]` は文の中のリンクの形にする。hover で下線を太くし、リングは字の外に出す。
- 部品: `button` と `data-text-box`・`data-hit-area` を持つものは、囲みの hover と内側のリングにする。

ページの CSS に文の中のリンクの規則を1つずつ書く形では、T5 で全ページに同じ規則を写すことになる（AP-I02）。

**直し方**: builder が、既定を上のように組み替える。プライマリボタンにも内側のリングを掛ける。`.prose a` の上書きは消す。

### Minor-2 コントロールを並べる間隔が、部品によって 0px と 8px に割れる

§5 は、「コントロールを並べる間隔は、押せる範囲と押せる範囲のあいだで測る」「8px の倍数（8 / 16 / …）」と定める。実測は次のとおりである。

| 並び                       | 押せる範囲のあいだ                         |
| -------------------------- | ------------------------------------------ |
| ページ送り                 | 8px（`--item-gap` で余白の分を足している） |
| 上端のナビ（45rem 未満）   | 0px（遊び 19〜69.4、ツール 69.4〜）        |
| 下端のリンク（45rem 未満） | 0px                                        |
| 共有のボタン（全幅）       | 0px（X 35〜135、LINE 135〜）               |

箱が前へ 8px 張り出す分を、ページ送りは足し、ほかは足していない。同じ仕組み（`data-text-box="inline"`）なのに、間隔が部品ごとに違う。

- 7590adc のコミットメッセージは、「ボタンは…押せる範囲どうしを 8px あける」と書くが、共有のボタンは 0px である。
- `Header.module.css` のコメントは、「8px では箱どうしが接し」と、接することを前提に書いている。
- 間隔が 0 なので、並んだ2つに hover の線が出ると、境目では 1px の線が2本接して見える。

**直し方**: builder が、並びの間隔を「押せる範囲のあいだ 8px 以上」に揃える。例えば、並びの `gap` に `--text-box-pad` を足す仕組みを1か所に持つ。320px の上端では、ナビの間隔を 8px にしても1行（右端 279px < 301px）に収まる。0 のまま接して並べるのが妥当と判断するなら、planner が §5 にその値を書く。どちらにするかを決め、ヘッダーのコメントも合わせる。

### Minor-3 プライマリでないボタンが、語の途中で折れる（前回の Minor-2 が直っていない）

`/tools/business-email` の 320px では、「コピー」が「コピ／ー」の2行に折れ、下線も2行に分かれる。`.button` に、語の幅より縮まない決まり（`flex-shrink: 0` など）がまだ無い。`text-align: start` は直った。

**直し方**: 前回の指摘どおり、ボタンを語の幅より縮ませない。コンテンツ幅に収まらないときだけ折り返す。

### Minor-4 ページ送りの「前へ」「次へ」の読み上げ名が、見える文言を含まない（WCAG 2.5.3。前回の Minor-3 が直っていない）

`PaginationNav.tsx` の `ariaLabel` は、今も「前のページ」「次のページ」である。見える文言は「‹ 前へ」「次へ ›」なので、声で操作する来訪者が「前へ」と言っても押せない。共有のボタンは、同じ問題を直した（見える文言で始まる名前になった）。

**直し方**: 読み上げ名を見える文言で始める。または `aria-label` を外す。

### Minor-5 スキップのリンクが上端のナビに重なり、字の欠けた項目を残す（前回の Minor-7 が直っていない）

- 375px の dark で Tab を1回押すと、スキップのリンクがサイト名・「遊び」・「ツール」・「辞典」の「辞」を覆い、枠の右に「典」だけがのぞく。
- 1280px では、リングの右の辺が「辞典」の字に接し、「メインコンテンツへスキップ辞典　ブログ」と1つの並びに読める。

今回、スキップのリンクの左端はコンテンツ幅に合わせたが、重なり方は決めていない。

**直し方**: 前回の指摘どおり、上端の行全体を地で覆うか、上端の上に1行として出す。どちらでも、残りの項目と接しないようにする。

### Minor-6 共有のボタンの `setTimeout` が片付けられない（AP-I11。前回の Minor-8 が直っていない）

`ShareButtons` の `handleCopy` は、今も `setTimeout(() => setCopied(false), 2000)` の ID を持たない。続けて押すと、先のタイマーが後の「コピーしました」を早く消す。

**直し方**: ID を `useRef` で持ち、押し直しと unmount のときに `clearTimeout` する。

### Minor-7 コードのコメントとテストの説明が、いまの規則と合わない

- `RelatedTools.test.tsx` のテストのコメントは、「一覧の行は字だけで見えるので、字を左端に揃え…」と書く。いまの §5 では、一覧の行は「縁が見えるもの」（区切りの罫線を揃え、字は 8px 内側）である。
- `Header.module.css` のコメント（「8px では箱どうしが接し」）は、Minor-2 の決め方に合わせて書き直す。
- `FrameLink.module.css` と `Breadcrumb.module.css` のコメントは、押せる範囲を「字の幅に左右の余白を足した幅と 44px の大きいほう」と書く。§5 の「届かなければ右へ広げる」と、何を言うかは同じだが、言い方が違う。揃えると読み違えが減る。

**直し方**: builder が、上の3か所を §5 の言い方に合わせて書き直す。

### Minor-8 文の中のリンクをどう組むかの記録が、index.md に無い

index.md の補足事項は、「箇条書きや表の中のリンクのように…どう組むかが画面を見ないと決まらないものは、T2・T5 の実装のレビューで撮って決める」と書く。今回、ブログの本文のリンクは撮って確かめられた（hover で 3px の下線、リングは字の外）。

しかし、箇条書きと表の中のリンクを、文の中のリンクとして組むか、字だけの箱で組むかは、まだどこにも決まっていない。Minor-1 で既定を組み替えると、この区別が既定の範囲を決める。

**直し方**: PM が、Minor-1 の直しと一緒に、箇条書き・表の中のリンクをどちらで組むかを決め、index.md の補足事項に書く。
