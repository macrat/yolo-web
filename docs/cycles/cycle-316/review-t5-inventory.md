## Major

### Major-1. sql-formatter の「当たらない」は誤り。文字サイズ 200% の 320px で選ぶ欄がはみ出して切れる

4-2 は「sql-formatter の選ぶ欄は、320px でラベルと同じ行に置かれ、はみ出さない」として、行の「sql-formatter の選ぶ欄が 320px で折れる並びを直す」を当たらないものとして扱っている。測ったのは既定の文字サイズだけである。

文字サイズ 200%（`html { font-size: 200% }`）の 320px で測ると:

- 選ぶ欄は x=197・幅 151 で、右端が **348**（画面は 320）。コンテナの `overflow-x: clip` で右が切れ、`scrollWidth` は 320 のままなので、`scrollWidth` だけを見る検査では見つからない。
- 選ぶ欄の字が「2スペ／ース」と語の中で折れ、欄の高さが 142px になる。
- 隣のチェックボックスのラベルも「キーワード大文／字」と語の中で折れる。

T5 の行は同じ 320px の項目（`Field` の「（必／須）」・年齢計算のエラー・色の辞典の表）を 200% で書いている。4-2 の「320px で語の中で折れるラベル」（4-g）も既定の大きさでしか測っていないので、200% では挙がっていないラベルがほかにもあるはずである。

**直し方**: sql-formatter の行を「当たる（200% の 320px）」に直し、はみ出しの量を書く。4-2 の「320px で語の中で折れるラベル」を 200% の 320px でも道具36本について測り直し、4-g の対象を足す。

### Major-2. PV の 81% を持つプレイ面で、h1 を §4 にすると T5a の「選択肢が画面に入る」が悪くなる。その事実と決めることが無い

5-a は h1 を §4 の主見出しにしたとき「はじめる」が最初の画面に入るかだけを問う。ところが、回答中の画面でも h1 は残る。character-personality の 375×667 で「はじめる」を押したあとを測ると:

- h1「あなたに似たキャラ診断」は y=147〜169（17.6px）のまま残る。
- 4つの選択肢は y=485〜804。いまでも最後の選択肢は 667 の外にある。

h1 を 33.28px にすると、この画面の選択肢はさらに下へ動く。T5a の行は「選択肢が画面に入るかは、この上端を含めて測る」と書いている。T5 の h1 の変更と T5a の組み方は同じ画面を取り合うので、別々に決めると、T5 のあとに T5a の前提が変わるか、T5a が h1 の段を §4 から外す判断を迫られる。

**直し方**: 5 章に、回答中の画面の h1 と選択肢の位置（320×667・375×667、主な診断数本）を足す。決めることに「回答中の画面にもページの h1 を §4 の大きさで残すか。T5 と T5a のどちらで、どの順に決めるか」を足す。
