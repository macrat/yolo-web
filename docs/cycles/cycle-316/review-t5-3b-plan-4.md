### 3. 数え方の関数を、途中のタスクが自分のファイルに当てる手順が無い【planner】

関数は `splitIntoPhrases` を使うが、`src/lib/phrase-breaks.ts` は `import "server-only"` を持ち、`server-only` はリポジトリの `node_modules` の頂に無い。vitest は `vitest.config` の `alias` で空のモジュールに向けるので動くが、`npx tsx` で読むと `Error: Cannot find module 'server-only'` で止まる（手元で確かめた）。一方、関数を `src/` の全体に当てる試験は最後の T5-26 が置き、T5-3b が置くのは関数の単体テストだけである。

そのため、T5-3d・T5-7・T5-15・T5-18（36本）・T5-24 の builder は「受け持ちのファイルでこの関数の数が0」を確かめるために、それぞれがその場の試験や台本を書くことになる。書き方が builder ごとに違えば、数えた範囲も記録の形もそろわず、レビューで再現できない。

直し方: T5-3b が、パス（ファイルかディレクトリ）を渡して数と中身を出す走らせ方を関数と一緒に置き（たとえば vitest を経由する npm script）、その走らせ方を 4-g と、関数を完了の条件に持つ各行（T5-3b・T5-3d・T5-7・T5-15・T5-18 の共通の条件・T5-24）から指す。T5-3b の完了の条件に、その走らせ方で T5-3b の受け持ちのファイルを数えた結果を記録することを入れる。
