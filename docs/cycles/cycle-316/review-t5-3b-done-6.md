## 指摘

### 1. （小）layout-shift の記録を左右するのは「マウスの入力の有無」でなく、「字を除いてから戻すまでのあいだにヒットテストが走るか」。ふつうの layout-shift は入力が無くても記録される。指では出なかった

`research-and-verification-techniques.md` の新しい項は、見出しで「Chromium の本体は、マウスの入力を受けるまで layout-shift の記録を出さない」と言い、1つ目の点で「字をスクリプトで選んでキーボードだけで操作すると、組みが動いても layout-shift の記録が出ない」と言う。自分の測りでは、次のとおり、これは一般には成り立たない。

つまり、描く前に元へ戻る変化が記録されるのは、除いてから戻すまでのあいだに、組みを描く手前まで進めるもの（ヒットテスト。マウスがページの上にあるとブラウザがホバーを直すために走らせ、スクリプトの `elementFromPoint` でも走る）が挟まったときである。本体は、Playwright でマウスの出来事を一度も受けていないとホバーを直さないので、その一瞬の組みを数えない。次の画面まで残る変化は、入力が無くても本体で記録される。いまの見出しと1つ目の点を読んだ人は、「本体では、押す前は CLS の元になる動きが記録されない」と受け取り、読み込みの後の CLS を押さずに測ることを避けるか、押さずに測った CLS の値を疑うことになる。押す必要があるのは、描く前に戻る一瞬の変化を測るときだけで、しかも押さなくてもマウスを動かせば足りる。

また、`clipboard-and-copy.md` の 2 は「ページがマウスや指の入力を受けたあとは……layout-shift の記録が 2 件出て……`scroll` の出来事が 2 回来る。来訪者は字をマウスか指で選ぶので、来訪者のブラウザでは記録も `scroll` も出る」と書くが、指では測っていない。Chromium の本体を `hasTouch`・`isMobile` の 375×900 で開き、ページを指で1度押して（`touchscreen.tap`）から選んで写すと、上端でも 3000px 送った所でも、layout-shift の記録も `scroll` も 0 だった（受け手は動いていて、`MutationObserver` には 16 件届いた）。Playwright の指の模倣で、実機の Chrome とは限らないが、少なくとも「指でも出る」は根拠が無い。

直すこと:

- `research-and-verification-techniques.md` の項を、「描く前に元へ戻る一瞬の組みの変化は、そのあいだにヒットテストが走ったときだけ layout-shift の記録と `scroll`（スクロールのアンカーの直し）になる。マウスがページの上にあるとホバーの直しで走るので、Playwright の Chromium の本体では、マウスの出来事を1度も送っていないページでは記録されない。次の画面まで残る変化は、入力が無くても記録される」という中身に書き直す。見出しも同じ中身にする。測るときは「写す前にマウスを動かすか押す」「0 件は根拠にならない」「ブラウザの種類と入力の有無を記録する」は今のままでよい。根拠に、上の対照（残る変化は入力なしで 1 件、`elementFromPoint` を挟むと入力なしでも 2 件、マウスを動かすだけで 2 件）を足す。
- `clipboard-and-copy.md` の 2 の「マウスや指の入力を受けたあとは」「マウスか指で選ぶので、来訪者のブラウザでは記録も `scroll` も出る」を、測ったことに合わせる（マウスを使うブラウザでは出る。指だけのときは Chromium の指の模倣では出ず、実機は測っていない）。根拠の段落にも、指の模倣で 0 だったことを書く。`scroll`・`MutationObserver`・layout-shift を読む処理を足すときに一瞬の DOM を考える、という結びは今のままでよい。

### 2. （小）Ctrl+A の選択を写すと、次のコピーから末尾の改行が1つ落ちる

受け手は、字を戻したあと、選択の両端が除いたあとのままなら、`setBaseAndExtent` で元の両端に置き直す。両端が語結合子の位置に無いとき（Ctrl+A の両端は、ページの最初の字の節の 0 と、フッターの「プライバシー」の字の節の 6）は、字を戻しても両端はもう元のままなのに、置き直しを呼ぶ。Chromium は、Ctrl+A で選んだ「全体の選択」を、両端が同じでもふつうの範囲に変えるので、同じ選択をもう一度写すと末尾の改行が落ちる。

本体の 1280×900 と 375×900 で、同じ Ctrl+A の選択を3回続けて写すと、受け手ありは 11,971・11,970・11,970 字（375px は 11,707・11,706・11,706）で、2回目から末尾の「プライバシー\n」の「\n」が無い。受け手を止めると 11,975 字が3回続く。受け手を止めたまま、Ctrl+A の選択に同じ両端で `setBaseAndExtent` を呼ぶだけで 11,975 → 11,974 字になるので、原因は置き直しである（画面の画素は変わらない）。h1 を3度押した選択と、見出しから段落までの選択では、3回とも同じ字数だった。

来訪者への害はごく小さい（ページ全体を2回写したときの末尾の改行1つ）が、知見の文書 2 の「クリップボードの中身は、受け手を止めたときの中身から語結合子を除いたもの……と同じになる」「選択の両端と h1 の字も元に戻った」は、2回目のコピーでは成り立たない。直し方は、字を戻したあとの両端が `ends` と同じなら置き直さない、の1つで済む（例: `keepSelection && !sameEnds(selection, ends) && …`）。試験に「字を戻しただけで両端が元に戻る選択では、`setBaseAndExtent` を呼ばない」を足す。直したあと、本体で Ctrl+A を3回写して字数が 11,971 のまま続くことを測り、知見の文書の根拠に書く。
