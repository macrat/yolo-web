## 行の一覧の中の字（文字サイズ 200%）

計り方: 見える行ごとに、行の中のすべての文字の矩形（テキストノードの `Range.getClientRects()`）とすべての要素の矩形を、次の3つと比べた。

- 行（`li`）の左右の端
- 一覧を囲む太い線を左右に持つ祖先（一覧のボックスとコンテナ）の、線の内側
- 各要素の `scrollWidth` と `clientWidth`

| 画面幅 | 行の外や線の外へ出る字・要素 | ページの `scrollWidth` が画面幅を超える |
| ------ | ---------------------------- | --------------------------------------- |
| 320px  | `ItemList` では0件           | 0 ページ                                |
| 375px  | 0件                          | 0 ページ                                |
| 1280px | 0件                          | 0 ページ                                |

同じページで、`.name` と `.reading` の `min-width` を `auto` に戻す CSS を当てて計り直すと、字が行の外へ出るページは 320px で 242（ブログの一覧 14・記事 20・辞典 203・ツール 4・storybook 1）、375px で 78、1280px で 0 になる。この変更が、はみ出しを消したことが分かる。

撮って目でも見た（320・375・1280px。`tmp/cycle-316/rv35r3/`）。タグ「Web開発」の 320px では、「50字で215秒／フリーズした／正規表現を、／Worker.termin／ate()で100ms／に収める」と、字がボックスの枠の内側で折れ、枠にも罫線にも掛からない。漢字の一覧では、読みが名前の下の行に落ち、「イチ・イツ・ひと・／ひとつ」とボックスの中で折れる。

320px で1件だけ外へ出る行は `ItemList` ではない（下の「このコミットの外で見つけたこと」）。

## 既定の文字サイズでの見た目

同じ 866 ページを、既定の文字サイズ（16px）の 320・375・1280px で、ce6cfe8 の CSS と、`.name`・`.reading` の `min-width` を `auto` に戻した CSS とで計り、行の中の各要素の矩形（行の左上からの位置と大きさ）を比べた。

- 1280px: 違う行は0。
- 320px: 違う行は、4本の記事（`site-rename-yolos-net`・`character-quiz-result-as-fuda`・`top-page-toolbox-launch`・`rss-feed-and-pagination`）の関連の一覧に並ぶ「コンテンツ信頼レベルの導入: 全ページにverified/curated/generated…」の1行だけ。戻した CSS では、名前のリンクの幅が 205px で行の中身の幅 180px を越えていた。直した CSS では 180px に収まる。既定の文字サイズでも起きていたはみ出しが消えたもので、ほかの形は変わらない。
- 375px: 違う行は0。

ページ全体の位置で比べたときに違いが出た3ページ（`/play/kanji-kanaru` など）は、行の中の位置で比べ直すと違いが無く、計るあいだに一覧より上の中身が動いたためだった。

§7 の組み方（読みが収まらなければ次の行の左端から始まる、`45rem` 以上で種別と補助情報が名前の行の右端に来る）も、撮った画像で変わっていない。flex の項目が次の行へ送られるかは最小の幅ではなく中身の幅で決まるので、`min-width: 0` は、名前と読みの並び方を変えず、1語が行より長いときだけ効く。

## 指摘

### Minor-1 `blog-series.test.ts` に、消えた連載の ID で組んだ、何も確かめないテストが残っている

- **どこで**: `src/blog/__tests__/blog-series.test.ts` の「does not include posts without a matching series」。
- **何が起きるか**: このテストは `getSeriesPosts("tool-guides")` の結果に、ほかの連載の記事が混ざらないことを見る。しかし連載 `tool-guides` はもう無い（`SERIES_LABELS` は `ai-agent-ops`・`japanese-culture`・`nextjs-deep-dive` の3つで、`series: tool-guides` の記事も0本）。そのため結果は必ず空の配列で、テストは中身を見ずに通る。
  - このコミットは、`blog.test.ts` から「削除されたシリーズ tool-guides が含まれないこと」を消した。同じ名残が、同じ `src/blog` のこのファイルに残っている。
- **来訪者への効き方**: 直接の見た目は変わらない。ただ、`getSeriesPosts` がほかの連載の記事を混ぜるようになっても、このテストは通る。連載の案内（`SeriesNav`）に別の連載の記事が並ぶ退行を、テストの名前が守っているように見せて見逃す。
  - 2巡目の Minor-3 は、同じ範囲の移行の名残のテストを「いまの規則を言うテストに書き直すか消す」ことを求めていた。CLAUDE.md のツギハギ禁止も、見つけたらその場で直すことを求めている。
- **直し方**: いまある連載（記事が2本以上の `ai-agent-ops` など）で、結果にほかの連載の記事が無いことを見る形に書き直す。1つ目のテスト（各記事の `series` を見る）で足りると判断するなら、消す。

## 指摘ではないが確かめたこと

- **200% の 320px の分類の見出し**: 「開発ノー／ト」と、語の途中で折れて「ト」が1字で行に残る（`tmp/cycle-316/rv35r3/shot-cat-dev-320-200-dark.png`）。2巡目の Minor-1 のタグと分類の見出しと同じもので、T5 が受け持つ。T5 で直したあと、この見出しも撮り直してほしい。
- **200% で「AI」が1行になる形**: 「AI」は IBM Plex Sans、「試行錯誤ブログ」は Zen Antique で組まれ（§3）、1行目が細く見える。§3 の書体の分け方どおりで、語の切れ目でもあるので、指摘にしない。
