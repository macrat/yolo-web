## 指摘

1. **5-2 の「2,740」の定義と「約 300回」の見込みが、同じ節の数と合わない。**
   - **どの数が縛るか**: 診断の12本の走査は 576 回（1本 48 回）で、問は 127 問ある。どの走査も全ての問に1度ずつ答えるので、答えは 127 × 48 = 6,096 回になる。答えは次の4つのどれかで入る。
     - 最後でない問への1打目（3,096）
     - 最後の問への1打目（L）
     - 2打目で最後でない問に答えた回（X）
     - 2打目で最後の問に答えて結果に移った回（S）
   - **下限**: どの走査も L か S のどちらか1つで終わるので、L ＋ S = 576 である。したがって X = 6,096 − 3,096 − 576 = **2,424** になる。2打目が答えを入れられるのは、次の問の選択肢に落ちた 2,823 回のうちだけである。そこで X ＋ S ≤ 2,823 となり、S ≤ 399 になる。
   - **2,740 に S が入っていなければ食い違う**: 5-2 は 2,740 を「帯の番号が2以上進んでいた押し」とする。これが途中の問を飛ばした回だけなら、X ≥ 2,740 になり、X = 2,424 と食い違う。数が合うのは、2,740 が結果に移った回（S）を含むときだけである。そのとき S = 2,740 − 2,424 = **316**、L = 260 になる。2打目で答えたのに記録の時点で帯が進んでいなかった回があれば、S はもっと多い（上限 399）。
   - **いまの本文の問題**: 本文の「約 300回（推論）」は、この下限 316 を割っている。「飛ぶ率（2,740/3,096）から見込む」という導き方も、文から組み直せない。さらに B-620 の材料として読む「問が飛んだ」2,740 には、途中の問を飛ばした 2,424 回と、結果に移った約 316 回が混ざる。T5a-7 がこれを知らずに「途中の問が飛んだ回」を数えると、比べを誤る。character-personality の測り直しも同じ形である（44 × 12 = 528、528 − 265 − 44 = 219。256 が S を含むなら S = 37）。
   - **関連（小さなもの）**: 同じ箇条の「1280×800 と 740×360 では、ほぼ毎回（120〜126/126）」は、126 が何ごとの分母かを書いていない。すべての答えが飛んだときの、画面・入力・間隔ごとの最後でない問への1打目の数（12本で 63 × 2行 = 126）と読める。しかし、飛ばない回があれば分母は 126 から動く。
   - **直し方**: 5-2 の「数え方」に次のことを書く。
     - 2,740 は、2打目で最後の問に答えて結果に移った回も含む。担当の記録で、結果の画面での帯の番号をどう扱ったかを確かめて書く。
     - 上の恒等式から、結果に移った回は 316 以上 399 以下、途中の問を飛ばした回は 2,424 である。
     - 「約 300（推論）」をこの算術に置き換える。
     - 「120〜126/126」の分母の単位を書く。
     - T5a-7 が走査ごとに S を記録する務めは、いまのまま残す。

2. **0章の「T5a-7 の前の確かめ」は `import` だけをたどるので、ページが読み込む書体のファイルと、`src` の外の変更を拾えない。** 本文の書体は `src/lib/fonts.ts` の `localFont` が `path: "../fonts/ibm-plex-sans/…woff2"` で読み込む。これは `import` でないので、手順の「読み込むファイル」に入らない（独立にたどった 148 ファイルにも入っていない）。`package.json`（Next.js の版など）や `next.config.ts` の変更も、`src` の差だけを見る手順には出てこない。書体の差し替えや、組版に掛かるフレームワークの更新は、条件1・6・7 の値を動かしうる。0章の「T5a-7 の前の確かめ」の例も、書体（T5-28）である。
