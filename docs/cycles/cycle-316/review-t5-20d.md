## 指摘

### 1. 漢字カナールの結果の2つの表で、列の境がそろわなくなった（直す）

漢字カナールの結果のボックスには、「読みと意味」と「これまでの成績」の2つの表が、小見出しを挟んで上下に並ぶ。

前の `ResultTable` は、見出しの列を 4.1em＋8px の決まった幅にして、同じ結果の中の2つの表で値の始まりをそろえていた。before では、どの幅でも両方の表の見出しの列が同じ幅である（既定で 78px、200% で 147px）。

after では、`DataTable` の `width: 100%` の表に、ブラウザが余りの幅を列の中身の長さに応じて配る。そのため、2つの表の見出しの列の幅がずれる。

| 画面       | 読みと意味（見出しの列＋値の列） | これまでの成績 |
| ---------- | -------------------------------- | -------------- |
| 320 既定   | 66＋178                          | 131＋113       |
| 375 既定   | 81＋218                          | 161＋138       |
| 1280 既定  | 239＋645                         | 476＋408       |
| 375・200%  | 111＋188                         | 162＋137       |
| 1280・200% | 315＋889                         | 651＋553       |

1つの太い枠の中で、縦の罫線が 1280 では x≈258 と x≈494、375 では x≈92 と x≈172 に立つ。上の表を読んだ目が下の表の値を探すとき、値の始まりが横に跳ぶ。PM が受け入れたのは「全幅になり、値がラベルから離れる」ことで、この食い違いは受け入れた範囲に入っていない。見出しの列の幅も、中身の長さに応じて配られた余りで決まる。そのため「音読み」の列が 1280 で 239px になるなど、幅がどこから来たのか読み取れない。遊び終えた来訪者の全員が見る画面である。

直し方への条件は次のとおりである。

- 呼ぶ側に幅の指定を足さない（AP-I02。T5-12 の決定 (2) の「ゲームごとに崩さない」）。部品（`DataTable`・`src/lib/scroll-frame.ts`）の側で、余りの幅をどう配るかを決める。
  - 候補の1つは、行の見出しの列をいちばん長い文節の幅に留め、余りを値の列に渡すことである。見出しの列が字の幅で決まるので、値がラベルのすぐ右に来て、2つの表のずれも1字ほどに縮む。
  - 見出しの列を字数で決めた幅にそろえる形もありうる。ただしその場合は、同じ結果の中の表の組をどう扱うかを DESIGN.md §5 の表の項に先に書く（AP-I08）。
- 部品を変えるなら、`DataTable` を使うすべての面を、変える前と後で撮り比べる（AP-I14）。色の辞典のカラーコード・年齢計算・文字数カウント・敬語早見表・逆張り運勢診断・4本のゲームなどで、`grep -rn "components/DataTable" src` で洗い出す。
- どの形にするかは、PM が planner に比べさせて決める。PM がこの食い違いを受け入れると決める場合は、その理由を index.md の決定に書き、次のレビューで確かめる。

### 2. irodori の要素のセルが、部品の取り決めの外にある（直す・小）

`DataTableCell` の注記と SKILL.md（実装の技術の「記事の外の表は `DataTable` で組み…」）は、要素のセルを「セルに置くコントロール（行の頭の開閉のボタンなど）」とし、面の字はその要素が区切りの並びで組むと決めている。

irodori は、色見本（コントロールでない見本）と「記録なし」の字（区切りの並びを通らない `span`）を要素で渡している。「記録なし」は1文節なので、いまの画面には違いが出ない。しかし、部品の取り決めと使い方が食い違ったままだと、次に要素のセルを使う人が、区切りを通らない字を要素で渡してよいと読む。

次のどちらかにして、取り決めと使い方を一致させる。

- 部品の注記と SKILL.md の同じ項に、中身の見本（色見本）を要素で渡すことを書き足す。
- 字は区切りの並びで渡す（たとえば「記録なし」を `PhrasedText` で組む）。

どちらにするかは builder が決め、注記はいまの形を言う文で書く（ツギハギにしない）。

### 3. irodori の 320 既定で、読み込みのときに 0.1625 のずれがある（T5-20d の外。PM が受け持ちを決める）

`/play/irodori` を、遊び終えた記録を持って 320 既定で開くと、入力に続かない layout-shift が1回、0.1625 出る。出どころは `HowToPlay`・`GameContainer` の日付・`Section` で、before でも同じ値である。T5-20d が生んだものではなく、表とも関わらない。

それでも、Core Web Vitals の「良い」の上限（0.1）を1回で超えるので、来訪者の読んでいた所が動く。受け持つタスクを PM が決め、index.md に書く。
