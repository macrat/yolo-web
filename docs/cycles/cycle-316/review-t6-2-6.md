## 指摘

### Minor-1: 4つの書体のどれにも無い字（「纁」）を、`next/og` が黙って別の書体で描き、取れないときは豆腐の画像ができる

`share-image.tsx` は、Zen Antique に無い字を含む名前を BIZ UDGothic で組む。しかし「纁」は BIZ UDGothic にも無い（opentype.js の `charToGlyphIndex` が4つの書体のどれでも 0。t1a-fonts.md の「彐・纁は BIZ UDGothic にも無い」とも合う）。このとき描いているのは次のものだった。

- `ImageResponse`（`next/dist/compiled/@vercel/og/index.node.js` の `loadDynamicAsset`）が、無い字を見つけると、`fonts.googleapis.com/css2?family=Noto+Sans+JP&family=Noto+Sans+SC…` と `…?family=Noto+Sans+JP&text=%E7%BA%81` と `fonts.gstatic.com` の3つを取り、Noto Sans JP で描く。スクラッチで `fetch` を記録して確かめた。つまり、画像の「纁」は BIZ UDGothic ではなく Noto Sans JP で、モジュールが読み込んだ4つの書体の外の書体。
- その取得が失敗すると、`loadDynamicAsset` は例外を握りつぶし（`console.error` だけ）、画像は 200 で書き出される。Noto の要求に 503 を返すようにして描くと、名前の所が×の箱（豆腐）の PNG になり、例外は出なかった。

来訪者にとっては、伝統色「纁」のページを X や LINE で共有すると、主役の名前が豆腐の画像が出うる。しかもビルドは止まらない。ファイルの頭のコメント「書体を取れないときは例外を投げる。…違う書体の画像が出荷される前にビルドが止まる」は、この字では成り立たない。伝統色の画像は T6-5 で出るが、字を選んで描くのはこのモジュールの仕事。部首の「彐」（索引のページ）も同じ種類の字になる。

記録とテストも事実と違う。

- t6-log.md の表の「纁（Zen Antique に無い字）｜96px｜1行、BIZ UDGothic」。描いた字は Noto Sans JP。
- テスト「Zen Antique に無い字を含む名前は、和文を丸ごと BIZ UDGothic で組む」は `run.family` だけを見ていて、字が本当にその書体で描かれるかを確かめていない。また描く時間のテストの `WARM_UP` にも「纁」があるので、このテストは知らないうちに Noto の取得（ネットワーク3本）に頼っている。

直すこと（builder。書体の選び方は t6-design.md の 212 行の決め事に足すことになるので、PM が方針を決めてから渡す）:

- 組む書体に無い字を、モジュールが自分で決めた書体で描く。DESIGN.md §3 の本文書体の並び（`"BIZ UDGothic", …, "Noto Sans JP"`）に合わせるなら、BIZ UDGothic に無い字だけを Noto Sans JP で組むのが筋。その書体はモジュールが `fetchGoogleFont` と同じく取り（`text=` で字を絞る場合、Google の返す URL は `.ttf` で終わらないので、今の正規表現はそのままでは使えない）、字の幅もその書体で測り、取れなければ例外を投げてビルドを止める。`next/og` の黙った取得に頼らない。
- テスト: 「纁」の名前で、字を描く run の書体がその字の形を持つこと（4つの書体と足した書体のどれか）。足した書体の取得が失敗すると例外を投げること。
- t6-log.md の「纁」の行を、描いた書体どおりに直す。t6-design.md の 212 行（Zen Antique に無い字の扱い）に、BIZ UDGothic にも無い字の扱いを足す。

### Nit-1: テストの名前と補助の関数に、前の形の名残がある

- テストの名前「字の範囲のまとまりに禁則の字が付いて1行を超えるときは、そのまとまりの中で折る」は、ソースが「書体のまとまり」「割れない字の組」に呼び分けたあとも古い呼び名のまま。ソースの呼び名に合わせる（たとえば「書体のまとまりに禁則の字が付いて1行を超えるときは、割れない字の組の境で折る」）。

### Nit-2: `breakUnits` のコメントの「組を字に分けるのは、行の頭に置かない字が1行より長く続くときだけ」が狭い

開き括弧が1行より長く続くとき（「「「…」）も、括弧と次の字が1つの組になって1行を超え、字に分けられる。今の入力には無い形だが、コメントは「禁則の字が1行より長く続くときだけ」と書けば正しくなる（直すこと: builder。Minor-1 と一緒に）。
