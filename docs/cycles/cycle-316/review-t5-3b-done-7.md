## 指摘

### 1. （中）キーを押さずに写すと、受け手の layout-shift が `hadRecentInput: false` になり、CLS に入る（1280px の h1 で 1回 0.241）

`hadRecentInput` が true になるのは、ずれの前 500ms 以内に、ページが押す・叩く・キーの出来事を受けたときだけである（[web.dev の CLS の説明](https://web.dev/articles/cls)、[MDN の LayoutShift](https://developer.mozilla.org/en-US/docs/Web/API/LayoutShift)）。Ctrl+C はキーなので true になる。一方、右クリックのメニューやブラウザの「編集」のメニューから選ぶ「コピー」は、ブラウザの UI での操作で、ページには入力として届かない。そのうえ、マウスはページの上にある。つまり、受け手が字を除いてから戻すまでのあいだに、ホバーの直しでヒットテストが走りうる（知見の文書が言う、記録が出る条件）。

Playwright では、ブラウザのメニューの項目は押せない。そこで、メニューからのコピーを次のように模して測った。本番のビルドを Chromium の本体（`/opt/pw-browsers/chromium`、Chrome 141.0.7390.37）で開き、1280×900 で h1 をマウスで3度押して選んだ。そのあと h1 の上で右クリックし、700ms か 1500ms 待ってから `document.execCommand("copy")` で写した。

どの場面でも、クリップボードの中身は正しかった（h1 は 70 字で語結合子 0、止めると 74 字で 4 個）。記録が出ない回があるのは、ホバーの直しが走る時機によると見られる（推論）。

来訪者にとっての意味は次のとおり。ハイフンやダッシュを含む記事の見出しを、キーボードを使わずにメニューで写す PC の来訪者がいる。そのページの読み込みでは、ずれは画面に描かれないのに、CLS が 1回で 0.241 増える。これは「良い」の上限 0.1 を超え、「悪い」の 0.25 に近い。CLS は Chrome の実測（CrUX）に入り、検索の評価の Core Web Vitals の1つである。サイトの CLS の p75 が動くほどの割合の来訪者がそうするとは考えにくい。それでも、決定 (7) は「見えない字で失敗しないようにする」ことと引き換えに何を払うかを量って決めるべきもので、この費用はその量りに入っていない。今の文書を読んだ後の作業者は「CLS には数えない」と受け取り、同じ組み方をほかの所に広げかねない。

直すこと:

- builder が、上の場面を自分で測り直す（メニューからのコピーを `execCommand("copy")` で模すことと、その限りを書く）。
- PM が、この費用を受け入れるか、組み方を変えるかを決め、決定 (7) の近くに記録する。変えるなら、除いたあいだに組みが変わらない方法があるかを builder に調べさせる。受け入れるなら、どの見出しのどの幅で、1回いくつ入るかを書き、受け入れる理由を来訪者と検索の評価の両方から書く。
- `clipboard-and-copy.md` の 2 の「（`hadRecentInput: true` なので CLS には数えない）」を、測ったことに合わせる。キーで写すと true で CLS に入らない。メニューから写すと false で CLS に入る（1280px の h1 で 0.127・0.114）。根拠の段落にも、メニューからのコピーの模し方と値を足す。`research-and-verification-techniques.md` の項は、「測った記録には、写す前の入力の有無と種類を書く」に並べて、「写す操作がキーかメニューかで `hadRecentInput` が変わり、CLS に入るかが変わる」ことを書く。どちらも、書き足した跡が残らない形にする。

### 2. （小）スキルの 5 の「「--」には置かない」が、コードと直前の文の逆に読める

スキルの 5 は、まず「ダッシュ（「—」「──」「--」）とハイフンで結んだ語は、`PhrasedText` が語結合子でつなぐ」と書き、「ダッシュの字どうしのあいだを語結合子にして前の語に付ける」と続ける。そのあとで、「語の中の1つの「-」の後ろにも語結合子を置き……数字の前（「UTF-8」……）と「--」には置かない」と書く。

コード（`INSIDE_OR_BEFORE_DASH` の `(?<=[^\s-])(?=--)|(?<=-)(?=-)`）は、「--」の前と、2つの「-」のあいだに語結合子を置く。最後の句は「1つの「-」の規則は「--」には当てはまらない」という意味のはずだが、書いたとおりに読むと「「--」には語結合子を置かない」になり、2文前ともコードとも食い違う。`phrase-dashes.ts` の説明（「前後が空白でも「-」でもなく、後ろが数字でない所」）は正しく書けている。

直すこと: たとえば「数字の前（「UTF-8」。ブラウザがもともと折らない）には置かず、「--」は上のダッシュとして組む」のように、「--」がどちらの規則で組まれるかを読み違えない文にする。
