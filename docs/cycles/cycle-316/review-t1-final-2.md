## 指摘

### Minor-1: 辞典を足して 320px の上端が3行（151px）になった。その代償が記録されておらず、補足事項の説明が事実と合わない

上端のナビに辞典を置いた（dcafbe7）ことで、320px の上端は 107px から 151px に伸びた。サイト名の行の下に、ナビが「遊び ツール 辞典 ブログ」と「サイト紹介」の2行に分かれるためである。PV の78%が集まる `/play/character-personality` では、320×568 の「はじめる」の下端が y=578 から y=623 に下がり、最初の画面の27%を上端が使う。

- index.md の補足事項は、辞典を置いた理由（検索の表示回数の76〜79%が辞典）は書いているが、320px で上端が1行分高くなる代償は書いていない。
- 同じ補足事項の「間隔を広げると 320px でナビが3行になり……フォーカスのあいだだけの重なりを受け入れた」は、いまの事実と合わない。320px は間隔が 8px のいまでも3行になっている。間隔を 16px にすると3行になるのは、375px のほうである（5項目の字の幅の和 259px ＋ 間隔 16px×4 ＝ 323px が、375px のコンテンツ幅 320px を越える）。
- 同じ項の「短い項目（遊び）にフォーカスがあるあいだだけ、輪が隣の字に約 3px 重なる」にも、辞典が抜けている。辞典も字の幅が 34px で、輪は両隣の「ツール」「ブログ」に約 3px ずつ重なる。なお「遊び」の輪は左の辺が、コンテナの左のボーダー（x=16〜19）とちょうど重なる。外の輪がボーダーに溶けて、左の辺だけ見分けがつかない。
- T5a の行は「上端は 375px で高さ 107px になる」とだけ書く。B-614 の解消の条件は 320×550 でも測るので、その幅では上端が 151px になることが書かれていない。

**直し方**: 補足事項に、辞典を置いたことで 320px の上端が 151px になる代償を書く。フォーカスの輪の重なりを受け入れた理由は、375px の話として書き直し、重なる項目に辞典を加える。T5a の行に 320px の値を足す。あわせて、上端の「サイト紹介」は下端にもあるので、上端から外せば 320px でも上端が2行（107px）に戻る。サイト紹介の PV を GA で確かめ、どちらが来訪者のためになるかを PM が判断して記録する。

### Minor-2: 和色のトークン（`--wairo-*`）の扱いがどのタスクの行にも無い。`globals.css` の注記も事実と合わない

- `globals.css` は、中身の色である和色8色と、その上に置く文字色（`--wairo-*-on`）を `:root` のトークンとして持っている。§12 は「コンテンツの色はトークンを持たない」と定めている。§2 は「コンテンツの色の上に文字を置かない」と定めているが、`-on` の色はその置き方のためにある。完了の条件の「UI のトークンとして定義する CSS 変数」にも当たり、このままでは T8 の検査で初めて引っかかる。
- review-t1-base-2.md は「T4: `--wairo-*` は……色が主題の面を組み直すときに扱う」と申し送った。しかし index.md の T4 の行には和色のトークンが書かれていない。T5 の「T5 の終わりに `globals.css` から古いトークンの定義を消す」の「古いトークン」も、T2 の行が挙げる5つ（`--accent` など）を指すと読める。
- 注記の「色が中身として出るところにだけ使い、UI には使わない」は事実と合わない。なかまわけの統計の強調のバー（`StatsModal.module.css` の `.distributionBarHighlight`）と、運勢の星（`StarRating.module.css`）は、色で飾ったり強調したりする UI に和色を使っている。

**直し方**: T4 の行に「`--wairo-*` と `--wairo-*-on` を使う面（包み・ゲームの判定・統計・星）を §2 のとおりに組み直し、`globals.css` から和色のトークンの定義を消す」と書く。消すタスクを1つに決める。`globals.css` の注記は、事実（どこで使っているか）だけにする。

### Minor-3: `scripts/generate-favicons.ts` の説明が経緯と事実に合わず、置いてある資産とも食い違う

dcafbe7 で `ACCENT` を `INK` に置き換えたとき、冒頭の説明を「ブランド標章 F2『墨の印・白抜き y』……B-576（cycle-306）で PM が実レンダーを見て確定した方向」に書き換えた。B-576 で確定したのは朱の印で、墨の印は誰も決めていない。`public/icon.svg` などの資産は朱（`#af3622`）と旧い紙の色（`#f8f7f2`）のままである。いまこのスクリプトを実行すると、今ある資産とも `DESIGN.md` §10（角丸なし・見出し書体の `y`）とも違う、墨の角丸の印ができる。`site-metadata.ts` のコメント「朱の角丸タイルに白抜きの y」は資産の事実に合っていて、スクリプトとは合わない。

**直し方**: 作り直しは T6 の範囲なので、いまは説明を事実に戻す（今ある資産を生んだのは朱の定数で、`INK` に替えたのは定数の名前が無くなったため、と書くのではなく、説明を「いま実行すると何ができるか」だけにする）。または、T6 の行に「`scripts/generate-favicons.ts` を §10 のとおりに作り直す」と書き、スクリプトの冒頭の説明から誤った経緯を消す。
