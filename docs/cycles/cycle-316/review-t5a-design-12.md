## 指摘

### 1. 知識クイズで答えた行の字は選べる字のままで、マウスのダブルクリックの2打目が押した名前の1語を塗る

ボタンをダブルクリックで押す来訪者は少なくない（review-t6-9-4.md が同じ癖を扱った）。知識クイズでは、1打目で答えが入り、その問の行はどれもボタンから字の `span` に替わる（4-2）。2打目は同じ点、つまり押した行の名前の字の上に落ちる。字は `user-select` の指定を持たない選べる字なので、ブラウザはダブルクリックとして点の下の1語を選ぶ。上の測りでは、押した名前「ねこと一緒に…」の「こと」が選択の色で塗られた。サイトの `::selection` は `--ink` の地に `--paper` の字（`globals.css` 350行）なので、黒い塊が押した名前の中に出て、解説を読むあいだ残る。来訪者には、答えた名前の一部が壊れて見える。

診断の押した行は `::after` が行を覆うので、選択は `"\n"` になり何も塗られない。知識クイズの行は 4-2 のとおり `data-hit-area` と `::after` を持たないので、この違いが出る。いまのコードの知識クイズ（答えた行は `.choiceText` の `span`）でも同じことが起きるが、T5a は答えた行の組みと2打目の扱いを決め直す設計で、4-2 は「2打目は押せない行に落ちる」を害の無いこととして扱い、6章 条件7 は落ちた要素だけを記録するので、この像は測りにも撮りにも出ない。

同じ理由で、4-2（181行）の「答えた選択肢は持たず、矢印になる」も事実と合わない。`cursor: auto` は選べる字の上では字のカーソル（I の形）になる（CSS UI 4 の `auto`）。矢印になるのは字の外の余白だけである。

直すこと: 答えた選択肢の字の上のダブルクリック（とトリプルクリック）で選択を出すかを決め、4-4 か 4-11 に書く。答えた名前を写したい来訪者（ことわざや四字熟語を調べる人）もいるので、`user-select: none` で写せなくするのか、同じ問の2打目（`mousedown` の `detail >= 2`）だけ既定の動きを止めるのか、受け入れるのかを比べて選ぶ。4-2 のカーソルの括弧書きは、決めた組みの事実（字の上では字のカーソル、など）に合わせる。決めた扱いは、条件3 か条件7 のマウスの2度押しの回で `getSelection()` を記録して確かめる。

### 2. 4-11 の `[data-text-box]` の説明の書き直しが、実行のさいちゅうの字を落としている

419行は、`globals.css` の `[data-text-box]` の規則の上の説明で、`"inline"` を使うものの並びに「答えた選択肢の字」を加える、と言う。ところが診断の押した行の字も、答えたあとの字と同じ箱の規則と `data-text-box="inline"` を持つ（4-4 の 252行「答えたあとの字も」、4-2 の「その問のどの選択肢もボタンから字に替わる」）。§6 の定義（453・457行）では、押した行の字は実行のさいちゅうで、答えた選択肢ではない。5章の §5 の文（445行）も「答えた選択肢と実行のさいちゅうの選択肢（§6）の字も、押す前のボタンと同じ字の箱に置く」と両方を挙げる。419行のまま書くと、`globals.css` の説明は `"inline"` を持つ押した行の字を並びから外し、`DESIGN.md` §5 とも食い違う。

直すこと: 419行を「答えた選択肢と実行のさいちゅうの選択肢の字（押す前のボタンと同じ字の箱に置くもの）」を加える形にする。

### 3. 第11回の直しで入った文が、4-2 と 4-11 のつながりを崩している

- **4-2（181行）の「そのため」**: 直す前は「ポインタが押した行の上にあれば…線が出て、外にあれば出ない。そのため、字の `span` にも…`data-hit-area="after"` と `::after` を持たせ、…hover の線が同じ範囲に出るようにする」と続いていた。あいだにカーソルの文が入ったので、「そのため」がカーソルの文を受け、`data-hit-area` と `::after` がポインタの形のための指定であるかのように読める。`data-hit-area` はカーソルを何も与えない（`globals.css` の `data-hit-area` の規則は hover とフォーカスだけ）。カーソルは `QuestionCard.module.css` に書く別の宣言である。
- **4-11（418行）**: 押した行の字の `cursor: pointer` の箇条が、「`globals.css` の説明を、次の事実のとおり…書き直す」の子の箇条に入っている。親の箇条の読みでは「`globals.css` の説明に書く事実」の1つになり、builder が `globals.css` の説明に `QuestionCard.module.css` のカーソルのことを書き込みうる。同じことは 421行（「その `span` に `cursor: pointer` を持たせる（4-2）」）にもあり、2度書かれている。

直すこと: 181行は、カーソルの文を hover の線と `data-hit-area` の文のあと（または前の独立した文）に置き、「そのため」が線の文を受けるようにする。418行の箇条は消し、421行の1か所に残す（「答えた選択肢の字には書かない」はそこに入れる）。
