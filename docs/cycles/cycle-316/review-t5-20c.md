# レビュー: T5-20c 今日のほかのパズルとほかの分類（9510306a）

対象: 9510306a「T5-20c: game banners as sections with a subheading, played-count wording, boxed lists」。基準は t5-design.md の T5-20c の行・6-a・6-c・10-4、DESIGN.md §4（見出しの段と折り方）・§5（線・ページの割り方・ボックス）・§7（行の一覧）、CLAUDE.md のツギハギ禁止。見た目は builder の撮った 42 枚（前後 × 4本 × 320/375/1280・320px 200%・375px ダーク・すべて遊んだ日）で来訪者の目から確かめた。

## 判定: 改善指示

部品2つの組み替えそのものは設計どおりで、来訪者にとっても前より良い（下の「確かめたこと」）。直す点は、このコミットの言い換えで事実と合わなくなったコメントが2か所に残ったこと（指摘1）と、「この結果を共有」の見出しの段がゲームごとに違い、受け持つタスクが無いこと（指摘2）。

## 指摘

### 指摘1（builder）: 旧い表示名「今日のパズル」を指すコメントが2か所に残る

このコミットで進みの行は「今日のパズル 1/4 クリア」から「今日は4本のうち1本を遊びました」になり、見出しは「今日のほかのパズル」になった。ところが、次の2か所は、もう画面に無い「今日のパズル」進捗を名指したまま残っている。

- `src/play/games/shared/_lib/crossGameProgress.ts:17-21`（`ALL_GAMES` の説明）: 「isDaily: true のゲームのみが「今日のパズル」進捗の対象となる。ランダム出題型ゲーム（ヨジドル等）はデイリー進捗から除外する。」
- `src/play/games/types.ts:39-44`（`isDaily` の説明）: 「trueのゲームはNextGameBannerの「今日のパズル」進捗に含まれる。…デフォルト: false（後方互換性のため、既存ゲームはregistryで明示的にtrueを設定）」

どちらも、このコミットの言い換えが原因で事実と違う記述になったので、このタスクで直す。同じ説明の塊には、いまのレジストリに無いゲーム（ヨジドル。registry.ts の4本はすべて `isDaily: true`）と、経緯の注記（「後方互換性のため、既存ゲームは…」）もある。直すなら同じ塊を読み直すことになるので、塊ごと、いまの事実だけで書き直す（例: 「デイリーゲームかどうか。true のゲームが、解き終えた画面の今日の進み（NextGameBanner）に数えられる。」）。経緯の注記は T5-20e の行（ゲームのタスクが触らないファイルの経緯の注記を消す）の範囲とも重なるので、PM は T5-20e の数え方でこの2か所が0になっていることを確かめる。

なお、`crossGameProgress.ts:9` の `GameInfo` の説明（「used by progress tracking and NextGameBanner」）はいまも正しく、直す必要はない。

### 指摘2（PM・planner）: 「この結果を共有」の見出しの段がゲームごとに違い、受け持つタスクが無い

このコミットで2つの区画は h2 になった。6-c は「ゲームの結果の中の「今日のほかのパズル」「ほかの分類」は、結果に続く小見出し」（最初のセクション＝h1 の中の小見出し）としているので、h2 は正しい。ところが、同じ並びで結果のすぐ下にある「この結果を共有」は、

- kanji-kanaru（`GameResult.tsx:119-124`）・irodori（`GameContainer.tsx:467`）: h2
- yoji-kimeru（`GameResult.tsx:141`）・nakamawake（`GameContainer.tsx:466`）: h3

と分かれている。yoji-kimeru と nakamawake では、見出しで移る読み上げの利用者に、共有が結果（h2 の答えの名前）の一部に入り、そのあとの「今日のほかのパズル」（h2）とは別の段に聞こえる。見た目の大きさは同じ小見出しの段なので、目で読む来訪者には差が無く、差は見出しの構造だけにある。

T5-20c の受け持ち（`NextGameBanner.*`・`CrossCategoryBanner.*`）の外で、このコミットでは直せない。t5-design.md を見ると、どの行もこれを受け持っていない。

- 6-c（最初のセクションの中の並び）を組むのは T5-20b だが、T5-20b のファイルは `GameLayout`。
- yoji-kimeru の `GameResult.tsx` は T5-20d（表）の受け持ちで、見出しの段は T5-20d の行に無い。
- nakamawake の `GameContainer.tsx` は T5-20a（済み）のあと、受け持つタスクが無い。

いちばん近いのは、6-c の最初のセクションの組み方を受け持つ T5-20b。PM は planner に、T5-20b の行に「最初のセクションの中の小見出し（この結果を共有・今日のほかのパズル・ほかの分類）を h2 にそろえる」と完了の条件（4本で共有の見出しが h2）を足させ、10-4 の受け持ちに yoji-kimeru の `GameResult.tsx`（T5-20d → T5-20b）と nakamawake の `GameContainer.tsx`（T5-20a → T5-20b）を書かせる。T5-20c の直しの前提ではないので、指摘1とは並行してよい。

## 確かめたこと

### 1. 6-a と T5-20c の行のとおりに組まれているか

- 見出し「今日のほかのパズル」（小見出しの段 `--text-heading-sub`）の下に、進みの行（`--text-small`・`--ink-2`＝補助情報）と §7 の行の一覧（ボックスあり）。一覧の名前は見出しが言う（`aria-labelledby`）。
- 細い枠・角丸・`--paper-2` の地が外れた。2つの部品の CSS に `--radius`・`1px solid var(--rule)`・`--paper-2` は0（完了の条件）。
- `CrossCategoryBanner` の上の線は `--rule-w-hair` と `--rule-2`（小見出しの上の細い線）。
- すべて遊んだ日は進みの行だけで一覧を出さない（設計どおり）。

### 2. 「遊んだ」の言い方

- 数えているのは `lastPlayedDate === 今日` で、4本とも勝ち負けにかかわらず解き終えたときに `lastPlayedDate` を今日にする（各 `GameContainer.tsx` の記録の更新を確かめた）。字「今日は4本のうち1本を遊びました」「今日の4本をすべて遊びました」は数えている値と一致し、行の補助情報「今日は遊んだ」とも同じ言い方。負けた来訪者に「クリア」と言わなくなった。
- 画面にもソースにも「クリア」「完全制覇」は残っていない（指摘1のコメントを除く）。

### 3. 試験

- `NextGameBanner.test.tsx` は `crossGameProgress` をモックせず、レジストリだけを3本に差し替え、`localStorage` に端末の記録を置いて、ほんとうの読み取りを通している。負けた回（`gamesWon: 0`）のあとに「今日は3本のうち1本を遊びました」と言い、「クリア」「制覇」が無いことを確かめる試験がある（完了の条件の単体テスト）。すべて遊んだ日には負けた回を混ぜている。
- `CrossCategoryBanner.test.tsx` は h2 の見出しが一覧の名前になることを確かめる。
- `npx vitest run src/play/games`: 44 ファイル・458 件すべて通過。`npx tsc --noEmit`: エラー0。eslint・prettier も通る。共有ツリーではビルドしていない。

### 4. 見出しの区切り（§4）

- `["今日の", "ほかの", "パズル"]`・`["他の", "コンテンツも", "試して", "みよう"]` は文節の切れ目。320px・200% で「今日のほかの／パズル」「他の／コンテンツも／試してみよう」と文節で折れ、語の中の折れは無い。

### 5. 一覧をボックスに入れたこと（CrossCategoryBanner、§7）

6-a が名指したのは NextGameBanner の一覧だが、`CrossCategoryBanner` の一覧もボックスに入れた。前の「区画は上の罫線で区切るので、一覧もボックスを持たず罫線で区切る」は §7 に無い例外で、§7 は、ほかのボックスの中に置くときだけボックスを持たないとしている。2つの区画はどちらもボックスの外にあるので、どちらの一覧もボックスを持つのが §7 どおりで、2つの一覧の見え方もそろう。逸脱ではなく、直すべき形に合わせたもの。

### 6. §5 の小見出しの線

- 「今日のほかのパズル」の上の線: すぐ上は「次の問題は…」の文で、前に分ける内容がある。正しい。
- 「他のコンテンツも試してみよう」の上の線: すぐ上は NextGameBanner のボックスの下の辺。§5 の「ボックスの太い枠のすぐ下」は、ボックスの中で上の枠のすぐ下に立つ小見出しのこと（review-t3-3-4-r3・review-t5-5a の読み方）で、前にボックスという内容がある小見出しは線を持つ。正しい。すべて遊んだ日（すぐ上が進みの行）も同じく線を持つ。

### 7. 撮った画面（来訪者の目で）

- 前: `--paper-2` の地の細い枠の中に「今日のパズル 1/4 クリア」と一覧があり、ほかの分類は太い罫線と罫線だけの一覧で、2つの区画の形が違っていた。後: 2つとも「細い線・小見出し・（補助情報）・ボックスの一覧」の同じ形になり、何の一覧かを見出しが言う。
- 320px・200% で横にはみ出す所は無い。ダークでも線・字・ボックスが読める。1280px では小見出しが §4 の段（2.08rem）になり、結果のあとの区画の頭として読める。
- 1280px で区画の幅が 470px ほどなのは前と同じで、このコミットの変更ではない。
