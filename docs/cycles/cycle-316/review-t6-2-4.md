## 指摘

### Minor-1: 字で割るとき、送った字で行の頭に禁則の字が来て、送った後の切れ端が枠の幅を超える

`joinForbiddenEdges`（`share-image.tsx` 355行）は、前の切れ端に付けると1行に収まらないとき、前の切れ端の最後の1字を次の切れ端の頭に送る。このとき、次の2つを確かめていない。

1. **送った字そのものが行の頭に置かない字か。** 前の切れ端が「?」「!」などで終わっていると、送った先の切れ端が「?」で始まる。
2. **送った後の切れ端が1行に収まるか。** 次の切れ端が、1行に収まるので丸ごと残した字の範囲のまとまり（`toRuns` の run）だと、1字足すと幅を超えることがある。`fillLines` は単位の幅を確かめないので、その行は枠からはみ出す。

どちらも、1行に収まらない単位の中で、1行近い長さの run（欧文の続きか、和文の続き）の隣に禁則の字があるときに起きる。スクラッチで補助情報（幅 996px）に渡した結果:

| 補助情報                                       | 行                                       | 起きたこと                      |
| ---------------------------------------------- | ---------------------------------------- | ------------------------------- |
| `"（" + "a"×（1行の約1.7倍）+ "?！カカカカ）"` | `["（aaa…aaaa", "?！カカカカ）"]`        | 2行目が「?」で始まる            |
| `"（" + "a"×20 + "、" + "カ"×28 + "）"`        | 2行目 `"a、カカ…カ）"` の幅が **1006px** | 中身の枠（996px）を 10px 超える |

1つ目は、ブラウザなら「?」の前の字ごと次の行へ送る。2つ目は、ブラウザなら和文の run の中で折る。どちらの入力も今のブログの題には無いが、丸括弧の中は割らない規則のせいで、丸括弧で囲んだ長い欧文や説明（T6-3 以降の道具の名前・副題など）は1つの単位になりやすく、この道を通る。

直すこと（builder）:

- 送る所で、送る字が行の頭に置かない字である間は、さらに前の字も一緒に送る（残った側が行の終わりに置かない字で終わらないことも確かめる）。
- 送った後の切れ端が1行に収まらないときは、その切れ端を字に分けてから結合をやり直すなど、どの切れ端も1行に収まるようにする（`fits` を満たさない切れ端を作らない）。
- テスト: 上の2つの形の入力（長さは組みの幅から決める）で、どの行も行の頭に置かない字で始まらず、行の終わりに置かない字で終わらず、行の幅が段の幅を超えないこと。結合と送りを外すと落ちることも確かめる。
