## 指摘

### 1. 欠片をつないだ語が、となりの語の頭や終わりを取り込み、語の中に折り所を置く。HEAD より悪くなる名前が作れる

辞書は、辞書に無い外来語だけでなく、辞書にある語の頭や終わりも短い欠片に刻む（「ト|ラッカー」「リ|ファクタ|リング」「ク|ローラー」）。今の決め方は、となり合う欠片を1つの語としてつなぐ。すると、前の語の終わりの欠片と次の語の頭の欠片が1つの「語」になり、次の語の残り（4字以上の辞書の語）とのあいだに折り所が置かれる。

| 名前                     | 辞書の刻み                           | T5-29                        | HEAD     |
| ------------------------ | ------------------------------------ | ---------------------------- | -------- |
| アクセストラッカー       | アク\|セ\|スト\|ラッカー             | アクセスト／ラッカー         | 分けない |
| ブラウザトラッカー       | ブラ\|ウ\|ザ\|ト\|ラッカー           | ブラウザト／ラッカー         | 分けない |
| セマンティクスクローラー | セ\|マン\|テ\|ィ\|クス\|ク\|ローラー | セマンティクスク／ローラー   | 分けない |
| レガシーリファクタリング | レ\|ガ\|シー\|リ\|ファクタ\|リング   | レガシーリ／ファクタ／リング | 分けない |
| プロセスイレギュラー     | プロ\|セ\|スイ\|レギュラー           | プロセスイ／レギュラー       | 分けない |

逆の向き（辞書の語が次の語の頭を持っていく）でも起きる（「シングルス／ケーラブル」「サプライ／ズガッコウ」「メッセージ／ングリベンジ」）。2語をつないだ 60,000 件では、区切りが変わった 3,197 件のうち 85 件が、つないだ所でない所に新しい折り所を持ち、そのほとんどがこの形の語の中の折り所だった（一覧は `pairs-out.txt`）。

どれも HEAD より悪い。HEAD は片仮名の続きを1つのまとまりとして組むので、続きが行の残りに入らなければ、続きごと次の行へ送る（続きが1行に収まる幅では語を割らない）。T5-29 の `<wbr>` は、行の終わりに来れば幅によらず使われる（§4）ので、次の行に丸ごと入る幅でも「アクセスト／ラッカー」と割る。道具の名前（「アクセストラッカー」「ブラウザトラッカー」）や記事の見出し（「レガシーリファクタリング」）は、これからのコンテンツで十分に来うる。`src/` に今ある文で悪くならないことは完了の条件だが、区切りは今後のすべての名前と見出しに効くので、決め方が語の中に折り所を置く形を持つままでは、来訪者に読み違えを渡す仕組みを入れることになる。

次のように直す。

- 決め方を見直し、上の5つの名前と逆の向きの例で語の中に折り所を置かないようにする。email-validator・password-generator・記事の題など、`src/` で良くなった 42 件は保つのが望ましい。
- 手がかりの候補として、次の2つは効かないことを確かめた。欠片をつないだものを単独で辞書に刻み直しても、辞書に無い並びは丸ごと1語で返る（「アクセスト」「ブラウザト」「セマンティクスク」が1語）ので区別できない。BudouX の境目の度合いも、正しい切れ目（-1,214〜-3,401）と誤った切れ目（-1,511〜-3,966）が重なる。
- 参考として、欠片をつないだ語を「続きの最後の単位で、前が辞書の語」のときだけ語とみなす形（外来語の終わりの「〜ジェネレーター」「〜バリデーター」の形）を試した。2語をつないだ 60,000 件では、区切りが変わった 1,279 件のうち、つないだ所でない所に新しい折り所を持つものが 19 件に減り、上の5つの名前はどれも分けなくなった。email-validator・password-generator・「CSSカスタム／プロパティ」・「AI／カラー／パレット／ジェネレーター」は保たれる。「レスポンシブ／チェッカー」「ポモドーロ／タイマー」のような、つないだ語が前に来る形は分けなくなる（HEAD と同じで、悪くはならない）。これは決め方の一案で、採るかは builder が上の比べ方で確かめて決める。
- 上の5つの名前と逆の向きの例を、「分けない」側の試験に足す。
- `MIN_KATAKANA_WORD` の注記は「これより短い切れ端は、辞書に無い外来語を刻んだ欠片」と言い切るが、短い切れ端には辞書にある語の頭や終わり（「ト」「リ」）や短い語そのもの（「ハッシュタグジェネレーター」の「タグ」。今の決め方では「ハッシュ／タグジェネレーター」になる）もある。直した決め方に合わせて、注記を正しく書き直す。
- 直したら、`src/` の前と後の比べと、2語をつないだ比べ（`pairs.mts`）をやり直し、悪くなる所が無いことを確かめる。

### 2. 欠片の無い片仮名の続きでも、辞書が刻んだ外来語の終わりの3字（「リング」）で割る（HEAD からある形。同じ関数の同じ種類の誤り）

欠片（3字未満の切れ端）が無い続きは、HEAD と同じく、辞書の切れ目をすべて語の頭にする。辞書は「フィルタリング」を「フィルタ|リング」、「スコアリング」を「スコア|リング」と刻むので、この2つの語の中に折り所が置かれる。公開している記事の見出しで、次の2つがそうなっている（`2026-03-05-ai-agent-concept-rethink-2-forced-ideation-1728.md`）。

- h2「1,728 → 31のフィルタリングパイプライン」→「1,728 → 31の／フィルタ／リング／パイプライン」
- h3「フィルタリング全体の流れ」→「フィルタ／リング／全体の／流れ」

`MIN_KATAKANA_WORD_BESIDE_JOINED` の注記は「語の辞書は、辞書に無い外来語の頭や終わりの3字を別の語に刻む」と書いているのに、欠片の無い続きでは3字の切れ端をそのまま語とみなしており、決め方が自分の前提と食い違っている。T5-29 が作ったものではなく、完了の条件（前と後の比べ）にも当たらないが、T5-29 の目的（片仮名の続きの中の語の切れ目を正しくする）そのものの誤りである。PM は、T5-29 の中で直すか、別のタスクを立てるかを決めて index.md に書く。

### 3. DESIGN.md §4 と SKILL.md の実装の注記5が、前の決め方のまま

`DESIGN.md` §4（109 行目）と `.claude/skills/frontend-design/SKILL.md` の注記5（129 行目）は、片仮名の続きの中は「切れ端がどれも3字以上のときだけ」語の頭を使うと書いている。T5-29 の後は、欠片をつないだ語と辞書の語のあいだにも折り所を置く（「メールアドレス／バリデーター」）。CLAUDE.md のツギハギ禁止に従い、決め方を変えたコミットで、最初からその決め方だったように書き直す。どちらのファイルにもほかのタスク（T5-28・T5-8）の未コミットの変更があるので、この行だけを直す。

指摘1で決め方を直すので、下の文は今の決め方（しきい値 3・5・4）に合わせたものである。直した決め方に合わせて言い換える。

DESIGN.md §4 の「漢字どうしのあいだ、助詞や送り仮名の前、辞書が短い切れ端に刻む片仮名の続き（「リ／ファクタ／リング」）の中には置かず、どちらの切れ端も2字以上（平仮名だけなら3字以上）にする。」を、次に置き換える。

> 漢字どうしのあいだと、助詞や送り仮名の前には置かない。辞書に無い外来語は、辞書が短い切れ端に刻む（「バリ／デー／ター」）ので、となり合う短い切れ端をつないで1つの語とみなし、その語とほかの語のあいだにだけ置く（「メールアドレス／バリデーター」）。つないでもどこまでが1つの語かを決められない片仮名の続き（「リ／ファクタ／リング」）の中には置かない。どちらの切れ端も2字以上（平仮名だけなら3字以上）にする。

SKILL.md の注記5の「（`Intl.Segmenter` の語の境目。片仮名の続きの中は、その続きの切れ端がどれも3字以上のときだけ）」を、次に置き換える。

> （`Intl.Segmenter` の語の境目。片仮名の続きの中は、3字未満の切れ端をとなりどうしでつないで1つの語とし、つないだ語がどれも5字以上で、そのとなりの辞書の語がどれも4字以上のときだけ、辞書の語とつないだ語の頭を使う。どれかが短ければ、どこまでが1つの語かを決められないので、続きの中には置かない。辞書は辞書に無い外来語の頭や終わりの3字を別の語に刻み（「レン|ダ|リング」）、つないだものが辞書の語に続く外来語の終わりの4字まで（「プログラマ|ティック」）のこともあるので、この長さで見分ける）

### 4. SKILL.md の測り方が、片仮名の欠片の切れ目を「語の切れ目での折れ」に数える

SKILL.md の「見出しとコントロールの名前の折り方を測る」の2（46 行目）は、`Intl.Segmenter` の語の切れ目で次の語が片仮名で始まる所の折れを「文節の中の語の切れ目での折れ」に数え、「語の中の折れ」に数えない。この数え方では、T5-17 のレビューが見つけた「メールアドレスバリ／データー」は「バリ|デー」の切れ目なので語の切れ目の折れになり、語の中の折れとして数えられない。T5-29 で「欠片の切れ目は語の切れ目ではない」と決めたので、測り方も同じ決め方（注記5の語の頭）で語の切れ目を見分けるように直す。直さないと、同じ種類の崩れを測って見つけられない。
