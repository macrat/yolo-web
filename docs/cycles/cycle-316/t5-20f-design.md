# T5-20f ゲームのページで次に遊ぶものの一覧が2度出る件の設計

この文書は、index.md の「T5-20b のレビュー（review-t5-20b.md）を受けた PM の決定」(1) が立てた T5-20f の設計である。3案以上を比べて1つを推し、変えるファイル・見出しの文・並び・試験・完了の条件・順序を決める。

数には出自を付ける。

- **実測**: 誰かがブラウザか BigQuery で測った値。誰がどの版で測ったかを書く。
- **算術**: 実測から四則で出した値。
- **推論**: 仕様や組み方から見込んだ値。

算術と推論の値は、合否に使わない。

### 4-3. 読み込みのあいだに下を動かさない

いまの `NextGameBanner` は、サーバーでは何も描かず、水和のあとに端末の記録を読んで描く。解き終えた回の結果の区画の中にあったので、その高さは結果の区画が取っておく高さ（`ReservedResultArea`・`savedLayout`）に含まれていた。E ではゲームのセクションの外に出るので、自分で動かないようにする。

**決まり: 「今日のほかのパズル」のセクションは、最初の描画から、端末の記録どおりの進みの行と行の補助情報で描き、あとから字が現れたり行の高さが変わったりしない。**

- セクションの見出しと一覧の行（名前とリンク）は、サーバーで描く。4本のゲームはどの来訪者にも同じなので、記録を待たずに描ける。
- 記録で変わるのは、進みの行の文と、行ごとの「今日は遊んだ」の有無だけである。`45rem` 未満では補助情報が名前の下に落ちる（§7）ので、行の高さも変わる。
- 組み方は builder が選ぶ。このリポジトリには、端末の記録や測った値で最初の描画から組む仕組みが2つあり、どちらかの考え方に沿う。(a) ゲームの `savedLayout`（本体の前のスクリプトが記録を読み、`<head>` に足す `<style>` で値を書き、水和のあとに外す）。(b) `DataTable` と記事の表（枠の直後の小さなスクリプトがその枠を組む）。どちらも、水和のときにサーバーの HTML と食い違う属性を `<html>` に書かない。
- JavaScript が動かないときは、進みの行を出さず、一覧は補助情報なしで出る（遊べないので、読み違えさせる字を出さない）。
- 採った組み方で、次の6の完了の条件（読み込みのずれ）を満たす。

### 4-4. 結果の区画が短くなることと、覚えた高さ

結果の区画から2つの小見出しの区画が外れるので、結果の区画は短くなる。`ReservedResultArea` は、解き終えた回を開き直したときのために、前に同じ日・同じ幅で描いた結果の区画の高さを端末に覚えている。**リリースの日に、それより前に解き終えていた来訪者が同じ日に開き直すと、覚えた高さ（外す前の高さ）が取っておかれ、結果が出たところで区画が縮み、その下が上へ動く。** 覚えた高さは日付ごとで、次の日には使われない。リリースの日の1日だけの、その日に解き終えて開き直した来訪者だけのずれなので受け入れ、キーの名前は変えない（キーを変えると、どの来訪者の端末にも使われない古い値が残り続ける）。builder はこのことを記録に書く。

### 4-5. GA の計測

- 一覧を押す出来事はもとから無いので、途切れる計測は無い。`level_start`・`level_end`・`share`（「この結果を共有」「このゲームを勧める」）は、部品も `contentType`・`contentId` も変えない。
- 一覧を押す出来事は足さない。どの一覧を押したかを数えるより、行き先のページの閲覧の並びで足りる（1-2 の数え方）。数える目的だけの計測を増やさない（AP-I04）。
- リリースのあと、1-2 と同じ数え方で「解き終えた閲覧の次のページ」と「解き終えていない閲覧の次のページ」を比べられる。ただし半年で解き終えた閲覧が 39 なので、差を見分けられる数になるまで何か月もかかる。賭けではなく重なりを消す直しなので、ADR は立てない（PM が決める）。
