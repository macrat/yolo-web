## 良いところ

- **状態の伝え方は名前の切り替えが合っている。** `DESIGN.md` §6 は、その場で状態を変えるものを形（ラジオボタン・チェックボックス・アコーディオン）で示し、ボタンは「実行するもの」として下線で示す。押すと何が起きるかをいつも名前で言うボタン（止める／動かす）は、実行するものとして §6 のボタンの定義にそのまま収まる。`aria-pressed` を付けると「押されている／いない」という状態を持つトグルになり、§6 では形で示すべき種類になる。WAI-ARIA APG のボタンの項も、状態に合わせて名前を変えるなら `aria-pressed` を付けない、としている。
- **reduced-motion で止めて始めるのは、設計に無い追加ではなく `DESIGN.md` §11 の要件そのもの。** §11 の最後の項は「`prefers-reduced-motion` のとき、自動で始まる動きは止まり」とあり、同じ §11 が刻み続ける時刻を動きに含めている。6-3 がこれを書いていなかっただけで、builder の判断は正しい。
- **タイマーの片付けは正しい。** 刻みを `ticking` に従う effect に分け、effect の中の `const` の ID を cleanup で `clearInterval` している。止めたとき・アンマウントしたときの両方で cleanup が走る。AP-I11 は「ID を `useRef` で保持」と書くが、要は cleanup で消すことで、effect の閉包に持つほうが素直で漏れも無い。
- **動かしたときに、すぐいまの値に戻す**（1秒待たせない）のは、写しに来た来訪者にとって良い。
- 経緯のコメント（C-3・D-4・T-22・AP-I11・cycle-228 など）は TSX・CSS・テストから消え、残ったコメントは「なぜそうするか」を言っている。

## 指摘

### Major-1 幅 320px・文字サイズ 200% で、数字とコピーのボタンが行と Panel の枠の外へはみ出す

`tmp/cycle-316/rv-t416/w320-font200-initial.png`。いまの時刻の行（内寸およそ 178px）に対して、

- 2つのボタンを包む `.currentActions` は `display: flex` だけで折り返さないので、「止める」（120px）と「コピー」（120px）が1組のまま横に並び、「コピー」が行の枠と Panel の枠を越えて右へ出る。変更前は「コピー」1つが行の中で折り返せたので、これはこの変更で生まれた。
- 数字の `code` は `flex: 1` だが `min-width` が既定の `auto` で、10桁の等幅の字（幅 228px）より縮まず、枠をまたいで出る。こちらは変更前からあるが、同じ行のことなので一緒に直す。

`DESIGN.md` §12「拡大と上書き——文字サイズ 200% で、内容が欠けず」に反する。ボタンの組が折り返せるようにし、数字も行の幅に収まる（必要なら桁の途中で折れる）ようにする。直したら 320px・200% を撮って、数字の全桁と2つのボタンが枠の中にあることを確かめる。builder の撮影には 320px が無かったので、320px（通常と 200%）を撮影に加える。

### Major-2 幅 375px でコピーを押すと、2つのボタンがまとめて次の行へ跳ぶ

`tmp/cycle-316/rv-t416/w375-bar-paused.png`（押す前、数字と2つのボタンが1行）と `w375-bar-copied.png`（押した後）。「コピー」が「コピーしました」に変わって幅が伸び、ボタンの組が数字の下の行へ移り、行の高さも変わる。変更前はボタンが「コピー」1つで、「コピーしました」になっても数字と同じ行に収まっていた（数字 125px + 間 12px + 約 124px < 内寸 267px）。375px は来訪者のいちばん多い幅の1つで、写した直後に押したボタンと「動かす」のボタンが別の場所へ動くと、「写せたか」を確かめる目と、続けて「動かす」を押す指が迷う。押す前と押した後でボタンの位置が変わらない組み方にする（例えばボタンの組をいつも数字の下の行に置く、コピーのボタンが「コピーしました」の幅をはじめから持つ、など。どれにするかは builder が決める）。

### Minor-3 reduced-motion で始まったとき、見出しが「止めた」と言い、値がいつのものか分からない

`tmp/cycle-316/rv-t416/w375-reduced-bar-initial.png`。来訪者は何も押していないのに、見出しは「止めたUNIXタイムスタンプ:」、コピーの名前は「止めたタイムスタンプをコピー」になる。しかも値はページを開いた瞬間のもので、数分読んでから写すと、来訪者は「いまの時刻」のつもりで古い値を写す。止めて始めること自体は §11 の要件なので変えない。そのうえで、止まっている値が何時何分何秒のものかを行の中で言う（例: 見出しを状態に合う言い方にし、止まっているあいだは値の時刻を添える）など、来訪者が写す前に値の古さに気づける形にする。これは自分で止めた来訪者にも役に立つ（止めてから時間がたった値を写すときの取り違えを防ぐ。6-3 が言う「取り違えを減らす」の狙いにも合う）。

### Minor-4 テストが確かめていないこと・名前と中身が合わないこと

- 「マウント前の表示」の「初期状態ではライブタイムスタンプが空文字（SSR 一致）」は、`code` があることしか確かめておらず、名前が言う「空」を確かめていない。変更で説明のコメントを消したので、いまは名前と中身が食い違うだけのテストになった。`react-dom/server` の `renderToString` でサーバーの HTML を作り、`code` が空で2つのボタンが無効であることを確かめる形にする。
- タイマーの片付けを確かめるテストが無い。PM が見てほしい点に挙げた「タイマーの片付け」は、いまは実装を読まないと分からない。止めたあと・アンマウントしたあとに `vi.getTimerCount()` が 0 になることを確かめる（止めたときに刻みを隠すだけでタイマーが回り続ける実装を、いまのテストは通してしまう）。
- 「タイムスタンプ変換後に5個のコピーターゲット（現在・ローカル・UTC・ISO・秒・ミリ秒）」は6つを並べて「5個」と言い、「現在」は確かめていない。名前を中身に合わせる。
- 「`--color-*` 旧トークンが存在しないこと」の「旧」は経緯の語。何を禁じているか（`--color-*` のトークンを使わない）で言う。
