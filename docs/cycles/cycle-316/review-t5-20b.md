## 指摘

### 指摘1（builder）: 関連の3つがセクションであることを、どの試験も確かめていない

T5-20b で `RelatedGames` と `RelatedBlogPosts` は `Section` を返すようになった。セクションを返すことで、その上に全幅の罫線とセクションの間隔が付く。これが「関連の見出しが上の一覧に寄る」を直した本体である。ところが、これを確かめる試験が無い。

- `RelatedGames` には試験のファイルが無い（`grep -rln "RelatedGames\|関連ゲーム" src --include=*.test.tsx` は0件）。
- `RelatedBlogPosts.test.tsx` は一覧と題名を確かめるだけで、`section` を確かめない（`RecommendedContent.test.tsx` は `container.firstChild` が `SECTION` であることを確かめている）。
- `GameLayout.test.tsx` に足した試験の名前は「…ページの共有・関連の順のセクションで組む」だが、確かめているのは `:scope > section` の3つだけである。`mockMetaFull` の `relatedGameSlugs: []` では `RelatedGames` が null を返し、`test-game` には関連記事が無いので `RelatedBlogPosts` も null を返す。`RecommendedContent` はモックの `<nav>` なので、関連の3つの順とセクションであることは、どれも試験されていない。

このままだと、あとで誰かが `RelatedGames` を `<section className=…>` に戻しても、試験は通る。すると、罫線が消えて見出しが上の一覧に寄る状態に戻ったことに、誰も気づかない。

直し方の例: `GameLayout.test.tsx` で、実在するゲームを `relatedGameSlugs` に入れた meta を使い、`:scope > section` の数と、関連ゲームがページの共有のあとのセクションであることを確かめる。試験の名前は、確かめている範囲と合わせる。`RelatedGames` の試験のファイルを足し、関連ゲームがあれば `SECTION` の中に h2「関連ゲーム」とその一覧を描き、無ければ何も描かないことを確かめる。`RelatedBlogPosts.test.tsx` にも、`SECTION` を返すことの確かめを足す。`RelatedBlogPosts` は T5-17 と同じファイルなので、PM は T5-17 の側と食い違わないよう調整すること。

### 指摘2（PM が扱いを決める）: 遊び終えた画面で、同じゲーム・同じおすすめが2度並ぶ

遊び終えた画面では、次の2組が上下に2度並ぶ。

- 最初のセクションの「今日のほかのパズル」と、関連ゲームのセクション。例: nakamawake で、どちらも漢字カナール・四字キメル・イロドリ。
- 最初のセクションの「他のコンテンツも試してみよう」と、セクション「他のジャンルも試してみよう」。見出しは1語しか違わず、中身も重なる。例: nakamawake で、今日のユーモア運勢・日本の伝統色診断が両方にある。

これは T5-20b より前からあり、6-c も両方を置くと決めているので、builder の直すことではない。ただし、T5-20b で下の2つがセクションの見出しの段（375 で 23.84px、1280 で 46.72px）になった。そのため、上の小見出し（17 / 33.28px）より目立つ形で、同じ行がもう一度出る。来訪者から見ると、ページの後半は「さっき見た一覧」の繰り返しになる。見出しの言い方も「他のコンテンツも」と「他のジャンルも」でほとんど同じなので、何が違う一覧なのか分からない。

PM は、どのタスクで扱うかを決めて index.md に記録すること。案は、T7 の文言の見直しで2つの見出しを言い分ける、遊び終えた画面では重なる行を下の一覧から除く、などを planner に比べさせる。

### 指摘3（PM が扱いを決める・小）: storybook の RelatedBlogPosts の見本

`/storybook` の「20. RelatedBlogPosts」では、見本の `Panel` の中に `Section` が入れ子になった。そのためパネルの中に、上 16px・下 32px（1280 で 24・48px）の余白が付くようになった。もう1つ、2つ目の見本の見出し「slug="char-count"（関連記事なし → null を返す）」の下に、実際には関連記事が1件出ている。これは T5-20b より前からの食い違いで、見本の説明が事実と合わない。storybook は noindex で来訪者の目には触れないが、部品の見本として読む人を誤らせる。ファイルは T5-17 と同じ変更なので、storybook を受け持つタスクか T5-17 の側で直すよう、PM が振り分けること。
