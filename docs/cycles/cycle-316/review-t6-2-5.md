## 指摘

### Minor-1: 禁則の字と空白が隣り合うと、まとまりが禁則を守らない

`unbreakableClusters` は、開き括弧の直後の字を括弧に付けるのを `cannotEndLine(last)` で決めるので、括弧の後ろに空白があると、空白で終わるまとまり（「「 」）ができ、次の字は付かない。その境で行が割れると、行の終わりの空白を落とした行が開き括弧で終わる。逆に、行の頭に置かない字の前に空白があると、その字は空白に付き（「 ？」）、空白の前で行が割れると、次の行の頭の空白を落とした行がその字で始まる。

スクラッチで補助情報に渡した結果:

| 補助情報                       | 行                                              |
| ------------------------------ | ----------------------------------------------- |
| `"（" + "カ"×26 + "「 ab」）"` | `["（カカ…カ「", "ab」）"]`（開き括弧で終わる） |
| `"（" + "カ"×28 + " ？カカ）"` | `["（カカ…カ", "？カカ）"]`（「？」で始まる）   |
| `"（" + "a"×50 + " ?bb）"`     | `["（aa…a", "?bb）"]`（「?」で始まる）          |

画面の見出しは、ブラウザが「 ？」の前でも「「 」の後ろでも折らない（`splitAtInnerBreaks` も、開き括弧は空白を除いてから `cannotEndLine(current.trimEnd())` で見ている）。今の入力には無いが、欧文の混じる題や道具の名前（「( UTF-8 )」「本当 ?」の書き方）で、丸括弧で1つの単位になったものが1行に収まらないときに起きる。

直すこと（builder）:

- 空白の字は前のまとまりに付ける（空白は行の頭に来ても描かないので、空白の前で割る意味が無い）。開き括弧の判定は空白を除いた終わり（`cannotEndLine(last.trimEnd())`）で見る。
- テスト: 上の3つの形の入力を、1行の字数の前後の長さで並べ、前回足した `expectAuxLinesKeepRules` で確かめる。

### Minor-2: 1つのまとまりが1行より広いとき、字が枠と画像の端を越え、コメントの約束が偽になる

`breakUnits` は、1行に収まらないまとまりもそのまま `fillLines` に渡すので、その行は段の幅を超える。起きるのは、行の頭に置かない字（長音符・小書きの仮名・感嘆符・リーダなど）や開き括弧が、段の1行の字数（名前 96px で約10字、補助情報で約27字）を超えて続くときだけで、実在の入力（上の 965 件）には無い。長い欧文の語と URL では起きない（1字ずつのまとまりになる）。

起きたときに描かれるもの: 補助情報に `"わ" + "ー"×34 + "！"` を渡すと、行の幅は 1,247px（段の幅は 996px）で、線が右の罫線を越えて画像の右端で切れ、「！」は画像に出ない。名前では、どの段でも1行に収まらない単位があると `fitsFrame` だけで段を選ぶので、いちばん大きい 96px が選ばれ、はみ出しがいちばん大きくなる。

画面の見出し（`PhrasedText` の `overflow-wrap: anywhere`）は、ほかに折り所が無いときは禁則の字の前でも折って枠に収める。画像も同じにするのが筋で、`breakUnits` の最後で、1行に収まらないまとまりを字に分ける（`fits(cluster) ? [cluster] : graphemes(cluster)`）だけで済む。そうすれば、コメントの「どの切れ端も1行に収まる」と、完了の条件の「どの字も中身の枠からはみ出さない」が、この場合にも本当になる（1字が1行より広いことは段の大きさからありえない）。

直すこと（builder）:

- 1行に収まらないまとまりを字に分ける。
- テスト: 行の頭に置かない字が1行の字数より長く続く補助情報（「わ」＋「ー」の続き＋「！」など）で、どの行も段の幅を超えず、字がすべて描かれること。

### Nit-1: `breakUnits` のコメントと中のコメントで「まとまり」が2つのものを指す

`breakUnits` のコメントは「字の範囲のまとまり」（run）と「禁則を破らないまとまり」（`unbreakableClusters`）を同じ「まとまり」で呼び、中のコメント「まとまりを、その頭の字が属する字の範囲のまとまりごとに集める。」は1文に両方が出る。また3文目「字の範囲のまとまりの端に禁則の字が付いて1行に収まらなくなったときは、そのまとまりも字で分ける」は、2文目までの規則から出る場合を後から書き足した形に読める。Minor-2 を直すときに、2つを別の語で呼び分け（たとえば run は「書体のまとまり」、cluster は「割れない字の組」）、規則を「割れない字の組を書体のまとまりごとに集め、1行に収まる集まりはそのまま、収まらない集まりは組に、それでも収まらない組は字に分ける」の1本の流れに書き直す。ファイルの頭のコメント（「字の組み方」）も同じ語にそろえる（直すこと: builder）。
