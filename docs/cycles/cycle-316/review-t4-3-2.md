## 指摘

### Major-1 サイトの中のリンクで移ったページでは、初めからある結果のボックスが登場の動きを持つ

`useIsServerRendered` は、サーバーの HTML を水和で引き継ぐ最初の描画だけで true を返します。Next の App Router でサイトの中のリンク（`next/link`）から移ると、移った先のページの部品は水和でなくブラウザで新しく描かれるので、false になります。そのため、移った先のページに初めからある結果のボックス（入力の初めの値で結果を出す道具・T4-15 の見本など）は、`appears` を持ち、ページを開くたびに 300ms かけて現れます。

自分の確かめ: 結果のボックスを1つだけ置いたページを、アドレスから開くと動きを持たず（class に `appears` が無く、アニメーションも0）、別のページから `next/link` で移ると `appears` を持ち、`appear` のアニメーションが running でした。量の帯の見本の3つのボックスも、リンクで移ると3つとも `appears` を持ちました。

来訪者はサイトの中をヘッダーや一覧のリンクで移るのが普通なので、ほとんどの来訪で、PM の決定（「ページを開いたときにサーバーの HTML に初めからあるボックスは動かさない。結果の登場は操作への応えで、開いたページの読み込みではない」）と §11 の「一律の fade-in を持たない」に反する見え方になります。部品のコメント（「ページを開いたときにサーバーの HTML に初めからあるボックスは動かさない」）と storybook の見出し（「ページを開いたときにあるボックスは動かない」）も、この場合を言い当てておらず、T4-6 以降でこの部品を使う builder を誤らせます。jsdom のテストは `renderToString` → `hydrateRoot` の道しか通らないので、これを捕まえません（AP-I07）。

同じ見分け方では、読み込んで開いたページでも、水和のあとに `useEffect` で保存した値を読んで初めの結果を出す道具のボックスが、操作なしに動きます。「サーバーで描いたか」は「操作に応えたか」の代わりになりません。

- 登場の動きを「操作に応えて現れたか」で決める形にする。たとえば、呼び出し側（操作を受けた道具）が「操作に応えて出した結果」であることを部品に伝える、など。どの形が §11 と 6-4 に合い、T4-6 以降の面で誤りにくいかは、planner に 2-1・6-1 で決めさせてから builder に渡すのがよい。
- 決めた形で、(1) アドレスから開いたとき、(2) `next/link` で移ってきたとき、(3) 操作で現れたとき、を本番のビルドで確かめ、(1)(2) は動かず (3) だけ動くことを記録する。テストも (2) にあたる場合（水和を通らずに最初に描いたとき）を含める。
- 部品のコメントと storybook の見出しを、決めた形に合わせて書き直す。

### Minor（まとめ）

1. **コードの結果で、中身が長くなっても枠の付け直しが走らないことがある**。`ResultBox` の ResizeObserver は `.body` と、その子（コードでは `pre`）を見ますが、`pre` は `overflow-x: visible` で幅が枠の幅のままなので、中の行が長くなっても `pre` の大きさは変わらず、観測が発火しません。親が描き直して `children` が替わるときは effect が走るので、今の見本と、結果を親の state で出す道具では困りません。ただ、コードを出す子の部品が自分の state で中身を変える場合や、文字の大きさの設定だけを変えた場合は、はみ出していても `tabindex` が付きません。`pre` の中の `code` を見るか、`Prose` と同じく幅の変化を捉える形を選ぶと確実です。
2. **水和のテストの後片付けが、失敗したときに走らない**。2つのテストとも、`console.error` の spy の戻し・`IS_REACT_ACT_ENVIRONMENT` の戻し・`unmount` を `expect` の後に書いているので、`expect` が落ちると後のテストに spy と環境が残ります。`try`/`finally` か `afterEach` に移す。
3. **量の帯の CSS に、既定と同じ指定が残る**。`.list[data-layout="inline"] .name { grid-area: 1 / 1; }` は既定の `.name` と同じ値で、要りません。

## よかった点

- 測れないときの組みを2行の組みに替えたことで、JavaScript の有無・幅・字の大きさのどれでも、量の帯が崩れない形を持つようになった。`layout.ts` が属性を外す形なので、組みの状態が2つの値でなく「測って1行にしてよいと分かったとき」の1つだけになり、読みやすい。
- 横に送る枠の付け外しが、記事の本文（`Prose`）と同じ決まりと同じ名前で、サイトの中でキーボードの来訪者が同じ扱いを受ける。
- 水和の不一致をなくしたことを、`hydrateRoot` のテストで確かめている。
