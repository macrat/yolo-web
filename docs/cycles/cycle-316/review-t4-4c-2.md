## 判定: 改善指示

前回の6つの指摘は、どれも筋の通った形で直っている。unix-timestamp は名前とボタンを1行目、値を幅いっぱいの次の行にしたことで、375px の既定で値が1行に戻り（前回の折れ `1704067` / `200` は無くなった）、320px でもボタンは行の右端にそろう。伝統色の配色は 375px で値とボタンが1行に入り、320px ではどの行もボタンが次の行の右端にそろい、値は折れない。押しても表の高さ・ボタンの右端・ページの高さは変わらない（撮った全組みで押す前後の差0）。storybook の見本は CopyButton になり、フックから面の字は消え、hash-generator のコメントは1つの説明になった。経緯のコメントは見当たらない。

残るのは、読み上げの形の根拠の誤り（1）、§6 の共有のボタンとの線引きの言い方（2）、unix-timestamp の新しい組みの小さな崩れ（3・4）、同じ名前のボタン（5）、フックに残った使われない形（6）である。

## 指摘

### 1.（中）「コピー失敗」の面のあいだ、ボタンの名前が見える字を含まない（WCAG 2.5.3）。builder の「名前が見える字『コピー』を含むので満たす」は判断の根拠として誤り

- 2.5.3 の文は「名前が、見えている字を含む」である（Understanding 2.5.3）。押したあとの面の見える字は「コピー済み」「コピー失敗」で、名前「HEXをコピー」はこれを含まない。見える字の一部（「コピー」）を含むことは、この基準を満たす理由にならない。Understanding は、押したあとに替わる状態の字をどう扱うかを述べていないので、「状態の字だから名前の外でよい」と言うなら、それは基準の外の判断として記録に書く必要がある。
- 来訪者への影響は、2つの面で違う。
  - 「コピー済み」は2秒で押す前の面に戻る。音声で操作する来訪者がこの2秒のあいだにこの字で押すことはまず無く、名前を変えると、戻るときにも（押していないのに）名前の変化が読まれうる（Adrian Roselli「Be Careful with Dynamic Accessible Names」）。名前を固定するのは妥当である。
  - 「コピー失敗」は次に押すまで残る。写し直したい来訪者は見えている「コピー失敗」を言って押そうとし、名前が「HEXをコピー」だと一致しない。Roselli の「Multi-Function Button」も、面の字を替えるボタンでは名前を面の字に合わせ、知らせは別のライブリージョンで言う形を取っている。
- 直し方の方向: 名前は「いつまでも出ている面の字」を含む、と決める。押す前は「HEXをコピー」、写せなかったあとは見える字を含む名前（例「HEXをコピー失敗」）にし、「コピー済み」のあいだは戻るまでの短い知らせなので名前を変えない。写せなかったときに名前の変化と知らせが重なって2度聞くことがありうるが、写せないことはまれで、重なっても言うことは食い違わない。この形か別の形かを PM が決め、理由を cycle の記録に残し、DESIGN.md §6 の3つめの項目（「名前は見える字の『コピー』をいつも含み、音声で操作する来訪者も同じ語で押せる」）と CopyButton のコメントを、選んだ形に合わせて書き直す。いまの書き方は、音声で操作する来訪者が「コピー失敗」と言っても押せないことを覆っている。

### 2.（中）DESIGN.md §6 の共有のボタンを外す理由「写すのが結果でなくリンク」が、サイトの「結果をコピー」と食い違う

- `ShareButtons` は `text` を受けると面の字が「結果をコピー」になり、結果の文と URL を写す（`src/components/ShareButtons/index.tsx` 205行）。§6 は共有のボタンを「写すのが結果でなくリンクで」と説明して規則の外に置くので、読む人には「結果をコピー」がどちら側かが分からない。§6 の規則の名前「結果を写すコピーのボタン」とも言葉がぶつかる。
- 実際の線は、写すものが結果かリンクかではなく、(a) 道具の出した値をその場で使うために写すボタンか、ページや結果を人に渡すための文とリンクを写す共有の区画の操作か、(b) 押したあとの知らせを面の字で言うか、共有の区画の知らせの行で言うか（`ShareButtons`・`FudaActions`・`InviteFriendButton` は面の字を変えず、知らせの行に「コピーしました」「リンクをコピーしました」を出す）である。
- 直し方の方向: 規則の対象を「道具や辞典が出した値を写すボタン」のように目的で言い、共有のボタンを外す理由を「人に渡すための文とリンクを写す共有の区画の操作で、面の字を変えず、区画の知らせの行で知らせる」のように、実際のボタンすべてに当てはまる言い方にする。§6 の規則の名前（「結果を写す」）も、共有の区画の「結果をコピー」と取り違えない語にそろえる。

### 3.（小）unix-timestamp の結果の値の字が、名前の字より 3.5px（200% で 7px）右から始まる

- 値の `<code>` は全体の `code` の指定で左右に 3.5px の余白を持つ（測った値: 名前の左端 x=50、値の要素の左端 x=50、値の字の始まり 53.5）。前は値が名前の右の列にあったので目立たなかったが、今回名前の真下に置いたので、2つの字の始まりがずれて見える（撮った絵でも分かる）。DESIGN.md §5「中央に寄せるのはコンテナだけ。……その中はすべて左端に揃える」に合わない。
- 直し方の方向: `.resultValue` で左右の余白を外すか、字の始まりが名前とそろうようにする。地の色が行の地と見分けられない余白なら、残す理由は無い。

### 4.（小）unix-timestamp の 375px・200% で、同じ表の中でボタンの位置が行ごとにばらつく

- 「秒」の行だけボタンが名前と同じ行に入り、「ローカル時刻」「UTC」「ISO 8601」「ミリ秒」ではボタンが次の行に落ちる。表を上から読むと、ボタンが名前の右と名前の下を行き来する。伝統色の配色はコンテナクエリで「狭いときはどの行もボタンを次の行へ」とそろえているのに、unix-timestamp は同じ手当てを持たない（320px・200% はどの行も次の行でそろう）。
- 直し方の方向: 配色と同じく、表の幅が「ふつうの長さの名前とボタン」を並べられないときは、どの行もボタンを同じ位置に置く。

### 5.（小）unix-timestamp に、名前が同じボタンが2つずつある

- 「タイムスタンプ → 日時」と「日時 → タイムスタンプ」の両方に `target="秒"`・`target="ミリ秒"` があり、ページに「秒をコピー」「ミリ秒をコピー」が2つずつある。ボタンの一覧で読む来訪者や、音声で「秒をコピー」と言う来訪者には、どちらか分からない。知らせの「秒をコピーしました」も同じになる。
- 直し方の方向: 日時から求めた側の target を、見出しと取り違えない名前にする（例「日時から求めた秒」）。見出しの行の名前は「秒」のままでよい。

### 6.（小）`useCopyToClipboard` に、もう誰も使わない「キーで複数のものを見分ける」形が残っている

- フックを使うのは `CopyButton` だけになり、`CopyButton` はキーも `resetDelay` も渡さない。それでもフックは `key` 引数・`CopiedKey`（`string | number | true | null`）・「1つのフックで複数のものを写すとき」の説明を持ち、テストも「単一ターゲット=パターンA」などの、道具ごとに組んでいたころの呼び方で書かれている。道具ごとにフックを組んでいた時代の形が残り、読む人は、いまも複数のキーで使う所があるのかを探すことになる（CLAUDE.md のツギハギ禁止）。
- 直し方の方向: フックを、1つのボタンの「写した・写せなかった」だけを返す形に絞る（あるいは CopyButton の中に入れる）。テストの名前と説明も、いまの使い方に合わせる。

## 前回の指摘の直り方（確かめた結果）

- 1（unix-timestamp の値の折れ）: 直った。375px の既定では、ローカル時刻・UTC・ISO 8601・秒・ミリ秒のどれも1行。320px の既定では UTC の `GMT` だけが語の区切りで2行目に回る。200% では値が数字の途中でも折れるが、その幅に入らない長さで、避けられない。
- 2（配色の RGB の折れ）: 直った。320px ではボタンが次の行の右端に回り、値は1行。
- 3（読み上げの二重）: 名前を固定して知らせをライブリージョン1つにし、押し直しでも要素を入れ直して読ませる形になった（テストで要素が替わることを確かめている）。名前の固定そのものは、上の指摘1のとおり「コピー失敗」の面だけ見直しが要る。
- 4（§6 と共有のボタン）: 規則を「結果を写すコピーのボタン」に絞り、showTarget の面も規則の中で言うようになった。線引きの言い方は上の指摘2。
- 5（storybook の見本）: CopyButton の既定・align=end・showTarget（primary・stretch）・無効の見本になった。
- 6（hash-generator のコメント）: 1つの説明になった。

## 対象の外で見えたもの（指摘ではない）

- 色の辞典（toki など）の表は、200% の 320・375px でコピーのボタンが画面の外（x=322〜435）に出て押せない。T4-4c の前から同じで、t4-design.md 1177行の決定で T5 の表の組み直しに回っている。T5 で落とさないよう、PM が受け持ちを確かめること。
