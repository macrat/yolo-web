## Major

### Major-1: 2列と1列の格子で、ことわざが句の中で割れる（句が1行に入る幅でも）

grid7.mjs の「文節中」の数（句の切れ目でない所で折れた行）は 122 マス。すべて #34（ことわざの日）で、320 と 375 のどの字の大きさにも出る。例（いちばん多い既定の大きさ）:

- 375 既定（2列、マス 157px）: 「目は口ほど／に物を言う」「風が吹けば桶／屋が儲かる」
- 320 既定（2列、マス 129px）: 「猿も木か／ら落ちる」「目は口ほど／に物を言う」「風が吹けば桶／屋が儲かる」
- 320 の 32px（1列）: 「目は口ほど／に物を言う」「風が吹けば桶／屋が儲かる」

スクリーンショット: `shots/grid-34-375-16-light.png`、`grid-34-320-16-dark.png`、`grid-34-320-32-light.png`。

「風が吹けば／桶屋が儲かる」「目は口ほどに／物を言う」なら、どちらの行も1行に入る。原因は `text-wrap: balance` で、2列と1列では `<wbr>` が折り所を足すだけなので、ブラウザは行の長さをそろえるために句の中で折る。前のコミットでは 320・375 が4列で、句がマスに入らなかったので目立たなかった。2列にしてマスが広がったいま、句が入るのに割れる。「桶／屋」は語を割り、「猿も木か／ら」は読み下しにくい。

コードの注釈は「ことわざのように句を持つ語は、句の切れ目（<wbr>）で折る。……句の中でも折る（1字だけの行を作らないため）」と書くが、いまの折れは1字の行を避けるためでなく、そろえるための折れで、注釈の決まりと合わない。#34 は 2026-10-12 にまた出る。スマートフォンで遊ぶ来訪者のいちばん多い幅で、その日の16語のうち2〜3語が割れて見える。

- **直すこと**: 句がマスに入るときは句の切れ目だけで折り、句がマスより長いときだけ句の中で折る組みにする（たとえば、句ごとに折らない箱にして箱が入らないときだけ中で折る、など）。1字の行と行頭の約物が0のままであることを grid7 の「文節中」と合わせて50問 × 320/375/1280 × 16〜32px で確かめる。

### builder の残り（45rem を越える回転）は別のバックログにする価値があるか

**ある。** 45rem（既定で 720px）を越える回転は、builder の試した 320→1280 だけでなく、いま多い Android の端末の回転（412×915 → 915×412、既定の字）で起きる。rotprobe.mjs で、ナカマワケを 412×915 で送ってから回すと、スクロールの位置がまったく合わせられず（scrollY 1070→1070）、見ていた所が -19〜-329px（画面の外）へ動く。漢字カナールも同じ。親の CSS でも同じなので今回の退行ではなく、このタスクを止める理由にはしない。ただし、45rem の境で組みが変わると Chrome がスクロールアンカーを止める（computed value の変わる要素がアンカーの祖先にある）ためで、サイト全体に及ぶ。

また、builder は残りを「45rem を越える回転」とまとめたが、45rem を越えない回転でも、漢字カナールの 320×568→568×320 の 200% で見ていた所が 461→-356 に動く（3回とも同じ）。バックログに書くときは、この件も含め、どの回し方でどのゲーム・ページが外れるかを測り直してから書く。iOS の Safari はスクロールアンカーを持たないので、Chrome と Firefox の問題として扱う。

4. **共有・trackContentEnd・キーボード**: 勝ち・負け・0組の負けで、共有の文（X と LINE）は正しく、`level_end` は1回だけ送られ、開き直しても重ねて送らない（play.mjs）。キーボードでは、チェックのたびに次に触る要素が画面にあり、終わったあとは結果の区画にフォーカスが移り、その上端が画面にある（kb5.mjs）。
