### Minor-1: §7 に足した一文が読みにくく、§6 の状態の表に無い見た目を足している

- 「開いているページの中で来訪者のものに決まった項目の行」は、何を指すのか一度で読み取れない。例の括弧（解き終えた画面での来訪者のタイプ）を読んで、やっと分かる。たとえば「来訪者自身の結果にあたる行（解き終えた画面での来訪者のタイプ）」のように、何かを先に言う言い方がよい。
- §6 は「種類と状態のそれぞれに別の見た目を割り当てる」と言い、表で種類と状態の見え方を定めている。太字で下線を持つ行は、その表に無い見た目である。§6 だけを読んだ人は、この状態を知らないまま部品を作る。§6 の表に1行足すか、§6 の現在地の行から §7 のこの規定を参照する。

### Minor-2: 太字だけでは、来訪者に「自分のタイプ」だと伝わりにくい

解き終えた画面で撮ると、自分のタイプの行は、ほかの行と字の太さだけが違う（伝統色診断の375 light では「若草色」、1280 dark では「山吹色」）。伝統色の短い名前は、太字でも目立ちにくい。見出しは「他のタイプ（8）」なので、「他の」の一覧に自分のタイプが太字で入っている理由を、来訪者が自分で推し量ることになる。読み上げでも `aria-current="true"` は「現在の項目」とだけ言い、「あなたのタイプ」とは言わない。

直し方の方向: 行に「あなたのタイプ」と文字で添える（補助情報の位置）。見出しを「全タイプ（8）」のように、自分のタイプを含むことが分かる語にする。この2つを合わせて検討し、§7 に書く。

### Minor-3: 8つの `*Content.tsx` が、見出しの階層から置く面を推し量っている

8つのファイルがどれも `placement={headingLevel === 2 ? "resultPage" : "solvedScreen"}` と書いている。「h2 なら結果のページ」という対応が8か所に散らばっているので、見出しの階層を変えるだけで現在地の意味が変わってしまう（AP-I02）。`OtherTypesNav` は `placement` を1つの概念にしたので、`*Content` も `placement` を受け取り、見出しの階層はそこから決めるほうがよい。

### Minor-4: T5 に引き継いだ「最も大きな字」の確かめが、他のタイプだけに限られている

関連の一覧の見出しを §4 のセクションの見出しにしたので、T5 の前のいまは、ほかの面でも末尾の関連の見出しがページで最も大きな字になっている。1280px で実測すると次のとおりである。

- ツール: h1「文字数カウント」25px、「関連ツール」46.72px
- ゲーム: h1「漢字カナール」25.6px、「関連ゲーム」46.72px
- 伝統色の詳細: h1「鴇（toki）」25px、「こちらもおすすめ」46.72px
- 診断のページ: h1 20px、「他のクイズ・診断も試してみよう」46.72px

部品は §4 に従っていて、ずれているのはページの側である。出荷は T5 のあとなので、来訪者には届かない。ただし index.md の T5 は「他のタイプ」の見出しにしか触れていない。T5 の確かめの項目を「どの面でも、末尾の関連の一覧の見出しが主見出しより大きくならない」に広げてほしい。

あわせて、ユーモア辞典の「関連語」も、ページの CSS のせいで 20px のまま、下に細い `--ink` の線を持つ。伝統色の「同じカテゴリの伝統色」だけを名指ししているので、「関連語」も同じ行に並べてほしい。
