## 指摘

### 1. 条件7 のマウスの2度押しの送り方が決まっておらず、既定の送り方では守りを1度も働かせずに「選択が空」で通る

条件7（545行）は「同じ座標を2度押す」とだけ書き、553行は「マウスの2度押しのすべての回で、2打目のあとの `getSelection().toString()` を記録し、空であること」を合否にする。上の測りのとおり、Playwright の `mouse.click` を2度呼ぶと2打目の `detail` は 1 のままで、ブラウザは語を選ばず、4-9 の守り（`detail >= 2` の `mousedown` だけを止める）も働かない。したがって、守りを実装しなくても、守りが壊れていても、553行の記録はいつも空になる。測りが自分の欠陥を見つけられない形である（第13回が使ったのは `clickCount: 2`）。

- 来訪者の本物のダブルクリックは、OS のダブルクリックの間隔（Windows の既定は 500ms）の内なら2打目が `detail` 2 になる。条件7 の間隔（0・90・150・300・500ms）はどれもその内に入りうる。
- 553行の対（見出しの字のダブルクリックで語が選ばれる）も、送り方しだいで選ばれない。

直すこと: 条件7 のマウスの2打目は `mouse.down`/`mouse.up` に `clickCount: 2` を渡して送る（来訪者のダブルクリックと同じ `detail` 2 にする）と決め、落ちた要素の記録（552行）とあわせて2打目の `mousedown` の `detail` を記録し、2 であることを測りの前提として確かめる、と書く。553行の対も同じ送り方にする。

### 2. 新しい節まわりの小さな欠け

- **(a) 範囲の比べが書かれていない**: 第13回は「範囲と比べた案（`ul` だけ・問の区画・操作の連続）を決めて書き」と求めた。4-9 の節は `user-select: none` を退ける箇条（407行）だけで、`ul` だけ・問の区画（`.stage`）だけの範囲をなぜ採らないか（区画の外の結果の字に落ちる、区画の中の字を狙ったダブルクリックまで止める）が書かれていない。4-2・4-3・4-7・4-9 はどれも表で比べており、ここだけ比べが無いと、あとで守りを狭めたい人が理由を追えない。短い表か箇条で足す。
- **(b) 2打目が落ちうる字の並びが1つ欠ける**: 403行は、2打目が落ちうる字を「答えたあとの行、知識クイズで送ったあとの解説の字、次の問の見出し、結果のボックスの字である」と閉じた並びで書く。4-9 自身が 395行で書くとおり、「もう一度挑戦する」のあとは開始の画面（事実の行・説明）の字にも落ちうる。条件7 の553行の括弧（「答えたあとの行・解説の字・次の問の見出し・結果の字のどこに落ちても」）も同じ。守りそのものは連続の全体を覆うので働きは変わらないが、並びを開始の画面の字まで足す。
- **(c) 「受け付けたか」をいつ見るかが書かれていない**: 405行は「操作を起こしたかは、その1打目の click で reducer が更新を受け付けたかで決める」とし、受け手は押した点を覚える `window` の捕捉の段階の受け手と「同じ所」とする。`window` の捕捉の段階の `click` は React の受け手より先に走るので、そこではまだ更新が受け付けられていない。builder が捕捉の `click` の中で決めると、守りはいつも働かない（4-9 の jsdom の試験が落ちるので気づけはするが、形は決めておく）。たとえば「`detail` 1 の `mousedown` のときの切り替わりの番号（4-7）を覚え、`detail >= 2` の `mousedown` のときに番号が変わっていれば止める」と、見る時と見るものを1文で書く。
- **(d) 試験の置き場**: 7章 T5a-6（576行）は守りの試験を中身に入れたが、触るファイルの列の試験は `QuizContainer.reveal.test.tsx`・`QuizContainer.intro.test.tsx` だけで、409行の試験をどちらに置くか（あるいは新しいファイルか）が無い。名指す。
- **(e) 182行の「（R2）。 押し直しが」**: 句点のあとに半角の空きが入っている。消す。
