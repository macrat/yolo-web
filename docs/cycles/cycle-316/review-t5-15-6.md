### 拡大の実測（PM の依頼）

`xvfb-run` と `Xvfb` があったので、自分で `Xvfb :97` を立て、画面ありの Chromium（1280 幅の窓）で javascript-date-pitfalls-and-fixes を開いて測った。拡大は `devicePixelRatio` と `innerWidth` で読んだ。

初めに CDP の `Input.dispatchMouseEvent`（`modifiers: 2`）で Ctrl+ホイールを送ったが、画面ありでも、目次を閉じた本文の上ですら拡大せず、ページが 360px 送られた。CDP の入力はブラウザの拡大の処理を通らないので、この方法では拡大を測れない。そこで、`ctypes` から `libXtst` の `XTestFakeKeyEvent`・`XTestFakeButtonEvent` を呼び、本物の X の入力（Control_L を押したまま、ボタン4（上へのホイール）を3回）を送った。拡大を戻すのも X の Ctrl+0 で送った（Playwright の `keyboard.press("Control+0")` では戻らない）。

| 送った所（y=4000）                                                  | 拡大                               | ページ     | 一覧の上の `wheel`（件・取り消し） |
| ------------------------------------------------------------------- | ---------------------------------- | ---------- | ---------------------------------- |
| ふつうのホイール・本文の上（X の入力が届くかの確かめ）              | 変わらない                         | 360px 送る | —                                  |
| Ctrl+ホイール・本文の上（目次は閉じる。対照）                       | 100%→150%（`innerWidth` 1280→853） | 動かない   | —                                  |
| Ctrl+ホイール・開いた短い一覧の上（中で送れない）                   | 100%→150%                          | 動かない   | 3・0                               |
| ふつうのホイール・開いた短い一覧の上                                | 変わらない                         | 動かない   | 3・3                               |
| Ctrl+ホイール・一覧にすべてを取り消す受け手を足した形（陰性の対照） | 変わらない                         | 動かない   | 3・3                               |

陰性の対照で拡大が止まるので、この測り方は「取り消すと拡大しない」を見分けられる。そのうえで、今の実装は短い一覧の上の Ctrl+ホイールを取り消さず、ブラウザは実際に拡大する。

指の2本のつまみは測れなかった。CDP の `Input.synthesizePinchGesture`（画面あり、`isMobile`・`hasTouch`）は、目次を閉じた本文の上でも拡大しなかった（対照が効かない）。受け手の側では、短い一覧の上の2本の指の `touchmove` 30件は1つも取り消されず、陰性の対照では30件すべて取り消された。スマホで実際につまんで拡大できるかは、T9 の実機の確かめに回してください。トラックパッドのつまみ（Chromium では `ctrlKey` の付いた `wheel` で届く）も、この環境では送れないので T9 に含めてください。

### 1. 知見の2の項の推論の段が、今回の実測で古くなった。拡大の測り方の落とし穴も知見に無い（軽い）

`docs/knowledge/browser-layout-and-scrolling.md` の2の項の「**推論**」は、「ヘッドレスの Chromium は Ctrl+ホイールで画面を拡大しない（…）ので、取り消さなかった Ctrl+ホイールでふつうのブラウザが実際に拡大することは、上の確認から導いたもので、実測していない」と書く。上のとおり、画面ありの Chromium 141 で本物の X の入力を送ると、短い一覧の上の Ctrl+ホイールで実際に拡大し、すべて取り消す形では拡大しないことを測れた。このままだと、知見を読む人は拡大がまだ確かめられていないと受け取り、同じ測りをやり直すか、実機でしか確かめられないと考える（誤りを含むドキュメントは直す決まり。`.claude/rules/doc-directory.md`）。

測り方そのものも非自明な知見で、次に同じことを測る人が詰まる所である。CDP の `Input.dispatchMouseEvent` で送った Ctrl+ホイールは、画面ありの Chromium でも拡大せず、取り消されなければページを送る（今回、本文の上で 4000→3640）。これを見て「拡大しない＝取り消されている」や「拡大の操作でページが送られる」と読み違えやすい。`Input.synthesizePinchGesture` も拡大しない。

直し方の例: 2の項の根拠の「実測」に、上の表の値（画面ありの Chromium 141.0.7390.37、`Xvfb` の上で `libXtst` から送った本物の X の入力、1280 の窓、javascript-date-pitfalls-and-fixes の短い一覧、陰性の対照）を足し、「推論」から拡大の段を外す。指の2本のつまみとトラックパッドのつまみは測れていないことを推論に残す。測り方の落とし穴（CDP の Ctrl+ホイールと合成のつまみはブラウザの拡大を通らないので、拡大は `Xvfb` と XTest の本物の入力で、対照を置いて測る）は、2の項の根拠に添えるか、測り方の項として足す。どちらにするかは builder が決める。
