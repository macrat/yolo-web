## 指摘

### Major-1 分類のページに見えるパンくずが無く、見出しを分類の名前にしたことで、どの集まりの中にいるかが画面から分からない

- **どこで**: `/blog/category/*` のページ。`BlogListView.tsx` は `scope.type === "tag"` のときだけ `Breadcrumb` を描く。`"category"` のときは、BreadcrumbList の JSON-LD だけを `<script>` で出す。
- **何が起きるか**: 見出しが「AI試行錯誤ブログ」から「開発ノート」に替わった。そのため、検索から着いた来訪者の画面には「開発ノート」と説明文しか無い。上端のナビの「ブログ」は現在地（太字）にならない。このページがブログの分類で、上に全記事の一覧があることを示すものは、閉じたアコーディオンの中にしか無い。
- **記事からの流れ**: この変更で、記事のパンくずは「ホーム / ブログ / 開発ノート / 題名」になった。「開発ノート」を押して着いた先のページだけに、パンくずが無い。同じ `BlogListView` で描くタグのページにはパンくずがあるので、同じ働きのものが同じ位置に無い（§12 位置の一定）。
- **構造化データ**: JSON-LD でパンくずを言い、画面には出さない形は、Google の構造化データの一般のガイドライン（「Don't mark up content that is not visible to readers of the page」）に反する。この形は変更前からあったが、この部品に分類のときだけの特別な分岐として書き直して残した。
- **直し方**: 分類のページにも、タグのページと同じ `Breadcrumb`（ホーム / ブログ / {分類}）を置き、JSON-LD だけの分岐を消す。分類のページには 375px の最初の行の条件が無いので、条件とぶつからない。見出しを分類の名前にした判断そのものは妥当（3-1「ページの見出しと中身が一致」）で、それを支えるためにパンくずが要る。

### Major-2 索引の見出し「分類（5）」「タグ（29）」の大きさが §4 と合わず、広い画面では見出しより中の語のほうが強く見える

- **どこで**: `BlogListView.module.css` の `.indexHeading { font-size: var(--text-step-1); }`。
- **何が起きるか**: `--text-step-1` は `1.0625rem` で、本文と同じ大きさになる。1280px で測ると、見出しは 17px・ウェイト400、すぐ下の現在地の語「開発ノート（35）」は 17px・太字だった（`tmp/cycle-316/rv35/cat-open-crop-1280.png`）。見出しが中身より弱く見え、現在地の語のほうが見出しに見える。
- **§4 との関係**: 見出しの大きさは、画面幅ごとの表で決まっている。この見出しはセクションの中の小見出しにあたり、`45rem` 以上では `1.49rem`、`64rem` 以上では `2.08rem` になる（トークンは `--text-heading-sub`）。§3 は「階層は大きさと罫線が作る」と決めている。いまの形は `45rem` 未満でしか §4 と合わない。「区切りの見出しと同じ段」という理由は、区切りの見出しに合わせる理由にはなるが、§4 の表に無い大きさを使う根拠にはならない。
- **直し方**: `--text-heading-sub` にする。大きくした見出しでアコーディオンの中が重く見えるなら、見出しを立てずに、索引の名前をラベルか `ul` の名前で言う形も比べて決める。どちらにしても `DESIGN.md` の段と合わせる。

### Minor-1 見出しの無い記事の一覧が、見出しの構造では「タグ（29）」の下に入る

- アコーディオンを開くと、見出しの並びは h1「開発ノート」→ h2「分類（5）」→ h2「タグ（29）」になる。そのあとの件数の行・名前の欄・記事の一覧には見出しが無い。
- 見出しで移動する読み上げの利用者には、記事の一覧が「タグ」の節の中身に聞こえる。
- Major-2 を直すときに、一覧の見出しの構造もあわせて決める。例えば、索引の見出しを見出し要素にしない。

### Minor-2 T3-10 で `/blog` にパンくずを足すと、この条件が崩れる

### Minor-3 分類の名前で探すと0件になる（消した `searchFilter` が持っていた働き）

- 変更前の `filterPostsByKeyword` は、分類の表示名も探す字に入れていた。いまは入れていないので、名前の欄に「開発ノート」と打つと「条件に合うものはありません（全86件）」になる。
- 分類の名前は、どの行にも種別として見えている。そのため来訪者は、見えている語で探して0件になる。
- 欄のラベル（「題名・説明・タグ・連載名で探す」）は分類を言わないので、§7 と矛盾はしていない。それでも、見えている語で当たらないのは来訪者には不親切。
- 直し方は2つある。1つは、分類の表示名を探す字に足す（行に見えている値なので、一致の度合いは4段目）。ラベルは設計どおりのままでよい。もう1つは、足さない判断を 3-1 に書き残すこと。

### Minor-4 「AI試行錯誤ブログ」が 320px で「ブロ／グ」と語の途中で折れる

## 来訪者から見た判断の妥当さ（依頼の4点）

- **分類のページの見出しを分類の名前にした**: 妥当。3-1 の「ページの見出しと中身が一致」に合い、タグのページとも揃う。ただし、パンくずが無いまま見出しを替えたので、集まりが分からなくなった（Major-1）。
- **外枠を Section にした**: 妥当。一覧のページは1つのセクションで、§5 の見出し・余白・左端がそのまま出る。320・375・1280 で左端が揃い、罫線の形も崩れていない。T5 で組み直す手間も減る。
- **「分類（5）」「タグ（29）」を h2・`--text-step-1` にした**: 見出しの語と数は 3-1 と §7 のとおり。大きさは §4 と合わない（Major-2）。構造は Minor-1。
- **`/blog` と分類のページに見えるパンくずを足していない**: `/blog` は受け持ちの外として理解できるが、先の条件とぶつかる（Minor-2）。分類のページは、この変更で必要になった（Major-1）。

## 消した部品の影響

- **`BlogList`・`BlogFilterableList`**: 行・絞り込み・ページ送り・分類の組・人気のタグは、`BrowsableList` と索引が引き継いだ。失ったのは次の3つ。
  - 分類名での名前の絞り込み（Minor-3）
  - 行のタグのリンクと「新着」。この2つは設計で外すと決めたもの
- **`newSlugsHelper`**: ブログの「新着」だけが使っていた。遊びとツールには別の同名の関数があり、影響は無い。
- **`searchFilter`**: Minor-3 のほかは、`list-browse` のほうが正規化（NFKC・仮名）が広い。
- **ブログのページ送りの定数と `paginate`**: どこからも参照が残っていない。`/page/1` の 308 は `next.config.ts` の共通の規則と `next-config-redirects.test.ts` が受け持つ。
- **記事のページ**: パンくずに分類が入り、JSON-LD も `Breadcrumb` から同じ4段で出る。タグのリンクは、一覧のページを持つタグだけのまま。
- **タグのページ**: 5件未満のタグの `noindex` は残っている。canonical・OGP・題（「Web開発 - AI試行錯誤ブログ | yolos.net」）も変更前と同じ形。
- **sitemap**: 変更は無く、2ページ目からの URL は載らない。2ページ目からは自分を canonical にしている。
