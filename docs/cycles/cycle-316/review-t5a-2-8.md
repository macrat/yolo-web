## 指摘

1. **136行の数え方では、変更後の版の 90ms の回で、1打目が入れた答えを2打目の X（最後の問なら S）として数えてしまう。また、突き合わせる「記録された答え」の出どころが書かれていない。**
   - 136行は、2打目がどの問の選択肢に落ちたか（落ちたときの帯の番号と選択肢の名前）を残し、「その走査で記録された答え（問ごとの選択肢）と突き合わせて、2打目の選択肢がその問の答えになっていれば X（最後の問なら S）」とする。
   - 変更後の版では、1打目で答えた問は 150ms そのまま見せる（t5a-design.md 4-3）。行は替わっても字の位置は変わらない（4-4）。90ms の2打目は、同じ点、つまり**同じ問の同じ行**に落ちる。そのときの帯の番号は1打目の問で、選択肢の名前は1打目が入れた答えと同じである。本文の突き合わせでは「2打目の選択肢がその問の答えになっている」ので X に数えられる。最後の問の 90ms の回は S に数えられる。実際には、この2打目は 4-3 の「その問の答えがまだ無い」に合わず捨てられている。
   - 基準の版は押すとすぐ進むので、2打目は次の問に落ちる。この誤りは変更後の版の 90ms の回にだけ、ほぼ毎回出る。両方の版に「同じ数え方」を使っても、B-620 の材料の比べ（間隔ごとの数）が、変更後の版で X と S が多い向きに誤る。
   - あわせて、「その走査で記録された答え」をどこから取るかが書かれていない。いまのコードは答えを `QuizContainer` の `useState` にしか持たず、基準の版は押した形も描かない。T5a-7 は、文だけからは突き合わせる先を組み直せない。
