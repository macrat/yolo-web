### 1-2. favicon と apple-touch-icon

- **commit された資産と、生成するスクリプトが食い違っている。** `public/icon.svg`・`favicon.ico`・`apple-touch-icon.png` の最後の変更は `6b6592c`（2026-09-21）で、朱の角丸タイル（`#af3622`）と地 `#f8f7f2` を持つ。スクリプトはそのあと `db7e525`（2026-09-25）で色を `utsuwaHex` の `INK`・`PAPER` に替えたが、資産は作り直されていない。スクリプトがいま作るのは「紙の地に墨の角丸（rx は1辺の 22%）の印と白抜きの `y`」で、これも §10 と合わない。
- `src/lib/site-metadata.ts:45` のコメントは「朱の角丸タイルに白抜きの y」と、いまのスクリプトとも §10 とも違う形を言う。
- §10 と合わない所: 角丸（§10「角丸なし」）、彩度（朱。§10「彩度なし」）、`--ink` の地でない（紙の地に印を置く）、字が明朝（Noto Serif JP 900）。§3 は「サイト名も favicon も欧文で…欧文は見出しも IBM Plex Sans」と定め、`y` は欧文の基本範囲の字なので、見出しの書体で組むとは IBM Plex Sans で組むことである。
- ライトとダーク: `icon.svg` は色を1組しか持たない（index.md の完了の条件は「ブラウザのタブのライトとダークの両方で見分けられる」）。
- Google 検索の favicon: 対応形式は BMP・GIF・ICO・PNG・JPEG・PPM・TIFF で SVG は挙がっておらず、推奨は 48px より大きいもの（[facts-external-specs.md](./facts-external-specs.md) §9）。いま Google が使える `rel="icon"` は `favicon.ico`（最大 48px）だけである（`icons.icon` は `icon.svg` と `favicon.ico` の2つ。`site-metadata.ts:49-54`）。

- **カードから来る人は、いまは数えられるほどいない。** カードの出来が流入を左右しているかは、この数からは読めない。

### 3-1. 札を残すか

| 案                                                                    | 来訪者から見て                                                                                                                                                                                                                                                 |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A. 保存と共有を残し、画像を結果の OGP と同じ1枚に描き直す**         | 28日で26人が使った持ち帰り方が残る。保存する画像は、結果の名前・診断名・サイト名が読める、サイトと同じ顔の1枚になる。色が主題でないのに付いていた和色の面と印は消える                                                                                          |
| B. 保存と共有を消す                                                   | 持ち帰りたい人は画面のスクリーンショットを撮ることになる。スクリーンショットには、結果のボックスの外（ボタン・パンくず）も写り、375px では名前と説明が1枚に収まらない（t4-design.md 0章の実測では、説明の終わりまで最初の画面に入るのは24タイプのうち3タイプ） |
| C. 残し、保存用に別の縦長の画像（キャッチコピーと説明を載せる）を作る | 持ち帰る物は豊かになる。ただし §10 の画像（名前とサイト名）と別の描き方をもう1つ持ち、その価値を裏づける数は無い（保存した人が何に使ったかは分からない）                                                                                                       |

**A を勧めます。** 札の保存は、サイトで結果を持ち帰る操作のうちいちばん使われていて（2-1）、消すと来訪者から実際に使われている手段を取り上げることになります。T4 で画面から包みを消したので、いまの札（和色の面と印）は画面のどこにも無い見た目で、画面とも §10 とも食い違っています。描き直せば、保存した画像も、人に送ったカードも、サイトの画面と同じ顔になります。C は、A のあとに保存の数が伸びるか、保存した人が何を求めているかの手がかりが得られてから考えます。

A にしたときに消すもの・変えるもの:

- **消す**: `src/lib/fuda-image.tsx`（描き方は `ogp-image.tsx` の1つにまとめる）・`src/lib/wairoHex.ts`（`WAIRO_HEX`・`pickResultWairoColor`・`WAIRO_INK_*`）・`src/lib/fudaSymbol.ts`・`src/play/color-utils.ts` と、それぞれのテスト（`fuda-image.test.tsx`・`wairoHex.test.ts` の和色の部分・`fudaSymbol.test.ts`・`src/play/__tests__/color-utils.test.ts`）。`wairoHex.test.ts` のうち、`utsuwaHex.ts` の値が globals.css のトークンから作れることを試す部分は、`utsuwaHex.ts` のテストへ移す。
- **変える**: `FudaActions` は残し、名前を今の見た目の呼び名（結果の画像の保存と共有）にする。共有の文は、同じ区画の文の共有と同じく `resultNameWithReading` で名前を組む。保存の Route Handler（`…/fuda-image/route.ts`）の URL とファイル名も同じ呼び名にそろえる（来訪者が外から指す URL ではない。`og:image` はハッシュ付きの別の URL）。
- **変えない**: GA に送る `surface` の値 `"fuda"`。ADR009 の率の分子がこの値で数えているので、値を変えると出荷の前後で数がつながらなくなる。コードの中では、この値を「結果の画像」を指す計測の値として1か所（`src/lib/analytics.ts` の `ShareSurface`）で説明する。
- ADR009 の「出荷の日から計測の出方が変わるもの」に、「保存と共有する結果の画像の見た目が変わる（和色の面と印が消える）」を足す（ADR の経過の記録で、cycle-completion で行う）。

### 3-2. OGP の組み方（§10）

| 案                                                                                                                                        | 来訪者から見て                                                                                                                                        |
| ----------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| a. いまの組み方のまま、書体を替え、線を画像の端まで伸ばし、印を消す                                                                       | 規定の字面には合う。ただ、縁の枠と余白の中の細い線という組み方はサイトの画面に無く、カードを見てもサイトの画面と同じものだと分からない                |
| **b. サイトの画面の頭と同じ組み方にする**（上端のサイト名と全幅の太い罫線、それを縦に貫くコンテナの左右の太い線、その中に補助情報と名前） | カードを見た人が、開いた画面と同じ顔に着く。§1 が「このサイトだと分かる形」とする罫線の交わり方（十字の残る端）が、タイムラインの小さなカードでも出る |

**b を勧めます。** §10 はサイトの外を「デザインだけで見分けがつくかが最初に試される場所」とし、§1 はこのサイトだと分かる形を罫線の交わり方に置いています。

試作（ソースを変えずに `ImageResponse` で描いたもの。値は出発点で、builder が PNG を見て詰める）:

- 1200×630、地 `PAPER`。縦の線（コンテナの左右）を x=56 と x=1138〜1144 に、横の線（上端のサイト名の下と、下端）を画像の左端から右端まで引く。線の太さは 6px（§5 の太い線 3px の2倍。カードはタイムラインで幅 500〜600px ほどに縮めて見られるので、そこで 2.5〜3px になる）。色は `INK`。
- 上端: サイト名「yolos.net」を IBM Plex Sans 400・36px・`INK` で、コンテナの内側の左に置く。
- 中身: 補助情報（「{診断名}の結果」・「ブログ」・「伝統色辞典」など）を本文の書体（BIZ UDPGothic）30px・`INK_2` で置き、その下に名前を見出しの書体で置く。読みがあれば名前のすぐ下に補助情報の大きさで添える。
- 色が主題のページ（traditional-color の結果・伝統色辞典）だけ、名前の左に色見本を1つ置く（試作は 200px 四方、`RULE_2` の細い枠）。見本の上に字を置かない（§2）。
- 印・回した `y`・画像の縁の枠・和色の面は持たない。
- X の 2:1 の切り取り（上下 15px）に掛かる所に字を置かない（試作では、いちばん上の字の上端が y=26 より下にある）。

試作で分かった、組むときに要ること:

- **欧文と和文の書体の分け方は、字の範囲で分けたまとまり（`span`）で指定する。** Satori（`next/og`）の `fontFamily` に「Plex, Zen」と並べると、「Markdown」は Plex で組まれたのに、同じ題の「GFM」は Zen Antique で組まれた。サイトと同じく U+0000-007F を IBM Plex Sans、それ以外を和文の書体（名前は Zen Antique、補助情報は BIZ UDPGothic）にするには、字をその範囲で分けて、まとまりごとに `fontFamily` を渡す。
- **名前は、サイトの見出しと同じ文節の区切り（`splitIntoPhrases`、`src/lib/phrase-breaks.ts`）で分け、文節を1つずつ flex の子にして折り返す。** 字の範囲で分けた `span` をそのまま並べると、Satori は `span` の境目で行を送り（「締切1」のあとで改行した）、境目の空白を落とした（「layoutで not-found」の空白が消えた）。文節ごとの子にし、子の中を `white-space: pre` にすると、どちらも起きず、名前は §4 の見出しと同じく文節の切れ目で折れた（「締切1時間前に突然スイッチが入って傑作を／叩き出す情熱の画家」）。
- **Zen Antique で組むと「——」は1本の線になる。** 同じ ezo-shika の題を Zen Antique 50px で組むと、線の画素は x=240〜339 の1本で、隙間が無い（3-4）。
- 書体のファイルは、いまと同じく Google Fonts の CSS に古い UA で問い合わせて TTF を取る。Zen Antique は1ファイル（5.5 MB。サイトの字の表 `src/data/zen-antique-charset.json` の `source` と同じ URL）、BIZ UDPGothic は1ファイル（4.4 MB）、IBM Plex Sans 400 は1ファイル。
- 名前に Zen Antique に無い字（𠮟・剝・塡・頰・纁。t4-inventory.md 3-2）があるときは、§3 のとおり名前の和文を丸ごと `"BIZ UDGothic"` で組む（`charsMissingFromZenAntique`、`src/lib/zen-antique-charset.ts`）。そのために BIZ UDGothic の TTF も取る。
- **書体を取れなかったら、ビルドを失敗させる。** いまは取れないと黙って `sans-serif` に落とし、違う顔の画像がそのまま出荷される（`ogp-image.tsx:213-214` のコメントのとおり）。画像はビルドで書き出すので、そこで止めれば出荷の前に分かる。
- 名前の大きさは、字の数で段を選ぶ（いまと同じ考え方）。いちばん長い名前は、ブログの題 69字（「Next.js複数root layoutで not-found.tsx が効かない -- global-not-found.js での解決」）と、診断の結果 35字（character-personality）。どの段でも、名前が中身の枠からはみ出さず、3行を超えないことを PNG で確かめる。

代替テキスト: 画像に書いてある字を言う（例「yolos.net 動物性格診断の結果 エゾシカ——北の大地を群れで駆ける繊細戦士」）。ルートごとの決まった文（「クイズ結果」など）をやめる。名前ごとに変わる `alt` の渡し方（ファイルの `alt` は決まった文しか出せない）は、Next 16 で使える形（`generateImageMetadata` か、ページの `metadata.openGraph.images` の `alt`）を builder が確かめて選ぶ。伝統色辞典は「伝統色辞典」の語を含める（index.md の T6 の行）。

`DESIGN.md` §10 に、この組み方（上端のサイト名と全幅の罫線・コンテナの左右の線・補助情報と名前・色見本の置き方・欧文と和文の書体・保存する結果の画像も同じ組み方）を、実装の前に書きます（`frontend-design` スキル「`DESIGN.md` に無いコンポーネントを足したくなったら、先に `DESIGN.md` へ書く」）。§10 のいまの規定（`--paper` の背景・`--ink` の文字・全幅の罫線・見出し書体・印を足さない）を変えるものではなく、組み方を書き足すものです。

### 3-4. 明朝の「——」の隙間

**書体を Zen Antique に替えることで直ります（3-2）。** 字を置き換える（「—」を別の字にする、線を描く）必要はありません。Zen Antique の「—」（U+2014）は字の表にあり、2つ並べると1本の線になりました（x=240〜339、隙間なし）。「―」（U+2015）は Zen Antique に無いので、置き換えの先にしてはいけません。確かめる画像は、「——」を持つ題の animal-personality 12タイプと japanese-culture 7タイプのうち、ezo-shika と kado のほか各1枚です。
