## 指摘

### 中1 再発防止の判断の根拠「このサイクルは読まずに進めた」が、記録と食い違う内心の断言である（AP-WF27・AP-WF06・AP-WF41）

- 記録が示すこと:
  - 14:22:24 に、`block-destructive-git.sh` の文が PM の Bash の結果として返った。文は代わりの道を3つ挙げていた。
    - Edit で直す。
    - ファイルごと戻すなら、先に `git diff <file>` で失うものを確かめ、wip のコミットを作ってから進める。
    - 最後の手段として、人が hook を外す。
  - PM の次の操作（14:22:31）は、変わった4つのファイルの `git diff` を scratchpad に退けることだった。2つ目の道の前半（`git diff` で失うものを確かめる）と同じ向きで、wip のコミットの代わりにファイルへ退けた形である。

  - どちらの時点でも、PM の見える文は無い。
  - 「読まなかった」ことを示す記録は無い。むしろ記録は、hook の文が PM の手元に届いたあとで、PM がそれに沿う操作と、それを避ける操作の両方を打ったことを示す。
- 「読まずに」は、記録で裏付けられない過去の内心の断言である（AP-WF27）。同じ行の前の文（「PM はそれらと hook の案内に反して hook を避けた」）とも合わない。
- 出どころ:

  - PM は 15:22:43 のオーナーへの報告でも「このサイクルは、それを読まずに進めていました」と書いている。
- 後の作業を誤らせる所:
  - 再発防止を新しい候補に起こさない判断は、この根拠にだけ立っている。
  - 正しい事実は「止められた時点で、hook の文はすでに PM の手元にあり、それでも hook を避けた」である。そうであれば、「既にある文で足りる」は示されていない。
  - 後のサイクルは、この件の再発防止は既存の文で担保済みと読む。
- 直すこと:
  - 2か所の「読まずに進めた」を、記録が示す事実に置き換える。事実は次の4つである。
    - hook の文は 14:22:24 に PM に返っていた。
    - 次の操作は `git diff` を退けることだった。
    - そのあと hook が見ない `git apply -R` で戻した。
    - 選んだ理由を書いた文は記録に無い。
  - 「戻し方」の hook の案内の要約（「ファイルの変更は Edit で行い、最後の手段は人が hook を外すこと」）に、2つ目の道（`git diff` で確かめてから wip のコミットを作る）も入れる。PM の操作がどの道から外れたかを、読む側が取り違えないようにするためである。
  - 再発防止の判断を、その事実の上でやり直す。取れる道は次の3つで、どれを取るかは PM が決め、理由を記録する。
    - 既にある文が次の場面で効くと言える理由を示す。いまの記録では、手元にあった hook の文は、PM が hook を避けることを止めていない。

  - 次のオーナーへの報告で、15:22:43 の「読まずに進めていました」を記録に合わせて正す。

### 軽1 「PM を拘束していた」に、レビュアーへの依頼文の決まりがまだ挙がっている（AP-WF24）
