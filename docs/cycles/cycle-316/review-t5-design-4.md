## Minor

1. **パスで名指ししてコミットする決まりのコマンドが、新しいファイルで失敗する（10章の頭）**
   - **事実**: 決まりは「`git commit -- <パス>…`」だけを示す。`git commit -- <パス>` は、まだ git が知らないファイル（新しく作ったファイル、`mv` で移した先）を名指すと `error: pathspec '…' did not match any file(s) known to git` で止まる（使い捨てのリポジトリで確かめた。先に `git add <パス>` で載せれば、ほかに段に載っているものを持っていかずに通る）。T5 には新しいファイルを作るか移すタスクが多い: T5-3b（`src/lib/phrase-dashes.ts` とその試験）、T5-8（表の部品・`scroll-frame.ts`）、T5-9 と T5-20a（`new/` の移動）、T5-22（`not-found.tsx`）、T5-3c（区切りを作るサーバーの関数）。
   - 止まったときに builder が `git add -A` に戻ると、この決まりを足した理由（3回目で見つけた、T6-2 の段に載せた削除を T5 のコミットが持っていった件）がそのまま起きうる。
   - **求めること**: 決まりに「新しいファイルと移した先は、先に `git add <パス>` で名指しして載せてから `git commit -- <パス>…` でコミットする」を1文足す（移すときは `git mv` を使うと書いてもよい）。
