# T6-1 のレビュー（`e43b46a` DESIGN.md §10・frontend-design スキル）

## 判定: 改善指示

§10 は t6-design.md の 3-2・3-3・3-5・3-7・3-8 の決定をほぼ漏れなく持っていて、「どう見えるか」の書き方も揃っています。線を2倍にすること（太い 6px・細い 2px）、読みと副題を補助情報と同じ書体・色・大きさにすること、3-5 と 3-8 の中身を入れたことは、どれも正しい判断です。ただ、§10 の中で矛盾する規則が1つ（Major-1）、例外の形で書かれた規則（Minor-1）、§3・§4 と食い違う所（Minor-2・Minor-5）、確かめていない事実を事実として書いた所（Minor-3）が残っています。T6-2〜T6-10 の builder はこの節だけを読んで組むので、直してから進めてください。

## Major

### Major-1: 「画像の名前は h1」と、トップの画像・伝統色辞典の画像が食い違う

§10「画像」は「画像の名前は、そのページの名前（h1）である」と書き、そのすぐ下で「トップの画像は、名前でサイト名を繰り返さず…」と書いています。トップの h1 は `SITE_NAME`（「yolos.net」、`src/app/page.tsx:182`）なので、この2つの規則はトップで食い違います。読む人には、1つ目の規則に書かれていない例外に見えます。

伝統色辞典の詳細も同じです。h1 は `{name}（{romaji}）`（「鴇（toki）」、`src/app/dictionary/colors/[slug]/page.tsx:40`）ですが、§10 の中身の規則では、名前は「鴇」、読みはその下に置きます。「名前 = h1」をそのまま当てると、丸括弧の読みが名前の段で組まれます。これは 3-3 で b 案として退けた形です。

直し方: 1つの原則から両方が出るように書き直してください。例えば「画像の名前は、そのページが何であるかを言う名前で、画面の見出し（h1）と同じ出どころから取る。見出しが読みを含むときは、読みを名前から分けて読みの位置に置く。サイトそのものであるトップでは、サイト名が上端にあるので、名前でサイトが何であるかを言う」のような形です。「どのページにも画像がある」ことと「名前は何から取るか」を1つの項目に混ぜないほうが読みやすくなります。

## Minor

### Minor-1: 保存する結果の画像が「規則＋だけは」の例外の形になっている

「診断・クイズの結果の画像は、その結果の OGP 画像と同じ画像である」の直後に、「知識のクイズの保存する画像だけは…点数を持つ」が続きます。1つ目の規則を2つ目が破っていて、CLAUDE.md が禁じる例外の形です。

どちらも同じ原則から出せます。**持ち帰る画像は、画面の結果のボックスと同じ中身を持つ。リンクのカードは、受け取った人が開くページと同じ中身を持つ。** 多くの診断ではこの2つが同じ中身なので、同じ1枚になります。知識のクイズでは、画面の結果のボックスに点数があり、開く段位のページには点数が無いので、点数の行だけが違います。この順で書き直してください。

### Minor-2: 400px での下限 12px が、§4 の補助情報の下限 14px と食い違って見える

§4 は「補助情報: 0.875rem（14px）が下限。これより小さい文字は持たない」と定めています。§10 は「400px で 12px 以上（画像で 36px 以上）」です。媒体が違うので矛盾ではありません。ただ、なぜ 12 で 14 でないのかの理由が無いので、読む人には2つの下限が並んで見えます。

次のどちらかにしてください。

- (a) §4 とのつながりを書く。例えば「カードがふつうに見られる幅（500〜600px）で §4 の下限の 14px 以上（36px は 15〜18px）になり、いちばん小さく縮められる 400px でも 12px で読める」。
- (b) 画像の側を 42px（400px で 14px）に上げる。この場合は、ルートの副題などが縦に収まるかを確かめる。

名前のいちばん小さい段の 42px（400px で 14px）とも関係を揃えて書いてください。

### Minor-3: favicon の「400 では 16px で線が 1px を下回り、滲む」は確かめていない。当てはまらない場合もある

t6-design 3-7 では、この一文は推測で、T6-10 で 400 と 700 を並べて確かめることになっています。レビューで `src/fonts/ibm-plex-sans/IBMPlexSans-Regular.woff` の `y` を、高さがタイルの 80% になる大きさで 16px に縮めて測りました（`tmp/fav-check.mjs`）。400 の左の払いの横の幅は約 1.4px、線に直交する幅は約 1.3px で、1px を下回りませんでした（700 では約 2.4px）。字をタイルに対して小さく置けば 1px を下回りますが、どちらになるかは T6-10 が決める大きさ次第です。

DESIGN.md に書いてよいのは、確かな理由（「favicon の仕事は 16px で字の形を残すことなので、§3 が配る2つの太さのうち太いほうを使う」）だけです。数についての一文は消してください。実測の結果は T6-10 の記録に残します。

### Minor-4: 下端の罫線が X の切り取りの帯に入りうる

「その下と画像の下端に、画像の左端から右端まで太い罫線を引く」とあります。下端の罫線を画像の下の縁（下から 15px の中）に置くと、X が 2:1 に切ったときに罫線が落ち、下側の十字の端も消えます。15px の規定は「字を置かない」だけで、線には掛かっていません。

画面の §5 のレイアウト（「下端: 上に全幅の罫線。その下に…」）と同じく、「下端の上に」罫線を引き、その下までコンテナの左右の線が伸びて十字の端が残る形にしてください。切り取りの帯には、字だけでなく罫線も置かないことを書いてください。

### Minor-5: 見出しの書体を読み込めないときの書体が §3 と食い違う

§10 は「見出しの書体を読み込めないときは、見出しの字も本文の並びで描く」と書いています。§3 は、見出しを本文の書体に落とすときは「仮名を全角で組む並び（BIZ UDGothic が先頭）」とし、「Zen Antique を読み込むあいだの見出しも、この並びで組む」と定めています。§3 の「本文の並び」は BIZ UDPGothic が先頭の並びなので、§10 の書き方では別の並びになります。すぐ上の「Zen Antique に無い字」の項は §3 どおり BIZ UDGothic の並びで、同じ節の中でも揃っていません。§3 の並びに合わせてください（t6-design 3-5 の書き方をそのまま写した所ですが、DESIGN.md の中の食い違いとしてここで直します）。

### Minor-6: 「名前の段」が定義されておらず、縦に収まるかが読み取れない

- DESIGN.md で「段」といえば、§4 の 1.4 倍ずつの5段です。画像の名前の段（試作の 96〜42px、約 1.14 倍ずつ）は別のもので、§10 はそれを定義していません。数字の結果の大きさは「名前のいちばん上の段の約 1.4 倍」で決まるので、少なくともいちばん上とそれ以下の段が何であるか（または枠の寸法のモジュールが持つ画像の段であること）を書いてください。
- 「3行以内で中身の枠に収まる」は、横幅だけの話にも、補助情報・数字の結果・読み・副題と合わせて縦に収まる話にも読めます。ルートの画像（名前と長い副題）や、知識のクイズの保存の画像（数字の結果が2行に折れたとき）では、縦が足りなくなりえます。段はほかの中身と合わせて縦にも収まるように選ぶ、と書いてください。
- いちばん小さい段でも3行に収まらない名前をどう組むかが書かれていません。

### Minor-7: 「ゲームの結果の画像」が irodori だけの形を、ゲーム全体の規則として書いている

「問ごとのお題と回答の色見本と点」は色のゲーム（irodori）の中身です。このままだと、今後ほかのゲームに保存する画像を足したときにも色見本を持つことになります。規則の側は「画面の結果の要約（合計点を数字の結果に、ランクとその言葉、問ごとの結果）を同じ枠で描く。問ごとの結果は画面と同じ形で持つ（色のゲームなら、お題と回答の色見本）」のように、中身から出る形で書いてください。

あわせて、ランクの言葉と問ごとの字・点の大きさの下限が、§10 の下限の規則（サイト名・補助情報・読み・副題・名前）のどれにも入っていません。t6-design では「補助情報の大きさ」です。下限の規則にこれらを入れてください。

### Minor-8: 色見本の置き方と色の値の置き場所

- 「左端を揃えて置く」と「色見本は…名前の左に置く」を合わせたとき、補助情報・読みの左端が色見本の左端に揃うのか、名前に揃うのかが決まりません。色見本を中身の左端に置き、名前と読みをその右から始める、などと形を書いてください。
- 伝統色辞典の画像は色の値（hex）を読みと同じ行に置く設計ですが（T6-5）、§10 は色の値に触れていません。T6-5 の実装に要る形なので、§10 に書いてください（画面の詳細が値を見せるのと同じく、色見本の画像は色の値を補助情報として添える、など）。

### Minor-9: 画像の折り方の規則が §4 の一部しか引いておらず、理由が無い

- 「§4 の見出しと同じく文節で折り、…」は §4 の最初の文だけを引いていて、1字だけの行・禁則・丸括弧の一続き・最後の1字の文節の扱いが画像にも掛かるかが読み取れません。「§4 の見出しの折り方で折る」と、§4 の全体を指してください（組み方で避けられないときの受け入れも §4 のとおり）。
- 画面では補助情報は通常の禁則処理で折ります（§4）が、画像では補助情報・読み・副題も文節で折ります。なぜ画像は違うのかという来訪者から見た理由（縮めた画像を一目で読むので、どの字も意味のまとまりで折る、など）を1文足してください。
- 「渡された空白は残し」は実装の言い方（Satori が空白を落とした事象の裏返し）です。「語のあいだの空白は画像でも空白として見え、行頭には出ない」のように、見え方で書いてください。

### Minor-10: 経緯の名残と言い回し

- 冒頭の「どれも、サイトの画面と同じ形で描き」は、favicon と検索結果には当たりません（favicon の形は画面に無い）。「同じ色・書体・線で描き」のように、全部に当たる言い方にしてください。
- favicon の「正方形の外に紙の縁を持たない」は、直前の「正方形を画像の全面に塗り」から出ることで、古い資産（紙の縁の上の印）を打ち消すための念押しに読めます。消してください。
- 「画面に無い飾り（印・回した字・画像の縁の枠・飾りの色の面）」の括弧は、消した古い画像の部品をそのまま並べたもので、経緯の名残に読めます。§5「持たないもの」と同じく、一般的な言い方にしてください。
- 「カードを宣言するページ」は実装の語（`twitter:card`）です。「SNS のカードに出るページ」など、見え方の語にしてください。
- 「既定のテーマは端末の設定に従う」の1項目だけが、小見出しの前に離れて置かれています。ブラウザの枠（`theme-color`）の小見出しに入れるか、冒頭の段落に続く形にして、節の構成を揃えてください。

### Minor-11: スキルの「サイトの外に出る画像を確かめる」の欠け

おおむね手順として使えますが、次のものが足りません。

- 冒頭の「ブラウザで組まれないので」は、クライアントの Canvas で描く irodori の画像には当たりません（「HTML と CSS で組まれないので」が正確です）。来訪者の端末で描く画像の PNG の取り方（Chromium で描いて落とす、など）と、見出しの書体を止めたときに §3 の並びで描かれることの確かめを足してください。
- 地・字・線の画素の色がトークンの light の値であること、色見本の中のほかに彩度のある画素と角丸が無いこと（T6-12 の条件）の確かめが無いこと。
- 「罫線の形」は横の罫線だけを数えていて、コンテナの左右の線が上端から下端まで途切れないことと、左右に十字の端が残ることを数えていないこと。
- §10 の「カードに出るページは、どれもそのページの画像を持つ」の確かめ（ビルドの HTML で、`twitter:card` を持ち `og:image` を持たないページが0件）が無いこと。
- 表の「作るもの」に favicon を挙げていますが、favicon の確かめ方が無いこと（ICO を拡大して見る・`emulateMedia` でライトとダーク・角の画素が `--ink`・404 と 410 の `<link>`。T6-10 の条件から）。
