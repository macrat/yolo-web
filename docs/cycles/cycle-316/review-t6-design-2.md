## Major

### Major-1 T5・T7 と同じファイルを触るのに、順序が書かれていない

4章の受け持ちの表は T6 の中の分け方だけで、ほかのタスクとの関係が無い。T6 の設計は T5 の棚卸しと並んで進んでおり、index.md の補足事項（234〜236・283行）には、同じ作業ツリーで builder が並行して同じファイルを触った事故が記録されている。

- **`src/app/global-not-found.js` と `build410Html`（`src/middleware.ts`）**: T6-10 が icon を足すが、T5 は「`global-not-found.js` を `not-found.tsx` に寄せるか」（t5-inventory.md 1-a）と「410 の見出しに文節の区切りを入れるか、GA を載せるか」（1-b）を決めて、同じファイルを書き換える。T5 が `global-not-found.js` を消すと、T6-10 の直す先が無くなる。
- **`ResultCard.tsx` の共有の区画**: T6-6 がすべての診断・クイズに保存と共有のボタンを置くが、T5 は「診断の結果のページで、24行の一覧のあとの共有と『次はこれを』までの距離を 375px で測る」。T6-6 のあとでは区画の高さが変わる。
- **一覧・`/about` の h1 とルートの説明**: T6-7 は画像の名前を h1 にそろえるが、T5・T7 が h1 や `TOP_DESCRIPTION` を変えうる。

直し方: 4章の頭に、T6 が T5（と T5a）の完了のあとに始まるのか、並行するならどのファイルをどちらが先に触るのかを書く。T6-10 は T5 の 1-a・1-b の決定のあとにし、「404 と 410 の icon」は T5 が残した形（`not-found.tsx` に寄せたならそちら）に足すと書く。T6-7 の条件の「名前がその h1 と同じ」は、画像のルートが h1 と同じ出どころ（ページのデータ・定数）から名前を取ることを条件にする（字を画像のルートに書き写すと、T7 が h1 を直したときに食い違う）。

## Minor

### Minor-1 ゲームの OGP は3本でなく4本

1-1・T6-3・受け持ちの表は「ゲーム3本」だが、共通の OGP を使うゲームのルートは `src/app/play/{irodori,kanji-kanaru,nakamawake,yoji-kimeru}/opengraph-image.tsx` の4本である（1-1 の「54ファイル」は4本で数えたときに合う: 道具 36・ブログ・ルート・プレイ面・`[slug]` の結果・専用の7本・daily・ゲーム4・ユーモア辞典・privacy）。3本のまま渡すと、T6-3 の builder が1本を移し漏れ、T6-11 で `ogp-image.tsx` を消す段になって初めて分かる。3か所を「ゲーム4本」に直し、T6-3 の確かめる PNG にゲームをもう1本（例 kanji-kanaru）足す。

### Minor-2 `twitter-image.tsx` を対にする判断は、今の時点で決められる

3-2 は「X が `og:image` を使うかを確かめられるまで、新しいルートにも `twitter-image.tsx` を対にする」とするが、X の開発者向けの文書（Cards の Getting started と Cards markup、https://developer.x.com/en/docs/x-for-websites/cards/guides/getting-started 。本文は JavaScript で描かれていて WebFetch では取れず、検索の索引に載った本文で確かめた）は「カードの処理は、まず Twitter 固有のプロパティを探し、無ければ対応する Open Graph のプロパティに戻る」と書き、`twitter:image` から `og:image` へ戻ることを例に挙げている。この形で決められるなら、T6-7・T6-8 で約2,890本の `twitter-image.tsx` を足してからあとで消す作業（書き出しの約半分、100 MiB 前後）が要らない。少なくとも、新しく置くルート（T6-7・T6-8）では対にせず、既存の40本を消すかは T6-3 で実際のカードを1枚見て決める形にする。確かめられない場合の扱いは今のままでよい。

### Minor-3 知識のクイズ3本では、保存する画像に点数が無い

A' では、保存する画像を結果の OGP と同じ PNG にする。知識のクイズ（kanji-level・kotowaza-level・yoji-level）の解き終えた画面は「10問中8問正解」の点数を結果のボックスに出す（`ResultCard.tsx:482-488`）が、OGP は段位（master など）の名前だけで、点数を持たない。持ち帰った画像に自分の点数が無いことを、来訪者は欠けと感じうる。知識のクイズでも OGP と同じ画像でよいとするか（その理由）、点数を持つ画像にするか、知識のクイズには置かないかを 3-1 で決めて書く。

### Minor-4 受け持ちの表と T6-0 の import の直し先の抜け

- `src/lib/__tests__/ogp-image.test.tsx` も `utsuwaHex` を import している。T6-0 の内容の import を直すファイルの一覧（と 3-6 の最後の段落の「使う所」）にこのテストが無い。T6-0 の条件「`utsuwaHex` が0件」で気づけるが、受け持ちの表の「`ogp-image.tsx`・`fuda-image.tsx`（import の行） T6-0 → T6-11」の行に、そのテストも入れる。
- `src/lib/__tests__/wairoHex.test.ts` は受け持ちの表で T6-0 だけの行にあるが、T6-11 が消す。「T6-0 → T6-11」にする。

### Minor-5 T6-0 の「favicon の資産がバイト単位で同じ」の意味があいまい

T6-0 は資産を作り直さないので、commit された資産は当然変わらない。確かめたいのは改名のあとのスクリプトの出力が変わらないことのはずだが、1-2 のとおり、いまのスクリプトの出力はそもそも commit された資産と違う。「`scripts/generate-favicons.ts` を変更の前と後で走らせ、出力がバイト単位で同じ（資産は commit しない）」と書く。
