## 0. 前提の事実（棚卸しに足したもの）

- **BudouX は、character-personality の24のタイプ名を、どれも語の途中で割らずに文節に分ける。** `budoux` 0.9.2 の既定の日本語の分け方（`loadDefaultJapaneseParser`）で24件を分けると、数字と助数詞は1つの文節に残り（「3秒後に」「10年経っていた」「1000回繰り返す美の」）、「来てるか！」と」「解釈だと…」と」のように括弧と助詞も文節の中に入った。文節の最長は「これ普通じゃないよね」と」の12字。
- **`word-break: keep-all` と `<wbr>` の組み方は、WebKit でも `<wbr>` の所でだけ折れる。** Playwright の WebKit（`npx playwright install webkit` で、このコンテナにも入る。Safari 26.5 相当）で、幅 299px・23.84px の見出しに文節の間に `<wbr>` を入れて組むと「締切3分前に5手先を／読む炎の策士」と折れた。同じ幅で折り方を指定しない見出しは「「もう少し調べてから」と／言って気づいたら10年経／っていた博士」と語の途中で折れた。サイトの索引とアコーディオンのラベル（`LinkIndex`・`IndexAccordion`）は、すでにこの組み方（`keep-all`・`<wbr>`・`overflow-wrap: anywhere`）を使っている。
- **character-personality の結果の文の長さ**（24タイプ）: タイプ名 16〜35字、キャッチコピー 15〜28字、説明（`description`）224〜266字。
- **診断のデータはサーバーから渡る。** `/play/[slug]` の `page.tsx`（サーバー）が `quizBySlug` のクイズを `QuizPlayPageLayout` の props に渡し、解き終えた画面の `ResultCard`（クライアント）はそれを受け取って描く。タイプ名の文節の区切りは、サーバーで作って同じ props で渡せる。
- **`QuizResult.icon`（絵文字）は、どこにも描かれない。** 包みを出す条件（`ResultCard.tsx:452`・`ResultPageShell.tsx`）と、相性の API と部品への受け渡し（`src/app/api/quiz/compatibility/route.ts:83`・`CompatibilitySection`）に使われるが、`CompatibilitySection.tsx:49` は絵文字を置かない。
- **道具を `Panel` で囲む形は、`DESIGN.md` の規定から来ていない。** `DESIGN.md` は結果をボックスに入れると定めるが（§8）、入力を囲むとは定めていない。道具のタイルのコメントは「§1 パネル準拠」と、いまの `DESIGN.md` に無い語を根拠にしている（棚卸し 7-2）。
- **共有のボタンは3つの実装がある**（`src/components/ShareButtons`・`src/play/quiz/_components/ShareButtons`・`src/play/games/shared/_components/new/GameShareButtons`）。T3 は、見える文言と読み上げの名前だけを1か所から取るようにし、部品を1つにまとめることを T4 に任せた（[t3-design.md](./t3-design.md) 6章）。
- **ブログのコードの色分け（Shiki の vitesse-light）には、`--paper-2`（ライト）の上で 4.5:1 に届かない色がある。** テーマのファイルの色を数えると、`#a0ada0`（2.0:1）・`#999999`（2.5:1）・`#b07d48`（3.1:1）・`#998418`（3.2:1）・`#ab5959`（4.2:1）がある。`--ink-2` は `--paper-2` の上でライト 6.7:1・ダーク 7.1:1（§2 の oklch の値から計算）。
- **サイトの中で `<dialog>` を使うのはゲーム4本だけ**（`GameDialog` を使う結果・統計・遊び方の12の部品）。

### 2-1. 結果のボックスが囲むもの

**ボックスは結果だけを囲み、入力と操作は囲みません。** 結果のボックスは `ResultBox`（`src/components/ResultBox/`）の1つの部品にし、診断・占い・道具・ゲームのどの結果もこれで組みます。

| B. 道具の枠の中で、結果の区画を小見出しと細い罫線で分ける | 太い枠が道具全体を囲み、結果は枠の中の小見出しの下                                                       | 捨てる。二重のボーダーは消えるが、コードの結果を `--paper-2` の地のボックス（§5）にできない。診断の結果（ボックス）と道具の結果（区画）で、結果の見え方が2つになる（§12 位置の一定）      |

### 2-2. 性格診断の解き終えた画面（論点1・2）

**組み方**（上から。375px の見積もりは 0章の文の長さと §4・§5 の値からの計算で、`/play/[slug]` の自前の余白を外したあとの幅 321px、ボックスの中身の幅 299px で出しました）:

1. **結果のボックス**
   1. 補助情報の1行「{診断名}の結果」（例「あなたに似たキャラ診断の結果」。`0.875rem`・`--ink-2`）。
   2. **タイプ名**を結果の見出し（`h2`）として、§4 のセクションの見出しの段（`45rem` 未満で `1.49rem`）で、見出しの書体で組みます。文節の区切りで折ります（2-3）。
   3. 伝統色診断だけ、タイプ名の下に結果の色の色見本（`result.color`。細い枠・文字を載せない。§2）。

3. **詳しい読みもの**（成り立ち・日常・メッセージなど、診断ごとの詳細）。セクションの中の小見出し（上に細い罫線。§5）で分け、文は段落、あるあるは箇条書きで組みます。`--paper-2` の地のカードと細い枠の行（`.behaviorsItem` など）は持ちません。
4. 相性（友だちの結果から来たとき）と招待。
5. すべてのタイプ（`OtherTypesNav`。T3 で組んだもの）。
6. 「もう一度挑戦する」。

**包みを何に置き換えるか**（論点2）

- 包み（`Tsutsumi`）と印（`In`）は、どの面からも外して部品ごと消します。包みの部位は、次のように置き換わるか消えます。

  | 包みの部位                             | 置き換え                                                                                                                                                             |
  | -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | 外枠（細い `--ink` の枠・`22rem`）     | 結果のボックス（太い線・コンテンツ幅いっぱい）                                                                                                                       |
  | 見出し帯の「yolos.net」と品名          | 補助情報の「{診断名}の結果」。サイト名は上端にあり、ボックスの中で繰り返さない。診断名は、来訪者が画面を撮って人に見せたときに、何の結果かが画面だけで分かるよう残す |
  | 印                                     | 消す（2-4）                                                                                                                                                          |
  | 記号面（和色の地とタイプ名の最初の字） | 消す。色は結果の中身でなく（3-2）、字はタイプ名の最初の字の繰り返しである                                                                                            |
  | タイプ名                               | 結果の見出し（上の表の C）                                                                                                                                           |
  | 一言（キャッチコピー）                 | 本文の大きさの段落                                                                                                                                                   |

- 伝統色診断では、結果の色（`result.color`）を色見本として出します。いまの画面は結果の色を出さず、id から選んだ別の和色を地にしている（棚卸し 2-3）。色が結果そのものの診断で、来訪者が自分の色を画面で見られるようにします。

**結果のページ**（`/play/[slug]/result/[resultId]` と専用の9本）

- h1 をタイプ名にし、§4 の主見出しの段で組みます（文節で折る）。その上の「{診断名}の結果」の行は残します。包みは置かず、h1 と同じタイプ名を2度出しません（棚卸し 2-2 の末尾）。
- 結果のページは、操作の結果ではなく、タイプを説明する詳細のページです（共有のリンクから来た来訪者が、友だちの結果を読む）。結果のボックスは持たず、キャッチコピーと説明を h1 のあとの段落として置きます。
- 伝統色診断の結果のページは、h1 のそばに結果の色の色見本を置きます。
- 詳しい読みもの・相性・すべてのタイプの組み方は、解き終えた画面と同じ部品です。

**トップの包みの見本**（`src/app/page.tsx:234`）

- 消します。見本は来訪者の受け取っていない結果を「これは見本です」と断って見せるもので、来訪者がトップで探すもの（何が遊べて何が使えるか）ではありません。新しい結果の形（太い枠の中に見出しの書体のタイプ名）は、見本として切り出すと中身の無い枠になります。トップの表示は28日で 65 で、見本が最初の画面に入るのは 1280px だけです。トップの組み方そのものは T5 が決めます。

**知識クイズの解き終えた画面**（kanji-level・kotowaza-level・yoji-level）

- 同じ結果のボックスに、補助情報「{クイズ名}の結果」・結果の見出し（段位の名前）・正解の数を §8 の数字の形（主見出しの段。単位を書く「10問中8問正解」）で置きます。

### 2-3. 見出しの折り方（論点1 の折り方）

**確かめ方の共通の決まり**

- 「WebKit」は Playwright の WebKit（`npx playwright install webkit`。0章）で、「Chromium」は `/opt/pw-browsers/chromium` です。折り方と位置の条件は、ことわりの無いものは両方で満たします。
- 「文節の区切り」は、BudouX がその文に返す文節です。「文節の中で折れない」は、文の字を1字ずつ Range で行の位置を取り、どの文節の字も2つの行に割れていないこと（1つの文節が1行に収まらないときを除く）です。
- 「200%」は、CDP の `Page.setFontSizes` で既定の文字サイズを 32px にした状態です（WebKit では `page.evaluate` でルートの文字サイズを 200% にする）。
- 本番のビルド（`npm run build` のあと `next start`）で測ります。
