## 指摘

### 指摘1（planner・大）: 遊ぶ前の来訪者が見る「ほかのゲーム」の行から、説明が消える

いまの「関連ゲーム」（`RelatedGames`）は、`toPlayListItems` で行を作る。行には名前に加えて、説明（「毎日1つの漢字を推理するパズル」「16個の言葉を4グループに分けるパズル」など、`shortDescription`）と補助情報「毎日更新」がある。案 E はこのセクションを消し、「今日のほかのパズル」の行を「名前と『今日は遊んだ』だけ（いまの `NextGameBanner` と同じ）」にする（4-2）。

そのため、遊ぶ前の来訪者が盤の下で見るのは「漢字カナール」「四字キメル」「ナカマワケ」「イロドリ」という造語の名前だけになる。GA では、ゲームのページの閲覧の 70%（90/129）が解き終えていない閲覧で、その多くは初めての来訪者である（離脱 36 は 26人、`/play` へ 15 は 13人）。この人たちが名前だけで、何のゲームかを選ぶことになる。設計が E を推す理由の2つ目（「このパズルが合わなかった来訪者が離脱する前に、ほかの3本に出会える」）は、行に何のゲームかが書いてあって初めて成り立つ。

§7 は「行は名前を必ず持つ。読み・説明・種別・補助情報・色見本は、項目がそれを持つときに持つ」と定める。4本のゲームは説明を持つので、行の一覧の行は説明を持つのが §7 の形である。

直し方: 4-2 で、「今日のほかのパズル」の行が持つものを、§7 と来訪者の選び方から決め直す。例は、名前・説明・「今日は遊んだ」である。3章の比較では、E で失う情報（関連ゲームの説明）を、解き終えた来訪者と遊ぶ前の来訪者の両方の列に書く。行の高さは説明のぶん増える。4-3 の「サーバーで描く」部分に説明が入ることと、記録で変わるのは補助情報の有無だけであることも、あわせて書き直す。完了の条件 3・4 にも、行が説明を持つことを足す。

### 指摘2（planner・大）: 「他のジャンルも試してみよう」の位置が、遊びのページどうしでそろわなくなる（§12 位置の一定）

§12 の「位置の一定」は、同じ働きの部品が「どのページでも」同じ位置にあることを求める。`RecommendedContent` は、クイズ・診断のページ（`QuizPlayPageLayout`: よくある質問 → 勧める → 同じ分類 → ほかの分類）と、占いのページ（`/play/daily`）とゲームのページで使う同じ部品である。道具のページ（`ToolPageLayout`）も、よくある質問 → 勧める → 関連 → 関連ブログ記事の順で組む。

案 E は、ゲームのページでだけ、「他のジャンルも試してみよう」をよくある質問と勧めるより上に置く。設計は §12 の位置の一定を、1つのページの状態の間（遊ぶ前と解き終えたあと）にだけ当てている。ページの間には当てていない（AP-P02 の留保の選択的適用）。

E' を捨てた理由は「そろえる相手のクイズのページにも同じ重なりがあり、そろえる先として固まっていない」である。しかしクイズのページの重なりは、解き終えた画面の「次はこれを試してみよう」とページの下の一覧の間の重なりである。ページの下の部品の並び（T5-4 が決め、コミット済み）の話ではない。E を採る利点は、ゲームでない遊びへの道が、FAQ（3問の開閉）と「このゲームを勧める」のぶん近くなることである。その道を解き終えたあとに選んだのは、半年で 4閲覧・4人だった。この差で、サイト全体の位置の一定を破る理由が立つかは、設計の中で比べられていない。

「今日のほかのパズル」をゲームのセクションのすぐあとに置くことは、別に扱える。これは今日の進みと次の1本を示す、ゲームのページに固有の働きで、クイズの「次はこれを試してみよう」（結果のすぐ下）に当たるからである。

直し方: 3章で、E と E'（それぞれ指摘1の直しを入れたもの）を、§12 のページ間の位置の一定を列に入れて比べ直す。E を採るなら、ゲームのページでだけ位置が違ってよい理由を書く。T5-30（index.md の補足事項で、診断・クイズの同じ重なりを直すために立てたタスク）とそろえる並びを PM に渡し、2つのタスクで遊びのページの並びが食い違わないようにする。

### 指摘3（planner・大）: 遊んでいる最中の来訪者に、事実と違う進みの文を出す

進みの行が数えるのは、各ゲームの `stats.lastPlayedDate` が今日かどうかである（`crossGameProgress.ts`）。これは、そのゲームを解き終えたときに書かれる（例: kanji-kanaru の `GameContainer.tsx` の 377〜403 行で、解き終えたときに `saveStats`）。いまの `NextGameBanner` は解き終えた画面にしか出ないので、この数え方と文が食い違うことは無かった。t5-design.md 6-a の「遊んだ」の言い方も、その前提で選んだものである。

案 E では、進みの行が盤のすぐ下に、遊ぶ前にも遊んでいる最中にも出る。

- 今日はじめて漢字カナールを3回推したところで、盤の下に「今日はまだ4本のどれも遊んでいません」と出る。
- 四字キメルを解き終えてから漢字カナールを遊んでいる来訪者には、「今日は4本のうち1本を遊びました」と出る。

どちらも、来訪者がいま遊んでいる事実と食い違う。設計はこの文を「新しい文」とし、T7 の文言の見直しに渡している。しかし、これは言い回しの問題ではない。数えているもの（解き終えたか）と、文の言うこと（遊んだか）の食い違いである。遊ぶ前・遊んでいる最中に進みの行を出すかどうかも含めて、T5-20f で決めることである。

一度だけ来た来訪者（解き終えていない閲覧の多く）にとって、「4本のどれも遊んでいません」がそもそも要る情報なのかも、比べられていない。

直し方: 4-2 の表に「遊んでいる最中」の状態を足す。何を数えて何と言うか（例: 「解き終えた」と言う、0本のときは進みの行を出さない、など）を、3案程度で比べて決める。4-3 の読み込みのずれの決まりと、完了の条件 4・5・12 も、それに合わせる。

### 指摘4（planner・大）: 読み込みのずれの完了の条件に、測る手順の抜けと、導線の抜けがある

(a) **S4・S5 の覚えた高さの用意が書かれていない。** 設計は「端末の記録は、localStorage に各ゲームの記録を書いてから開いて作る」とだけ書く。結果の区画の高さの記録（`{slug}-result-height`）が無いまま開き直すと、`ReservedResultArea` は場所を取っておけない。すると、結果が出たところで、その下のもの（新しい「今日のほかのパズル」のセクションを含む）が動く。これは一覧が起こすずれではないが、条件6の「源が今日のほかのパズルのセクションかそれより下にあるものが0」を落とす。条件6は、`layout-shift` の `sources` が「動いた要素」を言うことを使っている。そのため、上のゲームのセクションが伸びて下が動いたずれも数える。測る手順で「同じ版・同じ幅で一度解き終えた画面を描いて高さを覚えさせてから開き直す」ことを決めないと、測った人によって合否が変わる。

(b) **前の版の値を先に取ることが書かれていない。** 条件6の「0」は、前の版で同じ数え方をしたときにすでに0でない面があると、T5-20f の外の原因で落ちる。前の版の同じ数え方の値を先に取り、0でないときに誰が受け持つかを決めておく。

(c) **サイト内の移動と「戻る」が条件に無い。** 解き終えた来訪者のいちばん多い次の一歩は、この一覧でほかのデイリーゲームへ移ることである（19閲覧）。行き来を繰り返す人は、「戻る」で戻ってもくる。サイト内の移動（Next.js のページ内の移動）では、本体の前のスクリプト（`savedLayoutScript`）が描かれない（review-t4-12-3.md の Major-1。T4-12 で直した）。4-3 の組み方 (a)（`savedLayout` の考え方）を採るとき、この導線では値が書かれない。条件7が測るのは読み込み直し（ブラウザの送りの位置を戻す）だけである。次の2つが、どの条件でも測られていない。

- ほかのゲームの「今日のほかのパズル」の行からサイト内の移動で着いたときに、一覧の補助情報と進みの行が最初から正しいこと。
- 行を押して移ったあと「戻る」で帰ったときに、押した行の位置に戻り、下が動かないこと。

直し方: 6章の「測る状態」に、覚えた高さの作り方を書く。条件6に、前の版の値を先に取る手順と、0でないときの扱いを足す。条件7に、サイト内の移動で着いた場合と「戻る」で帰った場合（S2・S4、375・1280）を足す。4-3 には、組み方がサイト内の移動でも決まりを満たすことを書く。

6-1 は、`renderToString` で補助情報と進みの文が「出ない」ことを試すとする。一方で 4-3 は、組み方を builder に任せ、(a) `savedLayout` の考え方も (b) 枠の直後のスクリプトも認めている。組み方によっては、サーバーの HTML がすべての場合の字を持ち、CSS かスクリプトで見せるものを選ぶこともある。そのとき、この試験は正しい実装でも落ちる。試験は、来訪者に見えるもの（JavaScript を止めたときに進みの行が見えず、読み上げの木に無いこと。条件12）で書く。

### 指摘11（planner・小）: T4 の決定を替えることも記録に回す

8章は、t5-design.md 6-c の案 A を替えることだけを挙げる。結果の区画の下の順（「持ち帰る・共有の区画 → 次の問題の時刻 → 次のゲームと他の分野の案内」）は、t4-design.md（結果の区画の順）でも決まっている。T5-20f はそれも替える。index.md の補足事項に記録するものに、これも足す（AP-P24）。
