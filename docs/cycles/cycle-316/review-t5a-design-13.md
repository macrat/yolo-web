## 指摘

### 1. 語を選ばない守りが答えたあとの `ul` だけで、この設計の送りのあとに2打目が落ちる解説の字（と次の画面の字）を守らない

4-4（256行）は、ダブルクリックの2打目が「字になった行の語を選び、黒い地の選択が残ったまま解説を読むことになる」のを害とし、答えたあとの `ul` で `detail >= 2` の `mousedown` を止める。ところが2打目は、`ul` の外の字にも落ちる。

- **知識クイズの答え**: 答えたあとの形は解説と「次へ」の分だけ伸び、下に外れれば 4-6 のとおり「次へ」の下端が画面の下端から 8px 上に来るまで送る。押した点の下の中身はその分だけ入れ替わる。上の試しのページで、問のまとまりの下端を画面の下端から 8px 上に置いてから各行を押し、4-6 の送り（199px）をしてから同じ点に2打目（`clickCount: 2`）を送ると、1行目と2行目の点は答えた行に、4行目の点は「次へ」に、**3行目の点は解説の字に落ち、解説の「ます」が `--ink` の地で塗られた**（375×550）。4-9 の着地の選び方は、4行目のように点が「次へ」に来る送りを避けるので、点を解説の字へずらすこともある。避けるものの並び（押せるもの）に解説の字は入らない。来訪者は、まさにその解説を黒い塊の入ったまま読む。
- **切り替わる操作**: 診断の最後の答えのあと 150ms より後に届く2打目（人のダブルクリックの間は、ふつう 100〜300ms。review-t6-9-4.md）は、結果のボックスの字（結果の名前・説明）に落ちうる。「はじめる」・知識クイズの「次へ」のあとの2打目は、次の問の見出しの字に落ちうる。どれも選べる字で、上の試しで問の見出しのダブルクリックは1字を塗った。
- **条件7（544行）** は「答えたあとの行…に2打目が落ちた回で、空であること」だけを見るので、上の回は測りに出ない。
- **知識の文書**（5章 493〜497行）は、`input-events-and-guards.md` に「いまのコードは、次の形で2打目を扱う」と列挙させるが、この守りが入っていない。次に2打目を扱う人が、選択の守りがあることを知らずに外しうる。

直すこと: 守りの範囲を、4-9 の「押した点の下が入れ替わる操作」の2打目の全体にする。たとえば、`QuizContainer` が押した点を覚える捕捉の段階の受け手（4-9 の手順3）と同じ所で、1打目が回答の画面の操作（「はじめる」・答え・「次へ」・最後の答え・「もう一度挑戦する」）だった連続の押し（`mousedown` の `detail >= 2`）の既定の動きを止める。この形なら、来訪者が字の上で1打目から始めるダブルクリック（答えや解説の語を調べるために選ぶこと）は止めないので、いまの `ul` の形より写しやすくもなる。範囲と比べた案（`ul` だけ・問の区画・操作の連続）を決めて書き、条件7 の `getSelection()` の記録と合否を、マウスの2度押しのすべての回（落ちた要素を問わない）に広げる。5章の知識の文書の列挙にも、この守りを1項として足す。

### 2. 語を選ばない守りの置き場が、組みの箇条と CSS の片付けの箇条になっている

- 4-4 の256行は、「答えたあとの字は、ボタンの面と同じ箱で組む」の子の箇条（共有する規則・下線・行の並び・添えた字の要素・入れ子・WebKit・列挙の欠け）の中にある。ほかの子はどれも字の箱の形の話で、イベントの既定の動きを止める話はここに属さない。2打目の扱いは 4-2（「押し直し」）と 4-9 が受け持つ。
- 4-11 の422行は、見出しが「`QuestionCard.module.css` の片付け」の節に、JS のイベントの受け手の仕事を置く。builder が CSS で済ませようとする（`user-select` など。4-4 が捨てた形）読みを許し、7章の T5a-5 の中身の列にも、この仕事は「CSS の片付け（4-11）」としてしか現れない。

直すこと: 指摘1 で決めた守りを、2打目を扱う節（4-9。4-2 の「押し直し」からは参照）に置き、4-4 と 4-11 からは消す。7章で、その守りを担うタスク（押した点の捕捉を持つ T5a-6 か、答えの受け手を持つ T5a-5）の中身と試験に名指しで入れる。
