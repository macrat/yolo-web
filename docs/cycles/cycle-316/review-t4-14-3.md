### Minor-1: 途中まで遊んだ日を開き直すと、読み込みのあいだ1問目の盤（「1 / 5」と1問目のお題の色）が見え、そのあと3問目に替わる

| 条件                                  | 1問目が見えた時間        |
| ------------------------------------- | ------------------------ |
| 絞りなし                              | 220〜372ms（約 150ms）   |
| CPU 4倍の遅さ・約 1.6Mbps・遅れ 150ms | 1532〜1830ms（約 300ms） |

サーバーの HTML は1問目で描かれ、水和のあとに記録の問へ替わる。高さは同じなので CLS は 0 だが、来訪者には、その日に見ていない色（1問目のお題）と「1 / 5」がいったん出て、別の色と「3 / 5」に替わる。色を見比べるゲームで、お題の色が一瞬ちがう色で出るのは、どちらが今のお題かを迷わせる。さらに、水和の前でもネイティブのスライダーは指で動くので、その間に動かすと水和で値が戻る。解き終えた日は `inputVisibilityProperty` で読み込みのあいだ盤を見せない形になっているので、途中の日も同じ考えで、読み込みのあいだは見本と帯（またはボード全体）を見せない形にするか、ほかの形を planner が決める。直したら、途中の日の開き直しで、見えるものが1問目から替わらないことと CLS を測る。

### Minor-2: 字の幅の見積もりが、Web フォントを読む前の「@」で上限を超える

`textWidth.ts` は、数字でない半角の字を「IBM Plex Sans でいちばん広い字を下回らないよう 1em」とし、頭の注記は「どの書体で描いても実際の幅を下回らない」「Web フォントを読む前と後で、列の幅も組みも変わらない」と言う。ラベルの書体で字ごとに幅を測った（`glyph.mjs`、17px）。

| 字    | Web フォントのあと | 読む前（`IBM Plex Sans Fallback`） |
| ----- | ------------------ | ---------------------------------- |
| 「%」 | 0.927em            | 0.890em                            |
| 「@」 | 0.892em            | **1.016em**                        |
| 「W」 | 0.892em            | 0.944em                            |
| 和字  | 1.024em            | 1.024em                            |

読む前の代わりの書体は、端末の Arial（このコンテナでは寸法が同じ Liberation Sans）を `size-adjust: 101.13%` で広げたもので、Arial の「@」は約 1.015em なので、実機でも 1em を超える。「@」を持つラベルや値はいまの使い手（イロドリ・T5 で組み直す2つの道具）には無く、来訪者への影響はいまは無い。ただ、共有の部品が上限と言う値が上限でなく、テストもそれを確かめていない。数字でない半角の字の値を代わりの書体の最も広い字も含めた上限（例えば 1.05em）にし、テストの字に「@」を足すか、注記を実際の保証の範囲に合わせる。

### Minor-3: 5119855 だけでは型が通らず、イロドリの取り置きも働かない（AP-I09）

5119855 のイロドリの `GameContainer.tsx` は `savedLayoutScript({ …, finishedStatuses: ["completed"] })` を渡すが、その時点の `savedLayout.ts` は `finishedStatuses` を持たない（`git show 5119855:src/play/games/shared/_lib/savedLayout.ts`）。型の余分なプロパティで `tsc` が落ち、動きとしても「completed」を解き終えた回と見ないので、その版のイロドリでは取り置きが働かない。受け側は次の 879ff61（件名は T4-11〜T4-13 のレビュー）で入った。依存される側が後に来た順で、`git bisect` でその版に止まると壊れた状態を見る。すでに push されているので並べ替えはしない。サイクルの文書にこの順の食い違いを残し、これからは共有の部品の変更を先のコミットに入れる。

### Minor-4: 共有のスライダーの CSS の注記に、イロドリで測った経緯が残る

`Slider.module.css` の頭の注記の最後の段落は「Chromium は、スライダーを目印にして読み込み直しの送りの位置を戻すと、数 px ずれた所に戻す（イロドリの 375px で 4〜10px）」と、1つのゲームで測った値を共有の部品に書いている。CLAUDE.md の「ツギハギ禁止」は、試した経緯や測った値をファイルに残さず、サイクルの文書に置くとする。理由（スライダーを目印にすると戻る位置がずれる）だけを残し、数値とゲームの名前はサイクルの文書に移す。あわせて、`textWidth.ts` の正規表現 `/[\u0000-ɏ]/` は、始まりを逃がし書き、終わりを字そのもので書いていて、範囲の終わり（U+024F）が読み取りにくい。`ɏ` にそろえる。

### Minor-5: index.md の T5 の行で、画像のリサイズのボタンの位置の数が2つ並び、片方は何の画像かを言わない

前の Minor-4 を受けて「画像のリサイズの主なボタンの位置は読み込んだ画像で変わる（320×667 の PNG で 1529→1547）」が行の末尾に足されたが、同じ行の前の「画像のリサイズの「リサイズ」のボタンの下端は 320px で 1413→1431・375px で 1275→1293」は、画像を言わないまま残る。T5 の担当は同じ行に 1413 と 1529 の2つの数を読み、どちらを確かめればよいか迷う。前の文に画像を書き添えるか、差（約 18px 下がる）だけの言い方にまとめる。
