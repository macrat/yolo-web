## 指摘

### Major-1 ラジオボタンの円を「縁が見えるもの」に入れると、フォーカスのリングが円や四角に重なる

新しい箇条は、縁に地や線が見えるものに「ラジオボタンの円」を入れ、その縁をコンテンツ幅の左端に揃える。字の左右 8px を押せる範囲に含めるのは「縁が見えないもの」だけなので、ラジオボタンの押せる範囲の左端は円の左端と同じ x になる（§5 の外へ出てよいものに押せる範囲は入っていない）。

§6 はこの押せる範囲について、次のことを決めている。

- 「ラジオボタンとチェックボックスでは、ラベルを含む行全体がタップターゲットになる」
- 「フォーカスリングはタップターゲットと一致する」
- 「二重リングは、押せる範囲の内側に密着して出る」
- 「hover のボーダーは要素の内側に出る」

これを全部守ると、行全体を囲むリングの左辺（外 `--ink` 3px・内 `--paper` 3px）が、円の左端から内側 6px に重なる。チェックボックスでは四角の左辺（太い線 3px）がリングの外側の線とぴったり重なって行の高さいっぱいの1本の縦線に溶け、内側の `--paper` が四角の中の左 3px を塗る。キーボードで選んでいるあいだ、四角は左辺を失ってかぎ括弧のような形になり、円は左の弧が欠ける。§6 の「ラジオボタンは円、チェックボックスは四角。形だけで種類が分かる」が、ちょうど操作しているあいだに崩れる。hover の細い線も同じ位置に重なる。

プライマリボタン・入力欄・一覧の行では、見えている縁が押せる範囲の縁そのものなので、この重なりは起きない（リングは地や枠の内側に入るだけ）。ラジオボタンとチェックボックスだけは、見えている形（円・四角）が押せる範囲（ラベルを含む行）の一部でしかなく、**行の縁は見えていない**。性質で分けるという今回の原則に照らしても、円は「縁が見えないもの」の側に入る。

あわせて、次の2つのずれがある。

- 箇条の括弧にチェックボックスの四角が無い。例示なので類推はできるが、ラジオボタンと同じ扱いかどうかを文面で決めていない。
- サイクルの文書の補足事項は、縁が見えるものを「プライマリボタン・入力欄・一覧の行の区切り」とし、ラジオボタンの円を入れていない。DESIGN.md とサイクルの文書で分け方が違い、円をこちらに入れた理由がどこにも無い。

**直し方**: planner が、ラジオボタン・チェックボックス（とアコーディオン。Minor-4）を「縁が見えないもの」の側に入れ、揃えるのは最初の字か形（円・四角・三角）の左端、押せる範囲はその左右 8px ぶん広い行、とする。そうすればリングと hover の線は円や四角から 8px 離れた位置に出て、形は崩れない。サイクルの文書の分け方も同じにそろえる。

### Major-2 §5 の箇条と幅の表が、文の中のリンクにも 8px の押せる範囲と 44px を与え、§6 と両立しない

§5 の新しい箇条は、縁が見えないものの例に「リンク」を挙げ、「字の左右 8px を押せる範囲に含め、状態を示す線をそこに出す」と言う。幅の表の「コントロール」の行も、字の左右に 8px を足し、44px に届かなければ広げる。どちらも文の中のリンクを除いていない。

§6 は、文の中のリンクについて「押せる範囲が字そのもの」「タップターゲットの 44px の例外」「hover は下線が太くなる」と決めている。1つのリンクに、押せる範囲は字＋8px だという規定と字そのものだという規定が同時に掛かり、両方は満たせない。§5 の規定どおりに組めば、文の途中のリンクの押せる範囲が前後の字に 8px ずつ食い込み、hover の線が隣の字の上に出る。

前の版の §5 には「文の中のリンクは箱を持たず、字の流れの中にある」の一文があったが、短くしたときに消えた。§6 の二重リングの箇条とタップターゲットの箇条だけが文の中のリンクを扱うので、§5 だけを読んだ builder は、左端の規則を文の中のリンクにも掛けることになる。「最初の字をコンテンツ幅の左端に揃える」も、文の途中にあるリンクには意味を持たない。

**直し方**: planner が、§5 の左端の箇条で、規則が掛かるのは文の中のリンクを除くコントロールだと1か所で言う（例:「文の中のリンクは字の流れに置き、押せる範囲は字そのものである（§6）」を箇条の中の1文として組み込むか、箇条の主語を「文の中のリンクを除くコントロール」にする）。幅の表の「コントロール」の行も、同じ定めを指す形にする。足した注記に見えないよう、箇条全体をその形で書き直す。

### Minor-1 サイクルの文書の撮り比べの記述のうち、ナビの部分が実測と合わない

補足事項は「押せる範囲で揃える案では、パンくず・プライマリでないボタン・ナビの字が、同じページの見出しや入力欄の枠より 8px 右に立った」と書く。A の `measurements.json` を集計し直すと次のとおりである。

| 項目（A・年齢計算）  | 320px | 1280px | 比べる相手                   |
| -------------------- | ----- | ------ | ---------------------------- |
| パンくずの字         | 51    | 203    | 見出しの字 43 / 195 → 8px 右 |
| 共有ボタンの字       | 51    | 203    | 見出しの字 43 / 195 → 8px 右 |
| 「今日に設定」の字   | 76    | 228    | 入力欄の枠 68 / 220 → 8px 右 |
| ナビの最初の項目の字 | 35    | 300.2  | 見出しの字 43 → **8px 左**   |

パンくず・ボタンは記述どおりだが、ナビの字は見出しより左にある（320px）。1280px ではナビの最初の項目はサイト名の右に並ぶので、見出しとは比べられない。ナビで言えるのは「コンテンツ幅の左端（27）より 8px 右に立った」ことで、同じページの見出しや入力欄の枠との比較ではない。

あわせて、

- 「パネルの中の『今日に設定』の字が入力欄の枠とプライマリボタンの左端（x=68）にそろった」の x=68 は 320px の値で、1280px では 220 である。幅を添える。
- 補足事項の「縁に地や線が見えるもの」の括弧が DESIGN.md と違う（Major-1）。

**直し方**: planner（または PM）が、ナビの記述を実測どおりに直すか、比較から外す。x=68 に「320px で」を添える。

### Minor-2 見えている縁から中身までの距離と、コントロールどうしの間隔を測る場所が書かれなくなった

前の版にあった「中身はその内側 8px から始まる」と「コントロールを並べる間隔は、箱と箱のあいだで測る」が消えた。

- プライマリボタンは幅の表の「字の左右に 8px」から字の位置が決まるが、**一覧の行**（幅の表では「コンテンツ幅いっぱい」）と**入力欄**（「本文の幅で折り返す」）は、行の区切りや枠から中身がどれだけ内側に立つかがどこにも無い。一覧はこのサイトの探す面の主役で、名前の字が見出しの字と同じ列に立つか 8px 右に立つかが、この一語で変わる。フォーカスのリングは縁の内側に 6px 入るので、中身を 6px より内側に置かないとリングが字に重なる。
- ナビの項目どうし・ボタンどうしの間隔を、押せる範囲のあいだで測るのか、字と字のあいだで測るのかで、見える字の間隔が 16px 変わる。§6 の「並んだコントロールに食い込まない」も、押せる範囲が重ならないことが前提である。

**直し方**: 縁が見えるものは中身を縁の内側 8px から始め、間隔は押せる範囲と押せる範囲のあいだで測る、と箇条の中で言う（前の版の定めを、今の箇条の形で書き直す）。

### Minor-3 「要素」と「押せる範囲」が混在し、文の中のリンクのリングの位置と「一致する」が揺れる

- §5 と §6 の二重リングの箇条は「押せる範囲」、§6 の表の hover / フォーカスの行・読み分けの表・hover のボーダーの箇条は「要素」と言う。縁が見えないリンクでは、字（要素と読める）と押せる範囲が 8px 違うので、hover の線とリングが字に出るのか押せる範囲に出るのかが、箇所によって違って読める。
- 「フォーカスリングはタップターゲットと一致する」と、文の中のリンクの「リングは字の外に出る」が、同じ節で言い方が揃っていない。

**直し方**: 状態の線が出る場所を「押せる範囲」に統一する（表では「押せる範囲に密着した二重リング」など）。文の中のリンクは、押せる範囲（字）の外に密着する、と二重リングの箇条で1回だけ言い、「一致する」の箇条はそれを指す形にする。

### Minor-4 「最初の字」が、形から始まるコントロールを覆わない

アコーディオンは太い線の三角とラベルを持つ。三角がラベルの前にあるとき、「最初の字」を揃えるなら三角はコンテンツ幅の外へはみ出し、三角を揃えるなら規則の文面（字）と合わない。Major-1 でラジオボタン・チェックボックスを縁が見えない側に移すと、円と四角も同じ問題を持つ。「字の左右 8px」も同様。

**直し方**: 「最初の字か形」「字や形の左右 8px」とする。

### Minor-5 44px に届かせるために広げる向きが決まっていない

幅の表は、字の左右に 8px を足しても 44px に届かなければ「届くまで広げる」と言う。ページ送りの数字「1」のように1字のコントロールは、字＋16px で 44px に届かない。左右に均等に広げると、左への張り出しが 8px を超え、`45rem` 未満の画面（コンテナとボックスの内側の余白が 8px）では押せる範囲と状態の線がコンテナやボックスのボーダーをまたぐ。§5 の「状態を示す線をそこ（字の左右 8px）に出す」とも合わない。

**直し方**: 左への張り出しは 8px で固定し、足りない幅は右（と上下）へ広げる、と言う。

### Minor-6 狭い画面で状態の線がボーダーに接することを受け入れた理由が、サイクルの文書に無い

補足事項は「狭い画面では……その線がコンテナのボーダーに接することを受け入れた」と書くが、なぜ来訪者が困らないか（例えば、リングの残りの3辺と内側の `--paper` で読める、無効の枠は残りの3辺の破線と理由の文で読める）が書かれていない。前回の Major-1 の直し方が求めた点である。また、無効のプライマリボタン（反転をやめて破線の枠。枠は地の縁＝コンテンツ幅の左端）と無効のプライマリでないボタン（破線の枠は 8px 左）は、同じ見た目の枠が 8px ずれた位置に立つ。上下に並べば来訪者に見える。

どちらも見た目の程度の問題なので、今回の基準により Major にしない。受け入れた理由をサイクルの文書に一文で書き、T2・T5 の実装のレビューで 320px の撮影を確かめる項目に入れる。

### Minor-7 小さな文面のずれ

- §5「コンテンツ幅の左端は……すべてそこから始まり、右にだけ伸びる」の「すべて」が、2つ上の箇条の「状態を示す線は外へ出る」、2つ下の箇条の「押せる範囲に字の左右 8px を含める」と字面で食い違う。「見えているものはすべてそこから始まり」のように、何が始まるのかを言う。
- §5「コンテンツ幅の外へ出るのは……線だけである」は、縁が見えないものの押せる範囲（見えないが、タップを受ける）が外へ出ることを言っていない。
- 左端の箇条の「コンテンツ幅の左端」は、ボックスの中ではボックスのコンテンツ幅の左端を指すはずだが、それを言っているのは幅の箇条の最後の一文（「同じ割り当てがボックスのコンテンツ幅に対してかかる」）だけである。
- §6「前後に文字が続き」は「前にも後ろにも」とも「前か後ろに」とも読める。段落の頭のリンクや、行末の句点の前のリンクがどちらに入るかが変わる。T2・T5 で撮って決めてよいが、どちらの意味かは文面で決めておく。

## 作業の進め方について

- 前回の指摘に応えて、部品の列挙ではなく性質で分けたのはよい。ただし短くする過程で、前の版が持っていた定め（文の中のリンクの扱い、中身の位置、間隔の測り方）が3つ消えた。書き直したあとは、前の版の定めを1つずつ新しい文面に当てて、消えたものが無いかを確かめる（AP-P24「過去に確立された設計判断の無意識な打ち消し」）。
- ラジオボタンの円を縁が見えるものに入れた判断は、サイクルの文書に理由が無く、撮り比べにもラジオボタンは入っていない。性質で分けたなら、分けたあとに対象の部品を1つずつ §6 の状態の規定（リング・hover・タップターゲット）に通してみると、Major-1 は文面の上で見つかる（AP-P33）。
- 撮り比べの記述は、集計した数値の表を先に作ってから文にすると、Minor-1 のような取り違えを防げる（AP-WF14）。
