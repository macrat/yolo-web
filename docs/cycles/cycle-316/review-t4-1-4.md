## 指摘

Critical 0・Major 0・Minor 4。

### Minor-1 §4 の既定の文字サイズと大きい文字の子項目が、10章とスキルの条件と範囲がずれている

- **大きい文字の受け入れの範囲**: §4 は「文字を大きくした画面の**狭い段（1行に3〜5字しか入らない段）**では…受け入れる」と言う。10章とスキルの条件は「200% では、1字だけの行と禁則の破れは、**1行に収まらない文節の中の折れから出たものに限って**受け入れる」と言う。200% の 375px の結果のボックスで、セクションの見出し（`1.49rem`）は1行に約6字、小見出しは約9字入る。そこで長い文節が折れて1字の行が出ると、スキルの条件では受け入れ、§4 の文では「狭い段」に当たらず、既定の文字サイズの項にも当たらないので、どちらとも決まらない。T4-5・T4-7 のレビューが §4 で判定すると、直せない折れを直させにいく恐れがある。条件の言い方のほうが、どの段でも「文節が1行に入らないから割れた」という来訪者の側の理由と1対1なので、§4 を「文字を大きくした画面では、1行に収まらない文節の中の折れから出た1字だけの行と禁則の破れを受け入れる（1行に3〜5字しか入らない段では、どの組み方でも…）」のようにそろえる。8章の §4 の行も同じにする。
- **丸括弧の中の折れ**: 10章とスキルは、既定の文字サイズで「丸括弧の中の折れ」を0にする。§4 は2つ目の子項目で「一続きが1行に収まらないときだけ、その中で折る」と認め、5つ目の子項目は「1字だけの行と禁則の破れ」を作らないとだけ言い、丸括弧の中の折れそのものを既定で0にするとは言わない。「組み方で避けられないとき（1行に収まらない丸括弧の一続き…）は、見出しの文のほうを直す」から読めなくはないが、5つ目の子項目に「丸括弧の中の折れ」を並べて、条件と同じ3つにする。
- **禁則の字の並び**: §4 と測り方の並びは、`phrase-breaks.ts` の `NO_LINE_START` が持つ繰り返し記号（々・ゝ・ヽ など）とコロン・セミコロンを持たない。「人／々」は行頭禁則の破れだが、測り方では数えない。中点を足したのと同じ理由で、並びに繰り返し記号を足す（コロン類は見出しに出にくいので「など」でもよい）。

### Minor-2 「見出しの文のほうを直す」と、character-personality のタイプ名を変えない PM の決定が、`DESIGN.md` の上で食い違う

PM は「数式を見て「これ詩みたいだ」と感動するデータの詩人」を、来訪者が自分の結果として覚え共有している名前なので変えず、320px の既定での行頭の「」」を受け入れると決めた。理由は来訪者の側から筋が通っている。しかし `DESIGN.md` §4 は、既定の文字サイズの禁則の破れは「見出しの文のほうを直す」と例外なしに言う。この決定は設計（サイクルの文書）にしか残らないので、あとのサイクルで `DESIGN.md` に沿って見出しを点検した人は、このタイプ名を直すべき違反と読み、来訪者が持っている結果の名前を変えにいく恐れがある。PM の決定の理由は一般に言える（来訪者に渡した結果の名前は、見出しの折れのために変えない）ので、特例でなく §4 の規定の一部として、5つ目の子項目の「見出しの文のほうを直す」に、直さないものとその理由を添える。規定に入れないと決めるなら、その判断を設計に書く。

### Minor-3 2行の組みの、名前の行と枠のあいだが決まっていない

§5 の間隔の項は、1行の組みの列と行のあいだ（8px）と、2行の組みの項目のあいだ（16px）を決めるが、2行の組みで名前と値の行とそのすぐ下の枠のあいだは言わない（設計 3-1 の 4 も「すぐ下」とだけ言う）。8 の倍数から 0 と 8 のどちらも選べ、8 にすると名前から自分の枠までが 8px、次の項目の名前までが 16px で差が小さく、取り違えないための 16px の効き目が落ちる。T4-3 の部品と §5 の文が別の値を持たないよう、「名前の行と枠のあいだは 0（または 8px）」を間隔の項に足す。

### Minor-4 設計の8章・2-3 に、中点と「最初の空白より前」がまだ入っていない

- 8章の §4 の行（t4-design.md:689）の禁則の並びに中点が無い。builder が `phrase-breaks.ts` と10章の測り方に合わせて足し、PM が採ったことも、設計のどこにも記録が無い。
- 8章の §4 の行と 2-3（210〜211行・228行）は「最初の文節の中」「最初の文節は行の頭から始まるので」のままで、「最初の空白より前」は末尾の PM の決定に「この条件を含めて読む」とだけある。

サイクルの文書なのでツギハギの禁止には掛からないが、8章は `DESIGN.md` の正本とされ、T4-5・T4-7 の builder とレビューが 2-3 を読む。中点を採った PM の決定を末尾の決定の節に1行足し、8章の §4 の行（Minor-1 の直しも含めて）を `DESIGN.md` の今の文にそろえる。

## よくできている点

- §4 の6つの子項目が、`phrase-breaks.ts` の区切りの一つひとつに対応し、どれも来訪者の側の理由を持つ。とくに「最初の空白より前」は、実装の都合の語に見えて、「行の頭から始まる部分だから、1行に入らないときにしか使われない」という理由と一緒に書かれ、なぜそこだけかが読める。
- 測り方が「折り所・文節の中の語の切れ目・語の中」に分かれ、1字の行を文節でなく行の字で数えるようにしたので、前回の「型思考／者」の取りこぼしが無くなった。knowledge に「なぜ行の字で数えるか」が書かれ、あとの人が同じ誤りをしない。
- 閉じ括弧の直後を、関数でなく改行の規則が折ることを、スキルの「実装の技術」と knowledge の両方に書いたので、実装とレビューが `span` で止めにいかない。
- §5 の量の帯は、組み方の1つひとつに来訪者の側の理由があり、1つの組み方に決まっている。
