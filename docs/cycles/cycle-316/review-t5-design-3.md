## Major

### Major-1. ブログの本文の見出しのダッシュの組み方に持ち主が無い（T5-16）

- **事実**: 見出しの区切りでダッシュを前の語に付ける組み方（`joinDashes`）は、`src/components/PhrasedText/index.tsx:30` の中にあり、export されていない。T5-16 は本文の見出しに区切りを入れるが、`src/lib/markdown.ts` は見出しを HTML の文字列で組む（`:138` の `heading` の拡張）ので、React の部品の `PhrasedText` を使えない。ブログの本文のコードの外の見出しで、ダッシュ（「—」「──」「--」）を含むものは 18記事に 61 ある（例: 測る2記事の1つ `javascript-date-pitfalls-and-fixes` の「問題1: Dateの自動補正 -- 2月31日はエラーにならない」）。`DESIGN.md` §4 は、ダッシュを行の頭に置かず、ダッシュだけの行を作らないとしている。
- 10-1 の「区切りを組む仕組みは T5-3b が1つだけ作る」は、見出しの外の React の部品（リンク・ラベル・`summary`・表のセル）だけを言い、Markdown の見出しに触れていない。T5-16 の builder の取れる道は、(a) `markdown.ts` にダッシュの組み方をもう1つ書く（同じ禁則が2か所に分かれ、次に直すときに揃わない。b2 N1 と同じ形）、(b) `PhrasedText/index.tsx` から切り出す（10-4 で T5-3b だけの持ち物。T5-16 と T5-3b のあいだに順の決まりが無い）の2つで、どちらも設計に反するか、設計に書かれていない。どちらも選ばなければ、61 の見出しで「--」が行の頭に来うる。
- **求めること**: ダッシュを前の語に付ける組み方を、文字列を受けて文字列を返す1つの関数にし、`PhrasedText` と `markdown.ts` の両方がそれを使う形を、どのタスクが作るかを決めて書く（例: T5-3b が関数を切り出し、T5-3b → T5-16 を 10-1 に足す。関数を置くファイルの持ち主を 10-4 に書く）。T5-16 の完了の条件に、ダッシュを含む見出しでダッシュが行の頭に来ず、ダッシュだけの行が無いこと（既定の 320px）を足す。T5-23 の 410 の見出しは手で区切る決まった文でダッシュを含まないので、変えなくてよい。
