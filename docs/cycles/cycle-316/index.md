## 作業計画

### 目的

**来訪者が目にするすべての面を、`DESIGN.md` のとおりにする。**

`DESIGN.md` が決めているのは、`docs/site-concept.md` の約束を来訪者の画面で守るための見た目である。

- **サイトには多様なものが並び、入れ替わり続ける**（約束の「たくさん作って、たくさん試します」）。`DESIGN.md` §1 は、UI が色を持てばその色と喧嘩しないコンテンツしか置けなくなると考え、UI を無彩にして色をコンテンツに渡した。いまの UI は朱のアクセントを持っている。
- **来訪者は選別を経たものを探しに来る**（「ここに残っているのは、その結果です」）。だから一覧は1画面に入る項目数と目で追う速さを優先する（§7）。
- **誰もが使えること。** 入力欄にフォーカスすると画面が勝手に拡大する（B-663）。ブラウザで文字を大きくしても本文が追随しない（B-632）。狭い画面で表が1文字ずつ縦に潰れる（B-641）。これらは、いまの面が来訪者に掛けている実害で、`DESIGN.md` §4・§5・§12 が防ぐと定めている。

### 作業内容

進め方は [options.md](./options.md) の比較で **A（全面を1サイクルで、揃ってから1度だけ出荷）** に決めた。同じファイルを書き換える backlog 26件の振り分け（含める18件・含めない8件）も同じファイルにある。

作る順は、**下の層が決まらないと上の層が作れない順**にする。

1. **土台**（T1a・T1）——Web フォントの判断のあとに、トークン・書体・組版・枠。これが決まると、すべてのページの地と字と罫線が決まる。
2. **部品**（T2〜T4）——コントロール・入力・一覧・結果。面は部品の組み合わせなので、部品を先に `DESIGN.md` どおりにする。
3. **面**（T5）——部品で組み直し、ページ固有の CSS から `DESIGN.md` に無い値を消す。
4. **外と文章**（T6・T7）。
5. **確かめる**（T8・T9）。**出荷**の直前に基線を取り（T10）、出荷して本番で確かめる（T12）。

**作業の分け方**

- サブエージェント1体に渡すのは、**部品1つ、または面1つ**（ツールなら1本、診断なら1本）。数十の面を1体に丸ごと渡さない。
- **同じファイルを触る作業は直列にする。** `globals.css`・layout・共有部品は1体ずつ順に。面の作業は、部品が揃ってから並行させる。
- 部品1つ・面1つごとにレビューを受けてから、完了とする。

**作業中に守ること**

- **トークンの別名で旧値を新値に付け替えて済ませない**（AP-P28）。朱で示していた操作は、§6 の下線・反転・形で示し直す。
- **`DESIGN.md` を実装に合わせて書き換えない。** 変えてよいのは、その規定が来訪者にとって誤りだと示せたときだけで、判断と根拠をこのディレクトリの文書に残してレビューを通してから変える（[options.md](./options.md)「`DESIGN.md` を変えるとき」）。

### 完了の条件

**主な条件は、全ページが `DESIGN.md` の §1〜§12 を満たすことである。** 以下はそれを確かめる手段と、この作業に含めた項目が解消したことを来訪者の側で確かめる項目である。

**「全ページ」の範囲**: `src/app` の80ルートと、404・410。

- **機械の検査は、sitemap の全 URL と、sitemap に載らないページ（404・410・storybook・noindex の結果ページ）、それに操作で現れる状態（診断の設問の画面・回答後の結果・ダイアログなど、面の種類ごと）に掛ける。** 検査は安いので、見本の抽出にしない。
- **目視と操作は、テンプレートごとに実際のページを選んで確かめる。** 選び方は、中身の種類（色が主題・字形が主題・数字が結果・文章が結果・表を含む・コードを含む・図を含む）ごとに少なくとも1枚。そのうえで**境界の値**を必ず含める——ほぼ白・ほぼ黒の色、最も長い名前、最も多い件数、項目0件、**見出し書体に無い字を含む見出し**（漢字辞典の「𠮟」。[facts-design-gap.md](./facts-design-gap.md) §12-2）。

**機械で確かめる**

- `src/` で **UI のトークンとして定義する** CSS 変数は、`DESIGN.md` に名のあるもの（§2 の6色・§5 の `--rule-w`・`--rule-w-hair`・`--max-width`・`--measure`）、`DESIGN.md` が値を定めるもの（§4 の文字の大きさと行間、§5 の間隔とボックスの内側の余白）、§3 の4書体の役割を表す書体の変数だけ。中身の色を渡すための変数（ビルド時にコードの色分けが生成するものや、中身の色をインラインで渡すもの）はトークンではないので、この条件の範囲の外にある（§12「コンテンツの色はトークンを持たない」）
- `border-radius` の宣言はラジオボタンの円だけ。影・グラデーション・半透明ぼかしは、中身の色（§2）を除いて0件
- `frontend-design` スキルの「機械で確かめる」6項目（コントラスト・320px 幅・文字サイズ 200%・色の直書き・タップターゲット・Web フォントでのずれ）を満たす

### 検討した他の選択肢と判断理由

[options.md](./options.md) に6案の比較がある。要点は次のとおり。

- **B（土台と部品を先に出荷）** は、ページ本体の組み方（§5 のページの割り方とコンテナ）を後に回すため、§1 の仕掛けと罫線が作る形がページに出ない。
- **C（面の種類ごとに出荷）** は、1ページで終わるセッションが83.7%なので、面をまたいで混ざる害は小さい。しかし共有の枠と部品が全ページ共通のため、コードに2つのデザインを同居させるか、ページの中で2つのデザインを混ぜるかのどちらかになる。
- **D（統合ブランチで複数サイクル）** と **F（フラグで切り替え）** は、来訪者が見るものが A と同じで、作業中に他の修正を出荷できる。しかし D は旧と新の両方に同じ修正をすることになり、F は main のすべての部品が複数サイクルにわたって2つの見た目を抱える。
- **E（引き上げの判定を先に）** の利点は、引き上げる面にかける手間を省けることだけである。手間は判断の基準にならない。その間、残る面の来訪者に旧デザインを見せ続けることになる。

**A の代償**——このサイクルのあいだ他の修正を出荷できない（PV の78%が集まる面で回答中に選択肢が画面に入らない欠陥 B-614 は、同じファイルを書き換えるので含めた。B-620 は前回の修正が来訪者に正味でマイナスだったため含めず、B-614 のあとで改めて見る）、出荷が全部か無しかになる、PV の78%が集まる面が1度で大きく変わる、Web フォントの転送量——は [options.md](./options.md) に書いた。Web フォントは T1a で判断し（[fonts-decision.md](./fonts-decision.md)。本文の和文は端末のゴシックに改めた）、ほかは完了の条件で確かめる。

## 補足事項

- 完了の条件の「UI のトークンとして定義する CSS 変数」に、`DESIGN.md` が値を定めるもの（§4 の文字の大きさと行間、§5 の間隔とボックスの内側の余白）を加えた。§4 の見出しの5段は画面幅ごとに段が下がり、同じ値を部品ごとに書き写すと、段の下げ方を1か所で直せなくなるためである。条件の目的（`DESIGN.md` に無い値を部品が持ち込まない）は、値を `DESIGN.md` のものに限ることで守られる。
- テーマの切替（B-597）は置かない。§10 は既定のテーマを端末の設定に従うと定め、§5 の上端にも切替の場所が無い。失うのは、サイトの中でその場でテーマを替える手段である。別のテーマで読みたい来訪者は、端末の設定（iOS の Safari では OS 全体の外観の設定）で替えることになる。83.7% のセッションは1ページで終わり、サイトの中で選んだテーマを覚えておく得も小さいので、上端に部品を足してまで持たない。dark は `prefers-color-scheme` で当て、JS を待たずにテーマが決まるようにした。
- 410 のページは `src/middleware.ts` が HTML を直接返すので、React の共通の枠（`SiteFrame`）を使えない。来訪者が外部のリンクや検索から最初に着く面なので、同じ上端・下端・AI 運営の告知・コンテナの罫線を持たせ、告知とナビの文言は `src/lib/site-frame.ts` の1か所から取る。
- 410 のページは Web フォントを読み込まないので、見出しをアンティーク体でなく、ほかのページが Web フォントを読み込む前と同じ並び（仮名を全角で組む本文の書体）で組む。410 は1枚だけの案内の面で、見出しのために Zen Antique の分割ファイルを読ませる得が小さい。
- 上端のナビは、遊び・ツール・辞典・ブログの4つにした。辞典は検索の表示回数の76〜79%を占める面で、検索から辞典の詳細に着いた来訪者が、上端から辞典の一覧へ移れるようにする。サイト紹介は直近28日の PV が 3,347 のうち 10 で、上端に置くと 320px の上端が3行（151px）になり、PV の78%が集まる診断の「はじめる」を最初の画面の下へ押すので、下端にだけ置いた。下端のリンクは、サイトについての案内（サイト紹介・プライバシー）にした。
- コントロールの左端は、いつも見えているものの左端で揃えることにした（`DESIGN.md` §5）。縁に地や線が見えるもの（プライマリボタン・入力欄・一覧の行の区切り）は縁を、見えないもの（ナビ・パンくず・ページ送り・プライマリでないボタン・ラジオボタンやチェックボックスの行・アコーディオン）は最初の字か形を揃え、字の左右 8px を押せる範囲に含めて状態を示す線をそこに出す。「すべて押せる範囲で揃える」案と2つを組んで 320px と 1280px で撮り比べた（各ページの中身は、まだ T5 で組み直す前の自前の余白を持つ状態）。押せる範囲で揃える案では、パンくずとプライマリでないボタンの字が、同じページの見出しや入力欄の枠より 8px 右に立ち、上端のナビとサイト名の字もコンテンツ幅の左端より 8px 右に立った。いつも見えているもので揃える案では、パンくずの字と見出しの字が同じ x（320px で 43、1280px で 195）に立ち、パネルの中の「今日に設定」の字が入力欄の枠とプライマリボタンの左端（320px で x=68、1280px で x=220）にそろった。サイト名と見出しは、どちらの案でも揃っていない（ページの中身の自前の余白のためで、T5 で揃う）。部品を列挙して分ける書き方は分類に入らない部品が出るたびに例外が要ったので、縁が見えるかどうかという性質で分けた。状態を示す線はコンテンツ幅の外へ出てよいとし、狭い画面（コンテナの内側の余白が 8px）ではフォーカスや hover のあいだ、また無効のあいだ、その線がコンテナのボーダーに接することを受け入れた。線が出るのは状態のあいだだけで、接しないようにコンテナの内側の余白を広げると、狭い画面で本文の幅がいつも減るからである。無効のプライマリボタンの枠と、無効のプライマリでないボタンの破線は、この規則で 8px ずれた位置に立つ。T2・T5 の実装のレビューで、これらを撮って確かめる。本文の中のリンクは押せる範囲が字そのものなので、hover は下線を太くし（字に接する細い線を足すと下線と読み違えるため）、リングは字の外に出す。箇条書きや表の中のリンクのように、ここに書いた形でどう組むかが画面を見ないと決まらないものは、T2・T5 の実装のレビューで撮って決める。
- 本文の中のリンクは、段落だけでなく箇条書きと表の中のリンクも含めることにした（`DESIGN.md` §6）。どれも本文の字の行に収まり、行の高さ（17px × 1.85 ≒ 31px）で WCAG 2.5.8 の 24px を満たす。箇条書きや表の中だけ別の押せる範囲を持たせると、本文の中でリンクの見え方が2通りになる。縁の見えないコントロールどうしは押せる範囲を接して並べてよいとした。8px あけると、375px で上端のナビが2行に割れるからである。
- トグルスイッチは `DESIGN.md` に相当が無いので、部品ごと消してチェックボックスに置き換えた（5つの道具）。アコーディオンは、三角の向きと読み上げの開閉の状態で示し、開閉を言う文言は足さない。FAQ や目次に「開く」「閉じる」の字を並べると、読みたい中身の前に操作の字が増えるからである。選ぶ欄の下向きの印・候補の選択済みの印・読み取り専用の欄は、ブラウザの既定と平常時の欄の見え方のままにした。
- セグメント切替は `DESIGN.md` に相当が無く、中身は1つを選ぶ操作なので、見出しを持つラジオボタンの組（RadioGroup）に置き換えた。値札は §7 の「種別を一語」にあたる補助情報なので、枠と地を持たない `--ink-2` の文字にした。開いた選ぶ欄の候補には hover の線を出す（押すと選ばれる、進むものと同じ性質のため。§6）。
- 反転の地と太い枠を持つ押せるものは、共通の属性（`data-inverted`・`data-thick-frame`）で組み、開閉の三角は `details` の外でも使える共通の部品（DisclosureTriangle）にした。ページごとに同じ補いを書くと、見え方が面ごとにずれるからである。反転の地の上の hover の線は `--paper` で縁から内側に引き、太い枠を持つものではリングを枠の内側に出す（`DESIGN.md` §6）。
- T2 では、なかまわけの語のマスを、ボックスの中を太い線で区切った盤のマスとして組み、選んだ語は 20px の四角の塗りで示した（チェックボックスと同じ形で、選ぶ・外すが形で分かる）。kanji-kanaru・yoji-kimeru の難易度は、1つを選ぶ操作なので RadioGroup にした。笑辞典の「おもしろかった」は、押す前は下線のボタン、押したあとはボタンを消して送ったことを文で知らせる形にした（押したあとも切り替えのボタンに見えると、取り消せると読み違えるため）。
- T3 の設計と §7 は、単独のレビューを4巡受け、3巡目の指摘（Major 2）を文の書き換えで直した。指摘は §7 の条件の言い回しに移り、設計の構造は変わらなくなったので、以後の確かめは T3 の各タスクの実装のレビューで合わせて行う（規則の文面だけのレビューを重ねると、実装の前に細部の往復が続くため。incident-2 の教訓）。
- ADR: `docs/ADR/open/` は ADR009（次回確認日 2026-10-23）のみで、期限は来ていない。ただし ADR009 は「最初の出荷（B-754）の直前に基線を取る」ことを求めているので、このサイクルの出荷作業に含めた（T10）。
- Backlog の更新: B-754 を Queued → Active へ。B-754 の作業に含める18件のうち、B-573 を除く17件も Active へ（B-663・B-632 を含む。一覧は [options.md](./options.md)「この作業に含める」）。B-573 は B-754 へ統合して中止し、Done/Cancel へ。B-568 は Deferred → Queued へ（着手条件が「ADR009 が基線を取る前」という期限の形だったが、ADR009 の主計器は content_id に依存しないため期限を外した）。B-740 は条件（cycle-314 の事故分析のレビュー）が未達のため Deferred のまま。計画のレビューを受けて、B-629 を題を改めて Deferred へ（着手: 出荷＋7日）、B-620 を Queued から Deferred へ（着手: 出荷後、T9 の二度打ちの記録と B-613 の出荷を材料に判断）、B-613 を Queued から Deferred へ（着手: 出荷後、刷新後のコードに設計を突き合わせ直してから）移した。B-758（2026-09 の計測で、全5ページの実験室の LCP が 2.5 秒を超えている）を Deferred に起票した（着手: 出荷後、新しいデザインで測り直してから）。
