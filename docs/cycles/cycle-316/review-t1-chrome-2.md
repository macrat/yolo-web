## 指摘

### Major-1: セクションのあいだの全幅の罫線を引く仕組みが無く、どのタスクが作るかも決まっていない

§5「コンテナ」は、全幅の罫線を置く場所を「上端の下・下端の上・セクションとセクションのあいだ」の3つとする。§5「ページの割り方」は、セクションの切れ目に全幅の罫線があるので「§1 の仕掛けも、罫線が作る形も、どのページにも現れる」とする。今回の変更で出たのは、上端の下と下端の上の2つだけである。`src/` に、セクションのあいだに全幅の罫線を引く部品もクラスも無い。

T1 は「線とコンテナと全幅の罫線（§5）」を持つ（index.md の T1）。T2〜T5 の説明には、セクションや全幅の罫線の語が無い。このままでは、T3（一覧）や T5（各面）の builder が、それぞれに作ることになる。

しかも、罫線の引き方は今回の枠の組み方で決まる。`SiteFrame` は中間の `main` そのものをコンテナにした（幅 `--container-width`・左右のボーダー・内側の余白）。そのため、`main` の中のセクションの境目で `border-top` を引いても、罫線はコンテンツ幅（1280px で 179〜1101）までしか届かない。画面の端まで届かせるには、`main` の外へはみ出す組み方（`margin-inline: calc(50% - 50vw)` や、疑似要素に `100vw` の幅を持たせる、など）が要る。`100vw` は、Windows のように幅を取るスクロールバーがある環境ではその分を含む。今は `html, body { overflow-x: clip }` が切っているので横には流れないが、各面が別々に組めば、左右の張り出しの長さや交点の見え方がページごとにずれうる。§12「位置の一定」にも当たる。

別の組み方として、`main` はコンテナにせず、セクションごとに「全幅の帯＋その中のコンテナ」を積む形もある。上端・下端はすでにこの形である。どちらを採るかで、T3・T5 のすべての面の書き方が変わる。

直し方: T1 のうちに、セクションとその切れ目の全幅の罫線を引く共通の部品（またはクラス）を作る。`main` をコンテナのままにするか、帯を積む形に変えるかは builder が比べて選び、理由をサイクルの文書に残す。320・992・1280px と文字サイズ 200% で、セクションの切れ目の罫線が画面の左端から右端まで届き、コンテナの左右のボーダーと交点で切れないことを測る。幅を取るスクロールバーがある状態（Chromium の `--hide-scrollbars` を外す、または `::-webkit-scrollbar` で幅を与える）でも、横に流れず右の端まで届くことを確かめる。T1 で作らないなら、どのタスクで作るかを index.md に書く（計画の変更なので planner）。

### Minor-1: スキップのリンクの見え方が §5・§6 と違い、410 とも食い違う

`src/components/SkipLink/SkipLink.module.css` のスキップのリンクは、次の点で `DESIGN.md` と違う。

- **下線が無い**（`text-decoration: none`）。スキップのリンクは本文へ進むリンクなので、§6 の「下線か反転を必ず持つ」に当たる。
- **1px の `--ink` の枠を持つ**（`border: 1px solid var(--rule-strong)`）。§5 の線は、太い線（3px・`--rule`）と細い線（1px・`--rule-2`）の2種類だけである。1px で `--ink` の線は、そのどちらでもない。§6 は細い線で囲まれたものを「どれでもなければ hover」と読ませる。そのため、フォーカスが入る前から hover の見え方になる。`--rule-strong` は globals.css が「§2 に無い UI の色の名前」とする別名である。
- **フォーカスの輪が 2px の単色**。globals.css の `:focus-visible { outline: 2px solid var(--ink); outline-offset: 2px }` に従うため、§6 の二重リング（内外とも 3px）にならない。1px の枠と 2px の輪が重なり、太さの違う二重の線に見える（`k-cp-skip`）。
- 410 のスキップのリンクは `a:focus-visible` の 3px の輪を持つので、同じ部品の見え方がページで違う。

コメントも古い。「紙地・墨字・のれん罫・角丸 0」の「のれん罫」は、捨てた店の見立ての語である。「focus リングは globals.css の :focus-visible が担う」は事実だが、その輪は §6 のとおりでない。

直し方: スキップのリンクを §6 のリンクとして組む。下線を持たせ、枠は外すか太い線にし、フォーカスは上端のリンクと同じ二重リングにする。410 の `.skip` も同じにする。コメントから店の見立ての語を外す。

### Minor-2: スキップのリンクで本文へ飛ぶと、`main` の外側に 2px の輪が出て、コンテナの左右のボーダーが二重に見える

スキップのリンクを押すと、`main`（`tabIndex={-1}`）に `:focus-visible` が当たる。globals.css の 2px の輪が `main` の外、2px 離れたところに出る。コンテナの左右のボーダー（3px）のすぐ外にもう1本の線が並び、ページの長さいっぱいに枠が二重になる（`k-cp-afterskip`。320px では x=12〜14 と 16〜19 に2本の線）。§5 の「線は2種類だけ」と、§1 の罫線の形が崩れる。410 では、Chromium の既定の輪（`1px auto`）が出る。

`main` は操作するものではなく、スキップのあとに見せたいのは本文の位置である。飛び先の見え方は、枠の側で決める。

直し方: `main` のフォーカスの輪を消す（`main:focus { outline: none }` など。フォーカスは移るので、次の Tab は本文の最初のリンクに入る）。輪を出すなら、コンテナのボーダーと重ならない位置と形を決める。React の枠と 410 で同じにする。

### Minor-3: 410 のページが、幅 320px・文字サイズ 200% で横に流れる

ブラウザの既定の文字サイズを 32px にして 320px で開くと、410 の `scrollWidth` が 436px になる。h1「このコンテンツは終了しました」がはみ出している。原因は、410 の `main` が `display: flex; flex-direction: column; align-items: flex-start` で、h1 の幅が min-content（`word-break: auto-phrase` の文節の幅）で決まることである。`overflow-wrap: break-word` は min-content を縮めないので、文節「このコンテンツは」が1行に収まらないまま、h1 の幅がコンテンツ幅を超える。§12「文字サイズ 200% で、どの画面幅でもページが横に伸びない」に反する。410 の枠と中間の CSS は、2d48bdb が書いたものである。

直し方: h1 の幅をコンテンツ幅に収める（`align-items` を外す、h1 に `max-width: 100%` と `overflow-wrap: anywhere` を与える、など）。320px・200% で `scrollWidth` が 320 になることを確かめる。

### Minor-5: 短い語の項目のあとだけ、ナビの間隔が広く見える。トップではナビが 3px ずれる

前回の Minor-1 の直しで、字を箱の左に寄せ、44px に届かない分を右に足した。そのため、「遊び」「辞典」（字の幅 34px）のあとだけ、次の項目までの見かけの間隔が 10px 広い。1280px では「遊び」と「ツール」のあいだが 26px、ほかは 16px。320px では 18px と 8px になる（`v-top-320-light-top`・`v-top-1280-light-bot`）。3〜4項目の並びで1か所だけ間隔が違い、並びが崩れて見える。
