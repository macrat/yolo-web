### 1. 規則と仕組みの使い方がサイクルの文書にしか無く、次のサイクルから名前を書く者に届かない【planner】

「名前と面の区切りの規則」（2文節以上の名前は区切りの並びで書く、データの文はサーバーで `splitIntoPhrases` で分ける、`npm run check:phrased-names` で数える、値で渡す所を名前が出る状態で 200% で測る、`.ts` の並びを `followsPhraseRules` で試す）は、t5-design.md・t6-design.md・index.md にしか無い。cycle-316 のあとに道具・ゲーム・診断を足すサイクルは、これらを読まない。T5-26 のあとも残る網は `phrased-names.test.ts` だけで、これが止めるのは字で渡すものだけである。データや `.map` から名前を渡す新しい選択肢・ボタンの面は、誰も 200% で測らずに出荷される。

いま名前を書く者が読む `frontend-design` スキル（`.claude/skills/frontend-design/SKILL.md`）の「実装の技術」は、「見出しとコントロールの名前の折り所は、サーバーで HTML に入れる。データから作るものも含め……1. 文を BudouX で文節に分け」と書き、4-g が決めた「コードに書いた決まった文は書き手が区切りの並びを書く」も、`Button` の `phrases`・名前の props の並びも、数え方の関数と走らせ方も書いていない。10-4 は SKILL.md の受け持ちを終わった T5-1 だけにしている。

直し方: T5-3b の行に、`frontend-design` スキルの「実装の技術」へ次を書くことを足す。コードに書いた2文節以上の名前と面は書き手が区切りの並びで渡すこと（`Button` の `phrases`、名前の props の並び、`CopyButton` の `targetPhrases`）、データから来る文はサーバーで分けて渡すこと、`npm run check:phrased-names` で字で渡すものを0にし、出た値で渡す所を名前が出る状態で 320px の既定と 200% で測ること、`.ts` に書いた並びを `followsPhraseRules` の試験で確かめること。いまの「1. 文を BudouX で文節に分け」の項も、書き手が並びを書くときにも同じ折り所の決め方（1〜5）に従う、と読める形に直す。完了の条件にスキルの足しを入れ、10-4 の SKILL.md の行に T5-3b を足す（T6 のタスクがスキルを触るなら並行させない順も書く）。
