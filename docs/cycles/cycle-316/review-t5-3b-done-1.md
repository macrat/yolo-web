## 指摘

### 1. （中）見出しからコピーした語に、見えない語結合子が入る（決定 (6) で新しく起きる）

`joinDashes` がハイフンの後ろに U+2060 を置くようになったので、ハイフンで結んだ語をコピーすると、見えない字が入ったまま貼られる。HEAD のビルドで記事 `nextjs-global-not-found-for-multiple-root-layouts` の h1 を選んで Ctrl+C すると、クリップボードは `not-⁠found.tsx`・`global-⁠not-⁠found.js`（どちらもハイフンの後ろに U+2060）だった（Chromium。`window.find("not-found.tsx")` は当たるので、ページ内の検索には効かない）。

ハイフンで結んだ語は、このサイトではほとんどが記事の題のファイル名・パッケージ名・属性名（`not-found.tsx`・`global-not-found.js`・`marked-alert`・`grid-column`・`aria-live`・`JSON-LD`）である。題からこの語をコピーして端末・エディタ・`npm install` に貼った来訪者は、見えない字のせいでファイルやパッケージが見つからず、原因も見えない。ダッシュ（「-⁠-」）にも前から同じことがあったが、ダッシュをコピーして使う人はほとんどいない。識別子に入るのは決定 (6) からで、T5-16 で記事の本文の h2・h3 にも同じ関数を当てると、当たる語がもっと増える。

`src/lib/phrase-dashes.ts` の説明は「語結合子は見えず、ページ内の検索も元の文で当たる」とだけ書いていて、コピーで残ることに触れていない。

直し方の案（PM が決める）:

- (a) コピーした文から U+2060 を除く。サイトの全体に `copy` の出来事の小さな受け手を1つ置き、選んだ所に U+2060 があるときだけ、`text/plain`（と `text/html`）を U+2060 を除いたものに書き換える。語結合子を置くのは `PhrasedText` の1か所なので、除くのも1か所で済む。ダッシュの分も一緒に直る。
- (b) 受け入れるなら、そう判断したことと理由を index.md に書き、`phrase-dashes.ts` の説明と `docs/knowledge/` に「コピーした文には語結合子が残る」ことを書く（T5-16 が同じ関数を本文の見出しに当てるときに知っておくため）。

来訪者にとってよいのは (a) だと思う。どちらにするかを決め、(a) なら builder に組ませて撮って確かめる。

**PART 3 のコード**:

- `joinDashes` の正規表現 `(?<=[^\s-]-)(?=[^\s\d-])` は、語の中の1つの「-」の後ろにだけ語結合子を置き、数字の前（UAX #14 の LB25 でブラウザがもともと折らない。「UTF-8」「SHA-256」）・空白の隣・「--」には置かない。試験は `not-found.tsx`・`marked-alert`・`JSON-LD`・`global-not-found.js` と、置かない形（`UTF-8`・`a - b`・`-x`）と、語結合子を除けば元の文に戻ることを確かめている。ビルドした HTML のハイフンの語結合子は、記事の題5本の語と、`Wi-Fi`・`URL-safe`・`(a-z)`・`(A-Z)` だけで、どれも1行に収まる所で割れないほうがよい語である。
- 語結合子が入るのは `PhrasedText` が組む字だけで、本文・共有の文（`ShareButtons` の `text`・`title`）・`alt`・メタデータの題には入らない（`joinDashes` を使うのは `PhrasedText` の1か所）。見出しの外で困るのは、指摘 1 のコピーだけだった。

**決定 (6) の受け入れ**: 妥当と考える。CSS だけでは「入るときは折らず、入らないときはハイフンで折る」の優先を組めない。それができる、ハイフンで結んだ語を `inline-block` の要素で包む組み方は、見出しの中に字を分ける要素を置かない決まり（VoiceOver が見出しを切って読む）に反する。どちらの組み方でも1行に入らない語は割れるので、多くの来訪者が見る広い画面で、入る語が割れないほうを選ぶのは §4 の「語の中で折れるのは、語が1行に入らないときだけ」に合う。字の所で割れるのが既定の字で起きるのは、題が長い語を持つ記事1本（global-not-found）の 320・375px だけである。
