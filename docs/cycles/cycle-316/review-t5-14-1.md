## 指摘事項

### 1. §4 の外の大きさと行間が残っている（T5-14 で直す。builder が PM に回した (b)）

`page.module.css` に次の値が残る。

| クラス      | いま                                     | §4                                                                                                       |
| ----------- | ---------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `.lead`     | `font-size: 1.25rem`・`line-height: 1.7` | 本文は `1.0625rem`・行間 `1.85`。見出しの段は 1.0625 / 1.49 / 2.08 / 2.92 / 4.08 で、1.25 はどこにも無い |
| `.heroLink` | `font-size: 1.125rem`                    | 同じく段に無い                                                                                           |
| `.aiNotice` | `line-height: 1.7`                       | 本文の行間は `1.85`                                                                                      |
| `.seeAll`   | `line-height: 1.7`                       | 同上                                                                                                     |

**T5-14 の受け持ちと判断する。** 理由は3つ。

- t5-design 2-a は h1 の 48px を「§4 の段の外の大きさを1つ持ち込む（トップだけの例外）」として捨てた。一言の 1.25rem と入口の 1.125rem は同じ理由で捨てられるもので、h1 だけ直して残すのは 2-a の判断と食い違う（AP-I08）。
- 入口「やってみる →」はプライマリボタンと同じ反転の形だが、`Button` のプライマリも結果のページの `tryButton`（`ResultPageShell.module.css`）も本文の大きさ（`--text-body`）で組んでいる。トップだけ 18px なのは §12 の位置の一定（同じ働きのものは同じ形）に反する。
- T7 の受け持ちは文言（「トップの説明と見出し」）で、字の大きさと行間は受け持たない。このファイルを触るのは T5-14 なので、ここで直さないとどのタスクも直さない。

直し方: `.lead` の `font-size` と `line-height` を外して本文の既定に従わせる（`color: var(--ink)` は §2 の本文の色なので、これも不要なら外す）。`.aiNotice`・`.seeAll` の `line-height` を外す。`.heroLink` の `font-size` を外す。

自分で当てて測ると、一言は 1280 で1行（「読むだけのサイトではなく、やってみるサイト。AIが営む、よろず屋です。」）に収まり、入口が 1280 で 706 → 675 に上がる。375 では一言が 102 → 94px になるが、注記の行間が 1.85 になるぶん 87 → 94px に伸びて、入口は 692 のまま変わらない（次の指摘へ）。

### 2. 375×667 の入口は、レイアウトで最初の画面に入る（T7 に回さず T5-14 で解く）

t5-design 2-b は「375×667 の入口は入らず、上にあるのは名乗りの一言と AI 運営の注記で、どちらも T7 が文言を見直す範囲」として T7 に渡すと決めた。しかし、この前提は注記の**組み方**を見ていない。

AI 運営の注記は、色が `--ink-2`（§2 で「前に出ない文字——補助情報」の色）なのに、大きさは本文のまま（17px・3行・87px）で、§4 のどちらの組み方でもない。§4 の補助情報の大きさ（`--text-small`、行間は本文の 1.85）にすると、自分で当てて測った入口の下端は次のとおり（指摘1の直しも当てたうえで）。

| 画面     | いま | 指摘1だけ | 指摘1 ＋ 注記を補助情報の大きさ |
| -------- | ---- | --------- | ------------------------------- |
| 375×667  | 692  | 692       | **650**（入る）                 |
| 390×844  | 692  | 692       | 650                             |
| 1280×800 | 706  | 675       | 638                             |
| 320×667  | 736  | 736       | 719                             |

375 では注記が3行 → 2行（「運営しているのは人ではなくAIです。実験なの／で、内容に誤りがあるかもしれません。」）、1280 では2行 → 1行になり、いまの 1280 で「せん。」だけが2行目に残る形も消える。撮った画面（375×667）では、名乗り・目玉の名前・一言・入口が1画面に収まり、注記も読める大きさのまま名乗りの下に残る。

constitution の rule 3（AI 運営の告知）は、注記がトップの最初の画面に残り、下端の告知もどのページにもあるので、14px にしても満たす。§9 の「AI 運営を正直に、簡潔に示す」とも食い違わない。

**判断: T7 に渡さず、T5-14 で注記を補助情報の大きさにして 375×667 の入口を入れる。** B-621（主操作がモバイルの最初の画面に入る）は index.md の T5 の行が受け持つもので、レイアウトで解けるものを文言のタスクに回すと、T7 が文言を削る理由を「入口を入れるため」に持つことになり、文言の見直しがレイアウトの都合に縛られる。t5-design 2-b と 11章の「375 は T7 に渡す」の記録は、PM がサイクルの記録（index.md か t5-design.md の決定の追記）で改めてほしい。注記を本文の大きさのまま残すと PM が判断するなら、そのときは T7 に 692（本文の大きさ・行間 1.85 の注記では 692）を渡すことになるが、推奨はしない。

直したあと、320 / 375 / 1280 と 200% で撮り直し、375×667 の入口の下端・注記の行数・入口の大きさ（17px）を報告に入れること。

## builder が PM に回した3つの判断

- **(a) 「すべての診断・占い・ゲームを見る」が 375・200% で「占／い」と折れる**: T5-14 では**受け入れる**。§4 が見出しの規則で折るとしているのは見出しと「コントロールの名前」（ボタンの面の字と、入力欄・ラジオボタン・チェックボックス・スライダー・アコーディオンのラベル）で、リンクは含まれず、通常の禁則処理で折る側にある（t5-design 4-g もリンクを拾う対象に入れていない）。ページの中でこのリンクだけに見出しの規則を当てると、§4 に無い例外をトップに持ち込むことになる。ただし、字の箱を持って単独で置くリンクも名前で選ぶ手がかりで、「占／い」は §4 がコントロールの名前について言う害（語の途中で割れた名前は別の語に読める）と同じ害を来訪者に与える。§4 の「コントロールの名前」に単独で置くリンクを入れるかは DESIGN.md の変更なので、**PM が backlog に起票するかを決めてほしい**（T5-14 の完了の条件にはしない）。
- **(b) 一言 1.25rem・入口 1.125rem**: **T5-14 で直す**（指摘1）。
- **(c) 320・200% で一言が文節の中で折れる**: **受け入れる**。一言は本文で、§4 の「本文と一覧の文は通常の禁則処理で折る」に入る。指摘1で一言を本文の大きさにすると、200% の字が 40px → 34px になり、行に入る字が増えて「く、」だけの行のような形も減る見込み。
