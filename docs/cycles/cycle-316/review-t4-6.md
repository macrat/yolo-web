## 指摘

### 1. 【重大】結果のページの相性の文が、読む人を取り違える

`CompatibilitySection` の文を「あなたは「A」、友達は「B」。」にしたが、この部品は結果のページ（`/play/{slug}/result/A?with=B`。`CompatibilityDisplay`）にも出る。このページは、診断を解いた人（A）が「この相性を共有」で送ったリンクで、開くのは受け取った友達（B）かほかの人である。その来訪者に「あなたは「A」、友達は「B」」と言うと、読む人の立場が逆になる（B が開くと「あなた」が自分でないタイプを指し、「友達」が自分のタイプを指す）。変更前の「A × B」は、どちらの面でも立場を言わなかった。

- どう直すか: 置く面によらず正しい文にする（例「「A」と「B」の相性」のように、2人のタイプを立場を言わずに並べる）か、面ごとに文を変える（解き終えた画面は「あなたは…、友達は…」、結果のページは「「A」さんと「B」さんの相性」のような第三者の言い方）。どちらにするかは builder が両方の面を撮って、読む人の立場で決めて報告する。見出しの上の「友達との相性」も、結果のページで受け取った人から見て通じるかを同じく確かめる。
- テスト（`CompatibilitySection.test.tsx`）も、面ごとに正しい文を確かめる形にする。

### 2. 【中】`placement` を省いてよい props にしたので、結果のページで見出しの段が誤る

`CompatibilitySection` の `placement` は既定が `"solvedScreen"` で、結果のページの呼び出し（`CompatibilityDisplay`）は渡していない。5ea8a67 の本番のビルドでは、結果のページの相性の見出しが h1 の下の読みもの（h2）に続く h3 になっている（builder の `report.json` の `*/result/*` でも H3）。T4-7 の続きで `CompatibilityDisplay` に `placement="resultPage"` を足しているが、既定の値があると、次に置く面を足した人が渡し忘れても型が通り、同じ誤りがまた起きる（`docs/anti-patterns/implementation.md` AP-I02）。

- どう直すか: `placement` を必ず渡す props にし、呼び出し側（`ResultCard`・`CharacterPersonalityContent`・`MusicPersonalityContent`・`CharacterFortuneResultExtra`・`JapaneseCultureResultExtra`・`CompatibilityDisplay`）がどれも面を言う形にする。`CompatibilityDisplay` は T4-7 の受け持ちなので、T4-7 の続きと順序をそろえる（PM が調整）。

### 3. 【中】狭い画面で文字を大きくすると、レーダーが形として読めない

字を縮めずに半径を変える組み方と、幅や字の大きさが変わったときの測り直しは良い形で、どの幅でも字ははみ出さない。ただ、320px の 200%（`tmp/cycle-316/t4-6/after/science-thinking-profile-320-32.png`）では多角形の直径が約 55〜80px になり、半径 4.5px の頂点の点5つと `3px` の線がくっついて黒い塊になる。どの軸が大きいかを形で読めず、図が場所だけ取る。

- どう直すか（どれにするかは builder が撮り比べて決める）:
  - 頂点の点の大きさを半径に合わせて小さくする。点を持たない形（頂点は多角形の角で分かる）も比べる。点は `DESIGN.md` §5 の「丸い形を持つのはラジオボタンだけ」とも照らす。点をやめるなら設計 3-3 の「頂点の点も `--ink`」を直すことになるので、planner に設計の直しを頼む（PM が判断）。
  - 半径が小さくなるとき、図の字を1行（「理論 24%」）にするか、数値はすぐ下のスコアの帯が同じ値を字で言っているので図からは外すなど、多角形に幅を回す。これも 3-3 の「数値を紙の上の字で添える（いまと同じ）」に触れるので、同じく設計の直しが要る。
  - `stroke-linejoin: round` は角を丸めるので、§5 の角丸 0px に合わせて `miter` にするか理由を持つ。
- 確かめ方: 320px・375px の既定と 200%、1280px、ダークで撮り、どの軸が大きいかが図で見分けられること。

### 4. 【中】小見出しの文節の区切りが、2つのやり方に分かれ、仕組みの誤りが残る

読みものの小見出しは、区切りを手で書いた並び（`phrases={["今日", "試してほしい", "こと"]}` など）で渡している。サーバーの `splitIntoPhrases` に通すと「今／日試してほしい」「成り／立ち」「ある／ある」「座右の／銘と／して」になるので、手で直したのは来訪者にとって正しい。ただ次の2点が残る。

- `PhrasedText` と `ResultBox` の props の説明は「サーバーで splitIntoPhrases が作ったものを渡す」と言い、手で書いた並びはこの約束の外にある。コードに書いた固定の見出しを手で区切るのを正しい形とするなら、その約束（固定の文は書き手が文節で分けた並びで書く、データから来る文は `splitIntoPhrases` で分ける）を `PhrasedText` の説明に書き、手で書いた並びが `splitIntoPhrases` と同じ禁則（行頭に置けない字で始まる文節が無い・最後の文節が1字でない）を満たすことをテストで確かめる。こうすれば、規則は §4 の1つで、実装のやり方の使い分けが1か所に書かれた形になる。
- `splitIntoPhrases` の誤りは、データから来る見出しにそのまま出る。例えば `/play/[slug]/result/[resultId]` の既定の見出し「このタイプのあるある」は「ある／ある」で割れる。T4-6 の範囲の外だが、仕組みの直し（誤りの例と、どう直すか）を PM に渡すこと。

### 5. 【小】相性の名前の見出しが、文節で折られていない

`CompatibilitySection` の相性の名前（`compatibility.label`。最長で19字ほど）は見出しにしたが、`PhrasedText` を使わず、区切りを持たない。375px（`1.0625rem`、幅 299px）では2行に折れる名前があり、語の途中で割れうる（§4「見出しは文節で折る」）。区切りをどこで作るか（結果のページはサーバーで作れる。解き終えた画面は、character-personality は API の応答、ほかはクライアントのデータ）を決め、T4-6 で直すか、T4 のどのタスクで扱うかを PM が決める。

### 6. 【小】T4-6 が落としたテストを報告していない

5ea8a67 で `ResultCard.test.tsx` の「AnimalPersonalityContent の wrapper クラスが存在すること」が落ちる（`AnimalPersonalityContent` の `.wrapper` を消したため）。builder の `tmp/cycle-316/t4-6/test.log` にも3件の失敗があるが、報告は T4-7 の `CompatibilityDisplay` の2件だけだった。いまの作業ツリーの `ResultCard.test.tsx` ではこのテストが消えているが、それは T4-6 のコミットの外の変更である。T4-6 が落としたテストは T4-6 のコミットで直すか、どのタスクが直すかを報告に書く。

また builder の型検査の記録（`tc.log`）は release=d05dbe0 の worktree のもので、T4-6 の親（b2cac30）の上ではない。確かめは、コミットする木そのもので行う。

### 7. 【小】逆張り運勢診断の笑いの指標が、「一緒にいると」の区画に入って見える

笑いの指標の表（「ネタ化までの速度」など、タイプそのものについての数）は、小見出し「このタイプの人と一緒にいると」の段落のすぐ下に、見出しを持たずに置かれている。カードの区画が消えたので、読む人にはその小見出しの中身に見える。表に自分の小見出しを付けるか（例「このタイプの数字」。文言は builder が決める）、人物像の下に移すなど、表がどの話かが分かる置き方にする。

### 8. 【小】`RadarChart.test.tsx` の「多角形の面を塗らず」の確かめが、何も確かめていない

面の塗りは CSS（`fill: none`）で決まり、`fill` 属性は変更の前も後も持たないので、`getAttribute("fill")` が `null` であることは塗りの有無を言わない。jsdom では幅が 0 で半径も 0 なので、図の形も確かめていない。塗らないことは本番のビルドの測り（builder の `report-st.json` の `polygonFills`）で確かめているので、テストからは外すか、クラスが `fill: none` の規則を持つことなど意味のある形にする。
