## 指摘

### 1. 凡例が何の凡例かを、目でも読み上げでも言っていない（中）

- 凡例の `ul` は名前を持たず、読み上げでは「リスト 3項目 ◯ 一致…」とだけ聞こえる。盤のマスは印を読まず「部首: 一致」と読むので、読み上げで遊ぶ来訪者には、このリストが盤の印の意味だと分かる手がかりが無い。また、`×`（U+00D7）は日本語の読み上げで「かける」と読まれることが多い。リストに名前（例「盤の印」）を付け、印を読み上げでどう言わせるかを決める。
- nakamawake の凡例「難易度1（易しい）〜」「難易度4（とても難しい）」は、何の難易度かを言っていない。グループがまだ1つも解けていない最初の画面では、「難易度1〜4」が今日の問題の難しさや、選べる難易度にも読める。さらに、1つの範囲を2つの項目に分けたので、読み上げは「2項目」と数え、1つ目の項目が「〜」で終わる。見た目でも、375px・1280px で「〜」のあとに項目のあいだの 16px が空く。例えば「グループの難易度 1（易しい）〜4（とても難しい）」を1つの項目にし、括弧の一続きを折らない指定を項目の中で持てば、主語が入り、折れの問題も型の注釈の特別扱いも無くなる。3-1 の表の語を変えることになるので、語は PM が決め、そのあと builder が直す。
- `types.ts` の `legend` の注釈にある、nakamawake の分け方の理由（「括弧の一続きを項目の中に収める」）も、上の直しに合わせて書き直す。

### 2. 凡例の印の大きさがそろっていない（小）

`◯`・`△` は和文の書体で全角の大きさに組まれ、`×` は欧文の書体（IBM Plex Sans）の小さな字になる。375px でも 1280px でも、`×` だけが目に見えて小さい（撮った画像）。凡例は盤の印を読み解く鍵なので、3つの印を同じ大きさで見せる。盤の印（T4-11・T4-12）と同じ字と書体にそろえる。

### 3. kanji-kanaru・yoji-kimeru で、読み込みのずれが最初の画面に入った（中。記録の不足）

本番のビルドで layout-shift を測った（初めての来訪者。遊び方のダイアログは開かない状態）。

| ------------ | ----------------- | ----------------- | ------------------ |
| kanji-kanaru | 0 → 0.081         | 0 → 0.069         | 0.035 → 0.071      |
| yoji-kimeru  | 0 → 0.067         | 0 → 0.053         | 0.040 → 0.082      |
| nakamawake   | 0 → 0             | 0 → 0             | 0 → 0              |
| irodori      | 0 → 0             | 0 → 0             | 0 → 0              |

ずれたのは帰属表示（`GameLayout-module__attribution`）と FAQ で、読み込み中の区画が低く、盤が出たときに下へ押される。変更前は頭が高く、これが最初の画面の外で起きていたので数えられなかった。T4-11・T4-12 の条件（初めての来訪者で 0）で直る見込みだが、builder の報告にも index.md の補足事項にも書かれていない。出荷の前に必ず直すものとして、index.md の「T4-10 のあとで T4-11〜T4-14 が受け持つこと」に書き足す。

### 4. 要約の文（小）

- nakamawake「4回間違えるまでに、16の言葉を共通点で4語ずつ4組に分ける」は、何をするかより先に負けの条件が来て、1度で読み下しにくい。ほかの3本は「何を」から始まる。例「16の言葉を、共通点で4語ずつ4組に分ける。4回間違えると終わり」のように、何をするかを先に置く（320px で2行に収まるかを撮って確かめる）。
- kanji-kanaru・yoji-kimeru は「今日の」で毎日替わることを言うが、nakamawake と irodori は言わない。4本とも毎日替わる（`isDaily: true`）。毎日遊びに来る理由になる語なので、4本でそろえる（「今日の16の言葉を…」「今日のお題の5色に…」など）。

### 5. ダイアログを消したあとに残るものを、受け渡しに書く（小）

`gameTitle.ts`（`GAME_TITLE_ID`・`gameTitleRef`）、h1 の `id` と `tabIndex={-1}`、GameLayout の注釈「自分で開いたダイアログを閉じたとき、ゲームの部品がフォーカスをここへ戻す」は、どれも遊び方と結果のダイアログのためだけにある。ダイアログは T4-11〜T4-14・T4-19 で無くなるので、そのままだと、どこからも使われない ref と、事実と違う注釈と、理由の無いフォーカスを受ける h1 が残る。ダイアログを消すタスクがこれらも消すことを、index.md の受け渡しに書く。

### 6. 消した物の不在を確かめるテスト（小。ツギハギ）

`GameLayout.test.tsx` の「「こんなゲームです」の区画を持たない」は、前にあった物が無いことを確かめるだけのテストで、前の状態を知らない読み手には意味が分からない。仕様（h1・要約・凡例の順）はほかのテストが確かめているので、消す。

### 7. 次の問題の時刻が、日付をまたいで開いたままだと過去の時刻を「出ます」と言う（小）

`NextPuzzleTime` の `subscribe` は何も知らせないので、23:50 に解いて画面を開いたままにすると、0:00 を過ぎても「9月27日 0:00（日本時間）に出ます」のまま残る。1秒ごとに書き換えない方針は保ったまま、次の日本時間の 0:00 に1度だけ知らせる（`setTimeout` を1つ置き、cleanup で消す）ようにすると、文がいつも正しい。§11 の「書き換わり続ける」には当たらない。
