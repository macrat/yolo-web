## 来訪者に見える6つの変化の判断

1. **「シェア」→「この結果をシェア」**: 良い。何を共有するかを字で言い（§8「何を共有するかを見出しが言う」と同じ向き）、診断・占いと同じ語になった。
2. **コピー→X から X→コピー**: 良い。記事・道具・診断・占いと同じ並び（X・LINE・はてブ・コピー）で、面をまたいで同じ位置に同じボタンがある。
3. **共有シートに渡す文の URL の二重を1つに**: 良い。前は `text` の最後の行と `url` の両方に URL があり、共有先によっては URL が2回並んでいた（前の記録の `shared` で確認）。後は `text` から最後の行が外れ、`url` だけが持つ。
4. **「コピーしました!」→「コピーしました」**: 良い。記事・道具の知らせと同じになった。§9 とも食い違わない（Minor-6 の残りを除く）。
5. **ゲームの share を、閉じただけの回とコピー失敗の回に送らない**: 数え方として正しい。診断と同じ条件になり、送る値（`method`・`content_type`・`item_id`・`content_id`・`surface` の有無）は前後の記録で全面・全ボタンが一致した。ただし数え方が変わる日を記録していない（Minor-4）。
6. **結果のページの共有の区画の上が 24px 減った**: 良い。前は罫線の下の `padding-top` 24px と部品の `margin-top` 24px が重なり、罫線からボタンまで 48px あいていた。後は 24px で、罫線が区画の頭に付いて見える（375px の前後比較の画像で確認）。ゲームの結果の区画の数 px も、ボタンと知らせのあいだが部品の `gap` の 8px にそろっただけで、崩れはない。解き終えた画面・相性・今日の運勢は、外の余白と相殺して画像が前後で同じ（md5 一致）。

## とくに見てほしいと言われた点

- **GA の値が面ごとに変わらないこと**: 変わっていない。呼び出し側9か所の `contentType`・`contentId`・`surface` を前の値と1つずつ照らし、前後の記録の `gtag` も全クリックで一致した（数え方の変化は上の 5 だけ）。

- **`url` に絶対 URL・パスの両方を受ける処理**: 正しい。結果のページ・character-fortune は `BASE_URL` の絶対 URL をそのまま使い（前と同じく正規の URL を共有する）、ほかはパスに origin を付ける。テストも両方を確かめている。

## 指摘

### Major-1: 消した部品だけが使っていた関数と、それを確かめるテストが残っている（AP-I13）

`src/play/games/shared/_lib/share.ts` の `copyToClipboard` と `generateTwitterShareUrl` は、`GameShareButtons` を消したことで本番のコードから呼ばれなくなった（`src/` の grep でテスト以外の参照が0件）。それでも次のテストが、本番で使われない関数を確かめ続けている。

- `src/play/games/shared/_lib/__tests__/share.test.ts`
- `src/play/games/{irodori,kanji-kanaru,nakamawake,yoji-kimeru}/_lib/__tests__/share.test.ts` の `generateTwitterShareUrl` の describe

とくに4本のゲームのテストは「X に渡す文から URL を除く」ことを確かめているように読めるが、本番でそれをしているのは `ShareButtons` の `withoutTrailingUrl` で、テストは別の関数を見ている。後で読む人に、確かめていないものを確かめていると思わせる。

受け持ちの表では `src/play/games/shared/` は T4-10、ゲームのディレクトリは T4-11〜T4-14 のものなので、T4-4 の builder が触らなかったのは表に沿っている。直し方は次のどちらか。

- PM が T4-10・T4-11〜T4-14 が始まっていないことを確かめたうえで、T4-4 で消す（撤去は撤去したタスクで片付けるのが AP-I13 の趣旨）。`copyToClipboard` を Minor-1 のために残すなら、`src/lib/` へ移して `ShareButtons` から使う。
- あるいは、t4-design.md 10章の T4-10 の行（と T4-11〜T4-14 の行）に「`generateTwitterShareUrl`・`copyToClipboard` とそのテストを消す」を書き足し、完了の条件に入れる。

### Major-2: 共有の部品が、ゲームの古い文の形に合わせる特例を持ち、それを外す引き継ぎが無い（AP-I02）

`withoutTrailingUrl` と、`text` の説明の「最後の行が共有する URL なら、その行を除いて使う」は、ゲームの `generateShareText` が文の最後に URL を付けているからだけ要る。根は呼び出し側の文の形で、部品が呼び出し側の文を解析して直している。今回ゲームの `_lib/share.ts` を触れない（受け持ちの表）のは分かるが、3-6 で T4-11〜T4-14 が共有の文を組み直すときに URL の行を外せば、この特例は要らなくなる。いまはその引き継ぎがどこにも書かれていないので、特例が共有の部品に残り続ける。

直し方: t4-design.md 10章の T4-11〜T4-14 の行（または 3-6）に「共有の文に URL の行を持たせない（URL は `ShareButtons` が付ける）」を書き、最後のゲームのタスクで `withoutTrailingUrl` と `text` の説明のその文を消すことを、どのタスクがするかまで決めて書く。

### Minor-1: ゲームの「結果をコピー」が、クリップボード API が使えない環境での代わりの写し方を失い、失敗しても何も知らせない

前の `GameShareButtons` は `copyToClipboard`（`navigator.clipboard` が無いか失敗したら、隠した textarea と `execCommand("copy")` で写す）を使っていた。いまは `navigator.clipboard.writeText` だけで、失敗すると黙って何も起きない。本番の HTTPS と主なブラウザでは困らないが、クリップボードの権限を持たないアプリ内ブラウザなどでは、押しても何も起きず、知らせも出ない。代わりの写し方を持つ関数を `src/lib/` に置いて `ShareButtons` のコピーで使えば、ゲームだけでなく記事・道具・診断のコピーも同じだけ強くなる（Major-1 の `copyToClipboard` の置き場所の決め方と一緒に決めるとよい）。少なくとも、やらないならその判断を記録する。

### Minor-2: surface を送らない面の確かめが、前のテストより弱くなった

消した `src/play/quiz/_components/__tests__/ShareButtons.test.tsx` は、surface を渡さない面で `expect(params).not.toHaveProperty("surface")` を確かめていた。新しいテストは `toEqual` で比べていて、`toEqual` は値が `undefined` のキーを無視するので、`surface: undefined` が乗るように壊れても通る。今日の運勢・ゲームの行と「ページの共有は、surface を送らない」で、`toStrictEqual` を使うか `not.toHaveProperty("surface")` を足す。

### Minor-3: 変更したテストファイルに、無いファイルへの参照が残っている

`src/components/ShareButtons/__tests__/ShareButtons.test.tsx` の `beforeEach` のコメント「（既存パターン: common/ShareButtons.test.tsx）」の `common/` は、もう存在しない。T4-4 でこのファイルを書き換えているので、その場で消す（CLAUDE.md のツギハギ禁止）。

### Minor-4: ゲームの share の数え方が変わることを記録していない

ゲームの `web_share` は前は共有シートを開いた回をすべて、`clipboard` はコピーに失敗した回も数えていた。出荷の日から、どちらも減る。ゲームの `web_share` は過去の観測にも出ている値（ADR001 の出荷前の基線に `game / yoji-kimeru` の `web_share`）で、ADR009 は GA の前後を方向読みで使うので、記録が無いと出荷後の減りを来訪者の変化と読み違える。cycle-316 の記録（index.md の T4 の作業の記録など）に、変わる数え方と、送る値は変わらないことを書く。

### Minor-5: 実機の確かめに kanji-kanaru と yoji-kimeru の結果が無い

前後の記録の `kanji` は辞典の漢字のページで、ゲームの kanji-kanaru ではない。ゲームの結果の区画は irodori と nakamawake だけを撮っている。組み方は4本とも同じだが、並び順と文言が変わる面なので、kanji-kanaru・yoji-kimeru の結果の区画も、共有シートあり・なしで同じように記録と画像を取る（AP-WF05）。

### Minor-6: 結果の区画で「コピーしました」と「リンクをコピーしました!」が並ぶ

`FudaActions.tsx` と `InviteFriendButton.tsx` の知らせは「リンクをコピーしました!」のままで、T4-5 で共有の区画を1か所にまとめると、同じ区画に感嘆符のある知らせと無い知らせが並ぶ。どちらも T4-5 の受け持ちなので、T4-5 で「リンクをコピーしました」にそろえることを、T4-5 の行か引き継ぎに書いておく。

### Minor-7: ゲームだけ LINE を持たないことが、設計の説明と合っていない

7-3 は「3つとも……X・LINE・はてなブックマーク・コピー（と端末の共有シート）へ渡すだけで、違いは渡す文と計測の値だけ」と書くが、ゲームは `sns={["x", "copy"]}` で LINE を持たない（前と同じ）。LINE は日本の来訪者がいちばん使う送り先の1つで、ゲームの結果の並び（◯△× の格子）は友だちに送る使い方と合う。ゲームにも LINE を足すか、足さない理由を設計に書くかを決める。
