## 指摘

### 指摘1（planner・大）: 結果のページの並びが T5-6 の決定を黙って戻し、§5 の規則もその決定と両立しない

t5-design.md 5-c の結果のページは、B を採っている。

> h1・誘い・説明 → このタイプについて（読みもの・相性）→ **この結果を共有 → すべてのタイプ** → 他のクイズ・他のジャンル

T5-6 の完了の条件も「character-personality の 375px で h1 の下端から共有の見出しまでが 4,419 より短い（見込み約 2,020）」である。T5-6 はまだ実装されていない（`ResultPageShell.tsx` の最後のコミットは T5-5a。JSDoc も「すべてのタイプ、共有の区画」の順）。

一方、設計の記述は次のとおりで、この決定と食い違う。

- 1-3 の結果のページの行は、いまのコードの順（すべてのタイプ → この結果を共有）を書いている。1-4 はこの表を「いま、または決まっている組み」として使う。
- 5-1 の R は「このタイプについて → 他のクイズ・診断も → すべてのタイプ → この結果を共有 → 他のジャンルも」である。T5-6 の B が前へ送った共有を、すべてのタイプ（最大24行、375 で約 2,370px）と新しい一覧のさらに後ろへ戻している。
- 5-1 は「解き終えた画面と同じ順になる」と書く。しかし解き終えた画面では、共有は結果の区画の中にあり、すべてのタイプより前である。共有の位置については同じ順にならない。
- 6-1 の §5 の文は、すべてのタイプを「中身の続き」とし、共有より前に置く。T5-6 の B のまま実装すると、結果のページは入れた日から規則に反する。
- 9章の「替える過去の決定」の T5-6 の項は、「他のクイズ・診断も」を移すことしか書いていない。共有をすべてのタイプの後ろへ戻すことは書いていない（AP-P24）。

来訪者から見ると、結果のページで自分の結果を読み終えた人が共有に出会うまでの距離が、T5-6 の見込み（約 2,020）から、すべてのタイプと他のクイズ・診断もの分だけ延びる。T5-6 が B を採った理由（「結果のページを受け取って読んだ来訪者が、読み終えた所で共有に出会う」「2つの面でセクションの並びがそろう」）を比べずに打ち消している。

直し方:

- 1-3・1-4 の結果のページの行を、T5-6 の B の組みで書き直す。
- 結果のページの並びを、T5-6 の B を前提に決め直す。たとえば、結果の共有を、ゲーム・今日の占い・解き終えた画面と同じく「結果の区画の中の共有」として扱う形がある（このタイプについて → この結果を共有 → 他のクイズ・診断も → すべてのタイプ → 他のジャンルも）。
- 6-1 の文で、「結果の共有」（中身の一部。ゲーム・今日の占い・解き終えた画面・結果のページ）と「そのページを人に勧める共有」（よくある質問のあと）を分けて書く。そのうえで、文がすべての面を言い当てることを確かめ直す。
- 戻すと決めるなら、T5-6 の B の理由と比べ、9章の「替える過去の決定」と T5-6 の完了の条件の扱いに書く。
- 5-1・8-2 の条件1・8-4 の `ResultPageShell` の試験を合わせる。

### 指摘2（planner・大）: §7 の規則と 6-3 の検査を実際のページで試しておらず、6-4 で入れられなくなる

6-3 の検査は、`main` の中の同じサイトへのリンクから、`nav`・表・文の中・いま開いているページを除いて、同じ `href` が2度無いことを見る。6-3 は、関連の入口・1本だけの関連・結果ごとのリンクが「どれもこれで数えられる」と書く。しかし、この検査を実際のページにまだ掛けていない。コードを読むと、次のページで0にならない。

- **四字熟語の詳細の構成漢字**（`YojiDetail.tsx`）: 字ごとにリンクを置くので、同じ字を2度持つ語では同じ漢字の詳細を2度指す。400語のうち46語が当たる（`kanji-data.json` と `yoji-data.json` で数えた）。T5-11 の測る語の「一期一会」も当たる（「一」が2度）。9章が T5-10・T5-11 の完了の条件に足す「6-3 の手順で詳細のページの重なりが0」は、T5-11 で満たせない。

どれも来訪者にとって害のある重なりではない。規則の言葉（「リンクの並び」）と検査が、害のない繰り返しまで数えている。6-4 は「0でない面があれば入れずに PM に渡す」ので、規則と検査はこのままでは入らない。また builder が、検査を通すために主操作や構成漢字を消す向きに動きうる（AP-P33）。

直し方:

- 当たったものを、規則が止めたい重なり（2つの案内が同じ行き先を並べる）と、そうでないもの（そのページの主操作の繰り返し、中身の字の並び、同点の説明のリンクなど）に分ける。規則の文と検査の除外に、分けた理由とともに書く。除外が要らない形（例: 構成漢字は同じ字の2度目をリンクにしない）が来訪者にとって良いなら、それを受け持ちのタスクに渡す。

- yoji-level: 5つのうち四字キメルを指すのは2つだけ。

beginner などの結果の人の解き終えた画面では、漢字カナールが結果のリンクにも「他のジャンルも」にも無くなり、ページのどこからも消える。開始の画面（入口に残る）を除く設問の画面と、結果のページ以外の状態でも同じである。GA では、漢字カナールは kanji-level からほかの分類へ移る先の上位にある（6 閲覧・6人。確かめたこと）。3-4 の c の「来訪者から見て」の欄は「重ならない。理由付きの1本が残る」と書くだけで、この損を書いていない（AP-P02）。

入口の b にも、小さな同じ形の損がある。yoji-personality の入口の四字キメルは、「他のジャンルも」（よくある質問と勧めるの下）に並ぶので外される。その結果、「はじめる」のすぐ下の道がページの下端へ移る（GA では 0 閲覧で、影響は小さい）。3-3 は「一覧に並ぶ遊びは、説明と問数を持つ行で1度だけ読む」と書くが、その一覧がどこにあるかを見ていない。

直し方:

- 3-4 の c の欄に、上の損（どの結果の人から、どの状態で消えるか）と GA の数を書く。
- 解き終えた画面で、その結果のリンクが指すときだけ「他のジャンルも」から除く案を比べる。たとえば、サーバーが除いた場合と除かない場合の行を作って渡し、解き終えた結果に合わせて選ぶ形がある。ページの下の一覧なので、切り替えが画面の中を動かさないことも条件に入る。実装の手間は理由にしない（CLAUDE.md）。
- 3-3 の b で、外す理由が遠くの一覧に並ぶことであるときの扱いを決めて書く。そのまま外すなら、その損を書く。

### 指摘6（planner・小）: T5-31 の決定が設計に入っていない

index.md の「T5-20f の設計（第3稿）から」で、PM はブログの関連記事から前後の記事を除く T5-31 を立てた。しかし設計はまだ、この決定を反映していない。

- 冒頭の決定の並びにこの決定が無い。
- 9章の「ブログの記事の関連記事と前後の記事」は、いまも「扱うかどうかと受け持ちを PM が決める」と書いている。
- 6-4 の数える面の「関連記事が前後の記事と重なる記事」は、T5-31 のあとには無くなる。

9章の項を決定の記録（T5-31 が受け持つ）に書き直し、6-4 の面の選び方を T5-31 の前後どちらでも成り立つ言い方にする。

### 指摘7（planner・小）: ユーモア辞典の詳細の評価と「一覧へ戻る」が、6-1 の規則のどの群れにも入らない

6-1 の文のあとの段落は、「この文は、いまと決まっている組みの全部の面（1-4）を言い当てる」とする。しかし、ユーモア辞典の詳細の評価のボタン（関連語と共有のあいだ）と「一覧へ戻る」は、「中身の続き」「よくある質問」「共有」「ほかへの案内」のどれとも書かれていない。「一覧へ戻る」は `DESIGN.md` §7 の「一覧へ戻る道」に当たり、6-2 の「送りの案内」とも関わる。どちらの群れに入るか（評価は中身への応え、一覧へ戻る道は送りの案内、など）を文に書く。それが T5-13 の並びと合うことを 1-4 で確かめる。
