# T3 一覧の設計

対象は `DESIGN.md` §7 の一覧です。B-574 と B-599 のうち一覧の構造にかかる部分も含めます。現状の数値は [t3-inventory.md](./t3-inventory.md)（2026-09-25 計測、375×667 と 1280×800）から引きます。

## 0. 前提の事実

- 一覧を描く部品は、行の形のものだけで十数あり、読み上げの名前の作り方がばらばらです。
  - `Shinagaki`・`BlogList`・`OtherTypesNav` などは、読み上げの名前が行の名前だけです。
  - `DictionaryEntryList`・`RelatedTools`・`RelatedBlogPosts`・`RecommendedContent`・`RelatedQuizzes`・`RelatedGames`・`PlayRecommendBlock` は、説明や種別まで名前に連結しています（inventory 3-2）。
- 1画面に収まらない主な一覧のうち、次の3つはどれも持っていません。
  - 名前・種別・並び順の3つの操作
  - 件数の表示
  - ページ送り
  - 並び順を変える操作は、どの一覧にもありません。
  - ページ送りは `/blog` 系だけにあります（12件ずつ）。
- `/blog` 系の一覧は、配信された HTML に入っていません。
  - `BlogFilterableList` が `useSearchParams` を使い、fallback の無い `Suspense` で包まれているためです（`BAILOUT_TO_CLIENT_SIDE_RENDERING`）。
- 375px では、次の一覧で最初の行が画面の下端（667）より下にあります。
  - `/blog`（788）
  - `/dictionary/kanji`（777）
  - `/dictionary/yoji`（729）
  - `/dictionary/colors`（805）
  - `/tools/yoji-search`（897）
- 最長の一覧は `/dictionary/kanji/grade/7`（中学以降）の 1,110 件です。375px で文書の高さが 160,552px あります。
- ほかの大きな一覧の件数は次のとおりです。
  - 漢字 2,136、四字熟語 400、伝統色 250
  - 部首の最多は「水」の 118、画数の最多は 10画の 217
  - ブログ 86（分類の最多は dev-notes の 35、タグの最多は Web開発の 35）
  - ツール 36、遊び 20、ユーモア辞典 30

## 1. 一覧の行の部品 `ItemList`

### 1-1. 決定

§7 の一覧（ボックスの中に1行1項目）を `src/components/ItemList/` の1つの部品にします。サーバーでもクライアントでも描ける、フックを持たない部品です。

```ts
export interface ItemFact {
  /** 見える字（「2026-07-19」「4画」「全10問」など） */
  text: string;
  /** 日付なら ISO 8601。与えると <time dateTime> で包む */
  dateTime?: string;
}

export interface ItemListEntry {
  /** 行の名前。リンクの字であり、読み上げの名前はこれだけになる */
  name: string;
  /** 名前のリンク先。行の key を兼ねる */
  href: string;
  /** 名前に添える読み（辞典の項目）。名前の後ろに --ink-2 で置き、リンクに含めない */
  reading?: string;
  /** 何ができるか・何であるかを言う一文。--ink-2 */
  description?: string;
  /** 何の仲間かを言う一語 */
  kind?: string;
  /** 種別に続けて置く補助情報。並び順に使う値は、ここか種別に見えていること */
  facts?: ItemFact[];
  /** 主題が色の項目の色（中身の色。CSS の色の値）。行の先頭に色見本を置く */
  swatch?: string;
}

export interface ItemListProps {
  items: ItemListEntry[];
  /** 一覧の名前。見出しがあれば labelledBy にその id を、無ければ label に文を渡す（どちらか必須） */
  label?: string;
  labelledBy?: string;
  /** 順序に意味がある一覧（連載）は ol で組む */
  ordered?: boolean;
  /** いま開いているページの項目。その行は §6 の現在地（太字・下線なし・リンクのまま・aria-current="page"） */
  currentHref?: string;
}
```

組み方は次のとおりです。

- **ボックス**: `ItemList` がボックス（§5）を持ちます。見出し・件数・操作・ページ送りはボックスの外に置きます。
  - 結果のボックスの中に置くときは、ボーダーを二重にしません（§8）。
  - `Panel` の中に置く場合も同じで、ボックスを持たない形で描きます。
- **行の区切り**: ボックスのコンテンツ幅いっぱいの細い罫線で区切ります。
- **リンクと押せる範囲**: 行の中でリンクにするのは名前だけです。
  - 名前のリンクの `::after` で行全体を押せる範囲にします（`data-hit-area="after"`。hover の線とフォーカスのリングは T2 の規則で行全体に出ます）。
  - 読み・説明・種別・補助情報はリンクの外に置きます。これで読み上げの名前が行の名前だけになります（B-574）。
- **行の中に別のリンクを置かない**: 行が持つものは §7 の3つ（名前・説明・種別）と補助情報に限ります。行の中にリンクを重ねると押せる範囲が入れ子になり、行を目で追う速さも落ちるからです。
- **45rem 以上**:
  - 1行目は、左に色見本・名前・読み、右端に種別と補助情報を置きます。
  - 2行目は説明です。
- **45rem 未満**:
  - 名前の下・説明の上に、種別と補助情報の行が落ちます（§7）。
  - 色見本は、名前の行の左に置いた 32px の正方形で、細い線で囲みます（§5 色見本）。
- **並べ方**: `ul` で組み、`ordered` のときだけ `ol` にします。行に見出し要素は置きません。行ごとに見出しを立てると、ページの見出しの構造（§5「セクションの頭に見出しが1つ」）に一覧の件数ぶんの見出しが混ざるからです。

## 2. 増え続けることへの備え

### 2-1. 部品の分け方

| 部品                     | 置き場所                                        | 役目                                                                                                                                     |
| ------------------------ | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `src/lib/list-browse.ts` | 純粋な関数                                      | 名前の絞り込み（正規化を含む）・種別の絞り込み・並べ替え・ページの切り出し・URL のクエリとの読み書き・畳んだときのラベルの文を組む       |
| `ListControls`           | `src/components/ListControls/`（クライアント）  | 畳める操作の枠。中身は名前の絞り込みの欄・種別のラジオボタンの組・並び順のラジオボタンの組と、道具ごとの組（`children`）。状態は親が持つ |

### 2-2. 操作を出す条件

- **一覧のページ**（ページの主な中身が一覧であるもの）の範囲が **10件を超えるとき**、名前の絞り込みと並び順を出します。
  - 10件までは、名前を目で追えば1回のスクロールで見渡せます。そこに絞り込みを足すと、見渡す手間より操作の手間が増えます。
  - 375×667 に入る行は、説明を持つ行で3〜5件です。10件を超える一覧は、測ったどの幅でも1画面に収まりません。
- 種別の絞り込みは、範囲の中に種別が **2つ以上** あるときだけ出します。
- ページの中の短い一覧（関連・おすすめ・連載・他のタイプ）には、操作もページ送りも件数の行も出しません（3-2）。

### 2-3. 畳み方とラベル

- `ListControls` は、開閉のボタン（`button[aria-expanded]` と T2 の `DisclosureTriangle`）と、操作の領域でできています。
  - **45rem 未満**: 初めは閉じています。
  - **45rem 以上**: 開閉のボタンを CSS で消し、領域をいつも出します。
  - 閉じた状態は CSS のメディアクエリだけで隠します。サーバーの HTML と最初の描画が同じになり、読み込みのあとに一覧が動きません（CLS を出さない）。
  - `details` を使わないのは、広い画面でいつも開いた状態を、JS なしで、ずれなく作れないからです。
- ボタンの見える文言は「絞り込みと並び順（{条件}、{並び順}、{該当件数}{単位}）」とします。条件は次の順に「、」でつなぎます（値の中に「・」が現れるので、区切りに「・」を使わない）。
  - 名前の条件（「「json」を含む」）
  - 種別（選んでいなければ「すべて」）
  - `extraSummary`
  - 例: 「絞り込みと並び順（すべて、新しい順、86件）」「絞り込みと並び順（「みず」を含む、小学1年、学年順、3字）」
- 領域の中の順は、名前の欄（`Field`＋`Input type="search"`）→ 種別の `RadioGroup` → 道具ごとの組 → 並び順の `RadioGroup` です。種別の絞り込みはラジオボタン（1つを選ぶ）にします。ラベルに「いまの種別」を1語で言えるからです。

### 2-4. 件数の行（`ListStatus`）

- ボックスの上、`ListControls` の上に置き、畳んでも見えるようにします（§7 全体の件数）。
- 文の形は次のとおりです。
  - 絞り込みが無いとき: 「全86件」
  - 絞り込み中: 「12件（全86件）」
  - ページ送りがあるとき: 末尾に「のうち1〜50件目」を足す
  - 該当が0件のとき: 「条件に合う{単位}はありません（全N{単位}）」と、プライマリでないボタン「絞り込みを外す」
- `role="status"` にして、絞り込みで変わった件数を読み上げにも伝えます（§8）。
- クライアントでページを送ったあとは、この行にフォーカスを移し、行が画面の上に来るまでスクロールします（`tabindex="-1"`）。

### 2-5. 名前の絞り込み

- 字を打つたびに絞り込みます（送信のボタンは持たない）。IME の変換中（`compositionstart`〜`compositionend`）は掛けず、確定で掛けます。変換の途中の仮名で一覧が揺れないようにするためです。
- 正規化は NFKC・小文字化・片仮名から平仮名への寄せです。「すい」で音読みの「スイ」に、「JSON」で「json」に当たります。
- 何で探すかは一覧ごとに `searchText` で決め、欄のラベルでそれを言います（3章の表）。
- `autocomplete="off"`・`enterkeyhint="search"` を付けます。

### 2-6. 並び順

- どの一覧も、並び順を2つ以上持ちます（§7 変えられる）。
- 並び順に使う値は、行の種別か補助情報に見えていることにします（§7 並び順が見えている）。見えない値で並べると、来訪者は何の順かを確かめられないからです。
- 同じ値の中は、渡されたデータの順を保ちます（安定な並べ替え）。

### 2-7. ページ送りと URL

- **既定の状態**（名前の条件が空・種別が「すべて」・並び順が既定）では、ページは URL のパス（`{basePath}/page/{n}`）で、どのページも静的に生成します。
  - ページ送りは `Pagination` の link モードです。
  - 理由: JS の読み込みを待たずにどのページの行も読め、戻る・共有で同じページが出ます。辞典の全項目が一覧の HTML から辿れることにもなり、これは検索の表示回数の76〜79%が辞典であるサイトで大事です。
- **既定でない状態**は、範囲の全件からクライアントで組みます。状態は URL のクエリに持ちます。

  | 状態                           | クエリ | 書き換え方                                                      |
  | ------------------------------ | ------ | --------------------------------------------------------------- |
  | 名前の条件                     | `q`    | `history.replaceState`（300ms 遅らせる）                        |
  | 種別                           | `kind` | `history.replaceState`                                          |
  | 並び順                         | `sort` | `history.replaceState`                                          |
  | ページ（既定でない状態のとき） | `page` | `history.pushState`。ページ送りは `Pagination` の button モード |
  - クエリに持つ理由: 詳細を開いてから戻ったときに、同じ絞り込み・並び順・ページが出ます。
  - 書き換えるのはクエリだけで、パスは変えません。Next.js はネイティブの `pushState`・`replaceState` を `useSearchParams` と同期させるので、再取得は起きません。
  - 絞り込みを外すと、そのパスの既定のページに戻ります（`/blog/page/2` で絞り込んで外せば、2ページ目に戻る）。
  - 絞り込みと並び順を `replaceState` にするのは、戻るのボタンが打鍵のたびに一覧の中で止まらないようにするためです。

- **無限スクロールと「もっと見る」は持ちません**（§7）。
- **範囲外のページ番号**（`/blog/page/9` など）は、その一覧の1ページ目へ 308 で送ります。いまの `/tools/page/[page]` と同じ扱いです。
- 2ページ目からの URL は、いまのブログのページ送りと同じく、sitemap に載せず、自分を canonical にします。
- `page` という名前のパスの区切りは、`[char]`・`[yoji]`・`[slug]` より優先されます。各辞典に `page` という見出し語・slug が無いことを、テストで確かめます。

### 2-8. 静的な HTML

`BrowsableList` は、中で `Suspense` を持ちます。

- fallback は、同じ見た目の部品を既定の状態（パスのページ）で描いたものです。
- `useSearchParams` を読む子は、その中に置きます。
- こうすると、静的生成の HTML に、件数の行・閉じた操作・その回のページの行・ページ送りが入ります。
- クエリの無い来訪では、読み込みの前後で見た目が変わりません。
- 範囲の全件のデータは、サーバーからクライアントへ `BrowsableList` の props として1回だけ渡します。行のデータは表示と絞り込みに要るものだけにし、href はクライアントで組める形（接頭辞＋鍵）にして小さくします。

### 2-9. 名前の索引 `LinkIndex`

次のものは、`src/components/LinkIndex/` の1つの部品にまとめます。

- 漢字1字・四字熟語のように、名前だけで何か分かる語を横に並べて折り返すリンクの並び
- 分類の索引（学年・部首・画数・カテゴリ・色み）

仕様は次のとおりです。

- `ul`/`li` で組みます。
- 見出しには件数を添えます（例「同じ部首の漢字（117字）」）。
- いまの分類は §6 の現在地にします（`aria-current="page"`）。
- 項目は縁の見えないコントロールで、押せる範囲を接して並べます（§5）。

§7 の行にしない理由は、漢字1字の117件を1行ずつ並べると 375px で約5,600px になるからです。字を見渡して選ぶ速さも失います。いまの折り返しは 880px です。

## 3. 一覧ごとの割り当て

### 3-1. 一覧のページ

1ページの件数の決め方は次のとおりです。

- 説明の文を持つ行は **50件**、説明が語（読み）だけの行は **100件** です。
- どちらも 375px でおよそ1万px（行の高さ約200px×50、約100px×100）です。
- 大きいページほど、ブラウザのページ内検索で見つけられる範囲が広く、ページを送る回数が減ります。
- ツール（36）・遊び（20）・ブログの分類とタグ（最多35）は、1ページに収まって種別の絞り込みがページの中で完結します。

名前の絞り込みで探す字（`searchText`）と欄のラベルは、次のとおりです。

| 一覧         | 探す字                                         | 欄のラベル                         |
| ------------ | ---------------------------------------------- | ---------------------------------- |

| ブログ       | 題名・説明・タグ・分類名・連載名（いまと同じ） | 「題名・説明・タグで探す」         |
| 漢字         | 字・音訓・意味（英語）・使用例（いまと同じ）   | 「字・読み・意味で探す」           |
| 四字熟語     | 語・読み・意味・例文                           | 「語・読み・意味で探す」           |

| ユーモア辞典 | 語・読み・語義                                 | 「語・読み・語義で探す」           |

決定と理由:

- **ツールと遊びは、棚をやめて1つの一覧にします。** 種別を各行に一語で出し、既定の並び順を種別順にします。
  - 種別の絞り込みでいまの棚と同じ見方ができ、新しい順で戻ってきた来訪者が新しいものを見つけられます。
  - 名前順は持ちません。ツール名・遊びの名前は読みのデータを持たず、字の順は五十音順にならないからです。
  - 公開日を補助情報に出すのは、新しい順の並びが見えるようにするためです（2-6）。
- **ブログの行から、タグのリンク・「新着」の印・読了時間を外します。**
  - タグのリンクは、行の中に独立した押せる範囲を重ね、行を目で追う速さを落とします。
  - 「新着」は名前のリンクの中にあり、読み上げの名前を変えます（B-574）。新しい順の既定と公開日で同じことが分かります。
  - 読了時間は記事の上にあり、一覧で比べて選ぶのに要るのは分類と公開日です。
  - `/blog` の「タグで探す」（375px で y=571〜763 を占める）も外します。タグのページは記事の `TagList` から辿れます。
- **分類のリンクの並びは、種別のラジオボタンの組に替えます。**
  - `/blog` の分類は §7 の種別です。
  - 分類のページ（`/blog/category/*`）は、検索と記事のパンくずからの入口として残し、その分類の範囲の一覧にします。
  - 一覧の下に「ほかの分類」の `LinkIndex` を置きます。辞典の分類のページと同じ形です。
- **漢字の行の説明は、音訓にします。** 意味（`meanings`）は 2,136字すべてで英語の語なので、行には出しません（詳細には残す）。日本語の来訪者が字を見分けるのに要るのは読みです。英語の意味は `searchText` に残すので、「water」でも見つかります。
- **辞典のトップ（漢字・四字熟語・伝統色）は、いまの `DictionarySearch`（空の入力では何も出さない、最大100件）を、全件の一覧に替えます。**
  - 着いた来訪者に最初から中身が見え、HTML に行が入ります。
  - 漢字のトップの「部首から探す」（198）と「画数から探す」（24）は、一覧の下の `LinkIndex` に移します。いまは 375px で部首の198リンクが一覧の前に 1,452px を取っています。
  - 学年は種別の絞り込みに入ります。学年のページは、詳細の「学年」のリンクと、学年のページどうしの `LinkIndex` から辿れます。
- **分類のページ（学年・部首・画数・四字熟語と伝統色のカテゴリ・ブログの分類とタグ）は、それぞれが1つの範囲を持つ一覧です。** そのページの中で種別を替えて別の分類のページの中身に切り替えることはしません。
  - ページの見出し（「小学1年の漢字」）と中身がいつも一致します。
  - ページごとに渡すデータが、その分類の分だけで済みます。
  - 親の一覧で種別を選んだ状態（`?kind=`）の canonical は親の URL のままなので、分類のページと重複しません。

## 4. 描き方

### 4-1. `/blog` の一覧を HTML に入れる

- `BlogListView`（サーバー）は、全86件から `BrowsableEntry` を組みます。受け持つ範囲は、分類のページならその分類、タグのページならそのタグです。組んだものを `BrowsableList` に渡します。
- `BrowsableList` の中の `Suspense` の fallback が、既定の状態の一覧を描きます（2-8）。
- `BlogFilterableList`・`BlogList` は消します。
- 確かめ方は、`npm run build` のあとの `/blog`・`/blog/page/2`・`/blog/category/dev-notes`・`/blog/tag/Web開発` の HTML で次の3つを見ることです。
  - そのページの最初の記事の題名が入っている
  - ページ送りのリンクが入っている
  - 一覧の位置に `BAILOUT_TO_CLIENT_SIDE_RENDERING` が無い

### 4-2. 1,110件の一覧の分け方

- 100件ずつ URL のページに分けます（中学以降は12ページ）。行を送らずに探す来訪者のために、同じページに名前の絞り込みと並び順を置きます。
- 下位の分類（画数など）で分けることはしません。学年のページの見出しと食い違う、別の分類の軸を持ち込むことになるからです。画数ごとの一覧は、画数のページが持っています。
- 各ページには、学年の範囲の全件（1,110件）のデータを渡します。絞り込みはページをまたいで掛かるためです。
  - いまは同じ1,110件をすべて HTML の行で配っています。
  - これからは、HTML の行は100件で、ほかはデータだけになります。

## 5. 一覧へ戻る道

1. **`/` を除くすべてのページに、`Breadcrumb` を上端のすぐ下に置きます。**
   - 2つ目の項目は、上端のナビと同じ名前の一覧（遊び・ツール・辞典・ブログ）にします。サイト紹介とプライバシーは「ホーム / サイト紹介」の形です。
   - いまパンくずを持たない `/tools` と、ブログのタグのページの自前の「ブログ / タグ」を、この部品にします。
   - 同じ働きのものを、どのページでも同じ位置に置くためです（§12）。
2. **一覧の名前を、ナビ・パンくず・一覧の見出しで1つにします。** `/play` の見出しとパンくずの「遊ぶ」を、上端のナビの「遊び」に揃えます。上端のナビ（遊び・ツール・辞典・ブログ）は名詞で揃っています。
3. **記事のパンくずに分類を入れます**（ホーム / ブログ / {分類} / {題名}）。分類の一覧に1つの操作で戻れるようにするためです。タグのページは「ホーム / ブログ / {タグ}」です。
4. **絞り込み・並び順・ページの状態を URL に持ちます**（2-7）。詳細から戻るのボタンで、元の状態に戻れます。
5. **本文の下の「← ユーモア辞典一覧へ」を外します。** 戻る道をパンくずの1つの形に揃えるためです。
6. 辞典の詳細の学年・部首・画数・カテゴリのリンク（いまある）が、それぞれの分類の一覧へ戻る道になります。

## 6. B-574・B-599

- **読み上げの名前（B-574）**
  - 一覧の行は `ItemList` にし、名前だけをリンクの中身にします（1章）。
  - アコーディオンを行にする一覧（yoji-search・keigo-reference の 45rem 未満）は、`summary` の名前を語（普通語）の部分だけにします（`aria-labelledby`）。読み・意味・敬語の形は `aria-describedby` で説明として読ませます。見える文言は変えず、名前は見える文言の先頭と一致するので、声で押す来訪者も見えている語で押せます。
  - traditional-color-palette の色見本のボタンの名前（「鴇 (#eea9a9)」）は、そのままにします。一覧の行ではなく、色の格子の1つで、カラーコードは読み上げで色を知る唯一の手段だからです。
- **同じ部首の一覧の構造（B-599）**
  - 同じ部首の漢字（最多117）と同じカテゴリの四字熟語（最多57）は、`LinkIndex`（`ul`/`li`、見出しに件数）にします。
  - 同じカテゴリの伝統色は、`ItemList` にします。
  - 読み上げでリストとして扱われ、件数が伝わるようになります。
- **大字の二重読み（B-599）**
  - 漢字と四字熟語の詳細の大字（`span.character`）に `aria-hidden="true"` を付けます。直後の h1「漢字「水」」が同じ字を言うからです。
  - 伝統色の詳細の色見本は、効いていない `aria-label` を外して `aria-hidden="true"` にします。色の名前とカラーコードは本文の字が伝えています。
- **共有ボタンの外部予告（B-599）**
  - 3つの実装（`ShareButtons`・診断の `ShareButtons`・`GameShareButtons`）の文言と読み上げの名前を、`src/lib/share-labels.ts` の1か所から取ります。
  - 見える文言は「X でシェア」「LINE でシェア」「はてブに追加」です（空白の有無を揃える）。
  - 新しいタブで外部を開くものの名前は「{見える文言}（外部サイト・新しいタブで開く）」にします。はてブは、いまの形（はてなブックマーク・外部サイト・新しいタブで開く）を残します。
  - コピー・画像の保存・端末の共有シートを開くものには、予告を付けません。
  - 3つの部品を1つにまとめるのは、結果の組み方を決める T4 に任せます。

| 道具                      | 操作                                                                                      | 並び順                     | 件数の行                                          | ページ送り                                                               |
| ------------------------- | ----------------------------------------------------------------------------------------- | -------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------ |
