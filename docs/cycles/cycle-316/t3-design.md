## 1. 行の一覧の部品 `ItemList`

### 1-1. 決定

§7 の行の一覧（ボックスの中に1行1項目）を `src/components/ItemList/` の1つの部品にします。サーバーでもクライアントでも描ける、フックを持たない部品です。

下の「持つもの」は、決定を伝えるための形の見本です。名前と細部は実装で決めます。

項目が持つもの:

- 名前（必須）。リンクの字で、読み上げの名前はこれだけになる
- 名前のリンク先（必須）。行の key を兼ねる
- 読み。名前の後ろに `--ink-2` で置き、リンクに含めない
- 説明。何ができるか・何であるかを言う短い文
- 種別。何の仲間かを言う一語
- 補助情報の並び。見える字と、日付なら ISO 8601 の値（`<time dateTime>` で包む）
- 色見本の色（主題が色の項目）

一覧が持つもの:

- 一覧の名前（見出しの id か、見出しが無いときの文）
- 番号の付いた一覧か（連載は `ol`）
- いま開いているページの項目。その行は §6 の現在地（太字・下線なし・リンクのまま・`aria-current="page"`）
- ボックスを持つか。既定は持つ。結果のボックスや `Panel` の中では持たない形で描き、ボーダーを二重にしない（§8）

組み方は次のとおりです。

- **ボックス**: 見出し・件数・操作・ページ送りはボックスの外に置きます。
- **行の区切り**: ボックスのコンテンツ幅いっぱいの細い罫線で区切ります。
- **リンクと押せる範囲**: 行の中でリンクにするのは名前だけです。
  - 名前のリンクの `::after` で行全体を押せる範囲にします（`data-hit-area="after"`。hover の線とフォーカスのリングは T2 の規則で行全体に出ます）。
  - 読み・説明・種別・補助情報はリンクの外に置きます。これで読み上げの名前が行の名前だけになります（B-574）。
- **行の中に別のリンクを置かない**: §7 は行の中のリンクを認めていますが、この設計の一覧はどれも持ちません。行を目で追う速さを優先します（3-1 のブログのタグ）。
- **45rem 以上**:
  - 1行目は、左に色見本・名前・読み、右端に種別と補助情報を置きます。
  - 2行目は説明です。
- **45rem 未満**:
  - 名前の下・説明の上に、種別と補助情報の行が落ちます（§7）。
  - 色見本は、名前の行の左に置いた 32px の正方形で、細い線で囲みます（§5 色見本）。
- **並べ方**: `ul` で組み、連載だけ `ol` にします。行に見出し要素は置きません。行ごとに見出しを立てると、ページの見出しの構造（§5「セクションの頭に見出しが1つ」）に一覧の件数ぶんの見出しが混ざるからです。

## 2. 増え続けることへの備え

### 2-1. 部品の分け方

| 部品                     | 置き場所                                        | 役目                                                                                                                               |
| ------------------------ | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `src/lib/list-browse.ts` | 純粋な関数                                      | 名前の絞り込み（正規化を含む）・種別の絞り込み・並べ替え・ページの切り出し・URL のクエリとの読み書き・畳んだときのラベルの文を組む |
| `ListControls`           | `src/components/ListControls/`（クライアント）  | 畳める操作の枠。中身は名前の絞り込みの欄・種別のラジオボタンの組・並び順のラジオボタンの組と、道具ごとの組。状態は親が持つ         |
| `ListStatus`             | `src/components/ListStatus/`                    | 件数の行                                                                                                                           |
| `BrowsableList`          | `src/components/BrowsableList/`（クライアント） | 一覧のページで使う組み合わせ。`ListStatus`＋`ListControls`＋`ItemList`＋`Pagination` と、URL の状態                                |

`ListControls` と `ListStatus` を `BrowsableList` から分けるのは、7章の3つの道具が、行の形が違う一覧（アコーディオンの行・色の格子・表）に同じ操作の枠と件数の行を使うためです。

次の「持つもの」も形の見本で、名前と細部は実装で決めます。

`BrowsableList` が持つもの:

- 範囲の全件。各項目は `ItemList` の項目に、種別の値・名前の絞り込みで探す字（3-1 の表）・並び順ごとの比べる値を足したもの
- 一覧の名前（例「ツールの一覧」）と、件数の単位（「件」「字」「語」「色」）
- 名前の絞り込みの欄のラベル。何で探せるかを言う（3-1 の表）
- 種別の組の見出しと選択肢。「すべて」は部品が先頭に足す。範囲の中の種別が2つ未満なら組を出さない
- 並び順の選択肢。先頭が既定
- 1ページの件数・パスが示すページ・ページの URL の元（ページ n の URL は n=1 で元のパス、ほかは `{元のパス}/page/{n}`）

`ListControls` が持つもの:

- 名前の欄・種別の組・並び順の組の、それぞれの値と変わったときの処理
- ラベルに言う該当件数と単位
- 道具ごとの追加の組（yoji-search の難易度・出典など）と、その選択を言う語（既定の選択は言わない）

`ListStatus` が持つもの:

- 全体の件数・該当件数・単位
- ページ送りがあるとき、表示している範囲
- 該当が0件のときの「絞り込みを外す」の処理

### 2-2. 備えを出す条件

§7 のとおりに次のように決めます。

- **一覧のページ**（ページの主な中身が一覧であるもの）は、件数にかかわらず件数の行を出します。
- 範囲が **10件を超える** 一覧のページは、次の操作を出します。10件以下なら、件数の行だけです。
  - 名前の絞り込み
  - 種別の絞り込み。範囲の中に種別が **2つ以上** あるときだけ出します。1つしかないなら、行も種別を出しません（§7）。
  - 並び順の組。既定のほかに、来訪者が選ぶ理由のある並び順があるときだけ出します。無いなら、既定の並び順を件数の行の後ろに言います（例「全30語・五十音順」）。
- ページの中で補いに置く短い一覧（関連・おすすめ・連載・他のタイプ）には、操作もページ送りも件数の行も出しません（3-2）。

### 2-3. 畳み方とラベル

- `ListControls` は、開閉のボタン（`button[aria-expanded]` と T2 の `DisclosureTriangle`）と、操作の領域でできています。
  - **45rem 未満**: 初めは閉じています。
  - **45rem 以上**: 開閉のボタンを CSS で消し、領域をいつも出します。ラジオボタンの組は、選択肢を横に並べて折り返します（`RadioGroup` のいまの組み方）。
  - 閉じた状態は CSS のメディアクエリだけで隠します。サーバーの HTML と最初の描画が同じになり、読み込みのあとに一覧が動きません（CLS を出さない）。
  - `details` を使わないのは、広い画面でいつも開いた状態を、JS なしで、ずれなく作れないからです。
- ボタンの見える文言は「絞り込みと並び順（{条件}、{並び順}、{該当件数}{単位}）」とします。条件は次の順に「、」でつなぎます（値の中に「・」が現れるので、区切りに「・」を使わない）。
  - 名前の条件（「「json」を含む」）
  - 種別（選んでいなければ「すべて」）
  - 道具ごとの組の選択
  - 例: 「絞り込みと並び順（すべて、新しい順、86件）」「絞り込みと並び順（「みず」を含む、小学1年、学年順、3字）」
- 領域の中の順は、名前の欄（`Field`＋`Input type="search"`）→ 種別の `RadioGroup` → 道具ごとの組 → 並び順の `RadioGroup` です。種別の絞り込みはラジオボタン（1つを選ぶ）にします。ラベルに「いまの種別」を1語で言えるからです。

### 2-4. 件数の行（`ListStatus`）

- ボックスの上、`ListControls` の上に置き、畳んでも見えるようにします（§7 全体の件数）。
- 文の形は次のとおりです。
  - 絞り込みが無いとき: 「全86件」
  - 絞り込み中: 「12件（全86件）」
  - ページ送りがあるとき: 末尾に「のうち1〜50件目」を足す
  - 該当が0件のとき: 「条件に合う{単位}はありません（全N{単位}）」と、プライマリでないボタン「絞り込みを外す」
- `role="status"` にして、絞り込みで変わった件数を読み上げにも伝えます（§8）。
- クライアントでページを送ったあとは、この行にフォーカスを移し、行が画面の上に来るまでスクロールします（`tabindex="-1"`）。
  - フォーカスの移動とライブリージョンの読み上げが二重にならないかを、実装のレビューで読み上げを聞いて確かめます。二重になるなら、ページを送るときはライブリージョンの更新を抑えます。

### 2-5. 名前の絞り込み

- 字を打つたびに絞り込みます（送信のボタンは持たない）。IME の変換中（`compositionstart`〜`compositionend`）は掛けず、確定で掛けます。変換の途中の仮名で一覧が揺れないようにするためです。
- 正規化は NFKC・小文字化・片仮名から平仮名への寄せです。「すい」で音読みの「スイ」に、「JSON」で「json」に当たります。
- 何で探すかは一覧ごとに決め、欄のラベルでそれを言います（3-1 の表）。行に見えないもので探すときは、ラベルがそれを言います。
- `autocomplete="off"`・`enterkeyhint="search"` を付けます。

### 2-6. 並び順

- 並び順は、行に見えている値（名前・読み・種別・補助情報・色見本の色）で決めます（§7）。見えない値で並べると、来訪者は何の順かを確かめられないからです。
- 同じ値の中の順は、一覧ごとに見えている値で決めます（3-1 の表の括弧）。それでも同じなら、渡されたデータの順を保ちます（安定な並べ替え）。
- 読みで並べるときは、行に見えている最初の読みを平仮名にして比べます。漢字は、最初の音読み（音読みが無ければ最初の訓読み）です。

### 2-7. URL とページ送り

URL の組み方を比べて決めます。

| 案                                                          | JS なしでどのページの行も読める  | 状態を戻る・共有で復元できる | パスと中身の一致                | 複雑さ               |
| ----------------------------------------------------------- | -------------------------------- | ---------------------------- | ------------------------------- | -------------------- |
| A. クエリだけ（`?page=2&q=…`）                              | ×（静的な HTML は1ページ目だけ） | ○                            | ○                               | 小                   |
| B. パスだけ（状態をすべてパスに）                           | ○                                | ○                            | ○                               | 名前の条件を持てない |
| C. 既定の状態はパス、既定でない状態はクエリ。パスは変えない | ○                                | ○                            | ×（`/page/2` で絞ると食い違う） | 中                   |
| D. C と同じで、既定でない状態に入るとパスを元のパスに替える | ○                                | ○                            | ○                               | 中                   |

D にします。

- **既定の状態**（名前の条件が空・種別が「すべて」・並び順が既定）では、ページは URL のパス（`{元のパス}/page/{n}`）で、どのページも静的に生成します。
  - ページ送りは `Pagination` の link モードです。
  - 理由: JS の読み込みを待たずにどのページの行も読め、リンクとして開け、戻る・共有で同じページが出ます。
- **既定でない状態**は、範囲の全件からクライアントで組みます。状態は元のパスのクエリに持ちます。

  | 状態                           | クエリ                                     | 書き換え方                                                      |
  | ------------------------------ | ------------------------------------------ | --------------------------------------------------------------- |
  | 名前の条件                     | `q`                                        | `history.replaceState`（300ms 遅らせる）                        |
  | 種別                           | `kind`                                     | `history.replaceState`                                          |
  | 並び順                         | `sort`                                     | `history.replaceState`                                          |
  | 道具ごとの組                   | 組ごと（yoji-search は `level`・`origin`） | `history.replaceState`                                          |
  | ページ（既定でない状態のとき） | `page`                                     | `history.pushState`。ページ送りは `Pagination` の button モード |
  - `/blog/page/2` で絞り込むと、URL は `/blog?q=…` になり、中身は絞り込んだ結果の1ページ目です。見出しの「（2ページ目）」も消えます。
  - 絞り込みを外すと、URL は元のパスに、中身はその1ページ目に戻ります。
  - Next.js はネイティブの `pushState`・`replaceState` をルーターと同期させるので、再取得は起きません。パスを替える書き換えでも再取得が起きないことを、T3-4 のテストで確かめます。
  - 絞り込みと並び順を `replaceState` にするのは、戻るのボタンが打鍵のたびに一覧の中で止まらないようにするためです。

- **無限スクロールと「もっと見る」は持ちません**（§7）。
- **ページ送りは一覧の下だけに置きます。** 件数の行の近くにも置くと、375px で一覧を1行ぶん押し下げます。1ページが長い一覧で先のページを探す来訪者には、名前と種別の絞り込みが近道になります。
- **範囲外のページ番号**（`/blog/page/9`・`/page/0`・`/page/abc` など）は 404 にします（`dynamicParams = false`）。1ページ目へ送ると、Google はソフト 404 として扱うからです。
- **かつて存在したページ**は、その一覧の元のパスへ 308 で送ります。ブックマークと被リンクを失わないためです。対象は次の18本で、`next.config.ts` の redirects に並べます。
  - `/blog/page/3`〜`/blog/page/8`（6）
  - 分類の2ページ目から: dev-notes の2・3、ai-workflow の2、tool-guides の2（4）
  - タグの2ページ目から: Web開発の2・3、設計パターンの2・3、失敗と学び・Next.js・SEO・UI改善の2（8）
  - いまある `/tools/page/2` → `/tools` の 308 も残します。
- **`/page/1`** は、いまの `/blog` 系と同じく、どの一覧でも元のパスへ 308 で送ります。
- 2ページ目からの URL は、いまのブログのページ送りと同じく、sitemap に載せず、自分を canonical にします。
- `page` という名前のパスの区切りは、`[char]`・`[yoji]`・`[slug]` より優先されます。各辞典に `page` という見出し語・slug が無いことを、テストで確かめます。

### 2-8. 静的な HTML と、URL の状態の読み方

- `BrowsableList` は、URL のクエリを `useSearchParams` でなく `useSyncExternalStore` で読みます。
  - サーバーでの値は空（既定の状態）、クライアントでは `location.search` です。`popstate` と、自分で書き換えたときに購読を知らせます。
  - `useSearchParams` を使わないので、`Suspense` の境界も fallback も要りません。一覧は既定の状態でそのまま静的な HTML に入り、ハイドレーションは同じ DOM を引き継ぎます。
  - これで、件数の行・閉じた操作・そのページの行・ページ送りが HTML に入り、クエリの無い来訪では読み込みの前後で見た目が変わりません。
  - クエリのある URL に直に着いたときは、ハイドレーションのあとに状態が当たり、一覧が組み替わります。詳細から戻るときはクライアントの描画なので、最初から状態が当たった形で出ます。
  - 読み込みの前に欄に打った字は、ハイドレーションで消えることがあります。操作の枠は 375px では閉じていて、開くのにも JS が要るので、読み込みの前に字を打てる場面は 45rem 以上に限られます。受け入れます。
- 7章の道具も同じ読み方をします。いまの HTML にある結果の行は、そのまま HTML に残ります。
- 範囲の全件のデータは、サーバーからクライアントへ props として1回だけ渡します。行のデータは表示と絞り込みに要るものだけにし、href はクライアントで組める形（接頭辞＋鍵）にして小さくします。

### 2-9. 索引 `LinkIndex`

§7 の索引を `src/components/LinkIndex/` の1つの部品にします。

- `ul`/`li` で組みます。
- 語の数を、見出しか、包むアコーディオンのラベルに添えます（例「同じ部首の漢字（117字）」「部首から探す（198）」）。
- いまの分類は §6 の現在地にします（`aria-current="page"`）。
- 項目は縁の見えないコントロールで、押せる範囲を接して並べます（§5）。
- 一覧の上に置くときは、閉じた `Accordion`（`details`）に入れます。閉じていても索引のリンクは HTML にあるので、検索エンジンも分類のページを辿れます。

  - `/blog` の一覧の上の「タグで探す」（375px で y=571〜763 を占める）は外します。一覧を押し出すからです。
  - 下に置くのは、ブログの来訪者の多くが新しい記事を読みに来て、一覧そのものが主な入口だからです。辞典の分類の入口（次の項）とは役目が違います。

  - `/blog` の分類は §7 の種別です。

  - 意味（`meanings`）は英語の語なので、行には出しません（詳細には残す）。日本語の来訪者が字を見分けるのに要るのは読みです。

- **辞典の分類から探す入口は、一覧の上に閉じたアコーディオンで置きます（§7 索引）。**
  - 部首のページは直近12週で合わせて 476 PV あり、辞典のトップ3つ（46 PV）の10倍です。分類は、辞典を引く来訪者の主な入口です。

  - 辞典の分類のページ（学年・部首・画数・カテゴリ・色み）にも、同じ位置に同じアコーディオンを置き、いまの分類を現在地にします。いまの一覧の下の `FacetIndex` は、これに替わります。
  - 導入の文は、件数の行とアコーディオンが言うことを繰り返さない長さにします。漢字のトップはアコーディオンが3つあるので、375×667 と 1280×800 で最初の行が画面に入ることを、T3-7 で測って確かめます。
  - 比べた案: `ListControls` の中に分類のページへの組を置く案は、操作の枠を開くまで入口が見えず、ラベルが長くなります。件数の行の近くに索引へ飛ぶリンクを置く案は、飛んだ先が一覧の約1万px 下で、戻るのに送りが要ります。アコーディオンは入口がいつも見え、開いたその場で選べます。
- **分類のページ（学年・部首・画数・四字熟語と伝統色のカテゴリ・ブログの分類とタグ）は、それぞれが1つの範囲を持つ一覧です。** そのページの中で種別を替えて別の分類のページの中身に切り替えることはしません。
  - ページの見出し（「小学1年の漢字」）と中身がいつも一致します。
  - ページごとに渡すデータが、その分類の分だけで済みます。
  - 親の一覧で種別を選んだ状態（`?kind=`）の canonical は親の URL のままなので、分類のページと重複しません。
- **伝統色の「色み順」と「明るい順」は、色見本の色で並べます。** 色相と明度は数値では出しませんが、色見本の色として行に見えていて（§7）、並んだ色の移り変わりで何の順かが分かります。

1. **`/` を除くすべてのページに、`Breadcrumb` を上端のすぐ下に置きます。**
   - 2つ目の項目は、上端のナビと同じ名前の一覧（遊び・ツール・辞典・ブログ）にします。サイト紹介とプライバシーは「ホーム / サイト紹介」の形です。
   - いまパンくずを持たない `/tools` と、ブログのタグのページの自前の「ブログ / タグ」を、この部品にします。
   - 同じ働きのものを、どのページでも同じ位置に置くためです（§12）。
2. **一覧の名前を、ナビ・パンくず・一覧の見出しで1つにします。** `/play` の見出しとパンくずの「遊ぶ」を、上端のナビの「遊び」に揃えます。上端のナビ（遊び・ツール・辞典・ブログ）は名詞で揃っています。
3. **記事のパンくずに分類を入れます**（ホーム / ブログ / {分類} / {題名}）。分類の一覧に1つの操作で戻れるようにするためです。タグのページは「ホーム / ブログ / {タグ}」です。
4. **絞り込み・並び順・ページの状態を URL に持ちます**（2-7）。詳細から戻るのボタンで、元の状態に戻れます。
5. 辞典の詳細の学年・部首・画数・カテゴリのリンク（いまある）が、それぞれの分類の一覧へ戻る道になります。

## 6. B-574・B-599

- **読み上げの名前（B-574）**
  - 一覧の行は `ItemList` にし、名前だけをリンクの中身にします（1章）。
  - アコーディオンを行にする一覧（yoji-search・keigo-reference の 45rem 未満）は、`summary` の名前を語（普通語）の部分だけにします（`aria-labelledby`）。読み・意味・敬語の形は `aria-describedby` で説明として読ませます。見える文言は変えず、名前は見える文言の先頭と一致するので、声で押す来訪者も見えている語で押せます。
    - `summary` には対応する ARIA のロールが無く、Safari と VoiceOver で `aria-labelledby` が名前に使われるかは確かでありません。T3-9 で WebKit の読み上げの木を取って確かめます。効かなければ、行の開閉を `button[aria-expanded]` にして、同じ名前と説明を付けます。
  - traditional-color-palette の色見本のボタンの名前（「鴇 (#eea9a9)」）は、そのままにします。一覧の行ではなく、色の格子の1つで、カラーコードは読み上げで色を知る唯一の手段だからです。
- **同じ部首の一覧の構造（B-599）**
  - 同じ部首の漢字（最多117）と同じカテゴリの四字熟語（最多57）は、§7 の索引（`LinkIndex`、`ul`/`li`、見出しに件数）にします。
  - 同じカテゴリの伝統色は、`ItemList` にします。
  - 読み上げでリストとして扱われ、件数が伝わるようになります。
- **大字の二重読み（B-599）**
  - 漢字と四字熟語の詳細の大字（`span.character`）に `aria-hidden="true"` を付けます。直後の h1「漢字「水」」が同じ字を言うからです。
  - 伝統色の詳細の色見本は、効いていない `aria-label` を外して `aria-hidden="true"` にします。色の名前とカラーコードは本文の字が伝えています。
- **共有ボタンの外部予告（B-599）**
  - 3つの実装（`ShareButtons`・診断の `ShareButtons`・`GameShareButtons`）の文言と読み上げの名前を、`src/lib/share-labels.ts` の1か所から取ります。
  - 見える文言は「X でシェア」「LINE でシェア」「はてブに追加」です（空白の有無を揃える）。
  - 新しいタブで外部を開くものの名前は「{見える文言}（外部サイト・新しいタブで開く）」にします。はてブは、いまの形（はてなブックマーク・外部サイト・新しいタブで開く）を残します。
  - コピー・画像の保存・端末の共有シートを開くものには、予告を付けません。
  - 3つの部品を1つにまとめるのは、結果の組み方を決める T4 に任せます。

## 7. 絞り込みで一覧を押し出す道具

| 道具                      | 操作                                                                                      | 並び順                     | 件数の行                                          | ページ送り                                                               |
| ------------------------- | ----------------------------------------------------------------------------------------- | -------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------ |
| yoji-search               | `ListControls` に名前の欄・カテゴリ（種別）・難易度と出典（道具ごとの組）                 | 読みの五十音順／やさしい順 | 「全400語」「N語（全400語）」                     | 「もっと見る」をやめ、50件ずつの `Pagination`（button モード、`?page=`） |

- 3つとも、行の形（アコーディオンの行・表・色の格子）は道具の中身として残します。
  - 色の格子は色を並べて見比べることが価値で、1行1項目にするとその価値を失います。

- keigo-reference の並び順は、行に見えている普通語の五十音順を既定にします。データの並び（行く・来る・いる・する…）が使う頻度の順であることを、データの注記か作成の記録で確かめられたときだけ、それを「よく使う順」として既定にし、五十音順をほかの順にします（名前の付かない順を来訪者に見せない）。
- ラジオボタンの組で一覧を絞り込まない道具（inventory 5章の17本）は、対象にしません。

## 9. `DESIGN.md` との関係

この設計は、`DESIGN.md` §7 の規定に従います。

- 行の一覧は `ItemList`、索引は `LinkIndex` です。
- 行が持つもの（名前・読み・説明・種別・補助情報・色見本）は、§7「行の一覧」の規定のとおりです。
- 備えを出す条件（一覧のページ・10件を超える・種別が2つ以上・選ぶ理由のある並び順がほかにある）と、短い一覧が備えを持たないことは、§7「増え続けることへの備え」の規定のとおりです。
- 辞典の分類の入口を閉じたアコーディオンに入れて一覧の上に置くことと、ブログのタグの索引を一覧の下に置くことは、§7「索引」の規定のとおりです。
- 操作の枠の開閉は §6 のアコーディオン（太い線の三角と、読み上げの開閉の状態）です。
