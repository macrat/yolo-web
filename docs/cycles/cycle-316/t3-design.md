## 1. 行の一覧の部品 `ItemList`

### 1-1. 決定

§7 の行の一覧（ボックスの中に1行1項目）を `src/components/ItemList/` の1つの部品にします。サーバーでもクライアントでも描ける、フックを持たない部品です。

下の「持つもの」は、決定を伝えるための形の見本です。名前と細部は実装で決めます。

項目が持つもの:

- 名前（必須）。リンクの字で、読み上げの名前はこれだけになる
- 名前のリンク先（必須）。行の key を兼ねる
- 読み
- 説明。何ができるか・何であるかを言う短い文
- 種別。何の仲間かを言う一語
- 補助情報の並び。見える字と、日付なら ISO 8601 の値（`<time dateTime>` で包む）
- 色見本の色（主題が色の項目）

一覧が持つもの:

- 一覧の名前（見出しの id か、見出しが無いときの文）
- 番号の付いた一覧か（連載は `ol`）
- いま開いているページの項目。その行は §6 の現在地（太字・下線なし・リンクのまま・`aria-current="page"`）
- 来訪者自身の結果にあたる項目（解き終えた画面での来訪者のタイプ）。その行は §6 の来訪者の項目で、名前が太字で、押すと別のページへ移るので下線を残す（`aria-current="true"`）。来訪者のものであることは、呼び出し側がその項目の補助情報で「あなたのタイプ」のように文字で添える。`ItemList` はその行の補助情報を名前のリンクの説明（`aria-describedby`）につなぎ、Tab でリンクへ移った読み上げの利用者にも届ける
- ボックスを持つか。既定は持つ。結果のボックスや `Panel` の中では持たない形で描き、ボーダーを二重にしない（§8）

組み方は次のとおりです。

- **ボックス**: 見出し・件数・操作・ページ送りはボックスの外に置きます。
- **行の区切り**: ボックスのコンテンツ幅いっぱいの細い罫線で区切ります。
- **字の形**: 読み・種別・補助情報は §4 の補助情報の大きさ（`0.875rem`）で、`--ink-2` で組みます（§7）。
- **リンクと押せる範囲**: 行の中でリンクにするのは名前だけです。
  - 名前のリンクの `::after` で行全体を押せる範囲にします（`data-hit-area="after"`。hover の線とフォーカスのリングは T2 の規則で行全体に出ます）。
  - 読み・説明・種別・補助情報はリンクの外に置きます。これで読み上げの名前が行の名前だけになります（B-574）。
- **行の中に別のリンクを置かない**: §7 は行の中のリンクを認めていますが、この設計の一覧はどれも持ちません。行を目で追う速さを優先します（3-1 のブログのタグ）。
- **45rem 以上**:
  - 1行目は、左に色見本・名前・読み、右端に種別と補助情報を置きます。
  - 2行目は説明です。
- **45rem 未満**:
  - 名前の下・説明の上に、種別と補助情報の行が落ちます（§7）。
  - 色見本は、名前の行の左に置いた 32px の正方形で、細い線で囲みます（§5 色見本）。
- **並べ方**: `ul` で組み、連載だけ `ol` にします。行に見出し要素は置きません。行ごとに見出しを立てると、ページの見出しの構造（§5「セクションの頭に見出しが1つ」）に一覧の件数ぶんの見出しが混ざるからです。

## 2. 件数と備え

### 2-1. 部品の分け方

| 部品                     | 置き場所                                        | 役目                                                                                                                                           |
| ------------------------ | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/lib/list-browse.ts` | 純粋な関数                                      | 名前の絞り込み（正規化と一致の度合いを含む）・種別の絞り込み・並べ替え・ページの切り出し・URL のクエリとの読み書き・畳んだ枠のラベルの文を組む |
| `ListControls`           | `src/components/ListControls/`（クライアント）  | 名前の絞り込みの欄（畳まない）と、畳める枠（種別のラジオボタンの組・道具ごとの組・並び順のラジオボタンの組）。状態は親が持つ                   |
| `ListStatus`             | `src/components/ListStatus/`                    | 件数の行                                                                                                                                       |
| `BrowsableList`          | `src/components/BrowsableList/`（クライアント） | 一覧のページで使う組み合わせ。`ListStatus`＋`ListControls`＋`ItemList`＋`Pagination` と、URL の状態                                            |

`ListControls` と `ListStatus` を `BrowsableList` から分けるのは、7章の3つの道具が、§7 の2つの形の外にある一覧（開閉する行・色の格子・表）に同じ操作と件数の行を使うためです。

次の「持つもの」も形の見本で、名前と細部は実装で決めます。

`BrowsableList` が持つもの:

- 範囲の全件。各項目は `ItemList` の項目に、種別の値・名前の絞り込みで探す字（3-1 の表）・並び順ごとの比べる値を足したもの
- 一覧の名前（例「ツールの一覧」）と、件数の単位（「件」「字」「語」「色」）
- 名前の絞り込みの欄のラベル。何で探せるかを言う（3-1 の表）
- 種別の組の見出しと選択肢。「すべて」は部品が先頭に足す
- 並び順の選択肢。先頭が既定
- 1ページの件数・パスが示すページ・ページの URL の元（ページ n の URL は n=1 で元のパス、ほかは `{元のパス}/page/{n}`）

`ListControls` が持つもの:

- 名前の欄・種別の組・並び順の組の、それぞれの値と変わったときの処理
- 道具ごとの追加の組（yoji-search の難易度・出典など）と、その選択を言う語

`ListStatus` が持つもの:

- 全体の件数・該当件数・単位
- 選べる並び順が既定だけのとき、その並び順の名前
- ページ送りがあるとき、表示している範囲
- 読み上げに伝える件数の文（2-4）
- 該当が0件のときの「絞り込みを外す」の処理

### 2-2. 備えを出す条件

§7 に従い、次のように決めます。

- **全件の一覧**（集まりの全件を並べる一覧）は、件数にかかわらず件数を出します。一覧のページでは件数の行で、詳細や結果のページの中の全件の一覧（すべてのタイプ・連載）では一覧の見出しで言います。
- **選んだ一覧**（関連・おすすめ・トップと `/about`・404 の棚）は、件数も操作も出しません（3-2）。
- **詳細や結果のページの中にある一覧**は、全件の一覧（すべてのタイプ・連載）でも操作を出しません。来訪者がそこで項目を探すことはないからです（3-2）。
- **一覧のページ**（ツール・遊び・ブログ・各辞典の一覧と、その分類のページ）で、範囲が **10件を超える** ものは、次の操作を出します。10件以下なら、件数の行だけです。常用漢字の 2,136字のように数の決まった集まりでも、一覧のページなら同じです。
  - 名前の絞り込み。
  - 種別の絞り込み。次の2つを満たすときだけ出します。
    - 範囲の中に種別が **2つ以上** ある。1つしかないなら、行も種別を出しません（§7）。選択肢も、範囲の中に項目を持つ種別だけを出します。押すと必ず0件になる選択肢は、来訪者に何も見せないからです。
    - 一覧の上に、種別と同じ軸の索引を置かない。置くなら、その軸の一覧へは索引（3-1）で移ります（§7）。
  - 並び順の組。既定のほかに、来訪者が選ぶ理由のある並び順があるときだけ出します。行に種別を出さない一覧は、種別で並べる順を持ちません。組が無いときは、既定の並び順を件数の行の後ろに言います（例「全30語・五十音順」）。

### 2-3. 名前の欄と、畳む枠

名前の欄を畳むかどうかを、3案で比べて決めます。375×667 の見積もりは inventory 2-3・5章の実測から出しました。見えるラベルのある欄は、ラベルの行を含めて約100px です。

| 案                                        | 375px で名前で探し始めるまで                                              | 375px の最初の行の位置 | 位置の一定（§12）                    |
| ----------------------------------------- | ------------------------------------------------------------------------- | ---------------------- | ------------------------------------ |
| A. 名前の欄はいつも見せ、ほかの組を畳む   | 0手。欄が見えている                                                       | 畳む案より約100px 下   | 欄はどの一覧でも同じ位置             |
| B. すべてを畳む                           | 1手。畳んだ枠のラベルから、そこに検索があると読み取ってから開く必要がある | 最も上                 | 同じ                                 |
| C. 検索が主の面（道具・辞典）だけ欄を外に | 面によって 0手か1手                                                       | 面によって違う         | 欄の位置が面ごとに違い、§12 に反する |

A にします（§7「名前の欄と件数の行は畳まず、どの幅でもいつも見える」）。

- 一覧を押し出しているのはラジオボタンの組で、yoji-search では 292〜839 を占めます（inventory 5章）。名前の欄は1つで、押し出す量が小さいです。
- yoji-search と辞典のトップは、名前で探すことが主な使い道です。欄を畳むと、主な操作が最初の画面に無くなります（B-621）。
- 最初の行が画面に入るかは、8章の完了の条件で測って確かめます。

組み方は次のとおりです。

- 並びは、上から件数の行 → 名前の欄（`Field`＋`Input type="search"`）→ 畳む枠 → 一覧です。
- 畳む枠は、開閉のボタン（`button[aria-expanded]` と T2 の `DisclosureTriangle`）と、組の領域でできています。
  - **45rem 未満**: 初めは閉じています。
  - **45rem 以上**: 開閉のボタンを CSS で消し、領域をいつも出します。組どうしも横に並べ、収まらない組だけを次の段へ送ります（組が一覧を画面の外へ押し出さないため。§7）。組の中のラジオボタンは、選択肢を横に並べて折り返します（`RadioGroup` のいまの組み方）。
  - 閉じた状態は CSS のメディアクエリだけで隠します。サーバーの HTML と最初の描画が同じになり、読み込みのあとに一覧が動きません（CLS を出さない）。
  - `details` を使わないのは、広い画面でいつも開いた状態を、JS なしで、ずれなく作れないからです。
  - 畳む組が無い一覧（ユーモア辞典）は、枠を出しません。
- 領域の中の順は、種別の `RadioGroup` → 道具ごとの組 → 並び順の `RadioGroup` です。種別の絞り込みはラジオボタン（1つを選ぶ）にします。ラベルに「いまの種別」を1語で言えるからです。
- ボタンの見える文言は、畳んだ組のいまの選択を言います（§7）。
  - 組が並び順だけなら「並び順（{並び順}）」。
  - 絞り込みの組だけなら「絞り込み（{選択}）」（keigo-reference の分類）。並び順の組が無いので、ラベルは並び順を言いません。
  - 絞り込みの組と並び順の組があるなら「絞り込みと並び順（{選択}、{並び順}）」。選択は、絞っている組（「すべて」でない組）の値を、種別、道具ごとの組の順に「、」でつなぎます（値の中に「・」が現れるので、区切りに「・」を使わない）。どの組も絞っていなければ、選択は「すべて」の1語です。
  - 「すべて」のままの組を1つずつ言うと「すべて、すべて、すべて」のように並び、どれがどの組か読み分けられません。言わない組は「すべて」のままなので、ラベルは畳んだ組のいまの選択をすべて伝えています（§7）。
  - 例: 「並び順（新しい順）」「絞り込みと並び順（すべて、種別順）」「絞り込みと並び順（人生、初級、読みの五十音順）」（出典は「すべて」のまま）
  - 名前の条件と件数は、欄と件数の行がいつも見せているので、ラベルでは繰り返しません。

### 2-4. 件数の行（`ListStatus`）

- 名前の欄の上に置きます。畳む枠の外なので、どの幅でもいつも見えます（§7）。
- 文の形は次のとおりです。
  - 絞り込みが無いとき: 「全86件」
  - 絞り込み中: 「12件（全86件）」
  - 並び順の組が無いとき: 末尾に「・{並び順}」を足す（「全30語・五十音順」）
  - ページ送りがあるとき: 末尾に「のうち1〜50件目」を足す。表示している範囲が1件なら「のうち101件目」
  - 該当が0件のとき: 「条件に合う{単位}はありません（全N{単位}）」と、プライマリでないボタン「絞り込みを外す」
- 行は語の切れ目でだけ折ります。文を途中で折らない語（`white-space: nowrap` のインラインの `span`）に分けて並べ、語のあいだだけを折れる所にします。
  - 語は、数と単位（「全1,110字」「1,110字目」「（全86件）」）と、ほかの部分の文節（「のうち」「1,101〜」、並び順の「読みの」「五十音順」、0件の文の「条件に合う」「字は」「ありません」）です。並び順の前の「・」は行頭に置かない約物なので、前の語に付けます（「全10色・」「明るい順」）。並び順の語はどれも「○○順」か「○○の○○順」の形なので、「の」の後ろで文節に分けます。
  - 文字を大きくして読む来訪者が、「字／目」「明るい／順」「あ／りません」のように語の途中で割れた行や、1字だけの行を読まずに済むためです。
  - 句（「全1,110字のうち」「1,101〜1,110字目」）を `inline-block` で囲んでまとめて送る組み方は取りません。Chromium の読み上げの木で、段落と文のあいだに句ごとの `generic` が挟まり、`ariaSnapshot` も句のあいだに空白を入れて返すようになります。ページを送ったあとにフォーカスが移り、キーボードと読み上げの来訪者が最初に聞くこの行を、要素の境目で分けて読む読み上げソフトがあるからです。句でまとめないので、文字サイズ 200% の 320px でも、学年7の12ページ目の行は4行でなく3行（「全1,110字」「のうち1,101〜」「1,110字目」）で済みます。
- 絞り込みで変わった件数は、読み上げにも伝えます（§8）。伝えるのは、見えている行と別の、見えない `role="status"` の文です。
  - 見えている行をライブリージョンにすると、ページを送ったときに範囲の文の書き換えと行へのフォーカスの移動が重なり、同じ文を2度読みます。名前の欄に打つたびに途中の件数も読み上げの予約に積まれ、最後の件数に着くまで待たされます。
  - 読み上げの文は、範囲を含まない件数の文（「12件（全86件）」）です。ページを送っても替わりません。
  - 文を入れるのは、件数の文が前と変わったときだけです。同じ件数を聞かせても、来訪者に新しいことを伝えないからです。名前の条件は URL へ書くのと同じ遅れ（300ms）で落ち着いてから、種別は選んだときに、件数の文を前と比べます。並び順を変えても件数は変わらないので、文は入りません。種別でも、前と同じ件数になる選択では入りません。
  - 文を持つのは、来訪者が条件を変えて読み上げに渡したあとの 5秒だけで、ほかのときは空にしておきます。見えている行と同じ文を、ページを読み進める読み上げに2度読ませないためと、クエリのある URL に着いたときの組み替えで読ませないためです。
    - 5秒は、読み上げソフトが文を読み始める前に消えない長さです。`role="status"` は丁寧なライブリージョンなので、読み上げソフトは、打った字や IME の変換の読み上げを終えてから文を読みます。書き換えを受け取ってから読むまでに間があり、そのあいだに文が消えると、読まれないおそれがあります。打ち終えた字や変換した語の読み上げは長くても2〜3秒で終わると見積もり、その倍に近い余裕を取りました。実際の読み上げソフトでの長さは、この環境では測れないので、T3-11 で NVDA か VoiceOver を使える機会があれば聞いて確かめます。
    - 長くしすぎないのは、文が残っているあいだに一覧の頭から読み直すと、件数を2度聞くからです。件数の行は名前の欄の上にあり、欄から読み進めても着かないので、欄で打ち終えた来訪者が 5秒のうちに件数の行へ戻ることは少ないです。
    - 空に戻すことは読み上げに伝わりません。ライブリージョンは既定で、足された文と書き換わった文だけを読むからです。
  - 確かめ方: 読み上げのソフトを動かせない環境では、Chromium の読み上げの木（Playwright の `ariaSnapshot` と CDP の `Accessibility.getFullAXTree`）と、`MutationObserver` で数えた文の書き換えの回数を、操作の前後で記録します。
    - 着いたとき、見えている行は1つの `paragraph` で、その文は語のあいだに空白を挟まない1つの文として読める。`role="status"` の文は空である。
    - 名前の欄に2字を1字ずつ打つと、見えている行は2回替わり、`role="status"` の文は打ち終えて 300ms たってから1回だけ替わる。その 5秒後に空に戻り、読み上げの木には見えている行の件数の文が1つだけ残る。
    - 既定でない状態（`?sort=easy`）で「次へ」を押すと、見えている行が1回替わってフォーカスを受け、`role="status"` の文は1回も替わらない。link モードで送ったときも替わらない。
    - T3-4 の見本（`/storybook/list/101`）の 375px と 1280px の本番ビルドで、この3つが成り立つことを確かめました。
      - 着いたとき: `/storybook/list/101` は `paragraph: 全101語のうち1〜50語目`、`?q=一` は `paragraph: 36語（全101語）`、`/page/2` は `paragraph: 全101語のうち51〜100語目`。どれも `status` は空。
      - 「いっ」を 60ms おきに打つ: 見えている行は2回替わり、`status` は打ち始めから約 0.5秒で「9語（全101語）」へ1回替わり、その 5.0秒後に空に戻った（書き換えは合わせて2回）。文があるあいだの木は `paragraph: 9語（全101語）` → `status: 9語（全101語）`、空に戻ったあとは `paragraph: 9語（全101語）` → `status`（文なし）。
      - `?sort=easy` で「次へ」を Enter: 見えている行が1回替わって `paragraph: 全101語のうち51〜100語目` になり、フォーカスを受け、`status` は0回。link モードで送っても `status` は空のまま、フォーカスは件数の行。
    - `getFullAXTree` では、見えている行は `paragraph` の直下に語ごとの `StaticText` が並び、`generic` を挟まない（学年7の12ページ目は「全1,110字」「のうち」「1,101〜」「1,110字目」の4つ）。
  - 折り方の確かめ方: 件数の行の字を1字ずつ Range で行の位置を取って行ごとに集め、語の要素が2つ以上の行の箱に割れていないことと、ページも行も横に伸びないことを見ます。320px の既定と、320・360・375・414・480px の文字サイズ 200%（CDP の `Page.setFontSizes` で既定を 32px）で、ブログ（`/blog/page/2`・0件）・漢字（トップ・学年7の12ページ目・23画・0件）・四字熟語（トップ・0件）・伝統色（無彩色の「全10色・明るい順」・0件）・ユーモア辞典（「全30語・五十音順」・0件）の12ページを測り、語の途中の折れは72通りのどれにも無く、横に伸びたものもありませんでした。`ariaSnapshot` は72通りのどれでも、空白を挟まない1行の `paragraph`（「`paragraph: 全10色・明るい順`」「`paragraph: 条件に合う字はありません（全2,136字）`」など）でした。320px・200% の折れ方は次のとおりです。

    | ページ            | 320px・200% の行                                     |
    | ----------------- | ---------------------------------------------------- |
    | 学年7の12ページ目 | 「全1,110字」「のうち1,101〜」「1,110字目」          |
    | ブログの2ページ目 | 「全86件のうち」「51〜86件目」                       |
    | 無彩色            | 「全10色・」「明るい順」                             |
    | ユーモア辞典      | 「全30語・」「五十音順」                             |
    | 23画              | 「全1字・読みの」「五十音順」                        |
    | 0件（漢字）       | 「条件に合う字は」「ありません」「（全2,136字）」    |
    | 0件（ブログ）     | 「条件に合う」「ものは」「ありません」「（全86件）」 |

- ページを送ったあとは、この行にフォーカスを移し、行が画面の上に来るまでスクロールします（`tabindex="-1"`）。キーボードと読み上げの来訪者が、送った先で一覧の頭を探し直さずに済むようにするためです。ページ送りの2つのモードのどちらでも同じです。
  - 行は、縁の見えないコントロールと同じ §5 の字の箱（字の左右に 8px。`data-text-box="inline"`）を持って左へ張り出し、二重リングをその内側に出します（§6）。字の左端は名前の欄と揃ったままで、リングは一覧の上のほかのコントロールのリングと同じ位置に出ます。字の外にリングを出すと、行がコンテンツ幅の外まで太い線で囲まれ、ボックスに見えるからです。
  - **button モード**（既定でない状態）: 同じ `BrowsableList` の中でページが替わるので、替わったあとに移します。T2 の `PaginationButtons` は、端で押した項目が消えたときにいまのページへフォーカスを戻します。どちらが最後に効くかを T3-4 で件数の行にそろえます。
  - **link モード**（既定の状態）: `next/link` の遷移で、`BrowsableList` は行き先のページで作り直され、押したリンクは消えます。ページ送りのリンクを押したときに、行き先のパスをモジュールの変数に記録し、行き先で作り直された `BrowsableList` は、そのパスがいまのパスと同じときだけ件数の行へフォーカスを移して記録を消します。
    - Next.js 16.3 のルーターは、遷移のあとに新しいセグメントの先頭の要素へスクロールし、その要素に `focus()` を呼びます（`layout-router.js` の `handlePotentialScroll`）。この処理はクラスのコンポーネントの `componentDidMount`・`componentDidUpdate` で、描画を確定する段で走ります。件数の行へ移す処理は `useEffect` に置き、この処理のあとに走らせます。件数の行へのフォーカスとスクロールが残ることを、T3-4 で確かめます。
  - ほかのページから一覧のページを開いたとき・URL を直に開いたときは、記録が無いので移しません。ほかのページへの遷移と同じく、上端とパンくずから順に辿ります。
- 「絞り込みを外す」を押すと、該当が0件でなくなってボタンが消えるので、フォーカスを名前の欄へ移します。外したあとの来訪者の次の操作は探し直しで、欄に打てばそのまま一覧が絞られます。該当が0件になるのは、たいてい欄に打った名前が当たらなかったときで、そのとき来訪者は欄で打っていたところです。名前の欄を持たない10件以下の一覧では、件数の行へ移します。

### 2-5. 名前の絞り込み

- 字を打つたびに絞り込みます（送信のボタンは持たない）。IME の変換中（`compositionstart`〜`compositionend`）は掛けず、確定で掛けます。変換の途中の仮名で一覧が揺れないようにするためです。
- 正規化は NFKC・小文字化・片仮名から平仮名への寄せです。「すい」で音読みの「スイ」に、「JSON」で「json」に当たります。
- 何で探すかは一覧ごとに決め、欄のラベルでそれを言います（3-1 の表）。行に見えない値でも探すなら、ラベルがそれを言います（§7）。
- 絞り込んでいる間は、一致の近い順に並べます（§7）。
  - 度合いは、名前か読みが打った字と一致する → 打った字で始まる → 打った字を含む → 名前と読みでは当たらず、ほかの値（説明・タグ・熟語・例文など）で当たる、の4段です。説明のように行に見えている値でだけ当たったものも、4段目です。
  - 同じ度合いの中は、選んでいる並び順に従います。
  - 漢字の一覧で「水」と打つと、字が「水」の行が先頭に来て、熟語に「水」を含む字はその後ろに並びます。
- `autocomplete="off"`・`enterkeyhint="search"` を付けます。

### 2-6. 並び順

- 並び順は、行に見えている値（名前・読み・種別・補助情報・色見本の色）で決めます（§7）。見えない値で並べると、来訪者は何の順かを確かめられないからです。
- 同じ値の中の順は、一覧ごとに見えている値で決めます（3-1 の表の括弧）。それでも同じなら、渡されたデータの順を保ちます（安定な並べ替え。§7「見えている値が同じ項目どうしは、渡された順のまま」）。
- 読みで並べるときは、行に見えている最初の読みを平仮名にして比べます。漢字は、最初の音読み（音読みが無ければ最初の訓読み）です。
  - 並びは国語辞典の五十音順で、3段で比べます。「がりょうてんせい」は「かんぜんむけつ」の前に来ます。辞書の感覚で「が」の語を「か」の近くに探す来訪者が、そこで見つけられるようにするためです。
    - 1段目: 濁点・半濁点を外し、小書きの仮名を並の仮名に寄せ、長音符を直前の仮名の母音にした形。
    - 2段目: 1段目が同じ語どうしで、語全体の濁点を比べる。字ごとに清音 → 濁音 → 半濁音の順。
    - 3段目: 2段目も同じ語どうしで、語全体の長音符・小書きを比べる。字ごとに長音符 → 小書き → 並の順。
    - 濁点の差を、長音符や小書きの差より先に語全体で比べるので、違いの出た位置が前でも、長音符や小書きの差は濁点の差に負けます。「はーと・はあと・はあど」「きつか・きっが」の順です。
  - サーバーとクライアントで同じ結果を出すため、ロケールに依存する `Intl.Collator` は使わず、`list-browse.ts` で比べる形を作ります。四字熟語の全件の読みと、上の境目の語で `Intl.Collator("ja")` と同じ順になることを、単体テストで確かめます。漢字の最初の読み（2,136字）・訓読み（2,411語）でも同じ順になることを確かめました。
- 色見本の色で並べるときは、カラーコードを OKLCH にした値で比べます。色相は h、明るさは L です。HSL の L は目で見た明るさの順にならない（純粋な黄と青がどちらも 50%）ので使いません。色相を持たない無彩色は、色相の代わりに明るさで並べます。

### 2-7. URL とページ送り

URL の組み方を比べて決めます。

| 案                                                          | JS なしでどのページの行も読める  | 状態を戻る・共有で復元できる | パスと中身の一致                | 複雑さ               |
| ----------------------------------------------------------- | -------------------------------- | ---------------------------- | ------------------------------- | -------------------- |
| A. クエリだけ（`?page=2&q=…`）                              | ×（静的な HTML は1ページ目だけ） | ○                            | ○                               | 小                   |
| B. パスだけ（状態をすべてパスに）                           | ○                                | ○                            | ○                               | 名前の条件を持てない |
| C. 既定の状態はパス、既定でない状態はクエリ。パスは変えない | ○                                | ○                            | ×（`/page/2` で絞ると食い違う） | 中                   |
| D. C と同じで、既定でない状態に入るとパスを元のパスに替える | ○                                | ○                            | ○                               | 中                   |

D にします。

- **既定の状態**（名前の条件が空・種別が「すべて」・並び順が既定）では、ページは URL のパス（`{元のパス}/page/{n}`）で、どのページも静的に生成します。
  - ページ送りは `Pagination` の link モードです。
  - 理由: JS の読み込みを待たずにどのページの行も読め、リンクとして開け、戻る・共有で同じページが出ます。
- **既定でない状態**は、範囲の全件からクライアントで組みます。状態は元のパスのクエリに持ちます。

  | 状態                           | クエリ                                     | 書き換え方                                                      |
  | ------------------------------ | ------------------------------------------ | --------------------------------------------------------------- |
  | 名前の条件                     | `q`                                        | `history.replaceState`（300ms 遅らせる）                        |
  | 種別                           | `kind`                                     | `history.replaceState`                                          |
  | 並び順                         | `sort`                                     | `history.replaceState`                                          |
  | 道具ごとの組                   | 組ごと（yoji-search は `level`・`origin`） | `history.replaceState`                                          |
  | ページ（既定でない状態のとき） | `page`                                     | `history.pushState`。ページ送りは `Pagination` の button モード |
  - `/blog/page/2` で絞り込むと、URL は `/blog?q=…` になり、中身は絞り込んだ結果の1ページ目です。
  - 絞り込みを外すと、URL は元のパスに、中身はその1ページ目に戻ります。
  - Next.js はネイティブの `pushState`・`replaceState` をルーターと同期させるので、再取得は起きません。そのかわり、いまの木がそのまま残ります。`/blog/page/2` の `BrowsableList` は、パスが `/blog` に替わったあとも、props の「パスが示すページ＝2」を持ったままです。そこで、表示するページは props でなく、そのときの URL のパスとクエリから決めます。パスを替える書き換えで再取得が起きないことと、替えたあとの表示のページを、T3-4 のテストで確かめます。
  - `replaceState` では `<title>` が替わらないので、既定でない状態に入るときに `document.title` を元のパスの題（「（2ページ目）」の無いもの）に替えます。タブと履歴の名前が中身と食い違わないようにするためです。
  - 絞り込みと並び順を `replaceState` にするのは、戻るのボタンが打鍵のたびに一覧の中で止まらないようにするためです。

- **無限スクロールと「もっと見る」は持ちません**（§7）。
- **ページ送りは一覧の下だけに置きます。** 件数の行の近くにも置くと、375px で一覧を1行ぶん押し下げます。1ページが長い一覧で先のページを探す来訪者には、名前の絞り込みが近道になります。
- **範囲外のページ番号**（いまのページの数を超える番号・`/page/0`・`/page/abc` など）は 404 にします（`dynamicParams = false`）。
  - 1ページ目へ送ると、Google はソフト 404 として扱うからです。
  - 12件ずつのときにだけあったページ（`/blog/page/3`〜`8` など18本）も、範囲外として 404 になります。12週で合わせて 13 PV です（0章）。
  - かつてのページを 308 で送る一覧は持ちません。Next.js の redirects はページより先に判定される（`redirects.md`「Redirects are checked before the filesystem which includes pages」）ので、一覧が育ってその番号が本物のページになったとき、固定の送り先がそのページを隠します。
  - いまの `/tools/page/[page]`（`/tools` へ 308 で送る route）は、共通の経路に替えます。36本は1ページなので、`/tools/page/2` は 404 になり、51本目で本物のページになります。
- **`/page/1`** は、いまの `/blog` 系と同じく、どの一覧でも元のパスへ 308 で送ります（`next.config.ts`）。1ページ目はいつも元のパスなので、本物のページにはなりません。
- 2ページ目からの URL は、いまのブログのページ送りと同じく、sitemap に載せず、自分を canonical にします。
- `page` という名前のパスの区切りは、`[char]`・`[yoji]`・`[slug]` より優先されます。辞典の見出し語とブログの記事の slug に `page` が無いことを、テストで確かめます。

### 2-8. 静的な HTML と、URL の状態の読み方

- `BrowsableList` は、URL のクエリを `useSearchParams` でなく `useSyncExternalStore` で読みます。
  - サーバーでの値は空（既定の状態）、クライアントでは `location.search` です。`popstate` と、自分で書き換えたときに購読を知らせます。
  - `useSearchParams` を使わないので、`Suspense` の境界も fallback も要りません。一覧は既定の状態でそのまま静的な HTML に入り、ハイドレーションは同じ DOM を引き継ぎます。
  - これで、件数の行・名前の欄・閉じた枠・そのページの行・ページ送りが HTML に入り、クエリの無い来訪では読み込みの前後で見た目が変わりません。
  - クエリのある URL に直に着いたときは、ハイドレーションのあとに状態が当たり、一覧が組み替わります。詳細から戻るときはクライアントの描画なので、最初から状態が当たった形で出ます。
- 名前の欄の値は、URL でなく部品の中に持ちます。URL へは 300ms 遅れて書くので、欄を URL から描くと、打った字が遅れて出たり消えたりするからです。
  - 欄は、ハイドレーションのときに DOM に入っている値を初めの値として読みます。名前の欄はどの幅でもいつも見えていて、読み込みの前に打った字を消さないためです。
- 7章の道具も同じ読み方をします。いまの HTML にある結果の行は、そのまま HTML に残ります。
- 範囲の全件のデータは、サーバーからクライアントへ props として1回だけ渡します。行のデータは表示と絞り込みに要るものだけにし、href はクライアントで組める形（接頭辞＋鍵）にして小さくします。

### 2-9. 索引 `LinkIndex`

§7 の索引を `src/components/LinkIndex/` の1つの部品にします。

- `ul`/`li` で組みます。区切りの見出しを持つ索引は、区切りごとに見出しと `ul` を置きます。
- 語の数を、見出しか、包むアコーディオンのラベルに添えます（例「同じ部首の漢字（117字）」「部首から探す（198）」）。
- 順を持たない分類の語には、後ろに属する項目の数を添えます（「Web開発（35）」）。
- 見出し・ラベル・語の名前と、添えた数の括弧は、それぞれ1つのまとまりにし、そのあいだでだけ折ります。1行に収まらなければ始め括弧の前で折ります（§4。「部首／（198）」「対立・闘い／（26）」）。
  - アコーディオンのラベルの語の切れ目は、呼び出し側が渡します（「色みから」「探す」）。データは各一覧の組み立て（`*-list.ts`）が持ち、`ListPage` の見出しの意味の切れ目と同じ形です。ブラウザや ICU の分かち書きに任せると、「色み」を「色」「み」に割り、実行環境の辞書の版で切れ目が変わるからです。
  - 索引の見出しの名前（「学年」「部首」）と索引の語は、それぞれ1語として扱います。
- いまの分類は §6 の現在地にします（`aria-current="page"`）。
- 項目は縁の見えないコントロールで、押せる範囲を接して並べます（§5）。
- 一覧の上に置くときは、閉じた `Accordion`（`details`）に入れます。閉じていても索引のリンクは HTML にあるので、検索エンジンも分類のページを辿れます。
- 索引の名前は1か所だけが言います。
  - 区切りを持たない索引は、`ul` が索引の見出しかラベルを名前に持ちます。
  - 区切りを持つ索引は、区切りの `ul` がそれぞれの区切りの見出しを名前に持ち、全体を包むものには名前を付けません。索引の名前は、すぐ上の索引の見出しかアコーディオンのラベルが言います（§7「語の数が見える」）。包むものや、置いた `section` にも同じ名前を付けると、読み上げで同じ名前を3度聞き、詳細のページのランドマークにこの索引だけが出るからです。
- 区切りの見出しは、§7 のとおりセクションの中の小見出しです。
  - 大きさは §4 の小見出しの段（`h3` の既定と同じ `--text-heading-sub`）で、画面幅とともに段が下がります。
  - 区切りを持つ索引は、いつも索引の見出しかアコーディオンのラベルのすぐ下に置きます。上の細い罫線（§5）は `LinkIndex` が引き、最初の区切りは前に分ける内容を持たないので、2つ目の区切りから引きます。
- 語がどれも漢字1字の索引（同じ部首の漢字）は、字をリンクの本文の書体のまま、§4 の段の2段目（`1.49rem`）の大きさで組みます。字の形を見て選ぶ場面で（§7「語だけを見て選べる」）、「濯」「瀬」「濃」のように画数の多い字が並ぶからです。単字の押せる範囲は 44px に届くまで広げてあり、既定の文字サイズでは `1.49rem` の字でも 44px に収まるので、1行に入る字の数は本文の大きさのときと変わりません。
  - 区切りの見出しは `max(--text-heading-sub, 1.49rem)` で組み、字より小さくしません。`45rem` 未満では小見出しの段が本文の大きさ（17px）まで下がり、「5画」の見出しがその下の 24px の字に埋もれるからです。漢字「水」の詳細で、区切りの見出しと字は 320・375・800px でどちらも 23.84px、1280px で見出しが 33.28px・字が 23.84px でした。文字サイズ 200% では、320・1280px でどちらも 47.68px で、ページも要素も横に伸びませんでした。
  - `45rem` 未満では、区切りの見出しが §4 のセクションの見出し（`1.49rem`）と同じ大きさになります。漢字と四字熟語の詳細のセクションの見出しは、T5 で §4 の段にそろえます。親子は大きさでなく罫線で見分けます（§7）。セクションの見出しは上に全幅の罫線を持ち、最初の区切りの見出しは線を持たずにそのすぐ下に続き、2つ目からの区切りの見出しは上に細い罫線を持ちます。形は変えません。117字の索引の中で「5画」「6画」を拾う場面には、区切りの見出しが字と同じ大きさで立つ形が合っているからです。

決定と理由:

- **ツールと遊びは、棚をやめて1つの一覧にします。** 種別を各行に一語で出し、既定の並び順を種別順にします。
  - 種別の絞り込みでいまの棚と同じ見方ができ、新しい順で戻ってきた来訪者が新しいものを見つけられます。一覧のページの PV は小さく（12週で `/tools` 30・`/play` 124）、棚の見方は種別の絞り込みで残るので、失うものは小さいです。
  - 名前順は持ちません。ツール名・遊びの名前は読みのデータを持たず、字の順は五十音順にならないからです。
  - 公開日を補助情報に出すのは、新しい順の並びが見えるようにするためです（2-6）。36本のうち30本は公開日が 2026-02-13〜14 に集まるので、同じ日付の中は渡されたデータの順のままです（2-6）。
  - ツールの種別は、**何を扱うか**の1つの軸で、次の5語にします。いまのデータの分類（text・generator・security・developer・encoding）は、用途（開発）と働き（生成・エンコード）の軸が混ざり、「計算・生成」「パスワードとハッシュ」のように一語にもならないので、ツールの `meta.ts` の分類と `ToolCategory` をこの5つに替えます。
    - 働き（変換・計算・生成）で分けると、「変換」で絞った来訪者が、名前に「変換」を持つのに別の種別に入ったツールを見落とします。扱うものの軸なら、ツールはどれも1つの種別に迷わず入ります。
    - 働きで探す来訪者は、名前の絞り込みで着きます。働きはツール名に入っているからです（「変換」と打つと、名前に「変換」を持つ10本が出る）。

    | 種別（種別順） | ツール                                                                                                                                                                                          |
    | -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
    | 文章（11）     | char-count・byte-counter・text-diff・text-replace・fullwidth-converter・kana-converter・line-break-remover・dummy-text・business-email・keigo-reference・yoji-search                            |
    | 数値（7）      | age-calculator・bmi-calculator・percent-calculator・date-calculator・unit-converter・number-base-converter・unix-timestamp                                                                      |
    | データ（13）   | json-formatter・yaml-formatter・sql-formatter・csv-converter・markdown-preview・regex-tester・cron-parser・email-validator・base64・url-encode・html-entity・hash-generator・password-generator |
    | 画像（3）      | image-base64・image-resizer・qr-code                                                                                                                                                            |
    | 色（2）        | color-converter・traditional-color-palette                                                                                                                                                      |

- **ブログの行から、タグのリンクと「新着」の印を外します。読了時間は補助情報に残します。**
  - タグのリンクは、§7 のとおり行の中で独立に押せる形でも持てます。それでも外すのは、1行に3〜5個のリンクが並び、題名を縦に目で追う速さが落ちるからです。タグで辿る道は、一覧の上の索引が受け持ちます（下の項）。
  - 「新着」は名前のリンクの中にあり、読み上げの名前を変えます（B-574）。新しい順の既定と公開日で同じことが分かります。
  - 読了時間は、時間の限られた来訪者が記事を選ぶ材料になります。補助情報の短い値なので、行を目で追う速さはほとんど落ちません。
- **ブログの分類とタグは、一覧の上の索引で辿ります。**
  - ブログの一覧のページ（`/blog`・分類・タグ）は、どれも同じ位置に閉じたアコーディオン「分類・タグから探す」を置きます。開くと、見出し「分類（5）」の索引と見出し「タグ（29）」の索引が並びます。見出しの括弧は語の数です（§7「語の数が見える」）。いまの分類・タグは現在地です。
  - 分類もタグも順を持たないので、記事の多い順に並べ、語の後ろに記事の数を添えます（§7）。
  - `/blog` とタグのページの行には分類が種別として出ますが、一覧の上に分類の索引を置くので、分類のラジオボタンの組は置きません（§7）。同じ「dev-notes」を押して、その場で絞るものと分類のページへ移るものが並ばないようにするためです。分類で見たい来訪者は、索引から分類のページへ移ります。
  - タグのページには来訪があります（12週で合わせて 59 PV）。いま `/blog` の一覧の上にある「タグで探す」（375px で y=571〜763 を占める）は、開いたまま並んで一覧を押し出しているので、閉じたアコーディオンに入れます。
  - 分類のページ（`/blog/category/*`）は、検索と記事のパンくずからの入口として残し、その分類の範囲の一覧にします。
- **漢字の行は、字に音訓を読みとして添え、説明を持ちません。**
  - 意味（`meanings`）は英語の語なので、行には出しません（詳細には残す）。日本語の来訪者が字を見分けるのに要るのは読みです。
  - 音訓は、同じ読みを1つにまとめてから出します（「生」の「なま・なま」を出さない）。
  - 英語の意味は探す字にも入れません。日本語の来訪者は英語で漢字を探さないからです。
- **辞典のトップ（漢字・四字熟語・伝統色）は、いまの `DictionarySearch`（空の入力では何も出さない、最大100件）を、全件の一覧に替えます。** 着いた来訪者に最初から中身が見え、HTML に行が入ります。名前の欄はいつも見えているので、名前で引く来訪者はいまと同じく欄から始められます。
- **辞典の分類から探す入口は、一覧の上に閉じたアコーディオンで置きます（§7 索引）。**
  - 部首のページは12週で合わせて 476 PV あり、辞典のトップ3つ（43 PV）の10倍です。分類は、辞典を引く来訪者の主な入口です。
  - 各辞典のアコーディオンは次のとおりです。1つの辞典に1つにし、閉じた枠が一覧を押し出す量を 44px に抑えます。

    | 辞典     | アコーディオン               | 中の索引                                                                                                           |
    | -------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------ |
    | 漢字     | 「学年・画数・部首から探す」 | 「学年（7）」は学年の順、「画数（24）」は画数の順、「部首（198）」は部首の画数ごとの区切りの見出しつきで最後に置く |
    | 四字熟語 | 「カテゴリから探す（10）」   | 語の多い順で、語の後ろに数                                                                                         |
    | 伝統色   | 「色みから探す（7）」        | 赤系から無彩色までの色相の順                                                                                       |

  - 置く場所は、見出しと導入の文の下、件数の行の上です。
  - 辞典の分類のページ（学年・部首・画数・カテゴリ・色み）にも、同じ位置に同じアコーディオンを置き、いまの分類を現在地にします。いまの一覧の下の `FacetIndex` は、これに替わります。
  - 学年・カテゴリ・色みは、一覧の上の索引に入っているので、種別のラジオボタンの組を置きません（§7）。行には種別として出し、種別の順で並べられます。部首と画数のページでは、学年の索引はその部首・画数の中を絞らず、学年のページへ移します。その部首の中を学年で見たい来訪者は、学年順に並べ替えます。
  - 一覧の下には置きません。索引の置き場所は §7 が1つに決めていて、同じページに198語の索引が2つあると、読み上げとキーボードで同じリンクを2度通ることになるからです。100行を読み終えた来訪者は、ページ送りを押せば件数の行（アコーディオンのすぐ下）にフォーカスが移り、ほかの分類へ移るときもそこから開けます。
  - 導入の文は、件数の行とアコーディオンと名前の欄のラベルが言うことを繰り返さず、一覧と詳細のページで何が分かるかを言います（伝統色は「色見本とカラーコードを並べ、色のページでは RGB・HSL もコピーできます。」）。375×667 と 1280×800 で最初の行の全体が画面に入ることを、T3-7・T3-8 で測って確かめます。
  - 比べた案: `ListControls` の中に分類のページへの組を置く案は、操作の枠を開くまで入口が見えず、ラベルが長くなります。件数の行の近くに索引へ飛ぶリンクを置く案は、飛んだ先が一覧の約1万px 下で、戻るのに送りが要ります。アコーディオンは入口がいつも見え、開いたその場で選べます。
- **分類のページ（学年・部首・画数・四字熟語と伝統色のカテゴリ・ブログの分類とタグ）は、それぞれが1つの範囲を持つ一覧です。** そのページの中で種別を替えて別の分類のページの中身に切り替えることはしません。
  - ページの見出し（「小学1年の漢字」）と中身がいつも一致します。
  - ページごとに渡すデータが、その分類の分だけで済みます。
- **伝統色の並び順は、色見本の色を OKLCH にした値で比べます（2-6）。**
  - 色相と明度は数値では出しませんが、色見本の色として行に見えていて（§7）、並んだ色の移り変わりで何の順かが分かります。
  - 「色み順」は、色みの順（赤系 → 橙系 → 黄系 → 緑系 → 青系 → 紫系 → 無彩色）で、同じ色みの中は色相の順です。無彩色は色相を持たないので、明るい順です。
  - 有彩色の色みにも、ほとんど色を持たない色があります。OKLCH の C が **0.015** に満たない色は色相を持たないものとして扱い、トップの色み順でも色みのページの色相順でも、その色みの最後に明るい順で置きます。
    - その色相は測れても目には見えず、色相で並べると前後の色とつながらないからです（ほぼ黒の黒橡が露草と勿忘草のあいだに、ほぼ白の白練が菜種油と刈安のあいだに挟まっていました）。
    - 0.015 は、250色の C を並べて決めました。無彩色の色みの色はどれも 0.0122 以下で、有彩色の色みでは銀鼠（0.0131）と、目に緑みの灰と分かる利休鼠（0.0187）のあいだが最も大きくあきます。そのあいだに置くので、当たるのは胡粉・白鼠・黒橡・白練・溝鼠・銀鼠の6色です。
    - 色みのデータそのものを無彩色へ直す案は、データの見直しになるので取りません。行の種別は色みのデータのまま出し、並びだけを目に見える色の流れに合わせます。
  - 「明るい順」は、L の大きい順です。淡い色・濃い色を探す来訪者が選びます。
- **伝統色の名前の欄は、色名・ローマ字・カラーコードで探し、仮名の読みでは探しません。** ラベルもそう言います。
  - データ（`traditional-colors.json`）は仮名の読みを持たず、行の読みはローマ字です。
  - ローマ字から仮名の読みは確実に作れません。長音を落とした綴り（「kikyo」桔梗・「gunjyo」群青・「kanzo」萱草・「rikyu」利休）、長音の「oh」と「ho」の取り違え（「tohoh」籐黄）、仮名に戻せない綴り（「veludo」ビロード・「tonocha2」沈香茶）があり、250色のうち約20色で正しい読みにならないからです。正しい読みで打った来訪者がその色だけ見つけられない形になるので、作った読みは探す字に足しません。
- **`/dictionary` の行は、辞典ごとの収録数（「2,136字」「400語」「250色」「30語」）を補助情報に持ちます。** 辞典の規模を比べて選ぶ手がかりになるからです（§7）。
  - 見出しの下の文は、4つの辞典のどれにも当てはまることだけを言います（「漢字・四字熟語・日本の伝統色を引ける辞典と、AIが作ったユーモア辞典です。」）。伝統色は読みも由来も持たず、ユーモア辞典の定義は本当の意味ではないので、何がどの辞典にあるかは行の説明に任せます。

## 6. B-574・B-599

- **読み上げの名前（B-574）**
  - 一覧の行は `ItemList` にし、名前だけをリンクの中身にします（1章）。
  - アコーディオンを行にする一覧（yoji-search・keigo-reference の 45rem 未満）は、行の開閉を `button[aria-expanded]` にし、名前を語（普通語）の部分だけにします（`aria-labelledby`）。読み・種別・意味・敬語の形は `aria-describedby` で説明として読ませます。見える文言は変えず、名前は見える文言の先頭と一致するので、声で押す来訪者も見えている語で押せます。
    - `summary` を使わないのは、対応する ARIA のロールが無く、Safari と VoiceOver で `aria-labelledby` が名前に使われるかが確かでないからです。`button` の名前が `aria-labelledby` で決まることは accname の仕様どおりで、ブラウザごとの差が出にくいです。
  - keigo-reference の広い画面の表で行を開くボタン（行見出しの `th scope="row"` の中）も、名前を普通語だけにします。同じ行が幅によって別の名前にならず、行見出しとして読まれる名前も普通語になります。開閉の状態は `aria-expanded` が伝えます。
  - traditional-color-palette の色見本のボタンの名前（「鴇 (#eea9a9)」）は、そのままにします。一覧の行ではなく、色の格子の1つで、カラーコードは読み上げで色を知る唯一の手段だからです。
- **同じ部首の一覧の構造（B-599）**
  - 同じ部首の漢字（最多117）と同じカテゴリの四字熟語（最多57）は、§7 の索引（`LinkIndex`、`ul`/`li`、見出しに件数）にします。
  - 並びは、来訪者が順を読み取れるように区切りの見出しを立てます（§7）。同じ部首の漢字は画数ごと、同じカテゴリの四字熟語は難易度ごと（初級・中級・上級）です。区切りの中は、渡されたデータの順です。
  - 同じカテゴリの伝統色は、`ItemList` にします。
  - 読み上げでリストとして扱われ、件数が伝わるようになります。
- **大字の二重読み（B-599）**
  - 漢字と四字熟語の詳細の大字（`span.character`）に `aria-hidden="true"` を付けます。直後の h1「漢字「水」」が同じ字を言うからです。
  - 伝統色の詳細の色見本は、効いていない `aria-label` を外して `aria-hidden="true"` にします。色の名前とカラーコードは本文の字が伝えています。
- **共有ボタンの外部予告（B-599）**
  - 3つの実装（`ShareButtons`・診断の `ShareButtons`・`GameShareButtons`）の文言と読み上げの名前を、`src/lib/share-labels.ts` の1か所から取ります。
  - 見える文言は「X でシェア」「LINE でシェア」「はてブに追加」です（空白の有無を揃える）。
  - 新しいタブで外部を開くものの名前は「{見える文言}（外部サイト・新しいタブで開く）」にします。はてブは、いまの形（はてなブックマーク・外部サイト・新しいタブで開く）を残します。
  - コピー・画像の保存・端末の共有シートを開くものには、予告を付けません。
  - 3つの部品を1つにまとめるのは、結果の組み方を決める T4 に任せます。

3つの道具の一覧は、§7 の2つの形の外にある道具の結果です。行の形（開閉する行・表・色の格子）は §8 のとおり道具の中身として残し、§7 からは件数と備えだけを掛けます。

- ラジオボタンの組で一覧を絞り込まない道具（inventory 5章の17本）は、対象にしません。

## 9. `DESIGN.md` との関係

この設計は、`DESIGN.md` §7 の規定に従います。

- 行の一覧は `ItemList`、索引は `LinkIndex` です。どちらにするかは、その場面で語だけを見て選べるかで決めています（学年のページは読みが手がかりなので行の一覧、同じ部首の漢字は索引）。
- 行が持つもの（名前・読み・説明・種別・補助情報・色見本）と字の形、現在地の行は、§7「行の一覧」の規定のとおりです。
- 索引の2つの場面と置き場所（分類の入口は一覧の上の閉じたアコーディオン、同じ仲間の語は項目の本文のあと）、語の並びと区切りの見出しは、§7「索引」の規定のとおりです。
- 全件の一覧が件数を出すこと、選んだ一覧と詳細や結果のページの中の一覧が備えを持たないこと、備えを出す条件（一覧のページ・10件を超える・種別が2つ以上で同じ軸の索引を一覧の上に置かない・選ぶ理由のある並び順がほかにある）、一致の近い順、1ページの件数、名前の欄と件数の行を畳まないことは、§7「件数と備え」の規定のとおりです。
- 7章の道具の一覧は、§7 の2つの形の外にあり、行の形は §8、件数と備えは §7 に従います。道具のページには同じ軸の索引を置かないので、種別の組を持ちます。
- 操作の枠の開閉は §6 のアコーディオン（太い線の三角と、読み上げの開閉の状態）です。
