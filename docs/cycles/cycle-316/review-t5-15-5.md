## 指摘事項

### 1. 短い一覧の上で、ブラウザの拡大（Ctrl+ホイール・トラックパッドのつまみ）まで止める（中）

`CollapsibleTOC` の受け手は、一覧が中で送れないとき、wheel と touchmove をどれも `preventDefault` する。Chromium は Ctrl+ホイールと、トラックパッドのつまみ（`ctrlKey` の付いた wheel として届く）を、wheel の既定の動きとして拡大するので、それを取り消すとブラウザの拡大が起きない（[Chromium の変更の告知](https://groups.google.com/a/chromium.org/g/blink-dev/c/BW4hshtMsmo)、[Chromium の issue 40332613](https://issues.chromium.org/issues/40332613)）。

実測: 一覧を開いた y=4000 の位置で、一覧の上に `ctrlKey` の付いたホイールを CDP で送り、`document` の受け手で `defaultPrevented` を見た。

| 記事・大きさ                                 | Ctrl+ホイール  | ふつうのホイール |
| -------------------------------------------- | -------------- | ---------------- |
| javascript-date-pitfalls-and-fixes・1280     | 取り消される   | 取り消される     |
| javascript-date-pitfalls-and-fixes・375      | 取り消される   | 取り消される     |
| character-counting-guide・1280（送れる一覧） | 取り消されない | 取り消されない   |

ブログの来訪者の 89.1% は PC で（t5-design.md 8章）、見出しの少ない記事の目次を開いて一覧の上で字を大きくしようとすると、拡大だけが効かない。一覧が中で送れる記事では効くので、記事によって振る舞いが違う。指の2本のつまみ（touchmove で2点）も同じ受け手で取り消されるので、スマホで一覧の上からつまんで広げても拡大しないはずである（推論。Chromium の合成のつまみは、目次を閉じた本文の上でも拡大しなかったので、測れていない）。低い視力の来訪者が字を大きくする手段を、一覧の上だけで奪う。

直し方の例: wheel は `event.ctrlKey` のとき、touchmove は `event.touches.length > 1` のときは止めない。単体テストにその2つ（止めない）を足し、Chromium で Ctrl+ホイールが取り消されないことを確かめる。

### 2. 短い一覧の送りを止める理由が、短い一覧の形と合わない（軽い）

`CollapsibleTOC.tsx` の JSDoc は「一覧は画面の下端まで本文を覆うので、引き継ぐとページが見えないまま送られ」、`CollapsibleTOC.module.css` の `.list` のコメントも「一覧が画面の下端まで覆うので」と書き、その続きで短い一覧の送りも止めると書く。上の実測のとおり、短い一覧は画面の下端まで届かず（375 で 53px、1280 で 199px の本文が見える）、書いた理由は短い一覧に当てはまらない。コードを読む人は、短い一覧を止める理由を取り違える（あるいは、画面を覆わないなら止めなくてよいと直してしまう）。短い一覧も止める理由を、実際の形で書く（例: 一覧は本文の上に重なる層で、その上の送りは本文へ向けたものではない。一覧の下に見える本文は狭く、送るとほとんど見えないまま読んでいた所が動く。一覧の長さで振る舞いを変えない）。一覧の外の本文の上では送れることも書くと、閉じ込めないことが読み取れる。

### 3. `overscroll-behavior` が中で送れない箱で効かないことが、知見に無い（軽い）

短い一覧に受け手が要るのは、Chromium で、`overflow-y: auto; overscroll-behavior: contain` の箱でも、中身が収まって送れないときは送りがそのままページへ渡るからである。確かめ: 1280×800 の記事の上に、`position: fixed; max-height: 400px; overflow-y: auto; overscroll-behavior: contain` で中身が1段落だけの箱を置き、その上で 400px のホイールを送ると、ページが 3000 から 3400 へ送られた。CSS だけで済むと考えて同じ所で詰まりうる非自明な挙動なので、CLAUDE.md の決まりどおり `docs/knowledge/browser-layout-and-scrolling.md` に項を足す（実測と測ったブラウザ、推論の別を、1の項と同じ形で）。指摘1の直し（拡大の操作を止めない）も、その項の対処に含める。
