## 指摘

### major-1: 案の比較が A に有利に傾いている（AP-P02・AP-P30）

**どこ:** `options.md` の比較表、「A の弱いところ」、`index.md` の「検討した他の選択肢」

**なぜ問題か:**

- **C の害を大きく見積もっている。** C を退ける主な理由は「サイトの中で2つのデザインが混ざる」ことです。しかし同じ facts-ga.md に、全着地の平均で PV/セッション 1.29、1PV で終わるセッションが 83.7% とあります。大半の来訪者は2つのデザインを見比べません。一方で、PV の78%が集まる診断面は、C なら最も早く新しいデザインに変わります。78%という数字は引用しているのに、C に有利なデータは使っていません。
- **D は来訪者の理由でなく手順の都合で退けている。** 理由は「現行の手順と噛み合わない」だけで、手順が原理から決まったものか、たまたまそうなっているだけかを問うていません（AP-P30）。
- **A の本当の代償が書かれていない。**
  - A のあいだは、ほかの来訪者向けの修正を出荷できない。たとえば B-620 は、診断で設問が1問飛んで結果が変わる欠陥です。
  - 80ルートを一度に出荷するので、壊れたときに戻せるのは全部か無しかになる。
  - 出荷した瞬間に、78%の面が大きく変わる。
- **E の退け方で、コンセプトの引き方が偏っている。** 「手間を作らない理由にする」の裏返しとして退けていますが、site-concept.md には「うまくないものに手をかけ続けない」とあり、こちらは E に有利です。こちらには触れていません。
- **B は最も弱い形で定義されている。** 「旧トークンを新トークンへ置き換えるだけ」と決めてから退けているので、藁人形に近くなっています。
- **検討から漏れた案がある。** 新しいデザインをフラグの裏で main に積み続け、全面が揃った時点で一斉に切り替える案です。来訪者が見るものは A と同じまま、D の手順上の難点と、他の出荷が止まる問題を消せます。
- cycle-kickoff の「サイクルの作業は最小限に」と A の緊張にも触れていません。

**どう直すか:**

- C と B の害を、PV/セッションと1PV率の実測で見積もり直す。
- A の弱いところに、他の出荷が止まること・一度で壊れるリスク・78%の面が一度に変わることを加える。
- D は来訪者から見た違いで評価し直す。
- フラグで積んで一斉に切り替える案を加える。
- そのうえで、改めて案を選ぶ。

### major-2: 完了の条件で、来訪者に届いたかを判定できない

**どこ:** `index.md` の「完了の条件」

**なぜ問題か:**

- 条件は、トークンが無いこと・スキルの6検査・目視・ビルドです。吸収した7件が解消したかは判定できません。
  - B-641（表が1文字ずつ縦に折れる）: 320px の横スクロール検査では検出できない。縦に潰れても横には伸びないため。
  - B-663: iOS でフォーカスしても拡大しないこと自体を確かめていない。
  - B-649 の読み上げ名、B-577 の theme-color と 410 のダーク、B-597 も同様。
- DESIGN.md が求める機能が条件に入っていません。
  - §7: 名前と種別での絞り込み・並び順・件数・ページ送り・一覧へ戻れること
  - §8: 結果を操作の直後に置く
  - §11: `prefers-reduced-motion`
  - §12: キーボード・位置の一定・自動入力・一時表示
- 「全ページで」が80ルートを指すのか、実在する全URLを指すのか定義されていません。B-644 によれば約2845ページあります。
- T7（文言）には完了の条件がありません。

**どう直すか:**

- 「DESIGN.md の §1〜§12 を全ページが満たす」を主な条件にし、スキルの検査はその手段として位置づける。
- 吸収した7件それぞれについて、来訪者に何が見えれば解消かを1行ずつ書く。
- 「全ページ」の範囲を定義する。

### major-3: ADR009 の基線と B-568 の順序が決まっていない

**どこ:** T10、補足事項、backlog の B-568

**なぜ問題か:**

- ADR009 は、基線を「最初の出荷（B-754）の直前28日」と定め、「出荷後に取ると効果を永遠に読めなくなる」と書いています。T10 は「読んで、観測にどう掛かるかを確かめる」だけで、基線を取ることが作業になっていません。
- B-568 の期限は「ADR009 が基線を取る前」です。つまり、このサイクルの出荷前に済ませる必要があります。しかし Queued に置いただけです。サイクル完了と出荷が一体である以上、別のサイクルで先に済ませる道はありません。T10 の時点では、もう間に合いません。

**どう直すか:**

- T10 を「出荷の直前に、カテゴリ別の基線28日を取って保存し、撤退基準の値を確定する」に書き換える。
- B-568 は、次のどちらかを計画の段階で決めて書く。
  - このサイクルに入れる
  - 期限の考え方を改める

### major-4: 色以外で中身になっている面が抜けている（AP-P33・AP-P14）

**どこ:** options の「A の弱いところ」の AP-P33 の段、T4、T9、facts-design-gap.md

**なぜ問題か:**

- **字形が中身の面が挙がっていない。** 漢字辞典の大きな字（`KanjiDetail.module.css` は `--font-mincho`）、四字熟語辞典、漢字カナール（kanji-kanaru）では、字形が中身です。見出しの書体を一律に Zen Antique（アンティーク体）へ替えると、学習用の字形の正しさを損なう恐れがあります。
- **ブログの中に実測の漏れがある。** Shiki のコードの色分けと、11記事の mermaid 図（既定テーマは有彩）です。どちらも `src/` に16進数の色として現れないので、機械の検査を素通りします。色が中身か装飾かの判定もされていません。87記事のうち2記事には絵文字があり、DESIGN は絵文字を禁じています。
- **目視の選び方が、AP-P33 と B-581 が禁じる選び方になっている。** T9 の「色が中身の面は面ごとに1枚ずつ」は形で選んでいます。ほとんど白い色見本や、ダークでほとんど黒い色見本のような、境界の値が入っていません。

**どう直すか:**

- facts に次を加える: 字形が中身の面、コードの色分け、mermaid、ブログ本文の中身（表・絵文字・インラインの style）。
- それぞれについて、中身か装飾かの判定を T4 に入れる。
- T9 の選び方を「価値の種類ごとに、境界の値を必ず含める」にする。

### major-8: 78%の面で「楽しさ」が保たれるかを確かめる手段が無い

### major-9: 作業の粒度と、Web フォントの読み込みの重さ

**どこ:** 「どの作業も…1つの面の種類を渡す」、T1

**なぜ問題か:**

- **粒度:** 「ツール」の面は36ルートあります。1体に丸ごと渡すのは、CLAUDE.md の「Keep task smaller」と AP-WF07 に反します。globals.css や共有部品のように同じファイルに触る作業を、直列で進めることも書かれていません。
- **読み込みの重さ:** 和文 Web フォント2書体を足します。BIZ UDPGothic は2ウェイト×124分割、Zen Antique は118分割で、facts によれば日本語の分割ファイルは preload されません。来訪者の多くは検索から着いてそのページだけで去る初回訪問で、キャッシュが効きません（1PV率83.7%）。完了の条件には、読み込みのずれ（レイアウト）しかありません。LCP や転送量の悪化を検出する条件がありません。

**どう直すか:**

- ツールは1本ずつ（または少数ずつ）渡し、同じファイルを触る作業は直列にすると明記する。
- 出荷前後の LCP と転送量を比べる条件を、主な面について完了の条件に入れる。

## 来訪者から見た価値

入力欄の拡大（B-663）、文字サイズが追随しない問題（B-632）、表が縦に潰れる問題（B-641）は実害で、解消する価値ははっきりしています。全面を揃えることにも価値があります。
