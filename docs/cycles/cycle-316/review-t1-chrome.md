## 指摘

### Major-1: 410 のページに AI 運営の告知が無く、上端も下端も無い

`src/middleware.ts` の `build410Html()` は、見出し・短い文・「トップページへ」だけの HTML を返す。告知は下端（`Footer`）にしか無いので、410 に来た人は、AI が運営していることも、内容が誤りうることも知らされない。constitution の規則3に反する。410 は削除した記事への外部リンクや検索から来る人が着く面で、このサイトで最初に見るページになる。5a37f92 はこのページに手を入れ（dark に従わせた）、コメントに「テーマはほかのページと同じく」と書いた。それでも、上端・下端（§5「レイアウト」はどのページにもある部位として定める）と告知は持たせていない。Footer のコメントの「どのページにも出るよう」も、410 では事実と合わない。

ほかにも、`DESIGN.md` と違うところが同じ HTML に残っている。

- 中央揃え（§5「中央に寄せるのはコンテナだけ」）
- リンクに下線が無い（§6）
- 1px の枠
- 2px の単色のフォーカスの輪（§6 の二重リングでない）
- `transition 0.2s`（§11 の操作フィードバックは 150ms 以下）

これらは T5 の「410」で扱う範囲だが、告知が無いことは規則3に当たるので T1 で直す。

直し方: 410 でも、ほかのページと同じ上端・告知・下端を出す。告知の文言は一か所に置き、Footer と 410 の両方がそこから取るようにして、文言が食い違わないようにする。方法（middleware の静的 HTML に上端・下端を組み込む、410 の状態を返せる経路でアプリのページとして描く、など）は builder が選び、選んだ理由をコメントでなくサイクルの文書に残す。あわせて、「告知がどのページにも出る」ことを確かめる試験を、410 を含めて置く。

### Major-2: 上端・下端に、コンテナの左右のボーダーが無い。§1 の「罫線が作る形」がどのページにも出ない

§5「コンテナ」は「コンテナの左右のボーダーは、上端から下端まで途切れない」「全幅の罫線はコンテナの左右のボーダーを貫き、交点で切れない」と定める。§1 は、その交わりが残す「十字に切られた罫線の端」を「このサイトだと分かる形」とする。いまの上端と下端は、コンテナと同じ幅と内側の余白（`calc(var(--rule-w) + var(--box-padding))`）を取り、ボーダーの 3px の幅も空けている。しかし線そのものは引いていない。`src/` のどこにもコンテナの左右のボーダーは無い（`border-left: var(--rule-w)` は `globals.css` の1件だけで、コンテナのものではない）。そのため全幅の罫線は、どの幅でも、ただの横線になっている（`cc-1280-light` など、どの撮影でも同じ）。

コンテナは T1 の範囲（index.md の T1「線とコンテナと全幅の罫線（§5）・上端と下端」）に入っている。ボーダーは上端の罫線の上から下端の罫線の下まで続くので、上端・下端の組み方と一体で決まる。上端・下端を「DESIGN.md のとおりに作り直し」たと言えるのは、この交わりが出てからである。

直し方: コンテナの左右のボーダーを、上端・中間・下端を通して途切れずに引く。上端と下端の全幅の罫線が、そのボーダーを貫いて画面の端まで届くようにする。320・992・1280px で、§5 の x 座標の表（ボーダーの外 16・内 19・コンテンツ幅の左端 27／35／179 など）と一致することを測って確かめる。コンテナを T1 の別のコミットで作る予定なら、index.md の T1 にその順を書く。そのうえで、この交わりが出た状態で上端・下端をもう一度レビューに出す。

### Minor-1: 上端・下端のリンクの文字が、コンテンツ幅の左端から 5px ずれる

`.link` は `min-width: 44px` と `justify-content: center` を持つ。そのため、44px に満たない語（「遊び」「辞典」は 34px）では、文字が箱の中央に寄る。320px の上端では、サイト名の文字が x=27、「遊び」の文字が x=32 から始まる。下端でも、告知の文字は x=179、「辞典」は x=184 から始まる（1280px）。撮った画像でも、左の縁がそろっていないのが見える。§5「コンテンツ幅の左端は、どのページでも同じ位置。すべてそこから始まり、右にだけ伸びる」に当たる。

直し方: 文字を箱の左に寄せ、44px に届かない分の余白は右にだけ付ける。

### Minor-2: `/` でのサイト名が、§6 の現在地の見え方（太字）になっていない

`Header.module.css` は現在地の太字を `.navList .link[aria-current="page"]` に限り、`.siteName` を `font-weight: 400` に固定している。§6 は現在地を「いま開いているページを指すナビ項目」とし、見え方を「太字。下線を持たない」と定める。`/` のサイト名はまさにそれで、`aria-current="page"` も付いている。§3「見出しにウェイトの差を使わない」はサイト名には当たらない（サイト名は見出しでない）。欧文は IBM Plex Sans が組み、700 を持つので、太字にしても合成太字にはならない。

直し方: `/` のサイト名を現在地として太字にする。太字にしないなら、§6 のどの規定によるかを明らかにし、`DESIGN.md` を変える必要があるかを planner に判断させる。

### Minor-4: 404 のページにスキップのリンクが無い

`src/app/global-not-found.js` は、上端・下端を layout と同じ形で出すとコメントに書いている。しかし `SkipLink` を置いておらず、`main` に `id` と `tabIndex` も無い。そのため 404 では上端の5つのリンクを Tab で越えないと本文に入れない（WCAG 2.4.1）。layout の構造と食い違う。

直し方: layout と同じく `SkipLink` を body の最初に置き、`main` に `MAIN_CONTENT_ID` と `tabIndex={-1}` を付ける。layout と global-not-found で上端・下端とスキップの組み方がずれないよう、共通の部品にするかを builder が判断する。

### Minor-6: テーマの切替を外した理由が、来訪者にとっての損得を正しく言えていない

判断そのもの（切替を置かない）は、§10 と §5 に沿い、来訪者にとって妥当だと考える。切替の利用は計測されておらず、置き続ける根拠となるデータも無い。ただし、index.md の補足事項の理由には2つの誤りがある。

- 「83.7% のセッションは1ページで終わるので、選んだテーマを覚えておく得は小さく」は、覚えておくことの得しか言っていない。切替を外して失うのは、そのページのその場でテーマを替えられることである。
- 「別のテーマで読みたい来訪者は端末かブラウザの設定で選べる」は、iOS の Safari などでは OS 全体の設定を替えるしかない。

B-597 は「来訪者価値から判断」することを求めている。

直し方: 失うもの（その場で替えられないこと。iOS では OS 全体の設定を替えるしかないこと）と、それでも置かない理由（§10 の既定、§5 の上端に場所が無く、置けば上端の項目が増えて狭い画面で3行目に落ちうること、利用の計測が無いこと、など）を、事実どおりに書き直す。
