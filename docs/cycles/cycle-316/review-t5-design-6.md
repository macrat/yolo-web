## 5回目の指摘の確かめ

| 指摘                                                                   | いまの設計                                                                                                       | 判定 |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ---- |
| Minor-1 移したときに「移した先」だけを名指すと、移す元の削除が段に残る | 10章の頭の最初の項目の括弧が「移すときは `git mv` を使い、移す元と移した先の両方を名指してコミットする」になった | 解消 |

使い捨てのリポジトリで確かめたこと（どれも、ほかのタスクの代わりに `git rm other.txt` で段に載せた削除と、書きかけの変更 `wip.txt` を置いた状態で行った）:

- `git mv d/a.txt e.txt` のあと `e.txt` を書き換え、`git commit -- d/a.txt e.txt` → コミットには `d/a.txt` の削除と、書き換えたあとの `e.txt` が入った。`other.txt` の削除は段に、`wip.txt` は作業ツリーに残った。移したうえで中身を直すタスク（T5-9 は移してから自前の余白を外す）でも、この書き方で足りる。
- ディレクトリごと: `git mv app/new/x app/x` → `git commit -- app/new/x app/x` → `app/{new => }/x/…` の移動として入り、ほかは持っていかない。
- 実際の形に近いもの（`new/` の中のファイルと `new/__tests__/` の試験を、すでにある `__tests__/` のある親へファイルごとに移す）: `git commit -- c/new c/A.tsx c/__tests__/A.test.tsx` のように移す元をディレクトリ（`new`）で名指しても通り、`c/{new => }/…` の移動として入った。
- 実際の `new/` の中身（辞典の2部品と試験2つ、ゲームの `GameLayout`・`RelatedGames`・共有の4部品と試験）は、移す先の名前とぶつからない（`src/dictionary/_components/__tests__/` にあるのは `KanjiDetail`・`YojiDetail`・`ColorDetail` の試験だけ、ゲームの `_components/` には `new` しかない）。
