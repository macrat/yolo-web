## 指摘

### 1. 軸の数の試験が、名前の言う「前の軸で測った値では組まない」を確かめていない【builder・小】

`軸の数が変わっても、前の軸で測った値では組まず、いまの軸で測り直して描く` は、`RadarChart.tsx` 350 行目の見張り（`measured?.axes === axes`）を外して

```tsx
const frame = measured ? measured.frame : null;
```

にしても通る（8件すべて通ることを確かめた）。3→5 では、古い3つの幅で5本を組もうとして `widths[3]` が `undefined` になり、箱が `NaN` で比べがすべて偽になって `layoutWithLines` が null を返す。5→3 では古い5つの幅の先頭3つで組める。どちらも `useLayoutEffect` が描く前に測り直すので、最後の DOM は見張りがあってもなくても同じになる。いまこの試験が守っているのは「軸の数が変わっても落ちず、いまの軸の数で描く」ことで、見張りそのものではない。

来訪者の見え方は変わらない（見張りを外しても、描かれる前に測り直す）が、試験の名前を読む人は見張りが試験で守られていると受け取り、見張りを消しても気づけない。見張りは `NaN` の比べがたまたま偽になることに頼らないために正しいので、コードは残す。

- 試験の名前を、確かめていること（「軸の数が変わっても落ちず、いまの軸の数で描き直す」の形）に合わせる。見張りそのものを DOM で確かめられる手があるならそれでもよいが、描く前に測り直すので最後の DOM には出ない。名前を合わせるのが釣り合う直し。

### 2. afterEach が、`<head>` の `<style>` をすべて消している【builder・小】

`document.head.querySelectorAll("style").forEach((style) => style.remove())` は、`stubMeasurement` が足した1つだけでなく、`<head>` のどの `<style>` も消す。いまの vitest の設定では CSS を差し込まないので害は無いが、消したいのは自分が足した1つで、ほかの仕組みが `<style>` を入れるようになると黙って消す。`stubMeasurement` が作った要素を持っておき（`restoreAllMocks` で外れる spy と同じく）、それだけを外す形にする。
