## 指摘

### Major-1 「絞り込みを外す」を押すと、フォーカスが `body` に落ちる

- どこ: `src/components/ListStatus/index.tsx` 47〜49行（`empty && onClear` のときだけボタンを出す）と、`src/components/BrowsableList/index.tsx` 205〜208行の `handleClear`。
- 何が起きるか: 押すと絞り込みが外れて該当が0件でなくなるので、押したボタンそのものが消える。フォーカスを移す先が無いので、`document.activeElement` が `body` になる。`/storybook/list/11?q=zzz` でボタンにフォーカスして Enter を押し、確かめた。
- 来訪者にどう効くか: キーボードと読み上げの来訪者は、押したあといる場所を失う。次に Tab を押すと、ページの先頭（サイト名）からたどり直すことになる。読み上げでは、押したあと何も言わないまま位置を失う。「絞り込みを外す」は、困ったときに押す出口なので、ここで迷わせる損は大きい。T2 の `PaginationButtons` が「押した項目が消えたらフォーカスを戻す」を持つのと同じ扱いが要る。
- 直し方の方向: 消えたあとのフォーカスの行き先を決め、`BrowsableList` か `ListStatus` で移す。候補は名前の欄（外したあと、もう一度探し直す人の次の操作）か件数の行（外した結果の「全N件」がそこで読まれる）。決めた行き先を t3-design.md 2-4 に書き、単体テストに入れる。

### Major-2 button モードでページを送ると、件数の行が「ライブリージョンの更新」と「フォーカスの移動」で二重に読まれるおそれがあり、設計が求めた確かめが無い

- どこ: `src/components/ListStatus/index.tsx` 44行（`role="status"` の `p` に `tabIndex={-1}`）と、`src/components/BrowsableList/index.tsx` 241〜256行（送ったあとにその `p` へフォーカス）。
- 何が起きるか: button モード（絞り込みか並び替えをした状態）で「次へ」を押すと、件数の行の文が「全101語のうち1〜50語目」から「…51〜100語目」に替わり（ライブリージョンの更新）、続けて同じ要素にフォーカスが移る。`MutationObserver` で、送る1回ごとに文の書き換えが1回起き、そのあとフォーカスが件数の行にあることを確かめた。読み上げの多くは、フォーカスした要素の名前を読み、`role="status"` の更新も丁寧読みの順番で読むので、同じ文を2回聞くことになりやすい。
- t3-design.md 2-4 の最後の箇条は「フォーカスの移動とライブリージョンの読み上げが二重にならないかを、実装のレビューで読み上げを聞いて確かめます。二重になるなら、ページを送るときはライブリージョンの更新を抑えます」と決めている。この環境には読み上げのソフトが無いので、レビューで聞いて確かめることができない。サイクルの文書にも、聞いて確かめた記録が無い。
- あわせて、名前の欄に打つたびに件数の行が書き換わり、そのたびに読み上げの予約が積まれる（欄から URL へ書くのは 300ms 遅らせているが、件数の行の文は遅らせていない）。英字で「json」と打つと、1字ごとに件数が替わる。
- 来訪者にどう効くか: 読み上げの来訪者が、ページを送るたびに同じ範囲の文を2度聞く。打つたびに途中の件数を順に聞かされ、最後の件数に着くまで待たされる。
- 直し方の方向: 設計どおり、ページを送るときはライブリージョンの更新を抑える。たとえば、読み上げ用の `role="status"` を見える件数の行と分け、ページ送りでは更新しない。打鍵では、落ち着いてから（URL へ書くのと同じ遅れで）更新する。そのうえで、NVDA＋Chrome か VoiceOver＋Safari で聞いた結果をサイクルの文書に残す。聞けない環境なら、聞けないことと、代わりに何で確かめたかを書く。

### Minor-2 「読みの五十音順」が、濁音で始まる語を清音の行の後ろにまとめて並べる

- どこ: `src/lib/list-browse.ts` 134行（文字列を符号位置で比べる）と、その振る舞いを正しいとするテスト（`list-browse.test.ts` 121行）。
- 何が起きるか: 平仮名の符号位置は「か・が・き・ぎ…」の順なので、「かんぜん…」「かんき…」のような「か」で始まる語をすべて並べたあとに「が」で始まる語が来る。国語辞典の五十音順は、まず濁点を除いて比べ、同じときだけ清音を先にする（「がりょうてんせい」は「かんぜんむけつ」より前）。
- 来訪者にどう効くか: この比べ方は、T3-7・T3-8 で漢字2,136字・四字熟語400語の「読みの五十音順」にそのまま使われる。辞書の感覚で「が」の語を「か」の近くに探す来訪者は、見つけられずにページを送ることになる。
- 直し方の方向: 比べる値を2段にする（1段目は濁点・半濁点を外し、小書きの仮名を並の仮名に寄せたもの、2段目はもとの読み）。サーバーとクライアントで結果が同じになるという、ファイルの頭の方針は保てる。
