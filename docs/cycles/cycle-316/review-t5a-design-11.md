## 指摘

### 1. 名指しの言葉「次の問へ進む選択肢は、次の問が出るまで」が、診断の最後の問で押した選択肢を外す

5章が §6 冒頭の1つ目の定義に書き入れる文（446行）:

> 押したリンクと、押すと答えが決まって次の問へ進む選択肢は、次のページか次の問が出るまで、押す前と同じ下線を持ったままでいる（実行のさいちゅう）。

診断の最後の問の選択肢は、押すと次の問でなく結果へ進む。4-3（232行）は「最後の問でも、150ms 見せてから結果へ移る」と決めているが、名指しの言葉には当たらない。第10回の指摘1 で、実行のさいちゅうは性質でなく名指しで決めることにした（444行）ので、名指しから外れたものは当たらない。すると最後の問で押した選択肢は、4つ目の定義（450行）の「答えたあとの問の選択肢のうち実行のさいちゅうでないもの」、つまり答えた選択肢になり、`DESIGN.md` の文のうえでは下線を外すことになる。12問なら12回に1回、押した形が出ない。4-3 と食い違い、`DESIGN.md` だけを読む実装やレビューは、最後の問の押した形を誤りとも正しいとも決められない。

同じ言い方が次にもある。

- 467行（§6 の箇条）: 「この形を操作フィードバックの長さ（§11）見せてから次の問へ移る」
- 179行（4-2）: 「次の問が出るまでの 150ms」「その答えで次の問へ進む操作が、まだ終わっていない」
- 444行（5章の §6 の前置き）: 「答えで次の問へ進む選択肢」

直すこと: 名指しを「次の問か結果へ進む選択肢は、次の問か結果が出るまで」のように、最後の問を含む言葉にする。467行・179行・444行も同じ言葉にそろえる。

### 2. `globals.css` の説明の書き直しが、4-11 と T5a-5 で違う中身で2度書かれている

- 4-11（415行）: `data-hit-area` の規則と部品の hover の規則の上の説明を、「実行のさいちゅうの押した行（押せないが、押す前の行と同じ範囲に hover とフォーカスを出すもの）を含む並び」として書き直す。
- T5a-5（561行）: 同じ2つの説明を、「押せる範囲を `::after` に広げる要素に実行のさいちゅうの押した行が入り、hover の線が出ないのは現在地と無効（と押せない答えた選択肢）だと読める形」に書き直す。

T5a-5 だけが、hover の線が出ないものに答えた選択肢を足している。4-11 だけが、押した行が「フォーカスを出す」と言う。builder はどちらに従うかを決められない。

加えて、どちらの中身にも事実と合わない所がある。

- **フォーカス**: `data-hit-area` の規則の上の説明はいま「hover とフォーカスを要素の字の箱ではなくその範囲に出し」と言い、フォーカスは `:where([data-hit-area="after"]):focus-visible::after` が出す。押した行の `span` はフォーカスを受けない。フォーカスを受けるのは `li`（`tabIndex=-1`。4-7）で、リングは `[data-text-box="rows"] > li` を内側に置く対象に足す別の規則が出す。415行のとおり「`data-hit-area` の要素に押した行が入り、hover とフォーカスを出す」と書くと、説明は `span` がフォーカスを受けるかのように読める。
- **答えた選択肢**: 答えた選択肢の `span` は `data-hit-area` を持たず（4-2 は押した行にだけ持たせる）、部品の hover の規則の要素の並び（`a[href]`・`button`・`summary`・`[role="button"]`・`input[type="range"]`）にも入らない。hover の規則が「出さない」ものとして除いているのではない。561行の括弧書きは、規則がしていないことを説明に書かせる。

直すこと: 書き直しの中身を 4-11 の1か所で決め、T5a-5 は「4-11 の `globals.css` の説明の書き直し」と指すだけにする。中身は、`data-hit-area` の規則の説明には「押せる範囲を `::after` に広げた要素（一覧の行の名前と、実行のさいちゅうの選択肢の字）。hover はその範囲に出す。フォーカスを受けるものは、フォーカスもその範囲に出す」の類、部品の hover の規則の説明には、押しても何も起きないもののうち実行のさいちゅうのものは `data-hit-area` の規則で hover を出す、と読める形にする。答えた選択肢は規則が除いているものではないので、並びに足さない。

### 3. 「hover は押す前と同じように応える」に、カーソルが入るかが決まっていない

押す前の選択肢は `Button` の `.button` の `cursor: pointer` を持つ。押したあとの `span` には、4-4 が `Button` と共有するとした箱の規則（252行の列挙）にも下線の規則（253行）にも `cursor` が無く、`globals.css` にも `data-hit-area` の要素にカーソルを掛ける規則は無い。このまま組むと、マウスの来訪者が診断の選択肢を押すと、押した行の上のカーソルが指の形から矢印に替わり、150ms 後に次の問のボタンの上でまた指の形に戻る。問ごとに1回、ポインタの形が替わる。

`DESIGN.md` に入る文（446行・467行）は「hover は押す前と同じように応える」と言い、4-2（181行）は押した行を「押したリンクが次のページが出るまで下線を持っているのと同じ種類」とする。押したリンクは、次のページが出るまでカーソルも指の形のままである。カーソルが替わる組みは、この文と類比から外れる。6章 条件3 は像を撮って比べるので、カーソルの違いは測りに出ない。

直すこと: 押した行の字のカーソルを決めて、4-4 か 4-11 に書く。「hover は押す前と同じように応える」と類比に合わせるなら、押した行の字（`data-hit-area="after"` を持つ `span`）に `cursor: pointer` を掛ける（答えた選択肢には掛けない）。矢印に替えるなら、`DESIGN.md` に入る文を「hover の線は押す前と同じに出る」のように、線に限る言葉にする。
