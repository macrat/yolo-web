### M2. 1月29〜31日生まれの人が3月の初めに計算すると、日数が負になる（`logic.ts`）

`calculateAge` を直に呼んだ結果:

```
2001-01-31 → 2001-03-01  0歳1ヶ月-2日
2000-01-31 → 2000-03-01  0歳1ヶ月-1日
2001-01-30 → 2001-03-01  0歳1ヶ月-1日
2001-01-31 → 2001-03-02  0歳1ヶ月-1日
1990-01-31 → 2026-03-01  36歳1ヶ月-2日
```

原因:

- `days < 0` のとき、基準日の前の月（2月、28日か29日）の日数を足している。
- 生まれた日がその月の日数より大きいと、足しても負のまま残る。前の月が2月のときにだけ起きる。

来訪者が受ける感じ:

- 1月30〜31日（閏年でない年は29日も）生まれの人が3月1〜2日に使うと、結果の表の一行目に「36歳1ヶ月-2日」と出る。
- 画面の読み上げの知らせも「36歳1ヶ月-2日 を計算しました」と読む。
- 道具の中心の値が明らかに壊れて見え、道具全体が信じられなくなる。

その他:

- ロジックはこのコミットで触っていない前からの誤りだが、同じディレクトリ（`src/tools/age-calculator/`）の中の、来訪者が必ず見る値である。見本として出す前に直すのがよい。
- 直し方の例: 生まれた日を、その月の日数を超えない値に丸めて「月の応答日」を決める。あるいは、日数を「前の月の応答日から数えた日数」で数える。
- `logic.test.ts` に、上の5組と、月末生まれの組（3/31 → 5/1 など）を足す。

- Tab で着くと、二重のリングがボックスの太い線の外に出る（`after-320-32-light-frame-focus.png`）
- →キーで横に送れる（`scrollLeft` が 80）

目に見える手がかりは、右端で字が切れていることである（「35歳3」「12,88」「423ヶ」「平成3」が切れて見える）。枠・名前・目で見える手がかりの3つがそろっており、PM の決定の受け入れの条件を満たす。

一方で、1991 年生まれ（未（ひつじ））の 320px・200% と 375px・200% では、表の幅は 327px に対して見える幅が 299px（375）・244px（320）である。375px では 28px ぶんだけ隠れる。

- 1990 年生まれ（午）では同じ幅で3行に折れて収まる。

§5 のとおりで直す義務は無い。ただ、「未（ひつじ）」を「未／（ひつじ）」の2つの組として持たせれば（m2）、列の最小の幅は「（ひつじ）」のまま変わらない。字の幅の問題なので、受け入れの記録どおりでよい。記録として残す。

### m2. 干支の値は `<wbr>` の無い所（始め括弧の前）で折れ、CSS のコメントと食い違う

### m3. 読み上げの知らせの文と、同じ値で計算し直したとき

### m4. `variant` は受け取るだけで使われない、死んだ prop である

- `variant?: "full"` は型にあるが、分割代入で受け取られておらず、描き方に何の差も生まない。
- 「page.tsx が渡すから残す」は、残す理由にならない。渡す側と受ける側の両方が意味を持たない、AP-I13 の (2)「受け取り手のいない prop」そのものである。
- `as` と `className` も、呼ぶ所は1つで、どちらも渡していない。
- 型の説明が「表示の種類。生年月日と基準日から全部の値を出す "full" だけを持つ」と、意味のある prop のように書いているのも、読む者を誤らせる。

T4-15 の範囲が `src/tools/age-calculator/` だけで page.tsx を触れないなら、ここで消せないのは分かる。その場合は次のどちらかにする。

- (a) 型の説明を「呼ぶ側の互換のためだけに残る。B-755 で消す」と正直に書く（ただし経緯の注記にならないよう、B-755 で消す日まで）。
- (b) PM が B-755 の範囲に、この道具の `variant`・`as`・`className` と page.tsx の `variant="full"` を明記して記録する。

(b) がツギハギを増やさないのでよい。
