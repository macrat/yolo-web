## とくに見てほしいと言われた点

- **GA の値が面ごとに変わらないこと**: 変わっていない。builder の compare.txt（c05d08e と d5184a3 の本番のビルドを、13の面・共有シートあり／なしで全クリック比べたもの）は、ゲーム4本に `method: "line"` の送信が増えたこと以外すべて同じで、増えた送信も `content_type: "game"`・`item_id`/`content_id` がゲームの slug・`surface` なしで、ほかのゲームの送信と同じ形。自分でも本番のビルドで、道具（char-count）と yoji-kimeru の結果で、API で写せた回・API に拒まれて代わりの写し方で写せた回・API の無い端末で写せた回のどれも `clipboard` を1回だけ送り、どちらでも写せなかった回は何も送らないことを確かめた。
- **代わりの写し方の正しさ**（本番のビルド・Chromium で、API を拒ませる／無くす／`execCommand` も失敗させる の3通りと、普通の場合を確かめた）:
  - 写した中身: API を拒ませた場合も無くした場合も、ブラウザのクリップボードを読み返すと、ページの共有は「文字数カウント\n(URL)」、ゲームは「四字キメル #226 (中級) X/6 … #四字キメル #yolosnet\n(URL)」で、共有の文と URL が1つずつ正しく入っていた。
  - フォーカスの戻し: focusin の順は「押したボタン → 写すための欄 → 押したボタン」で、終わると押したボタンにある。マウスで押したときに `:focus-visible` にならず、リングが出ない。キーボードで押したときはリングが残る（押す前と同じ）。
  - 欄の片付け: 写したあと `textarea[aria-hidden]` は0件。
  - ダイアログ: 欄を押したボタンの並びに置くので、結果のダイアログは開いたままで写せ、ダイアログの中の送りもページの送りも動かなかった。
  - 読み上げ: 欄は `aria-hidden` と `readonly` を持ち、知らせは部品の `role="status"` で出る。失敗のあとにもう一度押して失敗したときも、いったん空にしてから文を入れ直すので、同じ知らせがもう一度読まれる。
  - iOS の Safari: 書き方は定番の形（`readonly` の textarea を `position: fixed` で画面の外に置き、`select()` と `setSelectionRange()` で選ぶ）に沿っている。欄の字の大きさは `globals.css` の `textarea { font-size: var(--text-input) }` で 16px 以上になるので、フォーカスしても画面は拡大しない。API に拒まれてから写す流れは `await` のあとになるが、WebKit は押してからおよそ1秒のあいだ `execCommand("copy")` を許し、API の拒否はすぐ返るので間に合う見込みが高い。この環境には WebKit が無く確かめられないので、実機で確かめる項目として残す（下の「確かめられなかったこと」）。間に合わなくても、失敗の知らせが出て、ほかの共有先へ案内される側に倒れる。
- **失敗の知らせの文言と置き方**: 「コピーできませんでした。ほかの共有先をお使いください」は、何が起きたかと次にどうするかを言い、§9 に沿う。知らせが出るのは共有シートのボタンを出さない側（X・LINE などが並ぶ側）だけなので、「ほかの共有先」はいつも画面に並んでいる。成功の知らせと同じ場所に出て、次に押すまで消えない。375px で2行になり、その下が1行ぶん下がるが、失敗は来訪者がそこを読むべきときなので、動いてよい。折れ方に小さな残りがある（Minor-4）。
- **テストの意味**: `copyText` のテストは、API で写せたらほかの方法を使わない・拒まれたら同じ文を選んで写す（選ばれた範囲の中身まで見ている）・API が無くても写す・置く所を渡すとその中に置く・どちらも駄目なら false・欄を残さずフォーカスを戻す、を確かめていて、どれも壊れ方を1つずつ捕まえる。`ShareButtons` のテストは、押したボタンの並びに欄を置くこと、失敗の知らせが5秒たっても残り、次に写せたら「コピーしました」に替わること、失敗の回に計測を送らないことを確かめている。
- **経緯のコメント**: 変更した行には無い。ゲームの `share.ts` の「The page URL is not part of the text; ShareButtons adds it for each share target.」は、いまの約束を言う文で経緯ではない。1か所、残ったコメントがファイルの中身と食い違う（Minor-3）。

## 範囲外の発見: ゲームの結果のダイアログの中のボタンをキーボードで押すと、ダイアログが閉じる

yoji-kimeru の結果のダイアログで、「結果をコピー」または「LINE でシェア」にフォーカスして Enter を押すと、写す・開くと同時にダイアログが閉じ、フォーカスがページの h1 に移る（本番のビルドで確認。API がある場合も無い場合も同じ）。

原因は `src/play/games/shared/_components/useDialog.ts` の `handleBackdropClick` で、ダイアログの `onClick` がクリックの座標がダイアログの矩形の外かどうかで背景のクリックを見分けている。キーボードで押したボタンのクリックは座標が 0, 0 なので、矩形の外と見なされて `onClose` が呼ばれる。ダイアログの中のすべてのボタン（共有のボタン・画像を保存・統計など）で起きる。

来訪者への影響: キーボードで操作する来訪者は、結果を写すと結果のダイアログを失い、「コピーしました」の知らせも閉じたダイアログの中にあるので読み上げで聞けない。LINE や X を押しても同じく閉じる。このファイルは c05d08e より前から変わっておらず、いまの本番にもある。T4-4 が作ったものではないので T4-4 の完了を止めないが、共有のボタンを1つにした効果をキーボードの来訪者から奪う。

直し方の例: 背景のクリックかどうかを、座標ではなく `e.target === e.currentTarget`（ダイアログの要素そのものを押したか）で見分ける（ダイアログの中身を包む要素が余白まで覆う組み方にする）。PM が、`src/play/games/shared/` を持つ T4-10 の行（またはそれより早いタスク）に「ダイアログの中のボタンをキーボードで押しても閉じない」を完了の条件として書き、キーボードでの確かめのテストを足させる。

### Minor-1: 計測の数え方の記録が、直しのあとの形に合っていない（ADR009 の読み違えの元）

index.md の「T4-4 で、ゲームの結果の共有の計測（GA の `share`）は……ゲームの `web_share` と `clipboard` の数は前より少なく出る」は c05d08e の時点の記録で、d5184a3 で次の2つが加わったのに、書き足されていない。

- 代わりの写し方で、クリップボードの API に拒まれる端末（アプリの中のブラウザなど）でも写せるようになった。記事・道具・辞典・診断・占い・ゲームのどの面でも、`clipboard` はそのぶん増えうる（ゲームは「失敗も数えた」前の数え方から「写せた回だけ」になったので、増減の向きは決まらない）。

ADR009 は GA の前後を方向読みで使うので、「少なく出る」だけが残ると、出荷後の増えを来訪者の変化と読み違える。直し方: index.md のその項を、出荷の日から変わる数え方（ゲームの `web_share` は共有を終えた回だけ・`clipboard` はどの面でも写せた回だけで、代わりの写し方のぶん写せる端末が増える・ゲームに `line` が加わる）と、送る値の形は変わらないことを言う1つの項に書き直す（サイクルの文書なので、PM が決定として書くか、builder に書かせるかは PM が決める）。

### Minor-2: サイトのほかのコピーは、まだ API に拒まれると黙って何もしない
