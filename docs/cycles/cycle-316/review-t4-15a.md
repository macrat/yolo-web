## Major

### M1. 文字の大きさが変わっても段を選び直さず、数がボックスからはみ出す

`FittedNumber` の説明は「幅と文字の大きさが変わったら（端末の回転・ブラウザの拡大）選び直す」と言うが、選び直すのは置かれた幅（`container.clientWidth`）が変わったときだけである。スマホではコンテナの幅が画面の幅で決まり、文字の大きさでは変わらない。

再現: 375×667 で 123,456 字を入れ（main・`scrollWidth 299 / clientWidth 299`）、ページを開いたまま既定の文字サイズを 32px にすると（CDP `Page.setFontSizes`。Chrome の設定や端末の文字サイズを開いたまま変えたのと同じ）、main の 66.56px のまま `scrollWidth 390 / clientWidth 299` になり、数がボックスの外へはみ出す。次の1字を打つまで直らない。Web フォント（IBM Plex Sans・Zen Antique）の差し替わりで字幅が変わったときも、同じ理由で選び直さない。

直し方の例: 幅の比較に加えて、ルートの `font-size`（または 1em の見本の要素の幅）が変わったときにも選び直す。`document.fonts` の `loadingdone` でも選び直す。`FittedNumber` のテストに「文字の大きさが変わったら選び直す」を足す。説明と振る舞いを一致させる。

### M2. 「絵文字や記号なども1文字として扱います」が事実と違う

`meta.ts` の `howItWorks` はこう言うが、数え方はコードポイント単位なので、見た目の1字が複数に数えられる。

| 入れたもの              | 表示                   |
| ----------------------- | ---------------------- |
| 👨‍👩‍👧（ZWJ の家族）        | 5文字・18バイト        |
| 🇯🇵（国旗）              | 2文字                  |
| 👍🏽（肌の色つき）        | 2文字                  |
| か＋濁点（U+3099、NFD） | 2文字（「が」は1文字） |

SNS やフォームの字数に合わせて数えに来た来訪者は、見た目の字数と表示が食い違う理由を知る手段が無い。主役の数を書記素（`Intl.Segmenter` の `grapheme`）で数えるか、コードポイントで数えることを説明と FAQ に正しく書くかを PM が決め、どちらでもテスト（いまは 😀 だけ）に ZWJ・国旗・結合文字の例を足す。byte-counter と数え方を共有する SSoT（`src/lib/text-counting.ts`）なので、変えるなら両方の説明を揃える。

### M3. 「空白を除いた文字数」は改行とタブも除いている

`countCharsNoSpaces` は `/\s/` で除くので、改行・タブも数えない（「a\tb」→2、「a\n\n\nb\n \nc」→3）。見出しは「空白を除いた」だけなので、原稿の字数（改行を含むか含まないかで規定が分かれる）を確かめに来た来訪者が、改行が含まれるのかを表から判断できない。「空白と改行を除いた文字数」のように、除くものを見出しで言う。

### M4. 呼び出し元の無い `compact` の組み方が残っている（死んだコード）

`CharCountTile` を使うのは `src/app/tools/char-count/page.tsx`（`variant="full"`）だけで、`variant="compact"` の呼び出しはリポジトリに無い（`git grep`）。それでも `CharCountTileVariant`・`COMPACT_KEYS`・`ROWS.compact`・`rows={variant === "compact" ? 5 : 10}`・compact のテストが組み直しで新しく書き直されている。使われない分岐はデザインの見本として読む人を迷わせる。消して、`variant` を持たない形にする。

## Minor

### m1. 読み上げの文を1打ごとに知らせる

`role="status"` の文が打つたびに変わるので、スクリーンリーダーの利用者には打つたびに「19文字、40バイト…」が読まれ、打った字の読み上げと重なる。打ち終えて少し（0.5〜1秒）止まってから知らせる形にする（表示の数は打つたびに更新したまま）。

### m2. 改行コードの FAQ を確かめる

FAQ は「CRLF は CR と LF で2文字」と言う。テキストエリアに貼った文の改行は、ブラウザが LF にそろえることが多い（HTML の仕様でもテキストエリアの値の改行は LF に正規化される）。実際に CRLF の文を貼って（クリップボード経由）数えた結果を確かめ、FAQ を来訪者が見る結果に合わせる。単独の CR（「a\rb」）は画面で2行に見えても行数が1になることも、あわせて確かめる。

- 「ライブリージョンは表を含まない」の1つ目の `not.toContainElement(resultBox())` は、2つが兄弟なので常に真。
- M1・M2 の直しに合わせたテストが無い。
