### Major-1: 語のマスの字が枠に接し、フォーカスのリングと hover の線が字を横切る（DESIGN.md §5・§6、AP-I08）

`.wordButton` の左右の余白を 0 にし、`letter-spacing: -0.05em` を掛けた。1字の行は消えたが、DESIGN.md が決めていない組みで、見た目を壊した。

- **字間を詰めることも DESIGN.md に無い**: DESIGN.md は字間を決めず（§3 は `palt` を掛けない全角の組み）、サイトのどこにも負の字間は無い（`letter-spacing` はほかはどれも正の値）。しかも、詰める必要があるのは狭いマスだけなのに、1280 を含むすべての幅に掛かっている。

- **目で見て**（shots/grid20-320-16-l.png・grid36-320-16-d.png・grid34-375-32-l.png）: 「ザーザー」「ワクワク」「一石二鳥」「以心伝心」などが左右の枠にぴったり付き、4列の格子が字で埋まった帯に見える。キーボードでフォーカスした「しとしと」「三日坊主」「犬も歩けば」では、§6 の二重リング（枠から太い線の太さだけ内側に出る）が字の左右の画を横切る。マウスを載せた「もちもち」「赤の他人」でも、hover の線が字に重なる。§6 の「リングは範囲の内側に密着して出る」の前提（中身が 8px 内側にある）が崩れている。

8px の余白を戻して同じ数を測った（grid6alt.mjs、43,200 マス）。

## Minor

### Minor-1: 句に分ける決まりをデータで確かめるテストが無い

`sayingPhrases` は「漢字を含み、最後のほかの句が2字以上で助詞などで終わる」という形の決まりで、いまの50問では正しく分ける（19語を分け、13語を分けない）。ただし、テストは手で選んだ11の例だけで、毎日の問題を足したときに「天の｜川」のような語を句に分けても気付けない。また、分ける19語には「春の小川」「秋の田の」「赤の他人」のようにことわざでない語も入り、注釈の「ことわざのように句を持つ語」とは少し違う（折れ方に害は無い）。

- **直すこと**: 問題のデータ（`nakamawake-data.json`）のすべての語について、句に分ける語の一覧をテストで固定する（スナップショットか期待の一覧）。問題を足したときに、分け方の変わった語がテストで見える。

### Minor-2: 解き終えた日を 200% で回すと、共有の区画が画面の外へ出る

回転（rot5.mjs・rotdbg.mjs、8回とも同じ）で、共有の見出しの位置は次のように動く。

| 回転                | 既定      | 200%             |
| ------------------- | --------- | ---------------- |
| 375×667 → 667×375   | 323 → 229 | 312 → **-478**   |
| 320×568 → 568×320   | 273 → 135 | 263 → **-1,101** |
| 320×667 → 1280×800  | 323 → 349 | 313 → **-1,302** |
| 1280×800 → 800×1280 | 379 → 293 | 379 → 442        |

区画に空きは残らず CLS も 0 だが、200% で共有まで送ってから回すと、見ていた共有の区画が上へ消え、「よくある質問」が画面に来る。320→568 では、h1 の位置はほぼ変わらず（-3,227 → -3,182）、ブラウザのスクロールアンカーがページの上の方の要素を目印にしているように見える。200% で横に回す来訪者は少ないが、毎日遊ぶ人が結果を読み返している最中に起こる。

- **直すこと**: builder が、回したときにブラウザがどの要素を目印にしているかを確かめ、結果の区画の中の見ている所が残るようにできるかを調べる。ほかの3つのゲームでも同じかを測り、共通の原因なら共有の部品で直す。直さないなら PM が受け入れを決めて t4-design.md に書く。
