## 計算の正しさ

### 法律の数え方

- 年齢計算ニ関スル法律は、年齢を出生の日から起算し（1項）、民法 143 条を準用する（2項）。
- 民法 143 条2項の本文は、期間を「最後の年（月）においてその起算日に応当する日の前日に満了する」とする。ただし書は「最後の月に応当する日がないときは、その月の末日に満了する」とする。
- したがって、4月2日生まれの人は4月1日の終わり（24時）に1つ年をとる。この道具は「誕生日の当日から1つ上」と出す。前日の24時は当日の0時なので、ふつうの誕生日では、この道具の出し方は法律と一致する。
- 応当日が無いときは、末日そのものの終わりに満了する。2月29日生まれなら、平年は2月28日の24時、つまり3月1日の0時から1つ上になる。閏年も、応当日（2月29日）の前日の28日の24時に満了する。結局、法律上の年をとる時は毎年同じ「2月28日の終わり」である。

### この道具が出す値（`calculateAge` を直に呼んだ結果）

```
2000-02-29 → 2001-02-28  1歳0ヶ月0日     （法律: 0歳11ヶ月30日。1つ上になるのは 3/1）
2000-02-29 → 2001-03-01  1歳0ヶ月1日     （法律: 1歳0ヶ月0日）
2000-02-29 → 2004-02-28  3歳11ヶ月30日   （法律と同じ）
2000-02-29 → 2004-02-29  4歳0ヶ月0日     （法律と同じ）
2001-01-31 → 2001-02-28  0歳1ヶ月0日     （法律: 0歳0ヶ月28日）
2001-01-31 → 2001-03-01  0歳1ヶ月1日     （法律: 0歳1ヶ月0日）
2001-03-31 → 2001-04-30  0歳1ヶ月0日     （法律: 0歳0ヶ月30日）
2000-04-02 → 2001-04-01  0歳11ヶ月30日   （法律と同じ）
2000-04-02 → 2001-04-02  1歳0ヶ月0日     （法律と同じ）
```

- 総当たりの 878,400 組のうち、10,858 組（1.2%）で月か日が法律の数え方と1日ずれる。
- 年がずれるのは、2月29日生まれが平年の2月28日を基準日にした組である。
- 通算日数と通算月数の組は、どの組でも食い違わない（上の表の M2 の行）。

## Major

### M1. 応当日の無い月で1日早く満了させ、2月29日生まれが平年の2月28日に1つ年上になる。コメントは「民法と同じ」と誤って書く

`logic.ts` の `monthAnniversary` は、応当日が無い月では、生まれた日を**その月の末日に丸めた日**を応当日にする。上の「計算の正しさ」のとおり、法律の満了は末日の**終わり**である。この道具は「応当日の当日から数える」ので、法律に合わせるには、末日の翌日（翌月の1日）を応当日にしなければならない。今の丸め方は1日早い。

来訪者が受ける感じ:

- 2月29日生まれの人は、自分の年齢がいつ変わるかを確かめに来る来訪者の典型である。「2月29日生まれ 年齢」は、法律の解説記事が何本も立つ問いでもある。
- その人が平年の2月28日に使うと「1歳0ヶ月0日」（年の数が法律より1つ上）と出る。閏年には2月29日に年が変わる。同じ人の年の変わる日が、年によって28日と29日に揺れる。
- 法律上は毎年「2月28日の終わり」で一定である。道具の出し方（誕生日の当日から1つ上）に直せば、平年は3月1日、閏年は2月29日である。
- 1月31日生まれ・3月31日生まれの「Nヶ月N日」も、30日の月・2月をまたぐと1日ずれる。1巡目の「−2日」ほど明らかではないが、民法に沿うと書いた値が民法とずれる。

コードとテストの問題:

- `monthAnniversary` のコメントは「民法の期間の数え方（最後の月に応当する日が無いときは、その月の末日に満了する）と同じ」と書いている。しかし、満了の日を応当日として数えている。後の者がこのコメントを信じて写すと、誤りが根拠つきで広がる。この道具は T5 が写す見本である。
- 7b18ef0 は、前からあった「2000-02-29 → 2001-02-28 は 0歳11ヶ月」のテストを「1歳0ヶ月0日」に書き換えている。前のテストは法律に合っていた。直しが、正しかった振る舞いを壊し、テストの期待値をその壊れた値に合わせている。
- `Feb 29 births` と `month-end births` の `it.each` は、どれもこの丸め方の値を期待値にしている。

直し方:

1. `monthAnniversary` で、応当日が無い月は、その月の末日の翌日（翌月の1日）を応当日にする。
   - 私が同じ総当たりで確かめた範囲では、この形でも日数は 0〜30 に収まる。年齢は基準日とともに増えるだけで、戻らない。
   - 閏年の2月29日は応当日があるので、4歳0ヶ月0日のまま変わらない。
2. コメントを、法律の数え方とこの道具の出し方の関係が分かる文に直す。
   - 法律は応当日の前日の終わりに満了する。応当日が無ければ末日の終わりに満了する。
   - この道具は、満了の翌日を「0日」として数える。
3. テストの期待値を法律の値に直す。
   - 2000-02-29 → 2001-02-28 は 0歳11ヶ月30日、→ 2001-03-01 は 1歳0ヶ月0日、→ 2004-02-29 は 4歳0ヶ月0日。
   - 2001-01-31 → 2001-02-28 は 0歳0ヶ月28日、→ 2001-03-01 は 0歳1ヶ月0日。
   - 2001-03-31 → 2001-04-30 は 0歳0ヶ月30日、→ 2001-05-01 は 0歳1ヶ月0日。
   - 日数が 0〜30 に収まる総当たりのテストは、そのまま残す。
4. 同じディレクトリの `meta.ts` の FAQ に、数え方の問いを1つ足す。
   - 巷では「法律上は誕生日の前日に年をとる」「2月29日生まれは2月28日に年をとる」と言われる。道具の出す日と、来訪者の知っている話が食い違って見えうる。
   - 例:「年齢はいつ1つ増えますか？」に次の答えを書く。
     - この道具は、誕生日の当日から1つ上として数える。
     - 法律（年齢計算ニ関スル法律・民法 143 条）では、誕生日の前日が終わった時に1つ増える。
     - 2月29日生まれの人は、平年は2月28日が終わった時、つまり3月1日から1つ上と出す。
   - 疑問を持った来訪者がその場で答えにたどり着ける。

## Minor

### m1. 通算日数・通算月数の桁区切りが、ブラウザの言語で変わる

`numberWithUnit` は `value.toLocaleString()` を言語の指定なしで呼び、`","` で割って折り所を置く。ブラウザの言語が日本語や英語でないと、次のように出る（1900-01-01 → 2026-09-27、375×667 で測った）。

| ブラウザの言語 | 通算日数        | 通算月数         |
| -------------- | --------------- | ---------------- |
| ja-JP・en-IN   | `46,<wbr>290日` | `1,<wbr>520ヶ月` |
| de-DE          | 46.290日        | 1.520ヶ月        |
| fr-FR          | 46 290日        | 1 520ヶ月        |

- ドイツ語の設定では「46.290日」と、小数に読める値が出る。フランス語の設定では、桁の切れ目が折れない空白になり、折り所も消える。
- 海外に住む人や、端末の言語を日本語以外にしている人も、日本語のページを読む。
- このヘルパーは T5 の31本が写す見本の一部なので、ここで直せば写した先の全部が直る。

直し方: `toLocaleString("ja-JP")`（か `Intl.NumberFormat("ja-JP")`）にする。言語を変えても同じ値と折り所になることを、テストで確かめる。

### m2. 和暦の値を、整えた文字列を切って作っている

`buildResult` は `wareki.formatted.slice(wareki.era.length)` で「2年」「元年」を取り出している。

- `toWareki` がすでに `era` と `year` を別に持っているのに、組み立てた文字列を元号の字数で切り直している。読む者は、`formatted` がいつも「元号＋年」の順であることを、`toWareki` の中まで読んで確かめなければならない。
- `WarekiInfo` に年の表記（「元年」「2年」）を持たせるなどして、組を直に渡すとよい。

## implementation.md のアンチパターンを1つずつ

- **AP-I01（来訪者にとって最高の体験か）**: 画面の体験は、1巡目の欠けが直り、どの幅でも押した直後に結果が見える。ただ、テストが通り、日数が負にならないことだけで「計算が正しい」としたので、法律から1日ずれる数え方が通った（M1）。値そのものを法律の数え方と突き合わせる確かめが無かった。該当する。
