## Minor

### Minor-1. T5 の行が、10-e（ハッシュ値とパスワードを「符号にした文字列」に含めるか）の答えを先に決めている

T5 の行は「長い値を出すほかの道具（hash-generator・number-base-converter・percent-calculator・byte-counter・password-generator）の、値の途中の折れ（t5-inventory.md 10-10）も、同じ組み方で直す」と書く。ところが棚卸しの 10-e は、ハッシュ値とパスワードを §4 の「符号にした文字列（字のあいだのどこでも折る）」に含めるかを問いとして残している。含めるなら hash-generator と password-generator の折れは §4 どおりで直す対象でなく、含めないなら「どこで折るか」を別に決める要がある。いまの行は、両者を §8 の数字と「同じ組み方で」直すと読めるので、設計者が 10-e を問わずに進みうる（AP-P16）。

**直し方**: 行を「10-10 の値の途中の折れを、10-d・10-e で決める折り方で直す」の形にし、ハッシュ値とパスワードを数字の値と同じ組み方で直すとは書かない。

### Minor-2. 10-10 の「測った入力（12章）」が 12章に無い

10-10 の本文は「測った入力（12章）では値の途中で折れない」と書くが、12章の「長い値の折れ（10-10）」は数え方だけで、道具ごとに入れた値を書いていない（表の例から読めるのは percent-calculator の 123456789 と 987654321、number-base-converter の 18446744073709551615 くらい）。hash-generator・byte-counter・base64・unix-timestamp 以外の道具（unit-converter・color-converter・cron-parser・age-calculator・date-calculator・char-count）は、何を入れて「折れない」としたかが分からない。12章は「T5 の実装のあとに同じ数え方で比べられるよう」書く章なので、入力が無いと T5 の合格の判定で同じ値を比べられない。

**直し方**: 12章の 10-10 の項に、道具ごとに入れた値（と選んだモード・進数・アルゴリズム）を書く。password-generator のように値が毎回変わるものは、そう書いたうえで何回作って数えたかを書く。
