## 指摘

Major は無い。

### Minor-1: コードとコメントの細かい所

- `splitFirstPhraseAtWords` の `chars.findIndex((grapheme) => /^\s/u.test(grapheme))` は、同じファイルにある `STARTS_WITH_SPACE`（`/^\s/u`）と同じ正規表現を、もう一度書いている。`STARTS_WITH_SPACE.test(grapheme)` を使う。
- 頭のコメントの「足した折り所は、文節が1行に収まらずブラウザが字の所で割るときの代わりにだけ使われる」は、条件がずれている。文節が1行に収まらなくても、空白より前の部分が1行に入るなら、ブラウザは空白で折るので、足した折り所は使われない。正しくは「この部分が1行に収まらないとき」で、関数のコメント（「そこが1行に収まらないときにしか使われない」）と同じ条件にそろえる。

### Minor-2: `docs/knowledge/nextjs.md` 11項の書き方

- 足した文の前、「…`(request: node:fs)`。 Node 組み込みを」の句点のあとに、半角の空白が入っている。
- 1段落目に「Node 組み込みを掴まないモジュールは…client のバンドルに入って来訪者に配られる」を足したので、2段落目の終わりの「セクション2はバンドル『サイズ』の問題だが、本項は…ビルド『可否』として落ちる点が異なる」と合わなくなった。黙ってバンドルされるほうは、サイズの問題である。この項がビルドが止まる場合と黙って入る場合の両方を扱うことを前提に、セクション2との違いを書き直す。
- 同じ「置かないと client に黙ってバンドルされる」ことが、1段落目と「予防」の段落の2か所に書かれている。どちらか1か所にまとめる。

## そのほか（指摘ではない）

- 空白より後ろには折り所を足さないので、空白の後ろに長い語の続きがあり、それが1行に入らないときは、ブラウザが字の所で割る。見本では、既定の文字サイズのセクションの 244px で「Unix ／タイムスタンプ変換ツ／ール」になり、行頭に長音符が出た（c5b6fae では「Unix タイムスタンプ／変換ツール」）。ただし、いまのサイトの道具の名前は空白を持たない（「UNIXタイムスタンプ変換」など）。この形は試しの入力にしか無く、PM が決めた「空白より前だけ」の範囲の中にある。ブログの題や早見表の名前のように空白を持つ見出しを T5 で当てるときは、同じ測り方で見る。避けられない所は、DESIGN.md §4 のとおり見出しの文のほうを直せば足りる。
