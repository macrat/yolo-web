## 指摘

### 1. §6 に足す文どうしが食い違う。冒頭の定義は答えた選択肢に下線を持たせず、下線の箇条と表の行は押した選択肢に下線を残す

5章は §6 に次の3つを書き入れる。

- 冒頭の4つ目の定義（443行）: 「**押しても何も起こらないもの**——現在地・無効・答えたあとの問の選択肢（答えた選択肢）——は、下線も反転も持たない。」
- 種類・状態の表の行（447行）: 「答えた選択肢……診断では押したものだけが下線を残し」
- 下線の箇条（455行）: 「診断で押した選択肢は……見せているあいだ下線を残す（答えた選択肢）。」

同じ `DESIGN.md` の中で、答えた選択肢は下線を持たないと定義し、その答えた選択肢の1つに下線を残すと書くことになる。冒頭の定義は §6 の「操作を色なしで示す土台」で、ほかの箇条はそれに従って読まれる。読み手（T5a-5 の builder、以後の面の書き手）はどちらに従うかを決められない。4-2 の177行（「その問のどの選択肢もボタンから字に替わり、押しても何も起こらない形になる」）も同じ食い違いを持つ。押した行は、下線という「実行するもの」の印を持ったまま「押しても何も起こらないもの」に数えられている。

直すこと: 診断で見せているあいだの押した選択肢を、§6 のどの種類に数えるかを1つに決め、冒頭の定義・表の行・下線の箇条・4-2 をその1つで書き直す。たとえば、押した選択肢は「実行されているさいちゅうのもの」として実行するものの側に数え（リンクを押してから次のページが出るまで、そのリンクが下線を持ったままなのと同じ）、冒頭の定義の「答えた選択肢」は押していない選択肢と、実行が終わった知識クイズの選択肢を指す、と定義の中で言い切る形がある。どの形でも、定義に「ただし」を後から足した跡を残さない（ツギハギ禁止）。

### 2. 知識クイズの添えた字を名前の下に置く CSS が決まっておらず、4-11 の消す指定だけを実装すると、添えた字が名前の右で縦の列になる

4-11 は `.choice` の `justify-content: space-between`・`flex-wrap`・`column-gap` を消し、`padding-block` と `min-height` を消すとする。残るのは `display: flex` と `align-items: baseline` で、並びの向きは行（横）のままである。4-2 と 4-4 は「添えた字は名前の下の自分の行」と結果を書くが、それをどの宣言で作るかを書いていない。

実測（上の組み。320 の画面）:

| `.choice` の組み                                       | 3行の名前の押した行（「あなたの回答は不正解」）                            | 1行の名前の正解の行（「正解」）                   |
| ------------------------------------------------------ | -------------------------------------------------------------------------- | ------------------------------------------------- |
| 4-11 の消す指定のまま（`display: flex`・折り返しなし） | 添えた字が名前の右に幅 14 の列で並び、1字ずつ縦に10行。行は 88.39 → 216.94 | 名前の右に並ぶ（下に来ない）                      |
| `display: block`（添えた字は `span` のまま）           | 名前の下に来る                                                             | 名前の右に並ぶ（名前の箱が `inline-flex` のため） |
| `flex-direction: column; align-items: flex-start`      | 名前の下。行は +27.59                                                      | 名前の下。行は +27.59                             |

- 名前の箱は `flex-shrink: 0`・`max-width: 100%` で、2行以上なら行の幅を使い切る。4-11 で `white-space: nowrap` も外すので、添えた字は残りの幅 0 に縮み、和文の最小の幅（1字）の列になる。
- 4-2 の「左の端を名前の字にそろえ（`data-text-box="inline"` の余白）」は、添えた字に `data-text-box` を掛けるとも読める。縦の並びなら、添えた字は `li` の内側の余白から始まり、掛けなくても名前の1字目とそろう（実測）。掛けると `globals.css` のリングの変数の対象にも入り、4-11 の説明の並び（答えた選択肢の字）とも合わない。
- T5a-2 の近似（7章）は「知識クイズの添えた字の行」を差し込むが、どの組みで差し込むかが決まっていないので、近似の値が実装と別の組みの値になりうる。

直すこと: 4-4 か 4-11 に、`.choice` の並びの向き（縦の並びにし、名前の箱と添えた字を左に寄せる。あるいは同じ結果になる別の組み）と、添えた字の要素の組み（大きさ・行間 1.4・下の 8px・太さ 400、`data-text-box` を持つか）を書く。診断の行もこの並びで、押す前と押したあとの字の位置が変わらないことを条件1 の走査が確かめる（縦の並びでも、名前の1字目の位置は押す前と同じだった。実測）。T5a-2 はこの組みで近似する。

### 3. 診断で押した行に残す下線の宣言を、どこから得るかが決まっていない

4-4 の共有する規則は `.button` の箱の宣言8つだけで、下線は `Button.module.css` の `.variantDefault`（`text-decoration: underline`・`text-decoration-thickness: var(--rule-w-hair)`・`text-underline-offset: 0.15em`）にある。答えたあとの字は `Button` のクラスを持たないので、4-2 の「押したものは下線を残す」を `text-decoration: underline` だけで実装すると、線の太さと字からの離れが書体の既定になり、押した瞬間に押した行の下線の太さか位置が変わる。「押した行は変わらずに残る」ことが押した形の印なので（上の「確かめたこと」）、そこが動くと印が弱まり、§11 の「1つの操作に応える動きは1つだけ」にも触れる。

直すこと: 4-4 の共有する規則に、下線の3つの宣言も `Button`（プライマリでないもの）と押した答えの字で共有することを書く（`.variantDefault` の下線の宣言を1つの規則にまとめる）。条件3 の撮る像で、押す前と押したあとの押した行の下線が同じであることを見る。

### 4. 診断の読み上げ専用の「あなたの回答」は、150ms のあいだしか無く、読み上げではほぼ読まれない

4-2（182行）は、診断で押した行にフォーカスを置き（4-7）、行の中の読み上げ専用の字「あなたの回答」で押したことを言う、とする。5章の §6 の箇条（460行）も「読み上げには、押したものであることを見えない字で言う」と `DESIGN.md` に書く。

- 行へのフォーカスは 150ms で次の問の見出しへ移る（4-7）。読み上げの支援技術は、フォーカスが移るとそれまでの読みを止めて新しいフォーカスを読むので、押した行の読みは 150ms で切られる（推論。NVDA・JAWS・VoiceOver の既定のふるまい）。150ms は数モーラで、行の名前の頭しか読めず、名前のあとにある「あなたの回答」には届かない。
- したがって、この字は画面の読み上げの来訪者に何も届けず、`DESIGN.md` の文は実際に起きないことを決まりとして書く。`aria-current` との比べ（182行）も、読まれる前提の上に立っている。読み上げの来訪者が答えが入ったと知るのは、次の問の見出しが読まれることによる。
- 8章の T9 は、VoiceOver の確かめを知識クイズの押した行だけに置いており、診断の流れで何が読まれるかを確かめない。

直すこと: 4-2 と 5章 §6 の文を、読み上げで実際に起きること（押した行のフォーカスは、画面の上の `body` に落とさずリングを見せるためのもので、読み上げの来訪者には次の問の見出しが読まれることで答えが入ったと伝わる）で書き直す。読み上げ専用の字を残すなら、読まれる見込みと残す理由を書き、残さないなら 182行の比べごと外す。8章の T9 と「PM が足す行」の3に、VoiceOver で診断を答えたときに何が読まれるか（押した行の読みが切られるか、次の問の見出しが読まれるか）を加える。

### 5. 4-6 の知識クイズの高さの見込みが、1行の選択肢が 1 ずつ高くなる分を数えていない

4-6（302行）は、kotowaza の 441 に添えた字の行2つ（約 55.2）を足して約 496、534 まで約 38 残るとする。同じ文書の 4-4（258行）は、1行の選択肢が近似の 44 から 45 へ行ごとに 1 高くなると書いている。知識クイズの選択肢は4つで、kotowaza の選択肢は1行なので、+4 して約 500、残りは約 34 になる（算術）。字の幅が狭くなる分（約 24 ずつ）を1行ぶん受けると約 10 しか残らない。数は合否に使わず T5a-2 が測るので設計の向きは変わらないが、4-4 が挙げた差の1つを 4-6 だけが落としている。

直すこと: 4-6 の算術に行ごとの +1 を入れる（約 500、残り約 34）。

### 6. 残った語と、触るファイルの説明の漏れ

- 6章 条件11（541行）の「押した形（添えた字が名前の下に落ちた行を含む）」は、添えた字が名前の右に入らないときだけ下に「落ちる」とした前の置き方の語である。いまは診断は字を添えず、知識クイズはいつも名前の下に置く。「押した形（診断で押した行だけが下線を持つ形と、知識クイズの添えた字の行）」のように、いまの置き方で書く。
- 7章 T5a-5 の触るファイルの `src/app/globals.css` の説明は「リングを内側に置く対象に行の一覧の行」だけで、4-11 が決めた `[data-text-box]` の規則の上の説明の書き直しが無い。T5a-5 の担当が表から作業を読むと落とす。説明にあわせて足す。
