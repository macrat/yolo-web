### 2. 指摘

**major-1 境界のページを「刷新後の Web フォントの転送量が最大のページ」と定義しているが、合否の線は「増分」なので、選ぶ尺度が問いとずれている（AP-P02）**

- どこ: index.md:94「刷新後に Web フォントの転送量が最も大きくなると見込まれるページ」
- なぜ:
  - 合否の線は「変更後が変更前を超えない」、つまり増分です。境界のページが試すべきなのは、**増分（変更後 − 変更前）が最も大きくなるページ**です。変更後の絶対値が最大のページとは限りません。
  - この2つは実際にずれうります。
    - いまのサイトは、見出しと辞典の大字などに Noto Serif JP 600 を Web フォントで配っています（src/lib/fonts.ts、facts-design-gap §4-1・§12-1）。
    - そのため `/dictionary/kanji/哀` は、変更前の時点で Web フォントを 835KiB 払っています（facts-speed-before の表）。
    - 刷新後に新しく増えるのは、主に本文の BIZ UDPGothic です。この分は、変更前に本文の Web フォントが0だったページ、つまり本文の字が多く見出しの明朝が少ないページで最も大きくなります。
  - 今の定義では、変更前から重い辞典系のページが選ばれる恐れがあります。その場合、増分は小さく出て、上限を最も越えやすいページが試されません。これは10巡目の major-1 と11巡目の major-1 (3) が指摘した「比べる相手の側での覆い隠し」と同じ構造です。
  - 「このサイクルで中身が変わらないページのうち」という限定の目的（比べる相手と中身が同じであること）も、index には書かれていません。そのため、ページ送りが入る一覧・T7 で文言が変わるトップ・T6 で札が変わる結果ページが範囲に入るのかを、T1a の作業者が判断できません。
- どう直すか: 定義を目的の側から書き直してください。見つけ方は引き続き T1a に任せてかまいません。例:
  - 「**境界のページ**は、変更前と変更後で同じ中身を描くページ（比べる相手が同じであるため）のうち、変更後の総転送量と変更前の差が最も大きくなると見込まれるページ。リクエストごとに描くページも含む全ページから T1a で選ぶ」
  - 本文の書体と見出しの書体で増分の出方が違うため、1ページでは最悪の場合を代表できないと T1a が判断したら、複数を選べるようにしておくとなお良いです。
