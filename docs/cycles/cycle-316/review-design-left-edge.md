## 指摘

### Major-1 無効の枠を「状態を示す線」に数えたので、前回の Major-2 のずれが規則として固定された

新しい規則は「状態を示す線（hover の線・無効の枠・フォーカスのリング）は、いつも見えている形に数えない」と書く。そのうえで、字だけで見えるものの状態を示す線は、字の左に 8px はみ出す箱に出す。

この書き方で、次の形が規則どおりになる。

- 無効のプライマリボタンは、地が消えて破線の枠だけになる（§6 の表「無効: 太い破線の枠・…反転しない」）。枠は地があった位置、つまりコンテンツ幅の左端にある。
- 無効のプライマリでないボタンの破線の枠は、コンテンツ幅の左端より 8px 左にある。
- 入力欄の枠はコンテンツ幅の左端にある。

道具のページでは、入力が揃うまでボタンが無効のことが多い。来訪者がページを開いた最初の画面で、入力欄の枠・無効のプライマリボタンの枠・無効のプライマリでないボタンの枠が縦に並び、1つだけ 8px 左へ出る。前回のレビューで「ずれが揃え損ないに見える」とした形が、そのまま残る。狭い画面（余白 8px）では、この破線の枠がコンテナの太いボーダーに接し、太い線が2本並ぶ。§6「太い線で囲まれたものは、線種・大きさ・位置で読み分ける」も崩れる。

hover の線とフォーカスのリングは、来訪者が載せたり移したりしているあいだだけ出る。無効の枠は、条件が揃うまでずっと出ている。「いつも見えている形に数えない」という理由は、前の2つには当てはまるが、無効の枠には当てはまらない。前回のレビューは「無効の破線の枠が、有効なときと同じ位置で、ほかの部品の左端と矛盾しない」形を決め、その理由を書くことを求めていた。今回の書き直しは、そのどちらもしていない。

**直し方**: planner が、プライマリでないボタンの無効の見え方を次のどれかに決め、理由とともに §5・§6 とサイクルの文書に書く。

- 無効のプライマリでないボタンは、破線の枠を箱の縁に出さない。字の位置は変えずに、無効を別の形で示す。§6 の表の「無効」は種類ごとの見え方に書き分ける。
- プライマリでないボタンを、有効なときも無効なときも「形を持つもの」として扱い、箱の左端をそろえる。この場合、字はリンクより 8px 右から始まる。そのずれを来訪者がどう読むかも評価する。
- 無効の枠を、プライマリボタンを含めて一律に「字の左に 8px はみ出す箱」に出す。この場合、プライマリボタンの無効のときの位置が有効なときとずれるので、その扱いを決める。

どれを選んでも、「無効の枠は、いつも見えている形に数えない」とは書かない。

### Major-2 本文の中のリンクのフォーカスのリングが決まっていない。hover を消す決め方は、来訪者が得られる手がかりを減らし、§6 の原則に例外を足している

**(a) フォーカスのリング。** 規則は、本文の中のリンクは「この箱を持たない」と書くだけである。リングをどこに出すかは、§6「二重リングは、要素の外に余地があれば外、なければ内側に出る」に任される。本文の中のリンクは、左右が隣の字に接している。外に出すと、前回のレビューで見た「、」「に」に掛かる形が残る。内に出すと、1行の高さの中に 6px の輪が入り、字と下線を覆う。どちらに読んでも来訪者の見る形が壊れる。キーボードでブログを読む来訪者が最初に出会うフォーカスが、ここである。前回の Minor-4 の直し方は「本文の中のリンクの hover とリングの出し方を §6 に書き、隣の字に掛からない形にする」だった。リングは書かれていない。

**(b) hover を消す決め方。** 新しい §6 の箇条は、「hover は、進むもの・実行するもの・状態を変えるものに出る」と言った直後に、進むものである本文の中のリンクを外している。書き込む欄と選ぶ欄は、もともと3つのどれでもないので、外すと書いても確認にすぎない。本文の中のリンクは3つの中にあるので、これは原則に足した例外になる。§6 の表の「hover / active: 要素の内側に細いボーダーが現れる」も条件を持たないので、この箇条と食い違う。active も消すのかは書かれていない。

理由の前半「下線がすでに進むことを示していて」は、上端のナビや一覧の行など、下線を持つすべての進むものに当てはまる。そのため、本文の中のリンクだけを外す理由にならない。本文の中のリンクだけに当てはまるのは、後半の「字に接する線を足すと下線と読み違える」である。つまり理由は「内側の細い線という形が本文の中に合わない」ことで、「hover が要らない」ことではない。

来訪者の側から見ても、hover を消すのは損である。GOV.UK Design System は 2019 年のアクセシビリティ監査で「hover の手がかりを見落とす利用者がいて、視覚に障害のある利用者に偏って影響する」と指摘され、本文のリンクの hover を、下線を太くする形に改めた（出典は冒頭の根拠を参照）。このサイトでも、§6「下線は、進むもの・実行するものの専有」の中で、細い下線を太い線と同じ太さにする hover が作れる。この形なら字に接する線を足さず、下線と読み違えることもなく、原則に例外を足さずに済む。

**直し方**: planner が §6 で、本文の中のリンクの hover とフォーカスの形を、ほかの進むものと同じ並びの中で決める。例えば、§6 の表の hover とフォーカスの行を、種類ごとの形として書く（字だけの箱を持つもの・形を持つもの・本文の中のリンク）。hover の箇条は「進むもの・実行するもの・状態を変えるものに出る」のまま例外を持たないようにする。§5 の規則の最後の一文（「本文の中のリンクは、この箱を持たない」）も、後から足した例外に読める。「字だけで見えるもの」の括弧を「本文の外に置くリンク」とし、本文の中のリンクの扱いは §6 に置く。§6 のタップターゲットの箇条の「本文中のインラインリンク」と今回の「本文の中のリンク」は、同じものを指す別の言葉なので、1つにそろえる。

### Major-3 ラジオボタン・チェックボックス・アコーディオンが、左端の規則のどの分類に入るかが読めない

規則は、いつも見えている形を「地を塗ったもの」「線で囲んだもの」「線で区切った並び」「字だけで見えるもの」に分ける。ラジオボタンとチェックボックスは「太い線で描く 20px の円・四角」とラベルの組で、アコーディオンは三角とラベルの組である。どれもこの4つにそのままは入らない。

読み方によって、来訪者に見える形が変わる。

- 円・四角を「線で囲んだもの」と読むと、円の左端をコンテンツ幅の左端にそろえる。§6 はラベルを含む行全体をタップターゲットにし、hover はその「要素の内側」に出し、リングはタップターゲットと一致させる。行の左端が円の左端と同じなので、hover の細い線の左の辺は円の太い線に重なる。リングは外に余地があれば外に出るので、狭い画面では余白 8px にリングの 6px が入り、コンテナのボーダーとの間は 2px しか残らない。
- 行を「字だけで見えるもの」と同じ箱で組むと読むと、円が左へ 8px はみ出すのか、円の左端をそろえて箱だけがはみ出すのかが決まらない。

次のタスクで builder が組むのは、まさにこれらの部品である。規則が一意に読めないまま渡すと、前回の Major-1・Major-2 と同じく、実装のレビューで規則の食い違いが見つかってやり直しになる。セグメント切替・トグルスイッチも、DESIGN.md に相当の無い部品として次のタスクで置き換えるので、同じ問題を持つ。

**直し方**: planner が、円・四角・三角とラベルの組を規則のどこに置くかを決める。いつも見えている形（円・四角・三角）の左端をそろえるのか、ラベルの字をそろえるのかを書く。hover の線とリングを、形に重ねず、コンテナのボーダーにも接しない位置に出すための組み方（行の内側の余白の有無）も書く。

### Minor-1 字だけで見えるもののリングが、箱の内側に出るのか外に出るのかが読めない（前回の Minor-5 の後半）

§5 は、状態を示す線を「箱に出し」と書く。§6 は「二重リングは、要素の外に余地があれば外、なければ内側に出る」と書く。この2つを合わせて読むと、1280px（余白 16px）では、箱の外に 8px の余地があるのでリングは箱の外に出て、狭い画面では内に出ることになる。画面の幅でリングの位置が変わる。いまの実装は、どの幅でも箱の内側に出している。前回の Minor-5 は、§6 の箇条に「字だけで見えるものは箱の内側に出る」と書き、§5 と同じことを言うように求めていた。§6 のこの箇条は今回変わっていない。

**直し方**: §6 のリングの箇条を、どの要素でどちらに出るかが1通りに読める形に書き直す。例えば「外に余地があれば外」の「余地」が何を指すか（隣の要素・コンテナのボーダーまでの距離）を書く。

### Minor-2 狭い画面で、箱の縁がコンテナとボックスのボーダーに接する形が規則に残る（前回の Minor-1）

新しい規則は、字だけで見えるものの箱が、字の左に 8px はみ出し、コンテナかボックスの内側の余白に張り出すと書く。`45rem` 未満では、コンテナとボックスの余白は 8px である（§5）。そのため、コンテンツ幅の左端にある字だけのコントロールは、箱の縁がボーダーにちょうど接する。リングを箱の内側に出しても外に出しても、ボーダーと一体に見える。§5「余白と間隔は 8px の倍数」があるので、箱の余白を 8px より小さくして間を空けることもできない。規則の数字の組み合わせのままでは、この形は避けられない。

前回のレビューは、この指摘を「次の作業 1」で planner が今回決め直すものに入れていた。今回の依頼の範囲からは外れていて、規則にも手が入っていない。

**直し方**: planner が、狭い画面での箱とボーダーの関係を決める。例えば、狭い画面では箱をはみ出させない、狭い画面の余白を広げる、リングの外の輪をボーダーと区別できる形にする、などである。

### Minor-3 「字の左右に 8px の余白を持つ箱」が、44px のタップターゲットと §5 の幅の表と一致しない

- ページ送りの番号（「3」など）は字の幅が 10px 前後である。左右 8px を足しても 26px 程度で、§6 の 44px に届かない。§6「フォーカスリングはタップターゲットと一致する」ので、リングの箱は 44px 以上になり、「字の左右に 8px」が成り立たない。いまの実装は、左の余白を 8px に保ち、`min-width: 44px` で右を広げている。規則は、この形を「字の左に 8px」「幅はタップターゲットに合わせる」と書くべきである。
- §5 の幅の表は、コントロールの幅を「字の大きさに、タップターゲットが 44px に届くまで余白を足した幅」と書く。字が 28px より広いときは、この表では余白が 0 になる。新しい規則では左右に 8px ある。字だけで見えるコントロールの幅がどちらで決まるのかを、表と規則のどちらかで言い直す。

### Minor-4 「線で区切った並び」に表と小見出しが入るかが読めない。一覧の行の字をどれだけ下げるかが書かれていない

- §5 の表は「行どうし・列どうしを細い罫線で区切る」。セクションの中の小見出しは「上に細い罫線を引く」。どちらも線で区切ったものである。新しい分類の括弧は（一覧の行）だけだが、原則「左端に揃えるのは、いつも見えている形の左端」と「字は形の内側の余白から始まる」を当てると、表の1列目の字や小見出しの字も内へ下げると読める。括弧が例示なのか、すべてを挙げたものなのかを決め、表と小見出しでは字を下げないならそう読める形にする。
- 一覧の行の「形の内側の余白」がいくつかが書かれていない。ボックスの余白（16px・狭い画面で 8px）と同じなのか、字だけの箱と同じ 8px なのかで、見出しとの字のずれが変わる。数値を書く。

### Minor-5 §5 の規則の箇条が長く、書き方の上で後から足した跡に読める。サイクルの文書に理由が無い

- §5 のほかの箇条は、太字の1文と短い補足でできている。新しい箇条は6文あり、分類・字の位置・状態の線・箱・張り出し・例外を1つの箇条に詰めている。最後の「本文の中のリンクは、この箱を持たない」は、書き足した例外に見える（Major-2 で扱う）。分類ごとの箇条か小さな表に分け、1つ読めば1つのことが分かる形にする。
- 前回のレビューは、Major-2 の決め方と理由を「DESIGN.md（§5・§6）とサイクルの文書に書く」ことを求めていた。`docs/cycles/cycle-316/` には、今回の決め方の理由がまだ無い（「状態を示す線」「線で区切った並び」を含む文書は見つからない）。理由はサイクルの文書に書く。
