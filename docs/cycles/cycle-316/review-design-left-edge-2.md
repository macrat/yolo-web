## 指摘

### Major-1 アコーディオンと、本文の外にある多くのリンクが、2つの分類のどちらにも入らない

新しい箇条は部品を列挙して2つに分ける。

- 箱の左端を揃えるもの: ボタン・入力欄・色見本・一覧の行・ラジオボタンとチェックボックスの行
- 字の左端を揃えるもの: 上端・下端のナビ、パンくず、ページ送り、本文の外に単独で置くリンク

列挙にしたので、列挙に無いものは規則が決めない。次のものが漏れている。

- **アコーディオン。** §6 はアコーディオンを「その場で状態を変えるもの」として、ボタン（下線を持つ、進むもの・実行するもの）と分けている。したがって「ボタン」には読めない。§7 は `45rem` 未満で絞り込みをアコーディオンに畳み、そのラベルが現在の絞り込み・並び順・件数を言う。狭い画面の一覧のページで、来訪者が最初に触るコントロールの一つである。三角をコンテンツ幅の左端に置くのか、箱の内側 8px に置くのかで、上の入力欄の枠・下のラジオの円との並びが変わる。
- **箇条書きの中のリンク**（関連ページの一覧など）、**表のセルの中のリンク**、**一覧の行の中に置く別のリンク**（§7「行の中に別のリンクを置くときは、それだけを独立に押せる」）、**結果のボックスの中のリンク**。どれも「本文の外に単独で置く」とも「本文中のインライン」とも言い切れない。とくに、項目がリンクだけの箇条書きは、WCAG 2.5.8 の inline の例外（"in a sentence or its size is otherwise constrained by the line-height of non-target text"）に当たらない。インラインとして扱えば 44px のタップターゲットも箱も失い、来訪者の指で押しにくくなる。

T2 で builder が組むのはまさにこれらの部品なので、規則が決めないまま渡すと、実装のレビューでまた規則の側に戻ることになる。

**直し方**: planner が、列挙を「どの性質で分けるか」の定義に改めるか、列挙に漏れた部品を入れる。例えば「形（地・枠・円・四角・三角）を持つコントロールと、形を持つものを含む行は箱で揃える。字だけで見えるコントロールは字で揃える。文の中にあるリンクだけが箱を持たない」と性質で書き、括弧で代表例を挙げる。インラインの範囲は WCAG 2.5.8 に合わせ、「文の中にあるリンク」とし、項目がリンクだけの箇条書きは字だけで見えるものの側に入れる。

### Major-2 §5 の幅の表と新しい箇条が、同じコントロールに別の幅を与える（前回の Minor-3）

- 幅の表: コントロールは「字の大きさに、タップターゲットが §6 の 44px に届くまで余白を足した幅」。字が 44px 以上なら余白は 0 になる。
- 新しい箇条: 「箱の幅は字の左右に 8px を足した幅で、44px に届かなければ右へ広げる」。字が 100px なら 116px になる。

同じ §5 の中で、例えば 100px の字のボタンに 100px と 116px の2つの答えが出る。さらに、この一文は字が並ぶだけのものの文の直後にあるので、ボタンにも掛かるのかが読めない（ボタンは「字は箱の内側 8px から始まる」とだけ書かれ、右の余白が無い）。入力欄と一覧の行は幅の表で決まる幅を持つので、この一文は掛からないはずだが、それも書かれていない。

**直し方**: 幅の表の「コントロール」の行を新しい規則と同じ言い方にする（例: 「字の左右に 8px を足した幅。44px に届かなければ右へ広げる」）。入力欄・一覧の行は表のそれぞれの行で幅が決まることが読めるので、箇条からは幅の文を取り、幅は表だけで言う。1つのことを1か所で決める。

### Major-3 §6 の二重リングの箇条が、頭の一文と足した一文で食い違い、「余地」が定義されない（前回の Major-2(a)・Minor-1）

- 頭の一文は「要素の外に余地があれば外、なければ内側に出る」。本文中のインラインリンクは左右が前後の字に接しており、余地が無い。足した一文は、そこで「字の外に出て、前後の字に掛かる」と言う。頭の一文の規則からは出ない答えで、書き足した例外に読める（CLAUDE.md のツギハギ禁止）。
- 「余地」が何を指すかは今回も書かれていない。§5 の新しい箇条は「フォーカスのリングは、どれも箱に出る」と言うだけで、箱の内か外かは言わない。字が並ぶだけのものの箱は、コンテナの余白 16px のうち 8px に張り出すので、1280px では外に 8px の余地があり（リング 6px が入る）、320px では 0 になる。画面の幅でリングが外に出たり内に出たりする。箱で揃えるものも、狭い画面で外に 8px しか残らず、外に出せばリングとコンテナのボーダーのあいだは 2px になる。「余地」が 6px 以上なのか、ボーダーから何 px あくことなのかで答えが変わる。
- インラインリンクのリングを外に出すと、内の `--paper` 3px と外の `--ink` 3px が、前後の字の 6px を覆う。16px の字では前後の1字の3分の1以上が隠れ、上下の行にも掛かりうる。フォーカスのあいだだけとはいえ、キーボードで本文を読む来訪者が、リンクの前後の字を読めなくなる。サイクルの文書の補足事項は hover の理由だけを書いていて、リングを外に出す判断の理由（内に出す案・下線を太くするだけの案と比べてなぜこれか）が無い。

**直し方**: planner が、二重リングの位置を要素の種類ごとに1通りに読める形で書く。例えば「箱で揃えるもの・字で揃えるものは箱の内側（または外側）に出る。一覧の行は内側。文の中のリンクは字の外に出る」と種類で列挙し、「余地があれば」を使わない。インラインリンクのリングは、前後の字を覆うことを来訪者の損として評価し、選んだ理由をサイクルの文書に書く。

### Minor-1 箇条の見出しと中身が合わず、「字」が円・四角・色見本に当てはまらない

- 見出しは「コントロールは、押せる範囲の箱で左端を揃える」だが、中身の後半は「字の左端を揃え」る。見出しを読んだ人は、ナビやページ送りも箱で揃えると受け取る。後半が見出しに対する例外に読める。
- 「字は箱の内側 8px から始まる」は、ラジオボタンとチェックボックスの行では最初に来るのが 20px の円・四角で、字ではない。円が 8px から始まり字がその右なのか、字が 8px から始まるのかが、文字どおりには決まらない（意図は前者と思われる）。色見本は §2 で「文字を載せない」ので、字が無い。
- 1つの箇条に分類・字の位置・張り出し・幅・状態の線が入っており、§5 のほかの箇条（太字の1文と短い補足）と形が揃わない。

**直し方**: 見出しを2つの分類を両方言える形にする（例:「コントロールの左端は、いつも見えているものの並びで揃える」のあとに2つの小箇条）。「字」は「中身」と書く。

### Minor-2 色見本はコントロールではない

§2 の色見本は「色だけを見せる」コンテンツで、§6 の押せるものの列挙にも無い。§5 の幅の表でも画像と同じ「コンテンツが決める」側にある。押せないものを「押せる範囲の箱で揃える」に入れると、色見本に箱の内側の余白があると読める。§7 の一覧では色見本は行の先頭、つまり一覧の行の箱の内側にある。色見本は細い枠を持つ形なので、単に「コンテンツ幅の左端に置く」と §5 のほかの位置の規定に任せればよい。

**直し方**: 列挙から色見本を外す。押せる色見本（クリックでコピーなど）を置くなら、それはボタンとして箱で揃う、と読める形にする。

### Minor-3 ページ送りの無効では、狭い画面で破線の枠がボーダーにずっと接する

サイクルの文書は「接するのはフォーカスか hover のあいだだけ」を理由に、狭い画面で箱の縁がコンテナ（とボックス）のボーダーに接する形を認めた。しかし新しい箇条は「無効の枠」も箱に出すと書き、ページ送りは字で揃える側にある。最初のページの「前へ」を無効で見せると、`45rem` 未満では太い破線の枠がボックスの太いボーダーに接したまま表示され続ける。§6「太い線で囲まれたものは、線種・大きさ・位置で読み分ける」も崩れる。

**直し方**: ページ送りの端（最初のページの「前へ」・最後のページの「次へ」）を無効で見せるのか、置かないのかを決める。無効で見せるなら、この形の扱いを書く。字で揃える側の部品で無効を持つものがほかに無いことも確かめる。

### Minor-4 プライマリでないボタンの字が、見出し・本文・単独のリンクより 8px 右に立つ。その評価がサイクルの文書に無い

プライマリでないボタンは、平常時は下線の字だけで見える。箱で揃えるので、字はコンテンツ幅の左端より 8px 右に立つ。見出し・本文・単独のリンクは左端に字がある。結果のボックスの中で、大きな数字の下に「コピーする」を置く、単独のリンクとボタンを縦に並べる、といった形では、同じく下線を持つ2つが 8px ずれて見える。サイクルの文書の理由は「箱の左端（無効の破線・入力欄の枠・一覧の罫線）がそろう」ことで、平常時のプライマリでないボタンでは箱が見えないことには触れていない。前回のレビューが選択肢の2つ目で求めた「そのずれを来訪者がどう読むか」の評価が無い。

この判断自体は成り立つ（無効のときに位置が動かないことの方が得が大きい、と言える）。ただ、評価と理由を書き、実装のレビューでスクリーンショットで確かめる項目にする。同じく、プライマリボタンの左右の余白が 8px（高さ 44px に対して）で窮屈に見えないかも、スクリーンショットで確かめる。

### Minor-5 字が並ぶだけのものを横に並べるときの間隔が、字どうしか箱どうしか読めない

箱は字の左右に 8px ずつ出る。字どうしの間隔を 8px にすると、隣り合う箱が 8px 重なり、hover の線とリングが隣の項目に食い込む。§5「余白と間隔は 8px の倍数」がどこからどこまでを測るのかを、この部品では「箱どうし」と書く。

### Minor-6 インラインリンクの hover の太い下線の色が読めない

§5 の線の表では、太い線の色は `--rule`（`--ink`）である。訪問済みのリンクは字が `--ink-2` なので、「下線が太い線になる」を線の表どおりに読むと、hover で下線だけが `--ink` に変わる。字の色の下線を太くするのか、太い線の色にするのかを書く。

### Minor-7 サイクルの文書のレビューの記録に、左端の規則の単独レビューの行が無い

`index.md` のレビューの記録の表は「T2 コントロールの土台 3巡目（1d28c86）」で終わり、[review-design-left-edge.md](./review-design-left-edge.md) の回（major 3・minor 5、改善指示）とその反映が記録されていない。今回の回も含めて行を足す。
