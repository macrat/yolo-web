## 指摘

### Major-1 正規表現テスターのパターンの欄が 15.2px のまま残り、iOS でフォーカスすると画面が拡大する（B-663）

`src/tools/regex-tester/RegexTesterTile.module.css` の `.patternInput` は `font-size: 0.95rem` で、既定のルートで 15.2px になる。320・375・1280px のどれで測っても 15.2px だった。

- inventory の §4「16px を下回るもの」は、この欄を部品の3つと並べて挙げている。T2 は B-663 を受け持ち、完了の条件は「すべての入力欄の文字サイズが 16px 以上」である。
- c233f78 のコミットメッセージは「文字を 16px 以上にする（B-663）」と書く。部品の3つは直ったが、この欄は直っていないので、主張と実装が合っていない（AP-WF04）。
- 来訪者への害: iPhone でパターンの欄を押すと、Safari が約 1.05 倍に画面を拡大し、来訪者が周囲を見失う。§4 が「16px を下回らない」と定める理由そのものである。

この欄は、`/` で挟む飾りのために枠を `.patternRow` に移した自前の入力欄で、ほかにも `--rule-strong`・`--radius-sm`・`outline: 2px solid var(--accent)` を持つ。T5 がページの独自の規則を消すのを待つと、B-663 の直しだけが T2 から抜け落ちる。

**直し方**: builder が、この欄の文字を `--text-input` にする。あわせて、欄の枠とフォーカスを共通の入力欄の形（`[data-field]` と、枠の外の二重リング）で組めるかを見る。組めないなら、その理由を index.md の補足事項に書き、T5 の行に残す。

### Minor-1 `DESIGN.md` の誤字と、§5 と §6 のあいだの食い違い

- §6 の箇条「タップターゲットは 44px 以上」が「**本本文**の中のリンク」になっている（c0c458d で入った）。
- c233f78 は §6 に「書き込む欄・選ぶ欄と本文の中のリンクだけは、（リングが）外に密着して出る」を足した。しかし §5 は「コンテンツ幅の外へ出るのは、全幅の罫線と、縁の見えないコントロールの押せる範囲と、そこに出る状態の線…だけである」と書く。入力欄の縁と本文の中のリンクの字はコンテンツ幅の左端に立つので、そのリングは 6px コンテンツ幅の外へ出る。§5 の文面では、これが許されない。実装はできる（狭い画面でもコンテナの内側の余白 8px に収まる）が、文書どうしが食い違っている。

**直し方**: planner が「本本文」を直し、§5 の「コンテンツ幅の外へ出るもの」に、入力欄と本文の中のリンクの外に出るリングを加える。

### Minor-2 アコーディオンの三角が、揃えるべき左端より約 4px 右に立つ

§5 は、アコーディオンは「最初の字か形を揃え」ると定める。三角の SVG の箱（20px）は左端に立つが、描いた三角は viewBox の x=6 から始まるので、見える形は箱の左から約 4.5px 右に立つ。

- 375px の `/tools/password-generator`: 「よくある質問」の見出しの字が x=43、三角の左端（線を含む）は約 47.5。
- `/storybook` の 18 番: 「Accordion」の字と、下に並ぶ三角の左端がずれて見える。同じパネルの 8 番では、チェックボックスの四角の縁が字と同じ x に立つので、並べると差が目に入る。

**直し方**: builder が、三角の左の頂点を SVG の箱の左端（線の太さの半分の内側）に置く。箱の幅は三角に合わせて詰めてよい。

### Minor-3 ファイルを選ぶ欄は、エラーのとき太い線にならず、理由の文とつながらない

§8 は「エラーのときだけ太いボーダーになる。その直下に、何が問題でどう直すかを文字で書く」と定める。`FileDropZone` は `error` を受け取らないので、10MB を超えるファイルを選んでも、欄は細い線のままである（`/tools/image-base64` の 375px で撮った）。理由の文（「ファイルサイズが10MBを超えています」）は欄の下に出るが、道具のページが別に置いた `ErrorMessage` で、欄の `aria-describedby` にはつながらない。文言も「何が問題か」だけで「どう直すか」が無い。

**直し方**: builder が、`FileDropZone` に `error` を渡せるようにし（`Field` と同じく、枠を太くし、理由の文を欄の直下に置いて説明として結ぶ）、image-base64・image-resizer をそれで組む。理由の文に直し方（「10MB 以下の画像を選んでください」など）を足す。

### Minor-4 無効の入力欄・チェックボックス・ラジオボタンに、理由を添える手段が無い

§6 の「無効」は「理由を文字で添える」までを含む。`Button` は `disabledReason` を持つが、`Field`・`Checkbox`・`Radio` は無効の見え方（太い破線の枠と `--ink-2`）だけを持ち、理由を添える手段が無い。storybook の見本も、理由の無い無効の欄と行を並べている。

いま道具で無効にしている欄は見当たらないが、部品として §6 の半分しか満たさないまま T5 に渡すと、使う側が理由を忘れる。

**直し方**: builder が、`Field` と `ChoiceRow` に無効の理由を渡す口を持たせ（`Button` の `disabledReason` と同じ作り）、storybook の見本に理由を添える。

### Minor-5 選ぶ欄の候補は、マウスを載せても見え方が変わらず、押す前にどれが選ばれるかがリングと食い違う

`Select.module.css` は、候補を開ける Chrome で、候補の hover の色を消している。そのため、マウスを「4スペース」に載せても、リングは「2スペース」に残る。この状態で Enter を押すと「2スペース」が選ばれる。マウスで開いた来訪者には、どれを押そうとしているかの手がかりが指の位置しか無い。

§6 の「選ぶ欄は hover で見え方を変えない」が欄そのものに掛かるのか、開いた候補の一つ一つ（押すと状態を変えるもの）にも掛かるのかは、`DESIGN.md` が決めていない。index.md の補足事項は、候補の選択済みの印をブラウザの既定のままにすると書くが、候補の hover は書いていない。

**直し方**: PM が、候補の hover をどう見せるかを決める。候補は押すと状態を変えるものとして、押せる範囲の内側に細い線を出すのが §6 の読み方に合う。決めた形を planner が §6 か §8 に書き、builder が合わせる。

### Minor-6 コードのコメントとテストの説明が、いまの実装と合わない

- `globals.css` の `[data-text-box="inline"]` のコメントは、「"inline" は縁が見えないもの（リンク・プライマリでないボタン・ページ送り・パンくず）」と書く。いまはチェックボックス・ラジオボタンの行とアコーディオンも `inline` を使う。
- `SqlFormatterTile.test.tsx`（「キーワード大文字トグルスイッチが表示される」ほか）と `LineBreakRemoverTile.test.tsx`（「トグルスイッチが表示される」）の説明が、消した部品の名前のまま。
- `RegexTesterTile.module.css` の冒頭のコメントは、フォーカスを「outline: 2px solid var(--accent)」、境界線を「--rule-strong」と書く。このコミットで同じファイルのチェックボックスの規則を書き換えたのに、冒頭は古いままである。
- `SeriesNav.module.css` の冒頭のコメント（「--paper-2 の地と --rule の一本罫」）も、同じファイルを書き換えたのに残った。

**直し方**: builder が、上の4か所をいまの実装に合わせて書き直す。

### Minor-7 並べたチェックボックスの間隔を、ほかの並びと別の値で書いている

§5 の「押せる範囲を接して並べる」を、上端・下端・ページ送り・共有のボタンは `--text-box-pad` で書く。今回の fullwidth-converter・regex-tester・text-replace の横並びは、同じ意味を `--space-8` で書いている。いまは値が同じなので見え方は変わらないが、押せる範囲の余白を変えると、この3つだけ接しなくなる（AP-I02）。

**直し方**: builder が、3つの並びの `column-gap` を `--text-box-pad` にする。

### Minor-8 アコーディオンを包む目次の枠が、§5 に無い線で囲まれている

`CollapsibleTOC.module.css` の `.tocDetails` は、今回アコーディオンで組み直したが、枠は `1px solid var(--rule)`（太い線の色で細い線の太さ）と `--paper-2` の地のまま残った。§5 の線は「太い（3px・`--rule`）」と「細い（1px・`--rule-2`）」の2種類だけで、`--paper-2` はコードのボックスにだけ使う。`SeriesNav` の `.seriesNav` も同じ。

目次と連載の案内の枠は、ブログのページの独自の規則として T5 で扱う範囲とも読める。しかし、この2つはアコーディオンの部品を包む共通の部品で、今回の作業で同じファイルを書き換えている。

**直し方**: PM が、この2つの枠を T2 で直すか T5 に回すかを決める。T5 に回すなら、index.md の T5 の行に名前を書く。
