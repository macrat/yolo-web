## 指摘事項

### 1. Firefox は 150 から仕様どおりに止める。知見とコメントの「Firefox は止めない」が今の Firefox で偽になる（中）

- Firefox 150（2026-04-21）のリリースノートは「`overscroll-behavior` とその個別の指定は、中身があふれていないスクロールコンテナ（`overflow: hidden` の要素など）にも正しく当たるようになった。前はそのような要素では無視された」と書く（Firefox bug 1837436、FIXED、Firefox 150。設定の切り替えの裏ではない）。
- 知見の出典の Bugzilla 1724358 は 2021 年（Firefox 93）の議論で、「送れる幅の無い `overflow: auto` の箱では従わない」はその時点の挙動である。
- それなのに、知見の2の項の見出し（「Chromium 143 以前と Firefox は…止めない」）・本文・対処（「止めないブラウザ（Chromium 143 以前・Firefox・確かめていない Safari）」）・「確認」の3つ目（「Firefox は…従わない」）と、`CollapsibleTOC.tsx` の JSDoc・`CollapsibleTOC.module.css` の `.list` のコメント（「（Chromium 143 以前・Firefox）」）は、Firefox を版の範囲なしで止めないブラウザに数える。前回の指摘1と同じ型の誤り（古い挙動を今の挙動として書く）が Firefox の側に残っている。

直し方の例: どこも「Chromium 143 以前・Firefox 149 以前」にする。知見の「確認」の Firefox の点は、Firefox 150 のリリースノートと bug 1837436 を出典に「150 で仕様に合わせた」と書き、1724358 は「149 以前の挙動の説明」として残すか外す。受け手が要る理由（止めない版を使う来訪者が残る。Firefox の ESR・更新していない Chrome・確かめていない Safari）は変わらないので、コードの振る舞いと試験は変えない。

### 2. キーボードの送りの変更は、Chrome 144 の別の変更である（軽い）

知見の2の項の「確認」の2つ目は「同じ変更で、キーボードの送りも `overscroll-behavior` に従う」と書く。Chrome 144 のリリースノートでは、「Respect `overscroll-behavior` on non-scrollable scroll containers」（chromestatus 5129635997941760）と「Respect `overscroll-behavior` for keyboard scrolls」（chromestatus 5099117340655616、issue 41378182）は別の項で、blink-dev の Intent to Ship もキーボードに触れない。「同じ版（144）の別の変更で」に直し、出典にキーボードの項を足す。あわせて、この事実は「Chromium 143 以前は、中で送れる箱でもキーボードの送りを `overscroll-behavior` で止めない」ことを意味するので、下の指摘3の実測と一緒に書くと、読む人に役立つ。

### 3. 開いた一覧の中にフォーカスがあるとき、キーボードの送りでページが動き、読んでいた所を失う（中）

`CollapsibleTOC` は「開いた一覧の上での送りはページを動かさない。ページが送られると、閉じたときに読んでいた所を失う」を目次の決まりにしていて、ホイールと指は止める。ところがキーボードの送りは止めない。本番のビルドを Chromium 141 で測った（y=4000 で開き、一覧の最後の項目へフォーカスを置いてキーを押す。一覧はどちらも最後の項目が見える所まで送られた状態）。

| ------------------------------------------------------ | ---- | ---------------- | ---------------------- | ---------- | --------- |

| 同                                                     | 375  | 4000→4080        | 4000→5166              | 4000→14574 | 4000→3920 |

| 同                                                     | 375  | （6回）4000→4240 | （6回）4000→7498       | 4000→19201 | —         |

目次は開いたまま一覧が本文を隠しているので、来訪者は下でページが動いたことに気づかない。Escape で閉じると、読んでいた所から数百〜1万数千 px 離れた所（End なら記事の末尾）にいる。項目のリンクにフォーカスがあるときの Space はリンクを押さず（Enter で押す）ページを送るので、ボタンと同じつもりで Space を押す来訪者、一覧を矢印で動こうとする来訪者に起きる。キーボードで目次を使う来訪者のために Escape とフォーカスの戻り先まで作り込んだ部品で、この穴は同じ来訪者を損なう。Chrome 144 以降は、送れる長い一覧の端の送りは CSS が止めるはずだが（指摘2のキーボードの変更）、送れない短い一覧と、143 以前・ほかのブラウザでは止まらないとみる（144 以降は測っていない）。

直し方の例: 開いているあいだ、一覧の中の `keydown` で、送りのキー（↑↓・PageUp・PageDown・Home・End・リンクの上の Space）を、一覧がその向きにもう送れない（送れない一覧を含む）ときだけ `preventDefault` する。一覧の中で送れるあいだはブラウザに任せ、一覧の中を送らせる。開閉の行（`summary`）の Space・Enter と、修飾キー付きのキーは触らない。DESIGN.md の目次の段と JSDoc の「送り（ホイール・指）」をキーボードを含む形にし、t5-design.md の T5-15 の完了条件（「一覧の端を越えてホイールと指で送っても」）にキーボードを足すかは PM が決める。単体テストで各キーの取り消しの有無を、Chromium で上の表の操作でページが動かないことを確かめる。知見の2の項にも、キーボードの送りの実測と対処を足す。

### 4. 知見の2の項に、項の主題でない作業の決まりがある（軽い）

2の項の本文の2つ目の段落「このリポジトリの作業の環境にある Playwright の Chromium は 141 で、来訪者の使う安定版の Chrome より古い。この環境で版に依る挙動を測ったときは、測った版を書き、今の安定版の挙動と取り違えない。」は、`overscroll-behavior` の挙動ではなく、このファイルのすべての項に当たる環境の事実と作業の決まりである。後ろ半分の決まりは、ファイルの頭の「測ったブラウザも根拠に書く」と重なり、`docs/knowledge/` に置かない運用の決まり（`.claude/rules/knowledge-directory.md`）に近い。環境の事実（Chromium 141）はファイルの頭の段落へ移し、2の項の本文からは外す。2の項の根拠の頭（「Chromium 141.0.7390.37…Chrome 144 以降…では測っていない」）で、この項に要ることは足りている。
