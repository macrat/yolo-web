### Minor

#### 1. business-email の「メール全文をコピー」が、200% の 320px で「メール全／文を／コピー」と語の中で折れる

- 押す前の面の字の行を比べると、この1つだけが前より行が増えた（前「メール全文を／コピー」2行、後「メール全／文を／コピー」3行）。前は字がボタンの外にはみ出していた（`textOverflow: true`、ボタン 178px に対して升 244px）ので、はみ出さなくなったこと自体は良い。
- ただ、折れる所が「全文」という語の中で、2行目が「文を」になる。ボタンの字の幅（178px のボタンで全角約4字）には「メール」も「全文を」も入るので、語の切れ目で「メール／全文を／コピー」と折れば、行の数は同じで語を割らない。§4 の「1行に収まらない文節の中で折るときも、語の切れ目を選ぶ」（frontend-design スキルの見出しの折り方の5）と同じ考え方に反する。
- 原因は、`CopyButton` の `.targetName` が `overflow-wrap: anywhere` で、何を写すかの名前の中の折り所を持たないこと。
- 直し方の方向: 何を写すかの名前の中にも語の切れ目の折り所を持たせる（たとえば `target` の語の切れ目に `<wbr>` を置けるようにし、`.targetName` も `keep-all` にする）。直したあと、320・375px の 200% で「メール／全文を／コピー」と折れることを確かめる。

#### 2. storybook の `align="stretch"` の見本が幅いっぱいに広がらず、`align` の説明と食い違う

- storybook の「何を写すかを面に出す（showTarget・primary・align="stretch"）」の見本は、375px でも 1280px でも、字の幅のボタン（「メール全文をコピー」の幅）で出ており、`align="start"` と見分けがつかない（撮った絵で確かめた）。
- `.copy` は `display: inline-grid` で、自分の幅は中身で決まる。`.stretch` は `--copy-button-align: stretch` を置くだけなので、升より広がらない。business-email が幅いっぱいに見えるのは、道具の側が `className={styles.copyAllButton}`（`width: 100%`）を渡しているからである。`CopyButton` の型のコメントは「"stretch": 置いた幅いっぱいに広げる」と言うので、見本を見た作り手は `align="stretch"` だけで幅いっぱいになると受け取り、実際にはそうならない。
- 直し方の方向: `align="stretch"` そのものが升を置いた幅いっぱいにする（`.stretch` に `width: 100%` など）ようにし、business-email の `copyAllButton` を不要にする。あるいは、見本にも幅を渡し、コメントを実際の振る舞いに合わせる。部品の名前どおりに振る舞うほうが、道具ごとの手当てが要らず AP-I02 にも合う。

#### 3. DESIGN.md §6 の「取っておく場所のために値の幅を削ることはしない」が、実際の組みと食い違う

- hash-generator の 1280px では、値の右に置くボタンの升が「コピー済み」の幅を取るので、値の折れる所が前より2〜4字ぶん前に寄る（既定の字の大きさで「…f5f6a13de8／28684f」→「…f5f6a1／3de828684f」、200% でも同じ向き）。行の数は変わらず、来訪者への影響はほとんど無い。
- それでも §6 は「値の幅を削ることはしない」と言い切っており、文を読んだ人は、値の隣に置いたボタンの取り置きが値の幅を1pxも取らないと受け取る。実際に守られているのは「取り置きのせいで値や見出しの行が増えない・語の中で新しく折れない」ことで、今回の測りもそれを確かめている。
- 直し方の方向: §6 の文を、実際に保証している形（取り置きのために値や見出しの行を増やさず、語を新しく割らない。足りない並びではボタンを次の行に送る）で書き直す。あるいは組みの側で値の幅を取らない形にする。前者で足りる。

#### 4. `disabledReason` は部品に入ったが、実際のページでは1つも使われず、残りの受け持ちもどこにも書かれていない

- `CopyButton` は `disabledReason` を受けて `Button` に渡し、storybook の見本では「変換すると写せます」が字で出て、ボタンの説明（`aria-describedby`）として読まれる（ariaSnapshot: `button "出力をコピー" [disabled]` のあとに `text: 変換すると写せます`。375px・1280px とも破線の「コピー」の右に字で出る）。見本の文も、base64 などで出力が空のあいだの状況に合っている。部品のテストもこれを確かめている。
- 一方で、`src` の中で `CopyButton` に `disabledReason` を渡しているのは storybook だけで、22の道具と色の辞典の無効のコピーのボタンは、いまも理由を言わない。3巡目の指摘5は「道具ごとの理由の文を T5 で書くなら、その受け持ちを index.md の T5 の項目に『CopyButton を含む』と書いておく」としたが、index.md の T5 は今も「道具の無効のボタンに、理由の文（`Button` の `disabledReason`）を添える」だけで、`CopyButton` に触れていない。T5 の作り手が `Button` だけを探すと、コピーのボタンを取りこぼす。
- 直し方の方向: このタスクで道具の側に理由の文を渡すか、index.md の T5 の項目に「`CopyButton` の `disabledReason` を含む」と書き足す（PM の受け持ち）。

5. 無効の理由: 部品の側は直った。ページの側は指摘4。
6. 面が戻ったあとの知らせ: 直った。写せた回のあと面が「コピー」に戻った時点で、どのページのどのボタンもライブリージョンが空だった。写せなかった回のあとは、どのボタンも「〜をコピーできませんでした」が次に押すまで残る。押すたびに知らせの要素は入れ直され、写せた回はどれも「〜をコピーしました」、写せなかった回はどれも「〜をコピーできませんでした」だった。

## アンチパターンの確かめ（docs/anti-patterns/implementation.md）

- AP-I01（来訪者目線）: 押す前・写せた・写せなかったの3つの面を、字を大きくする来訪者と読み上げを使う来訪者の目でも見た。押したときの得ははっきりしており、残るのは指摘1〜4の小さな食い違い。
- AP-I02（場当たりの回避）: 面の字の折り所は `<wbr>` と `keep-all` で部品が決め、3巡目の `anywhere` と 20em の切り替えは消えた。13の道具のラベルの行の `flex-wrap` と cron-parser の `flex: 1 1 auto; min-width: 0` は、§6 の「足りない並びではボタンを次の行に送る」を並びの側で組んだもので、個別の逃げではない。ただ `align="stretch"` が名前どおりに広がらず、business-email が自分で `width: 100%` を足している所は、部品の不足を道具の側で補う形で、指摘2にした。
- AP-I03（Core Vitals・バンドル）: 押しても升もページの高さも動かず、CLS は前より良い。部品は小さく、重いデータの読み込みは無い。
- AP-I04（指標を目的にした配置）: 該当なし。
- AP-I05（目的に無関係の足し算）: 該当なし。足したのは無効の理由の道と、面が戻ったときの知らせの片付けで、どちらも写す目的に沿う。
- AP-I06（反対の極端）: 取り置きを外して押したときの動きを戻すのでも、取り置きで値を削るのでもなく、並びが足りないときにボタンを次の行に送る形で、極端に振れていない。
- AP-I07（jsdom で見えない崩れ）: 単体テストは折り所（`コピー<wbr>済み`）・無効の理由の説明・知らせの片付けを確かめているが、折れ方と升の動きは本番のビルドで測った。指摘1〜3は本番のビルドでしか見えないもので、このレビューで見つけた。
