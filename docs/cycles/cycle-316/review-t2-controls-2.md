## 指摘

### Major-1 パンくずのリンクのフォーカスリングが、左右の区切りの「/」を覆う

`Breadcrumb` は押せる範囲を `::after` で 44px 幅に広げた。フォーカスの二重リングは、その範囲の外に 6px（内の輪 3px と外の輪 3px）出る。区切りの「/」は字から 0.4em（約 5.6px）しか離れていない。そのため、字の短い項目では、リングが両隣の「/」に重なる。

実例として、`/play/character-personality` の「遊ぶ」に Tab でフォーカスすると、左右の「/」が `--paper` の内の輪と `--ink` の外の輪に隠れ、欠けた点のように見える（1280px・320px、light と dark で同じ）。hover の線も「/」に接する。

§6 には「二重リングは、要素の外に余地があれば外、なければ内側に出る」「隣に食い込まない」とある。パンくずはすべての詳細ページの頭にあるので、キーボードの利用者が最初に Tab で入る場所で、隣の字が隠れる。

**直し方**: パンくずは外に余地が無いので、リングを内側に出す（`data-focus-ring="inset"`）。ただし、「ホーム」のように字の幅が 44px に近い項目では、内側のリング（6px）が字に掛かる。そのため、押せる範囲の幅は「字の幅＋左右にリングの分」と 44px の大きいほうにする。そのうえで、区切りの間隔をその幅に合わせる。どの長さの項目でも、リングと hover の線が字にも「/」にも掛からないことを、320px と 1280px で確かめる。

### Major-2 字だけが見えるコントロールの左端の決め方が3通りに割れ、ボタンの直し方が別の害を出している

前回の Major-3 への直しとして、プライマリでないボタンは余白を 3px にし、`margin-inline-start: -6px` で箱を左へ出した。字の左端はそろった。しかし、次の害が出ている。

1. **無効の破線の枠が左へはみ出す。** 無効のときに見えるのは破線の枠である。その枠の左端が、コンテンツの左端（または並びの左端）より 6px 左に出る。storybook の 320px では、無効の「結果をコピー」の枠が、プライマリの「計算する」の箱と「default」のラベルより左に出る。無効は、出力が空のあいだの道具のコピーのボタンなどで、ページを開いた直後からずっと見える状態である。§5「コンテンツ幅の左端は、どのページでも同じ位置」に対し、有効のときは字、無効のときは枠が基準になり、どちらかが必ずずれる。
2. **hover の線・破線の枠・リングが字に迫る。** 左右の余白が 3px になった。hover の線は字から約 2px、破線の枠の内側は字から 3px、上下は約 12px 離れる。例えば `/tools/html-entity` の「コピー」（無効）は、破線が字にほぼ接する。`/tools/age-calculator` の「今日に設定」は、hover と Tab で線が字に接する。前回までの 8px と比べて窮屈で、枠が字を締めつけて見える。
3. **同じ問いへの答えが3通りある。** 字だけが見えるコントロールの左端を、どこに置くかという問いである。ボタンは箱を −6px 出して字をそろえた。ページ送りは、項目の余白 8px のまま「‹ 前へ」の字が h1 より 8px 右から始まる（`/blog/page/2`: h1 の左端 203px・「‹ 前へ」の字 211px。320px では 51px と 59px）。一覧の行は 8px 右にずれたまま T3 に送ってある。§12「同じ働きのコンポーネントは同じ形」にも、ツギハギ禁止にも反する。部品ごとに個別の解き方をしている（AP-I02）。

**直し方**: 部品を直す前に、planner が `DESIGN.md`（§5 のコンポーネントの幅と §6）に1つの規則を書く。規則は「字だけが見えるコントロール（プライマリでないボタン・ページ送り・一覧の行の名前）で、左端にそろえるのは字か箱か。箱の外へ出る状態の線（無効の破線・hover・リング）を、コンテナの余白にどこまで出してよいか」を決める。規則は、次の3つを同時に満たす形で選ぶ。

- 無効の破線の枠が、有効なときと同じ位置で、ほかの部品の左端と矛盾しない。
- 線と字のあいだが、上下と左右で極端に違わない。
- 320px のコンテナの余白（8px）に収まる。

そのうえで、builder がボタン・ページ送り・一覧の行（T3 の該当分をここで決める）に同じ規則を掛ける。

### Minor-1 枠を持つ要素に出す内側のリングで、内の輪が 6px になる

`[data-focus-ring="inset"]` は `--focus-ring-fill: inset 0 0 0 6px var(--paper)` とする。これは、枠を持たない一覧の行を前提にした値である。プライマリでないボタンは 3px の透明な枠を持ち、`inset` の影は枠の内側から始まる。そのため、外の輪（0〜3px）の内側に、`--paper` の 6px の帯（3〜9px）ができ、字の頭が帯に載る。

`/tools/password-generator` の `--paper-2` のボックスの中の「コピー」を dark で拡大すると、外の輪 3px に対して、内の輪が 6px ある。§6「内も外も太い線と同じ太さ」、§5「あいだの太さを持たない」と食い違う。地が `--paper` のところでは見えないが、`--paper-2` とコンテンツの色の上では見える。

**直し方**: 内側のリングを、要素の枠の有無によらず 3px と 3px になるように組む。例えば、枠を持つ部品では塗りの広がりを 3px にする。Major-2 で余白を決め直すときに、あわせて確かめる。

### Minor-2 狭い画面のページ送りで「1 / 8」が「1/ 8」になる

`mobileIndicator` は `display: inline-flex` である。いまのページの番号を `inline-grid` の `span` に入れたため、その後ろの `{" "}` が flex の項目のあいだの空白として捨てられる。そのため、320px と 375px の `/blog` で「1/ 8」「5/ 10」と組まれ、斜線の前だけ空きが無い。

**直し方**: 空白を後ろの文字と同じ項目に入れる（例: `{` / ${totalPages}`}` を1つの文字にし、`white-space: pre` で前の空白を保つ）。または間隔を `gap` で取る。

### Minor-3 481〜608px では、ページ送りが2〜3行に割れ、1ページ目の先頭に空の行ができる

番号を畳む境を 30rem（480px）に下げた。そのため、481〜528px では「前へ（場所取り）」「番号の並び」「次へ」が3行に割れる（ナビの高さ 180px）。529〜608px では2行になる（128px）。

1ページ目は、先頭の行が見えない場所取りだけになり、番号の上に 44px の空白ができる（`/blog`、481px）。番号で飛べる利点はあるが、一覧の下端に 180px の縦長の塊が置かれ、「次へ」が番号の下の別の行に回る。

**直し方**: 1行に収まらない幅では畳む（いまの項目数では、1行に収まる境は約 609px ≒ 38rem）。または、番号の並びが折り返しても「前へ」「次へ」と同じ行に並ぶ組み方にする。どちらを採るかと理由をサイクルの文書に書く。

### Minor-4 パンくずが2行に割れると、2行目が「/」で始まり、左端から約 6px 右にずれる

区切りを後ろの項目の `li` の頭に置いているので、折り返した行は「/ あなたに似たキャラ診断」で始まる。区切りの左の余白（0.4em）の分、2行目は左端から右にずれる（`/play/character-personality` の 320px、storybook の「3 階層」の 320px）。§5「すべて左端から始まる」と食い違い、行頭の約物としても不自然である。変更前からあるが、この部品を作り直した範囲にある。

**直し方**: 区切りを前の項目の末尾に置き、改行が区切りの後ろで起きるようにする。行頭が必ず項目の名前になり、左端にそろう。Major-1 の区切りの間隔と一緒に直す。

### Minor-5 共有のボタンの読み上げ名が、見える文言を含まない（WCAG 2.5.3）

見える文言は「X でシェア」「LINE でシェア」「はてブに追加」である。一方、`aria-label` は「X で共有（外部サイト・新しいタブで開く）」「はてなブックマークに追加（…）」で、見える文言を含まない。音声で操作する来訪者が「X でシェア」と言っても押せない（WCAG 2.5.3 Label in Name、レベル A）。変更前からあるが、この部品は今回 `Button` で組み直した範囲にある。

**直し方**: 読み上げ名を、見える文言で始める（例:「X でシェア（外部サイト・新しいタブで開く）」）。

### Minor-6 ページ送りの「n / N」の `aria-label` が、名前を持てない `span` に付いている

`mobileIndicator` は role を持たない `span` なので、ARIA 1.2 では `aria-label` が禁止される（axe の `aria-prohibited-attr`）。読み上げで無視されることがある。コメントの「aria-hidden を付けないことでスクリーンリーダー利用者もページ位置を把握できる」は、中の文字が読まれることで成り立っている。`aria-label` は効いていない。

**直し方**: `aria-label` を外し、読ませたい文（「ページ 1 / 8」など）を、見えない文字（`.visually-hidden`）と見える文字の組で持つ。コメントを事実に合わせる。

### Minor-7 `DESIGN.md` §6 の冒頭の引用が、足した表の行と合わない

表には「ボタン——プライマリでないもの」の行が入った。しかし、冒頭の「下線か反転を必ず持つ」ものの列挙は「ほかのページへのリンク・一覧の行・ページ送り・プライマリボタン」のままである。プライマリでないボタンが列挙から抜けているので、表の行が後から足した例外のように読める（ツギハギ）。列挙を「プライマリボタンとそれ以外のボタン」を含む形に書き直す。

### Minor-8 index.md の T3 の行が、いまのページ送りと合わない

T3 の行には、次の記述が残っている。「ページ送りは、前後のページが無い端で『前へ』『次へ』を置かない形にした（押しても何も起きない項目を並べないため）。一覧の設計でこれを見直す。」いまは、端に同じ幅の場所取りを置く形になっている。場所取りを置いたことと、T3 で何を見直すのか（または見直さないのか）を書き直す。一覧の行の 8px の件は、Major-2 の決め方に合わせて書き直す。

### Minor-9 button モードのためだけに、ページ送り全体がクライアントの部品になった

`Pagination` に `"use client"` を付けたので、`/blog` の link モードのページ送りも JS を配ってハイドレーションする。フォーカスを戻す処理（`useEffect`・`useRef`）が要るのは、button モードだけである。link モードの部品はサーバーのまま置き、button モードの並びだけをクライアントの部品に分ける（AP-I03）。
