## 指摘

### Major-1: ダイアログの中で押し始めて外で離すと、ダイアログが閉じる

結果のダイアログの中の文（四字熟語の意味など）を選ぼうとしてドラッグし、ダイアログの外で指やマウスを離すと、ダイアログが閉じる（本番のビルドで確認。1280px でも 375px でも同じ）。ダイアログの余白で押し始めて外で離しても閉じる。

原因: 押し始めと離した所が違う要素のとき、ブラウザは click を2つの共通の祖先に送る。中の `<p>` で押して背景（`<dialog>` そのもの）で離すと、click の target は `<dialog>` になり、座標はダイアログの外なので、`e.target === e.currentTarget` と座標の判定の両方を通って `onClose` が呼ばれる（記録した事象の並び: `mousedown:P`・`mouseup:DIALOG`・`click:DIALOG`）。

来訪者への影響: 結果を読みながら文を選ぶ・なぞる来訪者が、そのはずみで結果と共有のボタンを失う。閉じたあとのページには結果を開き直すボタンが無い（残るのは「遊び方」「統計」とページの共有だけ）。この判定は今回 T4-4 が直した関数そのもので、依頼の「ダイアログの外へのドラッグの終わり」にあたる。前からある振る舞いだが、同じ数行で直せる。

直し方の例: 押し始めた所を覚えておき、押し始めも離した所も背景だったときだけ閉じる。たとえば `useDialog` が `onPointerDown`（または `onMouseDown`）用の手当てを返し、そこで「target がダイアログそのもので、座標が矩形の外か」を ref に残し、`onClick` ではその ref が真のときだけ閉じる。`GameDialog` の `<dialog>` にその手当てを付ける。テストは、中の要素で pointerdown してダイアログの外の座標で click したときに閉じないことを、実物の `<dialog>` のハーネスで足す。デスクトップの常に出るスクロールバー（このダイアログは 375px で縦に溢れてスクロールする）を掴んで外で離す場合も、同じ直し方で閉じなくなる。

### Major-2: 招待のボタンで共有シートを閉じただけで、「リンクをコピーできませんでした」が出うる

`InviteFriendButton` は、`navigator.share` が拒まれたとき（来訪者が共有シートを閉じた AbortError も含む）にコピーへ進む。今回コピーに失敗の知らせが付いたので、コピーに進んで写せないと「リンクをコピーできませんでした」が出る。

Web Share の仕様では、`share()` は来訪者の操作の有効期間（transient activation）を使い切る。iOS の Safari では `navigator.clipboard.writeText` も `execCommand("copy")` も来訪者の操作の中でしか写せないので、共有シートを閉じたあとのコピーはどちらも失敗する見込みが高い。つまり iOS の来訪者が「友達に診断を送る」を押し、気が変わって共有シートを閉じると、自分は何も頼んでいないのに「コピーできませんでした」と告げられる。character-personality の結果に着く来訪者の約66%が WebKit なので（index.md の補足事項）、招待を押す来訪者の多くがこの流れに乗る。前は黙って何もしなかった。テスト「share 取消 → どの写し方でも写せなければ何も計上せず、写せなかったと知らせる」は、この振る舞いを正しいものとして固めている。この環境に WebKit が無いので実機では確かめていないが、仕様と各ブラウザの条件から導ける。

直し方の例: 共有シートを閉じた回（`AbortError`）は何もしない（コピーに進まず、知らせも出さない）。コピーに進むのは、`navigator.share` が無いときと、AbortError 以外で拒まれたときだけにする。`ShareButtons` の共有シートのボタン（`shareGameResult`）も札の「共有」も、共有シートを閉じた回はコピーに進まない作りなので、それとそろう。テストは「共有シートを閉じた回は写さず、何も知らせず、何も送らない」に書き換える。Android の Chrome では、いまは閉じた回にも写して `clipboard`（surface `invite`）を送っているので、直すとその数が減る。index.md の計測の項に1つ足す（PM が決定として書くか builder に書かせるかは PM が決める）。

### Minor-1: 小さな残り

- **T9 の行に、WebKit で代わりの写し方が写せるかの確かめが無い。** index.md の補足事項には「T9 で実機で確かめる」とあるが、T9 を行う担当が読むのは T9 の行で、そこに無い。T9 の行に「iOS の Safari・アプリの中のブラウザで、共有・道具・札・招待のコピーが、API に拒まれても写せること、写せないときは失敗の知らせが出ること（招待では共有シートを閉じた回に何も出ないこと）」を足す。
- **招待の「コピーしました」が、続けて押すと早く消える。** 写せた知らせを消すタイマーを押すたびに作り、前のタイマーを止めないので、1.5 秒あけて2回写すと、2回目の知らせは 0.5 秒で消える。前からある形だが、今回この行を書き換えたので、`useCopyToClipboard` と同じくタイマーを ref に持って前のものを止める（アンマウントの時にも止める）。
- **伝統色の詳細のコメントの置き場所。** 「写せたら 1.5 秒「コピー済み」、写せなかったら…ボタンに出す。どちらも…」はボタンの振る舞いの説明だが、`COPIED_DISPLAY_MS` の定数の上に置かれている。`CopyButton` の上へ移し、定数には「コピー済み」を出す長さだけを言わせる。T4-4c でこのボタンを部品に移すなら、そのときに消えてもよい。
