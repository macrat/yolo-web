## Major

### Major-1: 結果の中の「ほかの遊び」から移って「戻る」と、結果でなくページの下の関連ゲームの一覧に着く

解き終えた来訪者が、結果の下の「今日のパズル 1/4 クリア」の一覧から「漢字カナール」へ移り、ブラウザの「戻る」で四字キメルに戻ると、どの幅でも8回とも、共有の見出しから 1,673〜4,536px 下の「関連ゲーム」の一覧（ページの下のほう）に着く。CLS は 0 だが、それはブラウザのスクロールアンカーが下の一覧を動かさないよう送りの位置を変えたからで、来訪者の画面は自分の結果から離れる。

375px・既定の流れ（`tmp` の計測の記録から）:

1. 移る前: `scrollY` 1389、画面の上に「6回目」の分布の行、共有の見出しは 100px。
2. 戻った直後: 本体は読み込み中の組み（入力欄が見え、結果の区画は空）で、ページの高さは 3,903px。ブラウザは `scrollY` 1389 を戻すが、その位置にあるのは結果でなく、ページの下の関連ゲームの「漢字カナール」。
3. 100ms 後: 記録を戻して結果の区画が 1,760px 伸び、スクロールアンカーが「漢字カナール」を画面の上に留めたまま `scrollY` が 3149 に移る。共有の見出しは −1660px（画面の外の上）。

原因: サイト内の移動では、本体の前のスクリプト（`isServerRendered && <script>`）が描かれず、`--yoji-kimeru-result-height` などの値が書かれない。そのため結果の区画も盤も最初の来訪者の高さで描かれる。ナカマワケは「ほかのページから移ってきて（「戻る」を含む）ブラウザで新しく描くときは、初めから端末の記録の回で描く」（`nakamawake/_components/GameContainer.tsx` 197行）で直しているが、四字キメルは同じ扱いを持たない。t4-design.md の PM の決定（T4-13 の2巡目・T4-14）は「ほかのページから戻ったとき」の着地を直す対象としており、このゲームの結果の下にほかのデイリーゲームへの一覧を置いている以上、毎日遊ぶ来訪者がいちばん通る戻り方である。

来訪者にとっては、次のゲームを遊んで戻ったとき、自分の結果や共有のボタンが見えず、知らない一覧の途中に出る。上へ 1,700px 以上（200% では 4,500px）送り戻さないと自分の結果に着かない。

直し方の向き: サイト内の移動でも、最初に描く前に取っておく値を書く。たとえば、`isServerRendered` が偽のときに `reserveSavedLayout`（同じ関数）を最初の描画の前（初めの `useState` の初期化や `useLayoutEffect`）に呼ぶ。答えは API から受け取るので、ナカマワケのように記録から回をそのまま描くことはできないが、盤の行・ヒントの行・結果の区画の高さを取っておけば、ブラウザが戻す位置に同じ中身が来る。直したら、上の表の「結果の中の『漢字カナール』から戻る」を幅ごとに8回測り、着地の差が 0 に近いことを記録する。3回遊んだ途中の回で移って戻る場合も同じ仕組みで直るので、あわせて測る。漢字カナールも同じ `isServerRendered && <script>` の形なので、PM は T4-11 の側でも同じ戻り方を確かめてほしい。

## Minor

### Minor-1: 200% の 320px・375px では、ヒントの帯の行が折れ、取っておいた行の数より高くなる

`HintBar` の説明と CSS の注釈は「どの行も…行の中で折れない短い文」「読み込みの前後で行の数が変わらない」と言い、開き直しの高さを `calc(var(--yoji-kimeru-hint-lines) * 1lh)` で取っておく。しかし 200% の 320px と 375px では、「ヒント 難易度 ★、／読み 8文字」「3回目のあとに読み／の最初の字」とどの行も2行に折れる（各行 104px）。読み込み中の1行目「ヒント 読み込んでいます」は1行なので、読み込んだときに盤から下が1行ぶん（51px）下がる。

- 解き終えた回を共有まで送って読み込み直すと・読み込みで戻ると、200% の 320px で 0.0665（8回のうち7回）、375px で 0.0681（8回とも）の CLS になり、共有の見出しが 51px 上にずれる（上の表）。ずれの元は、`--yoji-kimeru-hint-lines: 4` が 4行ぶんしか取らず、実際は1行目が折れて5行になること。
- 初めての来訪者も同じ 51px が動くが、200% では盤が画面の下にあるので CLS には出ない。

0.1 は下回るが、文字を大きくして読む来訪者だけに、戻った位置がずれる。また、コードの説明が実際の組みと合っていない（読む人は「折れない」前提で直しを考える）。ヒントの行を字の大きさにかかわらず折れない形にするか（折れても行の数が変わらない組み）、取っておく高さを行の数でなく、同じ画面で描いた高さで取っておく（結果の区画と同じ考え方）。説明の文も、実際の組みに合わせて書き直す。

### Minor-2: 4回目で勝ったあとも、ヒントの帯に「5回目のあとに分類」が残る

勝った回（1〜4回目で正解）では、解き終えたあともヒントの帯の最後の行に「5回目のあとに分類」（3回目より前に勝てば「3回目のあとに読みの最初の字」）が出たままになる。もう推測できないので、この行が言うことは起きない。開き直した来訪者は、結果の上で「まだ続きがあるのか」と読み違えうる。`HintBar` の次のヒントの行は、遊んでいるあいだだけ出す（行の数が変わるので、`byGuessCount` の値も解き終えた回を含めて決める）。

### Minor-3: 使われない `saveTodayGame` とそのテストが残っている

`src/play/games/yoji-kimeru/_lib/storage.ts` の `saveTodayGame` は、本番のコードのどこからも呼ばれず（`GameContainer` は `saveHistory` で記録する）、`storage.test.ts` の `describe("saveTodayGame")` だけが使う。前回のレビューでも同じ状態を記録しており、四字キメルを組み直したこのタスクで片付ける対象である。読む人は、記録を書く道が2つあると取り違える。関数とそのテストを消す。

## 見た目（320・375・1280 × 既定・200% × ライト・ダーク × 勝ち・負け、24通り）
