## 判定: 改善指示

押しても動かないこと（押すと動く 96→0）と、写せなかったことを字と知らせで言うことは、来訪者にとってはっきりした得である。部品の作りと移し替えも筋が通っており、振る舞いが失われた道具は見つからなかった（business-email の件名・本文・全文の知らせは部品の知らせに移り、password-generator は読み上げにパスワードを載せない）。一方で、取り置きの幅のために、いちばん多い幅（375px）の unix-timestamp で、押さなくても全員が目にする値の読みやすさが落ちている。T4-16 の3巡目の決定が完了の条件にした「既定の文字サイズで見え方が変わらない」を満たしておらず、得（押した人だけ）と損（見る人の全員）が釣り合わない。

## 指摘

### 1.（重大）unix-timestamp の結果の表で、押す前の値が前より細かく折れ、320px ではボタンがどこにもそろわない所に落ちる

- 375px・既定: 値の列が取り置きの幅（「コピー済み」と「コピー」の差、約26px）だけ細くなり、直す前は1行だった「秒」の `1704067200` が `1704067` / `200` に、「ローカル時刻」が `2024/0` / `1/01 0` / `0:00:00` に、「ミリ秒」が `1704067` / `200000` に折れる（日時→タイムスタンプの秒・ミリ秒も同じ）。数字を桁の途中で折る所が増え（DESIGN.md §8「数字を折るのは桁区切りの位置だけ」）、ページは 119px 伸びる。道具の目的の値そのものが読みにくくなり、コピーを押さない来訪者も含めて全員が損をする。
- 320px・既定: 並びが折り返してボタンが下の行に落ちる（値は1〜2行で読めるようになった）が、ボタンは見えない箱（94px）の右端に寄るので、ラベルの左端から約26px 右の、ラベルにも値にも行の右端にもそろわない位置に出る（ボタンの矩形 x=76、ラベルの左端 x=50）。行ごとに 44px 伸びる。
- 直し方の方向: 取り置きは残したまま、この表の組みを値に幅を渡す形にする（例: ラベルを値の上の行に置き、値とボタンを1行に並べる／ボタンの列の幅を取り置きの幅で固定し、値の列が桁の途中で折れない幅を先に取る）。落ちたボタンを置くなら、ラベルの左端か行の右端のどちらかにそろえる。どちらにするかは撮って決め、完了の条件（320・375px × 既定・200%、押す前と押したあと）で、既定の文字サイズで直す前より値が細かく折れないこと・押しても動かないことを両方確かめる。index.md 253行の「T5 で表を組み直す」に回すなら、いまより悪くしたまま出荷しないこと（T5 まで待つなら T4-4c で悪化させない組みが要る）。

### 2.（中）traditional-color-palette の 320px で、RGB の値が2行に折れる

- 直す前は1行だった `rgb(38, 69, 61)` が `rgb(38, 69,` / `61)` に折れる（HSL は直す前から `2` / `9%` のように数字の途中で折れており、これも残る）。値の右に取り置きの空きが見えるのに値が折れるので、来訪者には理由の分からない折れに見える。375px では変わらない。
- 1 と同じく、値の列が桁の途中で折れない組み（例: 狭い幅ではコードの行を「ラベル＋値」と「ボタン」の2段にする）を撮って選ぶ。色の辞典の表（最大5px）は、撮り比べて見た目の差は認められなかった。

### 3.（中）読み上げで、名前の変化と知らせが二重に届くおそれがあり、押し直しは知らせない

- 押すと、フォーカスのあるボタンの名前が「HEXをコピー」→「HEXをコピー済み」に変わり、同時にライブリージョンが「HEXをコピーしました」と言う。フォーカス中の操作部品の名前の変化は NVDA・VoiceOver・TalkBack が読むことが報告されており（Adrian Roselli「Be Careful with Dynamic Accessible Names」）、その組み合わせでは同じことを違う言い方で2度聞く。同記事は、名前をその場で変えず、知らせは別のライブリージョンで出すことを勧めている。
- 「コピー済み」のあいだにもう一度押すと、知らせの文が変わらないので読み上げは何も言わない（写し直せたかが耳で分からない）。
- 直し方の方向: 知らせの経路を1つにする（例: 名前は「HEXをコピー」に保ち、面の字の変化は `aria-hidden` にして、写した・写せなかったはライブリージョンだけで言う。あるいは名前の変化だけに頼らない理由があるなら、それを cycle の記録に残す）。押すたびに知らせを空にしてから入れ直し、押し直しでも読まれるようにする。DESIGN.md §6 の3つめの項目の書き方も、選んだ形に合わせる。

### 4.（中）DESIGN.md §6 の「面の字は3つだけ」が、部品自身の showTarget とサイトのほかのコピーのボタンに食い違う

- `showTarget` のボタンは押す前の面が「メール全文をコピー」「HTMLをコピー」で、「コピー」ではない。
- §6 は「コピーのボタン」一般の規則として書かれているが、共有の `ShareButtons`（「URLをコピー」→「コピーしました」）、`FudaActions`・`InviteFriendButton`（「リンクをコピーしました」）は別の面の字を持ち、押すと面の字の幅も変わる。規則を書いた時点で、サイトの一部が規則に反している。
- 直し方の方向: 規則の対象（結果を写すボタンか、リンクのコピーも含むか）をはっきりさせ、何を写すかを面に出す形（showTarget）も規則の中で言う。リンクのコピーも含めるなら、そろえる作業を受け持ちの表（T4-4 の共有のボタン・T4-5・T6 など）に足す。含めないなら、なぜ違ってよいかを規則が言う。

### 5.（小）Storybook が、DESIGN.md とスキルが禁じた組み方を見本として出している

- `src/app/storybook/StorybookContent.tsx` の「16. useCopyToClipboard」（1126行付近）と、結果のボックスの見本の2つのボタン（1441行・1457行付近）が、`useCopyToClipboard` と `COPIED_LABEL` で面の字を自前で組み、「コピーしました」を出す。部品の見本帳が、スキルの「道具の側で `useCopyToClipboard` から文言を組まない」と §6 の面の字に反し、`CopyButton` の見本が無い。`CopyButton`（既定・showTarget・primary・align、写せなかったときの面）の見本に置き換える。

### 6.（小）hash-generator の CSS で、`.resultRow` の上に説明のコメントが2つ重なっている

- 「各ハッシュ結果行」の上に「コピーのボタンは、値の右に置く広い画面では右端に……」を足したため、あとから差し込んだ跡が見える。1つの説明にまとめる。

## よかった点（直さなくてよい）

- 押しても行・ほかの要素・押したボタンの端が動かない（builder の計測 96→0・56→0。手元の撮り比べでもページの高さは押す前後で同じ）。
- 写せなかったときに「コピー失敗」を次に押すまで残し、「〜をコピーできませんでした」と知らせる。テストを実際に押す形に替え、クリップボードの API に拒まれたときの写し方（`execCommand`）まで確かめている。
- フックが状態だけを返す形に絞られ、道具ごとのキーと知らせの組み立てが消えた。経緯のコメント（T-4b など）も移し替えた所では消えている。
