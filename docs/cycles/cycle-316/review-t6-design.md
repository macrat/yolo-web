## Major

### Major-1 タスクの順序と受け持ちが、コードの依存と食い違っている

4章のとおりに進めると、途中のタスクでビルドが壊れるか、同じファイルを2つのタスクが触る。

1. **T6-4 が `fuda-image.tsx` を消す時点で、T6-5 が終わっている保証が無い。** `src/app/dictionary/colors/[slug]/opengraph-image.tsx` は `renderFudaImage` を import している（`:14-18`）。順序は「T6-3 → T6-4」だけで、T6-5 は T6-3 と並行してよいとしか書いていない。T6-5 より先に T6-4 が走ると、伝統色辞典の250枚の OGP のビルドが壊れる。**T6-4 は T6-3 と T6-5 の両方のあと**にする。
2. **T6-2 が `ogp-image.tsx` を作り直すと、`fuda-image.tsx` が壊れる。** `fuda-image.tsx:1-7` は `ogp-image.tsx` から明朝の書体の取り方（`getMinchoFontData` など）を import している。T6-2 が Noto Serif JP の取り方を消すと、T6-3・T6-4 が終わるまで札の画像がビルドできない。T6-2 の終わりにビルドとテストが通る形（`fuda-image.tsx` が使う分を T6-4 まで残すのか、`fuda-image.tsx` を T6-2 で新しい描き方に切り替えるのか）を決めて書く。
3. **`utsuwaHex.ts` の改名と `--ink` のダークの値を足す作業が T6-4 にあるのに、それを使う T6-8・T6-9 は T6-4 より前に走れる。** 3-6 は「favicon のダークの色（3-7）のために `--ink` のダークの値もここに持ち」とするが、その受け持ちは T6-4 で、T6-9 は「T6-1 → T6-9。T6-2 と並行してよい」になっている。改名は `ogp-image.tsx`（T6-2）・`site-metadata.ts` と `scripts/generate-favicons.ts`（T6-9）・`middleware.ts`・irodori の `share.ts`（T6-8）の import を書き換えるので、受け持ちの表の決まり（同じファイルを2つのタスクに並行して持たせない）を設計自身が破っている。受け持ちの表の「`site-metadata.ts` の import 先の名前は T6-4 が先に直す」は、T6-9 が T6-4 より先に走れる順序と両立しない。
4. **T6-8 の順序の文が食い違っている。** 「T6-1 → T6-8（irodori）・T6-9（favicon）。T6-2 と並行してよい。T6-8 は T6-2 の枠の寸法を使うので、T6-2 のあとにする」。

直し方の例: `utsuwaHex.ts` の改名・ダークの値・一致の試験の移し替えを、T6-2・T6-8・T6-9 より前の小さなタスクに分ける。順序を「T6-3・T6-5 → T6-4」にする。どのタスクも、終わった時点でビルドとテストが通ることを完了の条件に書く。

### Major-2 B-650 の勧めの案（3-8 a）が「実験であること」を落としていて、完了の条件を満たさない

index.md の B-650 の完了の条件は「ルートの OGP が、**実験であることに加えて**、何が得られるかを伝える」。3-8 の案 a は「何があるかを具体に言い、**AI が作っていることを添える**」で、例の文「…AI が作り続けているサイトです」には「実験」が無い。いまの副題「AIエージェントによる実験的Webサイト」が伝えていることを、勧めの案が消してしまう。constitution の3（AI が実験として運営していて、中身が壊れていたり誤っていたりしうることを知らせる）の趣旨にも沿わない。

あわせて、例の「ことばのゲーム」はイロドリ（色のゲーム）に当たらない。道具（36本。ADR009 のカテゴリの1つ）も含めるかを保留しているが、いまサイトにある以上、並べない理由が要る。

直し方: 案 a の定義を「何があるかを具体に言い、AI が実験として作っていることを添える」にし、例の文もそれに合わせる。T6-6 の完了の条件に「実験であることと、何が得られるかの両方を言っている」を足す。

### Major-3 補助情報・読み・副題でも空白が落ちるのに、直し方と確かめ方が名前にしか無い

設計の試作 `new2-toki.png` は、読みと hex を「ときいろ #eea9a9」として渡しているのに、画像では「ときいろ#eea9a9」と空白が落ちている。試作のスクリプトは補助情報・読み・副題を字の範囲で分けた `span` の並び（`runs()`）で組んでおり、3-2 が名前について見つけた「`span` の境目で空白を落とす」がここでも起きている。3-2 の「組むときに要ること」と T6-2 の完了の条件は、この直し方と確かめ方を名前にしか持っていない。

和文と欧文が混ざる補助情報は多い（道具の副題の `shortDescription`、「イロドリ #212の結果」、ブログの説明、伝統色辞典の hex）。どのカードにも出うる欠けなので、T6-2 の完了の条件に「名前・補助情報・読み・副題のどれでも、渡した空白が PNG に残る」を足し、空白を含む試しの文で確かめる。T6-5 の toki の確かめにも「読みと hex のあいだの空白」を入れる。

## Minor

### Minor-1 名前の大きさの段が小さく、カードの縮んだ大きさで読めるかを確かめる条件が無い

試作の character-personality（35字）は名前が 46px で2行に収まり、中身の枠（高さ約 400px）の上下に大きな空きが残る。カードは LINE や X で幅 250〜600px ほどに縮めて見られるので、46px は 10〜23px ほどになる。§10 は「名前とサイト名が画像単体で読める」を求めている。字の数で段を選ぶだけでなく、「3行以内で枠に収まるいちばん大きい段」を選ぶ形にし、T6-2・T6-3 の完了の条件に「幅 400px に縮めた PNG で名前が読める」を足す。

### Minor-2 Google の favicon の事実の読み方と、完了の条件のうち抜けている項目

- 1-2 は「いま Google が使える `rel="icon"` は `favicon.ico`（最大 48px）だけ」とし、3-7 はそれを理由に PNG 192 を足す。しかし Google の favicon のガイドライン（https://developers.google.com/search/docs/appearance/favicon-in-search 、2026-09-28 に確認）は `rel` の値として `icon`・`shortcut icon` に加えて `apple-touch-icon`・`apple-touch-icon-precomposed` を受け付ける。いまも 180×180 の PNG（`apple-touch-icon.png`）があり、48px を超える形式の条件は満たしている。事実を直し、PNG 192 を足す理由（あるなら）を書き直す。
- index.md の favicon の完了の条件にある「Googlebot-Image が favicon を、Googlebot がホームページをクロールできる」が、設計にも T6-9 の条件にも無い。`src/app/robots.ts` は `/` を許し `/api/` だけを拒むので満たしているはずだが、確かめたことを書き、T6-9 か T6-10 の確かめに入れる。
- `site-metadata.ts` は `favicon.ico` を `sizes: "48x48"` と宣言しているが、ファイルは 16/32/48 を持つ。T6-9 で宣言を中身に合わせる。

### Minor-3 404 と 410 のページの favicon が棚卸しに無い

`src/app/global-not-found.js` の `metadata` は `icons` を持たず、410 のページ（`middleware.ts` の `build410Html`）の `<head>` も icon の `<link>` を持たない。どちらもブラウザが既定の `/favicon.ico` を取りに行くだけで、ダークの規則を持つ `icon.svg` は使われない。T6-9 の対象に入れて、ほかのページと同じ icon を出すかを決める。

### Minor-4 ADR009 に書くことの受け持ちと、書く所

- 3-1 は ADR009 に「保存と共有する結果の画像の見た目が変わる」を「cycle-completion で」足すとし、3-5 はイロドリの保存の `save` を足すとだけ書く。index.md では、出荷の日から計測の出方が変わるものを ADR009 に書くのは T10 の受け持ちで、T10 の行にその一覧がある。PM が T10 の行にこの2つを足すよう、設計に書く。
- 画像の見た目が変わることは計測の出方の違いでなく、来訪者の行動を変えうる中身の変化である。ADR009 の率は「T4-5 で保存と共有のボタンが最初の画面から出たことで減っていないか」を読むためのものなので、同じ出荷で画像も変わることは「前後の差の原因を1つに断定できない、同時に変わるもの」として書く（「来訪者の変化と読まない」の一覧に入れると、画像の変化による本当の増減まで読み捨てることになる）。

### Minor-5 比べた案が足りない決定がある（AP-P17）

- 3-2（組み方）と 3-8 の B-650（副題）は2案しか比べていない。3-2 は来訪者の最初の印象を決める所なので、少なくとももう1案（例: 上端の帯を持たず、名前を大きく組み、罫線の交わりだけを見せる形）と比べて、b が勝つ理由を書く。
- 3-1 は「保存を character-personality だけに置く」ことを所与にしている。描き直すと、どの診断の結果も同じ形の画像を持つので、ほかの診断にも保存を置く案がありうる。28日の `level_end` はほかの診断を合わせて約100回（traditional-color 23・word-sense-personality 23 など）で、見込める保存は月に数回なので、置かない判断もありうるが、その比べと理由を書く。

### Minor-6 3-8 の判断に、SNS から来る人がほぼいない事実（2-3・B-575）が使われていない（AP-P02）

2-3 は「カードから来る人は、いまは数えられるほどいない」と書くが、3-8 の比べはこの事実に触れずに約2,890枚を足す案を勧めている。index.md の T6 の行は B-575 を判断の材料にすることを求めている。結論は変わらないかもしれない（LINE などアプリの中からはリファラが届かず数えられない、送られたカードは受け取った人の最初の印象になる）が、そう判断した理由を 3-8 に書く。

### Minor-7 文節を `white-space: pre` の子にすると、1行に収まらない文節がはみ出し、行頭の空白が残る

3-2 の組み方では文節の子の中で折れないので、枠より広い文節（空白を持たない長い英字の語など）は枠からはみ出す。§4 は「文節が1行に収まらないときだけ、その文節の中で折る」。また、空白で始まる文節が行頭に来ると、字下げに見える。いまの名前で起きなくても、これから足すブログの題で起きうるので、はみ出すときの折り方と行頭の空白の扱いを決め、T6-2 の完了の条件に、試しの長い語で確かめることを足す。

### Minor-8 ルートの画像の中身が決まっていない

新しい組み方では上端にサイト名「yolos.net」を置く。ルートの画像はいま名前も「yolos.net」で、そのままでは同じ語が2度出る。ルートの画像の補助情報と名前に何を置くか（名前を B-650 の文にするのか、など）を 3-8 か T6-6 で決める。

### Minor-9 irodori の画像の細部

- 枠の寸法（線の位置・太さ・余白）を OGP と irodori の2か所に持つことになる。`ogp-image.tsx` は `next/og` を読むのでクライアントから import できない。寸法をクライアントからも読める1つのモジュールに置き、両方がそこから取ることを書く（2つの描き方が別々にずれていかないように）。
- 3-5 の「中身」で、どの字を見出しの書体（Zen Antique）で組むのか（合計点か、ランクの言葉か）が書かれていない。
- T6-8 の完了の条件は `trackSave` の呼び出しだけで、T6-4 と違って、Chromium で解き終えた画面から「画像を保存」を押して PNG が落ちることを確かめる条件が無い。

### Minor-10 書体の版と、新しいルートの `twitter-image`

- サイトの IBM Plex Sans は `src/fonts/ibm-plex-sans/` に置いた woff2（Latin1 に絞ったもの）で、OGP は Google Fonts の TTF を取る。Satori は woff2 を読めないので TTF を取ること自体はよいが、画面と版が違うと字の幅が少し違いうる（版が同じかは確かめていない）。どこから取るかと、画面の書体と同じ版であることの確かめ方を書く（画面と同じ出どころの TTF をリポジトリに置けば、ビルドがネットワークにも依らない）。
- いまは `opengraph-image.tsx` のそれぞれに `twitter-image.tsx` の再エクスポートが対になっている（40本）。T6-6・T6-7 で新しく置くルートでもそろえるかを書く（X は `twitter:image` が無ければ `og:image` を使うので、置かない判断もありうる）。
