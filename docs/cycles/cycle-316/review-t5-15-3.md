## 完了の条件の見直し（全体）

- 読み込み: 2記事 × 375・1280・200%・667×375 で、`commit` と `load` の 1.5 秒後で開閉の行と最初の h2 の y が同じ（例: 375 で 554・1736）。
- 3000px 送ったあと、目次は上端（0〜66、1280 で 0〜82、200% で 0〜85）。667×375 では留まらない（`position: relative`）。
- 目次から章へ（マウスでも Enter でも）移ると、見出しは目次の下端の 16px 下（375 で 82／66、1280 で 98／82、200% で 101／85）。移ったあとの Tab は見出しの次のリンクへ進み、目次の下に見える。

## 指摘事項

### 1. `page.tsx` の `<article className={styles.article}>` が、`page.module.css` に無いクラスを指している（軽い）

`page.module.css` に `.article` は無く、描いた HTML は `<article>` だけになる（`styles.article` は `undefined`）。見た目には何も起きないが、読む人は記事の外側に何かの組みがあると思って CSS を探す。前の `.contentColumn` を外したときの名残で、ツギハギ禁止に当たる。`className` を外す（記事の外側の組みはセクションとコンテナが持ち、`page.module.css` の頭のコメントもそう書いている）。

## そのほか確かめたこと（問題なし）

- `CollapsibleTOC.tsx` の JSDoc・開く押し下げを capture で受けて即時に送る処理・`focus({ preventScroll: true })` は前回から変わらず、上の測りで振る舞いが一致した。
- `:has(.toc > details:not([open]))` は目次の直下の `details` にだけ効くので、本文の中の `details` や連載の案内の開閉には掛からない。
