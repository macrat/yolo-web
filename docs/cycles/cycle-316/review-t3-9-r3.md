## 指摘

### Minor-1 敬語早見表で、敬語の形が語の途中で折れる行が増えた

- 起きていること（実測。狭い画面の行の敬語の形 180 個のうち、「・」以外の位置で折れたもの）:

  | 幅    | 17px（いま） | 14px（前） |
  | ----- | ------------ | ---------- |
  | 320px | 34           | 25         |
  | 375px | 20           | 5          |
  | 414px | 13           | 1          |

  375px の例: 「いらっしゃる・おいでに／なる」（最初の行「行く」の尊敬語。最初の画面に出る）、「うかがう・拝聴する・承／る」「了解しました・承知しま／した」「ご報告する・ご報告申し／上げる」。「・」で折れた行は 0 件だった。広い画面の表でも「いらっしゃる・おいでになる・お見／えになる」（1280px の「来る」）のように折れる。

- 原因: `.mobileRowValue` は `flex: 1 1 8em` で、ラベルの右に 8em 残れば語をラベルの横に置き、その幅の中で通常の禁則で折る。語を 17px にして1行に入る字が減り、敬語の形の途中で折れる行が増えた。
- 来訪者への影響: 敬語の形はこの道具で引きに来た答えそのものである。「承／る」「承知しま／した」のように1語が2行に割れると、形をひと目で読み取れず、書き写すときに読み違えやすい。字を大きくした目的（答えを読みやすくする）が、折れ方で一部打ち消されている。
- 直し方: 「・」で区切った敬語の形を1つずつ折らないまとまり（形ごとの要素に `white-space: nowrap`、または `word-break: keep-all` と「・」の後ろの折り位置）にし、折るのは「・」の位置だけにする。1つの形が1行に収まらないときだけ形の中で折る（§4「語の中で折るのは、一語が1行に収まらないときだけ」と同じ考え方）。広い画面の表のセルにも同じ組み方を掛ける。直したあと 320・375px で最初の行の下端を測り直す。

### Minor-2 伝統色の色見本に hover の線が見えない

- 起きていること: `.swatch:hover` は `--hover-line`（内側に `--rule-w-hair` の `--rule-2`）を出すが、見本はもとから同じ太さ・同じ色の枠（§2 の色見本の細いボーダー）を持つ。hover すると 1px の灰の線が 2px になるだけで、ライト（1280px）でもダーク（375px）でも拡大して見て変化を見分けられなかった。
- `DESIGN.md` §6 は「細い線で囲まれたもの」を、色を囲めば色見本、どれでもなければ hover と読み分けるので、色見本の上では細い線が hover の印として働かない。今回見本がラジオボタンの行（その場で状態を変えるもの）になり、§6「hover は…状態を変えるものに出る」がかかる。
- 来訪者への影響: マウスで 250 個の見本の上を動かしても、どれを押そうとしているかの手応えがない。隣り合う似た色（紅・赤紅など）で、押す前に狙いを確かめにくい。
- 直し方: 見本の枠と重ならない形の hover を決める（例: 反転の地の hover と同じく、縁から内側に離して `--paper` を挟んだ線を引く）。`DESIGN.md` §6 の hover の規定に色見本の場合を書き、コードをそれに合わせる。

### Minor-3 道具のページのシェアの見出しだけが中央に寄っている

- 起きていること: `ToolPageLayout.module.css` の `.shareSectionTitle` が `text-align: center` を持ち、「このツールが便利だったらシェア」の字が 375px で x=60、1280px で x=372 から始まる。すぐ下のシェアのリンクと、上の「このツールについて」「よくある質問」は左端（27・179）から始まる（char-count・base64 ほか 11 ページで同じ）。
- `DESIGN.md` §5「中央に寄せるのはコンテナだけ。…その中はすべて左端に揃える」に反する。このコミットは同じファイルの値とコメントを書き直したが、この宣言は残った。T5 の行にも載っていない。
- 来訪者への影響: 見出しだけが浮いて、下のリンクとのまとまりが崩れて見える。全ての道具のページに出る。
- 直し方: `text-align: center` を外して左端にそろえる。

### Minor-4 `DESIGN.md` §8 に足した項目が、どの格子に掛かるかを言い切っていない

- 「格子に並んだ選択肢から1つを選ぶと、選んだものの名前と値は、その行のすぐ下に…開く」は、字のラベルを持つラジオボタンの組が折り返して並ぶ場合（`ListControls` の「色の系統」や yoji の「カテゴリ」）にも読める。そこでは名前は選択肢そのものに見えているので、行の下に開く理由が無い。理由の文（「押したものとその名前を同時に見られない」）が成り立つのは、選択肢が名前を見せない格子（色見本）だけである。
- また、この項目は「### 結果」の中にあり、直前の文は「結果はボックスにあり」と言うが、開く欄はボックスを持たない。欄が「結果」なのか「選んだものの表示」なのかが文から読めない。
- 来訪者への影響: 次に同じ規定を読んで別の道具を組む人が、字のある選択肢の組にも欄を開き、同じ名前を2度見せる画面を作りうる。
- 直し方: 掛かる範囲を「名前を見せない選択肢（色見本など）の格子」と書き、開く欄が結果のボックスの外に出るものであること（結果そのものは格子の後ろのボックスにあること）が文から分かるようにする。§6 の足した項目（「色見本から1つを選ぶ組」）と言い方をそろえる。
