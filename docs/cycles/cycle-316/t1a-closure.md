# T1a を判断として閉じ、残りを T1 の受け入れ条件に移す

## 何を決めたか

**T1a「Web フォントの判断」は、[t1a-fonts.md](./t1a-fonts.md)（6巡目の版）の結論をもって閉じる。** 6巡目のレビュー（[review-t1a-6.md](./review-t1a-6.md)）の指摘は、判断を覆すものではなく、実装の作り方と確かめ方に掛かるものなので、T1 の受け入れ条件に移す。

採る判断は次のとおり。

- **配り方**: ページが描く字だけのサブセットをビルド時に作り、ページ固有の家族名でページ自身が描く `<style>` に宣言して、生の HTML から preload する。その後ろに、全ページ共通の分割ファイルの予備を書体の並びで重ねる（最初のフォントが揃った後に並びに入れる）。変数は `[data-pf]` に当てる。
- **閉じたページ**（入力・回答と、そこから決まる結果を送らないページ）には予備を重ねず、コードが描きうる字をすべてページの層に入れる。入力欄は全ページで「欧文, 端末のゴシック」、入力を映す表示は `data-input-view` で端末のゴシックにする。
- **書体**: 本文は BIZ UDGothic の派生（U+2014 を全角にしたもの）、見出しは Zen Antique（swap）、欧文は IBM Plex Sans の名前を変えた派生（optional＋メトリクスを合わせた代わりの書体）、ロゴは SVG。
- **`DESIGN.md` の変更**: §3（本文の書体・入力の和文）と §4（連続約物を詰めない）を、[t1a-fonts.md](./t1a-fonts.md)「§3・§4 の変更」のとおり T1 で書き換える。

この判断は、4・5・6巡目のレビューのいずれもが「来訪者にとって正しい」と評価し、6巡目は判断全体を白紙から見直したうえで「同じ価値でより単純な形は見当たらない」とした。転送量の上限（増分0）は、測った17ページのすべてで満たしている。

## なぜ閉じるか

5巡目以降のレビューの往復は、`tmp/` の写しに作った試作の、自作の解析器の穴を1つずつ塞ぐ作業になっていた。これは T1a が決めるべき判断（どう配るか・§3 を変えるか）ではなく、T1 で `src/` に実装し、試験とレビューを付けて確かめるべき仕事である。判断の文書の中で試作の実装の品質を上げ続けたために、開始から1日半のあいだ `src/` に1行も変更が入らず、来訪者に何も届いていない（AP-P20「計画段階で実装の細部まで決める」）。

## T1 の受け入れ条件に移すもの

6巡目のレビューの指摘を、T1 で満たすべき条件として移す。T1 はこれらを満たしたことを試験とレビューで示してから完了とする。

1. **解析器は閉じる側に倒す。** 閉じたページでは、式が完全な有限の集合に解けない場合（`??`・`||`・条件式の片側だけ解けた場合、`?.`、出どころを追えない引数を含む）を必ずビルドの失敗にする。実体参照は解いてから字を集める。これまでに見つかった型（keigo の結果なしのメッセージ、`composes`、相性の API、`labels?.traitsHeading`、`&times;` など）を回帰の試験の一式にし、解析器を変えるたびに通す。
2. **多重の防御。** 閉じたページの見出しと太字の書体の並びで、端末の書体の前にページの本文の家族を置き、解析器が漏らしても新しい要求なしにサイトの書体で揃うようにする。CI はこの状態も失敗として報告する。
3. **CI の対象。** 15本の診断すべてを、結果の種類ごと（character-personality は紹介者の型ごとも）に開始から結果まで通し、「サイトの和文の家族で組む要素は、要素の書体に無い字の外で端末の書体を使わない」を検査する。Zen Antique に無い字（𠮟・剝・塡・頰・辵・疒・彐・黃・纁）を含む見出しは、Zen の字の表で印の付け忘れを検査する。
4. **ビルドの時間。** 2回の `next build` と全ページの切り出しを含めた時間を、2 vCPU と 4 vCPU で見積もり、Vercel の上限（45分）を越えるなら、字の集合のハッシュで切り出したファイルをキャッシュに残すか、CI で切り出して配る道を採る。**これは T1 の最初に確かめる。** 成り立たなければ T1 を止め、この判断に差し戻す。
5. 6巡目の minor（彐・纁 の見出しの扱い＝派生に足すか §3 の例外として書くか、`irodori` の扱い、CI の C を「URL で決まる集合を、答えに依らない時点で読む」に書き直すこと、§3 の冒頭と表を含めて書き直すこと、スキルへの提案の基線と CI の対象、ページの `<style>` を HTML に適合する形にすること）。

T1 は、`src/` への実装を、これらの条件ごとに小さく分けてサブエージェントに渡し、それぞれレビューを受ける。
