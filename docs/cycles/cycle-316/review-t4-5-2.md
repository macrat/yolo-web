## 指摘

### Major-1 画像を保存したあと、前に出た「コピーできませんでした」がまた出て、読み上げられる

`ShareButtons` の知らせの行は、`showsNotice && notice.length > 0` のときだけ `notice` を出し、`notice` が空の並びになると、コピーの知らせ（`copyFailed`・`copiedCount`）に戻る。札のボタンは、画像を用意し終えて保存できたとき、知らせを「画像を用意しています。」から空の並びに戻すので、そのとき前に出ていたコピーの知らせがまた出る。

実際に測った順（375×667、クリップボードに写せない端末）:

1. 「結果をコピー」を押す →「コピーできませんでした。ほかの共有先をお使いください」
2. 「画像を保存」を押す →「画像を用意しています。」
3. 画像のダウンロードが終わる →「コピーできませんでした。ほかの共有先をお使いください」がまた出る（知らせの行は `aria-live="polite"` なので読み上げもまた言う）

画像の保存はうまくいったのに、その直後に失敗の知らせが出るので、来訪者は保存が失敗したと受け取る。同じ理由で、「結果をコピー」を押して2秒のうちに「画像を保存」を押すと、保存を終えたあとに「コピーしました」がまた出る。`notice` の説明とテストの名前は「知らせが変わったときと、コピーを押したときのうち、あとのほうを出す」と言っており、あとの操作は画像の保存なので、行は空になるのが正しい。いまの実装は、この説明とも食い違っている。

直し方の例: 知らせの行は、`showsNotice` が真のあいだは `notice` だけを出す（空の並びなら空にする）。あわせて、ほかの操作の知らせが出たときに、コピーの知らせ（`copyFailed` と `copiedCount`）を下ろしてもよい。上の3段の順を単体テストに足す。

### Major-2 共有の区画のすぐ下が、次に来る要素によっては近すぎる

`.card > .share + * { margin-top: 0 }` で、区画の末尾の知らせの行（空のとき 1行の高さ）が区画の下のあいだを兼ねる。次が詳しい読みもの（上に線と余白を持つ）のときはよいが、次がおすすめのリンク（kanji-level・traditional-color・word-sense-personality など）のときは、知らせの行のすぐ下（0px）にリンクが来る。知らせが出ると「コピーしました」が「結果をコピー」とおすすめのリンク（例: 「朱色の詳しい解説を見る」）のあいだに同じくらいの間で挟まり、どちらの知らせか、リンクが共有の区画の一部かが見分けにくい（traditional-color の 375px で撮った）。区画のあとのあいだは、次の要素の種類によらず区画の外で決まる形にする（例: 区画のあとも 24px を保ち、区画の下の大きな空きは、次の読みものの側の上の余白を見直して詰める）。

### Minor（まとめ）

1. **`notice` の出し分けが、並びの参照が変わることに頼っている。** `notice !== shownNotice` で「知らせが変わった」と見るので、呼ぶ側が描くたびに新しい並びを渡すと（`notice={["…"]}` のような書き方）、描き直すたびにコピーの知らせを押しのける。いまの呼ぶ側は `useState` の値を渡すので起きないが、説明にその前提が無く、次に使う人が誤る。中身で比べるか、説明に「変わったときだけ新しい並びを渡す」と書く。
2. **名前と説明が、新しい働きに合っていない。** `ShareButtons.module.css` の `.copyMessage` と、その説明「コピーの知らせ。」は、いまはほかの操作の知らせも出す行である。`FudaActions` の `quizTitle` の prop は、いまは短い名前（`quizName`）を受け取る。どちらも名前を働きに合わせる。
3. **読みの位置が `ResultBox` の内側の間隔に頼っている。** `.reading` の `margin-top: calc(var(--space-8) - var(--space-16))` は、`ResultBox` の頭の行の下の 16px を打ち消す前提で、T4-17 が `ResultBox` の間隔を変えると黙ってずれる。T4-17 の直しのあとに、読みとタイプ名のあいだが 8px のままかを測るよう、PM が T4-17 のレビューの項目に入れる（または読みを `ResultBox` の頭の行の側で持つ形を T4-17 で決める）。
