# デザイントークンのコントラスト検証（2026-08-13）

新 `DESIGN.md` に「検証済み」として値を書くための独立検証。前提として、現行 `DESIGN.md` §2 が実測値として載せている `--ink` の 15.51/14.32 は**出典文書が `docs/` 内に存在しない**（DESIGN.md 自身が唯一の記載元）ことが棚卸しで判明したため、値そのものを再計算して確かめた。

## 方法

トークンの oklch 値（`DESIGN.md` §2 の正典値。`src/app/globals.css` の実装値と全16値が一致することは棚卸しで確認済み）から、OKLab → linear sRGB → 相対輝度（WCAG 2.x の定義）を計算し、コントラスト比を求めた。計算スクリプトは `tmp/cycle311/contrast.py`（本文書に手順が残っているので再現可能）。

## 判定

- **現行 DESIGN.md の記載値は正しい**（`--ink` 15.51/14.32 に対し計算値 15.52/14.26、`--ink-2` 6.92/7.07 に対し 6.93/7.06、`--accent` 5.80/6.19 に対し 5.79/6.19。差は測定手段の丸め）。出典が失われていただけで、値そのものは虚偽ではなかった。**新文書にはこの再計算値を書く。**
- **`--rule` のコントラストは 1.52:1（light）/ 1.61:1（dark）**。文字に使えないのは当然として、現行 DESIGN はこの罫を「構造の主役」と位置づけ、区画・一覧の区切り・表・広告の分離をすべて罫で組ませている。**情報の境界を罫だけに担わせている箇所では、その境界は視覚的に非常に弱い**（WCAG 1.4.11 が非テキストの識別に求める 3:1 を大きく下回る）。入力欄の枠のように「そこに何があるか」を伝える境界には、`--rule` ではなく `--rule-strong`（12.70/12.21）を当てる必要がある。新デザインシステムの品質バーで扱う。
