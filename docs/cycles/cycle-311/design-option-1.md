# デザイン案1: 罫紙（けいし）

起点: **A. 安心（ここは大丈夫だ）**

---

## 1. 系統の名前と一文の説明

### 罫紙（けいし） / Ruled Sheet

**すべての要素が一本の左基線と一つの目盛りの上に載っていることを目に見える形で示し、「ここは測って作られた場所だ」を着地から数秒で伝える系統。**

発想の核は、雑さの正体が「揃っていないこと」だという観察にある。来訪者は着地して最初の数秒で、文章を読む前に、要素の左端が揃っているか・間隔に規則があるかを一望で受け取る。逆に言えば、この数秒で「雑ではない」を伝えられる手段は、装飾でも色でもなく**規則が可視であること**しかない。

そこでこの系統は、構造を**罫（1pxの実線）と目盛り（4pxの縦リズム）**だけで示し、その罫と目盛りを隠さずに見せる。カード・影・角丸・グラデーションといった「面で浮かせる」手法を一切使わないのは、それらが規則を覆い隠して「なんとなく整って見える」を作るからである。罫紙は、規則そのものを見せることで安心を作る。

由来の物は、記録を書き留めるために罫を引いた紙——原稿用紙・帳面・伝票——であり、店でも実験室でもない。**測って、書き留めて、そのまま渡す場所**である。

## 2. 色

### 考え方

1. **地は紙の色。純白ではない。** 純白 `#FFFFFF` は「何も指定していないページ」の色であり、無検討の記号になる。わずかに温かい低彩度の地は「色を選んだ人がいる」ことを伝える。ただし彩度は知覚の閾値ぎりぎりまで下げ、「クリーム色のサイト」に見えないようにする。
2. **強調色は1色だけ。副次的な強調は「色の不在」で作る。** 2色目のアクセントは禁止。区別は罫の太さ・字面の大小・余白で作る。
3. **強調色は朱（校正の朱）。** 選択理由は、朱が「人が手で確認した印」の色だからである。青や藍は「信頼」の記号としてあまりに予期どおりで、紫〜青は AI 生成サイトの指紋に隣接する。ただし朱は煽りの色にもなりうるため、**面積を機械的に制限する**（下記）。
4. **純白は、来訪者の成果物のためだけに取ってある。** ページ内で唯一の純白は結果・答え・成果物の面である。地が紙色であることによって、白は「後から置かれた一枚」として読める。

**罫のコントラスト階層（意図的な非対称）**: 罫・細は 2.25:1 で、あえて 3:1 を満たさない。項目間の細罫は「読むための目安」であって、それ単体で境界を担わない（各項目は自分の文字とリズムで既に分かれている）。逆に、**罫がその境界の唯一の担い手になる場面**——入力欄・表の枠・成果物の枠・フォーカス——には必ず `--rule-edge` 以上（4.9:1 以上）を使う。これは「一律の薄いグレー罫」の対極で、罫の濃さが意味を持つことを示す。

**朱の面積規則（機械的制約）**: 朱で塗りつぶしてよい面は**1ページにつき最大1つ、辺 40px 相当の面積まで**。それはそのページの「実行」ボタン（結果を生む唯一の操作）である。それ以外の朱は、線幅 2px 以下の罫か、文字色としてのみ許す。文字ブロックの背景に朱を敷くことを禁じる。

**状態色を持たない。** 成功・警告・情報の色は定義しない。成功は「成果物の面が現れること」そのもので伝える。エラーは朱の 2px 罫と、何が起きたかを書いた1文で伝える。色を1色に保てるだけでなく、色覚に依存せず伝わる。

### ダークモードの扱い

- **`prefers-color-scheme` に従うことを既定とし、明示の切替も置く。** ダークを常時既定にすることは禁じる（意図なきダークは AI 生成サイトの指紋の一つであり、かつ来訪者の設定を無視する）。
- ダークは**別人格ではなく同じ紙の裏返し**。色相（85／38）も、罫の階層も、面積規則もすべて共通。変わるのは明度の並びだけ。
- 反転しても「成果物がページ内で最も明度差の大きい面である」という関係は保つ（ライト=最も明るい、ダーク=最も明るい）。
- ライト・ダークとも全文字が AA（4.5:1）以上、境界を担う罫が 3:1 以上であることを検査対象とする。

## 3. 書体

### 方針

- **見出しは明朝、本文はゴシック**——編集された誌面の対比をサイト全体で一貫して使う。ただし「見出しの中の1語だけセリフ／イタリック」は禁じる。それは AI 生成の指紋である。明朝は**すべてのページ見出し（h1・h2・辞典の見出し語・成果物の見出し）に例外なく適用される体系的な選択**であって、強調の道具ではない。
- **Web フォント配信は最小に。** 見出しの明朝は OS 搭載を第一候補にし、配信は Android 等の非搭載環境への保険に留める。着地から数秒で「雑ではない」を伝える系統が、フォント読込のちらつきで自己矛盾してはならない。
- **既定 sans（Inter / Roboto / Open Sans / system-ui 任せ）を本文に使わない。**
- **本文にモノスペースを使わない。** モノスペースはコード・入力値・ID のみ。

### 書体と積み方

```css
--font-heading:
  "Yu Mincho", "YuMincho", "Hiragino Mincho ProN", "Noto Serif JP",
  "Source Serif 4", serif;

--font-body:
  "Source Sans 3", "Yu Gothic Medium", "YuGothic", "Hiragino Sans",
  "Noto Sans JP", sans-serif;

--font-mono: "IBM Plex Mono", "SFMono-Regular", "Consolas", monospace;
```

- **欧文と和文の組み合わせ**: `--font-body` は欧文（Source Sans 3）を先に置き、和文は OS 搭載の游ゴシック／ヒラギノに落とす。和欧混植でウェイトと骨格が破綻しないようにサイズを合わせる（`size-adjust` で欧文側の x-height を和文の仮名に揃える）。
- **配信するのは Noto Sans JP（400/700）と Noto Serif JP（600）のサブセットのみ**。常用漢字＋人名用漢字＋かな＋約物に絞り、`layout-features` を保持して WOFF2 化（1ウェイト約 1.5MB → 実質は unicode-range 分割で初回数十 KB）。辞典が扱う漢字 2,136 字は常用漢字と一致するため、サブセットの範囲がコンテンツの範囲と一致する。
- **見出しは `font-display: swap`、本文は OS 搭載を第一候補にすることで FOUT を発生させない。**

### 数字

- **既定は等幅数字**: `font-variant-numeric: tabular-nums lining-nums;` を `:root` に置く。道具の計算結果、辞典の画数・コード、記事の日付、値札——数字が縦に並ぶ場面が多く、桁が揺れないことが「測って作られた」の最も分かりやすい証拠になる。
- 本文中の数字も同じ tabular で通す（プロポーショナルとの使い分けを設けない。使い分けはツギハギの温床になる）。
- 大きな結果値は `--font-body` の weight 600、字間 0、**字幅を詰めない**。
- 桁区切りは 3 桁ごとに `,`。単位は数値と別要素にし、数値より 1 段小さい `--ink-sub`。

### 組版（この系統の最大の差別化層）

| 項目                 | 値                                                                                                  |
| -------------------- | --------------------------------------------------------------------------------------------------- |
| 本文サイズ           | 16px（モバイルでも縮小しない）                                                                      |
| サイズ列（4px 基準） | 13 / 14 / 16 / 18 / 21 / 25 / 30 / 36 px                                                            |
| 本文行送り           | 1.85                                                                                                |
| 見出し行送り         | 1.4                                                                                                 |
| 和文字間             | 本文 `0.02em`、見出し `0.01em`                                                                      |
| 詰め                 | 本文は**ベタ組み**（`palt` オフ）。見出しのみ `font-feature-settings: "palt" 1, "chws" 1`           |
| 約物                 | `text-spacing-trim: trim-start`（対応環境）で行頭・連続約物の空きを整える                           |

## 3B. 文章の層（制約1への回答・書体と同格の層）

この系統は、色・書体・罫と**同じ強さで文章を規定する**。信頼を最初に壊すのは視覚ではなく日本語の不自然さだからである。以下はデザイントークンと同じく検査可能な規則として扱う。

**語り口**

- UI・道具の説明・記事は敬体（です・ます）。辞典の語釈だけは常体で簡潔に書く（辞書の語り口であり、面ごとの一貫した使い分けであって例外ではない）。
- 一人称は「このサイト」。「私たち」は使わない（運営主体を人間の集団に見せかけない＝**D. 正直**）。

**見出し**

- 見出しは**そのページで来訪者が得るものを書いた名詞句**にする。「〜について」「〜とは？」を連ねない。
- コロンで区切る見出し（「機能: 〜」）を禁じる。
- 抽象的な標語見出し（「未来をつくる」型）を禁じる。

**本文**

- ヘッジ（「かもしれません」「と言えるでしょう」「一般的に」）を禁じる。断定できないことは書かない。書く必要があるなら、根拠と限界を具体的に書く。
- 「〜だけではありません、〜なのです」構文を禁じる。
- 汎用最上級（「究極の」「最強の」「圧倒的な」）を禁じる。
- 数量は必ず実数で書く（「たくさんの漢字」ではなく「2,136 字」）。実数を持たないなら数量に言及しない。
- 1つの箇条書きの中の太字強調は 0 個か 1 個。
- 見出し・ナビゲーション・ラベルに絵文字を使わない。本文中も使わない。
- 半角スペース・記号の整形残りを残さない。

**煽らない構造**

- **結果を出し惜しみしない。** 診断・計算・変換の結果は、スクロールも待ちも追加操作もなしに、生成された位置に全文表示する。「続きを見るには」を作らない。
- 実際の制限がない限り「限定」「今だけ」「あと◯人」を書かない。
- 免責は**すべてのページのフッタに、同じ文言で、同じ位置に、1文で**置く。畳まない、色を変えない、目立たせない、隠さない。常に同じ場所に同じものがあることが開示の誠実さになる。

## 4. レイアウトの原理

### 構造を何で示すか

**罫と余白だけで示す。面（カード・影・囲みボックス）では示さない。**

面による囲みは、ページ内で**1つだけ**許される。それは来訪者の成果物である（下記「成果物の面」）。囲みが希少であることそのものが、成果物を主役にする仕組みになっている。

### 左基線（この系統の背骨）

- ページの全要素——見出し・本文・一覧・入力欄・ボタン・図・免責——が**同一の左端**に揃う。
- インデントを作らない。箇条書きのマーカー・引用符・番号はすべて**ぶら下げ（ハンギング）**で左基線の外に出し、文字の左端を守る。
- 版面はデスクトップで中央寄せ、その左端が基線。モバイルは画面左 16px。
- 中央揃えのテキストブロックを作らない（見出しも本文も左揃え）。中央揃えヒーローは禁止。

### 縦の目盛り

- 縦のリズムは **4px** 単位。すべての縦マージン・行の高さ・罫の位置が 4 の倍数に載る。
- **余白スケール**: `4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96` px（`--sp-1` … `--sp-9`）。
- **一律パディングを禁じる。** 見出しは上に広く下に狭い（例: 上 `--sp-6`(32) / 下 `--sp-3`(12)）。罫の上下も非対称（上 24 / 下 12）。要素は「所属する側」に近づく。一律 16px の四方パディングは AI 生成の指紋であり、かつ所属関係の情報を捨てている。

### 一覧の既定形

**罫線区切りの縦一列（品書き型）。カードグリッドは全面禁止。**

各行の構成（1行 = 名前 + 一行説明 + 値札）:

```
────────────────────────────────────────────────
文字数カウント                        道具 ・ 5秒
文章の文字数・行数・原稿用紙の枚数を数えます。
────────────────────────────────────────────────
四字熟語辞典                        辞典 ・ 400語
意味・読み・出典を引きます。
────────────────────────────────────────────────
```

- 名前: 16px `--ink` ゴシック。説明: 14px `--ink-sub` 1行（溢れたら切らずに書き直す）。
- **値札**: 13px `--ink-faint`、種別と規模（所要時間・件数）を tabular で。デスクトップでは右端に右揃え、モバイルでは名前の下に落ちる。
- 項目間は `--rule-hair` 1px。項目の上下は 16 / 12 の非対称パディング。
- 項目数が多い面（道具 36・遊び 20）は **2 列の罫リスト**にする。列は 1px の縦罫で分ける。**罫リストが幅によってカードに化けることはない**——レイアウトの種別が変わらないことが、どのデバイスでも同じ場所に同じものが見える理由になる。
- 番号付きの一覧では 01, 02 … の 2 桁 tabular を左基線にぶら下げる。

### 角の扱い

**すべて 0（直角）。例外なし。** ボタンも入力欄も画像も成果物の枠も直角。「8px の安全な中間」を避けて 0 に振り切る。罫紙という由来と、直角は完全に一致する。

### 成果物の面

来訪者が得たもの（診断結果・計算結果・生成物・辞典の答え）は、ページ内で唯一の**囲まれた面**として現れる。

- 地: `--paper-slip`（ライトでは純白、ダークでは最も明るい面）。
- 枠: 四辺すべてに `--rule-main` 2px。**上端だけ・左端だけの色付きボーダーを禁じる**（最も強い AI 生成の指紋）。
- 主役性は 4 つの手段の合成で作る: (1) ページ内で唯一の囲み、(2) ページ内で唯一の地色の切り替え、(3) ページ内で最大の文字サイズ、(4) 版面の全幅を使える唯一の要素。地色の明度差だけでは弱いため、単独の手段に依存させない。
- 成果物の中には、色・比喩・遊びを持ち込んでよい（後述「装飾の限度」）。器は静かなまま、中身だけが賑わう。

### ページの型（3種のみ）

1. **道具・遊びの面**（モバイル 87.5% / 10.0% と両極端。両方で成立させる）
   のれん → H1（明朝）→ 1行の説明 → **即、操作**（最初の画面内に操作が入る。説明を先に読ませない）→ 成果物の面 → 使い方の補足 → 隣の棚（関連する道具・遊び 6 件の罫リスト）→ 免責。
2. **辞典の面**（モバイル 66.1%）
   のれん → 見出し語（36px 明朝）→ 読み・画数・分類の**表**（罫のみ、縞なし、tabular）→ 語釈 → 用例 → 隣接する語（前後の語・同分類）の罫リスト → 免責。
3. **読み物の面**（モバイル 0.0%＝ほぼ全員がデスクトップ）
   のれん → 日付・読了時間（左の欄）→ H1（明朝）→ 本文1カラム → 関連記事の罫リスト → 免責。
   **読み物の面だけ、版面の左外に幅 96px の欄（左罫 1px で仕切る）を持つ**。日付・章番号・脚注をそこに置く。デスクトップが 100% の面だからこそ許される構造で、モバイル幅ではこの欄は畳まれて本文上部に載る。

### のれん（ヘッダ）とフッタ

- **のれん**: サイト名（明朝 21px）+ 直下に画面全幅の `--rule-main` 2px 実線。その下に区分名（試す / 片づける / 調べる / 読む）を 14px で横並び。高さ 56px 固定。
- **sticky にしない・スクロールで隠れない・追従しない。** 常に同じ位置に同じものがあることが安心であり、追従ヘッダは情報面積を奪う。
- **フッタ**: `--rule-main` 2px → 免責 1文 → 全区分と主要な道具・辞典への罫リンク（1ページで用が足りた来訪者に、次を示す唯一の常設の場所）。

### デバイス非対称への解

主デバイスが面ごとに違うため、**レイアウトの種別を切り替えずサイズだけを変える**方針を取る。罫リストは幅 320px でも 1200px でも罫リストのままで、値札の位置だけが変わる。列数と版面幅だけが breakpoint で変わる。これにより、モバイル主体の遊びの面とデスクトップ主体の読み物の面が同じ骨格を共有できる。

- タップ対象は最小 44px 四方、罫リストの行高は最小 56px。
- 入力欄は 16px（iOS の自動ズームを起こさない）。
- ホバーに依存する情報を作らない。

## 5. 装飾の限度

### 許すもの（これがすべて）

- **1px / 2px の実線罫**（水平・垂直）。色は定義した 4 段階のみ。破線・点線・二重線は使わない。
- **節見出しの左にぶら下がる朱の短罫**（長さ 8px・太さ 2px・`--vermilion`）。校正の朱の記号であり、ページ内の節の始まりを示す唯一の装飾。
- **tabular による連番**（01, 02 …）。
- **機能アイコン 8 種のみ**（コピー・ダウンロード・共有・外部リンク・検索・閉じる・前・次）。1.5px ストローク、単色 `--ink-sub`、16px、塗りなし。それ以外のアイコンを作らない。
- **成果物の面の中でだけ**、コンテンツ固有の色・図・比喩・マイクロインタラクションを足してよい。ただし朱以外の色を使う場合も、その面の外へ漏らさない。基層（罫・組版・トークン・グリッド）は全面で共通のまま動かさない。
- **モーション**: 状態変化のみ、120ms、`ease-out`。加えて**成果物が現れる瞬間だけ**、4px 下から上への移動 160ms を許す（結果が来たことを知らせる、ページ内で唯一の動き）。`prefers-reduced-motion: reduce` で全停止。

### 禁じるもの（検査可能な形で）

**色・面**

- グラデーション（線形・放射・メッシュ、全種）
- `box-shadow` / `text-shadow` / `filter: drop-shadow`（全種、`0 0 0` 相当も含む）
- 色付きグロー、ネオン、`backdrop-filter`（グラスモーフィズム）
- `border-radius` > 0
- 2 色目のアクセント。朱以外の彩色を器（罫・文字・ボタン・ラベル）に使うこと
- 文字ブロックの背景に朱を敷くこと。朱の塗り面が 1 ページに 2 つ以上あること
- ダークを既定にすること

**構造**

- カードのグリッド（同型の箱を並べる一覧）
- 上端だけ・左端だけの色付きボーダー
- ピル型バッジ（特に H1 直上のもの）
- 中央揃えヒーロー
- 「ヒーロー → アイコン3枚 → 証言 → 統計 → 料金 → フッタ」の定型順序
- 全要素に一律の四方パディングを与えること
- sticky ヘッダ、スクロール連動アニメーション、モーダル、ポップアップ、インタースティシャル（全種）
- 結果の一部を隠して操作を要求すること

**タイポ**

- Inter / Roboto / Open Sans / `system-ui` 任せを本文に使うこと
- 見出しの中の 1 語だけを明朝・イタリックにすること
- all-caps のラベル
- 本文へのモノスペース
- 見出し・ナビ・ラベルの絵文字

**画像**

- AI 生成イラスト、ストック写真、浮遊する 3D、Corporate Memphis 風のブロブ人間
- 内容と無関係な装飾画像（画像は、内容そのものであるときにだけ置く）
- 地に敷くテクスチャ・ノイズ・グレイン（「クラフト感の演出」も含めて禁止。規則が見えていれば効果は要らない）

**文章**

## 7. この案が弱い面

### 最も弱い: B. 気軽さ（気負わず、すぐできる）

**理由**: この弱さは起点 A の直接の副作用であり、構造的なものである。

「測って作られた」を可視にする手段——直角・明朝の見出し・朱・1px の罫・揃った左端——は、日本語圏では**帳面・証書・辞書・公文書**の記号でもある。これらは「きちんとしている」と同時に「かしこまっている」を運ぶ。来訪者が着地の数秒で受け取るのが「ちゃんとした場所だ」であるとき、「ちゃんとやらなきゃ」という緊張が一緒に来る危険がある。B が求めているのはその逆——気負わないこと——なので、A を最大化する選択がそのまま B を削る。

さらに、この系統は**削ることでしか安心を作れない**（装飾を足せば規則が隠れて A が崩れる）ため、B のために親しみを足すという逃げ道が原理的に塞がれている。

案の中の緩和策——操作を最初の画面に置く／朱のボタンを 1 つに絞る／入力欄の罫だけを濃くする／本文を大きく行送りを広く取る——はいずれも**「すぐできる」の側**は届かせるが、**「気負わず」の側**には届かない。緩和は部分的である。

賭けの内容を明示しておく: この案は、**「気負わなさ」を器の柔らかさではなく操作の少なさで作る**ほうに賭けている。柔らかさで作る系統（丸み・淡い色・くだけた語り口）と比べたとき、B で負ける可能性が高い。

### 次に弱い: E. 広がり（他にも面白そうなものがある）

**理由**: この系統は画像・サムネイル・カテゴリ色を持たない。したがって「他にも面白そうなものがある」を運ぶ手段が**文字と罫だけ**に限られる。

来訪者の 92.8% は検索から着地して 1 ページだけを見て帰る——つまり大多数は熟読者ではなく走査者である。走査者に対して、色も絵もない罫リストは「読めば分かるが、読まなければ気づかない」ものになる。値札（種別・所要時間・件数）と「隣の棚」6 件は E のための具体的な仕掛けだが、いずれも**視線を止める力そのものは弱い**。

E を強く届ける自然な手段——各項目にアイキャッチ画像を付ける、区分ごとに色を割り当てる、カードで並べる——は、この案が禁止した項目とそのまま重なる。つまり E の弱さも A から導かれた必然であり、部分的な追加では埋まらない。

### 弱くない 3 面

- **A. 安心（ここは大丈夫だ）** は起点であり、系統全体がこれに奉仕している。
- **D. 正直（取り繕っていない）** は、装飾を持たない器と、文章の層の禁止規則（3B）と、免責の常設によって、独立に 3 重で支えられている。
- **C. 手ごたえ（やってよかった）** は、「囲みはページに 1 つだけ」という規則が成果物に集中するため、器が静かであることがそのまま成果物の強さになる。器を静かにした唯一の見返りがここにある。
