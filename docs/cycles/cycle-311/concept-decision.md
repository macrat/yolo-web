# コンセプト＝ブランドイメージの決定（T4）

## 0. この文書が答える問い

**yolos.net は何であり、来訪者にどんな印象を持ってほしいか。**

これは二つの問いではなく一つである。喚起したい印象を持たない「正体」は来訪者にとって無価値であり、体現するものを持たない「印象」は接地しない。両者は一つの決定を作り手側と来訪者側から見たものにすぎないので、一体で決める（別文書に割ると必ずドリフトして矛盾する——それが前サイクルの失敗の構造的原因だった）。

## 1. 入力

**地（根拠に引いてよい）**

- `docs/constitution.md`（Goal と Rule 1〜5）。
- サイト名 yolos.net の由来＝**YOLO × よろず**の二重の意味（不変の事実）。
- **来訪者の実測**（[visitor-reality.md](./visitor-reality.md)・2026-08-13 取得）。
- **本番の実画面の実見**（2026-08-13・375×812 で `/play/character-personality` を実表示）。
- 外部の一次資料（Google の生成 AI 検索最適化ガイド）。

**容疑者（結論の根拠に引かない）**

現行 `docs/site-concept.md`・`DESIGN.md` の記述、cycle-310 の `brand-image.md`／`e1-decision.md`／`decision.md` の結論、現行の実デザイン（favicon・OGP・実装トークン）。これらは本サイクルが正す対象であって、正しさの根拠ではない。

## 2. 来訪者の実像

**誰が来ているか。** 検索クリックの 88% が `/play/character-personality` の1ページで、クエリはほぼ全量が「自分に似ているキャラクター診断」の言い換えである。つまり典型的な来訪者は「**自分に似たキャラを知りたくて検索した人**」であり、yolos.net を探して来た人ではない。

**どう経験しているか。** organic セッションの **95.1% が1ページで終わる**（人間の操作を伴う engaged セッションでも 70.8%）。トップページは28日で engaged_pv 5。**来訪者は「サイト」を経験していない。1ページを経験して帰る。** そしてその1ページは、**8割がモバイルの縦長画面**である。

**そこで何を見ているか（実見）。** 実際の画面に写るのは、店号 `yolos.net`・一本罫・明朝の見出し・紙と墨の色・朱のボタン・小さな値札ラベル・FAQ である。**「ここは店だ」と知覚させるものは画面上に一つも無い。** 来訪者が実際に受け取っているのは「静かで、丁寧に組まれた、和の紙面」という印象であって、店の物語ではない。

**この人が着地の瞬間に何を判断しているか。** 検索結果から診断サイトへ飛んだ経験のある人は、広告だらけの面・「本当の結果は次のページ」の出し惜しみ・不安を煽る鑑定 LP を何度も踏んでいる。だから最初の数秒で判断されるのは「**ここは大丈夫か**」である。次に「**すぐ始められるか**」、最後に「**やった甲斐があったか**」。

## 3. 決定: このサイトは何か

**yolos.net は、AI が作って公開している「やってみる」ためのサイトである。検索でたどり着いたそのページで、その場でためして、自分のための結果や作ったものを持ち帰れる。**

- **来訪者にとっての正体は「1ページ」である。** サイト全体ではなく、たどり着いたその面が価値の単位。だから各ページは、それ単体で完結し、それ単体で信頼に足るものでなければならない（サイトを巡って初めて像を結ぶ設計は、実測上ほぼ誰にも届かない）。
- **扱う領域は狭めない。** サイト名の「よろず（あらゆるもの）」は運営が候補空間を限定しないという**規律**であって、来訪者に見せる自己像ではない。広さは、来訪者が経験するものではなく、AI が試行回数を確保して当たりを探すための運営側の性質である。
- **AI が運営する実験であること、内容が誤りうることを明示する**（Rule 3 が明示的に要求している。省略の余地はない）。ただしそれは**正直の開示**であって、**売り物ではない**——「すごい実験でしょう」と関心を買いに行くことは Rule 3 の趣旨ではなく、下記 D（正直）を損なう。
- **何が残るかは来訪者の行動が決める。** AI の見立ては仕入れの目であって審判ではない。

## 4. 決定: 来訪者に持ってほしい印象

来訪者が **1ページの体験の中で** 受け取る印象として、次の4つを定める。いずれも「来訪者がどう感じるか」であって、サイトの仕組み・構造・作り方ではない。

### A. 安心（ここは大丈夫だ）

「雑に量産された場所でも、不安を煽って何かさせようとする場所でもない。安心して使える」と感じてほしい。**着地の瞬間に最初に判断されるのがこれであり、ここで失うと以降のすべてが届かない。**

- 由来: Rule 2（helpful/enjoyable・人を害さない・悲しませない）、Rule 4（量より質）。

### B. 気軽さ（気負わず、すぐためせる）

「難しいことも面倒な手続きもなく、いま、ここで、ちょっとためせる」と感じてほしい。登録も待ちも駆け引きもない、軽い招き。

- 由来: Rule 2（enjoyable）。実測の接地: 来訪者は「このサイトを使う」と決めて来たのではなく、検索の途中で立ち寄っている。重い入口は、その人の関心の軽さに釣り合わない。

### C. 手ごたえ（やってよかった）

「読んで終わりじゃなかった。自分で手を動かしたら、自分のためのものが手に入った」と感じてほしい。**このサイトが存在する理由**であり、ほかの3つはこれを受け取れる状態を作るために在る。

- 由来: Rule 2（helpful/enjoyable）。外部一次資料の接地: Google は「他が既に言ったこと・生成 AI が容易に作れるものを再生産するな」と明言しており、来訪者が関与して初めて得られるものだけが、配達されて消える情報と違う価値を持つ。

### D. 正直（取り繕っていない）

「この場所は自分に対して正直だ。隠しごとも、格好つけも、騙しもない」と感じてほしい。AI が作っていることを隠さず、しかし「すごい実験でしょう」と売りにもしない。結果を出し惜しみせず、できないことをできると言わない。

- 由来: Rule 3（AI 運営と誤りうることの明示）、Rule 1（法令・倫理）。

### 優先順位

衝突したら **A > D > B > C の順で守る**。A（安心）と D（正直）は失うと回復しない信頼の土台であり、B（気軽さ）は C（手ごたえ）へ到達するための条件である。ただし C を削って A を得るのは本末転倒——**C を届けるために A・B・D を土台として敷く**、という関係にある。

### 「広さ」を印象の面に立てない理由

「よろずの品揃えが楽しい」は、**来訪者が実際に経験していない**（95%が1ページで帰る）。広さは §3 のとおり運営側の規律であり、来訪者に持ってほしい印象として立てると、届かない相手に向けた設計（サイト全体の構えを見せる仕掛け・面をまたいで覚えさせる仕掛け）を上流から生み続ける。回遊は起きたら良いことだが、**印象の設計の前提には置かない**。

## 5. 判定: 店（よろず屋）メタファーを外す

**結論: 「よろず屋＝店」という自己定義と、そこから導かれる店メタファーを、コンセプトから外す。**

判定の根拠を、keep 側の効用と remove 側の損失の両方について検証する。

**(a) 来訪者に届いているか → 届いていない。** 店は「複数の品が並び、客が巡って選ぶ」場所である。しかし来訪者の 95% は巡らない。1ページで帰る。実見でも、画面に店を知覚させるものは無かった。**店フレームが来訪者に与えている印象は、現実にゼロである。**

**(b) 来訪者の理解を妨げていないか → 妨げる方向に働いている。** 店の独自 signifier（店/屋/のれん/品書き/棚/値札/札/印）は、来訪者に自明には伝わらない符牒である。現に内部語彙が `aria-label`（「関連記事の品書き」「辞典の品書き」）としてスクリーンリーダー利用者に読み上げられており、伝わらない符牒が可視の層へ漏れている（既起票 B-649）。

**(c) 設計を一貫させる力があるか → その力は店に固有ではない。** 「雑多な中身を一つの器で統一する」という規律には価値がある。しかしそれは「一つの器で統一する」と直接言えば足り、「店に見せる」という物語を必要としない。**物語は、統一という機能に何も足していない。**

**(d) 外さないことの害 → 実害が出ている。** 上流に「店」がある限り、そこから「店を見せる」施策（店構え・のれん・印・店の言葉）が繰り返し導出される。cycle-306 から cycle-310 までの churn（印の字・形・物語をめぐる往復と、2度の偽完了）は、すべてこの生成器から出ている。**来訪者が経験しないものを上流に置くと、来訪者の実態とずれた設計を再生産し続ける。**

**(e) 失うもの → 失わない。** 店フレームが担っていた中身は、すべて店なしで直接言える。「広さは正体」→ 運営が領域を狭めない規律（§3）。「一軒の店に見せる」→ 全ページが一つの器を共有する（§4 A の安心を届ける手段）。「仕入れの目と棚から下げる規律」→ 作る判断と撤退の判断（判断基準）。「店主が AI」→ AI が作っていることを隠さない（§4 D）。

**したがって店メタファーは、来訪者に何も与えず、理解を妨げる方向に働き、設計の churn を生み続けている。外す。**

**外し方（半分だけ外すことは許されない）**: コンセプトから外す以上、そこから導かれるデザインシステムの「店構え／のれん／品書き／棚／値札／包み／札／印」という**目的と語彙**も、店を体現するためのものとしては存続しない。デザインシステムの各規定は T8 で、**§4 の印象（A・B・C・D）を来訪者に届けるか**という基準から導き直す——その結果、視覚上の結論（紙と墨の色・明朝の見出し・罫で組む・角丸を作らない等）が現行と同じ値に着地することはありうるが、それは**同じ結論に別の正しい根拠で到達した**のであって、店の語彙を温存したのではない。実デザインとコードの語彙（コンポーネント名・内部識別子）の扱いは B-652 の範囲とする。

## 6. 自己点検（AP-P02: 結論先決・検証の非対称・測度のずれ）

- **測度は問いに一致しているか。** §4 の4面はすべて「来訪者がどう感じるか」である。「認識される」「面をまたいで一貫する」「見つけやすい」「美しい」「識別できる」といった**サイト側の性質・仕組み・手段は一つも面に入れていない**。前サイクルはここで問いを「認識」という機構にすり替えて失敗した。
- **自分の結論に不利なデータを探したか。** 店 keep 側に有利な事実として (i) 内部語彙としての一貫性生成力、(ii) 既存実装への適合、(iii) 過去サイクルの積み上げ、を検討した。(i) は §5(c) で「店に固有でない」と判定、(ii) は実装適合を根拠にすると導出が逆走する（前サイクルの失敗そのもの）ため入力から除外、(iii) は構築物であって地ではない。
- **導出の向きは正しいか。** 実デザイン（favicon・OGP・トークン）を一切見ずに、constitution と来訪者の実測・実見だけから決定した。この決定の結果として実デザインが変わるかどうかは、B-652 が受ける。
- **残る不確かさ。** 「広さを印象に立てない」判断は現在の流入構造（1ページ集中・95%が単ページ）に依存する。回遊が実際に起きる構造へ変わったら、この判断は再検証を要する（新 site-concept のトリップワイヤに載せる）。
