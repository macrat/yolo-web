# 視覚言語案 2: 手もと（てもと / Temoto）

起点: **B. 気軽さ（気負わず、すぐできる）**

---

## 1. 系統の名前と一文の説明

### 手もと（Temoto）

**どのページも開いた瞬間からすでに作業台であり、朱色は来訪者が手を入れた場所にだけ灯る——始めるまでを最短にし、成果を主役にする系統。**

この系統には根になる一つの比喩がある。**墨はこのサイトが言うこと、朱は来訪者がしたこと。**
校正の朱、判子の朱、書き込みの朱と同じで、朱はいつも「あとから手を入れた側」の色である。だからサイトの側の見出し・ロゴ・宣伝文句は決して朱をまとわない。来訪者が触れるもの（入力欄・ボタン・選んだ行）と、来訪者が得たもの（答え・結果・成果物）だけが朱になる。

この一本の規則から、以下すべてが機械的に導かれる。

## 2. 色

### 考え方

- **地は紙、面は手もと。** ページの地は暖かい生成り。来訪者が実際に作業する領域（入力欄・結果の器）だけが**純白**で、地よりわずかに明るく前に出る。奥行きは影ではなく**明度差だけ**で作る。「明るいところが、いま触るところ」という一文で全画面が説明できる。
- **色は1つだけ。** 朱。副次の色は持たず、副次は「色の不在」（墨の濃淡と罫）で表す。
- **朱は状態の色ではなく所有の色。** エラー・警告・成功を色分けしない。状態は**語と太さと位置**で示す。朱を警告に使った瞬間、朱は「サイトが来訪者を急かす色」に堕ちる。
- **恒常ダークは持たない。** OS の `prefers-color-scheme` にのみ従う。既定でダークにするのは「意図なきダーク」であり、AI が作った記号そのもの。

## 3. 書体

### 方針: 本文に Web フォントを載せない

**待たされないことが気軽さである。** 1.5MB のサブセットを待つ 0.4 秒は、「いま、ここで、ちょっと」を毎ページ削る。だから和文は**配信ゼロ**（端末内蔵書体）に振り切る。差別化は書体の珍しさではなく**組版の丁寧さ**で取る。日本語の約物処理と行分けは、量産サイトがまず手を付けない領域であり、そこにだけ手をかける。

| 層                       | 指定                                                                                                                                                                                                                            |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 和文（本文・見出し共通） | `"Hiragino Sans", "Yu Gothic", YuGothic, "Noto Sans JP", sans-serif`（iOS/macOS=ヒラギノ角ゴ、Windows=游ゴシック、Android=内蔵 Noto Sans JP。すべて配信ゼロ）                                                                   |
| 欧文・数字               | **IBM Plex Sans**（400 / 600）を**ラテン基本と数字だけにサブセット**した WOFF2（1ウェイト約 25KB）。`@font-face` に `size-adjust` を与えて内蔵書体とメトリクスを合わせ、`font-display: swap` でも字送りが揺れないようにする     |
| 明朝                     | 端末内蔵のみ（`"Hiragino Mincho ProN", "Yu Mincho", serif`）。**Web フォントとしては配信しない。** 使ってよいのは辞典の主役字（漢字1字・四字熟語4字・色名）だけ。Android 等で明朝が無い端末ではゴシックに落ちる——それを許容する |

### 見出しの方針: 見出しで身構えさせない

- **見出しは本文と同じ書体・同じ色。** 変えるのは**大きさと太さだけ**。書体を切り替えた「編集的コントラスト」は取らない。大きな別書体の見出しは、読む前に「これから読むぞ」という構えを要求する。それは B の敵である。
- **巨大見出しを持たない。** ページ名の上限は **24px 太字**。ヒーロー見出しは存在しない。
- 段階: ページ名 24px/1.4 太字 → 節 21px/1.5 太字 → 小節 17px/1.6 太字（本文と同寸、太さだけで差をつける）。

### 数字の方針: 数字は成果物である

道具と辞典では、来訪者が持ち帰るものはたいてい数字か短い文字列である。だから**数字だけが本文より大きく、別の書体を許される唯一の要素**。

- 単一の答え: IBM Plex Sans 600 / **56px** / `font-variant-numeric: tabular-nums` / 墨 / 直下に朱の 2px 罫。
- 複数の答え（換算表など）: 32px、同じく tabular。桁が縦に揃うことが正確さの表明になる。
- 単位・補足は和文 14px 淡墨で、数字の**後ろに置く**（先に読ませるのは値）。

### 組版（この系統の差別化の中心）

- 本文はベタ組み基調。`font-feature-settings` の `"palt"` は**見出しと 32px 以上の数字にだけ**（本文に詰めをかけると可読性が落ちる）。
- `text-spacing-trim` / `text-autospace` を有効化し、和欧間・約物前後のアキは CSS に任せる。**手で半角スペースを入れない**（整形残りは AI 臭さの症状そのもの）。
- 見出しは `word-break: auto-phrase` で文節改行。`line-break: strict`。
- 本文行間 **1.85**、見出し 1.4〜1.5。本文サイズ **17px**、読み物の面（記事）だけ **18px**。
- 禁じる: 本文モノスペース、見出し1語だけのセリフ／イタリック、all-caps ラベル、`Inter` / `Roboto` / `Open Sans` / `Poppins` / `Montserrat` を欧文既定に置くこと、見出しとナビの絵文字。

## 4. レイアウトの原理

### 構造は「面」と「1px 罫」の2つだけで示す

囲まない。**ボックスで囲むこと自体を禁じる。** 使えるのは次の2つに限る。

1. **面**: 純白 `#FFFFFF` の領域。意味は常に一つ、「ここが手もと（入力・結果）」。装飾として白面を置くことはできない。
2. **1px 実線罫**: 行の区切り（`#E2DBD0`）と節の区切り（`#C9BFB0`）。

影・角丸の枠・背景色ブロック・カードは構造の表現手段から外す。結果として、**カードは全面禁止**になる（同型カードのグリッドと「上端／左端だけ色付きボーダー」は最も確実な AI の指紋であり、そもそも構造の表現手段が2つしかないので発生しえない）。

### ファーストビュー規則（この系統の中核・検査可能）

> **どのページも、スクロールなしで、来訪者が最初に触る要素が見えていること。**

モバイル 640px 高を基準に、操作より上に置いてよいのは **店号バー 48px + ページ名1行** だけ。導入文・使い方・注意書き・AI 運営の開示・広告は、**すべて操作より下**に置く。辞典なら「答え」が、道具なら「入力欄」が、遊びなら「はじめる」が、最初の画面に必ずある。

この一行が同時に、結果を出し惜しみして誘導する情報商材型 LP の構造を構造的に不可能にする。

### 一覧の既定形: 品書き行

一覧は**例外なく全幅の行**。カードグリッドもタイルもない。

- 行の高さ **56px 以上**、上下に 1px 罫（隣接行で1本を共有）、左余白 20px。
- 行の中身: 名前（17px 太字・墨）＋ 値札（14px 淡墨・所要時間や種別）。
- **右端の矢印を置かない。** 行全体がタップ領域であることは、押せば分かる。矢印は 20 行あれば 20 個のノイズになる。
- 押下・選択中は行に朱・淡 `#FBEDE7` を敷く（ライト）／朱を 12% 重ねる（ダーク）。
- 装飾アイコン・サムネイルを持たない。**アイコンは操作にしか付かない**（コピー・音量・戻る・閉じる。線幅 1.5px・24px・淡墨）。

1画面に7〜9行入る密度が「まだ他にもある」を最短で伝える。

### 角の扱い: 触れるものだけが丸い

**丸みは装飾ではなく、触れることの記号である。** 一律 16px 角丸（AI の指紋）は起こりえない。

| 対象                                           | 半径                                                                         |
| ---------------------------------------------- | ---------------------------------------------------------------------------- |
| 単行の操作（ボタン・チップ・検索窓・単行入力） | **高さの 1/2**（52px 高のボタンなら 26px。値を選ぶのではなく高さから決まる） |
| 複数行の操作（テキストエリア・結果の器）       | **16px**                                                                     |
| 面・罫・表・見出し・画像                       | **0**                                                                        |

飾りのピル型バッジ（見出し直上のあれ）は禁止。丸い形は押せるものにしか許されない。

### 余白のスケール

一律のパディングを持たない。使える値は7段のみ。

`4 / 8 / 12 / 20 / 32 / 52 / 84`（px）

要素間の距離は**関係の近さで3段しか使わない**: 密着 = 8、段落 = 20、節 = 52。「なんとなく 16」が入る余地を残さない。リズムの基本単位は 4px。

### 面ごとの画面差（単一デバイスを前提にしない）

ブレークポイントは **760px の1つだけ**。1カラムが正本で、広い画面は原則「余白が増えるだけ」。ただし面ごとに次の差を持つ。

- **遊び（モバイル 87.5%）**: 単一カラム。主操作は親指圏に届くよう、画面下端に 52px 高の朱ボタンを sticky で置いてよい（この系統で position:sticky を許す唯一の場所）。
- **辞典（モバイル 66.1%）**: 答えを最上部に。760px 以上では左 240px に索引を出し、本文との間は**罫1本**で仕切る（面や背景色で区切らない）。
- **道具（PC 90%）**: 760px 以上で **左＝入力／右＝結果**の2カラム、間は罫1本。入力しながら結果が同時に見える。760px 未満では入力の直下に結果を置き、結果の器を画面内に sticky で保つ。**入力して画面外を探しに行く道具にしない。**
- **記事（PC 100%）**: 単一カラム、本文幅 **34em（約 620px）**、18px/1.9。見出しに罫を敷かず、上余白 52px だけで節を作る。

## 5. 装飾の限度

### 5-A. 視覚

**許す**

- 1px 実線罫（2色のみ）。
- 朱の 2px 下線（成果物の直下）、朱の傍点（本文中の唯一の強調手段）、朱の面（ボタン・選択行）。
- 白い面と暖かい地の明度差。
- 機能アイコン（操作に付随するもののみ、線 1.5px 単色）。
- モーションは2種類だけ: 押下 90ms（`transform: scale(.98)`）と、**成果物が現れるときの 160ms**（opacity + 4px 上へ）。成果物の出現だけがこのサイトで唯一「動く」ことに意味を持つ。`prefers-reduced-motion` で両方停止。
- フォーカスは朱 2px の outline、offset 2px（唯一許す「影のような」表現）。

**禁じる**（値として書ける形で）

- `box-shadow` 全般（フォーカスリング以外）、`filter: blur/glow`、あらゆる `linear-gradient` / `radial-gradient`、グラスモーフィズム。
- カード、同型カードのグリッド、上端／左端だけ色の付いたボーダー。
- 中央揃えヒーロー、見出し直上のピル型バッジ、「ヒーロー→アイコン3枚→証言→統計→フッター」の順序。
- 全要素一律の fade-in、スクロール連動アニメーション、パララックス。
- AI 生成イラスト、Corporate Memphis 風の人物ブロブ、内容と無関係なストック写真、浮遊する 3D オブジェクト。**画像は「その内容そのもの」であるときだけ置ける**（伝統色の色見本、ゲームの盤面、記事の実スクリーンショット）。
- 装飾目的の絵文字。
- 一律の角丸、一律のパディング。

### 5-B. 文章の限度（この系統の文章層）

信頼を最初に壊すのは視覚ではなく日本語である。よって文章も視覚と同じ強さの規則を持つ。

**書き方**

- **ラベルは動詞にする。** 「文字数カウント」ではなく「文字数を数える」。ボタンは行為名ではなく**得られるもの**を言う（「送信」ではなく「数える」「JSON を整える」）。
- **ページの冒頭に前置きを書かない。** 説明・使い方・出典は操作の**後ろ**に置く。
- 一人称は「このサイト」。運営者を人格化しない。
- 1文 60字以内を目安、1段落 3文以内。
- 見出しにコロンを使わない（「特徴: 3つのポイント」型）。太字の箇条書きを積み上げない。
- 数値・単位・英字は半角。和欧間のアキは CSS に任せ、手で空白を入れない。
- AI 運営の開示は全ページ同じ一文をフッターに置く。詫びず、隠さず、大きくもしない。

**禁じる語法**

- 抽象的な最上級と煽り（「究極の」「圧倒的」「今すぐ」「たった3分で」「知らないと損」）。
- 「〜ではないでしょうか」「かもしれません」の連発（ヘッジ）。
- 「単なる X ではなく、Y です」構文。
- 体言止めの見出しばかりを並べること。
- 実在しない主体（「多くのユーザーが」「専門家によると」）。数字を書くなら出所を書く。

## 7. この案が弱い面

### 最も弱い: C. 手ごたえ（やってよかった）——遊びの面で

構造上、**祝祭を作る道具を自分で捨てている**。色は朱1色、影とグラデーションは禁止、動きは 160ms が一度きり、見出しの上限は 24px、装飾画像は不可。道具と辞典では「56px の数字＋朱の下線」で十分に手ごたえが立つが、**診断とゲーム20種の「結果を受け取った瞬間」には明らかに足りない**。占い・診断の結果画面が期待されている「もらった感」「見せたくなる感じ」は、本来なら大きな図版・色面・間の演出で作るもので、この系統はそのすべてを禁じている。明朝の大見出しや図版を持つ案に対して、ここは素直に劣る。緩和策（成果物だけ明朝の端末内蔵書体を許す、朱の面で囲む）はあるが、規則の例外を増やすことになり、系統の一貫性と引き換えになる。

### 次に弱い: E. 広がり（他にも面白そうなものがある）——見分けの手がかりが語だけになる

品書き行はサムネイルもアイコンも色分けも持たない。密度で「まだある」ことは伝わるが、**20 種のゲームが全部同じ形の行に見える**。何が面白そうかの判断が完全にラベルの語（と 14px の値札）に委ねられ、視覚的な引っかかりがゼロになる。特に PC 100% の記事一覧では、罫で区切られた同じ高さの行が縦に並ぶだけで単調になりやすい。「見つける楽しさ」ではなく「読んで選ぶ作業」に寄る危険がある。これは装飾の限度を厳しくしたことの直接の代償で、文章層（ラベルの語選び）の質がそのまま E の質になるという賭けをしている。

### 補足: A・B・D は強いが、A には一点の緊張がある

朱 `#BF4722` は赤系であり、大面積で使えば警告色に読まれうる。この系統は「朱は状態に使わない・面積は行と 52px のボタンに限る」という規則でこれを抑えているが、規則が破られた瞬間に **A. 安心（ここは大丈夫だ）** が最初に壊れる。実装時に最も監視すべき箇所はここである。
