## 作業計画

### 目的

ゲームを遊び終えた人と、表で情報を見比べる人が、狭い画面でも列が1文字ずつ縦に折れず、結果を一目で読めること。irodori（伝統色）のページを開いた人が、読み込みの途中でレイアウトが跳ねて読む位置を見失わないこと。これらは T5-20f（次に遊ぶものの一覧）の前提でもある。

B-784・B-786 は来訪者に直接見えないが、残り十数サイクルの品質を守る。文書の肥大はレビューの全文通読を不可能にし、並行する担当の衝突は他人の変更をコミットに紛れ込ませる。どちらも来訪者に届く成果物の質を落とすので、最初のサイクルで止める。

### 作業内容

1. B-786 を先に設計する（planner → reviewer）。cycle-316/decisions.md の「hook の取り消し」の行と incident の記録を読み、担当ごとの作業ツリー（`git worktree` など）と、コミットする者（PM か担当か）の決め方を決める。
2. T5-33・T5-8b/T5-20d は、それぞれ別の builder に1タスクずつ任せ、それぞれ別の reviewer に通す。各タスクの従う決定は [cycle-316/carryover.md](../cycle-316/carryover.md) の索引の「T5-8b・T5-20d・T5-33」の行に挙がる decisions.md の行と t5-8b-design.md。
3. B-784 は planner が対象と線を設計し、reviewer に通してから builder が実装する。
4. すべての作業のあとに全体のレビューを受け、完了の処理で `design-rollout` へ進める。
