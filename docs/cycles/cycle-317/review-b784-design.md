## 指摘

1. major: `git status --porcelain` は既定で、追跡されていないディレクトリを中のファイルでなくディレクトリ1行（`?? docs/cycles/cycle-318/`）で出す。新しいサイクルの最初のコミットで index.md が正規表現に当たらず、検査から漏れる。`-uall` を使い、確かめ方に「新しいディレクトリの index.md が上限を超えると止まる」を足す。同じ漏れが pre-commit-check.sh 41 行にもある。
2. major: 線の根拠が食い違う。「Read 1回は約 25k トークンで日本語ではおよそ 50〜80KB」なら 60〜100KB も一度で読めず、100KB は「一度で通読できる」を守る線でない。上限を Read 1回に収まる量（実測で決める）に下げるか、根拠を「分けて読めば通読できる上限」に言い換えて2つの線の意味を揃える。Read の実際の上限を実測し、`docs/knowledge/` に残すのが望ましい。
3. minor: 「90 パーセンタイル 92KB」は32本では取り方で値が変わる。定義を書くか「上位10%は 92KB 以上」と書く。
4. minor: `git -C <木> commit` や `cd <木> && git commit` では `.cwd` とコミットする木がずれる。b786 の方針が前提であることを残る危険に書く。
5. minor: AP-WF17 候補（N=3）は、検査ができた時点で本採用か「仕組みで防いだので項目にしない」かを決めて明示し、候補の側は消す。
6. minor: cycle-316 の decisions.md（210KB）を「次に手を入れると止まり、そのとき分ける」とするのは受け身。今回分けるか backlog に積むかを決めて書く。
