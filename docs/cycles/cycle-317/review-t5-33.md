## 指摘

1. 【中】savedLayout.ts の注釈の「結果の区画は画面より高いので、区画の下のものは読み込みのあいだ画面の外にあり、結果が出ても見えている所は動かない」は、いつも成り立つわけではない。1280×2400 では、irodori の結果の区画（覚えた高さは 2138px）が 100vh（2400px）より低い。だから結果が出ると取り置きが縮み、見えている「他のコンテンツ」が上へ動く余地がある。今回の測りでは CLS は 0 だったが、結果が初めの描画より前に出たためとみられ、この注釈の理屈が保証しているわけではない。kanji-kanaru・yoji-kimeru・nakamawake の結果の区画の高さも確かめていない。直し方は二つある。一つは、結果の区画の高さを4つのゲームと縦に長い画面で測り、成り立つ範囲を確かめて、注釈を事実に合わせること。もう一つは、`min(100vh, …)` のような、画面より低い区画でも縮まない値にすること。
2. 【中】決定の行にある「320 の既定で 0.1625」が再現できなかったことの扱いが、記録に無い。0.0395（1280・100%・高さを覚えていない）が 0 になったことは、決定の条件の「その数値を 0 にする」と同じではない。だから「条件を満たした」とは言えない。サイクルの文書に次の三つを書くこと。再現を試みた条件（30 通り）。代わりに 0 にした値とその条件。0.1625 は前の版でも出ないので、測りの道具か条件が違っていた見込みであること。そのうえで、PM がこれで閉じると決めること。
3. 【小】builder は画面での確かめをしていない（報告にそう書いてある）。今回はレビュアーが撮ったが、UI に関わる変更で builder が画面を確かめないのは、作業の進め方のアンチパターン（docs/anti-patterns/workflow.md）に当たる。直す回では、builder が担当の木で撮ってから報告すること。
4. 【小】開発サーバーの画面に Next.js の「1 Issue」の印が出ている（変更の前後とも）。この変更から来るものではないとみられる。ただ、中身を確かめていないので、PM はほかのタスクとして中身を確かめるか、確かめたことをサイクルの文書に書くこと。
