## 作業計画

### 目的

来訪前（検索結果の favicon・シェアの OGP・来訪者に見えるコピー）に潜在来訪者が最初に受け取る「サイトの顔」から、**開発側都合のメタファー（印・店構えの統一・店の主張）が来訪者に価値を持つか**を constitution から導出し、必要なら解体する。5サイクル・約1ヶ月放置された本丸の付託 (a)(b)(d) に、字/形決めでなく**要否の導出**で正面から答え、文書化された判断（と、それが指示する変更）を成果として残す。

### 作業内容

上のチェックリストの通り。核は次を **PM 自身が・実体で接地し・constitution から導出し・実物の顔を見て**下すこと（委譲しない＝304/305 の致命傷）:

1. **接地**: どの顔が実際に潜在来訪者に届くか（favicon＝検索結果／OGP＝シェア）を GA 実測で確定。現状の顔を実レンダーで見る。店/印メタファーの現存箇所を悉皆列挙。
2. **導出**: constitution（Goal・Rule2/3/4）から「来訪前の顔がクリックを迷う人に何をすべきか」を導く。DESIGN.md 等の PM 文書は根拠に引かない（容疑者）。
3. **判定**: (a) 店構え統一 / (b) 印 / (d) 店の主張 の各要素に、keep/remove/change の立証責任を負わせ、実物の with/without を比較して来訪者価値から決める。**撤去も無料でない**。

分割方針（CLAUDE.md「Keep task smaller」）: 接地は観点ごとに sub-agent（GA は foreground）。**決定は PM が実物を見て下す（委譲しない）**。実装は顔（favicon/OGP）・コピーで別エージェント。レビューはタスク単位で個別 reviewer（**付託適合＝来訪者価値レンズを必須観点に**）。
