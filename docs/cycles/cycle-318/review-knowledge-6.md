## 指摘

### 1. 【中】探す先に除く4つのディレクトリそのものを渡すと、決まり3のコマンドは何も探さずに終了の値 1 を返す（偽の「無い」）

GNU grep の `--exclude-dir` は、探すうちに出会うディレクトリだけでなく、コマンドに渡したディレクトリも名前が合えば飛ばす。知らせは出さない。主の木での実測は次のとおり。

```sh
X="--exclude-dir=.git --exclude-dir=worktrees --exclude-dir=.next --exclude-dir=node_modules"
LC_ALL=C.UTF-8 grep -rla    "の" .next      # → .next/server/… のファイルが出る（終了の値 0）
LC_ALL=C.UTF-8 grep -rla $X "の" .next      # → 何も出さず、終了の値 1
LC_ALL=C.UTF-8 grep -rla $X "の" ./.next    # → 何も出さず、終了の値 1
LC_ALL=C.UTF-8 grep -rla $X "の" .next/     # → 出る（末尾の / があると名前が合わない）
LC_ALL=C.UTF-8 grep -rla $X "の" .claude/worktrees  # → 何も出さず、終了の値 1
LC_ALL=C.UTF-8 grep -rla $X "の" .claude/worktrees/agent-ac8afdc91fb65790b/docs/knowledge  # → 出る
```

決まり3は「`.gitignore` に載るファイル…まで含めて「無い」を言うとき」に使うコマンドとして、探す先を書かずにこの形を示す。`.gitignore` に載るファイルを探したい読み手は、まさにその中を探したいことがある（消した文言がビルドの出力 `.next` に残っていないかを確かめる、担当の木の全部 `.claude/worktrees` を探す）。決まりどおりにコマンドを写して探す先だけをそこに変えると、何も探さずに「無い」を返す。文書の目的（偽の「無い」を出さない）に直に掛かる。

あわせて、決まり3の文言は「`.gitignore` に載るファイル…まで含めて」のままだが、コマンドは `.gitignore` に載る `.next` と `node_modules` を除く。除く理由は5段目にあるが、決まりの1行だけを読む読み手には、含める範囲が文言と食い違って見える。
