## 指摘

### 1. 【重要】「C ロケールのままでも正しく一致する」型に、`-w` と `-i` を付けると偽の結果が出る

「安全な範囲」を崩す例を探し、次を見つけた。どちらも、文書が安全とした「固定の文字列（`grep -F`）・字の並びをそのまま書く型」に、よく使う選択肢を足しただけで起きる。

```sh
echo "あいう" | grep -cw "いう"                 # → 1, 終了の値 0（偽の「有る」）
echo "あいう" | grep -cwF "いう"                # → 1（-F でも同じ）
echo "あいう" | LC_ALL=C.UTF-8 grep -cw "いう"  # → 0, 終了の値 1
echo "あいう" | rg -cw "いう"                   # → 何も出ず、終了の値 1

echo "Ａ" | grep -ci "ａ"                       # → 0, 終了の値 1（偽の「無い」。全角の英字）
echo "Ａ" | grep -ciF "ａ"                      # → 0（-F でも同じ）
echo "Ａ" | LC_ALL=C.UTF-8 grep -ci "ａ"        # → 1
echo "Ω" | grep -ci "ω"                         # → 0（UTF-8 なら 1）
echo "Ａ" | rg -ci "ａ"                         # → 1
```

`-w`（と `\<`・`\>`・`\b`）は、C ロケールでは 0x80 以上のバイトを語の字と見ないので、日本語の字の並びの途中でも語の切れ目とみなす。`-i` は、C ロケールでは ASCII の外の大文字と小文字を同じに扱わない。全角の英字（ＡＢＣ）は日本語の文に普通に出るので、`-i` の偽の「無い」は現に起こりうる。

文書の「C ロケールのままでも正しく一致するのは…である」は選択肢に触れていないので、`grep -F -w` や `grep -i` を安全と読める。直し方の案: 安全な範囲の文に「`-w`・`-i`（と `\<`・`\b`）を付けない」を加えるか、例を1組（`-w` の偽の「有る」）足して範囲の外だと示す。ripgrep が両方とも正しく扱うことも、Grep の道具の段に一言で添えられる。

### 2. 【中】「日本語は BMP 内のため、`String.length` = 文字数」は誤り

「数える」の節の文（今回の差分で書き直された行）。常用漢字の「𠮟」（U+20B9F）は BMP の外で、`'𠮟'.length` は 2、`[...'𠮟'].length` は 1（`node -e` で確かめた）。人名や地名の「𩸽」「𠮷」なども同じ。「（サロゲートペア外）」の括弧書きはこの例外を言い当てておらず、本文は「日本語は BMP 内」と言い切っている。

直し方の案: 「かなと常用漢字のほとんどは BMP 内で `String.length` が文字数と一致するが、𠮟（U+20B9F）などは 2 になる。字の数が要るなら `[...s].length`」のように、UI が見る値（`String.length`）と字の数を分けて書く。あわせて「特に UI の表示幅・折り返し見積もり」は、`String.length` が全角と半角を同じ 1 に数えるので表示幅そのものではない。「UI の実装と同じ数え方で測る」の趣旨に言い換えるとよい。

### 3. 【軽微】`cut -c1-4` の出力のバイト

根拠に「`od -An -tx1` で `cut -c1-4` の出力が … `e3 81 82 e3` である」とあるが、実際の出力は `e3 81 82 e3 0a`（`cut` は行の終わりに改行を足す）。`head -c 4` は `e3 81 82 e3` で、例のコメントの「同じ」も改行の1バイトだけ違う。「`e3 81 82 e3` と改行」とするか、「切った中身が `e3 81 82 e3`」と書く。

### 4. 【軽微】1文字の単位の並べ方に `\?`・`\{n\}` が抜けている

冒頭の文は「日本語の字の後ろの `*`・`\+` はその字の最後の1バイトにだけ掛かる」と並べるが、`\?` と `\{n,m\}` も同じ（第1回で挙げた）。「それ以外の型」で `LC_ALL=C.UTF-8` に寄せているので実害は小さいが、「すべて」と言う文の列挙として足す。
