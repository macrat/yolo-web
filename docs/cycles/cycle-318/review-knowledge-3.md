## 指摘

### 1. 【重要】決まりを守っても `-w` は日本語で偽の「無い」を出す。`-w` の例が、UTF-8 の結果を正しいものとして教えている

3つ目の例は、C ロケールの `-w` を「偽の「有る」」、`LC_ALL=C.UTF-8` の `-w` を正しい答えとして並べている。しかし UTF-8 では、かなと漢字はどれも語の字なので、日本語の文の中の語は前後の字とつながって切れ目が無く、`-w` はほとんど一致しなくなる。

```sh
echo "東京に行く" | LC_ALL=C.UTF-8 grep -cw "東京"  # → 0, 終了の値 1（偽の「無い」）
echo "東京に行く" | rg -cw "東京"                   # → 何も出ず、終了の値 1（Grep の道具も同じ）
echo "東京に行く" | grep -cw "東京"                 # → 1（C ロケールでは、たまたま一致する）
```

読み手が決まりどおり `LC_ALL=C.UTF-8` を付け、「語として使われていないか」を `-w` で確かめると、「東京に行く」の行を見落とし、偽の「無い」をそのまま主張する。依頼の「決まりを守れば外れる場面が残らないか」に当たる穴である。

直し方の案: `-w`（と `\b`・`\<`・`\>`）は日本語にはどのロケール・どの道具でも使えない、と決まりの側に書く。例は「C ロケールでは日本語の字の並びの途中を切れ目と見る、UTF-8 では日本語の並び全体を1語と見る（`東京に行く` に `-w 東京` が一致しない）」と、両方とも当てにならないことが分かる形に直す。3つの例を外れ方の違う3つに絞った方針は保てる（`-w` を例から抜いて決まりの一文にするか、`-w` の例を「どちらも使えない」例に替える）。71行目の「`grep -F` で固定の文字列を探すときも `-w` や `-i` を付ければ外れる」も、`-w` は UTF-8 でも外れるので、`-i`（C ロケールでは全角の英字の大小を同じに見ない）だけを挙げる形に揃える。

### 2. 【中】Grep の道具（ripgrep）は .gitignore に載るファイルと NUL を含むファイルを見ず、`rg` コマンドはさらに隠しファイルを見ない

決まりは「「無い」を確かめるときは … Grep の道具（ripgrep）を使う」で、73行目は `rg` コマンドの結果も同じものとして並べている。ロケールの外れはないが、探す範囲が grep と違い、エラーを出さずに外れる。

- 試しの git の木で `.gitignore` に載せたディレクトリの「あいう。」は、`rg -c "あいう" .` でも Grep の道具でも見つからなかった（終了の値 1 / No matches found）。
- 隠しディレクトリ（`.hid/`）の中のファイルは、Grep の道具は見つけたが、`rg -c "あいう" h` は見つけなかった（終了の値 1）。このリポジトリでは `.claude/`・`.github/` がこれに当たる。
- NUL のバイトを含むファイルは、ディレクトリを探す `rg` も Grep の道具も黙って飛ばした（ファイルを名指しすると 1）。

日常の「無い」の確かめでは `node_modules`・`.next` を除けるので役に立つ面もあるが、読み手が Bash から `rg` で `.claude/` の skill やルールを含めて「無い」を言うと外れる。直し方の案: Grep の道具の段に「Grep の道具は .gitignore に載るファイルを、`rg` コマンドはそれに加えて隠しファイル（`.claude/`・`.github/` など）も見ないので、そこも含めて「無い」を言うときは `rg --hidden`（要れば `--no-ignore`）か `LC_ALL=C.UTF-8 grep -r` を使う」と一文添える。

### 3. 【軽微】`binary file matches` のふるまいの書き方が実際と少し違う

75行目は「一致した行に UTF-8 として壊れたバイトがあると、その行の代わりに `binary file matches` を出す」とある。実際は次のとおりだった。

```sh
printf 'あいう。1\nあいう。\377\nあいう。3\nあいう。4\377\nあいう。5\n' > b4.txt
LC_ALL=C.UTF-8 grep -n "あいう" b4.txt
# 1:あいう。1
# 3:あいう。3
# 5:あいう。5
# grep: b4.txt: binary file matches   ← 標準エラーに、ファイルごとに1度、最後に
```

壊れた行は「その行の代わりに」その場所へ出るのではなく、黙って抜け、知らせはファイルごとに1度、標準エラーへ最後に出る（`2>/dev/null` を付けると抜けたことに気づけない）。「壊れたバイトのある一致行は出ず、ファイルごとに1度、標準エラーに `grep: <ファイル名>: binary file matches` を出す（ほかの一致行は出る。終了の値は 0 で `-c`・`-l` は正しい）」と書くと、読み手が行の抜けに気づける。

### 4. 【軽微】「和文の記号は先頭のバイトがどれも E3」は言い過ぎ

71行目。句読点・かぎ括弧・中点・長音（U+3000〜30FF）は E3 だが、全角の（）！？は U+FF00 台で `ef bc 88`・`ef bc 81`・`ef bc 9f`（`printf %s "（！？・ー" | od -An -tx1` で確かめた）。「ひらがな・カタカナと、句読点・かぎ括弧などの和文の記号は」のように範囲を正す。
