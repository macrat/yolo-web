## 指摘

### 1. 【重要】「角括弧を使わない形は C ロケールでも正しく一致する」は誤りで、勧める回避策が偽の「無い」を生む

C ロケールの grep では、角括弧だけでなく、1文字を単位にするすべての書き方がバイトに掛かる。この環境で次を確かめた。

```sh
echo "あいう。" | grep -c "あ.う"          # → 0, 終了の値 1（偽の「無い」。. は1バイト）
echo "あ"       | grep -c "^.$"            # → 0, 終了の値 1（偽の「無い」）
echo "あ"       | grep -c "^...$"          # → 1（偽の「有る」）
echo "あいう"   | grep -c "^.\{3\}$"       # → 0, 終了の値 1
echo "あいいう" | grep -o "あい\+"         # → あい（\+ が「い」の最後の1バイトにだけ掛かり、「あいい」にならない）
echo "あいいう" | grep -o "あい*"          # → あい（同じ）
```

文書は「日本語を含む型で探すときは `LC_ALL=C.UTF-8` を付けるか、角括弧を使わない形にする」と、角括弧を外すことを `LC_ALL=C.UTF-8` と並ぶ回避策として勧めている。これに従って `[^。]` を `.` や `.\{n\}` に書き換えた読み手は、同じ偽の「無い」を受け取る。この節の目的（「無い」を確かめる場面で正しく動ける）を直接損なうので、直す必要がある。

直し方の案:

- 節の題と冒頭を「grep の角括弧」から「grep の1文字の単位」のように広げ、角括弧・`.`・日本語の字の後ろの `*`・`\+`・`?`・`\{n\}` がどれもバイトに掛かることを書く。上の再現の何本かを例に入れる。
- C ロケールのまま安全なのは、固定の文字列（`grep -F`）と、日本語の字の並びをそのまま書いて `.*` でつなぐだけの型だと、範囲を正しく狭めて書く。
- 「無い」を確かめるときの既定は `LC_ALL=C.UTF-8` を付けること、と一本にする。

### 2. Claude Code の Grep の道具（ripgrep）に触れていない

この環境で `echo "あいう。" | rg -c "あ[^。]*。"` は C ロケールのまま 1 を返した（ripgrep はロケールによらず UTF-8 で一致を取る）。エージェントが「無い」を確かめる場面の多くは、シェルの `grep` でなく Grep の道具で済み、そちらはこの落とし穴に当たらない。次の読み手が道具を選ぶ判断に直接効くので、「探す」の節に、Grep の道具（ripgrep）はロケールによらず文字で一致を取ること（実測）を1文足す。

### 3. 【軽微】`cut -c` の版の注記に、新しい版で挙動が変わることを添える

GNU coreutils 9.11（2026年4月）で `cut -c` はマルチバイトの字を扱うようになり、`-b` の別名でなくなった（[coreutils-9.11 の告知](https://lists.gnu.org/archive/html/info-gnu/2026-04/msg00006.html)、[linuxiac の記事](https://linuxiac.com/gnu-coreutils-9-11-released-with-speed-boosts-multi-byte-character-support/)）。文書は「9.4 の」と版を書いているので誤りではないが、環境が新しい版になると「`LC_ALL=C.UTF-8` を付けてもバイトで切る」は成り立たなくなる。読み手が版を確かめる手がかりとして、「9.11 からは UTF-8 のロケールで `-c` が文字で切る（C ロケールではバイトのまま）」を添えるとよい。あわせて「`head -c` は名前どおり」は、`-c` を chars と読む人には逆の意味になるので、「`head -c`（`--bytes`）はいつもバイトで数える」のように書く。

### 4. 【軽微】根拠の置き方がほかの知見の文書とそろっておらず、冒頭と末尾で同じ経緯を二度書いている

ほかの `docs/knowledge/*.md`（browser-layout-and-scrolling・clipboard-and-copy・codegen-patterns・dependency-security・input-events-and-guards）は、各節の末尾に「根拠」を置く。この文書は3つの節の根拠を末尾の1段にまとめ、しかもその段が「探す」の節の直後に区切りなく続くので、「探す」だけの根拠に読める。冒頭の「知見は cycle-216（数える）と cycle-318（切る・探す）の実測に基づき、数えるほうは cycle-316 に…」も末尾の根拠と同じことを繰り返している。冒頭は扱う範囲（数える・切る・探す、どれもバイトを単位に黙って誤る）だけにし、根拠は「数える」「切る」「探す」の各節の末尾に分けて置く。「cycle-318 に、角括弧に日本語を入れた grep が一致する行を見落として…ことから」の経緯は、根拠に1句あるのは他文書の書き方と同程度で許されるが、詳しい経緯は cycle-318 の記録に任せてよい。
