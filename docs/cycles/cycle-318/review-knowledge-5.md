## 指摘

### 1. 【中】決まり3の `grep -ra` を主の木で走らせると、`.git` と担当の木の中まで探すので、偽の「有る」が出る

決まり3は「`.gitignore` に載るファイルと NUL を含むファイルまで含めて「無い」を言うときは、`LC_ALL=C.UTF-8 grep -ra` を使う」で、探す範囲の節も「どのファイルも終わりまで探す」とだけ書く。一致が出れば、読み手は「無い」ではない、つまり「有る」と読む。ところが `grep -ra .` は `.gitignore` に載るファイルだけでなく、`.git`（コミットのメッセージ・reflog）、`.claude/worktrees/`（ほかの担当の木。主の木にはまだ無い変更）、`.next`（前のビルドの出力。消した文言が残る）、`node_modules`、`tmp/` も探す。主の木での実測は次のとおり。

```sh
cd /home/user/yolo-web   # 主の木
LC_ALL=C.UTF-8 grep -rla "ほかの道具では探さない" .
# → ./.claude/worktrees/agent-ac8afdc91fb65790b/docs/knowledge/text-measurement.md
#   （主の木の text-measurement.md にはまだ無い文言。Grep の道具は .claude/worktrees/ を .gitignore で飛ばすので出さない）
LC_ALL=C.UTF-8 grep -rla "日本語を探す道具を2つに限り" .
# → ./.git/worktrees/agent-ac8afdc91fb65790b/COMMIT_EDITMSG
#   ./.git/worktrees/agent-ac8afdc91fb65790b/logs/HEAD
#   ./.git/logs/refs/heads/worktree-agent-ac8afdc91fb65790b
#   （コミットのメッセージにしか無い文言）
```

このリポジトリでは、サイクル中は主の木の下に担当の木があり、探す文言はそれを足したり消したりしたコミットのメッセージに載りやすいので、珍しい場面ではない。文書の目的（偽の「有る」を出さない）に直に掛かる。逆に、決まり1の Grep の道具はこれらを飛ばすので、この偽の「有る」は決まり3を使ったときにだけ起きる。

直し方の案: 決まり3か探す範囲の節に、`grep -ra` は `.git`・`.claude/worktrees/`・`.next`・`node_modules` まで探すので、一致が出たらパスを見て、どの木・どのファイルの一致かを確かめる（あるいは `--exclude-dir=.git --exclude-dir=worktrees` などで除く）ことを短く書く。除く書き方を決まりにするなら、除いたディレクトリが偽の「無い」を生まないことも合わせて確かめてから書く。上の2本を走らせてから書く。

## 参考（直さなくてよい）

- 決まり1の根拠（`git grep`・`sed`・`awk` の5本）は「C ロケールの grep の外れ方」の小見出しの根拠の中にある。決まり1を読んで「なぜ `LC_ALL=C.UTF-8 git grep` も使わないのか」を探す読み手は、grep の小見出しの中までは見に行きにくい。なお `LC_ALL=C.UTF-8` の `git grep` は、角括弧・`-i`（全角）では正しく一致し、外れるのは `-w` だけだった。道具を2つに絞るのは決まりを簡単に保つための選択として妥当で、直す必要はない。
