## 指摘

1. **24行の取り方では、開いたタブの行き先の URL が取れない。**
   - 24行は「開いたタブは、ブラウザの文脈の `page` の出来事で拾い、行き先の URL をその押しの落ちた先に添えて記録し、読み込みを待たずに閉じる（ネットワークを止めているので、開いたタブは描かれない）」と書く。
   - 上の表の試しのとおり、ネットワークを止めた文脈では、`page` の出来事は止めた遷移が失敗してから来て、そのタブの `page.url()` は `chrome-error://chromewebdata/` になる。文のとおりに `page.url()` を記録した道具では、X と LINE とはてなの共有がどれも同じ値になり、どこへ開いたかが残らない。別の担当は `request` の出来事か `route` の受け手から URL を取るので、2人が組めば違う記録になる。
   - 括弧の「開いたタブは描かれない」も事実と違う。開いたタブには Chromium のエラーのページが描かれる（`chrome-error://chromewebdata/`）。
   - **直し方**: 例えば「開いたタブの行き先の URL は、そのタブの最初の遷移の要求の URL（`context` の `request` の出来事で、要求の `frame().page()` が開いたタブであるもの）で取り、その押しの落ちた先に添えて記録する。開いたタブは `page` の出来事で拾い、すぐに閉じる。ネットワークを止めているので、開いたタブの `page.url()` は行き先でなくエラーのページになる」とする。`route` の受け手から取る形でも、`addInitScript` で `window.open` の引数を記録する形でもよいが、どれか1つに決めて書く。
