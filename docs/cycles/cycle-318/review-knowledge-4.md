## 指摘

### 1. 【中】決まり1は `grep` にしか言っておらず、`git grep`・`sed`・`awk` で日本語の型を探す読み手は、まだ偽の「無い」に当たる。とくに awk は決まりどおり `LC_ALL=C.UTF-8` を付けても外れる

依頼の「3つの決まりを守った読み手が、まだ偽の結果に当たる場面が残らないか」に当たる。決まり1は「`grep` に `LC_ALL=C.UTF-8` を付けるか、Grep の道具を使う」で、節の題も「探す: grep」なので、ほかのコマンドで探す読み手には届かない。実測は次のとおり（行は「あいう。」）。

```sh
git grep -c "あ[^。]*。"                 # → 出力なし, 終了の値 1（偽の「無い」）
LC_ALL=C.UTF-8 git grep -c "あ[^。]*。"  # → 1
git grep -P -c "あ.う"                   # → 出力なし, 終了の値 1
sed -n "/あ.う/p"                        # → 出力なし（C ロケール）
LC_ALL=C.UTF-8 sed -n "/あ.う/p"         # → あいう。
awk "/あ[^。]*。/"                       # → 出力なし
LC_ALL=C.UTF-8 awk "/あ.う/"             # → 出力なし（mawk はロケールによらずバイトで動く）
LC_ALL=C.UTF-8 git grep -cw 東京         # → 1（git grep の -w は UTF-8 でも ASCII だけを語の字と見る）
```

`git grep` は追跡しているファイルだけを探すので「リポジトリに無い」を言うのに使われやすく、awk は「数える」の節で `LC_ALL=C.UTF-8` を付けてもバイトで動くと書いてあるのに、探すときの外れには触れていない。

直し方の案: 決まり1を grep に限らない形にする。たとえば「日本語を含む正規表現は、`LC_ALL=C.UTF-8` を付けた `grep`・`git grep`・`sed` か、Grep の道具・`rg` で使う。awk（mawk）はロケールによらずバイトで動くので、日本語の型には使わない」。節の題も「探す」の範囲に合わせる。上の再現を走らせてから書く。

### 2. 【中】NUL を含むファイルのふるまいが実際と違う（grep は「壊れた UTF-8 と同じ」ではない。rg と Grep の道具は「探さない」のではなく NUL で探すのをやめる）

(a) 「探す範囲」の3つ目は、NUL を含むファイルを `LC_ALL=C.UTF-8 grep -r` で探すと「扱いは次の「壊れた UTF-8 を含むファイル」と同じ」と書くが、違う。壊れた UTF-8 では壊れた行だけが抜けてほかの一致行は出るのに、NUL では NUL を読んだところから後の一致行が、NUL の無い行も含めて全部抜ける。

```sh
printf '\0x\nあいう。1\nあいう。2\n' > nul2.txt
LC_ALL=C.UTF-8 grep -n "あいう" nul2.txt   # → 一致行は1つも出ず、標準エラーに binary file matches だけ（終了の値 0、-c は 2）
```

約5000行の一致行のあとに NUL と「あいう。end」を置いた大きいファイルでは、`-n` は 4485 行目まで出して止まり、知らせを出した（`-c` は 5001 で正しい）。

(b) 「Grep の道具は … NUL のバイトを含むファイルを探さない」「`rg` コマンドは … NUL を含むファイルは `rg -uuu` まで付けないと探さない」も、正しくは「NUL を見つけたところで、そのファイルを探すのをやめる」である。上の大きいファイルで、Grep の道具の files_with_matches はそのファイルを挙げたが、count は挙げず、NUL より後の「あいう。end」は Grep の道具でも `rg -c` でも `rg --hidden --no-ignore -c` でも見つからなかった（終了の値 1）。読み手は「一覧に出たファイルは全部探された」と思い、NUL より後を見落とす。また `rg -uuu` は NUL のファイルの一致を `-l`・`-c` では正しく返すが、行を出す形では `binary file matches (found "\0" byte around offset N)` だけを出す。

直し方の案: 「探す範囲」の箇条を、「`rg`（と Grep の道具）は NUL を見つけるとそのファイルを探すのをやめる（小さいファイルは丸ごと飛び、大きいファイルは NUL より前の一致だけが出る）」「`rg -uuu` と `LC_ALL=C.UTF-8 grep -r` は NUL のファイルも終わりまで探すが、一致の行の代わりに `binary file matches` を出すので、行を見るには `-a` を付ける」と、実際のふるまいに合わせる。「壊れた UTF-8」の節と同じ扱いだとは書かない。上の2つのファイルで grep・rg・Grep の道具を走らせてから書く。

### 3. 【軽微】冒頭の文と表題が、いまの中身の一部に合わない

冒頭は「どれも、コマンドが文字ではなくバイトを単位にして動き、エラーを出さずに誤った結果を返す」、表題は「C ロケールで日本語テキストを扱うときの注意事項」だが、UTF-8 での `-w`（語の切れ目）、rg と Grep の道具の探す範囲、合成済みの字と分けた字、`String.length` と BMP の外の字は、バイトの単位の話でも C ロケールの話でもない。冒頭の「どれも」が偽になり、読み手は「`LC_ALL=C.UTF-8` を付ければ全部片づく」と読みやすい。表題を「シェルで日本語テキストを数える・切る・探すときの注意事項」のように広げ、冒頭は「多くはバイトを単位にして動くことから起き、どれもエラーを出さずに誤った結果を返す」のように中身に合わせる。
