# ADR009: 新しいコンセプトへのサイト全体の作り直し

- 状態: 実験中（open）
- 起票日: 2026-09-23 ／ 出荷日: 未（最初の出荷は B-754 サイトデザインの刷新）
- 決定・仮説:
  - **決定**: cycle-315 で確定した `docs/site-concept.md` と `DESIGN.md` に合わせて、サイト全体を作り直す。対象はデザイン（B-754）・about（B-746）・ツール（B-566）・辞典（B-564）・診断/ゲーム（B-756）。**ADR001 が担っていた「あらゆるものを扱うサイトへの方向転換」を引き継ぐ。**
  - **来訪者価値の仮説**: 定番の作り直しから降り、「他では見つからないもの」だけを残すと、来訪者が受け取る価値が上がり、結果として読まれる数が増える。
  - **賭けの中身**: いまの検索流入の相当部分は、定番のツールと参照型の辞典が集めている。コンセプトはそれらを「他所の土俵」と呼び、引き上げの対象に含める。**引き上げれば、その分の表示とクリックは確実に減る。** 賭けは「減った分を超えて、残したものと新しく作るものが取り返す」ことに置く。取り返せなければ負けである。
- 根拠:
  - `docs/site-concept.md`（確定したコンセプト。とくに「定番のものを、より良く作り直そうとする。それは他所の土俵である」）
  - `DESIGN.md`（コンセプトから導出したデザインの定義）
  - ADR001 の観測（2026-07-29）: 辞典は表示が約3.5倍に増えても CTR 0.08% で据え置き＝参照型の弱さ。play は clk/日・CTR・順位のいずれも上向き。
- 観測手段と評価窓:
  - **Search Console 週次・カテゴリ別**（tools / dictionary / play / blog）。基線＝最初の出荷の直前28日。読み始め＝出荷+2週、結論＝出荷+3ヶ月窓。反応は約3ヶ月遅れる。
  - **サイト合計だけを見ない。** 引き上げと新設が同時に動くため、カテゴリに分けないと相殺して何も読めなくなる。
  - GA4: 来訪者が最後まで受け取ったかを見る。小 n と計測欠落を常に疑い、単独の kill 根拠にしない。
    - **character-personality の結果の保存と共有の率**: T4-5 で解き終えた画面に結果の説明を先に置き、保存と共有のボタンが 375px の最初の画面から出たことで、保存と共有が減っていないかを見る。
      - 分子＝解き終えた画面の結果の保存と共有。`save`（`surface="fuda"`）と、`share` のうち `content_id="quiz-character-personality"` で `surface` が `fuda`・`invite`・`text` のもの。どれも `page_location` のパスが `/play/character-personality` のものだけを数え、結果のページ（`/play/character-personality/result/…`）から送られたものは入れない。ページの共有も入れない。
      - 分母＝結果に着いた回数（`level_end`。解き終えた画面でだけ送られる）。
      - 仮の値＝2026-08-29〜09-25 の28日で 44 ÷ 1,181 = 3.7%（札の保存 34・札の共有 9・招待 0・文の共有 1）。出荷の前の値は、Search Console の基線と同じく出荷の直前28日で T10 に取り直し、この仮の値を置き換える。出荷の日からの28日と比べる。
      - 分子は40件台なので、方向だけを読み、率の小さな差を損や得と断定しない。
      - 札の保存と札の共有の内訳は、T9 で iOS の Safari の「画像を保存」が共有シートへ進むと分かれば、保存のつもりの操作が `share`（fuda）に数えられていることになるので、その結果に従って読む（分子の合計は変わらない）。
    - **ページの共有（「この診断を勧める」）の回数**は、率とは別の数として読む。数え方は `share` のうち `content_type="quiz"`・接頭辞の無い `content_id`（slug）・`surface` 無し。仮の値＝同じ28日で character-personality 3回で、率と同じく T10 に出荷の直前28日で取り直す。出荷の日からの28日と比べる。1回の違いで向きが変わる数なので、0 になったかどうかだけを見る。
    - 出荷の日から計測の出方が変わるもの（前後の差を来訪者の変化と読まない）:
      - ゲームの `content_end` は遊び終えた回を開き直したときに送らなくなるので、前より少なく出うる。
      - `share`: ゲームの結果は、共有シートを閉じただけの回とコピーに失敗した回を送らなくなり（診断・占いと同じ数え方）、`web_share` と `clipboard` が前より少なく出る。
      - `share`: ゲームの結果に LINE を置いたので、ゲームの `line` が新しく出る。
      - `share`: クリップボードの API に拒まれる端末でも代わりの写し方で写せるようになったので、どの面でも `clipboard` が前より多く出うる。
      - `share`: 招待（surface `invite`）は、共有シートを閉じただけの回にコピーへ進まなくなるので、Android などで閉じた回に送られていた `clipboard` が減る。
      - `share`: イロドリの結果の共有は `surface="text"` を持つようになり、surface で見分けられる。
      - 送る値の形（contentType・contentId・surface）は、イロドリの `surface` のほかは前と同じ。
  - 時間軸の before/after は方向読みのみ。上げ下げとも単一原因に断定しない。
- 撤退基準:
  - 作り直しは段階的に出るため、全体を戻す基準は置かない。**カテゴリごとの修復トリップワイヤ**を置く——あるカテゴリの検索クリックが出荷+4週で基線の50%を割ったら、そのカテゴリの引き上げ判断を止め、個別修復に回す。
  - **発火線の具体値は、基線を取った時点で確定してここに追記する。** 基線が無いまま数値を置かない。
