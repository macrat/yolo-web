## 決定

**本文中に置く中身のうち、読む幅（`--measure`）に収まらないもの（表・コードブロック・図など）は、読む幅の外へはみ出させない。その面の中に閉じ込め、横スクロールで到達できるようにし、切れていることを言葉で知らせる。**

伴う3つの具体:

| 決めたこと                                                                   | 理由                                                                                                                                           |
| ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **はみ出しは読む幅の外へ流さない**                                           | 流すと `html, body { overflow-x: clip }` に食われて**到達できなくなる**。実測で 280px の68表が該当した。1280px では目次の列に45px 重なっていた |
| **切れていることは、罫や影ではなく言葉で知らせる**                           | DESIGN.md §1「装飾は枠・罫・言葉まで」／§4「影は原則使わない」。**実際に溢れた面にだけ**出す（出しっぱなしは嘘の案内になる）                   |
| **潰れない下限（床）は、面全体ではなく**要素ごと（表なら列ごと）**に決める** | 「面全体が収まるか」で出し分けると、**見積もり誤差数pxで面全体の指定が反転する崖**ができる。要素ごとなら誤差の影響はその要素に閉じる           |

## 根拠——なぜ「収まるように潰す」ではだめか

**日本語はどこでも改行できるので、列の min-content が1文字になる。** ブラウザの自動レイアウトは `width: 100%` に収めるため列をそこまで潰し、「ラ／イ／ト／の／タ／ブ／地」と1文字ずつ縦に折れる。**英語では起きない**（単語で切れるので min-content は単語幅）。

実測（60記事203表・数え方は `docs/cycles/cycle-302/index.md` の G 節に明記）:

| 幅     | 2文字/行以下のセル |
| ------ | ------------------ |
| 280px  | 931 → **0**        |
| 360px  | 561 → **0**        |
| 1280px | 51 → **0**         |

## 「床を面全体で出し分ける」を試して捨てた記録（この決定の中核）

**面全体で出し分ける方式は、実際に作って全数測定してから捨てた。** 捨てた理由が次の決定に効くので残す。

- 見積もりが実測を**下回った表が 36/203**（最大 −13px）→ 床が外れ、**23表すべてで折り返しが再発**（3表は1文字/行）。
- 見積もりが**上回った表が6個** → 収まる表が溢れる。**帯が 371〜404px にかかり、DESIGN.md §10 の実装基準 375px と iPhone 12〜15 の 390px を直撃**した。
- 例外扱いしたはずのカレンダーが **320px で外れた**（`**1**` の強調記号を文字数に数えていたため）。

**一つ塞ぐたびに次の穴が出る形**だったので、較正を重ねず前提を変えた。**列ごとなら、誤差の影響は「1列の床が数px ずれる」に縮む。**

同様に測って捨てた案: `width: max-content` に委ねる（列配分が auto レイアウト任せになり2文字/行以下が 280px で247残る）／一律の床（カレンダーが 280px で714pxに膨張）／文字数の閾値（同じ文字数でも列数と字幅で必要幅が変わる）／端のフェード（§4 に反する）。

## 払っている代償（隠さない）

- **多列の表が、広い画面で最終列を失う。** `nextjs-directory-architecture#3` が 1280px で +64px・高さ +114px。**変更前は一望できていた。** 読む列と目次の間は32px しかなく、表を広げると目次に食い込む（この決定が直した45px 重なりの再現）ので、**目次の配置を変えない限り解けない** → B-633。
- **狭い画面で欧文語が1文字残して割れる**（`Unauthorize|d`）。外すと 360px で8表が 23〜139px 溢れに転じるため、取引として引き受けた。
- **`container-type: inline-size` 非対応環境では床が効かない**（変更前の状態に戻るだけ）。
- **字幅の見積もりは計測環境依存**。実ユーザーのフォントが違えば床の出し分けは動きうる。

`.prose pre`（コードブロック。溢れの有無に関わらず `tabindex` が焼かれ、役割も名前も無い）と `src/tools/markdown-preview/` のプレビュー表 → **B-631** で棚卸しする。

## この決定を守る仕組み

- `tests/e2e/blog-table-min-width-floor.mjs`（18通り）。**列ごとの床は単体テストでは原理的に見られない**ので、これが唯一の自動の歯止め。
- `.claude/hooks/pre-push-check.sh` が build のあとに本番サーバを立てて実行する。**空きポートを探してから起動する**——使用中のポートで起動に失敗すると、そこに居座っている別の（古い）ビルドを測って無関係な PASS / FAIL を返す（cycle-302 で実際に起きた）。
- **測れていないもの**: `overflow-x: auto` そのもの。指標が `scrollWidth - clientWidth` で `auto` と `visible` を区別できないため、この形では守れない。**設計全体がこの一行に乗っている。**
