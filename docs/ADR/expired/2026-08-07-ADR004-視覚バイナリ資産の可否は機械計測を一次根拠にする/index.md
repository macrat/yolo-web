## 決定

**favicon・apple-touch-icon など、CSS も HTML も持たないバイナリの視覚資産について、合否の一次根拠を「見て読めるか」から `scripts/icon-metrics.ts` の機械計測へ移す。** 判定者（人でも LLM でも）の言語化は**必要条件**として残すが、それだけでは合格にしない。

測る量と、それが捕まえる失敗:

| 量                         | 捕まえる失敗                                                                                       |
| -------------------------- | -------------------------------------------------------------------------------------------------- |
| 地ごとの**最大連結可視塊** | 地に溶ける。**画素数だけでは足りない**——同じ画素数でも、まとまっていれば読め、散っていれば読めない |
| **ストローク充実度**       | 細さで消える（コントラストとは独立の機序）                                                         |
| 内接円の外にある図の割合   | 円マスクでの欠損（32px 以上にのみ課す）                                                            |
| **有彩色要素の CR**        | アクセントが読めない。**ページの地ではなくアイコン自身の地**と比べる                               |
| **青みの画素数**           | DESIGN §8-1 の禁止色の残存                                                                         |
| 透過の有無                 | apple-touch の透過（iOS が黒く合成する）                                                           |

**各地に対する可視性は、アイコンをその地の上に合成してから測る**（透過を無視すると、完全透過の画素がその RGB で「見えている」と数えられ、**安全でない方向に誤って合格を返す**）。

## 根拠——なぜ目視を一次根拠にできないか

**同じ対照（cycle-299 が実際に出荷した壊れた favicon）を、3人の観測者のうち2人が落とせなかった。**

| 観測者                     | 提示の仕方                                     | 結果                       |
| -------------------------- | ---------------------------------------------- | -------------------------- |
| cycle-302 3巡目レビュアー  | 16×16 を単体／タブストリップ状の地に合成       | 「y ＋赤い点」と読めた     |
| cycle-302 G-a のレビュアー | 4地色×2サイズ×円マスク有無を並べ、他候補と比較 | 「字が読めない」と落とせた |
| cycle-302 4巡目レビュアー  | 16×16 を単体／1280×300 の実面相当に合成        | 「y·」と読めた             |

**「LLM が等倍のラスタを見て読めるか」は、人間の 16px 可読性の代理に原理的にならない。** 人間の可読は画素の物理サイズと視距離という光学的限界で決まるが、LLM は画素配列をそのまま読む。提示の作り方で結果が反転する。

cycle-299 はこの領域で2度失敗し、成果物ゼロで終わっている（[incident-1](../../../cycles/cycle-299/incident-1.md)・[incident-2](../../../cycles/cycle-299/incident-2.md)）。

## しきい値の決め方（この決定の中核）

**しきい値は、落ちるべき実例と通るべき実例の**両方**を用意して、その間に置く。片側だけで決めない。**

- **落ちるべき側は「最も通りやすい（最大の）値」**を下限に使う。最小を使うと、落とすべき実例が複数あるとき1件しか担保できない。
- **アンカーは検証対象そのものにしない**（循環になる）。人間の観測が付いている実例を使う。
- **較正が要求しているのは「帯の中にあること」で、帯の中のどこかではない。帯の内側での変更はテストで検出されない**——それは較正が要求していないからである。

本サイトの固定点は、cycle-299 が出荷した favicon（commit `fd088fa1`）について記録された人間の観測「**y の下半分が切れて v に見える／細すぎる**」である。`scripts/__tests__/icon-metrics.test.ts` がこれを機械的に守る。

## 較正できていないもの（隠さない）

| しきい値                 | 状態                                                                         |
| ------------------------ | ---------------------------------------------------------------------------- |
| 最大連結可視塊           | **両側較正済み**（帯 17〜21）                                                |
| ストローク充実度         | **両側較正済み**（帯 0.16〜0.22）                                            |
| 円マスク上限             | **片側のみ**（通すべき側が全部 0.0% なので、実質どこに置いてもテストは通る） |
| 図の色距離・有彩色の定義 | **未較正**（「図」の定義そのものを決める最上流の値）                         |

## この計器が測れないこと

- **「何と読めるか」は測れない。** 測っているのは「消えていないこと」である。
- 対照は**失敗軸の遠い端しか持たず、境界性能は未校正**。
- 縮小レンダリング経路（32px 層が 16 CSS px 枠へ縮小される面）を見ていない。
- 隣接アイコンとの弁別、ICO の層ごとに別の図像が入っている場合。

**したがって、この計器を通ることは「壊れていない」の担保であって、「良い」の担保ではない。** 意匠の良し悪しは依然として設計判断の領域にある。

## この決定に伴って入れた歯止め

- `src/lib/utsuwaHex.ts` の **`ACCENT_ON_DARK`**（`#e87a65`）＋ `globals.css` の `:root.dark --accent` との乖離ガード。**ライト固定の `ACCENT` を暗い地の資産に当てる**という失敗（cycle-302 の E0 初版で実際に起き、旧ブランドの青よりコントラストが低くなった）をコードで止める。
- `.claude/skills/take-screenshot/SKILL.md` に、画像資産の例外として「可否は実面・実寸で判定し、**拡大は同定の補助であって可否の根拠にしない**」を追加。スキル本体は「拡大して見た方が適切」と書いており、視覚レビュアーが矛盾した指示を受けていた。

## なぜ観測を伴う「賭け」として起票しないか

cycle-302 が出荷した E0（禁止色の除去）の効果は、**このサイトの規模では測れない**。検索結果からのクリックは27日で 959 件で、favicon の寄与を分離できる母集団ではない。**測れないものに観測窓を設けて「観測した」と記録するほうが害が大きい**（AP-P31）。出荷後に確認するのは「新しいアイコンが検索結果に実際に表示されているか」という事実だけで、それは B-629 で扱う。
