# yolos.net サイトコンセプト

## この文書の射程

コンテンツについて「追加すべきか」「やめるべきか」「どう作るべきか」に迷ったとき、判断の基準として引く。
ここに具体的なコンテンツや計画は書かない。**この文書の規則はサイトの中身と見た目に向けたものであり、この文書自身の書き方を縛るものではない**——それは末尾の「この文書について」が定める。

## このサイトは何か

**yolos.net は、あらゆる題材で「その場でためせるもの」を作って置く場所である。**

名前が構えを表している。よろずは万事・あらゆるもの。YOLO は You Only Live Once、一度きりなんだから、やってみよう。
扱う題材を狭めず、来訪者がその場で手を動かして、自分のための結果や作ったものを持ち帰れるものを作る。

来訪者に「ここは何ができるの」と聞かれたときの答え: **「その場でためして、結果や作ったものを持ち帰れます。診断・計算・変換・あそび。」**

**運営しているのは人ではなく AI である。** 人が書いたように見せかけない。これは実験であり、内容が誤っていることがある。
そのことを隠さず、来訪者に分かる形で伝え続ける。この開示は名乗りとは別の仕事で、正直に告げるためのものであって売り文句ではない。
試しているのは運営であって、来訪者ではない。

サイト上の自己表示を書き換えるのは、実体が伴った時点である。まだ無いものを「あります」と言わない。
ただしこれは誤りの訂正を止める規則ではない。事実と食い違っている記述は、実体を待たずに直す。

## ゴール

**来訪者に最良の価値を提供することによる PV の最大化**（constitution の Goal）。
この文書のすべての規則はその手段であり、規則がゴールと衝突したら、改めるのは規則の方である。

## 何を作るか

中心にあるのは「**検索してきた人の『したい』に、関与して得られる体験・成果物で応える**」ことである。

「したい」は広く取る。試したい、作りたい、計算したい、変換したい、遊びたい、自分を知りたい。
検索の業界用語でいう取引・タスク意図に狭めない。狭めると娯楽が落ちる。

### 作るものと、作らないもの

**分ける問い: その価値は、検索結果の画面上でテキストとして配達しきれるか。**

- **配達しきれるものは作らない**（読んで終わるもの）。語義、全員に同じ静的テキスト、解説記事、検索エンジンがその場で即答する単純な計算や換算。
  来訪せずに得られてしまうため、構造的に訪問を失う。
- **来訪して関与しないと得られないものを作る**（ためして得るもの）。(a) 入力から生まれる結果、(b) 持ち帰る成果物（ファイル・スコア）、
  (c) 遊ぶ体験そのもの。(c) は全員に同じ出題でもよい。価値が問題文ではなくプレイにあるなら、配達しきれていない。
- **操作や入力を挟むこと自体は、作ってよい証明にならない。** 中身が静的に配達できるなら、入力欄を付けても読んで終わるものである。

### 作りの構造

**少数の「型」を磨き込み、その型で多くの面を作る。**
型とは体験の作り方そのもの（診断の作り、クイズの作り、変換の道具の作り）であり、面とはその型で作る個々のページである。
集中（型の品質に複利が効く）と探索（当たりを引く試行回数）を両立でき、個々の面の反応を、自サイトの少ないアクセスではなく検索という外部の大きな母集団で測れる。

- 広さは正体であって妥協ではない。扱う題材をあらかじめ狭めない。ただし広さは量の言い訳にならない。下の各条件は、広く扱う下でも変わらず適用される。
- 集中の複利は型の単位で効く。型を開きすぎればその分だけ薄まる。新しい型を開くことは、既存の型に中身を足すことより常に重い判断である。
- AI の供給力・量産力を、差別化の第一の柱にしない。それが効くのは、型の品質が確立して人が付いた後の、維持コストの優位としてだけである。

### 追加してよい条件

次をすべて満たすときだけ追加する。

1. 上の問いに合格する。
2. 実在する検索需要に応える。需要から出発し、その実在を証拠（サジェスト・供給の横並び・実測）で確かめてから作る。
   「作れるから作る」は禁じる。いま流入しているクエリを需要の全体像と混同しない。当たっているものは早咲きかもしれず、当たっていないものは遅咲きかもしれない。
3. それ単体で独立した価値を持つ。薄い面の量産は品質の憲法違反（rule 4）であり、
   同時に Google が「大量生成されたコンテンツの不正使用」として扱う範囲に正面から入る。面の数で露出を稼ぐことは、どの型でも禁じ手である。
4. 既存の型の中身として作れるか、新しい型を開くなら、集中が薄まることと保守できるかを考えたうえで明示的に判断している。
5. 下の「守るもの」に抵触しない。
6. 着手前に、いつ何で判定するかを決めてある。決めずに作り始めない。

### 賭けの枠

constitution rule 5 は多様な試みを求める。そのため、条件2（需要の実在証拠）を満たさなくても、
「役に立ちそう・楽しそう」という見立てだけで賭けとして出してよい。ただし次を守る。

- 賭けであることを事前に記録する。どんな来訪者価値の仮説に賭けたか、何を期待するか、いつ何で判定するか。事後の合理化を防ぐため、必ず事前に。
- 条件6（判定の時期と基準）は免除しない。
- 上の問い・独立した価値・守るもの・品質の各条件も免除しない。
- 賭けは原則として既存の型の中身で行う。新しい型を開く賭けは、条件4 の重い判断を免除しない。

**この枠が免除するのは需要証拠だけである。** 賭けて、結果を観測し、記録に残す。勝った賭けはコンテンツを残し、負けた賭けは見立ての精度を上げる記録を残す。

## 何をやめるか

- 判定の時期を待ってから決める。検索の反応は遅い。当サイトで観測した例では、当たった面でも順位を得たのは作成から数ヶ月後だった
  （観測できた例は少ないので、期間の目安として扱い、確定値として扱わない）。
  早く切りすぎる失敗と、惜しくて残し続ける失敗の両方を防げるのは、事前に決めた時期と基準だけである。
- 数値の基準は Search Console（表示・順位・クリック率）に置く。サイト内の即時指標（完了率・滞在）は母数が小さく判定に耐えないため、絞り込みの参考に留め、単独の削除根拠にしない。
- 外れを放置しない。低品質な面を残すことは、サイト全体の評価を下げる。判定の時期を過ぎて外れと分かったものは、直すか消す。
- 勝ち筋が出たら、探索をやめて勝ち筋に寄せる。
- 続ける理由が「もう投資したから」「愛着があるから」になっていたら、それはやめるべき合図である。
- 始める判断とやめる判断を別々に運用しない。何かを追加するとき、やめる条件も同時に決まっていなければならない。

## どう作るか

- AI の見立ては仕入れの目であって、審判ではない。「役に立ちそう・楽しそう」は作る理由にはなるが、残す理由にはならない。残すかどうかは来訪者の行動が決める。
- **品質と面白さの審判は、来訪者の行動データだけである。** 自分やレビュアーの「面白い」を判定に使わない。
  ただし行動データを読むときは、母数の小ささと計測の欠落を常に疑う。集計値の中身を確かめずに満足と読まない。
- AdSense 等の外部審査は、存続のための関門であって品質の定義ではない。審査を通すためのコンテンツ作りに滑らない。
- LLM が狙って書く面白さを、品質の前提にしない。それは大抵うまくいかない。面白さは仕組みから出す。偶発的なズレ、意外な組み合わせ、自分の入力との衝突。
  LLM の役割は、部品を大量に供給することと、検品することである。
- **来訪者の目に触れる生成物は、すべて出荷前に検証する。** 機械で検証できる題材（決定的な計算・辞書照合・解の一意性）を優先し、検証できない自由生成を大量に出荷しない。
  誤りうるものを作って出す以上、検証は正体の一部である。
- 持ち帰れる成果物を、最初から設計に入れる。SNS がリンクを抑える環境で働く拡散の形として、いまのところ他に見当たらない。
  ただし、持ち帰られた成果物が共有される記号に育つかは**まだ検証していない賭け**であり、行動データで確かめる。
- 毎日来させる仕掛け（デイリー・連続記録）は、検索で人が付いた後の装備である。先に置かない。
  後で扱うときも、目新しさが減っていくことと、最初は誰も来ないことを前提に置く。
- 増やすことは、整理する義務を伴う（rule 4 後半）。分類・回遊・見つけやすさの設計なしに面を増やさない。

### 来訪者に届く言葉

内輪の呼び名や凝った言い回しに、来訪者の理解を依存させない。平明な言葉で組む。

**「届く」は目に見えることではない。** 次の5つは、すべて来訪者に届いている。

1. 画面に表示される文字
2. スクリーンリーダーに読まれる文字列（`aria-label`・`alt`・`title`・視覚的に隠したテキスト）
3. メタデータ（ページ題・説明・共有カード・構造化データ）
4. URL のパス
5. 画像に描かれる文字（持ち帰る画像・共有カードの生成物）

**この5つのどこかに出る語は、初めて来た人に通じる言葉でなければならない。** どの語を避けるかの具体は `DESIGN.md` が列挙する。

**コードの中（部品名・変数名・コメント）は、この規則の対象外である。** 来訪者に届かないため。
ただし**新しく内輪の呼び名を増やさない**。規範が持たない語で実装が書かれている状態は、違反ではないが、次に読む人を迷わせる。

## デザインへ渡すもの

`DESIGN.md` は次を受け取る。どんな様式でそれを満たすかは `DESIGN.md` が選ぶ。

**正体から導かれるもの:**

| 正体のどこから      | 制約                                                                                                        |
| ------------------- | ----------------------------------------------------------------------------------------------------------- |
| あらゆる題材を扱う  | 題材が変わっても作りが変わらないこと。来訪者が別のサイトに来たと感じる状態を作らない                        |
| その場でためせる    | 入力と結果に最短で到達できること。待たせない、探させない、主操作を折り返しの下へ落とさない                  |
| 結果を持ち帰れる    | 成果物が単体で成立すること。サイトの文脈なしで何の結果か読み取れる                                          |
| AI が作り、誤りうる | **中身の確からしさと釣り合わない作り込みで、信頼を調達しないこと。** 組版を丁寧にすることはこれに当たらない |
| 来訪者に届く言葉    | 上の5面で、初めて来た人に通じない語を使わないこと。避ける語の具体は `DESIGN.md` が列挙する                  |

**constitution から直接来るもの**（正体からは導けない）: rule 4 から「面の数を増やす方向の設計をしない・分類と回遊を設計する」、
rule 2 から「煽らない・出し惜しみしない・偽の限定を作らない」。

**外部が決める下限**（こちらでは動かせない）: WCAG の現行勧告（本サイクル時点で 2.2）が定めるコントラスト比・文字サイズの拡大耐性・タップ標的の大きさ。
**等級を明示して引く**（AA と AAA を混同しない）。外部が決めるのは下限であって、選択ではない。

**観測から来るもの**（正体からも constitution からも導けない）: **面によってデバイスの比率が大きく違うため、単一デバイス想定をしない。**
観測が変われば、この制約も変わる。

## 守るもの

- **rule 1（法令）**: 実在するキャラクター名・作品名を返すことで検索意図を満たさない（著作権）。商標を避ける。
  実在の名前を使わずに意図を満たすには、こちらで作った名前や分類そのものに魅力があること、そして**タイトルと説明が中身と一致していること**による。
- **rule 2（害を与えない）**: 占い・鑑定の類は、断定・不安を煽ること・依存を促すことを禁じ、
  重大な人生の決断（結婚・離別・名付けの吉凶など）に関与せず、不安を残さない締めを必ず設計に入れる。
  医療・金融など重大な判断に踏み込まない。来訪者が預けたデータを、失わせない。
- **rule 3（AI であることを伝える）**: AI が運営していること、これが実験であること、内容が誤りうることを伝え続ける。
  作成者を偽ることは、検索品質評価ガイドライン §4.5.3 が最低評価の例として名指ししている（AI が作った内容に捏造した「著者」を付け、人が書いたように見せる行為）。
  **ただし rule 3 を守る理由はそこにはない。** constitution が求めているからである。外部の評価を理由に据えると、評価が変わったときに rule 3 を捨てる論理になる。
- **rule 4（量より質・探しやすく）**: 「何を作るか」「何をやめるか」「どう作るか」の各条件に接地している。
- **rule 5（多様な試み）**: 新しい試みを歓迎する。ただし賭けであることを記録し、判定の時期と基準を伴わせてから行う。

## この原則が禁じるもの

読んで終わる情報の量産。薄い面の量産。飽和した定番の語への汎用的な再実装。毎日来させる仕掛けを先に置く設計。
LLM のウィットに頼る品質設計。実在のキャラクター名で検索意図を満たすこと。
**「作れるから作る」**（来訪者価値の見立てなく、作れることを理由に作ること。見立てに基づく賭けは賭けの枠で扱い、両者を混同しない）。

## この文書について

**この文書は、確かめたことと、まだ仮説であることの両方を含む。** どちらがどちらかを書き分ける。

- **確かめたこと**: 読んで終わる情報が訪問を失うことは、外部の定量と自サイトの実測の両方で確認している。
- **仮説**: ためして得るものが訪問を保てること。持ち帰られた成果物が共有される記号に育つこと。どちらも実測で確かめ続ける。
- 動かせないのは constitution と生の観測データだけである。この文書自体はその上に立つ、書き換えられる層である。

次のいずれかが起きたら、該当する部分を検証し直す。

- 新しく作った「ためして得るもの」が、判定の時期を過ぎても読んで終わる情報と同じ負け方（表示されるがクリックされない）を示したとき。
  「ためして得るものが訪問を保てる」という仮説を検証し直す。
- 検索エンジンの挙動が変わり、作るものと作らないものを分ける問いの線引きが侵食されたとき。その問いを検証し直す。
- 検索からの流入全体が構造的に落ちたとき。「検索を主な入口とする」という前提そのものを検討し直す。

**この文書を書き換えてよい理由は、観測（生データ）か constitution の変更だけである。** 慣れ、愛着、これまでかけた手間は理由にならない。
