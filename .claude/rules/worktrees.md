# 担当の木での作業

この規則は、担当の木（`.claude/worktrees/agent-<id>`、枝 `worktree-agent-<id>`）で書いてコミットする担当（builder・blog-writer など）に向けたものである。主の木から担当の木のファイルを読むだけの PM と reviewer には当たらない（PM の決まりは `.claude/rules/delegation.md`）。

担当の木で書く担当は、次の順で作業する。主の木とほかの担当の木には触らない。

1. **起点を揃える**: 担当の木の起点は main の先頭で、作業ブランチの HEAD ではない。最初に `git merge --ff-only <作業ブランチ>` で起点を作業ブランチの HEAD に進め、`git rev-parse HEAD` が依頼に書かれた HEAD と一致することを確かめる。一致しなければ書き始めず、PM に知らせる。
2. **依存を置く**: 担当の木には `node_modules` と `.next` が無い。`cp -al <主の木>/node_modules ./node_modules` でハードリンクの写しを置く（シンボリックリンクは Turbopack が拒む）。写しは中身を主の木とほかの木と分け合うので、`node_modules` の下を書き換えない（`npm install` を打たない、パッケージのファイルを手で直さない、その場で書き換える道具を走らせない）。依存を変える仕事は担当の木では受けない。`.next` は要るときに自分の木で作る。
3. **自分の木だけをコミットする**: 自分の木の、依頼された変更だけをコミットする。試しのためのコミットを作らない（枝は作業ブランチに取り込まれるので、試しは作業ブランチの歴史に残る）。終わったら枝の名前と `git rev-parse HEAD` を PM に返す。
4. **push しない**: 担当の枝は origin に push しない。push は PM が主の木の作業ブランチだけをする。
5. **取り込みは PM がマージでする**: 変更をファイルの写しや cherry-pick で主の木へ運ばない。取り込みは PM が主の木で `git merge <担当の枝>` でする。取り込みで衝突したと頼まれたら、自分の木で `git merge <作業ブランチ>` をして解き、コミットする。取り込まないと決まったコミットは、自分の枝で `git revert` してから返す。
