**デザインの単一情報源はリポジトリルートの `DESIGN.md`。** そこには「何がどう見えるか」だけが書いてある。
**本スキルは、それをどう作り、どう確かめるかを持つ。** 食い違ったら `DESIGN.md` が正しい。

## 作る前に読む

**`DESIGN.md` は全文を読む。** どの節の規定も互いに掛かり合っている。作るものに応じて特に効くのは次の節。

| 作るもの                              | 特に効く節                          |
| ------------------------------------- | ----------------------------------- |
| 一覧                                  | §7 一覧                             |
| 道具・診断・ゲームの結果              | §8 入力と結果                       |
| 読みもの                              | §4 組版・§5 コンポーネント・§9 文章 |
| OGP 画像・保存する結果の画像・favicon | §10 サイトの外での見え方            |
| 動きのあるもの                        | §11 モーション                      |

**§1 の仕掛け3つ（端まで届く太い罫線の格子・巨大なアンティーク体の見出し・操作を色で示さない）と、罫線の交わり方が作る形（全幅の罫線がコンテナの左右のボーダーを貫いて画面の端まで伸びる）は、どのページにも現れる。** これが消えているページは、デザインが成立していない。

### 見出しとコントロールの名前の折り方を測る

測る要素は、§4 が折る所を限るもののうち、見出し・コントロールの名前・名前に括弧で数を添えたもの（索引の語を含む）である。このリポジトリの作業のコンテナには Chromium しか無いので、来訪者の多くが使う WebKit での折れ方は、次の手順の近似で数える。WebKit を使える環境では、WebKit で直接測る。近似が成り立つ前提と、スクリプトの書き方の要点は `docs/knowledge/playwright-mcp.md` の「WebKit の折り方を Chromium で近似して測る」にある。

1. 測る要素の字の Web フォントの分割ファイルが読み込まれるのを待つ。`document.fonts.load` に書体の名前と要素の字を渡して待ち、`document.fonts.check` が真になってから測る。見出しの和文は `"Zen Antique"`、見出しとコントロールの名前の欧文と数字（「（10）」「HEXをコピー」の数と英字）は `"IBM Plex Sans"` を待つ。そのうえで、測る要素とその中の計算値の `word-break` が `keep-all` で `auto-phrase` が効いていないこと、見出しとコントロールの名前では `line-break` が `strict` であることを確かめる。
2. 測る要素の字を1字ずつ（サロゲートペアの字も1字として、コードポイントごとに）Range で行の位置を取り、行に分ける。行の切れ目を、次の3つに分ける。
   - **折り所での折れ**: 要素の中の `<wbr>` の所（文節の切れ目と、最初の文節の中の語の切れ目）か、閉じ括弧の直後。
   - **文節の中の語の切れ目での折れ**: 折り所でなく、下の「実装の技術」の5の語の頭（`src/lib/word-starts.ts` の `wordStartsOf` が返す位置。`Intl.Segmenter("ja", { granularity: "word" })` の語の切れ目で、片仮名の続きの中は語に組み直した頭だけなので、「バリ|デー」のような切れ端の境目は含めない。このファイルはほかのモジュールを読み込まないので、測るスクリプトは Node で `node --experimental-strip-types` から読み込み、要素の字（`textContent`）の語の頭を求めてからページの行の切れ目と突き合わせる。位置は書記素の番号なので、行の切れ目も同じ数え方にそろえる）のうち、次の語が漢字・片仮名・開き括弧で始まり、前の語が数字で終わらない所。
   - **語の中の折れ**: どちらでもない所。

   そのうえで、要素ごとに次を数える。
   - 文節の中で折れた要素（折り所でない所で折れたもの。あとの2つを合わせる）
   - 語の中で折れた要素
   - 1字だけの行（字が2つ以上の要素で、字が1つだけの行。その字がどの文節の字かは問わない）
   - 禁則の破れ（行頭に置かない字（閉じ括弧・句読点・！？・…・中点・小書きの仮名・長音符・繰り返し記号（々・ゝ・ヽ など））で始まる行か、開き括弧で終わる行）
   - 丸括弧の中の折れ（丸括弧で囲んだ一続きの中で折れたもの）
   - 要素の幅からのはみ出し
   - 名前に括弧で数を添えたものでは、名前の中の語の切れ目と始め括弧の前のほかで折れた数

   行の切れ目を決めるのは `<wbr>` と字の幅である。見出しと欧文の字の幅は Web フォントが決め、本文の書体で組む和文（コントロールの名前）の字の幅は端末の書体が決める。コンテナの Chromium の和文も iOS のヒラギノもほぼ全角の幅で組まれ、コンテナのほうがわずかに広いので、折れを多めに数える側の近似になる（測った値は knowledge）。

3. `<wbr>` を持たず `word-break: auto-phrase` で折れている要素は、WebKit では `auto-phrase` が効かず `normal` で折れるので、Chromium でその要素に `word-break: normal` を当てて近似する。
4. 近似で拾えない差（読み上げ・実機の拡大・端末の書体で組む本文の書体の字の幅）は、実機の iOS の Safari で確かめる項目にして残す。

「200%」は、ブラウザの既定の文字サイズを 32px にした状態である（作り方は `docs/knowledge/playwright-mcp.md` の「クラウドのコンテナでは MCP のブラウザが起動しない」）。

測った要素のそれぞれが、次を満たせば §4 に沿う（数え方は上の 2）。

- どの幅と文字の大きさでも、はみ出しが0。行の切れ目は、折り所か、1行に収まらない文節の中か、1行に収まらない丸括弧の一続きの中にだけある。
- 既定の文字サイズ（320px・375px・1280px）では、1字だけの行・禁則の破れ・丸括弧の中の折れが、どれも0。来訪者にすでに渡した結果の名前（診断のタイプ名など）の見出しでは、組み方で避けられない折れに限って受け入れ、数を記録する。
- 200% では、1字だけの行と禁則の破れは、1行に収まらない文節の中の折れから出たものに限って受け入れ、数を記録する。
- 名前に括弧で数を添えたものは、どの幅と文字の大きさでも、名前の中の語の切れ目と始め括弧の前のほかで折れていない。語の中で折れてよいのは、一語が1行に収まらないときだけ。

### サイトの外に出る画像を確かめる

OGP 画像と保存する結果の画像（§10）は、HTML と CSS で組まれないので、描いた PNG そのものを測る。サーバーで描く画像は、ビルドが書き出す PNG（`.next/server/app/**/opengraph-image.body` など）か、テストの中で描いた PNG を使う。来訪者の端末で描く画像は、Chromium でその面を開いて「画像を保存」を押し、落ちた PNG を使う。どれも変更の前と後を並べて見る。

試しの入力には、次の組み方の難しいものを入れる: いちばん長い名前（ブログの題・診断のタイプ名）、1行に収まらない長い欧文の語を含む名前、空白を含む補助情報・読み・副題（和文と欧文が混ざるもの）、Zen Antique に無い字を含む名前、「——」を持つ名前、見出しが読みを含むページ（伝統色辞典）、トップ、数字の結果と名前の組（「10問中8問正解」と段位の名前、「72点」）、色見本を持つ画像、長い副題を持つ画像。

| 何を                 | どう                                                                                                                                                                                                                                                                                                                                                    |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 罫線の形             | 画素を行と列で数える。上下の横の罫線が画像の左端から右端（x=0〜1199）まで途切れないこと。コンテナの左右の線が上端から下端まで途切れないこと。横と縦の線が交点で切れず、上下の罫線の左右に十字の端が残ること                                                                                                                                             |
| 色                   | 地・字・線の画素の色が、トークンの light の値であること。色見本の中のほかに彩度のある画素が無いこと。角丸が無いこと                                                                                                                                                                                                                                     |
| 空白と行頭           | 渡した空白の前後の字のあいだの画素の空きを測り、名前・補助情報・読み・副題のどれでも空白が見えること。行頭に空白の出た行が無いこと                                                                                                                                                                                                                      |
| はみ出しと折れ       | どの字も中身の枠からはみ出さず、中身の全体が枠の縦に収まること。どの字も §4 の見出しの折り方で折れていること。名前の段を選ぶときに見積もった行数と、PNG の行数が一致すること。どのページの名前も、いちばん下の段で枠の縦に収まること。副題を切った画像では、副題が文節の切れ目で切れて「…」で終わり、名前・読み・数字の結果・補助情報は切れていないこと |
| 数字の結果           | 名前の上に、名前の段に依らない同じ大きさで描かれていること。名前がいちばん上の段でも、数字の結果の字の高さが名前の約 1.4 倍あること。折れるなら、渡した区切りの所だけであること                                                                                                                                                                         |
| 書体                 | 欧文の字が IBM Plex Sans で組まれていること（同じ字を Plex だけで描いた幅と合う）。「——」の線に隙間が無いこと。サーバーで描く画像は、書体の取得先を壊すとビルドが失敗すること。来訪者の端末で描く画像は、Web フォントの読み込みを止めると、見出しの字が §3 の仮名を全角で組む並びで描かれること                                                         |
| 縮めたカード         | PNG を幅 400px に縮めて並べて見て、名前・補助情報・サイト名が読めること                                                                                                                                                                                                                                                                                 |
| 切り取り             | 上下の端から 15px に、字も横の罫線も掛からないこと                                                                                                                                                                                                                                                                                                      |
| 描く時間             | 1枚を描き終えるまでが1秒を超えないこと                                                                                                                                                                                                                                                                                                                  |
| ページの meta        | ビルドを配信して、ページの `og:image`・`og:image:alt`・`og:image:width`/`height` が出ていて、`og:image` と構造化データの `image` の URL が 200 と PNG を返すこと。`og:image:alt` が画像に書いた字を言うこと。画像の名前が、そのページの h1 と同じ出どころの値であること                                                                                 |
| 画像を持たないページ | ビルドの HTML を数え、`twitter:card` を持ち `og:image` を持たないページが0件であること                                                                                                                                                                                                                                                                  |

### favicon を確かめる

- ICO の各大きさ（16・32・48px）と apple-touch-icon を8倍に拡大して見る。16px で `y` の線が潰れて塊にならず、上の2本の線のあいだの空きが残っていること。角の画素が `--ink` の値で、角丸が無いこと。
- `icon.svg` を、Playwright の `emulateMedia` で `colorScheme` を `light` と `dark` にし、16px と 32px の `<img>` で、ライトとダークのタブの地に近い灰色の上に並べて撮る。どちらでも正方形が地から見分けられること。ヘッドレスの Chromium はタブを写さないので、実際のタブでの見え方は人の目で確かめる項目に残す。
- 404 と 410 のページの HTML に、ほかのページと同じ icon の `<link>` があること。
- 資産を作るスクリプトを2度走らせ、資産がバイト単位で同じであること。

### 目で確かめる

**機械で判定できないものがある。** `take-screenshot` スキルでライト／ダーク × モバイル／PC の4枚を撮り、1枚ずつ次を見る。

- §1 の仕掛け3つと、罫線が作る形が出ているか
- どこにでもある構成や飾りが紛れ込んでいないか（アイコンを並べた3枚カード、意味のないバッジ、英字の全部大文字）
- UI に色が出ていないか（色が出てよいのは、その色がコンテンツそのものであるときだけ）
- 影・グロー・半透明ぼかしが紛れ込んでいないか。グラデーションは、移り変わりの各点を、その位置が表す値から作った色で塗るもの（例: 色を作るスライダーの溝）だけか
- 角丸が付いていないか（丸いのはラジオボタンだけ）
- イラスト・ストック写真・3D が無いか。絵文字が、その字そのものが話題の本文の字のほかに無いか
- 操作が色だけで示されていないか
- 見出しとコントロールの名前が文節か閉じ括弧の直後で折れているか。文節の中で折れてよいのは、文節が1行に収まらないときだけで、最初の文節の、最初の空白より前が収まらないときは、その中の語の切れ目で折れているか。丸括弧の一続き（読み仮名・添えた数）の中で折れていないか。1字の文節だけで行ができていないか。既定の文字サイズで、1字だけの行と禁則の破れ（行頭の閉じ括弧・句読点・！？・…・中点・小書きの仮名・長音符・繰り返し記号（々・ゝ・ヽ など）、行末の開き括弧）が無いか（文字を大きくしたとき（200%）は、1行に収まらない文節の中の折れから出たものを受け入れる。来訪者にすでに渡した結果の名前は、組み方で避けられない折れを受け入れる）。名前に括弧で数を添えたもの（見出し・アコーディオンのラベル・索引の語）は、名前の中の語の切れ目と始め括弧の前でだけ折れているか。語の中で折れてよいのは、一語が1行に収まらないときだけ（§4）
- 文章が §9 の作法に沿っているか

**動きと状態は静止画に写らない。** hover・フォーカス・アコーディオンの開閉・結果の登場は、実際に操作して見る。一律の fade-in やスクロール連動の登場アニメが無いことも、ここで確かめる。

## 値を変えるときの手順

- **トークンの値を変えたら、そのトークンが関わる組み合わせのコントラストを全部計算し直す。** 1組でも `DESIGN.md` §12 の要件を満たさないなら、その変更は採れない。
- **書体を変えたら、ページが読む Web フォントの転送量を変更前と比べる。** 配り方は Next.js の標準の仕組み（`next/font`）を使い、自前の切り出しは作らない。
- **`DESIGN.md` に無いコンポーネントを足したくなったら、先に `DESIGN.md` へ書く。** 文書に無いコンポーネントを実装に置かない。

## 実装の技術

- **Web フォントは `font-display: swap` で読み込み、読み込みの前後のずれを CLS で確かめる。** 欧文は、同じ `unicode-range` を付けてメトリクスを合わせた代わりの書体を置き、行の高さと字面を揃える。見出しの和文は、端末の和文の書体ごとに `local()` と `unicode-range` を分けた代わりの書体を置き、字の種類ごとの `size-adjust` で送り幅を Zen Antique に揃える（`globals.css` の `--font-zen-antique-fallback`。倍率の求め方と確かめ方は `docs/knowledge/web-fonts.md`）。見出しの書体の並びを変えたときは、`--font-zen-antique` を無い書体の名前に差し替えた組みと比べ、見出しの行の数が読み込みの前後で変わらないことを確かめる。§12 の「読み込みのずれ」はこれで確かめる。
- **見出しとコントロールの名前の折り所は、§4 の折り方を次の決め方で作り、サーバーで HTML に入れる。** データから来る文（記事の題・FAQ の問い・診断の選択肢・連載の名前など）は、`splitIntoPhrases`（`src/lib/phrase-breaks.ts`）がこの決め方で分け、サーバーから props で渡す。コードに書いた決まった文（ボタンの面・欄のラベル・選択肢の名前）は、書き手がこの決め方で分けた区切りの並びを書く。どの折り所も語の中には置かない（§4）。BudouX は語の中に境目を置くことがある（`splitIntoPhrases` の「ひらが|な| → カタカナ」）ので、書き手は機械に分けさせた結果をそのまま写さず、語の中の境目を外し（「ひらがな| → カタカナ」）、1〜5 の足し引きに照らして決める。名前の中の空白は、`keep-all` の組みでも区切りと同じく折り所になる（「ひらがな → |カタカナ」とも折れる）ので、空白の前後で折れても読める言い回しにする。
  1. 文を文節に分け、文節の切れ目を折り所にする（`splitIntoPhrases` は BudouX で分ける）。中点で並べた語の後ろ（「エンコード・|デコード」）と、英字を含む語から漢字か片仮名の語に移る所（「Base64|エンコード」）を足し、中点で並べた平仮名の語の中（BudouX の「ひらが|な・カタカナ」）を外す。
  2. 行の頭に置けない字（閉じ括弧・句読点・！？・…・中点・小書きの仮名・長音符・繰り返し記号など）の前と、開き括弧の後ろ、数とそれに続く字のあいだ（英字に続く数字は語の一部で、数でない）、丸括弧の一続きの中の切れ目を、折り所から外す。
  3. 閉じ括弧の後ろに2字までの続きがある文節（「「yolos.net」に」）は、続きを次の文節の頭に移す。閉じ括弧の直後はブラウザが折るので、続き（「に」）だけの行を作らない。最後の文節が1字なら、その前の折り所を外し、前の文節につなぐ。
  4. 最初の文節の、最初の空白より前に、字の種類が変わって漢字か片仮名の語が始まる所の折り所を足す。足すのは、前後がどちらも同じ字の種類の2字以上の続きで、丸括弧の中でない所だけ。解析で分けられない仮名の続き（「調べてから」）は、字の種類では切れ目を決められないので分けない。
  5. 見出しのいちばん狭い行（記事の主見出しを 320px の画面で組んだ行、全角6字）より広い文節は、収まるまで語と語の切れ目で分ける。1行に収まらない文節をブラウザが字の所で割ると、1字の行・行頭の約物が出るので、その代わりにする。分ける所は語の頭（`src/lib/word-starts.ts` の `wordStartsOf`。`Intl.Segmenter` の語の境目で、片仮名の続きの中は、辞書が刻んだ切れ端を語に組み直した頭だけ。英語の語尾を写した3字（「リング」「キング」「ション」）と撥音で始まる切れ端は前の切れ端に付け、3字未満の切れ端はとなりどうしでつなぐ。つないだ語を1つの語とみなすのは、続きの終わりにあり、5字以上で、前の辞書の語が5字以上で、頭が2字以上の切れ端か小書きの仮名と音を作る1字のとき（「メールアドレス|バリデーター」）だけで、そうでなければ続きの中には置かない。辞書の切れ端は前後の語の頭や終わりでもある（「アク|セ|スト|ラッカー」「フレンド|リー」「ホバート|ラン|ジ|ション」）ので、この形で見分ける。見分けられないのは、5字以上の辞書の語が辞書に無い外来語の頭で、残りが次の語とつながる形（「プログラマ|ティックジェネレーター」）だけである）のうち、禁則を満たし、丸括弧の中でなく、分けた切れ端のどちらも文字が2字以上（平仮名だけなら3字以上）の所。順位は、漢字・片仮名・英字の語の頭（漢字どうしを除く）を先に、「〜する」の頭（「リリース|しました」）を後にし、同じ順位の中は BudouX の境目の度合いの高い所を選ぶ。`<wbr>` には優先の順が無く、広い画面でも行の終わりに来れば使われるので、語の中には置かない。語が1行に入らないときは、ブラウザがその語の中で折る。1の BudouX の境目のうち、漢字か片仮名を含む語の中に落ちるもの（「見た|目」「切り|替え」）も外す。ダッシュ（「—」「──」「--」）とハイフンで結んだ語（「not-found.tsx」「JSON-LD」）は、`PhrasedText` が語結合子（U+2060）でつなぐ。ダッシュは前に空白があっても次の文節の頭に置かず、前の空白を折れない空白に、空白の無いダッシュの前とダッシュの字どうしのあいだを語結合子にして前の語に付ける。語の中の1つの「-」の後ろにも、後ろが数字のとき（「UTF-8」）を含めて語結合子を置き、語が1行に収まる幅ではハイフンの後ろで折らない。「--」は上のダッシュとして組む。語が1行に入らないときは、ハイフンの所でなく字の所で割れる。コピーした文からは、サイトの全体でコピーを受ける `WordJoinerCopyFilter` が語結合子を除く。
  6. 表のセル（`tableCell`）は丸括弧の中も文節で折り、1・3・5の語の切れ目の足し引きをしない（列の幅はいちばん長い文節で決まる）。4の最初の文節の字の種類の変わり目は、見出しと同じく置く。
  7. 折り所に `<wbr>` を置き、区切りを組む要素（見出しの要素と、区切りを受けて組む部品 `PhrasedText`・`Accordion` の `summary`）に `word-break: keep-all` と `overflow-wrap: anywhere` を持たせる。見出しとコントロールの名前には `line-break: strict` も持たせる（§4 の行頭の禁則）。閉じ括弧の直後は、Unicode の改行の規則が折り所とし、`keep-all` でも折れる（§4 が折ってよいとする所）。どれも WebKit と Chromium の両方で効く機能で、Chromium でしか効かない `word-break: auto-phrase` に頼らない。
- **2文節以上の名前と面は、区切りの並びで渡す。** 名前と面を組む部品は、文字列を区切りの無い1つの文節として組み、区切りの並びを受け取るとそのあいだで折る。1文節の名前は文字列のまま渡す。並びを渡す所は、`Button` の面の `phrases`（`children` とはどちらか一方だけ）、`Field`・`Checkbox`・`Radio`・`FileDropZone`・`GuessInput` の `label`、`RadioGroup` の `legend`、`Accordion` の `summary`、`ListControls`・`BrowsableList` の `searchLabel`（どれも `PhrasedName`）、選択肢の並びの要素の名前（`RadioGroup` の `options` と `Slider` の `items` の要素の `label`）、`CopyButton` の面に出す写すものの名前の `targetPhrases`、一覧の選択肢の `name` である。値を差し込む名前は、差し込む値をそれを含む文節に入れて並びを組む（括弧で添えた数は1つの文節）。コントロールの名前を素の `label`・`legend`・`button`・`summary` に書かず、区切りを受け取る部品で組む。受け取る部品の無いもの（チェックボックスの組の `legend` など）は、子を `PhrasedText` で組む。
- **名前と面を書いたら、`npm run check:phrased-names` で数える。** 数え方（`src/test/unphrased-names.ts`）は、上の名前の props・選択肢と組の並びの要素の名前・素の `label`・`legend`・`button`・`summary` の子を、三項演算子・`&&`・`||`・`??` の枝と同じファイルの `const` の中まで見て、2つに分けて出す。
  - **字で渡すもの**（`splitIntoPhrases` が2つ以上に分ける字と、`followsPhraseRules` を満たさない手書きの並び）は直すもので、0にする。1つでもあれば失敗する。出力の括弧に並ぶのは `splitIntoPhrases` の分け方で、書く並びではない。書く並びは上の決め方で決める。
  - **値で渡すもの**（ほかのモジュールの定数・`.map` して渡す並び・値を差し込んだ文・字と式を含む要素・広げた props・サーバーで区切る文）は、数え方が中身を確かめられない。出た位置ごとに、名前が出る状態（閉じた組を開く・モードを選ぶ・押したあと・エラー・無効など）を開き、320px の既定と 200% で「作ったあとに確かめる」の「見出しとコントロールの名前の折り方を測る」の手順で測って、語の中の折れを0にする。1行に収まらない文節の中の折れ（§4 が受け入れるもの）は数を記録する。
  - **走らせ方**: 数えるパスは環境変数 `PHRASED_NAMES_PATHS` に空白かカンマで区切って渡す（既定は `src`。vitest の位置引数は試験のファイルの絞り込みに使われる）。出力の頭に数えた `.tsx` の数を出し、渡したパスのどれかから `.tsx` が1つも出なければ（`.ts` のファイルや `.tsx` の無いディレクトリを渡したとき）失敗させる。`PHRASED_NAMES_REPORT_ONLY=1` を足すと失敗させずに出すだけにするので、ほかのタスクの受け持ちが残るファイルを数えて記録するときに使う。数え方は server-only の `splitIntoPhrases` を使うので vitest の上で走り、ふだんの `npm test` では何も数えない。書いたか書き換えたものを始めと終わりの出力の差で見分けるときは、行番号でなくファイルと字（または式）で突き合わせる。
- **`.ts` に手で書いた区切りの並びは、`followsPhraseRules` を満たすことを試験で確かめる。** 試験は特定の値を選ばず定義のすべての要素を回す形にし、あとから足した要素も同じ試験にかける。値を差し込む並びは、差し込む値のどの組でも確かめる。
- **記事の表のセルの折り所も、Markdown を組むとき（サーバー）に同じ区切りの関数で入れる。** 表のセルの指定（`tableCell`）で当てる（§4）。区切りはセルの字の全体（タグを除き、コード片の字も含め、文字参照を1字に数えた並び）に当て、切れ目のうちコード片の中に落ちるものを除いた所に `<wbr>` を置く。タグで分かれた字の切れ端ごとに当てると、強調やリンクの前後で文節が切られる。セルは `word-break: keep-all` で組み、区切りを持つ表だけに当てる（区切りの無いセルに当てると、句読点と空白のあいだの和文が1つの塊になって列が広がる）。
  - 列の幅と横に送るか（§4・§5）は、`src/lib/scroll-frame.ts` の1つの関数が決める。各列のいちばん長い文節の幅を、表の幅を0にして列を最小の幅にした組みで測り、収まらないときだけ長い列から同じ幅まで4字を下限に細くする。細くした列のセルにだけ `overflow-wrap: anywhere` を付ける。列の幅の計算は描画から切り離した関数にして単体で試す。
  - 最初の描画から組むため、記事のページは本文の前に置くスクリプトで関数を定め、表ごとにその直後に置く小さなスクリプトでその表を組む（回線が遅く本文の途中までで描くときも、描かれる表は組まれている）。`Link` で移ったときは差し込んだスクリプトが動かないので、本文の部品（`Prose`）が layout effect で同じ関数で組み、幅・文字の大きさ・Web フォントが変わったときも組み直す。スクリプトは関数を文字列にして（`String(fn)`）作るので、関数は外の名前を使わない（ビルドの変換で名前が変わっても動く）。
- **記事の外の表（値の並び・結果の表・カラーコードの表）は `DataTable`（`src/components/DataTable`）で組み、表ごとに `table` を書かない。** 列の幅と横に送るかは記事の表と同じ `src/lib/scroll-frame.ts` の関数が決め、サーバーで描いた表は、枠の前のスクリプトが組み方を定め、枠の直後のスクリプトがその表を組む。本文の中の最初の表より前にスクリプトが無いと組む前の表が描かれることがあり、回線が遅いと表の途中までが描かれることがあるので、組んだ印が付くまで表を描かない（`@media (scripting: enabled)` の中で隠す）。隠れたままにしないため、組むスクリプトが失敗したら組めなかった印を付けてすぐ見せ、どちらの印も付かないとき（スクリプトが止められた・水和が動かない）も CSS のアニメーションで3秒後に見せる。セルは区切りの並びで渡す。データから来る字はサーバーで `splitIntoPhrases` の表のセルの指定（`tableCell`）で分け、コードが組み立てる値（「36歳」「4ヶ月」「13日」）は組み立てた単位ごとの並びをそのまま渡す。セルに置くコントロール（行の頭の開閉のボタン）は要素で渡し、面の字はその要素が区切りの並びで組む。値を写すコピーのボタンは行の `copy` に写す文と何を写すかを渡し、部品が値のセルの右端に置く。どの行の値も1行のままボタンと並んで表が収まるときだけ横に置き、そうでなければどの行も値の次の行へ送る（§6）。結果のボックス（`ResultBox` の `kind="table"`）の中に置く表は `inBox` を渡し、横に送るのをボックスに任せて枠を重ねない（§8）。

- **スライダー（§6）は `Slider`（`src/components/Slider`）で組み、`input type="range"` を直に置かない。** 部品が持つのは、ネイティブの `input type="range"`・− と ＋・値の置き方・2行の組みへの切り替え・溝の色の止まりを決める1つの関数（つまみの中心の対応、§6）である。指・マウス・キーボードでの動きはネイティブの入力に任せ、`input` の上の指・マウス・キーボードの出来事を部品で受けない（受けると、VoiceOver で見つからなくなるか、エンジンの既定の処理と食い違う）。− と ＋ には `touch-action: manipulation` を掛け（iOS の Safari は速い2度の押しを拡大に取りうる）、押してもフォーカスを奪わず、端で無効にしてもフォーカスを落とさない（`disabled` でなく `aria-disabled` にする、など）。無効の破線の枠はフォーカスの二重リングと `outline` を取り合わないよう、リングの内側に別の線で描く。押して値を変えたら、使う側に新しい値を渡し（React の `onChange` は、`value` を代入しただけでは呼ばれない。ネイティブの値の setter で入れて `input` の出来事を起こすか、使う側の処理を直に呼ぶ）、新しい値を読み上げの知らせで1度言う。知らせは − と ＋ を押したときだけ出し、値が変わるたびには出さない。
- **スライダーの溝とつまみの見た目は、`globals.css` の `:where(input[type="range"])` の既定に書く。** 詳細度を 0 にして部品のクラスが上書きできるようにし、上下の余白を 0 にする。溝の細い線は内側の `box-shadow` で引き、`border` で引かない。WebKit・Chromium はつまみを溝の要素の枠の内側で動かすので、`border` で引くとつまみの動く幅が線の太さの2倍だけ縮み、溝の色の止まり（つまみの中心の対応）とつまみの位置がずれる。溝とつまみは、WebKit・Chromium の `::-webkit-slider-runnable-track`・`::-webkit-slider-thumb` と、Firefox の `::-moz-range-track`・`::-moz-range-thumb` に別々の規則で書く（1つのセレクタの並びにまとめると、その規則はどれかの擬似要素を知らないブラウザで丸ごと捨てられる）。WebKit・Chromium のつまみにも `-webkit-appearance: none` を掛ける（掛けないと大きさと枠の指定が効かず、既定の丸いつまみが出る）。WebKit・Chromium はつまみの上端を溝の中身の上端に付けて描くので、負の `margin-top` でつまみを上げて、溝の上下の中央に合わせる。HSL の色の溝は、`linear-gradient` の既定の補間（sRGB）のまま、色相は 60 ごと・明度は 50 に止まりを置けば、止まりのあいだの色も作られる色と一致する。

- **折らないために字のあいだに置く見えない字は、語結合子（U+2060）にし、`@/lib/phrase-dashes` の `WORD_JOINER` で書く。** 置く所と除く所が同じ定数を読むので、どこに置いたかをコードからたどれる。語結合子は選んで写した文にも残るので、ルートのレイアウトが置く `WordJoinerCopyFilter` が、写す文から U+2060 を除く（DESIGN.md §4）。いま語結合子を置くのは `joinDashes`（`PhrasedText`）と json-formatter の `keepTogether` で、ゼロ幅の空白などほかの見えない字は除かれずに写る。コピーの中身を変える受け手は、`preventDefault` して `Selection.toString()`・`Range.cloneContents()` から組み直さず、ブラウザに写させる。組み直すと、相対のリンク・`<script>`・隠れた要素・`user-select: none` の字が写る。写させるあいだも文書の字を除かず、写さない字を `user-select: none` の要素に入れるだけにする。字を除くと行の組みが変わり、メニューから写したときに CLS に入る layout-shift になる（`docs/knowledge/clipboard-and-copy.md`）。
