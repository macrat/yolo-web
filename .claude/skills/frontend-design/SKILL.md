**デザインの単一情報源はリポジトリルートの `DESIGN.md`。** そこには「何がどう見えるか」だけが書いてある。
**本スキルは、それをどう作り、どう確かめるかを持つ。** 食い違ったら `DESIGN.md` が正しい。

## 作る前に読む

**`DESIGN.md` は全文を読む。** 340行ほどで、どの節の規定も互いに掛かり合っている。作るものに応じて特に効くのは次の節。

| 作るもの          | 特に効く節               |
| ----------------- | ------------------------ |
| 一覧              | §7 一覧                  |
| 道具・結果ページ  | §8 入力と結果            |
| 読みもの          | §4 組版・§9 文章         |
| OGP 画像・favicon | §10 サイトの外での見え方 |
| 動きのあるもの    | §11 モーション           |

**§1 の仕掛け3つ（端まで届く太い罫線の格子・巨大なアンティーク体の見出し・操作を色で示さない）と、罫線の交わり方が作る形（全幅の罫線がコンテナの左右のボーダーを貫いて画面の端まで伸びる）は、どのページにも現れる。** これが消えているページは、デザインが成立していない。

## 作ったあとに確かめる

### 機械で確かめる

| 何を                             | どう                                                                                                                                                                                                                                                                            |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| コントラスト                     | §2 のトークンの値から、その画面で使う組み合わせの比を計算する。文字 4.5:1・線とコントロール 3:1。hover・フォーカス・訪問済み・無効・エラーで色が変わる組み合わせも計算する                                                                                                      |
| 320px 幅で横スクロールしない     | 幅 320px で `document.documentElement.scrollWidth` が画面幅を超えないことを見る                                                                                                                                                                                                 |
| 文字サイズ 200% で内容が欠けない | ブラウザの既定の文字サイズを 32px にして描く。`html { font-size }` の宣言では `rem` で決まる閾値（§4・§5）が動かず、来訪者に起こらない状態になる。`document.documentElement.scrollWidth` が画面幅を超えないことと、各要素の `scrollWidth` が `clientWidth` を超えないことを見る |
| UI の色が直書きされていない      | `src/` を `grep` して `oklch(` の直書きと16進数の色を探す。`globals.css` のトークン定義と、コンテンツそのものの色（§2）を除いて、残りが無いこと                                                                                                                                 |
| タップターゲットが 44px 以上     | 押せる範囲を測る。ラジオボタンとチェックボックスはラベルを含む行全体、本文中のインラインリンクは例外（§6）                                                                                                                                                                      |
| Web フォントで内容がずれない     | フォントの読み込みを止めた状態と読み込んだ状態で、レイアウトの矩形を比べる                                                                                                                                                                                                      |

### 目で確かめる

**機械で判定できないものがある。** `take-screenshot` スキルでライト／ダーク × モバイル／PC の4枚を撮り、1枚ずつ次を見る。

- §1 の仕掛け3つと、罫線が作る形が出ているか
- どこにでもある構成や飾りが紛れ込んでいないか（アイコンを並べた3枚カード、意味のないバッジ、英字の全部大文字）
- UI に色が出ていないか（色が出てよいのは、その色がコンテンツそのものであるときだけ）
- 影・グロー・半透明ぼかし・グラデーションが紛れ込んでいないか
- 角丸が付いていないか（丸いのはラジオボタンだけ）
- イラスト・ストック写真・3D・絵文字が無いか
- 操作が色だけで示されていないか
- 見出しが語の途中や括弧の前後で折れていないか（例外は、一語がコンテンツ幅に収まらないときの語中の折りだけ）
- 文章が §9 の作法に沿っているか

**動きと状態は静止画に写らない。** hover・フォーカス・アコーディオンの開閉・結果の登場は、実際に操作して見る。一律の fade-in やスクロール連動の登場アニメが無いことも、ここで確かめる。

## 値を変えるときの手順

- **トークンの値を変えたら、そのトークンが関わる組み合わせのコントラストを全部計算し直す。** 1組でも `DESIGN.md` §12 の要件を満たさないなら、その変更は採れない。
- **書体を変えたら、サブセットを作り直す。** 字種の使い方も見直す。
- **`DESIGN.md` に無いコンポーネントを足したくなったら、先に `DESIGN.md` へ書く。** 文書に無いコンポーネントを実装に置かない。

## 実装の技術

- **Web フォントは `font-display: swap` と `size-adjust` で、読み込みの前後で行の高さと字面を揃える。** §12 の「読み込みのずれ」はこれで満たす。
- **手で入れた改行は、幅に応じて無効化する。** 見出しを意味の切れ目で折る指定が、狭い画面で不自然な折り返しにならないようにする。
