**デザインの単一情報源はリポジトリルートの `DESIGN.md`。** そこには「何がどう見えるか」だけが書いてある。
**本スキルは、それをどう作り、どう確かめるかを持つ。** 食い違ったら `DESIGN.md` が正しい。

## 作る前に読む

**`DESIGN.md` は全文を読む。** どの節の規定も互いに掛かり合っている。作るものに応じて特に効くのは次の節。

| 作るもの                 | 特に効く節                          |
| ------------------------ | ----------------------------------- |
| 一覧                     | §7 一覧                             |
| 道具・診断・ゲームの結果 | §8 入力と結果                       |
| 読みもの                 | §4 組版・§5 コンポーネント・§9 文章 |
| OGP 画像・favicon        | §10 サイトの外での見え方            |
| 動きのあるもの           | §11 モーション                      |

**§1 の仕掛け3つ（端まで届く太い罫線の格子・巨大なアンティーク体の見出し・操作を色で示さない）と、罫線の交わり方が作る形（全幅の罫線がコンテナの左右のボーダーを貫いて画面の端まで伸びる）は、どのページにも現れる。** これが消えているページは、デザインが成立していない。

## 作ったあとに確かめる

### 機械で確かめる

| 何を                             | どう                                                                                                                                                                                                              |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| コントラスト                     | §2 のトークンの値から、その画面で使う組み合わせの比を計算する。文字 4.5:1・線とコントロール 3:1。hover・フォーカス・訪問済み・無効・エラーで色が変わる組み合わせも計算する                                        |
| 320px 幅で横スクロールしない     | 幅 320px で `document.documentElement.scrollWidth` が画面幅を超えないことを見る                                                                                                                                   |
| 文字サイズ 200% で内容が欠けない | ブラウザの既定の文字サイズを 32px にして描く（§4・§5 の `rem` の閾値も一緒に動く）。`document.documentElement.scrollWidth` が画面幅を超えないことと、各要素の `scrollWidth` が `clientWidth` を超えないことを見る |
| 見出しの折り方                   | 下の「見出しの折り方を測る」の手順で、320px・375px・1280px の既定と 200% で数える                                                                                                                                 |
| UI の色が直書きされていない      | `src/` を `grep` して `oklch(` の直書きと16進数の色を探す。`globals.css` のトークン定義と、コンテンツそのものの色（§2）を除いて、残りが無いこと                                                                   |
| タップターゲットが 44px 以上     | 押せる範囲を測る。ラジオボタンとチェックボックスはラベルを含む行全体、本文中のインラインリンクは例外（§6）                                                                                                        |
| Web フォントで内容がずれない     | フォントの読み込みを止めた状態と読み込んだ状態で、レイアウトの矩形を比べる                                                                                                                                        |

### 見出しの折り方を測る

このリポジトリの作業のコンテナには Chromium しか無いので、来訪者の多くが使う WebKit での折れ方は、次の手順の近似で数える。WebKit を使える環境では、WebKit で直接測る（手順の詳しい書き方は `docs/knowledge/playwright-mcp.md` の「WebKit の折り方を Chromium で近似して測る」）。

1. 測る見出しの字の Web フォントの分割ファイルが読み込まれるのを待つ（`document.fonts.load` に見出しの書体の名前（`"Zen Antique"`）と見出しの字を渡して待ち、`document.fonts.check` が真になってから測る）。見出しの要素とその中の計算値の `word-break` が `keep-all` で、`auto-phrase` が効いていないことを確かめる。
2. 見出しの字を1字ずつ（サロゲートペアの字も1字として、コードポイントごとに）Range で行の位置を取り、行に分ける。行の切れ目を、次の3つに分ける。
   - **折り所での折れ**: 見出しの中の `<wbr>` の所（文節の切れ目と、最初の文節の中の語の切れ目）か、閉じ括弧の直後。
   - **文節の中の語の切れ目での折れ**: 折り所でなく、`Intl.Segmenter("ja", { granularity: "word" })` の語の切れ目のうち、次の語が漢字・片仮名・開き括弧で始まり、前の語が数字で終わらない所。
   - **語の中の折れ**: どちらでもない所。

   そのうえで、見出しごとに次を数える。
   - 文節の中で折れた見出し（折り所でない所で折れたもの。あとの2つを合わせる）
   - 語の中で折れた見出し
   - 1字だけの行（字が1つだけの行。その字がどの文節の字かは問わない）
   - 禁則の破れ（行頭に置かない字（閉じ括弧・句読点・！？・…・中点・小書きの仮名・長音符・繰り返し記号（々・ゝ・ヽ など））で始まる行か、開き括弧で終わる行）
   - 丸括弧の中の折れ（丸括弧で囲んだ一続きの中で折れたもの）
   - 見出しの幅からのはみ出し

   行の切れ目を決めるのは `<wbr>` と Web フォントの字の幅なので、これを WebKit の近似とする。

3. `<wbr>` を持たず `word-break: auto-phrase` で折れている見出しは、WebKit では `auto-phrase` が効かず `normal` で折れるので、Chromium でその見出しに `word-break: normal` を当てて近似する。
4. 近似で拾えない差（読み上げ・実機の拡大）は、実機の iOS の Safari で確かめる項目にして残す。

「200%」は、CDP の `Page.setFontSizes` で既定の文字サイズを 32px にした状態である。

測った見出しのそれぞれが、次を満たせば §4 に沿う（数え方は上の 2）。

- どの幅と文字の大きさでも、はみ出しが0。行の切れ目は、折り所か、1行に収まらない文節の中か、1行に収まらない丸括弧の一続きの中にだけある。
- 既定の文字サイズ（320px・375px・1280px）では、1字だけの行・禁則の破れ・丸括弧の中の折れが、どれも0。来訪者にすでに渡した結果の名前（診断のタイプ名など）の見出しでは、組み方で避けられない折れに限って受け入れ、数を記録する。
- 200% では、1字だけの行と禁則の破れは、1行に収まらない文節の中の折れから出たものに限って受け入れ、数を記録する。

### 目で確かめる

**機械で判定できないものがある。** `take-screenshot` スキルでライト／ダーク × モバイル／PC の4枚を撮り、1枚ずつ次を見る。

- §1 の仕掛け3つと、罫線が作る形が出ているか
- どこにでもある構成や飾りが紛れ込んでいないか（アイコンを並べた3枚カード、意味のないバッジ、英字の全部大文字）
- UI に色が出ていないか（色が出てよいのは、その色がコンテンツそのものであるときだけ）
- 影・グロー・半透明ぼかし・グラデーションが紛れ込んでいないか
- 角丸が付いていないか（丸いのはラジオボタンだけ）
- イラスト・ストック写真・3D が無いか。絵文字が、その字そのものが話題の本文の字のほかに無いか
- 操作が色だけで示されていないか
- 見出しが文節か閉じ括弧の直後で折れているか。文節の中で折れてよいのは、文節が1行に収まらないときだけで、最初の文節の、最初の空白より前が収まらないときは、その中の語の切れ目で折れているか。丸括弧の一続き（読み仮名・添えた数）の中で折れていないか。1字の文節だけで行ができていないか。既定の文字サイズで、1字だけの行と禁則の破れ（行頭の閉じ括弧・句読点・！？・…・中点・小書きの仮名・長音符・繰り返し記号（々・ゝ・ヽ など）、行末の開き括弧）が無いか（文字を大きくしたとき（200%）は、1行に収まらない文節の中の折れから出たものを受け入れる。来訪者にすでに渡した結果の名前は、組み方で避けられない折れを受け入れる）。名前に括弧で数を添えたもの（見出し・アコーディオンのラベル・索引の語）は、名前の中の語の切れ目と始め括弧の前でだけ折れているか。語の中で折れてよいのは、一語が1行に収まらないときだけ（§4）
- 文章が §9 の作法に沿っているか

**動きと状態は静止画に写らない。** hover・フォーカス・アコーディオンの開閉・結果の登場は、実際に操作して見る。一律の fade-in やスクロール連動の登場アニメが無いことも、ここで確かめる。

## 値を変えるときの手順

- **トークンの値を変えたら、そのトークンが関わる組み合わせのコントラストを全部計算し直す。** 1組でも `DESIGN.md` §12 の要件を満たさないなら、その変更は採れない。
- **書体を変えたら、ページが読む Web フォントの転送量を変更前と比べる。** 配り方は Next.js の標準の仕組み（`next/font`）を使い、自前の切り出しは作らない。
- **`DESIGN.md` に無いコンポーネントを足したくなったら、先に `DESIGN.md` へ書く。** 文書に無いコンポーネントを実装に置かない。

## 実装の技術

- **Web フォントは `font-display: swap` で読み込み、読み込みの前後のずれを CLS で確かめる。** 欧文は、同じ `unicode-range` を付けてメトリクスを合わせた代わりの書体を置き、行の高さと字面を揃える。見出しの和文は、代わりの書体との送り幅と詰めの差で折り返しが変わりうるので、主要な見出しを読み込みの前後で見比べる。§12 の「読み込みのずれ」はこれで確かめる。
- **見出しの折り所は、サーバーで HTML に入れる。** データから作る見出しも含め、§4 の折り方を次のように作る。
  1. 見出しの文を BudouX で文節に分け、文節の切れ目を折り所にする。
  2. 行の頭に置けない字（閉じ括弧・句読点・！？・…・中点・小書きの仮名・長音符・繰り返し記号など）の前と、開き括弧の後ろ、数字とそれに続く字のあいだ、丸括弧の一続きの中の切れ目を、折り所から外す。
  3. 最後の文節が1字なら、その前の折り所を外し、前の文節につなぐ。
  4. 最初の文節の、最初の空白より前に、字の種類が変わって漢字か片仮名の語が始まる所の折り所を足す。足すのは、前後がどちらも同じ字の種類の2字以上の続きで、丸括弧の中でない所だけ。解析で分けられない仮名の続き（「調べてから」）は、字の種類では切れ目を決められないので分けない。
  5. 折り所に `<wbr>` を置き、見出しの要素に `word-break: keep-all` と `overflow-wrap: anywhere` を持たせる。閉じ括弧の直後は、Unicode の改行の規則が折り所とし、`keep-all` でも折れる（§4 が折ってよいとする所）。どれも WebKit と Chromium の両方で効く機能で、Chromium でしか効かない `word-break: auto-phrase` に頼らない。
- **区切りを作る関数（`src/lib/phrase-breaks.ts`）はサーバーだけで動かし、BudouX をブラウザに配らない。** 配ると分け方の表と処理を来訪者の全員に読ませ、区切りが入るまで見出しが違う所で折れてから組み直る。クライアントの部品が描く見出しは、サーバーの `page.tsx` が区切りを作って props で渡す。描くまでどれになるか決まらないもの（日付で選ぶ占いなど）は、候補の全件の区切りを渡す。
- **区切りを受けて組む部品（`PhrasedText`）が、区切りの印を1か所で決める。見出しの中に文字を分ける `span` を足さない。** 見出しの中の `span` で VoiceOver が見出しを切って読むという報告がある。
