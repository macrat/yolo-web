**デザインの単一情報源はリポジトリルートの `DESIGN.md`。** そこには「何がどう見えるか」だけが書いてある。
**本スキルは、それをどう作り、どう確かめるかを持つ。** 食い違ったら `DESIGN.md` が正しい。

## 作る前に読む

ページの種類ごとに、`DESIGN.md` の該当節を先に読む。

| 作るもの          | 読む節                                         |
| ----------------- | ---------------------------------------------- |
| どのページも      | §1 中心・§5 構造・§13 このデザインが満たす下限 |
| 一覧              | §7 一覧                                        |
| 道具・結果ページ  | §8 入力と結果                                  |
| 読みもの          | §4 組版・§9 文章                               |
| 共有画像・favicon | §10 サイトの外での見え方                       |
| 動きのあるもの    | §11 モーション                                 |

**§1 の担い手3つ（端まで届く太い罫の格子・巨大なアンティーク体の見出し・操作を色で示さない）と、罫の交わり方が作る形（横罫が縦罫を貫いて画面の端まで伸びる）は、どのページにも現れる。** これが消えているページは、デザインが成立していない。

## 作ったあとに確かめる

### 機械で確かめる

| 何を                                   | どう                                                                  |
| -------------------------------------- | --------------------------------------------------------------------- |
| コントラスト                           | Chromium の canvas から実測して比を出す。文字 4.5:1・罫と UI 部品 3:1 |
| 320px 幅で横スクロールしない           | 幅 320px で `document.documentElement.scrollWidth` を見る             |
| 文字サイズ 200% で内容が欠けない       | ルートの `font-size` を2倍にして描画する                              |
| 色が直書きされていない                 | `src/` を `grep` して `oklch(` の直書きと 16進数の色を探す            |
| 押して反応する範囲が 44px 以上         | 押せる要素の矩形を測る                                                |
| Web フォントの読み込みで内容がずれない | 読み込み前後でレイアウトの矩形を比べる                                |

### 目で確かめる

**機械で判定できないものがある。** どこにでもある構成・図像の質感・動きの意図・文章の自然さ。
**`take-screenshot` スキルでライト／ダーク × モバイル／PC の4枚を撮り、1枚ずつ次を見る。**

- 中身以外に色が出ていないか（色が出てよいのは、その色が中身そのものであるときだけ）
- 影・グロー・グラデーション・角丸が紛れ込んでいないか
- イラスト・ストック写真・3D・絵文字が無いか
- 操作が色だけで示されていないか
- 一律の fade-in やスクロール連動の登場アニメが無いか
- 見出しが語の途中や括弧の前後で折れていないか

## 値を変えるときの手順

- **トークンの値を変えたら、そのトークンが関わる組み合わせのコントラストを全部計算し直す。** 1組でも `DESIGN.md` §13 の下限を割るなら、その変更は採れない。
- **書体を変えたら、サブセットを作り直す。** 転送量の上限を超えるなら、字種の使い方を見直す。
- **`DESIGN.md` に無い部品を足したくなったら、先に `DESIGN.md` へ書く。** 文書に無い部品を実装に置かない。

## 実装の技術

- **Web フォントは `font-display: swap` と `size-adjust` で、読み込みの前後で行の高さと字面を揃える。** §13 の「読み込みのずれ」はこれで満たす。
- **手で入れた改行は、幅に応じて無効化する。** 見出しを意味の切れ目で折る指定が、狭い画面で不自然な折り返しにならないようにする。
- **端末ごとの書体の解決は実機で確かめて確定する。** 名前で指定しただけでは、同じ書体が当たっているとは限らない。

## `DESIGN.md` を改訂するとき

- **改訂の正当な理由は、来訪者にとっての価値が上がることだけである。** 実装がそうなっているから、は理由にならない。
- **実装と `DESIGN.md` が食い違っていたら、直すのは実装である。** 文書を実装に合わせて書き換えない。
- **数値の由来は `DESIGN.md` に書かない。** 検討した経緯はサイクルドキュメントに残す。定義は値を持ち、由来を持たない。
