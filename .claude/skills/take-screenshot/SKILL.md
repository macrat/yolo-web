スクリーンショットは`scripts/take.ts`を呼び出すことで撮ることができます。
取得したスクリーンショットは、既定ではプロジェクトルートの`tmp/screenshots/`に保存されます。ほかの作業者と並行して撮るときは、`--out <自分専用のディレクトリ>` で書き出し先を分けてください（名前は秒までの時刻と URL なので、同じ場所で同じ URL を同じ秒に撮ると上書きされます）。

`scripts/take.ts`は以下のように起動します。

```bash
# ページ全体を撮る場合（原則としてこちらを使う）
npx tsx .claude/skills/take-screenshot/scripts/take.ts <URL>

# 特定の要素だけを撮る場合（作業中の確認用。レビューで使うときはページ全体を併用すること）
npx tsx .claude/skills/take-screenshot/scripts/take.ts <URL> --selector <CSSセレクタ>

# ダークテーマで撮る場合（--dark フラグを追加）
npx tsx .claude/skills/take-screenshot/scripts/take.ts <URL> --dark
# --selector と併用も可能
npx tsx .claude/skills/take-screenshot/scripts/take.ts <URL> --selector <CSSセレクタ> --dark

# 書き出し先を自分専用のディレクトリにする場合（--out。ほかのフラグと併用できる）
npx tsx .claude/skills/take-screenshot/scripts/take.ts <URL> --out <ディレクトリ>
```

> **注意**: このサイトのテーマは端末の設定（`prefers-color-scheme`）に従う。
> `--dark` フラグはブラウザの設定を dark にして撮り、撮る前に dark の値が当たったことを確かめる。
> 当たっていなければ、ファイル名に `_dark-FAILED` を付けて非ゼロで終わる。

ブラウザは、リポジトリの `playwright` が求める版の Chromium で起動する。その版が入っていないとき（claude.ai のクラウドのコンテナのように、入っている版が違い、`playwright install` でブラウザを足さない環境）は、ブラウザの置き場（`PLAYWRIGHT_BROWSERS_PATH`、無ければ Playwright の既定の置き場）に入っている Chromium のうち版がいちばん新しいもので起動し、そのことと使った本体の場所を最初に表示する。どちらの場合も、`executablePath` を自分で指定したスクリプトを別に書く必要はない。

まだサーバーを起動していない場合は、`docs/knowledge/playwright-mcp.md` の「バックグラウンドのプロセスを起こして止める」の形で、自分専用のディレクトリとポートを決め、プロセスのグループごと起動してください。`npm run dev` は `sh` と `next dev` を通して `next-server` の子を起こすので、`npm` の PID だけを止めても `next-server` が残ります。ポートを決めずに起こすと、3000 番にいるほかの作業者のサーバーを撮ってしまうことがあるので、撮る URL は自分のポートにします。PGID・ログは共有の場所に置かず、`pkill` などの名前やポートで探して止めるコマンドは使わないでください（ほかの作業者のサーバーまで止めてしまいます）。

```bash
DIR=<自分専用のディレクトリ>; mkdir -p "$DIR"   # 例: scratchpad の下の作業ごとのディレクトリ
PORT=<自分で選んだ番号> setsid bash -c 'echo $$ > "$0/dev.pgid"; exec npm run dev' "$DIR" > "$DIR/dev.log" 2>&1 < /dev/null &
# ログに Ready が出てから、http://localhost:<その番号>/... を撮る
```

`next dev` は同じディレクトリで2つ目を起こしません。ログに `Another next dev server is already running.` と、先にいるサーバーの PID と `kill <PID>` を勧める文が出たら、それはほかの作業者のサーバーなので、勧められた `kill` は打たないでください。止めずに、自分の担当の木（`.claude/worktrees/agent-<id>`）で、依頼に書かれたポートで起こすか、その木で本番ビルドを起こして撮ります（`docs/knowledge/playwright-mcp.md` の同じ節と「本番ビルドの実機検証の段取り」）。担当の木は `.next` をほかの木と分けるので、そこで書いた変更をそのまま撮れます。ほかの担当の木のサーバーを撮るときは、撮る前に `ls -l /proc/<PID>/cwd` が依頼に書かれた木を指すことを確かめます。

撮り終えたら、グループごと止めて、グループのプロセスが0になったこととポートが空いたことを確かめます。Bash ツールはコマンドの間でシェルの変数を引き継がないので、止めるコマンドでも `DIR` を書き直します。止めた直後は片付けを待つ `<defunct>` が数に入ることがあるので、0 にならなければ少しおいて数え直します。

```bash
DIR=<自分専用のディレクトリ>
kill -- -"$(cat "$DIR/dev.pgid")"
ps -eo pgid= | awk -v g="$(cat "$DIR/dev.pgid")" '$1 == g' | wc -l   # 0 になればよい
lsof -nP -iTCP:<その番号> -sTCP:LISTEN                                 # 何も出なければよい
```

dev サーバーで撮った画像には、左下に Next.js の開発用の印（「N」の丸）が写る。来訪者には出ないものなので、見え方の評価から外すこと。

スクリーンショットはPCやモバイルを想定した様々なサイズで保存されます。
すべての画像を確認して、いろいろな環境での見え方を確認してください。

スクリーンショットの一部だけをよく確認する必要があるときは、以下のスクリプトで確認したい領域だけを切り取ってください。
切り取られた画像は、元のスクリーンショットと同じ場所に保存されます。

```bash
npx tsx .claude/skills/take-screenshot/scripts/crop.ts <ファイル名> <幅>x<高さ>+<X座標>+<Y座標>
```

通常のスクリーンショットは縦長になりやすいので、重点的に確認すべき部分を切り取りながら丁寧に確認してください。
全体を遠目に見るだけよりも、個々のパーツを拡大して見た方が適切なチェックができます。

**重要**: リポジトリの肥大化を防ぐため、原則としてスクリーンショットはコミットしないでください。コミットしても良い唯一の例外は、スクリーンショットをサイト内に掲載するときです。

## レビュー時の撮影ルール

UI 変更を伴うサイクルでは、レビューの根拠資料として以下のルールに従って撮影してください。

- **網羅性ルール**: UI 変更がある対象ページ N について、`N × {幅360, 幅1280} × {light, dark} = N × 4 枚` を必ず撮ること。幅360 / 幅1280 はそれぞれモバイル / PC を代表する幅の例であり、上述の「PCやモバイルを想定した様々なサイズ」と整合する。撮影漏れがあった場合は、サイクル完了処理を進めず、検証フェーズに戻して撮り直すこと。
- **着手前（変更前）撮影ルール**: UI 変更を伴う作業では、変更着手前（サイクル kickoff 直後）に「変更前」状態の N × 4 枚を必ず撮ること。これは変更後との対照を「同等以上」と評価するための必須資料であり、後から再現できない場合があるため最初に撮っておく。
- **取り忘れ時の復旧フロー**: 着手前撮影を取り忘れた場合のみ、変更前の状態（担当の木の起点にした作業ブランチのコミット）を `git worktree add <自分専用のディレクトリ>/before <そのコミット>` で別の木に取り出して撮影すること。取り出した木には `cp -al <主の木>/node_modules ./node_modules` で依存を置き、`node_modules` の下は書き換えない。自分の木で `git stash` や `git checkout` で状態を戻さない（書いた変更を退けて、戻すときに衝突しうる）。取り出した木でのサーバーの起こし方は上のとおりで、撮り終えたらサーバーのグループを止め、`git worktree remove` で木を消す。この例外フローで撮影したか否かは、サイクルドキュメントに明記すること。
- 撮影した画像は（上述のとおり）`./tmp/` 配下か `--out` で渡した自分専用のディレクトリに保存し、リポジトリルートやリポジトリ追跡対象に残さないこと。
